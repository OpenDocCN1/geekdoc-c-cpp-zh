## ES6 模块：导入与导出

在 JavaScript ES6 中，你可以从模块中导入和导出功能。这些功能可以是函数、类、组件、常量等。基本上是你赋值给变量的任何内容。模块可以是单个文件，也可以是以一个 `index` 文件作为入口的文件夹。

在书的开头，当你用 `create-react-app` 引导应用程序后，你的初始文件中已经有几个 `import` 和 `export` 语句。这曾是一团糟，因为你希望找到一种标准化的方法，而不是对同一件事采用多种方法。现在是解释这些内容的时机了。

`import` 和 `export` 语句帮助你在多个文件之间共享代码。在此之前，JavaScript 环境中已经有几种解决方案。这曾是一团糟，因为你希望找到一种标准化的方法，而不是对同一件事采用多种方法。现在自 JavaScript ES6 以来，这已成为原生行为。

此外，这些语句支持代码拆分。你将代码分布在多个文件中，以保持其可重用和可维护性。前者是正确的，你可以在多个文件中导入该段代码；后者也是正确的，因为你有一个单一的源来维护这段代码。

最后，它帮助你思考代码的封装。每个功能都需要从文件中导出。其中某些功能应该只在定义它们的文件中使用。文件的导出内容基本上是该文件的公共 API。只有被导出的功能才能在其他地方被重用。这遵循了封装的最佳实践。

但让我们回到实际操作。这些 `import` 和 `export` 语句是如何工作的？接下来的示例通过在两个文件之间共享一个或多个变量来展示这些语句。最后，这种方法可以扩展到多个文件并共享比简单变量更多的内容。

你可以导出一个或多个变量。这被称为命名导出（named export）。

### 代码沙场：file.js

```javascript
const firstName = 'robin';
const lastname = 'wieruch';
export { firstName, lastName };
```

并使用第一个文件的相对路径在另一个文件中导入它们。

### 代码沙场：file2.js

```javascript
import { firstname, lastname } from './file1.js';

console.log(firstname);
// 输出: robin
```

你也可以将另一个文件中所有导出的变量作为一个对象导入。

### 代码沙场：file2.js

```javascript
import * as person from './file1.js';

console.log(person.firstname);
// 输出: robin
```

导入可以有别名。你可能会从多个具有相同命名导出的多个文件中导入功能。这就是为什么你可以使用别名的原因。

### 代码沙场：file2.js

```javascript
import { firstname as foo } from './file1.js';

console.log(foo);
// 输出: robin
```

最后，存在 `default` 语句。它可以用于少数情况：

- 导出默认值
- 导入默认

### 代码组织与测试

代码沙场：file1.js

```javascript
const robin = {
  firstname: 'robin',
  lastname: 'wieruch'
};
```

```javascript

```

代码沙场：file2.js

```javascript
import developer from './file1.js';

console.log(developer);
// 输出: { firstname: 'robin', lastname: 'wieruch' }
```

此外，导入名称可以与导出的名称不同。你也可以将其与命名导出配合使用。

代码沙场：file1.js

```javascript
const firstname = 'robin';
const lastname = 'wieruch';
```

```javascript
const person = {
  firstname,
  lastname
};
```

```javascript
export {
  firstname,
  lastname
};
```

```javascript
export default person;
```

代码沙场：file2.js

```javascript
import developer, { firstname, lastname } from './file2.js';

console.log(developer);
// 输出: { firstname: 'robin', lastname: 'wieruch' }
console.log(firstname, lastname);
// 输出: robin wieruch
```

在命名导出中，你可以节省行并直接导出变量。

### 代码沙场：file1.js

```javascript
export const firstname = 'robin';
export const lastname = 'wieruch';
```

## 使用 Jest 进行快照测试

本书不会深入探讨测试主题，但它是不可忽视的。在编程中测试你的代码是关重要的，并被认为是强制性的。也许你听过测试金字塔。它包括端到端测试、集成测试和单元测试。如果你不熟悉这些，书籍将为你提供一个快速的概览。单元（Unit）用于测试一个孤立且较小的代码块。它可以是一个被单元测试测试的单个函数。然而，有时单元在孤立状态下运行良好，但与其他单元结合时无法正常工作。它们可能需要作为一个整体进行测试。这就是集成测试可以提供帮助的地方，它可以覆盖单元之间是否协同工作。此外，端到端测试是对真实用户场景的模拟。它在浏览器中自动执行。虽然单元测试快速且易编写和维护，但端到端测试则相反。每种类型需要多少测试？你需要许多单元测试来覆盖你的函数。之后，你可能需要几个集成测试来覆盖最重要的函数组合。最后，你可能只需要少量的端到端测试来模拟应用程序中的关键场景。

## 代码组织与测试

### src/App.test.js

```javascript
import React from 'react';
import ReactDOM from 'react-dom';
import renderer from 'react-test-renderer';
import App from './App';

describe('App', () => {
  it('renders without crashing', () => {
    const div = document.createElement('div');
    ReactDOM.render(<App />, div);
    ReactDOM.unmountComponentAtNode(div);
  });

  test('has a valid snapshot', () => {
    const component = renderer.create(<App />);
    let tree = component.toJSON();
    expect(tree).toMatchSnapshot();
  });
});
```

再次运行你的测试，查看测试是成功还是失败。它们应该是通过的。一旦你更改了 App 组件中渲染块的输出，快照测试就会失败。然后你可以决定是更新快照还是在你的 App 组件中进行调查。

基本上`renderer.create()` 函数创建了你的 App 组件的快照。它进行虚拟渲染并将 DOM 存储在快照中。之后，当你最后一次运行快照时，该快照预计与之前的快照匹配。通过这样，你可以确保你的 DOM 保持不变，不会意外更改任何内容。
