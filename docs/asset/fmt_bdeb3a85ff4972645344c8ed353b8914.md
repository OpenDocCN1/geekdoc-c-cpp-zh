
`Alloc` 总是返回初始化的内存。如果你不希望这种情况发生，请确保调试版本用 `ALL_CHK3` 填充一个 `alloc`。`realloc` 在你传递参数时会执行 `malloc`。在你的发行版中不要使用此函数将所有局部变量初始化为 0。这看起来可能比寻找由未初始化变量引起的 bug 更简单的解决方法，但你永远不知道那个 bug 会引发什么问题。

在每个传递指针的 `Alloc` 函数开始时被调用。它首先检查传递的指针。

`AllocWalkHeap` 函数检查整个堆。如果它发现某个元素的 `uId` 值为无效值，它会打印消息并立即退出（你可能更喜欢在这里使用 `abort` 而不是 `return`）。它会检查每个元素是否有覆盖和重写，如果发现则会打印消息。如果 `fShowOk` 为 `true`，它还将打印所有的分配情况。

这些函数不应在程序的零售版本中被调用。因此，它们被完全封装在 `#if DEBUG` 中，这样在非调试模式下就不会被编译。如果在非调试模式下调用它们，将导致链接错误。

### 如何使用内存

以下实践无法解决你所有的堆内存问题，但它们将让你在这个方向上走得很远。这个系统的精妙之处在于，一旦你开始使用它，在你出错之前，它会一直保持隐形状态。当你在处理堆内存时出错时，它通常会准确地告诉你去哪里查找 bug。

### 确保已释放

应该在程序结束时调用 `AllocDone`。这是一次最终检查，用以确保堆没有损坏，并且你已经释放了所有分配。虽然不释放在整个程序生命周期内必须保持 `malloc` 状态的指针是可以的，但你应该确保所有使用周期短于程序生命周期的都已释放。

在调用 `AllocDone` 之前，我会释放所有在程序生命周期内存在的指针。这样，如果我看到堆中留有任何元素，我就知道我在某处忘记释放指针了。
