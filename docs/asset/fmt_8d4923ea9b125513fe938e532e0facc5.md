
```
<?xml version="1.0" encoding="utf-8"?>

<Schema xmlns:cg="http://schemas.microsoft.com/ado/2006/04/codegeneration" xmlns="http://schemas.microsoft.com/ado/2006/04/edm" Namespace="Humanresource.Salaryschema" Alias="Self">

<Documentation>

<Summary>Shows general Syntax of Conceptual schema (csdl) </Summary>

</Documentation>

<EntityType Name="Employee">

<Key>

<PropertyRef Name="EmployeeId" />

</Key>

<Property Name=" EmployeeId " Type="Guid" Nullable="false" />

<!-- Other properties-->

</EntityType>

<Association Name="Monthly_Salary">

<End Role="Employee" Type="Self.Employee" Multiplicity="0..1" />

</Association>

<EntityContainer Name=" Humanresource.SalarySchema ">

<EntitySet Name="Employee" EntityType="Self. Employee" />

<AssociationSet Name="Monthly_Salary" Association="Self.Monthly_Salary">

<End Role="Employee" EntitySet="Employees" />

<!-- Other roles -->

</AssociationSet>

</EntityContainer>

</Schema>
```

前述代码片段中使用的一些元素和属性如下：

- `Schema` — 指每个 XML 模式的根元素。它表示模式中使用的元素已从 `http://schemas.microsoft.com/ado/2006/04/edm` 提取。该元素包含以下两个属性：
  - `Namespace` — 指模式中的顶级节点，分配应唯一的命名空间。模式中定义的类型在 `Humanresource.SalarySchema` 命名空间下逻辑组织。
  - `Alias` — 指可用于缩短模式其余部分中命名空间名称的属性，例如 `Humanresource.SalarySchema`。例如，`Employee` 表可以使用别名 `Self` 缩短，该别名已为命名空间声明，例如 `Self.Employee`。

- `Using` — 指用于缩短引用在单独命名空间中定义的类型时的语法的元素。它包含以下两个属性：
  - `Namespace` — 指定外部命名空间
  - `Alias` — 为命名空间提供别名

- `Documentation` — 指 EDM CSDL 文件中的元素，提供有关在模式中声明的实体和关联的使用信息。它具有以下两个子元素：
  - `Summary` — 提供类型的简要描述。此属性是可选的。
  - `LongDescription` — 包含广泛的文本信息。此属性也是可选的。

> **NOTE**
>
> CSDL 文件的语法中空的 `Documentation` 元素也是有效的。

- `EntityType` — 指 EDM 在 CSDL 模式中用于指定应用程序设计域中对象的元素。它包含以下属性：
  - `Key` — 指定实体的一个或多个属性作为键。它唯一标识实体的实例以进行所有操作，可以由一个以上属性组成。
  - `Name` — 标识设计的对象模型中的类型。
  - `NavigationProperty` — 声明用于在由 `Association` 类型关联的实体之间导航的快捷方式。
  - `Property` 元素 — 包含应用程序中使用的实体的大部分信息。
  - `Type` — 指属性元素的属性，设置为 `Guid` 以指定键的唯一值。

- `Association` — 指指定 EDM 中实体之间逻辑关系的元素。

- `EntityContainer` — 指与 `Schema` 元素不同的元素，即使 `EntityContainer` 元素在模式中定义。概念模式中的 `EntityContainer` 元素映射到存储元数据中相应的 `EntityContainer` 元素。它还控制从中定义的对象模型中实体和关联的范围。

- `AssociationSet` — 指指定从概念模式构建的类中的关联的元素。从概念模式构建的对象模型需要可编程类和存储结构来包含基于它的应用程序的数据。`AssociationSet` 元素的属性如下：
  - `AssociationSetMapping` — 将 CSDL 中定义的 `AssociationSet` 元素连接到 SSDL 中描述存储结构的 `AssociationSet` 元素
  - `Name` — 指定从 EDM 构建的对象模型中类的名称
  - `Extends` — 提供向现有模式添加实体和关联的手段

AssociationSet 元素的子元素如下：

- `EntitySet` — 指定从概念模式构建的类中的类型
- `ReferentialConstraint` — 指定关联的不同角色

> NOTE
> CSDL 的语法用 XML 表示，但它不是基于 XML Schema Definition (XSD)。

## Storage Schema Definition Language

存储元数据模式是对基于 EDM 的应用程序持久化数据的数据库的正式描述。它是映射概念模式中描述的实体和关联到存储模型中定义的相应实体和关联的基础。SSDL 中实体的声明与 CSDL 中实体的声明没有不同。这两种模式之间的基本区别在于实体声明中使用的数据类型。EDM 能够映射存储元数据模式和概念模式中使用的这些不同数据类型。第三种类型的 XML 文件是 MSL。

## Mapping Specification Language

MSL 将 CSDL 中声明的数据类型连接到数据库元数据。该元数据为使用定义的对象模型的应用程序保存数据。CSDL 模式中声明的 Namespace Name 和 EntityContainer Name 标签标识包含在概念模式中的实体和关联。MSL 语法将这些实体和关联映射到 SSDL 文件中的存储元数据。图 22.2 显示了概念模型和逻辑模型的映射：

MSL 文件由以下元素组成：

- `Mapping` 元素 — 指定使用 CSDL 定义的类型与 SSDL 中的元数据之间的映射。使用 `Mapping` 元素的语法如下：

  ```
  <?xml version="1.0" encoding="utf-8"?>

  <Mapping Space="C-S">
  ```

- `EntityContainerMapping` 元素 — 将概念模式中声明的 `EntityContainer` 元素映射到存储元数据模式中声明的 `EntityContainer` 元素。在概念模式中，`EntityContainer` 元素是编程对象模型中类的规范。在元数据模式中，`EntityContainer` 元素是对基于对象模型的应用程序使用的数据库结构的指定。

- `EntitySetMapping` 元素 — 将 CSDL 中定义的 `EntitySet` 连接到 SSDL 中定义的 `EntitySet`。

## The EDM Types

EDM 提供了一个基本结构来声明实体的模式。EDM `EntityType` 是 EDM 为电子商务网站等顶层应用程序概念定义的基本类型。以下几点证明 EDM 类型更基于结构而不是行为：

- EDM 类型不能被封装
- EDM 类型没有关联的方法
- EDM 支持结构继承但不支持行为继承
- EDM 类型使用简单以及复杂实体类型

现在，让我们讨论以下 EDM 类型：

- Simple types
- Entity types
- Complex types

## Simple Types

在 EDM 中，简单类型用于在模式中指定实体属性中包含的内容。它支持属性约束方面和跨多个系统的互操作性。数据类型可以通过方面根据应用程序要求进行自定义。表 22.2 列出了 EDM 的简单类型：

| Type | Description |
|---|---|
| `Binary (EDM)` | 表示固定长度或可变长度的二进制数据。 |
| `Boolean (EDM)` | 表示数学上的二值逻辑概念，如 true 或 false，yes 或 no，以及 0 或 1。 |
| `DateTime (EDM)` | 表示从公元 0001 年 1 月 1 日 12:00:00 午夜到公元 2999 年 12 月 31 日 11:59:59 P.M 的日期和时间。最大精度为毫秒。 |
| `Decimal (EDM)` | 表示具有固定精度和标度的数值。此类型可以描述从负 10^38 + 1 到正 10^38 -1 的数值范围。 |
| `Float (EDM)` | 表示具有七位精度的浮点数，可以表示近似范围为 ±1.18e-38 到 ±3.40e+38 的值。 |
| `Double (EDM)` | 表示具有 15 位精度的浮点数，可以表示近似范围为 ±2.23e-308 到 ±1.79e+308 的值。 |
| `Guid (EDM)` | 表示 16 字节（128 位）全局唯一标识符（GUID）值。 |
| `SByte (EDM)` | 表示有符号 8 位整数值。 |
| `Int16 (EDM)` | 表示有符号 16 位整数值。 |
| `Int32 (EDM)` | 表示有符号 32 位整数值。 |
| `Int64 (EDM)` | 表示有符号 64 位整数值。 |
| `Byte (EDM)` | 表示无符号 8 位整数值。 |
| `UInt16 (EDM)` | 表示无符号 16 位整数值。 |
| `UInt32 (EDM)` | 表示无符号 32 位整数值。 |
| `UInt64 (EDM)` | 表示无符号 64 位整数值。 |
| `Single (EDM)` | 表示单精度浮点变量为 32 位（4 字节）浮点数，负值范围为 -3.402823E38 到 -1.401298E-45，正值范围为 1.401298E-45 到 3.402823E38。 |
| `String (EDM)` | 表示固定长度或可变长度的字符数据。 |

> NOTE
> `String` 数据类型未指定要使用的 Unicode 类型。设计者必须从托管 EDM 的类型系统中指定适当的 Unicode 类型。

## Entity Types

EDM 中的实体类型是应用程序域中数据类型的设计模板。在模式中，实体类型具有名称、属性和在由应用程序代码实例化时标识数据类型的键。在被模式定义后，实体类型成为应用程序开发的操作单元，每个都具有唯一的身份。

## Complex Types

EDM 中的复杂类型是一种具有内部结构的数据类型，但不包含键属性。它用于实现具有自身内部属性的属性。
有时，我们需要放置约束来限制实体的某些属性。为此，EDM 提供了类型约束。让我们接下来探索类型约束。

## Type Constraints

在 EDM 中，我们可以对实体类型的属性施加某些约束。约束限制属性的可能值，并验证分配的值不仅纠正数据类型，而且检查其是否根据应用程序的业务需求工作。其中一些主要约束如下：

- `Nullable` 约束 — 指定属性的值是否可以未分配
- `MaxLength` 约束 — 限制字符串属性的长度

Entity Framework 还提供了某些工具来帮助处理模型，我们接下来描述这些工具。

## Data Model Tools

ADO.NET Entity Framework 允许用户将数据从高效的存储引擎（如 SQL Server）带到面向对象的编程中。许多开发人员实现复杂的 数据访问代码以在应用程序和数据库之间移动数据。ADO.NET Entity Framework 提供了以下有助于我们使用 EDM 开发应用程序的工具：

- ADO.NET Entity Data Model Item Template — 指可用于 Visual Basic (VB) 和 C# 项目以及 ASP.NET 网站和 Web 应用程序项目的模板。它基本上用于启动 Entity Data Model Wizard。
- Entity Data Model Wizard — 从现有数据库生成 EDM，并将连接字符串添加到 `App.Config` 或 `Web.Config` 文件中，并配置单个文件生成器以在 `.edmx` 文件中包含的概念模型上运行，该文件通过向导封装生成的 EDM。`.edmx` 文件中定义的概念模型有助于生成 C# 代码。
- The ADO.NET Entity Data Model Designer — 使我们能够在设计器中打开 `.edmx` 文件，并通过 EDM Designer 包含的一些可视化工具创建实体并将实体映射到数据库表和列。
- `EDMGen.exe` — 指可用于生成模型并对 EDM 元数据文件执行其他功能（如验证现有模型）的命令行工具。

## Understanding Object Services

在 Entity Framework 中，Object Services 是一种服务，支持对 EDM 中定义的所有类型的 LINQ 和 Entity SQL 查询。Object Services 以对象形式返回数据，包括将对象中的任何更改返回到数据存储。LINQ 和 Entity SQL 查询的支持使 Object Services 能够执行 QUERY、INSERT、UPDATE 和 DELETE 数据操作。该服务还能够跟踪更改、将对象绑定到控件并处理并发。

## 对象服务的类

对象服务的概念由 `System.Data.Objects` 和 `System.Data.Objects.DataClasses` 命名空间中的类实现。以下是与对象服务一起使用的一些类：

- `ObjectContext` 类 — 表示用于与数据交互的主要类，该数据以 EDM 中定义的实体类型的实例对象的形式存在。`ObjectContext` 类封装了 .NET Framework 与数据库之间的连接。此类充当 CREATE、UPDATE 和 DELETE 操作的网关。`ObjectContext` 类的实例封装了以下内容：
  - 一个 `EntityConnection` 对象，指定到数据库的连接
  - 一个 `MetadataWorkspace` 对象，描述模型
  - 一个 `ObjectStateManager` 对象，管理缓存中存在的对象

  `ObjectContext` 类使用 `System.Data.Objects` 命名空间和 `System.Data.Entity` 程序集（在 `system.data.entity.dll` 中）来以对象形式处理实体数据。`System.Data.Objects.ObjectContext` 类的继承层次结构如下：

  ```
  System.Object
  System.Data.Objects.ObjectContext
  ```

  声明 `ObjectContext` 类的语法如下：

  ```
  public class ObjectContext : IDisposable
  ```

- `EntityConnection` 类 — 表示到底层数据存储的连接。此类不能被继承。你需要使用 `System.Data.EntityClient` 命名空间和 `System.Data.Entity` 程序集（在 `system.data.entity.dll` 中）来使用此类。`System.Data.EntityClient.EntityConnection` 类的继承层次结构如下：

  ```
  System.Object
  System.MarshalByRefObject
  System.ComponentModel.Component
  System.Data.Common.DbConnection
  System.Data.EntityClient.EntityConnection
  ```

  声明 `EntityConnection` 类的语法如下：

  ```
  public sealed class EntityConnection : DbConnection
  ```

- `MetadataWorkspace` 类 — 表示 ADO.NET 元数据运行时服务组件，提供从各种源检索元数据的支持。你需要使用 `System.Data.Metadata.Edm` 命名空间和 `System.Data.Entity` 程序集（在 `system.data.entity.dll` 中）来使用此类。`System.Data.Metadata.Edm.MetadataWorkspace` 类的继承层次结构如下：

  ```
  System.Object
  System.Data.Metadata.Edm.MetadataWorkspace
  ```
