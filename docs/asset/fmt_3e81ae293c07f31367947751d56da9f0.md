
`class-object.event-name` += new `class-object.delegate-name(method-name)`;

同样，当你希望从事件源中分离时，可以使用重载的 `-=` 运算符，如下所示：

```
class-object.event-name -= new class-object.delegate-name(method-name);
```

让我们考虑一个系统对象跟踪数据库及其记录状态的场景。当数据库管理器对象添加、删除或甚至修改一行时，它会直接通知该系统对象数据库已更改。此过程耗时，因为数据库管理器需要知道系统对象的所有内部结构。如果系统对象被更改，或添加了额外的系统对象，程序需要进行重大修改以反映更改。

C# 提供了事件源和事件处理程序，有助于解决对象通知的问题，而无需在事件生成系统中提供有关外部对象的详细信息。

现在让我们学习事件源、事件处理程序、事件和委托，以及多个事件处理程序。

## Event Sources

事件源是一个通知其他对象或任务发生了某事的对象。C# 中的事件通知采用回调的形式。事件源在想要通知其他对象发生了更改时会发出一条通用消息，然后任何对该消息感兴趣的对象都可以读取并解释它。事件处理采用发布-订阅的形式，这需要一种广义的广播机制，并且所有对象接收所有消息。

在 C# 中，每个事件源维护其发布的所有事件。从调用者的角度来看，C# 中的事件被认为是异步的。回调的发生取决于触发事件的对象，而不是其调用者。

## Event Handlers

事件处理程序接收事件通知。当事件源通知事件被调用时，所有已注册接收该事件通知的事件处理程序开始执行。事件处理程序可以是类的静态或非静态方法。对于静态方法，事件处理程序只需响应给定的事件源，并根据传递给处理程序的信息采取行动。可以考虑对象的整个状态，从而允许对象为非静态事件处理程序的给定事件做出决策。

让我们考虑一个处理账户透支问题的事件处理程序。账户透支事件发生在账户所有者提取的金额会使账户变为负数时。在这种情况下，你可能希望向用户发送电子邮件消息，通知他除非当天将账户恢复平衡，否则用户将被收取费用。为此，事件处理程序需要被通知借记已导致余额变为负数这一事实。

## Events and Delegates

C# 中的整个事件机制都基于委托。委托充当事件源和事件处理程序方法之间的媒介。它将有关事件的信息传递给事件处理程序，并允许其将信息传回事件源。

为了学习如何实现事件，让我们看一个触发事件并接收事件发生通知的简单示例。在此示例中，一个简单的类包含一个可以被触发的事件。你需要的第一个两个元素是事件本身以及在事件被触发时调用的委托。

以下是处理这两个项目所需的代码中的方法定义：

```
// This is the event itself
public event ValueChangedEventHandler Changed;

// Allow a handler for the event
public delegate void ValueChangedEventHandler();
```

在创建事件并声明在事件触发时调用的委托之后，下一步是使用触发事件的方法。此方法用于在对象事件源和可能分配来处理事件的方法之间建立连接，如以下代码片段所示：

```
// This method is used to fire the event
protected virtual void OnChanged()
{
    if (Changed != null)
        Changed();
    else
        Console.WriteLine("Event fired. No handler!");
}
```

在前面的代码片段中，你可以看到事件触发机制很简单，它看起来与函数调用完全一样。与函数或方法调用类似，事件处理程序可以接受参数。例如，类中 `nValue` 变量的值已更改。如果你想通知监听者此更改，你必须触发事件。以下代码片段显示了如何触发事件：

```
public void SetValue( int nv )
{
    if ( nValue != nv )
    {
        nValue = nv;
        // Fire the event
        OnChanged();
    }
}
```

事件机制绝非自动的。如果类中的方法直接修改内部成员变量，而不调用方法，则不会触发事件。考虑以下声明名为 `BadMethod()` 的方法的代码片段：

```
public void BadMethod()
{
    nValue++;
}
```

在这种情况下，表示变量已更改的事件不会被触发，因为 CLR 不会识别事件与变量值的关联。在处理检查此类值的事件时，你需要确保在适当时始终调用事件触发机制。触发事件的最佳方式是将该事件嵌入访问器中。以下代码片段显示了如何在另一个类中定义事件处理程序：

```
public static void HandleChange()
{
    Console.WriteLine("Handler Called");
}
public static void Main()
{
    EventTestClass tc = new EventTestClass(3);
    // Create a handler for this class
    tc.Changed += new EventTestClass.ValueChangedEventHandler(
        HandleChange);
}
```

在前面的代码片段中，你可以看到我们选择了静态方法作为事件处理程序。事件处理程序方法的签名必须与事件本身的签名匹配。在这种情况下，委托方法签名指定了一个不包含参数且不返回值的方法（`void` 返回）。请注意，事件处理程序方法包含相同的签名。如果你尝试对该事件处理程序使用接受任何参数或返回任何类型值的方法，编译器会将其标记为错误。假设你想将变量的当前值传递给方法，并希望事件处理程序测试该值是否可接受，你可以修改委托以读取代码，如下所示：

```
public delegate Boolean ValueChangedEventHandler(int nValue);
```

如果委托被修改，你还需要修改事件源中 `OnChanged()` 方法中的事件触发机制以读取代码，如以下代码片段所示：

```
protected virtual void OnChanged()
{
    if (Changed != null)
        if (Changed(nValue))
            ; // Commit the change
}
```

同时，在事件处理程序对象中，代码需要被修改以验证输入。以下代码片段显示了如何声明变量所需的值范围：

```
public static Boolean HandleChange(int nValue)
{
    if (nValue <= 0 || nValue >= 10)
        return false;
    return true;
}
```

正如你所见，`HandleChange()` 方法强制事件源类中的成员变量介于 1 和 9 之间。任何其他值都会触发返回 `false` 条件，这会阻止事件源将值设置在成员变量中。回到监控负余额的类示例，你可以看到你可以使用事件处理程序拒绝会导致余额变为负数的交易。

## Multiple Event Handlers

我们可以向单个事件添加单个以及多个事件处理程序。正如你之前所学的那样，在为给定事件源对象中的给定事件设置事件处理程序时，你使用了 `+=` 运算符来添加事件处理程序。使用仅 `+=` 运算符而不使用 `=` 或其他运算符的原因是，可以从同一事件处理对象或多个对象为事件定义额外的处理程序。

正如你在前一节中可能注意到的那样，事件源仅调用一次事件处理程序的委托。在这种情况下，事件源不知道有多个处理程序可用以处理事件。它也不知道其中任何一个其他事件处理程序是否已被调用。

例如，如果你添加了两个不同的事件处理程序，它们返回布尔值以指示给定值是否正确，那么 CLR 如何使用该值并链接到下一个委托？答案是多播委托，这是唯一可以用于链接事件处理程序且不能返回值的那种。因此，你会得到编译时错误，因为多播仅支持 `void` 返回类型。现在，让我们进入 Immediate Solutions 部分，在实践中实现这些概念。
