## Silverlight 中的数据绑定

简单来说，数据绑定是指数据提供程序与包含数据绑定控件（如`DataGrid`）的UI之间的连接。UI被称为目标，数据提供程序被称为源。这种数据绑定的划分有助于维护应用程序并提高应用程序的性能。性能之所以提高，是因为这种数据绑定划分减少了对服务器的往返调用。`Silverlight`是`.NET Framework 4.0`的一部分，您可以在其中实现数据绑定。让我们来了解`Silverlight`中数据绑定的各个方面。

### Silverlight 中数据绑定的类型

在`Silverlight`应用程序中，您可以将数据绑定为以下几种类型：

- `OneTime` – 设置目标，然后绑定完成。当您显示很少或从不更改的数据时，可以使用`OneTime`绑定。
- `OneWay` – 设置目标，并在源更改时保持目标最新。当您显示不允许更改的数据时，可以使用`OneWay`绑定。
- `TwoWay` – 设置目标，并在源更改时保持目标最新。当您更改目标或应用程序中有其他更改导致源发生变化时，它也会使源保持最新。

您可以使用一个简单的示例来理解`Silverlight`中的数据绑定类型。假设您负责构建一个在线书店。如果您正在显示有关一本书的信息，您可能会对书名和作者使用`OneTime`绑定，因为它们永远不会更改。对于书的价格，您会使用`OneWay`绑定，因为用户无法更改它。对于手头的书的数量，您会选择`TwoWay`绑定，因为它可能会发生变化。

### 绑定对象

`Silverlight`中的绑定对象是目标与源之间的通用连接器。该绑定对象负责从源检索目标所需的数据。`Silverlight`中的绑定对象表示对象的属性值与控件的属性值之间的绑定。例如，您可以将`TextBox`控件的`Text`属性绑定到`Customers`表的`FirstName`列。类似地，您可以将另一个`TextBox`控件的`Text`属性绑定到`Customers`表的`LastName`列。当您运行应用程序时，绑定对象将确保在相应的`TextBox`控件中检索到正确的数据。数据绑定的这一特性在`Silverlight`应用程序中非常有用。在前一节解释的示例中，您实际上是在使用绑定对象绑定`TextBox`控件的`Text`属性。

### 数据上下文

数据上下文是在运行时从源中选择正确的数据并将其发送到目标的过程。例如，当您将目标与源绑定时，您只需指定目标将显示的数据种类。您指定特定的文本框将显示客户的姓名。您不指定要显示哪个客户姓名。您只需将`TextBox`与`Customers`表绑定。这就是数据上下文发挥作用的地方。数据上下文是在运行时显示的特定客户。简单来说，您可以将数据上下文视为可以绑定到目标的数据源。当容器控件中有多个控件且所有控件都使用相同的绑定源时，数据上下文非常有用。每个`FrameworkElement`对象都有一个数据上下文。

在创建绑定时，必须将`FrameworkElement`对象的依赖项属性分配给绑定。这是绑定操作的基本目标。您可以通过元素的`DataContext`属性设置绑定的源。数据上下文还允许其元素从父容器继承有关数据源的信息。

## Converters

你可以在 `Silverlight` 中使用转换器（converters）对数据绑定应用自定义逻辑。通过自定义逻辑，我们指的是格式化在 UI 中显示的数据。转换器最初在 `WPF` 中使用，并已完全迁移到 `Silverlight`，以使 `Silverlight` 中的数据绑定过程变得简单。`Silverlight` 中的数据绑定支持转换器，它允许你在绑定中使用的属性之间进行映射。与 `WPF` 不同，`Silverlight` 中的数据模板没有用于绑定数据的触发器。`Silverlight` 中的转换器的工作方式与 `WPF` 中的数据触发器相同。

## DataTemplate and ObservableCollection

你在 `.NET Framework` 中使用的数据是一个对象集合。你可以使用 `DataTemplate` 对象在 `Silverlight` 中提供数据绑定项的自定义显示，该对象负责显示列表中的每个项目。例如，`Silverlight` 中的 `ListBox` 控件是一个 `ItemsControl` 对象。这意味着你可以通过将 `ItemTemplate` 属性设置为 `DataTemplate` 来为其包含的每个项目建立 `DataTemplate` 对象。

`.NET Framework` 中的 `ObservableCollection` 对象表示一个动态数据集合，当你添加项目、删除项目或刷新整个列表时提供通知。你可以将 `ObservableCollection` 对象称为数据绑定的一个不错选择，因为它实现了 `INotifyPropertyChanged` 和 `INotifyCollectionChanged` 接口。这些接口负责在列表中的项目发生变化或属性本身发生变化时向绑定目标提供更改通知。你应该在 `Silverlight` 应用程序中添加 `System.Collections.ObjectModel` 命名空间以使用 `ObservableCollection` 类。

## Data Binding Using Networking API

`Silverlight 3.0` 支持跨域网络支持。`Silverlight` 中的网络支持超文本传输协议（`HTTP`）和套接字。这意味着你的应用程序可以调用最初指定的站点之外的站点。`Silverlight` 将检查目标服务器上是否存在 `XML` 策略文件，该文件指示是否允许使用 `Silverlight` 中的网络进行跨域网络访问。此外，`Silverlight 3.0` 具有内置的网络应用程序编程接口（`API`），使 `Silverlight` 客户端能够调用远程 `XML HTTP` 服务。此外，`Silverlight 3.0` 还包含内置的套接字 `API`（`System.Net.Sockets`），使 `Silverlight` 客户端能够通过非 `HTTP` 协议进行通信。

`Silverlight 3.0` 还引入了新的网络监控 `API`，帮助你检查是否已连接到网络。你可以使用以下语法确定网络状态，即已连接或未连接：

```csharp
bool connectionStatus = NetworkInterface.GetIsNetworkAvailable();
```
