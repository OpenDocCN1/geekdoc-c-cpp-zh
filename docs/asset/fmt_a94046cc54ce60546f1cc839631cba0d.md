
**注意：** Apple 文档建议在 `+sharedInstance` 方法中使用 `@synchronized(self)` 来创建单例。那种方法比本节提议的方法要慢得多，而且需要更多代码，因此没有什么推荐的。

你不需要在单例中重写 `+allocWithZone:`，但如果你这样做，它会提供一点额外的运行时检查。如果你在单例实例创建后尝试分配该类的新实例，示例代码将抛出异常。

注意 `+allocWithZone:` 和 `+initialize` 方法中的测试。这些测试对于子类化是必要的。你不希望在有人创建你的单例对象的子类时抛出异常。单例子类化相当复杂，如果你不想支持它，可以跳过这个额外的测试。

## 代理 (Delegation)

Objective-C 不支持多继承。这并不是一个巨大的限制，因为很难很好地使用多继承，但在某些问题上，它似乎是自然的解决方案。

> ¹GCC 运行时中存在一个长期存在的 bug，阻止了该功能的正常工作，但在 GNUStep 运行时中已修复。

代理模式背后的思想与继承和原型背后的思想相似：你允许一个对象定义另一个对象行为的子集。

你不会在 Foundation 框架中经常看到这种用法，但在 AppKit 或 UIKit 代码中非常常见。每个用户界面对象都使用代理来允许你定义响应用户界面事件时发生什么。

有几种模式与代理有关，它们都遵循一个通用规则：你应该优选对象组合而非继承。这对于松耦合非常重要，因为它使得代码复用变得容易得多。

如果你有一个 C++ 类，由三个父类提供其行为的某些方面，那么修改它比一个将其功能某些方面委托给三个其他类的 Objective-C 类要困难得多。

## 提供外观层 (Façades)

```
@interface Control : View
{
    id cell;
}
@end
@implementation Control
-(id)selectedCell {
    return cell;
}
-(BOOL)isEnabled {
    return [[self selectedCell] isEnabled];
}
-(void)setEnabled:(BOOL)flag {
    [self selectedCell] setEnabled:flag];
    [self setNeedsDisplay: YES];
}
@end
```

代理的一个非常常见的用途是外观模式（Facade pattern）。它将一个或多个私有或半私有对象封装在一个公共接口中。这在 Objective-C 中非常常用，用于提供类似于多继承的功能，即对象结合了几个不同对象的行为，并将其部分功能委托给每个对象。

AppKit 中的 `NSControl` 层次结构是一个很好的例子。该层次结构中的类继承 `NSView` 的行为，并将行为委托给 `NSCell` 子类。`NSView` 提供了诸如图形上下文、事件处理和与视图层次结构交互等功能。`cell` 则提供了诸如绘制等功能。本节开头的示例是 `NSControl` 的（非常）简化的版本。

当你点击 OS X 上的按钮时，你通常是在点击一个 `NSControl` 子类的实例，并使用 `NSButton` 和 `NSCell` 作为其实现。作为程序员，你可以交替使用控件，也可以复用它们包含的 `cell`。例如，如果你在表格或大纲视图中看到一个按钮，它是用 `NSCell` 绘制的，而不是用 `NSButton` 绘制。

在第 19 章中，我们将研究如何使用 Objective-C 转发机制来快速方便地实现这种外观。直接通过调用被封装的对象或多个对象的方法来实现它们也是可能的，而且很常见。

这种方法比多继承要灵活得多，因为它允许同一个类用于许多不同的委托。在 C++ 中，你会使用模板类来实现相同的效果。Objective-C 版本生成的代码少得多，这有利于更好的指令缓存利用。

## 创建类簇 (Creating Class Clusters)

```
static Pair *placeHolder;
+ (void)initialize
{
    if ([Pair class] == self)
    {
        placeHolder = [self alloc];
    }
}
+ (id)allocWithZone:(NSZone*)aZone
{
    if ([Pair class] == self)
    {
        if (nil == placeHolder)
        {
            placeHolder = [super allocWithZone:aZone];
        }
        return placeHolder;
    }
    return [super allocWithZone:aZone];
}
- (Pair*)initWithFloat:(float)a float:(float)b
{
    return [[FloatPair alloc] initWithFloat:a float:b];
}
- (Pair*)initWithInt:(int)a int:(int)b
{
    return [[IntPair alloc] initWithInt:a int:b];
}
```

源自 `classCluster.m`

类簇在 Objective-C 中非常常见。许多 Foundation 类都是类簇，你可能会实现自己的类簇是有用的。

类簇是一个隐藏了具体子类的抽象父类。这比许多语言更容易，因为没有创建对象的关键字。当你向类发送请求新实例的消息时，该类可能返回自身的实例，也可能返回某些子类的实例。

如果你使用 `+arrayWithObjects:` 创建 `NSArray`，你可能会得到一个封装简单 C 数组的子类。如果你使用 `+arrayWithArray:` 创建，你可能会得到一个仅仅引用另一个数组的类。

另一个很好的例子是 `NSNumber`。它封装了一个单个 C 原始值。你可以用两个实例变量来实现它：一个包含所有可能类型的联合体（union），另一个说明它是哪种类型。这将浪费大量的空间并且相当复杂。一个更简单的解决方案为你支持的每个类型实现一个不同的子类。

大多数类簇都提供了命名的构造函数，例如 `+numberWithFloat:`，用于创建正确子类的新实例。如果你使用 `+alloc` 创建它们，通常会得到一个占位类，并在响应 `initialize` 消息时获得真实对象。

示例是一个 `Pair` 类。它没有声明任何实例变量，也从未被直接使用。如果你向该类发送 `+alloc` 消息，你会得到一个单例实例。当你

向它发送初始化消息，你将获得两个私有子类的一个实例。

```objc
@implementation IntPair
-( (Pair*)initWithInt:(int)a int:(int)b {
    first = a;
    second = b;
    return self;
}
-(NSString*)description {
    return [NSString stringWithFormat:@"%d, %d",
	first, second];
}
-(float)firstFloat { return (float)first; }
-(float)secondFloat { return (float)second; }
-(int)firstInt { return first; }
-(int)secondInt { return second; }
@end
```

这些具体子类都非常简单。它们都声明了两个实例变量：一个是 `int`，另一个是 `float`。它们各自提供一个单一初始化器（该初始化器仅从父类调用），然后它们重写了方法。这个示例没有在父类中提供任何实用的方法。在实际实现中，根据这里显示的四个方法，可能会在父类中实现比较或算术方法。或者，它们可能会在单独的分类（category）中提供。

类簇（class cluster）隐藏了实现的所有细节。你可以更改私有子类的任何方面，而无需修改甚至重新编译使用它们的代码。这就是为什么 Objective-C 中的代码复用比 C++ 等语言更常见的原因之一。在 Objective-C 中，很容易编写出具有公共接口和私有实现的代码，而使用它的代码不需要依赖于实现的任何方面。

子类类簇通常需要实现少数原始方法。其他方法都是基于这些核心功能实现的。我们将在第 7 章的“集合子类”部分详细介绍。

例如，如果你想创建一个 `NSString` 的子类，必须实现 `-length` 和 `-characterAtIndex::`。该类中的所有其他方法只是调用这两个。更高效的实现还会实现 `-getCharacters:range::`。

## 使用运行循环

```
[NSRunLoop currentLoop] run];
```

来自：`timer.m`

定义大多数非复杂 Objective-C 程序结构的设计模式是运行循环（run loop）。通常，运行循环等待来自一个或多个事件源的数据，然后响应这些数据执行代码，提供了一种事件驱动的编程模型。

Foundation 框架在 `NSRLoop` 类中提供了运行循环的实现。如果你正在编写应用程序，通常会自动为你创建一个该实例。你也可以在命令行工具中显式地创建一个。

应用程序的主运行循环监听来自窗口服务器的事件，对应于按键、鼠标移动、触摸事件等。其他各种类会隐式地向运行循环添加事件源。例如，我们将在第 8 章介绍的 `NSTimer` 类会向运行循环添加定时器事件源，从而允许你在特定时间执行某些操作。

第 16 章介绍的通知机制允许你通过运行循环在程序内部传递任意事件的通知，你还可以通过 `NSFileHandle` 注册文件描述符上的活动通知。

运行循环本身与内存管理有关。每次运行循环迭代都有自己的自动释放池（autorelease pool）。这意味着在运行循环迭代期间发送 `-autorelease` 消息的对象将在迭代结束时被销（除非在其他地方保留）。由于这一点，加上运行循环用于递送来自用户输入的事件，最好将单个运行循环迭代中执行的工作尽可能减小。在大多数程序中，你不需要直接与运行循环交互。它在后台运行，而其他类提供了更方便的接口。

## 数字

Objective-C 和 Smalltalk 之间的一个大区别是 Objective-C 继承了全范围的原始（非对象）C 类型。这些按 own从小到大排列是 `char`, `short`, `int`, `long` 和 `long long` 整数，带有有符号和无符号变体，以及两种浮点类型：`float` 和 `double`。它们的行为与 C 中完全相同，并包含完整的类型提升规则。你还会发现 Objective-C 编译器支持 `long double` 类型，它是取决于架构的。

注意，这与 Java 非常相似，在 Java 中你只有少量的非对象类型可选，但存在一些非常重要的区别。在 Java 中，*固有类型（intrinsic types）*被定义为固定大小。在 C 中，它们被定义为具有最小精度。例如，规范说 `int` 具有“执行环境架构建议的自然大小”，而在 Java 中，它被显式地定义为“32 位有符号补码整数”。

除了原始类型外，C 还支持通过 `typedef` 关键字为现有类型定义新名称。最常见的原因是规范没有要求任何标准类型具有特定大小，只需每种类型至少与前一个一样大。特别是，目前部署的平台中 `int` 可能是 16 位、32 位或 64 位，因此你不能依赖它们的任何特定大小。

OS X 支持 IL32 和 LP64 模式。这种简写用于描述哪些 C 类型具有什么大小。IL32 意味着 `ints` 和指针是 32 位。LP64 意味着 `longs` 和指针是 64 位。将指针转换为整数是一个严重的问题。C99 引入了 `intptr_t` typedef，它是指针的大小。Apple 引入了等效物：`NSInteger`。它在整个 Cocoa 框架中都被使用，且大小始终与指针相同。还有一个无符号版本 `NSUInteger`。在 GUI 代码中，你经常会遇到 `CGFloat` 或 `NSFloat`。它们相互之间是等价的，且大小与 `double` 相同。

## 在集合中存储数字

```
NSMutableArray *array = [NSMutableArray array];
[array addObject:[NSNumber numberWithInt:12]];
```

来自：`numberInArray.m`

所有的标准 Objective-C 集合类都允许你存储对象，但你通常也想存储原始类型。解决此问题的方法是装箱（boxing）——将原始类型包装在对象中。

`NSValue` 类层次结构用于此操作。`NSValue` 是一个设计用于包装原始值的类。该类非常通用，是类簇的一个示例。当你创建 `NSValue` 实例时，你会得到某个子类，专门用于存储不同类型的数据。如果你在 `NSValue` 中存储一个指针，你不希望该实例占用的空间像包含 `NSRect`（一个包含四个 Float 的 C 结构体）那样大。

`NSValue` 的一个具体子类特别重要：`NSNumber`。该类旨在包装单个数值，并可以从任何 C 标准整数类型初始化。

这两个类的指定构造函数（designated constructor）都是 `+writeValueBytes:objcType`。第一个参数是某个值的指针，第二个参数是该类型的 Objective-C 类型编码（type encoding）。类型编码是表示特定类型的字符串。它们在 Objective-C 的内省中被大量使用；你可以作为类型编码字符串获取类中任何方法或实例变量的类型，并解析它以获取相关的编译时类型。

你可以使用 `@encode()` 指令获取任何类型的类型编码。这类似于 C 中的 `sizeof()`，但它不是以整数形式返回大小，而是以 C 字符串的形式返回类型编码。在处理类型编码时，一个非常方便的技巧是使用 `typeof()` GCC 扩展。它返回表达式的类型。你可以将其与 `@encode()` 结合使用，如下所示：

```objc
NSValue *value =
[NSValue valueWithBytes:&aPrimitive
objcType:@encode(typeof(aPrimitive))];
```

这段代码将返回一个包装了 `aPrimitive` 的 `NSValue`

这是一个原始类型（primitive），并且无论原始类型的类型如何都能工作。你可以将其封装在一个宏中，但如果你这样做，请注意不要传递一个带有副作用的表达式。

请注意，你必须传递指向原始值的指针。此方法将使用类型编码来确定该原始类型的大小，然后对其进行拷贝。

通常情况下，你会使用其他构造构造函数之一。例如，如果你想从一个整数创建一个 `NSNumber` 实例，可以这样做：

```
NSNumber *twelve = [NSNumber numberWithInt: 12];
```

生成的对象可以添加到集合中。与 `NSValue` 不同，`NSNumber` 实例是有序的因此你可以对包含 `NSNumber` 实例的集合进行排序。

`numberArray.m` 示例将一组 `NSNumber` 实例存储在数组中，然后使用 `-compare:` 选择器对其进行排序。从输出可以看出，无论数字是如何创建的，排序都是强制执行的。

## 执行小数算术

```
NSDecimalNumber *one = [NSDecimalNumber one];
NSDecimalNumber *fortyTwo = [NSDecimalNumber decimalNumberWithString:"42"];
NSDecimalNumber *sum = [one decimalNumberByAdding:fortyTwo];
NSDecimalNumber accumulator = [sum decimalValue];
NSDecimalNumber temp = [fortyTwo decimalValue];
NSDecimalMultiply(&accumulator, &accumulator, &temp, NSRoundPlain);
temp = [one decimalValue];
NSDecimalAdd(&accumulator, &accumulator, &temp, NSRoundPlain);
NSDecimalNumber *result = [NSDecimalNumber decimalNumberWithString:accumulator];
```

来自：`decimal.m`

C 语言提供了两种处理数字的选项：整数和浮点值。

浮点值由两个部分组成：尾数和指数。它们的值是 2 的幂乘以尾数。

浮点值的问题在于它们是二进制的。这意味着它们的精度是根据二进制位定义的，而这并不总是你想要的。例如，对于金融应用程序，你可能需要精确存储到四位小数的金额。这通过浮点值是不可能的；像 0.1 这样的值无法用任何有限的二进制浮点表示，就像三进制的 0.1（三分之一）无法用任何有限的十进制序列一样。
