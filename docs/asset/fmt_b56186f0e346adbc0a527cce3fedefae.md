## 使用 Blocks

```
int (^getCounter(void))(void)
{
    __block int counter;
    int(^block)(void) = ^void() { counter++; };
    return Block_copy(block);
}
int main(void)
{
    [NSAutleasePool new];
    int(^block)(void) = getCounter();
    NSAssert(block == 2, @"Block counted incorrectly");
    int(^block2)(void) = getCounter();
    NSAssert(block2 == 2, @"Block didn't start from 0");
    return 0;
}
```

*来自：`block.m`*

从1.6开始，Apple 引入了 blocks 作为 C 语言的扩展，通常与 Objective-C 结合使用。Blocks 是闭包（closures），有时称为 lambdas。这个名字源于 Smalltalk，在其中闭包封装了变量。创建 blocks 的语法非常丑陋。它基于 C 语言的函数指针语法，但用脱字符（^）代替了星号（*）。blocks 的用法几乎和函数指针完全一样。你可以像调用函数一样调用它们，但不能将它们强制转换为函数指针，因为它们有不同的调用约定。在示例中，`getCounter()` 函数返回一个实现计数器的新 block。每当你调用它时，它返回的值比上一次调用时大1。这之所以有效，是因为在创建 block 的作用域内 `counter` 变量使用 `__block` 修饰符进行了声明。blocks 引用的栈上任何变量都会被复制到堆上并进行引用计数。当你调用 `Block_copy()` 时，如果 block 本身在栈上，它会被复制到堆上；如果不在栈上，则会增加它的引用计数。`Block_copy()` 实际上是一个宏，它封装了该函数并将返回类型从 `void*` 转换为参数的类型。

在 Foundation 框架的最新版本中，你会发现许多以 blocks 作为参数的方法。例如，你可以使用 block 参数来遍历数组。Blocks 并没有给 C 语言增加任何表达能力。一个 block 只是隐藏在一个单一结构中的函数指针和数据指针，编译器中还有一些额外的逻辑，在调用函数时将数据指针作为隐藏参数插入函数中。这并不意味着 blocks 是没用的。毕竟，Objective-C 的情况也是如此；它并没有让你做任何在 C 中无法做的事情，它只是增加了一些语法糖，让事情变得更简单。就像 Objective-C 对象一样，blocks 有一个 `isa` 指针并可以发送消息。它们是 `NSBlock` 抽象类的实例，该类实现了 `NSCopying` 协议。blocks 大多数类似对象的行为是没有记录的。你可以将它们存储在 Objective-C 集合中，但不要依赖它们理解任何特定消息的能力。在最新版本的 Clang 中，blocks 还支持内省（introspection），将它们的类型暴露为 Objective-C 类型。我们将在第15章详细介绍 blocks。

## 内存管理

如果你有 C 或 C++ 背景，你可能习惯于跟踪对象的所有权，并手动分配和销毁它们。如果你来自 Java 这样的语言，你可能习惯了让垃圾回收器为你处理好这一切。

Objective-C 在语言层面没有提供任何用于分配或释放对象的机制。这被留给了 C 代码。你通常通过向类发送 `+alloc` 消息来分配对象。这会调用类似 `malloc()` 的函数为对象分配空间。向实例发送 `dealloc` 消息将清理它的变量并将其删除。Foundation 框架为这种简单的人工内存管理增加了引用计数。一旦理解了它的工作原理，这会让生活变得容易得多。新的编译器为你提供了一些帮助，让你无需自己编写引用计数代码。

## 留（Retaining）与释放（Release）

```
NSArray *anArray = [NSArray array];
anArray = [[NSArray alloc] init];
[anArray release];
```

*来自：`retainRelease.m`*

每个继承自 `NSObject` 的对象都有一个关联的引用计数。当这个引用计数达到0时，它就会被销毁。使用 `+alloc` 或任何相关方法（如 `+new` 或 `+allocWithZone:`）创建的对象，其生命周期开始时的引用计数为1。

为了控制对象的引用计数，你向它发送 `-retain` 和 `-release` 消息。正如它们的名字暗示的那样，当你想要保留对象的引用或想要释放现有的引用时，应该使用这些消息。`-retain` 消息增加对象的引用计数，而 `-release` 消息则递减它。

你也可以向对象发送 `-retainCount` 消息来确定其当前的引用计数。人们很想用它来优化，并在你确定一个对象只有一个引用时调用某些特殊情况。这是一个非常糟糕的主意。

## 留（Retaining）与释放（Release）

Objective-C 中的指针被分为两类：所有权引用（owning references）和非所有权引用（non-owning references）。所有权引用是对引用计数有贡献。当你调用像 `+new` 或 `-retain` 这样的方法时，你会获得所有权引用。这意味着对象可能被两个地方引用，尽管它的引用计数只有1。临时变量通常是非所有权的。自动引用计数（ARC）和垃圾回收（我们将在本章晚些时候讨论）都引入了特殊的非所有权引用。

## 赋值给实例变量

```
(void)setStringValue:(NSString*)aString {
    id tmp = [aString retain];
    [string release];
    string = tmp;
}
```

*来自：`ivar.m`*

以这种方式使用引用计数时，有几点需要注意。考虑以下简单的设置方法：

```
(void)setStringValue:(NSString*)aString {
    [string release];
    string = [aString retain];
}
```

*来自：`ivar.m`*

这看起来很合理。你释放旧值的引用，然后保留新值并赋值。在大多数情况下，这样做是有效的，但在少数情况下并不有效，调试起来可能会非常困惑。如果 `aString` 和 `string` 的值相同怎么办？在这种情况下，你向同一个对象发送 `arelease` 消息然后是 `retain` 消息。如果其他代码持有该对象的引用，它仍然可以工作；但如果没有，第一条消息会导致对象被销毁，第二条消息将发送给悬指针。

该方法的更正确的实现应该是先保留新对象，正如本节开头所示。注意，你应该分配 `-retain` 消息的结果，因为某些对象在你保留它们时会返回另一个对象。这种情况非常罕，但偶尔会发生。

最后，该方法不是线程安全的。如果你需要一个线程安全的设置方法，你需要保留新值，在结果和实例变量之间执行原子交换操作，然后释放旧值。总的来说，理解支持这种细粒度并发的代码几乎是不可能的，而且它引发的缓存抖动会抵消并行带来的任何性能收益，因此这是一个非常糟糕的主意。如果你真的需要它，使用声明的属性来合成访问器要比自己写要好得多。

### 自动引用计数

如果生命有那么简单就好了。遗憾的是，ARC 有一些局限性。具体来说，它规范了 C 和 Objective-C 的边界。ARC 将指针分为三类。强指针（Strong pointers）遵循我们看过的 retain/release 语义。默认情况下，实例变量或栈上的指针都是强指针。弱指针（Weak pointers，稍后我们会讨论）是在对象销毁时会自动置零。不安全未保留指针（Unsafe unretained pointers）是被 ARC 忽略的指针：你负责跟踪对象的生命周期。结构体中的指针没有默认，它们必须显式标记为 `__unsafe_retained` 修饰符。

### 通过参数返回对象

```objc
weak id weak;
int writeBack(id *aValue) {
    *aValue = [NSObject new];
    weak = *aValue;
    return;
}

int main(void) {
    @autoreleasepool {
        id object;
        writeBack(&object);
        NSLog("Object: %@", object);
        object = nil;
        NSLog("Object: %@", weak);
    }
    return 0;
}
```

来自：`writeback.m`

在 ARC 模式下，指针的指针参数有点复杂。这些通常用于两种情况：传递数组或返回对象。如果你在栈上传递数组，你应该确保将其标记为 `const`。这告诉编译器调用者不会对其进行任何赋值，因此 ARC 可以直接传递指针。

如果你通过这种机制返回对象，ARC 会产生一些复杂的代码。在本节开始的示例中，生成的代码大致如下：

```objc
id tmp = [object retain];
writeBack(&tmp);
[object release];
object = tmp;
```

在 `writeBack()` 中，新对象在存储到 object 之前会被释放。这意味着在结束时，object 包含一个所有权引用。如果你将 object 声明为 `weak id`，生成的代码要简单得多。对于所有指针——即使是自动存储——初始值将为 nil。如果改为将参数标记为 `out`（仅允许方法参数，不允许函数参数），那么调用者保证在调用期间不会读取该值。

如果你需要向栈上传递多个对象，你应该返回一个 `NSArray` 实例。虽然有一些替代方案，但它们足够复杂，完全不值得费精力：它们很容易出错并花费大量时间调试，而且如果你真的写对了，你可能会发现它比使用 `NSArray` 慢。

如果你向下栈传递多个值，应该使用带有显式所有权修饰符的类型而不是指针类型。例如，使用 `__unsafe_retained id` 而不是 `id*`。这确保不使用 ARC 机制。

### 避免保留循环

```objc
(void)setDelegate:(id)aDelegate {
    delegate = aDelegate;
}
```

来自：`ivar.m`

纯引用计数的问题在于它无法检测循环。如果你有两个互相引用的对象，那么它们永远不会被释放。

通常情况下，这不是一个主要问题。Objective-C 数据结构往往是无环的，但在某些常见情况下循环是不可避免的。最常见的是委托模式（delegation pattern）。在这种模式下，一个对象通常实现某些机制并将委托交给另一个对象。大多数 AppKit 都是这样工作的。

代理需要对对象的引用，而对象需要对其代理的引用。这会立即创建一个循环。解决这个问题的常见惯用法是对象不保留它们的代理。如果你将对象作为 `-set:` 方法的参数传递，你需要确保其他对象持有它的引用，否则它会被过早删除。

使用 ARC，你有两个选择：你可以将实例变量标记为 `__weak` 或 `__unsafe_retained`。前者更安全，因为确保了没有悬挂指针的可能性：当代理被销毁时，实例将被设置为 nil。

使用弱指针有两个缺点。第一个是可移植性。弱指针在 iOS 5、Mac OS 10.7 和 GNUstep 上工作，但在旧版本的 iOS 或 Mac OS 上无法工作。另一个缺点是性能。对弱指针的每次访问都会通过一个辅助函数。该函数会检查对象是否正在释放过程中，如果它仍然有效则保留它，如果已失效则返回 nil。

相比之下，不安全未保留指针只是普通的指针。它们的访问成本很廉，并适用于任何部署目标。它们的缺点是，你负责确保在指向的对象被释放后不要尝试访问它们。

一个很好的折中方案是在调试时使用弱指针，而在部署时使用不安全未保留指针。在向其发送任何消息之前添加检查指针是否为空的断言，这样如果你有 bug，就会得到一个有用的错误，而不是崩溃。

如果你在 Xcode 中启动新项目，ARC 将是默认选项，没有理由不使用它。如果你在处理现有代码库，那么你可能正在使用手动引用计数。通过迁移到 ARC，你可以节省一些长期开发工作，但这比简单的切换编译器开关要复杂一点。
