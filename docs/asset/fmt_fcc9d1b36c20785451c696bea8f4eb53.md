
在使用某些拉丁字母变体的国家，最常见的文本编码是 UTF-8。这允许你用一个字节表示任何 ASCII 字符，用两个字节表示大多数其他常见字符。`NSString` 提供了用于方便的方法来获取和设置 UTF-8 编码的数据：`-UTF8String` 和 `+stringWithUTF8String:`。在大多数代码中，每当你与 C 字符串进行转换时，都可以使用这些方法。

要从其他编码的 C 字符串创建字符串对象，你可以使用 `+stringWithCString:encoding:` 方法。

该方法的第一个参数是 C 字符串，第二个参数是表示编码的枚举类型成员。如果数据来自旧的 Mac，你可能想使用 `NSMacOSRomanStringEncoding`，这是在 Mac OS 获得 Unicode 支持之前的默认编码。如果你需要与旧的 Windows 系统相互操作，`WindowsCP1252StringEncoding` 是你在大多数地区需要的编码。较新的 Windows 系统将使用 UTF-16，但它们更偏于小端版本，`UTF16LittleEndianStringEncoding`。

如果你在特定的编码中存储字符串数据，通常会使用 `NSData` 实例而不是指针。这是一个非常简单的类，它封装了一个内存区域：一个指针和一个大小。因为它是一个对象，你可以对它进行内省（introspection），使用引用计数处理销毁，并将其存储在集合中。这使得在许多情况下，它比直接使用指针更方便。

## 拆分字符串

```objc
NSString *str = @"A String with\twords and spaces";
NSArray *wordsWithTab = [str componentsSeparatedByString:@" "];
NSArray *words = [str componentsSeparatedByCharactersInSet:[CharacterSet whitespaceCharacterSet]];
```

来自：`split.m`

在 Objective-C 中拆分字符串有三种方法。第一种是显而易见的：简单遍历字符，直到找到方便的拆分位置，然后使用 `-substringWithRange:` 创建新的标记（token）。这在通用情况下可行，但对于本该轻而易举的事情来说，太费精力了。

在 C 语言中，你可以使用 `strsep()` 函数或已弃用的 `strtok()` 函数在特定集合中字符出现的地方拆分字符串。`NSString` 上的 `-componentsSeparatedByCharactersInSet:` 方法工作原理几乎完全一样，尽管它接受一个 `CharacterSet` 作为参数而不是字符串。

你可以通过使用 `+characterSetWithCharactersInString:` 构建字符集，使该方法的行为得像 `strtok_r()`。该 `NSString` 方法返回一个包含子字符串的 `NSArray`。这与 C 函数的作用原理完全相同；每当有两个相邻的分隔符字符时，你将得到空字符串。

或者，你可以根据特定子字符串的出现来拆分字符串。当分隔符由多个字符组成时，这种方法非常有用。

## 复制字符串

*来自：`stringcopy.m`*

C++ 往往比其应速度慢的地方之一就是处理字符串。在任何纯内存管理的环境中，都倾向于防御性地复制对象以保持清晰的所有权规则。

在 Objective-C 中，这种情况较少见，更多代码面临的是相反的问题：在应该使用副本的地方保留了对可变对象的引用（references）。当你向一个 `NSString` 发送 `-copy` 消息时，它的效果与发送 `-retain` 相同。

你可能会想，为什么我们有两个执行相同操作的方法？答案很简单：`NSMutableString` 是 `NSString` 的子类。如果你向一个 `NSMutableString` 发送 `-retain` 消息，你会增加引用计数。如果你发送 `-copy` 消息，你将得到一个新对象。情况可能比这更复杂，因为某些 `NSMutableString` 的具体子类支持写时复制（copy-on-write）行为，因此你会获得两个引用相同数据的对象，只有当你修改其中一个时，才会创建一个真正的副本。

由于 `NSMutableString` 是 `NSString` 的子类，你可以在任何期望 `NSString` 指针的地方传递 `NSMutableString` 指针。如果你期望一个不可变字符串但得到的是不可变字符串，那么是复制对象还是仅对它建立另一个引用都没有区别。相反，如果你得到的是一个可变字符串，你就不只想保留它的引用，否则可能会导致它在之后被修改。

重要的是，向任何 `NSString` 子类发送 `-copy` 消息将始终返回一个不可变字符串。如果你想要一个可变字符串，必须使用 `-mutableCopy`。

注意：如果你是从 Java 转过来的，请记住 `NSString` 大致相当于 Java 的 `String` 类，而 `NSMutableString` 大致相当于 Java 的 `StringBuffer` 类。Objective-C 没有等同 `final` 关键字，所以 `NSString` 可能（且确实有）子类，你可以在任何可以使用不可变字符串的地方使用可变字符串。

这种模式在 Foundation 框架的多个处可见。大多数具有不可变父类和可变子类的类都会实现 `NSMutableCopying` 协议。向它们的可变或不可变实例发送 `-mutableCopying` 消息将给你一个该可变子类的实例。

## 从模板创建字符串

```objc
int a = 12;
float b = 42.0;
const char *cString = "words";
id object = [NSDictionary new];
NSString *string = [NSString stringWithFormat:"%d, %f, %s, %@", a, b, cString, object];
```

来自：`formatstring.m`

如果你有 C 语言背景，学到的第一个函数之一可能是 `printf()`。这是一个可变函数，接受格式字符串作为第一个参数。格式字符串的内容随后定义了其他参数的类型。

Objective-C 作为 C 的后代，继承了格式字符串的概念。Objective-C 的格式字符串与 C 的格式字符串几乎完全一样，但增加了一点：`%@` 表示匹配的参数是一个对象。

对象预期知道如何描述自己。每个对象都应该响应 `-description` 消息命令，该命令返回一个描述该对象的 `NSString`。许多类从 `NSObject` 继承，它只返回类名和对象在内存中的地址。

**注意：** GNU 调试器 (`gdb`) 对 `-description` 方法有一些内置支持。当你对对象使用 `po` 时，它会调用该 `-description` 方法。这样做要小心，它可能也包含 bug。然而，当它有效时，会非常有帮助。我们将在第 18 章讨论更多调试内容。

你可以使用类似于 `sprintf()` 的可变方法从格式字符串创建 Objective-C 字符串对象。第一个参数是一个包含某些格式规范的 Objective-C 字符串，其余参数是用于替换格式规范的变量。`formatstring.m` 示例展示了如何将格式字符串用于 `NSString`。该示例从参数构建一个字符串，然后将其写入标准错误。注意，我们需要在程序的开头创建一个 `AutoreleasePool`。使用格式字符串会创建一些临时的自动释放（autoreleased）对象。如果你没有自动释放池，将收到关于这些对象泄漏的警告。在这个简单的程序中，它们无论如何都泄漏了。

```objc
int main(int argc, char **argv) {
    [NSAutoreleasePool new];
    MutableString *str = [MutableString stringWithFormat:"%d arguments: %s", argc];
    for (int i=0; i<argc; i++) {
        [str appendFormat:"%s ", argv[i]];
    }
    NSLog("%@", str);
    return 0;
}
```

来自：`formatstring.m`

这个示例首先创建了一个包含传递给程序的参数数量的可变字符串。然后它遍历剩余的参数，将每个（作为 C 字符串）追加到可变字符串中。最后，它将结果传递给 `NSLog()`。

`NSLog()` 函数也使用格式字符串。人们很容易直接将 `str` 作为第一个参数传递。在有人使用带有百分比符号的字符串作为此程序的参数之前，这运行良好。但那时函数将查看第二个参数并尝试解释它。不幸的是，并没有第二个参数，因此它将从寄存器中读取一个随机值。通过传递 `@"%@"`，我们告诉 `NSLog()` 只有一个真实的参数，且它是一个对象。

源自：`regex.m`

使用过 Perl 或 JavaScript 等语言，那么你可能已经习惯了使用正则表达式进行字符串模式匹配。Foundation 框架的最新版本包含了 `NSRegularExpression` 类，它是对 Unicode国际组件（ICU）正则表达式代码的薄封装封装。

该类有一个原始方法，它接受一个 block 作为最后一个参数，并为每个匹配项调用一次。该类中的所有其他方法都是基于该方法实现的。

本节开头的示例展示了使用该类的两种常用方法。它们都从构造该类的实例开始，封装一个简单的正则表达式。为了效率考虑，你应该尝试重用正则表达式对象，而不是每次都从字符串创建它们。当实例被创建时，输入字符串将被解析并转换为状态机，该状态机可以在字符串上快速运行。正则表达式对象是不可变的且线程安全的，因此你可以将常用模式存储在全局变量中，并在多个线程中反复重用它们。

使用正则表达式的第一种方法展示了底层 API。它传递了一个 block，该 block 为每个匹配项调用一次。这个简单的示例打印了每个匹配项在字符串中的位置。

高层 API 则为你执行了替换工作。它有两种形式：一种接受一个 `NSString` 并返回一个带有替换结果的新副本；另一种接受一个 `NSMutableString` 并在原地进行替换。

请注意，用于替换的模板并不是一个简单的字符串。它可以包含对原始正则表达式部分的引用，使用你在正则表达式其他地方中使用的 `$n` 语法。

## 操作集合

与我们看过的其他内容一样，Objective-C 中有两种集合：面向对象的版本和原始 C 类型。前者一如既往地是构建在后者之上的。

在 C 语言中，有两种复合数据类型：数组和结构体。数组只是包含相同类型数据的内存块。结构体具有固定的布局，并可能包含不同类型的元素。

C 复合类型是指针运算上层非常薄的语法糖。当你访问数组中的元素时，编译器会将数组索引乘以单个元素的大小，并将结果加到数组的起始指针上。当你访问结构体中的元素时，编译器会向结构体的起始指针添加一个固定偏移量。

### 第 7 章：操作集合

Objective-C 集合是更高级的构造。每个 Objective-C 集合与 Objective-C 添加的大多数其他功能一样，都是对象。你通过向它们发送消息来与其通信。

Foundation 框架包含了许多集合类，用于存储有序和无序数据，以及映射或索引集。Objective-C 中的大多数集合类都存储对象。与 C++ STL 集合（需要根据其可能包含的类型进行细化）不同，Objective-C 集合是异质的。它们可以存储任何类型的 Objective-C 对象。

大多数 Objective-C 集合（如字符串）使用*可变子类模式*，即基类实现不可变集合的行为，而子类提供一个可变版本。

所有遵循此模式的类都实现了 `NSMutableCopying` 协议，这意味着你可以向集合发送 `-mutableCopy` 消息并获得一个可变的副本，即使原始对象不可变。

大多数集合也是*类簇（clusters）*。当你创建一个集合时，你将得到一些私有的抽象子类。公共类通常是抽象的。用户友型方法都是基于少数几个原始方法实现的。如果你创建自己的子类，将需要自己实现这些方法。
