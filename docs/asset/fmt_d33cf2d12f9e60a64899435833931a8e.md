## 指针：指向同一个地址

这是 C 语言中非常酷的一个特性：任意数量的指针可以指向同一个地址。例如，你可以将 `p`、`q` 和 `r` 声明为整数指针，并将它们都指向 `i`，如下：

```c
int i;
int *p, *q, *r;

p = &i;
q = &i;
r = p;
```

注意，在这段代码中，`r` 指向与 `p` 指向相同的地方，即 `i`。你可以将指针相互赋值，在赋值过程中，地址从右侧复制到左侧。变量 `i` 现在有四个名字：`i`、`*p`、`*q` 和 `*r`。持有（因此指向）相同地址的指针数量没有限制。

## 指针：常见错误

### 错误 #1 - 未初始化的指针

创建指针错误的最简单方法之一是尝试引用指针的值，即使该指针尚未初始化且尚未指向有效的地址。例如：

```c
int *p;
*p = 12;
```

指针 `p` 在你声明它时是未初始化的，并且指向内存中的一个随机位置。它可能指向系统栈、全局变量、程序代码空间或操作系统。当你说 `*p = 12;` 时，程序将简单地尝试向 `p` 指向的任何随机位置写入 12。程序可能会立即崩溃，或者等待半小时后才崩溃，也可能会损坏程序中其他部分的数据，而你可能永远无法察觉。这使得这种错误非常难以追踪。在解引用指针之前，请确保将指针初始化为有效地址。

### 错误 #2 - 无效的指针引用

当引用指针的值，但该指针并没有指向有效的内存块时，就会发生无效的指针引用。

创建此错误的一种方法是在 `q` 未初始化时说 `p = q;`。此时，指针 `p` 也会变成未初始化状态，对 `*p` 的任何引用都是无效的指针引用。

避免此问题的唯一方法是为程序的每一步画图，并确保所有指针都指向某个地方。无效的指针引用会导致程序由于错误 #1 中提到的相同原因莫名其妙的崩溃。

### 错误 #3 - 零指针引用

当指向 0 的指针被用于尝试引用内存块的语句时，就会发生零指针引用。例如，如果 `p` 是指向整数的指针，以下代码是无效的：

```c
p = 0;
*p = 12;
```

`p` 没有指向任何内存块。因此，尝试对该块进行任何读取或写入都是无效的指针引用。正如我们将在随后的文章中看到的，将指针指向 0 有充分且合法的理由。然而，解引用这样的指针是无效的。

所有这些错误对于包含它们的程序来说都是致命的。你必须监控你的代码，以防止这些错误的发生。做到点的最好方法是逐步绘制代码执行执行图。

## 使用指针作为函数参数

大多数程序员首先使用指针来实现函数中所谓的“可变参数”。你实际上已经在 `scanf` 函数在使用可变参数了——这就是为什么你在配合 `scanf` 使用变量时必须使用 `&`（地址操作符）。现在你理解了指针，就可以看到实际上发生了什么了。

要理解可变参数是如何工作的，让我们看看如何在 C 中实现一个 `swap`（交换）函数。要实现一个 `swap` 函数，你想传入两个变量并让函数交换它们的值。这里有一个实现尝试——输入并执行以下代码，看看发生了什么：

```c
#include <stdio.h>

void swap(int i, int j)
{
    int t;

    t = i;
    i = j;
    j = t;
}

void main(void)
{
    int a, b;
    a = 5;
    b = 10;
    printf("%d %d\n", a, b);
    swap(a, b);
    printf("%d %d\n", a, b);
}
```

当你执行这个程序时，你会发现交换确实发生了。`a` 和 `b` 的值被传递给了 `swap`，`swap` 函数确实交换了它们，但当函数返回时，什么都没有发生。

要让这个函数正常工作，你可以使用指针，如下所示：

```c
#include <stdio.h>

void swap(int *i, int *j)
{
    int t;
    t = *i;
    *i = *j;
    *j = t;
}

void main(void)
{
    int a, b;
    a = 5;
    b = 10;
    printf("%d %d\n", a, b);
    swap(&a, &b);
    printf("%d %d\n", a, b);
}
```

为了直观理解这段代码的作用，将其打印出来，画出整数 `a` 和 `b`，并在它们输入 5 和 10。现在画出两个指针 `i` 和 `j`，以及整数 `t`。

# 第 12 章 动态数据结构 MALLOC 和 FREE

```c
if (p == 0)
{
    printf("ERROR: Out of memory\n");
    return 1;
}
*p = 5;
printf("%d\n", *p);
free(p);
return 0;
```

该程序的第一行调用了 `malloc` 函数。该函数执行了三件事：

1. `malloc` 语句首先查看堆 `heap` 上可用内存量，并询问：“是否有足够的内存来分配请求大小的块？”该块所需的内存量通过传递给 `malloc` 的参数已知——在这种情况下是 4 字节。如果没有足够的可用内存，`malloc` 函数返回地址零表示错误（零的另一个名称是 `NULL`，你会在 C 代码中到处看到它）。否则，`malloc` 继续执行。
2. 如果堆上有可用内存，系统将从堆中“分配”或“预留”一个指定大小的块。系统预留该块内存，以防止它被多个 `malloc` 语句意外使用。
3. 系统随后将预留块的地址放入指针变量（本例中为 `p`）中。指针变量本身包含分配块可以持有指定类型的值，且指针指向它。

程序接下来通过 `if (p == 0)` 这一行检查指针，以确保分配请求成功（该行也可以写成 `if (p == NULL)` 甚至 `if (!p)`）。如果分配失败（如果 `p` 为零），程序将终止。如果分配成功，程序随后将该块初始化为值 5，打印该值，并在程序终止前调用 `free` 函数将内存返回给堆。

这段代码与之前将 `p` 赋值为现有整数 `i` 的地址的代码之间真的没有区别。唯一的区别在于，在变量 `i` 的情况下，内存作为程序预留内存空间的一部分存在，并有两个名称：`i` 和 `*p`。在从堆上分配内存的情况下，该块只有一个名称 `*p`，并且是在程序执行期间分配的。有两个常见问题：

- 在每次分配后检查指针是否为零真的重要吗？是的。堆的大小不断变化，取决于运行哪些程序、它们分配了多少内存等，没有任何保证能确保 `malloc` 成功。你应该在每次调用 `malloc` 后检查指针，以确保指针是有效的。
- 如果我在程序终止前忘记删除内存块会发生什么？当程序终止时，操作系统会对其进行清理，释放其可执行代码空间、栈、全局内存空间以及任何堆分配以供回收。因此，在程序终止时留下悬挂的分配不会产生长期后果。然而，这被认为是一种不规范，而且程序执行期间的“内存泄漏”是有害的，正如下面讨论的那样。

这两个程序展示了指针的不同有效用法，并尝试区分指针的使用与指针值的区别：

```c
void main() {
    int *p, *q;

    p = (int *)malloc(sizeof(int));
    q = p;
    *p = 10;
    printf("%d\n", *q);
    *q = 20;
    printf("%d\n", *q);
}
```

这段代码的最终输出将是第 4 行的 10 和第 6 行的 20。

以下代码略有不同：

```c
void main(void)
{
    int *p, *q;

    p = (int *)malloc(sizeof(int));
    q = (int *)malloc(sizeof(int));
    *p = 10;
    *q = 20;
    *p = *q;
    printf("%d\n", *p);
}
```

这段代码的最终输出将是 `*p = *q`，第 6 行的 20。

注意，编译器允许 `*p = *q`，因为 `p` 和 `*q` 都是整数。这条语句的意思是：“将 `q` 指向的值移动到 `p` 指向的整数值中。”这条语句移动的是值。编译器也会允许 `p = q`，因为 `p` 和 `q` 都是指针，且都指向相同类型（如果 `s` 是指向字符的指针，则不允许 `p = s`，因为它们指向不同类型）。语句 `p = q` 的意思是：“让 `p` 指向 `q` 所指向的同一个内存块。” 换句话说，`q` 指向的地址被移动到了 `p` 中，因此它们都指向同一个块。这条语句移动的是地址。

从所有这些示例中，你可以看到初始化指针有四种方法。当指针被声明为 `int *p` 时，它在程序启动时处于未初始化状态。它可能指向任何地方，因此对其解引用是一个错误。初始化指针变量涉及将其指向内存中的一个已知位置。

1. 方法一种如前所示，使用 `malloc` 语句。该语句从堆上分配一块内存，然后指针指向该块。这初始化了指针，因为它现在指向了一个已知位置。指针被初始化，因为它被填充了一个有效地址——新块的地址。
2. 第二种方法正如刚才所示，使用如 `p = q` 的语句，使 `p` 指向与 `q` 相同的地方。如果 `q` 指向一个有效块，那么 `p` 就被初始化了。指针 `p` 加载了 `q` 的有效地址。然而，如果 `q` 未初始化或无效，`p` 将同样的无用地址。
3. 第三种方法是将指针指向已知地址，例如全局变量的地址。例如，如果 `i` 是整数而 `p` 是指向整数的指针，那么语句 `p = &i` 通过指向 `i` 来初始化 `p`。
4. 第四种初始化指针的方法是使用零值。零是与指针使用的特殊值，如下：

```c
p = 0;
```

或：

```c
p = NULL;
```

这在物理上的作用是将零放入 `p` 中。指针 `p` 的地址为零。

任何指针都可以设置为零。但是，当 `p` 指向零时，它并不指向任何块。指针仅仅包含零。

```c
int main(void)
{
    struct rec *p;
    p=(struct rec *) malloc(sizeof(struct rec));
    (*p).i=10;
    (*p).f=3.14;
    (*p).c='a';
    printf("%d %f %c\n",(*p).i,(*p).f,(*p).c);
    free(p);
    return 0;
}
```

注意以下行：

```
(*p).i=10;
```

许多人奇奇为什么下面的写法不起：

```
(*p).i=10;
```

答案与 C 语言中运算符的优先级有关。计算 5+3*4 的结果是 17 而不是 32，因为在大多数计算机语言中，`*` 运算符的优先级高于 `+`。在 C 中，运算符的优先级高于 `*`，所以括号强制了正确的优先级。

大多数人都厌倦了总是输入 `(*p).i`，因此 C 了一种了一种简写符号。以下两个语句完全等价，但第二种更容易输入：

```
(*p).i=10;
p->i=10;
```

在阅读他人的代码时，你看到的第二种会比第一种多。
