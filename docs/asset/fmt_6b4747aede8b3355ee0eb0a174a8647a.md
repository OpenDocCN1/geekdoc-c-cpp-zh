## 部署 Web 应用程序和 Web 站点

要部署 ASP.NET Web 应用程序或 ASP.NET Web 站点，您需要将应用程序或 Web 站点托管在 Web 服务器上。 要部署 Web 应用程序或 Web 站点，您需要将应用程序的文件从源服务器复制到目标服务器或 Web 服务器。 此外，您需要在目标服务器上执行以下附加任务：

- 对 `Web.config` 文件进行更改，例如调试设置或数据库连接字符串
- 在目标计算机上配置 Internet Information Services (`IIS`) 设置
- 安装安全证书
- 设置目标计算机注册表中的值
- 在目标计算机的 GAC 上安装应用程序程序集

Visual Studio 2010 使您能够通过执行以下任务将 Web 应用程序或 Web 站点部署到目标服务器：

- 创建 Web 部署包
- 使用一键发布功能
- 转换 `Web.config` 文件
- 部署 SQL Server 数据库
- 使用 Copy Web Site 工具

### 创建 Web 部署包

Web 应用程序项目可以通过创建 Web 部署包并在目标服务器上安装该包来部署。 Web 部署包是一个压缩的 `.zip` 文件，存储以下信息：

- **IIS 设置** – 包括应用程序池、身份验证方法和错误处理
- **数据库脚本** – 执行数据库及其结构的更改
- **调试和连接字符串参数** – 包含在安装包时可能需要更改的值

除了上述信息外，`.zip` 文件可能还包括安全证书、Windows 注册表设置以及安装在目标计算机 GAC 上的程序集。

### 转换 Web.config 文件

`Web.config` 是一个 XML 文档，其中包含 ASP.NET Web 应用程序的设置。 它包含控件模块加载、安全配置、会话状态配置、应用程序语言和编译设置的信息。 `Web.config` 文件还可以包含应用程序特定项，例如数据库连接字符串。 当您将 Web 应用程序部署到不同的计算机时，您可能需要更改以下设置：

- 更改指向生产数据库的数据库连接字符串
- 禁用调试
- 删除敏感信息，例如当您必须向社区站点提供包时连接代码

设置上述设置的解决方案之一是手动管理 `Web.config` 文件中的更改，通过执行以下任务：

- 每次部署项目时修改目标服务器上的 `Web.config` 文件
- 为每个环境设置创建和维护多个版本的 `Web.config` 文件（在单独的文件夹中或使用不同的名称），并根据条件使用最合适的版本
- 创建 XSLT 文件以转换 `Web.config` 文件，并在项目部署时应用它们。

现在在 Visual Studio 2010 中，ASP.NET 提供了工具来自动化在部署 Web 项目时转换 `Web.config` 文件的过程。 对于您想要部署 Web 应用程序的每个环境，您需要创建一个转换文件，该文件指定 `Web.config` 文件在每个环境基础上的设置。

转换文件包括目标环境的名称，以前缀节点 `Web` 和后缀节点 `Config` 为前缀。 例如，Debug 构建配置的转换文件是 `Web.Debug.Config`。 转换文件是一个 XML 文件，使用 XML 属性指定应如何更改 `Web.config` 文件。 请考虑以下代码片段：

```
<connectionStrings>
  <add name="WebApplicationServices"
       connectionString="[ProductionDatabase]" />
</connectionStrings>
```

在前面的代码片段中，转换文件指定连接字符串 `WebApplicationServices` 将在 Web 应用程序部署到目标服务器时转换为生产数据库。 现在，请考虑以下代码片段：

```
<?xml version="1.0"?>
<configuration xmlns:xdt="http://schemas.microsoft.com/XML-Document-Transform">
  <connectionStrings>
    <add name="WebApplicationServices"
         connectionString="[ProductionDatabase]"
         xdt:Transform="Replace" xdt:Locator="Match(name)"/>
  </connectionStrings>
</configuration>
```

在前面的代码片段中，`Locator` 属性指定只有具有与 `WebApplicationServices` 相同名称的 `add` 元素才应被更改。 而 `Transform` 属性指定部署过程应替换整个 `add` 元素。

### 部署 SQL Server 数据库

在 Visual Studio 2010 中，您还可以通过创建脚本文件（`.sql` 文件）部署使用 SQL Server 数据库来存储和维护与应用程序相关的数据的 Web 应用程序。 您可以创建自定义 `.sql` 脚本文件并指定脚本应在目标服务器上运行的顺序，然后将此脚本文件添加到 Web 包中。 当 Web 包安装在目标服务器上时，它会运行脚本文件并在服务器上创建相同的数据库。

您在项目属性窗口的 Package/Publish SQL 选项卡中指定 SQL Server 数据库脚本选项。 您可以通过在解决方案资源管理器中右键单击项目名称来访问项目属性窗口

## Using the Copy Web Site Tool

Copy Web Site 工具用于直接用先前的网站替换目标服务器上的最终网站。这意味着你可以打开目标服务器上的一个文件夹，然后从源网站上传和下载文件到目标网站。Copy Web Site 工具同步两个网站中的文件并保持网站使用更新后的文件。

当应用程序文件从源网站复制到目标网站时，Copy Web Site 工具会在目标网站的根目录中创建一个名为 `App_offline.htm` 的文件。只要 `App_offline.htm` 文件存在，所有对网站的请求都会重定向到该文件。`App_offline.htm` 文件向客户端显示网站正在更新的消息。复制完应用程序文件后，Copy Web Site 工具会从目标网站删除 `App_offline.htm` 文件。

Copy Web Site 工具的一些功能如下：

- 你可以从源服务器复制 `.aspx` 和类文件到目标服务器。
- 你可以打开并复制任何类型的网站的文件，例如 Visual Studio 2010 支持的本地 IIS、远程 IIS 和文件传输协议（FTP）。
- Copy Web Site 工具的同步功能会自动检查两个网站的文件并保持它们为文件的最新版本。
