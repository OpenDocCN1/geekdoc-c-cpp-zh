## 如何指定 Medicare FFS 连续投保的编程

根据您的项目需求，“连续投保”有许多不同的定义方式；它仅仅是一项业务规则。我们将连续投保定义如下：如果受益人在 2010 年内仍然世、在该年内的任何时候都没有参加过管理型医疗，且全年都参加了 Medicare A 和 B 部分，则被认为在 2010 年全年在 Medicare FFS 中连续投保。完成这项任务需要理解并使用主受益摘要文件（Master Beneficiary Summary File, MBSF）中的以下变量，本章将在剩余部分进行详细解释：

- 医院保险（Part A）和补充医疗保险（Part B）覆盖变量
- HMO 覆盖变量
- 死亡日期变量

### Medicare A 部分和 B 部分的投保变量

Medicare A 部分和 B 部分的投保变量（`BENE_HI_CVRAGE_TOT_MONS` 和 `BENE_SMI_CVRAGE_TOT_MONS`）描述了人参加 A 部分和 B 部分的月份。这些变量有时被称为简称为 `A_CNT` 和 `MO_CNT`。确定投保情况是非常重要的，因为受益人在某段时间内未参加 Medicare A 部分或 B 部分时接受的服务将不会包含在索赔文件中。因此，对利用率等描述的扭曲可能会导致允许的覆盖范围内出现缺口。

检查 MBSF 的数据字典，我们只想保留每个值为 12 的受益人，这表示该受益人在全年的 12 个月内都参加了 A 部分和 B 部分。我们不想保留 `HI_CVRAGE_TOT_MONS` 变量或 `SMI_CVRAGE_TOT_MONS` 变量值小于 12 的受益人，因为我们已经声明过，只想保留那些在 2010 年全年都参加了 Medicare A 部分和 B 部分的受益人。

### HMO 覆盖变量

HMO 覆盖变量（`BENE_HMO_CVRAGE_TOT_MONS`）描述了受益人在全年参加管理型医疗计划（也称为健康维护组织或 HMO）的月份。如上所述，Medicare Part C 允许 Medicare 受益人参加私人管理型医疗计划，而不是参与传统的 Medicare FFS。通常，这些管理型医疗计划的受益人类别不会出现在行政索赔数据中，因此我们试图从研究人群中排除这些受益人。再次快速检查 MBSF 数据字典显示，我们只想保留 `BENE_HMO_CVRAGE_TOT_MONS` 变量值为 0 的受益人。

### 死亡日期变量

死亡日期变量（`DEATH_DT`）描述受益人去世的日期。我们只想保留 2010 年生存的受益人。尽管我们不会使用它，但可以使用有效死亡日期开关（`V_DOD_SW`）来确认死亡日期；此变量表示受益人的死亡日期已由社会安全局确认准确。¹在这种情况下，我们将选择将人群限制在 `DEATH_DT` 变量等于缺失（missing）的记录上，这表示没有可死亡日期。

## 如何在 SAS 中编程以定义 Medicare FBS 的连续投保

现在我们已经指定了如何定义连续投保，就可以编写代码了。SAS 的伟大之处在于完成单一任务有许多许多不同的方法，而且实际上没有对错之分（只要不同的方法提供了相同且正确的答案即可）。也就是说，在使用可能非常大的 Medicare 数据集时，我们关注的是效率。养成尽可能减少读取和写入的习惯是非常重要的。因此，我们将尝试在尽可能少的 `DATA` 步骤中完成上述列的任务，同时创建（希望）从教学角度来看有用的代码。此外，我们将通过检查输出并尝试复制结果，迈出代码质量保证的第一步。

我将介绍以下方法，用以识别并保留在 Medicare FBS 中连续投保的受益人。首先，在步骤 6.1 中，我们执行一个简单的数据步骤，标记那些在 Medicare A 和 B 部分中连续投保的人。具体来说，我们创建了一个名为 `CONTENTRL_2010` 的变量，如果 `BENE_HI_CVRAGE_TOT_MONS` 和 `BENE_SMI_CVRAGE_TOT_MONS` 的值均等于 12，则设置为 ‘AB’，表示该受益人在全年的 12 个月内参加了 Medicare A 部分和 B 部分。通过这种方式，我们创建了一个名为 `CONTENTRL_HMO_2010` 的变量，如果 `BENE_HMO_CVRAGE_TOT_MONS` 的值等于 0，则设置为 ‘NHMO’，表示该受益人在一年内的任何时候都没有参加过 HMO。最后，我们创建了一个名为 `DEATH_2010` 的变量，如果 `DEATH_DT` 的值为空（null），则设置为 0，表示该受益人在 12 个月内仍然世。

```sas
* STEP 6.1: 在 2010 MOBS 文件中构建连续投保信息
 */
data contentrl_2010;
    set src.mbsf_2010;
    length contentrl_ab_2010 contentrl_hmo_2010 $5;
    /* 标记参加 A 和 B 部分或 HMO 覆盖的人 */
    if bene_hi_cvrage_tot_mons=12 and bene_smi_cvrage_tot_mons=12 then
    contentrl_ab_2010='ab'; else contentrl_ab_2010='noab';
    if bene_hmo_cvrage_tot_mons=12 then contentrl_hmo_2010='hmo'; else
    contentrl_hmo_2010='nohmo';
;
```

```sas
/* 标记在 2010 年去世的人 */
death_dt ne . then death_2010=1; else death_2010=0;
run;
```

## 算法：根据某些特征保留数据元素

除了将我们的人群限制为在 2010 年连续投保的人之外，我们必须创建标记，以便在后续章节中按以下特征显示结果：

- 2010 年 Medicare 覆盖特征
- 性别
- 种族
- 年龄组（65岁以下、65-74岁、75-84岁、85-94岁和95岁及以上）
- 受益人地理信息，通过为每个受益人分配 SSA 州代码以及相应的州县名称来定义

### 覆盖特征、月份、性别和种族

我们的数据集是连续投保练习的输出，`ENR_CONTENTOR_2010_FNL`。我们不需要创建单独标记来定义投保特征，因为我们可以直接使用步骤 6.2 创建的变量。此外，不需要进行任何编程来创建包含性别或种族信息的变量；MBSF 文件提供的 `SEX` 和 `RACE` 变量符合我们的需求。在步骤 6.4 中，我们简单地探索包含的信息

使用频率分布的性别和种族变量。请注意，我们使用了 `PROC FORMAT`，因此性别和种族变量的定义将显示在我们的输出中。我们使用 SAS 输出交付系统（ODS）来创建输出。

```sas
* STEP 6.4: 对 2010 年数据中的性别和种族进行初步调查 */
proc format;
  value $sex_cats_fmt
    '0'='UNKNOWN'
    '1'='MALE'
    '2'='FEMALE';
run;
ods html file="C:\Users\mgillingham\Desktop\SAS Book\FINAL_DATA_ODS_OUTPUT\mgillingham_fig6_4_RACE.html"
  image_dpi=300 style=GrayscalePrinter;
ods graphics on;
title "2010 年数据中性别的频率";
proc freq data=enr.contr_2010_fnl;
  tables sex / missing;
  format sex $sex_cats_fmt.;
run;
ods html close;
proc format;
  value $race_cats_fmt
    '0'='UNKNOWN'
    '1'='WHITE'
    '2'='BLACK'
    '3'='OTHER'
    '4'='ASIAN'
    '5'='HISPANIC'
    '6'='NORTH AMERICAN NATIVE';
run;
ods html file="C:\Users\mgillingham\Desktop\SAS Book\FINAL_DATA_ODS_OUTPUT\mgillingham_fig6_4_RACE.html"
  image_dpi=300 style=GrayscalePrinter;
ods graphics on;
title "2010 年数据中种族的频率";
proc freq data=enr.contr_2010_fnl;
  tables race / missing;
  format race $race_cats_fmt.;
run;
ods html close;
```
