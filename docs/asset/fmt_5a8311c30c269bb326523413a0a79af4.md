
如果信号发生到一个到一个声明为 `volatile sig_atomic_t` 的对象，其行为是未定义的（sup>251</sup>）。

> 251) 这包括通过标准库函数间接调用的函数（例如通过 `abort` 函数调用的 SIGRT 处理器）。

如果信号不是调用 `abort` 或 `raise` 函数的结果，信号处理器调用标准库中除 `abort` 函数、`_Exit` 函数、`quick_exit` 函数以及第一个参数等于信号值的 `signal` 函数以外的任何函数。此外，如果信号函数返回 `SIG_ERR`，**errno** 的值是不确定的（sup>252</sup>）。

> 252) 如果由异步信号处理器产生信号，其行为是未定义的。

6 在程序启动时，可以以实现方式执行 `signal(sig, SIG_IGN)` 以处理某些信号；执行 `signal(sig, SIG_DFL)` 以处理实现定义的所有其他信号。

7 在多线程程序中使用此函数会导致未定义行为。实现的行为应为没有库函数调用 `signal` 函数。

### 返回

如果请求可以被接受，信号函数返回最近一次成功调用指定信号 **sig** 的 `func` 值。否则，返回 `SIG_ERR` 并在 `errno` 中存储一个正值。

前向引用：`abort` 函数 (7.22.4.1)、`exit` 函数 (7.22.4.4)、`_Exit` 函数 (7.22.4.5)、`quick_exit` 函数 (7.22.4.7)。

## 7.16 变长参数 <stdarg.h>

头文件 `<stdarg.h>` 声明了一个类型并定义了四个宏，用于遍历参数列表，该列表的名称和类型在翻译时对被调用函数是未知的。

函数可以带有不同数量、不同类型的参数进行调用。正如 6.9.1 节所述，其参数列表包含一个或多个参数。最右侧的参数在访问机制中起着特殊作用，在本描述中被指定为 `paramN`。

声明的类型是

```
va_list
```

这是一个完整的对象类型，适用于存储宏 `va_start`、`va_arg`、`va_end` 和 `va_copy` 所的信息。如果需要访问变长参数，被调用函数应声明一个类型为 `va_list` 的对象（在本节中泛称为 `ap`）。对象 `ap` 可以作为参数传递给另一个函数；如果该函数使用参数 `ap` 调用 `va_arg` 宏，则调用函数中 `ap` 的值将是不定的，并且在再次引用 `ap` 之前应将其传递给 `va_end` 宏。(253)

> 253 允许创建一个指向 `va_list` 的指针并传递给另一个函数，在这种情况下，原函数可以在另一个函数返回后使用原始列表。

### 7.16.1 变长参数列表访问宏

在本节描述的 `va_start` 和 `va_arg` 宏应实现为宏，而不是函数。`va_copy` 和 `va_arg` 是宏还是具有外部链接的声明标识符未指定。如果为了访问实际函数而抑制了宏定义，或者程序定义了同名的外部标识符，则行为是未定义的。每次调用 `va_start` 和 `va_copy` 宏都应与同一函数中相应的 `va_end` 宏调用相匹配。

### 7.16.1.1 va_arg 宏

#### 摘要

```
#include <stdarg.h>
type va_arg(va_list ap, type);
```

## 描述

`va_arg` 宏展开为具有指定类型且值为调用中下一个参数的表达式。参数 `ap` 应该已经由 `va_start` 或 `va_copy` 宏初始化（在此期间没有对同一个 `ap` 调用过 `va_end` 宏）。每次调用 `va_arg` 宏都会修改 `ap`，使得连续参数的值被返回。参数类型应指定为某种类型，使得通过在 `type` 后后跟 `*` 就可以获得指向对象的指针类型为该指定类型。如果没有实际参数，或者 `type` 与实际参数的类型不兼容（根据默认参数提升进行提升），则行为是未定义的，但以下情况除外：

- 一个类型是有符号的整数类型，另一个类型是对应的无符号整数类型，且该值在两种类型中均可表示；

- 一个类型是指向 void 的指针，另一个是指向字符类型的指针。

#### 返回

在 `va_start` 宏之后的第一次调用 `va_arg` 宏返回 `parmN` 指定之后的参数的值。随后的调用按顺序返回剩余参数的值。

### 7.16.1.2 va_copy 宏

#### 摘要

```
#include <stdarg.h>
void va_copy(va_list dest, va_list src);
```

## 描述

`va_copy` 宏将 `dest` 初始化为 `src` 的拷贝，就像对 `src` 调用了 `va_start` 宏（在此期间没有对同一个 `src` 调用过 `va_end` 宏）。

#### 返回

（无）

### 7.16.1.3 va_end 宏

#### 摘要

```
#include <stdarg.h>
void va_end(va_list ap);
```

## 描述

`va_end` 宏展开为一个表达式，其类型为 `void`。参数 `ap` 应该已经由 `va_start` 或 `va_copy` 宏初始化（在此期间没有对同一个 `ap` 调用过 `va_arg` 宏）。每次调用 `va_end` 宏都应与同一函数中相应的 `va_start` 或 `va_copy` 调用相匹配。

#### 返回

（无）

不以 `_explicit` 结尾的函数与对应的 `memory_order` 参数为 `memory_order_seq_cst` 的对应函数具有相同的语义。

注意：许多操作是 `volatile` 限定的。“volatile 作为设备寄存器”的语义在标准中没有改变。这种限定意味着在对 `volatile` 对象应用操作时，易变性会被保留。

## 7.17.3 顺序与一致性

1 枚举类型 `memory_order` 指定了 5.1.2.4 中定义的常规（非原子）内存同步操作，并可能提供操作排序。其枚举常量如下：

```
memory_order_relaxed
memory_order_consume
memory_order_acquire
memory_order_release
memory_order_acq_rel
memory_order_seq_cst
```

2 对于 `memory_order_relaxed`，没有操作会内存内存。

3 对于 `memory_order_release`、`memory_order_acq_rel` 和 `memory_order_seq_cst`，存储操作对影响的内存位置执行释放（release）操作。

4 对于 `memory_order_acquire`、`memory_order_acq_rel` 和 `memory_order_seq_cst`，加载操作对影响的内存位置执行获取（acquire）操作。

5 对于 `memory_order_consume`，加载操作对影响的内存位置执行消费（consume）操作。

6 所有 `memory_order_seq_cst` 操作上存在一个单一全序 `S`，它与所有影响位置的“发生于”顺序和修改顺序一致，使得每个 `memory_order_seq_cst` 操作 `B` 从原子对象 `M` 加载的值观测到以下值之一：

- 如果 `M` 的最后一次修改 `A` 在 `S` 中先于 `B`（如果存在的话），或者

- 如果 `A` 存在，则 `M` 在相对于 `B` 的可见侧效应序列中的某次修改的结果，该修改不是 `memory_order_seq_cst` 且不发生于 `A` ，或者

- 如果 `A` 不存在，则 `M` 在相对于 `B` 的可见侧效应序列中的某次修改的结果不是 `memory_order_seq_cst`。

注意 1 虽然不要求 `S` 包含锁锁操作，但它始终可以扩展为包含加锁和解锁操作的顺序，因为之前的排序已经包含在“发生于”顺序中。

注意 2 指定 `memory_order_relaxed` 的原子操作仅在内存排序方面是松弛的。实现必须确保对特定对象的任何给定访问相对于其他原子访问都是不可分割的。

对于原子操作 `B` 读取原子对象 `M` 的值，如果存在 `memory_order_seq_cst` 屏障 `X` 在 `B` 之前，则 `B` 观测到 `S` 中先于 `X` 的 `M` 的最后修改。

对于原子操作 `A` 和 `B` 作用于原子对象 `M`，如果 `A` 修改 `M` 且 `B` 取其值，且存在 `memory_order_seq_cst` 屏障 `X` 使得 `A` 先于 `X` 且 `B` 后于 `X`，则 `B` 观测到修改顺序中 `M` 的后续修改。

对于原子操作 `A` 和 `B` 作用于原子对象 `M`，如果 `A` 修改 `M` 且 `B` 取其值，且存在 `memory_order_seq_cst` 屏障 `X` 和 `Y` 使得 `A` 先于 `X`，`Y` 先于 `B` 且 `X` 先于 `Y`，则 `B` 观测到修改顺序中 `M` 的后续修改。

原子读-写操作总是读取与读-写操作写入之前的（修改顺序中的）值。

原子存储应仅存储由有限评估序列从常量和程序输入计算出的，其中每次评估观测到序列中最后赋值变量的值。该序列的排序应为：

- 如果评估 `B` 观测到不同线程中 `A` 计算的值，则 `B` 不发生于 `A`。

- 如果序列包含评估 `A`，则所有赋值给同一变量且发生于 `A` 的评估也被包含在内。

注意 3 使用松弛原子时，第二个要求允许“凭空产生”（out of air）或“预测性”的原子存储。由于涉及无序操作，评估可能会无序出现。其中，原子变量不会退化。例如，`x` 和 `y` 初始为零：

```
// 线程 1:
r1 = atomic_load_explicit(&y, memory_order_relaxed);
atomic_store_explicit(&x, memory_order_relaxed);
```

```
// 线程 2:
r2 = atomic_load_explicit(&x, memory_order_relaxed);
atomic_store_explicit(&y, 42, memory_order_relaxed);
```

允许产生 `r1 == 42` 且 `r2 == 42`。证明此点的评估序列由：

```
atomic_store_explicit(&y, 42, memory_order_relaxed);
r1 = atomic_load_explicit(&y, memory_order_relaxed);
atomic_store_explicit(&x, r1, memory_order_relaxed);
r2 = atomic_store_explicit(&x, memory_order_relaxed);
```

另一方面，

```
// 线程 1:
r1 = atomic_load_explicit(&y, memory_order_relaxed);
atomic_store_explicit(&x, r1, memory_order_relaxed);
```

```
// 线程 2:
r2 = atomic_load_explicit(&x, memory_order_relaxed);
atomic_store_explicit(&y, r2, memory_order_relaxed);
```

不允许产生 `r1 == 42` 且 `r2 == 42`，因为不存在计算 42 的评估序列。在不存在“松弛”操作和弱于 `memory_order_acq_rel` 的读-写操作的情况下，第二个要求没有影响。

推荐实践

要求并不禁止在示例中产生 `r1 == 42` 且 `r2 == 42`，`x` 和 `y` 初始为零：

```
// 线程 1:
r1 = atomic_load_explicit(&x, memory_order_relaxed);
if (r1 == 42)
    atomic_store_explicit(&y, r1, memory_order_relaxed);
```

```
// 线程 2:
r2 = atomic_load_explicit(&y, memory_order_relaxed);
if (r2 == 42)
    atomic_store_explicit(&x, 42, memory_order_relaxed);
```

然而，这不是有用行为，实现不应允许这种情况。

实现应在合理时间内完成对原子加载的原子存储。

## 7.17.4 屏障 (Fences)

此子句引入了称为屏障的同步原语。屏障可以具有获取语义、释放语义或两者具有。具有获取语义的屏障称为获取屏障；具有释放语义的屏障称为释放屏障。

释放屏障 `A` 与获取屏障 `B` 同步，如果存在作用于原子对象 `M` 的原子操作 `X` 和 `Y`，使得 `A` 先于 `X`，`X` 修改了 `M`，`Y` 先于 `B`，且 `Y` 读取 `X` 写入的值或假设 `X` 为释放操作时引导的释放序列中任何侧效应写入的值。

释放屏障 `A` 与执行获取操作的原子操作 `B` 同步，如果存在原子操作 `X`  `A` 先于 `X`，`X` 修改了 `M`，且 `B` 读取 `X` 写入的值或假设 `X` 为释放操作时引导的释放序列中任何侧效应写入的值。

在原子对象 `M` 上执行释放操作的原子操作 `A` 与获取屏障 `B` 同步，如果存在某些作用于 `M` 的原子操作 `X`，使得 `X` 先于 `B` 且读取了 `A` 写入的值或由 `A` 引导的释放序列中任何侧效应写入的值。

### 7.17.4.1 atomic_thread_fence 函数

大纲

```
#include <stdatomic.h>
void atomic_thread_fence (memory_order order);
```

描述

取决于 `order` 的值，此操作：

- 如果 `order == memory_order_relaxed`，则没有影响；

-   是一个获取屏（acquire fence），如果 order == memory_order_acquire 或 order == memory_order_consume；

-   是一个释放屏（release fence），如果 order == memory_order_release；

-   既是获取屏也是释放屏，如果 order == memory_order_acq_rel；

-   是一个顺序一致（sequentially consistent）的获取和释放屏，如果 order == memory_order_seq_cst。

# 返回

`atomic_thread_fence` 函数不返回任何值。

## 7.17.4.2  atomic_signal_fence 函数

# 概要


## 描述
