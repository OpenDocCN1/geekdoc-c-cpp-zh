
这是 Objective-C 中往往让那些来自 C++ 和 Java 等语言的人士感到畏畏的部分，因为它的语法直接取自 Smalltalk，对于更熟悉 C 语法的人来说看起来非常陌生。这是刻意为之。C 语言中没有任何东西的行为与 Objective-C 消息发送相同，因此引入新语法突出了你同时也拥有了新语义的事实。记住 Tom Love 曾将其描述为一种混合语言，在纯 C 部分和“对象世界”之间有清晰的语法分离，后者具有类 Smalltalk 的语法，用以伴随类 Smalltalk 的语义。

最简单的消息发送不接受任何参数。这方面的一个例子可能是发送给数组的 `-count` 消息。注意消息名称前的减号。这是 Objective-C 文档中使用的惯例，用于表示发送给实例的消息。加号用于表示发送给类的消息，例如 `+new` 或 `+arrayWithObject:`。

```

```

这段代码段获取数组中的元素个数并将其存储在变量 `size` 中。在 C++ 或 Java 等语言中，等效的操作类似于这样：

如果 `anArray` 是一个 C 结构体且 `size` 字段是一个函数指针，那么 Objective-C 中将使用相同的语法。由于这与向对象发送消息意味着完全不同的，设计者认为使用相同的语法会引起混淆。

接收一个参数的消息看起来非常相似。如果你想向 Objective-C 数组添加一个对象，你会使用类似这样的代码：`[anArray addObject:anObject];`

当消息有多个参数时，情况开始变得有点不同。和小 Smalltalk 一样，每个参数都有独立的名称，因此你可以在特定索引处插入对象：

```

```

当你理解了基本语法，这会让 Objective-C 代码非常易读，因为每个消息都会告诉你每个参数的用途。如果你在文档中遇到这个消息，它的写法是这样的：`-insertObject:atIndex:`。你可以从两个冒号看出它接受两个参数，并从两个冒号之前的文本看出这些参数是什么。和之前一样，减号表示这是发送给实例的消息。

如果你向一个没有实现该方法的对象发送消息，那么将会使用若干回退方法。在默认实现中，这些方法中的最后一个将抛出一个异常（你可以在运行时捕获并绕过它）。在发送消息之前，你也可以询问对象是否知道如何处理它。我们将在第 19 章查看如何这样做。

# 声明类

```objc
@interface Integer : NSObject
{
  int integer;
}
  (int)intValue;
  (void)addInteger:(Integer*)other;
@end

@implementation Integer
  (int)intValue { return integer; }
  (void)addInteger:(Integer*)other {
    integer += [other intValue];
  }
@end
```

来自：`integer.m`

当你创建一个新类时，你需要做两件事：描述它的公共接口并编写它的私有实现。你需要使用三个 Objective-C 关键字：`@interface`、`@implementation` 和 `@end`。

注意，所有新的 Objective-C 关键字都以 `@` 符号开头。这是因为该符号在 C 标识符中是不允许使用的。与之对比的是，C++ 引入了如 `class` 之类的标识符，这会破坏任何使用 `class` 作为变量名的 C 代码。

Objective-C 继承了 C 的编译模型，其中编译器期望单个文件，并通过让预处理器组合各种文件来完成分离。按照惯例，Objective-C 类的接口被放在具有 `.h` 扩展名的头文件中，而实现则存放在 `.m` 文件中。没有人记得为什么选择 `.m`。Objective-C 的设计者曾建议过，它可能代表“module（模块）”、“methods（方法）或“messages（消息）”。

由于头文件是由预处理器插入到编译单元中的，在 Objective-C 编译器看到它们之前就已经完成了插入，因此这种分离并不是强制执行的。C++ 和 C 中的不透明数据类型也是如此。

Objective-C 的一个稍微惊讶的方面是，实例变量（Java 和 C++ 称为“字段”）被声明为接口的一部分，而不是实现的一部分。这是早期 Objective-C 版本实现方式的产物。每个对象都被转换为一个 C 结构，其第一个字段是指向类的指针。为了生成这个结构，编译器需要能够看到所有父类的实例变量。这种方法一个不幸的副作用是，修改类的布局意味着你必须重新编译所有的子类。

现在，有了非脆弱性 ABI（non-fragile ABI），你可以向子类隐藏私有实例变量。对它们的每个引用都通过一个间接层。偏移量现在是一个变量，而不是编译时常量。新的编译器允许你在 `@implementation` 上文中以及 `@interface` 中定义实例变量。

默认情况下，Objective-C 实例变量是受保护的，这意味着它们只能由类或其子类访问。如果你为它们加上 `@private` 前缀，它们仅对该类可用；如果加上 `@public`，则可以在任何地方访问。这并不常见。运行时对访问权限的检查很少，并且有几种机制可以绕过访问控制，因此通常将所有内容保持为受保护状态，仅在私有类中将实例变量设置为公共。

**注意：** Apple 的非脆弱性 ABI 限制了 iv 偏移变量的可见性，如果你尝试从不同的编译单元访问私有实例变量，将产生硬错误。仍然可以通过运行时内省访问私有实例变量，而这种保护在其他运行时中是不提供的。

类接口的基本结构包含三个部分。第一部分是新类在层次结构中的位置：

```objc
@interface ClassName : Superclass <protocols>
```

类名紧跟在 `@interface` 关键字之后。接着是一个冒号，然后是父类的名称。可以设计新的根类，但要正确做到这一点非常复杂，大多数情况下你将使用 `NSObject` 或 `NSProxy` 作为你的父类。

之后，你还可以可选地在角括号中指定一个由逗号分隔的协议列表。Objective-C 中的协议类似于 Java 中的接口。它们定义了对象必须实现的方法列表。

注意：在较新版本的编译器中，你可以在类声明前加上 `__attribute__((weak_import))`。这使得所有引用都变为弱引用（weak）。如果你向该类发送消息而它未被链接，则等同于向 `nil` 发送消息。以这种方式导入的类的子类在父类加载之前将不会解析。这允许你定义一个继承自可选加载的包（bundle）中类的类。

接下来是相同的实例变量列表。它遵循在 C 中定义结构的语法。一个只包含实例变量而没有方法的简单类定义看起来如下：

{

}

在 C 结构定义中有效的任何内容在在这里都是有效的。如果你使用 Objective-C++，你还可以添加指向 C++ 对象的指针以及具有简易构造函数的 C++ 对象。

最后，你列出类所实现的公共方法。与其为此列表随口编造一些，让我们来看一些真实的方法声明：

+ + `(id)new`;

- `(void)append:(NSString*)aString`;

方法声明前的加号表示这是一个附加到类的方法。你可以向类发送 `+new` 消息，它会返回一个对象指针。`id` 类型是 Objective-C 引入的一种新类型，类似于 C 中的 `void*` 类型，但被限于 Objective-C 对象。

# 使用协议

与类一样，Objective-C 中的协议也是对象。协议的行为是 Apple 在现代运行时更改的内容之一。以前，协议是通过名称标识的，如果两个协议名称相同，它们被认为是等价的。这意味着如果你在不同的库中声明了同名的协议，你就无法判断一个对象实现了其中哪一个。更重要的是，你无法查找协议并查看它需要哪些方法。

在 Objective-C 2 中，协议现在是唯一的。

你现在可以按名称获取协议并对其进行检查。这在旧模型中曾经是可行的，但它取决于编译器是否已经输出了该协议的完整定义。

你可以使用 `@protocol()` 关键字获取协议的引用。此操作的主要目的是测试协议的遵从性。

```
if (![delegate conformsToProtocol: @protocol(DelegateProtocol)]
{
testIndividualMethods = NO;
}
```

你可能会在设置代理（delegate）的方法中使用类似下面的代码段。如果代理符合该协议，则可以保证它已经实现了该协议中的所有方法，因此你不需要测试每一个方法。如果它不符合，你可能需要在发送每条消息之前对每条消息进行测试。

协议为你提供了编译时和运行时的类型检查。你可以通过在类型名后的角括号中放入名称来要求一个对象符合某个协议。以下是一些示例：

```
id <NSCopying> a;
id <NSObject, NSCopying> b;
Object<NSCopying> *c;
```

在这里，你可以将任何实现了 `NSCopying` 协议的对象赋值给 `a`。赋值给 `b` 的对象也必须实现 `NSObject` 协议，任何继承自 NSObject 的对象都会自动实现它。最后，`c` 必须是 `NSObject` 的子类并且必须实现 `NSCopying` 协议。

如果你将一个对象赋值给要求它符合某个协议的变量，但该协议不在声明列表中，编译器将生成警告而不是错误。这不是硬性错误，因为尽管它没有声明协议遵从性，但它仍然实现了该协议所要求的所有方法。

## 向类中添加方法

```
@interface NSObject (Logging)
- (void)log;
@end
@implementation NSObject (Logging)
- (void)log
{
NSLog("@%@@", self);
}
@end
```

来自：`logging.m`

Objective-C 与 C++ 或 Java 等语言之间的最大区别之一是分类（categories）的概念。这些在 Smalltalk 中就已经存在，但它是作为一种将方法分组以便的方式。在 Objective-C 中，它们允许你向类添加方法，即使你没有该类源代码的权限。

分类定义的结构与类定义相似。分类不能改变类的实例变量，也不能改变其父类，因此 `@interface` 指令中的这些部分被省略了。在类名后的方括号中会添加分类名称。在前面的代码中，你可以看到一个简单的分类接口和实现，它为 `NSObject` 添加了一个 `-log` 方法。然后，你可以向任何对象发送 `-log` 消息并将其打印到控制台。

注意，分类的接口和实现都是可选的。在下一节中，我们将查看指定了分类接口但没有对应实现会有什么用处。如果你只想替换对象中的方法，那么在不指定接口的情况下指定实现是有用的。

在分类中声明的方法将替换在类中声明的同名方法。这种顺序是有保证的，因此如果存在冲突，分类将始终具有优先级。如果有两个分类定义了相同的方法，则被使用的那一个是未定义的。

分类的一个较少被文档记录的特性是，它们允许你为类添加协议遵从性。在 Foundation 框架中，各种集合（collections）没有共同的父类，也没有实现共同的协议。在 EtoileFoundation 框架中，我们为它们都添加了分类，使它们采用了 Collection 协议。这允许我们在需要某些集合但并不不在乎具体是哪种类型的地方使用该协议。

```
@protocol Collection
- (BOOL)isEmpty;
@end
@interface NSArray (Collection) <Collection> @end
@interface NSSet (Collection) <Collection> @end
@implementation NSArray (Collection)
- (BOOL)isEmpty
{
    return [self count] == 0;
}
@end
@implementation NSSet (Collection)
- (BOOL)isEmpty
{
    return [self count] == 0;
}
@end
```

来自：`collection.m`

`collection.m` 的示例展示了这种方法的（非常）简化版本。Collection 协议被添加到了 `NSSet` 和 `NSArray` 类中。如果你向这些类的实例发送一个 `-conformsToProtocol:` 消息，并将 `@protocol(Collection)` 作为参数，它将返回 YES。

分类有一个特殊情况，即你声明了一个没有名称的分类接口。这被称为“类扩展”（class extension）。与其他应该配有单独指定了分类名称的独立 `@implementation` 指令的分类不同，在类扩展中声明的方法预计会出现在类的主 `@implementation` 指令中。你可以用它来前向声明私有方法。

在最现代的 Objective-C 编译器中，你还可以在类扩展内部声明实例变量。你也可以在 `@implementation` 上下文中声明实例变量，就像在 `@interface` 上下文中做的那样。这两个机制允许你将实现细节从公共头文件中移出。
