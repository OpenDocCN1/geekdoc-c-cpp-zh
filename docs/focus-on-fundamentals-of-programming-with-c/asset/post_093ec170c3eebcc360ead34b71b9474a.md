- Software objects would be constructed to represent:

### OOP is Programming with Objects

- When you approach a programming problem in an object-oriented language, you no longer ask how the problem will be divided into functions, you ask how it will be divided into objects.
- Thinking in terms of objects, rather than functions, has a surprisingly helpful effect on how easily programs can be designed.
- This results from the close match between objects in the programming sense and objects in the real-world.

## Exactly What is an Object?

- An object is a software "package" that contains a collection of related functions or methods (behavior) and data (state).

- Everything an object "knows" is expressed by its state (data).

- Everything an object can do is expressed in its methods (behavior).

### State of Objects

For example:

- A ball might consist of a radius and a position
- A paddle, side, or brick might be described by position, width, and height

This represents the state of the objects

### Behavior of Objects

Likewise, each kind of object supports a set of operations that may be applied to the object to modify or interrogate its state.

For example:

- A ball responds to requests to report or modify its position.
- Similarly, a ball can be asked whether it is located behind the game paddle or whether it is colliding with any of the other components in the game.
- The paddle can be asked whether or not it is colliding with the ball.

### State and Behavior of an Object

So objects are characterized by their state and the operations that can be performed on that state.

This fundamental concept distinguishes OOP from procedural programming.

### OOP Objects

In traditional programming systems, data and procedures are separate entities. The programmer is responsible for applying active procedures to passive data structures, and frequently for ensuring that the procedure will work correctly on the data types to which it is applied.

By contrast, an OO programming system doesn't view an object just as passive data but as the combination of its private state and the methods that manipulate it.

### Procedural vs Object-Oriented Approach

Procedural Approach
- Problems are separated into code and data
- Commands operate on passive data

Object-Oriented Approach
- Objects define both data and functions
- Objects are responsible for their own behavior
- Functions and data are treated as entity

### How can Objects be Accessed?

- If objects can be accessed only through their public interface, how, then, is such access permitted?
- One object accesses another object by sending it a message.

### Messages

![](img/7f36c52b5170b89b142dbb7b1ea4666b_580_0.png)

- Sending a message to an object is the way of asking an object to carry out one of its operations (methods).
- When an object receives a message, it determines whether it has an appropriate method to allow it to respond to the message.
- If it does, it performs the requested operation in any manner it knows.
- The request does not specify HOW an operation is to be performed. Such information is always hidden from the sender.
