**Table 15-1  HTML document properties**

| Property name | Description |
|---|---|
| ALink | Color of the active links on the page |
| Background | Background picture used behind the text |
| BgColor | Background color for the page |
| Culture | Culture setting of the page |
| Debug | Indicates whether the class should be debugged with debug symbols |
| EnableSessionState | Session state mode |
| ID | Body element ID |
| Link | Color of unvisited links |
| Language | Specifies the language used when compiling all inline rendering and code declaration blocks within the page |
| MasterPageFile | Master page (read only) |
| StyleSheetTheme | Page stylesheet theme |
| Theme | Page theme |
| Trace | Indicates whether tracing is enabled |
| TraceMode | Indicates how traces are to be displayed when tracing is enabled |
| UICulture | UI Culture setting of the page |
| Text | Color for the foreground text on the page |
| Title | Caption for the title bar |
| VLink | Color of links in the document that have already been visited |

As with Windows applications, you can set some properties during design using the **Properties** window by selecting the individual property and either typing a new value or selecting a value from a pull-down list when available. Doing so adds code to the visual interface file containing the HTML tags (.aspx extension). You may notice several informational messages listed in the **Error List** indicating that *some of the attributes are considered outdated and that a newer construct is recommended* when you add properties for the items listed in Table 15-2. You can disregard this “Validation” messages. As you read in the last section, newer Web applications use Cascading Style Sheets (CSS) to do similar actions. For simplicity, properties for the document were set using the **Properties** window for this example. Table 15-2 shows the properties set for the document.
