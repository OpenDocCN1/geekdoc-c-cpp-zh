## Web Page

You will recall that two files are created for each page when you build Web applications. Selecting **File, New, Web Site** with the **File System** option selection enables you to specify where the Web site files should be stored on your local machine. The Source code file for the .aspx markup file is automatically opened when you first create a Web site as illustrated in Figure 15-5.

![](img/e33ae760e23d89eac66541252ad65de8_955_0.png)

Figure 15-5  Source code for HTML file

In Figure 15-5, the `Default.aspx` file for the `DynamicPage` site is shown in source code. This file (ending in .aspx) holds the HTML tags. You can view and directly edit the HTML source code here. The tags automatically generated by Visual Studio are actually XHTML tags. They are referred to as HTML tags for the remainder of the chapter. Tags are automatically inserted for head, title, body, form, and div. The first two lines in the .aspx markup file are called page directives. Page directives are delimited with `<%@` and `%>`. They provide information needed by ASP.NET to process the file.

The first attribute, `Page Title="Home Page"`, identifies the text title that will be associated with the page. This name appears in the title bar or tab for the browser.

When a new Web Site is created, you automatically get a MasterPage added to your site. An ASP.NET MasterPage allows you to set a template for common user interface elements that can be used across the entire Web site. The directive, `MasterPageFile="~/Site.master"`, specifies the path to this file. As you review Figure 15–5, you should see `Site.master` in the **Solution Explorer** window. Lines 4 and 6 give names for content pages that are associated with the master page.

Notice that the language used is identified; the name of the CodeFile is provided. The AutoEventWireup indicates how events are to be handled. When this attribute is set to `true`, the event-handler methods in the class are used. The attribute Inherits identifies the class in the code-behind file from which the ASP.NET class extends. If you change the class name in the code-behind file, it is not automatically changed in the .aspx source file. It is set initially to `_Default`. When you change the class name in the code-behind file, you must manually change it here for the application to run properly.

Line 4 assigned "server" to the runat attribute, indicating that when a client requests this .aspx file, it should be processed on the server before being rendered and sent back to the client. You see this runat="server" again on line 6 and will see it again as you build ASP.NET applications.

Although you can change the tags by typing new values, this is not the ideal method. You will probably prefer to drag and drop the controls onto the form, and let Visual Studio generate the tags for you. You can drag and drop controls from the **Toolbox** directly onto the .aspx source file that holds the HTML tags or onto the blank page. Selecting the **Design** tab at the bottom of the screen displays the .aspx page in design mode illustrated in Figure 15–6.

## Master Pages

When you have more than one page associated with a Web site, you may want to consider beginning with a master page. You can lay out the design you want to see and indicate on the page where content will change from one page to the next. For example, on a master page you might place an HTML table for the layout and include an image element for a logo. You might also include special controls for page navigation for your site. The concept of a master page allows you to create and maintain a consistent theme across several pages for a Web site. As you look back at Figures 15-5 and 15-6, notice one of the nodes listed in the **Solution Explorer** window is **Site.master**; this is a master page. It is automatically created when you create a New Web Site in Visual Studio 2010. A master page ends with an extension of .master.

Figure 15-7 shows most of the **Site.master** file. You will notice it contains formatting HTML tags. A master page can include static text, HTML elements, and server controls. If you look at the Site.master file in Figure 15-7, you will find html, head, body, form, and div elements on the page. There are a few subtle differences between a master page and other pages, like the Default.aspx page. First, it has a special **@ Master** directive instead of the **@ Page** directive.

![](img/e33ae760e23d89eac66541252ad65de8_957_0.png)

Figure 15-7 Site.master master page

Master pages actually consist of two pieces: the master page itself and one or more content pages. Individual content pages contain the content you want to display in the context of the master page template. When users request the content pages, the master page is merged with the content page to produce output that combines the layout of the master page with the new material from the content page. The content pages associated with the master page for the DynamicPage example are About.aspx and Default.aspx.

The other major difference between a master page and content pages like Default.aspx and About.aspx is that the master page has one or more ContentPlaceHolders defined with an ID. These placeholders define areas where replaceable content will appear. HeadContent and MainContent ContentPlaceHolders are shown on Lines 9 and 44 in Figure 15-7. Figures 15-8 and 15-9 show the replaceable content for the About.aspx and Default.aspx pages.

![](img/e33ae760e23d89eac66541252ad65de8_958_0.png)

The static text "About" and "Put content here" is the content used to fill the white area (MainContent) on the page. As you review Figure 15-9, notice the content for MainContent is defined on lines 6 through 19 for the Default.aspx page.

This is a style sheet. The file is automatically added to the project when a Visual Studio 2010 Web site is created.
