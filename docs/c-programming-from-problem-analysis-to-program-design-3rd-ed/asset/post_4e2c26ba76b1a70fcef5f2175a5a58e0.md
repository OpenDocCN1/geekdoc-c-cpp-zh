
Significant security changes were implemented, beginning with SQL Server 2005, to make it more secure. These changes may be problematic for your development. To create or attach to a SQL Server database during development, you need administrative permissions on the local machine. But, it is not enough to have membership in the Windows Administrator group. SQL Server accounts are no longer automatically granted access to SQL Server because of their membership in the Windows Administrator group. Users must be assigned special security roles, such as dbcreator or sysadmin, in order to create database tables.

Primary keys can be established by right-clicking the row containing the unique field. To indicate a concatenated primary key, hold the Shift key down to select multiple rows. A right-click on the row also reveals options to insert or delete columns and to create indexes.

### Storing Data in a SQL Server Table

When you close the table definition window, you have the opportunity to name the table. To populate the table with data, right-click the table, using the **Server Explorer** window, and select **Show Table Data** from the shortcut menu. Another option from the shortcut menu, **Open Table Definition**, can be used to modify the structure. It is beyond the scope of this book to provide a detailed discussion on creating databases. However, creating a SQL Server database using Visual Studio and the **Server Explorer** window is a fairly simple process. You are encouraged to explore this on your own and use the online MSDN documentation if you need additional help.

### Adding a Connection

As shown in Figure 14-9, another option when you right-click on the **Data Connections** node is the **Add Connection** option from the shortcut menu in the **Server Explorer** window. If you select this option, a dialog box is displayed that allows you to specify the data source and database file name and test the connection. You can also add the connection using the **Add New Data Source** option from the **Data** menu. Selecting this option launches the **Data Source Configuration Wizard** shown previously in Figure 14-5.

Because of potential permission constraints associated with SQL Server, Access data source is used for the remaining examples in this chapter. To connect to an Access database, click the **Change** button beside the **Data Source**, as shown in Figure 14-8. This opens another dialog box, where you would choose **Microsoft Access Database File** as the **Data Source**. This option lets you use the .NET Framework Data Provider for OLE DB. If you select the checkbox in the extreme left corner, Access will become the default data source for future connections.

You enter the name of the database file next using the **Browse** button. When connecting to an Access database, you are asked to enter a username and password for the database. The default (**Admin**) is automatically added as the **User name**. You are encouraged to keep this default setting and to leave the **Password** text box blank.

### Local Copy of Your Database

The first time you establish a connection to the database for your application, the message shown in Figure 14–11 is displayed. The configuration tool offers to make a copy of the database and place it in your project folder. The file is not placed in the bin\debug folder where referenced resources are often placed. Instead, it is placed at the root level of the project folder—that same location as your solution (.sln) file for the Windows form. Selecting Yes copies the database into your project and modifies the connection so that it now points to the database in your project. If you choose not to make a copy, then a connection is established, and the database file is left in its original location.

![](img/e33ae760e23d89eac66541252ad65de8_897_1.png)

Another option for making a local copy of the database for your project is to use Windows Explorer and drag a copy of the database to the Visual Studio **Solution Explorer** window. The copy should be dropped on top of the project node. When you do this, the **Data Source Configuration Wizard** launches and gives you an opportunity to identify which table(s) to include in the dataset. Access database files end with an .accdb extension. SQLExpress database files end with an .mdf extension.

Both Microsoft Access and SQL Server databases can be stored locally with your project. If multiple applications are using the same database, you will probably prefer to leave the database in its original location so that changes made by one application are available to all other applications using the database.

![](img/e33ae760e23d89eac66541252ad65de8_897_2.png)

If you are using the **Data Source Configuration** and **DataSet Designer** tools and are planning to update or make changes to the database within your application, it is recommended that you not make a local copy of the database. The underlying database does not get changed properly. Having a local copy works fine if you only intend to display the data.

### Connection String Created

Visual Studio offers to store the connection string in a configuration file that contains settings specific to your application. This is illustrated in Figure 14–12. As a final step before you identify the data to be placed in the dataset, you decide whether to store the connection string.

![](img/e33ae760e23d89eac66541252ad65de8_898_0.png)

Figure 14-12  Save connection string

As shown in Figure 14–12, storing the connection string in the application’s configuration file makes maintenance and deployment easier. It simplifies the process of maintaining your application if the database connection changes. In the event of a change in the database connection, you can edit the connection string in the application configuration file as opposed to editing the source code and having to recompile your application. The default name for the connection string for the application is `StudentDataBaseConnectionString`, as shown in Figure 14–12.

If you save the connection string to the application configuration file, as shown in Figure 14–12, an `app.config` file is created. Example 14–22 shows the file contents. It is an XML file that can be viewed and modified in Visual Studio.

### Example 14-22

```xml
<?xml version="1.0" encoding="utf-8" ?>
<configuration>
    <configSections>
    </configSections>
    <connectionStrings>
        <add name="CnfToolExample.Properties.Settings.StudentDataBaseConnectionString"
            connectionString="Provider=Microsoft.ACE.OLEDB.12.0;Data Source=|DataDirectory|\studentDataBase.accdb"
            providerName="System.Data.OleDb" />
    </connectionStrings>
</configuration>
```

If you look ahead at Figure 14-14, you will find the app.config file listed in the **Solution Explorer** window for the project.
