
## Creating a Smart Device Application

After selecting **File**, **New**, **Project** and choosing **Visual C#** as the Project type, you will see **Silverlight for Windows Phone** as one of the **Installed Templates**. Selecting this option reveals an option to create a **Windows Phone Application** project. You name the Project as you have done with previous applications. The desktop is filled with 4 panes as illustrated in Figure 15-35.

![](img/e33ae760e23d89eac66541252ad65de8_1013_0.png)

**Figure 15-35** Windows phone application

A blank miniature form (**PhoneApplicationPage**) that looks like a phone is displayed with a left arrow, the Windows logo, and a search tool. A **ContentGrid** is placed on the form. As you review Figure 15-35, you will notice that there is a reduced number of options found in the **ToolBox** and **Properties** window.

Using the WYSIWYG approach, you can drag and drop controls to the form. To illustrate developing an application for a smart device, a multiplier is designed as an example. As shown in Figure 15-36, a **TextBox**, **Button**, two **RadioButtons**, and several **TextBlock** objects are added to the form. The **TextBlock** object is similar to the **Label** found previously with Window Form objects. As shown in Figure 15-36 you have great control over sizing and moving the controls. In Design mode, you have an interactive canvas where you can drag and drop controls from the toolbox and set properties for existing controls on the designer surface.

![](img/e33ae760e23d89eac66541252ad65de8_1014_0.png)

**Figure 15-36** Adding controls to the smart device application

A number of Properties were set. The Text property for the TextBlock labels were set. Button and RadioButton objects did not have a Text property, instead the Content property was used to provide identifying information on the form. For the TextBox objects, Text was set to " ". The controls that are used in the program statements were named in the Properties Window. The size and color of several controls were set. An Image control was placed on the grid on the phone. The Source property was used to identify a .jpg image. The image was resized and moved.

The final design is shown in Figure 15-37. As illustrated in that figure, you have great control over the canvas. You can zoom in/out as you work with controls placed on the form.

![](img/e33ae760e23d89eac66541252ad65de8_1015_0.png)

**Figure 15-37** Metric/English Converter final design

The only programming statements added were those included in the button click event-handler method. These statements are placed in the code-behind file stored with an .xaml.cs file extension. The other changes were to the properties in the Properties window. Tags were added to the file ending with an .xaml extension. The program statements are shown in Example 15-17.

### Example 15-17

```
private void btnConvert_Click(object sender, RoutedEventArgs e)
{
    if (rdBtnInches.IsChecked == true)
        this.txtBlockResult.Text = "Result: "
            + (double.Parse(txtBxValue1.Text) * 0.39).ToString();
    else
        this.txtBlockResult.Text = "Result: "
            + (double.Parse(txtBxValue1.Text) * 2.54).ToString();
}
```

The `btnConvert_Click()` event handler determines which radio button is selected, retrieves the input value from the TextBox objects, converts it to a `double`, multiplies the values, and then stores the result to the text property of the `lblResult` TextBlock object.

## QUICK REVIEW

- 1. A Web application, also called a Web site, is simply a collection of one or more related files or components stored on a Web server. Web servers are software that is responsible for hosting or delivering the Web application.
- 2. When a page is requested using HTTP, the request goes to the Web server, which sends back the document in an HTML format. This is considered a round-trip to the server. Another round-trip is required when changes are made on a dynamic Web page.
- 3. Every trip to the server creates a new **object** because Web pages are considered state-less. They do not retain their values from one trip to the Web server to the next.
- 4. Static pages do not require any processing by a Web server. They are precreated and reside on the server’s hard drive. Dynamic Web sites involve processing in addition to rendering the formatting HTML.
- 5. To develop ASP.NET applications, you must either have Microsoft Internet Information Services (IIS) installed or use the personal Web server available with Visual Studio or the Visual Web Developer Express product.
- 6. ASP.NET Web application projects are created at *http://localhost* if you select the HTTP option for Location. Physically the files are stored in the home directory, `C:\Inetpub\wwwroot`. This is the default for the home directory. A directory is also created with the name you typed for the project, and it is placed (along with the two solution files) at the location you configured Visual Studio to store all of your Visual Studio projects. Choosing the File System option for the Location lets you identify where on your local machine the Web site application is stored.
- 7. The Web Forms page **object** has a number of properties, many with the same functionality that was available for setting a Windows application form.
- 8. Two files are created for Web applications. Code for the visual interface file is placed in the file containing the HTML tags (.aspx extension). The other file, the code-behind file, contains the logic for the application. There is no .designer.cs file as you find with Windows applications. The ASP.NET code-behind model requires an additional step—compiling the source code when ASP runs the application.
- 9. HTML controls are also called client-side controls. The biggest advantage HTML controls offer is that the page is rendered “as is” to the browser. Client-side controls require no processing by the Web server.
- 10. One option for creating a New Web site, creates a number of files and folders, including a master page. A master page allows you to create and maintain a consistent theme across several pages for a Web site.
- 11. Cascading Style Sheets can be used with Web applications. They enable you to separate the actual page content from the visual appearance of the page.
- 12. Server controls are referred to as Web controls. Web Forms server controls, ASP server controls, or simply Web Forms controls. Visual Studio prefixes the control name with `<asp:control>` and ends the tag with `</asp:control>`.
- 13. Only a few events trigger a postback to the server. ListBox, RadioButton, RadioButtonList, CheckBox, CheckBoxList, and DropDownList have a property called AutoPostBack that can be set to **true** to trigger a postback automatically.
- 14. Validation controls enable input to be validated or checked by the server. You can check to make sure that values have been entered, that values fall between a range of values, or you can create custom validation checks.
- 15. You tie the validation control to a specific control such as a TextBox **object**, using the ControlToValidate property. The ErrorMessage property can be set to the message you want to display when the input control does not pass the validation test.
