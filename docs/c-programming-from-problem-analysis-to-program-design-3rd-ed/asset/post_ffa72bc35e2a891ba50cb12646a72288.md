
## Appendix A
### Visual Studio Configuration

To increase productivity, you might want to configure the appearance and behavior of the integrated development environment (IDE) for Visual Studio. This appendix presents suggestions for possible settings.

### Customizing the Development Environment

When Visual Studio is launched, it opens the current default **Start Page**. As shown in Figure A-1, you have the options to create a **New Project** or **Open Project** from the **Start Page**. Tabs are available to provide **Guidance and Resources** and the **Latest News**. If you have an internet connection, you can subscribe to an RSS feed that provides latest updates and information about Visual Studio and C#.

You can choose to have this page opened each time you run Visual Studio or, as illustrated in the figure, you can deselect the checkbox in the extreme left corner and not **Show page on Startup.** You can begin customizing your environment even at that point. You can also check the **Close page after project load** if you do not want to see the **Start Page** listed as one of the available tabs while you are working on your project.

![](img/e33ae760e23d89eac66541252ad65de8_1029_0.png)

Figure A-1 Visual Studio Start Page

You have an option to pin an important project right on the **Start Page** so it will always be there. The pushpin is revealed when you right-click on the project in the **Recent Projects** area. The **PizzaParlourKiosk** and **LingDataBaseAccessExample** are pinned in Figure A-1. Six projects are shown under the **Recent Projects** area. This number can be changed as described below. You use the **Options** from the **Tools** menu as shown in Figure A-2 to make most useful changes.

![](img/e33ae760e23d89eac66541252ad65de8_1030_0.png)

Figure A-2 Using Tools, Options to configure Visual Studio

Depending on how the system you are using is configured, the options on your menu may vary slightly from the one displayed in Figure A-2.

### Environment

After you select Options, the first folder node shown is Environment. When you select the Environment, the right pane of the dialog box changes to reveal options shown in Figure A-3.

![](img/e33ae760e23d89eac66541252ad65de8_1031_0.png)

**Figure A-3** Environment General options

As shown in Figure A-3, the **Environment** node enables you to indicate how many files should display under the **Windows** menu option. You can specify from 1 to 24. The default is 10. If you have more files open than the number you select, older filenames just fall off the list, which is also the case for the second option under the **Recent files** area. The default for **items shown in recently used lists** is also 10. It was changed to 6 for this illustration. This value impacts the **File** menu option and also the **Start Page** list. Using the **Recent Files** or **Recent Projects and Solutions** option from the **File** menu saves time when you are working with the same project over a long period. It eliminates the need to browse to the same location where the project is stored every time you want to reopen the file. Pinning the project to the list, as was described above, is also useful if you have a project that gets worked on often to keep it from falling off the list. From the **Environment General** node dialog box, you also specify whether the status bar is displayed and indicate whether the close box impacts the active window only.

From the **Environment, Fonts and Colors** node, you can change the size and type of the font for almost every item that appears in Visual Studio, including dialog boxes, windows, and text editor’s text. It is useful to increase the font size if you are performing paired programming (working as a team of two) at a computer station or if you want to project your source code to a screen for others to view. As shown in Figure A-4, you have the capability of changing the display item’s background or foreground.

![](img/e33ae760e23d89eac66541252ad65de8_1032_0.png)

Figure A-4 Setting the fonts and colors

If you review the list of items available to change in the drop-down list of the **Display Items** control shown in Figure A-4, you will find there are over 100 items listed just for the **Text Editor**.

A new feature incorporated into the Visual Studio 2010 IDE is a zoom control. This feature enables you to increase/decrease the displayed font size of text items. Figure A-5 illustrates this option, it is extremely useful if you want to quickly enlarge your program statements. You can zoom up to 400% of the actual size.

![](img/e33ae760e23d89eac66541252ad65de8_1033_0.png)

Figure A-5 Zoom capability

The **Environment, Startup** node lets you determine what is opened when you first start Visual Studio. You can select options such as **Show Start Page**, **Open Home Page**, **Load last loaded solution**, **Show Open Project dialog box**, **Show New Project dialog box**, or **Show empty environment**. You might also want to make changes at the **Environment, Web Browser** node, where the URL for your **Home page** and **Search page** are set.

### Projects and Solutions

You identify the default location for where your projects should be saved using the **Projects and Solutions** node, as shown in Figure A-6. C:\CSharpProjects was the location entered for projects created for this book. From this dialog box, you also indicate whether you want the **Always show Error List if build finishes with errors** or to **Show Output window when build starts**. If you select the **Build and Run** option on the Projects and Solutions node, you can also indicate whether your project should **Save all Changes** before building. The other options are to **Save changes to open documents only**, **Prompt to save all changes**, and **Don't save any changes**. The **Save all changes** is a good option to set for the **Before building** selection.

![](img/e33ae760e23d89eac66541252ad65de8_1034_0.png)

Figure A-6 Setting the location for Visual Studio projects

You should definitely configure the Visual Studio **Projects location** setting as shown in Figure A-6. You are encouraged to review and explore the other settings available on the **Environment** and **Projects and Solutions** tabs.

### Text Editor

If you do not like the auto-completion IntelliSense feature of Visual Studio, you can turn the feature off under the **IntelliSense for C#** within the **Text Editor** option as shown in Figure A-7 or adjust the features to fit your preferences.

![](img/e33ae760e23d89eac66541252ad65de8_1035_0.png)

**Figure A-7** Text Editor IntelliSense settings for C#

On the C# **IntelliSense** dialog box, shown in Figure A-7, notice that the second checkbox option is **Committed by pressing the space bar**. Turning on this feature reduces the number of keystrokes required while you are programming. As does turning on the selection from the first checkbox, **Show completion list after a character is typed**.

![](img/e33ae760e23d89eac66541252ad65de8_1035_1.png)

You can press **CTRL+ALT+SPACEBAR** to switch to IntelliSense suggestion mode (as opposed to completion mode). In suggestion mode, IntelliSense is less aggressive. It does not autocomplete member names after you type open parenthesis or equal symbols. Instead, you are able to choose an existing member from a list.

You can set the editor to **Display Line Numbers**, **Enable single-click URL navigation**, and display the **Navigation bar** from the **Text Editor, C#** node as shown in Figure A-8.

![](img/e33ae760e23d89eac66541252ad65de8_1036_0.png)

Figure A-8 Text Editor display option

You also specify whether you have **Statement completion** to **Auto List members** and/or to have **Statement completion** with **Parameter information** displayed from the **Text Editor, C#, General** option. When you select **Display Line numbers**, the line numbers are displayed to the left of the source code in the IDE.

The **Tabs** node, which is immediately below the **General** option, enables you to specify the amount of space inserted when a tab or indent is set and whether tabs or spaces are inserted for tabs. From this option, you can also set **Smart indenting** so that it automatically indents the next line, if a statement doesn’t fit on a single line. Smart indenting does not always work the way you think it should. As the name implies, it tries to be smart and sometimes you have to override it.

The **Formatting** option under the **Text Editor** expands to reveal a number of features grouped under **General, Indentation, New Lines, Spacing, and Wrapping**. As shown in Figure A-9, you can decide whether you prefer to place your braces on a new line for type, methods, and control blocks. This is how braces have been displayed in this book. Here you indicate whether keywords like `else`, `catch`, and `finally` should appear on a separate line.
