
## WSDL

**Web Services Description Language (WSDL)** is a language formatted in XML that is used to describe the capabilities of a Web service and is itself part of that service. WSDL includes details about the method in terms of what type of data it can receive and what type of results it will return. Think about the signature and return type of a typical method. To use or call on the method, you must know what arguments it receives and what, if anything, it returns. To use a Web service, client applications must know the method name, the number and type of parameters the method is expecting, and what is expected upon return from the method. A Web service that offers keyword search functionality would expect to receive a data item in a string format. The Web service would return a string containing a list of Web addresses in which the keyword is located. The WSDL would provide the details in XML format.

A number of Web services are already available that you can add to your application, and the list is growing daily. Typically, a Web service defines a business object that executes a unit of work. You use the WSDL to determine how to call the Web service. But, for clients to use a Web service, they have to know that the Web service is available. A couple of options exist. You can use UDDI or Web Services Dynamic Discovery (WS-Discovery). **UDDI** stands for **Universal Description, Discovery, and Integration**. UDDI, like WSDL, uses an XML grammar. Web services publish information in a standardized format about their location and functionality in a UDDI registry. You can find Web services available at sites such as *http://webservices.seekda.com/* and *http://xmethods.net*. You can search for Web services using your favorite search engine. WS-Discovery is used with Windows Communication Foundation, which is the subject of the next section.

## Windows Communication Foundation (WCF)

**Windows Communication Foundation (WCF)** is an Application Programming Interface (API) used to build connected service-oriented applications. WCF can be used to build Web services in .NET 4.0. Web services were previously designed using the ASP.NET Web Service Application template in Visual Studio. Beginning with 4.0, you no longer see Web Services listed as a template option in Visual Studio; however, the template is still available. ## SMART DEVICE APPLICATIONS (OPTIONAL)

Mobile applications are becoming very important in our society. Mobile application development involves writing apps for handheld devices like smart phones or personal digital assistants. Currently there are many different platforms that a developer can choose for their applications. Unfortunately these platforms are pretty much incompatible. Applications developed on one platform will not run on another and most handheld devices only support one particular platform. Current platforms include Blackberry, iPhone OS, Android, a Linux-based platform, Symbian, Palm, Brew, Java ME, Pocket PC, and Windows Mobile OS.

Windows Mobile OS is a compact operating system developed by Microsoft. You can create mobile applications for this operating system using Visual Studio. One of the installed templates with Visual Studio versions prior to Visual Studio 2010 was Smart Device applications. Recall that Figure 15-33 illustrated how to target different frameworks. You may want to develop a smart device application targeting one of the previous frameworks. As you review the left pane of Figure 15-33, notice one of the templates listed for the .NET 4.0 Framework is labeled **Silverlight for Windows Phone**. When Visual Studio 2010 was first released, it did not include support for smart device development. The Windows Phone Developer Tools–CTP were added as a separate install after installing Visual Studio 2010. The Download is free and when this book was written it was available online at http://go.microsoft.com/fwlink/?LinkID=185584. You can also go download the tools at Microsoft’s Download Center (http://www.microsoft.com/downloads). Once this is installed, you can create mobile devices targeted to the Windows Phone 7 Operating System.

The current version of Windows Mobile is 6.5. If you prefer to develop your application for this OS, you can download that plug-in instead of the one for 7.0. Both are available at the Microsoft Download Center.

The Windows Phone Developer Tools includes a Windows Phone IDE and the Windows Phone Emulator.

The template for developing applications for smart devices targets Silverlight. **Silverlight** was initially released as a video streaming plugin, but today provides functionality similar to Adobe Flash. It is a Web application framework that enables you to integrate multimedia like graphics, sounds, and animations into applications. Silverlight uses a subset of the framework. You can design, develop, debug, and deploy applications that run on personal digital assistants (PDAs), mobile phones, tablet PCs, and other resource-restricted devices. These applications can be created even if you do not own a smart Mobile device. An emulator that simulates the device is included as part of the IDE. The **emulator** has many of the same features you find on PDAs. It enables you to see what the output would look like displayed on the real device.

Because there has been and continues to be such an explosive growth in wireless devices, this section is included to illustrate the ease of development for these types of applications. You are encouraged to continue exploring beyond what is presented in this limited example. You use the same programming development model that you have been using to develop complete smart device applications using C#.

Currently, all mobile devices are significantly less powerful than desktop computers. They run more slowly, have less memory available, and their display capability restricts their functionality. Keep in mind that for development purposes, the typical smart device display screen is small. Thus, the user interface should be kept simpler than traditional applications.

## Silverlight

Silverlight user interfaces are declared in Extensible Application Markup Language (XAML) and programmed using a subset of the .NET Framework. You will be able to use much of the same programming model you have used to develop applications. You still have access to the core methods and classes so that the business logic and data access layer can be used. A Silverlight application starts by invoking the Silverlight control from the HTML page, which then loads up a XAML file. The XAML file contains a Canvas object, which acts as placeholder for other elements. Like Web applications, you have fewer controls to drag and drop and fewer events to program.
