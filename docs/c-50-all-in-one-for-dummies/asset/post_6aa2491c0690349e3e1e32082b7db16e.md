# Working with the visual tools

The Rapid Application Development (RAD) tools for C# are a massive improvement over what Microsoft previously provided. The RAD data tools in Visual Studio are usable and do what you need, and they write decent code for you.

![](img/6df7bb88e9302e98442acc219cfbd7fc_453_0.png)

You need to know that I would never show this kind of black magic if it wasn't a best practice. In the past, tools that did something you couldn't see often did their job properly. Using the tools, in the long run, made your program worse. The new tools, though, are a good way to build software. People may tell you that I am wrong, but it really isn't bad. Try it!

# Writing data code

In most enterprise environments, however, you won't be using the visual tools to build data software. Generally, an infrastructure is already in place.

The reason for this is that often, enterprise software has specific requirements, and the easiest way to manage those is with unique and customized code. In short, some organizations don't want done the way Microsoft does.
