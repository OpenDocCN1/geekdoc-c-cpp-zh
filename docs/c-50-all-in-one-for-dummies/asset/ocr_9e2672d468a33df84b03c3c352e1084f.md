# Building and debugging

I'm sure by now you have gotten the basics of building and debugging. A few other options in the Build and Debug menus deserve at least a small explanation, including the:

+   **Rebuild**: This checks all the references throughout the project before compiling the project. It's useful if your development computer changed configuration since your last build.

+   **Clean**: This actually deletes not only the EXEs and DLLs created as part of your project (but not your code files), but all DLLs that were copied into your project by references that were set to that mode.

+   **Batch Build**: This enables you to build release and debug versions (for instance), or 32 and 64 bit (as another example) at the same time.

+   **Configuration Manager**: Use this to set the order and mode in which you build your projects. The most common configurations are DEBUG (for code in progress) and RELEASE (for finished).

# Refactor menu

Refactoring is the practice of reorganizing code that might have been scattered or duplicated during development or debugging. The Refactoring menu in Visual Studio on the Edit menu provides a few tools that help with refactoring in C#, including these:

+   **Rename**: Rename is simple — anytime you rename a symbol (a named object as a variable, a property, or an enum, for example), you can change the name throughout the project. After you change the name of something, you should see a smart tag near the end of the symbol name has Rename as an option.
