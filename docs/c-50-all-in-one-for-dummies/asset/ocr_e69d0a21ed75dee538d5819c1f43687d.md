# Skipping the Ref Statement

Because of a different programming model, many COM APIs contain a lot of reference parameters. Contrary to C#, these are typically not meant to mutate a passed-in argument for the subsequent benefit of the caller but are simply another way of passing value parameters.

It seems unreasonable that a C# programmer should have to create temporary variables for all ref parameters and pass these by reference. So let's delete them.

Instead, for COM methods, the C# compiler allows you to pass arguments by such a value and automatically generates variables to hold the passed-in values, subsequently disagreeing them when the call returns. In this way, the caller sees semantics and doesn't experience any side effects, but the called method gets a reference.

You can see this action in the optional parameter example from Chapter 2. In the usual SaveAs from Microsoft Word, which is a reference parameter.

```
object filename = "test.docx";nobject missing = System.Reflection.Missing.Value;
doc.SaveAs(ref filename,
ref missing, ref missing, ref missing,
ref missing, ref missing, ref missing,
ref missing, ref missing, ref missing,
ref missing, ref missing, ref missing);
```
