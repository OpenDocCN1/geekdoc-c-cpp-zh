## Building and debugging

I'm sure by now you have gotten the basics of building and debugging. A few other options in the Build and Debug menus deserve at least a small explanation, including the:

- **Rebuild**: This checks all the references throughout the project before compiling the project. It's useful if your development computer changed configuration since your last build.
- **Clean**: This actually deletes not only the EXEs and DLLs created as part of your project (but not your code files), but all DLLs that were copied into your project by references that were set to that mode.
- **Batch Build**: This enables you to build release and debug versions (for instance), or 32 and 64 bit (as another example) at the same time.
- **Configuration Manager**: Use this to set the order and mode in which you build your projects. The most common configurations are DEBUG (for code in progress) and RELEASE (for finished).

## Refactor menu

Refactoring is the practice of reorganizing code that might have been scattered or duplicated during development or debugging. The Refactoring menu in Visual Studio on the Edit menu provides a few tools that help with refactoring in C#, including these:

- **Rename**: Rename is simple — anytime you rename a symbol (a named object as a variable, a property, or an enum, for example), you can change the name throughout the project. After you change the name of something, you should see a smart tag near the end of the symbol name has Rename as an option.

Rename changes all symbols representing the same object in the project (not the solution). Rename with Preview shows you each change before it is performed and lets you select or deselect any of the items that would be renamed.

- **Extract Method:** Perhaps you've written a block of code and then thought "oh boy, I am going to need this over there." If so, Extract Method is for you. It will take a highlighted block of code, move it to a method, extract all the variables, make them parameters, and then you'll be ready to use code.
- **Encapsulate Field:** In a similar vein as extracting a method, Encapsulate Field takes a private variable and makes it a public field. For instance, take a line of code like private string _theValue; highlight it in designer and select Encapsulate Field from the Refactor menu.

Visual Studio asks you to name the property and create a new property:
```cs
public string TheValue
{
    get { return _theValue; }
    set { _theValue = value; }
}
```

- **Extract Interface:** Extract Interface takes a set of method signatures and makes an interface for you. Interfaces are vital to contract development.

- **Remove Parameters**: This is the safe way to get excess parameters out of methods. In honesty, use this to the last.

- **Reorder Parameters**: Being able to change the order of parameters is significantly handier. Sometimes, you just need to switch the order of two parameters. If you do this, all the places you call the method must have the order changed, or you will send the wrong stuff.

This simple tool enables you to change the parameter order and finds all places that call the method in question.
