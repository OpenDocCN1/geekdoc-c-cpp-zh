# Coding in the Code Editor

If you go back to the design view and double-click on the Button control you dragged over, you will see something a little more familiar than all of this crazy markup. Usually the code-behind, this is the C# code that makes the form manageable by the server. The code-behind is in a file Default.aspx.cs, below Default.aspx in its Solution Explorer tree. This code should look like this:

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Web;
using System.Web.UI;
using System.Web.UI.WebControls;

namespace AspNetFirstSample
{
    public partial class _Default : Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
        }

        protected void ChangeText_Click(object sender, EventArgs e)
        {
        }
    }
}
```

I'll break this down for a little. I know you've seen a class before, and that's all this is, but I want to point out a few things:

+   * This is a partial class. The rest of this class is built-in web functionality, and it used to appear in this file. Is fact, no one ever needed to edit it, so Microsoft toolled it out. I'm glad they did. This is a lot easier to look at.

+   * The class inherits from System.Web.UI.Page . The Page class provides all the tools you need to keep control of controls in the page together. This is very important for some web applications, but it's a little beyond the scope of this book. Read the documentation for the Page class. It's an important part of ASP.NET.

+   * There is an event handler for Page.Load. Remember the ASP.NET load sequence in Chapter 1? (Recall requests sequence and post-backs?) This is important. You can do pre-setup operations in this handler.

+   * There is an event handler for the Button.Click event. Hey, how did this get there? Yeah, you double-clicked the control to get the default event handler, just like I talk about in I.
