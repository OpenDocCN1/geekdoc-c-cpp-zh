# Using surround snippets

Surround snippets are very cool. Have you ever written a few lines of code, and realized that you should probably try to catch errors? You have to add a little code at the beginning, then add a little code at the end, and make sure the middle is in the right place. It's a pain.

Surround snippets are designed to solve that problem. They are normal snippets with a bit of logic in them that say, "This part goes above the selection, and this part goes below the selection." If you want to handle errors for a section, you highlight that section, and the snippet will put the try before the selection and the catch at the end.

To use a surround snippet, follow these steps:

- 1. Highlight some code in the Code Designer.
- 2. Press Ctrl+K,S to open the snippets menu.
- 3. Select the appropriate snippet for the menu.

You can choose the snippet that is right for whatever you are coding.
Try Tab for a property getter and setter. To open submenus, use Tab. Close, use Shift+Tab.

- 4. Set the various variables that Visual Studio prompts you with.

The snippet will appear appropriately above and below the selected text.
For instance, if I had this chunk of code:

```c
for (int loopcounter = 1; loopcounter <= 10; loopcounter++)
{
    Console.WriteLine(string.Format("The number is (0).*", loopcounter));
}
```

And I felt that I needed a try ... catch block around it, I could highlight that code and the preceding steps. If I select try from the menu, I would get this:

```csharp
try{
    for (int loopcounter = 1; loopcounter <= 10; loopcounter++)
    {
        Console.WriteLine(string.Format("The number is (0).*", loopcounter));
    }
}catch (Exception)
{
    throw;
}
```

the exception is highlighted in green; I can tap to and add the exception type I am expecting. It's a slick system.

# Making snippets

Snippets are XML files that follow a format understood by Visual Studio.
They include a Header and Snippet element. The Header includes a title, which is how the snippet is referred to. The Snippet, where all the work is done, includes a Code element, which has to be inserted.

The best way to make a new snippet is to modify an existing one. Snippets can be found in your Visual Studio install directory, which could be in C:\Program Files (x86)\Microsoft Visual Studio 11.0\VC#:\Snippets\1033 if you are on a 64-bit operating system (otherwise you might drop the (x86)).

In the folder referenced in the preceding paragraph, look at a simple example: cw.snippet is a Console.WriteLineeline command. Right-click the file to open it. Here's the code:

```xml
<xml version="1.0" encoding="utf-8" ?>
<CodeSnippet xmlns="http://schemas.microsoft.com/VisualStudio/2005/CodeSnippet">
  <CodeSnippet Format="1.0.0">
    <Header>
      <Title>cw</Title>
      <Shortcut>cw</Shortcut>
      <Description>Code snippet for Console.Writeline</Description>
      <Author>Microsoft Corporation</Author>
      <SnippetTypes>
        <SnippetType>Expansion</SnippetType>
      </SnippetTypes>
    </Header>
    <Snippet>
      <Declarations>
        <Literal Editable="false">
          <ID>SystemConsole</ID>
          <Function SimpleTypeName global="System.Console"></Function>
        </Literal>
      </Declarations>
      <Language Language="csharp">
        <Code><![CDATA[${SystemConsole.WriteLine($send)}]]></Code>
      </Language>
    </Snippet>
  </CodeSnippet>
</CodeSnippet>
```

This list describes what's in the Header element:

- **Title**: Shows up the combination you use for IntelliSense.
- **Shortcut**: Show up in the tooltip when you mouse over the snippet in Visual Studio.
- **SnippetType**: Defines where the snippet appears on. Common types are Expansion and SurroundsWith. **Expansion means** it inserts there. **SurroundsWith means** it's placed above and below the selection.

The snippet element is where the work is done. In the cw.snippet, there are two elements in Snippet: Declarations and Code. Declarations declares the variables, and Code is what gets inserted. Within these, these statements are true:

- The Literal element describes a variable that will be used in the creation of the snippet.
- In this case, Function tries to get the simplest version of the **System.Console** namespace given the current constraints, and ID names it SystemConsole.

# Sharing snippets

Sharing a snippet is a more complicated act than it should be. One would think that you could just create a .snippet file, send it to someone, and then it is just a matter of.

A snippet sharing escapade has three components:

- **The .snippet itself**: This topic is discussed in the preceding section.
- **The .vscontent file that lists the (even if there is only one):** The .vscontent file is one with a listing of snippets. For instance, here is the .vscontent file that would be used for the previous Console. example.
- **The .vsi file to package it all together**: The .vsi file is a Zip file with a new extension. To make it, literally zip your folder of snippets with the .vscontent file and change the file extension from .zip to .vsi.

Visual Studio users can double-click .vsi files in order to have the vstudio installer handle them. The command line can also be used for more in-depth installs. The complexity of the system on the snippet developer makes sense when you consider that the end user ends with a better experience.
