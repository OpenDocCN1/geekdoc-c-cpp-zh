# Using information from requests

The request is a place that you can collect information about the user's needs and use it. It Especially on postback (though not just then), there is a lot of information that you can use, using the following:

+   - **The content of the request.** The type (ContentType) of the request tells you if it has data or just text. I can learn it if it is ISO or Unicode (ContentEncoding). I also know how long the request is (ContentLength).
- **The text of the request itself.** For instance, I have all the text of the URL (Url) and the request before this one (UrlReferrer). If I just want the querystring (part after the question mark), I can get it with QueryString.
- **Whether the user is logged into a domain** (IsAuthenticated) and if so, who the user is (LogonUserId).
- **Access to the collections** (Cookies).

When you have access to the request, you can make decisions about content. If you need to know about their login information, you have check. A cookie — no problem. Confirm the querystring. Whatever needs to be done. You get information to the business layer, get what you need back, compose the new page of controls, and then need to modify the response. That's when you need the `HttpResponse` class.
