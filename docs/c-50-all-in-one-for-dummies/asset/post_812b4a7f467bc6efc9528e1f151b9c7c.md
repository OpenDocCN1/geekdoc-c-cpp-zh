## Asynchronous I/O: Is it worth waiting?

Normally, a program waits for a I/O request to complete before continuing. Call a `read()` method, and you generally don't get control back until the file data is safely in the buffer. This is known as synchronous I/O. Synchronous means "while you wait."

Using asynchronous I/O, you can start cutting up the onions while the hamburger patties are cooking. Once in a while, you peek over to see if the meat is done. When it is, you stop cooking, take the meat off, and slap it on the buns.

The `.IO` classes also support asynchronous I/O. Using asynchronous I/O, the `read()` returns immediately to allow the program to continue doing something else while the I/O request is completed in the background. The program can check a "done" flag at its convenience to decide when the I/O has completed.

Asynchronous I/O, and other asynchronous functionality, is a core part of C# 5.0. Any operation that should take more than 50 milliseconds to complete should be asynchronous in the Windows Store. Of course, web applications or your WPF apps don't have to follow that standard. In looking towards the future, and with Windows 8, I cover asynchronous methods in the bonus materials.

This is like cooking hamburgers. Using synchronous I/O, you put the meat in the pan and stand by the stove and wait until the meat has completed before you go.

FileStream isn't the only class that can perform I/O. However, it represents your basic file stream that covers 90 percent of your I/O needs. This primary class is the one described in this chapter. If it's good enough for C#, it's good enough for me.

The stream concept is fundamental to I/O. Think of a parade where "streams" are horses. Viewing a file as a stream of bytes (or characters) is much like a parade. A "stream" is the data in and out of your program. The .NET classes used in C# include an abstract Stream base class and several subclasses for working with files on the disk, over a network, or already sitting as chunks of data in memory. Some stream specialize in encrypting and decrypting data, which are provided to help speed up I/O operations that might be slow. You're free to extend Stream with your own subclass if you come up with a great idea for a new stream (although you learn that extending classes in the later section "Exploring More Streams").

# Going Where the Fish Are: The FileStream

## Readers and writers

FileStream, the stream you'll probably use most, is a basic class. Open a file, close a file, read a block of bytes, and write a block — that's about all. But reading and writing files at the byte level is a lot of work.

When you create a new reader (one of several available types), you associate a stream with it. It is immaterial whether the stream connects to a file, a block of memory, or a network. The reader requests input from the stream, which gets it from. Using readers is quite simple, except that you're sending output to the stream rather than asking for input. The stream sends it to a specified destination. Often that is file, but not always. The System.IO namespace contains classes that wrap around FileStream (or other streams) to give you easier access and usage:

- TextReader/Writer: A pair of abstract classes for reading characters (text). These classes are the base for two subclasses: StringReader/StringWriter and StreamReader/StreamWriter.
- StreamReader/StreamWriter: A more sophisticated reader and writer for more — not to mention they aren't abstract, you can even read and write with them. For example, StreamWriter has a WriteLine() method that works like the Console class. StreamReader has a corresponding ReadLine() method and Read() grabs the whole text in one line — which you could then use with a foreach loop, the String.Split() method, and so on.

One thing about reader/writer classes such as StreamReader and StreamWriter is that you can use them with any kind of stream in this chapter. This makes reading from and writing to the kind of FileStream discussed in earlier sections easier than the section "Exploring More Streams".

The following sections provide FileWrite and FileRead programs which demonstrate ways to use these classes for text I/O.

Programs generate two kinds of outputs:

- Some programs write blocks of data in binary format. This output is useful for storing objects in an efficient way — example, a file of objects that you need to persist (keep on disk a permanent file).
- Most programs read and write human-readable text: you know human-readable data was formerly known as ASCII, or slightly later, ANSI. These refer to the standards that defined them. However, ANSI encoding provides only Roman letters used in English. It has no characters for Russian, Hebrew, Hindi, or any other language using a non-Roman alphabet, including Asian languages as Chinese, Japanese, and Korean. The modern, more flexible Unicode file format is "backward-compatible" — including the ANSI characters at the beginning of its character set, but still providing a large number of other alphabets, including everything for the languages I just listed. Unicode comes in several variations, called encodings; however, UTF8 is the default encoding for C#. (You can find out more about encodings and how to use them in the article "Converting between Byte and Char Arrays" at csharp12.info.)

## Using the stream: An example

The following StreamWriter program reads lines of data from the console and writes them to a file of the user's choosing. This is pseudocode — it isn't meant to compile. I used only as an example.

```csharp
// FileWrite -- Write input from the Console into a text file.
using System;
using System.IO;

namespace FileWrite
{
    public class Program
    {
        public static void Main(string[] args)
        {
            // Get a filename from the user -- the while loop loops
            // keep with different filenames until you succeed.
            StreamWriter sw = null;
            string fileName = "";
            while (true)
            {
                // Enter filename (simply Enter to quit).
                Console.Write("Enter filename: ");
                fileName = Console.ReadLine();
                if (fileName.Length == 0) // this jumps beyond the while
                    // loop to stop. You're done.
                    break;
            }
            // Factored out these tasks to simplify the loops a bit.
            sw = new StreamWriter(fileName);
            // Read one string at a time, outputting each to
            // FileStream open for writing.
            WriteFileFromConsole(sw);
            // Done writing, close the file you just created.
            sw.Close(); // A very important step. Close the file too.
            sw = null; // Give it to the garbage collector.
        }
        catch (IOException io)
        {
            // Error occurred during the processing of the
            // file -- tell the user the name of the file:
            // Tack the name of the default directory to the filename.
            string dir = Directory.GetCurrentDirectory(); // Directory class
            string path = Path.Combine(dir, fileName); // System.IO.Path class
            Console.WriteLine("Error on file " + path);
        }
    }
}
```
