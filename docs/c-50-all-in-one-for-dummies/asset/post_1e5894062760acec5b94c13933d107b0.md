## Using Dynamic Import

Many COM methods accept and return variant types, which are represented by the primary Interop assemblies as objects. In most cases, a programmer calling these methods already knows the static type of a returned object from context, but explicitly has to perform a cast on the returned value to make use of that knowledge. These casts are so common in day-to-day development that they constitute a major nuisance.

To create a smoother experience, you can import these COM APIs in such a way that variants are represented using the type dynamic. In other words, from your point of view, COM signatures have occurrences of dynamic instead of object in them.

This means that you can easily access members directly off a returned object, or you can assign an object to a strongly typed local variable without having to cast. To illustrate, you can say

```csharp
excel.Cells[1, 1].Value = "Hello";
```

instead of

```csharp
{Excel.Range}excel.Cells[1, 1].Value2 = "Hello";
```

and

```csharp
Excel.Range range = excel.Cells[1, 1];
```

instead of

```csharp
Excel.Range range = {Excel.Range}excel.Cells[1, 1];
```

Why is this a big deal? One is that it simplifies the programmer’s work. Code from Microsoft Office is tremendously difficult to read. Take a look at this code from an Office application I wrote for the Vis For Dummies book:

## Working without Primary Interop Assemblies

Speaking of PIAs (excuse the similarity to another well-known, acronym), they are handled a lot better in .NET 4.0.

PIAs are large .NET assemblies generated from COM interfaces to facilitate strongly typed interoperability. They provide great support at design time, where your experience of the Interop is as good as if the types were really defined in .NET. However, at runtime these large assemblies can easily build your program and also cause versioning issues because they are distributed independently of your application.

The no-PIA feature allows you to continue using PIAs at design time without having them around runtime. The C# 4.0 compiler makes the small part of the PIA that a program actually uses directly into its assembly. The PIA doesn't have to be loaded at runtime.

To see how, these steps work in Visual Studio 2012 and Visual Studio 2010 (if you have):

1. Create a console application by choosing File: New::Project and picking C# - Console application and name your project PIAs.
2. After the project loads, right-click References.
3. Click Add Reference.
4. Select Microsoft.Office.Interop.Excel, version 12, if you have it, or the latest version you have loaded.
5. Click OK.
6. Add using Microsoft.Office.Interop.Excel; to the header.
