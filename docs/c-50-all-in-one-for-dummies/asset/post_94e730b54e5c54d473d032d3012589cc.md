## Introducing WPF

### List 1-1: App.xaml

```xml
<Application x:Class="MyFirstWPFApplication.App"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    StartupUri="MainWindow.xaml">
    <Application.Resources>
  </Application.Resources>
</Application>
```

List 1-1 displays the XAML that was generated by the WPF Application template in Visual Studio. The WPF namespaces are defined. The namespace that represents the CLR objects will be distinguished in the XAML file with the .x prefix.

The StartupUri defines the window that will be displayed after the application is executed. In this case, the MainWindow.xaml will be displayed.

The x:Class attribute defines the C# code-behind of this XAML file. If you open App.xaml.cs, you see that its class name is App and it inherits from the Application class (which is the root element of the XAML file).

C# namespaces organize and locate classes. In order to locate objects from a specific namespace, you use the "using" syntax at the top of your class definitions. Similar to C#, XAML also requires you to declare which namespaces are used in the document. Namespaces are typically defined as an attribute within the root element of the document; the first XML tag in the XAML document. XAML uses XML syntax to define a namespace — "xmlns" means "XML namespace," and it's typically followed by a colon (:) and an alias. This is the shorthand reference to the namespace the XAML document; it's what you use to instantiate an object from a class in that namespace.

For instance, if you want to add the namespace MyTemplates.DataTemplates from the assembly MyTemplates.dll, you could define the namespace as

```xml
xmlns:myDTS="clr-namespace:MyTemplates.DataTemplates;assembly=MyTemplates.dll"
```

You are then able to instantiate an object from the MyTemplates Templates namespace as follows:

```xml
<myDTS:myClass/></myDTS:myClass>
```

## Declaring an application-scoped resource

+ 1. Add the System namespace located in the mscorlib.dll assembly. This is where the String class is located.

+ 2. To do this, add the following name to the App.xaml root element:
`xmlns:sys="clr-namespace:System;assembly=mscorlib"`

+ The String class is now available for use through the App.xaml document.

+ 3. Create the resource between the Application.Resource tags, add the following String class element:
`<sys:String x:Key="Hello WPF!"</sys:String>`

This element instantiates an object of type String, initialized to the value Hello WPF!, and keyed off of the key Purpose. This resource is now available throughout the MyFirstWPFApplication by requesting the resource "Purpose" (see Listing 1-2).

### List 1-2: Updated App.xaml with Resource and System Namespace Defined

```xml
<Application x:Class="MyFirstWPFApplication.App"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:sys="clr-namespace:System;assembly=mscorlib"
    StartupUri="MainWindow.xaml">
    <Application.Resources>
      <sys:String x:Key="Hello WPF!"</sys:String>
    </Application.Resources>
</Application>
```
