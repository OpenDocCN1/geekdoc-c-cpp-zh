The catch block is like a soccer goalie: it's there to catch any file error that may have occurred in the program. The catch outputs an error message, including the name of the err file. It doesn't output a simple filename—it outputs the entire filename, including the path, for your pleasure. It does this by using the Path.Combine() method to track the current directory name, obtained through the Directory class, onto the file you entered. (Path is a class designed to manipulate path information. Directory provides properties and methods for working with directories.) Block gives you the goods on exceptions, including the exceptions to exceptions, the exceptions to those—I give up.

![](bbox=[0.139, 0.303, 0.239, 0.403])

The path is the full name of the file folder. For example, in the file c:\user\directory.txt, the path is c:\user directory.

The Combine() method is simple enough to realize that for a file like c:\test.txt, the path isn't in the current directory. Path.Combine() is also the safest way to ensure that two path segments combine correctly, including a path separator between them. (Windows, the path separator is \. You can obtain the correct separator for whatever operating system your code is run, with Path.DirectorySeparatorChar. The .NET Framework library is full of features like that, clearly aimed at C# programs that run on multiple operating systems, such as Mono for Linux and Unix, which I discuss in this book's Introduction.)

Upon encountering the end of the while loop, either by successfully completing the try block or being vectored through the catch, the program returns to the top of the while loop allowing the user to write to another file.
