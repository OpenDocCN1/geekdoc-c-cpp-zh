# 466 Using the System.Net Namespace

```
private void button1_Click(object sender, EventArgs e)
{
    DownloadFile("ftp://ftp.server/sampleFile.bmp", "c:\sampleFile.bmp");
    SendEmail(textBox1.Text, textBox2.Text,
    "FTP Successfully downloaded");
}
```

Notice that I sent in the text box: once for the address, and once for the from address. This isn't always necessary, because you may have a situation where you want the e-mail to come only from a Webmaster address or to go only to your address.

You should have enough code in place to run the application. Press F5 to launch the application in debug mode and give it a try.

When you click the button, the application should download the file to the local drive and then-email you to inform you that the download is complete. A host of things can go wrong with network applications, though, and you should be aware of them. Here are a few:

+   * For most activity, the machine running the software must be connected to a network. This isn't a problem for you as the developer, but you need to be conscious of the end users, who may need connectivity to access the features you want to use. Use of the network status code can help inform users about the availability of these features.
* Firewalls and other network appliances sometimes block network traffic from legitimate applications. Some of these include
* FTP is often blocked from corporate networks.
* Network analysis features of .NET are often blocked on corporate servers. If the server is available to the public, these openings can holes for hackers to crawl through.
* Speaking of hackers, make sure that if you are using network features in your application, you adequately secured your application. More on this can be found in the excellent book Writing Code, Second Edition, by Michael Howard and David C. LeBlanc (Microsoft Press).
* E-mail is especially fragile. Internet service providers will block email from an address that is not registered on a mail server. This means that if you are using your local server (like in the example in Listing 4-2), your ISP might block the e-mail.

Network traffic is notoriously hard to debug.
