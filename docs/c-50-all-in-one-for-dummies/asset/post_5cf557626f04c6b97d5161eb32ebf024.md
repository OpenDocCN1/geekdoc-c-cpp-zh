## Coding in the Code Editor

If you go back to the design view and double-click on the Button control you dragged over, you will see something a little more familiar than all of this crazy markup. Usually the code-behind, this is the C# code that makes the form manageable by the server. The code-behind is in a file Default.aspx.cs, below Default.aspx in its Solution Explorer tree. This code should look like this:

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Web;
using System.Web.UI;
using System.Web.UI.WebControls;

namespace AspNetFirstSample
{
    public partial class _Default : Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
        }

        protected void ChangeText_Click(object sender, EventArgs e)
        {
        }
    }
}
```

I'll break this down for a little. I know you've seen a class before, and that's all this is, but I want to point out a few things:

- * This is a partial class. The rest of this class is built-in web functionality, and it used to appear in this file. In fact, no one ever needed to edit it, so Microsoft tolled it out. I'm glad they did. This is a lot easier to look at.
- * The class inherits from System.Web.UI.Page. The Page class provides all the tools you need to keep control of controls in the page together. This is very important for some web applications, but it's a little beyond the scope of this book. Read the documentation for the Page class. It's an important part of ASP.NET.
- * There is an event handler for Page.Load. Remember the ASP.NET load sequence in Chapter 1? (Recall requests sequence and postbacks?) This is important. You can do setup operations in this handler.
- * There is an event handler for Button.Click. Hey, how did this get there? You double-clicked the control to get the default handler, just like I talk about in. Depending on your background, this feels very familiar or very foreign. This is not like classic Active Pages.

## Adding functionality with C#

Start by making the form do something. Code View basically allows the developer to write code that does something useful with the web form. Here keep it simple, but it can get much more complex. There is already an event handler for Button.Click, so I suggest using that method to change the text of the label. The label ID was TextChange, so you need to add this code:

```csharp
OnChange.Text = "It has changed!";
```

That was simple. You need to know this will be the simplest event handler you will ever write, however. Run the application by pressing F5. If you made a mistake, it should build. ## Using Page.Load to add more functionality

Now the client wants something to happen when the page loads. Pretend “something” is dynamic. It isn't gonna be dynamic for this example, but it could be. Because of the nature of ASP.NET and programming in general for Windows, you can't always code properties in the design time — especially for events. Sometimes you need to manually write an event handler to deal with an event. That is what you are going to do — from the Code View this time. Last follow these steps to write your event handler:

- 1. Start by writing an event handler in Code View.

```csharp
protected void ChangeColor(object sender, EventArgs e)
{
    TextToChange.BackColor = System.Drawing.Color.Red;
}
```

![](img/6df7bb88e9302e9844acc219bd7fc_0.png)

No event arguments are required in C# 5.0, if you're planning on using them. If you want the forms to work properly, however include them.

- 2. Change back to Design view and select the TextToChange label.
- 3. Open the Properties panel and click the lightning bolt at the top. This changes the Properties panel into an Event panel of sorts.
- 4. Click the Load event under the Misc drop-down list, as shown in Figure 2-5.
- 5. Pick the ChangeColor method you created in Step 1.
- 6. Run the application again.

The background color of the label should be set to red.

# Recognizing the other file types

I am sure you get the idea at this point on the ASPX markup file. There are ASPX files that have markup, and there are ASPX.CS files that have C# code. That's the core of the ASP.NET model.

![](img/6df7bb88e9302e9844acc219bd7fc_0.png)

**Figure 2-5:** The Event panel.

If you've ever done any web development, you know that there are other files that you used. Lots of all other files get used, in fact. Visual Studio has a place for nearly all those other files. Table 2-1 is a breakdown of some of those files, what they are for, and how they are accessed.

### Table 2-1
Web Application File Types
| File Type | What It Does | How Visual Studio Handles It |
| :--- | :--- | :--- |
| Stylesheets (.css files, usually) | Controls how the page looks. For CSS, check out HTML and CSS For Dummies. | Visual Studio has a fantastic CSS handler. I like it more than the suppressed ones from Blend. |
| JavaScript Files | Handles client-side interactivity. | Now that Microsoft supports AJAX, JavaScript (the j in AJAX) is suddenly a lot more important. JavaScript IntelliSense is supported now, as well as real debugging. |
| Images (GIFs, JPEGs, and PNGs) | Making pretties. | Don't depend on Visual Studio to edit your images. Use Photoshop, or a merged product or suite like Expression Blend. |
| User Controls (ASCX) | I deal with these in Chapter 4, but basically they are a way to combine controls to do something specific. | Perfect support, and always has been. Visual Studio wants to reuse code, so do it! |
