Mocking frameworks create proxy objects based on interfaces. For the single event, create an interface (shown in Listing 14-16) that has the required signa-ture the event handler — in this case, the PropertyChanged event.

# Listing 14-16: The Event Subscriber

```
public interface IPropertyChangedChangedSubscriber
{
    void Handler(object sender, PropertyChangedEventArgs e);
}
```

The test starts by creating a mock of subscriber and registering the PropertyChanged event with the handler. The test acts on the Customer object by changing the name and then asserts that the handler was called. The Arg<object>.Is.Anything syntax tells Rhinoocks not to test the arguments for equality. Again, the test is verifying that the event is raised when a property on the Customer object is updated. See the code in Listing 14-17.

# Listing 14-17: Testing an Event Was Raised

```
[Test]
public void Should_Raise_PropertyChanged_Event_On_Property_Change()
{
    var sut = new Customer();
    var args = new PropertyChangedEventArgs(string.Empty);
    var subscriber = MockRepository.GenerateMock<IPropertyChangedSubscriber>();
    sut.PropertyChanged += subscriber.Handler;
    sut.Name = "New Name";
    subscriber.AssertCalled(x => x.handler(Arg<object>.Is.Anything, Arg.Is.Anything));
}
```

In the preceding code, the expression x => x.Handler(...) is an example of a .NET lambda expression. You can find out more about lamb-das and the query expressions that enable them on the website at http://csharp102.info.
