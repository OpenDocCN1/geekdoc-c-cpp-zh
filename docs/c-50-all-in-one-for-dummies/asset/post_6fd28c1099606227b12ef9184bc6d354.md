# Finding Out More about WPF Data Binding 621

WPF provides a number of controls called ItemsControls that allow you to bind collections of objects to them. Examples of ItemsControls are ListBox and ComboBox (among others). Collections are bound to an ItemsControl through the ItemsSource attribute. A data template can also be applied to each object bound through the ItemTemplate attribute.

Through Property inheritance, the ItemsSource of the ListBox is defaulted to the DataContext of Window. The [Binding] element simply states that you use the current binding of its parent, you are setting the DataContext up the element tree until it reaches a place where a binding is set. Remember that in the GenerateData, binding to the list of Servers to the Window itself, so the ListBox will inherit that list as its Source.

The data template was defined in resources to describe a Server Status object will be used to render each object bound. You can see this through the ItemTemplate attribute that uses the StaticResource points to the ServerTemplate that was defined in resources.

# Finding Out More about WPF Data Binding

This chapter is not meant to be inclusive of all functionality possible through WPF’s amazing data binding support. Other aspects of WPF data templates worth looking into include these concepts:

- DataTemplateSelector: This is a base class that allows you to render a data template based on some logical condition.

- Using data templates as a means to provide data adding/editing capabilities to the user.

- Switching a data template at runtime the preference of the user. This allows users to switch a data template at will. For instance, in a ListBox, you may only display summary information; however, you can provide a button in your data template that will enable users to switch between the summary template and a more detailed template on demand.
