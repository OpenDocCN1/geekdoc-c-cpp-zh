The template gives you a few important things.

+   **Configuration**: The configuration of WCF is a bear (as you can see in Chapter 3) and making REST-capable even worse. The template takes care of the details for you.
**File formats**: The files for REST aren't any different from WCF, but how you set them up is.
**Project setup**: Visual Studio helps you set up the project well for a REST project.

One of the changes that the REST template does for you is the routing. Remember that REST is a URI-based format. The routing needs to be set up with the excellent WebServiceHostFactory to direct incoming requests to the appropriate code in the project. All that needs to be in place is the base service (for a default project), but the global.asax file has if you need to add more.

Another place where the configuration is tuned is in the config file. Remember that WCF is essentially IIS add-on. REST projects are extensions of ASP.NET MVC. The web.config is built the project, and you can change it largely without. The routing module especially is important — it makes the code in the global.asax work:

```
<system.webServer>
  <modules runManagedModulesForAllRequests="true">
    <add name="UrlRoutingModule" type="System.Web.Routing.UrlRoutingModule,System.Web, Version=4.0.0.0, Culture=neutral, PublicKeyKey=b03f5f7f71d50ala" />
  </modules>
</system.webServer>
```
