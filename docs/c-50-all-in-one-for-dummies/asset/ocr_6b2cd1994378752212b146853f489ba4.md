# Get Your ViewModel On 643

To create a customer, a list of Sales Regions must be available, so the Customer Repository Fake (as shown in Listing 4-20) uses Constructor Injection to insert the allowable values into the repository. It could have created its own list, but would have thrown off the binding in XAML since the objects would be different.

What is Fake all about? Unit testers need to write a double test: an object that fakes, or simulates, a real object. Often, test doubles are the only way to peek inside an otherwise impenetrable object, or the object does things that you don't want to do during testing. The fake SalesRegion repository in Listing 4-20 is an example of a test double. For more information on Test Doubles and their uses, see the website at http://csharp12.info. Faking certain things for testing purposes is a valid to do. Just don't fake the object you're testing. The objects that it makes use.

# Listing 4-20: Fake Customer Repository

```
public class CustomerRepositoryFake : IRepository<Customer>
    readonly IList<SalesRegion> _salesRegions;

    public CustomerRepositoryFake(IList<SalesRegion> salesRegions)
    {
        _salesRegions = salesRegions;
    }

    public List<Customer> GetAll()
    {
        var list = new ObservableCollection<Customer>();
        var customer = new Customer(Name = "Jane Doe", ID=1, SalesRegion = salesRegions[0]);
        list.Add(customer);
        var customer = new Customer(Name = "John smith", ID=2, SalesRegion = salesRegions[1]);
        list.Add(customer);
        var customer = new Customer(Name = "John Doe", ID = 3, SalesRegion = salesRegions[2]);
        list.Add(customer);
        return list;
    }

    public bool Update(Customer customer)
    {
        throw new NotImplementedException();
    }
```
