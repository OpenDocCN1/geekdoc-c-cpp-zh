## WPF to Lay Out Your Application

Traditional Forms development deals in absolute. Position and size for controls are decided at design time and are based on the resolution of the developer's machine. When applications are deployed to users, the form that looked great on the developer's machine could now look very different (and possibly be downright unusable) because of hardware resolution differences.

Instead of designing on screen resolution, WPF measures UI Elements in Device Independent Units (DIUs) that are based on the system DPI. This enables a consistent look between many different hardware configurations.

WPF layout is based on relative values and is adjusted at runtime. When you place controls in a layout container (see the next section), the rendering engine considers the height and width only as "suggested" values. Location is defined in relation to other controls or the container. Actual rendering is a two-step process that starts with measuring all controls (and querying them for their preferred dimensions) and then arranging them accordingly. If controls could, the conversation might go something like this:

> Layout Engine: "Control <I would like 50 DIUs for height, 100 DIUs for width, and a margin of 3 DIUs in the Grid cell."

> Layout Engine asks all controls and layout containers.

> Layout Engine: "Sorry, you can have only 40 DIUs for height, and I grant the rest of your requests."

> <This is the Arrange Stage>

## New tech, new terms

It seems every time Microsoft introduces a new technology, we have to learn a new whole set of terms. WPF is no different! At the root of the change are what we refer to as Forms and Controls in Windows Forms (WinForms). Here are some of the new terms:

- Panels are WPF UIElements used for layout.
- A Control in WPF is a UIElement that can receive focus and respond to user events.
- A Content in WPF can contain only a single item, which can turn in other UIElements.
- The WPF Window class is a specialized Content control.

## Arranging Elements with Layout Panels

Designing a Window begins with a Layout control, or Panel. Panels are different than Content controls in that they can hold multiple items, and depending on the Panel, a significant amount of plumbing is taken care of you.

Panels control how UIElements relate to each other and their containing UIElement and do not dictate absolute positioning. Most application Windows require some combination of Panels to achieve the required user interface, so it's important to understand them all. WPF ships with six core Panels:

- Stack Panel
- Wrap Panel
- Dock Panel
- Canvas
- Uniform Grid
- Grid
