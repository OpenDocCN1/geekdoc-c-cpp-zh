# Readers and writers

FileStream, the stream you'll probably use most, is a basic class. Open a file, close a file, read a block of bytes, and write a block — that's about all you. But reading and writing files at the byte level is a lot of work, something I esche studiously. Fortunately, the .NET class introduces the notion of “readers” and “writers”. Objects of these types generally simplify file (and other) I/O.

When you create a new reader (one of several available types), you associate a stream object with it. It is immaterial to the reader whether the stream connects to a file, a block of memory, a network location, or the Mississippi. The reader requests input from the stream, which gets it from — well, ever. Using readers is quite simple, except that you're sending output to the stream rather than asking for input. The stream sends it to a specified destination. Often that is file, but not always.

The System. IO namespace contains classes that wrap around FileStream (or other streams) to give you easier access and warm fuzzing:

+   * TextReader/Writer: A pair of abstract classes for reading characters (text). These classes are the base for two subclasses: StringReader/StringWriter and StreamReader/StreamWriter.

Because TextReader and StreamWriter are abstract, you'll use one of their subclass pairs, usually StreamReader/StreamWriter, to do actual work. I explain abstract classes in Book II.

+   * StreamReader/StreamWriter: A more sophisticated reader and writer for the more discriminating palate — not to mention that they aren't abstract, you can even read and write with them. For example, StreamWriter has a WriteLine() method that works like the Console class. StreamReader has a corresponding ReadLine() method and a Read() grabs the whole text in one line, returning the characters read as a string — which you could then use with StreamReader (discussed later), a foreach loop, the String.Split() method, and so on. Check out the constructors for these classes in Help.

You see StreamReader and StreamWriter in the next two sections.

One thing about reader/writer classes such as StreamReader and StreamWriter is that you can use them with any kind of stream. This makes reading from and writing to the kind of FileStream discussed in earlier sections of this chapter. (I cover MemoryStream in the “Exploring More Streams than than Lewis and Clark” section, later in this chapter.)
