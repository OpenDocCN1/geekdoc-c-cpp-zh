## Writing generic code the easy way

Now you have to figure out how to go about writing a generic class with all those <T>. Looks confusing? Well, it’s not so hard as this section demonstrates. The simple way to write a generic class is to write the non-generic version first and then substitute <T>. For example, you would write the PriorityQueue class for Package objects, test it, and then “genericize” it. Here’s a small piece of non-generic PriorityQueue to illustrate:

```csharp

{
    // Queues -- The three underlying queues: non-generic!
    Queue<Package> _queueHigh = new Queue<Package>();
    Queue<Package> _queueMedium = new Queue<Package>();
    Queue<Package> _queueLow = new Queue<Package>();

    // Enqueue -- Prioritize Package and add it to the correct queue.
    public void Enqueue(Package item)
    {
        switch(item.Priority) // Package has this property.
        {
            case Priority.High:
                _queueHigh.Enqueue(item);
                break;
            case Priority.Low:
                _queueLow.Enqueue(item);
                break;
```

## Saving PriorityQueue for last

Why would the priority queue be last? Seems a little backward to me. But it’s time to examine the PriorityQueue class itself. This section shows the code and walks you through it and shows how to deal with a couple of issues. Take it piece at a time.

## The underlying queues

PriorityQueue is a wrapper class that hides three Queue<T> objects, one for each priority level. Here’s the first part of PriorityQueue, showing the three underlying queues (now generic):

```csharp
// PriorityQueue -- A generic priority queue class
// Types added to the queue *must* implement IPriorizable.
class PriorityQueue<T> where T : IPriorizable
{
    // Queues -- The three underlying queues: all generic!
    private Queue<T> _queueHigh = new Queue<T>();
    private Queue<T> _queueMedium = new Queue<T>();
    private Queue<T> _queueLow = new Queue<T>();
    // The rest will follow shortly ...
}
```

These lines declare three private data members of type Queue<T> and initialize them by creating the Queue<T> objects. I say more in the section “Tending to unfinished business,” later in this chapter, about that odd-looking class line above the queue declarations.

## The Enqueue() method

Enqueue() adds an item of type T to the PriorityQueue. This method’s job is to look at the item’s priority and put it into the correct underlying queue. In the first line, it gets the item’s Priority property and switches based on that value. To add the item to the high-priority queue, for example, Enqueue() turns around and enqueues the item in the underlying queueHigh. Here’s PriorityQueue’s Enqueue() method:

```csharp
// Enqueue -- Prioritize T and add it to the correct queue; an item of type T.
// The item must know its own priority.
public void Enqueue(T item)
{
    switch (item.Priority) // Require IPriorizable to ensure this property.
    {
        case Priority.High:
            _queueHigh.Enqueue(item);
            break;
        case Priority.Medium:
            _queueMedium.Enqueue(item);
            break;
        case Priority.Low:
            _queueLow.Enqueue(item);
            break;
        default:
            throw new ArgumentOutOfRangeException(
                item.Priority.ToString(),
                "bad priority in PriorityQueue.Enqueue");
    }
}
```

## The Dequeue() method

Dequeue()’s job is a bit trickier than Enqueue()’s: It must locate the highest-priority underlying queue that has contents and then retrieve the front item from that subqueue. Dequeue() delegates the first part of the task, finding the highest-priority queue that isn’t empty, to a private TopQueue() method (described in the next section). Then Dequeue() calls the underlying queue’s Dequeue() method to retrieve the frontmost object, which it returns. Here’s how Dequeue() works:

```csharp
// Dequeue -- Get T from highest-priority queue available.
public T Dequeue()
{
    // Find highest-priority queue with items.
    Queue<T> queueTop = TopQueue();
    if (queueTop != null && queueTop.Count > 0)
    {
        return queueTop.Dequeue(); // Return front item.
    }
    // If all queues are empty, throw an exception.
    return default;
}
```

A difficulty arises only if none of the queues have any items. What does Dequeue return in that case? Dequeue() should check if it is empty.

## The TopQueue() method

Dequeue() relies on the private TopQueue() method to find the highest-priority queue. It starts with queueHigh and if it’s greater than zero, the queue contains items, so TopQueue() returns a reference to the queue. On the other hand, if queueHigh is empty, TopQueue() tries Medium and then Low.

```csharp
// TopQueue -- What’s the highest-priority underlying queue with items?
private Queue<T> TopQueue()
{
    if (_queueHigh.Count > 0) // Anything in high-priority queue?
        return _queueHigh;
    if (_queueMedium.Count > 0) // Anything in medium-priority queue?
        return _queueMedium;
    if (_queueLow.Count > 0) // Anything in low-priority queue?
        return _queueLow;
    return null; // All empty.
}
```
