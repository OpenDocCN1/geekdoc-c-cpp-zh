FileStream has numerous constructors, each of which defaults or both of the mode and access arguments. However, in my humble opinion, you should specify these explicitly because they have a strong effect on the program's clarity. That's good advice in general. Defaults can be convenient for the programmer but confusing for anyone reading the code.

In the next-to-last line of the GetWriterToFile() method, the program “wraps the newly opened FileStream object in a StreamWriter object, sw. The StreamWriter class wraps around the FileStream object to use a set of text-friendly methods. This StreamWriter is what the method returns.

The first argument to the StreamWriter constructor is the FileStream object to use. That's the wrapping. The second argument specifies the encoding to use. The default encoding is UTF8.

![](bbox=[0.138, 0.517, 0.233, 0.59])

You don't need to specify the encoding when reading a file. StreamWriter writes the encoding type in the first three bytes of the file. The StreamReader reads these three bytes when the file is opened to determine the encoding. Hiding this kind of detail is an advantage that good software libraries provide.

# Finally, you're writing!

After setting up the StreamWriter, the FileWrite program begins reading lines of input from the console (this code is in the WriteFromConsole() method, called from Main()). The program reads when the user enters a blank line; until then, it gobbles whatever it is and gives it into the StreamWriter sw using that class's WriteLine() method.

![](bbox=[0.138, 0.733, 0.233, 0.806])

The similarity between StreamWriter.WriteLine() and Console. WriteLine() is more than a coincidence.

Finally, the stream is closed with the sw.Close() expression. This is important to do, because it also closes the file. (I have to say about closing things in the next section).
