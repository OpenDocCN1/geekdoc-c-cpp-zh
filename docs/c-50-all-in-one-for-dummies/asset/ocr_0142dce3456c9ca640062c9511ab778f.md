# Looking at Named Parameters

Hand in hand with the concept of optional parameters are named parameters. If you have more than one default parameter, you need a way to tell the compiler which parameter you're supplying!

For example, look at the addall method earlier in this chapter, after optional parameters are implemented:

```
public static int addall(int z, int y, int x = 0, int w = 0, int v = 0)
{
    return z + y + x + w + v;
}
```

Clearly, the order of parameters doesn't matter in this implementation, but if this were in a class library, you might not know what the order of the parameters is a non-issue! How would you tell the compiler to skip x and if you want to supply v? In the old days, you would do this:

```
int answer = addall(3,7, , .4);
```

Fortunately, you don't have to do that anymore. Now, with named parameters, you can say

```
int answer = addall(z:3, y:7, v:4);
```

The nonoptional parameters don't have to be named, because the position is assumed they're required anyway. Nonetheless, it's good practice to name them. If you skip naming them, you have to this instead:

```
int answer = addall(3, 7, v:4);
```

You have to admit that is a little harder to read. One would have to go back to the method signature to figure out what is happening.
