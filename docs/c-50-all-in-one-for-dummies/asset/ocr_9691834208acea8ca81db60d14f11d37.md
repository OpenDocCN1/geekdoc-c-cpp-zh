# Securing ASP.NET

Book III, Chapter 1 covers .NET security, and there is a whole book on security that you should read — Writing Secure Code, Second Edition (Microsoft Press) by Michael Howard and DavidLeBlanc. I'm only covering security in this chapter because the AspNetHostingPermission is in the System namespace, and I want to give it a little attention.

ASP.NET security is a complex topic. Visitors to websites are often bypassing the Windows security system often occurs. Then, bypassing—called impersonation—allows IIS to do things on behalf of the user even if it isn't really known to Windows. Remember, just because you put in a username and password doesn't mean that Windows is okay with your credentials.

So ASP.NET websites are run most often with whatever the IIS service is running with. Under normal conditions, the service is a fairly restricted account called Network Service. The fact is, however, that you really have no idea what the permissions will be because a hosting company most likely will be managing that. Your users can have administrative permissions for all you.

You can purposefully restrict the permissions of your users in your code. This prevents someone from finding a way through your code logic to call a method you don't be able to call.

Believe me, it happens.

The general idea is to trust no one, which I harp on in Chapter 1 in Book III. You want to pretend that most people are going to run your code are the enemy. I realize that isn't any fun.
