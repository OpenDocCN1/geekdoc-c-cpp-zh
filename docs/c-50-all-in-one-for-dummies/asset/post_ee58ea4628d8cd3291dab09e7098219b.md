The red stroke is sufficient to indicate that an error has occurred, but it's of little use to the users as they're not informed of the details of the error. A simple way to display the error is to add a tooltip to the TextBox. By adding a Style to your Window that defines a style that will trigger the tooltip when the data is in an invalid state.

```xml
<Window>

    <Style.Triggers>
      <Trigger Property="Validation.HasError" Value="true">
        <Setter Property="ToolTip"
              Value="Binding RelativeSource=(x:Static RelativeSource.Self),Path=(Validation.Errors[0].ErrorContent)" />
      </Trigger>
    </Style.Triggers>
  </Style>
</Window>
```

## Converting your data

WPF provides the capability to cater your user interface to be intuitive for the user. Sometimes this means them to enter data in different formats that make sense to them, giving you the responsibility of translating your data entry into a format allowable by your data source. The same is true versa; you want to translate from your data source into a more intuitive form for the user. A popular use-case for this type of conversion is the string representation of a data value, or if you want to display a red or green circle instead of the values True or False.

WPF makes converting data easy by providing a simple interface called IConverter. This interface contains two methods:

- **Convert:** This method obtains values from the data source and merges them to the form displayed to the user control.
- **ConvertBack:** This method does the opposite — it takes the value from the user interface and merges it into a form that the data source expects.

It is important to note that with these methods, you're not held to the same data type as the value being bound. For instance, your data property being bound could be a Date type, and the Convert method can still return a string value to the user interface.

To demonstrate this feature, create a new WPF application project called BindingSample3. This project is a dashboard application that can show the status of servers on the network. In this project, you implement two user controls, RedX and GreenCheck. You also create a value named BooleanToIconConverter that converts a Boolean False to display the RedX control and a True value to display the GreenCheck control. These values indicate whether the server is available.

A user control is a collection of reusable XAML. It can be made up of any number of elements and is implemented with the same rules as when you implement a normal Window (for instance, you can have only one root element). You can also define properties (including dependency properties!) on user controls.

- 8. Have the BooleanToIconConverter inherit IConverter interface. In the Convert method, if the value is True, it return a new instance of the GreenCheck control. If the value passed in is False, the Convert method return an instance of the RedX control.

Here's the code for BooleanToIconConverter:

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
using System.Windows.Data;

namespace BindingSample3
{
    public class BooleanToIconConverter : IConverter
    {
        public object Convert(object value, Type targetType,
            object parameter,
            System.Globalization.CultureInfo culture)
        {
            if (value != null)
            {
                bool boolValue = (bool)value;
                if (boolValue)
                    return new GreenCheck();
                else
                    return new RedX();
            }
            return null;
        }

        public object ConvertBack(object value, Type targetType,
            object parameter,
            System.Globalization.CultureInfo culture)
        {
            throw new NotImplementedException();
        }
    }
}
```
