# # 3. Use the Tools: Automated Tests

You need a single command to run tests.
If you don't have that, no one will run the tests.

+   - [Catch2](https://github.com/catchorg/Catch2)<sup>1</sup> - popular and well supported testing framework from [Phil Nash](https://twitter.com/phil_nash)<sup>2</sup> and [Martin Hořeňovský](https://twitter.com/horenmar_ctu)<sup>3</sup>
+   - [doctest](https://github.com/onqtam/doctest)<sup>4</sup> - similar to catch2, but trimmed for compile-time performance
+   - [Google Test](https://github.com/google/googletest)<sup>5</sup>
+   - [Boost.Test](https://www.boost.org/doc/libs/1_74_0/libs/test/doc/html/index.html)<sup>6</sup> - testing framework, boost style.

[ctest](https://cmake.org/cmake/help/latest/manual/ctest.1.html)<sup>7</sup> is a test runner for CMake that can be used with any of the above frame-works. It is utilized via the [add_test](https://cmake.org/cmake/help/latest/command/add_test.html)<sup>8</sup> feature of CMake.

You need to be familiar with these tools, what they do, and pick from them.

Without automated tests, the rest of this book is pointless. You cannot apply the practical exercises if you cannot verify that you did not break the existing code.

Oleg Rabaev on CppCast stated:

> > - If a component is hard to test, it is not properly designed.
> > - If a component is easy to test, it is a good indication that it is properly designed.
