Alas, the obvious solution is not always
available. Many reasons exist for not
incorporating libraries in a project. First,
many libraries are not free, and the cost of a
library may be prohibitive, especially if the
license has usage fees in addition to
development fees. Second, a library’s license
may be incompatible with a project’s license.
For example, maybe you are building a
closed source code, but the only available
library has an incompatible open source
license (or vice versa). Third, libraries are
frequently shipped without source code.
Lacking source code makes extending a
library’s functionality impossible. Fourth,
you might require support for a library, but
the vendor might not supply any. Fifth, a
library may ship with an upgrade cycle
incompatible with your own. Sixth, a library
might be incompatible with your toolchain.
Finally, a library may not exist at all for the
functionality you are seeking. Therefore,
