A common scenario that has always caused me trouble is where straight alphabetical sorting doesn't properly represent alpha-numeric strings. The most common example is alphabetical sorting strings such as File1, File10, File2. Naturally, the desired sorting order would be File1, File2, but that's not alphabetical. A custom comparer that will sort the alphabetical part and the numeric part is separated to achieve this common scenario. This is called natural sorting.

Listing 3-1 and Output 3-9 demonstrate a custom sort class that correctly orders alpha strings that end with numbers. Anywhere this sort order is required, the class name can be passed into any of the orderBy or ThenBy extension methods in the following way:

```
string[] partNumbers = new string[] { "SCW10", "SCW1",
    "SCW2", "SCW11", "NUT10", "NUT1", "NUT2", "NUT11" };
```

```
var custom = partNumbers.OrderBy(s => s,
    new AlphaNumberSort());
```

The code in Listing 3-12 checks if either input string is null or empty. If either string is empty, it returns the result from the default comparer (no specific alpha-numeric string to check). Having determined that there are two actual strings to compare, the trailing section of each string is extracted into the variables numericX and numericY. If either string doesn't have a trailing section, if no trailing numeric section exists for one of the strings, a straight string compare is adequate). If both strings have a trailing numeric section, the alpha part of the strings is compared. If the strings are different, the result of the default comparer is returned (if the strings are different, the numeric part of the string is irrelevant). If both alpha parts are the same, the numeric values in numericX and numericY are compared, and that result is returned. The final result is that all strings are sorted alphabetically, and where the string part is the same between elements, the numeric section controls the final order.
