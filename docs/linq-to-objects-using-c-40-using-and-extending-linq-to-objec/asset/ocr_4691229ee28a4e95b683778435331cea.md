To understand how the Join operator works, the basic pseudo-code carries out is as follows:

+   1. Create a grouping on the inner sequence function value for all elements that share the inner key selector function value (as determined by the innerKeySelector argument). Call this list of groups lookup.
2. Iterate the outer sequence. Call each element item.
   a. Create a grouping on the lookup sequence for all elements that share the same outer-key selector function value as this item (as determined by the outerKeySelector argument). If a comparator argument is supplied, use this comparator to calculate the equality.
   b. If there are any items in this grouping result
      i. Loop through all elements in this group
      ii. Yield the result returned by the result selector on each element (using the resultSelector)

The returned sequence will be in the order of the outer sequence elements, one record for each matching inner element, followed by the outer element's records. Outer elements without matching inner elements will be skipped. (I think you get that by now—this is an inner join. If you want the unmatched elements, see the “Simulating Outer Joins—Getting Unmatched Elements” section.)

The key selection expression for the outer and inner sequence can be any expression that evaluates to a comparable type. The equals operator (what is called when you do an evaluation) will determine if the keys are equal or a custom EqualityComparator can be supplied to customize this equality comparison in the same way a custom equality comparator was used in the grouping examples earlier in this chapter. (See the “Specifying Your Own Key Comparison Function” section.)

From the final query select projection, you have access to both sequences’ matching elements. The range variable can be used for both the inner and outer records throughout the query and referenced within the selection projection to create a new type or an anonymous type.
