```csharp
Console.WriteLine();

    new { LastName = "Doherty",

```

```csharp
// compiler optimization - from the C# specification:
// within the same program, two anonymous object
// initializers that specify a sequence of properties of
// the same names and compile-time types in the same order
// will produce instances of the same anonymous type.
var p1 = new { Name = "Lawnmower", Price = 495.00 };
var p2 = new { Name = "Shovel", Price = 26.95 };
p1 = p2; // valid: the same anonymous type.
```

The importance of anonymous types becomes evident when writing queries that build collections using a subset of properties from an existing type (known as a projection). Imagine if working with a relational database you cannot define the column list to be used as the return of an SQL query. The same issue occurs with LINQ; without anonymous types, you would need to define a concrete type for each and every return set that altered the columns of interest. Optional parameters added in C# 4.0 (covered in Chapter 4, “Grouping and Joining Data”) make this somewhat easier; anonymous types should be considered when results are needed temporarily.

Beyond their usefulness of supporting LINQ, anonymous types allow temporary data structures to be created during processing of that data. It was often necessary to build a plain, old class with nothing more than property declarations to support holding data; anonymous types fulfill the need perfectly. Although it is possible to pass anonymous types beyond the method that declared them by declaring an argument type as Object, this is highly discouraged. When using anonymous types outside of LINQ functionality, keep the scoping to the method they are, otherwise define a concrete type or struct.

# Lambda Expressions

Lambda expressions build upon the anonymous methods feature added in C# 2.0. Anonymous methods added the ability to inline the code by using the delegate keyword, which provided a more concise way to write methods. Lambda expressions introduced in C# 3.0 provide an even more concise syntax by using the `=>` operator. A lambda expression consists of a parameter list and an expression or body. This syntax allows for the omission of the delegate keyword and the parameter types, as the compiler can infer them from the context. Lambda expressions are particularly useful in LINQ queries to define filters and projections.

While lambda expressions can be used on their own, they are frequently used as arguments to methods that take a delegate as a parameter. This is a common pattern in LINQ methods like `Select`, `Where`, and `OrderBy`. By using lambda expressions, code becomes more readable and maintainable compared to using traditional anonymous methods or separate delegate definitions.
