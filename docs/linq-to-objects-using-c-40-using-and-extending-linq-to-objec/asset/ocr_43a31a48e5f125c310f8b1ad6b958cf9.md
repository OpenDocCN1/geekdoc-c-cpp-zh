Although it is completely up to the implementer to decide behavior for empty and null source query collections, following the same pattern used for the standard query operators is highly recommended, as it makes consuming your custom operators the same as the other LINQ operators. The general conventions are as follows:

+   1. If the source collection being extended is null, throw an ArgumentNullException.
2. If the source collection is empty, throw an InvalidOperationException.
3. Provide a variation of the operator with the suffix of "OrDefault" that does not raise the InvalidOperationException, but returns the value default(T) instead.

+   - The source sequence is null.
- The source sequence has no elements (is empty).
- The source sequence implements IList.
- The source sequence implements IEnumerable<T>.

These tests, in Listing 7-4, are the minimum required for the RandomElement operator, and lightly confirm both the IList<T> and IEnumerable implementations with a single element and a two-element source. Pay attention to boundary conditions when writing these tests; my first attempt at coding this operator returned the last element—the unit tests allowed me to find and correct this error quickly.
