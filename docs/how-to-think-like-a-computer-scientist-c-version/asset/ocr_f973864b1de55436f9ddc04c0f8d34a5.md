Unfortunately, many C++ compilers do not catch this error. By now you are probably sick of seeing compiler errors, but as you gain more experience, you will realize that the only thing worse than getting a compiler error is not getting the compiler when your program is running.

In this case this kind of thing is likely to happen: you test absoluteValue with several values of x and it may work correctly. Then you give your program to someone else and they run in another environment. It fails in mysterious way, and it takes days of debugging to discover that the problem is an incorrect implementation of absoluteValue. If only the compiler had warned you!

From now on, if the compiler points out an error in your program, you should not blame the compiler. Rather, you should thank the compiler for finding your error and sparing days of debugging. Some compilers have an option that tells them to be strict and report all the errors they can find. You should turn this option on all the time.

As an aside, you should know that there is a function in the math library fabs that calculates the absolute value of a double—correctly.

# 5.2 Program development

At this point you should be able to look at complete C++ functions and tell what they do. But it may not be clear yet how to go about writing them. I am going to suggest one technique that is incremental development.

As an example you might want to find the distance between two points, given by the coordinates (x1, y1) and (x2, y2). By the usual definition,

```
$distance = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$
```

The first step is to consider what a distance function should look like in C++. In other words, what are the inputs (parameters) and what is the output (return value).

In this case, the two points are parameters, and it is natural to represent them using doubles. The return value is the distance, which will have type double.

Already can write an outline of the function:

```
double distance (double x1, double y1, double x2, double y2) {
  return 0.0;
}
```
