$$a[i][j] \leq a[i][j+1]$$

+   - $a_{11} \leq a_{12} \leq \cdots \leq a_{1n}$
+   - $a_{21} \leq a_{22} \leq \cdots \leq a_{2n}$
+   - $\vdots$
+   - $a_{m1} \leq a_{m2} \leq \cdots \leq a_{mn}$

4. Entries in each column are ordered by $\leq$, i.e., for $0 \leq i < m$ && for $0 \leq j < n$

$$a[i][j] \leq a[i+1][j]$$

+   - $a_{11} \leq a_{21} \leq \cdots \leq a_{m1}$
+   - $a_{12} \leq a_{22} \leq \cdots \leq a_{m2}$
+   - $\vdots$
+   - $a_{1n} \leq a_{2n} \leq \cdots \leq a_{mn}$

With the properties above, we have to develop an efficient algorithm to find the position of a given integer $x$ in the array $a$, i.e., the algorithm should find $i$ and $j$ such that $x = a[i,j]$. By efficient we mean to minimize the number of comparisons as much as possible.

Let us treat the input array as some kind of a rectangular region.

The problem demands that the integer $x$ does exist somewhere in this region. Let us label this condition as *Input Assertion* or *Precondition*.

# Precondition (aka *Input Assertion*)

$$x \in a[0..m-1, 0..n-1]$$

i.e., $x$ is present somewhere in this rectangular region $a$.
