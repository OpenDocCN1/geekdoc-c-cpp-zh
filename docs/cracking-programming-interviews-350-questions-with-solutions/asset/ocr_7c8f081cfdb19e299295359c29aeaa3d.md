```
1: if ? then
2:     a ← (a + b) / 2
3: else if ? then
4:     b ← (a + b) / 2
5: end if
```

Each command must maintain the invariant P. To find a suitable condition for the first command, first calculate

(a + b) / 2 < b ≤ n + 1 ∧ ((a + b) / 2)² ≤ n ∧ b² > n

The precondition will be the invariant together with the condition of the loop

P ∧ a + 1 ≠ b

The extra condition needed is ((a + b) / 2)² ≤ n, so we take it as the condition for the first command. In a similar fashion, the condition for the second command is found to be ((a + b) / 2)² > n. Introducing a fresh variable d to save local calculations, we arrive at the program

```
1:  a ← 0
2:  b ← n + 1
3:  Invariant: P : a < b ≤ n + 1 ∧ a² ≤ n < b²
4:  bound t: b − a + 1
5:  while a + 1 ≠ b do
6:      d ← (a + b) / 2
7:      if d × d ≤ n then
8:          a ← d
9:      else if d × d > n then
10:         b ← d
11:     end if
12: end while                                      ▷ a² ≤ n < (a + 1)²
```

It may seem that the technique of halving the interval was pulled out of a hat. It is simply one of the useful techniques that programmers must know about, for its use often speeds up programs considerably. The execution time of this program is proportional to log n, while the execution time of the program developed earlier is proportional to √n.

This program illustrates another reason to introduce a variable d: d has been introduced to make a local optimization. The introduction of d not only reduces the number of times the expression (a + b) / 2 is evaluated, it also makes the program more readable.

Note that no definition is given for d. Variable d is essentially a constant.
