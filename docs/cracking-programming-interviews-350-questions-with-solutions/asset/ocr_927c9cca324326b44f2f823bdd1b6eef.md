Now, consider execution of $h \leftarrow h+1$. Under what conditions does its execution leave $p$ true? The condition for this command must obviously imply $f[h] \ne g[k-1]$, but we want the condition to be simple. As it stands, this seems out of the question.

Perhaps strengthening the invariant will allow us to find a simple job. One thing we have not tried to exploit is moving through the arrays in a synchronized fashion, the invariant does not imply this at all. Suppose we add to the invariant the conditions $f[h-1] < g[k]$ and $g[k-1] < f[h]$, this might provide the synchronized search that we desire. That is, we use the invariant

$$P: 0 \le h \le F \land 0 \le k \le G \land f[h-1] < g[k] \land g[k-1] < f[h]$$
$$C: (i: 0 \le i < h: f[i] \ne g[0 \ldots G-1]) \land (j: 0 \le j < k: g[j] \ne f[0 \ldots F-1])$$

Then the additional condition $f[h] < g[k]$ yields

$$g[k-1] < f[h] < g[k]$$

so that $f[h]$ does not appear in $G$, and increasing $h$ will maintain the invariant. Similarly the condition for $k \leftarrow k+1$ will be $g[k] < f[h]$.

This gives us our program, written below. We assume the existence of virtual values $f[-1] = g[-1] = -\infty$ and $f[F] = g[G] = +\infty$; this allows us to dispense with worries about boundary conditions in the invariant.

```
Algorithm 10  The Non-Crooks Program
```text
 1: h ← 0, k ← 0, c ← 0
 2: invariant p; bound c = F − p + G − q
 3: while f ≠ F ∧ g ≠ G do
 4:     if f[h] < g[k] then
 5:         h ← h + 1
 6:         c ← c + 1
 7:     else if f[h] = g[k] then
 8:         h ← h + 1
 9:         k ← k + 1
10:     else if f[h] > g[k] then
11:         k ← k + 1
12:         c ← c + 1
13:     end if
14: end while
15: Add to c the number of unprocessed elements of f and g:
16: c ← c + F − h + G − k
