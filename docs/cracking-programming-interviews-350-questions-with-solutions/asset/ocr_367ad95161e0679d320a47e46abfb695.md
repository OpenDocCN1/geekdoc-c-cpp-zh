Algorithm 29 Counting Sort Algorithm
1: function COUNTING-SORT(A, B, k)
2:     for i ← 0 to k do
3:         C[i] ← 0
4:     end for
5:     for j ← 1 to length[A] do
6:         C[A[j]] ← C[A[j]] + 1    ▷ C[i] now contains the number of elements equal to i.
7:     end for
8:     for i ← 1 to k do
9:         C[i] ← C[i] + C[i - 1]   ▷ C[i] now contains the number of elements ≤ i.
10:    end for
11:    for j ← length[A] downto 1 do
12:        B[C[A[j]]] ← A[j]
13:        C[A[j]] ← C[A[j]] - 1
14:    end for
15: end function

# ### Time Complexity

+   1. The for loop of lines 2-4 takes time Θ(k),
+   2. the for loop of lines 5-7 takes time Θ(n),
+   3. the for loop of lines 8-10 takes time Θ(k), and
+   4. the for loop of lines 11-14 takes time Θ(n).

Thus, the overall time is Θ(k + n).

In practice, we usually use counting sort when we have k = O(n), in which case the running time is Θ(n).

Counting sort beats the lower bound of Ω(n log n) because it is not a comparison sort. In fact, no comparisons between input elements occur anywhere in the program. Instead, counting sort uses the actual values of the elements to index into an array. The Θ(n log n) lower bound for sorting does not apply when we depart from the comparison-sort model.
