
## 1.9.1 Call-by-Value vs. Call-by-Reference

When arguments are call-by-value it implies that copies of any variables within the parameter list are made as they are called. So, in Source 1.20, copies of a and b in the body of Product() are made during execution and not a and b themselves. This works but can be inefficient when dealing with large numbers of parameters and function calls in a program. In order to get around this problem, we can use call-by-reference which passes the memory address of the argument variables to the function body which can then act directly on the variables and dynamically change them as required. Changing the value of the variable stored in the allocated memory is the same as changing the value of the variable itself. If we are passing an argument by reference to a parameter x on its body, then x is an alias for a and both share the same address in memory. It essentially acts on a, so it changes, it changes a as well. In order to pass an argument by reference, the reference operator (&) is placed in front of both the function prototype and definition.

A major disadvantage of using references in lists is that the function is able to modify the inputs. What we ideally need is the address of a variable while at the same time not being able to modify it in any way. In this case call-by-value, call-by-reference and constant reference are used to control access to arguments in a function.

## 1.9.2 Overloading Functions

In C++, it is possible to create functions that have the same type and name but
different number of parameters or data types. This is known as overloading a
function (or polymorphism). The main reason for overloading functions would be
where two or more functions perform similar tasks but different parameters.
For example, we could use overloading to declare two swap() functions; one that accepts integer values and another that accepts doubles as shown in
Source 1.22.

## SOURCE 1.22: OVERLOADING THE FUNCTION swap()

```cpp
// Function prototype
void swap(int &i, int &j);
void swap(double &k, double &m);

int main() {
    SetConsoleTitle(L"Console Output");

    //declare variables
    int i = 1, j = 2;
    double k = 2, m = 3;

    cout << "\n" << " i = " << i << " << " << " j = " << j << "\n";
    swap(i,j);
    cout << "\n" << " i = " << i << " << " << " j = " << j << "\n";

    cout << "\n" << " k = " << k << " << " << " m = " << m << "\n";
    swap(k,m);
    cout << "\n" << " k = " << k << " << " << " m = " << m << "\n";

    cin.get();
    return 0;
}

// Function definition (integers)
void swap(int &i, int &j) {
    int t;
    t=i;
    i=j;
    j=t;
}

// Function definition (doubles)
void swap(double &k, double &m) {
    double t;
    t=k;
    k=m;
    m=t;
}
```

## 1.10 OBJECT ORIENTED PROGRAMMING

As already mentioned, only those parts of the C++ language that we need to successfully implement the tools and techniques in the rest of the book have been covered.
However, one very useful development in C++, and something we will make great use of this book, is the concept of Object-Oriented Programming (OOP). OOP allows building of large and complex programs that can be broken down into smaller self-contained reusable units known as classes. In OOP, data and its manipulation are brought together into a single entity called an object. Programs consist of one or more objects interacting with each other only to solve a particular problem. The object is responsible for its data and manipulated by a predefined list of applicable operations. In essence, OOP aims to emulate the ways humans with the world around them. In this way, anything can be modelled as an object. A typical day, get out of bed, have a cup of coffee, catch a bus to work, go to a restaurant for lunch, go to your home, eat dinner with a knife and fork, watch television etc. It is possible to look on life as a series of interactions with things. These things we call objects. We can view all of these objects as consisting of data (properties) and operations that can be performed on them (methods).

If it is parked the velocity is zero, if it is on the road it is moving at a certain speed in a particular direction. What are the methods that can modify the car's velocity? Can we press the accelerator to increase the speed, we can press the brake to reduce and finally we can turn the steering wheel to alter the direction of motion. The speedometer is a method we can consult at any time to access the value of the speed component of velocity. However, it is clear that without any of the other methods we cannot directly manipulate the vehicle (unless we have a crash in which the velocity goes to zero rapidly).

## 1.10.1 Classes and Abstract Data Types

The basic building block of OOP is the class. A class defines the available characteristics and behaviour of a set of similar objects. A class is an abstract definition that is made concrete at run-time when objects upon the class are instantiated and taken on the behaviour of the class. Data abstraction is the process of creating an object whose implementation details are hidden (or encapsulated) and the object is used through a well-defined interface. Data abstraction leads to an abstract data type (ADT), e.g. when we use a floating point number in a program that we are not really bothered exactly how it is represented inside the computer, it provides benefits in the manner you expect. ADTs should be independent of their implementation modification. Most people would be unhappy if they took their car to the garage for a service and afterwards the mechanic said 'She's running lovely, but you'll have to use the pedals from reverse now on'. If this were the case, we would not think of the car as an ADT. However, the reality is that we can take a car to a garage for a major overhaul (which represents a change of implementation) and still drive it in exactly the same way afterwards.

Consider the concept of a 'Vehicle' class. The class would include methods such as Steer(), Accelerate() and Brake(). The class would also include properties such as Colour, NumberOfDoors, TopSpeed. The class is an abstract design that becomes real when objects such as Car, RacingCar and Tank are created, each with its own version of the class's methods and properties. Furthermore, message passing (or interfacing) describes the communication between objects using their public interfaces. There are three main ways to pass messages: properties, methods, and events:

- Properties can be defined in a class to allow objects of that type to advertise and allow changing of state information, such as the 'TopSpeed' property.
