# 1.9.1 Call-by-Value vs. Call-by-Reference

When arguments are call-by-value it implies that copies of any variables within the parameter list are made as they are called. So, in Source 1.20, copies of a and b in the body of Product () are made during execution and not a and b themselves. This works but can be inefficient when dealing with large numbers of parameters and function calls in a program. In order to get around this problem, we can use call-by-reference which passes the memory address of the argument variables to the function body can then act directly on the variables and dynamically change them as required. Changing the value of the variable stored in the allocated is the same as changing the value of the variable itself. If we are passing an argument by reference to a parameter x on its body, then x is to an alias for a and both share the same address in memory. It essentially acts on a, so it changes, it changes a as well. In order to pass an argument by reference, the reference operator (&) is placed in front of both the function prototype and definition.

A major disadvantage of using references in lists is that the function is able to modify the inputs. What we ideally need is the address of a variable while at the same time not being able to modify it in any way. In this case call-by-value, call-by-reference and constant reference are used to control access to arguments in a function.
