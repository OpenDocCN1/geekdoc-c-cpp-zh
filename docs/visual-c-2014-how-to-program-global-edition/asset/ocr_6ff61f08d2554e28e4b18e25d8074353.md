If Read returns null, the program closes the StreamReader object (line 86), automatically closing the FileStream object, then notifies the user that there are no more records (lines 92–93).

# 17.5 Case Study: Credit-Inquiry Program

To retrieve data sequentially from a file, programs normally start from the beginning of the file, reading consecutively until the desired data is found. It is sometimes necessary to process a file several times (from the beginning of the file) during the execution of a program. A FileStream object can reposition the position-pointer (which contains the byte number of the text to be read from or written to the file) to any position in the file. When a FileStream object is opened, the position-pointer is set to position 0 (i.e., the beginning of the file).

We now present a program that builds on the concepts employed in Fig.17.6. Class CreditInquiryForm (17.7) is a credit-inquiry program that enables a credit manager to search and display account information for customers with credit balances (i.e., customers to whom the company owes money), zero balances (i.e., customers who do not owe the company money) and debt balances (i.e., customers who owe the money for previously received goods and services). We use a RichTextBox in the program to display more functionality than regular TextBoxes—for example, RichTextBox offer better Find for searching virtual strings and LoadFile for displaying file contents. RichTextBox and TextBox both inherit from abstract class System.Windows.TextBase. In this example, we use a RichTextBox, because it displays multiple lines of text by default, whereas a regular TextBox displays only one line.
