
## 4.3 Account Class with an Instance Variable and Set and Get Methods

store a name in an Account object, and method GetName that a program can call to obtain the name from an Account object.

```cs
// Fig. 4.2: Account.cs
// A Simple Account class that contains a private instance
// variable name and public methods to Set and Get name's value.
class Account {
    private string name; // instance variable
    // method that sets the account name in the object
    public void SetName(string accountName) {
        name = accountName; // store the account name
    }
    // method that retrieves the account name from the object
    public string GetName() {
        return name; // returns name's value to this method's caller
    }
}
```

### 4.3.2 Keyword class and the Class Body

The class declaration begins in line 5 with

```
class Account
```

As mentioned in Chapter 3, every class declaration contains the keyword class followed immediately by the class's name—in this case, Account. Also, each class declaration is typically stored in a file having the same name as the class and ending with the .cs file extension, so we've placed class Account in the file Account.cs. The class's body is enclosed in a pair of braces (lines 6 and 20 of Fig. 4.2).

### Identifiers and Camel-Case Naming

Class, property, and method variable names are all identifiers and by convention all use the naming schemes we discussed in Chapter 3:

- class, property and method begin with an initial uppercase letter (i.e., PascalCase)
- variable names begin with an initial lowercase letter (i.e., camel case).

### 4.3.3 Instance Variable name of Type string

Recall from Section 1.6 that a class has attributes, implemented as instance variables. Objects of the class carry these variables throughout their lifetimes. Each object has its own copy of the class's instance variables. Normally, a class also contains methods and properties. These manipulate the instance variables belonging to particular objects of the class.

Instance variables are inside a class declaration but outside the bodies of the class's methods and properties. Line 7

```
private string name; // instance variable
```

declares instance variable of type string outside the bodies of methods SetName and GetName. If there are many Account objects, each has its own name. Because name is an instance, it can be manipulated by each of the class's methods and properties. Clients of Account—that is, any code that calls the class's methods (such as AccountTest's Main in Fig. 4.1)—can access the instance variable because it's private. However, clients can access Account's public methods SetName and GetName. These methods access private instance variable. We discuss this architecture of private variables and public access methods is powerful in more detail in Section 4.5.

#### null—the Default Initial Value for String Variables

Every instance has a default initial value—a value provided by C# if you do not specify the instance initial value. Thus, instances are not required to be explicitly initialized before they're used in a program—unless they be initialized to values other than their default values. The default value for an instance variable of type string is null, which we discuss in Chapter 7 when we consider-referenced types. When you use Console.Write or Console.WriteLine to display a string that contains the value null, no text is displayed on the screen—this is why line 13 in Main (Fig. 4.1) did not display a name first time we called Account's GetName.

### 4.3.4 SetName Method

Let's walk through the code of method setName's declaration (Fig. 4.2, lines 10–13):

```cs
public void SetName(string accountName)
{
    name = accountName; // store the account name
}
```

The first line of each method declaration (line 10) is the method header. The method's return-type (which appears to the left of the method's name) specifies the type of data the method returns to its caller after performing its task. The return type void (line 10) indicates that setName completes its task, it does not return (i.e., give back) any information to its calling method—in this example, line 18 of the Main method (Fig. 4.1). As you'll see, Account method GetName returns a value.

### SetName’s Parameter

Our car analogy from Section 1.6 mentioned that pressing a car’s gas pedal sends a message to the car to perform a task—make the car go faster. But how fast should the car accelerate? The further down you press the pedal, the faster the car accelerates. So the message to the car includes both the task and information that helps the car perform that task. This information is known as a parameter—the value helps the car determine how fast to accelerate. Similarly, a method can require one or more parameters that represent the data it needs to perform its task.

MethodName declares the parameter accountName—which receives the name passed to it as an argument. When line 18 in Fig. 4.1

```
myAccount.setName(theName); // put theName in myAccount object
```

executes, the argument value in the parentheses (i.e., the value stored in theName) is copied into the corresponding parameter (accountName) in the method’s header (line 10 of Fig. 4.2). In Fig. 4.1 sample execution, we entered "Jane Green" for theName, so "Jane Green" was copied into the accountName parameter.

### SetName Parameter List

Parameters like accountName are declared in a parameter list located in the parentheses following the method name. Each parameter must specify a type (e.g., string) followed by a name. When there are multiple parameters, they are placed in a comma-separated list, as

```
(type name1, type2 name2, ...)
```

The number and order of arguments in a method declaration must match the number and order of parameters in the method parameter list.

### SetName Method Body

Every body is defined by an opening left brace (Fig. 4.2, line 11) and a closing right brace (line 12). Within these braces are one or more statements that perform the task. In this case, the method body contains a single statement (line 12)

```
name = accountName; // store the account name
```

assigns the accountName parameter’s value (a string) to the class’s instance variable, storing the name in the object for which SetName was called—myAccount in this example’s Main program. After line 12 executes, program execution reaches the method’s body (line 13), the method returns to its caller.

### Parameters Are Local Variables

In Chapter 3, we declared all of an app’s variables in the Main method. Variables declared in a particular method (such as Main) are local variables which can be used only in that method. Each method can access its own local variables, not those of other methods. When a method terminates, the values of local variables are lost. A method’s parameters are also local variables.

### 4.3.5 GetName Method

Method GetName (lines 16–19)

```cs
public string GetName()
    return name; // returns name's value to this method's caller
}
```

returns a particular object's name to the caller—a string, as specified by the method's return type. The method has an empty parameter list, so it does not require additional information to perform its task. When a method with a return type other than void is called and completes its task, it must return a result to it. A statement that calls GetName on an Account object expects to receive the Account's name. For example, the statement in line 21 of Fig. 4.1
```
Console.WriteLine("myAccount name is: {myAccount.GetName()}");
```

uses the returned value by GetName to output the name stored in the object.

### 4.3.6 Access Modifiers private

The keyword private (line 7 of Fig. 4.2)

```
private string name; // instance variable
```

is an access modifier. Instance variable name is private to indicate that it is accessible only to class Account's methods (and other members, like properties, as you'll see in sequences). This is known as information hiding—the instance variable name is hidden and can be used only in class Account's methods (SetName and GetName). Most instance variables are declared private.
