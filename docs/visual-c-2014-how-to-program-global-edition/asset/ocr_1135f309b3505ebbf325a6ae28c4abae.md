Instead, if we attack the problem with recursion in $n-1$ disks, it immediately becomes tractable. Moving $n$ disks can be viewed in terms of moving only $n-1$ disks (hence the recursion) as follows:

+   a) Move $n-1$ disks from peg 1 to 2, using peg 3 as a temporary holding area.
b) Move the last disk (the largest) from peg 1 to peg 3.
c) Move the $n-1$ disks from peg 2 to 3, using peg 1 as a temporary holding area.

The process ends when the last task involves moving $n=1$ disk (i.e., the base case). This task is accomplished by simply moving the disk, without the need for a temporary holding area. Write an app to solve this method. Allow the user to enter the number of disks. Use a recursive method with the following parameters:

+   a) the number of disks to be moved,
b) the peg on which these disks are initially threaded,
c) the peg to which this stack of disks is to be moved,
d) the peg to be used as a temporary holding area.

Your app should display the precise instructions it will take to move the disks from the starting peg to the destination. For example, to move a stack of three disks from peg 1 to peg 3, your app should display the following sequence of moves:


**7.37** (What Does This Code Do?) What does the following method do?

```
// Parameter b must be positive to prevent infinite recursion
static int Mystery(int a, int b)
{
    if (b == 1) 
        return a;
    else
        return a + Mystery(a, b - 1);
}
```

```
static int Sum(int n)
```
