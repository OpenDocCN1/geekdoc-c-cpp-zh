# 10.10 readonly Instance Variables

The principle of least privilege is fundamental to software engineering. In the context of an app, the principle states that code should be granted the amount of privilege and access needed to accomplish its designated task, but no more. Let's see how this principle applies to instance variables.

Some instance variables need to be modifiable, and some not. In Section 8.4, we used const to declare a constant, which must be initialized in its declaration—all objects of the class have the same value for that constant. Suppose, we want a constant that can have a different value for each object of a class. For this purpose, C# provides keyword readonly to specify that an instance variable of an object is not modifiable and that any attempt to modify it after the object is constructed is an error. For example:

```
private readonly int Increment;
```

declares instance variable of type int. Like a constant, a readonly identifier uses Pascal Case by convention. Although readonly instance variables can be initialized when they are declared, this isn't required. A readonly variable should be initialized by each of the class's constructors or in its declaration. Each constructor can assign values to a readonly instance variable multiple times—the variable can become unmodified until the constructor completes execution. If a constructor does not initialize the readonly variable, the variable uses the default value as any other instance variable (0 for numeric types, false for bool and null for reference types)—these values are set before constructor executes and can be overwritten by the called constructor.

# Software Engineering Observation 10.13

> Declaring an instance variable readonly enforces the principle of least privilege. If an instance variable should not be modified after the object is constructed, declare it to prevent modification.

const members must be assigned values at compile time. Therefore, const members can be initialized only with other constant values, such as integers, string literals, and other const members. Constants with values that cannot be determined at compile time—such as those that are initialized with the result of a method call—must be declared with keyword readonly, so they can be initialized at execution time. Variables that are readonly can be initialized with more complex expressions, such as an array initializer or a method that returns a value or a reference to an object.

# Common Programming Error 10.3

> Attempting to modify a readonly instance variable anywhere but in in its declaration or the object's constructors is a compilation error.

# Error-Prevention Tip 10.1

> Attempts to modify a readonly instance variable are caught at compilation time rather than causing execution-time errors. It's preferable to get bugs at compile time, if possible, rather than allowing them to slip through to execution (where we have found that repairing bugs is often much more costly).
