Local Variables in Main
Lines 10, 11, 17 and 23 declare local variables total, gradeCounter, grade and average, respectively. A variable declared in a method is a local variable and can be used from the line of its declaration to the closing right of the block in which the variable is declared. A local variable's declaration must appear before it is used; otherwise, a compilation error occurs. Variable grade—declared in the body of the while loop—can be used only in that block.

Initialization Phase: Initializing Variables total and gradeCounter
# requires local variables to be definitely assigned—that is, each local variable must be assigned a value before the variable's value is used. Lines 10-11 declare and initialize total to 0 and gradeCounter to 1 before their values are used, so these variables are definitely assigned (as grade and average in lines 17 and 23, respectively).

Processing Phase: Reading 10 Grades from the User
Line 14 indicates that the while statement should continue looping (also iterating) as long as grade's value is less than or equal to 10. While this condition remains true, the while statement repeatedly executes the statements within the braces that limit its body (lines 15–20).

Line 16 displays "Enter grade: ". Line 17 inputs the grade entered by the user and assigns it to variable grade. Then line 18 adds the new grade entered by the user to the total and assigns the result to total, replacing its previous value.
Line 19 adds to gradeCounter to indicate that the program has processed a grade and is ready to input the next grade from the user. Increment gradeCounter eventually causes it to exceed 10. Then the loop terminates, because its condition (line 14) becomes false.

When the loop terminates, line 23 performs the averaging calculation in the average variable's initializer. Line 26 displays the "Total of 10 grades is " followed by total's value. ### 5.10 Formulating Algorithms: Sentinel-Controlled Iteration
Let us generalize 5.9's class-average problem. Consider the following problem: Develop a class-averaging app that processes grades for an arbitrary number of students each time. In the previous class-example, the problem statement specified the number of students, so the number of grades (10) was known. In this example, no indication of how many grades the user will enter before the loop. How can we determine when to stop?

One way to solve this is to use a special sentinel value (also called a signal value, a dummy value or a flag value) to indicate "end of data." The user enters until all grades have been entered. Sentinel-controlled iteration is often called indefinite iteration because the number of iterations is not known before the loop begins. Clearly, a sentinel value must be chosen that it cannot be confused with an acceptable value. Grades on a quality average so -1 is not an acceptable value for this problem. Thus, a run of the class-averaging program might process a sequence of inputs such as 95, 96, 75, 74, 89 and -1. The program would then compute and print the class average for the grades 95, 96, 75, 74 and 89; since -1 is the sentinel value, it should not* enter into the averaging process.

### 5.10.1 Top-Down, Stepwise Refinement: The Top and First Refinement
We approach this class-average program with a technique top-down, stepwise refinement, which is essential to the development of well-structured programs. We begin with a pseudocode representation of the top—a statement that conveys the overall purpose of the program:

> Determine the class average for the quiz

The top is, in effect, a complete representation of a program. Unfortunately, the top rarely conveys specific detail from how to write a C# app. So we begin the refinement process. We divide the top into smaller sets of tasks and list them in the order they'll be performed. This results in the following first refinement:

- Initialize variables
- Input, sum and count the quiz grades
- Calculate and print the class average

This refinement uses only the sequence structure—the steps listed should execute in order, one after the other.
