## 22.3 A Books Database

We consider a simple Books database that stores information about some Deitel books. First, we overview the database's tables. A database's tables, their fields and the relationships among them are collectively known as a database schema. The ADO.NET Framework uses a database's schema to define classes that allow you to interact with the database. Sections 22.5–22.8 show how to manipulate the Books database. The database file—Books.mdb—is provided with this chapter's examples. SQL Server database files have the .master data file extension.

### AuthorISBN Table of the Database
The AuthorISBN table (described in Fig. 22.7) consists of two columns that maintain ISBNs for each book and their corresponding authors' ID numbers. This table associates authors with their books. The Author column is a foreign key—a column in one table that matches the primary key column in another table (that is, Author table). The ISBN column is a foreign key—it matches the primary key column (that is, Titles table). A database might consist of many tables. A goal of database's designer is to minimize the amount of duplicated data among the tables. Foreign keys, which are specified when a database table is created, link multiple tables. Together the Author and ISBN columns in this table form a composite primary key. Every row in this table uniquely matches one author to one book's ISBN. Every foreign-key value must appear as another table's primary-key value so the DBMS ensures the foreign key value is valid. For example, the DBMS ensures the AuthorID value for any particular row of the AuthorISBN table (Fig. 22.8) is valid by checking that there is a row in the table with AuthorID as the primary key.
Foreign keys also allow related data in table to be selected from those tables—this is known as joining the data. There's a one-to-many relationship between a primary key and a corresponding foreign key—e.g., an author can write many books and can be written by many authors. So a foreign key can appear many times in its own table but only *once* (as the primary key) in another table. For example, the ISBN 0132151006 can appear in several rows of AuthorISBN but only once in Titles, where ISBN is the primary key.

### Primary Keys
The first compartment in each box contains the table name. The names in italic font are *primary keys*—AuthorID in the Authors table, AuthorID and ISBN in the AuthorISBN table, and ISBN in the Titles table. Every row *must have* a value in the primary-column (or group of columns), and the value of the key must be *unique* in the table; otherwise, the DBMS will report an error. The names AuthorID and ISBN in the AuthorISBN table are both italic—together they form a *composite primary key* for the AuthorISBN table.
