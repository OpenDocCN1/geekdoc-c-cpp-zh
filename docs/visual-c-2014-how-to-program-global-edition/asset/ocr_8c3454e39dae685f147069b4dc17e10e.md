# Section 12.2 Polymorphism Examples

+   - With polymorphism, the same method name and signature can be used to cause different actions to occur, depending on the type of object on which the method is invoked.
- Polymorphism promotes extensibility: Software that invokes polymorphic behavior is independent of the object types to which messages are sent. New object types that can respond to existing method calls can be incorporated in a system without requiring modification of the base system.

# Section 12.3 Demonstrating Polymorphic Behavior

+   - Invoking a method on a derived-class object via a base-class reference invokes the derived-class functionality—the type of the referenced object determines which method is called.

# Section 12.4 Abstract Classes and Methods

+   - Abstract classes are incomplete classes for which you never intend to instantiate objects.
- The purpose of the abstract class is primarily to provide an appropriate base class from which other classes can inherit, and share a common design.
- Classes that can be used to instantiate objects are concrete classes.
- You make a class abstract by declaring it with keyword abstract.
- Each derived class of an abstract base class must provide concrete implementations of the base class's abstract methods and properties.
- Failure to implement a base class's abstract methods and properties in a derived class is a compilation error unless the class is declared abstract.
- Although we cannot instantiate objects of abstract classes, we can use them to declare variables that can hold references to objects of any concrete class derived from such abstract classes.

# Section 12.5 Case Study: Payroll System Using Polymorphism

+   - By declaring a abstract method, we indicate that each concrete class must provide an appropriate implementation.
- All virtual method calls are resolved at execution time, based on the type of object to which the reference-type variable refers. This process is known as dynamic binding or late binding.
- The is operator determines whether the type of the object in the left matches the type specified by the right operand and returns true if the two have an-a relationship.
- The as operator performs a downgrade that returns a reference to the appropriate object if the downgrade is successful and returns null if it fails.
- A base-class reference can be used to invoke only the methods declared in the base class. If an app needs to perform a derived-class specific operation on a derived-class object referenced by a base-class variable, the app must first down the base-class reference to a derived-class reference.
- Every object has its own type and can access this information through method GetType, which all classes inherit from this object.
- Assigning a base-class reference to a derived-class variable is not allowed without an explicit cast or using the as operator. The is operator can be used to ensure that such a cast is performed only if the object is a derived-class object.

# Section 12.6 sealed Methods and Classes

+   - A method that declared sealed in a base class cannot be overridden in a derived class.
- A class that declared sealed cannot be a base class (i.e., a class cannot extend a sealed class). All methods in a sealed class are implicitly sealed.
