# 19.8 Wrap-Up

In this chapter, you learned that simple types are value-type structs but can still be used anywhere objects are expected in a program due to boxing and unboxing conversions. You learned that linked lists are collections of data items that are “linked together in a chain.” You also learned that a program can perform insertions and deletions anywhere in a linked list (though our implementation performed insertions and deletions only at the ends of the list). We demonstrated that the stack and queue structures are constrained versions of lists. For stacks, we saw that insertions and deletions are made only at the top—stacks are known as last-in, first-out (LIFO) structures. For queues, representing lines, you saw that insertions are made at the tail and deletions are made from the head—so queues are known as first-in, first-out (FIFO) structures. We presented the binary tree data structure. You saw a binary search tree that facilitated high-speed searching and sorting of data and efficient duplicate elimination. In the next chapter, we introduce generics, which allow you to declare a family of classes and methods that implement the same functionality any type.

# Summary

# Section 19.1 Introduction

+   - Dynamic data can grow and shrink at execution time.

# Section 19.2 Simple-type structs, Boxing and Unboxing

+   - All simple-type names are aliases for representing structs in namespace.
- Each simple type struct declares methods for manipulating the corresponding simple-type values.
- Each struct that represents a simple type inherits from class ValueType in namespace System.
- A boxing conversion creates an object that contains a copy of a simple-type value.
- An unboxing conversion retrieves a simple-type value from an object.

# Section 19.3 Self-Referential Classes

+   - A self-referential class contains a data member that refers to an object of the same class type. Self-referential objects can be linked to form data structures, such as lists, queues, and trees.
- Creating and maintaining data structures requires dynamic memory allocation—a program’s ability to obtain more memory at execution time (to hold new nodes) and release memory when no longer needed.
- Operator new acts as an operand the type of object being dynamically, calls the appropriate constructor to initialize the object and returns a reference to the new object. If no memory is available, new throws an OutMemoryException.

# Section 19.4 Linked Lists

+   - A linked list is a linear collection (i.e., a sequence) of self-referential class objects nodes, connected by reference links.
- A node can contain properties of any type, including references to objects of other classes.
- A list is accessed via a reference to the first node of the list. Each subsequent node is accessed via the link-reference member stored in the previous node.
