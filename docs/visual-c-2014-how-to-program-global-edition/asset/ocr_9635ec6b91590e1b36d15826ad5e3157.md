# Method TestPushDouble

Method PushDouble (lines 28–47) invokes Method Push to place the double values
1.1, 2.2, 3.3, 4.4 and 5.5 in the array doubleElements for-
each statement terminates when the program attempts to push a sixth value onto-
double(which is full, because doubleStack can store only five elements). In this,
the method throws a FullStackException (20.6) to indicate that the Stack is full.
Lines 42–46 of Fig. 20.8 catch this exception and display the message and stack-trace
in. The stack trace identifies the exception that occurred and shows that Stack
method Push generated the exception at line 35 of the Stack.cs (Fig. 20.5). The trace
also shows that method Push was called by StackTest methodPushDouble at line 39
of StackTest.cs. This information enables you to determine the methods that were
the method-call at the time that the exception occurred. Because the program catches
the exception, the C runtime environment considers the exception to have been handled,
and the program can continue executing.

# Method TestPopDouble

Method Pop (Fig. 20.8, lines 50–71) invokes Method Pop in an infinite
while loop to remove all the values from the stack. Note in the output that the values are
pped off in last-in, first-out-order—this, is the defining characteristic of stacks.
The while loop (lines 60–64) continues until the stack is empty. An EmptyStackEx-
curs when an attempt is made to pop from the empty stack. This causes the-
program to continue to the catch block (lines 66–70) and handle the exception, so the
program can continue executing. When the program attempts to Pop a sixth value, the
doubleStack is empty, so method Pop throws an EmptyStackException.

# Methods TestPushInt and TestPopInt

Method PushInt (lines 74–93) invokes Method Push to place values onto int-
tack until it is full. Method PopInt (lines 96–117) invokes Method Pop to re-
move from intStack until it is empty. Again, values pop in last-in, first-out order.
