# Linear and Circular Singly Linked and Doubly Linked Lists

The kind of linked list we have been discussing is a singly linked list—it begins with a reference to the first node, and each node contains a reference to the next node “sequence." This list terminates with a node whose member has the value null. A singly linked list may be traversed in only one direction.

A circular, singly linked list begins with a reference to the first node, and each node contains a reference to the next node. The “last node” does not contain a null reference; rather, the last node points back to the first node, thus closing the “circle.”

![](img/57baed2319be0bb1b5f98674846f2711_827_0.png)

**Fig. 19.10** | Circular, singly linked list.

A doubly linked list (Fig. 19.11) allows traversals both forward and backward. Such a list is often implemented with two “start references”—one that refers to the first element of the list to allow front-to-back traversal of the list and one that refers to the last element to allow back-to-front traversal. Each node has both a forward reference to the next node in the list and a backward reference to the previous node. If your list contains an alphabetized telephone directory, a search for someone whose name begins with a letter near the front might begin from the front of the list. A search for someone whose name begins with a letter near the end might begin from the back.

# 19.5 Stacks

A stack may be viewed as a constrained version of a linked list—it receives new nodes and releases nodes only at the top. For this reason, a stack is referred to as last-in, first-out (LIFO) data structure. The primary operations to manipulate a stack are push and pop. Operation push adds a new node to the top of the stack. Operation pop removes the top of the stack and returns the data item.

Stacks have many interesting applications. For example, when a program calls a method, the method must know how to return to its caller, so the return address is pushed onto the method stack. If a series of method calls occurs, the return values are pushed onto the stack in first-out order so that each method can return to its caller. Stacks support recursive method calls in the same manner they do for nonrecursive method calls.

In our next example, we take advantage of the relationship between lists and stacks to implement a class by reusing a list. We demonstrate two forms of reusability: First, we implement the stack by inheriting from List (Fig. 19.4). Then we implement stacks identically through composition by including a List object as a private member of the stack class. St grow and shrink during program execution.

# Stack Class That Inherits from List

The code in Fig. 19.13 creates a stack by inheriting from List (Fig. 19.4). We want the stack to have methods Push, Pop, and Empty. Essentially, these are the methods InsertFront, RemoveFront, and Display of class List. Of course, class List contains other methods (such as InsertBack and RemoveBack) that we would rather make accessible through the public interface of the stack (Fig. 19.13).

```csharp
// Fig. 19.13: StackInheritance.cs
// Implementing a stack by inheriting from List.
using LinkedList;

namespace StackInheritance
{
    // Class StackInheritance inherits List's capabilities
    public class StackInheritance : List
    {
        // pass name "stack" to constructor
        public StackInheritance() : base("stack") { }

        // dataValue at top of stack by inserting
        // dataValue at front of linked list
        public void Push(object dataValue)
        {
            InsertFront(dataValue);
        }

        // remove item from top of stack by removing
        // item at front of linked list
        public object Pop()
        {
            return RemoveFront();
        }
    }
}
```

Fig. 19.13 | implementing a stack by inheriting from List.

The implementation of each StackInheritance method calls the appropriate List method—method Push calls InsertFront, method Pop calls RemoveFront. StackInheritance does not define methods Empty and Display because it inherits its methods from class List into StackInheritance's public interface. StackInheritance uses namespace LinkedList (Fig. 19.4); thus, the class library that defines StackInheritance must have a reference to the LinkedList library.
