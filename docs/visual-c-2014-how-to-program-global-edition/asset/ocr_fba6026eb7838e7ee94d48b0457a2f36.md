# Every Object Knows Its Own Type

Lines 59-63 display each employee's type as a string. Every object knows its own type and can access this information through method GetType, which all classes inherit from class type.(of namespace System), This method returns an object of class type (including its class name, the names of its methods and the name of its base class). Line 62 invokes GetType on the object to get its runtime class (a Type that represents the object's type). Then ToString is implicitly invoked on the object returned by GetType. The type's ToString method returns the class name.

In the previous example, we avoid compilation errors by downcasting an Employee variable a BasePlusCommissionEmployee inherited from the cast operation. If we remove the cast operator and attempt to assign Employee variable currentEmployee directly to BasePlusCommissionEmployee variable named (with this type declared, rather than using var), we'd receive a "Cannot implicitly convert type" compilation error. This error indicates that the attempt to reference of base-class object currentEmployee to derived-class employee is not allowed without an appropriate cast operator. The compiler prevents this assignment, because CommissionEmployee is not a BasePlusCommissionEmployee—again, the is-relationship applies only between the derived class and its base classes, not versa.

Similarly, if lines 50 and 52 use base-class variable currentEmployee, rather than derived-class variable employee, when accessing derived-class-only BaseSalary, we receive an "Employee" does not contain a definition for "BaseSalary" compilation error on each of these lines. Attempting to invoke derived-class-only methods or properties on a base-class reference is not allowed. While lines 50 and 52 execute only if is in line 44 return true to use derived-class BasePlusCommissionEmployee object, we cannot attempt to use BasePlusCommissionEmployee property BaseSalary with base-class reference currentEmployee. The compiler would generate errors in lines 50 and 52, because BaseSalary is not a base-class and cannot be used with a base-class variable. Although the method that's called depends on the object's type at execution time, a variable can be used to invoke only methods that are of variable's type, the compiler verifies. Using a base-class Employee variable, we can invoke only methods and properties found in class Employee—methods Earnings and ToString, and properties FirstName, LastName and SocialSecurityNumber—and methods inherited from object class.
