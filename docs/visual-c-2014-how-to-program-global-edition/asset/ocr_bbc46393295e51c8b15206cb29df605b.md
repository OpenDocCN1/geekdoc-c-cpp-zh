# 4.6.3 UML Class Diagram with a Property

Figure 4.7 presents a UML class diagram for class Account of Fig. 4.6. We model C# properties in the UML as attributes. The property Name is listed as a public attribute—as indicated by the plus (+) sign—followed by the word “property” in guillemets (« »). # 4.7 Auto-Implemented Properties

In Fig. 4.6, we created an Account class with a private name instance variable and a public property Name to enable access to the name. When you look at the Name property's definition (Fig. 4.6, lines 10–20), notice that the getter simply returns private instance variable name value and the setter accessor assigns a value to the instance—no other logic appears in the acceptors. For simple cases, C# provides auto-implemented properties.

With an auto-implemented property, the C# compiler automatically creates a hidden instance variable. The get and setters for getting and setting that instance variable, which is handy when you're first designing a class. If you later decide to include other logic in the get or setter, you can simply implement the property and an instance variable using the techniques shown in Fig. 4.6. To use an auto-implemented property in the Account class of Fig. 4.6, you'd replace the private instance variable at line 7 and the property at lines 10–22 with the following single line of code:

```
public string Name { get; set; }
```
