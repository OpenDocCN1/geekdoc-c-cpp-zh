### foreach vs. for
The for statement can be used in place of the for statement looping through an array does not require access to the current array element's index. For example, totaling the integers in an array requires access only to the element values—each element's index is irrelevant. If an app must use a counter for some reason other than simply loop through an array (e.g., to calculate an element's value based on the counter's value, as in Fig. 8.4), you should use the for statement.

## Common Programming Error 8.5

Attempting to modify an array element's value using a foreach statement's iteration variable is a logic error—the iteration variable can be used only to access each array element's value, not modify it.

## 8.4.6 Using Bar Charts to Display Data Graphically; Introducing Type Inference with var

Many apps present data to users in a graphical manner. For example, numerical values are often displayed as bars in a bar chart. In such a chart, bars represent proportionally larger values. One simple way to display data graphically is with a bar chart that shows each numerical value as a bar of asterisks (*).

An instructor might graph the number of grades in several categories for an exam. Suppose the grades on an exam were 87, 68, 94, 100, 83, 78, 85, 91, 76 and 87. Included were one grade of 100, two grades in the 90s, four in the 80s, two grades in the 70s, one grade in the 60s and no grades below 60. Our next app (Fig. 8.7) shows this grade-distribution in an array of 11 elements, each responding to a category of grades. For example, array[0] indicates the number of grades in the range 0–9, array[7] the number of grades in the range 70–79 and array[10] the number of 100 grades. The two versions of class GradeBook in Sections 8.8 and 8.10 contain code that calculates these grade frequencies and initialize it with the number of grades in each range (Fig. 8.7, line 9). We decide the keyword var (lines 14 and 27) after we present the app's logic.


## Implied Typed Local Variables and Keyword var

In line 14

```csharp
for (var counter = 0; counter < array.Length; ++counter)
```

notice var keyword has no type preceding the variable counter. This declares the variable and lets the compiler declare the variable's type, based on its initialization. This is known as type inference and local variables declared in this manner are known as implicitly typed variables. Here, the compiler infers that counter's type is int, because it's initialized with the literal 0.

Similarly, consider line 11 of 8.4:

```csharp
Account count1 = new Account("Jane Green");
```

Notice that the type Account appears twice—once to declare variable count1's type and to specify the type of the new object being created. From this point forward, the preference is written to this statement:

```csharp
var count1 = new Account("Jane Green");
```

Here, the compiler infers that count1's type is Account, because the compiler can determine the type from the expression

```csharp
var next = new Account("Jane Green");
```

which creates an Account object. The Microsoft C# Coding Conventions https://msdn.microsoft.com/library/f9926074 recommend using type inference when a local variable's type is obvious, based on its initial value. These conventions are guidelines, not requirements. In industry, your employer may have its own coding requirements that differ from Microsoft's.

## More on Implicit Typed Local Variables

Implied typed local variables also can be used to initialize an array via an initializer. In the following statement, the type of values is inferred as int[]

```csharp
var values = new[] {32, 27, 64, 18, 95, 14, 90, 70, 60, 37};
```

new[] specifies the initializer list is for an array. The array's element type, int, is inferred from the initializer. The following statement—in which values are initialized without new[]—generates a compilation error

```csharp
var values = {32, 27, 64, 18, 95, 14, 90, 70, 60, 37};
```

## Common Programming Error 8.6

Initializer lists can be used with both arrays and collections. If an implicitly typed local variable is initialized via an initializer list without new[], a compilation error occurs, because the compiler cannot infer whether the variable should be an array or a collection. We use a List in Chapter 9 and cover collections in detail in Chapter 21.
