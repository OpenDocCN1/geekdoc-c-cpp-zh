## 7.18 Passing Arguments By Value and By Reference

Two ways to pass arguments in many programming languages are pass-by-value and pass-by-reference. When an argument is passed by value (the default in C#), a copy of its value is passed to the called method. Changes to the copy do not affect the original variable's value in the caller. This prevents the accidental side effects that could greatly hinder the development of correct and reliable software systems. Each argument that's been passed in the programs so far has been passed by value. When an argument is passed by reference, the caller gives the method the ability to access and modify the caller's original variable—no copy is passed.

To pass an object by reference into a method, simply provide it as an argument in the method call that refers to it. Then, in the method body, reference the object using the corresponding parameter name. The parameter refers to the original object in memory, so the called method can access the original object directly.

In the previous section, we began discussing the differences between value types and reference types. A major difference is that:

- value-type variables store values, specifying a value-type variable in a method call passes a copy of that value.
- reference-type variables store references to objects, specifying a reference-type as an argument passes a copy of the reference that refers to the object.

Even though the reference is passed by value, the method can still use the reference to interact with and possibly modify the original object. Similarly, when returning information from a method, the method returns a copy of the value stored in a value-type variable or a copy of the reference stored in a reference-type variable. When a reference is returned, the calling method can use that reference.

## 7.18 Passing Arguments By Value and By Reference

- Performance Tip 7.1: A disadvantage of pass-by-value is that, if a large data item is passed, copying that data can take a considerable amount of execution time.
- Performance Tip 7.2: Pass-by-reference improves performance by eliminating copying overhead.
- Software Engineering Observation 7.6: Pass-reference can weaken security; the called method can corrupt the caller's data.

### 7.18.1 ref and out Parameters

What if you like to pass a variable by reference so the called method can modify the variable's value in the caller? To do this, C# provides keywords ref and out.

ref Parameters
Applying the ref keyword to a parameter declaration allows you to pass a variable to a method by reference—the method will be able to modify the original variable in the caller. Keyword ref is used for variables that have already been initialized in the calling method.

Common Programming Error 7.12: When a method contains an uninitialized variable as an argument to a ref parameter, the compiler generates an error.

out Parameters
Preceding a parameter with out creates an output parameter. This indicates to the compiler that the argument will be passed to the called method by reference and that the method will assign a value to the original variable in the caller. This also prevents the compiler from generating an error message for an uninitialized variable that is passed as an argument to a method.

Common Programming Error 7.13: If the method does not assign a value to the out parameter in every path of execution, the compiler generates an error. Also, reading an output before it's assigned a value is also a compilation error.

Software Engineering Observation 7.7: A method can return only one value to its caller via a return statement, but can return many values by specifying multiple output (ref and out) parameters.

Passing Reference-Type Variables by Reference
You can also pass a reference-type variable by reference, which allows you to modify it that it refers to a new object. Passing a reference by reference is a tricky but powerful technique that we discuss in Section 8.13.
