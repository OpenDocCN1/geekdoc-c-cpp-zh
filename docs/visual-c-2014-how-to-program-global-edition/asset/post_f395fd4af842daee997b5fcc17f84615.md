## Section 22.5 Querying a Database with LINQ

- The IDE provides visual programming tools and wizards that simplify accessing data in your project. These tools establish database connections and create the objects easy to view and manipulate the data through the GUI—a technique known as binding.
- GridView (namespace System.windows.Forms) displays data from a data source in tabular format.
- BindingNavigator a collection of controls that allow you to navigate through the records displayed in a GUI. BindingNavigator also allow you to add records, delete records and save your changes to the database.

### Section 22.5.1 Creating the ADO.NET Entity Data Model Class Library

- An entity data model describes the C# classes that you'll be manipulating.
- To interact with a database, add an ADO.NET entity data model to the project (typically a class library for reuse). This will also configure the connection to the database.
- The ADO.NET entity data model's .edmx file contains information about the entity model.
- When configuring the model, you create a connection to the database and choose the model's contents from the database.
- The entity connection string contains the information that the ADO.NET Entity Framework requires to connect to the database at runtime.
- The entity data model contains the selected database objects and shows the relationships between them.

### Section 22.5.2 Creating a Windows Forms Project and Configuring It to the Entity Data Model

- To use the entity data model classes from a class library for data binding, you must first add a reference to the class library to your project. You will also need to add a reference to the EntityFramework library.
- The Framework library is required in each app that will use an entity data model.
- Each app that will use an entity data model also requires the connection string that tells the Framework how to connect to the database. The connection string is stored in the App.Config file of which the entity data model is defined and must be copied into the App.Config file of any project that uses the entity data model.

### Section 22.5.3 Data Bindings Between Controls and the Entity Data Model

- You must write code to enable the autogenerated GUI to interact with the entity data model.
- To use the entity data model classes for data binding, first add them as a data source via Visual Studio's Data sources. The entity data model classes are used to create objects representing tables in the database, so use an Object data source.

- The default GUI for a table is a DataGridView with column names representing all the properties of the data source object. The IDE also creates a BindingNavigator that contains Buttons for moving between entries, adding entries, deleting entries and saving changes to the database. The IDE also generates a BindingSource, which handles the transfer of data between the data source and the data-bound controls on the Form.

- Nonvisual components such as the BindingSource and the nontrivial aspects of the Navigator appear in the component tree—the gray region below the Form in Design view.

- The IDE names the BindingNavigator and BindingSource based on the data source's name.

- To edit the columns displayed in a DataGridView, right click it, then select Edit Columns... to delete the Edit Columns

- To complete the data binding, you must create an object of the entity model DbContext and use it to obtain data.

- The OrderBy extension method receives a Func delegate and orders rows in ascending order by the value returned by the delegate.

- The ThenBy extension method receives a Func delegate and enables you to order results by an additional column.

- The Load extension method (defined in DBExtensions of the namespace System.Data.Entity) loads data into memory. This data is tracked in local memory so that any changes to the data can eventually be saved into the database.

- The local property of a DbContext property is an ObservableCollection<T> that represents the data in memory.

- When a BindingSource's DataProperty is assigned an ObservableCollection<T> (namespace System.Collections.ObjectModel), the GUI bound to the BindingSource is notified of changes to the data so the GUI can be updated accurately. In addition, changes made by the user to the data in the GUI will be tracked by the DbContext can eventually save those changes to the database.

- Calling EndEdit on the BindingSource forces it to save any changes to the DbContext model.

- Calling SaveChanges on the DbContext object saves changes to the database.

## Section 26.2 Dynamically Binding Query Results

- The data bindings created by the IDE automatically update a DataGridView each time the BindingSource's DataSource changes.

- The MoveFirst method of the BindingSource sets the Position property to 0 to move to the first row of the data source.

- Invoking OrderBy on an ObservableCollection<T> returns an IOrderedEnumerable<T>.

- A Func delegate that the where extension method must return a bool value indicating whether the delegate's argument matches the specified criteria.

## Section 22.7 Retrieving Data from Multiple Tables with LINQ

- To join multiple tables you use the properties that the entity model contains for foreign-key relationships between the database's tables. These properties enable you to easily access related results in other tables.

- Most queries return result with data arranged in relational-style rows and columns. With LINQ to Entities you can create queries that return hierarchical results in each item in the result contains a collection of other items.

## Section 22.8 Creating a Master/Detail View App

- In a master/detail view, one part of GUI (the master) allows you to select an entry, and another-part (the details) displays detailed information about that entry.

- The IDE allows you to specify the type of control(s) that it will create when you drag-and-drop an object from the Data Sources window onto a Form. To do so, click a data source object's node in the Data Sources window—it changes to a drop-list from which you can select the controls to use on GUI. The Details option indicates that the IDE would generate Label-Text boxes that represent each column of the data source object.

- Dragging a property from a data source object in the Data Sources window creates a BindingSource and a GUI for it in another table that are associated with the data source object. The items in this BindingSource automatically update based on the currently selected master object.

## Section 22.9 Address Book Case Study

- You cannot bind a LINQ to Entities query's results directly to a BindingSource's DataSource.
- When you convert a query to a List, only changes to records in the DbContext are tracked—any that you add or remove while viewing the filtered data in a List will be tracked.
