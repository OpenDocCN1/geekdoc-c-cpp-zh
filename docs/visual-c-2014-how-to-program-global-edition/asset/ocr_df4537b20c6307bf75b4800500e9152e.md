# Section 12.7 Case Study: Creating and Using Interfaces

+   - Interfaces define and standardize the ways in which things such as people and systems interact with one another.

+   - An interface declaration begins with keyword interface and can contain only abstract methods, properties, indexers and events.

+   - All interface members are implicitly declared public and abstract. They do not specify any implementation details, as concrete method declarations.

+   - Each interface can extend one or more interfaces to create a more elaborate interface that other classes can implement.

+   - A class must specify that it implements an interface by listing it after the colon (:) in the class declaration.

+   - A class that implements an interface but does not implement all the interface's members must be declared abstract and contain an abstract declaration of each unimplemented member.

+   - The UML expresses the relationship between a class and an interface through a realization. A class is said to "realize," or implement an interface.

+   - To implement more than one interface, a comma-separated list of interface names after the colon (:) in the class declaration.

+   - Inheritance and interfaces are similar in their implementation of the is-a relationship. An object of a class that implements an interface can be thought of as an object of that interface type.

+   - All methods of class object can be called using a reference of an interface type—the reference refers to an object, and all objects inherit the methods of class object.
