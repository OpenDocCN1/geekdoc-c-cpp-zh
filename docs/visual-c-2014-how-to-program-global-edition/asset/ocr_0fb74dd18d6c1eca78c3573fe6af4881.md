# Chapter 10 Classes and Objects: A Deeper Look

In the next chapter, you'll learn about inheritance. You'll see that all classes in C# are related directly or indirectly to the object root class and begin to understand how inheritance enables you to build related classes faster.

# Summary

# Section 10.2.1 Time1 Class Declaration

+   * The public methods of a class are part of the public services or the public interface that the class provides to its clients.

+   * Methods and properties that modify the private variables should verify that the intended values are valid.

+   * A class's methods and properties can throw exceptions to indicate invalid data.

# Section 10.2.2 Using Time1

+   * The actual data representation used within the class is no concern to the class's clients. This allows you to change the implementation of the class. Clients could use the same public methods and properties to get the same results without being aware of this change.

+   * Clients are never aware of, nor involved in, a class's implementation. Clients generally care about what the class does but not how it does.

# Section 10.3 Controlling Access to Members

+   * Access public and private access to a class's variables, methods, and properties. A class's private variables, methods and properties are not directly accessible to the class's clients.

+   * If an attempt to use the private members of another class, the compiler generates error stating that these private members are not accessible.

# Section 10.4 Referring to the Current Object's Members with this Reference

+   * Every object has a reference to itself using this keyword. When a non-static method is called for a particular, the method's body implicitly uses keyword to refer to the object's instance variables, other methods and properties.

+   * If a class contains a local variable with the same name as a field, this will refer to the local variable rather than the field. However, a non-static method can use this reference to refer to a hidden instance explicitly.

+   * Avoid-parameter names or local-names that conflict with field names. This helps prevent subtle, hard-to-debug bugs.
