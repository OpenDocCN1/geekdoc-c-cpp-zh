# Summary

# Section 23.1 Introduction

+   - Computers can perform operations concurrently.
- Tasks that proceed independently of one are said to execute asynchronously and are referred to as asynchronous tasks.
- Only computers that have multiple processors or cores can truly execute multiple asynchronous tasks concurrently.
- Visual C# apps have multiple threads of execution, where each thread has its own methodcall, allowing it to execute concurrently with other threads while sharing application-wide resources such as memory and processors. This capability is called multithreading.
- Operating systems on single-core computers create the illusion of concurrent execution by idling switching between activities.
- Today's modern computers, smartphones and tablets enable computers to perform tasks truly concurrently.
- Asynchronous programming is a technique for writing tasks that can execute asynchronously, which can improve performance and GUI responsiveness in apps with longrunning or compute-intensive tasks.
- The async modifier and await operator generally simplify asynchronous programming, reduce errors and enable your apps to take advantage of the power in today's multicore computers, smartphones and tablets.
- In .NET, many classes for web file processing, networking, image processing and more methods return Task objects for use with async and await, so you can take advantage of this new asynchronous programming model.

# Section 23.2.1 async Modifier

+   - The async modifier indicates that a method or lambda expression contains at least one await expression.
- An async method executes its body in the same thread as the calling method.

# Section 23.2.2 await Expression

+   - When an async method encounters an await expression: If the asynchronous task has already completed, the async method simply continues executing. Otherwise, program control returns to the async method's caller until the asynchronous task completes. When the asynchronous task completes, control returns to the async method and continues with the next stateafter the await expression.
