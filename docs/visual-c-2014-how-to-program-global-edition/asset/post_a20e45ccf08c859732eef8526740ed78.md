## 17.1 Introduction

Variables and arrays offer only temporary storage of data—the data is lost when a local variable goes "out of scope" or when the program terminates. By contrast, files (and databases, which we cover in Chapter 22) are for long-term retention of large amounts of data, even after the program terminates. Data maintained in files is called persistent data. Computers store files on secondary storage devices, such as hard drives, solid-state drives, DVDs and tapes. In this chapter, we explain how to create, update and process files in C#. We overview some of the Framework Library's file-processing classes. We create Forms that write to and read from text files that are human readable and binary files that store objects in binary format. Finally, we present examples that show how you can determine information about files and directories on your computer.

## 17.2 Files and Streams

C# views each file as a sequential stream of bytes (Fig. 17.1). Each file ends with an end-of-file marker or a specific byte number recorded in system-maintained administrative structure, because file organization is operating-system dependent. A C# program processing a stream of bytes receives an indication from the operating system when it reaches the end of the stream—the program does not need to know how the platform represents files.

### Standard Streams in Console Apps

When a file is opened, an object is created and a stream is associated with it. When a console app executes, the runtime environment creates three stream objects that are accessible via Console.Out, Console.In and Console.Error, respectively. These objects use streams to facilitate communication between a program and a particular file or device. Console.In refers to the standard input object, which enables a program to input data from the keyboard. Console.Out refers to the standard output object, which enables a program to output data to the screen. Console.Error refers to the standard error stream to output error messages to the screen. These can be redirected to other files or devices. We will be using Console.Out and Console.In in our apps:

- Console methods write and Write use Console.Out to perform output,
- Console methods Read and ReadLine use Console.In to perform input.

### File-Processing Classes

There are many file-processing classes in the Framework Library. System.IO namespace includes stream classes such as StreamReader (for input from a stream), StreamWriter (for output to a stream) and FileStream (for both input and output to a stream). These classes inherit from abstract classes TextReader, TextWriter and Stream, respectively. class provides functionality for representing streams as bytes. FileStream, MemoryStream and BufferedStream (all from namespace.IO) inherit from class. FileStream can be used to write data and read data from files. MemoryStream enables the transfer of data directly to and from memory—much faster than reading and writing to external devices. BufferedStream uses buffering technique to transfer data to or from a stream. Buffering is an I/O performance-enhancement technique, in which each operation is directed to a region in memory, called a buffer, that is large enough to hold the data for many operations. The actual transfer is performed in physical output operation each time the buffer fills. The output operations directed to the output buffer in memory are called logical output operations. Buffering also can be used to speed input operations by initially reading more than required into a buffer, so subsequent reads get data from high-speed memory rather than a slower external device. this chapter, we use classes to implement file-processing programs that create and manage sequential-access files.

## 17.3 Creating a Sequential-Access Text File

C# imposes no structure on files. Thus, the concept of a “record” does not exist in C# files. This means that you must structure files to meet the requirements of your app. The next few examples use special characters to organize our concept of a “record”.

### Class BankUIForm

The following examples demonstrate file processing in a bank-account maintenance app. These programs have similar interfaces, so we created class BankUIForm (Fig. 17.2) to encapsulate the common GUI (see the screen capture in Fig. 17.2). Class BankUIForm (part of the BankLibrary project with this chapter’s examples) contains four Labels and two TextBoxes. Methods ClearTextBox (22–30), SetTextBoxValues (lines 33–51) and GetTextBoxValues (lines 54–59) clear, set the text and get the text from the TextBoxes, respectively. Using visual inheritance—presented in Section 15.13—you can extend this class to create the GUIs for examples in this chapter. Recall that to reuse BankUIForm, you must compile the GUI into a library, then add a reference to the new class library’s DLL in each project that you will reuse (see Section 15.13).

```
// Fig. 17.2: BankUIForm.cs
// A reusable Windows Form for the examples in this chapter.
using System;
using System.Windows.Forms;

namespace BankLibrary
{
    public partial class BankUIForm : Form
    {
        protected int TextBoxCount { get; set; } = 4; // number of TextBoxes
        // enumeration constants specify TextBoxIndices
        public enum TextBoxIndices {Account, First, Last, Balance}

        // parameterless constructor
        public BankUIForm()
        {
            InitializeComponent();
        }

        // clear all TextBoxes
        public void ClearTextBoxes()
        {
            // iterate through every Control on form
            foreach (Control guiControl in Controls)
            {
                // If Control is TextBox, clear it
                if (guiControl is TextBox textBox)
                {
                    textBox.Clear();
                }
            }
        }

        // set text values to string array
        public void SetTextBoxValues(string[] values)
        {
            if (values.Length != TextBoxCount)
            {
                // throw exception if not correct length
                throw new ArgumentException($"There must be {TextBoxCount} strings in the array", nameof(values));
            }
            // set array values to TextBox values
            accountTextBox.Text = values[(int)TextBoxIndices.Account];
            firstNameTextBox.Text = values[(int)TextBoxIndices.First];
            lastNameTextBox.Text = values[(int)TextBoxIndices.Last];
            balanceTextBox.Text = values[(int)TextBoxIndices.Balance];
        }

        // return TextBoxValues as string array
        public string[] GetTextBoxValues()
        {
            return new string[] {
                accountTextBox.Text, firstNameTextBox.Text,
                lastNameTextBox.Text, balanceTextBox.Text};
        }
    }
}
```
