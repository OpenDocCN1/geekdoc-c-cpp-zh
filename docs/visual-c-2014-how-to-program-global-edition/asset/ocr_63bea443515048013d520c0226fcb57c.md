# Chapter 12 OOP: Polymorphism and Interfaces

# 12.3 Demonstrating Polymorphic Behavior

Section 11.4 created a commission-employee class hierarchy, in which BasePlusEmployee inherited from CommissionEmployee. The examples in that section manipulated CommissionEmployee and BasePlusEmployee by using references to them to invoke their methods. We aimed base-class references to base-class objects and derived-class references at derived-class objects. These assignments are natural and straightforward—base-class references are intended to refer to derived-class objects, however, other as-signments are intended to refer to derived-class objects.

The next example aims a base-class reference to a derived-class object via a base-class reference invokes the derived class functionality—the type of the actual object, not the type of reference, methods which is called. This demonstrates the concept that a derived-class object can be treated as an object of its base class, which enables various manipulations. An app can create a collection of base-class references to refer to objects of many derived-class types, for instance, we assign the reference of a BasePlusCommissionEmployee to a base-class CommissionEmployee because BasePlusCommissionEmployee is a CommissionEmployee—so we can treat a BasePlusCommissionEmployee as a CommissionEmployee.

A base-class is not an object of any of its derived classes. For example, we cannot directly assign the reference of a CommissionEmployee to a derived-class BasePlusCommissionEmployee variable, because CommissionEmployee does not, for example, have a baseSalary instance and does not have a BaseSalary property. The compiler allows the assignment of a base-class reference to a derived-class variable if we explicitly cast the base-class reference to the derived-class type—a technique we discuss in greater detail in Section 12.5.6.
