# Implied Typed Local Variables and Keyword var

In line 14

```
for (var counter = 0; counter < array.Length; ++counter)
```

notice var keyword has no type preceding the variable counter. This declares the variable and lets the compiler declare the variable's type, based on the variable's initialization. This is known as type inference and local variables declared in this manner are known as implicitly typed local variables. Here, the compiler infers that counter's type is int, because it's initialized with the literal 0, which is an int.

Similarly, consider line 11 of 4.9:

```
Account count1 = new Account("Jane Green");
```

Notice that the type Account appears twice—once to declare variable count1's type and to specify the type of the new object being created. From this point forward, the preference is written to this statement:

```
var count1 = new Account("Jane Green");
```

Here, the compiler count1's type is Account, because the compiler can determine the type from the expression

```
var next = new Account("Jane Green");
```

which creates an Account object.
The Microsoft of C# Coding Conventions

```
https://msdn.microsoft.com/library/f9926074
```

recommend using type inference when a local variable's type is obvious, based on its initial value. These coding conventions are guidelines, not requirements. In industry, your employer may have its own coding requirements that differ from Microsoft's guidelines.

# More on Implicit Typed Local Variables

Implied typed local variables also can be used to initialize an array via an initializer. In the following statement, the type of values is inferred as int[]

```
var values = new[] {32, 27, 64, 18, 95, 14, 90, 70, 60, 37};
```

new[] specifies the initializer list is for an array. The array's element type, int, is inferred from the initializer. The following statement—in which values are initialized without new[]—generates a compilation error

```
var values = {32, 27, 64, 18, 95, 14, 90, 70, 60, 37};
```

# Common Programming Error 8.6

Initializer lists can be used with both arrays and collections. If an implicitly typed local variable is initialized via an initializer list without new[], a compilation error occurs, because the compiler cannot infer whether the variable should be an array or a collection.
