# 21.2 Collections Overview

All collection classes in the .NET Framework implement some combination of the interfaces that declare the operations to be performed on various types of collections. Figure 21.1 lists some of the collection interfaces in namespace System.Collections.Generic which also have legacy-based analogs in System.Collections. Many collection classes implement these interfaces. You may also provide implementations specific to your requirements.

| Interface | Description |
|---|---|
| IEnumerable<T> | An object that can be enumerated—for example, a foreach loop can iterate over an object's elements. This interface contains one method, GetEnumerator, which returns an IEnumerator<T> object, (which you will see in Section 21.3) can be manually iterated through a collection. In fact, each collection's IEnumerable<T> extends Iumerable<T> so all collection classes implement Iumerable directly or indirectly. |
| Collection<T> | The interface which interfaces IList<T> and Dictionary<K,V> inherits. It has a Count property to determine the size of a collection and a CopyTo method for copying contents to a traditional array, and an IsReadOnly property. |
| IList<T> | An ordered collection that can be manipulated using a [] operator (known as index) for accessing elements with an int index. It also has methods for searching and modifying a collection, including Add, Remove, Contains and IndexOf. |
| Dictionary<K,V> | A collection of values, indexed by an arbitrary "key" of type K. Provides an indexer [] for accessing elements by key and for modifying the collection (e.g., Add, Remove). Dictionary<K,V> property Keys contains all the keys, and property Values contains all the stored values.

Namespace.Collections.Generic
With the collections of the System.Collections.Generic namespace, you can specify the exact type that will be stored in a collection. This provides two benefits over the object-based legacy collections:

+   * Compile-time checking ensures that you are using appropriate types with your collection and, if not, the compiler issues error messages.
* Any item you retrieve from a generic collection will have the correct type. With object-based collections, any item you retrieve is returned as an object. Then, you must explicitly cast the object to the type that your program manipulates. This could lead to InvalidCastExceptions at execution time if the referenced object does not have the appropriate type.
