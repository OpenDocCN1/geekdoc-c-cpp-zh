You can access many common menu commands from the toolbar (Fig. 2.7), which contains icons that graphically represent them for the most common commands. By default, the standard toolbar is displayed when you run Visual Studio for the first time—it contains icons for the most used commands, such as opening a file, saving and running apps (Fig. 2.7). The icons that appear on the standard toolbar may vary, depending on the version of Visual Studio you're using. Some commands are initially disabled (grayed out or unavailable to use). These commands are enabled by Visual Studio only when you can use them. For example, Visual Studio enables the command for saving a file once you begin editing a file.

To execute a command via the toolbar, click its icon.

## 2.4 Navigating the Visual Studio IDE

The IDE provides windows for accessing project files and customizing controls. This section introduces several windows that you'll use frequently when developing Visual Studio. Each of the IDE's windows can be accessed by selecting its name in the View menu.

### Auto-Hide

Visual Studio provides an auto-hide space-saving feature. When auto-hide is enabled for a window, a tab containing the window's name appears over the IDE's window left, right or bottom edge (Fig. 2.10). Clicking the name of an auto-hidden window displays the window (Fig. 2.11). Clicking the name again (or clicking outside) hides the window. To "pin down" a window (that is, to disable auto-hide and keep the window open), click the pin icon. When auto-hide is enabled, the pin icon is horizontal as shown in Fig. 2.11.

![](img/57baed2319be0bb1b5f98674846f2711_82_0.png) (Fig. 2.11)

When a window is "pinned down," the pin icon is vertical as shown in Fig. 2.12.

The next sections present three Visual Studio windows that you'll use frequently—the Solution Explorer, the Properties window and the Toolbox. These windows display project information and include tools that help you build your apps.

### 2.4.1 Solution Explorer

The Solution Explorer (Fig. 2.13) provides access to all of a solution's files. If it's not shown in the IDE, select View > Solution Explorer. When you open a new or existing solution, the Solution Explorer displays the solution's contents.

![](img/57baed2319be0bb1b5f98674846f2711_83_1.png)

Fig. 2.13 Solution Explorer window showing the WindowsFormsApplication1 project.

The solution's start project (shown in **bold in the Solution Explorer**) is the one that runs when you select Debug > Starting (or press F5) or select Debug > Without Debugging (or press Ctrl+F5). For a single-project solution like the example in this book, the start project is the only project (in this case, WindowsFormsApplication1). When you create an app for the first time, the Solution Explorer appears as shown in Fig. 2.13. The C# file that connects to the Form shown in Fig. 2.4 is named Form1.cs. Visual C# files use the .cs file extension, which is short for “C#.”

By default, the IDE only displays files that you need to edit—other files that the IDE generates are hidden. The **Solution Explorer** window includes a toolbar that contains several icons. Clicking the Show All icon (Fig. 2.13) displays all the solution's files, including those generated by the IDE. Clicking the arrow to the left of a node expands or collapses that node. Clicking the arrow again to collapse the tree. Other Studio windows also use this convention.

### 2.4.2 Toolbox

To display the Toolbox, select View > Toolbox. The Toolbox contains the controls you can “drag and drop” onto the Forms (Fig. 2.15). With visual development, the IDE will write the code that creates the controls. This is faster and simpler than writing this code yourself. Just as you do not need to know how to build an engine to drive a car, you do not need to know how to build controls to use. Reusing preexisting controls saves time and money.

The Toolbox groups prebuilt controls into categories—All Forms, Common Controls, Containers, Menus & Toolbars, Data, Components, Printing, Dialogs, Reporting, WPF Interoperability and General are listed in Fig. 2.15. Note the use of arrows for expanding or collapsing a group of controls. With many of the Toolbox’s controls and functionality throughout the book.

### 2.4.3 Properties Window

If the Properties window is not displayed below the Solution Explorer, select View > Properties Window to display it—if the window is in auto-hide mode, pin down the window by clicking its horizontal icon. The Properties window contains the properties for the currently selected Form, control or file in the IDE. Properties specify information about the Form or control, such as its size, color and position. Each Form has its own set of properties. When you select a property, its description is displayed at the bottom of the Properties window.

Figure 2.16 Form1's Properties window—you can view by clicking anywhere in the Form1.cs design view. The left column lists the Form properties—the right column displays the current value of each property. You can sort the properties either:

- alphabetically (by clicking the Alphabetical icon)
- categorically (by clicking the Categorized icon).

Depending on the Properties window, some properties may be hidden from your view. You can scroll through the list of properties by dragging the scrollbox up or down inside the scrollbar, or by clicking the arrows at the top and bottom of the toolbar. We show how to set individual properties later in this chapter.
