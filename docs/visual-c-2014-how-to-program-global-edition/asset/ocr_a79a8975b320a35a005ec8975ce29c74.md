# Efficiency of Binary Search

In the worst-case scenario, searching a sorted array of 1,023 elements causes *Binary*-Search to loop iterate only 10 times. Repeating 1023 by 2 (because each iteration, eliminates half of the array) and rounding down (because we remove the middle element) yields values 511, 255, 127, 63, 31, 15, 7, 3, 1 and 0. The number 1023 ($2^{10} - 1$) is divided by 10 times to get the value 0, which indicates that there are no more elements to test. Dividing by 2 is equivalent to one loop iteration in the binary search algorithm. Thus, an array of 1,048,575 ($2^{20} - 1$) elements takes a maximum of 20 to 30 iterations. This is a tremendous improvement in performance over the linear search. For a billion-element array, this is a difference between an average of 500 iterations for the linear search and a maximum of 30 iterations for the binary search! The number of iterations needed for the binary search of any sorted array is the exponent of the power of 2 that the number of elements in the array, which is represented as $\log n$. All logarithms grow at roughly the same rate, in Big O notation the base is omitted. This results in a Big O of $O(\log n)$ for a binary search, which is also known as logarithmic runtime.

# 18.3 Sorting Algorithms

Sorting data (i.e., placing the data in some particular order, such as *ascending or descending*) is one of the most important computing applications. A bank sorts by check account number so that it can prepare individual bank statements at the end of each month. Telephone companies sort their lists of accounts by name and last, and by first name to make it easy to find phone numbers. Virtually every organization will sort some data—that has attracted substantial, compute-intensive problem research.

It's important to understand that sorting is the *end result*—the sorted array. The choice of algorithm affects only the runtime and *memory use* of the app. The rest of the chapter introduces three common sorting algorithms. The first two—*selection sort* and *insertion sort*—are simple to program, but inefficient. The last—*merge sort*—is much faster than selection sort and insertion sort but more difficult to program.
