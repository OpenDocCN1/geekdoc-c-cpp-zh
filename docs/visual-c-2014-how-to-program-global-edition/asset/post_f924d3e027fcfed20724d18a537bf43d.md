## Answers to Self-Review Exercises

- 1.1 a) 16, because an O(n²) algorithm takes 16 times as long to sort four times as much information. b) O(n log n).

- 1.2 Both of these incorporate “halving”—reducing something by half. The binary search eliminates from consideration one half of the array after each comparison. The merge sort splits the array in half each time it's called.

- 1.3 The insertion sort is easy to understand and perform compared to the merge sort. The merge sort is far more efficient (O(n log n)) than the insertion sort (O(n²)).

- 1.4 In a sense, it does not really sort these two. It simply splits the array in half until it provides a one-element subarray, which is, of course, sorted. It builds up the original by merging these one-element arrays to form larger subarrays, which are merged until the whole array has been sorted.

## Exercises

1.5 (Bubble Sort) The bubble sort—another simple, yet inefficient, sorting technique. It's built by sinking sort because smaller values “bubble” to rise to the top of the array (i.e., toward the first element) as bubbles rising in water, while the larger values sink to the bottom (end) of the array. The technique uses nested loops to make several passes through the array. Each pass compares successive overlapping pairs of elements (i.e., elements 0 and 1, 1 and 2, 2 and 3, etc.). If a pair is in increasing order (or the values are equal), the bubble sort leaves the values as they are. If a pair is in decreasing order, the bubble sort swaps their values in the array.

The first pass compares the first two elements of the array and swaps them if necessary. It then compares the second and third elements. The end of this pass compares the last two elements in the array and swaps them if necessary. After one pass, the largest element will be in the last position. After two passes, the largest elements will be in the last two positions. Why is bubble sort O(n²)?

18.7 (Bucket Sort) A bucket sort begins with a one-dimensional array of positive integers sorted into a two-dimensional array with rows from 0 to 9 and columns from 0 to n-1, where n is the number of values to be sorted. Each row of the two-dimensional array is referred to as a bucket. A class named BucketSort contains a method called sort that operates as follows:

- Place each value of the one-dimensional array into a row of the bucket array based on the "ones" (rightmost) digit. For example, 97 is placed in row 7, 3 is placed in row 3 and 100 is placed in row 0. This procedure is called a distribution pass.
- Loop through each bucket and copy the values back to the original array. This procedure is called a gathering pass. The new order of values in the one-dimensional array is 100, 3 and 97.
- Repeat this process for each subsequent digit (tens, hundreds, etc.). On the second pass (tens digit), 100 is placed in row 0, 3 is placed in row 0 (because it has no tens digit) and 97 is placed in row 9. After the gathering pass, the order of values in the one-dimensional array is 100, 3 and 97. On the third pass (hundreds digit), 100 is placed in row 1, 3 is placed in row 0. The two-dimensional array of buckets is 10 times the length of the array being sorted. This sorting technique provides better performance than bubble sort, but requires more memory—bubble sort requires space for only one additional element of data. This comparison is an example of space/time trade-off; bucket sort uses more memory than bubble sort, but performs better. This version of bubble sort requires copying all the data back to the original array on each pass. Another possibility is to create a two-dimensional bucket array and repeat the swap between the buckets.

18.10 (Quicksort) The recursive sorting technique quicksort uses the following basic algorithm for a one-dimensional array of values:

- a) Partitioning Step: Take the first element of the unsorted array and determine its final location in the sorted array (i.e., all values to the left of the element in the array are less than it, and all values to the right of the element in the array are greater than it—we show how to do this below). We now have one element in its location and two unsorted subarrays.
- b) Recursive Step: Perform Step a on each unsorted subarray.

Each step a performed on a subarray creates another element and two unsorted subarrays. When a subarray consists of one element, the element is in its final location (because a one-element array is already sorted). The basic algorithm seems simple enough, but how do we determine the final position of the first element of each subarray? For example, consider the following set of values (the element in bold is the partitioning element—it will be placed in its final location in the sorted array):

37 2 6 4 8 9 10 12 68 45

- Starting from the rightmost element, compare each element with 37 until an element less than 37 is found, swap and element. The first element less than 37 is 12, so 37 and 12 are swapped. The new array is:

12 2 6 4 8 9 10 37 68 45

12 is in italics to indicate that it was swapped with 37.

- Starting from the left of the array, beginning with the element 12, compare each element with 37 until an element greater than 37 is found—swap 37 and element. The first element greater than 37 is 89, so 37 and 89 are swapped. The new array is:

12 2 6 4 37 8 10 89 68 45

- Starting from the right, beginning with the element 89, compare each element with 37 until an element less than 37 is found, swap and element. The first element less than 37 is 10, so 37 and 10 are swapped. The new array is:

12 2 6 4 10 37 8 89 68 45

- Starting from the left, beginning with the element 10, compare each element with 37 until an element greater than 37 is found—swap and element. There are no elements greater than 37, so when we compare 37 with itself, we know that 37 has been placed in its final location of the sorted array. Every value to the left of 37 is smaller than it, and every value to the right of 37 is larger than it.

Once the partition has performed on the previous array, the subarray with values less than 37 contains 12, 2, 6, 4, 10 and 8. The subarray with values greater than 37 contains 89, 68, and 45. The sort continues recursively, with both subarrays being partitioned in the same manner as the original array.
