# Summary 503

+   - A derived class is more specific than its base class and represents a more specialized group of objects.
- The is-a relationship represents inheritance. In an is-a relationship, an object of a derived class can also be treated as an object of its base class.

# Section 11.2 Base Classes and Derived Classes

+   - Inheritance relationships form treelike hierarchical structures. A base class exists in a hierarchical relationship with its derived classes.
- Objects of all classes that share a common base class can be treated as objects of that base class. However, base-class objects cannot be treated as objects of their derived classes.
- When a base-class method is inherited by a derived class, that class often needs a customized-version of the method. In such cases, the derived class can override the base-class method with an appropriate implementation.

# Section 11.3 protected Members

+   - Using protected offers an intermediate level of access between public and private. A base-class protected members can be accessed by members of base class and members of the derived class.
- Base-class members retain their original access modifier when they become members of the derived class.
- Methods of a derived class cannot directly access private members of the base class.

# Section 11.4.1 Creating and Using a Employee Class

+   - A colon ( followed by a base-name at the end of a class declaration header indicates that the declared class extends the base class.
- If a class does not inherit from another class, the class implicitly inherits from object.
- The first task of any derived class constructor is to call its direct base class's constructor, either explicitly or implicitly (if no constructor is specified).
- Constructors are not inherited. If a class does not have constructors, the default constructor that the compiler declares will call the base class's default or parameterless constructor.
- ToString is one of the methods that every class inherits directly or indirectly from class object, which is the root of the C# hierarchy.
- To override a base-class method, a derived class must declare the method with keyword override and with the same signature (method name, number of parameters and parameter types) and return type as the base-class method. Also, the base-class method must be declared virtual.
- It's a compilation error to override a method with a different access modifier.

# Section 11.4.2 Creating a Employee Class Without Using Inheritance

+   - Copying and pasting code from one class to another can spread errors across multiple source-code files. To avoid duplicating (and possibly errors) in situations where you want one class to "absorb" the other class, use inheritance.
