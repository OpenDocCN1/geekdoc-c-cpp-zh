# 7.9.1 Method RollDice

In the rules of the game, the player must roll two dice on the first roll and do the same on all subsequent rolls. We declare Roll1Dice (lines 83–94) to roll the dice and compute and display their sum. Roll1Dice is declared once, but it's called from two places (lines 30 and 54) in method Main, which contains the logic for complete game of craps. Roll1Dice takes no arguments, so it has an empty parameter list. Each time it is called, Roll1Dice returns the sum of the dice as an int. Although lines 86 and 87 look the same (except for the dice), they do not necessarily produce the same result. Each of these statements produces a random value in the range 1–6. # 7.9.2 Main's Local Variables

The game is reasonably involved. The player may win or lose on the first roll or lose on any subsequent roll. Method Main (lines 24–80) use local variable gameStatus (line 27) to keep track of the game status, local variable myPoint (line 28) to store the "point" if the player does not win or lose on the first roll and local variable sumPoint (line 30) to maintain the sum of the dice for the most recent roll. Variable myPoint is initialized to 0 to ensure that the app will compile. If you do not initialize myPoint, the compiler error occurs because myPoint is not assigned a value in every case of the switch statement—thus, the app could use myPoint before it's defined assigned value. By contrast, gameStatus does not require initialization because it's assigned a value in every branch of the switch statement—thus, it's guaranteed to be initialized before it's used. However, as good practice, we initialize anyway.
