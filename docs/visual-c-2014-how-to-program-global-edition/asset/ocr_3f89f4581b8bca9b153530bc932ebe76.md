# 16.2 Fundamentals of Characters and Strings

Characters are the fundamental building blocks of C# source code. Every program is composed of characters, when grouped together meaningfully, create a sequence that the compiler interprets as instructions describing how to accomplish a task. A program can also contain character constants. Character constant is a constant that's represented as an integer value, called a character code. For example, the integer value 122 corresponds to the character 'z'. The integer value 10 corresponds to the newline character '\n'. Character constants are established according to the Unicode character set, an international character set that contains many symbols and letters than does the ASCII character (listed in Appendix C). To learn more about Unicode, see our online appendix.

A series of characters treated as a unit: these characters can be uppercase letters, lowercase letters, digits and special characters: +, -, *, /, and others. A string is an object of type. Just as the C keyword object is an alias for class object, string is an alias for class (namespace System). We write string literals, also called string constants, as sequences of characters in double quotation marks, as follows:

> "John Q. Doe"
"9999 Main Street"
"Waltham, Massachusetts"
"(201) 555-1212"

A declaration can assign a string to a string reference. The declaration

```
string color = "blue";
```

initializes the color to refer to the string literal "blue".

# Performance Tip 16.I

If there are multiple occurrences of the same string literal in an app, a single copy of it will be referenced from each location in the program that uses that string literal. It is possible to share the object in this manner, because string literals are implicitly constant. String sharing saves memory.

# Verbatim strings

Recall that backslashes in strings introduce escape sequences and that placing a backslash in a string requires \\. On occasion, a string will contain multiple backslashes (this often in the name of a file). To avoid excessive backslashes, it is possible to exclude escape sequences and interpret all the characters in a string literally, using the @ character to mark what is known as a verbatim string. Backslashes within the double quotation marks following the @ are not considered to be part of escape sequences. This simplifies programming and makes code easier to read.

For example, consider the string in the following assignment:

```
string file = "C:\MySubFolder\MySubFolder\MyFile.txt";
```

Using the verbatim syntax may also span multiple lines, in which case they preserve all newlines,

spaces and tabs between the opening @ and closing " delimiters.
