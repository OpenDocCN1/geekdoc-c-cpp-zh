+   - The worst case in linear search is that every element must be checked to determine whether the search item exists. This occurs if the search key is the last element in the array or is not present.

# ##18.2.2 Binary Search

+   - The binary search algorithm is more efficient than the linear search algorithm, but it requires that the array be sorted.

+   - The first iteration of binary search tests the middle element. If this is the search key, the algorithm returns its location. If the search key is less than the middle element, the search continues with its first half. If the search key is greater than the middle element, the search continues with its second half. Each iteration of binary search tests the value of the remaining array, and if it is not found, eliminates half of the remaining elements.

+   - Binary search is a more efficient searching algorithm than linear search because each partition eliminates consideration half of the elements in the array.

+   - Binary search runs in O(log n) time, because each step removes half of the remaining elements.

# ##18.3.1 Selection Sort

+   - The selection sort is simple, but inefficient, sorting algorithm.

+   - The first iteration of selection sort sorts the smallest element in the array and swaps it with the first element. The second iteration sorts the second-smallest element (which is the smallest remaining element) and swaps it with the second element. Selection sort continues until the largest element is in the last position. After the ith iteration of selection sort, the smallest i elements of the whole array are sorted in the first positions

+   - The selection sort algorithm runs in O(n²) time.

# ##18.3.2 Insertion Sort

+   - The first iteration of insertion sort takes the second element in the array and, if it's less than the first, swaps them. The second iteration looks at the third element and inserts it in the correct position with respect to the first two. After the ith iteration of insertion sort, the first i elements of the original array are sorted.

+   - The insertion sort algorithm runs in O(n²) time.

# ##18.3.3 Merge Sort

+   - Merge sort is a sorting algorithm that is faster, but more complex to implement, than selection and insertion sort.

+   - The merge sort sorts an array by splitting it into two equal-sized subarrays, sorting each recursively and merging them into one large array.

+   - Merge sort's base case is an array with one element. A one-element array is already sorted.

+   - Merge sort performs the merging by looking at the first element in each array, which is also the smallest. Merge sort sorts the smallest of these and places it in the first of the larger array. If there are still elements in the subarray, merge sort looks at the second element in that subarray (which is now the smallest element) and compares it to the first element in the other subarray. Merge sort continues until the larger array is filled.

+   - In the worst case, the first call to merge sort has to make O(n) comparisons to fill the n slots in the final array.

+   - The merging portion of merge sort is performed on two subarrays, each of approximately n/2. Creating each of these subarrays requires n/2 - 1 comparisons per subarray, or O(n) comparisons total. This pattern continues as level twice as many arrays, but each is half the size of the previous array. Similar to binary search, this halving in log n levels for a total efficiency of O(n log n).
