## 11.1 Introduction

This chapter continues our discussion of object-oriented programming (OOP) by introducing one of its primary features—inheritance, a form of software reuse in which a new class is created by absorbing existing class's members and enhancing them with new or modified capabilities. Inheritance lets you save time during development by reusing proven, high-performance and debugged-quality software. This also increases the likelihood that a system will be implemented effectively.

The existing class from which new class inherits is the base class, and the new class is the derived class. A derived class normally adds its own fields, properties and methods. Therefore, it's more specific than its base class and represents a more specialized group of objects. The derived class exhibits the behaviors of its base class and additional ones that are specific to it.

The direct base class is the class from which a derived class inherits. The direct base class in the class hierarchy defines the inheritance relationships between classes. Section 11.7 lists class object—a C# keyword that's an alias for System.Object in the Framework Class Library. Every directly or indirectly extends (or inherits from) that object. Section 11.7 lists class object's methods, which every other class inherits. In single inheritance, a class is derived only once. C# supports from one direct base class. In Chapter 12, we explain how to use interfaces to realize many of the benefits of multiple inheritance.

## 11.2 Base Classes and Derived Classes

Often, an object of one class is an object of another class. For example, in geometry, a rectangle is a quadrilateral (as squares, parallerams and trapezoids). Thus, class Rectangle can be inherited from Quadrilateral. In this context, Quadrilateral is a base class and class Rectangle is a derived class. A rectangle is a specific type of quadrilateral, but it's incorrect to claim that quadrilateral is a rectangle—the quadrilateral could be a parallelogram or some other shape. Figure 11.1 lists several examples of base classes and derived classes—base classes tend to be more general, and derived classes tend to be more specific.

| Base class | Derived classes |
| --- | --- |
| Student | GraduateStudent, UndergraduateStudent |
| Shape | Circle, Triangle, Rectangle |
| Loan | CarLoan, HomeImprovementLoan, MortgageLoan |
| Employee | Faculty, Staff, HourlyWorker, CommissionWorker |
| SpaceObject | Star, Moon, Planet, FlyingSaucer |
| BankAccount | CheckingAccount, SavingsAccount |

> **Fig. 11.1** | Inheritance examples.

Because every derived-class is an object of its base class, and one base class can have many derived classes, the set of objects represented by a base class is typically larger than the set of objects represented by any of its derived classes. For example, the base class Vehicle represents all vehicles—cars, trucks, bicycles and so on. By contrast, derived car represents a smaller, more specific subset of vehicles.

Inheritance relationships form hierarchical structures (Figs. 11.2 and 11.3). A base class exists in a hierarchical relationship with its derived classes. When classes participate in inheritance, they become "affiliated" with other classes. A class becomes either a base class, supplying members to other, or a derived class, inheriting its members from another.
