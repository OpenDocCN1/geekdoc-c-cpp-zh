
结果是对 `SortArray` 方法进行两次递归调用，其子数组的大小约为原数组的一半，并调用一次 `Merge` 方法。这次对 `Merge` 的调用最坏情况下需要 $n-1$ 次比较来填充原始数组，其复杂度为 $O(n)$。（回想一下数组中的每个元素可以通过比较每个子数组中的一个元素来选取。）两次 `SortArray` 方法的调用会导致四次 `SortArray` 递归调用，每个子数组的大小大约是原数组的四分之一，并调用两次 `Merge` 方法。这两次调用需要 $n/2-1$ 次比较，总比较次数为 $(n/2-1)+(n/2-1)=n-2$，以此类推，直到 `SortArray` 生成了两个额外的 `SortArray` 调用和一次 `Merge` 调用，直到算法将数组拆分为单元素子数组。在每一层中，都需要 $O(n)$ 次比较来合并子数组。每一层都将数组的大小减半，因此数组大小翻倍只需要多增加一层。数组大小增加四倍只需要两层。这种模式是对数级的，共有 $\log n$ 层。这导致了总效率为 $O(n \log n)$。

## 性能提示 18.2

正如你所注意到的，实现合并排序高效的关键在于巧妙地使用额外内存。这是空间/时间权衡的另一个例子：如果你有更多空间，可以让算法运行得更快；如果你空间较少，算法可能需要更多时间。在工业领域，你可能会为内存受的设备开发应用，这可能会阻止你使用合并排序算法。

## 总结

### 第 18.1 节 引言

- 搜索值确定数据中是否存在，如果存在则找到其位置。
- 排序涉及对数据进行排序。

### 第 18.2.1 节 线性查找

- 线性查找顺序搜索数组元素，直到找到与搜索键匹配的元素。如果数组中不存在，则搜索失败。

### 第 18.2.2 节 二分查找

- 二分查找要求先对数据进行排序。对于大型数据集，它比线性查找快得多。

### 第 18.3.1 节 选择排序

- 选择排序找到最小元素并将其交换到第一个位置。

### 第 18.3.2 节 插入排序

- 插入排序通过将每个新元素插入其正确位置，逐个构建排序数组。

### 第 18.3.3 节 合并排序

- 合并排序是一种分治法算法，对于排序大型数据集非常高效。
