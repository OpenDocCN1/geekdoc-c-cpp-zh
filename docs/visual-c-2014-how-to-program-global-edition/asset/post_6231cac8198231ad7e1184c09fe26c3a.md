
# Chapter 7 Methods: A Deeper Look

## Software Engineering Observation 7.8

By default, C# does not allow you to choose whether to pass any argument by value or reference. Value types are passed by value. Objects are not passed to methods; rather, references to objects are passed by value. When a method receives a reference to an object, the method can manipulate the object directly, but the reference value cannot be changed to refer to a new object.

## 7.18.2 Demonstrating ref, out and Value Parameters

The app in Fig. 7.20 uses ref and out keywords to manipulate integer values. The class contains three methods that calculate the square of an integer.

```cs
// Fig. 7.20: ReferenceAndOutputParameters.cs
// Reference, output and value parameters.
using System;

class ReferenceAndOutputParameters
{
    // call methods with reference, output and value parameters
    int y = 5; // initialize y to 5
    int z; // declares z, but does not initialize it

    // display original values of y and z
    Console.WriteLine($"Original value of y: {y}");
    Console.WriteLine($"Original value of z: uninitialized\n");

    // pass y and z by reference
    SquareRef(ref y); // must use keyword ref
    SquareOut(out z); // must use keyword

    // display values of y and z after they're modified by method
    // SquareRef and SquareOut, respectively
    Console.WriteLine($"Value of y after SquareRef: {y}");
    Console.WriteLine($"Value of z after SquareOut: {z}\n");

    Square(y);
    Square(z);

    // display values of y and z after they're modified by method
    // to demonstrate arguments passed by value are not modified
    Console.WriteLine($"Value of y after Square: {y}");
    Console.WriteLine($"Value of z after Square: {z}");
}

// uses reference parameter to modify caller's variable
static void SquareRef(ref int x)
{
    x = x * x;
}

// uses output parameter to assign a value to uninitialized variable
static void SquareOut(out int x)
{
    x = 6; // assigns a value to caller's variable
    x = x * x; // squares value of caller's variable
}

// parameter receives a copy of the value passed as argument,
// so this method cannot modify the caller's variable
static void Square(int x)
{
    x = x * x;
}
```

| Method | Description |
| :--- | :--- |
| `SquareRef(ref int x)` | lines 37–40: multiplies parameter x by itself and assigns the new value to x. Because the parameter is declared as ref, it modifies the original argument's value in the caller. |
| `SquareOut(out int x)` | lines 44–48: multiplies parameter value 6, which squares. parameter is declared as out, which indicates that the argument passed to this method does not need to be initialized. |
| `Square(int x)` | lines 52–55: multiplies parameter x by itself and assigns the new value to x. When this method is called, a copy of the argument is passed to parameter x. Thus, even if x is modified in the method, the original value in the caller is not modified. |

## 7.18 Passing Arguments By Value and By Reference

Lines 27–28 call Square with y and z as arguments. In this case, both values are passed by value—only copies of them are passed to Square. As a result, the values of y and z remain 25 and 36, respectively. Lines 32–33 output the values of y and z to show they were not modified.

> **Programming Error 7.14**: The ref and arguments in a method call must match the ref and out parameters specified in the method declaration; otherwise, a compilation error occurs.

In this chapter, we discussed the difference between non-static and static methods, and we showed how to call static methods by preceding the method name with the name of the class in which it appears and the member-access operator (.). # Summary

### Section 7.1 Introduction

- Experience has shown that the best way to develop and maintain a large app is to construct it from small, simple pieces. This technique is called divide and conquer.

### Section 7.2 Packaging Code in C#

- Three common ways of packaging code are methods, classes and namespaces.

### Section 7.2.1 Modularizing Programs

- Methods allow you to modularize an app by separating the tasks into self-contained units.
- Dividing an app into meaningful methods makes it easier to debug.

### Section 7.3 static Methods, Variables and Class

- You can call any static method by specifying the name of the class in which it appears, followed by the member-access operator (.), as `ClassName.MethodName(arguments)`.

### Section 7.3.2 Class Constants

- A constant is declared with the const keyword; its value cannot be changed after the statement.
- Math.PI (3.141592653589793) is the ratio of a circle's circumference to its diameter.
- Math.E (2.718281828459045) is the base value for natural logarithms.

### Section 7.3.4 Additional Comments About Main

- If you declare more than one method among the classes of your project, you'll need to indicate which one is the entry point. You can do this by clicking the menu Project > [ProjectName] Properties... and selecting the class containing the Main method from the Startup object list.
