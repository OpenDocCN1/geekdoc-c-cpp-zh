When the compiler encounters a method call like line 15, it analyzes the set of methods (both generic and generic) that match the method call, looking for a method that best matches the call. If there's no matching method, or if there's more than one match, the compiler generates an error.

In the case of line 15, the compiler determines that the best match occurs if the type parameter T in line 23 of DisplayArray's declaration is replaced with the type of the elements in the method call's argument intArray(int, int). Then the compiler calls up to DisplayArray with int as the type argument for the type parameter T. This is known as the type-inference process. The same process is repeated for the calls to method DisplayArray in lines 17 and 19.

# Common Programming Error 20.2

If the compiler cannot find a single generic or generic method declaration that's a best match for a method call, or if there are multiple best matches, a compilation error occurs.

For each variable declared with a type parameter, the compiler checks whether the operations performed are allowed for all types that the type parameter can assume. By default, a parameter can assume any type, but we'll show in Section 20.4 that you can restrict to this specific type. The only operation performed on array element in this example is to output its string representation. Line 27 performs an implicit toString call on the current array element. Since all objects have a toString method, the compiler is satisfied that line 27 performs a valid operation for any array element.

By declaring DisplayArray as a generic method in Fig 20.3, we eliminated the need for the overloaded methods of Fig 20.1, saving 22 lines of code and creating a reusable method that can output the string representations of any one-dimensional array, not arrays of int, double or char elements.

# Value vs. Reference Types in Generics

The compiler handles value and reference types differently in generic methods. When a type-value argument is used for a given type parameter, the compiler generates a version of the method's specific to that value parameter—if one has been generated previously, the compiler reuses that one. So in Fig.20.3, the compiler generates three versions of method DisplayArray—each for int, double and char. If DisplayArray were called with a reference type, the compiler would also generate a single version of the method that's used by all reference types.

# Explicit Type Arguments

You can use explicit type arguments to indicate the exact type that should be used to a generic function. For example, line 15 could be written

DisplayArray<int>(intArray); // pass an int array argument
