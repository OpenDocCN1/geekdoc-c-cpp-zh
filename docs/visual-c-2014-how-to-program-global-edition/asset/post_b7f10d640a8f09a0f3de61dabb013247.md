## 5.10.5 Braces in a while Statement

Notice the while statement’s block in Fig. 5.11 (lines 20–27). Without the braces, the loop would consider to be only the first statement, which adds the grade to the total. The last three statements in the block would fall outside the loop’s body, causing the computer to interpret the code incorrectly as:

```
while (grade != -1)
    total = total + grade; // add grade to total
    gradeCounter = gradeCounter + 1; // increment counter
```

```cs
// prompt for input and read grade from user
Console.Write("Enter grade or -1 to quit: ");
grade = int.Parse(Console.ReadLine());
```

The preceding code would cause an infinite loop if the user did not enter the sentinel -1 at line 16 (before the while statement).

> Error-Prevention Tip 5.5
Omitting the braces that delimit a block can lead to logic errors, such as infinite loops. To prevent this and other problems, we always enclose the body of every control statement in braces even if the body contains only a single statement.

## 5.10 Formulating Algorithms: Sentinel-Controlled Iteration

### Cast Operator

To perform a floating-point calculation with integers in this example, you first create a temporary floating-point value using the unary cast operator. Line 34 uses the (double) unary operator—which has higher precedence than the arithmetic operators—to create a temporary copy of its operand total, which appears to the right of the operator. The value stored in total is still an integer. Using a cast operator in this manner is explicit conversion.

### Promotions

After the cast operation, the compilation consists of temporary copy of total divided by the integer counter. For arithmetic, the compiler knows how to evaluate only expressions in which the operands are identical. To ensure this, the compiler performs an operation (also called implicit conversion) on an expression containing values of int and double, the compiler promotes int to double values. So, in line 34, the compiler creates a temporary copy of gradeCounter's value double, then performs the floating-point division. Finally, average is initialized with the floating-point value. Section 7.6.1 discusses the allowed-simple promotions.

### Cast Operators for Any Type

We discuss cast operators for other types in Chapter 12. The cast is formed by placing parentheses around the name of a type. This operator is a unary operator—it takes only one operand. C# also supports unary versions of the plus (+) and minus (-) operators—so you can write expressions like +5 or -7. Cast operators have the second precedence. (See the operator chart in Appendix A.)

## 5.10.7 Formatting Floating-Point Numbers

Line 39

```cs
Console.WriteLine("average is {average:F}");
```

outputs the class average. In this example, we decided that we'd like to display the average rounded to the nearest hundredth and output the average with exactly two digits to the right of the decimal. The format specifier F in the interpolation expression

```cs
{average:F}
```

typically formats average's value with two digits to the right of the decimal point—again, the Windows culture settings on the user's machine determine the actual format, including the digits to the right of the decimal point, whether commas or periods are used for separating thousands, millions, etc.

### Rounding Floating-Point Numbers

When the F specifier is used to format a floating-point value, the formatted value is rounded to a specific decimal position, although in memory remains un-tered. In many cultures a floating-point value output with F will be rounded to the hundredth position—for example, 123.457 will be rounded to 123.46, and 27.333 will be rounded to 27.33—some cultures these values are rounded to whole numbers. In this app, the three grades entered during the sample execution 257, which yields the average 86.66666... In the United States, the F format rounds to the hundredths position, so the average is displayed as 85.67.

## 5.11 Formulating Algorithms: Nested Control Statements

For the next example, we once again formulate an algorithm using pseudocode and top-down, refinement, and write a corresponding C# app. We see that control statements can be stacked on top of one another (in sequence). In this case, we examine the only other structured control statements that can be connected, namely by nesting one statement within another.

### 5.11.1 Problem Statement

Consider the following problem statement:

> A college offers a course that prepares students for the state licensing exam for real-estate brokers. Last year, 10 of the students who completed this course took the exam. You've been asked to write an app to summarize the results. How well students did on the exam. You've been given a list of these 10 students. Next to each name is written 1 if the student passed or 2 if the failed. Your app should analyze the results as follows

> Analyze exam results and decide whether the instructor should receive a bonus

Let's proceed with top-down, stepwise refinement. We begin with a pseudocode representation of the top:

> Analyze exam results and decide whether the instructor should receive a bonus

Once again, the top is a complete representation of the app, but several refinements are likely to be needed before the pseudocode can evolve into a C# app.

### 5.11.3 Top-Down, Stepwise Refinement: First Refinement

Our first refinement is

+   * Initialize variables
Input the 10 exam results, and count passes and failures
Display a summary of the exam results and decide if the instructor should receive a bonus

Here, too, even though we have a complete representation of the entire app, further refinement is necessary. We now specify individual variables. Counters are needed to record the passes and failures, a counter will be used to control the looping process and a variable is needed to store the user input. The variable in which user input be stored is not initialized at the start of the algorithm, because its value is read from the user during each iteration of the loop.
