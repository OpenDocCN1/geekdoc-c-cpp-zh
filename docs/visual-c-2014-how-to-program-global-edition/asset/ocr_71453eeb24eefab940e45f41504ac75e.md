# Chapter 4 Introduction to Classes, Objects, Methods and strings

In Fig. 4.6, class Account defined a Name property in which the setter simply assigned the value in its implicit parameter value to class Account's instance variable. The Name property did not ensure that name contains only valid data.

The Balance property setter performs validation (also known as validity checking). Line 27 (F.11) shows that the setter's implicit value parameter is greater than 0.0—the letter (m or M) indicates that 0.0 is a decimal literal. If value is greater than 0.0, the amount stored in value is assigned to instance variable (line 29). Otherwise, balance is left unchanged—we'll say more about error processing throughout the book.

Though we validated the balance in this example, we did not validate the name. Names are usually "free form”—there's a wide variety of acceptable name formats. When you fill out a form, you're asked to limit name to a certain number of characters. In Chapter 16, Strings and Characters: A Deeper Look, you will learn how to create a string's length, so you can validate strings by checking that they're not too long.

# set and get Access with Different Access Modifiers

By default, property's get and setter have the same access as the property—e.g., public Name public. It is possible to declare the get and setter with different access modifiers. In this case, one of the accessors must imply a more restrictive modifier than the property. We declared Balance property's setter private—this indicates it may be used only in Account, not by the class's. This enables us to ensure that any Account object exists, its balance can be modified only by method Deposit (and in the exercises, by method Withdraw as well).
