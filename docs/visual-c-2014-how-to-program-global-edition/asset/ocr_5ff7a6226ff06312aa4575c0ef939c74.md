Your simulator should check for various types of errors. During the programming phase, for example, each number the user enters into the Simpleton’s memory must be in the range -9999 to +9999. Your simulator should detect that each number entered is in this range and, if not, keep prompting the user to re-enter the number until user enters a correct number.

During the execution phase, your simulator should check for various errors, such as attempts to divide by zero, attempts to execute invalid code orders and accumulator overflows (i.e., arithmetic operations resulting in values larger than +9999 or smaller than -9999). Such errors are called fatal errors. When a fatal error is detected, your simulator should display an error message, as

> *** Attempt to divide by zero ***
*** Simpleton execution abnormally terminated ***

and display a full core dump in the format we discussed previously. This treatment will help the user locate the error in the program.
