# Chapter 7 Methods: A Deeper Look

```
// square method with double argument
static double Square(double doubleValue)
{
    Console.WriteLine("Called square with double argument: " + doubleValue);
    return doubleValue * doubleValue;
}
```

Called square with int argument: 7
Square of integer is 49
Called square with double argument: 7.5
Square of double 7.5 is 56.25

**Fig. 7.14** Overloaded method declarations. (Part 2 of 2.)

Line 10 in Main invokes Square with the argument 7. Literal integer values are treated as type int, so the method in line 10 invokes version of Square at lines 15–19 which specifies an int parameter. Similarly, line 11 invokes Square with the argument 7.5. Literal real-number values are treated as double, so the method in line 11 invokes the version of Square at lines 22–27 that specifies a double parameter. Each method outputs a line of text to prove that the proper method was called in each case.

The overloaded methods in Fig. 7.14 perform the same calculation, but with different types. C#'s generic features provide a mechanism for writing a single "generic method" that can perform the same task as an set of overloaded methods. We discuss generic methods in Chapter 20.

# 7.12.2 Distinguishing Between Overloaded Methods

The compiler distinguishes overloaded methods by their signature—a combination of the method's name, numbers and order of its parameters. The signature also includes how those parameters are passed, which can be modified by the ref and out keywords (discussed in Section 7.18). If the compiler looked only at method names during compilation, the code in Fig. 7.14 would be ambiguous—the compiler would not know how to distinguish between the Square methods (lines 15–19 and 22–27). Internally, the compiler uses signatures to determine which class's method is unique in that class.

For example, in Fig. 7.14, the compiler will use the signatures to distinguish between "Square of int" method (the Square method that specifies an int parameter) and the "Square of double" method (the Square method that specifies a double parameter). As Method1’s declaration begins as

```
void Method1(int a, float b)
```

then that will have a different signature than a method that begins with

```
void Method1(float a, int b)
```

The order of the parameter types is important—the compiler considers the preceding Method1 headers to be distinct.
