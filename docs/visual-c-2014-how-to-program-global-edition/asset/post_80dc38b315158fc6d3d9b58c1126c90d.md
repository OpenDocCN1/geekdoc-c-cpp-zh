## Good Programming Practice 12.1

By convention, the name of an interface begins with I (e.g., IPayable). This distinguishes interfaces from classes, improving code readability.

## Good Programming Practice 12.2

When declaring a method in an interface, choose a name that describes the method's purpose in a general manner, because the method may be implemented by a broad range of unrelated classes.

### 12.7.2 Declaring Interface IPayable

The declaration of interface IPayable begins in Fig. 12.11 at line 3. Interface IPayable contains public abstract method GetPaymentAmount(line 5). The method cannot be explicitly declared public or abstract. Interfaces can have any number of members and methods have parameters.

```cs
// 12.11: IPayable.cs
// IPayable interface declaration.
public interface IPayable
{
    decimal GetPaymentAmount(); // calculate payment; no implementation
}
```

Fig. 12.11 | IPayable interface declaration.

### 12.7.3 Creating Class Invoice

We now create class Invoice (Fig. 12.12) to represent a simple invoice that contains information for one part of kind. The class contains properties PartNumber (line 7), PartDescription (line 8), Quantity (lines 23–39) and PriceItem (lines 42–58) that indicate the part number, the description of the part, the quantity of the part ordered and the price per item. Class Invoice also contains a constructor (lines 13–20) and a ToString method (lines 61–63) that returns a string representation of an Invoice object. The set of properties Quantity and PriceItem ensure that quantity and priceItem are assigned only nonnegative values.

```cs
// 12.12: Invoice.cs
// Invoice class implements IPayable.
using System;
public class Invoice : IPayable
{
    public string PartNumber { get; }
    public string PartDescription { get; }
    private int quantity;
    private decimal priceItem;
    // four-parameter constructor
    public Invoice(string partNumber, string partDescription, int quantity,
        decimal priceItem)
    {
        PartNumber = partNumber;
        PartDescription = partDescription;
        Quantity = quantity; // validate quantity
        PriceItem = priceItem; // validate price per item
    }
```

Fig. 12.12 | Invoice class implements IPayable. (Part of 2.)

## Chapter 12 OOP: Polymorphism and Interfaces

To implement more than one interface, use a comma-separated list of interface names after the colon (:) in the class declaration, as in

```cs
public class ClassName : BaseClassName, FirstInterface, SecondInterface
```

When a class inherits from a base class and implements one or more interfaces, the class declaration must list the base-class name before any interfaces.

> Software Engineering Observation 12.6 C does not allow derived classes to inherit from more than one class, but it does allow a class to inherit from a base class and implement any number of interfaces.

Class Invoice implements the method in interface IPayable declared in line 66. The method multiplies the values of quantity and priceItem (obtained through the appropriate properties) and returns the result. This method satisfies the implementation requirement for the method in interface IPayable—we fulfilled the interface contract with the compiler.

### 12.7.4 Modifying Class Employee to Implement IPayable

We now modify Employee to implement interface IPayable (Fig. 12.13). This class declaration is identical to that of Fig. 12.4 with two exceptions:

- Line 3 of Fig. 12.13 indicates that class Employee now implements IPayable.
- Line 27 implements interface IPayable's GetPaymentAmount method.

Notice that GetPaymentAmount calls Employee's abstract method Earnings. At execution, when it is called on an object of derived class, GetPaymentAmount calls the concrete Earnings method which knows how to calculate earnings for objects of derived-type class.

```cs
// Fig. 12.13: Employee.cs
// Employee abstract base class that implements IPayable
public abstract class Employee : IPayable
{
    public string FirstName { get; }
    public string LastName { get; }
    public string SocialSecurityNumber { get; }

    // three-parameter constructor
    public Employee(string firstName, string lastName,
        string socialSecurityNumber)
    {
        FirstName = firstName;
        LastName = lastName;
        SocialSecurityNumber = socialSecurityNumber;
    }
}
```

Fig. 12.13 | Employee abstract base class that implements IPayable. (Part of 2.)

```cs
// return string representation of Employee object, using properties
public override string ToString() => $"{LastName}\n" +

public virtual decimal GetPaymentAmount() => Earnings();
```

## Derived Classes of Employee and Interface IPayable

When a class implements an interface, the is-a relationship inherits inheritance. Class Employee implements IPayable, so we can say that an Employee is an IPayable, and any object of Employee class is also an IPayable. If we update the hierarchy in Section 12.5 with the new Employee class in Fig. 12.13, SalariedEmployees, HourlyEmployees, CommissionEmployees and BasePlusEmployees are all IPayable objects. We can assign the reference of a SalariedEmployee-derived class to a base-class interface, we can assign the reference of a SalariedEmployee object (or any other Employee derived-class object) to an IPayable variable. Invoice implements IPayable, so an Invoice is also an IPayable object, and we can assign the reference of an Invoice object to an IPayable variable.

> Software Engineering Observation 12.7 Inheritance and interfaces are similar in implementation of the is-a relationship. Object of a class that implements an interface may be thought of as an object of that interface type. Object of any derived classes of a class that implements an interface can also be thought of as an object of the interface type.

![](img/57baed2319be0bb1b5f98674846f2711_539_1.png)

> Software Engineering Observation 12.8 The is-relationship exists between base classes and derived classes, and between interfaces and the classes that implement them, holds when passing an object to a method. When a method receives an argument of a base class or interface type, the polymorphically processes the object received as an argument.
