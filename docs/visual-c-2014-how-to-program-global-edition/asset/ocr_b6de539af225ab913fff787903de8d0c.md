Step 5: Making the AddressID TextBox ReadOnly
AddressID column of the addresses table is an autoinmented identity column, so users should not be allowed to edit the values in column. Select the TextBox for the AddressID and set its ReadOnly property to using the Properties window.

Step 6: Adding Controls to Allow Users to Specify a Last Name to Locate
While the Navigator allows you to browse the address book, it would be more convenient to find a specific entry by last name. To add this functionality to the app, we must create controls to allow the user to enter a name and provide event handlers to perform the search.

Add a Label named findLabel, a TextBox named findTextBox, and a Button named findButton. Place these controls in a Group named findGroup, then set its property to Find entry by last name. Set the Text property of the Label to Last Name: and set the Text property of the TextBox to Find.

Step 7: Allowing the User to Return to Browsing All Rows of the Database
To allow users to return to browsing all contacts after searching for specific contacts, add a Button named browseAllButton below the findGroup. Set the Text property of browseAll Browse Entries.

Method RefreshContacts
As showed in previous examples, we must connect the addressBindingSource that controls the GUI with the DbContext that interacts with the database. In this example, we declare the AddressEntities DbContext at line 20 of Fig. 22.41, and we create and initiate the data binding in the RefreshContacts method (lines 23–45), which is called from several other methods in the app. When this method is called, if dbcontext is not null, we use its Dispose method, then create a new AddressEntities DbContext at line 32. We do so so we can re-sort the data in the data model. If we maintained one dbcontext. Addresses object in memory for the duration of the program and the user changed a person's last name or first name, the records would still remain in their original order. Lines 36–39 order the Address objects by LastName, then FirstName and load the objects into memory. Then line 42 sets the addressBindingSource's DataSource property to dbcontext.Addresses.Local to bind the data in memory to the GUI.
