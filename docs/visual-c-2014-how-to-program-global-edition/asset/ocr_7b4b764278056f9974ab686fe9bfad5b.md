A relational database organizes data in tables. Figure 22.1 illustrates a sample Employees table that might be used in a personnel system. The table stores the attributes of employees. Employees are composed of rows (also called records) and columns (also called fields) which values are stored. The table consists of six rows (one per employee) and five columns (one per attribute). The ID column of each row is the table's primary key—a column (or group of columns) requiring a unique value that cannot be duplicated in others. This guarantees that each primary-key value can be used to identify one row. A primary key of two or more columns is known as a composite key—in this case, every combination of column values in the composite key must be unique. Good examples of primary-key columns in other apps are a book's ISBN in a book information system or a part number in an inventory system—values in each of these must be unique.
