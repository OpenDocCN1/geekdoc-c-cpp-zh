
# Chapter 7 Methods: A Deeper Look

There are several motivations for modularizing an app with methods:

- Soft reuse. For example, in previous apps, we did not have to define how to read a line of text from the keyboard—C# provides this capability via the Console's class's ReadLine method.
- Avoiding code repetition.
- Making programmers easier to test, debug and maintain.

> Software Engineering Observation 7.2
> To promote software usability, every method should be limited to performing a single, well-defined task, and the name of the method should express effectively.

## 7.2.2 Calling Methods

As you know, a method is invoked by a call, and when the called method completes its task, it returns control and possibly a result to its caller. An analogy to the method-call-and-return structure is the hierarchical form of management (Fig. 7.1).

![](img/57baed2319be0bb1b5f98674846f2711_280_0.png)

**Fig. 7.1** Hierarchical boss-method/worker-method relationship.

A boss (caller) asks a worker (the called method) to perform a task and report back (i.e., return) the results after completing the task. The boss does not need to know how the worker performs its tasks. The worker may call other methods, including one unknown to the boss. As we see, hiding of implementation promotes good engineering. Figure 7.1 shows the boss communicating with several workers in a hierarchical manner. The boss divides the responsibilities among various workers. Note that worker also acts as a “boss” to worker. The relationship does not need to be hierarchical, but often it is, which makes it easier to test, debug and update.

## 7.3 Static Methods

As mentioned in Section 6.6, although most methods are called to operate on specific objects, this is not always the case. Sometimes a method performs a task that does not depend on data of any object (other than the method's arguments). Such a method applies to the class in which it is declared and is known as a static method.

It's common for a class to contain a group of static methods to perform common tasks. For example, recall that we used Pow of class to raise a value to a power. To declare a method as static, use the static keyword before the return type in the method's declaration.

### 7.3.1 Math Methods

We use various methods of the Math class (from System namespace) that enable you to perform mathematical calculations. For example, you can calculate the square root of a value with the static method. We did not create a Math object before calling Sqrt, nor did we create a Console object before calling WriteLine. Also, all Math methods are static—therefore, each is called by the name of the class and the member operator (.). Method arguments may be constants, variables or expressions. If c = 13.0, d = 3.0 and f = 4.0, the following statement calculates and displays the square root of 13.0 + 3.0 * 4.0—namely, 5.0. In the figure, x and y of type double:

```csharp
double value = Math.Sqrt(9.0);
Console.WriteLine(Math.Sqrt(c + d * f));
```

## 7.3.2 Constants

The expression Math.Sqrt(900.0) evaluates to 30.0. Sqrt takes an argument of type double and returns a result of type double. The following statement displays in the console window using the preceding method:

```csharp
Console.WriteLine(Math.Sqrt(900.0));
```

Here, Sqrt returns the argument to WriteLine. We did not create a Math object before calling Sqrt. Also, all Math methods are static—therefore, each is called by the name of the method with the class and the member operator (.).

### 7.3.3 Why Is Main Static

Why must Main be static? During startup, no instance of the class are created. Main is typically called by the environment to begin execution. Declaring Main as static with the header:

```csharp
static void Main()
```

but can also be declared with:

```csharp
static void Main(string[] args)
```

which we'll discuss in Section 8.1, Using Command-Line Arguments. In addition, you can declare Main with return type int (instead of void)—this can be useful if an app is executed by another app and needs to return an indication of success or failure.
