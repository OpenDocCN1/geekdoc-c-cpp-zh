## 21.6 C# 6 Null Conditional Operator ?[]

Section 13.9 introduced nullable types and C# 6’s null-conditional operator (?), which checks whether a reference is null before using it to access a property or method. C# 6 provides another null-conditional operator, [], for arrays and collections that support the [] indexing operator.

Assume a class Employee has a decimal salary property and that an app defines a List<Employee> employees. The statement

```c
decimal? salary = employees[0]?.Salary;
```

uses null-conditional operators and executes as follows:

- The first ?(employees[0]) Salary short-circuits—that is, it terminates immediately—and the expression evaluates to null. In the preceding statement, this is assigned to nullable variable.
- If employees is not null, employees[0] accesses the element at position 0 of the List-Employee object, so we use the ?. operator to check whether employees[0] is null. If so, the entire evaluation evaluates to null; otherwise, the property’s value is assigned to salary. Note in the preceding statement that salary must be declared as a nullable type, because the expression employees[0]?.Salary can return null.

## 21.7 Dictionary Initializers and Collection Initializers

C# 6 supports two new features with respect to initializing collections—index initializers and using collection initial with collections.

### Index Initializers

Prior to C# 6, you could use a fully braced to initialize a Dictionary's key-value pairs. For example, if you have a Dictionary<string, int> named toolInventory, you could create and initialize it as follows:

```csharp
var toolInventory = new Dictionary<string, int>{
    { "Hammer", 13 },
    { "Saw", 17 },
    { "Screwdriver", 7 }
};
```

This is shorthand for creating the Dictionary using its Add method to add each value pairs. C# 6 introduces index initializers, which enable you to clearly indicate the key and the value in each key-pair as follows:

```csharp
var toolInventory = new Dictionary<string, int>{
    ["Hammer"] = 13,
    ["Saw"] = 17,
    ["Screwdriver"] = 7
};
```

### Collection Initializers

Prior to C# 6, any defined instance could be initialized with collection initializer. As of C# 6, the compiler also supports collection initializer for any collection that has an Add method.

## 21.8 Delegates

In Section 14.3.3, we introduced the concept of a delegate—an object that holds a reference to a method. You can call a method through a delegate—delegating the referenced method's responsibility of performing a task. Delegates also allow you to pass methods to and from other methods. We introduced delegates in the context of GUI event handlers, but they are used in many areas of the .NET Framework. For example, in Chapter 9, we used LINQ query syntax. The compiler converts such LINQ queries into extension methods—many of which have delegate parameters. In Section 21.1, we'll use delegates in the context of LINQ extension methods. This is similar to function pointers and function objects (also called functors) in C++.

### 21.8.1 Declaring a Delegate Type

Line 9 declares a delegate type named NumberPredicate. A variable of this type can store a reference to any method that takes one int and returns a bool. A delegate type is declared by preceding a method header with the keyword delegate (placed after any access specifiers, as public or private) and following the method header with a semicolon. A delegate declaration includes the method header only—the header describes a set of methods with specific parameters and a specific return type.

### 21.8.2 Declaring a Delegate Variable

Line 16 declares NumberPredicate as a delegate variable and initializes it with a reference to the expression-bodied IsEven method (line 62). Since IsEven's signature matches the NumberPredicate delegate's signature, IsEven can be referenced by a variable of type NumberPredicate. Variable evenPredicate can now be used as an alias for method IsEven. A NumberPredicate variable can hold a reference to any method that returns an int and a bool.

### 21.8.3 Delegate Parameters

The real power of delegates is in passing method references as arguments, as we do in this example with method FilterArray (lines 42–59). The method takes as arguments

- an int array
- a NumberPredicate that references a method used to filter the array

The method returns a List<int> containing only the ints that satisfy the condition specified by the NumberPredicate.

```csharp
// display the elements of a List
private static void displays(string description, List<int> list)
{
    Console.Write(description); // display the output's description
    // iterate over each element in the List
    foreach (var item in list)
    {
        Console.WriteLine($"{item} // print item followed by a space
    }
    Console.WriteLine(); // add a new line
}

// determine whether an int is even
private static bool IsEven(int number) => number % 2 == 0;
// determine whether an int is odd
private static bool IsOdd(int number) => number % 2 == 1;
// determine whether an int is greater than 5
private static bool IsOver(int number) => number > 5;

public static List<int> FilterArray(int[] numbers, Func<int, bool> filter)
{
    List<int> result = new List<int>();
    foreach (int item in numbers)
    {
        if (filter(item))
        {
            result.Add(item); // add the element to the result
        }
    }
    return result; // return the result
}
```

> Call IsEven using a delegate variable: True
> UseEven to filter even numbers: 2 4 6 8 10
> Use IsOdd to filter odd numbers: 1 3 5 7 9
> Use IsOver to filter numbers over: 5 6 7 8 9 10

## 21.9 Lambda Expressions

Lambda expressions allow you to define simple, anonymous methods—that is, methods that do not have names and are defined where they are assigned to a delegate or passed to a delegate parameter. In many cases, working with lambda expressions can reduce the size of your code and the complexity of working with delegates.
