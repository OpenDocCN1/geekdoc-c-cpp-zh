# 18.5 Wrap-Up

In this chapter, you learned how to search for items in arrays and how to sort arrays so that their elements are arranged in order. We discussed linear search and binary search, and selection sort, insertion sort and merge sort. You learned that linear search can operate on any set of data, but binary search requires the data to be sorted first. You also learned that the simplest searching and sorting algorithms exhibit poor performance. introduced Big O notation—a measure of the efficiency of algorithms—and used it to compare the efficiency of the algorithms we discussed. In the next chapter, you'll learn about dynamic data structures that grow or shrink at execution time.

# Section 18.2.1 Linear Search

+   - The linear search searches an array's elements sequentially until it finds one that matches the search key. If the search is not in the array, the algorithm tests every element and returns an index (such as a sentinel value) that the search key was found.
- One way to describe the efficiency of an algorithm is with Big O notation (O), which indicates how an algorithm may have to solve a problem.
- In searching and sorting algorithms, Big O depends on how many elements are in the data.
- An O(n) algorithm is referred to as having a linear runtime.
- Big O is designed to highlight dominant factors and ignore terms that become unimportant with high n values. Big O notation is concerned with the growth rate of algorithm times, so constants are ignored.
- The linear search algorithm runs in O(n) time.
