Whenever the mouse moves over a control, the MouseMove event for control occurs. Inside the PainterForm_MouseMove event handler (lines 35–46), the program draws only if ShouldPaint is true (i.e., a mouse button is pressed). In the using state,line 40 calls inherited from method CreateGraphics to create a Graphics object that allows the program to draw on the Form. Class Graphics provides methods to draw various shapes. For examples, lines 42–43 use method F1111Ellipse to draw a circle. The first parameter to method F1111Ellipse is an instance of class SolidBrush, as argument which specifies the solid color that will fill the shape. The color is specified by predefined color constants—we selected Color.Blueviolet. F1111Ellipse draws an oval in a bounding rectangle that is specified by the x- and y-coordinates of its upper-left corner, its width and height—the four arguments to the method. The x- and y-coordinates represent the location of the mouse event and can be taken from the mouse-event arguments (e.X and e.Y). To draw, we set the width and height of the bounding rectangle so that they're equal—in which there are 4 pixels. Graphics, SolidBrush and Color are all of namespace System.Drawing. Recall from Chapter 13 that the using automatically calls Dispose on the object that was created in the parentheses keyword using. This is important because Graphics objects are a limited resource. # 14.12 Keyboard-Event Handling

Key events occur when keyboard keys are pressed and released. Such events can be handled for any control that inherits from System.Windows.Control. There are three key—KeyPress, KeyUp and KeyDown. The KeyPress event occur when the user presses a character or the space bar key. The specific key or KeyChar of the event handler is KeyEventArgs.
nThe KeyEvent does not indicate whether modifier keys (e.g., Shift, Alt and Ctrl) were pressed when a key event occurred. If this information is important, the KeyError or KeyDown can be used.
