Derived Classes of Employee and Interface IPayable
When a class implements an interface, the is-a relationship inherits inheritance. Class Employee implements IPayable, so we can say that an Employee is an IPayable, and any object of Employee derived class is also an IPayable. If we update the hierarchy in Section 12.5 with the new Employee class in Fig. 12.13, SalariedEmployees,HourlyEmployees,CommissionEmployees and BasePlusEmployees are all IPayable objects. We can assign the reference of a SalariedEmployee-derived class to a base-class interface, we can assign the reference of a SalariedEmployee object (or any other Employee derived-class object) to an IPayable variable. Invoice implements IPayable, so an Invoice is also an IPayable object, and we can assign the reference of an Invoice object to an IPayable variable.

> Software Engineering Observation 12.7
Inheritance and interfaces are similar in implementation of the is-a relationship. Object of a class that implements an interface may be thought of as an object of that interface type. Object of any derived classes of a class that implements an interface can also be thought of as an object of the interface type.

![](bbox=[0.141, 0.655, 0.203, 0.752])

> Software Engineering Observation 12.8
The is-relationship exists between base classes and derived classes, and between interfaces and the classes that implement them, holds when passing an object to a method. When a method receives an argument of a base class or interface type, the polymorphically processes the object received as an argument.
