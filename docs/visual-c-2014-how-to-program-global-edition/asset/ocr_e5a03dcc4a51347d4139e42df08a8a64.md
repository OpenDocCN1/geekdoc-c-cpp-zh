# Chapter 15 Graphical User Interfaces with Windows Forms: Part 2

# Method LoadFilesInDirectory

The LoadFilesInDirectory method (lines 63–110) populates browserListView with the directory passed to it (currentDirectoryValue). It clears browserListView and adds the element "Go Up One Level". When the user clicks this element, the program attempts to move up one level (see how lively). The method creates a DirectoryInfo object initialized with the currentDirectory (lines 74–75). If permission is not given to browse the directory, an exception is thrown (and caught in line 140). MethodLoadFilesInDirectory works differently from PopulateTreeView in the previous program (Fig. 15.28). Instead of loading all folders on the hard drive, method LoadFilesInDirectory only loads the folders and files in the current directory.

Class DirectoryInfo (namespace System) enables us to browse or navigate the directory structure. Method GetDirectories (line 79) returns an array of DirectoryInfo objects containing the subdirectories of the current directory. Similarly, GetFiles (line 80) returns an array of FileInfo objects containing the files in the current directory. Property Name (of class DirectoryInfo and FileInfo) contains only the directory or file name, such instead of `myfolder\temp`. To access the full name, use property FullName.

Lines 83–90 iterate through the subdirectories and files of the current directory and add them to browserListView. Lines 88 and 99 set the ImageIndex of the new elements created. If an item is a directory, we set it to a directory icon (0); if it is a file, we set it to a file icon (1).

# Method browserListView_Click

Method browserListView_Click (lines 23–60) responds when the user controls browserListView. Line 26 checks whether an item selected. If a selection has been made, line 29 determines whether the user chose the first item in browserListView. The first item in browserListView is Go Up Level; if it is selected, the program attempts to go up a level. Line 32–33 creates a DirectoryInfo object for the current directory. Line 36 tests Parent to ensure the user is not at the root of the directory tree. Property Parent indicates the parent directory or Parent returns value null. If a parent directory exists, line 38 pass the parent directory name to LoadFilesInDirectory.

If the user did not select an item from browserListView, lines 43–55 allow the user to continue navigating the directory structure. Line 46 creates string and assigns it to the selected item (the first item in collection SelectedItems). Lines 49–50 determine whether the user selected a valid directory (rather than a file). Using the Combine method of class Path, the program combines strings currentDirectory and chosen to form the new directory path. The Combine method automatically adds a backslash (/), if necessary, between the two pieces. This value is passed to the Exists method true if the string parameter is a valid directory. If so, the program passes the string to LoadFilesInDirectory (lines 52–53). Finally, displayLabel is updated with the new directory (line 58).

This program loads quickly, because it indexes the files in the current directory. A small delay may occur when a new directory is loaded. In addition, the directory structure can be shown by reloading a directory. The previous program (Fig. 15.28) may have a large initial delay, as it loads an entire directory structure. This type of tradeoff is typical in the software world.
