# Functional Programming

With functional programming, you specify what you want to accomplish in a task, not how to accomplish it. For example, Microsoft's LINQ—which we introduce in Chapter 9, then use in many later chapters—can say, "Here's a collection of numbers, give me the sum of elements." You do not need to specify the mechanics of walking through the elements and adding them into a running total until one—LINQ handles all that for you. Functional programming speeds development and reduces errors. We take a deeper look at functional programming in Chapter 21.

# 1.8.8 Asynchronous Programming with async and await

In most programming today, each task in a program must finish executing before the next task can begin. This is called synchronous programming and the style we use for most of our C#. C# also allows asynchronous programming in which multiple tasks can be performed at the same time. Asynchronous programming can help you make apps more responsive to user interactions, such as clicks and keystrokes, among many others.

Asynchronous programming in early versions of Visual C was difficult and error prone. C#'s async and await simplify asynchronous programming by enabling the compiler to handle much of the associated complexity from the developer. In Chapter 23, we provide an introduction to asynchronous programming with async and await.
