
# Chapter 23 Asynchronous Programming with async and await

- The mechanisms for determining whether to return control to the async method's caller or for continuing the async method, and for continuing the async method's execution when the asynchronous task completes, are handled entirely by code that's written by the compiler.

## Section 23.2 async, await and Threads

- The async and await mechanism does not create new threads. The method that you call to start an asynchronous task or you await the results is responsible for creating any threads that are used to perform the asynchronous task (e.g., Task.Run).

## Section 23.3.1 Performing a Task Asynchronously

- If a long-running calculation was to be performed in a GUI app, the GUI would freeze until calculation completed and the user would not be able to interact with the app.
- Launching a calculation asynchronously and executing it on a separate thread keeps the GUI responsive.
- The recursive implementation of the Fibonacci calculation is a compute-intensive calculation.

## Section 23.3.2 Method calculateButton_Click

- A method is declared async to indicate to the compiler that it will await an asynchronous task.
- In effect, an async method allows you to write code that looks as if it executes sequentially, while the compiler deals with the complicated details of managing asynchronous execution.

## Section 23.3.3 Task.Run: Executing Asynchronously in a Separate Thread

- A Task promises to return a value at some point in the future.
- Class Task is part of .NET's Task Parallel Library (TPL) for parallel and asynchronous programming.
- Task.static method receives a Func<T> delegate as an argument and executes a method in a separate thread. The method returns Task<T>, where TResult represents the type of value returned by the method being executed.
- The Func<T> delegate represents any method that has no arguments and returns a result of generic type TResult.

## Section 23.3.4 awaiting the Result

- Task property Result returns the value returned by a Task.
- An async method can perform other statements between those that launch an asynchronous Task and await the Task's Result. In such a case, the method continues executing those statements after launching the asynchronous task until it reaches the await expression.
- You can place the await expression on the right side of an assignment. The await operator unwps and returns the Task's result so you can use it directly without accessing the Task's Result property.

## Section 23.3.5 Calculating the Next Fibonacci Synchronously

- Handling short computations in the GUI thread does not cause the GUI to become unresponsive.

## Section 23.4 Sequential Execution of Two Compute-Intensive Tasks

- An app that performs synchronous tasks on a single-core computer takes longer to execute than on a multicore computer, because the processor is shared between all and the other apps that happened to be executing on the computer at the same time. On the dual-core system, one of the cores could have been handling the ’other stuff’ executing on the computer, reducing the demand on the core that’s doing the synchronous calculation.

## Section 23.5 Asynchronous Execution of Two Compute-Intensive Tasks

- When you run any program, your program’s tasks compete for time with the operating system, other activities that the operating system is running on your behalf. In any time, to perform the app’s tasks can vary based on your computer’s processor speed, number of cores and what is running on your computer.
- Executing asynchronous methods in separate threads on a dual-core computer typically takes less time than executing the same tasks sequentially.
- Executing asynchronous methods in multiple threads on a single-core processor can actually take longer than simply performing them synchronously, due to the overhead of sharing one processes among your app’s threads, while all the other apps executing on the computer at the same time and the chores operating system was performing.

## Section 23.5.1 Awaiting Multiple Tasks with Task Method WhenAll

- You can wait for multiple tasks by awaiting the result of Task.static method WhenAll, which returns a Task that waits for all WhenAAll’s argument to complete and places all the results in an array. This array can be used to iterate through the results of the awaitedTasks.

## Section 23.5.3 Modifying a GUI from a Separate Thread

- GUI controls are designed to be manipulated only by the GUI thread—modifying a control from a non-GUI thread can corrupt the GUI, making it unreadable or unusable.
- When updating a control from a non-GUI thread, you must schedule that to be updated by the GUI. To do so in Windows Forms, check the InvokeRequired property of class Form. If this property value is true, the code is executing in a non-GUI thread and must not update the GUI directly. Instead, call the Invoke method of class Form, which receives as an argument a Delegate representing the update to the GUI thread.
- A MethodInvoker(namespace System.Windows.Forms) is a Delegate that invokes a method with no arguments and a void return type.

## Section 23.5.4 Awaiting One of Several Tasks with Task Method WhenAny

- Task.static WhenAny enables you to wait for any one of Several specified as arguments to complete. WhenAny returns the Task that completes.

## Section 23.6.3 Processing the XML Response

- XML represents data as elements, attributes and text.
- XML delimits elements with start tags and end tags.
- A start tag consists of the element name, followed by attributeName=value pairs, all enclosed in angle brackets.
- An end tag consists of the element name preceded by a forward slash (/) in angle brackets.
- An element start and end tag enclose a piece of data or nested elements.
- If an element is—that is, it does not contain nested elements between its start and end tags—the element can be represented by a start tag that uses /> rather than.
- Namespace System.Xml.Linq contains the classes used to parse XML using LINQ to XML.
- LINQ to query an XDocument to extract data from the XML.
- XDocument method Descendants returns a list of XElement objects representing the elements with the name specified as an argument.
- XElement method Attribute returns XAttributes representing an attributes.
- XAttribute property returns the value of a given attribute.

## Section 23.6.4 Binding the Title to the ListBox

- You cannot bind a LINQ query directly to a ListBox. You must first convert the result to a List with ToList or to ToArray.
- A ListBox’s DataSource property indicates the source of data that populates the ListBox’s Items collection. A ListBox’s DisplayMember property indicates which property of each item in the data source should be displayed in the ListBox.

## Section 23.6.5 Asynchronously Downloading Image’s Bytes
