## 12.3 Demonstrating Polymorphic Behavior

Section 11.4 created a commission-employee class hierarchy, in which BasePlusEmployee inherited from CommissionEmployee. The examples in that section manipulated CommissionEmployee and BasePlusEmployee by using references to them to invoke their methods. We aimed base-class references to base-class objects and derived-class references at derived-class objects. These assignments are natural and straightforward—base-class references are intended to refer to derived-class objects, however, other assignments are intended to refer to derived-class objects.

The next example aims a base-class reference to a derived-class object via a base-class reference invokes the derived class functionality—the type of the actual object, not the type of reference, methods which is called. This demonstrates the concept that a derived-class object can be treated as an object of its base class, which enables various manipulations. An app can create a collection of base-class references to refer to objects of many derived-class types, for instance, we assign the reference of a BasePlusCommissionEmployee to a base-class CommissionEmployee because BasePlusCommissionEmployee is a CommissionEmployee—so we can treat a BasePlusCommissionEmployee as a CommissionEmployee.

A base-class is not an object of any of its derived classes. For example, we cannot directly assign the reference of a CommissionEmployee to a derived-class BasePlusCommissionEmployee variable, because CommissionEmployee does not, for example, have a baseSalary instance and does not have a BaseSalary property. The compiler allows the assignment of a base-class reference to a derived-class variable if we explicitly cast the base-class reference to the derived-class type—a technique we discuss in greater detail in Section 12.5.6.

## 12.4 Abstract Classes and Methods

When we think of a class type, we assume that apps create objects. In some cases, however, it is useful to declare classes for which you never intend to instantiate. Such classes are called abstract classes. Because they are used only in inheritance hierarchies, we refer to them as abstract base classes. These classes cannot be used to instantiate objects.

## Purpose of an Abstract Class

The purpose of an abstract class is to provide an appropriate base class from which other classes can inherit and share a common design. In the hierarchy of Fig. 11.3, derived classes inherit the notion of what it means to be a Shape—common attributes such as Location and Color, and behaviors such as Draw, Move and ChangeColor. Classes that can be used to instantiate are implementations of every method they declare. For example, we derive concrete classes Circle, Square and Triangle from abstractShape. Similarly, we derive Sphere, Cube and Tetrahedron from abstract base. Abstract classes are too general to create real objects—they specify only what is common among derived classes. For example, if you use the Draw method to abstractShape, the class knows that two-dimensional shapes should be drawable, but it does not know what shape to draw, so it cannot implement a real Draw method. Concrete classes provide the specifics needed to instantiate.

## Client Code Uses Only Abstract Base-Class Types

Not all hierarchies contain abstract classes. However, you'll often write client code that uses only abstract base class types to reduce client code's dependencies on specific derived types. For example, you can write a method with a parameter of an abstract base class type. When called, such a method can be passed an object of any concrete class that directly or indirectly extends the base class specified as the parameter's type.

## Multiple Levels of Abstract-Class Types in a Hierarchy

Abstract classes constitute several levels of the hierarchy. For example, the Shape hierarchy starts with an abstract class, Shape. On the next level of the hierarchy we have two abstract classes, TwoDimensionalShape and ThreeDimensionalShape. The next level of the hierarchy declares concrete classes for TwoDimensionalShapes (Circle, Square and Triangle) and for ThreeDimensionalShapes (Sphere, Cube and Tetrahedron).

## Creating an Abstract Class

You make a class abstract by declaring it with the keyword abstract. An abstract class normally contains one or more abstract methods. An abstract method is one with keyword abstract in its declaration, as

```csharp
public abstract void Draw(); // abstract method
```

Abstract methods are implicitly virtual and do not provide implementations. A class that contains abstract methods must be declared as an abstract class even if it contains some implementations.
