# 13.5.4 Throwing Exceptions Using the throw Statement

Line 16 of Main invokes method ThrowWithCatch(lines 70–89), which begins in its try block (lines 73–77) by outputting a message. Next, the try block creates an exception object using throw statement (line 76). Executing the throw statement indicates that a problem has occurred in the code. As seen in earlier chapters, you can throw exceptions by using the throw statement. Just as with exceptions thrown by the Framework Class Library methods and the CLR, this indicates to client that an error has occurred. A throw statement specifies an object to be thrown. The operand of a throw statement to the constructor can be of Exception or any type derived from it.

The string passed to the constructor becomes the exception object's error message. When a throw statement in a try block executes, the try block exits immediately, and program control continues with the first matching catch block (lines 78–81) following the try block. In this example, the type (Exception) matches the type specified in the catch, so line 80 outputs a message indicating that the exception occurred. Then, the finally block (lines 82–86) executes and outputs a message. At this point, program control continues with the statement after the finally block (line 88). Program control returns to Main. In line 80, we use the exception's message property to retrieve the error message associated with the exception (i.e., the message passed to the Exception constructor). Section 13.7 discusses several properties of class Exception.
