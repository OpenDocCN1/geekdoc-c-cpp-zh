## 12.1 Introduction

We continue our study of object-oriented programming by explaining and demonstrating inheritance hierarchies. Polymorphism enables us to use in the general rather than program in the specific. In particular, polymorphism enables us to write apps that share the same base class in a hierarchy as if they were all objects of the base class.

Let's consider a polymorphism example. Suppose we create an app that moves several types of animals for a biological study. Classes Fish and Bird represent the types of animals under investigation. Each that class extends base class Animal, which has a method Move and maintains an animal's location as x-y-z coordinates. Each derived class implements Move. Our main app maintains a collection of references to objects of the various Animal-derived classes. To simulate movements, the app sends each object the same message once per second—namely, each specific type of Animal responds to a Move message in a unique way—a Fish might swim three feet, a Frog might jump five feet, and a Bird might fly ten feet. The app issues the Move message to each animal object generally, but each object modifies its x-y-z coordinates appropriately for its specific type of movement. Relying on object to “do the right thing” in response to the same method call is the key concept of polymorphism. The same message (in this case, Move) sent to a variety of objects has many forms of results—hence the term polymorphism.

## Systems Are to Extend

With polymorphism, we can design and implement systems that are easily extensible—new classes can be added with or no modification to the polymorphic portions of the app, as long as the new classes are part of the inheritance hierarchy that the app processes.

Let's consider several additional examples of polymorphism. Let's consider Quadrilateral.

## Quadrilateral Hierarchy

If Rectangle is derived from Quadrilateral (a four-sided shape), then Rectangle is a more specific version of Quadrilateral. Any operation that can be performed on Quadrilateral (e.g., calculating the perimeter or the area) can also be performed on Rectangle. This is also true for as Squares, Parallelograms and Trapezoids.

## Video Game SpaceObject Hierarchy

Another example, suppose we design a video game that manipulates objects of different types, including Martian, Plutonian, SpaceShip and LaserBeam. Imagine that each class inherits from the common base class SpaceObject, which contains method Draw. Each derived class implements this method. A manager maintains a collection (a SpaceObject array) of objects of various classes. To refresh the screen, the screen manager periodically sends each object the same message—Draw. However, each object responds in a unique way. For example, a Martian might draw itself with the appropriate number of antennae. A SpaceShip might draw itself as a silver flying saucer. A LaserBeam might draw itself as a bright red beam across the screen. The same message (in this case, Draw) sent to a variety of objects has many results from.

A screen manager uses polymorphism to facilitate adding classes to a system with minimal modifications to the system's code. To do so, we must build a Mercurian class that extends SpaceObject and provides its own Draw implementation. When objects appear in the SpaceObject collection, the screen manager invokes method Draw, exactly as it does for every other object in the class, regardless of its type, the new Mercurian objects simply "plug in" without any modification of the screen manager.
