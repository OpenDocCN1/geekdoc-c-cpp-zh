Main—before returning to the operating system—calls method Square in line 11 of Fig. 7.10. This causes a stack frame for Square (lines 15–18) to be pushed onto the method-call stack (Fig. 7.12). This stack frame contains the return address that Square needs to return to Main (i.e., R2) and the memory for Square's local variable y.

After Square performs its calculation, it needs to return to Main—and no longer the memory for y. Square's stack frame is popped from the stack—giving the return location in Main (i.e., R2) and losing Square's local variable (Step 3). Figure 7.13 shows the method-call stack after Square's activation record has been popped.

Main now displays the result of calling Square (Fig. 7.10, line 11). Reaching the closing right brace of Main causes its stack frame to be popped from the stack, giving the address needs to return to the operating system (i.e., R1 in Fig. 7.11)—at this point, Main's local variable x no longer exists.

## 7.12 Method Overloading

You've now seen how valuable the stack data structure is in implementing a key mechanism that supports recursion. Data structures have many important applications in computer science. We discuss stacks, queues, lists, trees and other data structures in Chapter 19, Custom Linked Data Structures, and Chapter 21, Generic Collections; Functional Programming with LINQ/PLINQ.

Methods of the same name can be declared in the same class, as long as they have different sets of parameters (determined by the number, type and order of parameters). This is called method overloading. When an overloaded method is called, the C# compiler selects the appropriate method by examining the number, type and order of arguments in the call. Method overloading is commonly used to create methods with the same name that perform the same or similar tasks, but on different types or different numbers of arguments. For example, Random method Next (Section 7.8) has overloads that accept different numbers of arguments, and Math Max has overloads that accept different types of arguments (ints vs doubles). We find the minimum and maximum, respectively, of two values of each of the numeric types. Our next example demonstrates declaring and invoking overloaded methods. We see several examples of overloaded constructors in Chapter 10.

### 7.12.1 Declaring Overloaded Methods

In class MethodOverload (Fig. 7.14), we include two overloaded versions of a method called Square—one calculates the square of an int (and returns an int) and one calculates the square of a double (and returns a double). Although these methods have the same name and similar parameter lists and bodies, you can think of them as different method names as "Square of int" and "Square of double", respectively.

```csharp
// Fig. : MethodOverload.cs
// Overloaded method declarations.
using System;

class MethodOverload
{
    // test overloaded square methods
    static void Main()
    {
        Console.WriteLine($"Square of integer 7 is {Square(7)}");
        Console.WriteLine($"Square of double 7.5 is {Square(7.5)}");
    }

    // square method with int argument
    static int Square(int intValue)
    {
        Console.WriteLine($"Called square with int argument: {intValue}");
        return intValue * intValue;
    }
}
```

Line 10 in Main invokes Square with the argument 7. Literal integer values are treated as type int, so the method in line 10 invokes version of Square at lines 15–19 which specifies an int parameter. Similarly, line 11 invokes Square with the argument 7.5. Literal real-number values are treated as double, so the method in line 11 invokes the version of Square at lines 22–27 that specifies a double parameter. Each method outputs a line of text to prove that the proper method was called in each case.

The overloaded methods in Fig. 7.14 perform the same calculation, but with different types. C#'s generic features provide a mechanism for writing a single "generic method" that can perform the same task as a set of overloaded methods. We discuss generic methods in Chapter 20.

### 7.12.2 Distinguishing Between Overloaded Methods

The compiler distinguishes overloaded methods by their signature—a combination of the method's name, numbers and order of its parameters. The signature also includes how those parameters are passed, which can be modified by the ref and out keywords.

### 7.12.3 Return Types of Overloaded Methods

In discussing the logical names of methods, we did not mention return types. Methods cannot be distinguished by return type. If in class MethodOverload you define methods with the following:

```csharp
int Square(int x)
double Square(int x)
```

which has the same signature but different return types, the compiler generates the following error: Type 'MethodOverload' already defines a member called 'Square'.

### 7.13 Optional Parameters

Methods can allow the calling method to vary the number of arguments to pass. An optional parameter specifies a default value that is assigned to the parameter if the optional argument is omitted. You can create methods with one or more optional parameters. All optional parameters must be placed to the right of the method's optional parameters—that is, at the end of the parameter list.

When a method has a default value, the caller has the option of passing that particular argument. For example, the method header

```csharp
static int Power(int baseValue, int exponent = 2)
```

specifies an optional argument. Each call to Power must pass at least a baseValue, or a compilation error occurs. Optionally, the exponentValue parameter can be passed to Power. Each optional parameter must specify a default value by using an equal (= sign followed by value. For example, the method header sets Power 2 as exponentValue's default value. Consider the following calls to Power:

- Power()—This calls a compilation error because this method requires a minimum of one argument.
- Power(10)—This is valid because one argument (10) is being passed. The exponentValue is not specified in the call, so the compiler uses 2 for the exponentValue, as specified in the method header.
- Power(10, 3)—This call is also valid because 10 is passed as the required argument and 3 is passed as the optional argument.
