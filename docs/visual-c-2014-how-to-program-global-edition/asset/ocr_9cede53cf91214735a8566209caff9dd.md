**Declaring a Named Constant with const**

> **Good Programming Practice 8.1**
Constants are also called named constants. Apps using constants are often more readable than those using literal values (e.g., 5)—a named constant such as ArrayLength clearly indicates its purpose, whereas the literal value 5 could have different meanings based on the context in which it is used. Another advantage of using named constants is if the constant's value must be changed, the change is necessary only in the declaration, thus reducing code-maintenance costs.

> **Good Programming Practice 8.2**
Defining the size of an array as a named constant instead of a literal makes code clearer. This technique eliminates so-magic numbers. For example, repeating the size 5 in array-processing code for a five-element array gives the number 5 an artificial significance and can be confusing when the program includes other 5s that have nothing but the array size.

> **Good Programming Error 8.2**
Assigning a value to a named constant after it's been initialized is a compilation error.
