## LINQ Providers
The syntax of LINQ is built into C#, but LINQ queries may be used in many contexts via libraries known as providers. A LINQ provider is a set of classes that implement LINQ operations and enable programs to interact with data sources to perform tasks such as sorting, grouping and filtering elements. Many LINQ providers are more specialized, allowing you to interact with a specific website or data format. Figure 9.1 shows where and how we use LINQ throughout the book.

# 9.2 Querying an Array of int Values Using LINQ

Figure 9.2 shows how to use LINQ to Objects to query an array of integers, selecting elements that satisfy a set of conditions—a process called filtering. Iteration statements that filter arrays focus on the process of getting the results—iterating through the elements and checking whether they satisfy the desired criteria. LINQ specifies the conditions that selected elements must satisfy. This is known as declarative programming—as opposed to imperative programming (which we’ve been doing so far) in which you specify the actual actions to perform a task. The query in lines 22–24 specifies that the results should consider all of the ints in the values array are greater than 4. It does not specify how results are obtained—the C# compiler generates all the necessary code, which is one of the strengths of LINQ. Using LINQ to Objects requires the System.Linq namespace (line 4).

```csharp
// Fig. 9.2: LINQWithSimpleTypeArray.cs
// LINQ to Objects using an int array.
using System;
using System.Linq;
class LINQWithSimpleTypeArray
{
    static void Main()
    {
        // create an integer array
        var values = new[] {2, 9, 5, 0, 3, 7, 1, 4, 8};

        // display original values
        Console.Write("Original array:");
        foreach (var element in values)
        {
            Console.Write($"{element}");
        }

        // LINQ query that obtains values greater than 4 from the array
        var filtered =
            from value in values // data source is values
            where value > 4
            select value;

        // display filtered results
        Console.Write("\nArray values greater than 4:");
        foreach (var element in filtered)
        {
            Console.Write($"{element}");
        }

        // use orderby to sort original values in ascending order
        var sorted =
            from value in values // data source is values
            orderby value
            select value;

        // display sorted results
        Console.Write("\noriginal array, sorted:");

foreach (var element in sorted)
{
    Console.Write($"{element}");
}

// sort the filtered results into descending order
var sortFilteredResults =
    from value in filtered // data source is LINQ query filtered
    orderby value descending
    select value;

// display the sorted results
Console.Write(
    "\ngreater than 4, descending order (two queries):");
foreach (var element in sortFilteredResults)
{
    Console.Write($"{element}");
}

// filter original array and sort results in descending order
var sortAndFilter =
    from value in values // data source is values
    where value > 4
    orderby value descending
    select value;

// display the filtered and sorted results
Console.Write(
    "\nvalues than 4, descending order (one query):");
foreach (var element in sortAndFilter)
{
    Console.Write($"{element}");
}

Console.WriteLine();
}
```

## 9.2.1 The From Clause

A LINQ query begins with a from clause (line 22), which specifies a range variable (value) and the data source to (values). The range variable represents each item in the data source (one at a time), like the control variable in a for statement. Since value is assigned one element at a time from the array—the compiler infers that value should be type int.

Implicitly Typed Local Variables
Typically, implicitly typed local variables (var) are used for the collections returned by LINQ queries, as we do in lines 21, 34, 47 and 61. We also use this feature to declare the control variable in the foreach statements. Introducing the variable in the from clause allows the IDE to provide IntelliSense as you type the variable's name.

## 9.2.2 The where Clause

If the condition in where clause (line 23) evaluates to true, the element selected—i.e., it's included in the results. An expression that takes a value and returns true or false by testing on that value is known as a predicate.

## 9.2.4 Iterating Through the Results of the LINQ Query

Lines 28–31 use a foreach statement to display the query results. As you know, a foreach statement can iterate through the contents of an array, allowing you to process each element in the array. The foreach statement in lines 28–31 iterates over the query, displaying each of its int items.

LINQ vs. Iteration Statements
It would be simple to display the integers greater than 4 using an iteration statement that tests each value before displaying it. However, this would intertwine the code that selects elements and the code that displays them. With LINQ, these are kept separate:

- the LINQ query specifies how to locate the values and
- a loop accesses the results

## 9.2.5 The orderby Clause

The order clause (line 36) sorts the query in ascending order. Lines 49 and 64 use the descending modifier in the orderby clause to sort the results in descending order. An ascending modifier also exists but isn't normally used, because it's the default. Any value that can be compared with other values may be used with the orderby clause. A value of a simple type (e.g., int) can always be compared to another value of the same type; we'll discuss how to compare values of reference types in Chapter 12.
