# Chapter 10 Classes and Objects: A Deeper Look

```
// Fig. 10.11: EmployeeTest.cs
// static member demonstration.
using System;
class EmployeeTest{
    static void Main()
{
        // show that Count is 0 before creating Employees
        Console.WriteLine($"{Employees before instantiation: {Employee.Count}}");

        // create two Employees; Count should become 2
        var el1 = new Employee("Susan", "Baker");
        var el2 = new Employee("Bob", "Blue");

        // show that Count is 2 after creating two Employees
        Console.WriteLine($"\nEmployees after instantiation: {Employee.Count}");

        // get names of Employees
        Console.WriteLine($"\nEmployee 1: {el1.FirstName} {el1.LastName}");
        Console.WriteLine($"\nEmployee 2: {el2.FirstName} {el2.LastName}");

        // in this example, there is only one reference to each Employee,
        // so the following statements allow the CLR to mark each
// Employee as being eligible for garbage collection
nel1 = null; // mark object referenced by el1 as no longer needed
el2 = null; // mark object referenced by el2 as no longer needed
    }}
```

Employees before instantiation: 0
Employee constructor: Susan Baker; Count = 1
Employee constructor: Bob Blue; Count = 2
Employees after instantiation: 2
Employee 1: Susan Baker
Employee 2: Bob Blue

Fig. 10.11 | static member demonstration.

Lines 18–19 of Fig. 10.11 display the updated Count. When Main has finished using the two Employee objects, el1 and el2 are set to null at lines 28–29, so they no longer refer to the objects that were instantiated in lines 14–15. The objects become eligible for destruction because there are no more references to them. After the objects' destructors are called, the objects become eligible for garbage collection. (Note that we did not need to set el1 and el2 to null here they're local variables—a local variable of a reference goes out of scope, the object's reference count is decremented automatically.)
Eventually, the garbage collector might reclaim the memory for the objects (or the operating system will reclaim it when the app terminates). C# does not guarantee when, or even when, the garbage collector will execute; it's possible that no objects or a subset of the eligible objects will be collected.
