
## Exercises 335

**7.23 (Find the Minimum)** Write a method Minimum that returns the smallest of three floating-point numbers. Use the Math.min method to implement Minimum. Incorporate the method into an app that reads three values from the user, the smallest value, and displays the result.

**7.24 (Amicable Numbers)** Two numbers are said to be amicable numbers if the sum of factors including 1 (but not the number itself) of one number is equal to the other number and vice versa. For example, (220, 284) are amicable numbers. The sum of factors of 220 are 2, 4, 5, 10, 11, 20, 22, 44, 55 and 110, which sums to 284. Write a method Checkable that determines whether a pair of numbers is amicable or not. Display the factors of each number to confirm that the numbers are amicable or not.

**7.25 (Prime Numbers)** An integer is said to be prime if it's greater than 1 and divisible by only 1 and itself. For example, 2, 3, 5 and 7 are prime; but 4, 6, 8 and 9 are not.
a) Write a method that determines whether a number is prime.
b) Use this method in an app that displays all the prime numbers less than 10,000.
c) Initially, you might think that n/2 is the upper limit for you must test to see whether a number is prime, but you need to go as high as the square root of n. Rewrite the app, and run it both.

**7.26 (Reversing Digits)** Write a method that takes an integer value and returns the number with its reversed digits. For example, using the number 7361 returns 1367. Incorporate the method into an app that reads a value from the user and displays the method's result.

**7.27 (Lowest Common Multiple)** The lowest common multiple (LCM) of two integers is the lowest integer that is evenly divisible by each of the two numbers. Write a method lcm that returns the lowest common multiple of two integers. Incorporate the method into an app that reads values from the user and displays the result.

**7.28 (Converting Average to a Four-Point Scale)** Write a method QualityPoints that inputs a student's average and returns it a scale of 90–100, 3 if the average is 80–89, 2 if the average is 70–79, 1 if the average is 60–69 and 0 if the average is less than 60. Incorporate the method into an app that reads values from the user and displays the result.

**7.29 (Coin Toss)** Write an app that simulates coin tossing. Let the user to toss a coin each time the app appears. Display the results. The app should use a separate method Flip that takes no arguments and returns true for heads and false for tails. [Note: If it realistically simulates coin tossing, each side of the coin should appear approximately half the time.]

**7.30 (Guess-the-Number)** Write an app that 'guesses the number' as follows: Your app chooses the number by selecting a random integer in the range 1 to 1000. The app displays a prompt for a number between 1 and 1000. The player enters the first guess. If the player's guess is incorrect, your app should display Too High or Too Low. Try again. To help the player 'zero' in on the correct answer, the app should prompt for the next guess. When the user enters the correct answer, display Congratulations. You guessed the number! and allow the user to choose again to play. The guessing technique employed in this problem is similar to a binary search, which is discussed in Chapter 18.

**7.31 (Enhanced Guess-the-Number)** Modify the exercise of 7.30 to count the number of guesses the player makes. If the number is 10 or fewer, display Either you know the secret or you got lucky! If the player guesses in 10 tries, display Ah you know! If the player makes more than 10 guesses, display you should be able to do better! Why should it take no more than 10 guesses? Well, with "good guess", the player should be able to eliminate half of the numbers. Now show how any number from 1 to 1000 can be guessed in 10 or fewer trials.

**7.32 (Distance Between Two Points)** Write a method Distance to calculate the distance between two points (x1, y1) and (x2, y2). All numbers and return values should be double type. Incorporate the method into an app that enables the user to enter the coordinates of the points.

**7.36 (Towers of Hanoi)** If we were to approach this classic problem (Fig. 7.24) with conventional methods, we would find ourselves hopelessly managing the disks. Instead, if we attack the problem with recursion, it becomes tractable as follows:

- a) Move $n-1$ disks from peg 1 to 2, using peg 3 as a holding area.
- b) Move the last disk (the largest) from peg 1 to 3.
- c) Move $n-1$ disks from peg 2 to 3, using peg 1 as a holding area.

Write an app to solve this. Allow the user to enter the number of disks. Use a recursive method with the following parameters:
- a) the number of disks to be moved,
- b) the peg on which these disks are threaded,
- c) the peg to which this stack of disks is to be moved,
- d) the peg to be used as a holding area.

Your app should display the precise instructions it will take to move the disks from the starting peg to the destination. For example, to move a stack of three disks from peg 1 to peg 3, your app should display the following sequence of moves:

```
1 --> 3 (This notation means "Move one disk from peg 1 to peg 3")
1 --> 2
3 --> 2
1 --> 3
2 --> 3
1 --> 3
```

**7.37 (What Does This Code Do?)** What does the following method do?

```
// Parameter b must be positive to prevent infinite recursion
static int Mystery(int a, int b)
{
    if (b == 1) 
        return a;
    else
        return a + Mystery(a, b - 1);
}
```

**7.38 (Find the Error)** Find the error in the following recursive method, and explain how to correct it:

```
static int Sum(int n)
{
    if (n == 0) 
    {
        return 0;
    }
    else
    {
        return n + Sum(n);
    }
}
```
