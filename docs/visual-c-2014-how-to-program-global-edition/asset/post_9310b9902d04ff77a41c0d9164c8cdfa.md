### 22.1 Introduction
A database is an organized collection of data. A database management system (DBMS) provides mechanisms for storing, organizing, retrieving and modifying data. Many of today's popular DBMSs manage relational databases, which organize data simply as tables with rows and columns.

Some popular DBMSs are Microsoft SQL Server, Oracle, Sybase and IBM DB2. PostgreSQL, MariaDB and MySQL are open-source DBMSs that can be downloaded and used freely. In this chapter, we use a version of Microsoft's SQL Server that is installed with Visual Studio. It can also be downloaded separately from
> https://www.microsoft.com/en-us/server-cloud/products/sql-server-editions/sql-server.aspx

### SQL Server Express
SQL Server Express provides many features of Microsoft's full (fee-based) SQL Server product, but has some limitations, such as a maximum database size of 10GB. SQL Server database file can be easily migrated to a full version of SQL Server. You can learn more about the SQL Server versions at
> https://www.microsoft.com/en-us/server-cloud/products/sql-server-editions/overview.aspx

The version of SQL Server bundled with Visual Studio Community is called SQL Server LocalDB. It's meant for development and testing of apps on your computer.

### Structured Query Language (SQL)
A language called Structured Query Language (SQL)—pronounced “sequel”—is an international standard used with relational databases to perform queries that request information satisfies criteria and to manipulate data. For years, programs that accessed a relational database passed SQL queries as strings to the database management system, then processed the results.

LINQ to Entities and the ADO.NET Entity Framework
A logical extension of querying and manipulating data in databases is to perform similar operations on any sources of data, such as arrays, collections (the Items collection of lists). ### 22.2 Relational Databases
A relational database organizes data in tables. Figure 22.1 illustrates a sample Employees table that might be used in a personnel system. The table stores the attributes of employees. Employees are composed of rows (also called records) and columns (also called fields) which values are stored. The table consists of six rows (one per employee) and five columns (one per attribute). The attributes are the employee's
- ID
- name
- department
- salary and
- location

The ID column of each row is the table's primary key—a column (or group of columns) requiring a unique value that cannot be duplicated in others. This guarantees that each primary-key value can be used to identify one row. A primary key of two or more columns is known as a composite key—in this case, every combination of column values in the composite key must be unique. Good examples of primary-key columns in other apps are a book's ISBN in a book information system or a part number in an inventory system—values in each of these must be unique.
