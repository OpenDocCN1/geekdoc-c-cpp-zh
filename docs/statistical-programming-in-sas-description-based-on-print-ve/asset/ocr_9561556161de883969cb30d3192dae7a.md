# Display 2.3 Example code that generates a temporary data set

```
data lin_reg_data;
  call streaminit(32123);  Std?
  do x = 0 to 10 by 1;
    y = 3 + 2*x + 2*RAND('NORMAL');
    output;
  end;
run;

ods rtf bodytitle file='C:\Users\baileraj.IT\Desktop\ch2-fig2.3.rtf';
proc sgplot data=lin_reg_data;   * or equivalently, data=work.lin_reg_data;
  scatter y=y x=x;
run;

proc reg data=lin_reg_data;
  model y=x;
run;
ods rtf close;
```

The data set produced in the Display 2.3 code contains 11 observations and two variables (X, Y). A glance at the SAS log confirms this with the following message:

```
NOTE: The data set WORK.LIN_REG_DATA has 11 observations and 2 variables.
```

The WORK library is temporary storage that is allocated by SAS during the execution of a SAS session. lin_reg_data is a data set stored in this temporary library for the duration of this SAS session. After SAS is closed, the lin_reg_data data set disappears into the virtual vapors, or into the electronic ethos, if you prefer.

# 2.2 Reading Data into a SAS Data Set

A common starting point for a statistical collaborator or consultant is to meet with a colleague or client who needs assistance exploring relationships among variables, testing for treatment differences, or other equally fun stuff. At this point, an important question is, “Do you have your data in an electronic format?” The answer to this question varies across disciplines. Colleagues from biological and medical sciences and business often use Microsoft Excel spreadsheets for data entry and analysis. Colleagues from the social sciences are more likely to use SPSS or some other statistical application to set up data and manipulate it. If it is a small data set, then it might be in a text file with variable fields separated by blanks, tabs, or some other delimiter. Importing different raw data file types is discussed in later sections. It is possible to enter your data directly into a SAS data table, or to save your data in a SAS data format when using a different system.
