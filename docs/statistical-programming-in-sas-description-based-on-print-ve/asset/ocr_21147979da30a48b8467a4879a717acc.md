```
data nitro_tox;
 infile 'C:\Users\baileraj.IT\desktop\DT-Book 3\ch2-dat.txt'
    firstobs=16 expandtabs missover pad ;
 input @9 animal 2. @17 conc 3. @25 brood1 2. @33 brood2 2. @41
    brood3 2. @49 total 2.;
```

In this example, data are in particular columns. For example, the animal ID starts in column 9 and occupies two columns, the concentration starts in column 17 and occupies three columns, and so on. The @9 command before the ANIMAL variable moves the input pointer to the ninth column of an input record. The 2. following the ANIMAL variable signifies that values of this numeric variable occupy a width of two columns. The remaining variables start in columns 17, 25, 33, 41, and 49, respectively. The w. (width informat) and other informats are discussed in more detail in Section 3.2 and in Section 7.2.

The INFILE statement has some options that are worth examining. The firstobs=16 option declares that SAS should ignore the first 15 lines of the data file. This is an efficient way to include comments and descriptions of the variables, data source, etc. as part of the data file. This is a recommendation that is consistent with the recommendations in Chapter 1. The expandtabs option expands any tab characters to a standard tab spacing of eight columns. The missover option assigns missing values to variables that are not defined in the INPUT line (which is not as problematic as reading free-formatted data with missing values at the end of a line), and pads the data lines to be the same length as pad. This input structure is specified for reading this file on the StatLib server. With the exception of firstobs=16, this structure might not be needed to correctly read the data on your system.

# 2.2.4 Reading comma-separated values—text files with comma delimiters

A copy of the SMSA data set was created to have comma-separated values and is stored in a file named DASL-SMSA-commasep.csv. An observation in this file has values of the variables separated by commas. Missing values are indicated by two consecutive commas. For example, here is the first observation in the file:

```
"Akron, OH",27,71,59,36,921.87,11.4,3243,8.8,42.6,660328,3.34,29560,21,15,59,15
```

To read this file, SAS needs to know that there is a delimiter separating the values. The DSD (delimiter-sensitive data) option in an INFILE statement is needed for reading this type of data. A comma is the default delimiter with the DSD option. If you have a different delimiter, then you can use the DELIMITER= option or DLMSTR= option to set it.
