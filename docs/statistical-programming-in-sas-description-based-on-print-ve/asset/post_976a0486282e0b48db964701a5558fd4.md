## 7.5 Descriptive Displays of Spatial Data

Regional or geographical differences are often best depicted as maps. SAS provides a collection of maps and procedures to display data on these maps. The GMAP procedure is the basic procedure for producing maps in SAS. For an overview of producing maps in SAS, see Zdeb (2004). In Display 7.14, the code for producing a choropleth map of the 1990 population in Ohio counties is provided.

## Display 7.14 Producing a choropleth map of the 1990 population in Ohio counties

```
proc gproject data=maps.counties out=OHIO_counties;
    where state eq 39;
    id state;
run;

/*
(Subset of years from data set of) Ohio County population sizes from 1900-1990
http://www.census.gov/population/cencounts/oh190090.txt
*/
data county_pop;
    length char_county $ 10;
    input county6 1-5 pop90 pop80 pop70 pop60 char_county &;
    county = county6-39000;  * removing state id from FIPS;
    datalines;
39001    25371    24328    18957    19982 Adams
39003    109755   112241   111144   103691 Allen
... (see appendix for complete data set) ...
39175    22254    22651    21826    21648 Wyandot
;
run;
proc gmap data=county_pop
    map=OHIO_counties;
    id county;
    choro pop90;
    note '1990 Population Size (Source: US Census)';
run;
quit;
```

This code begins with an initial projection using GPROJECT to restructure the internal SAS map data set coordinates in a familiar map orientation. The Ohio county population data are then read into a data set. (See the Appendix for the complete data set.) The map is constructed by linking the map data set (map=OHIO_counties) to the population data (data=county_pop). A variable must link each map region to a response associated with that region (id county). You need to identify that you want a choropleth map with shading for each county proportional to the county population values (choro pop90). The map produced by this code is shown in Display 7.15.

## 7.6 Summary

This chapter emphasized traditional SAS graphics and customizing their graphical displays. Other manipulations were presented. The chapter closed with a glance into the SAS world of mapping. There is much more to be explored in graphical displays in SAS/GRAPH software. If you are interested in contour plots and three-dimensional plots, then you should explore GCONTOUR and G3D. If you are interested in learning more about map displays, then dig into the SAS mapping procedures, including SAS/GIS software.

Overviews of ODS Graphics and traditional SAS graphics were presented in Chapters 6 and 7, respectively. You can find additional information about traditional SAS graphics

and ODS Graphics in SAS/GRAPH 9.2: Reference. The appearance of traditional graphics is controlled by GOPTIONS, and graphs are displayed in graph windows and can be saved in SAS graphics catalogs. In contrast, the appearance of ODS Graphics is controlled by templates and options in the ODS GRAPHICS statement. ODS Graphics are displayed in ODS destinations and can be saved in a variety of file formats. Annotate data sets are used for customizing graphs produced by traditional SAS graphics. The ODS Graphics Editor is used for customizing graphs produced by ODS Graphics, and the GTL can be used for permanent modifications.
