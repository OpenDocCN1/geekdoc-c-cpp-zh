## 8.2 Character, Numeric, Time, and Date Formats

As the band Chicago sings:

> "Does anybody really know what time it is? Does anybody really care?"

The simple answer is "yes." You care if you are analyzing time-indexed observations and you want SAS to represent and manipulate the time-and-date data correctly.

There are many formats that can be used to read and display dates and times. This is to be expected. There are numerous ways these values might be recorded and entered as data. Dates might be recorded as 30jun10, 30jun2010, 063010, or even 30.06.10. All of these values require the use of a different informat to read them into SAS as shown in Display 8.8.

Dates are stored in SAS as the number of days from a selected point in time. In particular, the default selected point in time for SAS is January 1, 1960. Thus, June 30, 2010 is 18443 days from January 1, 1960. It is useful to store dates numerically. You might want to construct variables from dates. For example, suppose DOB and DOD are variables corresponding to the date of birth and the date of death, respectively, for an individual in your study. If DOB and DOD are stored as numeric variables, then the age at death (in years) could be calculated directly with AGE AT DEATH=(DOD–DOB)/365.25. Even though you want to store dates numerically, displaying dates numerically is not useful. To display the dates in a useful format, assign one of the date formats to the variable containing the dates as shown in Display 8.10.
