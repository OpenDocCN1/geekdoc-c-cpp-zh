
## 2.2.2 Reading data sets saved as text—INFILE can be your friend

It’s OK to use a DATALINES statement for so-called instream data entry when you have relatively small data sets. In fact, you might want to use a subset of a large data set as a test data set for making sure that you have your INPUT statement correctly specified. The code in the previous section accomplishes this, and the previous INPUT statement is used again in this section. When you get to larger data sets, it would make for large and ugly programs if you had to slog through hundreds of lines of data before getting to analysis statements or PROCs. Thus, an alternative for specifying an external file for data entry is needed. If the external file is a text file, data can be read using an INFILE statement in which the data file is identified. You might discover that some preprocessing of the data is needed before reading it into a SAS data set. For example, as shown in the comments before the program in Display 2.8, tabs are replaced with two spaces and missing values for two Fort Worth variables are assigned the SAS missing code for numeric variables (a period).

### Display 2.8 Reading an external text file into a SAS data set using an INFILE statement

```
/*
Notes:
1) Two spaces separate each entry in the input data file. A global replace of tabs with two spaces was performed before saving the text file.
2) The first line contains the names of the variables, and the data begins on the 2nd line of the file.
3) Fort Worth had missing values for POP and INCOME and "." were entered in the data file.
4) Increased LENGTH to 39 to accommodate GREENSBORO-WINSTON-SALEM...
*/
options nodate nocenter;
data SMSA_from_txt;
infile "C:\Users\baileraj.IT\Desktop\DT-Book 3\SMSA-DASL-2space-sep.txt";
firstobs=2;
length city $ 39;
input city & JanTemp JulyTemp RelHum Rain Mortality Education PopDensity pct_NonWhite pct_WC pop pop_per_house income HCPot NOxPot SO2Pot NOx;
run;
ods rtf bodytitle file='C:\Users\baileraj.IT\Desktop\ch2-fig2.8.rtf';
proc print data=SMSA_from_txt;
var city JanTemp JulyTemp RelHum NOxPot SO2Pot NOx;
run;
ods rtf close;
```

## 2.2.3 Sometimes variables are in particular columns or in particular formats

Now, for a quick confession: not all data are in a free-formatted collection where variable values are separated by spaces. Sometimes, variables are in fixed, specified columns and lines, and are in a format that needs to be read (e.g., times, dates, numbers with commas, etc.). You will see several illustrations of this scenario throughout the book. For example, in Display 3.9 the data for the nitrofen example (mentioned in Display 2.2) is read from an external file. Here are the INFILE and INPUT statements used in Display 3.9:

```
data nitro_tox;
 infile 'C:\Users\baileraj.IT\desktop\DT-Book 3\ch2-dat.txt'
    firstobs=16 expandtabs missover pad ;
 input @9 animal 2. @17 conc 3. @25 brood1 2. @33 brood2 2. @41
    brood3 2. @49 total 2.;
```

In this example, data are in particular columns. For example, the animal ID starts in column 9 and occupies two columns, the concentration starts in column 17 and occupies three columns, and so on. The @9 command before the ANIMAL variable moves the input pointer to the ninth column of an input record. The 2. following the ANIMAL variable signifies that values of this numeric variable occupy a width of two columns. The remaining variables start in columns 17, 25, 33, 41, and 49, respectively. The w. (width informat) and other informats are discussed in more detail in Section 3.2 and in Section 7.2.

The INFILE statement has some options that are worth examining. The firstobs=16 option declares that SAS should ignore the first 15 lines of the data file. This is an efficient way to include comments and descriptions of the variables, data source, etc. as part of the data file. This is a recommendation that is consistent with the recommendations in Chapter 1. The expandtabs option expands any tab characters to a standard tab spacing of eight columns. The missover option assigns missing values to variables that are not defined in the INPUT line (which is not as problematic as reading free-formatted data with missing values at the end of a line), and the PAD option pads the data lines to be the same length. This input structure is specified for reading this file on the StatLib server. With the exception of firstobs=16, this structure might not be needed to correctly read the data on your system.

## 2.2.4 Reading comma-separated values—text files with comma delimiters

A copy of the SMSA data set was created to have comma-separated values and is stored in a file named DASL-SMSA-commasep.csv. An observation in this file has values of the variables separated by commas. Missing values are indicated by two consecutive commas. For example, here is the first observation in the file:

```
"Akron, OH",27,71,59,36,921.87,11.4,3243,8.8,42.6,660328,3.34,29560,21,15,59,15
```

The program for reading this .csv data file is shown in Display 2.10. The first line of this file (the line that contains the variable names) is skipped using the firstobs option. In addition, printed observations are restricted to those in the middle of the data set using the firstobs and obs options specified with PROC PRINT.

### Display 2.10 Reading input data from files using commas as delimiters between variable values

```
options nodate nocenter;
data SMSA_from_CSV;
infile "C:\Users\baileraj.IT\Desktop\DT-Book 3\DASL-SMSA-commasep.csv"
firstobs=2 dsd;
length city $ 39;
input city & JanTemp JulyTemp RelHum Rain Mortality Education PopDensity pct_NonWhite pct_WC pop pop_per_house income HCPot NOxPot SO2Pot NOx;
run;

ods rtf bodytitle file='C:\Users\baileraj.IT\Desktop\ch2-fig2.10.rtf';
proc print data=SMSA_from_CSV (firstobs=17 obs=25);
  var city JanTemp JulyTemp RelHum pop pop_per_house income;
run;
ods rtf close;
```

A partial printing of the data set is shown in Display 2.11. The observations in the Fort Worth bracket are printed even though it contains missing values. This is a good check that you have read in the data correctly and that unusual or missing observations are correctly processed.
