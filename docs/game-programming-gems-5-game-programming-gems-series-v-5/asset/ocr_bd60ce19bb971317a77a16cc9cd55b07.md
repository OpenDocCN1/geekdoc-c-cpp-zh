We expect the small rotations to be more accurate, as the distance between the quaternions is smaller. Large rotations are less common in animation data, but an algorithm must cope with these as well. Table 2.4.1 summarizes the accuracy of the methods for different classes of input data.

| Data set | Large angles | | Medium angles | | Tiny angles | |
|---|---|---|---|---|---|---|
| | Worst | Avg | Worst | Avg | Worst | Avg |
| SlerpDirect | 11 | 13 | 11 | 11 | 11 | 11 |
| SlerpRenormal | 16 | 18 | 17 | 19 | 19 | 19 |
| SlerpMatrix | 13 | 16 | 14 | 15 | 15 | 15 |
| SlerpSimpleRenormal | 4 | 8 | 11 | 15 | 19 | 19 |

This shows that the approximate functions are quite a bit faster than the reference function, although to get real speed improvement, we would need to code using native instruction sets.

The Matrix method is the clear winner, beating even the simple lerp and renormalization method, probably because of the slow implementation of sqrt on the fpu.

This would work especially well on the PS2 VU0 coprocessor, where micro mode could be used to calculate large batches of quaternions for skinning.
