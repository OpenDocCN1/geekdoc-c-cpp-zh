At this point, you might be wondering why the numeric characters on our keyboard are ASCII codes. For example, a 9 should be stored using the binary number system, as we learned earlier? The answer is that the computer uses the binary number to store the *number*, but it uses the ASCII coding scheme to store the character *9*. But how does the computer know whether the 9 is a number or a character? The answer to this question is: by the memory location's data type. Consider a program that displays the message "Enter your age: " on the computer. The program stores your response in a variable named *age*. When you press the 9 key on your keyboard in response to the message, the computer uses the data type of *age* to determine whether to store the 9 as a number (using the binary number system) or as a character (using the ASCII coding scheme). If the variable's data type is *int*, the 9 is stored as the binary number 1001 (one + 8). On the other hand, the 9 is stored as a character using the ASCII code 57, which is represented in internal memory as 00111001 (one + 8 + 16 + 32). The memory location's data type determines how the computer interprets a memory location's existing data.

If a program instruction needs to access the value stored in a memory location—to display the value on the screen—the computer uses the memory location's data type to determine the value's data type. To illustrate this point, assume a memory location named input contains the eight bits 01000001. If the memory location's data type is char, the computer displays the uppercase letter A on the screen. This is because the computer interprets 01000001 as the ASCII code 65, which is equivalent to the uppercase letter A. However, if the memory data type is int, the computer displays the number 65 on the screen, because the 01000001 is interpreted as the binary representation of the decimal number 65. In summary, the data type of a memory location is important because it determines how the data is stored when first entered into the memory location. It also determines how the data is interpreted when the memory location is used in an instruction later in the program.
