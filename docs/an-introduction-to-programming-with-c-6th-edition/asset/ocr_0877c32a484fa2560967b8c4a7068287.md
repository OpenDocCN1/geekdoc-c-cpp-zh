Next, for the clause's condition argument is reevaluated to determine whether the loop instructions should be processed or skipped once. The initialization argument is processed with each repetition (or iteration) of the loop. The condition argument is processed with the desk-table in Figure 7-32, the numStores contains the number 2. Therefore, the numStores <= 3 condition evaluates to true, and the statements in the loop body are processed. The first statement prompts the user to enter Store 2 payroll, and the second statement stores the user's response (in this case, 25000) in the store's payroll to the total payroll: the sum of both values is 40000. The for clause's argument is processed once, like the condition argument update argument is processed with each repetition of the loop. The update argument adds the number 1 to the value stored in the numStores variable, giving 3. Figure 7-33 shows the desk-table after the update argument is processed the second time.

Next, the for clause's condition argument should be processed or skipped whether the loop body instructions are processed or over. Around the desk-table in Figure 7-33, the numStores contains the number 3. The numStores <= 3 condition evaluates to true, and the statements in the loop body are processed. The first statement prompts the user to enter Store 3's payroll, and the second statement stores the user's response (in this case, 60000) in the storePayroll variable. The last statement in the loop body adds the store's payroll to the total payroll: the sum of both values is 100,000. The for clause's update argument is processed next. The update argument adds the number 1 to the value stored in the numStores variable, giving 4. Figure 7-34 shows the desk-table after the update argument is processed the third (and last) time.
