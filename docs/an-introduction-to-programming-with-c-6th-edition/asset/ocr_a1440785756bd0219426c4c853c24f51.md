# Opening a Sequential Access File

Use a program's input and output files, with the C++ open function, to open access files on your computer's disk. Figure 14-3 shows the open function syntax and describes the modes most commonly used to open a sequential file. In the syntax, fileObject is the name of either an ifstream file object or an ofstream file object, and fileName is the name of the file you want to open. Although it is not a requirement, many programs use "txt" (short for "text") extension when naming sequential access files. The open function opens the file name specified in the fileName argument and associates the file with the fileObject. When a subsequent statement in the program needs to read from or write to the file, the fileObject is used. The open function's argument can be either a string constant or a string value. In addition to the file, the fileName argument can also contain an optional path. If the fileName argument does not contain a path, the computer assumes that the file is located in the same folder as the program file. (See the second TIP on this page.) The optional mode indicates how the file is opened. Figure 14-3 uses the ios::in mode to open a file for input, which allows the computer to read the data stored in the file. The ios::out and ios::app modes are used to open output files. Both of these modes allow the computer to write to the file. You use the ios::app (app stands for append) mode when you want to add data to the end of an existing file. If the file does not exist the computer creates the file for you. You use the ios::out mode to open a new, empty file for output. If the file already exists, the computer overwrites the contents of the file before writing any data. The colons (::) in each mode are the scope resolution operator and indicate that the keywords, in, out, and app are defined in the ios class. If the fileName argument does not contain a path, the computer will look for the payroll file in the same location as the program file. Because all files associated with an ifstream file object are opened automatically, it is not necessary to specify ios::in when opening an input file. Unlike files associated with an ofstream object, files associated with an ofstream object are opened automatically for output.
