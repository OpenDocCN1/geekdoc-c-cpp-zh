
终结器声明与C#的前身——即C++——的析构函数语法相同。如清单9.20所示，终结器声明在类名之前使用波浪号（~）作为前缀。

## 清单9.20：定义终结器

```
using System.IO;

class TemporaryFileStream
{
    public TemporaryFileStream(string fileName)
    {
        File = new FileInfo(fileName);
        Stream = new FileStream(
            File.FullName, FileMode.OpenOrCreate,
            FileAccess.ReadWrite);
    }

    public TemporaryFileStream()
        : this(Path.GetTempFileName()) { }

    // Finalizer
    ~TemporaryFileStream()
    {
        Close();
    }

    public FileStream Stream { get; }
    public FileInfo File { get; }

    public void Close()
    {
        Stream?.Close();
        File?.Delete();
    }
}
```

终结器不允许传递任何参数，因此不能被重载。此外，终结器不能被显式调用——也就是说，只有垃圾回收器才能调用终结器。因此，终结器上的访问修饰符是没有意义的，并且不受支持。基类中的终结器会在对象终结调用过程中自动被调用。

> 注意
> 终结器不能被显式调用；只有垃圾回收器才能调用终结器。

由于垃圾回收器负责所有内存管理，终结器并不负责释放内存。相反，它们负责释放诸如数据库连接和文件句柄之类的资源——这些资源需要显式操作，而垃圾回收器并不了解这些操作。

终结器在自己的线程上执行，这使得它们的执行更加不确定。这种不确定性使得终结器内未处理的异常（在调试器之外）难以诊断，因为导致异常的环境并不明确。从用户的角度来看，未处理的异常会相对随机地被抛出，并且与用户正在执行的任何操作关系不大。因此，你应该注意避免在终结器中抛出异常。相反，你应该使用防御性编程技术，例如检查null（参见清单9.20）。

## 使用using语句的确定性终结

终结器本身的问题在于它们不支持**确定性终结**（即能够知道终结器何时运行的能力）。相反，终结器扮演着一个重要角色，即当使用某个类的开发人员忽略显式调用必要的清理代码时，作为清理资源的后备机制。

例如，考虑`TemporaryFileStream`，它不仅包含一个终结器，还包含一个`Close()`方法。这个类使用了一个文件资源，该资源可能占用大量磁盘空间。使用`TemporaryFileStream`的开发人员可以显式调用`Close()`来恢复磁盘空间。

提供一种确定性终结的方法非常重要，因为它消除了对终结器不确定时序行为的依赖。即使开发人员未能显式调用`Close()`，终结器也会处理这个调用。在这种情况下，终结器会比显式调用时运行得更晚——但它最终会被调用。

由于确定性终结的重要性，基类库包含了一个特定的接口来实现这种模式，并且C#将该模式集成到了语言中。`IDisposable`接口通过一个名为`Dispose()`的方法定义了该模式的细节，开发人员在资源类上调用该方法来“释放”所消耗的资源。清单9.21演示了IDisposable接口以及调用它的一些代码。

## 垃圾回收、终结与IDisposable

在清单9.21中还有几个值得注意的地方。首先，IDisposable.Dispose()方法包含一个对System.GC.SuppressFinalize()的重要调用。其目的是将TemporaryFileStream类实例从终结（f-reachable）队列中移除。这是可行的，因为所有清理工作都在Dispose()方法中完成，而不是等待终结器执行。

如果没有对SuppressFinalize()的调用，对象实例将被包含在f-reachable队列中——这是一个包含所有“几乎准备好进行垃圾回收”但还具有终结实现”的对象的列表。运行时不能在终结方法被调用之前对具有终结器的对象进行垃圾回收。然而，垃圾回收本身并不会调用终结方法。相反，对终结对象的引用会被添加到f-reachable队列中，并由另一个线程根据执行上下文认为合适的时间进行处理。具有讽刺意味的是，这种方法延迟了对托管资源的垃圾回收——而恰恰是这些资源很可能应该更早地被清理。延迟的原因是f-reachable队列是一个“引用”列表；因此，在终结方法被调用并且对象引用从f-reachable队列中移除之前，这些对象并不被视为垃圾。

注意

未显式释放的带终结器的对象将最终导致对象生命周期延长。即使在所有显式引用都超出作用域之后，f-reachable队列仍然会持有引用，使对象保持存活，直到f-reachable队列处理完毕。
