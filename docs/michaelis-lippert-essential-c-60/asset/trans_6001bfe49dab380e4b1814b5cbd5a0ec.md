

处理诸如内存映射设备或实现时间关键算法时，关键是将代码的一部分指定为不安全代码。

不安全代码是一个显式的代码块和编译选项，如清单20.10所示。unsafe修饰符对生成的CIL代码本身没有影响，它只是告诉编译器允许在不安全块中进行指针和地址操作的指令。此外，unsafe并不意味非托管。

### 清单20.10：将方法指定为不安全代码

```
class Program
{
    unsafe static int Main(string[] args)
    {
        // ...
    }
}
```

可以将unsafe用作类型或类型中特定成员的修饰符。

此外，C#允许将unsafe作为一条语句来标记允许不安全代码的代码块（参见清单20.11）。

### 清单20.11：将代码块指定为不安全代码

```
class Program
{
    static int Main(string[] args)
    {
        unsafe
        {
            // ...
        }
    }
}
```

不安全块中的代码可以包含诸如指针之类的不安全构造。

> **注意**
>
> 必须显式地向编译器指示支持不安全代码。

由于指针只是恰好引用内存地址的整数，它们不受垃圾回收的影响。C#不允许除非托管类型之外的目标类型，非托管类型既不是引用类型，也不是泛型，并且不包含引用类型。因此，以下命令无效：

```
string* pMessage;
```

同样，以下命令也是无效的：

```
ServiceStatus* pStatus;
```

其中ServiceStatus的定义如清单20.12所示。问题同样在于ServiceStatus包含一个字符串字段。

## 语言对比：C/C++ — 指针声明

在C/C++中，同一声明中的多个指针按如下方式声明：

```
int *p1, *p2;
```

注意p2上的*，这使p2成为int*而不是int。相比之下，C#始终将*与数据类型放在一起：

```
int* p1, p2;
```

结果是两个int*类型的变量。这种语法与在单个语句中声明多个数组的语法一致：

```
int[] array1, array2;
```

指针是一种全新的类型类别。与结构体、枚举和类不同，指针最终并不派生自System.Object，甚至不能转换为System.Object。相反，它们可以（显式地）转换为System.IntPtr（而System.IntPtr可以转换为System.Object）。

### 清单20.12：无效的目标类型示例

```
struct ServiceStatus
{
    int State;
    string Description; // Description is a reference type
}
```

除了仅包含非托管类型的自定义结构体之外，有效的目标类型还包括枚举、预定义值类型（sbyte、byte、short、ushort、int、uint、long、ulong、char、float、double、decimal和bool）以及指针类型（如byte**）。最后，有效语法还包括void*指针，它表示指向未知类型的指针。

## 分配指针

一旦代码定义了指针，就需要在访问它之前为其赋值。与引用类型一样，指针可以包含null值；这是它们的默认值。指针存储的值是一个位置的地址。因此，要为指针赋值，必须先获取数据的地址。

你可以显式地将整数或long转换为指针，但在没有方法在运行时确定特定数据值的地址的情况下，这种情况很少发生。相反，你需要使用地址运算符（&）来获取值类型的地址：

```
byte* pData = &bytes[0];  // Compile error
```

问题在于，在托管环境中，数据可能会移动，从而使地址失效。错误消息是“只能在fixed语句初始化器内获取未固定表达式的地址”。在这种情况下，所引用的字节出现在数组中，而数组是引用类型（一种可移动类型）。引用类型出现在堆上，并且可能会被垃圾回收或移动。当引用可移动类型上的值类型字段时，也会出现类似的问题：

```
int* a = &"message".Length;
```

无论哪种方式，要为某些数据分配地址都需要满足以下条件。

- 数据必须被归类为变量。
- 数据必须是非托管类型。
- 变量需要被归类为固定的，而不是可移动的。

如果数据是非托管变量类型但未被固定，则使用fixed语句来固定可移动变量。

## 固定数据

要获取可移动数据项的地址，必须固定（或称为钉住）数据，如清单20.13所示。

### 清单20.13：fixed语句

```
byte[] bytes = new byte[24];
fixed (byte* pData = &bytes[0]) // pData = bytes also allowed
{
    // ...
}
```

在fixed语句的代码块内，所分配的数据不会移动。在此示例中，bytes将保持在相同地址，至少在fixed语句结束之前不会移动。

fixed语句要求在其作用域内声明指针变量。这避免了在fixed语句之外访问该变量，因为此时数据不再被固定。但是，作为程序员，你有责任确保不将指针赋给另一个在fixed语句作用域之后仍然存在的变量——例如，可能通过API调用。不安全代码被称为“不安全”是有原因的；你需要确保安全地使用指针，而不是依赖运行时替你强制安全性。类似地，对于在方法调用之后不会继续存在的数据，使用ref或out参数也会有问题。

由于字符串是无效的目标类型，定义指向字符串的指针似乎是无效的。然而，与C++一样，字符串在内部是指向字符数组中第一个字符的指针，因此可以使用char*声明指向字符的指针。因此，C#允许在fixed语句中声明char*类型的指针并将其赋给字符串。fixed语句在指针的生命周期内防止字符串移动。类似地，在给定fixed语句的情况下，它允许任何支持隐式转换为另一种类型指针的可移动类型。

你可以用简写形式bytes替换&bytes[0]的冗长赋值，如清单20.14所示。

### 清单20.14：不带地址或数组索引器的fixed语句

```
byte[] bytes = new byte[24];
fixed (byte* pData = bytes)
{
    // ...
}
```

根据fixed语句执行的频率和所需时间，它们可能会导致堆碎片化，因为垃圾回收器无法压缩固定对象。为了减少这个问题，最佳实践是尽早固定块，并且固定较少的大块而不是许多小块。不幸的是，这种偏好必须与尽可能少、尽可能短地固定的做法相平衡，以尽量减少在数据被固定期间发生垃圾回收的可能性。在某种程度上，.NET 2.0通过包含一些额外的感知碎片的代码来减少这个问题。

你可能需要在某个方法体中固定一个对象并使其保持固定直到调用另一个方法；使用fixed语句无法实现这一点。如果你遇到这种不幸的情况，可以使用GCHandle对象上的方法无限期地固定对象。但是，只有在绝对必要的情况下才应该这样做；长时间固定对象很可能会导致垃圾回收器无法有效地压缩内存。

## 在栈上分配

你应该对数组使用fixed语句，以防止垃圾回收器移动数据。不过，另一种方法是在调用栈上分配数组。栈上分配的数据不受垃圾回收或其伴随的终结器模式的影响。与目标类型类似，要求stackalloc数据是非托管类型的数组。例如，你可以将字节数组放到调用栈上，而不是在堆上分配，如清单20.15所示。

### 清单20.15：在调用栈上分配数据

```
byte* bytes = stackalloc byte[42];
```

由于数据类型是非托管类型的数组，运行时可以为数组分配固定缓冲区大小，并在指针超出作用域后恢复该缓冲区。具体来说，它分配sizeof(T) * E的空间，其中E是数组大小，T是目标类型。鉴于要求stackalloc仅用于非托管类型数组，运行时只需展开栈即可将缓冲区归还给系统，从而消除了遍历f-reachable队列的复杂性（参见第9章中题为“垃圾回收”的部分以及关于...的讨论）
