## Transforming Base Claim and Line-Level Carrier Data into a Claim-Level File

Let's combine our base claim and line carrier SAS data set into a single carrier SAS data set with one record for each claim and its associated lines. In Step 5.1, we sort the carrier line file (SRC.CARRIER2010LINE) by the variables BENE_ID, CLM_ID, and CLM_LN.

```sas
* STEP 5.1: SORT CARRIER LINE FILE IN PREPARATION FOR TRANSFORMATION */
proc sort data=src.carrier2010line out=carrier2010line;
  by bene_id clm_id clm_ln;
run;
```

In Step 5.2, we transform the sorted carrier line file (CARRIER2010LINE) from one record per line (identified using the CLM_LN) to one record for each claim, with the line variables array in that record. Because carrier claims have up to 13 claim lines, we will create 13 new variables. As you can see, we do the same for the other variables in our carrier line. These variables will be used in our work in later chapters.

```sas
* STEP 5.2: TRANSFORM CARRIER LINE FILE */
data carrier2010line_wide (drop=expnsdt1 expnsdt2 hcpcs_cd
line_icd_dgns_cd clm_id linepmpt1-13 mmddyy10);
  format expnsdt1_1-expnsdt2_13 mmddyy10;
  line_icd_dgns_cd1-line_icd_dgns_cd3 $5
  hcpcs_cd-hcpcs_cd3 $7
  linepmpt1-linepmpt13 12.
  prfnpipl1-prfnpipl13 $12.
  tax_num1-tax_num13 $10;
  set carrier2010line;
  by bene_id clm_id ln;
  retain
  expnsdt1_1-expnsdt13
  expnsdt2_1-expnsdt213
  line_icd_dgns_cd1-line_icd_dgns_cd3
  hcpcs_cd1-hcpcs_cd13
  linepmpt1-linepmpt13
  prfnpipl1-prfnpipl13
  tax_num1-tax_num13;
  array xline_icd_dgns_cd(13) line_icd_dgns_cd-
line_icd_dgns_cd3;
  array xexpnsdt1(13) expnsdt1_1-expnsdt13;
  array xexpnsdt2_(13) xexpnsdt2_1-expnsdt2_13;
  array hcpcs_cd(13) hcpcs_cd1-hcpcs_cd13;
  array xlinepmt(13) linepmt1-linepmt13;
  array xprfnpi(13) prfnnpil1-prfnnpil13;
  array xtax_num(13) tax_num1-tax_num13;
  if first.clm_id then
    do i=1 to 13
        xline_icd_dgns_cd(clm_ln)='';
        xexpnsdt1_(clm_ln)=.;
        xexpnsdt2_(clm_ln)=.;
        hcpcs_cd(clm_ln)='';
        xlinepmt(clm_ln)=.;
        xprfnpi(clm_ln)='';
        xtax_num(clm_ln)='';
    end;

  xline_icd_dgns_cd(clm_ln)=clm_id_dgns_cd;
  xexpnsdt1_(clm_ln)=xexpnsdt1;
  xexpnsdt2_(clm_ln)=xexpnsdt2;
  hcpcs_cd(clm_ln)=hcpcs_cd;
  xlinepmt(clm_ln)=linepmt;
  xprfnpi(clm_ln)=prfnpi;
  xtax_num(clm_ln)=tax_num;

  if last.clm_id then output;
run;
```

## Chapter 5: Request, Receive, Load, and Transform Data

In Step 5.4, we merge CARRIER2010CLAIM and CARRIER2010LINE_WIDE files by the unique beneficiary identifier (BENE_ID) and the unique claim identifier (CLM_ID), using an “a and b” merge. We use a SAS data set called ETL_2010. This output data set, by BENE_ID, will be used for the remainder of this book. Note that output file called CARR_MATCH contains the records that did not match by BENE_ID and CLM_ID for quality assurance purposes (mismatches indicate a potential issue with the data).

```sas
* STEP 5.4: MERGE BASE CLAIM AND TRANSFORMED LINE FILES */
data etl2010 carr_nomatch;
  merge carrier2010claim(in=a) carrier2010line_wide(in=b);
  by bene_id clm_id;
  if a and b then output;
  else output;
```

Figure 5.4 is a single record of the outputted ETL_2010 data set for the same beneficiary displayed above. ## Chapter Summary

In this chapter, we learned how to receive, load, and transform the Administrative claims and enrollment data we use to complete our research programming project. To this end, we discussed the following information:

- A request can take a lot of time and cost a lot of money to fulfill, so it is important to plan as much as possible before initiating our data request.
- Depending on the source of funding, there are several routes to procuring Medicare data for research purposes. We discussed CMS’s Integrated Data Repository (IDR), Data Extract System (DES), and Research Data Center (VRDC). In addition, we discussed the Research Assistance Center (ResDAC), and CMS’s data distribution contractor.
- ResDAC and CMS’s data distribution contractor are the research community’s gateway to CMS data.
- Our instructional plan is to request data from CMS’s data distribution contractor and quickly convert the data we receive into separate files for each claim type that contain all of the information for a claim in one record.
- CMS offers a variety of datasets for research purposes which we grouped into three categories: Research Identifiable Files (RIFs), Limited Data Sets (LDS), and Public Use Files (PUFs). Consult with ResDAC to ensure you are requesting the right kind of data for your research.
- Our data utilized a file provider by CMS to query the following claims and enrollment data for calendar year 2010: Part B claims, DME claims, inpatient patients, outpatient claims, SNF claims, home health claims, and MBSF enrollment data.
- We discussed a high-level overview of the data acquisition process.
- The package of data received from CMS’s data distribution contractor contained our requested data (in encrypted files), the SAS code for loading the files into SAS datasets, summary information detailing the data transmission, and a host of documentation and data dictionaries.
- We decrypted our data and loaded the files into SAS datasets. Then, we combined the administrative claims, separated into files by claim type, header and line information, and retained access to the finder file (also called attribution file) for use in subsequent chapters.
- As stated in Chapter 3, all discussions of acquisition of source data are for instructional purposes. In other words, although we pretend to go through process of requesting data, we did not actually produce the data in this book.
- See, for example, ResDAC’s Data for Student Research webpage, available at http://www.resdac.org/data-request-student-research.
- The list of data is not exhaustive, and new sources of data do become available.
- For instructional purposes, as part of our work we will transpose some of the files we create in this chapter to create a file containing one record per line.
- All this said, it is important to note that there are advantages to maintaining separate header and line data sets, and using PROC SQL to join the data sets. In your work, and consistent with our discussion planning, you should consider the most efficient way to arrange your data and use your SAS code.
- The reader may wish to request a prior or subsequent year of data to study measures like hospital readmissions, or to make comparisons to prior years of performance outcomes (i.e., compare provider’s performance in 2010 to performance in 2009).
- Our code and explanation draws on a helpful SAS Learning Module provided by UCLA’s Institute for Digital Research and Education, available at http://www.ats.ucla.edu/stat/sas/modules/longtowide_data.htm.
