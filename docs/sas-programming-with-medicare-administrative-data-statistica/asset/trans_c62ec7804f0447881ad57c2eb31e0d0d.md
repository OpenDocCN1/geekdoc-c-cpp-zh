
## 第7 章：衡量服务利用率

在第 5 章中加载的内容（但我们没有将其用于我们的示例研究编程项目）以及第 6 章中创建的相关注册数据（ENR_CONTENT_2010_FNL）。由于我们希望消除所有并非我们研究范围内的受益人的索赔主张，我们必须通过受益人标识变量 `BENE_ID` 来合并数据集。为了让我们的算法运行得尽可能快，我们在使用受益人数据集时，显式地将 `BENE_ID` 加载到内存中。我们可以使用相同的代码来限制我们的七个索赔数据集，我们创建了一个简单的宏 `CLM_LOOP` 来进行界定。使用此宏可以让我们避免重复编写六次合并算法。减少我们需要编写的总代码行数可以节省开发时间并减少编码错误的潜在可能。请注意，我们执行的是“内连接”（if a）合并，仅保留给定数据集中与我们注册数据中的 `BENE_ID` 匹配的记录。

```sas
* 步骤7：按受益人人口界定索赔数据 */
* 创建宏循环处理所有七种类型的索赔数据 */
%macro clm_loop(clmtyp=)
data data.util&clmtyp._2010_fnl;
  merge enr.conterz_2010_fnl(keep=bene_id in=a)
         etl.&clmtyp._2010(in=b)
  by bene_id;
  if a;
  run;
%end clm_loop
%clm_loop(clmtyp=c);
%clm_loop(clmtyp=dm);
%clm_loop(clmtyp=op);
%clm_loop(clmtyp=ip);
%clm_loop(clmtyp=sn);
%clm_loop(clmtyp=hh);
%clm_loop(clmtyp=hs);
```

## 算法：衡量评估与管理 (E&M) 利用率

让我们通过衡量 2010 年医生诊所环境下的 E&M 服务数量，开始对我们持续注册受益人人口的利用特征进行调查。在步骤 7.2 中，我们创建了一个宏变量，通过寻找以“99”开头的程序代码值（表示标准中的“E&M”部分）来识别我们正在衡量的 E&M 服务。我们在宏变量中包含了以下程序代码：99201、99202、99203、99204、99205、99211、99213、99214 和 99215。你可以在网上查询或通过购买程序代码术语手册来了解关于这些程序代码值的定义的信息。请注意，我们并没有使用所有以“99”开头的程序代码。例如，99241 和 99245 等程序代码值识别的是会诊，但这些会诊发生在医生诊所之外。

```sas
* 步骤7.2：定义 E&M 代码 *
%let emcodes='99201', '99202', '99203', '99204', '99205', '99211',
               '99212', '99213', '99214';
```

在步骤 7.3 中，我们在索赔数据集（标准中的“医生诊所环境”部分）`UTL_CARR_2010_FNL` 中搜索宏变量包含的程序代码。承运索赔有 13 行项目，因此我们的数据集每条索赔（或每条记录）有 13 个程序代码需要搜索。我们通过创建一个代表程序代码变量（HPCS_CD1-HPCS_CD13）的数组 `HPCS_CD` 来执行此搜索。然后，我们创建一个名为 `EM_SVC` 的标记，如果数组中的程序代码变量位于宏变量定义的程序代码集中，则将该标记置为 1。如果发现此类证据，`leave` 语句将结束处理并搜索下一条记录（换句话说，我们不是统计索赔中可能存在的所有 E&M 服务，而是寻找单个 E&M 服务的证据）。输出（EM_UTIL）包含了承运数据集中的索赔，并精简了变量集，用于定义受益人、服务日期、提供者以及指示发现 E&M 服务的标记。此输出文件仅包含 `EM_SVC` 等于 1 的记录。

```sas
* 步骤7.3：根据 EMCODES 列表从承运文件提取记录 */
data em_util (keep=bene_id em_svc);
  set utl.carr_2010_fnl (keep=bene_id expnsdt=prfnpi; hcpcs_cd:);
  array hcpcscd(13) hcpcs_cd1-hcpcs_cd13;
  em_svc=0;
  do i=1 to 13;
    if substr(hcpcscd(i),1,5) in (&emcodes) then do;
      em_svc=1;
      leave;
    end;
  end;
  if em_svc=1;
run;
```

在步骤 7.4 中，我们按受益人标识对 `EM_UTIL` 进行去重，每个受益人仅保留一条存在 E&M 服务证据的记录。我们输出一个名为 `UTL_EM_UTIL` 的永久文件。换句话说，这是我们在承运索赔数据中发现 E&M 服务证据的受益人列表。

```sas
* 步骤7.4：去重以创建至少有一次 E&M 服务的受益人列表 */
proc sort data=em_util out=util.em_util nodupkey;
  by bene_id;
```
