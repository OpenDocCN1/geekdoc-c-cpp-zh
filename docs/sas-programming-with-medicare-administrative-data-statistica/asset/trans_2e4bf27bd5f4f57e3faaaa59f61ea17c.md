# 引言

这是一段程！我们学习了医疗保险（Medicare）计划、医疗保险数据，并完成了示例研究编程项目中的所有最后步骤。本章的目的是通过综合结果并完成项目计划中的项目处置阶段，完成研究编程项目的最后步骤。正如前面的章节所述，本书的在线辅助位于 http://support.sas.com/publishing/authors/gillingham.html。在这里，你将找到关于创建虚拟数据的信息、本章及后续章节的代码，以及书中练习的答案。我希望你访问书籍网站，创建自己的虚拟数据并亲自运行代码。

在项目的这个阶段，很容易认为我们已经快完成了！毕竟，我们进行了大量的数据处理，为注册、利用和成本分析创建了分析文件，包括查看慢性病和质量衡量。我们已经定位了项目；我们现在只需要交付一些输出，对吧？嗯，没那么快！现在，你可能已经意识到没有任何事情像初看起来看起来那么简单！作为调查人员，我们需要投入大量精力，以有意义的方式展示存储在分析文件中信息。然后，在展示我们的结果后，我们必须结束项目。有条理地结束项目的方法被称为项目处置（project disposition）；项目处置需要充足的时间和精力，以确保我们的规范、代码和结果在未来几年内都是清晰的。通过这种方式，对我们的研究编程项目进行适当处置将为我们的工作增加额外的的合法性，并便于我们未来使用这些工作。

# 展示救护车利用情况

一种有趣的输出展示方式是检查至少有一次救护车理赔的受益人，以及每位受益人的年龄。这种类型的算法为分析可能引导进一步分析的相关摘要信息提供了一个很好的示例。

在步骤 10.1 中，我们开始通过合并连续注册受益人（ENR_CONTENT_2010_FNL）与第 7 章步骤 7.11 创建的分析摘要文件 UTL_AMB_UTIL，来展示救护车利用情况（我们还处于年龄类别的格式化阶段，你在第 6 章的工作中熟悉的这些）。UTL_AMB_UTIL 文件包含每个至少有一次救护车理赔的受益人的一条记录。由于两个文件已按 BENE_ID 排序，因此不需要预合并排序。输出文件名为 FNL_PRESENT_AMB，同样包含 UTL_AMB_UTIL 中每个受益人的每条记录（我们使用了“if”合并）。
