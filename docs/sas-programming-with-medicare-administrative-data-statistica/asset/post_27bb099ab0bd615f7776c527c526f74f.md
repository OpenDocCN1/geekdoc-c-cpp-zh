## ## Algorithms: Measuring Part A Payments

In the above work, we have measured payments for specific services (like E&M), or in specific settings (like a physician's office or acute-stay hospitals). We must continue this work, using the PMT_AMT variable to summarize total Medicare Part A payments. To this end, we will summarize the total payments in each of the inpatient, SNF, home health, and hospice data sets, and then as a whole. We are not including the outpatient data set, while the outpatient data set contains services performed in an inpatient setting, the claims for these are paid through Medicare Part B. Considering the fact that we are using the same PMT_AMT variable present in each set to summarize payments, we can perform this summaries of payments in a standardized fashion by utilizing a macro loop.

First, in Step 8.7, we utilize a macro to calculate the total Medicare amount paid by the beneficiary, which outputs a separate file for each claim type. Our macro, CLM_LOOP, is reminiscent of the macro utilized in Chapter 7 (Step 7.1) to delimit the data in each claim type by the beneficiaries in our enrollment data, but we code to conditionally process inpatient data. Specifically, our CLM_LOOP macro includes a single PROC SQL statement that should look very familiar; it is the same code we used to define other summaries of payments throughout this chapter.

# Chapter 8: Measuring Costs to Medicare 101

There is, however, one major difference: we figure out how to process inpatient claims that are named differently than the SNF, some health, and hospice files in such a way as require special coding in the macro. Indeed, the inpatient file we are using has already been processed to exclude payment amounts. The name of this file does not follow the same pattern as the other Part A files we are processing in the macro. To include the processing of the inpatient files in the macro, we use %if logic within the macro to identify the type of data that is being processed. Apart from this, the code uses the data created in Chapter 7 (delimited by our enrollment data and, in case of inpatient claims, type of hospital and value of payment amount), and outputs separate files for each claim containing beneficiary identifiers (BENE_ID) and total payments associated with that beneficiary (TOTCOST_BENE). At this point, we have created payment summaries for each of the Part A claim types.

```sas
/* STEP 8.7: CALCULATE TOTAL BENEFICIARY INSTITUTIONAL COSTS USING MACRO LOOP */
%macro clm_loop(clmtype=);
  create table totcost_clmtyp as
  select distinct (bene_id), sum(pmt_amt) as totcost_bene
  if %clmtype=sn or %clmtype=hh or %clmtype=hs then do;
    from utl._clmtyp._2010_fnl
  end;
  else if %clmtype=ip then do;
    from utl._ip_2010_fnl_ss
  end;
  group by bene_id;
  quit;
%mend clm_loop;
%clm_loop(clmtype=ip);
%clm_loop(clmtype=sn);
%clm_loop(clmtype=hh);
%clm_loop(clmtype=hs);
```

Now that we have summarized payments by claim, we can summarize beneficiaries’ total payments for all Medicare Part A services performed the year. To complete this task, we must sum all of the payment amounts calculated in Step 8.7. Step 8.8 utilizes the output of Step 8.7, concatenating each data set from the macro used in Step 8.7. The concatenation is performed by BENE_ID so that the data is sorted by beneficiary. Next, we leverage the concatenation by beneficiary by "group" processing. Simply, for each beneficiary identifier (BENE_ID), we set the total Part A payment variable (PA_TOTCOST_BENE) equal to 0. Then, we add the payment summary for each beneficiary created in Step 8.7. In this way, the final PA_TOTCOST_BENE variable becomes the summary of Part A payments.

```sas
/* STEP 8.8: CALCULATE TOTAL BENEFICIARY INSTITUTIONAL COSTS FROM EACH CLAIMS 102 SAS DATA */
data cst.pa_totcost_bene(keep=bene_id pa_totcost_bene);
  set totcost_clmtyp*;
  by bene_id;
  if first.bene_id then pa_totcost_bene=0;
  pa_totcost_bene+=totcost_bene;
  if last.bene_id then output;
  format pa_totcost_bene dollar15.2;
  label pa_totcost_bene='TOTAL PART A COSTS PER BENEFICIARY';
```
