- 将文件加载到 SAS 数据集中的 SAS 代码（通过文件扩展名 .sas 识别）

- 大量的文档和数据字典，包括一个列出组成数据传输包的文件的‘readme’文件、解密数据的指令、详细每个文件中包含变量的电子表格、数据中诊断和程序代码的信息以及数据字典

## 解密我们的 Medicare 行政数据

我们的第一个障碍是解压缩并解密我们的数据。我们通过 CMS 分发商的电子邮件收到了解密密钥（这是“密码”的一种花丽说法）。我经常提到的问题中，最常见的问题之一是无法解密文件；这个问题通常根源于尝试将文件解密到我们接收数据的介质上。我建议增加一个步骤：将海量存储设备上的所有文件复制到目录中，然后将该目录设为只读。这确保了我们不会意外修改数据，并且可以放心地从该目录进行工作。由于文件是 SDA，我们不需要获取任何特殊的解密软件；除了包含解密密钥的文件外，我们解密过程所需的一切都包含在货物中，包括一个运行解密过程的可执行文件 (.exe)。我们需要遵循数据包中包含的数据文件的解密指令。

## 将我们的 Medicare 行政数据加载到 SAS 数据集中

一旦文件被复制并解密，我们必须将它们加载到 SAS 数据集中。如上所述，CMS 数据分发商通过使用 SAS 代码和我们数据包中完成任务所需的指令，使这一过程变得可行。因此，我们不会花时间（也不会提供代码）来讨论如何将源文件加载到 SAS 数据集中，但讨论一些细节是值得的。

首先，注意我们收到了以下文件：

- 所有机构（住院、门诊、SNF、健康中心和医院）的基础索赔文件和收入中心文件。回想我们在第 3 章中讨论过基础索赔和收入中心文件之间的区别。
- 所有非机构客户（DME 和承运商）的基础索赔文件和收入行文件。回想我们在第 3 章中讨论过基础索赔和行级文件之间的区别。
- 我们还收到了包含注册数据的主二进制摘要文件 (MBSF)。回想我们在第 3 章中讨论过 MBSF。

此外，注意我们收到了文件传输摘要文件（上述的 .sts）以及与每个索赔和注册文件对应的 SAS 程序文件。传输摘要文件包含关于我们的每个索赔和注册文件内容的信息，证实了我们已正确将数据加载到 SAS 中。例如，文件中包含列数、行数、行长度和文件大小的信息。一旦我们加载了平直文件，SAS 数据集中的记录数应与文件传输摘要中的行数计数。
