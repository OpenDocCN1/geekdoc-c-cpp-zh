## Algorithms: Presenting Inpatient Length of Stay Information by State

In this section, we build on our present work of previous chapters by displaying the inpatient length of stay by state. To this end, we use the data set UTL_STAY_UT that we created in Step 7.5 through Step 7.8 presented in Chapter 7. This data set contains summary information on length of stay, but it also contains one record for each beneficiary's unique inpatient claim admission and discharge dates (more on below). We also use the data set of continuously enrolled beneficiaries used in the examples above. This data set, called ENR_CONTEN_2010_FNL, contains information on each beneficiary's place of residence (added to the ENR_CONTNER_2010_FNL data set in Chapter 6).

As mentioned above, the UTL_STAY_UT data set contains one record for each beneficiary's unique inpatient claim admission and discharge dates. We do not need to use the admission and discharge date information for our analysis. Therefore, in Step 10.7, we sort the UTL_STAY_UTIL data, removing duplicate records for each beneficiary, and keeping only the beneficiary identifier and summary information pertaining to each beneficiary's hospital stays. A output, a data set called STAY_UTIL, contains one record for each beneficiary, as well as each beneficiary's inpatient length of stay summary information.

```sas
* STEP 10.7: REMOVE STAY DATES AND SORT IP STAY UTILIZATION DATA */
proc sort data=util_stay_util(keep=bene_id stay_cnt tot_ip_los ip_alos)
out=stay_util nodupkey;
  by bene_id;
```

## 132 SAS Programming with Medicare Administrative Data

In Step 10.8, we add the beneficiary's state to the STAY_UTIL data by merging it with the ENR_CONTENTR_2010_FNL data set. We are presenting a summary of length of stay only for those beneficiaries with at least one inpatient, so we do not retain all beneficiaries in the ENR_CONTENTR_2010_FNL data set (i.e., we use an "in" merge to ensure only the one hospital stay). ## Algorithms: Presenting Rates of Diabetic Eye Exams

In our final example, we present the occurrence of diabetic eye exams by SSA state and county name. We wish to limit our presentation only to those continuously enrolled beneficiaries who are identified as diabetic. This work incorporates the work of previous chapters to identify beneficiaries who have diabetes, and then requires us to identify diabetic eye exams for these diabetic beneficiaries.

Specifically, we utilize the data set CHD.EYE_DIA_COND that we created in Chapter 9 and use the variable EYE_SVC, which flags evidence that a diabetic beneficiary has a service for a diabetic eye exam. However, the data set CHD.EYE_DIA_COND contains records only for beneficiaries identified as having a diabetic eye exam. Because we want to look at the occurrence of eye exams in the overall population of continuously enrolled beneficiaries identified as diabetic, we utilize the data set CHD.DIA_COPD_COND that contains a list of beneficiaries identified as having diabetes. Finally, we utilize the ENR.ContNER_2010_FNL data set to add beneficiary state and county name to our analysis.
