Chapter 1, we discussed the starting point for our example research programming project is a file provided by CMS that contains identifiers for the providers that participated in the pilot program we are studying, along with identifiers for the beneficiaries associated with those providers. Associating providers and beneficiaries to assign responsibility for a beneficiary’s care is called attribution. Constructing algorithms for provider attribution is outside of the scope of this text, so we simply assume that this file of providers and beneficiaries provided by CMS can be used for provider attribution. From this point forward, we refer to this data as a "finder file" (because we send it to CMS's data distribution contractor upon their request for finding all of the claims for the beneficiaries listed in this file). We may also refer to this data as an "attribution file" (because in subsequent chapters we will use this to describe the providers associated with the beneficiaries in the file). Further, we will use this finder file be provided to us both as a flat text file and a SAS set data (so we will not present code for reading the file into a SAS data set).

Our request to CMS must describe the need for identifying claims and enrollment information with the entities in our finder file. Therefore, we will ask CMS's data distribution contractor to extract claims and enrollment data for beneficiaries with the providers who participated in our example pilot program by providing the data distribution contractor over our finder file. Our request will be for claims from year 2010: Part B carrier claims, DME claims (even though we will not use them in this book), inpatient, outpatient claims, SNF claims, hospice claims, home health claims, and MBSF enrollment data. We will use the data received from CMS’s data distribution contractor to develop algorithms to produce summaries of payment, utilization, and quality outcomes. In Chapter 10, we will use these analytic summaries of beneficiary-level data to analyze the providers who participated in the pilot program (and we will use the aforementioned "attribution file" submitted by CMS to accomplish this task).

# Contacting ResDAC and Completing Paperwork

It is important to keep in mind that ResDAC’s mission is to assist researchers with CMS data. When you work on your research programming project, you will need to contact ResDAC to execute a data request. Not only does ResDAC’s expert staff answer questions about obtaining data, but they also answer questions about how to use the data. In other words, there are many reasons for you to turn to the data extraction process: from this book, to ResDAC, to fellow professional research systems specialists, to fellow researchers, to folks at CMS! The high-level instructions for completing a data request are intended to introduce the topic of requesting data and are not a substitute for contacting ResDAC directly. ResDAC staff are the real experts, and the remainder of this chapter is no substitute for seeking their know-how.

Our first step is to visit the ResDAC and data distribution contractor’s websites to obtain the most up-to-date forms and information on data (like data dictionaries). We may wish to contact ResDAC to discuss our planned project, the research questions we need to answer, the data we believe we must request in order to answer those questions, and other pertinent information like the source of our funding. We may also wish to request an estimate of the cost to fulfill our data request at this time.
