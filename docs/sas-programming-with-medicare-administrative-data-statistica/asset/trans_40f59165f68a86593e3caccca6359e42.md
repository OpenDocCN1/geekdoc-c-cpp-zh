# 受益人汇总文件 (Master Beneficiary Summary File)

我们已经审查了七份包含理赔数据的文件，但我们的项目还需要关于我们正在研究的受益人的信息。我开始使用医疗保险数据文件，其中受益人信息最常见的数据源是分母文件（Denominator file）。“分母文件”听起来可能很奇怪，但它是恰当的。在受益人人口统计信息的许多应用中，会将一个计算出的数值（例如，看诊所的次数）除以受益人的数量（可能是样本人群）。例如，如果我们计算了急诊室（ED）服务的总利用率，我们可能希望通过除以样本中受益人的总数来获得人均利用率。在急诊室人均利用率公式中，样本受益人的计数就是分母！人口统计文件中的信息通常被用作此类方程中分母的来源。因此，包含特定年份全医疗保险人口此类信息的文件命名为分母文件。

在 2010 年 3 月，我亲爱的分母文件整合到一个名为“受益人汇总文件”（MBSF）的内容中。¹MBSF 包含了在创建该文件的日历年内任何时间生存且符合医疗保险资格的受益人的人口统计信息。这些信息包括受益人的标识符、性别、出生日期和死亡日期（如适用）。此外，它还包括地理信息，如受益人的州和县代码。可能最重要的是，它包含了与受益人参加医疗保险计划相关的信息，例如可用于确定受益人在医疗保险 A 部分、B、C 和 D 部分注册状态的数据元素。

# 医疗提供者数据 (Provider Data)

对于我们的研究编程项目，我们假设已经获得了一份研究中的医疗提供者列表（以及他们相关的受益人），我们不需要上述那些提供者的信息以及已付理赔数据中包含的内容。例如，Part B 文件包含了如执行提供者的 NPI、提供者类型（例如：团体、个人执业者、独立实验室和机构提供者）、专科、州、邮政编码和专科代码等信息。

CMS 通过国家计划和提供者列举系统（NPPES，发音为“in-pez”）文件提供提供者的描述性数据。NPPES 文件是一个公开的数据集，可以从 CMS 网站下载。该文件包含数据元素，如提供者的 NPI、提供者是个人还是组织（如门诊中心）的信息、医疗保健提供者分类代码（HPTC，简单来说，这是一个描述提供者专科的代码）、名称、业务名称和地址、联系信息以及执照号码。¹¹¹⁷

# 示例：急诊室 (ED) 利用率的识别

假设你正在参加一个名为“医疗保险百万富翁”（Medicare Millionaire）的游戏，你必须使用医疗保险理赔和注册文件来回答研究问题。个人而言，我每晚都会准时收看，但我感觉我可能是唯一的观众之一（毕竟，做这项工作的人群很小！）。想象一下，你已经成功回答了几个问题，现在有机会通过回答以下问题来赢得大奖：哪些数据文件被用于识别急诊 利用率？如果你已经使用了救生线打给朋友，那么你需要做出你最好的猜测。那会是什么？除了我们在本章中学到的知识外，我的猜测将是住院理赔数据。考虑到急诊室通常位于住院医院内，这是一个很好的选择吗？遗憾的是，这个答案只有部分正确。

关于急诊室相关信息的完整信息可以在至少三组理赔数据中找到：住院数据、门诊数据和 Part B 承运商数据¹¹⁸我们将编写代码来为我们的研究编程项目计算急诊利用率，在此期间讨论如何识别急诊利用率是很有启发性的。有几个因素使得急诊服务的识别变得复杂：首先，是受益人是否进入了机构进行住院留留；其次，存在识别通常所谓的服务“专业部分”（professional component）的问题（见下文描述）。

如果受益人在急诊就诊后被收收在医院，那么与急诊就诊相关的信息可以在住院数据集中找到。这些急诊服务使用收入中心代码 0450-0459 和 0981 进行识别。住院理赔数据包含了从急诊就诊中获取的诊断信息。另一方面，如果受益人在急诊室就诊但随后未入住医院，则可以在门诊数据中找到急诊就诊！这些理赔可以使用与住院识别急诊服务时相同的收入中心代码进行识别。

服务的“专业部分”（professional component）简单意味着由医生提供的服务部分。例如，当进行实验室测试时，“专业部分”是提供者（通常是病理学家或其他医生）对测试的解释，而“技术部分”（technical component）则是测试本身的执行。在急诊服务的情况下，专业部分将出现在 Part B 承运商数据中，因为它在使用 CMS-1500 理赔单和受益人的医疗保险 Part B 范围内进行结算。

再次，我们将在第 7 章中构建 SAS 代码来识别急诊利用率。目前，这个示例说明了使用医疗保险数据识别某些常用服务利用的复杂性。以防你还不信服其潜力。

# 总结

本章介绍了研究工作中常用的医疗保险理赔和注册数据。我们学习了：

- 存在由医疗保险 A 部分和 B 部分支付的机构和非机构理赔数据。
- 有七种类型的理赔（不包括 D 部分信息）：Part B 承运商、DME、门诊、住院、SNF、居家医疗和临终。
- 出教学目的，我们将从 CMS 数据分发处获取我们的理赔和注册数据。非机构数据以 Part B 承运商基础理赔、Part B 承运商行项目、DME 基础理赔和 DME 行项目的单独文件存在。机构数据以每种理赔类型的基础理赔和收入中心信息（行项目细节）单独文件存在。在类型 5 中，我们根据理赔类型将这些基础理赔和行项目信息合并为记录。
- 至少使用理赔数据进行研究编程通常需要以下数据元素：
  - 识别受益人标识符的信息，如 BENE_ID 或 HIC。
  - 识别服务提供者的信息，如 NPI。
