For example, it may be desired to take an action if two conditions are both TRUE at the same time. Such an example is already given toward the end of Sec. 4.6. IF [[[#1 LT #2] AND [#3 LT #4]] OR [[#5 LT #6] XOR [#7 LT #8]]] GOTO 100;

The total number of nested left and right brackets is three each in this command. Without nesting, any number of brackets can be used. Seven left and seven right brackets have been used in this example.

It is a good programming practice to first prepare a flowchart for the chosen algorithm, and trace the execution, as far as possible. Program coding should be started only after fully verifying the algorithm. This reduces the possibility of logical errors to a great extent.

There is one more advantage of working with a flowchart. The macro variables do not reflect the physical meaning of a variable (which is really a serious limitation of macro programming). For example, if variable #100 is defined to contain the value of a certain variable, one would always have to remember the meaning of #100. This becomes difficult when working with a large number of variables. As a result, developing a program becomes a bit difficult because one does not have an intuitive feeling of which variable is being used for which purpose. The human brain does not work like a computer. In fact, this is one of the reasons why some programmers find macro programming too complex. A flowchart solves this problem. Once it is prepared, one simply has to copy it in terms of macro variables, and the program is ready! So, drawing a flowchart should not be considered an additional and unnecessary exercise.
