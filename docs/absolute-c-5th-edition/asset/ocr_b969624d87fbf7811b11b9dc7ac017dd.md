# Stream Hierarchies: A Preview of Inheritance

# 12.3 Stream Hierarchies: A Preview of Inheritance

One useful way to organize classes is by means of the "derived from" relationship. When we say that one class is derived from another we mean the derived class was obtained from the other class by adding features. For example, the class of input-file streams is derived from the class of all input streams by adding additional member functions such as open and close. The stream cin belongs to the class of all input streams, but does not belong to the class of input-file streams because cin has no member functions named open and close. This section introduces the notion of a derived class as a way to think about and organize the predefined classes. (Chapter 14 shows how to use the idea of a derived class to define classes of yours.)

Both cin and an input-file stream are input streams. In some sense they are similar. For example, you can use the extractor, >>, with either kind of stream. On the other hand, an input-file stream can be connected to a file using the member function open, but the stream cin has no member function named open. An input-file stream is similar but different kind of stream than cin. An input-file stream is of type ofstream. The cin is an object of the class istream (spelled without the 'f'). The classes istream and ofstream are different but closely related types. Let us see what that means.

When we say that some class D is a derived class of some other class B, it means that class D has all the features of class B but also added features. For example, a stream of type istream (without the 'f') can be used with the extractor, >>. The class ofstream (with the 'f') is a derived class of the class istream, so an object of type ofstream can be used with the extraction operator, >>. An object of the class ofstream has all the properties of an object of type ofstream. In particular, an object of the class ofstream is also an object of type stream.

However, ofstream has added features so that you can do more with an object of ofstream than an object of only type istream. For example, one added feature is that a stream of type istream can be used with the function open. The stream cin is only of type istream and not of type ofstream. You cannot use cin with the function open. Notice that the relationship between the classes istream and ofstream is not symmetric. Every object of type ofstream is of type istream (a file input stream is an input stream), but an object of type istream need not be of ofstream (the object cin is of type istream but not of type ofstream).

The idea of a derived class is really common. An example from everyday life may help make the idea clearer. The class of convertibles, for instance, is a derived class of all automobiles. Every convertible is an automobile, but a convertible is not an automobile. A convertible is a special kind of automobile with special properties that others of automobiles do not have. If you have a convertible, you can lower the pop so that the car is open. (You might say that a convertible has an "open" function as an added feature.)
