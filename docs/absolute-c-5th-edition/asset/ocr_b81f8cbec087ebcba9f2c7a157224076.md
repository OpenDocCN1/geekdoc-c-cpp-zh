# Constructors 277

For example, suppose we wanted to add a constructor for initializing the month and day for objects of type DayYear, which we gave in Display 6.4 and redefine in what follows so it includes a constructor. (We have omitted some of the comments to save space, they should be included in an actual program.)

```
class DayYear {
public:
    DayYear(int monthValue, int dayValue); // Constructor
    //Initializes the month and day to arguments.

    void input();
    void output();
    void set(int month, int day);
    void set(int month);
    int getMonthNumber();
    int getDay();

private:
    int month;
    int day;
}
```

Notice the constructor is named DayYear, which is the name of the class. Also notice that the declaration (prototype) for the constructor DayYear does not start with void or any other name. Finally, notice that the constructor is placed in the public section of the class definition. Normally, you should make your constructors public member functions, otherwise you would not be able to declare any objects of that type, which would make the class completely useless.

With the redefined class DayYear, two objects of type DayYear can be declared and initialized as follows:

```
DayYear date1(7, 4), date2(5, 5);
```

Assuming that the definition of the constructor performs the initializing action that we promised, the declaration will declare the object date1.month to 7, and set the value of date1.day to 4. Thus, the date1 is initialized so that it represents the day July 4. Similarly, date2 is initialized so that it represents the day May 5. What happens if the object date is declared, and then the constructor DayYear is called with the two arguments 7 and 4. Similarly, date2 is declared, and then the constructor DayYear is called with the arguments 5 and 5. The result is conceptually equivalent to the following (although you cannot write it in C++):

```
DayYear date1, date2; //PROBLEMS—BUT FIXABLE
date1.DayYear(7, 4); //VERY ILLEGAL
date2.DayYear(5, 5); //VERY ILLEGAL
```
