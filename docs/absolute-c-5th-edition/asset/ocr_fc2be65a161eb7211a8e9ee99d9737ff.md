> TIP: Separate Interface and Implementation

The principle of encapsulation is that you should define classes so that a programmer who uses the class need not be concerned with the details of how the class is implemented. The programmer who uses the class need only the rules for how to use the class. The rules for how to use the class are known as the interface or API. There is some disagreement on exactly what the interface stand for, but it is generally agreed that they stand for something like application interface or abstract programming interface or something similar. In this book we call these rules for the class. It is important to keep in mind a clear distinction between the interface and the implementation of a class. If your class is well designed, then any programmer who uses the class need only know the interface for the class and not know any details of the implementation of the class. A class interface and implementation are separated in this way is sometimes called an abstract data type (ADT). In Chapter 11 we show you how to separate the interface and implementation by placing them in different files, but the important thing is to keep them conceptually separated.

For a C++, the interface consists of two sorts of things: comments, usually at the beginning of the class definition, that tell what the data of the object is proposed, such as a date or bank account or state of a simulated car; and the public member functions of the class along the comments that tell how to use these public member functions. In a well-designed class, the interface of the class should be all you need to know in order to use the class in your program.
