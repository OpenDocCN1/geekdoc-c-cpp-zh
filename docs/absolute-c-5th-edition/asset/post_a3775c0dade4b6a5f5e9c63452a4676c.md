## Protected Members

If you use the qualified protector (rather than private or public) before a member of a class, then for any class or function other than a derived class the effect is the same as if the member variable were labeled private. However, in the definition of a member function of a derived class, the variable can be accessed by name. Similarly, if you use the qualified protector before a member function of a class, or function other than a derived class, the effect is the same as if the member variable were labeled private. However, in the definition of a member function of a derived class, the protected function can be used.

Protected members are inherited in the derived class as if they were protected in the derived class. In other words, if a member is marked as protected in a base class, then it can be accessed by name in the definitions of all descendant classes, not just in those classes directly derived from the base class.

## Redefining an Inherited Function

A derived class inherits all the member functions (and member variables) that belong to the base class. However, if a derived class requires a different implementation for an inherited member function, the function may be redefined in the derived class. When a member function is redefined, you must list its declaration in the definition of the derived class, even though the declaration is the same as in the base class. If you do not wish to redefine a member function that is inherited from the base class, do not list it in the definition of the derived class.

## Redefining versus Overloading

Do not confuse redefining a function in a derived class with overloading a function name. When you redefine a function definition, the new definition given in the derived class has the same number and types of parameters. When you overload a function, the function in the derived class has a different number of parameters or a parameter of a different type from the function in the base class, and the derived class has both functions. For example, suppose we added a function with the following function declaration to the definition of the class HourlyEmployee:

```cpp
void setName(string firstName, string lastNameName);
```

the class HourlyEmployee would have this two-argument function setName

```cpp
void setName(string newName);
```

the class HourlyEmployee would have two functions named setName. This would be overloading the function name setName.

On the other hand, both the class Employee and the class HourlyEmployee define a function with the following function declaration:

```cpp
void printCheck();
```

In this case, the class HourlyEmployees has only one function named printCheck, but the definition of the function printCheck for the class HourlyEmployee is different from its definition for the class Employee. In this case, the function printCheck has been redefined.

If you are redefining and overloading confused, you do one consolation: both are legal. So, it is more important to learn how to use them than it is to learn distinguish between them. Nonetheless, you should learn the difference between them.

## Signature

A function **signature** is the function's name with the sequence of types in the parameter list, not including the const keyword and the ampersand, &. When you overload a function name, the two definitions of the name must have different signatures using this definition of signature. (Some authorities include the const and/or ampersand as part of signature, but we wanted a definition that works for explaining overloading.) A function that has the same name in a derived class as the base class but has a different signature is overloaded, not redefined.

(As we noted in Chapter 4, some compilers will, in fact, allow you to overload on the basis of const versus no const, but you should not count on it.)

## Access to a Redefined Base Function

Suppose you redefine a function so that it has a difference in the derived class from what it had in the base class. The definition that was not completely lost to the derived class objects. However, if you want to invoke the version of the function in the base class with an object in the derived class, you need some way to say “use the definition of this function in the base class (even though I am an object of the derived class).” The way you say this is to use the scope resolution operator with the name of the base class. An example should clarify the details.

Consider the base class `Employee` (Display 14.1) and the derived class `HourlyEmployee` (Display 14.3). The function `printCheck()` is defined in both classes. Now suppose you have an object of each class, in the following:

JaneE;
HourlyEmployee SallyH;

Then
JaneE.printCheck() ;

uses the definition of `printCheck` given in the class `Employee`, and
SallyH.printCheck() ;

uses the definition of `printCheck` given in the class `HourlyEmployee`.
But suppose you want to invoke the version of `printCheck` given in the definition of the base class `Employee` with the derived class object `SallyH` as the calling object for `printCheck`. Do that as follows:

SallyH.Employee::printCheck() ;
