> TIP: (continued)

You should recognize the following as a legal way to declare an object of type
SampleClass and call the constructor for that class:

SampleClass myVariable(7, 7.77);

However, the following is illegal:

SampleClass yourVariable;

The compiler interprets the previous declaration including a call to a constructor
with no arguments, but there is no definition for a constructor with zero arguments.
You must either add two arguments to the declaration of yourVariable or else add a
constructor definition for a constructor with no arguments.

If you refine the class SampleClass as follows, the previous declaration of
yourVariable would be:

```
class SampleClass
{
public:
    SampleClass(int parameter1, double parameter2);
    SampleClass( ); // Default constructor
    void doStuff();
private:
    int data;
    double data2;
}
```

To avoid this sort of confusion, you should always include a default constructor in any
class you define. If you do not want the default constructor to initialize any member
variables, you can simply give it an empty body when you implement it. The following
constructor definition is perfectly legal. It does nothing but create an uninitialized object:

```
SampleClass::SampleClass() 
/*/Do nothing.*/ */
```

# Constructors with No Arguments

A constructor that takes no arguments is called a default constructor. When you declare an
object and want the constructor with zero arguments to be called, you do not include any
parentheses. For example, to declare an object and pass two arguments to the constructor,
might you do the following:

```
DayYear date(12, 31);
```

However, if you want the constructor with zero arguments to be used, you declare the
object as follows:

```
DayYear date;
```

# EXAMPLE: BankAccount Class

Display 7.2 contains the definition of a class representing a simple bank account embedded in a small demonstration program. A bank account of this has two pieces of data: the account balance and the interest rate. Note that we have represented the account balance as two values of type int, one for the dollars and for the cents. This illustrates that the internal representation of the data need not simply be a member variable for each conceptual piece of data. It may seem

that the balance should be represented as a value of type exact double, rather than two int values. However, an account contains an exact number of dollars and cents, and a value of type double is practically since, an approximate quantity. Moreover, a balance as $323.52 is not a dollar sign in front of a floating-point value. You $323.525 cannot have more or fewer two digits after the decimal point. You cannot have a balance of $323.525, and a member variable of type double would allow a balance. It is not possible to have an account with fractional cents. It is not just what we want for a bank account.

Note that the programmer is using the class BankAccount can think of the balance as a value of type double or two values of int (for dollars and cents). The constructor and mutator functions allow the programmer to read and set the balance as either a double or two ints. The programmer who is using the class need not should think of any underlying member variables. That is part of the implementation that is "hidden" from the programmer using the class.

Note that the mutator function setBalance, as the constructor names, are overloaded. Also note that all constructors and mutator functions check values to make sure they are appropriate. For an instance rate cannot be negative. A balance can be negative, but you cannot have a positive number of dollars and a negative number of cents.

This class has four private member functions: dollarsPart, centsPart, round, and fraction. These member functions are made private because they are only intended to be used in the definitions of other member functions.
