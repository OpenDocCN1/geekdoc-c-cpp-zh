# PITFALL: Unexpected '\\n' in Input

When using the function get you must account for every character of input, even the characters you do not think of as symbols, such as blanks and the newline character, '\n'. A common problem when get is forgetting to dispose of the '\n' that enters every input line. If there is a newline character in the input stream that is not read (usually discarded), then when your program expects to read a "real" symbol using the function get, it will instead read the character '\n'. To clear the input of leftover '\n', you can use the function newLine, which we defined in Display 9.2 (or you can use the function ignore, which we discuss in the next section). Let us look at a concrete example. It is legal to mix different forms of cin. For example, the following is legal:

```
cout << "Enter a number:\n"
int number;
cin >> number;
out << "Enter a letter:\n"
char symbol;
cin.get(symbol);
```

However, this can produce problems, as illustrated by the following dialogue:

+   Enter a number:
21
ter a letter:
A

With this dialogue, the value of number will be 21 as you expect. However, if you expect the value of the symbol is '\A', you will be disappointed. After reading 21, the next character in the input stream is the newline character, '\n', and so that is next. Remember, get does not skip line breaks and spaces. (In fact, what is in the rest of the program, you may not get a chance to type in the A. Once the symbol is filled with the character '\n', the program proceeds to whatever statement is next in the program. If the next statement sends to output, the screen will be filled with output before you get a chance to type in the A.)
