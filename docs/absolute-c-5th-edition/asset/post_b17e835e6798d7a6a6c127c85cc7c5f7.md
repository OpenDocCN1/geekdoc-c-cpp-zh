## Tracing a Recursive Call

Let's see exactly what happens when the following function call is made (as in Display 13.1):

```cpp

```

When this function call is executed, the computer proceeds just as it would with any function call. The argument 123 is substituted for the parameter n, and the body of the function is executed. After the substitution of 123 for n, the code to be executed is equivalent to the following:


## A Closer Look at Recursion

The definition of the function writeVertical uses recursion. Yet we did nothing new or different in evaluating the function call writeVertical(123). We treated it just like any of the function calls saw in previous chapters. We simply substituted the argument 123 for the parameter n and executed the code in the body of the function definition. When we reached the recursive call

```cpp
writeVertical(123 / 10);
```

we simply repeated this process once more.
The computer keeps track of recursive calls in the following way: When a function is called, the computer gets the arguments for the parameter(s) and begins to execute the code. If it should encounter a recursive call, it temporarily stops its computation it must know the result of the recursive call before it can proceed. It saves all the information it needs to continue the computation on, and proceeds to evaluate the recursive call. When the recursive call is completed, the computer returns to finish the output.

- how recursion works
- how recursion ends
- base case or stopping case

The C++ language places no restrictions on how recursive calls are used in function definitions. In order for a recursive function definition to be useful, it must be designed so that any call of the function must terminate with some piece of code that does not depend on recursion. The recursion may call the function again. The process may be repeated by any number of times. However the process will not terminate unless one of the recursive calls does not depend on recursion in order to return a value. The general outline of a successful recursive function is:

- One or more cases in which the function completes its task using one or more recursive calls to accomplish one or more versions of the task.
- One or more cases in which the function accomplishes its task without any recursive calls. These cases without any recursive calls are called base cases or stopping cases.

Often an if-else statement determines which of the cases will be executed. A typical scenario is for the original function call to execute a case that includes a recursive call. That recursive call may turn execute a case that requires another recursive call. For some number of times each recursive call produces another recursive call, but eventually one of the stopping cases holds. Every call of the function must eventually lead to a stopping case or the function will never end because of an infinite chain of recursive calls. (In practice, a call that has an infinite chain of recursive calls will usually terminate normally than actually running.)

The most common way to ensure a stopping case is reached is within the function so that some (positive) numeric quantity is decreased on each recursive call and to provide a stopping case for "small" value. This is how we designed the function writeVertical in Display 13.1. When the function writeVertical is called, that produces a recursive call with a smaller argument. This continues with each recursive call producing another recursive call until the argument is less than 10. When the argument is less than 10, the function calls without producing any more recursive calls, and the process works its way back to the original call and ends.
