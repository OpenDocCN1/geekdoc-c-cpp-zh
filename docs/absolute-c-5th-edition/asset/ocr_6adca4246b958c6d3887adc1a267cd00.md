If you have a compiler that fully conforms to the new C++ standard, then if there is insufficient available memory to create the new variable, the new operator terminates the program. Chapter 18 discusses ways to configure your program so it can do anything other than when new exhausts the frestore.

If you have another compiler, you can check if a call to new was successful by testing if NULL was returned by the call to new. For example, the following code tests to see if the attempt to create a new variable succeeds. The program will end with an error message if the call to new failed to create the desired dynamic variable:

```
int *p;
p = new int;
{
  cout << "Error: Insufficient memory.\n*";
  exit(1);
}
// if new succeeded, the program continues from here.
```

(Remember that this code uses exit, you need an include directive for the library header file <stdlib.h>.)

The constant NULL is actually the number 0, but we prefer to think of it and spell it as NULL to clear that you mean this special-purpose value you can assign to pointer variables. We will discuss other uses for NULL later in this book. The definition of the identifier NULL is a number in the standard libraries, such as <iostream> and <cdef>, so you should include an include directive for either <iostream> or <cdef> (or another suitable library) when you use NULL.

As said, NULL is actually the number 0. The definition of NULL is handled by the C++ preprocessor so the compiler never sees 'NULL' and there is no namespace issue and no using directive is needed for NULL. While we prefer to use NULL rather than 0 in our code, we note that authorities hold the opposite view and advocate using zero rather than NULL.

(Do not confuse the NULL pointer with the null character '\0' which is used to terminate C-strings. They are not the same. NULL is the integer 0 while the other is the character '\0').

Newer compilers do not require the explicit check to see if the new variable was created. On newer compilers, your program will automatically end with an error message if a call to new fails to create the desired dynamic variable. However, with any compiler, the previous check will cause no harm and will make your program more portable.
