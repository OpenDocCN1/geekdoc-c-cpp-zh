## Evaluating Boolean Expressions

As you will see in the next sections of this chapter, Boolean expressions are used to control branching and looping statements. However, a Boolean expression has independent identity apart from any branching or looping statement you might use in. A variable of type bool can store either of the values true or false. Thus, you can set a variable of type result equal to a Boolean expression. For example,

```
bool result = (x < z) && (z < y);
```

A Boolean expression can be evaluated in the same way that an arithmetic expression is evaluated. The only difference is that an arithmetic expression uses operations as +, *, and / produces a number as the final result, whereas a Boolean expression uses relational operations as == and < and Boolean operations as &&, |, and produces one of the two values true or false as the final result. Note that =, !=, <=, >= and so forth, operate on pairs of any built-in type to produce a Boolean value true or false.

First's review evaluating an arithmetic expression. The same technique will work to evaluate Boolean expressions. Consider the following arithmetic expression:

```
(x + 1) * (x + 3)
```

Assume that the variable x has the value 2. To evaluate this arithmetic expression, you evaluate the two numbers to obtain 3 and 5, and then you combine these two using the * operator to obtain 15 as the final value. Notice that in performing this evaluation, you do not multiply the expressions (x + 1) and (x + 3). Instead, you multiply the values of these expressions. You use 3; you do not use (x + 1). You use 5; you do not use (x + 3).

The computer evaluates Boolean expressions the same way. Subexpressions are evaluated to obtain values, each of which is true or false. These individual values of true or false are then combined according to the rules in the tables shown in Display 2.2. For example, consider the Boolean expression

```
!(y < 3) || (y > 7)
```

which might be the controlling expression for an if-else statement. Suppose the value of y is 8. In this case (y < 3) evaluates to false and (y > 7) evaluates to true, so the previous Boolean expression is equivalent to

```
!(false || true)
```

Consulting the tables for || the expression inside the parentheses (which is labeled OR), the computer sees that the expression evaluates to true. Thus, the computer sees that the entire expression is equivalent to

```
!(true)
```

Consulting the tables again, the computer sees that !(true) evaluates to false, and so it concludes that false is the value of the original Boolean expression.

## Precedence Rules

Boolean expressions (and arithmetic expressions) need not be fully parenthesized. If you omit parentheses, the default precedence is as follows: first, then: perform relational operations such as <, &&, and ||. However, it is a good practice to include most parentheses to make the expression easier to understand. One place where parentheses can safely omitted is a simple string of or || (but not a mixture of the two). The following expression is acceptable in terms of both C++ and readability:

```
(temperature > 0) && (humidity > 0)
```

Since parentheses are omitted from an expression, it would have the same meaning, including some precedence rules. Most of the precedence rules for C++ are given in Display 2.3. The table includes a number of operators that are discussed later in this book, but they are included for completeness for those who already know about them.

If one operation is performed before another, the operation that is performed first is said to have higher precedence. All the operators in a given box in Display 2.3 have the same precedence. Operators in higher boxes have higher precedence than operators in lower boxes. When operators have the same precedences and the order is not determined by parentheses, unary operations are done right to left. The assignment operations are also done right to left. For example, x = y means x = (y = z). Other binary operations that have the same precedences are done left to right. For example, x + y + z means (x + y) + z.

Notice that the precedence rules include both arithmetic operators as + and * well as Boolean operators as && and ||. This is because many expressions combine arithmetic and Boolean operations, as in the following simple example:

```
(x + 1) > 2 || x+1 < -3
```

If you check the precedence rules in Display 2.3, you will see that this expression is equivalent to

```
((x + 1) > 2) || ((x + 1) < -3)
```

because and < have higher precedence than ||. In fact, you could omit all the parentheses in the previous expression and it would have the same meaning, although it would be harder to read. Although we do not advocate omitting the parentheses, it would be instructive to show how such an expression is interpreted using the precedence rules. Here is the expression without any parentheses:

```
x + 1 > 2 || x + 1 < -3
```

The precedences first apply the unary -, then apply the +s, then the and <, and finally the ||, which is exactly what the fully parenthesized version says to do. The previous description of how a Boolean expression is evaluated is basically correct, but in C++, the computer takes an occasional shortcut when evaluating a Boolean expression. Notice that in many cases you need to evaluate only the first of two subexpressions in a Boolean expression. For example, consider the following:

```
(x >= 0) && (y > 1)
```

If x is negative, then (x >= 0) is false. As you can see in the tables in Display 2.2, when one subexpression in an && expression is false, the whole expression is false, no matter whether the other expression is true or false. Thus, if the first expression is false, there is no need to evaluate the second expression. A similar happens with ||. If the first of two expressions joined with the || operator is true, then you know the entire expression is true, no matter whether the second expression is true or false. The C++ language uses this to sometimes save itself the trouble of evaluating the second subexpression. This method of evaluation is called short-circuit evaluation.
