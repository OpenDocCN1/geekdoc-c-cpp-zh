# PITFALL: the Inconsistency of const

Use of the const modifier is an all-or-nothing proposition. If you use const for a parameter of a particular type, you should use it for every other parameter that has that type and is not changed by the function call. Moreover, if the type is a class type, you should also use the const modifier for every member function that does not change the value of its calling object. The reason has to do with function calls within function calls. For example, consider the definition of the function welcome:

```
void welcome(const BankAccount& yourAccount)
    cout << "Welcome to our bank.\n";
    cout << "The status of your account is:\n";
}
```

If you do not add the const modifier to the function declaration for the member function output, the member function welcome will produce an error message not changing the account price. However, when the compiler processes the function definition for welcome, it will think that welcome (or at least much) changes the value of yourAccount. This is because when it is translating the function definition for welcome, all the compiler knows about the member function output is the function declaration for output. The function declaration does not contain a const that tells the compiler that the calling object will not be changed, then the compiler assumes that the calling object will be changed. Then you should also use const with parameters of type BankAccount member functions that do not change the values of their calling objects. In particular, the function declaration for the member function output should include a const.
