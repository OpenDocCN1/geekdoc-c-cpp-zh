### Display 5.3 Function with an Array Parameter

Function Declaration

```cpp
void fillUp(int a[], int size);
//Precondition: size is the declared size of the array a.
// The user will type in size integers.
// Postcondition: The array is filled with size integers
// from the keyboard.
```

Function Definition

```cpp
void fillUp(int a[], int size)
{
  cout << "Enter " << size << " numbers:\n";
  for (int i = 0; i < size; i++)
    cin >> a[i];
  cout << "The last array index used is " << (size - 1) << endl;
}
```

When the fillUp is called, it must have two arguments: the first gives an array of integers, and the second should give the declared size of the array. For example, the following is an acceptable function call:

```cpp
int score[5], numberOfScores = 5;
fillUp(score, numberOfScores);
```

This call to fillUp will fill the array with five integers typed at the keyboard. Notice that the parameter a[] (which is used in the declaration and the heading of the function definition) is given with square brackets but no index expression. (You may insert a number inside the square brackets for an array parameter, but the compiler will simply ignore the number, so we will not use such numbers in this book.) On the other hand, the argument given in the function call (score, in this example) is given without any square brackets or any index expression.

What happens to the argument score in this function call? Very loosely speaking, the argument score is plugged into the formal array parameter a in the body of the function, and then the function is executed. Thus, the function call

```cpp
fillUp(score, numberOfScores);
```

is equivalent to the following code:

```cpp
int size = 5;
cout << "Enter " << size << " numbers:\n";
for (int i = 0; i < size; i++)
  cin >> score[i];
  cout << "The last array index used is " << (size - 1) << endl;
```

So far it looks as if an array parameter is simply a call-by-reference parameter for an array. That is close to true, but an array parameter is slightly different from a call-by-reference parameter. To explain the difference, let us review some details about arrays.

Recall that an array is stored as a contiguous chunk of memory. For example, consider the following declaration for the array score:

```cpp
int score[5];
```

When we declare this array, the computer reserves enough memory to hold five variables of type int, which are stored after the other in the memory. The computer does not remember the addresses of each of these indexed variables; it remembers only the address of indexed variable score[0]. The computer also remembers that score has a total of five indexed variables, all of type int. It does not remember the address in memory of any indexed variable other than score[0]. For example, if your program needs score[3], the computer calculates the address of score[3] from the address of score[0]. The computer knows that score[3] is located three variables past score[0]. Thus, to obtain the address of score[3], the computer takes the address of score[0] and adds a number that represents the amount of memory used by three variables; the result is the address of score[3].

Viewed this way, an array has three parts: the address (location in memory) of the first indexed, the base type of the array (which determines how much each indexed variable uses), and the size of the array (that is, the number of indexed variables). When an array is used as an argument to a function, only the first of these three parts is given to the function. When an argument is plugged in for its formal parameter, all that is plugged is the address of the array's first indexed. The base type of the array argument must match the base type of the formal parameter, however, the array argument does not tell the function size of the array. ### The const Modifier

When you use an argument in a function, the function can change the values stored in the. This is usually fine. However, in a complicated function definition, you might write code that inadvertently changes one of the values in the. As a precaution, you can tell the compiler that you do not intend to change the array argument, and the computer will tell you to make sure your code does not inadvertently change any of the values in the array the array should not be changed. For example, the following function outputs the values in an array but does not change the values in the array:

```cpp
void showTheWorld(int a[], int sizeOf)
//Precondition: sizeOf is the declared size of the array a.
//All indexed variables of a have been given values.
//Postcondition: The values in a have been written to the screen.

cout << "The array contains the following values:\n"
for (int i = 0; i < sizeOf; i++)
    cout << a[i] << " ";
cout << endl;
```

This function works however, as an added safety measure, you can add the modifier const to the function heading as follows:

```cpp
void showTheWorld(const int a[], int sizeOf)
```

With this modifier const, the computer will issue an error message if your function definition contains a mistake that changes any of the values in the array argument. For example, this is a version of the function showTheWorld that contains a mistake that inadvertently changes the value of the array argument. Fortunately, this version of the function definition includes us that the array has been changed. This error message will help you to explain the mistake:

```cpp
void showTheWorld(const int a[], int sizeOf)
//Precondition: sizeOf is the declared size of the array a.
//All indexed variables of a have been given values.
//Postcondition: The values in a have been written to the screen.
```
