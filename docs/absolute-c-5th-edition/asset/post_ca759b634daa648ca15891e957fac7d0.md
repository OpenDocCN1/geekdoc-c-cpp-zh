
# I/O with the Class string

You can use the insertion operator, << to output string objects just as you do for data of other types. This is illustrated in Display 9.4. Input with the class string is a bit subtle.

The extraction operator, >> and cin work the same for string objects as other data, but remember that the extraction operator ignores initial whitespace and stops when it encounters more whitespace. It is as true for strings as it is for other data. For example, consider the following code:

```
string s1;
cin >> s1;
cin >> s2;
```

If the user types in

> May the on your toes grow long and curly!

then s1 will receive the value "May" with any leading (or trailing) whitespace deleted. The variable s2 receives the "the". Using the extraction operator, >>, and cin, you can only read in; you cannot read a line or other string that contains a blank. Sometimes this is exactly what you want, but it is not at all what you want.

If you want to program to read an entire line of input into a variable of string, you can use the function. The syntax for using getline string objects is different from what we described for C-strings in Section 9.1. You do not use cin::getline; instead make cin the first argument to getline. (This version of getline is not a member function).

```
string line;
cout << "Enter a line of input:\n";
getline(cin, line);
cout << "END OF OUTPUT\n";
```

When embedded in a complete program, this code produces a dialogue like the following:

```
Enter some input:
Do be to you!
Do be to you!END OF OUTPUT
```

If there were leading or trailing spaces on the line, they would be part of the string value read by getline. In the library <string> (As we will see in Chapter 12, you can use a stream object connected to a text file in place of cin to input from a file using getline).

> This is a bit ironic, since the class string was designed using more modern object-oriented techniques, and the notation for getline is the old, less object-oriented notation. This is an accident of history. This getline function was defined after the <iostream> library was already in use, so the designers had little choice but to make getline a standalone function.

# TIP: More Versions of getline

So far, we have described the following way of using getline:

```cpp
string line;
cout << "Enter a line of input:\n";
getline(cin, line);
```

This version stops when it encounters the end-of-line marker, '\n'. There is a version that allows you to specify a different character as a stopping signal. For example, the following will stop when the first question mark is encountered:

```cpp
string line;
cout << "Enter some input:\n";
getline(cin, line, '?');
```

It makes sense to use getline as if it were a void function, but it actually returns a reference to its first argument, which is cin in the previous code. Thus, the following will read a line of text into s1 and a string of non-whitespace characters into s2:

```cpp
string s1, s2;
getline(cin, s1) >> s2;
```

The invocation getline(cin, s1) returns a reference to cin, so that after the invocation of getline, the next thing to happen is equivalent to

```cpp
cin >> s2;
```

This kind of use getline seems to have been designed for use in a C++ quiz show than to meet any actual programming need, but it can come in handy sometimes.

# PITFALL: Mixing cin >> variable; and getline

Take care in mixing input cin >> variable; with input using getline. For example, consider the following code:

```cpp
int n;
string line;
cin >> n;
getline(cin, line);
```

# PITFALL: (continued)

When this code reads the following input, you might expect the value of n to be set to 42 and the value of line to be set to a string value representing "Hello hitchhiker":

```
42
Hello hitchhiker.
```

However, while n is indeed set to the value 42, line is set equal to the empty string. What happened?
Using cin >> skips leading whitespace on the input but leaves the rest of the line, in this case '\n', for the next input. A statement like
```cpp
cin >> n;
```
always sees on the line for a following getline to read (even if it is the '\n'). In this case, the getline sees the '\n' and stops reading, getline reads an empty string. If you find your program appearing to mysteriously ignore input data, if you mixed these two kinds of input. You might need to use either the newline function from Display 9.5 or the ignore from the library iostream. For example,
```cpp
cin.ignore(1000, '\n');
```
With these arguments, a call to the ignore member function will read and discard the entire rest of the line up to and including the '\n' (until it discards 1000 characters if it does not find the end of the line).

Other baffling problems can appear with programs that use cin with getline. these problems can come and go as you move from one C++ compiler to another. When all else fail, or if you want to be certain of portability, you can resort to character-by-character input using cin.get.

These problems can occur with any of the versions of getline that we discuss in this chapter.
