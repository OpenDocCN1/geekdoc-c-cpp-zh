> PITFALL: Inadvertent Local Variables

If you want to change the value of a variable, the corresponding formal parameter must be a call-by-reference parameter and must have the ampersand, &, attached to its type. If you carelessly omit the ampersand, the function will have a call-by-value parameter where you meant to have a call-by-reference parameter. When the program runs, you will discover that the function call does not change the value of the corresponding argument, because a formal call-by-value parameter is a local variable. If the variable has its value changed in the function, then, with any local variable, that change has no effect outside the function body. This is an error that can be very difficult to see because the code looks right.

For example, the program in Display 4.4 is similar to the program in Display 4.2 except that the parameters were mistakenly omitted from the function arguments. As a result, the arguments firstNum and secondNum are local variables. The argument firstNum and secondNum are never substituted in variable1 and variable2; variable1 and variable2 are instead initialized to the value of firstNum and secondNum. Then, the values of variable1 and variable2 are exchanged. The omission of two ampersands has the program completely wrong, yet it looks identical to the correct program and will compile and run without any errors.

## TIP: Choosing Formal Parameter Name

Functions can be self-contained modules that are designed separately from the rest of the program. On large programming projects, different programmers may be assigned to write functions. The programmer should choose the most meaningful names if he can find for formal parameters. The arguments that will be substituted for the formal parameters may be variables in another function or in the main function. These variables should also be given meaningful names, often chosen someone other than the programmer who writes the function definition. This makes it likely that some or all arguments will have the same names as the formal parameters. This is perfectly acceptable. No matter what names are chosen for the variables that will be used as arguments, these names will not produce any confusion with the names used for formal parameters.

## EXAMPLE: Buying Pizza

The large "economy" size of an item is not always a better buy than the smaller size. This is particularly true when buying pizzas. Pizza sizes are given as the diameter of the pizza in inches. However, the quantity of pizza is determined by the area of the pizza, and area is not proportional to the diameter. Most people cannot easily estimate the difference in area between a ten-inch pizza and a twelve-inch pizza and so cannot easily determine which size is the best buy—that is, with size has the lowest price per inch. Display 4.5 shows a pizza that a consumer can use to determine which of two sizes is the better buy.

Note that functions getData and giveResults have the same parameters, but since getData change the values of its arguments, its parameters are call-by-reference. On the other hand, giveResults only needs the values of its arguments, and so its parameters are call-by-value.

Also note that giveResults has two local variables and that its function body includes calls to the function unitPrice. Finally, note that the function unitPrice has both local variables and a locally defined constant.

C++ allows to give two or more definitions to the same function name, which means you can reuse names that have strong intuitive appeal across a variety of situations. For example, you could have three functions max: one that computes the largest of two numbers, and another that computes the largest of three numbers. Giving two (or more) function definitions for the same name is called overloading the function name.

## Introduction to Overloading

Suppose you are writing a program that requires you to compute the average of two numbers. You might use the following function definition:

```cpp
double ave(double n1, double n2)
{
    return (n1 + n2) / 2.0;
}
```

Now suppose your program also requires to compute the average of three numbers. You might define a new function ave3 as follows:

```cpp
double ave3(double n1, double n2, double n3)
{
    return (n1 + n2 + n3) / 3.0;
}
```
