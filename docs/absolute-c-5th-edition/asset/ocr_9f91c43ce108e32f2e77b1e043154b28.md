Nevertheless, our linked list implementation would probably be fine for an application that uses small sets or for an application that does not invoke the setIntersection function, and we have the benefit of relatively simple code that is easy to understand. If we needed the efficiency, we could maintain the same interface to the Set<T> class but replace our linked list implementation with something else. If we used the hash table implementation from Display 17.25, the contains function would run much more quickly. Switching to a hash table makes it more difficult to retrieve the set of items. Instead of traversing a single linked list must now iterate through the hash table array, and for each index in the array, iterate through the linked list that was not necessary in the linked list implementation of a set. So while we decreased the number of steps it takes to iterate over every item, we have increased the number of steps. If this were troublesome, you could overcome this problem with an implementation of Set<T> that used a linked list (to facilitate iteration) and a hash table (fast lookup). However, the complexity of the code is significantly increased using such an approach. You are asked to explore the hash table implementation in Programming Project 17.10.
