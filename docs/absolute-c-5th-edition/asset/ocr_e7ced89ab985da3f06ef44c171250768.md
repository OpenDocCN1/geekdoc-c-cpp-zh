Overloading an operator as a nonmember gives you automatic type conversion of all arguments. There is a way to overload an operator (and certain functions) that offers both of these advantages. It called overloading as a friend function and is our next topic.

# Friend Functions

If your class has a set of accessor and mutator functions, you can use the accessor and mutator functions to define nonmember overloaded operators (as in Display 8.2). However, although this may give you access to the private member variables, it may not give you efficient access to them. Look again at the definition of the overloaded addition operator + in Display 8.1. Rather than just four member variables, it must incur the overhead of two invocations of getCounts and getDollars. This adds a bit of inefficiency and can also make the code harder to understand. The alternative of overloading as a member gets around this problem at the price of losing automatic type conversion of the first operator. Overloading + as a friend will allow you to directly access member variables and have automatic type conversion for all operations.

A friend function of a class is not a member function of the class, but it has access to the private members of that class (to both private member variables and member functions) just as a friend in the class definition. To make a function friend function, you must name it as a friend in the class definition. For example, in Display 8.3 we have rewritten the definition of the class Money yet another time. We have overloaded the operators as friends. You may operator or function as a friend of a class by listing the operator or function declaration in the definition of the class and placing the keyword friend in front of the operator or function declaration.

A friend or will list the declaration of a member function, except that you would precede the declaration by the keyword friend. just as you would the declaration of a member function. However, a friend is not a member function; rather, it is an ordinary function with extraordinary access to the data members of the class. The friend is defined exactly like the ordinary function it is. In particular, the operator definitions shown in Display 8.3 do not include the qualifier Money: in the function heading. Also, do not use the keyword friend in the function definition (only in the function declaration). The friend operators in Display 8.3 are invoked just like the nonfriend, nonmember operators in Display 8.1, and have automatic type conversion of all arguments just like the nonfriend, nonmember operators in Display 8.1.
