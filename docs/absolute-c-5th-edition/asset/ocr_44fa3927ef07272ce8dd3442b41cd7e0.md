Although this is legal, it is misleading. It looks like both p1 and p2 are pointer variables, in fact only p1 is a pointer variable; p2 is an ordinary int variable. As far as the C++ compiler is concerned, the * that is attached to the identifier int may be as well attached to the identifier p1. One correct way to declare both p1 and p2 to be variables

```
*p1, *p2;
```

An easier and less-prone way to declare both p1 and p2 to be pointer variables using the defined type IntPtr as:

```
IntPtr p1, p2;
```

The second advantage of using a defined pointer type, such as IntPtr, is seen when you define a function with a call-reference parameter for a pointer variable. Without the defined type name, you would need to include both * and & in the declaration for the function, and the details can get confusing. If you use a name for the pointer type, then a call-reference parameter for a pointer type involves complications. You define a call-reference parameter for a defined pointer type just like you any other call-reference parameter. Here is an example:

```
void sampleFunction(IntPtr& pointerVariable) {
```
