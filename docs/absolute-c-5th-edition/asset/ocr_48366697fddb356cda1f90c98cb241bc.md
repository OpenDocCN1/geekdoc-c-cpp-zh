# I/O with the Class string

You can use the insertion operator, << to output string objects just as you do for data of other types. This is illustrated in Display 9.4. Input with the class string is a bit subtle.

The extraction operator, >> and cin work the same for string objects as other data, but remember that the extraction operator ignores initial whitespace and stops when it encounters more whitespace. It is as true for strings as it is for other data. For example, consider the following code:

```
string s1;
cin >> s1;
cin >> s2;
```

If the user types in

> May the on your toes grow long and curly!

then s1 will receive the value "May" with any leading (or trailing) whitespace deleted. The variable s2 receives the "the". Using the extraction operator, >>, and cin, you can only read in; you cannot read a line or other string that contains a blank. Sometimes this is exactly what you want, but it is not at all what you want.

If you want to program to read an entire line of input into a variable of string, you can use the function. The syntax for using getline string objects is different from what we described for C-strings in Section 9.1. You do not use cin::getline; instead make cin the first argument to getline. (This version of getline is not a member function).

```
string line;
cout << "Enter a line of input:\n";ngetline(cin, line);
cout << "END OF OUTPUT\n";
```

When embedded in a complete program, this code produces a dialogue like the following:

```
Enter some input:
Do be to you!
Do be to you!END OF OUTPUT
```

If there were leading or trailing spaces on the line, they would be part of the string value read by getline. In the library <string> (As we will see in Chapter 12, you can use a stream object connected to a text file in place of cin to input from a file using getline).

> This is a bit ironic, since the class string was designed using more modern object-oriented techniques, and the notation for getline is the old, less object-oriented notation. This is an accident of history. This getline function was defined after the <iostream> library was already in use, so the designers had little choice but to make getline a standalone function.
