# Queue

A queue is a first-in/first-out data structure; that is, the data items are removed from the queue in the same order that they were added to the queue.

> TIP: A Comment on Namespaces\Notice that both of the namespaces StackSavitch (Display 17.17) and QueueSavitch (Display 17.20) define a template class Node. As it turns out, the two definitions of Node are the same, but the point discussed here is whether the two definitions are same or different. C++ does not allow you to define the same name twice, even if the definitions are same, unless the names are somehow distinguished. In this case, the two definitions are allowed because they are in different namespaces. It is legal to use both the Stack template class and the Queue template class in the same program. However, you should use


# Friend Classes and Similar Alternatives

You may have found it a nuisance to use the accessor and mutator functions getLink and setLink in the template class Node (see Display 17.17 or Display 17.20). You might be tempted to avoid the invocations of getLink and setLink by simply making the member variable link of the class public instead of private. Before you abandon the principle of making all members private, note two things. First, using getLink and setLink is not really harder for you, directly accessing the links in nodes. (However, getLink and setLink introduce some overhead and may slightly reduce efficiency.) There is a way to avoid using getLink and setLink and instead directly the links of nodes without making the link member variable public. Let us explore this possibility.

Chapter 8 discussed friend functions. As you will recall, if f is a function of a class C, f is not a member function of C; however, when you write the definition

friend class of the function f, you can access private members of C just as you can in the definitions of member functions of C. A class can be a friend of another class in the same way that a function can be a friend of a class. If the class F is a friend of the class c, then every member function of the class F is a friend of the class C. Thus, if, for example, the Queue template class is a friend of the Node template class, then the private member variables would be directly available in the definitions of the member functions of Queue. The details are outlined in Display 17.22.

# EXAMPLE: Hash Tables with Chaining

A hash table or hash map is a data structure that efficiently stores and retrieves data. There are many ways to construct a hash table; in this section we will use an array in combination with linked lists. An object is stored in a hash table by associating with a key. Given the key, we can retrieve the object. Ideally, the key is unique to each object. If the object has intrinsically unique key, then we can use a hash function to compute one. For example, let us use a hash table to store a dictionary of words. Such a hash table might be useful to make a spell-checker—words missing from the hash table might not be properly corrected. We will construct the hash table with a fixed array, each array element references a linked list. The key computed by the hash function will map to the index of the array. The actual data will be stored in a linked list at the hash value's index. Display 17.23 illustrates the idea with a fixed array of ten entries. Initially each entry of the array hasharray contains a reference to an empty linked list. First, we add the word “cat,” which has been assigned the key or hash value of 2 (we will show how this was computed shortly). Next, we add “dog” and “bird,” which are assigned hash values of 4 and 7, respectively. Each of these strings is inserted as the head of the linked list using the hash value as the index in the array. Finally, we add “turtle,” which also has a hash of 2. Since “cat” is already stored at index 2, we now have a collision. Using the existing linked list, there are now two nodes at index 2: “turtle” and “cat.”

To retrieve a value from the hash table, we first compute the hash value of the target. Next we sequentially search the linked list that is stored at hasharray[hashvalue] for the target. If the target is not found in this linked list, the target is not stored in the hash table. If the size of the linked list is small, the retrieval process will be quick.
