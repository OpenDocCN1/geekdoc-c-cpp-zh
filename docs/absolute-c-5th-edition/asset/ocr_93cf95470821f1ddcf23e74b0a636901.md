# Separate Compilation

# TIP: Reusable Components

A class developed and coded into separate files is a software component that can be used again and again in a number of different programs. A reusable component saves effort because it does not need to be redesigned, recoded, retested for every application. A reusable component is also likely to be more reliable than a component that is used only once. It is likely to be more reliable for two reasons. You can afford to spend more time and effort on a component if it will be used many times. Second, if the component is used again and again, it is tested again and again. Every use of a software component is a test of that component. Using a component many times in a variety of contexts is one of the best ways to discover any remaining bugs in the software.

# Using #ifdef

We have given you a method for placing a program in three (or more) files: two for the interface and implementation of each class and one for the application part of the program. A program can be kept in more than three files. For example, a program might use several classes, and each class might be kept in a pair of files. Suppose you have a program spread across more of files and that more than one has an include directive for each interface file as the following:

```
#include <dime.h>
```

Under these circumstances you may have that other files, and these files may in turn include other files. This can easily lead to a situation in which a file, contains definitions in dime.h more than once. C++ does not allow you to define a class more than once, even if the repeated definitions are identical. Moreover, if you are using the same header file in many different projects, it becomes close to impossible to keep track of which includes the class definition more than once. To solve this problem, C++ provides a way of marking a section of code to say "if you have already included this file, before not include it." The following directive defines DIME_H:

```
#define
```

```
#define DIME_H
```

What this means is the compiler's preprocessor puts DIME_H on a list to identify that DIME_H has been seen. Defined is perhaps not the best word for this, since DIME_H is not defined to mean anything but merely put on a list. The important point is that you can use another directive to test whether DIME_H has been defined and so test whether a section of code has already been processed. You can use any (nonkeyword) identifier in place of DIME_H, but you will see that there are standard conventions for which you should use.

The following directive to see whether DIME_H has been defined:

```
#ifdef
```

```
#ifndef DIME_H
```
