## PITFALL: Dangling Pointers

![](img/f4b6fc3d28ec32a6e3350e2846d6e0d1_461_0.png)

When you apply `delete` to a pointer variable, the dynamic variable to which it is destroyed. At that point, the value of the pointer variable is undefined, which means you do not know where it is pointing. Moreover, if some other pointer variable was pointing to the dynamic variable that was destroyed, then this pointer variable is also undefined. These undefined pointer variables are called **dangling pointers**. If p is a dangling pointer and your program applies the dereferencing `operator *` to p (to produce the expression `*p`), the result is unpredictable and usually disastrous. Before you apply the dereferencing operator `*` to a pointer, you should be certain that the pointer variable points to some variable.

C++ has no built-in test to check whether a pointer is a dangling pointer. One way to avoid dangling pointers is to set the pointer variable to equal to `NULL`. Your program can test the pointer variable before applying the dereferencing operator `*` to the pointer. When you use this technique, you follow a call to `delete` by code that sets all dangling pointers to `NULL`. Other pointer variables may become dangling pointers besides the one pointer used in the call to `delete`, so be sure to set all dangling pointers and set them to `NULL` or otherwise ensure that they are not dereferenced.

## Dynamic Variables and Automatic Variables

Variables created with the `new` operator are called dynamic (or dynamically allocated) variables because they are created and destroyed while the program is running. Local variables—that are variables declared within a function definition—also have a certain dynamic characteristic, but they are not called dynamic. If a variable is local to a function, then it is created by the C++ system when the function is called and destroyed when the function is called. Since the main part of a program is just a function called `main`, this is true of the variables declared in the main part of your program. (Since the call to main does not end until the program ends, the variables declared in main are not destroyed until the program ends, but the mechanism for handling local variables is the same for main as any other function.) These local variables are sometimes called automatic variables because their dynamic properties are controlled automatically for you. They are automatically created when the function in which they are declared and automatically destroyed when the function ends.

Variables declared outside any function or class definition, including outside main, are called global variables. These global variables are sometimes called statically allocated variables, because they are truly static in contrast to dynamic and automatic variables. We discussed global variables in Chapter 3. As it turns out, we have no need for global variables and not used them.

> *Variables declared within a class using the modifier `static` are static in a different sense than the dynamic/static contrast we are discussing in this section.*

## TIP: Define Pointer Types

You can define a type name so that pointer variables can be declared like other variables without the need to place an asterisk in each pointer variable. For example, the following defines a type called IntPtr, which is the type for pointer variables that contain pointers variables:

```cpp
typedef int* IntPtr;
```

Thus, the two pointer variable declarations are equivalent:

```cpp
IntPtr p;
```

and

```cpp
int *p;
```

You can use `typedef` to define an alias for any name or definition. For example, the following defines the name Kilometers to mean the same thing as the type name:

```cpp
typedef double Kilometers;
```

Once you have given this definition, you can define a variable of type double as follows:

```cpp
Kilometers distance;
```

Renaming existing types this way can occasionally be useful. However our main use of `typedef` will be to define types for pointer variables.

Keep in mind that a `typedef` does not produce a new type but is simply an alias for the type definition. For example, the previous definition of Kilometers, a variable of type Kilometers may be substituted for a parameter of type double. Kilometers and double are two names for the same type.

There are two advantages to defining pointer type names, such as IntPtr previously defined. First, it avoids the mistake of omitting an asterisk. Remember, if you intend p1 and p2 to be pointers, then the following is a mistake:

```cpp
int *p1, p2;
```

Since the * was omitted from p2, the variable p2 is just an ordinary variable, not a pointer variable. If you get confused and place the * on the int, the problem is the same but is more difficult to notice. C++ allows you to place the * on the type name, such as int, so that the following is legal:

```cpp
int* p1, p2;
```

## TIP: (continued)

Although this is legal, it is misleading. It looks like both p1 and p2 are pointer variables, in fact only p1 is a pointer variable; p2 is an ordinary int variable. As far as the C++ compiler is concerned, the * that is attached to the identifier int may be as well attached to the identifier p1. One correct way to declare both p1 and p2 to be variables

```cpp
*p1, *p2;
```

An easier and less-prone way to declare both p1 and p2 to be pointer variables using the defined type IntPtr as:

```cpp
IntPtr p1, p2;
```

The second advantage of using a defined pointer type, such as IntPtr, is seen when you define a function with a call-reference parameter. Without the defined type, you would need to include & for the pointer. Here is an example:

```cpp
void sampleFunction(IntPtr& p) {
```

## Type Definitions

You can assign a name to a type definition with the `typedef` keyword. These type definitions are normally placed outside the body of functions, typically near the start of a file. That the typedef is global and available to your entire program.

### SYNTAX

```cpp
typedef Known_Type Type_Name;
```

### EXAMPLE

```cpp
typedef int* IntPtr;
```

The name IntPtr can be used to declare pointers to dynamic variables, as in the following example:

```cpp
IntPtr pointer1, pointer2;
```

## PITFALL: Pointers as Call-by-Value Parameters

When a call-by-value parameter is a pointer type, its behavior can occasionally be subtle and troublesome. Consider the function call in Display 10.4. The temp in the function sneaky is a call-by-value parameter, and hence it is a local variable. When the function is called, the value of temp is set to the value of the argument and the function is executed. Since temp is a local variable, no changes to temp should go outside the function sneaky. In particular, the value of the pointer p should not be changed. The sample dialogue makes it like the value of the pointer variable p has changed. Before the call to the function sneaky, the value of *p was 77, and after the call to sneaky the value of *p is 99. What happened?

The situation is diagrammed in Display 10.5. Although the sample dialogue makes it as if the value of p was not changed by the function call to sneaky, p has two things associated with: p's value and the value stored where p points. But the value of p is the pointer (that is, a memory address). After the call to sneaky, the variable p contains the pointer value (that is, the same memory address). The call to sneaky has changed the value of the variable pointed to by p, but it has not changed the value of p.

If the pointer type is a class or structure that has members of a pointer type, the same kind of surprising changes can occur with call-by-value arguments of the class type. However, for classes, you can avoid (and control) these surprise changes by defining a copy constructor, as described in this chapter.
