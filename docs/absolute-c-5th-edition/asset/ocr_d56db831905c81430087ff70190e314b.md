Remember that the forward iterator, bidirectional, and random-access iterator refers to kinds of iterators, not type names. The actual type names will be something like std::vector<int>::iterator; which in this case happens to be a random-access iterator.

Display 19.18 shows some nonmodifying generic functions in the STL. Display 19.18 also uses a notation that is common when discussing iterators. The iterator locations encountered in moving an iterator first—but including an iterator last are called the range. For example, for the loop out the elements in the range [first, last):

```
for (iterator p = first; p != last; p++)
cout << *p << endl;
```

Note that when ranges are given, they may not be in the same container or even the same type of container. For example, for the search function, the ranges [first1, last1) and [first2, last2) may be in the different containers.

Notice that there are three functions in Display 19.18: find, search, and binary_search. The function searches for a subsequence, while the find and binary_search functions search for a single value. How do you decide whether to use find or binary_search when searching for a single element? One returns an iterator whereas the other returns a Boolean value, but that is not the difference. The binary_search function requires that the range be sorted (in ascending order <) and run in time O(log N), whereas the find function does not require that the range be sorted, but guarantees only linear time. If you have the elements in sorted order, you can find them for much more quickly by binary_search.

# Range [first, last)

The movement from some iterator, often container.begin( ), but up to including some location last, often container.end( ), is so common that it has to come with a special range [first, last). The following code outputs all elements in the range [c.begin( ), c.end( )), where c is some container object, such as a vector:

```
for (iterator p = c.begin( ); p != c.end(); p++)
cout << *p << endl;
```

Note with the binary_search function, you are guaranteed that the implementation will use the binary search algorithm, which was discussed in Chapter 13. The importance of using the binary search algorithm is that it guarantees a fast running time, O(log N). If you have not read Chapter 13 and not otherwise heard of a binary search, think of it as a very efficient search algorithm that requires the elements to be sorted. Those are the only two points about binary searches that are relevant to the material in this chapter.
