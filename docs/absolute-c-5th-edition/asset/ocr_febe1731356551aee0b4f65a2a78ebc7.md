Once you make a member variable a private member variable, there is no way to change its value (or to reference the member variable in any other way) except by using one of the member functions. That means that the compiler will enforce the hiding of the implementation of the data for class DayOfYear. If you look carefully at the program in Display 6.4, you will see that the only place the member variable names month and day are used in the definitions of the member functions. There is no reference to today.month, today.day, bachBirthday.month, or bachBirthday.day outside the definitions of member functions.

All the items that follow the word public (in this case the member functions) are said to be public, which means they can be referenced by name anywhere. There are no restrictions on the use of public members.

Any member variables can be public or private. Any member functions can be public or private. However, normal good programming practices require that all member variables be private and typically most members be functions.

You can have any number of occurrences of public and private access specifiers in a class definition. Every time you insert the label

```
public:
```

the list of members changes from private to public. Every time you insert the label

```
private:
```

the list of members changes back to private members. You need not have just one public and one private group of members. However, it is common to have just one public section and one private section.

There is no universal agreement about whether the public members should be listed first or the private members should listed first. The majority seems to prefer listing the public members first. This allows easy viewing of the portions programmers are actually get to use. You can make your own decision on what you wish to place first, but the examples in the book usually list the public members before the private members.

In sense C++ seems to favor the private members first. If the first group of members has neither the public: nor the private: specifier, members of that group automatically become private. You will see this default behavior used in code and should be familiar with it. However, we will not use it in this book.
