# Checking for the End of a File

A common way of processing an input file is to use a loop that processes data from the file until the end is reached. There are two standard ways to test for the end of a file. The most straightforward way is to use the eof member function. Every input-stream has a member function eof that can be used to test for reaching the end of the input file. The function takes no arguments, so a call to the member stream is written

```
fin.eof()
```

This is a Boolean expression that can be used to control a loop, do-while loop, or an if-else statement. This expression returns true if the program has read past the end of the input file; otherwise it returns false. Since we want to test that we are not at the end of a file, a call to the member function is used with a not for. Recall that in C++ the symbol ! is used for not. The entire contents of the file connected to the input stream can be written to the screen with the following loop:

```
inputStream.get(next);
while (!inputStream.eof())
{
    cout << next << endl;
    inputStream.get(next);
}
```

The previous loop reads each character from the input file into the char variable next using the member function, and it writes the character to the screen. After the program has passed the end of the file, the value of instream.eof() changes from false to true. Thus,

```
!inputStream.eof()
```

changes from true to false and the loop ends.
Notice that inStream.eof() does not become true until the program attempts to read one character beyond the end of the file. For example, suppose the file contains the following (without any newline character after the c):

```
ab
c
```

This is actually the following list of characters:

```
ab the newline '\n'>c
```

The loop will read an 'a' and write it to the screen, read a 'b' and write it to the screen, then read the newline '\n' and write it to the screen, then read a 'c' and write it to the screen. At that point the loop will have all the characters in the file. However, the value of inStream.eof() will still be false, not change to true until the program tries to read one more character. That is why the while loop ends with inStream.get(next). The loop needs to read one extra character in order to end the loop.

There is a special end-of-file marker at the end of a file. The member function does not change from false to true until this end-of-file marker is. That is why the while loop could read one character beyond what you think is the character in the file. However, this end-of-file marker is not an ordinary character and should not be manipulated like an ordinary character. You can read this end-of-file marker, but you should not write it out. The result is unpredictable. The system automatically places this end-of-file marker at the end of each file.

To complicate things, the implementation of eof on some compilers will return true without having the end-of-file marker, so you may need to check your compiler's documentation or write a short program to determine your compiler's behavior.

The second way to check for the end of the file is to note (and) the fact that we read with an extraction operator actually returns a Boolean value. The expression

```
(inStream >> next)
```

returns true if the loop was successful and returns false when your code attempts to read beyond the end of the file. For example, the following will read all the numbers of integers connected to the input stream inStream and compute their sum in the variable

```
double sum = 0;
while (inStream >> next)
    sum = sum + next;
cout << "the sum is " << sum << endl;
```

The previous loop might look peculiar, because inStream >> next reads a number from the stream and returns a Boolean value. An expression involving the extraction operator >> is simultaneously an action and a Boolean condition. If there is another number to input, the number is read and the Boolean value true is returned, so the body of the loop executes one more time.

> Technically, the Boolean condition works this way: The returned value of operator >> is an input stream reference (istream&), as explained in Chapter 8. This stream reference is automatically converted to a bool value. The resulting value is true if the stream was able to extract data, and false otherwise.

This second method of testing for the end of a file is preferred by many C++ programmers for what appears to be a cultural reason. It was commonly used in C programming.
