## Display 19.13 The map Template Class

### map Template Class Details

Type name: `map<KeyType, T>` or `map<KeyType, T, Ordering>` for a map that associates ("maps") elements of type KeyType to elements of type T. The Ordering is used to sort elements by key value for efficient storage. If no Ordering is given, the default is used by the operator <.

Library header: `<map>`, which provides the definition in the std namespace.

Defined types: include `key_type` for the type of the key value, `mapped_type` for the type of the values mapped to, and `size_type` (so, the defined key_type is simple as what we call key_type above).

Iterator, `const_iterator`, `reverse_iterator`, and `const_reverse_iterator`: All iterators are bidirectional. those not including const are neither constant nor mutable but something in between. For example, if p is of type iterator, then you can change the key value but not the value of type T. It is best, at least, to treat all iterators as if they were constant. `begin()`, `end()`, `rbegin()`, and `rend()` have the expected behavior. Adding or deleting elements does not affect them, except for an iterator located at the element removed.

## MEMBER FUNCTIONS

| MEMBER FUNCTION (m IS A MAP OBJECT) | MEANING |
| :--- | :--- |
| m.insert(Element) | Inserts Element in the map. Element is of `pair<KeyType, T>`. Returns a value of `pair_iterator`, bool. If the insertion is successful, the second part of the returned pair is true and the iterator is located at the inserted element |
| m.erase(TargetKey) | Removes the element located at the key TargetKey. |
| m.find(TargetKey) | Returns an iterator to the element with key value TargetKey. Returns m.end() if there is no such element. |
| m[TargetKey] | Returns a reference to the object associated with the Target_Key. If the map does not already contain such an object, then a default object of type T is inserted. |
| m.size() | Returns the number of pairs in the map. |
| m.empty() | Returns true if the map is empty; otherwise, returns false. |
| ml == m2 | Returns true if the map contain the same pairs; otherwise, returns false. |

The map template class also has a default constructor, a copy constructor, and other specialized constructors not mentioned here. It has a destructor as well as returns all storage for recycling, and a well-behaved assignment operator.

# Containers

The STL template class `pair<T1, T2>` has objects that are pairs of values such that the first element is of type T1 and the second is of type T2. If aPair is an object of type `pair<T1, T2>`, then aPair.first is the first element, which is of type T1, and aPair.second is the second element, which is of type T2. The member first and second are public members, so no accessor or mutator functions are needed.

The header file for the pair template is `<utility>`. So, to use the pair template class (or something like it) in your file:

```cpp
#include <utility>
using std::pair;
```

The map template class uses pair template class to store the association between the key and a data item. For example, given the definition

```cpp
map<string, int> numberMap;
```

if we add to the map

```cpp
numberMap["*"] = 10;
```

then when we access this pair using, iterator->first will refer to the key "*" while iterator->second will refer to the data value 10.

A simple example shows how to use the member functions of the template class map is given in Display 19.14.

We mention four other associative containers, although we will not give any details about them. The template classes multiset and multimap are essentially the same as map, respectively, multiset allows repetition of elements and multimap allows multiple values to be associated with each key value. Some implementations of STL also include the hash_set and hash_map classes. These template classes are essentially the same as set and map, except they are implemented using a hash table. Hash tables are described in Chapter 17. Instead of hash, most implementations of the set and map use balanced binary trees. In a balanced binary tree, the number of nodes to the left of the root is approximately equal to the number of nodes to the right. Binary search trees are also described in Chapter 17, although we do not discuss details of balancing

## Efficiency

The STL implementations strive to be optimally efficient. For example, the set and map elements are stored in sorted order so that algorithms search for the elements can be more efficient.

Each of the member functions for each of the template classes has a guaranteed maximum time. These maximum running times are expressed using big-O notation, which we discuss in Section 19.3. (Section 19.3 also gives guaranteed running times for some of the container members we have already discussed. These are given in the rest of this chapter. You will be told the guaranteed running times for certain functions.)
