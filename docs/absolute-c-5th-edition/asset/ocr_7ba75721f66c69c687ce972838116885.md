# Classes, Pointers, and Dynamic Arrays

The definition of the overloaded assignment operator uses the this pointer to return the object on the left side of the = sign (which is the calling object):

```
//This version does not work in all cases.
StringClass::operator=(const StringClass& rtSide)
    capacity = rtSide.capacity;
    length = rtSide.length;
    delete [] a;
    a = new char[capacity];
    for (int i = 0; i < length; i++)
        a[i] = rtSide.a[i];

return *this;
```

This version has a problem when used in an assignment with the same object on both sides of the operator, like the following:

s = s;

When this assignment is executed, the following statement is executed:

```
delete [] a;
```

But the calling object .a is s, so this means

```
delete [] s.a;
```

The pointer .a is then undefined. The assignment operator has corrupted the object s and this run of the program is properly ruined.

For many classes, the obvious definition for overloading the assignment operator does not work when the same object is on both sides of the assignment operator. You should always check this case and be careful to write your definition of the overloaded assignment operator so that it also works in this case.

To avoid the problem we had with our first definition of the assignment operator, you can use the this pointer to test this special case as:

```
//Final version with bug fixed:
StringClass::operator=(const StringClass& rtSide)
    if (this == &rtSide)
        //if the right side is the same as the left side
        return *this;
    else
        capacity = rtSide.capacity;
        length = rtSide.length;
        delete [] a;
        a = new char[capacity];
```
