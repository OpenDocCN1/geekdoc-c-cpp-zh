The one-argument constructor says that 25 should be converted to an object of type Money whose member variable dollars is equal to 0. In other words, the constructor converts 25 to an object of type Money that represents $25.00. (The definition of constructor is in Display 8.1)

Note that this type conversion will not work unless there is a suitable constructor. If the class does not contain a constructor with one parameter of type int (or of some other type, such as long or double), the expression

```
baseAmount + 25
```

would produce an error.
Automatic type conversions (produced by constructors) seem most common and compelling over numeric operators as + and -. However, these automatic conversions apply exactly the same way to arguments of ordinary functions, arguments of member functions, and arguments of overloaded operators.

# PITFALL: Member Operators and Automatic Type Conversion

![](bbox=[0.11, 0.558, 0.173, 0.593])

When you overload a binary operator as a member operator, the two arguments are no longer symmetric. One is a calling object, and the second "argument" is a true argument. This is not only unaesthetic but also has a practical shortcoming. Any automatic type conversion will apply only to the second argument. So, for example, as we noted in the previous section, the following would be:

```
Money baseAmount(100, 60), fullAmount;
fullAmount = baseAmount + 25;
```

```
fullAmount = 25 + baseAmount;
```

because 25 cannot be a calling object. Conversion of int values to type Money works for arguments but not for calling objects.
