
## PITFALL: Arguments in the Wrong Order

When a function is called, the computer substitutes the first argument for the first formal parameter, the second argument for the second formal parameter, and so forth. Although the computer checks the type of each argument, it does not check for reasonableness. If you confuse the order of the arguments, the program will not do what you want it to. If there is a type violation to an argument of the wrong type, then you will get an error message. If there is no type violation, your program will probably run normally but produce an incorrect value for the value returned by the function.

## PITFALL: Use of the Terms Parameter and Argument

The use of terms formal parameter and argument that we follow in this book is consistent with common usage, but people also use the terms parameter and argument interchangeably. When you see the terms parameter and argument, you must determine their exact meaning from context. Many people use the term parameter for what we call formal parameters and what we call arguments. Other people use the term argument both for what we call formal parameters and what we call arguments. There is no consistency in how people use these two. (In this book we use the term parameter to mean formal parameter, but this is more of an abbreviation than a true inconsistency.)

## Functions Calling Functions

A body may contain a call to another function. The situation for these sorts of function calls is as if the function had occurred in the main part of the program; the only restriction is that the function declaration (or function definition) must appear before the function is used. If you set your programs as we have done, this will happen automatically, since function definitions come before the main part of the program and all function definitions come after the main part of the program. Although you may include a function call within the definition of another function, you cannot place the definition of one function within the body of another function definition.

## Functions That Return a Value

The returned type of a function can be bool. A call to such function returns true or false and can be used anywhere a Boolean expression is allowed. This can be used in an if-else statement or to control a loop. This often makes a program easier to read. For example, the following function defined:

```cpp
bool appropriate(int rate)
{
    return ((rate >= 10) && (rate < 20)) || (rate == 0);
}
```

## Defining void functions

In C++ a void function is defined in a way similar to that of functions that return a value. For example, the following is a void function that outputs the result of a calculation that converts a temperature expressed in Celsius to Fahrenheit expressed in degrees. The actual calculation would be done elsewhere in the program. This void function implements only the subtask for outputting the results of the calculation.

```cpp
void showResults(double fDegrees, double cDegrees)
{
    cout.set(ios::fixed);
    cout.set(ios::showpoint);
    cout.precision(1);
    cout << fDegrees << " * degrees Fahrenheit is equivalent to\n"
         << cDegrees << " * degrees Celsius.\n";
}
```

As the previous definition illustrates, there are only two differences between a function definition for a void function and a function that returns a value. One difference is that we use the keyword void where we would normally specify the type of the value to be returned. This tells the compiler that this function will not return any value. The name is used as a way of saying "no value is returned by this function." The second difference is that a void function does not require a return statement. The function execution ends when the last statement in the function body is executed.

A void function is an executable statement. For example, the function showResults might be called as follows:

```cpp
showResults(32.5, 0.3);
```
