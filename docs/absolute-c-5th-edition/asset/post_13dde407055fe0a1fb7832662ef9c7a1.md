## Function Declaration (Function Prototype)

A function declaration (function prototype) tells you all you need to know to write a call to the function. A function declaration (or the full function definition) must appear in the main part prior to a call to the function in your program.

> Do not forget
> this semicolon.

## SYNTAX

```
Type_Returned_Or_void FunctionName (Parameter List);
```

where the Parameter_List is a comma-separated list of parameters:

```
Type_1 Formal_Parameter_1, Type_2 Formal_Parameter_2,...
Type_3 Formal_Parameter_Last
```

## return Statements in void Functions

Both void functions and functions that return a value can have return statements. In the case of a function that returns a value, the return statement specifies the value returned. In the case of void function, the return statement does not include any expression for a value returned. A return statement in a void function simply ends the call. Every function that returns a value must end by executing a return statement. However, a void function need not contain a return statement. If it does not contain a return statement, it will end after executing the code in the function body. It is as if there were an implicit return statement just before the final brace, }, at the end of the function body.

## Preconditions and Postconditions

One good way to write a function declaration is to break it down into two kinds of information called the precondition and the postcondition. The precondition states what should be true when the function is called. The function should not be used and cannot perform correctly unless the precondition holds. The postcondition describes the effect of the function call; that, the postcondition tells what will be true after the function is executed in a situation which the precondition holds. For a function that returns a value, the postcondition will describe the value returned by the function. For a function that changes the value of some argument variables, the postcondition will describe all the changes made to the arguments.

## Programmer-Defined Functions

For example, the following is a function declaration with precondition and postcondition:

```cpp
void showInterest(double balance, double rate);
//Precondition: balance is a nonnegative savings account balance.
//rate is the interest rate expressed as a percentage, as between 0
//and 5%.
//Postcondition: The amount of interest on the given balance
//at the given rate is shown on the screen.
```

You do not need to know the definition of the function showInterest in order to use this function. All that you need to know to use this function is given by the precondition and postcondition.

When the only postcondition is a description of the value returned, programmers usually omit the word Postcondition, in the following example:

```cpp
double celsius(double fahrenheit);
//Precondition: fahrenheit is a temperature in degrees
//Fahrenheit.
//Returns the equivalent temperature expressed in degrees
//Celsius.
```

Some programmers choose not to use the words precondition and postcondition in their function comments. However, whether you use the words or not, you should always think in terms of precondition and postcondition when designing a function and deciding what to include in the function comment.

## Main Is a Function

As we noted, the main part of a program is actually the definition of a function called main. When the program is run, the main is automatically called; it in turn, may seem that the return statement in the main part of a program should be optional, practically speaking, it is not. The C++ standard says that you can omit the return statement in the main part of the program, but many compilers require it and almost all compilers allow you to include it. For the sake of portability, you should include a return statement in the main function. You should consider the main part of your program to be a function that returns an integer thus requires a return statement.

Although some compilers may allow you to get away with it, you should not include a call to main in your code. The only system should call main, which it does when you run your program.
