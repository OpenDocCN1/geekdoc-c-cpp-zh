## EXAMPLE: An Abstract Class

In Display 15.6, we have slightly rewritten the class Employee from Display 14.1. This time we have made Employee an abstract class. The following line (highlighted in Display 15.6) is the only thing that is different from our previous definition of Employee (Display 14.1):

```
virtual void printCheck() const = 0;
```

The word virtual and the = in the member function telling the compiler that it is a pure virtual function and therefore the class Employee is now an abstract class. The implementation for the class Employee includes no definition for the class Employee::printCheck, but otherwise the implementation of the class Employee is the same as before (that is, the same as in Display 14.2).

It senses that there is no definition for the member function Employee::printCheck, since you know not what kind of check to write until what kind of employee you are dealing. In our first definition of the class Employee (Displays 14.1 and 14.2), we were forced to give a definition to Employee::printCheck and so gave that an error message saying that the function should not be invoked. We have a more elegant solution. by making Employee::printCheck a pure virtual function, we have set things up that the compiler will enforce the ban against invoking Employee::printCheck.

## 15.2 Pointers and Virtual Functions

> Beware lest you lose the substance by grasping the shadow.

AESOP, The Dog and the Shadow

This section explores some of the more subtle points about virtual functions. To understand this material, you need to have covered the material on pointers in Chapter 10.

## Virtual Functions and Extended Type Compatibility

If Derived is a derived class of the base class Base, then you can assign an object of Derived to a variable (parameter) of type Base, but not the other around. If you consider a concrete example, this becomes sense. For example, DiscountSale is a derived class of Sale (Displays 15.1 and 15.3). You can assign an object of the class DiscountSale to a variable of type Sale, since a DiscountSale is a Sale. However, you cannot reverse the reverse assignment, since a Sale is not necessarily a DiscountSale. The fact that you can assign an object of a derived class to a variable (or parameter) of its base class is critically important for reuse of code via inheritance. However, it does its problems.

For example, a program or unit contains the following class:

```cpp
class Pet
{
public:
    string name;
    virtual void print() const;
};
class Dog : public Pet
{
public:
    string breed;
    virtual void print() const; //keyword virtual not needed,
//but put here for clarity.
};
```

Now concentrate on the data members, name and breed. (To keep this example simple, we have made the member variables public. In a real application, they should be private and have functions to manipulate them.)

```cpp
Dog vdog;
Pet vpet;
```

## Pointers and Virtual Functions

Anything that a Dog is also a Pet. It would seem to make sense to allow programs to consider values of type Dog to be values of type Pet, and hence the following should be allowed:

```cpp
vdog.name = "Tiny"
vdog.breed = "Great Dane"
vpet = vdog;
```

C++ allows this sort of assignment. You may assign a value, such as the value of vdog, to a variable of a parent type, such as vpet, but you are not allowed to perform the reverse assignment. Although the preceding assignment is allowed, the value that is assigned to the variable *pet* loses its breed field. This is the *slicing problem*. The following attempted access will produce an error message:

```cpp
cout << vpet;
// Illegal: class Pet has no member breed
```

You can argue that this makes sense, since once a Dog is moved to a variable of type Pet it should be treated like any other Pet and not have properties peculiar to Dogs. This makes for a lively philosophical debate, but it is usually a nuisance when programming. The named Dog Tiny is still a Great Dane, and we would like to refer to its breed, even if it is treated as a *Pet* somewhere along the way.

Fortunately, C++ offers us a way to treat a Dog as a Pet without throwing away the name of the breed. To do this, we use pointers to dynamic variables. Suppose we have the following declarations:

```cpp
Pet *ppet;
Dog *ppdog;
```

If we use pointers and dynamic variables, we can cast Tiny as a Pet without losing its breed. This is the following:¹

```cpp
ppdog = new Dog;
ppdog->name = "Tiny";
ppdog->breed = "Great Dane";
ppet = ppdog;
```

Moreover, we can still access the *breed* of the node pointed to by ppet. Suppose that

```cpp
Dog::print() const;
```

has been defined as:

```cpp
void Dog::print() const
{
  cout << "name:" << name << endl;
  cout << "breed:" << breed << endl;
}
```

> ¹If you are not familiar with the -> operator, see the subsection of Chapter 10 entitled "The -> Operator."
