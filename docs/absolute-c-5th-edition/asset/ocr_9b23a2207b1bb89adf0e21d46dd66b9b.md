# PITFALL: Arguments in the Wrong Order

When a function is called, the computer substitutes the first argument for the first formal parameter, the second argument for the second formal parameter, and so forth. Although the computer checks the type of each argument, it does not check for reasonableness. If you confuse the order of the arguments, the program will not do what you want it to. If there is a type violation to an argument of the wrong type, then you will get an error message. If there no type violation, your program will probably run normally but produce an incorrect value for the value returned by the function.

# PITFALL: Use of the Terms Parameter and Argument

The use of terms formal parameter and argument that we follow in this book is consistent with common usage, but people also use the terms parameter and argument interchangeably. When you see the terms parameter and argument, you must determine their exact meaning from context. Many people use the term parameter for what we call formal parameters and what we call arguments. Others people use the term argument both for what we call formal parameters and what we call arguments. In not consistency in how people use these two. (In this book we use the term parameter to mean formal parameter, but this is more of an abbreviation than a true inconsistency.)

# Functions Calling Functions

A body may contain a call to another function. The situation for these sorts of function calls is as if the function had occurred in the main part of the program; the only restriction is that the function declaration (or function definition) must appear before the function is used. If you set your programs as we have done, this will happen automatically, since function definitions come before the main part of the program and all function definitions come after the main part of the program. Although you may include a function call within the definition of another function, you cannot place the definition of one function within the body of another function definition.

# EXAMPLE: A Rounding Function

The table of defined functions (Display 3.2) does not include any function for rounding a number. The functions ceil and floor are almost, but not quite, rounding functions. The function ceil always returns the next-highest whole number (or its argument if it happens to be a whole number). So, ceil(2.1) returns 3.0, not 2.0.
