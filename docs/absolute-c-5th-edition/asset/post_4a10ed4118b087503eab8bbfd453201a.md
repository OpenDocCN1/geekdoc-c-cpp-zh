## A HASH FUNCTION FOR STRINGS

A simple way to compute a numeric hash value for a string is to sum the ASCII value of every character in the string and then compute the modulus of the sum using the size of the array. A subset of ASCII codes is given in Appendix 3. Code to compute the hash value is shown in the function computeHash.

```cpp
int computeHash(string s) {
    int hash = 0;
    for (int i = 0; i < s.length(); i++) {
        hash = hash + s[i];
    }
    return hash % SIZE; // SIZE = 10 in example
}
```

For example, the ASCII codes for the string "dog"

- d -> 100
- g -> 111
- g -> 103

The hash function is computed as

```
Sum = 100 + 111 + 103 = 314
Hash = Sum % 10 = 314 % 10 = 4
```

In this example, we compute an unbounded value, the sum of the ASCII values in the string. However, the array was defined to hold a finite number of elements. To scale the sum to the size of the array, we compute the modulus of the sum with respect to the size of the array, which is 10 in the example. In practice, the size of the array is generally a larger number than the number of elements that can lead into the hash table¹. For the string "dog", other strings may also map to the same value. For example, we can verify that "cat" maps to (99 + 97 + 116) % 10 = 2 and "turtle" maps to (116 + 117 + 114 + 116 + 101) % 10 = 2.

A complete code listing for a hash table is given in Displays 17.24 and 17.25. A demo is shown in Display 17.26. The hash table definition uses an array where each element is a Node class defined in Display 17.14. The linked list is implemented using the generic linked list library in Displays 17.14 and 17.15.

> ¹A prime number avoids common divisors modulus that can lead to collisions.

### Display 17.24 Interface File for a HashTable Class

```cpp
// This is the header file hashtable.h. This is the interface
// for the class HashTable, which is a class for a hash table
// of strings.
#ifndef HASHTABLE_H
#define HASHTABLE_H

#include <string>
#include "listtools.h"

using LinkedListSavitch::Node;
using std::string;

namespace HashTableSavitch
{
    const int SIZE = 10; //Maximum size of the hash table array

    class HashTable {
    public:
        HashTable(); //Initialize empty hash table.

        //Normally a copy constructor and overloaded assignment
        //operator would be included. They have been omitted
        //to save space.

        virtual ~HashTable(); //Destructor destroys hash table.
        bool containsString(string target) const;
        //Returns true if target is in the hash table,
        //false otherwise.

        void put(string s);
        //Adds a new string to the hash table.

    private:
        Node<string>* *hashArray[SIZE]; //The actual hash table
        static int computeHash(string s); //Compute a hash value
    }; //HashTable
} //HashTableSavitch
#endif //HASHTABLE_H
```

### Display 17.25 Implementation of the HashTable Class (part 1 of 2)

```cpp
// This is the implementation file hashtable.cpp.
// This is the implementation of the class HashTable.

#include <string>
#include "listtools.h"
#include "hashtable.h"

using LinkedListSavitch::Node;
using LinkedListSavitch::search;
using LinkedListSavitch::headInsert;
using std::string;

namespace HashTableSavitch
{
    HashTable::HashTable()
    {
        for (int i = 0; i < SIZE; i++) {
            hashArray[i] = NULL;
        }
    }

    HashTable::~HashTable()
    {
        for (int i=0; i<SIZE; i++) {
            Node<string> *next = hashArray[i];
            while (next != NULL) {
                Node<string> *discard = next;
                next = next->getLink();
                delete discard;
            }
        }
    }

    int HashTable::computeHash(string s)
    {
        int hash = 0;
        for (int i = 0; i < s.length(); i++) {
            hash = hash + s[i];
        }
        return hash % SIZE;
    }
}
```

## Efficiency of Hash Tables

The efficiency of our hash table depends on several factors. First, let us examine extreme cases. The worst-case run-time performance occurs if every item inserted into the table has the same key. Everything will be stored in a single linked list, and the find operation may require searching through each item in the list. Fortunately, if the items we insert are random, the possibility that all of them have the same key is highly unlikely.

We can decrease the chance of collisions by using a better hash function. For example, the sample hash function that sums each letter of a string ignores the order of the letters. The "rat" and "tar" would have the same value. A better hash function for a string is to multiply each letter by an increasing weight depending on the position in the word:

```cpp
int hash = 0;
for (int i = 0; i < s.length(); i++) {
  hash = 31 * hash + s[i];
}
```

Another way to decrease the chance of collisions is by making the hash table bigger. For example, if the hash table array had a 10,000-capacity but we were only inserting 1000 items, the probability of a collision would be much smaller than if the hash table array could store only 1000 entries.
