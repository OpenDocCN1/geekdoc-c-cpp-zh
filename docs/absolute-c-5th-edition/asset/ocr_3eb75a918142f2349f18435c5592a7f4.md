# CHAPTER 15 Polymorphism and Virtual Functions

> TIP: (continued)

We are now ready to explain why all destructors should be virtual. Consider what happens when destructors are not declared as virtual in a base class. In particular, consider the base class PFArray (partially filled array of doubles) and its derived class PFArrayBak (partially filled array of doubles with backup). We discussed these in Chapter 14, before we knew about virtual functions, and so the destructor in the base class PFArray was not marked virtual. In Display 15.8, we have summarized all facts about we need about the classes PFArray and PFArrayBak so that you need not look back to Chapter 14.

Consider the following code:

```
PFArray *p = new PFArrayBak;
delete p;
```

Since the destructor of the base class is not marked virtual, only the destructor for the base class (PFArray) will be invoked. This will return the memory for the base array a (declared in PFArray) to the freelore, the memory for the base array b (declared in PFArrayBak) will never be returned to the freelore (until the program ends).

On the other hand, if (unlike Display 15.8) the destructor of the base class PFArray were virtual, when delete is applied to p, the constructor for the class PFArrayBak would be invoked (the object pointed to is of type PFArrayBak). The destructor for the class PFArrayBak would delete the array b and then automatically invoke the destructor for the base class PFArray, which would delete the member a. So, with the base class marked virtual, all the memory is returned to the freelore. To prepare for eventualities such as these, it is best to mark destructors as virtual.

# Downcasting and Upcasting

You might think some sort of type casting would allow you to easily get around the slicing problem. However, things are not that simple. The following is illegal:

```
Pet vpet;
Dog vdog; //Dog is a derived class with base class Pet.
...
vdog = static_cast<Dog>(vpet); //ILLEGAL!
```

However, casting in the other direction is perfectly legal and does not even need a casting operator:

```
vpet = vdog; //Legal (but does produce the slicing problem)
```
