

# 使用类字符串 (class string) I/O

你可以使用插入运算符 `<<` 来输出字符串对象，就像对待其他类型的数据类型一样。这在显示 9.4 中所示。使用类 string 进行输入稍微有一点微妙。

提取运算符 `>>` 和 `cin` 对字符串对象的操作方式与其他数据相同，但请记住，提取运算符会忽略开头的空白字符，并在遇到下一个空白字符时停止。这对于字符串和其它数据来说都是成立的。例如，考虑以下代码：

```cpp
string s1;
cin >> s1;
cin >> s2;
```

如果用户输入：

> May the on your toes grow long and curly!

那么 s1 将接收到 "May" 的值，并且任何前导（或尾随）空白字符都会被删除。变量 s2 接收到 "the"。使用提取运算符 `>>` 和 `cin`，你只能读取，而不能读取包含空格的整行或其他字符串。有时这正是你想要的，但有时这完全不是你想要的。

如果你想编写程序将整行输入读入一个 string 变量中，可以使用该函数。使用 `getline` 对象的语法与我们在 9.1 节中描述的 C 字符串不同。你不需要使用 `cin::getline`；相反，将 `cin` 作为 `getline` 的第一个参数。（这个版本的 `getline` 不是成员函数）。

```cpp
string line;
cout << "Enter a line of input:\n";
getline(cin, line);
cout << "END OF OUTPUT\n";
```

当嵌入到完整的程序时，这段代码会产生如下的对话：

```
Enter some input:
Do be to you!
Do be to you!END OF OUTPUT
```

如果行中有前导或尾随空格，它们将成为 `getline` 读取的字符串值的一部分。在 `<string>` 库中（正如我们在第 12 章将看到的，你可以可以使用连接到文本文件的流对象来代替 `cin`，以便使用 `getline` 从文件中输入）。

> 这有点讽刺，因为类 string 是使用更现代的面向对象技术设计的，而 `getline` 的表示法却是旧的、不那么面向对象的符号。这是一个历史的偶然。这个 `getline` 函数是在 `<iostream>` 库已经在使用之后定义的，因此设计者几乎别无选择，只能让 `getline` 成为独立函数。

# 标准类字符串 (Class string)

你不能使用 `cin` 和 `>>` 读取空白字符。如果你想一次读取一个字符，可以使用 `cin.get()`，这是我们在 9.2 节中讨论过的内容。`cin.get()` 函数读取的是 `char` 类型的值，而不是 `string` 类型，但在处理字符串输入时它很有帮助。显示 9.5 包含一个程序，说明了了用于字符串输入的 `getline` 和 `cin.get()`。`newline` 函数的意义在“混合使用 `>> variable;` 和 `getline`”陷阱中得到了解释。

## 字符串对象的 I/O
你可以使用插入运算符 `<<` 配合 `cout` 输出字符串对象。你可以使用提取运算符 `>>` 和 `cin` 输入字符串。当使用 `>>` 输入时，代码读取的是一个由空白符分隔的字符串。你可以使用 `getline` 函数将整行文本输入到字符串对象中。

### 示例

显示 9.5 使用类字符串的程序（2 部分中的第 1 部分）

```cpp
// 展示了 getline 和 cin.get。
#include <iostream>
#include <string>
using namespace std;

void newline();
int main() {
{
    string firstName, lastName, recordName;
    string motto = "Your records are our records.";
    cout << "Enter your first and last name:\n";
    cin >> firstName >> lastName;
    newline();

    recordName = lastName + ", " + firstName;
    cout << "Your name in our records is: ";
    cout << recordName << endl;
    cout << "Our motto is\n";
    motto << endl;
    cout << "Please suggest a better (one line) motto:\n";
    getline(cin, motto);
    cout << "Our new motto will be:\n";
    cout << motto << endl;
```

# 提示：getline 的更多版本

到此为止，我们描述了 `getline` 在遇到行结束符时停止的方式：

```cpp
string line;
cout << "Enter some input:\n";
getline(cin, line);
```

但有一个版本允许你指定一个不同的字符作为停止信号。例如，以下代码遇到问号时停止：

```cpp
string line;
cout << "Enter some input:\n";
getline(cin, line, '?');
```

使用 `getline(cin)` 看起来像是一个 void 函数，但它实际上返回其第一个参数的引用。因此，以下代码读取非空白字符的字符串到 `s2`：

```cpp
string s1, s2;
getline(cin, s1);
```

`getline(s1)` 返回 `cin` 的引用，因此在调用 `getline` 之后，接下来的事情是：

```cpp
>> s2;
```

# 陷阱：混合使用 `>> variable;` 和 `getline`

在混合使用 `cin >> variable;` 和 `getline` 输入时要小心。例如，考虑以下代码：

```cpp
int n;
string line;
cin >> n;
getline(cin, line);
```

# 陷阱（继续）

当这段代码读取以下输入时，你可能期望 `n` 被设置为 42，而 `line` 被设置为代表 "Hello hitchiker" 的字符串：

cin >> 跳过了输入中的空白，但将行的剩余部分（在本例中为 `\n`）留给了下一个输入 `getline`。

```
42
Hello hitchiker.
```

然而，虽然 `n` 确实被设置为 42，`line` 却设置为空字符串。发生了什么？
`getline` 看到 `\n` 并停止读取，在这种情况下，`getline` 读取了一个空字符串。如果你发现你的程序似乎神秘地忽略了输入数据，可能需要使用显示 9.5 中的 `newline` 函数或 `iostream` 库中的 `ignore`。例如：

```cpp
cin.ignore(1000, '\n');
```

使用这些参数，`ignore` 成员函数的调用读取并丢弃包括 `\n` 在内的整行剩余部分（如果未找到行尾，则丢弃 1000 个字符）。

其他奇怪的问题可能会出现在使用 `cin` 配合 `getline` 的程序中。这些问题随着你切换 C++ 编译器而出现或消失。当所有方法都失效时，或者为了确保移植性，可以使用 `cin.get` 进行逐字符输入。

这些问题可能出现在我们在本章讨论的任何 `getline` 版本中。
