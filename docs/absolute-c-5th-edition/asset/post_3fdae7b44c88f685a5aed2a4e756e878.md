
The call to the base constructor is the first action taken by a derived class. Thus, if class B is derived from class A and class C is derived from class B, then when an object of class C is created, first a constructor for class A is called, then a constructor for B is called, and finally the remaining actions of the class C constructor are taken.

## Constructors in Derived Classes

A derived class does not inherit the constructors of its base class. However, when defining a constructor for the derived class, you can and should include a call to a constructor of the base class (within the initialization section of the constructor).

If you do not include a call to a constructor of the base class, then the default (zero-argument) constructor of the base class will be called when the derived class constructor is called.

## PITFALL: Private Member Functions Are Effectively Not Inherited

As noted in the previous Pitfall section, a member variable (or member function) that is private in a base class is not directly accessible the interface and implementation of the base class, not even in a member function definition for a derived class. Note that private member functions are just like private variables in terms of not being directly available. In the case of member functions, the restriction is more dramatic. A private variable can be accessed indirectly via an accessor or mutator member function. A private member function is simply not available. It is as if the private member function was not inherited.

This should not be a problem. Private member functions should be used just as helping functions, and their use should be limited to the class in which they are defined. If you want a member function to be used as a helping member function in a number of inherited classes, then it is not just a helping function, and you should make the member function public.

## The protected Qualifier

As you have seen, you cannot access a private member variable or private member function in the definition of a member function of a derived class. If you use the protected qualifier, rather than private, for a member variable or function, the effect is the same as if it were marked private for any class other than a derived class.

## Inheritance Basics

For example, consider the class HourlyEmployee, which was derived from the base class Employee. We were required to use accessor and mutator functions to manipulate the inherited member variables in the definition of HourlyEmployee::printCheck. If all the member variables of Employee were marked protected instead of private, the definition of HourlyEmployee::printCheck in the derived class could be simplified to the following:

```
void HourlyEmployee::printCheck() {
    // if the member variables of Employee are
    // protected instead of private.
    netPay = hours * wageRate;
    cout << "Pay to the order of " << name << endl;
    cout << "The sum of " << netPay << " Dollars\n";
    cout << "Check Stub: Not NEGOTABLE\n";
    cout << "HourlyEmployee: " << ssn << endl;
    cout << "HourlyEmployee.hours worked: " << hours << endl;
    cout << "Rate: " << wageRate << " Pay: " << netPay << endl;
}
```

In the derived class HourlyEmployee, the inherited member variables name, netPay, and ssn can be accessed by name provided they are marked protected (as opposed to private) in the base class Employee. In any class that is not derived from the base class, these member variables are treated as if they were marked private.

Member variables that are protected in the base class act as though they are also protected in any derived class. For example, suppose you define a class PartTimeHourlyEmployee of the class HourlyEmployee. The class PartTimeHourlyEmployee inherits all the member variables of the class HourlyEmployee, including the member variables that HourlyEmployee inherits from the class Employee. The class PartTimeHourlyEmployee will have the member variables netPay, name, and ssn. If these member variables are protected in the class Employee, then they can be used by name in functions of the class PartTimeHourlyEmployee.

Except for derived classes (and derived of derived classes, etc.), a member variable that is protected is treated as if it were marked private.
