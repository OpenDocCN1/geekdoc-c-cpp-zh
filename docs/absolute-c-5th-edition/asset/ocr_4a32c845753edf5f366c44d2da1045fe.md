# Constructors 283

constructor DayYear creates an anonymous object for the date May 5. This anonymous object is assigned to the variable holiday (which has been declared to be of type DayYear) so that holiday also represents the date May 5.

```
holiday = DayYear(5, S)
```

(As you might guess from the notation, a constructor sometimes behaves like a function that returns an object of its class.)

Note that when you invoke a constructor with no arguments, you include parentheses as follows:

```
holiday = DayYear();
```

The parentheses are only omitted when you declare a variable of the class type and you invoke a constructor with no arguments as part of the declaration.

A constructor that takes no arguments is called a default constructor. This name can be misleading because it is generated by default (that is, automatically) and sometimes it is not. Here is the full story. If you define a class and include absolutely no constructors of any kind, a default constructor will be automatically created. This default constructor does not do anything, but it gives you an uninitialized object of the class, which can be assigned to a variable of the class. If your class definition includes one or more constructors of any kind, no constructor is generated automatically. For example, suppose you define a class called SampleClass.

If you include one or more constructors that take one or more arguments, but you do not include a default constructor in your class definition, then there is no default constructor and any declaration like the following will be illegal:

```
SampleClass variable;
```

The problem with the previous declaration is that it asks the compiler to invoke the default constructor, but there is no default constructor in this case.

To make this, suppose you define a class as follows:

```
class SampleClass {
  public:
    SampleClass(int parameter1, double parameter2);
    void doStuff();
  private:
    int data1;
    double data2;
} (continued)
```

> Note that this process is more complicated than simply changing the values of member variables. For efficiency reasons, you may wish to retain the member functions named to use in place of an explicit call to a constructor.
