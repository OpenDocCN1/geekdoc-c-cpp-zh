Each time the loop is executed, the following operations are performed: <, !=, !, and++. This adds five operations for each loop iteration. After N iterations, the Boolean expression is again checked and found to be false. This adds a final three operations (<, !=, !). If we tally up all these operations, we find a total of 6N+5 operations when the target is not in the array. We will leave it to the reader to confirm that if the target is in the array, then the number of operations will be 6N+5 or fewer. Thus, the worst-case running time is T(N)=6N+5 operations for any array of N elements and any value of target.

We just determined the worst-case running time for our search is 6N+5 operations. But an operation is not a traditional unit of time, like a nanosecond, if we want to know how long the algorithm will take for some particular computer, we must know how long it takes to perform one operation. If an operation can be performed in one nanosecond, then the time will be 6N+5 seconds. If we use a slow computer that takes ten seconds to perform an operation, the time will be 6N+50 seconds. In general, if the computer c performs one operation, then the actual running time will be approximately (6N+5) nanoseconds. (We said approximately because we are making some assumptions, and the result may not be the absolute exact running time.) This means our running time of 6N+5 is a very crude estimate. To get the running time expressed in nanoseconds, you must multiply by some constant that depends on the computer you are using. Our estimate of 6N+5 is only accurate to a certain multiple.

Estimates on running time, as the one we just went through, are normally expressed in something called Big-O notation. (The O is the letter "Oh," not the digit zero.) Suppose we estimate the running time to be, 6N+5 operations, and suppose we know that no matter what the running time of each different operation may turn out to be, there will always be some factor c such that the real running time is less than

+   c (6N + 5)

Under these circumstances, that code (or program or algorithm) runs in time O(6N+5). This is usually called "big-O of 6N+5." We need not know the constant c will be. In fact, it would be undoubtedly for different computers, but we must know there is one c for any reasonable computer system. If the computer is very fast, the c might be less than 1—say, 0.001. If the computer is slow, the c might be very large—say, 1000. Moreover, since the units (from nanosecond to second) only involve a constant, there is no need to give any units of time.
