## CHAPTER 7 Constructors and Other Tools

### const Parameter Modifier

If you place the modifier before the type for a call-by-reference parameter, the parameter is called a constant parameter. When you add the const: you are telling the compiler that this parameter should not be changed. If you make a mistake in your definition of the function so that it changes the constant parameter, the compiler will give an error message. Parameters of a class type that are not changed by the function ordinarily should be constant call-by-reference parameters rather than call-by-value parameters.

If a member function does not change the value of its calling object, you can then mark the function by adding the const: modifier to the function declaration. If you make a mistake in your definition of the function so that it changes the calling object and the function is marked with const, the computer will give an error message. The const is placed at the end of the function declaration, just before the final semicolon. The heading of the function definition should also have a const: so that it matches the function declaration.

## EXAMPLE

```cpp
class Sample
{
public:
    Sample();
    void input();
    void output( ) const;
private:
    int stuff;
    double morestuff;
};

int compare(const Sample& s1, const Sample& s2);
```

Use of the const modifier is an all or nothing proposition. You should use the const modifier whenever it is appropriate for a class parameter and whenever it is appropriate for a member function of the class. If you do not use const every time that it is appropriate for a class, then you should never use it for that class.

## Inline Functions

You can give the complete definition of a member function within the definition of its class. Such definitions are called inline function definitions. These are typically used for short function definitions. Display 7.5 shows the class in Display 7.4 rewritten with a number of inline functions.

Inline functions are more than just a notational variant of the kind we have already seen. The compiler treats an inline function in a special way. The code for an inline function declaration is inserted at location where the function is invoked. This saves the overhead of a function invocation.

All other things being equal, an inline function should be more efficient and hence preferable in the usual way. However, all other things are seldom, if ever equal, Inline functions have the disadvantage of mixing the interface and implementation of an equal and so go against the principle of encapsulation.

It is generally believed that only short function definitions should be defined inline. The inline version can actually be less efficient, because a large piece of code is repeated. To decide whether to use inline, just place the keyword inline before the declaration.

## Static Members

Sometimes you want to have one variable that is shared by all objects. For example, you might want one variable to count the number of times a member function is invoked by all objects. Such variables are called static variables and can be used by objects of the class to communicate with each other or coordinate their actions. Such variables allow some of the advantages of global variables without opening the flood gates to all the abuses global variables invite. In particular, a static variable can be private so that only objects of the class can directly access it.

If a member function does not access the data of any object and you want the function to be a member of the class, you can make it a static function. Static functions can be invoked in the normal way, using a calling object. However, it is more common and clearer to invoke a static function using the class name and resolution operator, in the following example:

```
Server::getTurn()
```

Because a static function does not need a calling object, the definition of a static function cannot use anything that depends on a calling object. A static function definition cannot use any nonstatic variables or member functions, unless the nonstatic variable or function has a calling object created in the definition. If that last sentence seems hard to understand, use the simpler rule that the definition of a static function cannot use anything that depends on a calling object.

initializing static variables

Such initialization requires a bit of explanation. Every static variable must be initialized outside the class definition. Also, a static variable cannot be initialized more than once. As in Display 7.6, private static variables—in fact, all variables—are initialized outside the class. This may seem to be contrary to the notion of private. However, the author of a class is expected to do the initializations, typically in the same file as the class definition. In that case, no programmer uses the class to initialize the static variables, since a static variable cannot be initialized a second time.
