# Inheritance Basics

For example, consider the class HourlyEmployee, which was derived from the base class Employee. We were required to use accessor and mutator functions to manipulate the inherited member variables in the definition of HourlyEmployee::printCheck. If all the private member variables in the class were labeled with the keyword protected instead of private, the definition of HourlyEmployee::printCheck in the derived class Employee could be simplified to the following:

```
void HourlyEmployee::printCheck() {
// if the member variables of Employee are marked
// protected instead of private.
{
  netPay = hours * wageRate;
  cout << "Pay to the order of " << name << endl;
  cout << "The sum of " << netPay << " Dollars$\n";
  cout << "Check Stub: Not NEGOTIABLE\n";
  cout << "HourlyEmployee: " << ssn << endl;
  cout << "HourlyEmployee.hours worked: " << hours << endl;
  cout << "Rate: " << wageRate << " Pay: " << netPay << endl;
}
```

In the derived class HourlyEmployee, the inherited member variables name, netPay, and ssn can be accessed by name provided they are marked protected (as opposed to private) in the base class Employee. In any class that is not derived from the base class, these member variables are treated as if they are marked private.

Member variables that are protected in the base class act as though they are also protected in any derived class. For example, suppose you define a class PartTimeHourlyEmployee of the class HourlyEmployee. The class PartTimeHourlyEmployee inherits all the member variables of the class HourlyEmployee, including the member variables that HourlyEmployee inherits from the class Employee. The class PartTimeHourlyEmployee will have the member variables netPay, name, and ssn. If these member variables are protected in the class Employee, then they can be used by name in functions of the class PartTimeHourlyEmployee.

Except for derived classes (and derived of derived classes, etc.), a member variable that is protected is treated as if it were marked private. We include this discussion of protected member variables primarily because you will see them used and be familiar with them. Many, but not all, programming authorities say it is bad style to use protected member variables because so compromises the principle of hiding the class implementation. That is all member variables should be marked private, the inherited member variables cannot be accessed by name in derived class function
