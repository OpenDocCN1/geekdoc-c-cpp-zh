When an object is returned, for example, (m1 + m2), where m1 and m2 may be used to invoke a member function, which may or not change the value of the member variables in the object (m1 + m2). For example,

```
(m1 + m2).output();
```

is perfectly legal. In this case, it does not change the type returned by the object (m1 + m2). However, if we omitted the const before the type returned by the plus operator, then the following would be legal and would change the values of the member variables of the object (m1 + m2):

```
(m1 + m2).input();
```

So, objects can be changed, even when they are not associated with any variable. One way to make this is to note that objects have member variables and thus have some kinds of variables that can be changed.

Now let us assume that everything is as in Display 8.1; that is, there is a const before the return type of each operator that returns an object of type Money. For example, here is the declaration of the overloaded plus operator as it appears in Display 8.1:

```
const Money operator+(const Money& amount1, const& amount2);
```

The first const on the line is new use of the const modifier. This is called returning a value as const or returning by const value or returning by constant value. What the const modifier means in this case is that the returned object cannot be changed. For example, consider the following code:

```
Money m1(10.99), m2(23.57);
(m1 + m2).output();
```

The invocation of output is perfectly legal because it does not change the object (m1 + m2). However, with const before the return type, the following will produce a compiler error message:

```
(m1 + m2).input();
```

Why you want to change by const value? It provides a kind of automatic error checking. When you construct (m1 + m2), you normally do not to inadvertently change it. In this case changing the object (m1 + m2) probably does not matter, but if the returned object is a reference to an existing object then this can cause problems. References are covered in Section 8.3.


and you well may want to change m3. No problem—the following is perfectly legal:

```
m3 = (m1 + m2);
```

# Basic Operator Overloading

The values of m3 and (m1 + m2) are two different objects. The assignment operator does not make m3 the same as the (m1 + m2). Instead, it copies the values of the member variables of (m1 + m2) into the member variables of m3. With objects of a class, the default assignment operator does not make the two objects same object, it only copies values of member variables from one object to another.

This distinction is subtle but important. It may help you understand the details if you recall that a variable of a class and an object of a class type are not the same thing. An object is a value of a class type and may be stored in a variable of a class type, but the variable and the object are not the same thing. In the code

```
m3 = (m1 + m2);
```

the variable m3 and its value (m1 + m2) are different things, just as n and 5 are different things in

```
int n = 5;
```

or in

```
int n = (2 + 3);
```

It may take a while to become comfortable with this notion of return by const value. In the meantime, a general rule of thumb is to always return by const value unless you have an explicit reason to do so. For most simple programs this will have no effect on your program than to flag such subtle errors.

Note that although it is legal, it is pointless to return base types, such as int, or const value. The const has no effect in basic cases. When a function or returns a value of one of the basic types, such as int, double, or char, it returns the value, such as 5, 5.5, or 'A'. It does not return a variable or anything like a variable. Unlike unlike, the value cannot be changed—you cannot change 5. Values of a basic type cannot be changed whether there is a const before the return type or not. On the other hand, values of a class type—that is, objects—can be changed, since they have member variables, and so the const modifier has an effect on the object returned.

# Overloading Unary Operators

In addition to the binary operators, as x + +, C++ has unary operators, such as -. A unary operator is an operator that takes only one operand. For example, in the statement

```
-x;
```

The increment and decrement operators, ++ and --, are other examples of unary operators. In this chapter we will discuss ++ and -- more fully and explain their use in prefix and postfix position.

# Overloading as Member Functions

In Display 8.1 we overloaded operators as standalone functions. It is also possible to overload an operator as member function. This is illustrated in Display 8.2. Note that when + is overloaded as a member, there is only one parameter. The calling object serves as the first parameter. For example, consider the following code:

```
cost(1, 50), tax(0, 15), total;
total = cost + tax;
```

In the expression cost + tax the cost is the calling object and tax is the single argument.
