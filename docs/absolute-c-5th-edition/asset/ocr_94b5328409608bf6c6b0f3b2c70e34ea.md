# Programmer-Defined Functions

function initializeScreen, defined next, simply sends a newline command to the screen:

```
void initializeScreen() {
  cout << endl;
}
```

If your program includes the call to this function as its first executable statement, then the output from the previously run program will be separated from the output for your program:

initializeScreen();

Be notice to even when there are no parameters to a function, you must still include the parentheses in the function declaration and a call to the function.

Placement of the function declaration (function prototype) and the function definition is the same for void functions as what we described for functions that return a value.

# return Statements in void Functions

Both void functions and functions that return a value can have return statements. In the case of a function that returns a value, the return statement specifies the value returned. In the case of void function, the return statement does not include any expression for a value returned. A return statement in a void function simply ends the call. Every function that returns a value must end by executing a return statement. However, a void function need not contain a return statement. If it does not contain a return statement, it will end after executing the code in the function body. It is as if there were an implicit return statement just before the final brace, }, at the end of the function body.

The fact that an implicit return statement before the final closing brace in a function body does not mean that you never need a return statement in a void function. For example, the function definition in Display 3.7 output instructions for dividing a given amount of cream among the people at a table. If there are no people on the table (that is, if number 0), then the return statement within the if statement terminates the function and calls division by zero. If number is not 0, then the function ends when the last statement is executed at the end of the function body.

# Preconditions and Postconditions

One good way to write a function declaration is to break it down into two kinds of information called the precondition and the postcondition. The precondition states are what should be true when the function is called. The function should not be used and cannot perform correctly unless the precondition holds. The postcondition describes the effect of the function call; that, the postcondition tells what will be true after the function is executed in a situation which the precondition holds. For a function that returns a value, the postcondition will describe the value returned by the function. For a function that changes the value of some argument variables, the postcondition will describe all the changes made to the arguments.
