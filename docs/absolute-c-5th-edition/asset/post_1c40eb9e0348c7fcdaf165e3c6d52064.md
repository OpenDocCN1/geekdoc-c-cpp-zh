Display 18.1 Handling a Special Case without Exception Handling

```cpp
#include <iostream>
using std::cin;
using std::cout;

int main() {
    int donuts, milk;
    double dpg;
    cout << "Enter number of donuts:\n";
    cin >> donuts;
    cout << "Enter number of glasses of milk:\n";
    cin >> milk;

    if (milk <= 0) {
        cout << donuts << " donuts, and No Milk!\n";
        cout << "Go buy some milk.\n";
    } else {
        dpg = donuts / static_cast<double>(milk);
        cout << donuts << " donuts.\n";
        cout << milk << " glasses of milk.\n";
        cout << "You have " << dpg << " donuts for each glass of milk.\n";
    }
    return 0;
}
```

## 18.2 Same Thing Using Exception Handling (part 1 of 2)

```cpp
#include <iostream>
using std::cin;
using std::cout;

int main ( ) {
    int donuts, milk;
    double dpg;

    try {
        cout << "Enter number of donuts:\n";
        cin >> donuts;
        cout << "Enter number of milk:\n";
        cin >> milk;

        if (milk <= 0) {
            throw donuts;
        }

        dpg = donuts / static_cast<double>(milk);
        cout << " donuts.\n";
        cout << "You have " << dpg << " donuts for each glass of milk.\n";
    } catch (int e) {
        cout << e << " donuts, and No Milk!\n";
        cout << "Go buy some milk.\n";
    }

    cout << "End of program.\n";
    return 0;
}
```

> This is just a toy example to learn C++ syntax. Do not take it as an example of good
typical use of exception handling.

Rather than the big if-else statement (highlighted in Display 18.1), this new program has the following smaller if statement (plus some simple nonbranching statements):

```cpp
if (milk <= 0)
    throw donuts;
```

This statement says that if there is no milk, then do something exceptional. Something exceptional is given after the word catch. The idea is that normal situation is handled by the code following the try, and exceptional situations are handled by the code following the catch. Thus, we have separate case from the exceptional. This example does not really use us too much, but in other situations it will prove to be very helpful. Let us look at the details.

The basic way of handling exceptions in C++ consists of the try-throw-catch threesome. A try block has the following syntax:

```cpp
try
{
    Some_Code
}
```

This try block contains the code for the basic algorithm that tells what to do when everything goes smoothly. It is called a try block because you are not 100% sure that all will go without a hitch, but you want to "give it a try."

# Exception Handling Basics

If something unusual does happen, the way to indicate this is to throw an exception. So the basic outline, when we add a throw, is as follows:

```cpp
try {
  Code_To_Try
  Possibly_Throw_An_Exception
  More_Code
}
```

The following is an example of a try block with a throw statement included (copied from Display 18.2):

```cpp
try {
  cout << "Enter number of donuts:\n";
  cin >> donuts;
  cout << "Enter number of glasses of milk:\n";
  cin >> milk;
  if (milk <= 0)
    throw donuts;
}

dpg = donuts / static_cast<double>(milk);
cout << donuts << " \n";
cout << milk << " glasses of milk.\n";
cout << "You have " << dpg << " \n";
cout << donuts << " for each glass of milk.\n";
```

The following statement throws the int value donuts:
`throw donuts;`

The value thrown (in this case, donuts) is called an exception; the execution of it is called throwing an exception. You can throw a value of any type. In this case, an int value is thrown.

### Throw Statement

`throw Expression_for_Value_to_Be_Thrown;`

When the throw statement is executed, the execution of the try block is stopped. If the try block is followed by a suitable catch block, then flow of control is transferred to the catch block. A throw statement is almost always embedded in a branching statement, such as an if statement. The value can be of any type.

EXAMPLE
```cpp
if (milk <= 0)
  throw donuts;
```

# CHAPTER 18 Exception Handling

When something is "thrown," something goes from one place to another place. In C++, what goes from one place to another is the value (as well as the value thrown). When an exception is thrown, the code in the surrounding block stops executing and another portion of code, as a catch block, begins execution. When an exception is thrown, it should be immediately handled by (caught by) catch block. In Display 18.2, the appropriate catch block immediately follows the try. We repeat the catch block in what follows:

```cpp
catch (int e) {
    cout << e << " donuts, and No Milk!\n";
    cout << "Go buy some milk.\n";
}
```

This catch block looks very much like a function definition that has a parameter of type int. It is not a definition, but in some ways a catch block is like a function. It is a separate piece of code that is executed when your program encounters (and executes) the following (within the preceding try block):

```cpp
throw some_int;
```

So, this throw statement is similar to a function call, but instead of calling a function, it calls the exception and executes the code in the catch block. A catch block is often referred to as an exception handler, which is a term that suggests a catch block has a function-like nature.

What is identifier e in the following line from a catch block?

```cpp
catch (int e)
```

Identifier e looks like a parameter and acts much like a parameter. In fact, the identifier, as e, in the catch block heading is called the catch-block parameter. Each catch block has at most one catch-block parameter. The catch-block parameter does two things:

1. The catch-block parameter is preceded by a type name that specifies what kind of thrown value the catch block can catch.
2. The catch-block parameter gives you a name for the value that is caught, so you can write code in the catch block that does with that value.

We will discuss these two functions of the catch-block parameter in reverse order. This subtitle discusses the catch-block parameter as a name for the value that was thrown. The current example has only one catch block. The common name for the catch-block parameter is e. Let us see how the catch block in 18.2 works. When a value is thrown, the value is plugged in for the catch-block parameter and the code in the catch block is executed.

# Exception Handling Basics

catch block applies only to an immediately preceding try block. Note that if no exception is thrown, the catch block is ignored. The reproduced here:

```cpp
catch (int e) {
    cout << e << " donuts, and No Milk!\n";
    cout << "Go buy some milk.\n";
}
```

When a value is thrown, the thrown value must be of type int in order for this catch block to apply. Suppose the value of donuts is 12 and the value of milk is 0, as in the second example in Display 18.2. Since the value of milk is not positive, the throw statement within the if statement is executed. This produces the following output:

| 12 donuts, and No Milk! |
| Go buy some milk. |

If the value of donuts is positive, the throw statement is not executed. In this case, the entire try block is executed. After the last statement in the try block is executed, the statement after the catch block is executed.

This discussion might sound like a try-catch setup is equivalent to an if-else statement. It is almost equivalent, except for the value thrown. A try-throw-catch setup is just like an if-else statement with the added ability to send a message to the branches.

To summarize in a more formal tone, a try block contains some code that we assuming a throw statement. The throw statement is normally executed in exceptional circumstances, but when it is executed, it throws a value of some type. When an exception (a value as donuts in Display 18.2) is thrown, the try block ends. All the rest of the code in the try block is ignored and control passes to a suitable catch block. For now, we will assume that every block is followed by an appropriate catch block. We will later discuss what happens when there is no appropriate catch block.
