C++ programming style is similar to that used in other languages. The goal is to make your code easy to read and modify. We will say a bit about indenting the next chapter. Choice of variable names and careful indenting should eliminate the need for very many comments, but any points that remain unclear deserve a comment.

# Comments

There are two ways to insert comments in a C++ program. In C++, two slashes, // are used to indicate the start of a comment. All the text between the // and the end of the line is the comment. The compiler simply ignores anything that // on a line. If you want a comment that covers more than one line, place a // on each line of the comment. The symbols // do not have a space between them.

Another way to insert comments in a C++ program is to use the symbols /* and /. Text between these symbols is considered a comment and is ignored by the compiler. Unlike the // comments, which require an additional // on each line, the /** can span several lines, so:

```
/*This is a comment that spans three lines. Note that there is no kind on the second line.*/
```

Comments of the /* type may be inserted anywhere in a program where a space or line break is allowed. However, they should not be inserted anywhere except they are easy to read and not distinct from the layout of the program. Usually, comments are placed at ends of lines or on separate lines by themselves.

Opinions differ regarding which kind of comment is best to use. Either variety (the // or /*) can be used with care. One approach is to use // in final code and reserve the /*-style comments for temporarily commenting out code while debugging.

It is difficult to say how many comments a program should contain. The only correct answer is "just enough," which courses little to the novice programmer It will take some experience to get a feel for when it is best to include a comment. Whenever something is important and not obvious, it merits a comment. However, too many comments are as bad as too few. A program that has a comment on each line will be buried in comments that the structure of the program is hidden in a sea of obvious obstructions. Comments like the following contribute nothing to understanding and not appear in a program:

```
distance = speed * time; //Computes the distance traveled.
```
