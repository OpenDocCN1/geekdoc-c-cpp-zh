All procedures start with the word **to** and end with the word **end**. A procedure like this adds a new word to MicroWorlds vocabulary. It uses **pd**, which puts the turtle’s “pen” down, **forward 50**, which moves the turtle 50 “steps” in the direction it is facing, and **right 90**, which turns the turtle by 90 degrees, or a right turn. Let’s try it out! Move over to the Graphics Page. Hatch a turtle and push **<Enter>** in the Command Center if you need to clear old messages. Then type square and press **<Enter>**.

Hmm, **square** didn't work very well. The problem is that the turtle went so fast, you couldn't see it.

It is very common that things don't work right the first time. It is not a failure, it just means we can tweak our procedure to make it better!

Before we solve the movement down, there is another problem with our **square** procedure. As it is now, it is not really readable. Let’s write the same long instruction over several lines, making it much more readable. We can do that on the Procedure Page. It's just not as easy as in the Command Center. MicroWorlds Logo ignores the fact that the instruction is spread over many lines. MicroWorlds Logo is really just interested in whether the inputs and outputs are all satisfied.
Change your procedure so it looks like this:

```
square
pd
forward 50 right 90
forward 50 right 90
forward 50 right 90
forward 50 right 90
end
```

There, that is much more readable and you can see at a glance how it works. Notice that our procedure **square** takes no inputs and has no output, so its puzzle piece looks like this:

It is a "satisfied" instruction all by itself.
Now back to improving our first procedure. To slow the movement of the turtle, let's add a built-in procedure, **wait**, after each turn the turtle makes. **Wait** takes one input, a number. Change your procedure so it looks like this:

```
square
pd
forward 50 right 90 wait 1
forward 50 right 90 wait 1
forward 50 right 90 wait 1
forward 50 right 90 wait 1
end
```
