## 如何阅读此书？

这本书是我尝试在让你编写应用程序的同时教你 React。它是一本学习 React 的实用指南，而不是一本关于 React 的参考工具书。你将编写一个与真实 API 交互的 Hacker News 应用程序。在几个有趣的话中，它涵盖了 React 中的状态管理、缓存和交互（排序和搜索）。在此过程中，你将学习 React 中的最佳实践和模式。

此外，这本书帮助你完成从 JavaScript ES5 到 JavaScript ES6 的过渡。React 吸收了许多 JavaScript ES6 特性，我希望这能帮到你。（此处注：由于提供的原始文本存在大量 OCR 重复和跳跃，翻译已基于核心逻辑进行清理）。

# Node 和 npm

这一章将为你提供关于 node 和 npm 的简短课程。它并不是详尽的，但你将获得所有必要的工具。如果你熟悉熟悉两者，可以跳过这一章。

node 包管理器 (npm) 允许你从命令行安装外部 node 包。这些包可以是一组实用函数、库或整个框架。它们是你应用程序的依赖。你可以将这些包安装到全局 node 包文件夹中，或者你的本地项目文件夹中。

全局 node 包可以在终端的任何地方访问，你只需要在全局目录中安装一次。你可以通过在终端输入以下命令安装全局包：

## 命令行

```
npm install -g <package>
```

-g 标志告诉 npm 全局安装包。本地包用于你的应用程序。例如，React 作为一个库是一个本地包，可以在应用程序中引入它进行使用。你可以通过终端输入以下命令进行安装：

## 命令行

```
npm install <package>
```

在 React 的情况下，命令应该是：

## 命令行

```
npm install react
```

安装的包将自动出现在名为 `node_modules/` 的文件夹中，并列在 `package.json` 文件的依赖旁边。

但是最初如何为项目初始化 `node_modules/` 文件夹和 `package.json` 文件呢？有一个 npm 命令可以初始化 npm 项目并生成 `package.json` 文件。只有当你有了该文件，才能通过 npm 安装新的本地包。

## 命令行

```
npm init -y
```

## React 简介

-y 标志是初始化 `package.json` 中所有默认值的快捷方式。如果不使用该标志，你必须决定配置该文件。初始化 npm 项目后，你可以通过 `npm install <package>` 安装新包了。

关于 `package.json` 再说一点。该文件允许你与其他开发者共享你的项目，而无需共享所有的包。该文件包含了项目中使用的所有 node 包的引用。这些包被称为依赖。每个人都可以在没有依赖的情况下拷贝你的项目。依赖是 `package.json` 中的引用。拷贝你项目的人只需在命令行上使用 `npm install` 即可安装所有包。`npm install` 脚本会获取 `package.json` 文件中列出的所有依赖，并将它们安装到 `node_modules/` 文件夹中。

## 命令行

```
npm install --save-dev <package>
```

--save-dev 标志表示该 node 包仅在开发环境中使用。当你将应用程序部署到服务器上时，它不会出现在生产环境中。那可能是种什么样的 node 包呢？想象你想通过一个 node 包的帮助来测试你的应用程序。你需要通过 npm 安装它，但想将其排除在生产环境之外。测试应该在开发过程中进行，而不应该在你的应用程序已经在生产环境中运行时进行。你不再需要测试你的应用程序了。它应该已经过过测试并且对你的用户开箱即用。这就是你想要使用 --save-dev 标志的唯一用例。

这是文件夹和文件的简要介绍。在开始阶段，你不理解它们也没关系。

- *README.md*: `.md` 扩展名表示该文件是一个 markdown 文件。Markdown 被用作带有纯文本格式语法的轻量级标记语言。当源码项目带有 README.md 文件时，它会向你提供关于项目的初始说明。当你最终将项目推送到 GitHub 等平台时，访问仓库时，README.md 文件会正常显示其内容。由于你使用了 `create-react-app`，你的 README.md 将与官方 create-react-app GitHub 仓库中显示的内容相同。$^{49}$
- *node_modules/:: 该文件夹包含所有通过 npm 安装的包。由于你使用了 `create-react-app`，应该已经为你安装了几个 node模块。通常你永远不会碰这个文件夹，只会通过命令行安装和卸载 node 包。
- *package.json*: 该文件显示了 node 包依赖项的列表以及项目配置。
- *.gitignore*: 该文件指定了在使用时哪些文件和文件夹不应该被添加到你的远程仓库中。它们应该只存在于你的本地项目中。`node_modules/` 文件夹就是其中之一。只需与同事共享 `package.json` 文件即可，让他们能够自行安装所有依赖项，而无需共享整个依赖文件夹。

> $^{49}$https://github.com/facebookincubator/create-react-app

- *public/*: 文件夹存放了你为生产环境构建项目时所有的文件。最终，当你构建项目时，在 `src/` 文件夹中编写的所有代码都将被打包成几个文件并放在 public 文件夹中。
- *manifest.json* 和 *registerServiceWorker.js*: 在此阶段不用担心这些文件的作用，我们在这个项目中不需要它们。

归根，你不需要碰上述的文件和文件夹。在开始阶段，你需要的一切都位于 `src/App.js` 文件中，用于实现 React 组件。它将用于实现你的应用程序，但你可能希望将组件拆分为多个文件，每个文件独立维护一个或几个组件。

此外，你还会发现一个用于测试的 `src/App.test.js` 以及作为通往 React 世界入口的 `src/index.js`。你将在稍后的章节中了解这两个文件。此外，还有一个 `src/index.css` 文件用于为你的通用应用程序和组件设置样式。打开它们时，它们都带有默认样式。

## JSX 简介

现在你将了解 JSX。它是 React 中的语法。如前所提到的，`create-react-app` 已经为你初始化了一个样板应用程序。所有文件都有默认实现。让我们深入源码。你开始时唯一会碰的文件将是 `src/App.js` 文件。

```javascript
src/App.js
import React, { Component } from 'react';
import logo from './logo.svg';
import './App.css';

class App extends Component {
  render() {
    <div className="App">
      <header className="App-header">
        <img src={logo} className="App-logo" alt="logo" />
        <h1 className="App-title">Welcome to React</h1>
      </header>
      <p className="App-intro">
        要开始的话，请编辑 <code>src/App.js</code> 并保存以重载。
      </p>
    </div>
  }
}

## 热模块替换 (Hot Module Replacement)

你可以在 src/index.js 文件中做一件事来提升你作为开发体验。但它是可选的，在刚学习 React 时不应该让你感到无所措。

在 create-react-app 中，当你更改源代码时，浏览器会自动刷新页面，这是一个优势。尝试更改 src/App.js 文件中的 `helloWorld` 变量。浏览器应该会刷新页面。但有一种更好的方法。

热模块替换 (HMR) 是一种在浏览器中重新加载应用程序的工具。浏览器不会执行页面刷新。在 create-react-app 中，在你的 src/index.js（进入 React 的入口点）中，你需要添加一个小小的配置。

src/index.js

```javascript
import React from 'react';
import ReactDOM from 'react-dom';
import App from './App';
import './index.css';

ReactDOM.render(
  <App />,
  document.getElementById('root')
);

if (module.hot) {
  module.hot.accept();
}
```

就是这样。再次更改 src/App.js 文件中的 `helloWorld` 变量。浏览器不应该执行页面刷新，但应用程序会重新加载并显示正确的输出。HMR 有许多优势：

想象你正在使用 `console.log()` 语句进行调试。即使你更改了代码，这些语句也会保留在你的开发者控制台中，因为浏览器不再刷新页面。这对于调试目的非常方便。

在一个不断增长的应用程序中，页面刷新会降低你的效率。你需要等待页面加载。页面重新加载可能需要几秒钟。

## ES6 解构

JavaScript ES6 有一种方法可以更方便地访问对象和数组中的属性。这被称为解构。对比以下 JavaScript ES5 和 ES6 的代码片段。

## 代码沙场

```javascript
const user = {
  firstname: 'Robin',

## 受控组件

你已经学习了 React 中的单向数据流。同样的规则也适用于输入框，它通过 `searchTerm` 更新本地状态以过滤列表。当状态改变时，`render()` 方法会再次运行，并使用本地状态中最新的 `searchTerm` 应用过滤条件。

但我们没有在输入元素中漏掉什么吗？HTML `input` 标签带有一个 `value` 属性。该属性通常具有显示在输入框中的值。在这种情况下，它应该是 `searchTerm` 属性。然而，似乎在 React 中我们不需要它。

你应该如何做呢？你只需要设置输入框的 `value` 属性即可。

## 生命周期方法

在开始在组件中使用 API 获取数据之前，你需要了解 React 的生命周期方法。这些方法是进入 React 组件生命周期的钩子（hook）。它们可以用于 ES6 类组件，但不能用于函数式无状态组件。

你还记得之前某一个章节教过你 JavaScript ES6 类以及它们在 React 中是如何用法的吗？除了 `render()` 方法外，还有几个方法在 React ES6 类组件中可以被重写。所有这些都是生命周期方法。让我们深入研究它们：

你已经知道两个可以在 ES6 类中使用的生命周期方法：`constructor()` 和 `render()`。

`constructor` 只有在组件实例创建并插入 DOM 时才会被调用。此时组件被实例化。这个过程被称为组件的挂载（mounting）。

`render()` 方法在挂载过程中会被调用，当组件更新时也会被调用。每当组件的状态（state）或属性（props）发生变化时，组件的 render() 方法就会被调用。

现在你对这两个生命周期方法以及它们的调用时机有了更多的了解。你已经熟悉它们了。但还有更多。

组件的挂载有两个生命周期方法：`componentWillMount()` 和 `componentDidMount()`。`constructor` 先被调用，`componentWillMount()` 在 `render()` 方法之前调用，而 `componentDidMount()` 在 `render()` 方法之后调用。

总来说，挂载过程有 4 个生命周期方法。它们按照以下顺序触发：

- `constructor()`
- `componentWillMount()`
- `render()`
- `componentDidMount()`

当状态或属性变化时，组件的更新生命周期又是怎样的？总来说，它有 5 个生命周期方法，顺序如下：

- `componentWillReceiveProps()`
- `shouldComponentUpdate()`
- `componentWillUpdate()`
- `render()`
- `componentDidUpdate()`

## 实战 API 调用

最后但同样重要的是还有卸载（unmounting）生命周期。它只有一个生命周期方法：`componentWillUnmount()`。

毕竟，你不需要从一开始就知道所有的生命周期方法。这看起来可能望人生畏，但你并不会使用所有的它们。即使在 React 应用中，在使用 `constructor()` 和 `render()` 方法之后，你也只会使用其中的几个。尽管如此，了解每个生命周期方法可以用于特定情况是很有用的：

- `constructor(props)` - 在组件初始化时调用。你可以在该生命周期方法中设置初始组件状态并绑定类方法。
- `componentWillMount()` - 在 `render()` 生命周期周期方法之前调用。这就是为什么它可以被用于设置内部组件状态，因为它不会触发组件的第二次渲染。通常建议使用 `constructor()` 设置初始状态。
- `render()` - 该生命周期是强制性的，并返回元素作为组件的输出。该方法应该是纯净的，因此不应该修改组件状态。它接收 props 作为输入并返回一个元素。
- `componentDidMount()` - 仅在组件挂载后调用。这是执行异步请求以从 API 获取数据的完美时机。获取的数据将存储在组件内部状态中，以便在 `render()` 生命周期方法中显示。
- `componentWillReceiveProps(nextProps)` - 该生命周期方法在更新生命周期期间调用。你作为输入接收 next props。你可以通过这些 props 将 next props 与之前的 props 进行对比（diff），并根据差异应用不同的行为。此外，你可以根据 next props 设置状态。
- `shouldComponentUpdate(nextProps, nextState)` - 当组件由于状态或变化而更新时，该方法总是会被调用。你将在 React 应用中用它进行性能优化。取决于该生命周期方法返回的布尔值，组件及其所有子组件将在更新生命周期中渲染或不渲染。你可以阻止组件的 render 方法。
- `componentWillUpdate(nextProps, nextState)` - 该生命周期方法在 `render()` 方法之前立即调用。你可以自由使用 next props 和状态。你可以将该方法作为在 render 方法执行之前进行准备工作的最后机会。请注意，你不能再触发 `setState()`。如果你想从 next props 计算状态，你必须使用 `componentWillReceiveProps()`。
- `componentDidUpdate(prevProps, prevState)` - 该生命周期方法在 `render()` 方法之后立即调用。你可以利用它作为执行 DOM 操作或执行进一步异步请求的机会。
- `componentWillUnmount()` - 在销毁组件之前调用。你可以使用该生命周期方法执行任何清理任务。

`constructor()` 和 `render()` 生命周期方法已经被你使用了。这些是 ES6 类组件中常用的生命周期方法。实际上，`render()` 方法是必须的，否则你将不会返回一个组件实例。

## 实战 API 调用

还有一个生命周期：`componentDidCatch(error, info)`。它是在 React 16 中引入的，用于捕获组件中的错误。例如，在应用程序中显示列表运行良好。但可能会出现一种情况：本地状态被意外设置为 null（例如，当从外部 API 获取列表时，请求失败且你将本地状态设置为 null）。之后，将无法再次对列表进行过滤和映射（map），将会失败，因为它是 null 而不是空列表。组件将会崩溃，整个应用程序也将失败。现在，通过使用 `componentDidCatch()`，你可以捕获错误，将其存储在本地状态中，并向应用程序用户显示一条已发生错误的可选消息。

## 条件渲染

条件渲染在 React 应用中很早就引入了。但在本书中还没有引入，因为没有这样的这样的用例。当你想要决定渲染一个元素还是另一个元素时，就会发生条件渲染。有时这意味着渲染一个元素或什么都不渲染。毕竟，简单的条件渲染可以用 JSX 中的 `if-else` 语句来表示。

内部组件状态中的结果对象初始为 `null`。到目前为止，当结果从 API 返回之前，App 组件没有返回任何元素。这已经是一种条件渲染了，因为你根据特定条件提前从 `render()` 生命周期方法中返回。App 组件要么不渲染任何内容，要么渲染它的元素。

但让我们更进一步。将 `Table` 组件（它是唯一依赖结果的组件）封装在一个独立的条件渲染中是有意义的。其他所有内容都应该显示，即使目前还没有结果。你可以在这里中使用三元运算符：

```javascript
src/App.js
class App extends Component {
  ...
  render() {
    const { searchTerm, result } = this.state;
    return (
      <div className="page">
        <div className="interactions">
          <Search
            value={searchTerm}
            onChange={this.onSearchChange}
          </Search>
        </div>
        { result
        ? <Table
            list={result.hits}
            pattern={searchTerm}
            onDismiss={this.onDismiss}
          />
        : null
        }
      )
    );
  }
}
```

这是你表达条件渲染的第二种方案。第三种方案是逻辑 `&&` 运算符。在 JavaScript 中，`true && 'Hello World'` 始终求值为为 `'Hello World'`。`false && 'Hello World'` 始终求值为为 `false`。

# 代码游场

```javascript

console.log(result);
// output: Hello World
```

```javascript
const result = false && 'Hello World';
console.log(result);
// output: false
```

在 React 中你可以使用这种行为。如果条件为 `true`，`&&` 之后的表达式将被输出。如果条件为 `false`，React 会跳过该表达式。这适用于条件渲染的情况，因为它应该返回 `Table` 或什么都不渲染。

### src/App.js

```javascript

<Table
list={result.hits}
pattern={searchTerm}

/>
```

这些都是在 React 中使用条件渲染的几种方法。你可以阅读更多关于条件渲染方法的示例¹，以及何时应用它们。

毕竟，你应该能够在数据获取挂起时在应用程序中看到获取的数据。一旦请求解析并将其存储到本地状态中，`Table` 就会显示，`render()` 方法再次运行，以便于显示 `Table` 组件。

## ES6 模块：导入与导出

在 JavaScript ES6 中，你可以从模块中导入和导出功能。这些功能可以是函数、类、组件、常量等。基本上是你赋值给变量的任何内容。模块可以是单个文件，也可以是以一个 `index` 文件作为入口的文件夹。

在书的开头，当你用 `create-react-app` 引导应用程序后，你的初始文件中已经有几个 `import` 和 `export` 语句。这曾是一团糟，因为你希望找到一种标准化的方法，而不是对同一件事采用多种方法。现在是解释这些内容的时机了。

`import` 和 `export` 语句帮助你在多个文件之间共享代码。在此之前，JavaScript 环境中已经有几种解决方案。这曾是一团糟，因为你希望找到一种标准化的方法，而不是对同一件事采用多种方法。现在自 JavaScript ES6 以来，这已成为原生行为。

此外，这些语句支持代码拆分。你将代码分布在多个文件中，以保持其可重用和可维护性。前者是正确的，你可以在多个文件中导入该段代码；后者也是正确的，因为你有一个单一的源来维护这段代码。

最后，它帮助你思考代码的封装。每个功能都需要从文件中导出。其中某些功能应该只在定义它们的文件中使用。文件的导出内容基本上是该文件的公共 API。只有被导出的功能才能在其他地方被重用。这遵循了封装的最佳实践。

但让我们回到实际操作。这些 `import` 和 `export` 语句是如何工作的？接下来的示例通过在两个文件之间共享一个或多个变量来展示这些语句。最后，这种方法可以扩展到多个文件并共享比简单变量更多的内容。

你可以导出一个或多个变量。这被称为命名导出（named export）。

## 使用 Jest 进行快照测试

本书不会深入探讨测试主题，但它是不可忽视的。在编程中测试你的代码是关重要的，并被认为是强制性的。也许你听过测试金字塔。它包括端到端测试、集成测试和单元测试。如果你不熟悉这些，书籍将为你提供一个快速的概览。单元（Unit）用于测试一个孤立且较小的代码块。它可以是一个被单元测试测试的单个函数。然而，有时单元在孤立状态下运行良好，但与其他单元结合时无法正常工作。它们可能需要作为一个整体进行测试。这就是集成测试可以提供帮助的地方，它可以覆盖单元之间是否协同工作。此外，端到端测试是对真实用户场景的模拟。它在浏览器中自动执行。虽然单元测试快速且易编写和维护，但端到端测试则相反。每种类型需要多少测试？你需要许多单元测试来覆盖你的函数。之后，你可能需要几个集成测试来覆盖最重要的函数组合。最后，你可能只需要少量的端到端测试来模拟应用程序中的关键场景。

基本上`renderer.create()` 函数创建了你的 App 组件的快照。它进行虚拟渲染并将 DOM 存储在快照中。之后，当你最后一次运行快照时，该快照预计与之前的快照匹配。通过这样，你可以确保你的 DOM 保持不变，不会意外更改任何内容。

## 高阶组件 (Higher-Order Components)

高阶组件（HOC）是 React 中的一个高级概念。HOC 等同于高阶函数。它们接受任何输入——大多数情况下是组件，但也可能是可选参数——并返回一个组件作为输出。返回的组件是输入组件的增强版本，可以在你的 JSX 中使用。

HOC 用于不同的用例。它们可以准备属性、管理状态或更改组件的表示形式。一个用例是将 HOC 用作条件渲染的辅助工具。假设你有一个 `List` 组件，它可以渲染项目列表或者什么都不渲染（因为列表为空或为 null）。另一方面，普通的 `List` 组件不再需要担心不存在的列表了。它只关心渲染列表。

让我们在 `src/App.js` 中实现一个接收组件作为输入并返回组件的函数。你可以将其放在 `src/App.js` 文件中。

```javascript
src/App.js
function withFoo(Component) {
  return function(props) {
    return <Component {...props} />;
  }
}
```

```javascript
src/App.js
const withFoo = (Component) => (props) =>
  <Component {...props} />
```

一个整洁的约定是用 `with` 前缀对 HOC 命名。由于你正在使用 ES6，可以使用箭头函数更简洁地表示 HOC。在示例中，输入组件与输出组件保持相同。什么都没有发生。它渲染相同的内容，并将所有 props 传递给输出组件。但这没有用处。让我们增强输出组件。当加载状态为 `true` 时，输出组件应该显示 `Loading` 组件，否则它应该显示输入组件。条件渲染是 HOC 的一个极佳用例。

```javascript
src/App.js
const withLoading = (Component) => (props) =>
  props.isLoading
    ? <Loading />
    : <Component {...props} />
```

通常情况下，将像上示例中的 props 对象展开并作为组件的输入是非常高效的。看下面的代码片段。

```javascript
// 之前你必须在传递之前对 props 进行解构
const { foo, bar } = props;
<SomeComponent foo={foo} bar={bar} />

// 但你可以使用对象展开来传递所有属性
<SomeComponent {...props} />
```

有一点你应该避免：通过展开对象将包括 `isLoading` 属性在内的所有 props 传递给输入组件。然而，输入组件可能不在 `isLoading` 属性。你可以使用 ES6 剩余解构来避免这一点。

```javascript
src/App.js
const withLoading = (Component) => ({ isLoading, ...rest }) =>
  isLoading
    ? <Loading />
    : <Component {...rest} />
```

它获取了对象中的一个属性，但剩余的对象也同样有效。你可能已经读过关于解构赋值[^2](https://developer.mozilla.org/en-US/docs/JavaScript/Reference/Destructuring_assignment) 了。

## 重温：setState()

到目前为止，你一直在使用 `setState()` 来管理组件的内部状态。你可以向函数传递一个对象，并在其中部分更新内部状态。

代码沙练场

```javascript
this.setState({ foo: bar });
```

但 `setState()` 不仅仅接受一个对象。在它的第二个版本中，你可以传递一个函数来更新状态。

代码沙练场

```javascript
this.setState((prevState, props) => {
  ..
});
```

你为什么想要这样做呢？有一个关键情况，使用函数比使用对象更有意义。那就是当你根据之前的状态或 props 更新状态时。如果你不使用函数，内部状态管理可能会导致 bug。

但是，当更新依赖于之前的状态或 props 时，使用对象而不是函数会导致 bug 吗？React 的 `setState()` 方法是异步的。React 会批处理 `setState()` 调用并最终执行它们。可能会出现这种情况：在你赖的 `setState()` 调用中依赖的值之间，之前的状态或 props 发生了变化。

代码沙练场

```javascript
const { fooCount } = this.state;
const { barCount } = this.props;
this.setState({ count: fooCount + barCount });
```

想象一下在你调用 `setState()` 时，`fooCount` 和 `barCount`（状态或 props）在其他地方异步发生了变化。在一个不断增长的应用程序中，你的应用程序会有多个 `setState()` 调用。由于 `setState()` 是异步执行的，你可能会依赖于这个关于过时值的示例。

使用函数的方法，`setState()` 中的函数是一个回调，它在执行回调函数时对状态和 props 进行操作。即使 `setState()` 是异步的，但通过函数，它获取的是执行执行时的状态和 props。

## 代码沙练场

```javascript
this.setState((prevState, props) => {
  const { fooCount } = prevState;
  const { barCount } = props;
  return { count: fooCount + barCount };
});
```

现在，让我们回到你的代码来修复这种行为。我们将共同修复一个 `setState()` 使用并依赖状态或 props 的地方。之后，你也能修复其他地方。

}
```

这将修复过时状态的问题。还有一个改进。由于它是函数，你可以提取该函数以提高可读性。这是使用函数而不是对象的另一个优势。函数可以位于组件外部。但毕竟，你想根据从 API 获取的结果来更新状态。

```javascript
src/App.js
setSearchTopStories(result) {
  const { hits, page } = result;
  this.setState(updateSearchStoriesState(hits, page));
}
```

`updateSearchStories()` 函数必须返回一个函数。它是一个高阶函数。可以将此高阶函数定义在 App 组件之外。注意函数签名现在发生了细微变化。

```javascript
src/App.js
const updateSearchStoriesState = (hits, page) => (prevState) => {
  const { searchKey, results } = prevState;

  const oldHits = results && results[searchKey]
    ? results[searchKey].hits
    : [];

  const updatedHits = [
    ...oldHits,
    ...hits
  ];

  return {
    ...results,
    [searchKey]: { hits: updatedHits, page }
  },
    isLoading: false
  };
};

class App extends Component {
....
};
```

就是这样。`setState()` 中函数优对象的方法解决了潜在的 bug，同时增加了代码的可读性和可维护性。此外，你可以将其导出并作为练习编写测试。

## 驯服状态

之前的章节向你展示了，状态管理在大型应用中是一个至关重要的课题。通常情况下，不仅是 React，许多 SPA 框架都为此苦恼。近年来，应用程序变得越来越复杂。如今 Web 应用程序的一个大挑战就是驯服并控制状态。

与其他解决方案相比，React 已经迈出了巨大一步。单向数据流和用于管理状态的简单 API 是不可或缺的。这些概念让你更容易推导出你的状态以及状态的变化。它让你在组件层面、在某种程度上在应用层面，更容易进行推理。

在一个不断增长的应用程序中，推理状态的变化变得越来越困难。在 `setState()` 中使用对象而非函数来操作状态时可能会引入 Bug。你必须通过提升状态（lift state）来在组件之间共享或隐藏状态。可能会某个组件需要向上移动，因为它的兄弟组件依赖它。也许该组件在组件树中离得很远，你必须跨越整个组件树共享状态。总之，组件参与状态管理的程度越来越大。但根结底，组件的主要职责应该是表示 UI，不是吗？

正因为所有这些原因，存在独立的解决方案来处理状态管理。这些解决方案不仅用于 React。然而，这让 React 生态变成了一个强大的地方。你可以使用不同的解决方案来解决你的问题。为了解决状态管理扩展的问题，你可能听过库 Redux¹ 或 MobX²。你可以在 React 应用中使用这些解决方案之一。通过扩展 react-redux³ 和 mobx-react⁴，你可以将它们集成到 React 视图层中。

Redux 和 MobX 不在本书的范围内。当你读完这本书后，你将获得关于如何继续学习 React 及其生态系统的指导。一条学习路径可以是学习 React。在深入研究外部状态管理主题之前，我建议阅读这篇文章⁶。它旨在让你更好地理解如何学习外部状态管理。

## Eject (弹出)

下一步由你决定。尽管如此，create-react-app 带有一个功能，以保持其可扩展性并防止供应商锁定（vendor lock-in）。供应商锁定通常发生在你投入某项技术但未来没有逃生口时。幸运的是，在 create-react-app 中，你有这样一个名为 "eject" 的逃生口。

在你的 package.json 中，你会找到启动、测试和构建应用程序的脚本。最后一个脚本是 eject。你可以尝试它，但没有路可以回了。这是一个单向操作。一旦你执行了 eject，就无法回去了！如果你刚刚开始学习 React，离开 create-react-app 方便的环境是没有意义的。

如果你运行 `npm run eject`，该命令会将所有配置和依赖复制到你的 package.json 和一个新的 config 文件夹中。你会将整个项目转换为带有包含 Babel 和 Webpack 等工具链的自定义设置。毕竟，你将对所有这些工具拥有完全控制权。

官方文档说，create-react-app 适用于小型到中项目。你不应该觉得有义务使用 "eject" 命令。
