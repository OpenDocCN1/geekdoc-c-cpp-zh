These classes share two important properties: Exception and ExceptionHandled. The first contains the actual exception that occurred or Nothing (in VB.NET) or null (in C#) when everything goes according to plan and no error occurs. You can examine this error and take appropriate action. For example, you can inform the user that something went terribly wrong, or you can send an e-mail to the site's webmaster informing her about the error so appropriate follow-up action can be taken.

If you decide to handle the error in the event handler of the data source control, you should set the ExceptionHandled property of the object to True. This signals to the ASP.NET run time that you are aware of the exception and have dealt with it adequately. If you omit setting this property, the run time forwards the exception, which is eventually displayed to the user.
