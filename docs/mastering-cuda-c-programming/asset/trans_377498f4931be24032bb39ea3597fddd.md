

块的形状（每个维度上的线程数）：块可以是一维的，CUDA 同时也支持二维和三维块。这种能力在处理多维数据结构时特别有用。

内存用量：每个块的共享内存（shared memory）是有限的，因此优化该内存的使用以及每个块的线程数对于获得良好的性能至关重要。

有效利用 CUDA 的线程层次结构和块维度是充分发挥 GPU 并行计算能力的关键。通过精心设计具有优化块和线程配置的内核（kernels），开发者可以显著提升各种范围应用程序的计算性能。

## 5.4

## 内核执行配置与参数

CUDA 内核的执行通过指定执行配置和参数进行精细控制。这种级别的控制对于调整 CUDA 应用以高效利用 GPU 提供的并行性是基础。在本节中，我们将深入探讨决定内核启动的元素，包括网格（grid）和块（block）维度，以及向内核传递参数。

### 定义执行配置

CUDA 内核的执行配置指定了启动多少线程，以及这些线程如何组织成块和网格。这至关重要，因为 CUDA 程序的性能很大程度上取决于计算映射到 GPU 架构的优劣。

执行配置在内核调用期间使用三尖括号语法（`>>>`）指定，如下：

```
block_size>>>(parameter1, parameter2, ...);
```

在这里，`grid_size` 和 `block_size` 的类型分别指定了网格和块的维度。这些配置都起着特定的作用：

- 网格（Grid）：决定并行执行的块的数量。网格可以是一、二或三维的，允许对问题空间进行灵活划分。
- 块（Block）：规定每个块内线程的数量。类似于网格大小，块也可以是多维的。选择正确的块大小对于实现最优性能至关重要，因为它影响占用率（occupancy），即 GPU 资源的利用率。

### 向内核传递参数

CUDA 内像普通 C 函数一样接受参数。这些参数可以包括标量、指针和用户定义的结构。在向内核传递参数时，确保内存地址从 GPU 可访问是非常重要的。例如，传递给内核的指针必须指向分配在 GPU 上的内存（使用或对托管内存（使用

以下是一个向 CUDA 内核传递参数的示例：

```
__global__ void add(int *a, int *b, int *result, int N) { 
    int index = threadIdx.x + blockIdx.x * blockDim.x; 
    if (index < N) { 
        result[index] = a[index] + b[index]; 
    } 
}
int main() { 
    int *a, *b, *result, N = 1024; 
    // 分配并初始化内存 
    // 在 GPU 上分配和初始化 'a', 'b' 和 'result' 数组的代码 
    // 启动内核
    add<<((N+255)/256), 256>>>(a, b, result, N); 
    // 拷贝回并处理结果的代码 
}
```

在此示例中，`add` 内核逐元素相加两个向量。启动内核时的网格大小足以处理 N 个元素，每个块有 256 个线程，确保每个元素都由单个线程处理。

### 同步内核执行

CUDA 内核是异步启动的，这意味着 CPU 在继续执行下一行代码之前不需要等待内核完成。为了确保内核在访问结果之前完成执行，可以使用 `cudaDeviceSynchronize()` 函数。该函数会阻塞调用的 CPU 线程，直到 GPU 完成所有之前的任务（包括内核执行）。

```cpp
// 启动内核
add<<((N+255)/256), 256>>>(a, b, result, N); 
// 同步
cudaDeviceSynchronize();
// 现在，'result' 可以供 CPU 使用了。
```

理解并正确配置内核执行是充分利用 GPU 全计算能力的关键。这不仅涉及选择合适的网格和块大小，还涉及有效管理内存和同步以确保数据完整性和性能优化。通过这种对内核执行配置和参数传递的整体方法，CUDA 程序员可以构建出既高效又可扩展的解决方案。

## 5.5

## 内核中的内存访问模式

理解 CUDA 内核中的内存访问模式是优化 GPU 加速应用性能的基石。支持 CUDA 的 GPU 架构决定了内存访问方式会显著影响内核的执行速度。本节将深入探讨 GPU 上可用的内存类型、内存合并（memory coalescing）的作用以及有效使用内存的策略。

支持 CUDA 的 GPU 具有几种类型的内存，每种内存都有自己的作用域、生命周期和缓存行为。包括：

- 全局内存（global memory）：大但慢，所有线程均可访问。
- 共享内存（shared memory）：比全局内存快得多但大小有限，同一块内的线程共享。
- 局部内存（local memory）：每个线程私有，由于是片外的，较慢。
- 常量内存和纹理内存（constant and texture memory）：针对特定访问模式进行了缓存和优化。

在这些中，优化对全局内存的访问至关重要，因为它是最常用的，并且最有成为性能瓶颈。

### 全局内存合并

如果线程以可以合并的方式访问全局内存，内存操作的性能将得到极大提高。内存合并是指 GPU 在遵循特定访问模式时，将多次内存访问合并为单次事务的能力。

一个 warp（一个一起调的 32 个线程的组）中的线程对连续内存位置进行合并访问，可以显著减少事务数量。相反，warp 的非对齐或离散内存访问会导致多次非合并事务。

考虑以下说明邻接线程访问内存位置的代码片段：

```cpp
__global__ void kernel(int *array) {
    int idx = threadIdx.x + blockIdx.x * blockDim.x;
    int val = array[idx];
}
```

在这里，只要 `idx` 为同一 warp 中的线程生成连续地址，访问就是合并的，有利于高效的内存事务。

### 内存访问优化策略

优化内存访问涉及多种减少延迟和最大化吞吐量的策略。这些包括：

- 最小化发散（divergent）：确保 warp 中的线程以统一模式访问内存，以避免导致序列化的发散内存访问。
- 使用共享内存最大化吞吐量：在可能的情况下，使用共享内存来减少全局内存流量。共享内存快得多，但需要显式管理。数据必须从全局内存加载到共享内存，任务必须必须合并的方式完成。考虑以下模式：

```cpp
__global__ void kernel(float *input, float *output) {
    float sharedMem[256];
    int idx = threadIdx.x + blockIdx.x * blockDim.x;
    // 以合并方式将输入加载到共享内存
    sharedMem[idx] = input[idx];
    __syncthreads();
    // 使用 sharedMem 执行操作
    // 写回全局内存
    output[idx] = sharedMem[idx];
}
```

- 内存对齐：地址应与事务大小对齐。非对齐可能会强制 GPU 为本可以通过单次事务完成的操作生成多个事务。
- 填充和：为了避免共享内存中的存储冲突（bank conflicts）（当多个线程访问同一个存储库导致序列化），可以使用填充或通过步长调整数据布局。
