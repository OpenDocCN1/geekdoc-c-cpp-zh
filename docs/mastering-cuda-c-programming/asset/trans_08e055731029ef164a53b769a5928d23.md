

# 理解动态并行 (Dynamic Parallelism)

动态并行的核心思想非常直观：它允许正在运行的内核（kernel）调用另一个内核或一组内核。这些子内核反过来可以启动其他内核，从而创建一个完全由 GPU 管理的内核启动层次结构。这种能力对于得益于递归方法的算法来说特别有用，例如快速排序、n 体模拟或有限元分析中的自适应网格细化。

动态并行的优势包括：

-   **减少 CPU-GPU 交互**：通过尽量减少 CPU 启动内核的需求，动态并行可以减少与 CPU-GPU 通信相关的开销，从而潜在地提高性能。
-   **算法设计灵活性更高**：程序员可以直接在 GPU 上实现复杂的层次化算法，而不受扁平并行结构的限制。
-   **简化复杂问题的代码**：动态并行允许对递归和自适应算法进行更自然的表达，使代码更易编写和理解。

然而，考虑从内核内部启动内核的开销是非常关重要的。如果不谨慎使用，过度使用动态并行可能会导致性能下降。

# 示例：使用动态并行

让我们探索一个简单的示例，展示如何在 CUDA 中使用动态并行。在这里，父内核启动了一个子内核，并在它们之间传递数据。

```cpp
__global__ void childKernel(int *data) {
    int idx = threadIdx.x + blockIdx.x * blockDim.x;
    data[idx] += 1; // 对数据进行简单操作
} 

__global__ void parentKernel(int *data, int N) {
    int threadsPerBlock = 256;
    int blocksGrid = (N + threadsPerBlock - 1) / threadsPerBlock;
    childKernel<<<blocksGrid, threadsPerBlock>>>(data);
}
```

在这个示例中，`parentKernel` 由主机（CPU）启动，反过来启动 `childKernel` 以对传递给它的数据数组执行简单操作。这展示了在 CUDA 应用中使用动态并行的基本结构。

在使用动态并行时，仔细地管理同步和数据依赖关系至关重要。CUDA 提供了各种机制，例如块内同步的 `__syncthreads()` 以及用于父子内核之间协调的事件（events）。

# 动态并行的最佳实践

为了在 CUDA 中有效使用动态并行，请考虑以下实践：

-   仅在提供明确收益时使用动态并行，例如减少 CPU-GPU 通信或简化复杂算法的表达。
-   注意从内核内部启动内核的开销。进行测量和优化以确保性能提升。
-   妥善管理内存和同步，以避免数据竞态并确保程序的正确执行。
-   利用 CUDA 事件进行父子内核之间的同步，特别是对于复杂的依赖结构。

动态并行为 GPU 编程开启了新的可能性，允许构建更灵活、更复杂的并行计算应用。通过理解其优势和潜在的陷阱，开发者可以利用这一强大特性来创建高效且直观的 CUDA 应用。

# 使用 CUDA Graphs 简化执行

CUDA graphs 为简化 CUDA 中任务的执行提供了一种精髓方法。这一特性在较新版本的 CUDA 中引入，允许开发者显式地定义操作（或任务）的图及其依赖关系，而不是按步进的方式将这些任务提交给 GPU。通过将一系列操作封装到单个图中，CUDA graphs 可以显著减少 CPU 开销，最小化延迟并提高整体执行效率，特别是在复杂且多步骤的 GPU 工作流中。

# 理解 CUDA Graphs

CUDA graphs 的核心是节点（nodes）和边（edges），其中节点代表 GPU 操作（如内核启动、内存拷贝和其他 CUDA 操作），而边定义了这些操作之间的依赖关系。通过将多个 GPU 操作及其依赖关系结构化为图，CUDA 允许更高效的调度和执行，从而更有效地利用 GPU 的所有能力。

创建 CUDA graph 涉及几个关键步骤：

-   定义图及其组成节点。
-   使用边指定节点之间的依赖关系。
-   在 GPU 上实例化并启动图。

这些步骤中的每一步对于最大化通过 CUDA graphs 实现性能提升都起着至关重要的作用。

# 创建并执行 CUDA Graph

为了说明创建和执行 CUDA graph 的过程，考虑一个简单的示例，其中两个 GPU 内核必须顺序执行，随后执行一个从设备到主机的内存拷贝操作。

```cpp
#include <cuda_runtime.h>

__global__ void kernelA() { /* 内核 A 实现 */ }
__global__ void kernelB() { /* 内核 B 实现 */ }

void createAndExecuteGraph() {
    cudaStream_t stream;
    cudaGraph_t graph;
    cudaGraphNode_t kernelANode, kernelBNode;
    cudaKernelParams_t kernelAParams, kernelBParams;

    cudaStreamCreate(&stream);
    cudaGraphCreate(&graph);

    kernelAParams.gridDim = dim3(1, 1, 1);
    kernelAParams.blockDim = dim3(1, 1, 1);
    cudaGraphAddKernelNode(&kernelANode, graph, NULL, 0, &kernelAParams);

    kernelBParams.gridDim = dim3(1, 1, 1);
    kernelBParams.blockDim = dim3(1, 1, 1);
    // 添加依赖关系（边）
    cudaGraphAddKernelNode(&kernelBNode, graph, kernelANode, 1, &kernelBParams); 
    // 注意：这是通过指定 kernelANode 为 kernelBNode 的依赖项隐式完成的

    cudaGraphExec_t graphExec;
    cudaGraphInstantiate(&graphExec, graph);
    cudaGraphLaunch(graphExec, stream);
    // 清理
    cudaGraphDestroy(graphExec);
    cudaGraphDestroy(graph);
    cudaStreamDestroy(stream);
}
```

在这个示例中，两个内核 `kernelA` 和 `kernelB` 被封装在图中图中。通过指定 `kernelA` 为依赖项，确保 `kernelB` 在 `kernelA` 完成之前不会开始执行。最后，在 GPU 上启动图。

这种编程模型允许清晰地定义和执行复杂的的操作序列，减少了 CPU 对单个任务和依赖关系的管理。

# 7.3

# Cooperative Groups 及其在同步中的作用

Cooperative Groups 是一种强大的 CUDA 特性，显著增强了编程模型管理内核线程的能力。这种抽象允许开发者定义可以进行协作的线程组。其能力扩展到块内、跨块甚至跨 GPU 之间的通信，从而消除了早期版本的许多限制。

# 理解 Cooperative Groups

Cooperative Groups 的核心是将线程组织成可以执行协作操作的概念。这些操作范围从简单任务（如屏障同步）到更高级的操作（包括归约、扫描和自定义模式）。使用 Cooperative Groups 的主要优势在于它允许编写更具读性的代码，使其匹配算法的高层结构，并大幅减少了与复杂同步和通信模式相关的样板代码。

让我们演示如何在内核中初始化协作组：

```cpp
#include <cooperative_groups.h>
using namespace cooperative_groups;

__global__ void kernelFunction() {
    // 初始化协作组
    auto group = this_thread_block();
    // 使用组进行同步或其他操作
}
```

# Cooperative Groups 中的同步

同步是并行编程的一个关键方面。高效同步线程的能力对 CUDA 程序的性能和正确性产生巨大影响。Cooperative Groups 提供了一种更灵活、可扩展的方法来实现这一点，突破了只能同步同一块内线程的限制。

Cooperative Groups 提供的 `sync()` 方法允许组内的线程在屏障处等待，直到组内所有线程都到达该屏障。这对于块中不同线程集执行不同代码部分的复杂内核特别有用。
