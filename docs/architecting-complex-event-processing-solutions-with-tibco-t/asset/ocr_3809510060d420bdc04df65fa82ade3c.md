# Logging and Exception Reporting

Virtually every solution you define will require some form of logging and exception reporting. Each processing unit has a log file configuration defined in the CDD file for the cluster. The choice of logging levels determines the amount of information logged. The CDD file defines the default level, but the logging level can be changed at runtime using the Hawk AMI interface or the BEMM interface.

The Data Grid underlying the cache agent is an implementation of TIBCO ActiveSpaces®. Its log settings are set via the CDD properties (see the Developer's Guide for details).

For inference, query, and process agents, additional reporting can be managed via rule functions. Here, logic can be added to either generate events or make log file entries. However, be sure to consider the performance implications—disk activity can slow down a design!
