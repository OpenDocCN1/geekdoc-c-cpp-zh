## 2. Generic Header File
```
#include "p24hxxxx.h"  /* generic header for PIC24H family */
```
- This file is referenced in the Source code. It is known as a header file (has an .H extension). It was developed and supplied by Microchip. For our work it's internal definitions are needed in supporting reading/writing to the PIC24H microcontroller peripherals and I/O in a C language environment.
- The actual file exists outside our project and resides within the MPLAB C30 directory.
- This file contains reference to all the specific Microchip peripheral function and register definitions. This reference allows us to access Microchip SFR functions in a seamless manner with ANSI C compliant language components.

## 3. Configuration word
- These are C language macros (custom C language scripts) that set the configuration word. These macros are defined as part of the .H file. In this case individual scripts are used to fix the PIC24H CPU clock source to the internal RC oscillator and disable the main primary crystal oscillator.
```
_FOSCSEL(FNOSC_FRC);
_FOSC(FCKSM_CSDCMD & OSCIOFNC_ON & POSCMD_NONE);
_FWDT(FWDTEN_OFF);
```

## 5. Delay function
- In order to blink the LED we need some delay time for turning it on and turning it off in order to allow it to persist in our vision as a "blink". This function provides this. It is configured with a fixed delay, that idles and does nothing else but consume CPU cycle time for about ½ second. The delay is configured as a loop within a loop. The loop times are established by lend and jend values. The total delay time is approximately lend times jend cycles or 400 x 1000 or 400,000 cycles to achieve 500 millisecond delay.
```c
void delay(void); // 501 msec

int i,j;
for (i=0; i<lend; i++)
    for (j=0;j<jend; j++);
}
```

## 6. Main code
- Every C program must have a single function called "main". This is where execution begins for the user, only after the compiler sets the configuration word, initializes the processor stack pointer, and initializes all the variables. Only one main function can exist in a C language application at a time. As we will see the main function is often segmented with an initialization section and a continuous loop section. Once initialization is complete the microcontroller enters the continuous ("infinite") loop for its operations. This is marked by a while (1) { ...... }. The microcontroller normally never leaves this part of main unless a power reset or watchdog timeout occurs.
```c
// main entry point
...................
int main(void)
/* Initialize ports */
AD1PCFGL = 0x0fff;    // reset all pins that others initialized make them digital
LATB = 0x0000;        // set latch levels for ports
TRISB = 0x0000;       // set IO as outputs for ports
/* endless loop */
while (1) {
    delay();
    led = !led;
}
```
- Normally PC based C applications will run on and then return back to the PC operating system once the main function is finished. For microcontroller applications there is no operating system so if main terminates the compiler resets the processor by starting execution from the beginning

## 7. I/O initialization
- This is within the main function, as mentioned earlier, and it is the segment of main that is dedicated to initializing all microcontroller ports and peripherals (SFR) before the application can begin to use them. Initialization usually happens once in main before it enters into a continuous operating loop. Three special function registers (SFR) are involved for our application. AD1PCFGL is used and configured to turn off all analog associated capability to those pins that have analog content. LATB is a latch output setting for all pins associated with PORTB pin outputs. In this case all latched settings are zeroed —nothing will appear as a high level on output to start. TRISB is the directional setting for PORTB that in this case makes them all outputs.
```
AD1PCFGL = 0xFFFF
LATB = 0x0000
TRISB = 0x0000
```

## 8. Continuous loop
- This is the primary working segment of microcontroller applications. The continuous loop is where all the work gets done. In our loop we invoke the delay function and after this we 'toggle' the current value of LED (which is defined as the LATB bit 5 or RB5 pin). By 'toggling' if the current RB5 is value 1 then is set to 0, if 0 then it is set to 1. In this way after every delay the LED connected to RB5 will blink.
```
while(1)
    delay()
    led = !led
```

## Experiment 1 - How it Works
The application uses a single C source file (main_led.c) that is a main function that references generic PIC24H headers/peripherals use (#include "pic24Hxxx.h"). This header will determine the specific PIC24H processor in use. The processor configuration is set using predefined C library macros (also referenced in the header file). These settings are internal CPU clock selection of 8MHz, no external oscillator, no clock switch over, no watchdog operation, and finally use of RA3 as a digital/analog pin versus an external crystal pin input.

In the main function the application executes I/O initialization and then proceeds to enter a continuous loop for alternately turning on and then off the LED. A flow diagram of this specific LED display application is shown in Figure 2-5.
