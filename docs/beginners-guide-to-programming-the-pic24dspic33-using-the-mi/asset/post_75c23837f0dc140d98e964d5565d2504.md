### Review of PIC24H Timers capability:

- Five 16 bit general purpose timers/counters
  - Similar functionality between all 5 timers
  - Period registers for each
  - Interrupt generation on match with period
  - Reset on match
- Four of these timers (Timer 2+3 and 4+5) can make two 32 bit timers/counters
- In 32-bit operations: Timer 2+3 or Timer 4+5 = Least Significant Word and Most Significant Word

## Chapter 7 – Serial Communications

In this chapter we will introduce serial communications using a UART (Universal Asynchronous Receiver Transmitter) for RS-232 and USB applications. We will apply the PIC24H UART peripheral using the PIC24H configurable peripheral pin assignment system designated Peripheral Pin Select (PPS). Let's first discuss serial communications.

### Serial Communications Overview

Serial communications is performed by transmitting and receiving data bytes one bit at a time. The bits transferred are specifically composed of not only the full data byte but also framing bits for start, stop and error checking. This type of communication is perhaps one of the oldest used by microcontrollers and still very much applied. Serial communication application can exist between microcontrollers, or a microcontroller to a PC or display, or even a wireless transceiver.

The PIC24H has two completely independent UARTs; UART1 and UART2. For our experiments we will use the PIC24H UART2 to communicate with a PC. Each UART peripheral has separate transmit and receive hardware. The transmit section takes in a parallel data (byte) from the PIC24H CPU and transmits it as a serial bit by bit stream at a fixed bit or baud rate. In this manner the transmit hardware functions as a PISO (Parallel in Serial Out) digital register. The receive hardware takes in serial data and forms a parallel data (byte) for transfer to the PIC24H CPU. The receive section functions as a SIPO (Serial in Parallel Out) digital register. The complete UART peripheral contains not only these functions but the internal bit clock generator, framing logic, and data buffers necessary to perform serial data transfer between two devices with or without use of a common shared clock between those devices.

We will use a type of serial communications termed "asynchronous", when no shared clock is used. If a shared clock is used then the communications is termed synchronous. The concept for making asynchronous communications work is that each UART in the communication system is preconfigured with the same bit rate clock or baud rate clock. In the PIC24H the baud rate clock is generated by using an internal clock source. During system communications the transmitter side alerts the receiver side that a byte is to be transferred. It does this by lowering the serial data line for one bit time (this is designated the start bit). The receiver synchs up its internal baud rate generator to this start bit to begin its data reception. Data is then transferred from the transmitter side to the receiver side one bit at a time for the 8 data bits that make up the data byte.

Besides the 8 data bits an error correction or parity can be sent (optional). The final part of the communication is a stop bit which occurs when the serial communication line is fixed high for one or two bits times (size is optional as well), after parity. See Figure 7-1 below.

Note for this communication to work each transmitter output line must be tied directly to a receiver input line. Specifically, side one's transmitter must be tied to side two's receiver and side two's transmitter must be tied to side one receiver (if communication is to occur in both directions).

When only one UART is allowed to transmit its data traffic at a time the communications is designated "half-duplex". However, when the configuration allows for both UARTs to simultaneously transmit data, the communication is termed "full-duplex".

### RS-232 and RS-485 Industry Standard Serial Communications

There are several legacy industry standards for connecting equipment that have UARTs. One of these standards for point to point communication is RS-232. This standard captures the connector types, baud rates, pin outs and voltage levels. RS-232 dictates that the voltage level from +3.3V to 0V of the PIC24H UART output must be modified to -12V to +12V to meet the standard. This means that voltage level changing electronics is needed. The RS-232 standard also uses a common connector set 9-pin male and female connector pair. For RS-232 one side of the communication must be configured as DCE (data communications equipment) and the other as DTE (data terminal equipment). This partitioning establishes each side's transmit and receive pin outs and connector type. The PC is pre-configured as DTE. This forces the PIC24H or Microstick II to be DCE.

A complete end-to-end hookup diagram for a Microstick II connection to a PC using RS-232 is shown in Figure 7-3. The PC runs a software application program known as HyperTerminal which allows the serial data communications stream to be visible on the PC screen. This software will be required in our experiments. Level conversion hardware and a DCE connector for RS-232 are needed for the Microstick II. We will use an ACRONAME module; it contains both in a convenient pluggable board. We then incorporate a standard RS-232 cable DCE to DTE to pair the connector to the PC to brainstorm. As a final note the data rates and serial format for communication needs to be set. This is important for both the PIC24H UART initialization software, and HyperTerminal configuration. The considerations are baud rate, number of stop bits, data size, use of parity, and finally any hardware handshaking. For our purposes we will use 1200 baud, 8 bits; no parity, 1 stop bit and no hardware handshake. The shorthand notation for this is 1200-8-N-1.

### American Standard Code for Information Interchange (ASCII)

In reality, a user can select any type of digital byte for transfer but HyperTerminal can only display ASCII (American Standard Code for Information Interchange) formatted data. A table is shown in Figure 7-4. The table is for 128 different characters that includes control, data (upper /lower case A-Z), numerical (0-9), special characters like quotes, exclamation point, question mark, and pound sign. We will be using ASCII data coding for our serial communication experiments.
