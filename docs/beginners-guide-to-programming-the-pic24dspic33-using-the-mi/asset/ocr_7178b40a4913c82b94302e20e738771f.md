# Chapter 7 – Serial Communications

In this chapter we will introduce serial communications using a UART (Universal Asynchronous Receiver Transmitter) for RS-232 and USB applications. We will apply the PIC24H UART peripheral using the PIC24H configurable peripheral pin assignment system designated Peripheral Pin Select (PPS). Let's first discuss serial communications.

# Serial Communications Overview

Serial communications is performed by transmitting and receiving data bytes one bit at a time. The bits transferred are specifically composed of not only the full data byte but also framing bits for start, stop and error checking. This type of communication is perhaps one of the oldest used by microcontrollers and still very much applied. Serial communication application can exist between microcontrollers, or a microcontroller to a PC or display, or even a wireless transceiver.

The PIC24H has two completely independent UARTs; UART1 and UART2. For our experiments we will use the PIC24H UART2 to communicate with a PC. Each UART peripheral has separate transmit and receive hardware. The transmit section takes in a parallel data (byte) from the PIC24H CPU and transmits it as a serial bit by bit stream at a fixed bit or baud rate. In this matter the transmit hardware functions as a PISO (Parallel in Serial Out) digital register. The receive hardware takes in serial data and forms a parallel data (byte) for transfer to the PIC24H CPU. The receive section functions as a SIPO (Serial in Parallel Out) digital register. The complete UART peripheral contains not only these functions but the internal bit clock generator, framing logic, and data buffers necessary to perform serial data transfer between two devices with or without use of a common shared clock between those devices.

We will use a type of serial communications termed "asynchronous", when no shared clock is used. If a shared clock is used then the communications is termed synchronous. The concept for making asynchronous communications work is that at each (UART) in the communication system is preconfigured with the same bit rate clock or baud rate clock. In the PIC24H the baud rate clock is generated by using an internal clock source. During system communications the transmitter side alerts the receiver side that a byte is to be transferred. It does this by lowering the serial data line for one bit time (this is designated the start bit). The receiver synchs up its internal baud rate generator to this start bit to begin its data reception. Data is then transferred from the transmitter side to the receiver side one bit at a time for the 8 data bits that make up the data byte.
