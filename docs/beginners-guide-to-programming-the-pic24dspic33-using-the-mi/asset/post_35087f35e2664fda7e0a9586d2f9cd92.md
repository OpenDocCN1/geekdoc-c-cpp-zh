
The class of interest to us is CDC. We will use a UART to USB Bridge that allows for a UART interface on microcontroller side and USB CDC compliant device interface on the PC side. ACRONAME provides a pluggable module with their S22. The S22 module provides the bridge chip with the same four pin connector for the micro side and a USB device connector on the other side. You connect to the PC using the familiar USB Host type A to Device Type B connector cable. USB supports "plug and play".

Each device, when it is connected to the USB, is "enumerated" by the PC, which means the device identifies to the PC its class type, operational needs, and driver requirements. The PC checks that it can meet the operational needs and that the identified driver for the device is present in its current software registry. Only when all this is accomplished, will communications be allowed. We can then open HyperTerminal on the PC and identify the COM port associated with the S22, configure the COM port, and begin communications.

For USB CDC we will use the ACRONAME supplied registry file (.INF) to register the communication port with the Operating System and the ACRONAME supplied S22 driver. When first connecting to the PC the system will see the S22 as "new hardware" on the USB and will attempt to retrieve driver information. At this point you direct the PC to the ACRONAME driver locations you stored on your PC. This is a one-time configuration requirement which will then be automatic every time you connect again. The USB is +5V bus, however, we only need to power up the S22 with available +3.3V on the micro USB (Universal Serial Bus).

## Serial Communications Review

Some important reminders and rules of thumb with serial communications:

- Message is equal in size to a Start bit, # of stop bits, # of data bits, parity if present (10 bits shown)
- Baud rate
  - Bit transfer rate during message up to 115K
- Data bits
  - Number of data bits transferred in a message
- Parity
  - Optional Parity error checking bit present in message

- Five 16-bit timers (5 input pins)
- Five input capture – automatic pulse capture and measurement (5 input pins)
- Five Output Compare / PWM modules – automatic pulse generation (5 output pins)
- Two UART (Universal Asynchronous Receiver Transmitter) with address capability (4 pins (2 in and 2 out))
- Two SPI (Synchronous Peripheral Interface) (6 pins (2 data out, 2 data in, 2 clock (in/out))
- I2C (Inter Circuit Communication) interface (2 pins (1 in and 1 out))

Obviously the total peripheral pin needs are large and, in fact, and with these 28 pin PIC24H devices, there are more internal peripherals than there are available pins. As a compromise solution the PIC24HJ128GP502 28 supports PPS with 16 remappable pins. These remappable pins are configurable as input or output to any of the above peripheral set. These pins are designated with "RP" for reprogrammable pin. This is the closest thing to having to layout of your own device.

## Initializing PPS

Peripheral Pin Select or PPS has to be initialized, and once initialized it cannot be changed accidentally. To achieve this Microchip has instituted a specific sequence of steps that need to occur for PPS configuration.

Here's the basic idea; at the start of the main program, you can unlock, and configure the PPS for designated peripherals, first the outputs, and then the inputs. Once this is done the PIC24H is locked and remains with this pin state configuration. To do this the IOLOCK bit in the OSCON SFR register is set. Once set the PPS cannot be undone unless reset occurs. The PPS lock and unlock controls are really implemented as special code sequences to access the OSCON SFR. This ensures that random code reads or writes cannot access and contaminate the fixed PPS settings. The general software flow is shown in Figure 7-7.

## Software Configuration

The experiment has #include "CONU2.H" in MAIN and CONU2.C driver source code in the project that allows use of the UART2 serial port from the user application code side. The CONU2 library functions used in the serial communications are:

- initU2 () – initializes the serial port using UART2 of PIC24H for RB11 and RB10 or pins 22 and 21 respectively of the Microstick II. Pin 21 is the input receive (RX) for the Microstick II UART2 and pin 22 is the output transmit (TX) for the Microstick II UART2. UART2 is configured for 1200 BAUD, 8 bit data, no parity and 1 stop bit or shorthand 1200 8N1.
- putU2( character) – writes character out to the serial port
- putsU2( string)- writes an entire string out to serial port
- Clrscr() – this macro clears screen using a VT100 known escape sequence
- Home() – positions cursor to home position on screen using a known VT100 escape sequence
- Character getU2 ( ) – waits for a new character to arrive to the serial port and returns it.
