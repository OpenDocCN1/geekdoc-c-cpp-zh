The 25LC256 uses an SPI interface to talk to the Microstick II PIC24H Microcontroller. For our experiment we use a software 'C' library where a SPI communication is supported with an easy to use API.

For this library each 25LC256 storage word is two bytes. Given the byte size of the 25LC256 this means we can store up to 16K words total. The double byte storage and retrieval makes sense since the PIC24H is a 16 bit machine. In general, for your experiments, you need to establish what data you want to store and how that data is organized over 16K words. Figure 8-3 shows the physical EEPROM. It is an 8 pin DIP. You already can recognize the basic SPI signals /CS, SCK, SI and SO. In addition for this EEPROM there are additional control signals. There is a write protect (/WP) control line to physically lock out the Microcontroller from writing to the EEPROM. /HOLD suspends a command/data sequence, and puts the device in a suspended state that does not require restarting the sequence once /HOLD is released.

- CS – Chip Select
- SCK – Serial Clock
- SI – Serial Input
- SO – Serial Output
- WP – Write Protect
- HOLD – Hold Enable

## Experiment 1- Hardware

The PIC24H has user programmable PPS pins to place the I/O of any internal digital peripheral onto any of these pins. We will configure pins 18, 17, and 16 to function as the interface for SPI2, namely, SO, CLK and SI. Pin 15 will be configured as a normal digital output for /CS. /HOLD and /WP are not required and, so, wired high to disable. The final hardware schematic is shown in Figure 8-4. Figures 5, 6, 7 show the 25LC256 EEPROM instruction set and a read/write byte sequence using SPI. Note that all addresses to the EEPROM are sixteen bit. Upon /CS becoming active the microcontroller first sends the specific command (see Figure 8-5) to the EEPROM, followed by address. What happens next depends on whether the command is a read or write operation; if read the EEPROM will output data to Master to read, if it is a write operation the Master will output data to the EEPROM to store. Most EEPROM are not typically high speed devices and a memory write cycle may take several milliseconds. The API handles this.

## Experiment 1- The Software

Ok, the hardware has been discussed, let's now discuss the software. The EEPROM library is fairly straightforward, and uses 16 bits of data as its argument (2 byte read or 2 byte write). Take a quick look at the functions listed below. Using the EEPROM library function we can do the basic initialization of SPI2 to access the EEPROM and then read and write from it once it is initialized.

- **InitNVM ()** - initializes the EEPROM for access using SPI2. This must be called first before any other EEPROM library function is called. NVM stands for "Non-Volatile Memory".
- **iReadNVM ( address)**- SPI2 reads EEPROM at address and returns the 16 bit value stored at that location
- **iWriteNVM (address, data)** – SPI2 writes 16 bit data value for EEPROM at the designated address.

An example project EEPROM.MCW will be used for our experiment. It configures SPI2 interface for pins 18, 17, 16 using PPS. It initializes the SPI2 Special Function Registers SPI2CON1(control) and SPI2STAT (status) for correct operation, finally it writes a 16 bit value to an even address in EEPROM (located on a 16 bit boundary) and then reads this value back from the EEPROM and compares values. A flowchart is provided.

// I/O definitions for PIC24H prototype
#define CS EE _RB6 // select line for Serial EEPROM
#define TCS EE _TRISB6 // tris control for CS EE pin pin 11
#define SPI_MASTER 0x0122 // select 8-bit master mode, CKE=1, SMP=0, 4MHz
#define SPI_ENABLE 0x8000 // enable SPI port, clear status
void InitNVM(void)
{ // init the SPI peripheral
 CS EE = 1; // select the Serial EEPROM
 TCS EE = 0; // make CS EE pin output
 SPI2CON1 = SPI_MASTER; // select mode
 SPI2STAT = SPI_ENABLE; // enable the peripheral
}
