### Review of SPI Key features:

- Supports four wires SDO, SDI, SCLK, /CS
- Data can move in both directions simultaneously
- Master supplies Clock and initiates data transfer
- Simple synchronous interface used extensively in microcontroller peripheral communications
- Capable of high speed transfers (clock rate dependent)
- SPI Peripheral functions as a digital shift register

### Review of EEPROM Key Features:

- EEPROM retains memory content when power is off
- Use in setting passwords, access code, and calibration data

### Review of PIC24H SPI Key Features:

- PIC24H has two available SPI peripherals #1 and #2
- PPS is used to configure programmable pins for SPI interface
- SPI is programmed through the bit setting in two SFR registers SPI2CON1 and SPI2STAT

The OCx module can use either the PIC24HJ64GP502 16 bit Timer 2 (TMR2) or Timer3 (TMR3) as a time base, and the period setting for the output pulse waveform. PR2 is the period setting for Timer 2 and PR3 is the period setting for Timer 3. In our examples we will use Timer 2. The OCxRS and OCxR registers are loaded with a 16 bit value to control the width of the pulse generated during the output period. This value is compared against the Timer during each period cycle. The OCx output starts high and then when a match occurs OCx logic will generate a low on output. This will be repeated on a cycle by cycle basis (See Figure 9-2).

This is OCx Pulse Width Modulation (PWM) mode. An important notion in thinking about PWM is that it allows dynamic changing of the DC voltage level to a load. Wait a minute you say --- where's the DC voltage here? Think of the DC voltage as an average voltage value of the pulsed DC across the waveform period. For example, if we have pulse high for 50% of the period consistently, and the pulses are +3.3V then we are supplying on the average 50% of 3.3V to the load or 1.65V. In order to change the pulse width while the system is running we simply write into OCxRS and it automatically loads into OCxR on the next cycle.

- void turnon (int setting) - turn on RB2 pin output, Timer2 clock and the PWM OC1 configuration on this pin. The period of Timer2 is preset to 0x7FF the max value of the 12 bit ADC. Setting is any value set by the pot ADC between 0-0x7FF that adjusts the PWM duty cycle. If setting is 0 then duty cycle is zero, if setting is 0x3FF then duty cycle is 50%, if setting is 0x7FF then duty cycle is 100%
- void setPWM (int setting) - This performs the same function of running turnoff (void) and turnon (int setting) with one call. This turns PWM off first before setting it.

There are also several ADC functions that we will use. These functions were introduced in Chapter 4 and are in the ADC library. If you need to, please review chapter 4 to gain an understanding of ADC.

- void initADC (int ANpin) – this function initializes the ADC for 12 bit manual conversion using the "ANpin" as the single input pin. ANpin possible settings are AN0, AN1, AN4, AN5, AN9, AN10, AN11, and AN12. In this experiment we will use AN0.
- int readADC (int ANpin) – this function forces a manual ADC conversion on the designated ANpin, again we will use AN0.

## Chapter 10 – RTCC (Real Time Clock Calendar)

In this chapter we will exercise the RTCC (Real Time Clock Calendar) peripheral on the PIC24H. The experiment is recommended for use only with the 16 Bit Micro Experimenter (see appendix A), because all necessary support hardware i.e. clock crystal, LCD, and four pushbuttons are already in place.

### The Real Time Clock Calendar

We have been talking about the Experimenter's clock, so here it is. It is a Real-Time Clock and Calendar (RTCC) function and is intended for applications where accurate time must be maintained for extended periods of time with minimum to no intervention from the CPU. The peripheral is optimized for low-power usage in order to provide extended battery lifetime while keeping track of time. It features a 100-year clock and calendar with automatic leap year detection. The range of the clock is from 00:00:00 (midnight) on January 1, 2000 to 23:59:59 on December 31, 2099. The hours are available in 24-hour (military time) format. The clock provides a granularity of one second.

The RTCC internal register interface with the PIC24H Microcontroller is implemented using the Binary Coded Decimal (BCD) format. This simplifies the software, when reading and writing to the module, as each of the digit values is contained within its own 4-bit value.

![](img/a9229e7b0ddd9608f171b22b52514f39_174_0.png)

The LCD and pushbuttons. To operate these you must first call library function RTCCInit(). The two functions we will discuss use the RTCC library but reside outside of it in the MAIN.C.

- Set_ALARM(alarm) – this function initializes the alarm functions of the RTCC and sets the alarm (for the data logger we referred to this as rate) based on the value passed as alarm. It is called during the rate setting menu. It sets as follows:
    - if (alarm =0) then alarm every 10 seconds
    - if (alarm =1) then alarm every minute
    - if (alarm =2) then alarm every 10 minutes
    - if (alarm =3) then alarm every hour
    - if (alarm =4) then alarm every day
    - if (alarm =5) then alarm every week
    - if (alarm =6) then alarm every month
    - if (alarm =7) then alarm every year

Once the alarm is set this function will then enable the RTCC to interrupt the PIC24H when the alarm condition occurs. The RTCC interrupt service then can perform whatever function required for the alarm application. Code snippets for set alarm and RTCC interrupt are shown in Figures 10-5 and 10-6. Note in the interrupt that there is a comment for you to add your own code for whatever function you want to perform as a result of alarm condition (the default is toggling the LED).

- clock_Setup() – This routine displays current RTCC time setting in ASCII on the display and allows the operator to accept or make changes to RTCC using the display and pushbuttons.
    - Button SW1 - toggles between clock set mode and clock accept mode. Hitting the SW1 twice in accept mode exits the function with RTCC set to the displayed time.
    - Button SW2 - if in clock setting mode increments current data field
    - Button SW3 - if in clock setting mode decrements current data field
    - Button SW4 - advance to next allowable data field
