# Algorithm 12.1 SEQUENTIAL(C_KB): Δ

```
{C_KB: configuration knowledge base}
{\overline{C_KB}: the complement of C_KB}
{Δ: set of redundant constraints}
{C_KBt: copy of C_KB used for redundancy elimination}
C_KBt ← C_KB;
for all c_i in C_KBt do
  if isInconsistent((C_KBt − {c_i}) ∪ {¬c_i}) then
    C_KBt ← C_KBt − {c_i};
  end if
end for
Δ ← C_KB − C_KBt;
return Δ;
```

The approach of SEQUENTIAL is straightforward (see, e.g., Boufkhad and Roussel, 2000; Chmeiss et al., 2008; Fourdrinoy et al., 2007; Grimm and Wissmann, 2011; Piette, 2008): each individual constraint c_i is evaluated with regard to redundancy by checking whether C_KB − c_i is still inconsistent with \overline{C_KB}. Instead of checking the inconsistency of C_KB − {c_i} ∪ \overline{C_KB}, SEQUENTIAL systematically reduces the number of constraints to be checked in \overline{C_KB}. Given a configuration knowledge base C_KB and its complement \overline{C_KB}, the (in)consistency check of C_KB − {c_i} ∪ \overline{C_KB} can be reduced to the inconsistency check of C_KB' − {c_i} ∪ \overline{C_KB'} where \overline{C_KB'} = {¬c_i}. If we assume that C_KB = {c1 ∧ c2 ∧ ... ∧ c_m ∧ c_{m+1} ∧ ... ∧ c_n}, \overline{C_KB} = {¬c1 ∨ ¬c2 ∨ ... ∨ ¬c_m ∨ ¬c_{m+1} ∨ ... ∨ ¬c_n}, and γ = {c_{m+1} ∧ ... ∧ c_n} then the consistency check of C_KB − γ ∪ \overline{C_KB} can be reduced to {c1 ∧ c2 ∧ ... ∧ c_m} ∪ {¬c_{m+1} ∨ ... ∨ ¬c_n}. In the SEQUENTIAL algorithm this property is exploited correspondingly.

If (C_KB − {c_i}) ∪ {¬c_i} is inconsistent, c_i can be considered redundant. If C_KB − {c_i} is consistent with ¬c_i, c_i is a nonredundant constraint since its deletion induces consistency with \overline{C_KB}. Applying the algorithm SEQUENTIAL to our example C'_KB results in Δ = {c_a} since (C_KB − {c_a}) ∪ {¬c_a} is inconsistent and no further constraint c_i can be deleted from C_KB such that (C_KB − {c_a, c_i}) ∪ {¬c_i} is still inconsistent.
