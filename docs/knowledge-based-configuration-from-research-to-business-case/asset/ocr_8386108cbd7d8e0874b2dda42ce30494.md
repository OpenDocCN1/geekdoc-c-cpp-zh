# ## 12.2 An Example Configuration Knowledge Base

For illustration purposes we use the following *car configuration task* throughout this chapter. The variable type represents the type of the car, pdc is the park distance control feature, fuel represents the average fuel consumption per 100 kilometers, a skibag allows convenient ski stowage inside the car, and 4-wheel represents the gear type (4-wheel supported or not supported). These variables represent the possible combinations of customer requirements. The configuration knowledge base $C_{KB} = \{c_1, c_2, c_3, c_4, c_5\}$ defines additional restrictions on the set of possible customer requirements $C_R = \{c_6, c_7, c_8, c_9, c_{10}\}$.

+   - **Variables ($V$)** = {type, fuel, skibag, 4-wheel, pdc}
+   - **Domains ($D$)** = {
+     - $dom(type)$ = {city, limo, combi, xdrive},
+     - $dom(fuel)$ = {4l, 6l, 10l},
+     - $dom(skibag)$ = {yes, no},
+     - $dom(4\text{-}wheel)$ = {yes, no},
+     - $dom(pdc)$ = {yes, no}
+   }

+   - **Knowledge Base ($C_{KB}$)** = {
+     - $c_1$: 4-wheel = yes → type = xdrive,
+     - $c_2$: skibag = yes → type ≠ city,
+     - $c_3$: fuel = 4l → type = city,
+     - $c_4$: fuel = 6l → type ≠ xdrive,
+     - $c_5$: type = city → fuel ≠ 10l
+   }

+   - **Customer Requirements ($C_R$)** = {
+     - $c_6$: 4-wheel = no,
+     - $c_7$: fuel = 4l,
+     - $c_8$: type = city,
+     - $c_9$: skibag = no,
+     - $c_{10}$: pdc = yes}
