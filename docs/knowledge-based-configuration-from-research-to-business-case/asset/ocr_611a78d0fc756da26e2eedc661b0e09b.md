A *configuration* (see Hotz et al., 2014⁶) for our example configuration task would be \(I = \{4\text{-wheel} = \text{no},\ \text{fuel} = 41,\ \text{type} = \text{city},\ \text{skibag} = \text{no},\ \text{pdc} = \text{yes}\}\).

# 12.3 Determining Redundant Constraints

Let us now consider a simple adaptation of the original set of constraints \(C_{KB}\), which we denote with \(C'_{KB}\). \(C'_{KB}\) includes an additional constraint \(c_a\), which has been added by a knowledge engineer.

```
\[
C'_{KB}=\{\
\begin{aligned}
 c_a &: \text{skibag} \ne \text{no} \to \text{type}=\text{limo} \lor\\
    &\quad \text{type}=\text{combi} \lor\\
    &\quad \text{type}=\text{xdrive},\\
 c_1 &: 4\text{-wheel}=\text{yes} \to \text{type}=\text{xdrive},\\
 c_2 &: \text{skibag}=\text{yes} \to \text{type}\ne\text{city},\\
 c_3 &: \text{fuel}=41 \to \text{type}=\text{city},\\
 c_4 &: \text{fuel}=61 \to \text{type}\ne\text{xdrive},\\
 c_5 &: \text{type}=\text{city} \to \text{fuel}\ne101\}
\end{aligned}
\]
```

It is obvious that \(c_a\) is redundant since it does not further restrict the solution space defined by \(C_{KB}=\{c_1,c_2,c_3,c_4,c_5\}\). In order to discuss constraint *redundancy* on a more formal level, we introduce the following definitions.

**Definition (Redundant Constraint).** Let \(c_a\) be a constraint of the configuration knowledge base \(C_{KB}\). \(c_a\) is called redundant iff \(C_{KB}-\{c_a\}\models c_a\). If this condition is not fulfilled, \(c_a\) is said to be *nonredundant*. Redundancy can also be analyzed by checking \(C_{KB}-\{c_a\}\cup\overline{C}_{KB}\) for consistency. If consistency is given, \(c_a\) is nonredundant.

This definition is based on the definition of Dechter and Dechter (1987). Iterating over each constraint of \(C_{KB}\), executing the nonredundancy check \(C_{KB}-\{c_a\}\cup\overline{C}_{KB}\) and deleting redundant constraints from \(C_{KB}\) results in a set of nonredundant constraints (the *minimal core*). If the nonredundancy check fails (no solution can be found), the constraint \(c_a\) is redundant and can be deleted from \(C_{KB}\). Otherwise, \(c_a\) is nonredundant.

**Definition (Minimal Core).** Let \(C_{KB}\) be a configuration knowledge base. \(C_{KB}\) is denoted as minimal core iff \(\forall c_i\in C_{KB}: C_{KB}-\{c_i\}\cup\overline{C}_{KB}\) is consistent. Obviously, \(C_{KB}\cup\overline{C}_{KB}\models\bot\).

The principle of the following algorithm (SEQUENTIAL - Algorithm 12.1) is often used for determining such redundancies (see, e.g., Boulkhad and Roussel, 2000; Chmeiss et al., 2008; Fourdrinoy et al., 2007; Grimm and Wissmann, 2011; Piette, 2008).
