# 16.10.2 Example: Cyclic Dependencies Are Not Allowed

**A module is not allowed to have a dependency on itself**—that is, a module cannot import itself directly or indirectly.⁶⁷,⁶⁸ Figures 16.23 and 16.24 define primary module interface units moduleA and moduleB—moduleA imports moduleB, and vice versa. Each module indirectly has a dependency on itself due to the import statements in line 5 of Fig. 16.23 and line 5 of Fig. 16.24—moduleA imports moduleB, which in turn imports moduleA.

```
```cpp
// Fig. 16.23: moduleA.ixx
// Primary module interface unit that imports moduleB.
export module moduleA; // declares the primary module interface unit

export import moduleB; // import and re-export moduleB
```
```

**Fig. 16.23**  Primary module interface unit that imports moduleB.

```
```cpp
// Fig. 16.24: moduleB.ixx
// Primary module interface unit that imports moduleA.
export module moduleB; // declares the primary module interface unit

export import moduleA; // import and re-export moduleA
```
```

**Fig. 16.24**  Primary module interface unit that imports moduleA.

Compiling Figs. 16.23 and 16.24 in Visual C++ results in the following error message:

```
```text
error : Cannot build the following source files because there is a
cycle dependency between them: ch16\fig16_23-24\moduleA.ixx depends
on ch16\fig16_23-24\moduleB.ixx depends on ch16\fig16_23-24\
moduleA.ixx.
```
```

You cannot compile this example in g++ or clang++ because each compiler requires a primary module interface unit to be compiled before you can import it. Since each module depends on the other, this is not possible.
