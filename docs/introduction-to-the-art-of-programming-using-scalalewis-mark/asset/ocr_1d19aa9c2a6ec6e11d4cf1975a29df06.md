```
In this example we used simple literals for the arguments to the function, but the arguments can be any expression with the proper type. For example, we could do the following:

```
```scala
scala> val a=5
```

```

Here we show that the arguments to g can include a reference to a val or a call to the square function. The call to square needs to be followed by a conversion to an Int because g is declared to take type Int and the result of square is Double. If you leave that out, you will get an error like this:

```
```scala
scala> g(a+2,square(3))
<console>:9: error: type mismatch;
 found   : Double
 required: Int
        g(a+2,square(3))
                 ^
```
```

With the val and var declarations, we saw that we could typically leave off the types and Scala would figure them out for us. With functions, the types on the parameters are required. The result type is not required as it can often be inferred, but it is considered better style to specify it.¹ The reason this is preferred is that if you tell Scala a type and make a mistake in the function that causes it to result in a different type, Scala can tell you earlier that something has gone wrong.
```
