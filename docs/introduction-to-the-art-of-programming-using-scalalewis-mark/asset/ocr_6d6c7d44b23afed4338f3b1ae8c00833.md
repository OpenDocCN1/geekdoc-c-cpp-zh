# 18.3 Design

In the first half of this book, most of the work you did in the design process was to break the problem down into different functions and decide what data needed to be passed between those functions. When you are working in an object-oriented mode the design process involves figuring out the types of objects that you need in the programs and laying out classes, objects, and traits for them. Each class, object, and trait can have member data and and methods in it.

The way to represent this in UML is with a Class diagram. Figure 18.2 shows a simple class diagram showing two classes, one for a Student type and one for a Course type. Each class is represented with a box that has three different parts. The top is the name of the type. Below that are the data members of the type. The bottom section lists the methods for that type. The data members and methods are preceded by a symbol indicating their visibility. A ‘+’ indicates that it is public, a ‘-’ indicates that it is private, and a ‘#’ indicates that it is protected.

This figure also shows an arrow between the Course and Student classes. There are multiple types of arrows the are used in class diagrams. We’ll see more of them over time.
