The next two lines start two nested If blocks. The meat of our code is inside these blocks. They check to make sure that a customer has been chosen and a sale date has been entered. If either of those are blank, the rest of the code will fail. The IsNull function will return True if those values aren’t set and the Not operator turns True to False and vice versa.

You’ve already seen how to open recordsets in the previous sections. The actual writing of data occurs in the five-line If block. It first checks to see that we’re not at the end of the file. The SQL statement is designed to return one record (the customer with a certain ID). If no records are returned, rsContacts.EOF will be True, and the code that updates will be skipped.

The three lines that write the date include the Edit method, an assignment statement, and the Update method. Calling the Edit method tells DAO that you intend to change data on the current record. The assignment statement changes the LastSalesDate field’s value to the value in the sale date text box. Once data has been changed, you call Update to write the data and tell DAO that you’re done editing. You can have as many assignment statements between Edit and Update as you like.

Finally, the code closes the recordset and releases the memory held for the two DAO variables.

One major difference between a table open in Datasheet view and a recordset is that a recordset provides no visual representation of the data it contains. A datasheet provides you with rows and columns of data and even includes column headings so you know the names of the fields in the underlying table.

A recordset exists only in memory. There is no easy way to visualize the data in a recordset. As a developer you must always be aware of the field names, row count, and other data attributes that are important to your application.

When you are working with datasheets and recordsets, only one record is active. In a datasheet the active record is indicated by a color difference in the row. Recordsets have no such visual aid, so you must always be aware of which record is current in a recordset.

Before you change data in any of the recordset’s fields, you need to make sure that you’re in the record you want to edit. When a recordset opens, the current record is the first record in the set. If the recordset contains no records, the recordset’s EOF property is True. In this example, the SQL statement was designed to return only one record. But if you’re dealing with a recordset with multiple records, you need to navigate so that the record you want to change is the current record.
