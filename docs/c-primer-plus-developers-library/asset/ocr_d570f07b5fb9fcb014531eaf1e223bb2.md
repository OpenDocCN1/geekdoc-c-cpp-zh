# Program Notes

We’ve already discussed the two functions in Listing 7.12, so let’s review how the program uses cin to control a while loop:

```
while (cin >> replace.x >> replace.y)
```

Recall that cin is an object of the istream class. The extraction operator (>>) is designed in such a way that cin >> replace.x also is an object of that type. As you’ll see in Chapter 11, “Working with Classes,” class operators are implemented with functions. What really happens when you use cin >> replace.x is that the program calls a function that returns a type istream value. If you apply the extraction operator to the cin >> replace.x object (as in cin >> replace.x >> replace.y), you again get an object of the istream class. Thus, the entire while loop test expression eventually evaluates to cin, which, as you may recall, when used in the context of a test expression, is converted to a bool value of true or false, depending on whether input succeeded. In the loop in Listing 7.12, for example, cin expects the user to enter two numbers. If, instead, the user enters q, as shown in the sample output, cin >> recognizes that q is not a number. It leaves the q in the input queue and returns a value that’s converted to false, terminating the loop.

Compare that approach for reading numbers to this simpler one:

```

    if (temp < 0)

    ar[i] = temp;
}
```
