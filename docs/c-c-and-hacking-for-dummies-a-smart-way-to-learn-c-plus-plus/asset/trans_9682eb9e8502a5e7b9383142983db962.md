## 引言

数据库充当一个容器。它是一个存储空间，程序员可以在其中以建设性的方式组织数据。请记住，如果你只处理少量数据，则无需创建数据库。例如，处理数百个 Excel 电子表格需要数据库，而五个电子表格即使没有数据库也可以处理。换句话说，在数据库中组织一定数量的数据将帮助你避免复杂的数据管理。

### 深入了解数据库

将数据全部组织在数据库中，可以让你轻松执行查询数据、更新数据和删除旧数据等任务。最重要的是，数据库可以防止因数据存在多个副本而引发的冲突。

例如，假设一家公司必须管理其整体财务支出。基本上，有一个专门的部门负责此事，该部门中有多人。现在，如果这些人各自持有电子表格的副本，那么考虑到人为错误的可能性，要得出无冲突的数据会有些困难。

而数据库则能够以更高的准确性和更少的冲突来存储和组织数据。

另一个帮助你理解数据库的示例是查看手机的通讯录。每个联系人是一条数据，而你的智能手机是数据库。只需轻按几个按钮，你就能轻松找到所需联系人。你也可以轻松编辑每个联系人的详细信息。这种先进的数据管理方式远胜于用纸笔电话簿列出手写联系人。

### 数据库的类型

数据库的不同类型如下：

- 关系型数据库
- 面向对象数据库
- 基于文档的数据库

在本电子书中，我主要关注关系型数据库。不过，如有必要，我也会毫不犹豫地介绍其他两种类型。

你可能已经听说过某种新型数据库，例如 NoSQL。它们被认为属于基于文档的数据库这一类别。这些数据库如今正变得越来越流行，你可能会认为学习它们比学习 SQL 更好。

请不要认为关系型数据库已是过时之物。我们今天仍然使用的许多数据库都采用关系模型。此外，SQL 在关系数据查询方面非常有用。而且，新流行的数据库的查询语言仍然与 SQL 有某种关联，因为它们大多是在 SQL 之后开发的。

换句话说，如果不理解 SQL 就直接跳入新型数据库领域，你会遇到许多挑战。因此，在转向 MongoDB 等其他数据库之前，先学习 SQL 是正确的决定。

话不多说，现在让我带你进入 SQL 的世界。

## 第 1 章 – 深入了解关系模型

结构化查询语言（Structured Query Language，简称 SQL）最初是为关系模型设计的。它是用于定义多个数据之间关系的语言。它也是用于在关系模式中查询数据的数据库编程语言。

那么这一切是从何时开始的呢？

第一个关系数据库创建于 60 年代，该模型的编程主要由数学定义。事实上，这种数据库模型基于元组关系演算和关系代数。

不过，不用担心，你不需要深入学习代数和演算来处理关系数据库。SQL 将使关系数据库编程变得更加容易。

### 表、列和行

在关系数据库中，数据存储在表中。在这种模型中，所有表都有名称。例如，你可以将一个表命名为“people”，同时将另一个表命名为“sales”。这些名称指的是存储在表中的数据类型。换句话说，我们称为“people”的表包含人员数据，而称为“sales”的表包含销售数据。

每个表都有一组列。这些列定义了表中不同的数据片段。这也是关系模型区别于其他类型数据库的地方。你会发现有些数据库将数据整体存储。然而，在关系模型中，所有数据都按列分隔，每列都有名称。每列还可以限制将添加到其中的数据的类别和大小。例如，某些列只能存储字符串，而某些列只能存储数字。分配给每列的限制取决于数据库的创建者。

列还分为必填列和非必填列。必填列意味着表中的每一行都必须具有与该列要求相对应的数据。另一方面，非必填列意味着我们可以在该列下为每行设置 NULL 值。随着你学习 SQL，你会发现 NULL 在数据库编程中有很多用途。

使用行的主要意义在于拥有可检索的数据和可以存储数据的容器。我们为什么要存储数据？仅仅是因为我们希望在将来再次获取这些数据，并且我们只是希望暂时有一个地方让它们存放。因此，这就是数据库的核心思想。

### 键

关系数据库的关键要素之一是键。我们现在知道表有多个列，每列都有名称。每列也具有相关属性。我们可以在列上设置的这些属性之一就是键。

在关系数据库中，我们总是为每一行分配一个主键。这种特殊类型的键用于唯一地确定特定行。这意味着该键的值必须保持唯一，并且在表内不得有任何重复。当且仅当我们的关系模型中有另一个表包含该键时，我们才可以将这两个表合并在一起。

合并两个表时，总是会有没有重复值的主键。合并后，你会注意到表中将出现一个包含这些键的新列。这些键现在称为外键。它们充当第二个表主键的链接，使你能够方便地将两个分离表中的行关联起来。

除了主键和外键，我们还有自然键。自然键是全局性的。这意味着你不能更改它们，因为它们在全世界范围内用于标识单个实体。例如，已出版的书籍总是有自然键，我们称之为 ISBN。每本已出版的书籍都有其唯一的 ISBN，在处理书籍的关系数据库时，你需要将其用作主键。这与处理具有非自然键的数据库（如电子邮件、人员）不同，你需要为每一行自行创建主键。

让我们以人员及其联系方式的数据库为例。我们不能将姓名视为主键。我们也不能将人员的电话号码视为主键。这是因为全球可能有两个或更多人具有相同的联系电话、名字甚至姓氏。因此，我们应该自己创建主键。这就是标识列发挥作用的地方。

标识列充当自动递增的列，随着我们在表中添加数据，它会持续生成唯一的键。键的组合方式并不重要，因为我们所需的只是为数据库中的每个标识提供一个唯一键。
