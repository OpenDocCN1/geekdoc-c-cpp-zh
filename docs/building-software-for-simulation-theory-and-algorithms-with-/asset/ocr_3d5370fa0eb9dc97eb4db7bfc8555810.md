As the set of states, the output function is defined by a recursive descent into the network. The output generated by a state $s_r \in S_r$ is

$$\lambda_r(s_r)=\bigcup_{d\in I_N\setminus Z_{d,N}}\mathcal{N}(\lambda_d(s_d))$$ (3.19)

The function $\lambda_d$ is evaluated directly if $d$ is an atomic model. If $d$ is a network model, then $\lambda_d$ is found by applying Equation 3.19 to it, that is, by finding the output of its resultant. The result of $\lambda_r$ is the collective output, possibly modified by the coupling functions, of the components that influence the network (i.e., that are in $I_N$).

The state transition function of the resultant is defined in a similar way. To determine the next value of an element $s_d$ in the resultant state $s_r$, it is necessary to find the input to the model $d$ and then apply its state transition function. From its siblings, $d$ receives the input

$$x_d^b=\bigcup_{d'\in I_{N\setminus\{N\}} Z_{d',d}(\lambda_{d'}(s_{d'}))$$ (3.20)

where $\lambda_d$ is computed directly if $d'$ is an atomic function or by Equation 3.19 if it is a network model, that is, by using the output function of its resultant. The bag $x_d^b$ does not contain input applied to the network to which $d$ belongs. The next state of the resultant is

$$\delta_r(s_r,x^b)=\delta_r((s_{d_1},s_{d_2},\ldots,s_{d_k}),x^b)=(s'_{d_1},s'_{d_2},\ldots,s'_{d_k})$$ (3.21)

where

$$s'_{d_i}=\begin{cases}\delta_{d_i}(s_{d_i},x_d^b), & \text{if }N\notin I_{d_i}\\\delta_{d_i}(s_{d_i},x_d^b\cup Z_{N,d_i}(x^b)), & \text{if }N\in I_{d_i}\end{cases}$$

The second case in Equation 3.21 handles input to the network that is destined for the component. If $d_i$ is an atomic model, then $\delta_{d_i}$ is calculated directly. Otherwise, Equation 3.21 is used, namely, the state transition function of the resultant of $d_i$.

This set of definitions and Algorithm 3.2 for simulating an atomic model are a complete description of a simulation engine. Nonetheless, the simulation software will be organized somewhat differently. The relatively simple definition given here tells us what a correct implementation of the simulator must do, not how it must do it. Every simulator for discrete-time systems in this sense is identical—two simulators that are given the same model must produce the same result regardless of how they are constructed.
