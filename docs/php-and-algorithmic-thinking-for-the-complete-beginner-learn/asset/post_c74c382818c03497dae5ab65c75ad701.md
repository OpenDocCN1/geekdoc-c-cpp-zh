

As you can see in the trace table, there are three variables named $test in three different memory locations and each one of them holds a completely different value.

Now, let’s see something else. In the next PHP script, the variable $test of the main code is passed to function f1() through an argument that also happens to be a variable named $test. As already stated, even though both variables have the same name, they are actually two different variables in two different locations in main memory! In reality, this means that although f1() alters the value of its variable $test, when the flow of execution returns to the main code, this change does not affect the value of the variable $test of the main code.

```php
<?php
function f1($test) {
    $test++;
    echo $test; //This is the variable of procedure f1().
    //Value 6 is displayed
}

$test = 5;
f1($test);
echo $test; //This is the variable of the main code.
//Value 5 is displayed
?>
```

**Notice:** Please note that variables used in a subprogram “live” as long as the subprogram is being executed. This means that before calling the subprogram, none of its variables (including those in the formal argument list) exists in main memory (RAM). They are all created in the main memory when the subprogram is called, and they are all removed from the main memory when the subprogram finishes and the flow of execution returns to the caller. The only variables that “live” forever, or at least for as long as the PHP script is being executed, are the variables of the main code!

## 41.2 Can a Subprogram Call Another Subprogram?

All the time you’ve been reading this section, you may have had the impression that only the main code can call a subprogram. Of course, this is not true!

A subprogram can call any other subprogram which in turn can call another subprogram, and so on. You can make whichever combination you wish. For example, you can write a function that calls a procedure, a procedure that calls a function, a function that calls another function, or even a function that calls one of the built-in functions of PHP.

The next example presents exactly this situation. The main code calls the procedure `display_sum()`, which in turn calls the function `add()`.

```php
<?php

function add($number1, $number2) {
    $result = $number1 + $number2;
    return $result;
}

function display_sum($num1, $num2) {
    echo add($num1, $num2);
}

$a = trim(fgets(STDIN));
$b = trim(fgets(STDIN));

display_sum($a, $b);
?>
```

> **Notice:** Please note that there is no restriction on the order in which the two subprograms should be written. It would have been exactly the same if the procedure `display_sum()` had been written before the function `add()`.

## 41.3 Passing Arguments by Value and by Reference

By default, variables are passed to subprograms by value. This means that if the value of an argument is changed within the subprogram, it does not get changed outside of it. Take a look at the following example.

```php
<?php
function f1($b) {
    $b++;
    echo $b;    //Value 11 is displayed
}

$a = 10;
f1($a);
?>
```

The value 10 of variable $a is passed to procedure f1() through argument $b. However, although the content of variable $b is altered within the procedure, when the flow of execution returns to the main code this change does not affect the value of variable $a. This is regardless of the fact that the main code and the procedure are using two variables with different names. The same would have happened if, for example, both the main code and the procedure had used two variables of the same name. The next PHP script operates exactly the same way and displays exactly the same results as previous script did.

# file_41.3b.php

```php
<?php
function f1($a) {
    $a++;
    echo $a; //Value 11 is displayed
}

$a = 10;
f1($a);
echo $a; //Value 10 is displayed
?>
```

Still, if you want a subprogram to change the value of its arguments and also reflect this change outside of the subprogram, you must pass the arguments by reference. To do so, you must prepend an ampersand ( & ) at the beginning of the argument name in the formal argument list. Take a look at the following example, in which an ampersand ( & ) is prepended to the argument $b in the formal argument list.

# file_41.3c.php

```php
<?php
function f1(&$b) {
    $b++;
    echo $b; //Value 11 is displayed
}

$a = 10;
f1($a);
echo $a; //Value 11 is displayed
?>
```

> Notice: Please note that the ampersand ( & ) symbol is prepended only to arguments within the formal argument list. Prepending an ampersand to arguments within the actual argument list is syntactically incorrect!

Be careful about one thing though: only variables can be passed by reference. You cannot pass by reference a constant value or an expression, as shown here.

```php
<?php

function f1(&$b) {
    $b++;
}

$x = 9;
f1($x);             //This works fine!

f1(10);             //This produces an error!

f1($x + 1);         //This produces also an error!

?>
```

The second and third calls to the function produce an error. This happens because when the flow of execution returns from the procedure to the main code, the value of variable $b must be assigned back to an argument in the actual argument list. Obviously, this cannot be done when the argument is either a constant value or an expression.

So, as you have probably realized, passing values by reference can provide an indirect way for a subprogram to “return” values. In the next example, the function div_mod() divides variable $a by variable $b and finds their integer quotient and their integer remainder. If all goes well, it returns true; otherwise, it returns false. Moreover, through the two arguments $int_quotient and $int_remainder, the function also indirectly returns the calculated quotient and the calculated remainder.

```php
<?php

function div_mod($a, $b, &$int_quotient, &$int_remainder) {
    $return_value = true;
    if ($b == 0) {
        $return_value = false;
    }
    else {
        $int_quotient = intval($a / $b);
        $int_remainder = $a % $b;
    }
    return $return_value;
}

$val1 = trim(fgets(STDIN));
```
