# Initializing an object directly with an initializer

Besides letting you initialize data members in a constructor, C# enables you to initialize data members directly by using initializers.

Thus you could have the BankAccount class as follows:

```
public class BankAccount
{
    // Bank accounts start at 1000 and increase sequentially
    private static int __nextAccountNumber = 1000;
    // Maintain the account number and balance for each object.
    private int _accountNumber = __nextAccountNumber;
    private double _balance = 0.0;
    // other members ...
}
```

# 282 Replacing the Default Constructor

Here the initializer business. Both _accountNumber and _balance are assigned a value as part of their declaration, which has the same effect as a constructor without having to do the work in it.

Be clear about exactly what's happening. You might think that this statement sets _balance to 0.0 right now. However, _balance exists only as a part of an object. Thus the assignment isn't executed until a BankAccount object is created. In fact, this assignment is executed before every object is created.

Note that the data member _nextAccount is initialized the first time the BankAccount class is accessed — as your in the debugger, that's the first time you access any property or method of the object owning the static data member, including the constructor.

After the static member is initialized, it isn't reinitialized every time you construct a BankAccount instance. That's different from the nonstatic members.

Initializers are executed in the order of their appearance in the class declaration. If C# encounters both initializers and a constructor, the initializers are executed before the body of the constructor.

# New feature: Initializing an object without a constructor

Suppose that you have a little class to represent a Student:

```c
public class Student {
    public string Name { get; set; }
    public string Address { get; set; }
    public double GradePointAverage { get; set; }
}
```

A Student has three public properties, Name, Address, and GradePointAverage, which specify the student's basic information.

Normally, when you create a new Student, you have to initialize its Name, Address, and GradePointAverage properties like this:

```csharp
Student randal = new Student();
randal.Name = "Randall Spar";
randal.Address = "123 Elm Street, Truth or Consequences, NM 00000";
randal.GradePointAverage = 3.5;
```

(Yes, Virginia, there is a Truth or Consequences, New Mexico. My nephew Randall was born there.)

If Student had a constructor, you could do something like this:

```csharp
Student randal = new Student();("Randall Spar", "123 Elm Street, Truth or Consequences, NM 00000", 3.5);
```

Sadly, however, Student lacks a constructor, unlike the default in C# which initializes automatically — which takes no parameters.

In C# 3.0 and later, you can simply that initialization with something that looks suspiciously like a constructor — well, sort of:

```csharp
Student randal = new Student()
{ Name = "Randall Spar";
  Address = "123 Elm Street, Truth or Consequences, NM 00000";
  GradePointAverage = 3.5;
}
```
