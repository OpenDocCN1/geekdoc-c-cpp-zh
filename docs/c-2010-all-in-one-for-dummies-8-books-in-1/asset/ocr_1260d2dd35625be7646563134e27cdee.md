# Garbage collection and the C# destructor

C# provides a method that's inverse to the constructor: the destructor. It carries the name of the class with a tilde (-) in front. For example, the ~BaseClass() method is the destructor for BaseClass.

C# doesn't anything in particular when a memory block first becomes unreachable. A low-priority system task executes in the background, looking for unreachable memory blocks. To avoid affecting performance this "garbage collection" executes only a short period when memory begins with little is happening in your program. As the garbage collector finds unreachable memory blocks, it returns them to the heap.

C# invokes the destructor when it is no longer using the object. The default destructor is the only destructor that can be created because the destructor cannot be invoked directly. In addition, the destructor is always virtual.

Normally, the garbage collector operates silently in the background. The garbage collector takes over control of the program for heap memory begins to run out.

When an inheritance ladder of classes is invoked, destructors are invoked in reverse order of constructors. That is, the destructor for the subclass is invoked before the destructor for the base class.

The destructor method in C# is much less useful than in other object-oriented languages, such as C++, C# has nondeterministic destruction. Understanding what term means — and why it's important requires explanation.

The C destructor for example, ~BaseClass() is nondeterministic because it isn't invoked until the object is garbage-collected, and that can occur long after the object is no longer used. In fact, if the program terminates before the object is found and returned to the heap, the destructor is never invoked. You can't predict when the object will be garbage-collected.

The memory for an object is borrowed from the heap when the program executes the new command, as in NewClass(). This block of memory is reserved as long as any valid references to that memory are by any running programs. You may have variables that refer to the same object.

C programmers seldom use the destructor. C# has other ways to return borrowed resources when they're no longer needed, using a Dispose() method, a topic that exceeds the scope of object. (You can search for the Dispose method in Help.)

The memory is said to be unreachable when the last reference goes out of scope. In other words, no one can access that block of memory after no more references to it.
