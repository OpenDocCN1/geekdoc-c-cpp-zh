# 390 Going Beyond Public and Private: More Access Keywords

You can mark a method inside an internal class as public, though it isn't truly public. A class member can't be more accessible than its class, so the so-called "public" member is just internal.

CIA can still keep its deepest, darkest secrets ultra-hush-hush by declaring them private inside their own owning class. That strategy makes them accessible only in that class.

# Protected: Sharing with subclasses

The main purpose of private is to hide information. In particular, private hides a class's internal implementation details. (Classes who know classes too intimately are the luckiest classes in the world. Classes with a lot of implementation details are said to be "too tightly coupled" with the classes they know too much about. If A is aware of the internal workings of class B, A can rely too much on those details. If they ever change, you end up modifying both classes.)

The other classes and assemblies — know how class B performs its magic, the better. In Chapter 5 of this minify, I use the example of a BankAccount class. The bank doesn't forget folks like me — or forget classes such as A — to be able to change a balance directly. Balance is properly part of the BankAccount class's implementation. It's private. BankAccount provides access to the class — but only through a carefully controlled public interface. In the BankAccount class, the public interface consists of three methods:

+   * Balance: Provides a read-only way to find out the current balance. You can't use Balance to modify the underlying balance.

+   * Deposit(): Lets someone outside the class add to the balance in a controlled way.

+   * Withdraw(): Lets someone (presumably the account owner) subtract from the balance, but within carefully controlled limits. Withdraw() enforces the rule that you can't withdraw more than you have.

Access considerations other how private and public arise in programming. I explain in the previous section how the internal keyword opens a class — but to other classes in its assembly.

However, suppose that the BankAccount class has a subclass, Savings Account. Methods in SavingsAccount need access to balance defined in the base class, of course, although other classes, even in the same assembly, probably don't. Luckily, SavingsAccount can use the same public interface, the same access, as outsiders: using Balance, Deposit(), and Withdraw().
