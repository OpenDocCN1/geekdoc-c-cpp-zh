# Dealing with Web Servers

The other side of this client/server equation is the server. For those of us in ASP.NET, the server will be Internet Information Server fully 99.5 percent of the time. Other servers implement ASP.NET in one fashion or another, but you never see them.

The role of the Web server is to accept requests from clients, whatever is being processed, and then pass a browser-viewable page. This means that the ASP.NET code we write will be turned into HTML and JavaScript by the server. You have less control over what is happening than you might think.

# Getting a PostBack (Hint: It's not a returned package)

A PostBack isn't a returned package from the post office. It is how ASP.NET handles communication with the client and the server so you don't have to.

The first time users request a page in ASP.NET in a given session, usually type the URL into the address bar, or click a link like csaharpdummies.com. The next page loaded, however, is a controlled communication with the server, called a PostBack.

A PostBack is a JavaScript function used in the built-in POST function to send information about the data on the page back to the server. It looks like to the client:

```
javascript:WebForm_PostBackWithOptions(new WebForm_PostBackOptions(&quot;ctl0$phchdmin$btnSave&quot;&quot;&quot;&quot;true,&quot;&quot;&quot;&quot;false,false))
```
