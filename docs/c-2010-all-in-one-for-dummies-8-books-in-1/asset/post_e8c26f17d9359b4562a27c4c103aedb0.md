**Iterated property doesn't mean "a house that keeps getting"**
You can also implement an iterator block as a property of a class - specifically in the get accessor for the property. In this simple class with a DoubleProp property, the property's get() accessor acts as an iterator block to return a stream of double values:

## Looping Around the Iterator Block 161

```cs
//PropertyIterator - Demonstrate implementing a class
// property's get accessor as an iterator block.
class PropertyIterator
{
    double[] doubles = { 1.0, 2.0, 3.5, 4.67 };
    // DoubleProp - A "get" property with an iterator block
    public System.Collections.IEnumerable DoubleProp
    {
        get
        {
            foreach (double db in doubles)
            {
                yield return db;
            }
        }
    }
}
```

You write the DoubleProp method header in the same way as you write the DescendingEvents(1) method header in the iterator examples. The header returns an IEnumerator interface, but as a property it has no parents after the name and it has a get() accessor — though set(). The get() accessor is implemented as a loop that iterates the collection and uses the standard yield to yield up, in turn, each item in the collection Doubles.

Here's the property is accessed in Main():

```cs
// Instantiate a PropertyIterator "collection" class.
PropertyIterator prop = new PropertyIterator();
// Iterate: it produces one double at a time.
Console.WriteLine("\name of double values:\n");
foreach (double db in prop.DoubleProp)
{
    Console.WriteLine(db);
}
```

Well, of course, it isn't quite simple A few "gotchas" are inevitable here:

- * You have to make sure you starting at the beginning of the list.

To make this, the new LinkedList class adds a member, currentNode, with which it tracks the iterator's progress through the list. (That member used to reside in LinkedListIterator class). The currentNode is initially null, so the iterator needs to check for it. If so, it sets currentNode to point to the list's head.

Unless head is null (the list is empty), currentNode is non-null for the rest of the iteration. When the iterator finally reaches the end of the list, it returns null, which signals the foreach loop to stop.

- * Each step through the list to the next node; MoveNext() used to — advance to the next node; while the loop:

```cs
// This what MoveNext() did.
while(currentNode == null) {

// This what Current did.
yield return currentNode... // Parts omitted for a moment

}
```

Most iterator block implementations employ a loop to step through the collection — sometimes even an foreach loop. (But StringChunks does so that it's not the only way).

- * When you step through the list and start to yield data, you have to dig inside the LLNode to extract its stored data. A list node is a storage bin for a string, an int, a Student, and so on. It requires that you yield return not currentNode, but rather, this:

```cs
yield currentNode.Data; // Now complete
currentNode = currentNode.forward;
```

Under the hood, the original enumerator returns the data's as an object. I intentionally designed the original nongeric linked list to be as general as possible — back in the old days before generics. Hence it stores objects.

Now the while loop, with break statement, is doing the work that you had to do with more effort, and the resulting GetEnumerator() method works with foreach, as it did before, in Main().
