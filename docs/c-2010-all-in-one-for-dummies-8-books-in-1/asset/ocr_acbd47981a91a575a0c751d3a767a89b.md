You might have two generic parameters and both need to be constrained.
(Yes, you can have more than one generic parameter — think of Dictionary<TKey, TValue>) Here's how to use two clauses:

```
class MyClass<T, U> : where T: IPrioritizable, where U: new()
```

You see two clauses, separated by a comma. The first constrains Tnto any object that implements the IPrioritizable interface. The second
constrains U to any object that has a default (parameterless) constructor.

# Determining the null value for type T: Default (T)

In case you read the last paragraph in the previous section and are confused, well, each type has (as mentioned above) a default value that signifies "nothing"
ing that type. For ints, doubles, and all other types of, it is 0 or
(0.0). For bool, it's false. And, for all reference types, such as Package, it is null.
With all reference types, the default is null

But because a generic class such as PriorityQueue can be instantiatedfor any data type, it cannot predict the null value to use
the generic's class. For example, if you use the Dequeue() method ofnPriorityQueue, you may face this situation: You call Dequeue() to get
package, but not none. What do you want to return "nothing"?
Because Package is a class type, it should return null. Signals that
caller of the Dequeue() that there was nothing to return (and the caller must
check for a null return value)

The compiler can make sense of the null keyword in a generic class
because the class can be instantiated for all sorts of data types. That's why
Dequeue() uses this line instead:

```
return default(T); // Return the right null for whatever T is.
```

This line tells the compiler to look at it and return the right kind of null
value for that type. In the case of Package, which as class is a reference
type, the right null to return is, well. But, for some other T, it may be
different and the compiler can figure out what to use.
