```
// Stop every 20 lines so that the data doesn't scroll

```

```
// DumpBuffer - Write a buffer of characters as a single line in hex format.
public static void DumpBuffer(byte[] buffer, int numBytes)
{
    for(int index = 0; index < numBytes; index++)
    {
        byte b = buffer[index];
        Console.Write("{0:X2}, ", b);
    }
    Console.WriteLine();
}
```

From the command line, the user specifies the directory to use as an argument to the program. The following command "hex-dumps" each file in the temp directory (including binary files as well as text files):

loopthroughfiles c:\randitemp

If you don't enter a directory name, the program uses the current directory by default. (A hex dump displays the output as numbers in the hexadecimal — base 16 — system. See the nearby sidebar, "Getting hex.")

> Both FileRead and FileWrite read the input from the console, whereas this program takes its input from the command line. I try not to confuse you — I'm trying to show different ways of approaching the same problem.

# Getting hex

Like binary numbers (0 and 1), hexadecimal, or "hex", are fundamental to computer programming. In base 16, the digits are 0 through 9 and A, B, C, D, E, F — A=10, B=11...F=15. To illustrate (using the zero-x prefix to indicate hex):

0x2A = 42 decimal; 2*16 + A*1 (where A=10)
alabetic digits can be uppercase or lowercase: C is the same as c. It's weird, but quite useful, especially when you're debugging or working close to the metal with memory contents.

```
0xD = 13 decimal
0x10 = 16 decimal; 1*16 + 0*1
```
