# Creating an abstract object — not!

Notice about the AbstractInheritance program: It isn't legal to create an AbstractBaseClass object, but the argument to Test() is declared to be of of the class AbstractBaseClass or one of its subclasses. It's the "subclasses" clause that is critical here. The SubClass and SubClass2 objects can be passed because each one is a concrete subclass of AbstractBaseClass. The IS_A relationship applies. This powerful technique lets you write highly general methods.

# Sealing a Class

You may decide that you won't want future generations of programmers to extend a particular class. You can lock the class using the keyword.

A sealed class cannot be used as the base class for any other class.

Consider this snippet:

```

public class BankAccount{
    // Withdrawal -- You can withdraw any amount up to the
    // balance; return the amount withdrawn
    virtual public void Withdraw(decimal withdrawal)
    {

}
```
