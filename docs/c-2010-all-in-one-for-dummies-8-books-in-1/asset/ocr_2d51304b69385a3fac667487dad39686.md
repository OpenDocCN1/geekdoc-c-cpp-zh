Each of these bindings is using a OneWay mode, which means the label content will be bound only once, regardless of the under-lying property being changed.

The Path component of the XAML Binding expression simply tells the XAML processor to take its value from a specific property of its DataContext. The Path value can also express properties that are nested, as in the case of nested objects. In these cases, you use dot notation to reach the desired property, such as Property.SomeOtherProperty.

# Defining a binding with C#

Defining bindings can also be done entirely from both labels in the XAML file. The label markup should now remove the following:

```
<Label xName="lblCarMake" Grid.Row="0" Grid.Column="0" />
<Label xName="lblCarModel" Grid.Row="0" Grid.Column="1" />
```

Modify the GenerateData() method in MainWindow.xaml to implement the Binding definitions in code. To do this, you must instantiate Binding objects directly. The constructor of the Binding object takes in string Path value. Use the BindingOperations class to apply the Binding to the Content property of your labels.
