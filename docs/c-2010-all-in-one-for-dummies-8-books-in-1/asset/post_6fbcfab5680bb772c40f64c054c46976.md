## Jumping head — other levels of security

Understanding this section depends on your having some knowledge of inheritance (see Chapter 6 in this minibook) and namespaces (Chapter 10 in this minibook). You can skip this section if you want, but just know that it's here when you need it.

C# provides these levels of security:

- A public member is accessible to any class in the program.
- A private member is accessible only from the current class.
- A protected member is accessible from the current class and any of its subclasses.
- An internal member is accessible from any class within the same program or assembly.

C# "module", or assembly, is a separately compiled piece of code. either an executable program in an .EXE file or a supporting library module in a .DLL file. A single namespace can extend across assemblies (Chapter 10 in this minibook explains C# assemblies and namespaces and discusses access levels other than public and private.)

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_289_3.png)

- An internal protected member is accessible from the current class and any subclass, and from classes within the same module.

## Why You Should Worry about Access Control

Declaring the internal members of a class public is a bad idea for at least these reasons:

- With all data members public, you can't easily determine when and how data members are being modified. Why not better safety checks into the Deposit() and Withdraw() methods? In fact, even better with these methods? Any method of class can modify these elements at any time. If other methods can access these elements, they almost certainly win.

Your BankAccount program may execute for an hour or before you notice that one of the accounts has a negative balance. The Withdraw() method would have ensured that this situation didn't happen, so obviously another method accessed the balance without going through Withdraw(). Figuring out which method is responsible and under conditions is a problem.

- Exposing all members of the class makes the interface too complicated. As a programmer using the BankAccount class, you don't want to know the internal workings of the class. You just need to know that you can deposit and withdraw funds. It's like a candy machine that has 50 buttons versus just the ones you need.

- Exposing internal elements can lead to corruption of the class rules. For example, my BankAccount class doesn't allow the balance to be negative under any circumstances. That business rule should be isolated within the Withdraw() method. Otherwise, you have to add this check everywhere that the balance is updated.

### Accessor methods

A getter is a method that returns the value of a private field. Conversely, a setter is a method that sets the value of a private field. In C#, properties are used to implement getters and setters. A property is a special member that looks like a data field but can be read or written using the assignment operator.

```csharp
public class BankAccount {
    private double _balance;

    public double Balance {
        get { return _balance; }
        set { _balance = value; }
    }
}
```

The code above defines a property named `Balance` with a getter and a setter. This allows external code to read and set the `_balance` field while keeping the field private.

```csharp
BankAccount account = new BankAccount();
account.Balance = 1000;
Console.WriteLine(account.Balance);
```

However, properties also allow you to add logic to the setter. For example:

```csharp
public class BankAccount {
    private double _balance;

    public double Balance {
        get { return _balance; }
        set {
            if (value < 0) {
                throw new ArgumentException("Balance cannot be negative");
            }
            _balance = value;
        }
    }
}
```

This ensures that the balance can never be set to a negative value. This is one reason why properties are better than using public fields. They allow you to encapsulate your logic and provide a clean interface.

```csharp
public class BankAccount {
    private double _balance;

    public double Balance {
        get { return _balance; }
        set {
            if (value < 0) {
                throw new ArgumentException("Balance cannot be negative");
            }
            _balance = value;
        }
    }

    public void Deposit(double amount) {
        _balance += amount;
    }

    public void Withdraw(double amount) {
        if (_balance - amount < 0) {
            throw new InvalidOperationException("Insufficient funds");
        }
        _balance -= amount;
    }
}
```

In this example, the property controls how the balance is modified. The `Deposit` and `Withdraw` methods provide controlled ways to change the balance, while the `Balance` property allows access to the current value.

```csharp
public class Program {
    public static void Main(string[] args) {
        BankAccount account = new BankAccount();
        account.Balance = 1000;
        Console.WriteLine("Initial balance: {account.Balance}");

        account.Deposit(500);
        Console.WriteLine("Balance after deposit: {account.Balance}");

        account.Withdraw(200);
        Console.WriteLine("Balance after withdrawal: {account.Balance}");

        try {
            account.Withdraw(2000);
        } catch (InvalidOperationException ex) {
            Console.WriteLine($"Error: {ex.Message}");
        }
    }
}
```

The code above shows how the `BankAccount` class can be used. The properties and methods provide a safe way to interact with the account.
