A few "gotchas" are inevitable here:

+   * You have to make sure you starting at the beginning of the list.

To make this, the new LinkedList class adds a data member, currentNode, with which it tracks the iterator's progress through the list. (That member used to reside in the LinkedListIterator class). The currentNode is initially null, so the iterator needs to check for it. If so, it sets currentNode to point to the list's head node.

Unless head is null (the list is empty), currentNode is non-null for the rest of the iteration. When the iterator finally reaches the end of the list, it returns null, which signals the foreach loop to stop.

+   * Each step through the list to the next node; MoveNext() used to — advance to the next node; while the loop:

```
// This what MoveNext() did.
while(currentNode == null) {

// This what Current did.
yield return currentNode... // Parts omitted for a moment
currentNode = currentNode.forward;
}
```

Most iterator block implementations employ a loop to step through the collection — sometimes even an foreach loop. (But StringChunks does so that it's not the only way).

+   * When you step through the list and start to yield data, you have to dig inside the LLNode to extract its stored data. A list node is a storage bin for a string, an int, a Student, and so on. It requires that you yield return not currentNode, but rather, this:

```
yield currentNode.Data; // Now complete
currentNode = currentNode.forward;
```

Under the hood, the original enumerator returns the data's as an object. I intentionally designed the original nongeric linked list to be as general as possible — back in the old days before generics. Hence it stores objects.
