# Model repositories

The repository pattern is commonly used for Life of Business applications
to move data between the data store and the model classes. For the sample
ViewModel, I've included a very simple interface (shown in Listing 4-18)
that has a GetAll and an Update method (not remotely a
complete repository, but all that we need for the examples). Note the
of generics to enforce strict typing in the repositories that implement this
interface.

# Listing 4-18: The Repository Interface

```
public interface IRepository<T>
{
    IList<T> GetAll();
    bool Update(T model);
}
```

The repositories in the sample return hard-coded values instead of con-
ecting to a data store. It's a common practice to create classes that are used
only for testing or prototyping. The convention I prefer is to call out
by appending Fake to the name (as shown in Listing 4-19) so other develop-
ers have no doubt about their intended purpose. Additionally, the examples
er implement the Update methods because they aren't used for the
ViewModel samples shown.
