# A Method Example for Your Files

In this section, I divide the monolithic CalculateInterestTable from Book I, Chapter 5 into several reasonable methods; the demonstration how the proper definition of methods can help make a program easier to write and understand. The process of dividing working code is by refactoring, and Visual Studio 2010 produces a handy Refactor menu that automates the most common refactorings.

REMEMBER

I explain the exact details of the method definitions and method calls later in sections of this chapter. This example simply gives an overview.

By reading the comments with the C# code, you should be able to get a good idea of a program's intention. If you cannot, you aren't commenting properly. Conversely, if you can't strip out comments and understand the intention from the method and variable names, you aren't naming your methods clearly enough or aren't making them small enough (or both). Smaller methods are preferable, and using good method names beat comments (That's why real-world code has fewer comments than the code examples in this book. I comment more heavily here to explain more).
