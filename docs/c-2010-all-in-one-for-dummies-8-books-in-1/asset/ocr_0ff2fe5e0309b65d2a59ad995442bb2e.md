# Letting the C# Compiler Infer Data Types 43

If you've worked with a scripting language such as JavaScript or VBScript you may have gotten used to all-purpose-in-one data types. VBScript calls them Variant data types — a Variant can be anything. But does var in C# signify a Variant type? Not at all. The object you declare with var definitely has a C# data type, such as int, string, or double. You just don't have to declare what it is.

What's really lurking in the variables declared in this example with var? Take a look at this:

```
var aString = "Hello C# 3.0";nConsole.WriteLine(aString.GetType().ToString());
```

The jumbo dump in WriteLine statement calls the String. GetType() method on aString to get its C# type. Then it calls the resulting object's ToString() method to display the object's type (Yadda yadda). Here's what you see in the console window:

System.String.

Most of the time I recommend you don't use var. Save it for when it's necessary. Being explicit about the type of a variable is clearer to anyone reading your code using var. However, common usage in the C# world may change so that everybody uses var all the time, in spite of my good advice. In that case, you can go along with the crowd.

You see examples later in var is definitely called for, and I use it of the time throughout this book, even where it's not strictly necessary. You need to see it, and use it, to internalize it. I'm still getting to use it myself (It can't help me if I'm a slower learner).

You can see var used in other ways: with arrays and collections of data, in Chapter 6 of this minibook, and with anonymous types, in Book II. Anonymous? You can't wait.

What's more, a new type in C# 4.0 is even more flexible than var: The dynamic type takes var a step further.

The var type causes the compiler to infer the type of the variable based on expected input. The dynamic keyword does this at runtime, using a totally set of tools called the Dynamic Language Runtime. You can find more about the dynamic type in Book VIII.
