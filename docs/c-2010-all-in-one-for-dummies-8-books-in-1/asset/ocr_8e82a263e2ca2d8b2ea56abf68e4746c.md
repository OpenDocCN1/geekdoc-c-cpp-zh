# Classy Generics: Writing Your Own 185

Did you notice the where clause earlier? This boldfaced where clause speci-
fies that T must implement IPrioritizable. That's the enforcer. It means,
Make sure that T implements the IPrioritizable interface — or else!

You specify constraints by using one or more of the following elements (sep-
arated by commas) in a where clause:

+   * The name of a required base class that T must derive from (or be).
* The name of an interface that T must implement, as shown in the premi-\ous example.
* You can see more — Table 8-1 has the complete list.

For information about these constraints, look up Generics [C#], constraints in
The Help index.

| Constraint | Meaning | Example |
|---|---|---|
| MyBaseClass | T must be, or extend, MyBaseClass. | where T: MyBaseClass |
| IInterface | T must implement IInterface. | where T: IInterface |
| struct | T must be any value. | where T: struct |
| class | T must be any reference type. | where T: class |
| new() | T must have a parameterless constructor. | where T: new() |

The struct and class options in particular. Specifying struct means
t T can be any value type: a numeric type, a char, a bool, or any object
declared with the struct keyword. Specifying class means T can be
an reference type: any class type.

These constraint options give you quite a bit of flexibility for making your
ew generic class behave just as well as you want. And a well-behaved class is a
peacock beyond price.

You're not limited to just one constraint, either. Here's an example of a hypo-	hetical generic class declared with multiple constraints on T:

```
class MyClass<T> : where T: class, IPrioritizable, new()
{ 
 }
```
