## Running with the Dynamic Language Runtime

There is more to dynamic languages than just the dynamic typing. You can do some powerful things. Like all power, you have to be careful not to misuse it.

The Dynamic Language Runtime — shown in Figure 1–1 — is a library added to the .NET Framework specifically to provide for adding dynamic languages (like Ruby) to the Visual Studio fold (like IRONRuby), or to add dynamic language features to extend existing static languages (like C# 4.0).

| IronRuby | IronPython | C# | Visual Basic |
|---|---|---|--|
| Dynamic Language Runtime | | | |
| Expression Trees | Call Site Caching | Dynamic Object Interoperability | | |
| Common Language Runtime (CLR) | | | |

**Figure 1-1:** The Dynamic Language Runtime.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_802_0.png)

The runtime helps the compiler to construct code in the compiled assembly that will make a lot of choices dynamically. The code block at the end of the preceding section is an example of the simplest kind.

The DLR assisted in the creation of IRONRuby, which makes it possible to code in Ruby — the current dynamic language — right in Visual Studio. Of course, because the DLR enables C# to take on dynamic language features, much that you can do in Ruby you can now do in C#.

## Dynamic Ruby

Ruby takes advantage of its dynamic roots in its implementation of the Trabb Pardo-Kunto algorithm. Don't be put off the name — this is just a straightforward problem that can be solved by computer code.

The program needs to read 11 numbers from an input device — in our case, the console's `ReadLine` method. It stores them in an array. Then, it processes the array backward — starting from the last value — with some function. If the value doesn't exceed some arbitrary threshold, it prints the result.

The program looks like this in Ruby:

```ruby
class TPK
  def f( x )
    return Math.sqrt(x.abs) + 5*x ** 3
  end
```

```ruby
def main
  Array.new(11) { gets.to_i }.reverse.do |x|
    y = f(x)
    puts "#{x} #{(y>400) ? 'TOO LARGE' : y"
  end
end
```

This isn't a Ruby book, and that fact it isn't lost on me. Nonetheless, this is the best dynamic language that I can use for an example — bare-bone.

Two functions are: f and main. Main accepts 11 numbers from the console and moves them to an integer array (that's what gets.to_i does). For each value in the array, it sets y equal to f(x) and then sees if it is higher than our arbitrary value. If it prints "TOO LARGE"; otherwise, it prints the numbers.

Why is dynamic important for this algorithm? It isn't. Could you not all statically typed? The dynamic bit has an impact, though.

First, f(x) doesn't care what x is. The program assumes that whatever comes in gets changed to an integer at gets.to_i, but the function itself is agnostic. This is good and bad, because if we happen to give it a string or some other type, it will fail.

The array itself isn't typed, either. This can have benefits, because it is possible to drop a differently typed value there if you know you are just going to write to the screen.
