## Nesting Loops

An inner loop can appear within an outer loop, in this way:

```
for( . .some condition . .)
  for( . .some other condition . .)
    // do whatever . . .
}
```

The inner loop is executed to completion after each pass through the outer loop. The loop variable (such as year) used in the for loop isn't defined outside the inner loop's scope.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_131_2.png)

A loop contained within another loop is a nested loop. Nested loops "cross." For example, the following code won't:

```
do // Start a do..while loop.
  for( . . . ) // Start some for loop.
    while( . . . ) // End do..while loop.
  // End for loop.
}
```

I'm not sure what this chunk would mean, but it doesn't matter because the compiler tells you that it's not legal anyway.

## Don't goto Pieces 107

A break statement within a nested loop breaks out of the inner loop only. In the following example, the break statement exits loop B and goes back into loop A:

```
// for loop A
for(. .some condition .)
{
    // for loop B
    for(. .some condition .)
{
        // do whatever
        if (something is true)
            break; // Breaks out of loop B and not loop A
    }
}
```

C# doesn't have a break command that exits both loops simultaneously.

That's not a big limitation as it sounds. In practice, the often-complex logic contained within nested loops is better encapsulated in a method. Executing a return from any of the loops exits the method — thereby out of all loops, no matter nested they were. We describe methods and the return statement in Chapter 7 of this minibook.

## Don't goto Pieces

You can transfer control in an unstructured fashion by using the goto statement. It's followed by one of these items:

- * A label
- A case in a switch statement
- The keyword default (the default clause of a switch statement)

The idea behind the latter two items is to "jump" from one case to another.

This snippet demonstrates how the goto statement is used:

```
// If the condition is true .
if (a > b)
{
    . .control passes unconditionally from the goto to the label.
    goto exitLabel;
}
// whatever other code goes here
exitLabel:
// Control continues here.
```

## 108 Don't goto Pieces

The goto statement is unpopular for the very reason that makes it such a powerful control: It is almost completely unstructured. Tracking the flow of control through anything larger than a trivial piece of code can be difficult if you use goto. (Can you say "spaghetti code?")"

Religious wars have sprung up over the use of the goto statement. In fact, the C# language itself has been criticized for its inclusion of the control. Actually, goto is neither harmful nor necessary. Because you can almost always avoid using goto, I recommend staying away from it, other than occasionally using it to link two cases within a switch statement, like this:

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_133_0.png)

```
switch(n) // This example becomes gnarly in the logic department . . .
{
    case 0:
        // Do something for the 0 case, then . . .
        goto 3; // jump to another case; no break statement needed.
        break;
    case 1:
        // Do something for the 1 case.
        break;
    case 3: // Case 0 jumps to here after doing its thing.
        // Add some case 3 stuff to what case 0 did, thus "chaining" the cases.
        break;
    default:
        // Default case.
        break;
}
```

Don't get addicted to goto, Really.

Simple one-value variables of the sort you may encounter in this book fall a bit short dealing with lots of the same kind: ten ducks instead of just one, for example. C# gives you a quote of collection classes, and they come in various shapes, such as flexible lists (like strings of beads), queues (like the line to buy with your Spider-Man tickets), stacks (like the semistack of junk on someone's desk), and more. The built-in class Array is a structure that can contain a series of elements of the same type (all int values and double values, for example, or Vehicle objects and Motor objects — you meet these latter sorts of objects in Chapter 7 of thisbook).

## The argument for the array

Consider the problem of averaging a set of six numbers. Each of the six numbers requires its double storage:

```
double d0 = 5;
double d1 = 2;
double d2 = 7;
double d3 = 3.5;
double d4 = 6.5;
double d5 = 8;
```

(Averaging int variables can result in rounding errors, as described in Chapter 2 of thisbook.)

Computing the average of those variables might look like this:

```
double sum = d0 + d1 + d2 + d3 + d4 + d5;
double average = sum / 6;
```

Listing each element by name is tedious. Okay, maybe it’s not tedious when you have only 6 numbers to average, but imagine averaging 600 (or even 6 million) floating-point values.

## The fixed-value array

Fortunately, you don’t need to name each element. C# provides the array structure that can store a sequence of values. Using an array, you can put all your doubles into one variable, like this:

```
double[] doublesArray = (5, 2, 7, 3.5, 6.5, 8, 1, 9, 3);
```

You can also declare an empty array without initializing it:

```
double[] doublesArray = new double[6];
```

This line allocates space for six doubles but doesn’t initialize them.
