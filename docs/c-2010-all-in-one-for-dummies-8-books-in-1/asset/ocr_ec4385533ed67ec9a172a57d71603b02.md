In this simple example, you're putting all code in the form class. (The form is your window; here, named Form1—responsible for all things graphical.) Generally, you should put all "business" code—the code that does your calculations, data access, and other important work—in other classes. Reserve the form code that's intimately involved with displaying elements on the form and responding to its controls. I break that rule here—but delegate works no matter where its callback method is.

Now, in design mode, add a handler method for each button:

+   1. On the form, double-click the new button class.

This action generates a method in the "code behind the form" (or, simple, "the code-behind")—the code that makes the form work. It looks like this—when you bold the code:

```
private void button2_Click(object sender, EventArgs e)
{
    this.Click(); // 'this' refers to the Form class.
}
```

![](bbox=[0.158, 0.538, 0.203, 0.603])

+   2. Double-click the new Click to Start button to generate its handler method, which looks like the following in the code-behind:

```
private void button1_Click(object sender, EventArgs e)
{
    UpdateProgressBar callback = UpdateProgressBar(this);
    DoUpdate();
    // Do something that needs progress reports.
    // This passes a delegate instance that knows how to update the bar.
    DoSomething(callback);
    // Clear the bar so that it can be used again.
    progressBar.Value = 0;
}
```

+   3. Add the following DoUpdate() method to the form class:

```
private void DoUpdate()
{
    progressBar.PerformStep(); // Tells progress bar to update itself
}
```
