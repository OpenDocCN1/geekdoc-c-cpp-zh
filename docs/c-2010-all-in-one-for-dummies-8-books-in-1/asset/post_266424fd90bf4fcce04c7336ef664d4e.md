The CalculateInterestTable program begins by reading the principal and interest values from the user and checking to make sure they're valid. CalculateInterestTable then reads the number of years over which to iterate and stores this value in the variable duration.

Before entering the while loop, the program declares a variable year, which initializes it to 1. This will be the "current year" — that is, this number changes each year as the program loops. The key to the loop lies in the last line within the block. The statement year = year + 1; increments year by 1. If year begins with the value 3, its value will be 4 after this expression. This increment moves the calculations from one year to the next.

After the year has been incremented, control returns to the top of the loop, where the value year is compared to the requested duration. In the sample run, if the year is less than 10, the calculation continue. Most loops follow this basic principle of incrementing a count until it exceeds a previously defined value.

The counting variable year in CalculateInterestTable must be declared and initialized before the while loop in which it is used. ## Doing the do .. while loop

A variation of the while loop is the do . . while loop. In this example, the condition isn't checked until the end of the loop:

Getting into the Program Flow

```cs
int year = 1;
do{
    // . . some calculation . . .
    year = year + 1;
} while (year < duration);
```

In contrast to the while loop, the do . . while loop is executed at least once, regardless of the value of duration.

## Breaking up is easy to do

You can use two special commands to bail out of a loop: break and continue. Executing the break command causes control to pass to the first expression immediately following the loop. The similar continue command passes straight back up to the conditional expression at the top of the loop to start over and get it right this time.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_124_1.png)

I have rarely used continue in my programming career, and I doubt that many programmers even remember it. Don't forget about it; it might be a trick question in an interview or a crossword puzzle.

Suppose you want to take your loop out of the bank as soon as the principal exceeds a certain number of times the original amount, regardless of the duration in yours. (After, how much do you really need?) You could easily accommodate this amount by adding the code within the loop:
