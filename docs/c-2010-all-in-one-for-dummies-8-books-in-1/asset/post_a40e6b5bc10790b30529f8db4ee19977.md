BindingOperations is a helper class provided to you by WPF. It has static methods that give you the power to add and clear data binding definitions on application elements.

The following code shows how to define the Binding objects, and assign the binding to the Content of the labels:

```csharp
private void GenerateData() {
    Car car1 = new Car() { Make = "Athlon", Model = "XYZ" };

    Binding makeBinding = new Binding("Make");
    makeBinding.Mode = BindingMode.OneTime;
    BindingOperations.SetBinding(lblMake,
    Label.ContentProperty, makeBinding);

    Binding modelBinding = new Binding("Model");
    modelBinding.Mode = BindingMode.OneTime;
    BindingOperations.SetBinding(lblModel,
    Label.ContentProperty, modelBinding);

    this.DataContext = car1;
}
```

Run the application and observe that it runs the same way as your bindings were defined using XAML.

Dependency properties are typically defined with the suffix "Property", but you only see them when navigating MSDN documentation and accessing them through code. In XAML, you specify dependency property attributes by dropping the "Property" suffix off the name.

- 7. Click the Change Data Context With Code-Behind button.

Hmmm. Nothing is happening. What is up with that? If you click on the Show CurrentDataContext Value button, you will see the properties that have been changed. Because you're using a TwoWay binding, your settings should automatically update your UI, right? Wrong! This is another feature of WPF, the context of INotifyPropertyChanged comes into play.

INotifyPropertyChanged is a simple interface that allows your objects to raise an event that notifies its subscribers (namely your application) that a property value on the object has changed. Client applications subscribe to these events and update the user interface with the new values when changes occur.

A similar interface exists for collections — the INotifyCollectionChanged. WPF provides a generic class called ObservableCollection<T> that already implements INotifyCollectionChanged. When creating an ObservableCollection or your own collection implements INotifyCollectionChanged, you need to ensure that the objects that will be contained within the collection also implement the INotifyCollectionChanged interface.

The INotifyPropertyChanged interface contains a single event that must be implemented. This event called PropertyChanged, and its parameters are the object that owns the property that has changed (the sender), and the string name of the property that has changed.

- 8. Open your class, and implement the INotifyPropertyChanged interface.

The interface is located in the System.ComponentModel namespace (using System.ComponentModel; at the top of your class). Implementing this interface adds the following event to the Car class:

```csharp
public event PropertyChangedEventHandler PropertyChanged;
```

In order to be notified of the changes that occur in Car objects, the PropertyChanged event must be fired each time a property value has changed.

- 9. To implement this in the Car class, create a helper method called NotifyPropertyChanged that takes in a string property name and fires the PropertyChanged event for the object instance and the name of the property that has changed:

```csharp
private void NotifyPropertyChanged(string propertyName)
{
    if (PropertyChanged != null)
    {
        this.PropertyChanged(this,
            new PropertyChangedEventArgs(propertyName));
    }
}
```

- 10. Now you need to modify the Set methods in each of the public properties on the Car object to call the NotifyPropertyChanged helper method each time the property value has changed. Edit the public properties like this:

```csharp
public string Make
  get { return _make; }
  set {
    if (_make != value)
      _make = value;
      NotifyPropertyChanged("Make");
    }
  }
```

```csharp
public string Model
  get { return _model; }
  set {
    if (_model != value)
      _model = value;
      NotifyPropertyChanged("Model");
    }
  }
```

- 11. Run the application again.

Now when you click the Change Data Context with Code-Behind button, the changed values get reflected automatically in the TextBox elements. This is due to the combination of the TwoWay binding mode as well as the implementation of INotifyPropertyChanged. (See Figure 3-3.)
