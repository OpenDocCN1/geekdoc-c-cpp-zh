# Compounding the confusion with compound logical operations

The bool variables have another set of operators defined just for them, as shown in Table 4-3.

| Table 4-3 | The Compound Logical Operators |
| Operator | Is True If |
| !a | a is false (also known as the "not" operator). |
| a & b | a and b are true (also known as the "&" operator). |
| a | b | Either a or b both are true (also known as an and/or b). |
| a ^ b | a is true or b is true not both (also known as a xor b). |
| a && b | a and b are true with short-circuit evaluation. |
| a || b | a is true or b is true with short-circuit evaluation. (I discuss short-circuit evaluation in this section.) |

![](bbox=[0.116, 0.546, 0.193, 0.599])

The ! (NOT) is logical equivalent of the minus sign. For example, !a (read "not a") is true if a is false and if a is true. Can be true?

The next two operators are in the straightforward. First, a & b is true only if a and b are true. And a | b is true if either a or b is true (or both). The exclusive or (xor) operator, or ^, is sort of an odd beast. An exclusive is true if either a or b is true but not both a and b are true.

All three operators produce a bitwise value as your result.

The & , and ^ operators have a bitwise operator version. When applied to variables, these operators perform their magic on a bit-by-bit basis. Thus 6 & 3 is 2 (0110₂ & 0011₂), 6 | 3 is 7 (0110₂ | 0011₂), and 6 ^ 3 is 5 (0110₂ ^ 0011₂). Binary arithmetic is could but beyond the scope of this book. You can search for it at your search engine.

The remaining two logical operators are similar to, but subtly different from, the first three. Consider the following example:

```
bool b = (boolExpression1) & (boolExpression2);
```
