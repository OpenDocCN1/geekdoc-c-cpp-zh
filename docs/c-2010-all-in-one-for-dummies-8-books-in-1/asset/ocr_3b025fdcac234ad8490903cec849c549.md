# Using some better fishing gear: The using statement

Now that you've seen FileStream and StreamWriter in action, I should point out the most usual way to do stream in C# — inside a using statement:

```
using (<resource>)
// Use the resource.
```

The using statement is a construct that automates the process of cleaning up after a stream. On encountering the curly brace of the using block, C# manages "flushing" the stream and closes it for you. A flush is to push any bytes left over in the stream's buffer out to the associated file before it gets closed. Thinking of a handle to handle the last water out of ... trout stream.) Using using eliminates the common error of forgetting to flush and close a file after writing to it. Don't leave files lying around.

Without using, you'd need to write:

```
FileStream stream = null;
writer writer = null;
try {
  // Create and use the stream, then ...
nfinally {
  stream.Flush();
  stream.Close();
  stream = null;
}
```

Note how I declared the stream and writer above the try block (so they're visible throughout the method). I also declared the fileStream and writer using abstract base classes rather than the concrete types FileStream variables and StreamWriter. That's a good practice. I set them to null so the compiler won't complain about uninitialized variables.
