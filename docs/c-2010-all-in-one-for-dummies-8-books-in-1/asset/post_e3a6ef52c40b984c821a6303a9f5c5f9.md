# Dealing with Web Servers

The other side of this client/server equation is the server. For those of us in ASP.NET, the server will be Internet Information Server 99.5 percent of the time. Other servers implement ASP.NET in one fashion or another, but you never see them.

The role of the Web server is to accept requests from clients, whatever is being processed, and then pass a browser-viewable page. This means that the ASP.NET code we write will be turned into HTML and JavaScript by the server. You have less control over what is happening than you might think.

# Getting a PostBack (Hint: It's not a returned package)

A PostBack isn't a returned package from the post office. It is how ASP.NET handles communication with the client and the server so you don't have to.

The first time users request a page in ASP.NET in a given session, usually type the URL into the address bar, or click a link like csaharpdummies.com. The next page loaded, however, is a controlled communication with the server, called a PostBack.

A PostBack is a JavaScript function used in the built-in POST function to send information about the data on the page back to the server. It looks like this to the client:

```javascript
javascript:WebForm_PostBackWithOptions(new WebForm_PostBackOptions("ctl0$phchdmin$btnSave","&quot;&quot;true,"&quot;&quot;false,false))
```

Quite a change from a URL, huh? To make what I mean more clear, let's go back in time.

# Looking back at how things used to be

Back in the day, Web servers supported GETs and POSTs. What's more, they still support GETs and POSTs.

A GET is a request for a page, using the URL. You can send data in the URI (after a question mark in the text of that) but that's all you are sending — nothing from the page itself goes. A GET request looks like this:

```
GET /fiddler/updatecheck.asp?a=False HTTP/1.1
User-Agent: fiddler/2.2.4.6 (.NET 2.0.50272.4918; Microsoft Windows NT 6.1.7100)
Pragma: no-cache
Host: fiddler2.com
Connection: Close
```

A POST sends values from a form. The form can be invisible, but it has to be there. POSTs are a lot bigger than GETs and have a set format that is hard to navigate at times. Here is an example:
