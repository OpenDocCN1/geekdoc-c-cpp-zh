# Executable or library?

C# can produce two assembly types:

- Executable (.EXE): A program in its own right that contains a Main() method. You can double-click a .EXE file in Windows Explorer, for example, and cause it to run. This book is full of executables in the form of console applications. Executables often allow supporting code from libraries in other assemblies.

- Class library (.DLL): A compiled library of functionality that can be used by other programs. All programs in this book also use libraries. For example, the System namespace (the home of classes such as String, Console, Exception, Math, and Object) exists in a set of library assemblies. Every program needs System classes. Libraries are housed in DLL assemblies.

Libraries are not executable — you can't make them directly. Instead, you must call their code from an executable or another library. The Common Language Runtime (CLR), which runs C# programs, loads library assemblies into memory as needed.

The important concept to know is that you can easily write your own class libraries. I show you in the later section "Putting Your Classes into Class Libraries."

# Assemblies

Assemblies, which are the compiled versions of individual projects, contain the project's code in a special format, along with a bunch of metadata, or detailed information about classes in the assemblies.

I introduce assemblies in this section because they round out your understanding of the C# build process — and discussion of assemblies and access keywords such as protected and internal (it covers namespaces and these two access keywords later in this chapter). Assemblies also play a big part in understanding class libraries. It's covered in the later section "Putting Your Classes into Class Libraries."

The C# compiler converts the project's code to Common Intermediate Language (usually called IL) that's stored in the appropriate type of assembly. IL represents assembly assembly language (one step beyond the 1s and 0s used in machine language) that hardcore programmers have used for decades to get down "close to the metal" because their higher-level languages don't do what they needed or the compilers couldn't produce the most efficient code.

One major consequence of compiling from .NET to IL, regardless of language, is that a program can use assemblies written in different languages. For example, a C# program can call methods in an assembly originally written in Visual Basic or C++ or the C# program can subclass a VB class.

You can take a look at IL by running the Ildasm.exe tool in the .NET Software Development Kit (SDK) or the Reflector tool that I point you to at csharp102.info. Select a .EXE or .DLL assembly file to view its code as IL. A Visual Studio solution can contain any number of projects.

## Executables

You can run executable assemblies in a variety of ways:

- Run in Visual Studio: Choose Debug;Start Debugging (F5) or Debug;Without Debugging (Ctrl+F5).
- Double-click the assembly file (.EXE) in Windows Explorer.
- Right-click the file in Windows Explorer and choose Run or Open from the pop-menu.
- Type the assembly's name (and path) into a console window.
- If you drag the files to the executable file in Windows Explorer, I show you this in the article "Passing Arguments to a Program" at csharp102.info, check the Articles tab and look in the section "C Techniques."

Visual Studio can contain multiple projects — .DLL and .EXE. A solution contains more than one .EXE project, you must tell Visual Studio which project is the start-project. That one runs from the Debug menu. Specify a start-up project, right-click that project in Solution and choose Set As Start-up Project. The start-project's name appears in bold in Solution Explorer.

Think of a solution containing two .EXE assemblies as two separate programs that happen to use the same library assemblies. For example, you might have in a solution a console executable and a Windows Forms plus some libraries. If you make the console app start-up project and compile the code, you produce a console app. If you make the Windows Forms app start-up — well, you get the idea.

## Class libraries

A library contains one or more classes, usually those that work in some way. Often, the classes in a library are in their own namespaces. (I explain namespaces later in this chapter). You may build a library of math routines, a library of string-handling routines, and a library of input/output routines, for example.

Sometimes, you build a whole solution that is nothing but a class library, rather than a program that can be executed on one. (Typically, while developing this type of library, you also build an accompanying .EXE project, or driver, with which to test your library during development. But when you release the library for programmers to use, you just release the .DLL [not the .EXE] — documentation for it that's generated by the XML comments are described in Book IV, which is all about Visual Studio.

# Putting Your Classes into Class Libraries

The simplest definition of a class library project is one whose classes contain no Main() method. Can that definition be correct? Can the existence of Main() distinguishes class library from an executable. C# libraries are much easier to write and use than similar libraries were in C or C++.

The following sections explain the basic concepts involved in creating your own class libraries. Don't worry; C# does the heavy lifting. Your end of it is quite simple.

Even the free Visual# 2010 Express Edition can now create class libraries. It needed to use a small hack to make it work.

## Creating the projects for a class library

You can create the files for a new class library project and its driver in either of two ways:

- Create the class library project first and then add the driver project to its solution. You might take this approach if you were writing a standalone-class library assembly. I describe how to create the class library project in the next section.
- Create a driver program first and then add one or more library projects to its solution. Thou might first create the driver program as a console application or a graphical Windows Forms (or Windows Presentation Foundation) application. Then you would add class library projects to that solution.

## Creating a stand-alone class library

If your purpose is to develop a stand-alone class library that can be used in various other programs, you can create a solution that contains a class library project from scratch — here's how it is:

- 1. Create a new project.

- 2. When you pick the template to base it on in the New Project dialog box, select Class Library (rather than, Console Application).
