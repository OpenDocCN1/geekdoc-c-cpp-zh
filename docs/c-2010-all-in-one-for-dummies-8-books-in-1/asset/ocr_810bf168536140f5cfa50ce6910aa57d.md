# 436 Going Where the Fish Are: The File Stream

FileStream isn't the only class that can perform I/O. However, it represents your good ol' basic file that covers 90 percent of your file I/O needs. This primary class is the one described in this chapter. If it's good enough for C#, it's good enough for me.

The stream concept is fundamental to C I/O. Think of a parade, which "streams" by you, the clowns, and the floats, and a band and two horses, a troupe of Customer objects, a BankAccount, and so on. Viewing a file as a stream of bytes (or characters or strings) is much like a parade. You "stream" the data in and out of your program.

The .NET classes used in C# include an abstract base class and subclasses, for working with files, over a network, or already sitting as chunks of data in memory. Some classes specialize in encrypting and decrypting data, some are provided to help speed I/O operations that might be slow using one of the other streams, and you're free to extend class with your own subclass if you come up with a great idea for a new stream (I warn you that extending Stream is arduous). You give a tour of the stream classes in the later section Exploring More Streams than Lewis and Clark.

# Readers and writers

FileStream, the stream class you probably use most, is a basic class. Open a file, read a block of bytes, and write a block—that's all about you. But reading and writing files down the byte level is a lot of work, something I eschew unfortunately. Fortunately, the .NET library introduces the notion of "readers" and "writers." Objects of these get incredibly simple (and other) I/O.

When you create a new reader (of one of several available types), you associate a stream with it. It is immaterial to the reader whether the stream connects to a file, a block of memory, a network location, or the Mississippi. The reader requests input from the stream, which it gets from—well, whenever. Using readers is quite simple, except that you're sending output to the stream rather than asking for input. The stream sends it to a specified destination. Not always.

The System.IO namespace contains classes that wrap around FileStream (or other streams) to give you easy access and warm feeling:

+   ** StreamReader/TextWriter**: A pair of abstract classes for reading characters (text). These classes are the base for two subclasses: StreamReader/StringWriter and StreamReader/StreamWriter.

Because StreamReader and StreamWriter are abstract, you'll use one of their subclass classes, usually StreamReader/StreamWriter, to do actual work. I explain abstract classes in Book II.
