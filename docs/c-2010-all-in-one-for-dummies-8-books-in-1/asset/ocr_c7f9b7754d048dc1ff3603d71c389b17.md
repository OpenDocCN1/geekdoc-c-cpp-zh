All static data members are initialized before the first MyObject() constructor runs. In this case, C# populates _staticObj with a newly created MyObject before passing control to the MyObject constructor. This step accounts for the third line of output.

+   4. The constructor for MyObject is given control. It outputs the initial message, and then notes that the static member was already constructed before the MyObject() constructor:

```
(Static data member constructed before this constructor).
```

+   5. After announcing its intention to Now create nonstatic data member dynamically, the MyObject constructor creates an object of class MyObject using the new operator, generating the same MyObject constructing message as the MyOtherObject constructor.

+   6. Control returns to the MyObject constructor, which returns to Main().

# Executing the constructor from the debugger

Executing the same program from the debugger is illuminating:

+   1. Rebuild the program: Choose the command Build:Build DemonstrateCustomConstructor.

+   2. Before you starting the program from the debugger, set a breakpoint in the Console.WriteLine() call in the MyObject constructor.

To set a breakpoint, click in the gray trough on the left side of the editor window, next to the line at you want to stop.

Figure 5-1 shows my display with the breakpoint set: The dark ball is in the trough.

+   3. Rather than choose Debug:Start Debugging, choose Debug:Step Into (or press F11).

Your menus, toolbars, and windows would change a bit, and then a bright yellow highlight appears on the opening curly brace in Main().
