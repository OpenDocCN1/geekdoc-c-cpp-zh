The resulting FileStream object fs is then wrapped in a StreamReader obj to provide convenient methods for accessing the text file. The StreamReader is finally passed back to Main() for use.

When the file-open process is done, the FileReadToFileConsole() method, which loops through the file reading lines of text using the ReadLine(). The program echoes each line to the console with the ubiquitous Console.Write() before calling back up to the top of the loop to read another line of text. The ReadLine() returns a null when the program reaches the end of the file. When this happens, the method breaks out of the loop and returns. Main() then closes the object and terminates. (You might say that the reading of this reader is wrapped in a while loop inside a method that's in a try block wrapped in enigma.)

The catch block in Main() exists to keep the exception from propagating up the food chain and aborting the program. If the program throws an exception, I have the catch block write a message and then simply swallow (ignore) the error. You're in Main(), so there's nowhere to rethrow the exception and nothing to do but close the stream and close up shop. The catch is there to let the user know why the program failed and to prevent an unexpected crash. You could have the program loop back and ask for a different line, but is so small that it's simpler to let the user run it.
