public void Enqueue(T item)
{
    switch (item.Priority) // Require IPriorizable to ensure this property.

            );
}

# The Dequeue() method

Dequeue()'s job is a bit trickier than Enqueue()'s: it must locate the highest-priority queue that has contents and retrieve the front item from that subqueue. Dequeue() delegates the first part of the task, finding the highest-priority queue that is not empty, a private TopQueue() method (described in the next section). To retrieve the frontmost object, which it returns. Here's how Dequeue() works:

```
// Dequeue -- Get T from highest-priority queue available.
public T Dequeue()
{
    // Find highest-priority queue with items.
    Queue<T> topQueue = TopQueue();
    // If a non-empty queue is found
    if (topQueue != null && topQueue.Count > 0)
    {
        return topQueue.Dequeue(); // Return its front item.
    }
    // If all queues are empty, return null (you could throw exception).
    return default(T); // What is this? See discussion.
}
```

A difficulty arises if only one of the queues has any packages — in other words, the whole PriorityQueue is empty. What do you return in that case? Dequeue() returns null. The client — the code that calls PriorityQueue.Dequeue(T) — should check the Dequeue() return value in case it's null. Where's the null it returns? It's that odd duck, default(T), at the end. I deal with default(T) a little later in this chapter.
