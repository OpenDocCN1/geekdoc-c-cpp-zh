## Discriminating between Objects

Detroit car manufacturers can track every car they make without getting the cars confused. Similarly, a program can create numerous objects of the class, as shown in this example:

```csharp
Vehicle car1 = new Vehicle();
car1.manufacturer = "Studebaker";
car1.model = "Austin";
// The following has no effect on car1.
Vehicle car2 = new Vehicle();
car2.manufacturer = "Hudson";
car2.model = "Hornet";
```

Creating an object car2 and assigning it the manufacturer name Hudson has no effect on the car1 object (with the manufacturer name Studebaker).

In part, the ability to discriminate between objects is the real power of the class construct. The object associated with the Hudson Hornet can be created, manipulated, and dispensed with with a single entity, separate from other objects, including the Avanti. (Both are classic automobiles, especially the latter.)

## Can You Give Me References?

The dot operator and the assignment operator are the only two operators defined on reference types:

```csharp
// Create a null reference.
// yourCar;
// Assign the reference value.
yourCar = new Vehicle();
// Use dot to access a member.
yourCar.manufacturer = "Rambler";
// Create a new reference and point it to the same object.
yourSpousalCar = yourCar;
```

The first line creates an yourCar without assigning it a value. A reference that hasn't been initialized is said to point to the null object. Any attempt to use an uninitialized (null) reference generates an immediate error that terminates the program.

The C# compiler can catch most attempts to use an uninitialized reference and generate a warning at build-time. If you somehow slip past the compiler, accessing an uninitialized reference terminates the program immediately.

The second statement creates a new Vehicle and assigns it to yourCar. The last statement in this code snippet assigns the reference yourSpousalCar to the reference yourCar. This action calls yourSpousalCar to refer to the same object as yourCar. This relationship is shown in Figure 2-1.

## 222 Can Give Me References?

The following two calls have the same effect:

```csharp
// Build your car.
yourCar = new Vehicle();
yourCar.model = "Kaiser";
// It belongs to your spouse.
yourSpousalCar = yourCar;
// Changing one changes the other.
yourSpousalCar.model = "Henry J";
Console.WriteLine("Your car is a " + yourCar.model);
```

Executing this program would output Henry J and not Kaiser. Notice that yourSpousalCar doesn't point to yourCar; rather, both yourCar and yourSpousalCar refer to the same vehicle.

In addition, the referenceSpousalCar would still be valid, even if the variableCar were somehow "lost" (if it went out of scope, for example), in this chunk of code:

```csharp
// Build your car.
yourCar = new Vehicle();
yourCar.model = "Kaiser";
// It belongs to your spouse.
yourSpousalCar = yourCar;
// When your spouse takes your car away
yourCar = null;
// .../yourCar now references the "null object."
// .../yourSpousalCar still references the same vehicle
Console.WriteLine("Your car is a " + yourSpousalCar.model);
```

Executing this program generates the output Your car was a Kaiser, even though the referenceCar is no longer valid.

The object is no longer reachable from the referenceCar. The object doesn't become completely unreachable until both yourCar and your SpousalCar are "lost" or nulled out.

At that point — well, at some unpredictable late point, anyway — the C# garbage collector steps in and returns the space formerly used by that particular Object to the pool of space available for allocating more Vehicles (or Students, for that matter)(I say a little more about garbage collection later in this minibook).

Making one object variable (a variable of a reference type, as Vehicle or Student, rather than one of a simple type as int or double) point to a different object — as I did here — makes storing and manipulating objects in arrays and collections quite efficient. Each element of the array stores a reference to an object, and when you swap elements within the array, you're moving references, not the objects themselves. References have a fixed size in memory, unlike the objects they refer to.

## Classes That Contain Classes Are the Happiest Classes in the World

The members of a class can themselves be references to other classes. For example, vehicles have motors, which have power and efficiency factors.

```csharp
public class Vehicle {
    public string model;
    public string manufacturer;
    public int doors;
    public int wheels;
    public Motor motor;
}

public class Motor {
    public double power;
    public double efficiency;
}
```
