
# Breaking Down the Projects

All there is left to do after you have run the setup program and set your default settings is to start on a project and get your fingers dirty. All projects (expect maybe one or two) in the first two minibooks were Console applications, meaning they are meant to be run at the command prompt. There are a lot more projects available.

Notice three main kind of projects in the Visual Studio New Project dialog box.

- * Windows projects are client applications that compile into EXEs and run on your computer. Microsoft Word is a Windows application.

- * Web projects make Sites and require a Web server to run. (A Web server is included with Visual Studio for development purposes.) Microsoft.com is an example of a Web application.

- * Special projects include things like setup projects (projects that build setup programs) and database projects (projects that give a framework for databases). They are usually used with Windows or Web application. The Setup.exe you run in the preceding section to install Visual Studio is an example of these special project — a setup project.

# Exploring the New Project dialog box

Let's start with a breakdown of the New Project dialog box, shown in Figure 1-2. This screen is an important part of the usability of Visual Studio. You can open it by clicking the New Project link on the setup page.

The section of the dialog box to the far left is a tree-view selector, similar to the one in Outlook. You have three options — Recent Templates, Installed Templates, and Online templates. Installed Templates is selected. These templates, as Visual Studio calls them, project types.

Within the selector is a WPF style tree viewer. Instead of maples and oaks, this tree has all the project categories described in upcoming sections of this chapter.

If you click, for the Visual C option in the tree view, all the projects for Visual C# appear in the window just to the right. If you click one of the suboptions, just those project types — for Visual C#—appears.

To specify version of the .NET Framework you would like to develop for, you can use the drop-down list just above the project list that says .NET Framework 4.0. To change the sorting options, use the Sort By: drop-down list directly to the right. One more step to the right and you can change your view options.

# Understanding the solutions

For more solutions, see the next section. Solutions are collections of projects. You can think of a solution as a container that holds one or more projects. Projects within a solution interact with each other.

A project is a unit of work that can be compiled into an executable file or a library. Each project has its own settings, dependencies, and code.

The solution is the top-level container in Visual Studio. It allows you to manage multiple projects together. This is particularly useful for large applications where the code is divided into different layers, such as the UI, the business logic, and the data access layer.

The solution file (with a .sln extension) contains information about the projects that make it up. When you open a solution file in Visual Studio, it loads all the projects and allows you to work on them simultaneously.

This strategy keeps me more organized. The following list describes the project types listed in the New Project dialog.

| Project Type | Description |
| :--- | :--- |
| Windows projects | These are programs that compile into a running program, like Microsoft Word. |
| Forms Application | The classic "program." Compiles into a program that runs with its own window and a little X to exit. |
| Class Library | Makes a DLL when you're all done. This is the basis of reusable code. |
| WPF Application | The new "program." Also compiles into an EXE, but uses a new interface format called Windows Foundation. |
| WPF Browser | Just like a WPF application but runs in Internet Explorer. This is not a Silverlight application. |
| Console application | These EXEs are designed to be run from a command prompt. |
| WPF Custom Control Library | This is a way to make actual controls that you can use in your WPF applications. |
| Empty Project | Just what it sounds like — a project that's empty. It's used to build a program when you don't have a template. |
| Windows Services | These programs appear in the Services control panel. |
