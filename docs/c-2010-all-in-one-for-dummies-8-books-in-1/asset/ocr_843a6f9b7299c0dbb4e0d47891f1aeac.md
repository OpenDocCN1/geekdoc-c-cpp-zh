# Table 2-1
The System.Data Namespaces

| Namespace | Purpose | Most Used Classes |
|---|---|---|
| System.Data | Classes common to all ADO.NET | The containers DataSet, DataView, DataTable, DataRow |
| System.Data.Common | Utility classes used by database-specific classes | DbCommand, DbConnection |
| System.Data.OBC | Classes for connections to ODBC databases such as dBASE | SqlCommand, DbAdapter |
| System.Data.OleDb | Classes for connections to OleDb databases such as Access | OleDbCommand, OleDbAdapter |
| System.Data.OracleClient | Classes for connections to Oracle | SqlCommand, OracleAdapter |
| System.Data.SqlClient | Classes for connections to Microsoft SQL Server | SqlCommand, SqlDataAdapter |
| System.Data.SqlTypes | For referencing the native types common to SQL Server | SqlDateTime

Though there is a lot to the System.Data namespace and related tools, I focus on the Visual Studio implements these tools. In previous versions of the development software of all modern apps, the visual tools make things harder because of the black box problem.

The black box problem is of having a development environment some things for you which you have no control. Sometimes it's nice to have things done for you, but when the development environment doesn't build exactly what you need them, code that is generated isn useless.

Fortunately, that isn't the case anymore. Visual Studio now generates completely open and sensible # code when you use the visual tools. I think you will be pleased with the results.

# How the Data Classes Fit into the Framework

The data classes are all about information storage. In Book I, I talk about collections, which are for storage of information while an application is running. Hashtags are another example of storing information. Collections holds lists of objects, and hashtags hold name and value pairs.
