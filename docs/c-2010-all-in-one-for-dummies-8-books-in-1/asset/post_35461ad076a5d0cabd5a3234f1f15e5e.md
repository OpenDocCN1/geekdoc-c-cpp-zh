# Using PackageFactory

To generate a randomly prioritized Package object, you will call your object's CreatePackage() method this way:

```csharp
PackageFactory fact = new PackageFactory();
IPriorizable pack = fact.CreatePackage(); // Note the interface here.
```

CreatePackage() tells its random-number generator to generate a number from 0 to 2 (inclusive) and uses the number to set the priority of a new Package, which returns the method (to a Package, or better, an IPriorizable variable).

I note that CreatePackage returns a reference to IPriorizable, which is more general than returning a reference to a Package. This example shows induction — Main() returns to a Package directly, through an interface that Package implements. Indirection insulates Main() from the details of CreatePackage returns. You then have greater freedom to alter the implementation of the factory without affecting Main().

# More about factories

Factories are helpful for generating lots of test data. (A factory doesn't need random numbers — that's what was needed for the PriorityQueue example.)

Factories improve portability by isolating code. Every time you mention a specific class by your name, you create a dependency on that class. The more such dependencies you have, the more tightly coupled (bound) your classes become.

# Tending to unfinished business

PriorityQueue needs a couple small bits of "Spacking." Here are the issues:

- By itself, PriorityQueue wouldn't prevent you from trying to instantiate it for, say, int or string or Student — elements that don't have priorities. You need to constrain the class so that it can be instantiated only for types that implement IPriorizable. Attempting to instantiate for a non-IPriorizable class should result in a compiler error.
- The Dequeue() method for PriorityQueue returns the value instead of an actual object. But generic types such as <T> don't have a natural default value the way elements as ints, strings, and down-and-out object references do. That part of it needs to be generalized.

# Adding constraints

PriorityQueue must be able to ask an object what its priority is. To make it work, all classes that are storeable in PriorityQueue must implement the IPriorizable interface, as Package does. Package lists IPriorizable in its class declaration header, like:

```csharp
class PriorityQueue : IPriorizable
```

Then it implements IPriorizable Priority property.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_209_1.png)

A matching limitation is needed for PriorityQueue. You want the compiler to squawk if you try to instantiate a type that doesn't implement IPriorizable. In the generic form of PriorityQueue (written specifically for type Package), the compiler squeals automatically (if recommend enough) when one of your priority queue methods tries to call the next level with an explicit constraint. Because you could instantiate the generic class with literally any type, you need a way to tell the compiler which types are acceptable — because they are guaranteed to have the right methods.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_209_2.png)

You add the constraint by specifying IPriorizable in the heading of PriorityQueue, like this:

```csharp
class PriorityQueue<T> where T: IPriorizable
```

Did you notice the where clause earlier? This boldfaced where clause specifies that T must implement IPriorizable. That's the enforcer. It means,
Make sure that T implements the IPrioritizable interface — or else!

You specify constraints by using one or more of the following elements (separated by commas) in a where clause:

- The name of a required base class that T must derive from (or be).
- The name of an interface that T must implement, as shown in the previous example.
- You can see more — Table 8-1 has the complete list.

For information about these constraints, look up Generics [C#], constraints in
The Help index.

| Constraint | Meaning | Example |
|---|---|---|
| MyBaseClass | T must be, or extend, MyBaseClass. | where T: MyBaseClass |
| IInterface | T must implement IInterface. | where T: IInterface |
| struct | T must be any value. | where T: struct |
| class | T must be any reference type. | where T: class |
| new() | T must have a parameterless constructor. | where T: new() |

In this line, T must be a class, not a type; it must implement IPriorizable; and it must have a constructor without parameters.

```csharp
class MyClass<T> where T: class, IPriorizable, new()
```

You might have two generic parameters and both need to be constrained. (Yes, you can have more than one generic parameter — think of Dictionary<TKey, TValue>) Here's how to use two:

```csharp
class MyClass<T, U> where T: IPriorizable, U: new()
```

# Determining the null value for T: Default (T)

In case you read the last paragraph in the previous section and are confused, well, each type has (as mentioned above) a default value that signifies "nothing" for that type. For ints, doubles, and all other types, it is 0 or (0.0). For bool, it's false. And, for all reference types, such as Package, it is null. With all reference types, the default is null

But because a generic class such as PriorityQueue can be instantiated for all sorts of data types, it cannot predict the null value to use. For example, if you use the Dequeue() method of PriorityQueue, you may face this situation: You call Dequeue() to get package, but not none. What do you want to return "nothing"? Because Package is a class type, it should return null. Signals that caller of the Dequeue() that there was nothing to return (and the caller must check for a null return value)

The compiler can make sense of the null keyword in a generic class because the class can be instantiated for all sorts of data types. That's why Dequeue() uses this line instead:

```csharp
return default(T); // Return the right null for whatever T is.
```
