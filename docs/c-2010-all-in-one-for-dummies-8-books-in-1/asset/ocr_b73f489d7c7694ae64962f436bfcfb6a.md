Class Pen might look like this:

```
class Pen : IRecordable
{
    public void TakeNote(string note) // Interface method implementations
    {
        // scribble a note with a pen ... // MUST be declared public.
    }
}
```

This example fulfills two requirements: Note that the class implements IRecordable, and provide a method implementation for TakeNote().

The syntax indicating that a class inherits a base class, such as ThingsThatRecord, is essentially different from the syntax indicating that the class implements a C# interface as IRecordable:

```
public class PDA : ThingsThatRecord ...
public class PDA : IRecordable ...
```

# How to name your interface

The .NET naming convention for interfaces precedes the name with the letter I. Interface names are typically adjectives, such as IRecordable.

# Why C# includes interfaces

The bottom line of interfaces is that an interface describes a capability, such as Swim Safety Training or Class A Driver's License. As a class, I earn my IRecordable badge when I implement the TakeNote ability.

More than that, an interface is a contract. If you agree to implement every method defined in the interface, you can get to claim its capability. Not only that, but a client using your program is guaranteed to be able to call all those methods. Implementing an interface is a promise — enforced by the compiler. Enforcing promises through the compiler reduces errors.

# Mixing inheritance and interface implementation

Unlike some languages, such as C++, C# doesn't allow multiple inheritance — a class inheriting from two or more base classes. Think of class HouseBoat inheriting from House and Boat. Just don't think of it in C#.
