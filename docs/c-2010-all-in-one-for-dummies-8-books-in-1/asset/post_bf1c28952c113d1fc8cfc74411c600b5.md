Luckily, C# also has the internal keyword. Using internal is just one step down from public and well above private. If you mark the GroupA class and its “public” methods — the ones that are outside the class — with the internal keyword instead, everybody at CIA can see and access Secret X — as long as the secret itself (a data member) as internal or provide an internal property to get it, as shown in this version:

```csharp
// In assembly CIAAssembly:
internal class GroupA
{
    private string _secretFormulaForCocaCola; // Secret X
    internal string SecretX { get { return _secretFormulaForCocaCola; } }
}
public class GroupB
{
    public void DoSomethingWithSecretX()
    {
        // Do something with Secret X, now that we can see it:
        Console.WriteLine("I know Secret X, which is {0} characters long, but " + "I'm not telling.", GroupB.SecretX.Length);
    }
}
```

You can mark a method inside an internal class as public, though it isn't truly public. A class member can't be more accessible than its class, so the so-called "public" member is just internal.

CIA can still keep its deepest, darkest secrets ultra-hush-hush by declaring them private inside their own owning class. That strategy makes them accessible only in that class.

## Protected: Sharing with subclasses

The main purpose of private is to hide information. In particular, private hides a class's internal implementation details. (Classes who know classes too intimately are the luckiest classes in the world. Classes with a lot of implementation details are said to be "too tightly coupled" with the classes they know too much about. If A is aware of the internal workings of class B, A can rely too much on those details. If they ever change, you end up modifying both classes.)

The other classes and assemblies — know how class B performs its magic, the better. In Chapter 5 of this minify, I use the example of a BankAccount class. The bank doesn't forget folks like me — or forget classes such as A — to be able to change a balance directly. Balance is properly part of the BankAccount class's implementation.

Sometimes, though, the base class doesn't supply such access methods for its subclasses to use. What if the _balance data member in BankAccount is private?

Enter the protected keyword: if the _balance instance variable in the base class is protected rather than private, outsiders can't see it — is effectively private to them. But subclasses can just see it.

An even better solution is to mark _balance private in BankAccount before then provide a Balance property marked protected. Subclasses using SavingsAccount can access the balance is invisible to outsiders, which protects the BankAccount implementation.

If the data does need to be accessible (read-only) to outsiders, you should provide the public property to get the balance. However, you may still need to get the balance from inside SavingsAccount itself. To do that, you can use the set accessor of protected access — accessible from SavingsAccount and other subclasses inaccessible to outsiders.

```csharp
// In BankAccount:
public decimal Balance
{
    get return _balance; // Public
    protected set {_balance = value;} // Not public
}
```

The ProtectedLimitsAccess example on the Web illustrates using the protected keyword as described.

You can subclass BankAccount in a different assembly and the subclass has access to anything declared protected in BankAccount. The ProtectedLimitsAccess example also illustrates this.

The example has two subclasses of BankAccount: one in the same assembly as BankAccount and one in a different assembly. What's interesting with respect to protected is that either BankAccount subclass can access any item in BankAccount marked protected. The subclass doesn't have to be in the same base class.

The ability to extend (subclass) a class from outside the base class's assembly has implications for security, which is why many classes should be sealed. A sealing class prevents outsiders from gaining access by subclassing it. That's why you're advised to make classes extendable (nonsealed).
