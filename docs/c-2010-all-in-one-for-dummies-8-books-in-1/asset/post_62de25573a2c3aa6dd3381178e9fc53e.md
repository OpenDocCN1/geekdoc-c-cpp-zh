# Submitting input with Submit buttons

After you get all input into a form, you need to send it to you. The basic way to do this is through the Submit button.

In Chapter 1, I talk about the PostBack event, and how Microsoft used JavaScript to change the posting of forms back to the server works. The Submit button is how one does this.

Let's be clear — any control can cause a postback. If you set an event handler for an event, it will cause a postback. You can save off the form data at any point once it gets back to the server. We use the Submit button because it is what the user is used to.

The ASP.NET default controls have three buttons.

- Button is just what it says — an input of type submitted in HTML.

- ImageButton is a control that has a built-in src property for images.

- LinkButton shows an HTML anchor and treats it like a button.

We use of these for nearly every page where we accept user input. Of of the time, the users expect it.

# Data Binding

Getting the data into a control in a Web page isn't enough. There needs to be some way to persist (save for reuse) that information after the data is entered. Data binding is the answer.

# Data Binding

Data binding tells a control member of the underlying class to get its data from. For instance, if you have a collection of Apple objects with a property of Color that you want to show in a text box, you can bind the value Apple.Color to the Text property.

But things get more interesting than that. Let's say you want to provide a list of colors and allow the user to select the color of the object in question. You can do that by binding the list of a collection and the selected value to the SelectedItem property of the list control. If you want to show the color itself, you can bind to the FontColor property of a text control.

# Setting up your markup for binding

Back in the Active Server Page days, you put all your data on the page by simply printing it. Sounds simple but it had a lot of problems. Foremost, your form had to have a lot of knowledge about the data it was showing. This is a bad thing. Anyway, the format for it was

```
<%= ThisIsWhatIWantToPrint % %>
```

If you needed a list, you looped in the surrounding code. If you needed a method result, you just put the method in there. What you saw was what you got.

Data binding is the more enlightened form of getting data on the screen. The controls that are built into ASP.NET know how to handle data on their own, so long as data meets some basic specifics.

Data binding is accomplished by setting a property of a control to a member of the underlying class. For a single control, like a text box, you set the property in question, like

```
<asp:Label ID="Label" runat="server" Text='<%# IAmBindingToThisVariable %>' />
```

If you are binding a repeating control, like a Grid or a List, then you set the DataSource property. I show you how to do that in the next section, "Bindings in code."
