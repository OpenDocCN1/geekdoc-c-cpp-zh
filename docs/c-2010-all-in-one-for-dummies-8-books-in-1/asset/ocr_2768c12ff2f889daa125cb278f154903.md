The catch block is like a soccer goalie: it's there to catch any file error that may have occurred in the program. The catch outputs an error message, including the name of the errant file. It doesn't output just a simple filename—it outputs the entire filename, including the path, for your reading. It does this by using the Path.Combine() method to tack the current directory name, obtained from the Directory class, onto the filename you entered. (Path is a class designed to manipulate path information. Directory provides properties and methods for working with directories.) I will give you the goods on exceptions, excluding the the exceptions to those—I give up.

The path is the full name of the file folder. For example, in the filename c:\temp directory\txt.txt, the path is c:\temp directory.

The Combine() method is enough to ensure that for a file like c:\txt, the path isn't in the current directory. Path.Combine() is also the safest way to ensure that two segments being combined correctly, including a path separator between them. (In Windows, the path separator is \. You can obtain the correct separator for whatever operating system you are running, whether it is Windows or some, with Path.DirectorySeparatorChar.) The .NET Framework library is full of features like that, clearly aimed at writing C# programs that run on multiple operating systems, as Mono for Linux and Unix, which I discuss in this book's Introduction.)

Upon encountering the end of the while loop, either by completing the try block or by being vectored through the catch, the program returns to the top of the while loop to allow the user to write another file.
