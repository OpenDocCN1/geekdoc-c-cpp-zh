# Diving In! Creating Your First WPF Application

# Listing 1-1: App.xaml

```
<Application x:Class="MyFirstWPFApplication.App"
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
xmlns:x="http://schemas.microsoft.com/winfx//2006/xaml"
StartupUri="MainWindow.xaml">
<Application.Resources>
</Application>
```

Listing 1-1 displays the XAML that was generated by the WPF Application template in Visual Studio. Note that the WPF namespaces are defined. The namespace that represent the CLR objects is defined in the XAML file with a .prefix

The StartUri value defines the window that will be displayed after the application is executed. In this case, the MainWindow.xaml window will be displayed.

The x:Class attribute defines the C# code-behind of this XAML file. You open App.xaml.cs, so you see that its class name is App and it inherits from the Application class (which is the root element of the XAML file).

C# uses namespaces to organize and locate classes. In order to create objects from a specific namespace, you use the "using" syntax at the top of your class definitions. Similar to C#, XAML also requires you to declare which namespaces are used in the document. Namespaces are typically defined as an attribute within the root element of the document, the root element is the first tag in the XML document. XAML uses syntax xmlns means "XML namespace," and it's typically followed by a colon (:) and an alias. This alias is the shorthand reference to the namespace throughout the XAML document; it's what you use to instantiate an object from a class in that namespace.

For instance, if you want to add the namespace MyTemplates.DataTemplates from the assembly MyTemplates.dll, you could define the namespace as:

```
xmlns:myDT="clr-namespace:MyTemplates.DataTemplates;assembly=MyTemplates.dll"
```

You will be able to instantiate an object from the MyTemplates.DataTemplates namespace as follows:

```
<myDT:Class/></myDT:Class>
```
