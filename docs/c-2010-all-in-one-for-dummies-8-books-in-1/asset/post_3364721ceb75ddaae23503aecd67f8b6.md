## A recommended way to raise your events

The earlier section "How to publish an event" shows the bones of raising an event. However, I recommend that you always define a special "event raise" method, like this:

```csharp
protected void OnNewEdition(NewEditionEventArgs e)
{
    EventHandler<NewEditionEventArgs> temp = NewEdition;
    if (temp == null)
    {
        temp(this, e);
    }
}
```

Providing this method ensures that you always remember to complete two steps:

- 1. **Store the event in a temporary variable.**

This step makes your event more usable in situations where multiple "threads" try to use it at the same time—threads divide your program into a foreground task and one more background tasks, which run simultaneously (concurrently). I don't cover how to write multithreaded programs in this; just follow this guideline.

- 2. **Check the event for null before you raise it.**

If it's null, trying to raise it causes an error. Besides, null means that no other objects have shown an interest in your event (none is subscribed); Always check the event for null, regardless of whether you write this OnSomeEvent method.

## How observers "handle" an event event

The subscribing object specifies the name of a handler method when it subscribes — it's the argument to the constructor (boldfaced):

```csharp
button1.Click += new EventHandler<NewEditionEventArgs>(button1_Click);
```

This line sort says, "Send me to this address, please." Here's a handler for the NewEdition event:

```csharp
myPublisher.NewEdition += new EventHandler<NewEditionEventArgs>(NewHandler);
void NewHandler(object sender, NewEditionEventArgs args)
{
    // Do something in response to the event.
}
```

For example, a BankAccount class can raise a custom TransactionAlert event when it occurs in a BankAccount object, such as a deposit, withdrawal, transfer or an error. A Logger observer object can subscribe and log these events to a file or as an audit trail.

## When to delegate, when to event, when to go on the lambda

**Events**: Use events when you have multiple subscribers or when communicating with client software that uses your classes.

**Lambdas**: There is an article about lambdas on this book's companion Web. A lambda expression is, in essence, just a short way to specify the method you're passing to a delegate. You can use lambdas instead of anonymous methods.

**Delegates**: Use delegates or anonymous methods when you need a callback or need to randomize an operation.
