```csharp
// InputPositiveDecimal -- Return a positive decimal number
// from the keyboard.
public static decimal InputPositiveDecimal(string prompt)
{
    // Keep trying until the user gets it right.
    while (true)
    {
        // Prompt the user for input.
        Console.WriteLine("Enter * " + prompt + ":");
        // Retrieve a value from a keyboard.
        string input = Console.ReadLine();
        decimal value = Convert.ToDecimal(input);
        // Exit the loop if the value's entered is correct.
        if (value >= 0)
        {
            // Return the decimal value entered by the user.
            return value;
        }
        // Otherwise, generate an error on incorrect input.
        Console.WriteLine(prompt + " * cannot be negative");
        Console.WriteLine("Try again");
        Console.WriteLine();
    }
}

// OutputTable -- Given the principal and interest,
// generate a future value table for the number of periods
// indicated in duration. (Implements Section 3).
public static void OutputTable(decimal principal, decimal interest, decimal duration)
{
    for (int year = 1; year < duration; year++)
    {
        // Calculate the value of the principal plus interest.
        decimal interestPaid;
        interestPaid = principal * (interest / 100);
        // Now calculate the new principal by adding
        // the interest to the previous principal.
        principal = principal + interestPaid;
        // Round off the principal to the nearest cent.
        principal = decimal.Round(principal, 2);
        // Output the result.
        Console.WriteLine(year + " *=" + principal);
    }
}
```

To carry out the Promote Variable to Parameter refactoring, right-click the local principal's name and click Promote Variable to Parameter to move the variable definition to the parameter list:

However, principal is at the end of the list and you want it at the beginning. You can use the Reorder Parameters refactoring to fix this problem. ### Why you should bother with methods

When FORTRAN introduced the function concept — methods, in C# during the 1950s, its purpose was to avoid duplication of code by combining similar sections into a common element. Suppose that you were to write a program to calculate ratios in multiple places. Your program could use the CalculateRatio() method needed, for or less the sole purpose of avoiding duplication. The savings are not important for a method such as calculateRatio(), but methods can grow much larger. Besides, a common method such as WriteLine() may be invoked in hundreds of different places.

This assignment can implement this complex operation with no concern about how it may. The applications programmer can use CalculateSin() with no concern how this operation is performed internally, which greatly reduces the issues she must monitor. After the number of "variables" is reduced, a large job is accomplished by implementing two smaller jobs.

Large programs, such as word processors, are built up from many layers of methods at increasing levels. For example, a DisplayDocument() method would undoubtedly call a DisplayParagraph() method to display the paragraph in the document. Paragraph() would need to invoke a CalculateWordWrap() method to decide where to wrap the lines that make up the paragraph. CalculateWordWrap() would have to call a LookupWordBreak() method to decide where to break a word at the end of the line, to make the sentences wrap naturally. Each of these methods was described in a single sentence. (Notice that methods are well named). Quick, a second advantage becomes obvious: Coding a simple method is as easy as coding many — and double easier if the method is small. The CalculateRatio() method includes a check to ensure that the denominator is not zero. If you repeat the calculation code throughout your program, you can easily test this in some cases — and in other places.

Not as obvious is this advantage: A carefully crafted method reduces the complexity of the program. A well-defined method should stand for a concept. You should be able to describe the purpose of the method without using the words and or or. The method should only do one thing. Without the absolute complex concepts, writing programs of even moderate complexity would find that the task becomes almost impossible — let alone creating an operating system such as Windows, Vista, a word processor such as Word, or a game such as Halo.
