# Writing generic code the easy way

Now you have to figure out how to write a generic class, with all those <T>s. Look confusing, doesn't it? Well, it's not so hard, with these section demonstrators.

The simple way to write a generic class is to write a nongeneric version first and substitute the <T>s. For example, you would write the PriorityQueue class for Package objects, test it, and "genericize" it.

Here's a simple place for a nongeneric PriorityQueue, to illustrate:

```
public class PriorityQueue
{
    //Queues -- The three underlying queues: all generic!
    private Queue<Package> _queueHigh = new Queue<Package>();
    private Queue<Package> _queueMedium = new Queue<Package>();
    private Queue<Package> _queueLow = new Queue<Package>();
    //Enqueue -- Prioritize a package and add it to correct queue.
    public void Enqueue(Package item)
    {
        switch(item.Priority)
        {
            case Priority.High:
                queueHigh.Enqueue(item);
                break;
    }
```

# Saving PriorityQueue for last

Why would a priority queue be? Seems a little backward to us. But you've seen the rest. Now it's to examine the PriorityQueue class itself. This section shows the code and then walks you through it how to deal with a couple of small issues. It takes a piece at a time.

# The underlying queues

PriorityQueue is a wrapper class that has three ordinary Queue<T> objects, one for each priority level. Here's the first part of PriorityQueue, showing the three underlying queues (now generic):

```
//PriorityQueue -- A generic priority queue class
// Types to be added to the queue "must" implement IPrioritizable interface.
class PriorityQueue<T> where T : IPrioritizable

// Queues for the three queues: all generic:
Queue<T> queueHigh = new Queue<T>();
Queue<T> queueMedium = new Queue<T>();
Queue<T> queueLow = new Queue<T>();
// The rest will follow shortly
```

These lines declare three private data members of type Queue<T> and initialize them by creating the Queue<T> objects. I say later in this chapter about odd-looking class declaration line above the "subqueue" declarations.

# The Enqueue() method

Enqueue() adds an item of T to the PriorityQueue. This method's job is to look at the item's priority and put it into the correct underlying queue. In the first line, it gets the item's Priority property and switches based on that value. To add the item to the high-priority queue, for example, Enqueue() turns around and enqueues the item in the underlying queue High. Here's PriorityQueue's Enqueue() method:

```
// Enqueue Prioritize T and add it to correct queue; an item of type T.
// The item must know its own priority.
public void Enqueue(T item)
{
    switch (item.Priority) // Require IPriorizable to ensure this property.
        case Priority.High:
            _queueHigh.Enqueue(item);
            break;
        case Priority.Medium:
            _queueMedium.Enqueue(item);
            break;
        case Priority.Low:
            _queueLow.Enqueue(item);
            break;
        default:
            throw new ArgumentOutOfRangeException(
                item.Priority.ToString(),
                "bad priority in PriorityQueue.Enqueue*"
            );
}
```

# The Dequeue() method

Dequeue()'s job is a bit trickier than Enqueue()'s: it must locate the highest-priority queue that has contents and retrieve the front item from that subqueue. Dequeue() delegates the first part of the task, finding the highest-priority queue that is not empty, a private TopQueue() method (described in the next section). To retrieve the frontmost object, which it returns. Here's how Dequeue() works:

```
// Dequeue -- Get T from highest-priority queue available.
public T Dequeue()
{
    // Find highest-priority queue with items.
    Queue<T> topQueue = TopQueue();
    // If a non-empty queue is found
    if (topQueue != null && topQueue.Count > 0)
    {
        return topQueue.Dequeue(); // Return its front item.
    }
    // If all queues are empty, return null (you could throw exception).
    return default(T); // What is this? See discussion.
}
```

A difficulty arises if only one of the queues has any packages — in other words, the whole PriorityQueue is empty. What do you return in that case? Dequeue() returns null. The client — the code that calls PriorityQueue.Dequeue(T) — should check the Dequeue() return value in case it's null. Where's the null it returns? It's that odd duck, default(T), at the end. I deal with default(T) a little in this chapter.

# The TopQueue utility method

Dequeue() relies on the private TopQueue() method to find the highest-priority, nonempty queue. TopQueue() just starts with queue and asks for its Count property. If it is greater than zero, the queue contains items, so TopQueue() returns a reference to the whole queue that it found. On the other hand, if queueHigh is empty, TopQueue() tries queueMedium and then queueLow.

What happens if all subqueues are empty? TopQueue() could return null, but it is possible to simply return one of the empty queues. When Dequeue() calls the returned queue's Dequeue() method, it returns null. TopQueue works like this:

```
// What's the highest-priority queue with items?
private Queue<T> TopQueue()
    if (queueHigh.Count > 0) // Anything in high-priority queue?
        return queueHigh;
    if (queueMedium.Count > 0) // Anything in medium-priority queue?
        return queueMedium;
    if (queueLow.Count > 0) // Anything in low-priority queue?
        return queueLow;
    else // All empty, so return an empty queue.
```
