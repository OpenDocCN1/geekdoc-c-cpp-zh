# Classy Generics: Writing Your Own 183

```
// Return a randomly selected package priority:
// need a 0, 1, or 2 (values less than 3).
int rand = _randGen.Next(3);
// Use that to generate a new package.
// Casting to enum is clunky, but it saves
// having to use if or a switch statement.
return new Package((Priority)rand);
```

Classy Factory has one data member and one method. (You can just as easily implement a simple factory as a method rather than a class — for program.) When you instantiate a PackageFactory object, it creates an object of class Random and stores it in the data member. Random is a .NET library class that generates random numbers.

Take a look at the PackageFactoryWithIterator example on csharp102.info.

# Using PackageFactory

To generate a randomly prioritized Package object, you will call your object's CreatePackage() method this way:

```
PackageFactory fact = new PackageFactory();
IPriorizable pack = fact.CreatePackage(); // Note the interface here.
```

CreatePackage() tells its random-number generator to generate a number from 0 to 2 (inclusive) and uses the number to set the priority of a new Package, which returns the method (to a Package, or better, an IPriorizable variable).

I note that CreatePackage returns a reference to IPriorizable, which is more general than returning a reference to a Package. This example shows induction — Main() returns to a Package directly, through an interface that Package implements. Indirection insulates Main() from the details of CreatePackage returns. You then have greater freedom to alter the implementation of the factory without affecting Main().

# More about factories

Factories are helpful for generating lots of test data. (A factory doesn't need random numbers — that's what was needed for the PriorityQueue example.)

Factories improve portability by isolating code. Every time you mention a specific class by your name, you create a dependency on that class. The more such dependencies you have, the more tightly coupled (bound) your classes become.
