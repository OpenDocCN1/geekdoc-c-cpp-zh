# Explicit type conversion — the cast

Imagine what happens if C# was wrong about implicit conversion and the programmer wanted to perform integer multiplication?

You can change the type of any value-type variable by using the cast operator. A cast consists of a type enclosed in parentheses and placed immediately in front of the variable or expression in question.

The following example uses the * int operator:

```c
int aInt = 10;
double aDouble = 5.0;
int result = aInt + (int)aDouble;
```

The cast of aDouble to an int is known as an explicit demotion or downcast. The conversion is explicit because the programmer explicitly declared it. (Duh).

You can make an explicit conversion between any two value types, it's up or down the promotion ladder.

Avoid implicit type conversion. Make any changes in value types explicit by using a cast. Doing reduces the possibility of error and makes code much easier for humans to read.

# Assigning types

The matching of types that you do in conversions applies to the assignment operator.

Inadvertent type mismatches generate compiler error messages usually occur in the assignment operator, not at the point of the mismatch.

Consider the following multiplication example:

```csharp
int n1 = 10;
int n2 = 5.0 * n1;
```

The second line in this example generates an error message because of a type mismatch, but the error occurs at the assignment — not at the multiplication. Here's the horrible tale: To perform the multiplication, C# implicitly converts nl to a double. C# can then perform double multiplication, the result of which is the all-powerful double.

The type of the right-hand and left-hand operators of the assignment operator must match, but the type of the left-hand operator cannot change. Because C# refuses to demote an expression implicitly, the compiler generates the error message Cannot implicitly convert type double to int.

C# allows this expression with an explicit cast:

```csharp
int nl = 10;
int n2 = (int)(5.0 * nl);
```
```
(The parentheses are necessary because the cast operator has very high precedence.) This works — explicit demotion is okay. The nl is promoted to a double, the multiplication is performed, and the double result is demoted to an int. In this case, however, you would worry about the sanity of the programmer because 5 * nl is so much easier for both the programmer and the C# compiler to read.

## # Branching Out with if and switch

The basis of all C# decision-making capability is the if statement (and the basis of all decisions is off by the **maybe**);

```csharp
if (bool-expression)
{
    // Control goes here if the expression is true.
}
 Control passes to this statement whether the expression is true or not.
```

A pair of parentheses immediately following the keyword if contains a conditional expression of type bool. (See Chapter 2 of this minibook for a discussion of bool expressions.) Immediately following the expression is a block of code off by a pair of braces. If the program executes the code within the braces; if the expression is not true, the program skips the code in the braces. its ends after the closing brace and continues from there.)

The if statement is easy to understand by looking at a concrete example:

```csharp
// Make sure a is not negative:
// If a is less than 0
if (a < 0)
    // then assign 0 to it so it's no longer negative.
    a = 0;
```

This segment of code ensures that the variable a is nonnegative — greater than equal to 0. If the if statement says, "If a is less than 0, assign 0 to a." (In other words, turn a into a positive value)

The braces aren't required. C# treats if (bool-expression) statement; as if it had written if (bool-expression) {statement}. The general consensus (and my preference) is to always use braces for better clarity. In other words, do not ask — just do it.

## # Introducing the if statement

Consider a small program that calculates interest. The user enters the principal amount and the interest rate, and the program spits out the resulting value for each year. (This program isn't sophisticated.) The simplistic calculation appears as follows in C#:

```csharp
// Calculate the value of the principal plus interest.
double interestPaid;
interestPaid = principal * (interest / 100);
// Calculate the total.
double total = principal + interestPaid;
```

The first equation multiplies the principal times the interest to produce the interest to be — interestPaid. You divide by 100 because interest is usually calculated by entering a percentage. The interest to be is then added back into the principal, resulting in a new principal, which is stored in the variable total.

The program must anticipate anything when dealing with human input. For example, you don't want your program to accept a negative principal or interest (well, maybe be a negative interest). The CalculateInterest program includes checks to ensure that none of these happens:
