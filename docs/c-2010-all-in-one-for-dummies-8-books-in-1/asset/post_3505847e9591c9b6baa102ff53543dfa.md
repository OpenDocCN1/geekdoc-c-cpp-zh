## Using an Exceptional Error-Reporting Mechanism

C# introduces a completely different mechanism for capturing and handling errors: the exception. This mechanism is based on the keywords try, catch, throw, and finally. In outline form, it works like this: A method will try to execute a piece of code. If the code detects a problem, it will throw an error indication, which your code can catch, and no matter what happens, it finally executes a special block of code at the end, as shown in this snippet:

```csharp
public class MyClass {
    public void someMethod() {
        // Set up catch an error.
        try {
            // Call a method or do something that could throw an exception.
            SomeMethod();
            // .. make whatever other calls you want . . .
        } catch (Exception e) {
            // Control passes here in the event of an error anywhere
            // within the try block.
            // The Exception object e describes the error in detail.
        } finally {
            // Clean up: close files, release resources, etc.
            // This block runs even if an exception was caught.
        }
    }
    public void someMethod() {
        // .. error occurs somewhere within this method . . .
        // and the exception bubbles up the call chain.
        throw new Exception("Description of error");
        // .. method continues if throw didn't happen
    }
}
```

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_213_0.png)

The combination of try, catch, and (possibly) finally is an exception handler.

The someMethod() method surrounds a sequence of code in a block labeled with the keyword try. Any method called within that block (or any method that calls it or on up the tree...) is considered to be within the try block. If you have a try block, you must have either a catch block or a finally block, or both.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_213_1.png)

A variable declared inside a try, catch, or finally block is not accessible from outside the block. If you need access, declare the variable outside, before the block.

```csharp
int aVariable; // Declare aVariable outside the block.
try {
    aVariable = 1;
    // Declare aString inside the block.
    string aString = aVariable.toString(); // Use aVariable in block.
}
// aVariable is visible here; aString is not.
```

## About try blocks

Think of using the try block as putting the C# runtime on alert. If an exception pops up while executing any code within this block, a lantern in the old church tower (one by land, two if by sea—or, call 911).

Then, if any line of code in the try block throws an exception—or if any method called by that method throws an exception, and so—try to catch it.

Potentially, a try block may “cover” a lot of code, including all methods by its contents. Exceptions can percolate up (sometimes a long way) from the depths of the execution tree. It shows you examples.

## About catch blocks

A try block is usually followed immediately by the keyword catch, which is followed by the catch keyword's block. Control passes to the catch block in the event of any error anywhere within the try block. The argument to the catch block is an object of class Exception or, more likely, a subclass of Exception.

If your catch doesn't need any information from the exception object it catches, you can specify only the exception type:

```csharp
catch(SomeException) // No object specified here (no "Exception e")
{
    // Do that doesn't require access to exception object.
}
```

However, a catch block doesn't have to have arguments: A bare catch catches any exception, equivalent to catch(Exception):

```csharp
catch
{}
```

Unlike C++, the exception requires that it be a class that derives from Exception.

## About finally blocks

A try block is usually followed immediately by the keyword catch, which is followed by the catch keyword's block. Control passes to the catch block in the event of any error anywhere within the try block. The argument to the catch block is an object of class Exception or, more likely, a subclass of Exception.

A finally block accompanies the try block, regardless of whether an exception was caught. The finally is called before the stack unwinds to the next-method in the call chain. All finally blocks anywhere up the call chain also.

The common use of finally is to clean up. If an exception occurs, the finally block is called before the exception is propagated up. If the exception is caught, the finally block is called after the catch block. If no exception occurs, the finally block is still runs.

You often see code like this:

```csharp
try {
    // some code
} finally {
    // clean up, even if an error occurred.
}
```

## What happens when an exception occurs

When an exception occurs, the sequence of events takes place:

1. An exception is thrown.
2. The stack unwinds, looking for a catch block.
3. If an appropriate catch block is found, it executes.
4. If a finally block accompanies the try block, it executes.
5. If no catch block is found anywhere, the program crashes.
