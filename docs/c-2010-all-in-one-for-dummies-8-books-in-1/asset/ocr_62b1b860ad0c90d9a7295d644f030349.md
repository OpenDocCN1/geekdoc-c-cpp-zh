# Using information from requests

The request is a place that you can collect information about the user's
, use it. Especially on postback (though not just then), there is
lot of information that you can use, including the following:

+   * The content of the request. The type (ContentType) of the
tells us if it has data or just text. I can learn if it is ISO or
Unicode (ContentEncoding). I also know how long the request is
(ContentLength).

+   * The text of request itself. If I have all the text of the URL
(Url) and the request before this one (UrlReferrer). If I just want the query-
string (the part after the question mark), I can get it with QueryString.

+   * The user is logged into a domain (IsAuthenticated) and if so,
who is the user (LogonUserIdentity).

+   * Access to the Cookies collection (Cookies).

When you have access to the request, you can make decisions about
ent. If you need to know your login information, you have it. Check a
cookie — no problem. Confirm the querystring. Whatever needs to be done.
You get information to the business layer, get what you need to write, compose
the new page of controls, and then need to modify the response. That's
when you need the HttpResponse class.

# Altering content to clients

ASP.NET and IIS do a good job of setting up markup for a client browser.
You can tell Visual Studio that you are targeting a certain browser (say, in
a workgroup environment), and it will tweak the HTML to send the client
to make it closer to the exact implementation of the HTML standard that
browser supports.

You sometimes need to change the way the page is rendered on the client.
More often, you need to change the metadata about the page is
handled to the client. An HTML page has a lot more than the values you see on
tscreen. HttpResponse helps you to manage what you can and see can.
