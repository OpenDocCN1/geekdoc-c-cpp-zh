The code looks strikingly similar to the FTP example, as you can see in the following bit of code. The same stream is recovered; only the formatting is different.

```c
private void DownloadWebFile(string remoteFile, string localFile)
{
    FileStream localFileStream = new FileStream(localFile, FileMode.OpenCreate);
    WebRequest webRequest = WebRequest.Create(remoteFile);
    webRequest.Method = WebRequestMethods.Http;
    WebResponse webResponse = WebRequest.GetResponse();
    Stream webResponseStream = webResponse.GetResponseStream();
    byte[] buffer = new byte[1024];
    int bytes = webResponseStream.Read(buffer, 0, 1024);
    while (bytes > 0)
    {
        localFileStream.Write(buffer, 0, bytes);
        bytes = webResponseStream.Read(buffer, 0, 1024);
    }
    localFileStream.Close();
    webResponse.Close();
}
```

## E-mailing a status report

E-mail is a common requirement of networked systems. If you are working in an enterprise environment, you are going to write a larger scale application to handle all e-mail requirements, rather than make each individual application.

However, if you are writing a standalone product, it might require e-mail support. Because I happen to be writing a standalone application, that is exactly what I'm going to.

E-mail is a server-based operation; if you don't have an e-mail server that you can use to send from, this might be hard. Many ISPs no longer allow relaying which is sending an outgoing message without first having an account and logging in. Therefore, you might have trouble running this part of the sample.

## Using the System.Net Namespace

If you are in a corporate environment, however, you can usually talk to your e-mail administrator and get permission to use the e-mail server. Because outgoing requests are usually harnessed inside the firewall, relaying is often available. To build your e-mail function, follow these steps:

- 1. Add a text box to the default form in Design View, and then change to Code View. At the top of Code View, make sure you have referenced the System.Net namespace.
- 2. Create a new subroutine SendEmail. It should accept from the e-mail address, to the e-mail address, the subject of the e-mail, and the body of the e-mail.
- 3. Create a new MailMessage and pass parameters in the fromAddress, toAddress, subject, and body parameters, like this:
```csharp
MailMessage message = New MailMessage(fromAddress, toAddress, subject, body);
```
- 4. Declare a new smtpClient and pass in the address of your mail server. This can be an IP address, name, or URL.
- 5. Use the method of the SmtpClient object you created to send the MailMessage, which is passed in as a parameter.
- 6. When you're finished, make sure that you set the values of the MailMessage and SmtpClient to Nothing, because they do so resources.

Listing 4-2 shows the completed subroutine.

### Listing 4-2: The SendEmail Subroutine

```csharp
private void SendEmail(string fromAddress, string toAddress, string subject, string body)
{
    MailMessage message = new MailMessage(fromAddress, toAddress, subject, body);
    mailClient = new SmtpClient("localhost");
    client.Send(message);
}
```

Notice we use localhost as the e-mail server name. If you have an e-mail server installed locally, even IIS 6.0 with SMTP, this will work. Most of the time, you will have to put another e-mail server name in the SmtpClient constructor. The e-mail server can be found in your Outlook preferences.
