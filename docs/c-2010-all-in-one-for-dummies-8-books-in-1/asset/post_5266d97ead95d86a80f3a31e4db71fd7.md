# Returning data in different ways

The WebServiceHost is a servicehost class that happens to handle ReST very well, so we can use it for that purpose. There are a few ways to do this, just like there are in WCF. These include the following:

- .NET application running on a box can be a host. A Windows service, console application, or running WCF application can host it as long as it has access to the network device, it should work.

- IIS can host the application, and you can configure it in this code. This involves using a WebWebService object in the service codebehind, and decorating the class with attributes for configuration.

- The Web.config file can be set up to define an endpoint. This is the easiest way, and how we do it in Chapter 3. If configured this way, adding other endpoints to the code is a straightforward forward change.

# Chapter 1: Programming Dynamically!

For many years, I thought that dynamic programming referred to being really flashy while writing code. So I started wearing Hawaiian shirts. Later, I found out this isn't the case.

Dynamic programming is another one of those buzzwords that doesn't have a clear definition. At its simplest, it means developing something in such a way that the program makes decisions about how it runs, rather than when you compile.

Scripting languages are a great example of this. When you write something in script, you don't compile it at all—all the decisions are made at runtime. Ruby is another good example: most of an entire program can be typed into a command prompt and run right from there.

There are examples that are not so good—VB Classic. Remember Variant? You could declare a variable to be Variant and VB would decide what it was supposed to be until the program ran. In the best cases, this adds immense flexibility to the language. In the worst cases, Type Mismatch errors at runtime.

![](img/36596fb11aa4233d5cab0d6ddd1d82e8_794_0.png)

To give a concrete example, when you declare a variable in a dynamically typed language, you don't have to say what type you are making it. The compiler will just figure it out for you. In a static language, like C# 3.0, you do have to say what type you are making it.

Microsoft originally promised that dynamic types would never be in C#, but later the feature had to be added. Why? Mostly, it's because of the development for Microsoft Office (like the reasoning for much of the rest of Book VIII). Office uses COM, the pre-.NET structure for Microsoft applications.

# Shifting C# Toward Dynamic Typing

COM expects that the languages that use it (like VB Classic and C++) will have dynamic types. This made developing for Microsoft Office difficult for C# programmers, which was exactly opposite of what Microsoft wanted. The result? The dynamic type.

# Shifting C# Toward Dynamic Typing

So-called "dynamic languages" are a trend that keeps coming back, like recurring tides. Dynamic languages are languages that allow for loose typing, rather than static. The concept started in the 1960s with LISP. Dynamic languages came back in the late 1980s for two reasons: network management scripting and the artificial intelligence craze. Thanks to the Web, the buzzword is back again.

The World Wide Web, for those of you who aren't old enough to remember, was built on view source and dynamic languages. Microsoft's original Web development language, Active Server Pages, was built on VBScript—a dynamic language.

The Web is better with a dynamic programming environment, so the trend is probably here to stay this time (until the next big thing, anyway). C# isn't the only language feature that has been added to make it more appealing for Web programmers.

Several dynamic languages have been around for a while, like these:

- Perl
- Visual Basic
- Smalltalk
- LISP
- Scheme

Some of these aren't as popular as they once were, they are still out and have pushed the trend in the newer languages. You can see this trend in all the newer or refurbished dynamic languages that have popped up over the last ten years. Many of them have roots in the Web, while others are being newly used for the Web:

- PHP
- Ruby
- JavaScript
- Cold Fusion
