# Listing 4-1: The DownloadFile Method(string remoteFile, string localFile)

```
{
    FileStream localFileStream = new FileStream(localFile, FileMode.OpenCreate);
    FtpWebRequest ftpRequest = (FtpWebRequest)remoteFile;
    ftpRequest.Method = WebRequestMethods.Ftp.DownloadFile;
    ftpRequest.Credentials = new NetworkCredential("Anonymous", "bill@example.com");
    FtpResponse ftpResponse = ftpRequest.GetResponse();
    Stream buffer = ftpResponse.GetResponse();
    byte[] buffer = new byte[1024];
    int bytes = ftpResponse.Read(buffer, 0, 1024);
    while (bytes > 0)
    {
        localFileStream.Write(buffer, 0, bytes);
        bytes = ftpResponse.Read(buffer, 0, 1024);
    }
    localFileStream.Close();
    ftpResponse.Close();
}
```

This example is watered down, but it makes my point. The WebRequest and Response classes in the System.Net namespace are fully utilized to create the more complex FtpWebRequest, for instance. Properties like the Method of download and Credentials make it an easy.

In fact the toughest part of this process is dealing with a FileStream object, which is still the best way to move files and not specific to the System.Net namespace. Streams are discussed in Chapter 3 of this book, which covers the System.IO namespace, but they have significance to the network classes too. Streams represent a flow of data of some kind, and a flow of information from the Internet.

That's what you are doing when you get a Web page or a file from the Internet — gathering a flow of data. If you think about it, it makes sense that this is a flow, the status bar in an application shows a percentage of completion. Like pouring water into a glass, the flow of data is a stream, so the concept is named Stream.
