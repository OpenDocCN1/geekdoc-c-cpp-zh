# 750 Creating a WCF Service

```
[DataMember]
public bool BoolValue
{
    get { return boolValue; }
    set { boolValue = value; }
}

[DataMember]
public string StringValue
{
    get { return stringValue; }
    set { stringValue = value; }
}
```

Hey, look here! Decorations for the classes! And the mythical CompositeType!Don't let the name fool you — this code is just a class, like any other class. It is just like the List<T of Conference types that we returned from the ASMX service. The Framework doesn't have a Conference class — we defined it in the Data Model.

Line 4 has a [ServiceContract] attribute that is similar to [WebClass] of ASMX, and the [OperationContract] too, is similar to [WebMethod], at least in usage.

We have the DataContract. This allows us to decorate classes — even in our domain model — with attributes that define which classes and methods to go out to the service if and when the class is called into service (so to speak).
