using System;
using System.Windows.Forms;
namespace SimpleProgress
{
    public class Form1 : Form {
        // Declare the delegate. This one is void.
        delegate void UpdateProgressCallback();

        public Form1() {
            InitializeComponent();
        }

        // DoSomethingLength method takes a delegate.
        private void DoSomethingLength(UpdateProgressCallback updateProgress) {
            int duration = 2000;
            for (int i = 0; i < duration; i++) {
                Console.WriteLine("Something or other");
                // Update every tenth of the duration.
                if ((i % updateInterval) == 0 && updateProgress != null)
                    updateProgress(); // Invoke the delegate.
            }
        }

        // DoUpdate -- The callback method
        private void DoUpdate() {
            progressBar1.PerformStep();
        }

        private void button1_Click(object sender, EventArgs e) {
            // Instantiate the delegate, telling it what method to call.
            UpdateProgressCallback callback = new UpdateProgressCallback(this.DoUpdate);
            // DoSomething needs periodic progress reports.
            // This passes a delegate instance that knows how to update the bar.
            DoSomethingLength(callback);
            // Clear the bar so that it can be used again.
            progressBar1.Value = 0;
        }

        private void button2_Click(object sender, EventArgs e) {
            this.Close();
        }
    }
}

# Tracking the delegate life cycle

Look at the example through the parts of the delegate life cycle:

- 1. You define the UpdateProgressCallback delegate near the top of the class:
```csharp
delegate void UpdateProgressCallback();
```

Methods that delegate can "point" to be void, with no parameters. After the delegate return, defines the signature of any method that the delegate can point to; its return type and the number. Delegates don't have to be void — you can write delegates that return any type and take any arguments.

Defining a delegate defines a type, just as class Student (...) does. You can declare the delegate public, internal, protected, or even private, as needed.

> It's considered good form to append the name Callback to the name of a delegate type that defines a callback method, though C# couldn't care less.

- 2. You instantiate the delegate and pass the instance to the button1_Click() method:
```csharp
UpdateProgressCallback callback =
new UpdateProgressCallback(this.DoUpdate); // Instantiate the delegate.
DoSomethingLength(callback); // Pass the delegate instance to a method.
```

This delegate "points" to this class (and this is optional). To point to another class, you need an instance of that class (if the method is an instance method), and you pass the method like this:

```csharp
SomeClass sc = new SomeClass();
UpdateProgressCallback callback =
new UpdateProgressCallback(sc.DoUpdate);
```

But if the method is a static method (anywhere), pass it like this:

```csharp
UpdateProgressCallback callback =
new UpdateProgressCallback(SomeClass.DoUpdate);
```

The "length process" doesn't do much. The duration variable for 2000 iterations — a few seconds at runtime, which is more than enough for this demo. The next, method computes an "update interval" of 200 iterations by dividing the overall duration into them. Then the loop ticks off for each one, it checks whether it's time to update the user interface. Most times the loop, no update occurs. But whenever the if condition is true, the method invokes the DoProgressCallback instance that was passed to the updateProgress parameter. Modulo expression, i % update Interval, comes out with only a 0 remainder, satisfying the condition, every 200 iterations.

# Shh! Keep It Quiet — Anonymous Methods

And you have the gist of using delegates, take a quick look at Microsoft’s first cut at simplifying delegates in C# 2.0 a couple years ago.

To come out of the delegate rigamole, you can use an anonymous method. Anonymous methods are just written in more traditional notation. Although the syntax and few details are different, the effect is essentially the same whether you use a “raw” delegate, an anonymous method, or a lambda expression. You can find out about lambda expressions in your book’s companions Web site.
