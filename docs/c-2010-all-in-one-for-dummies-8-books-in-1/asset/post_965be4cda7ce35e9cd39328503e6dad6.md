# What's a Value Type?

The variable types that I describe in this chapter are of fixed length — again
with the exception of string. A fixed-length variable always occupies the
same amount of memory. So if you assign a = b, C can transfer the
value of b into a without taking extra measures to handle variable-
length types. This characteristic is why types of variables are called
value types.

The types int, double, and bool, and their derivatives (like unsigned
int) are intrinsic types built right into the processor. The intrinsic
value types plus decimal are also known as value types because variables
store the actual data. The string is neither — because the variable
actually stores a sort of "pointer" to the string's data, called a reference. TheThedata in the string is actually off in another location.

# Comparing string and char

Although strings deal with characters, the string type is amazingly different from the char. Of course, certain trivial differences exist. You enclose a character with single quotes, as in this example:

```
'a'
```

On the other hand, you put double quotes around a string:

```
"this is a string"
"a" // So is this -- see the double quotes?
```

The rules concerning strings are not the same as those characters. For one thing, you know right up that a char is a single character, and that it's for, the following code makes no sense, either as addition or concatenation:

```
char c1 = 'a';
char c2 = 'b';
char c3 = c1 + c2
```

Actually, this bit of code compiles — but with a completely different meaning from what was intended. These statements convert c1 into an int consisting of the numeric value of c1. C# also converts c2 into an int and then adds the two integers. The error occurs when trying to store the results back into c3 -- numeric data may be losing an int into the smaller char. In any case, the operation makes no sense.

A string, on the other hand, can be any length. Concatenating two strings, as shown here, does make sense:

```
string s1 = "a";
string s2 = "b";
string s3 = s1 + s2; // Result is "ab"
```

As part of its library, C# defines an entire string of operations. I describe them in Chapter 3 of this minibook.

# Naming conventions

Programming is hard enough without programmers making it harder. To make your C# source code easy to wade through, adopt a naming convention and stick to it. As much as possible, your naming convention should be adopted by all C# programmers.

Prior to the .NET era, it was common among Windows programmers to use a convention in which the first letter of the variable name indicated the type of the variable. Most of these were straightforward: f for float, s for string, and d for double. The only one that was even the strictest bit before was for int. For reasons that stretch back into the Fortran programming language of the 1960s, the single letters i, j, and k were also used as common names for int, and they are still used in C#. This style of naming was called Hungarian, after Charles Simony, a famous Microsoft executive who recently went to the International Space Station as a space tourist (Martha Stewart had his hunch).

- The names of other variables start with a capital letter, and variables start with a lowercase letter. Make these as descriptive—which often means that a name consists of multiple words. These words should be capitalized but built up between them without underscore for example, thisAlongName. Names that start with a capital are Pascal-cased, from the way 1970s-era language named them (My first book was about Pascal).

- The variables start with a lowercase letter. A typical variable name looks like this: thisAlongVariableName. This variable naming style is called camel-casing because it humps in the middle.

Hungarian naming has fallen out of favor, in recent .NET programming versions, you can simply rest the cursor on a variable in the debugger to have its data type revealed in a tooltip. That makes the Hungarian prefix a bit less useful, although some folks still hold out for Hungarian.

With the DateTime data type, you can do something like 80 different
operations, such as just out the month; get the day of the week; add
days, hours, minutes, seconds, milliseconds, months, or to a given
date: get the number of days in a given month; subtract two dates.

The following sample lines use a convenient property of DateTime called
Now to capture the present date, and one of the numerous
DateTime methods that let you convert one into another:

```
DateTime thisMoment = DateTime.Now;
int hourFromNow = thisMoment.AddHours(1);
```

You can also extract specific parts of a DateTime:

```
int year = DateTime.Now.Year; // For example, 2007
DayOfWeek dayOfWeek = DateTime.Now.DayOfWeek; // For example, Sunday
```

If you print out that DayOfWeek object, it prints like "Sunday".
And you can do here many manipulations of DateTimes:

```
DateTime date = DateTime.Today; // Get the date part.
```

The fourth line adds the three-day duration to the DateTime representing right
now, resulting in a new DateTime whose component is greater than
