
## 13.4 Complex Numbers

C++ supports mathematical numbers via the complex class. Recall from mathematics that a complex number has a real component and an imaginary component. Often written as a+bi, a is the real part, ordinary real number, and bi is the imaginary part where b is a real number and i^2 = -1.

The complex class in C++ is a complex vector. In the angle you specify the precision of the number's components:

```
complex<float> fc;
complex<double> dc;
complex<long> ldc;
```

Here, the real and imaginary coefficient of fc are single-precision floating-point values. dc and ldc have the indicated precisions. Listing 13.7 (complex.cpp) is a small example that computes the product of complex conjugates (which should be real numbers).

```
Listing 13.7: complex.cpp
// File complex.cpp
#include <iostream>
#include <complex>

using namespace std;

int main() {
    // c1 = 2 + 3i, c2 = 2 - 3i; c1 and c2 are complex conjugates
    complex<double> c1(2.0, 3.0), c2(2.0, -3.0);

    // Compute product "by hand"
    double real = c1.real();
    double imag1 = c1.imag();
    double real2 = c2.real();
    double imag2 = c2.imag();

    cout << c1 << " * " << c2 << " = " << endl;
    cout << real*real2 + imag1*real2 + real*imag2 - imag1*imag2 << endl;

    // Use complex arithmetic
    cout << c1 << " + " << c2 << " = " << c1+c2 << endl;
}
```

Listing 13.7 (complex.cpp) prints

| (2,3) * (2,-3) = 13 |
| (2,-3) * (2,3) = (13,0) |

Observe that the program displays the complex number 2-3i as the ordered pair (2,-3). The first element of the pair is the real part, and the second element is the imaginary coefficient. If the imaginary part is zero, the number is a real (or, in this case, a double).

Imaginary numbers have scientific and engineering applications that extend the scope of this book, so this concludes our brief intro into C++s complex class. If you need to solve problems that involve complex numbers, more information can be found at http://www.cplus.com/reference/std/complex/.

## 13.5 BETTER PSEUDORAND NUMBER GENERATION

Listing 12.9 (comparepermutations.cpp) showed that we must care when randomly permuting the contents of a vector. A naive approach can introduce accidental bias into the result. It turns out that our simple technique for generating pseudorandom numbers using rand and modulus has some issues.

Suppose we wish to generate pseudorandom numbers in the range 0–9999. This range spans 10000 numbers. Using Visual C++ RAND_MAX is 32767, which is large enough to handle a maximum value of 9999. The expression rand() % 10000 will evaluate to a number in our desired range. A good pseudorandom number generator should be just like producing one number another. In a program that generates a billion pseudorandom numbers in the range 0–9999, we would expect each number value to appear approximately $\frac{1,000,000,000}{10,000} = 100$ times. The actual value for a given number will vary slightly from one run, but the average over billion runs will be close to 100.

Listing 13.8 (badrand.cpp) evaluates the quality of the rand with modulus technique by generating a billion pseudorandom numbers in a loop. It counts the number of times the pseudorandom generator produces 5 and also counts the number of times 9995 appears. Note that 5 is near the beginning of the range 0–9999, and 9995 is near the end of that. To verify the consistency of its results, it repeats this 10 times. The program reports the results of each individual trial, and it computes the average of the 10 trials.

```
Listing 13.8: badrand.cpp
#include <iostream>
#include <iomanip>
#include <cstdlib>
#include <ctime>

using namespace std;

int main() {
    // Initialize a random seed
    srand(static_cast<unsigned>(time(NULL)));

    // Verify the largest number rand can produce
    cout << "RAND_MAX = " << RAND_MAX << endl;

    // Total counts over all runs.
    // Make these double-precision floating-point numbers
    // so the average at the end will use floating-point arithmetic.
    double total5 = 0.0, total9995 = 0.0;

    // Accumulate the results of 10 trials, with each trial
    // generating 100,000,000 pseudorandom numbers
    const int NUMBER_OF_TRIALS = 10;

    for (int trial = 1; trial <= NUMBER_OF_TRIALS; trial++) {
        // Initialize counts for this run
        int count5 = 0, count9995 = 0;
        // Generate a billion pseudorandom numbers in the range 0...9999
        for (int i = 0; i < 1000000000; i++) {
            int r = rand() % 10000;
            if (r == 5) // Number 5 generated, count it
                count5++;
            else if (r == 9995) // Number 9995 generated, count it
                count9995++;
        }
        // Display the number of times the program generated 5 and 9995
        cout << "Trial " << setw(2) << trial << " 5: " << count5 << " 9995: " << count9995 << endl;
        total5 += count5; // Accumulate the counts
        total9995 += count9995; // average at the end
    }
    cout << "Averages for " << NUMBER_OF_TRIALS << " trials: 5: " << total5 / NUMBER_OF_TRIALS << " 9995: " << total9995 / NUMBER_OF_TRIALS << endl;
}
```

The first line verifies that the largest pseudorandom number that C++ can produce through rand is 32,767. The next 10 lines of the program show the result of each trial, monitoring the activity of the one billion generators. We are dealing with pseudorandom numbers, the results for each trial will not be exactly the same, but over billion runs they should be consistent. Note how consistent the results are among them.

While expected both 5 and 9,995 to appear about the same number of times—approximately 100,000 times—in fact the number 5 appeared consistently more than 100,000 times, averaging 122,072 times. The number 9,995 appeared less than 100,000, averaging 91,554.2. Note that 122,072 = 1.33; this means the value 5 appeared 1.33 times more than 9,995. Looking at it another way, 1.33 ≈ 4/3 so for every four times the program produced a 5 it produced 9995 only three times. As we will see, this ratio of 4:3 is not accidental.
