# Fine Tuning Objects

In Chapter 14 we introduced the basics of object-oriented programming: private data, public methods, and automatic initialization and destruction. In this chapter examine some details that enable C++ programmers to tune class design.

## 15.1 Pointers to Objects and Object Arrays

Given the Point class from Section 14.2, the statement

```cpp
Point pt;
```

declares the variable pt to be a Point object. With primitive data, we can declare pointers to objects:

```cpp
Point pt;
Point *p_pt;
```

Here, p_pt is a pointer to a Point object. Before we use the pointer we must initialize it to point to a valid object. We can assign the pointer to refer to an existing object, as in

```cpp
p_pt = &pt;
```

or use the new operator to dynamically allocate an object from the heap:

```cpp
p_pt = new Point;
```

If the class has a constructor that accepts parameters, we need to provide the appropriate arguments when using new. Recall the Account class from Section 14.4. The declarations

```cpp
Account acc("Joe", 3143, 90.00);
Account *acct_ptr;
```

before we use acct_ptr must point to a valid object. As in the Point class example, we can assign the pointer to refer to an existing object, as in

```cpp
acct_ptr = &acct;
```

or use the new operator to dynamically allocate an object from the heap:

```cpp
acct_ptr = new Account("Moe", 200, 1300.00);
```

Note that we include the arguments expected by the Account class constructor. This statement allocates memory for one Account object and executes the constructor's code to initialize the newly created object. Figure 15.1 illustrates a pointer to an account object. C++ supports vectors and arrays of objects, but they present special challenges. First, consider a simple situation. The Point class defines no constructor, so the following code is valid:

```cpp
vector<Point> pts(100);      // Okay
```

The compiler happily generates code that will allocate enough space for 100 Point objects. No special initializations are needed since Point has no constructor. What if a class defines a constructor that accepts arguments and does not supply a constructor that requires arguments? Consider the Account class. The following statement is illegal:

```cpp
vector<Account> accts(100);      // Illegal, the Account class has
                                            // no default constructor
```

When creating the accts elements, C++ expects a default constructor to properly initialize all of the vector's elements. Only one constructor in the Account class requires arguments, and so the compiler refuses to accept such a declaration. The compiler cannot enforce that the vector's elements are properly initialized before the programmer uses the vector.

One solution is to use pointers, as in

```cpp
vector<Account*> accts(100);      // A vector of account pointers
```

Note that this does not create any Account objects. The programmer subsequently iterate through the vector and uses new to individually initialize each account object. An example of this would be

```cpp
vector<Account*> accts(100);      // A vector of account pointers
for (int i = 0; i < 100; i++) {
    // Get information from the user
    cin >> name >> id >> amount;
// Create the new account object
    accts[i] = new Account(name, id, amount);
}
```

The dot operator syntax to access a field of an object through a pointer is a bit awkward:

```cpp
Point *p = new Point;
(*p).x = 253.7;
(*p).y = -00.5;
```

The parentheses are required since the dot (.) has higher precedence than the pointer dereferencing operator (*). Without the parentheses, the statement would be evaluated as if the parentheses were placed as shown here

```cpp
*p.x) = 253.7; // Error
```

The variable p is not a Point object, but a pointer to a Point object, so it must be dereferenced with the * operator before applying the .operator. C++ provides a simpler syntax to access fields of an object through a structure. The pointer operator eliminates the need for the parentheses:

```cpp
Point *p = new Point;
p->x = 253.7;
p->y = -00.5;
```

The pair of symbols -> constitute one operator (no space is in between), and the operator is meant to look like an arrow pointing right. There is no left arrow pointing in C++.

You can use the -> operator to access the methods of an object referenced by a pointer:

```cpp

```

An executing program will not automatically deactivate memory allocated with new. It is the programmer's responsibility to manually deactivate the memory when the object is longer needed. The delete operator frees a single dynamically allocated object

The following function has a logic error because it fails to free memory allocated with new:

```cpp
void faulty_func() {
    Account *acct_ptr = new Account("Joe", 400, 1300.00);
    if (acct_ptr->withdraw(10.00))
        cout << "Withdrawal success" << endl;
    else
        cout << "*** Insufficient funds ***" << endl;
    acct_ptr->display();
}
```

## 15.2 THE THIS POINTER

Here, acct_ptr is a local variable, so occupies space on the stack. It represents an address, number. The space for the acct_ptr variable is automatically deallocated when faulty_func completes. The program has acct_ptr points to memory that was allocated with new, and this memory is not freed until the function returns. The pointer acct_ptr is the only way to get to memory, so when the function is finished, memory is lost for the life of the program. If the program runs to completion, the leak may go undetected. In a longer running program such as a web server, memory leaks occurs repeatedly and eventually all of available memory becomes used.

```cpp
void faulty_func() {
  Account *acct_ptr = new Account("Joe", 400, 1300.00);
  if (acct_ptr->withdraw(10.00))
    cout << "Withdrawal success" << endl;
  else
    cout << "*** Insufficient funds ***" << endl;
  acct_ptr->display();
  delete acct_ptr;
}
```

Recall (10.6) in C++ there is one literal value to a pointer of any type may be assigned—nullptr.

Account *p_rec = nullptr; // p_rec is null

A pointer with the value nullptr is interpreted to mean a pointer that is pointing to nothing. An attempt to delete a null pointer is legal and does nothing.
