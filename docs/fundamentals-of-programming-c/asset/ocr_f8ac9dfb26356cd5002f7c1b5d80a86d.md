The values with the curly braces constrain all the values that a variable of an enumerated type can obtain. The name of each of an enumerated type is a valid C++ identifier (see Section 3.3).

Given the Color type defined as above, we can declare and use variables of the enum type as shown by the following code fragment:

```
Color myColor;
myColor = Orange;
```

Here the variable myColor has our custom type Color, and its value is Orange.
It is illegal to reuse an enumerated value within another enumerated type within the same program. In the following code, the enumerated value Light is used in Shade and Weight:

```
enum Shade { Dark, Dim, Light, Bright };
enum Weight { Light, Medium, Heavy };
```

These two enumerated are incompatible because they share the value Light, and so the compiler will issue an error.
The value within an enum type must be unique. Convention in C++ is to capitalize the first letter of an enum and its associated values, although the language does not enforce this convention.

An enum type is handy for representing a small number of discrete, non-numeric options. For example, a program that controls the movements made by a robot. The allowed orientations are forward, backward, left, right, and down. The program can encode these movements as integers, where 0 means forward, 1 means backward, etc. While implementation works, it is not ideal. Integers may assume more values than just the six values. The compiler cannot ensure that an integer representing a move will stay in the range 0... If the programmer makes a mistake and under certain circumstances assigns a value outside of the range 0... then the program may result in erratic behavior with the robot. With enum types, if the programmer uses only the named values of the enum, the compiler will ensure that such a mistake cannot happen.

A particular enumerated type necessarily has fewer values than a type such as int. Imagine making an integer enum type and having to list all of its values! (The 32-bit int represents over four billion values.) Enumerated types, therefore, are practical for types that have a relatively small range of values.
