If a method is not supposed to change the state of an object, that method should be const. In the SimpleRational class, the methods get_numerator and get_denominator return copies of the fraction's numerator and denominator. Neither method is intended to modify any instance variables. If we look at the code for these methods, we see that indeed method changes anything about a SimpleRational object. What if the programmer make a mistake—perhaps a spurious copy and paste error—and the statement

```
numerator = 0;
```

made its way into the get_numerator method? Unfortunately, the ways thing stand, the compiler cannot detect this error, and get_numerator contains a serious logic error.

We can remove the possibility of such an error by declaring get_numerator and (get_denominator

```
class SimpleRational {
  public:
    /* stuff omitted ... */
    int get_numerator() const {
      return numerator;
    }
    int get_denominator() const {
      return denominator;
    }
    /* other stuff omitted ... */
}
```

The const keyword goes after the closing parenthesis of the parameter list and before the opening curly brace of the method's body. If we accidentally reassign an instance variable in a const method, the compiler will report an error.

Declaring a const is not merely a defensive programming strategy used by a class developer. Methods declared to be const can be called with const objects, it is illegal to invoke a non-const method with a const object. The new const version of SimpleRational's get_numerator, the following

```
const Rational fract(1, 2); // Constant fraction 1/2
fract.set_numerator(2); // Error, cannot change a constant
```

is still illegal, since Rational::set_numerator is not const,

```
const Rational fract(1, 2); // Constant fraction 1/2
cout << fract.get_numerator(); // OK with const get_numerator
```

now is legal.

Any method that has no need to change a field in the object should be declared const. A const method can be used with const and non-const objects, but a non-const method cannot be used with const objects. For maximum flexibility, always declare a method to const unless doing so would prevent the method from doing what it is supposed to do.
