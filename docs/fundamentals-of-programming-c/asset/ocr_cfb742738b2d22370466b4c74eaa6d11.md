# 16.5 AUTOMATING TEST

```
// sort has a bug (it does not doing anything)
void sort(vector<int>& vec) {
    // Not yet implemented
}

// sum has a bug (misses first element)
int sum(const vector<int>& vec) {
    int total = 0;
    for (size_t i = 1; i < vec.size(); i++) {
        total = vec[i];
    }
    return total;
}

int main() {
    Tester t; // Declare a test object
    // Some cases to test sort
    vector<int> vec = {4, 2, 3};
    sort(vec);
    t.check_equals("Sort test #1", {2, 3, 4}, vec);
    vec = {2, 3, 4};
    sort(vec);
    t.check_equals("Sort test #2", {2, 3, 4}, vec);
    // Some cases to test sum
    t.check_equals("Sum test #1", sum({0, 3, 4}), 7);
    t.check_equals("Sum test #2", sum({3, 0, 5}), 2);
```

The program's output is

![](bbox=[0.226, 0.595, 0.823, 0.725])

Notice that the sort function has to be implemented, but we can test it anyway. The first test is bound to fail. The second test checks to see if our sort function will not disturb an already sorted vector, and we pass this with no problem. This is an example of coincidental correctness.

In the sum function, the programmer was careless and used 1 as the index for the vector. Notice that the first test does not catch the error, the element in the zeroth position (zero) does not affect the outcome. A tester must be creative and devious to try and force the code under test to demonstrate its errors.
