# Chapter 14

# Custom Objects

In earlier times programmers wrote in the machine language of the computer system because compilers had yet to be invented. The introduction of variables in association with higher-level programming languages marked a great step forward in the late 1950s. No longer did programmers need to be concerned with the lower-level details of the processor and absolute memory addresses. Named variables and functions allow programmers to abstract away machine-level details and focus on concepts that transcend computers, such as integers and characters. Objects provide a level of abstraction that go beyond simple values—developers can focus on more complex things like geometric shapes, bank accounts, and aircraft wings. Programming objects that represent these real-world things possess capabilities that go far beyond the simple variables we have studied to this point.

A C++ object typically consists of a collection of data and code. By bundling data and code together, objects store information and provide services to other parts of the software system. Objects form a computational unit that makes up the overall application. A programming object can model a real-world object more naturally than a collection of simple variables since it can encapsulate complexity. Objects make it easier for developers to build complex software systems.

C++ is classified as an object-oriented language. Most modern programming languages have some degree of object orientation. This chapter shows how programmers can define, create, and use custom objects.

# 14.1 Object Basics

Consider the task of dealing with geometric points. Mathematicians represent a single point as an ordered pair of real numbers, usually expressed as (x, y). In C++, the double type serves to approximate a subset of the mathematical real numbers. A point with coordinates within the range of double-precision floating-point numbers can be modeled by double variables. Notice something that conceptually is one requires two variables in C++. As a consequence, a function that computes the distance between two points requires four parameters—x1, y1, x2, and y2—rather than two points—{x1,y1} and {x2,y2}. Ideally, we should be able to use one variable to represent a point.

One approach to represent a point using a two-element vector, for example:

```
vector<double> pt = { 3.2, 0.0 };
```

# 14.1 OBJECT BASICS

This approach has several problems:

- We must use numeric indices instead of names to distinguish between the components of a point object. We may agree that pt [0] means the x coordinate of point pt and pt [1] means the y coordinate of point pt, the compiler is powerless to detect the error if a programmer uses an expression like pt [19] or pt [-3]
- We cannot restrict the vector's size to two. A programmer may accidentally push extra items into the back of a vector returning representing object.
- We cannot use a vector to represent objects in general. Consider a bank account object. A bank account could include many other diverse things, an account number (integer), a customer name (string), and an interest rate (double-precision floating-number). Vector implementation of such an object is impossible because the elements in a vector must be of the same type.

In storing data, we want our objects to be active agents that perform computational tasks. We need to be able to associate code with a class of objects.

Before examining how C++ specifically handles objects, we will first explore what capabilities are desirable. Consider an automobile. An automobile user, the driver, uses the car for transportation. The user provides input to the car via its steering wheel, accelerator and brake pedals, turn signal, shift lever, etc. The automobile produces outputs to the driver with its speedometer, tachometer, various instrument lights and gauges. These standardized driver-interfaces enable an experienced driver to drive easily without the need for specific details.

The typical driver can use a car very effectively without understanding how it works. From point A to point B the driver does not need to know the number of cylinders in the engine, the engine's horsepower, or whether the vehicle is front-wheel drive or rear-wheel drive. A driver may look under the hood of the engine, but the driver cannot confirm any details about what is inside the engine without considerable effort or expense. Many details are of interest only to enthusiasts or mechanics. There may be only a few engineers capable of understanding and appreciating other esoteric details about the vehicle's design and implementation.

In some ways objects in object-oriented programming are analogous to automobile components. An object may possess considerable capability, but a programmer using the object needs to know only what the object does without knowing how it works. An object provides an interface to any code that wishes to use it. A typical object exposes some parts to clients and keeps other parts hidden from clients. The designer's, on the other hand, must know the complete details of the object's implementation.

C++ uses the class keyword to define the structure of an object. A class serves as a pattern or template from which a programmer may produce objects. We will concentrate on five things facilitating object-oriented programming with C++ classes:

1. A class can define the data that constitutes an object's state.
2. A class can define code to be executed on an object that provides services to clients that use the object.
3. A class may define code that initializes a newly-created object ensuring it begins life in a well-defined state.
