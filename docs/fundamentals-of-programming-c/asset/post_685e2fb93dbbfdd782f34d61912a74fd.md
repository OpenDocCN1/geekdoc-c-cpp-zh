## 15.5. Preventing Multiple Inclusion 

C++ follows the definition rule, which means a variable, function, class, instance variable, or method may not have more than one definition in the same context. The code within the following function definition violates the one definition rule:

```cpp
int sum_and_display(const vector<int>& list) {
    int s = 0, size = list.size();
    // Add up the values in the list
    int i = 0;
    while (i < size) {
        s += list[i];
        i++;
    }
    // Print the contents of the list
    int i = 0; // Illegal, variable i already defined above
    while (i < size) {
        cout << setw(5) << list[i] << endl;
        i++;
    }
    cout << "----------" << endl;
    cout << setw(5) << s << endl;
}
```

The line

```cpp
int s = 0, size = list.size();
```

is not a problem even when the identifier size appears twice. The first appearance denotes the local variable named size, and the second use is a call to the size method of the std::vector class. The statement defines (declares) only the variable size; the size method already has been defined in the std::vector class (and the compiler processes its definition from the vector header file).

The variable i has two distinctions in the same context, so its redeclaration right before the display code is an error.

Like a variable, a class may have only one definition. When we build used in programs we must take care that we do not violate the one definition rule. In fact, we can violate the one definition even if we define it only once!

To see how we accidentally violate the one definition rule, consider the following simple example. Suppose we have a simple class declared in counter.h:

```cpp
class Counter {
    int count;
public:
    // Allow clients to reset the counter to zero
    void clear();

    // Allow clients to increment the counter
    void inc();

    // Return a copy of the counter's current value
    int get() const;
};
```

with its implementation in counter.cpp:

```cpp
// Allow clients to reset the counter to zero
void Counter::clear() {
    count = 0;
}

// Allow clients to increment the counter
void Counter::inc() {
    count++;
}

// Return a copy of the counter's current value
int Counter::get() const {
    return count;
}
```

Next, consider the following two header files defining objects that themselves use Counter objects, wide-get.h:

```cpp
// File widget.h

#include "count.h"

class Widget {
    Counter meter;
public:
    // Other stuff omitted
};
```

and gadget.h:

```cpp
// File gadget.h

#include "count.h"

class Gadget {
    Counter ticker;
public:
    // Other stuff directive
};
```

The preprocessor

```cpp
#include "count.h"
```

is required for widget.h, because the compiler will accept gadget.h. Similarly, client code must use:

```cpp
#include "count.h"
```

```cpp
int main() {
    Widget w;
    Gadget g;
}
```

Like a C++ program, the preprocessor can maintain a collection of variables. The preprocessor directive #ifndef evaluates whether the preprocessor has seen the definition of a variable; #indef returns false if it has seen the definition. The #define directive defines a variable. The effect of the #ifndef/#define/#endif directives is that the preprocessor will not include the header file more than once when it is processing a C++ source file. This means the compiler will see the class definition exactly once.

#endif should be used to avoid class declaration in the header file and do not appear in the .cpp file that contain the method definitions.

```cpp
#ifndef COUNT_H
#define COUNT_H

class Counter {
    int count;
public:
    // Allow clients to reset the counter to zero
    void clear();

    // Allow clients to increment the counter
    void inc();

    // Return a copy of the counter's current value
    int get() const;
};

#endif
```
