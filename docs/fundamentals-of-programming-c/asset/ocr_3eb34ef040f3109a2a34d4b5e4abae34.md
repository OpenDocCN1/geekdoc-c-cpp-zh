# 13.5 Better Pseudorandom Number Generation

Listing 12.9 (comparepermutations.cpp) showed that we must care when randomly permuting the contents of a vector. A naive approach can introduce accidental bias into the result. It turns out that our simple technique for generating pseudorandom numbers using rand and modulus has some issues.

Suppose we wish to generate pseudorandom numbers in the range 0–9999. This range spans 10000 numbers. Using Visual C++ RAND_MAX is 32767, which is large enough to handle a maximum value of 9999. The expression rand() % 10000 will evaluate to number in our desired range. A good pseudorandom number generator should be just like produce one number another. In a program that generates billion pseudorandom numbers in the range 0–9999, we would expect each number value

to appear approximately $\frac{1,000,000,000}{10,000} = 100$ times. The actual value for a given number will vary slightly from the one run, but the average over billion runs will be close to 100.

Listing 13.8 (badrand.cpp) evaluates the quality of the rand with modulus technique by generating billion pseudorandom numbers in a loop. It counts the number of times the pseudorandom generator produces 5 and also counts the number of times 9995 appears. Note that 5 is near the beginning of the range 0–9999, and 9995 is near the end of that. To verify the consistency of its results, it repeats this 10 times. The program reports the results of each individual trial, and it computes the average of the 10 trials.
