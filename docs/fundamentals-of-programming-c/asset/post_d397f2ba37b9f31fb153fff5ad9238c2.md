A simple recursive function definition is based on four key concepts:

- 1. The function must optionally call itself within its definition; this is the recursive case.
- 2. The function must optionally not call itself within its definition; this is the base case.
- 3. Some sort of conditional execution (such as an if/else statement) selects between the recursive case and the base case on one or more parameters passed to the function.

We can easily write a non-recursive factorial function, as Listing 10.6 (nonrecursfact.cpp) shows.

### Listing 10.6: nonrecursfact.cpp

```cpp
#include <iostream>

using namespace std;

/*
 * factorial(n)
 * Computes n!
 * Returns the factorial of n.
 */
int factorial(int n) {
    int product = 1;
    for (int i = n; i > 0; i--) {
        product *= i;
    }
    return product;
}

int main() {
    // Try out the factorial function
    cout << "0! = " << factorial(0) << endl;
    cout << "1! = " << factorial(1) << endl;
    cout << "6! = " << factorial(6) << endl;
    cout << "10! = " << factorial(10) << endl;
}
```

Which factorial function is better, the recursive or non-recursive version? Generally, if the same algorithm is being used by both recursive and non-recursive functions, the non-recursive version will be more efficient. A function call is a relatively expensive operation compared to a variable assignment or comparison. The body of the non-recursive factorial function invokes no functions, but the recursive version calls itself—during all but the last recursive invocation. The iterative version of factorial is much more efficient than the recursive version.

Even though the iterative version of the factorial is technically more efficient than the recursive version, on many systems you could not tell the difference. The factorial function "grows" fast, meaning it returns fairly large results for small arguments. For example, 32-bit integers, 13! is the largest integer value that can be computed. The execution difference between the two is negligible on most systems.

### Listing 10.7: gcd.cpp

```cpp
#include <iostream>

using namespace std;

/*
* Euclid's method to compute
* the greatest common divisor
* (also called greatest common
* factor) of m and n.
* Returns the gcd of m and n.
 */
int gcd(int m, int n) {
    if (n == 0)
        return m;
    else
        return gcd(n, m % n);
}

void iterative_gcd(int num1, int num2) {
    // Determine the smaller of num1 and num2
    int min = (num1 < num2) ? num1 : num2;
    // 1 is a definitely common factor to all ints
    int largestFactor = 1;
    for (int i = 1; i <= min; i++) {
        if (num1 % i == 0 && num2 % i == 0)
            largestFactor = i; // Found larger factor
    }
    return largestFactor;
}

int main() {
    for (int num1 = 1; num1 <= 100; num1++) {
        for (int num2 = 1; num2 <= 100; num2++) {
            cout << "gcd(" << num1 << ", " << num2 << ") = " << gcd(num1, num2) << endl;
        }
    }
}
```

Note that this gcd function is recursive. The algorithm is much different from our original iterative version. Because of the difference in the algorithms, the recursive version is actually more efficient than our original iterative version. A recursive function, therefore, cannot be dismissed as inefficient just because it is recursive.

Listing 10.8: histobar.cpp provides another example of a recursive function. The segments1 function uses iteration to draw segments that make up a bar that could be part of a histogram. The segments2 function does that thing, except it uses recursion.

### Listing 10.8: histobar.cpp

```cpp
#include <iostream>
using namespace std;

// Draws a bar n segments long
// using iteration.
void segments1(int n) {
    while (n > 0) {
        cout << "*";
        n--;
    }
    cout << endl;
}

// Draws a bar n segments long
// using recursion.
void segments2(int n) {
    if (n > 0) {
        cout << "*";
        segments2(n - 1);
    } else {
        cout << endl;
    }
}

int main() {
    segments1(5);
    segments2(5);
    return 0;
}
```

## 10.5 Making Functions Reusable

The notion of copying code from one program to another is not ideal, however, it is too easy for the code to be incomplete or for some error to be introduced during the copy. Furthermore, code duplication is wasteful. Finally, in the most compelling demonstration of the weakness of this copy-paste approach, if a bug is discovered in the function the other 99 programs will still contain their bug. The situation would be the same if a user were to define their own function; while the function definitions might be identical, there is no mechanism for tying these common together.

Fortunately, C++ provides a way to develop functions in separate files and combine the code from these independently developed functions into one program. We can compile the source files separately, and the linker can combine the code into an executable. What we need is for the compiler to verify that the calling code in one file is correctly invoking the function defined in another source file.

10.9 provides the first step in making a reusable is_prime function.

In Visual Studio, you simply add a new item to your project as a header file named prime.h, and you are ready to type the line of code into the newly created file. This file contains the prototype for our is_prime function (see earlier discussion of function prototypes in Section 8.1). Caller calls the code so that compiler can check if the caller is using our is_prime function must include this file to function properly. For an attempt, to pass two arguments to is_prime would result in a compiler error since the prototype accepts a single integer.

A second file, which could be named prime.cpp, appears in Listing 10.10 (prime.cpp).

### Listing 10.10: prime.cpp
```cpp
// prime.cpp
#include <math> // Needed for sqrt

bool is_prime(int n) {
    if (n <= 1) return false;
    for (int i = 2; i <= sqrt(n); i++) {
        if (n % i == 0) return false;
    }
    return true;
}
```
