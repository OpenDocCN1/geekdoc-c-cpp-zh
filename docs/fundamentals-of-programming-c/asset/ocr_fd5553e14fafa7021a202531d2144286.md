Another example, suppose x and y are two integer variables in some program. How would we interchange the values of the two variables? We want x to have y's original value and y to have x's original value. This code may seem reasonable:

```
x = y;
y = x;
```

The problem with this code is that the first statement is executed, x and y both have the same value (y's original value). The second assignment is superfluous and does nothing to change the values of x or y. The solution requires a third variable to remember the original value of one of the variables before it is reassigned. The correct code to swap the values is

```
temp = x;
y = y;
y = temp;
```

This small example emphasizes the fact that algorithms must be precisely specified. Informal notions about how to solve a problem can be valuable in the early stages of program, the coded program requires a correct description of the solution.

The algorithms we have seen so far begin. Statement 1, followed by Statement 2, until every statement in the program has been executed. These constructs allow us to build programs that do more interesting things, but more complex algorithms are required to make it happen. We must not lose sight of the fact that a complicated algorithm is 99% correct is not correct. An algorithm's design and implementation can be detailed by allant to the smallest of details.
