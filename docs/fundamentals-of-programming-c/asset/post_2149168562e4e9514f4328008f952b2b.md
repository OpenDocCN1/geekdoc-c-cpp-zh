```cpp
/*
 * selection_sort(a, n, compare)
 * Arranges the elements of vector vec in an order determined
 * by the compare function.
 * vec is a vector.
 * compare is a function that compares the ordering of
 * two types that support the < operator.
 * The contents of vec are physically rearranged.
 */
template <typename T>
void selection_sort(vector<T>& vec, int n, bool (*compare)(const T&, const T&)) {
    int n = vec.size();
    for (int i = 0; i < n - 1; i++) {
        // Note: i, and j represent positions within vec.
        // vec[i], vec[j], and a[j] represents the elements at
        // those positions
        // small is the position of the smallest value we've seen
        // so far; we use it to find the smallest value less
        // than vec[i]
        int small = i;
        for (int j = i + 1; j < n; j++) {
            if (compare(vec[j], vec[small]))
                small = j; // Found a smaller value
        }
        // Swap vec[i] and vec[small], if a smaller value was found
        if (i != small)
            swap(vec[i], vec[small]); // Uses std::swap from <utility>
    }
}
```

Notice that all the functions except main are generic functions. The selection_sort function is the most interesting one. It accepts a generic function and a pointer that accepts generic parameters of the same type. In one of its iterations in main:

selection_sort(list, greater_than<int>);

the expression greater_than<int> is an explicit template instantiation, and it tells the compiler we want to send the selection_sort function a pointer to the greater_than instantiated with integer parameters. This explicit instantiation is required because the compiler cannot automatically instantiate the greater_than function without an actual call to the function params, and a pointer to a function is not a function invocation. At this point in the program we are not calling the greater_than function but only passing a pointer to it. Calling it would provide the necessary type information to the compiler via the actual parameters, but a pointer to a function does not contain parameter information. The compiler needs the assistance of this explicit template instantiation from the std:

The call to swap selection_sort is actually invoking the swap function from the standard library. #include <utility> directive brings in the declaration for std::swap is itself a template function.

The compiler can instantiate an actual function from a template function only if the type substituted for the template parameter supports it within the function. Consider the following code:

```cpp
// Make two ofstream objects
std::ofstream fout1("file1.data"), fout2("file2.data");
```

The expression less_than(fout1, fout2) is illegal because no operator exists to compare two ostream objects; the compiler does not produce the machine language that represents a expression < b when a and b are ofstream. Ultimately, the compiler cannot instantiate a all_than function that accepts ofstream objects.

When programmers use incorrectly or construct incorrect template functions or classes, the compiler can detect and report the problems. This is because template messages tend to be difficult even for programmers.

// Compare them // <-- Error!
