```
char *word = "Howdy!";
out << word << endl;
```

The variable word is declared to be a pointer to a character, and it is initialized to point to string literal.

The following code fragment is less safe:

```
char word[256];
cin >> word;
```

word can hold 255 characters plus the null terminator. If the user types in relatively short words (length less than 255 characters), there is no problem. If at any time the user types more than characters will fit in the array, executing the program will have a problem. The problem is known as a buffer overrun. In the best case, buffer overflows lead to buggy programs. In the worst case, users can exploit buffer overflows to compromise software systems. Buffer overflows are logic errors and you should take care to avoid them.

The following code provides a safe way to get user input:

```
char word[10];
fgets(word, 10, stdin);
out << word << endl;
```

The fgets is a standard C function. The second parameter specifies the maximum length of the string, including the terminating character, which will be placed in the string. The last argument, stdin is a C struct related to the C++ object cin. In order to use fgets within a program you must include the <stdio> header.

The following code has bugs for:

```
char *word;
cin >> word;
```

In this case word points to a random location in memory, and no buffer has been allocated to receive the input characters from cin. The program's behavior executing this code is undefined, but it likely will lead to the program crashing. Independently, depending on how the operating system manages memory, the program may run a few times and then crash. Regardless, the program contains a serious bug.

When passing an array to a caller must provide the size of the array so that the function can process the array properly. Since C strings are not terminated, such information is not necessary.
