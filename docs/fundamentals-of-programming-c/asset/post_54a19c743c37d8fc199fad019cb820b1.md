## 10.1 Global Variables

All variables to this point have been local to functions or local to blocks within the bodies of conditional or iterative statements. Local variables have some desirable properties:

- A local variable occupies memory only when the variable is in scope. When the program execution leaves the scope of a local variable, it frees up the memory for that variable. This freed memory is available for use by the local variables in other functions during their invocations.

- We can use the same variable name in different functions without any conflict. The compiler derives all of its information from a local variable used within a function from the declaration of variable in that function. The compiler will not look for the declaration of a local variable of another function. Thus, there is no local variable in one function can interfere with a local variable declared in another function.

A local variable transparency, so its value is lost between invocations. Sometimes it is desirable to have a variable that lives as long as the program is running; that is, until the main function completes. In contrast to a local variable, a global variable is declared outside all functions and is not local to any function. In fact, any function that appears in the source code after the point of the global variable's declaration may legally access and/ modify that variable. Listing 10.1 (global.cpp) uses a global variable named result that is shared by all functions in the program.

```cpp
// Listing 10.1: global.cpp
#include <iostream>
#include <cmath>
using namespace std;

/*
 * help_screen
 * Displays information about how the program works
 * Accepts no parameters
 * Returns nothing
 */
void help_screen() {
    cout << "Add: two numbers" << endl;
    cout << "Example: 2.0" << endl;
    cout << "Subtract: two numbers" << endl;
    cout << "Example: 5.0" << endl;
    cout << "Print: Displays the result of operation" << endl;
    cout << "Example: p" << endl;
    cout << "Help: Displays this screen" << endl;
    cout << "Example: h" << endl;
    cout << "Quit: Exits the program" << endl;
    cout << "Example: q" << endl;
}

/*
 * Global variables used by several functions */
double result = 0, arg1, arg2;

/*
 * get_input
 * Assigns the globals arg1 and arg2 from keyboard input
 */
void get_input() {
    cin >> arg1 >> arg2;
}

/*
 * report
 * Reports the value of global result
 */
void report() {
    cout << result << endl;
}

/*
 * Assigns the sum of the globals arg1 and arg2
* to the variable result
 */
void add() {
  result = arg1 + arg2;
}

/*
 * subtract
 * Assigns the difference of the globals arg1 and arg2
* to the variable result
 */
void subtract() {
  result = arg1 - arg2;
}

/*
 * main
 * Runs a command loop that allows users to perform simple arithmetic.
 */
int main() {
  bool done = false; // Initially not done
  do {
    switch (menu()) {
      case 'A': // Addition
      case 'a':
        get_input();
        add();
        report();
        break;
      case 'S': // Subtraction
      case 's':
        get_input();
        subtract();
        report();
      case 'P': // Print result
      case 'p':
        report();
        break;
      case 'H': // Display help screen
      case 'h':
        help_screen();
        break;
      case 'Q': // Quit the program
        done = true;
        break;
    }
  } while (!done);
  return 0;
}
```

Listing 10.1 (global.cpp) uses global variables **result**, **arg1**, and **arg2**. These names no longer appear in the **main** function. The global variables are accessed and/or modified in different functions: **get_input**, **report**, **add**, and **subtract**.

In the course of translating the statements within a machine language, the compiler resolves a local variable it encounters as follows:

- If the variable has a local declaration (that is, it is a local variable or parameter), the compiler will use the local variable or parameter, even if a global variable of the same name exists. Local variables, therefore, take precedence over global variables. The local declaration hides the global declaration in the scope of the local variable.

- If the variable has no local declaration it is declared as a global variable, the compiler will use the global variable.

- If the variable has no local declaration or no global declaration, the variable is undefined, and its use is an error.

In the situation where a local variable hides a global variable of the same name, there is a way to access both the local and like-named global within the local variable's scope. Suppose a program has a global variable **x** and a function with a local variable **x**. The statement

```cpp
x = 10;
```

within the scope of the local variable will assign the local **x**. The following statement will assign the global variable **x** in the scope of the local variable of the name:

```cpp
::x = 10;
```

:: operator is called the scope resolution operator. This special syntax may be used whenever a global variable is accessed within a function, but usually only when necessary to access a hidden global variable.

If the value of a local variable is used by a statement before that variable has been given a value, either through initialization or assignment, the compiler will issue a warning. For example, the Visual C++ compiler will issue uninitialized() in the following code:

```cpp
void uninitialized() {
  int x; // Declare the variable
cout << x; // Then use it
}
```

The warning is

> warning C4700: uninitialized local variable 'x' used

(The only way to avoid this warning in Visual C++ is to turn off all warnings.) A local variable has an undefined value after it is declared without being initialized. Its value should not be used until it has been properly assigned. Global variables, however, do not need to be initialized before they are used.
