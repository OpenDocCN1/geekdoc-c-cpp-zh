
## 14.3. METHODS

```cpp
* deposit (amt)
* Adds amount amt to the account's balance.
*
* Author: Sam Coder
* Date: September 3, 2012
****************************************************************/
void deposit(double amt) {
    balance += amt;
}
```

```cpp
****************************************************************/
* withdraw (amt)
* Deducts amount amt from the account's balance,
* if possible.
* Returning true if successful; otherwise, it returns false.
* A call can fail if the withdraw would
* cause the balance to fall below zero
*
* amt: funds to withdraw
*
* Author: Sam Coder
* Date: September 3, 2012
****************************************************************/
bool withdraw(double amt) {
    bool result = false; // Unsuccessful by default
    if (balance - amt >= 0) {
        balance -= amt;
        result = true; // Success
    }
    return result;
}
```

In this new definition of Account, the members named deposit and withdraw are not fields; they are method definitions. A method definition looks like a function definition, but it appears within a class definition. Because of this, a method is also known as a member function.

A client accesses a method with the dot (.) operator:

```cpp
// Withdraw money from the Account object named acct
acct.withdraw(100.0);
```

The method definition uses three variables: amt, result, and balance. The variables amt and result are local to withdraw-amt's method, and balance is declared within the body of withdraw. Where is balance declared? It is the field declared in the private section of the class. The withdraw method affects the balance field of the object upon which it is called:

```cpp
// Affects the balance field of acct1 object
acct1.withdraw(100.0);
// Affects the balance field of acct2 object
acct2.withdraw(25.0);
```

Methods may be overloaded just like global functions (see Section 10.3). This means multiple methods in the same class may have the same names, but their signatures must be different. Recall that a function's signature consists of name and parameter types; a method's signature consists of its name and parameter types.

We saw in Section 14.2 that each object provides storage for its own data fields. An object does not require any space for its methods. This means the only things about an object that an executing program must manage are the object's fields. The exact organization of memory among operating systems, Figure F.10 shows a typical layout. All the data processed by a program appears in one of three sections: stack, heap, or static. With simple data types like ints, the fields of an object declared local to a function reside in the segment of memory known as the stack. Also like simple data types, the fields of an object allocated with new appear on the heap. Fields in global and static objects reside in the static section of the executing program's memory.

Consider the following simple class:

```cpp
class Counter {
    int count;
    public:
        // Allows to reset the counter to zero
        void clear() {
            count = 0;
        }

        // Allows to increment the counter
        void inc() {
            count++;
        }

        // Return a copy of the counter's current value
        int get() {
            return count;
        }
};
```

For this code each Counter object will store a single integer value (its count field). Under Visual C++ sizeof Counter is the same as sizeof int: A local Counter consumes four bytes of stack, a global Counter uses four bytes of static, and a dynamically-allocated Counter uses four bytes of heap.

The segment of memory in Figure F.10 labeled code stores the name list for the program's functions and methods. The compiler translates methods into machine language as it does return functions. Internally, the method inc in the Counter class is identified by a longer name, Counter::inc. Although Counter::inc is a member, in the compiled code it works like a normal function unrelated to any class. In the code

```cpp
Counter ctr1, ctr2; // Declare a couple of Counter objects
ctr1.clear(); // Reset the counters to zero
ctr2.clear();
ctr1.inc(); // Increment the first counter
```

the statement

```cpp
ctr1.clear();
```

sets the private count field of ctr1 to zero, while the statement

```cpp
ctr2.clear();
```

sets count2's field to zero. since all Counter objects share the reset method, how does each call to Counter::clear reset the field of the proper Counter object? The trick is: While it appears that the reset method of the Counter class accepts no parameters, it actually receives a secret parameter that corresponds to the address of the object on left side of the doc. The C++ source code statement

```cpp
cnt1.clear(); // Actual C++ code
```

internally is treated

```cpp
Counter::clear(&cnt1); // -- Not real C++ code
```

in the compiled code. The code within the method can influence the field of the correct object via the pointer it receives from the caller. The clear method contains the single statement

```cpp
count = 0;
```

Since the count is not declared locally within the clear method and it is not a global variable, it must be the named count of the object pointed to by the secret parameter passed to clear.

Section 15.2 shows how programmers can access this pointer.

## 14.4 CONSTRUCTORS

One crucial piece is still missing. How can we make the fields of an object reasonable values before a client begins using the object? A class may define a constructor that looks like a method definition. A constructor executes on behalf of an object when a client creates the object. For some classes, the client can provide information for the constructor to use when initializing the object. With functions and methods, class constructors may be overloaded. An enhanced account class offers deposit and withdraw methods, as well as a constructor.

### Listing 14.3: bankaccountmethods.cpp

```cpp
#include <iostream>
#include <iomanip>
#include <string>

namespace std;
class Account {
// String representing the name of the account owner
string name;
// The account number
int id;
// The current account balance
double balance;
public:
    // Initializes a bank account object
    Account(const string& customer_name, int account_number, double amount);
```

```cpp
Account(customer_name), id(account_number), balance(amount) {
    if (amount < 0) {
        cout << "Warning: negative account balance" << endl;
        balance = 0;
    }

// Adds amount amt to the account's balance.
void deposit(double amt) {
    balance += amt;
}

// Deducts amount amt from the account's balance,
// Returns true if successful; otherwise, it returns false.
// A call can fail if the withdraw would
// cause the balance to fall below zero
bool withdraw(double amt) {
    bool result = false; // Unsuccessful by default
    if (balance - amt >= 0) {
        balance -= amt;
        result = true; // Success
    }
    return result;
}

// Displays information about the account object
void display() {
    cout << "Name: " << name << ", ID: " << id
         << ", Balance: " << balance << endl;
}

```cpp
int main() {
    Account acct1("Joe", 2312, 1000.00);
    Account acct2("Moe", 2313, 500.29);
    acct1.display();
    acct2.display();
    cout << "--------------------------------" << endl;
    acct1.withdraw(800.00);
    acct2.deposit(200.00);
    acct1.display();
    acct2.display();
}
```

Listing 14.3 (bankaccountmethods.cpp) produces:

```
Name: Joe, ID: 2312, Balance: 1000
Name: Moe, ID: 2313, Balance: 500.29
--------------------------------
Name: Joe, ID: 2312, Balance: 200
Name: Moe, ID: 2313, Balance: 522.29
```

The following characteristics differentiate a constructor definition from a regular method definition:

- A constructor has the same name as the class.
- A constructor has no return type, except void.

The constructor in Listing 14.3 (bankaccountmethods.cpp) initializes all the fields with values supplied by the client. The comma-separated list between the colon and the curly brace that begins the body of the constructor is called the initialization list. An initialization list contains the name of each field with its initial value. All of the fields that make up an object must be initialized before the body executes. In this case the constructor adjusts the balance to zero and issues a warning if a client attempts to create an account with an initial negative balance. The constructor ensures that account object never has a negative value. The withdraw method ensures that, once created, an Account object will never be negative. Notice that the client provides the required parameters at the object's declaration:

```cpp
// Creating two Account objects
acct1("Joe", 2312, 1000.00);
Account acct2("Moe", 2313, 500.29);
```

Since the Account class contains a constructor definition which requires arguments, it now is impossible for a client to declare an Account object:

```cpp
Account acct3; // Illegal, must supply arguments for constructor
```

If an Account object is defined in Listing 14.3 (bankaccountmethods.cpp), the following code is illegal:

```cpp
acct.balance = -100; // Illegal, balance is private
```

Clients do not have direct access to the balance field since it is private. Clients should use the appropriate method to adjust the balance of an Account object:

```cpp
Account acct("Joe", 1033, 50.00); // New bank account object
acct.deposit(1000.00); // Add some funds
acct.withdraw(2000.00); // Method should disallow this operation
```

The details of depositing and withdrawing funds are the responsibility of the object itself, not the client. The attempt to withdraw $2,000 dollars above would not change the account's balance, and the client can check the return value of withdraw to provide appropriate feedback to the user about the error or take steps to correct it.

A constructor that specifies no parameters is called a default constructor. If the programmer does not specify any constructor for a class, the compiler will provide a default constructor that does nothing. If a programmer defines any constructor for a class, the compiler will not generate a default constructor. Section 15.1 for the consequences of this constructor.
