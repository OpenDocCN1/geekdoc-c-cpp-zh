
# F.10: COPYING AN ARRAY

```
int a[10], *b;      // Declare two arrays, one dynamic
for (int i = 0; i < 10; i++) // Populate one of them
    a[i] = i;                // a is filled with increasing values
b = a;                      // Make a copy of array a?
```

but b is not a copy of a b aliases, so changing the contents of a will also change the contents of b identically, since b refers to the exact memory to which a refers. Figure F.7 illustrates the aliasing.

Figure F.7: Faulty array copy

The following code shows the proper way to make a copy of a:

```
int a[10], *b;      // Declare two arrays, one dynamic
for (int i = 0; i < 10; i++) // Populate one of them
    a[i] = i;                // a is filled with increasing values
// Really make a copy of array a
b = new int[10];         // Allocate b
for (int i = 0; i < 10; i++)
    b[i] = a[i];
```

Separate data for the dynamic array must be allocated, and then each from the original array must be copied into the new array. Figure F.8 shows how this process works.

It is important to note that since the code allocates b dynamically with new, elsewhere within the program should eventually use delete to free b's space when it is no longer used. Failure to properly allocate b constitutes a memory leak.

# F.11 Memory Management

Memory issues with new and delete frequently are the source of difficult to find and fix logic errors. Programmers must adhere to the following tenets:

- * Every call to new should have an associated call to delete when the allocated memory is no longer needed. It sounds simple enough, but it is not clear when delete should be used. The following function exhibits a memory leak:

```
void calc(int n) {
    // /
    // /
    // Do some stuff
    // /
    // /
    int *p = new int[n];
    // /
    // /
    // Do some stuff with p
    // /
    // /
    // Exit function without deleting p's memory
}
```

When a call to calc completes, the function clean up automatically releases the space held by the variable p. Because all functions automatically manage the memory for their parameters and local variables. The problem is p assigned new to memory allocated from the heap, not the stack. Execution functions manage the stack memory only. When the function’s execution completes, p is gone, and the memory to which p pointed is not deallocated automatically. Worse yet, the heap memory referenced by the local variable p now unreachable because no other variables remain anything about it.

- * delete operator should never be used to free memory that was not allocated by a previous call to new. This code fragment illustrates one example:
```
int list(calc), *p = list; // p points to list
//
Do some stuff

delete [p]; // Logic error, attempt to deallocate p's memory
//
```

- * delete must not be used to deallocate the memory more than once. This can happen when two pointers refer to the same memory. Such pointers are called aliases. The following code fragment illustrates situation:
```
int *p = new int[10], *q = p; // q aliases p
//
Do some stuff with p and/or q
//
//
```

```
delete [] p; // Free up p's memory
// /
// Do some other stuff
// /
delete [] q; // Logic error, q's memory already freed!
```

Since pointer p and pointer q point to the same memory, they are aliases of each other. Deallocate the memory referenced by one of them, and the other's memory is deallocated, since it is the same memory.

- * Memory previously deallocated by delete should never be accessed. It is a logic error to access memory previously deallocated by delete. The code fragment

```
int *list = new int[10];
// /
// Use list, then
delete [] list; // Deallocate list's memory
// /
// Sometime later
int x = list[2]; // Logic error, but sometimes works!
```

illustrates how a situation can arise. For efficiency the delete operator generally marks heap space as "available" while modifying the contents of the memory. Careless programmers can accidentally use that memory obviously as if it were still there. The problem manifests when the free memory gets reallocated elsewhere via a call to new. The result is that programs seem "work" for a while and mysteriously fail at unpredictable times. Debugging such situations can be very difficult. The problem often happens because of aliasing:

```
int *list = new int[10];
// /
int *arr = list; // arr aliases list
// /
delete [] list; // Deallocate list's memory
// /
// Sometime later
int x = arr[2]; // Same problem!
```
