Why would programmer intentionally choose to access parts of an object? Restricting access obviously limits the client's control over the objects it creates. This may appear to be a disadvantage at first glance, this access restriction provides a number of advantages:

- Flexibility in implementation. A class conceptually can be separated into two parts:

- The interface—the public part. Clients see and use the public parts of an object. The public methods and variables of a class constitute the interface of the class. The class's interface specifies what it does.

- The implementation—the hidden part. Clients cannot see any private methods or variables. Since this private information is invisible to clients, class developers are free to do whatever they want with the private parts of the class. A class's implementation specifies how it accomplishes what it needs to do.

We would like objects to be black boxes: clients shouldn't need to know how the objects work but merely rely on what objects do.

> A good rule of thumb in class design is: make data private, and make methods that provide a service to clients public.

Real-world objects follow this design philosophy. Their display uses the current time and date. It can produce different output in different modes; for examples, elapsed in stopwatch mode or wake up in alarm mode. It presents to its users only a few buttons for changing modes, starting and stopping stopwatches, and setting the time. How it works is irrelevant to most users; most users are concerned with what it does. Its user risks great peril by opening the watch and looking at intricate internal details. The user is to interact with the watch only through its interface—the display and buttons.

Similarly, an automobile presents an accelerator pedal to its driver. The user knows that pushing the pedals makes the car go faster. That the pedal is connected to the fuel injection system (and possibly other systems, like cruise control) by a wire, cable, or other type of linkage is of concern only to the automotive designer or mechanic. Most drivers prefer to be oblivious to the under-hood details.

## 14.8. SUMMARY

The concept of information hiding is encapsulation. Details are exposed to particular parties when appropriate. In sum, the use of encapsulation results in:

- software is more flexible and resilient to change,
- software that is more robust and reliable, and,
- a software development process that programmers can more easily comprehend.

Finally, the++ encapsulation model has its limits. It is not possible to protect an object from code within itself. Any method within a class has full access to any member defined within that. If it appears that parts of a class should be protected from some of its methods, the class should be split into multiple classes with suitable restrictions among the resulting component classes.

- The class word introduces a programmer-defined type.
- A semicolon ; must follow the curly brace of a declaration.
- Variables of a class are called objects or instances of that class.
- The public label within a class specifies the parts of that class that are visible to code outside of that class.
- The parts of a class that are not in the public section are by default private and inaccessible to code outside the class. The private label explicitly declares a declaration of a class to be private. The public and private labels may appear multiple times within a class declaration allowing programmers to order class members as they choose without being forced to put all the private members in one place.
- The (.) operator is used to access elements of an object.
- A data member of a class is known as a field. Equivalent terms include data member, instance variable, and attribute.
- A function in a class that operates on objects of that class is called a method. Equivalent terms include member function and operation.
- A constructor executes code automatically when an object comes into existence. A constructor has the same name as the class and no specified return type (not even void).
- A constructor initialization list assigns initial values to an object's fields. The initialization list appears after the closing parenthesis of the constructor's parameter list but before the opening curly brace of the constructor's body.
