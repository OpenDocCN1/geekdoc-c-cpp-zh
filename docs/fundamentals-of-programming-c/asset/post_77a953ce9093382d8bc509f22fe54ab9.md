
## 11.1. VECTORS

- an arithmetic expression: a[x + 3]
- an integer result of a function call returns an numeric value: a[max(x, y)]
- an element of a vector that contains numeric values: a[b[3]]

A floating-point index is permissible but discouraged. The compiler will issue a warning about using a floating-point index with good reason. A vector may have an element at index 2 or index 3, but it is not possible to have an element between indices 2 and 3; therefore, any floating-point index must be truncated to an integer to select the proper element within the vector.

### 11.1.2 Traversing a Vector

The action of moving through a vector visiting each element is known as traversal. for loops are ideal for traversal. If an integer vector contains 10 elements, the following loop prints each element:

```cpp
for (int i = 0; i < 10; i++)
    cout << a[i] << endl;
```

The control variable, i, steps through each valid index of vector a. Variable i's value starts at 0 and ends at 9, the last valid position in vector a.

The following prints contents of vector a in reverse order:

```cpp
for (int i = 9; i >= 0; i--)
    cout << a[i] << endl;
```

```cpp
vector<int> set(1000);
for (int i = 0; i < 1000; i++)
    set[i] = i;
```

We now have the tools to build a program that flexibly averages numbers while retaining all the values. Listing 11.3 (vectoraverage.cpp) uses a vector and a loop to achieve the generality of Listing 11.2 (averagenumbers.cpp) with the ability to return all input for later display.

```cpp
// Listing 11.3: vectoraverage.cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    double sum = 0.0;
    const int NUMBER_OF_ENTRIES = 5;
    vector<double> numbers(NUMBER_OF_ENTRIES);

    cout << "please enter " << NUMBER_OF_ENTRIES
         << " numbers: ";
    // Allow the user to enter in the values.
    for (int i = 0; i < NUMBER_OF_ENTRIES; i++) {
        cin >> numbers[i];
        sum += numbers[i];
    }

    cout << "The average of ";
    for (int i = 0; i < NUMBER_OF_ENTRIES; i++)
        cout << numbers[i] << ", ";
    // No comma following last element
    cout << numbers[NUMBER_OF_ENTRIES -1] << " is "
    cout << sum/NUMBER_OF_ENTRIES << endl;
}
```

Unlike the original program, we now conveniently extend this program to handle many values as well. We only need the definition of the NUMBER_OF_ENTRIES constant to allow the program to handle any number of values. This centralization of the vector's size eliminates duplicating a hard-coded value and leads to a program that is more maintainable. Suppose every occurrence of NUMBER_OF_ENTRIES were replaced with the literal value 5. The program would work exactly the same way, but changing the size would require touching many places within the program. When duplicate information is scattered throughout a program, it is a common error to update some but not all of the information when a change is to be made. If all of the duplicate information is not updated to agree, the inconsistencies remain in errors within the program. By faithfully using the NUMBER_OF_ENTRIES constant throughout the program instead of the literal value, problems with inconsistency can be avoided.

The first loop in Listing 11.3 (vector.cpp) collects all input values from the user. The second loop only prints the first four elements a comma after each element. Since no comma should be displayed after the last element, the program prints the last element after the loop.

The compiler will insist that you use a numeric value for an index, but the programmer must ensure that the index is used within the bounds of the vector. Since the index may consist of an integer expression whose value cannot be determined until runtime, the compiler cannot check for out-of-bounds accesses, for example the:

```cpp
int x;
vector<int> v(10); // Make a vector with 10 spaces available
cin >> x; // User enters x at runtime
v[x] = 1; // Is this OK? What is x?
```

This means that an index can lead to runtime errors. Consider Listing 11.4 (vectorofbounds.cpp).

```cpp
// Listing 11.4: vectorofbounds.cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
  const int SIZE = 3;
  vector<int> a(5);
  // Print the contents of the vector
  cout << "a contains";
  for (int i = 0; i < SIZE; i++)
    cout << a[i] << " ";
  cout << endl;

  // Change all the 5s in vector to 8s Bug: <= should be <
  for (int i = 0; i < SIZE; i++)
    a[i] = 8;

  // Reprint the contents of the vector
  cout << "a contains";
  for (int i = 0; i < SIZE; i++)
    cout << a[i];
  cout << endl;
}
```

11.4 vectoroutofbounds contains logic error: accessing elements outside the bounds of a vector produces what is known as undefined behavior. The C++ language standard uses this term to indicate program's behavior is not specified, and writers are free to do whatever they want. Running programs that venture into undefined behavior will crash, but they may continue executing without indication of a problem and behave correctly. In other words, the actual behavior is system and compiler dependent. Simply saying the program's behavior is unpredictable. In most cases, out-of-bounds access accesses memory outside the vector. This includes memory that does not belong to the executing program, modern operating systems will terminate the program and produce an error message. Under C++ when the program is built as a debug version (the default) it prints the contents of the vector the first time but crashes before it can print it a second time. Microsoft Windows then displays the dialog box in Figure 11.4. The program running under Linux or OS X may simply print fault in the console:

Segmentation fault

If you are using a vector, and it terminates with such a message, you should check your source code carefully for places where out-of-bounds accesses are possible. The following code fragment shows some proper and improper vector accesses:

```cpp
vector<int> numbers(10); // Declare the vector
numbers[0] = 5; // Put value 5 first
numbers[9] = 2; // Put value 2 last
numbers[-1] = 5; // Out of bounds; first valid index is 0
numbers[10] = 5; // Out of bounds; last valid index is 9
numbers[1.3] = 5; // Compiler warning, 1.3 is not an int
```

C++11 supports a for statement that uses special syntax for vectors. Commonly known as the range-based for "foreach" statement, this version permits vector traversal without an index variable keeping track of the position. The following code uses a range-based statement to print the contents of an integer vector named vec:

```cpp
for (int n : vec)
    cout << n << ' ';
```

You can read this as "for int n in vec { cout << n << ' '; }". The colon (:) therefore is pronounced "in". In the first iteration of this range-based loop the variable n represents the first element in the vector. In the second iteration n represents the second element. The third time n is the third element, and so on. The declared variables assume the role of a vector element during each iteration of the loop. The range-based loop requires no control variable to keep track of the current index within the vector; the loop takes care of that, freeing the programmer from that task.
