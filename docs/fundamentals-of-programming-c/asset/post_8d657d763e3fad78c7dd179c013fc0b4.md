
## 4.1. EXPRESSIONS

| Operator | Meaning |
| --- | --- |
| + | addition |
| - | subtraction |
| * | multiplication |
| / | division |
| % | modulus |

Table 4.1: The simple C++ arithmetic operators

x = y + z;

the right side is an addition expression y + z. The two operands of the + operator are y and z. Two of the operators above, + and -, serve as unary operators. A unary operator has only one operand. The unary operator expects a single numeric expression (literal number, variable, or complex numeric expression) immediately to its right; it computes the additive inverse of its operand. If the operand is positive (greater than zero), the result is a negative value of the same magnitude; if the operand is negative (less than zero), the result is a positive value of the same magnitude. Zero is unaffected. For, the following code sequence

```
int x = 3;
int y = -4;
int z = 0;
cout << -x << " " << -y << " " << -z << endl;
```

within a program would print

```
-3 4 0
```

The following statement

```
cout << - (4 - 5) << endl;
```

within a program would print

```
1
```

The unary + operator is used only for completeness; when applied to a numeric value, variable, or expression, the resulting value is no different from the original value of its operand. Omitting the unary + operator from the following statement

x = +y;

does not change the statement's behavior.
All the arithmetic objects are subject to the limitations of the data types on which they operate; for example, on a system where the largest int is 2,147,483,647, the expression
2147483647 + 1

will not evaluate to the correct answer since the correct answer falls outside the range of ints.

If you add, subtract, multiply, divide is two ints, the result is an integer. As long as the operation does not exceed the range of ints, the arithmetic works as expected. However, division is another matter. The statement

```
cout << 10/3 << " " << 3/10 << endl;
```

prints

```
3 0
```

because in the first case 10 divided by 3 is 3 with a remainder of 1, and in the second case divided by 10 is 0 with a remainder of 3. Since integers are whole numbers, any fractional part of the answer must be discarded. The process of discarding the fractional part leaving only the whole number is called truncation. 10 divided by 3 should be 3.3333..., but that value is truncated to 3. Truncation is not rounding; for example, 11 divided by 3 is 3.6666..., but it also truncates to 3.

> Truncation removes any fractional part of the value. It does not round. 10.01 and 10.999 truncate to 10.

The modulus operator (%) computes the remainder of integer division; thus,

```
cout << 10%3 << " " << 3%10 << endl;
```

prints

```
1 3
```

since 10 divided by 3 is 3 with a remainder of 1, and 10 divided by 10 is 0 with a remainder of 3. Figure 4.1 uses long division for a more hands-on illustration of how the integer division and modulus operators work.

The modulus operator is more useful than it first appear. Listing 4.11 (timeconv.cpp) shows how we can use it to convert a number of seconds to hours, minutes, and seconds.

In contrast to integer arithmetic, floating-point arithmetic with doubles behaves as expected:

```
cout << 10.0/3.0 << " " << 3.0/10.0 << endl;
```

prints

```
3.33333 0.3
```

Recall from Section 3.4 that integers can be represented exactly, but floating-point numbers are imprecise approximations of numbers. Listing 4.2 (imprecise.cpp) clearly demonstrates their weaknesses.

```
Listing 4.2: imprecise.cpp
#include <iostream>

using namespace std;

int main() {
    double one = 1.0;
    double one_third = 1.0/3.0;
    double zero = one - one_third - one_third - one_third;

    cout << "one = " << one << ", one_third = " << one_third 
         << <<, zero = " << zero << endl;

}
```

The reported value is 1.1102 × 10⁻¹⁶, or 0.0000000000000011022. While this is very small, with mathematical real numbers we get

> 1/3 - 1/3 - 1/3 = 0

Floating-point numbers are not real numbers, so the result of 1.0/3 cannot be represented exactly without infinite precision. In the decimal (base 10) number, one-third is a repeating fraction, so it has an infinite number of digits. Even simple non-repeating decimal numbers can be beside as a problem. (0.1) is obviously non-repeating, so it can be expressed exactly with a finite number of digits. As it turns out, numbers within computers are stored in binary (base 2) form, even double-precision floating-point numbers cannot represent one-tenth exactly. Listing 4.3 (imprecise.cpp) illustrates this.

```
one = 1, one_third = 0.333333, zero = 1.11022e-016
```

Listing 4.3: imprecise10.cpp
#include <iostream>

using namespace std;

int main() {
  double one = 1.0,
  double one_tenth = 1.0/10.0,
  double zero = one - one_tenth - one_tenth - one_tenth
  - one_tenth - one_tenth - one_tenth
  - one_tenth - one_tenth - one_tenth;

  cout << "one = " << one << << "" , one_tenth = " << one_tenth
  << << " , zero = " << zero << endl;
}

The program's output

```
one = 1, one_tenth = 0.1, zero = 1.38778e-06
```

Surely the reported answer (1.38778 × 10⁻⁶) is close to the correct answer (zero). If you rounded to the one-hundredth place (15 places after the decimal point), it is correct. Listing 5.5 (samifferent.cpp) in Chapter 5 emphasizes that the programmers must use care when dealing with the imprecision of floating-point numbers.

Despite their inexness, double-precision floating-point numbers are used day throughout the world to solve sophisticated scientific and engineering problems. The limitations of floating-point numbers are unavoidable when we do our best to represent values with infinite characteristics in a finite way. Floating-point numbers provide a good trade-off of precision for practicality..

Since a char is stored internally as a number (see Section 3.7), we can perform arithmetic on characters. We will have little to apply mathematics to characters, but sometimes it is useful. As an example, the lower-case letters of the alphabet–z are ASCII values 97–123, with a = 97, b = 98, etc. The upper-case letters A–Z are 65–91, with A = 65, B = 66, etc. To capitalize any lower-case letter, you need only subtract 32, as

```
char lower = 'd', upper = lower - 32;
cout << upper << endl;
```

This code would print D. If you do not remember the offset of 32 between upper- and lower-case, you can compute it with the themselves:

```
upper = lower - ('a' - 'A');
```

In this case, if lower has been assigned in the range 'a' to 'z', the statement will assign to the capitalized version of lower. On the other hand, if lower's value is outside range, upper will not receive a meaningful value.

## 4.2 Mixed Type Expressions

Expressions may contain mixed elements; for example, the following program

```
int x = 4;
double y = 10.2, sum;
sum = x + y;
```

adds an int to a double, and the result is assigned to a double. How is the arithmetic performed?

![](img/e326304bd50fbc4f7d5a64c1487eb635_51_0.png)

Figure 4.2: Range of ints vs. range of doubles

As shown in Figure 4.2, the range of ints completely falls within the range of doubles; thus, any int value can be represented by a double. The int 4 also can be expressed as the double 4.0. In fact, since the largest int on most systems is 2,147,483,647, the minimum 15 digits of double precision are more than enough to represent all integers. This means that any int value can be represented by a double. The contrast is not true; however, 2,200,000,000 can be represented by a double but it is too big for the int. We say that the double type is wider than the int type that the int type is narrower than the double type.

It would be reasonable, then, to be able to assign int values to double variables. The process is called widening, and it is always safe to widen an int to a double. The following code fragment

```
double d1;
int i1 = 500;
d1 = i1;
cout << "d1 = " << d1 << endl;
```

is legal C++ code, and when part of a complete program it would display

```
d1 = 500
```

Adding a double to an int variable is not always possible, the double value may not be in the range of ints. Furthermore, the double value falls within the range of ints but is not a whole number, the int variable is unable to manage the functional part. Consider the following code

```double d = 1.6;
int i = d;
```
