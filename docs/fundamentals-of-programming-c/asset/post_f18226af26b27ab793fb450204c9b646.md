```cpp
int x;
int v[10]; // Make an array with 10 spaces available
cin >> x; // User enters x at run time
v[x] = 1; // Is this OK? What is x?
```

the compiler cannot predict what number the user enters. This means that misuse of an index can lead to run-time errors. To illustrate this, consider Listing F.1 (arrayoutofbounds.cpp).

# Listing E.1: arrayoutofbounds.cpp

```cpp
#include <iostream>
using namespace std;

int main() {
    const int SIZE = 3;
    int a[SIZE] = { 5, 5, 5 };
    // Print the contents of the array
    cout << "contains: ";
    for (int i = 0; i < SIZE; i++)
        cout << a[i] << " ";
    cout << endl;
    // Change the 5s in array to 8s
    for (int i = 0; i <= SIZE; i++) // Bug: should be <
        a[i] = 8;
    // Reprint the contents of the array
    cout << "contains: ";
    for (int i = 0; i < SIZE; i++)
        cout << a[i] << " ";
    cout << endl;
}
```

Listing F.1 (arrayoutofbounds.cpp) contains a logic error, the reassignment loop goes past the end of array a. Attempting to access elements outside the bounds of an array is known as undefined behavior. The C++ language standard uses this term to indicate a program's behavior is not specified, and compiler writers are free to do whatever they want. Some possible behaviors include:

- The compiled code could check to ensure the index is within range and produce an intelligent runtime-error message,
- the program could crash mysteriously.
- the program could continue with no indication of a problem and appear to behave correctly most of the time,

or any other possible outcome. In other cases, the actual program behavior is system dependent and compiler dependent. The code in a program that exhibits undefined behavior is considered a logical error, since its action is inconsistent across platforms and compilers. Simply said, the program's behavior is unpredictable. Unpredictable behavior is incorrect.

In most cases, out-of-bounds access accesses memory outside the array. This includes memory that does not belong to the executing program; modern operating systems will kill the program and produce some error message. Under Visual C++ when the program is built as a debug version, the program prints the contents of the array first time but crashes before it can print it second time. If your program is using an array, and it terminates with such a message, you should check its source code carefully for places where out-of-bounds array accesses are possible.

The following code fragment shows some proper and improper array accesses:

```cpp
int numbers[10];      // Declare the array
numbers[0] = 5;      // Put value 5 first
numbers[9] = 2;      // Put value 2 last
numbers[-1] = 5;     // Out of bounds; first valid index is 0
numbers[10] = 5;     // Out of bounds; last valid index is 9
numbers[1.3] = 5;    // Out of bounds; 1.3 is not an int
```

Notice the comment does check that the type of the index is a valid expression.

In an array with a for loop such as

```cpp
for (int i = 0; i < SIZE; i++)
    cout << a[i] << endl;
```

it is easy to ensure that x falls out of the bounds of an array, but arbitrary values should be checked before their use:

```cpp
int x;
int a[10];            // Make an array with 10 spaces available
cin >> x;             // User enters x at run time
if (0 < x && x < 10) // Ensure x is within the bounds of the array
    a[x] = 1;         // This is safe now
else
    cout << "Index provided is out of range" << endl;
```

Here, the if statement ensures the array access is within the array's bounds.

```cpp
        cout << a[i] << " ";
    cout << endl;
}

/* sum(a, n)
* Adds up the contents of an int array
* a is the array to sum
* n is the size of the array
*/

int sum(int a[], int n) {
    int result = 0;
    for (int i = 0; i < n; i++)
        result += a[i];
    return result;
}

int main() {
    int list[] = { 2, 4, 6, 8 };
    // Print the contents of the array
    print(list, 4);
    // Compute and display sum
    cout << sum(list, 4) << endl;
    // Zero out all the elements of list
    for (int i = 0; i < 4; i++)
        list[i] = 0;
    // Reprint the contents of the array
    print(list, 4);
    // Compute and display sum
    cout << sum(list, 4) << endl;
}
```

As shown in the print function's definition:

```cpp
void print(int a[], int n)
```

when an array formal parameter is declared, its square brackets are left empty. The programmer can supply a number within the square brackets, but it is ignored by the compiler. When calling a function that accepts an array parameter,

```cpp
print(list, 4);
```

the programmer must pass the array's size along with the array name. This is because an array simply represents a block of memory and has no notion of its size. Consequently, when an array is passed by reference, as in F.2 (arraytoofunc.cpp), the square brackets are left empty.

### F.3. PRIME GENERATION WITH AN ARRAY

```cpp
int sum(int a[], int n)
```

In Listing F.2 there is no reason why the print and sum functions should be able to modify the contents. To protect an array from corruption, the parameter must be declared const.

As a general rule, all functions that accept array parameters should declare the array const unless they need to modify the elements.

C++ does not support empty arrays. A physical array must contain at least one element. Sometimes it is possible to consider an array that is conceptually empty: for example, if we wish to pass an "empty" array to the sum function; we can pass 0 as the second parameter since an empty array contains no elements, but what should we pass as the first? Any array will do, but there is no need to create a real array. Instead, we may use nullptr.

```cpp
quantity = sum(nullptr, 0);
```

If you scrutinize the body of the sum function, you will see that this will assign to quantity the correct answer, namely zero.

## F.3 Prime generation with an Array

Listing F.4 (fasterprimesarray.cpp) uses an algorithm developed by the Greek mathematician Eratosthenes who lived from 275 B.C. to 195 B.C. The principle behind the algorithm is: Make a list of all the integers under two. Two is a prime number, but any multiple of two cannot be a prime number (since a multiple of two has a factor). Go through the rest of the list and mark out all multiples of two (4, 6, 8, ...). Move to the next number in the list (in this case, three). If it is not marked out, it must be prime, so go through the list and mark out all multiples of that number (6, 9, 12, ...). Continue this process until you have listed all the primes you found.
