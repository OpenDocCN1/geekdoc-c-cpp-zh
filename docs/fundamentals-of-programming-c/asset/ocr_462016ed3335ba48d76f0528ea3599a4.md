# Listing E.1: arrayoutofbounds.cpp

```
#include <iostream>
using namespace std;

int main() {
    const int SIZE = 3;
    int a[SIZE] = { 5, 5, 5 };
    // Print the contents of the array
    cout << "contains: ";
    for (int i = 0; i < SIZE; i++)
        cout << a[i] << " ";
    cout << endl;
    // Change the 5s in array to 8s
    for (int i = 0; i <= SIZE; i++) // Bug: should be <
        a[i] = 8;
    // Reprint the contents of the array
    cout << "contains: ";
    for (int i = 0; i < SIZE; i++)
        cout << a[i] << " ";
    cout << endl;
}
```

Listing F.1 (arrayoutofbounds.cpp) contains a logic error, the reassignment loop goes past the end of array a. Attempting to access elements outside the bounds of an array is known as undefined behavior. The C++ language standard uses this term to indicate a program's behavior is not specified, and compiler writers are free to do whatever they want. Some possible behaviors include:

+   * The compiled code could check to ensure the index is within range and produce an intelligent runtime-error message,

+   * the program could crash mysteriously.

+   * the program could continue with no indication of a problem and appear to behave correctly most of the time,

or any other possible outcome. In others cases, the actual program behavior is system dependent and compiler dependent. The code in a program that exhibits undefined behavior is considered a logical error, since its action is inconsistent across platforms and compilers. Simply said, the program's behavior is unpredictable. Unpredictable behavior is incorrect.

In most cases, out-of-bounds access accesses memory outside the array. This includes memory that does not belong to the executing program, modern operating systems will kill the program and produce some error message.
