
## D.2. The Floating-Point Types

Floating point numbers consist of **float** and **double**. Floating point numbers can have fractional parts (decimal places), and the term floating point refers to the decimal point in a number can float left or right as necessary as the result of a calculation (for example, $2.5 \times 3.3 = 8.25$, one-decimal place produce a two-decimal place as result). With the two types, the floating-point types are distinguished by the number of bits storage required and corresponding range of values. The type **float** stands for *single-precision floating-point*, and **double** stands for *double-precision floating-point*. Floating point numbers are rough approximations of mathematical *real* numbers, but as we shall see, they have some severe limitations compared to actual numbers.

On modern computers floating-point numbers are stored internally in exponential form according to the standard adopted by the Institute for Electrical and Electronic Engineers (IEEE 754). In the decimal system, *scientific notation* is the most familiar form of exponential notation:

- One $6.023 \times 10^{23}$ molecules.

Here 6023 is called the mantissa, and 23 is the exponent. The IEEE 754 standard uses binary exponent floating-point numbers (type **float**) occupy 32 bits, as distributed as:

| Field | Bits |
| :--- | :--- |
| Mantissa | 24 bits |
| Exponent | 7 bits |
| Sign | 1 bit |
| Total | 32 bits |

Double-precision floating-point numbers (type **double**) require 64 bits:

| Field | Bits |
| :--- | :--- |
| Mantissa | 52 bits |
| Exponent | 11 bits |
| Sign | 1 bit |
| Total | 64 bits |

The details of the IEEE 754 implementation are beyond the scope of this book, but a simplified example serves to highlight the limitations of floating-point types in general. Recall the place values in the decimal system. The place values, from left to right,

| ... | ... | ... | ... | ... | ... | ... | ... | ... |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 10,000 | 1,000 | 100 | 10 | 1 | 1/10 | 1/100 | 1/1000 | 1/10000 |
| $10^4$ | $10^3$ | $10^2$ | $10^1$ | $10^0$ | $10^{-1}$ | $10^{-2}$ | $10^{-3}$ | $10^{-4}$ |

Each place value is one-tenth the place value to its right; move to the left, divide by ten; move to the right, multiply by ten. In the binary system, the factor is instead of ten:

| 16 | 8 | 4 | 2 | 1 | 1/2 | 1/4 | 1/8 | 1/16 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| $2^4$ | $2^3$ | $2^2$ | $2^1$ | $2^0$ | $2^{-1}$ | $2^{-2}$ | $2^{-3}$ | $2^{-4}$ |

As in our **nibble** example (see Section D.1), consider a binary exponential number that consists of fewer bits than either **floats** or **double** in C++. The mantissa consists of three bits, all of the binary point. The base of the exponent is, of course, two, and a 2-bit exponent is used. D.4 illustrates such a value. For simplicity, neither the mantissa nor the exponent is negative. Thus, the mantissa ranges.

![](img/e326304bd50fbc4f7d5a64c1487eb635_581_0.png)

Figure D.4: Simplified exponential value

```
$(1 \times 2^{-1} + 0 \times 2^{-2} + 1 \times 2^{-3}) \times 2^{(1\times 2^{-1}+0\times 2^{-2})} = (\frac{1}{2} + \frac{1}{8}) \times 2^2 = \frac{5}{8} \times 4 = 2.5$
```

The range of these abbreviated floating-point numbers is $0\dots7$. This range is misleading, however, since it leaves the impression that any value could be represented. 2.5 can be represented in this scheme, but 2.4 *cannot*. This floating-point scheme is so simple that we can easily enumerate all the possible values, as Table D.2.

| :--- | :--- | :--- | :--- | :--- | :--- |
| .000 (0) | $00$ ($0$) | $01$ ($1$) | $10$ ($2$) | $11$ ($3$) | $2^3 (8)$ |
| .001 (0.125) | 0.125 | 0.25 | 0.5 | 1 | |
| .010 (0.25) | 0.25 | 0.5 | 1 | 2 | |
| .011 (0.375) | 0.375 | 0.75 | 1.5 | 3 | |

Figure D.5 plots these values on the real number line.

Table D.2 and Figure D.5 reveal several troubling issues:

1. There are many gaps; for example, the value 2.4 is missing and cannot be represented exactly (2.5 is the closest approximation).

![](img/e326304bd50fbc4f7d5a64c1487eb635_582_0.png)

2. The scheme duplicates some numbers; for example, three different bit patterns represent the decimal value 0.5:

$0.100 \times 2^{00} = 0.010 \times 2^{01} = 0.001 \times 2^{10} = 0.510$

This duplication limits the number of different values that can be represented by a given number of bits.

3. They are not uniformly dense. There are more values near zero, and the integers become sparse farther away from zero.

The integer types discussed in Section D.1 exhibit one of these weaknesses. All integers in a range are present, no two bitstrings represent the same value, and the integers are uniformly distributed across their specified range. The standard floating-point types provided by C++ use many more bits than this.
