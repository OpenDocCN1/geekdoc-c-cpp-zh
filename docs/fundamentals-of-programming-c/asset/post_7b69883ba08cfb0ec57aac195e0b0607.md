It is important to note that since a programmer must explicitly allocate the space for a dynamic array using the new operator, the program should contain a corresponding call to delete to free up the array’s memory when the array is no longer needed. C++ uses a special syntax for array deletion:

```cpp
int *list = new int[10]; // Allocate the array dynamically
// Use the array
delete [] list; // Deallocate the array’s memory
```

Note that the square brackets must be empty. The run-time environment keeps track of the array’s allocated size and knows how much memory to reclaim.

Figure 11.6 shows that, like vectors, array elements may be located by their index, and the very first element in an array is located at index 0. The similarity to vectors is not accidental—the developers of the C++ vector library designed vectors to behave as much as possible C arrays. Once declared, programmers treat static and dynamic arrays similarly. The following code creates a static array and populates it with pseudorandom values:

```cpp
int random_numbers[25];
for (int i = 0; i < 25; i++)
    random_numbers[i] = rand();
```

Unlike vectors, an array has a fixed size. It is impossible to change the size of a static array (short of editing the source code and recompiling). In order to change at run time the size of a dynamic array,

- 1. allocate a different block of memory of the desired size,
- 2. copy all of the existing elements into the new memory,
- 3. use delete to deallocate the previous memory block to avoid a memory leak, and
- 4. reassign the original array pointer to point to new memory block.

Appendix F provides more detail about this process.

Unlike vectors, it is not possible to assign one array to another through a simple assignment statement copying all the elements from one array into another. If the arrays are static, the assignment is illegal. If the arrays are dynamic, the assignment simply moves the two pointers to the same block of memory, which is not the same effect as vector assignment. Furthermore, simple assignment of one dynamic array to another creates a memory leak. Appendix F shows how to do proper assignment.

Because an array is not an object it has no associated methods. It is the programmer's responsibility to keep track of the size of an array. An array, both static and dynamic, is simply the starting address of a raw block of memory. When passing an array to a function you must pass additional information so the function can process the array properly. The following function prints the contents of the array:

```cpp
void print(int a[], int n) {
    for (int i = 0; i < n; i++)
        cout << a[i] << ' ';
    cout << endl;
}
```

Inside the function there is no way to determine a's size; the second parameter specifies the array's size. A caller could invoke the function as:

```cpp
int list[25];
for (int i = 0; i < 25; i++) // Fill with pseudorandom values
    list[i] = rand() % 1000; // Print the elements of list
print(list, 25);
```

Another option is to pass a pointer to the beginning of the array and another pointer to just pass the end of the array:

```cpp
void print(int *begin, int *end) {
    for (int *elem = begin; elem != end; elem++)
        cout << *elem << ' ';
    cout << endl;
}
```

Notice that this code does not involve using arrays at all! This code takes advantage of pointer arithmetic. If elem is a pointer to a value in memory, the expression elem++ makes point to the next location in memory that can store the value to which elem points. Since the memory devoted to an array is a continuous, block of memory addresses, pointer arithmetic simply redirects a pointer from one element to another element in that array. Listing 11.11 (pointerarithmetic.cpp) provides some example of pointer arithmetic.

### Listing 11.11: pointerarithmetic.cpp

```cpp
#include <iostream>
using namespace std;

int main() {
    // Make an array
    int arr[] = {10, 20, 30, 40, 50};
    int *p = arr; // p points to the first element
    cout << p << endl; // Prints address, does not change p
    cout << p[0] << endl; // Prints 10, does not change p
    cout << p[1] << endl; // Prints 20, does not change p
    cout << ++p << endl; // Prints 20, does not change p
    p++; // Advances to the next element
    cout << ++p << endl; // Prints 30, does not change p
    p += 2; // Advance two places
    cout << p[0] << endl; // Prints 40, does not change p
    cout << p[1] << endl; // Prints 50, does not change p
    p--; // Moves p back one place
    cout << ++p << endl; // Prints 30, does not change p
}
```

Going back to the print function that uses pointers:

```cpp
void print(int *begin, int *end) {
    for (int *elem = begin; elem != end; elem++)
        cout << *elem << ' ';
    cout << endl;
}
```

the pointer elem points to the same element as begin points, and within the loop it moves to the next element repeatedly until the last element. A caller could invoke the function as:

```cpp
int list[25]; // Allocate a static array
for (int i = 0; i < 25; i++)
    list[i] = rand() % 1000; // Fill with pseudorandom values
print(list, list + 25); // Print the elements of list
```

The advantage of the begin/end pointer approach is that it allows a programmer to parse a slice of the array. If we want to print the elements of the array from index 3 to 7, call the function as:

`print(list + 3, list + 8); // Print elements at indices 3, 4, 5, 6, 7`

It is important to note that arrays are not objects, and therefore, have no associated methods. The square bracket notation used with arrays does not represent a special operator. The square bracket array notation is part of the C language since its beginning, but vectors (added by C++) of the C++ library were designed to behave as much like possible primitive C arrays. Provide access to a block of memory that can hold multiple elements. A vector object adds additional capabilities and conveniences that make the vectors better choice for C++ developers. Vectors have a close association with arrays—a vector object is a thinner wrapper around a dynamic array. A vector object simply manages its dynamic by providing convenient methods for adding elements and resizing the array it manages. A vector keeps track of its own size. Arrays provide none of methods that vectors do. The overhead that a vector imposes over a raw array is negligible. You should prefer vectors over arrays when writing C++ code.

If you want to "unwrap" the array that the vector manages, you need to use a C library that accepts only arrays? Fortunately it is easy to use "unwrap"; If vec is a vector, the expression &vec[0] is the address of the first element within the vector. Given a function such as:

```cpp
void print(int a[], int n) {
    for (int i = 0; i < n; i++) {
        cout << a[i] << ' ';
    }
    cout << endl;
}
```

that expects &vec[0], vec.size()), can invoke it with your vec vector object:

```cpp
print(&vec[0], vec.size());
```

Note that the first parameter is the starting address of the wrapped array, and the second parameter is the number of elements. If you have a function that uses your pointer:

```cpp
void print(int *begin, int *end) {
    for (int *elem = begin; elem != end; elem++) {
        cout << *elem << ' ';
    }
    cout << endl;
}
```

you can invoke it with your vec vector object:

```cpp
print(&vec[0], &vec[0] + vec.size());
```
