F11. MEMORY MANAGEMENT 614

```
delete [] p; // Free up p's memory
// /
// Do some other stuff
// /
dendelete [] q; // Logic error, q's memory already freed!
```

Since pointer p and pointer q point to the same memory, they are aliases of each other. Deallocate the memory referenced by one of them, and the other's memory is deallocated, since it is the same memory.

+   * Memory previously deallocated by delete should never be accessed. It is a logic error to access memory previously deallocated by delete. The code fragment

```
int *list = new int[10];
// /
// Use list, then
ndelete [] list; // Deallocate list's memory
// /
// Sometime later
int x = list[2]; // Logic error, but sometimes works!
```

illustrates how a situation can arise. For efficiency the delete operator generally marks heap space as "available" while modifying the contents of the memory. Careless programmers can accidentally use that memory obviously as if it were still there. The problem manifests when the free memory gets reallocated elsewhere via a call to new. The result is that programs seem "work" for a while and mysteriously fail at unpredictable times. Debugging such situations can be very difficult. The problem often happens because of aliasing:

```
int *list = new int[10];
// /
int *arr = list; // arr aliases list
// /
delete [] list; // Deallocate list's memory
// /
// Sometime later
int x = arr[2]; // Same problem!
```

We deleted list's memory, not arr's memory, didn't we? No, since arr is an alias for list, arr references memory previously deallocated by delete.

The space for non-static local variables is allocated when a function begins, and that space is deallocated when the function returns. A programmer need not explicitly use something like new and delete to manage memory for locals. The space for function parameters is handled automatically also.

The space for global variables and static variables is automatically allocated before the program begins its main function.
