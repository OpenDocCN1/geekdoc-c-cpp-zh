The line

```
int s = 0, size = list.size();
```

is not an problem even when the identifier size appears twice. The first appearance denotes the local variable named size, and the second use is a call to the size method of the std::vector class. The statement defines (declares) only the variable size; the size method already has been defined in the std::vector class (and the compiler processes its definition from the vector header file).

The variable i has two distinctions in the same context, so its redeclaration right before the display code is an error.

Like a variable, a class may have only one definition. When we build used in programs we must take care that we do not violate the one definition rule. In fact, we can violate the one definition even if we define it only once!

To see how we accidentally violate the one definition rule, consider the following simple example. Suppose we have a simple class declared in counter.h:

```
class Counter {
    int count;
public:
    // Allow clients to reset the counter to zero
    void clear();

    // Allow clients to increment the counter
    void inc();

    // Return a copy of the counter's current value
    int get() const;
};
```

with its implementation in counter.cpp:

```
// Allow clients to reset the counter to zero
void Counter::clear() {
    count = 0;
}

// Allow clients to increment the counter
void Counter::inc() {
    count++;
}
```

```
// Return a copy of the counter's current value
int Counter::get() const {
    return count;
}
```
