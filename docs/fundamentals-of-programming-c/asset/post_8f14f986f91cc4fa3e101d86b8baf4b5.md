
Bits 2 and 3 are one for 13 and 14; thus, bits 2 and 3 in the result must be one.

The bitwise or operator, `|`, takes two integer subexpressions and computes an integer result. The expression $e_1 \mid e_2$ is evaluated as follows:

- If bit 0 in $e_1$ and $e_2$ is 0, then bit 0 in the result is 0; otherwise, bit 0 in the result is 1.
- If bit 1 in $e_1$ and $e_2$ is 0, then bit 1 in the result is 0; otherwise, bit 1 in the result is 1.
- If bit 2 in $e_1$ and $e_2$ is 0, then bit 2 in the result is 0; otherwise, bit 2 in the result is 1.
- If bit 31 in $e_1$ and $e_2$ is 0, then bit 31 in the result is 0; otherwise, bit 31 in the result is 1.

For example, the expression $13 \mid 14$ evaluates to 15:

```
$$\begin{aligned}
13_{10} &=0000000000000000000000001101_2 \\
14_{10} &=0000000000000000000000011110_2 \\
15_{10} &=0000000000000000000000011111_2
\end{aligned}$$
```

Bits 4-31 are zero in both 13 and 14. Bits 0-3 either has a one or 14 has a; therefore, the result has ones in bits 0-3 and zeros everywhere.

The bitwise exclusive or (often referred to as *xor*) operator (`^`) takes two integer subexpressions and computes an integer result. The expression $e_1 \wedge e_2$ is evaluated as follows:

- If bit 0 in $e_1$ is the same as bit 0 in $e_2$, then bit 0 in the result is 0; otherwise, bit 0 in the result is 1.
- If bit 1 in $e_1$ is the same as bit 1 in $e_2$, then bit 1 in the result is 0; otherwise, bit 1 in the result is 1.
- If bit 2 in $e_1$ is the same as bit 2 in $e_2$, then bit 2 in the result is 0; otherwise, bit 2 in the result is 1.
- If bit 31 in $e_1$ is the same as bit 31 in $e_2$, then bit 31 in the result is 0; otherwise, bit 31 in the result is 1.

For example, the expression $13 \wedge 14$ evaluates to 3:

```
$$\begin{aligned}
13_{10} &=0000000000000000000000001101_2 \\
14_{10} &=0000000000000000000000011110_2 \\
3_{10} &=00000000000000000000000000011_2
\end{aligned}$$
```

0 and 1 differ in 13 and 14, so these bits are one in the result. The bit matches in all the other positions, so these positions must be set to zero in the result.

The bitwise negation operator (`~`) is a unary operator that flips all the bits of its expression. The expression $\sim e$ is evaluated as follows:

- If bit 0 in $e$ is 0, then bit 0 in the result is 1; otherwise, bit 0 in the result is 0.
- If bit 1 in $e$ is 0, then bit 1 in the result is 1; otherwise, bit 1 in the result is 0.
- If bit 2 in $e$ is 0, then bit 2 in the result is 1; otherwise, bit 2 in the result is 0.
- If bit 31 in $e$ is 0, then bit 31 in the result is 1; otherwise, bit 31 in the result is 0.

For example, the expression $\sim 13$ evaluates to -14, since:

$13_{10} = 0000000000000000000000001101_{2}$
$-14_{10} = 111111111111111111111010_{2}$

The shift operators moves all the bits in one left or to the right:

- * Shift left (<<). Expression $x \ll$ shifts all the bits in $x$ to the left places. Zeros fill vacant positions. The bits shifted off the left side are discarded. $x \ll 2$ evaluates to 20, since $5_{10} = 101_{2}$ shifted two places to the left yields $10100_{2} = 20$. Observe that $x$ is equal to $2^{2}$.
- * Shift right (>>). Expression $x \gg$ shifts all the bits in $x$ to the right places. The vacant bits on the left depend on whether the integer is signed or unsigned:
    - For signed values the vacant bit positions are filled with the sign bit (the leftmost bit).
    - For unsigned values the vacant bit positions are filled with zeros. The bits shifted off the right side are discarded. The expression $5 \gg 2$ evaluates to 1, since $5_{10} = 101_{2}$ shifted two places to the right yields $1_{2}$.

Developers use bitwise for a variety of systems-level programming languages. For example, in a graphical user interface (GUI), it generates events by interacting with the mouse and a keyboard. One event might be a mouse button over a particular graphical element (like a button) within a window. Information about this event can be stored in an integer. For example, it may indicate whether or not the Shift key was held down when the mouse button was clicked. 1 may be responsible for the Shift key, 2 for the Ctrl key, value 5, which in binary is `00000000000000000000000000000101`, means that the mouse button was clicked by the Shift and Alt keys held down. This might require a different action on the part of the program if some other combination of keys (or none) were pressed. If the user presses the Shift key during mouse click, you can display some warning dialog box. The following code fragment uses bitwise to accomplish the tasks:

```cpp
if (key_status & 1)
    show("Warning: Operation not supported.");
```

If the expression `key_status & 1` is zero, then bit 0 is zero in mouseEvent, and therefore, the Shift key was not pressed. If the expression is nonzero, the condition is interpreted as false and the running program will not display the dialog box. On the other hand the expression evaluates to non-zero, the Shift key is depressed and the expression is non-zero. Recall from Section 5.1 that any non-zero condition is considered true, and so the dialog box appears.

Using the GUI library with defined constants that you can use to enhance or modify particular, for example the following constants:

```cpp
const int SHIFT_DOWN = 1;          // This is 0...0001
const int CTRL_DOWN = SHIFT_DOWN << 1;  // This is 0...0010
const int ALT_DOWN = CTRL_DOWN << 1;    // This is 0...0100
```

The above code could be written:

```cpp
if (key_status & SHIFT_DOWN)
    show("Warning: Operation not supported.");
```

If you wanted to check if the user was holding down the Shift and Alt keys during the mouse event, you could write

```cpp
if (key_status & (SHIFT_DOWN | ALT_DOWN))
    show("Warning: Operation not supported.");
```

Do you see how `SHIFT_DOWN | ALT_DOWN` means both keys are down simultaneously?

Since we concentrate on applications programming systems in this book, we will have little use bitwise operators except for a few isolated situations. It is good to be aware of their presence, though their accidental use may lead to debug compiler messages and logic errors. For example, suppose you mean to use `&` (logical AND) in a conditional expression instead of `&&`. Because C++ allows integers to be treated as Boolean operators and anything else is true, the mistake might affect the compiler's detection. The resulting logic error may be difficult to track.
