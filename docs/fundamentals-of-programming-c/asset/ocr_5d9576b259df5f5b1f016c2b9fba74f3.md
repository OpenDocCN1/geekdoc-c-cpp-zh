# 17.6. FINE TUNING INHERITANCE

for "implementation", protected compare_impl represents the implementation details of the compare method and swap_impl represents the implementation details of the swap method.

+   - The public compare and swap methods both depart part of the work to the protected compare_impl and swap_impl.

+   - The compare and swap methods are not declared virtual, so derived classes cannot override them.

+   - The compare and swap methods manage the compare_count and swap_count counter fields. Since derived classes cannot see these fields, there is noting that a designer of a derived class can when overriding compare_impl or swap_impl to disturb the correct accounting of the number of times a client calls compare or swap.

+   - The comparisons and swaps methods report the results to the client are non-virtual, so derived classes may not override their behavior.

Observe that the nature of the Comparer class allows the comparisons and derived classes to be flexible, but it is rigid on the enforcement of how the accounting is performed and reported. The proper use of protected and private specifiers in a base class as shown in Compar affords designers general of control over what derived class can do. Derived classes may adapt some behaviors, but other behaviors are non-virtual.

What kind of customization would a programmer want to do to the Compar class beyond how the comparison is performed? Consider the LogComparator class declared in Listing 17.21 (logcomparer.h).
