In Listing F.2 there is no reason why the print and sum functions should be able to modify the contents of their array parameters, the const specifier should be added to their definitions.

As a general rule, all functions that accept array parameters should declare the array contents const unless they need to modify the elements of the array.

> As a general rule, all functions that accept array parameters should declare the array contents unless they need to modify the elements of the array.
For example use,

int sum(const int a[], int n)
rather than
\int sum(int a[], int n)
if the sum function must be examine the contents of the array but is not intended to modify its contents.

C++ does not support empty arrays. A physical array must contain at least one element. Sometimes it is possible to consider an array that is conceptually empty: for example, if we wish to pass an "empty" array to the sum function; we can pass 0 as the second parameter since an empty array contains no elements, but what should we pass as the first? Any array will do, but there is no need to create a real array when one is truly needed. Instead, we may use nullptr.

```
quantity = sum(nullptr, 0);
```

If you scrutinize the body of the sum function, you will see that this will assign to quantity the correct answer, namely zero.

# F.3 Prime generation with an Array

Listing F.4 (fasterprimesarray.cpp) uses an algorithm developed by the Greek mathematician Eratosthenes who lived from 275 B.C. to 195 B.C. The principle behind the algorithm is: Make a list of all the integers under two. Two is a prime number, but any multiple of two cannot be a prime number (since a multiple of two has a factor). Go through the rest of the list and mark out all multiples of two (4, 6, 8, ...). Move to the next number in the list (in this case, three). If it is not marked out, it must be prime, so go through the list and mark out all multiples of that number (6, 9, 12, ...). Continue this process until you have listed all the primes you found.
