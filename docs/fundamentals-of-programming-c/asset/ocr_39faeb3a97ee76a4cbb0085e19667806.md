# 7.1. THE SWITCH STATEMENT

```
if (x == 1) {
    // Do 1 stuff here
}
else if (x == 2) {
    // Do 2 stuff here
}
else if (x == 3) {
    // Do 3 stuff here
}
```

The corresponding switch statement is:

```
switch (x) {
    case 1:
        // Do 1 stuff here
        break;
    case 2:
        // Do 2 stuff here
        break;
    case 3:
        // Do 3 stuff here
        break;
}
```

Now consider the following if/else:

```
if (x == y) {
    // Do "y" stuff here
}
else if (x > 2) {
    // Do ">2" stuff here
}
else if (x == 3) {
    // Do 3 stuff here
}
```

This code cannot be easily translated into a switch statement. The variable y cannot be used as a case. The second code checks for an inequality instead of an exact match, direct translation to a case label is impossible. In the last condition, a different variable is checked, z instead of x. The control flow of a switch statement is determined by a single value (example, the value of x), but a multi-way if/else statement is not so constrained.

Where applicable, a switch statement allows programmers to compactly express multi-way logic. Most programmers find a switch statement easier to read than an equivalent if/else construct.

A positive consequence of the switch statement's restrictions is that the compiler to produce more efficient code for a switch statement than for an equivalent if/else. If a choice must be made from several or more options, and the switch statement can be used, then the switch statement will likely be faster than the corresponding multi-way if/else.
