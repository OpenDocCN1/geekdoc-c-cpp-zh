When it is acceptable to use global variables, and when is it better to use local variables? In general, local variables are preferred to global variables for several reasons:

- When a function uses local variables exclusively and performs no other operations (like using the cin object), its behavior is influenced only by the parameters passed to it. If a non-local variable appears, the function's behavior is affected by every other function that can modify non-local variable. As a simple example, consider the following trivial function that appears in a program:

```cpp

  return n;
}
```

Can you predict what the following statement within the program will print?

```cpp

```

If your guess is 13, you are correct. The increment function returns the result of adding one to its argument. The increment function behaves the same way time it is called with the same argument.

The exclusion of global variables from a function leads to functional independence. A function that depends on information outside of its scope to perform its task is a dependent function. When a function operates on a global variable it depends on that global variable being in the correct state for the function to complete its task correctly. ## 10.1. GLOBAL VARIABLES

Unlike global variables, global constants are generally safe to use. Code within functions that use global constants are dependent on those constants, but since constants cannot be changed, developers need not worry that other functions that have access to the global constants may disturb their values.

The use of constants within functions has drawbacks in program maintenance. As a program evolves, code is added and removed. If a global constant is removed or its meaning changes during the course of the program's development, the change will affect any function using the global constant.

List 10.2(digitaltimer.cpp) uses global constants to assist the display of a digital timer.

## List 10.2: digitaltimer.cpp

```cpp
#include <iostream>
#include <iomanip>
#include <time>

using namespace std;

// Some conversions from seconds
const clock_t SEC_PER_MIN = 60,               // 60 sec = 1 min
                   SEC_PER_HOUR = 60 * SEC_PER_MIN;  // 60 min = 1 hr
                   SEC_PER_DAY = 24 * SEC_PER_HOUR;    // 24 hr = 24 hr

/*
* Displays the time in hr:min:sec format
* seconds is the number of seconds
*/

void print_time(clock_t seconds) {
    clock_t hours = 0, minutes = 0;

    // Prepare to display
    cout << endl;

    // Compute and display
    hours = seconds/SEC_PER_HOUR;
    cout << setw(2) << setfill('0') << hours << ":";

    // Remove the hours
    minutes = (seconds % SEC_PER_HOUR)/SEC_PER_MIN;
    cout << setw(2) << setfill('0') << minutes << ":";
    cout << setw(2) << setfill('0') << seconds % SEC_PER_MIN << endl;
}

int main() {
    clock_t start = clock();      // Record starting time
    clock_t elapsed = (clock() - start)/CLOCKS_PER_SEC; // Elapsed time in sec.
    clock_t previousElapsed = elapsed;

    // Counts up to 24 hours (1 day), then stops
    while (elapsed < SECPER_DAY) {
        // Update the display every second
        if (elapsed - previousElapsed >= 1) {
            // Remember when we updated the display
            previousElapsed = elapsed;
            print_time(elapsed);
        }
        // Update elapsed time
        elapsed = (clock() - start)/CLOCKS_PER_SEC;
    }
    return 0;
}
```

- The main function controls the time initialization and deals strictly in seconds. The logic in main is kept simply.
- The code that extracts hours, minutes, and seconds from a given number of seconds is isolated in print_time. The print_time function can now be used anytime a value in seconds needs to be expressed in the hours : minutes : seconds format.
- The second uses SEC_PER_HOUR, SEC_PER_MIN, and SEC_PER_DAY global constants that both functions can access. If the functions use different constants, it makes sense to place all the conversion factors in one place.

Since the two functions divide the responsibilities in a way they can be developed independently, the design is clean and easy to develop. The use of constants ensures that the shared values cannot be corrupted by either function.
