# 10.9. HIGHER-ORDER FUNCTIONS

```
swap(var1, var2);
```

does not require any special decoration. It looks like a normal pass by value function invocation. A programmer must be aware that swap reference parameters and any function that uses reference parameters can change the actual values passed to it.

Reference parameters were introduced in C++ so that of the more advanced object-oriented features could be implemented more cleanly. Some argue that for simpler situations like the swap function, pointer pass is less desirable than reference pass because reference by pointer pass the caller is forced to looking inside of the function and seeing the actual parameters may be modified. In this way there can be no doubt that pass is going on. With reference parameters, by value pass cannot be denied at the call site, since a call with reference parameters looks exactly like a value invocation.

In general, pass by value functions are preferred to reference parameters. Functions using side effects can change the state of the program in ways that cannot be understood only by looking inside the function and seeing how it works. Functions that access global variables (see Section 10.1) can cause side effects. Development is much easier when functions can be treated as black boxes that perform computations without the possibility of affecting anything outside of their local context. The result of a function's work can be assigned to a variable thus changing the state of the program, but that change is the responsibility of the caller, not the responsibility of the function. With pass by value, the function's parameters and local variables come into existence when the function executes, and local variables disappear when the function is finished, and nothing is erased by the function's execution.

Side-effect-free functions can be developed and in isolation from the rest of the program. Once programmers are satisfied with their correctness, they need not be touched again as the remainder of the system is developed. Functions with side effects, however, have dependencies to other parts of the program, and changes in the system may require programmers to modify and re-evaluate existing functions.
