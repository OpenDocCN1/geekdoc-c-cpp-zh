# 4.6.3 Logic Errors

Consider the effects of replacing the expression

```
dividend/divisor;
```

in Listing 4.7 (dividedanger.cpp) with the expression:

```
divisor/dividend;
```

The program compiles with no errors. It runs, and unless a value of zero is entered for the dividend, the run-time errors are away. However, the answer it computes is not correct in general. The only time the answer is printed is when dividend = divisor. The program contains an error, neither the compiler nor the run-time system is alerted. The problem of this type is known as a logic error.

Listing 4.14 (faultytempconv.cpp) is an example of a program that contains a logic error. Listing 4.14 (faultytempconv.cpp) compiles and does not generate any run-time errors, but produces incorrect results.

Beginning programmers struggle early on compile-time errors due to their unfamiliarity with the language. The compiler and error messages are the programmer's best friend. As the programmer gains experience with the language and the programs become more complicated, the number of compile-time errors decrease or are trivially fixed and the number of logic errors increase. Unfortunately, the compiler and run-time environment are powerless to provide any insight into the nature and location of logic errors. Logic errors tend to be the most difficult to find and fix. Tools such as debuggers are frequently used to help locate and fix logic errors, but these tools are far from mastering their operation.

Errors that escape detection (run-time errors and logic errors) are commonly called bugs. Since the compiler is unable to detect these problems, such bugs are the major source of frustration for developers. The frustration often arises because complex programs the bugs sometimes reveal themselves in situations that are difficult to reproduce exactly during testing. You will discover this frustration as your programs become more complicated. The good news is that programming experience and the disciplined application of good programming techniques can reduce the number of logic errors. The bad news is that software development in an inherently intellectual pursuit, logic errors are inevitable. Accidentrou and later finding and eliminating logic errors is an integral part of the programming process.
