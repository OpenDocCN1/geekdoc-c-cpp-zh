Unlike the original program, we now conveniently extend this program to handle many values as well as. We only need the definition of the NUMBER_OF_ENTRIES constant to allow the program to handle any number of values. This centralization of the vector's size eliminates duplicating a hard-coded value and leads to a program that is more maintainable. Suppose every occurrence of NUMBER_OF_ENTRIES were replaced with the literal value 5. The program would work exactly the same way, but changing the size would require touching many places within the program. When duplicate information is scattered throughout a program, it is a common error to update some but not all of the information when a change is to be made. If all of the duplicate information is not updated to agree, the inconsistencies remain in errors within the program. By faithfully using the NUMBER_OF_ENTRIES constant throughout the program instead of the literal value, problems with inconsistency can be avoided.

The first loop in Listing 11.3 (vector.cpp) collects all input values from the user. The second loop only prints the first four elements a comma after each element. Since no comma should be displayed after the last element, the program prints the last element after the loop is finished.

The compiler will insist that you use a numeric value for an index, but the programmer must ensure that the index is used within the bounds of the vector. Since the index may consist of an integer expression whose value cannot be determined until run time, the compiler cannot check for-of-bounds accesses, for example the code:

```
int x;
vector<int> v(10); // Make a vector with 10 spaces available
cin >> x; // User enters x at run time
v[x] = 1; // Is this OK? What is x?
```

the compiler cannot predict what the user will enter. This means that of a vector index can lead to run-time errors. To consider Listing 11.4 (vectorofbounds.cpp).
