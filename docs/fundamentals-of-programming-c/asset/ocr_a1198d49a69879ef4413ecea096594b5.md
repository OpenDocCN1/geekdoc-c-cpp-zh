The code with Listing 15.5 (trafficlight.cpp) must #include the trafficlight.h header so the compiler is expose to the Trafficlight declaration; otherwise when compiling trafficlight.cpp the compiler would not know if the method implementations fairly agreed. If the definition of Trafficlight::change in trafficlight.cpp specified parameters but its declaration in trafficlight.h did not, that would be a problem. Furthermore, without including trafficlight.h, the type SignalColor would be an undefined type within trafficlight.

Notice that the class declaration in Listing 15.4 (trafficlight.h) must prefix the names and enumerated type SignalColor with Trafficlight::. Without this prefix the compiler would treat the identifiers as global. TrafficLight::SignalColor is the declared in the TrafficLight class, but by itself is a global type (that does not exist).
