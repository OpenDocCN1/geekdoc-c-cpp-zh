```
int ZERO;
ZERO = 1;
```

The identifier in the first line ends with a capital "Oh." In the second line, the identifier ends with the digit zero. The distinction may be difficult or impossible to see in a particular article or printout of the code. A C++ compiler would immediately detect the type in second statement, since ZERO (last letter a) has not been declared. A dynamically-typed language would create two variables: ZERO and ZERO.

+   - When variables are declared, the programmer can catch invalid operations. For example, a variable may be declared of type int, but the programmer might accidentally assign a non-numeric value to it. In a dynamically-typed language, the variable would silently change its type thereby introducing an error into the program. In C++, the compiler would report the improper assignment as error, since once declared cannot change its type.
- Ideally, requiring the programmer to declare variables forces the programmer to plan and think more about the variables a program might require. The type of a variable is tied to it so the programmer must have a clear notion of the variable's purpose before declaring it. When variable declarations are not required, a programmer can "make" of variables as needed as the code is written. The programmer need not think about the dosage of the variable's purpose that writing the variable's declaration requirements. While this is a very limited advantage, any opportunity to catch such errors is beneficial.
