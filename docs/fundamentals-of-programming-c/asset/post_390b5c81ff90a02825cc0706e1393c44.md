## 16.1 A Better Rational Number Class

Listing 16.1 (rational.cpp) enhances the SimpleRational class (Listing 14.5 (simplerational.cpp)) providing a more complete type.

```cpp
Listing 16.1: rational.cpp
#include <iostream>

using namespace std;
class Rational {
    int numerator;
    int denominator;

    // Compute the greatest common divisor (GCD) of two integers
    static int gcd(int m, int n) {
        if (n == 0)
            return m;
        else
            return gcd(n, m % n);
    }
    // Compute the least common multiple (LCM) of two integers
    static int lcm(int m, int n) {
        return m * n / gcd(m, n);
    }
public:
    Rational(int n, int d) : numerator(n), denominator(d) {
        if (d == 0)
            // Disallow an undefined fraction
            cout << "*****Warning---Illegal Rational*****" << endl;
            numerator = 0; // Make up a reasonable default fraction
            denominator = 1;
    }
}

// Default fraction is 0/1
Rational() : numerator(0), denominator(1) {}

int get_numerator() const {
    return numerator;
}

int get_denominator() const {
    return denominator;
}

Rational reduce() const {
    // Find the factor that numerator and denominator have in common
    int factor = gcd(numerator, denominator);
    // then divide it out in the new fraction
    return Rational(numerator/factor, denominator/factor);
}

// Equal fractions have identical numerators and denominators
bool operator=(const Rational& fract) const {
    // First, reduce the reduced form of this fraction and the parameter
    Rational f1 = reduce();
    Rational f2 = fract.reduce();
    // then see if their components match.
    return (f1.numerator == f2.numerator && f1.denominator == f2.denominator);
}

// Compute the sum of fract and the current rational number
Rational operator+(const Rational& fract) const {
    // Find common denominator
    int commonDenominator = lcm(denominator, fract.denominator);
    // Add the adjusted numerators
    int newNumerator = numerator * commonDenominator/denominator
        + fract.numerator * commonDenominator/fract.denominator;
    return Rational(newNumerator, commonDenominator);
}

// Compute the product of fract and the current rational number
Rational operator*(const Rational& fract) const {
    return Rational(numerator * fract.numerator,
        denominator * fract.denominator).reduce();
}

// Allow a Rational object to be displayed in a nice-readable form.
ostream& operator<<=(ostream& os, const Rational& r) {
    os << r.get_numerator() << "/" << r.get_denominator();
    return os;
}

```

int main() {
    Rational f1(1, 2), f2(1, 3);
    cout << f1 << " + " << f2 << " = " << (f1 + f2) << endl;
    cout << f1 << " * " << f2 << " = " << (f1 * f2) << endl;
}
```

Listing 16.1 (rational.cpp) produces some notable features:

- **Constructors.** The overloaded constructors permit convenient initialization and make it impossible to create an undefined fraction.
- **Private static methods.** *Rational* provides two static methods: *gcd* and *lcm*. The algorithm for *gcd* (greatest divisor) method was introduced in Section 10.4. The *lcm* (least common multiple) method is derived from the mathematical relationship: gcd(m,n) × lcm(m,n) = m × n. These methods are declared private because they are not meant to be used by client code. Client code expects functionality typical of rational numbers, such as addition and reduction; these two methods are used by other methods that provide functionality more related to rational numbers. An object is not required to compute the greatest divisor of two integers. It is legal for *gcd* and *lcm* to be instance methods, instance methods should be used only when necessary, since they have the power to alter the state of an object. Faulty coding modifying an instance variable can be difficult to track. If a class is used, the compiler can stop any attempt to access an instance variable immediately.
- **Public instance methods.** None of the instance methods (operator==, reduce, operator+, operator*) modify the state of the object upon which they are invoked. The *Rational* class still produces immutable objects. The operator+, operator*, and reduce use private helper methods to accomplish their respective tasks.
- **Global** operator<< is a global function that allows a *Rational* object to be displayed conveniently as a built-in type.

## 16.2 Stopwatch

The linear search vs. binary search program (Listing 12.5 (searchcompare.cpp)) accessed the system clock in order to time the execution of a function. The program used the clock function from the standard C library and an additional variable to compute the elapsed time. The following skeleton code fragment:

```cpp
clock_t seconds = clock(); // Record starting time

/*
  * Do something here that you wish to time
*/

clock_t other = clock(); // Record ending time
cout << static_cast<double>(other - seconds)/CLOCKS_PER_SEC
     << "seconds" << endl;
```

Certain works can be adapted to any program, but it has several drawbacks:

- A programmer must care to implement the timer code correctly for each section of code to be timed. This is prone to error:
- clock_t is a specialized type that is used frequently. It is not obvious from its name that clock_t is equivalent to an unsigned integer, so a programmer may need to consult a library reference to ensure its proper use.
- The programmer must specify the correct arithmetic: (other - seconds)/CLOCKS_PER_SEC
- The cast to double of time difference is easily forgotten or applied. If a programmer incorrectly applies parenthetical as so static_cast<double>((other - seconds)/CLOCKS_PER_SEC) the result will lose precision. Yet, the following parenthetical grouping static_cast<double>(other - seconds)/CLOCKS_PER_SEC will give an incorrect value, since division has precedence over subtraction.
- The timing code is supplemental to the actual code that is being profiled, but it is not obvious by looking at the code what statements are part of the timing code and which statements are part of the code to be timed.

Section 10.5 offers a solution to the above shortcomings of using the raw types, constants, and functions available from the C library. Listing 10.13 (timerodule.cpp) hides the details of the C library and provides a convenient functional interface to callers. Unfortunately, as mentioned in Section 10.5, the functional approach has a serious limitation. In Listing 10.13 (timerodule.cpp) uses global variables to maintain the state of the timer. There is only one type of global variable. This means programmers using the timer function cannot independently measure the elapsed time of overlapping events; for example, you cannot measure how long it takes for a function to execute and simultaneously measure how long it takes for another function.

Objects provide a solution. Consider the following code that uses a stopwatch to keep track of the time:

```cpp
Stopwatch timer; // Declare a stopwatch object
timer.start(); // Start the clock
timer.stop(); // Stop the clock
cout << timer.elapsed() << " seconds" << endl;
```

This code using a stopwatch is as simple as the raw clock function, but then we are back where we began: messy, potentially error-prone code. Objects provide a better way.

```cpp
16.2: stopwatch.h
#ifndef STOPWATCH_H_DEFINED
#define STOPWATCH_H_DEFINED

#include <ctime>

class Stopwatch {
    clock_t start_time;
    bool running;
    double elapsed_time;
public:
    Stopwatch();
    void start(); // Start the timer
    void stop(); // Stop the timer
    void reset(); // Reset the timer
    double elapsed() const; // Reveal the elapsed time
    bool is_running() const; // Is the stopwatch currently running?
};

#endif
```

From this class we claim that when we create a Stopwatch constructor is avoidable to take care of any initialization data. Four methods are available to clients: start, stop, reset, and elapsed. The reset method is included to set the clock back to zero to begin a new timing. Note that the "messy" detail of the clock_t variable is private and, therefore, clients cannot see or directly access its value within a Stopwatch object. What do you need to time two things at once? If you use two stopwatches, of course, you would declare two Stopwatch objects. Each object maintains its instance variables, each Stopwatch can keep track of its elapsed time independently of all other active objects.

Programmers using a Stopwatch object in their code are much less likely to make a mistake because the details are hidden and invisible. With objects we can wrap the messy timing code into a convenient package.
