# 4.6. ERRORS AND WARNINGS

```
### Listing 4.7: dividedanger.cpp
// File dividedanger.cpp

#include <iostream>

using namespace std;

int main() {
    int dividend, divisor;

    // Get two integers from the user
    cout << "Please enter two integers to divide";
    cin >> dividend >> divisor;
    // Divide them and report the result
    cout << dividend << " /" << divisor << " = " 
         << dividend/divisor << endl;
}
```

The expression
divident/divisor

is dangerously. If the user enters, for example, 32 and 4, the program works nicely

![](bbox=[0.156, 0.485, 0.781, 0.546])

and displays the answer of 8. If the user types the numbers 32 and 0, the program reports an error and terminates. Division by zero is undefined in mathematics, and division by zero in C++ is illegal. When the program attempts the division at run time, the system detects and terminates the program.

This particular program can fail in other ways as well; for example, outside of the C++ world, 32.0 looks like a respectable integer. If the user types 32.0 and 8, the program crashes because 32.0 is not a valid way to represent an integer in C+. When the compiler compiles the source line

```
cin >> dividend >> divisor;
```

given that dividend has been declared to be an int, it generates slightly different language code than if dividend had been declared to be a double instead. The compiled code expects the text entered by the user to be digits with no decoration. Deviation from this expectation results in a run-time error. Similar results occur if the user enters text that does not represent an integer, like fried.

Observe that in this case—entry of a bad integer (zero) or entry of a non-integer (32.0) or fried)—is impossible for the compiler to check for these problems at compile time. The compiler cannot predict what the user will enter when the program is run. This means it is up to the programmer to write code that can handle bad input the user may provide. As we continue our exploration of programming in C++, we will discover ways to make programs more robust against user input (see Listing 5.2 betterdivision.cpp) in Chapter 5, for example). The solution involves changing the way the program runs on the actual input provided by the user.
