All C++ standard exception classes have std::exception as their direct or indirect base class. C++ does not require exception objects to be derived from exception: in fact, primitive types such as int and char can be thrown and caught. Because of this, the "catch all" exception clause is

```cpp
catch (...) {
    // Catches any exceptions caught by more specific
    // catch blocks in this try/catch block
}
```

The ellipses (...) stand for any exception of type. Any function or method can throw an exception. Given an exception of type E, the statement to do is:

```cpp
throw E();
```

## 19.6 Using Exceptions

Exceptions should be reserved for uncommon errors. For example, the following code adds up all the elements in an integer vector named vec:

```cpp
int sum = 0, n = vec.size();
for (int i = 0; i < n; i++) {
    sum += vec[i];
}
cout << "Sum = " << sum << endl;
```

This loop is fairly typical. Another approach uses exceptions:

```cpp
int sum = 0;
int i = 0;
try {
    while (sum += vec.at(i));
} catch (out_of_range&) {
    cout << "Sum = " << sum << endl;
}
```

Both approaches compute the same result. The second approach terminates the loop when the array access is out of bounds. It interrupts the statement

```cpp
sum += vec.at(i));
```

in midstream, it does not incorrectly modify sum's value. The second approach, however, always throws and catches an exception. The exception defines not an uncommon occurrence.

You should not use exceptions to dictate normal logic flow. While useful for intended purpose, the exception mechanism adds some overhead to program execution, especially when an exception is thrown. This overhead is reasonable when exceptions are rare but not when exceptions are part of the program's normal execution.

Sometimes it is not clear when an exception is appropriate. Consider a function that returns the position of an element within a vector. The straightforward approach does not use exceptions could be written:

```cpp
int find(const vector<int>& a, int elem) {
    int n = a.size();
    for (int i = 0; i < n; i++)
        if (list[i] == elem)
            return i; // Found it at position
    return -1; // Element not present
}
```

A return value of -1 indicates that the element is not present in the array. Should an exception be thrown if the element is not present? The following code illustrates:

```cpp
int find(const vector<int>& a, int elem) {
    for (int i = 0; i < n; i++)
        if (list[i] == elem)
            return i; // Found it at position
    // Element not there; throw an exception
    throw ElementNotPresentException();
}
```

In the first approach, you may check the result and blindly use -1 as a valid position. The exception code would not allow this to happen. However, the first approach is useful for determining if an element is present in the vector. If find(x) returns -1, then x is not in the vector; otherwise, it is in the vector. If the exception approach is used, a client programmer cannot determine if an element is present without the risk of throwing an exception. Since exceptions should be rare, the second approach appears to be less than ideal. In,

- The first approach is more useful, but clients need to remember to check the result.
- The second approach provides an exception safety net, but an exception will be thrown when searching for missing elements.

Which approach is ultimately better? The first version uses a common programming idiom and is the better approach for most programming situations. The exception version is a poorer choice since it is not uncommon to attempt to look for an element missing from a vector; exceptions should be reserved for uncommon error situations.
