An exception almost always represents a problem, usually some run-time error. Suppose we have a vector v and an integer i. Unless 0 <= i < v.size(), the expression v[i] attempts to access the outside element of the vector. The operator[] performs no bounds checking; thus an executing using the expression v[i] could produce undefined behavior. Consider instead the expression v.at(i). The method works just like operator[], except it does check the vector's bounds. If i >= v.size() or i < 0, the expression v.at(i) represents an exceptional situation, and we say the vector's method throws, or raises, an exception.

Without advantage of C++ exception handling infrastructure, the following statement:

```
v.at(i) = 4;
```

could terminate the program with an error message. This is better than without undefined behavior, it is not ideal. The program crashes. When a real application crashes the user may lose data. Badly behaving programs terminate unexpectedly. It would be better to defend against the out-of-bounds index and keep the program alive.

An algorithm could help many potential problems solved. For example, a programmer can use an if statement to see if a vector's index is within the proper bounds:

```
if (0 < i && i < v.size()) // Ensure i is in range
v.at(i) = 4;
```

However, if the program accesses a vector in several different locations within a function and the index variable can change from place to place, the if statements necessary to ensure safe access might miss the overall logic of the function or method.

Consider Listing 19.1 (vectorboundscrash.cpp). The program crashes whenever the user enters an index out of the range of vector `nums`.

Listing 19.1: vectorboundscrash.cpp
```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    vector<double> nums { 1.0, 2.0, 3.0 };
    int input;
    cout << "Enter index: ";
    cin >> input;
    cout << nums.at(input) << endl;
}
```

The method guarantees that an illegal access will not go undetected. To intercept the problem at time and prevent the program from terminating due to an error, we use a try/catch block, which consists of two parts: a try block and a catch block. To form a try/catch block we:

1. wrap the code that has the potential to throw an exception in a try block,
2. provide code to execute only in the event of an exception in a catch block.

Listing 19.2 (vectorboundexcept.cpp) adds the exception handling code to Listing 19.1 (vectorboundscrash.cpp).

```
Listing 19.2: vectorboundexcept.cpp
```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    vector<double> nums = {1.0, 2.0, 3.0};
    int input;
    cout << "Enter an index: ";
    cin >> input;
    try {
        cout << nums.at(input) << endl;
    } catch (exception& e) {
        cout << e.what() << endl;
    }
}
```

If a user enters a value less than zero or greater than two when executing Listing 19.2 (vectorboundexcept.cpp), the program will print an error message and terminate successfully instead of crashing.

Both try and catch are keywords in C++. Unlike the bodies of the structured statements such as if and while, the statements within a try block and statements within a catch block must appear with curly braces, if only one statement appears in the section.

> Every try or catch block must surround its statements with curly braces—even if it contains just one statement.

The variable e in the catch block of Listing 19.2 (vectorboundexcept.cpp) is a reference to an exception object. The exception class is part of the standard C++ library and is the base class for all exceptions. The exception class provides a method that returns a string. The exception::what method's string is a message containing information about the exception. The C++ standard does not specify the exact message, but at the least the exception::what method indicates the kind of exception caught. The following shows what the program reports under Visual C++ when the user enters the value 3:

```
Enter an index: 3
invalid vector<T> subscript
```

```cpp
try {
    cout << nums.at(input) << endl;

catch (exception& e) {

if (0 < input && input < nums.size()) {

### Listing 19.3: callexception.cpp
```cpp
#include <iostream>
#include <vector>
#include <string>

using namespace std;

// Used to keep track of object creation and destruction
class Tracker {
    string name;
public:
    Tracker(const string& s) : name(s) {
        cout << "Creating Tracker " << name << endl;
    }
    ~Tracker() {
        cout << "Destroying Tracker " << name << endl;
    }
};

bool find(const vector<int>& vec, int lower, int upper) {
    cout << "---find------" << endl;
    Tracker obj("find"); // Local object
    bool result = false; // Not default
    int seek;
    // What to look for
    cout << "Enter item to locate: ";
    cin >> seek;
    for (int i = lower; i < upper; i++) {
        if (vec.at(i) == seek) {
            result = true;
            break;
        }
    }
    cout << "---find------" << endl;
    return result;
}

void process(const vector<int>& v) {
    cout << "---process----" << endl;
    Tracker obj("process"); // Local object
    int low, high;
    cout << "Enter a range: ";
    cin >> low >> high;
    if (find(v, low, high))
        cout << "Found it" << endl;
    else
        cout << "Not there" << endl;
    cout << "---process----" << endl;
}

int main() {
    cout << "---main----" << endl;
    Tracker obj("main"); // Global object
    vector<int> nums = {11, 42, 23};
    try {
        process(nums);
    } catch (const exception& e) {
        cout << "nums bounds exceeded" << endl;
        cout << "---main----" << endl;
    }
}
```

Listing 19.3 (callexception.cpp) is specially crafted to provide insight into the program's execution. Each function prints a message at its beginning and end so we can see when the code within a function is active. Each function also declares a local object which is identified by the name of function and automatically destroys the object when the function returns to caller. These local objects, however, have a lifetime that mirrors the lifetime of the function they manage. Listing 19.3 (callexception.cpp) declares a global Tracker. An executing function creates global objects before it calls main and automatically destroys them after main completes.

Listing 19.3 (callexception.cpp) covers the vector nums, declared in main. During this call, the main function has no control over the process function's attempt to access an element outside of the range. The process function, however, does not attempt to access any elements within the vector that main supplies. Instead, process passes the vector to the find function. It is in find that calls the at method at an out-of-bounds index, which will throw an exception. Unlike in 19.2 (vectorexception.cpp), the method that calls vector<int>::at does not within a try/catch block. This means find cannot catch any exceptions that vector<int>::at might.

The following shows a sample run of Listing 19.3 (callexception.cpp).

```

---main----
Creating Tracker (main)
---process----
Creating Tracker (process)

---find------
Creating Tracker (find)

```

In this output of Listing 19.3 (callexception.cpp) we see the following sequence of events:

1. The program creates the global Tracker object.
2. The program calls main.
3. The main function creates its Tracker object.
4. main calls process.
5. The process function creates its Tracker object.
6. The process function obtains the user's input for range values. Here the users entered the range 0..2.
7. The process function calls find.
8. The find function creates its Tracker object.
9. The find function obtains the user's input for the element. Here the user enters 4 (which is not present in the vector).
10. The find executes its last statement.
11. When find returns to process, the program destroys find's local Tracker object.
12. process uses find's result to print the message that the element is not present in the vector.
13. The process function executes its last statement.
14. When process returns to main, the program destroys process's local Tracker object.
15. The main function executes its last statement.
16. When main returns, the program destroys main's local Tracker object.
17. The program terminates it destroys the global Tracker object.
