Note that in Listing 19.9 (retrow.cpp) the compute function does not create a new exception object; simply re-throws the same exception that it caught. This concept of intermediate exception handlers is important because a function invocation has complete knowledge of its local context such as the local variables. While an intermediate function (or method) in the call chain has access to information that may be unavailable to all other functions (methods) the catch block in the compute function of Listing 19.9 (retrow.cpp) involves only local variables. The catch block within the main function cannot know the subscript caused compute's failure since i is local to compute. Some general guidelines include:

+   * Handle exceptions (or the up call) as possible to the code that throws the exception.
* Use local information where applicable to correct as much of the problem as possible within that local context:

+   - Local information which may be important for recovering from the exceptional situation is available; this local information is unavailable to functions or methods up the call chain.
- The lower-level functions/methods that promote exception may be called by many different higher-level functions/methods. If the lower-level functions/methods are responsible for their exception handling, then the higher-level functions/methods may be dispense with exception handling making the lower-level methods most robust of use.
- The lower-level functions handle many different kinds of exceptions, do local clean up based on the type of exception, and then draw a type of exception to the higher-level methods. The higher-level method may just need to know there was a problem needing to know exactly what the problem was. For example, in Listing 19.9 (retrow.cpp), the compute function would throw a ComputeException object whenever filters throws its out_of_range instead of passing up the call chain the out_of_range object.

If recovery is not possible or desired at the lower levels of the call chain, re-throw the exception so an exception handler up can take steps to recover from the problem in a manner that makes sense in its context.

When a section of code throws an exception, the catch blocks within the exception handler are checked in the order they appear in the C++ source code. The first catch that matches the type of the exception is the one executed.
