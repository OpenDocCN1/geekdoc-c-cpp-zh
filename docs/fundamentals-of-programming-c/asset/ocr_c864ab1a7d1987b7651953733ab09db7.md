+   - A programmer must care to implementing the timer code correctly for each section of code to be timed. This is prone to error:
- clock_t is a specialized type that is used frequently. It is not obvious from its name that clock_t is equivalent to an unsigned integer, so a programmer may need to consult a library reference to ensure its proper use.
- The programmer must specify the correct arithmetic:(seconds)/CLOCKS_PER_SEC
- The cast to double of time difference is because easily forgotten or applied. If a programmer incorrectly applies parenthetical as so static_cast<double>((other - seconds)/CLOCKS_PER_SEC
The result will lose precision. Yet, the following parenthetical grouping static_cast<double>(other - seconds)/CLOCKS_PER_SEC
will in an incorrect value, since division has precedence over subtraction.

+   - The timing code is supplemental to the actual code that is being profiled, but it is not obvious by looking at the code what statements are part of the timing code and which statements are part of the code to be timed.

Section 10.5 offers a solution to the above shortcomings of using the raw types, constants, and functions available from the C library. Listing 10.13 (timerodule.cpp) hides the details of the C library and provides a convenient functional interface to callers. Unfortunately, as mentioned in Section 10.5, the functional approach has a serious limitation. In Listing 10.13 (timerodule.cpp) uses global variables to maintain the state of the timer. There is only one type of global variable. This means programmers using the timer function cannot independently measure the elapsed time of overlapping events; for example, you cannot measure how long it takes for a function to execute and simultaneously measure how long a section of code within that function to execute.

A programmer could time multiple, simultaneous activities using the raw C library clock function directly, but then we are back where we began: messy, potentially error-prone code.

Objects provide a solution. Consider the following client code that uses a stopwatch to keep track of the time:

```
Stopwatch timer; // Declare a stopwatch object
```

```
timer.start();    // Start timing
```
