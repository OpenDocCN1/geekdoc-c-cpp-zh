Listing 19.3 (callexception.cpp) demonstrates that exceptions have the potential to radically alter the normal call and return pathways. In one sense an exception works like a “super goto” statement. The program's execution jumps to a previous point in its execution sequence, bypassing all functions in the call chain. Recall Section 6.3.2 discouraged the use of the goto statement except for to exit from a nested loop. This is the code in which goto instead of a super structured branching and looping constructs such as if/else, switch, while, and for to be difficult to extend and maintain. C++'s exception mechanism is different than a “super goto” in several important ways:

- A goto statement cannot jump to outside the code of the function in which it appears. Exceptions have no such limitation.
- The programmer must specify a destination (label) for a goto statement. The vector<int>::at method throws the exception. We can call at at many different functions within a single program and use at in many different programs. The code within the method cannot possibly know where to go if it encounters an exceptional situation. An exception simply redirects the program's execution to the most recent try/catch block in the call chain that can handle the exception.

## 19.3 Custom Exceptions

**CAUTION! CONSTRUCTION**

The standard C++ library has a limited number of exceptions. We can create our custom exceptions for specialized handling that applications may require. FileNotFoundException, derived from exception, defines a custom class.

```cpp
class FileNotFoundException : public exception {
    string message;
public:
    // Constructor establishes the exception's
    FileNotFoundException(const string& fname):
        message(fname + " not found") {}

    // Reveal message to clients
    const char *what() const {
        return message.c_str();
    }
};
```

## 19.6: filereadexcept.cpp

```cpp
#include <iostream>
#include <fstream>
#include <vector>
#include <string>

using namespace std;

// Exception to throw when a client attempts to
// open a file by a name that does not correspond
// to the file in the current directory.
// Returns a vector of integers.
vector<int> load_vector(const string filename) {
    ifstream fin(filename);
    if (fin.open(filename)) {
        int n;
        fin >> n;
        vector<int> data(n);
        int i = 0;
        while (fin >> value) {
            data.at(i++) = value;
        }
        fin.close();
        return data;
    } else {
        throw FileNotFoundException(filename);
    }
}
```
