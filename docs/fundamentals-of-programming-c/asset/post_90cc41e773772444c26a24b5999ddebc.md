
## 15.7. STATIC MEMBERS

# Listing 15.8: trafficsignal.h

```cpp
#ifndef TRAFFICSIGN_H_
#define TRAFFICSIGN_H_

class TrafficSignal {
    int color; // The light's current color: RED, GREEN, or YELLOW
public:
    // Constants available to clients
    static const int RED = 0;
    static const int GREEN = 1;
    static const int YELLOW = 2;

    TrafficSignal(int initial_color);
    void change();
    int get_color() const;
};

#endif
```

The state of a traffic light—which of its lamps is illuminated—is determined by an integer value: 0 represents red, 1 stands for green, and 2 means yellow. It is much more convenient for clients to use the symbolic constants RED, GREEN, and YELLOW to remember which values stand for which colors. These constants are public, so clients can freely access them, but since they are constants, clients cannot alter them. An additional benefit to using a static const is this: you may initialize a static const outside the class body itself. You do not need to re-define a non-const static field outside the class body as you do.

Listing 15.9 (trafficsignal.cpp) provides the implementation of the methods of TrafficSignal class.

# Listing 15.9: trafficsignal.cpp

```cpp
#include "trafficsignal.h"

// Ensures a traffic light object is in the state of
// red, green, or yellow. A rogue integer value makes the
// traffic light
TrafficSignal::TrafficSignal(int initial_color) {
    switch (initial_color) {
        case RED:
        case GREEN:
        case YELLOW:
            color = initial_color;
            break;
        default:
            color = RED; // Red by default
    }
}

// Ensures the traffic light's signal sequence
void TrafficSignal::change() {
    // Red -> green, green -> yellow, yellow -> red
    color = (color + 1) % 3;
}

// Returns the light's current color so a client can
// act accordingly
int TrafficSignal::get_color() const {
  return color;
}
```

Within the methods of the TrafficSignal class we can use the simple names RED, GREEN, and YELLOW. Code outside of the TrafficSignal class can access the colors because they are public but must use the fully-qualified names TrafficSignal::RED, TrafficSignal::GREEN, and TrafficSignal::YELLOW.

A client can create a traffic light object

```cpp
TrafficLight(TrafficSignal::YELLOW);
```

Since the code is outside of the TrafficSignal class must use the full TrafficSignal::YELLOW name. This makes an initially yellow traffic light. The RED, GREEN, and YELLOW fields are constants, clients cannot access them directly to control the state of a traffic light. To see why, consider a minor change to TrafficSignal in the class we will call TrafficSignalAlt:

```cpp
TrafficSignalAlt {
  int color; // The light's current color: RED, GREEN, or YELLOW
public:
  // Constant instance fields available to clients
  const int RED;
  const int GREEN;
  const int YELLOW;

  TrafficSignalAlt(int initial_color);
  void change();
  int get_color() const;
};
```

TrafficSignalAlt is identical to TrafficSignal, except that the constants are instance fields instead of class (static) fields. Observe that like the TrafficSignal class, the TrafficSignalAlt has no default constructor. Recall from Section 14.4 that a default constructor accepts no arguments, and if a programmer provides any constructor for a class, the compiler will not automatically provide a default constructor. This client cannot write code such as

```cpp
TrafficSignal light;
```

or

```cpp
TrafficSignalAlt light;
```

During the object's construction the client must create an integer argument representing a traffic light color. If RED, GREEN, and YELLOW are constant instance variables (that is, non-static fields), every TrafficSignalAlt object has its own copy of the fields, and the RED, GREEN, and YELLOW fields cannot exist outside of any traffic light. This leads to a chicken-and-egg problem—how can we create the first TrafficSignalAlt object using the symbolic constants RED, GREEN, or YELLOW? These do not exist unless we have a traffic light object, yet we need a traffic light to have any of these constants!

## 15.8 CLASSES VS. STRUCTS

During a program's execution, static class fields are created before main executing. This means any data pertaining to a class that must exist before any object of that class is created must be declared static. Static class variables exist outside of any instance of that class.

C++ allows methods to be declared static. A static method executes on behalf of the class, not an instance of it. This means that a static method may not access any instance variables (that is non-static fields) of the class, nor may they call all other non-static destructors. A static method executes on behalf of the class, it has no access to the fields of any instance of that class. This explains the restriction static accessing non-static data members. Since a non-static method may access instance variables of an object upon which it is called, a static method may call a non-static method and indirectly have access to instance variables. The restriction goes only one way—any class, static or non-static, may access a static data member or call a static method. Said another, no static methods have the this implicit parameter (Section 15.2). No static method has this parameter.

### 15.8 Classes vs. structs

All members of a C++ class are private by default. The class

```cpp
class Point {
public:
    double x;
    double y;
};
```

must use the public label so clients can access a Point object's fields. The struct keyword is exactly like the class keyword, except that the default access to members is public:

```cpp
struct Point {
    double x;   // These fields may now public
    double y;
};
```

The C language supports the struct feature, but not the class C structs do not support methods, constructors, and destructors. In C++ (unlike C), a struct can contain methods, constructors, and destructors. By default, members in struct are public, but you can apply the private and public labels as a class to tune client access.

Despite their similarities, C++ programmers favor classes over structs for programmer-defined types with methods. The struct is useful for designing simple composite data types that are not treated like primitive types. It makes sense to allow client to directly manipulate the coordinates, rather than use methods like set_x and set_y. On the other hand, a fraction with a zero denominator is undefined.

## 15.9 SUMMARY

In C++, by default everything in an object defined by a struct is accessible to clients that use that object. In contrast, clients have no default access to the internals of an object that is instance of a class. The default member access for struct is public, and the default member access for class is private.

The struct feature is, in some sense, redundant. It is a carryover from C. By retaining the struct however, C++ programs can use C libraries use use structs. Any C++ program that expects to use C library using struct must restrict its definitions to the limited form supported by C. Such struct definitions may not contain non-public members, methods, constructors, etc.

### 15.9 Summary

- The dot (.) operator is used to access a member of an object, the arrow (->) operator is used to access a member of an object via a pointer.
- A method declared const may not modify the value of an instance variable within an object. The compiler enforces this restriction.
- The class interface includes variable declarations and method prototypes. The method implementations can appear in a separate file.
- Method implementations can appear in class declarations so that a class interface and implementation are combined in one place.
- A non-const method may not be called with a const object. Any public method can be called with a non-const object.
- Operators may be overloaded for programmer-defined types. Overloaded operators may be global functions and methods.
- A programmer-defined operator obeys the same precedence and associativity as the built-in operator it overloads.
- Unlike instance variable, a static field is shared by all objects of their class.
- Unlike instance variables, a static field must be declared outside of the class declaration.
- A static method executes on behalf of the class, not instance of the class.
- A static method may not access any instance variables of the class, nor may they call other static methods.
- Any class method, static or non-static, may access a static data member or call a static method.
