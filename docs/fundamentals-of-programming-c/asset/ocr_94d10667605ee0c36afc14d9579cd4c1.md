```

or

```

results in an empty loop. Some programmers use an empty loop to produce a non-portable delay in the program's execution. A programmer may, for example, need to slow down a graphical animation. Such an attempt using empty loop is non-portable for several reasons. If the program executes the loop, slower computers will delay longer than faster computers. The timing of the program's delay will differ from one computer to another. Worse yet, some compilers may detect that such code has no functional effect and optimize the empty loop. This means this compiler will ignore the for statement altogether.

> As mentioned in Section 5.3, be careful about accidentally putting a semicolon at the end of the for header, as in
for (int i = 0; i < 10; i++);
/* Intended body goes here */
The semicolon terminates the for statement, and the intended body that follows is not the body, even if it be properly indented.

One common C/C++ idiom to make an infinite loop is to use a for statement with all control information:

```
for ( ; );
/* Body goes here */
```

Omitting all parts of the for loop is a statement that the programmer says "I know what I am doing—I want an infinite loop." In reality the loop may not be infinite at all; its body could contain a break or goto statement.

While the for loop supports the omission of parts of it, structures should be bounded. The intention of the for loop is to allow the programmer to see all the aspects of the loop's control in one place. Some of these control responsibilities are better handled elsewhere (not in the for header) when considering another kind of loop.

Programmers generally use a simple name for the control of a variable to reflect the meaning of their use within the program. It may come as a surprise that i is the most common name for an integer variable in a for loop. This practice has its roots in mathematics where variables as i, j are commonly used to identify vectors and matrices. Mathematical structures have functional analogies to arrays and vectors, which we explore in Chapter 1. Computers use for loops in array and vector processing, so programmers have universally adopted this convention of short control variable names. Thus, it is generally acceptable to use identifiers like i as loop control variables.
