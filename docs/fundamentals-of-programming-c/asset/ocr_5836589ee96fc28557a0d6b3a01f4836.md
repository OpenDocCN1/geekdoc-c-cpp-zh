# 17.2. INHERITANCE MECHANICS

If we omit the word public from class D's definition, as in

```
class D: B {
    // Details omitted
};
all the public members of B inherited by D objects will be private by default; for
example, if base class B looks like the following:

class B {
    public:
    void f();
};

void B::f() {
    std::cout << "In function 'f'" << std::endl;
}
```

the following code is not legal

```
D myD;
myD.f(); // Illegal, method f now is private
```

This means a client may not treat a D object as if it were a B object. This violates the Liskov Substitution Principle, and is a relationship that does not exist.

While this particular inheritance is useful in rare situations, the majority of object-oriented software designs uses public inheritance. C++ is one of the few object-oriented languages that supports private inheritance.

There is no limit to the number of classes may derive from a single class. In the following code:

```
class D1: public B { /* Details omitted */ };nclass D2: public B { /* Details omitted */ };nclass D3: public B { /* Details omitted */ };
```

the classes D1, D2, and D3 are all derived from class B.

A developer may derive a class from more than one base class in a process known as multiple inheritance. In the following code:

```
class B1 { /* Details omitted */ };nclass B2 { /* Details omitted */ };
```

```
class D: public B1, public B2 { /* Details omitted */ };
```

Here D has two base classes, B1 and B2. If a particular function or method expects a B1 object as an argument, the caller may pass a D object; any context that requires a B2 object will accept a D. In object-oriented design, multiple inheritance is not as common as single inheritance (one base class).
