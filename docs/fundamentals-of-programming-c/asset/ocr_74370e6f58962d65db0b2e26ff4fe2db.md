In Listing 10.2 (digitaltimer.cpp):

+   * The main function controls the time initialization and deals strictly in seconds. The logic in main is kept simply.
* The code that extracts hours, minutes, and seconds from a given number of seconds is isolated in print_time. The print_time function can now be used anytime a value in seconds needs to be expressed in the hours : minutes : seconds format.
* The second conversion uses SEC_PER_HOUR, SEC_PER_MIN, and SEC_PER_DAY global constants that both functions can access them if necessary. If the functions use different constants, it makes sense to place all the conversion factors in one place.

Since the two functions divide the responsibilities in a way that they can be developed independently, the design is clean and easy to develop. The use of constants ensures that the shared values cannot be corrupted by either function.

The exclusion from a function's definition of global variables and global constants does not guarantee that it will always produce the same parameter value; consider

```
int compute(int n) {
    int favorite;
    cout << "Please enter your favorite number: ";
    cin >> favorite;
    return n + favorite;
}
```

The compute function avoids globals, yet we cannot yet predict the value of the expression compute(12). Recall the increment function from above:

```
int increment(int n) {
    return n + 1;
}
```

Its behavior is totally predictable. Furthermore, increment does not modify any global variables, meaning it cannot in influence the overall program's behavior. We say that increment is a pure function. A pure function cannot perform any input or output (for example, using the cout and cin objects), nor may it use global.
