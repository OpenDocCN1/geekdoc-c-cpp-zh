is thrown. This overhead is reasonable when exceptions are rare but not when exceptions are part of the program's normal execution.

Sometimes it is not clear when an exception is appropriate. Consider a function that returns the position of an element within a vector. The straightforward approach does not use exceptions could be written:

```
int find(const vector<int>& a, int elem) {
    int n = a.size();
    for (int i = 0; i < n; i++)
        if (list[i] == elem)
            return i; // Found it at position
    return -1; // Element not present
}
```

A return value of -1 indicates that the element is not present in the array. Should an exception be thrown if the element is not present? The following code illustrates:

```
int find(const vector<int>& a, int elem) {
    for (int i = 0; i < n; i++)
        if (list[i] == elem)
            return i; // Found it at position
    // Element not there; throw an exception
    throw ElementNotPresentException();
```

In the first approach, you may check the result and blindly use -1 as a valid position. The exception code would not allow this to happen. However, the first approach is useful for determining if an element is present in the vector. If find(x) returns -1, then x is not in the vector; otherwise, it is in the vector. If the exception approach is used, a client programmer cannot determine if an element is present without the risk of throwing an exception. Since exceptions should be rare, the second approach appears to be less than ideal. In,

+   - The first approach is more useful, but clients need to remember to check the result.
- The second approach provides an exception safety net, but an exception will be thrown when searching for missing elements.

Which approach is ultimately better? The first version uses a common programming idiom and is the better approach for most programming situations. The exception version is a poorer choice since it is not uncommon to attempt to look for an element missing from a vector; exceptions should be reserved for uncommon error situations.
