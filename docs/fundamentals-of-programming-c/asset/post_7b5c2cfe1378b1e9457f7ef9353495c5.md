
## 8.2. STANDARD MATH FUNCTIONS

![](img/e326304bd50fbc4f7d5a64c1487eb635_186_0.png)

Figure 8.4: Orbital distance problem

- 1. **Problem:** We recompute the location of the moving point as it moves along the circle.

**Solution:** Given an initial position $(x_1,y_1)$ of the moving point, a rotation of $\theta$ degrees around the origin will yield a new point at $(x_2,y_2)$, where

$x_2 = x_1\cos\theta - y_1\sin\theta$
$y_2 = x_1\sin\theta + y_1\cos\theta$

- 2. **Problem:** The distance between the moving point and the fixed point is recalculated as the moving point moves to a new position.

**Solution:** The distance $d_1$ in Figure 8.4 between two points $(p_x,p_y)$ and $(x_1,y_1)$ is given by the formula

$d_1 = \sqrt{(x_1-p_x)^2 + (y_1-p_y)^2}$

Similarly, the distance $d_2$ in Figure 8.4

$d_2 = \sqrt{(x_2-p_x)^2 + (y_2-p_y)^2}$

Listing 8.4 (orbitdist.cpp) these mathematical results to compute in the distances.

```cpp
Listing 8.4: orbitdist.cpp

#include <iostream>
#include <cmath>

using namespace std;

int main() {
    // Location of orbiting point is (x,y)
    double x;    // These values change as the
               // satellite moves
    double y;    //
    const double PI = 3.14159;

    // Location of fixed point is always (100, 0),
    // AKA (p_x, p_y). Change these as necessary.
    const double p_x = 100;
    const double p_y = 0;

    // Radians in 10 degrees
    const double radians = 10 * PI/180;

    // Precompute the cosine and sine of 10 degrees
    const double COS10 = cos(radians);
    const double SIN10 = sin(radians);

    // Get starting point from user
    cout << "Enter initial satellite coordinates (x,y):";
    cin >> x >> y;

    // Compute the initial distance
    double d1 = sqrt((p_x - x)*(p_x - x) + (p_y - y)*(p_y - y));

    // Let the satellite orbit 10 degrees
    double x_old = x; // Remember x's original value
    x = x + COS10 - y*SIN10; // Compute new value
    // x's value changed, but y's calculate depends on
    // x's original value, use x_old instead of x.
    y = x_old + SIN10 + y*COS10; // Corrected from y_old logic

    // Compute the new distance
    double d2 = sqrt((p_x - x)*(p_x - x) + (p_y - y)*(p_y - y));

    // Print the difference in distances
    cout << "Difference in distances: " << d2 - d1 << endl;

    return 0;
}
```

We use the square root to improve the efficiency of our programs. Instead of trying all the factors of n up to n-1, we only consider potential factors up to the square root of n. Listing 8.5: moreefficientprimes.cpp uses the sqrt function to reduce the number of factors that need to be considered.

```cpp
#include <iostream>
#include <cmath>

using namespace std;

int main() {
    int max_value;
    cout << "Display primes up to what value?";
    cin >> max_value;
    for (int value = 2; value <= max_value; value++) {
        // See if value is prime
        bool is_prime = true; // Provisionally, value is prime
        double r = value, root = sqrt(r);
        // Try all possible factors from 2 to the square
        // of value
        for (int trial_factor = 2; trial_factor <= root; trial_factor++) {
            if (value % trial_factor == 0) {
                is_prime = false;
                break;
            }
        }
        if (is_prime)
            cout << value << " "; // Display the prime number
    }
    cout << endl; // Move cursor down to next line
    return 0;
}
```

## 8.3. MAXIMUM AND MINIMUM

The sqrt function comes in three forms:

```cpp
double sqrt(double)
float sqrt(float)
long double sqrt(long double)
```

The function names are the same, but the parameters differ. We say that the sqrt function is overloaded. (Overloaded functions are covered in more detail in Section 10.3). When the caller passes a double parameter, the compiler selects the closest matching prototype. If the caller passes a float parameter, the compiler selects the float version. When an int is passed to sqrt, the compiler cannot decide which version to use, either to float, or long double. The caller needs some help to resolve the ambiguity, so we introduced a variable of type double the compiler will use the double version of the sqrt function. Another option is to use a type cast to convert the integer value into one of the types acceptable the sqrt function.

++ provides standard functions for determining the minimum and maximum of two numbers. Listing 8.6 (maxmin.cpp) exercises the standard max functions.

```cpp
Listing 8.6: maxmin.cpp
#include <iostream>
#include <algorithm>

using namespace std;

int main() {
    int value1, value2;
    cout << "Please enter two values: ";
    cin >> value1 >> value2;
    cout << "max = " << max(value1, value2) << endl;
    cout << ", min = " << min(value1, value2) << endl;
    return 0;
}
```

To use the standard max and min functions in programs you must use the <algorithm> header.

## 8.4. CLOCK FUNCTION

The clock function from the <ctime> library requests from the operating system the amount of time program has been running. The units returned by the call clock() is system dependent, but can be converted into seconds with the constant CLOCKS_PER_SEC, also defined in ctime library. Under C++, CLOCKS_PER_SEC constant is 1000, which means the call clock() returns the number of milliseconds that program has been running. Using two calls to the clock function can measure elapsed time. Listing 8.7 (time.cpp) measures how long it takes a user to enter a character from the keyboard.

```cpp
Listing 8.7: time.cpp
#include <iostream>
#include <ctime>

using namespace std;

int main() {
    char letter;
    cout << "Enter a character: ";
    clock_t seconds = clock(); // Record starting time
    cin >> letter;
    clock_t other = clock(); // Record ending time
    cout << static_cast<double>(other - seconds)/CLOCKS_PER_SEC
         << " seconds" << endl;
    return 0;
}
```

The clock_t is a type defined in the <ctime> header, equivalent to unsigned long, and you can perform arithmetic on clock_t values and variables as if they are unsigned. In the expression `static_cast<double>(other - seconds)/CLOCKS_PER_SEC`, the cast is required to force floating-point division; otherwise the result is truncated to an integer value. Listing 8.8 (measureprimes.cpp) measures how long it takes a program to display all the prime numbers up to half million using the algorithm from Listing 7.7 (forprimes.cpp).

```cpp
Listing 8.8: measureprimes.cpp
#include <iostream>
#include <ctime>
#include <cmath>

using namespace std;

// Display the prime numbers between 2 and 50000
int main() {
    clock_t start_time = clock(); // Record start time
    clock_t end_time;
    for (int value = 2; value <= 500000; value++) {
        // See if value is prime
        bool is_prime = true; // Provisionally,
        // Try all possible factors from 2 to n - 1
        for (int trial_factor = 2; trial_factor < value && is_prime; trial_factor++) {
            if (value % trial_factor == 0) {
                is_prime = false;
            }
        }
        if (is_prime) {
            cout << value << " "; // Display the prime number
        }
    }
    cout << endl; // Move cursor down to next line
    end_time = clock();
    // Print the elapsed time
    cout << "Elapsed time: "
        << static_cast<double>(end_time - start_time)/CLOCKS_PER_SEC
        << " sec." << endl;
    return 0;
}
```

On one system, the program took 93 seconds to run all the prime numbers up to 500,000. By comparison, the newer, more efficient version, Listing 8.5 (efficientprimes.cpp), which uses the square root optimization takes only 15 seconds to display all the primes up to 500,000. Exact times will vary depending on the power of the computer.

As it turns out, the program's execution time is taken by printing the output, not computing the prime numbers. We can compare the algorithms by redirecting the program's output to a file. If the executable is named primes.exe, you can redirect its output at the command line by issuing the command

```bash
primes > run.out
```

This creates a file named run.out that can be viewed with any text editor. Its contents are exactly what would have been printed to the screen if the redirection is not used.

When using redirection, the time difference is even more dramatic: The unoptimized version generates prime numbers up to 500,000 in 77 seconds, while the optimized square root version requires only 2 seconds to generate the same number of primes! An even faster prime generator can be found in Listing 8.12 (fasterprimes.cpp); it uses a completely different algorithm to generate prime numbers.

The ctime header must be #included to use the standard time function in a program.
