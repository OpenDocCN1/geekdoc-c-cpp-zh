# 10.5 Making Functions Reusable

A function definition packages one functionality that we can exercise (call) from many different places within a program. This far, however, we have not seen how we can easily function definitions in other programs. For example, our is_prime function in Listing 9.9 (primefunc.cpp) works well within Listing 9.9 (primefunc.cpp), and we could put it to use in other programs that need to test prim (encryption software, for example, makes easy use of prime numbers). We could use the copy-paste feature of our text editor to copy the is_prime function from Listing 9.9 (primefunc.cpp) into our new program we are developing.

It is possible to reuse a function in this way only if the function does not use any programmer-defined global variables, programmer-defined constants, other programmer-defined functions. If a function uses any of these programmer-defined external entities, they must be included for the function to compile. Thus another, the code in the function definition will use only local variables and parameters. Such a function is easily reused in multiple programs.

The notion of copying code from one program to another is not ideal, however, it is too easy for the code to be incomplete or for some other error to be introduced during the copy. Furthermore, code duplication is wasteful. If 100 programs on all need to use the is_prime function, under them they must all include the is_prime code. This redundancy wastes space. Finally, in the most compelling demonstration of the weakness of this copy-and-paste approach, if a bug is discovered in the is_prime function that all 100 programs are around? the other 99 programs will still contain their bug. The source code must be updated, and each then updated to be more efficient. The situation would be the same if a user were to define their own is_prime function; while the function definitions might be identical, there is no mechanism for tying these common definitions together. We would really like to reuse the function without copying it.

Fortunately, C++ provides a way to develop functions in separate files and combine the code from these independently developed functions into one program. We can compile the source files separately, and the linker can combine the code into an executable. What we need is for the compiler to verify that the calling code in one source file is correctly invoking the function defined in another source file.

10.9 provides the first step in making a reusable is_prime function.

Listing 10.9: prime.h
bool is_prime(int);

The simple-line code in 10.9 can be stored in a file named prime.h. In Visual Studio, you simply add a new item to your project as a header file named prime.h, and you are ready to type the line of code into the newly created file. This file contains the prototype for our is_prime function (see earlier discussion of function prototypes in Section 8.1). Caller calls the code so that compiler can check if the caller is using our is_prime function must #include this file to function properly. For an attempt, to pass two arguments to is_prime would result in a compiler error since the prototype accepts a single integer.
