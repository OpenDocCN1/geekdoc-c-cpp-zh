When a call to calc completes, the function clean up automatically releases the space held by the variable p. Because all functions automatically manage the memory for their parameters and local variables. The problem is p assigned new to memory allocated from the heap, not the stack. Execution functions manage the stack memory only. When the function’s execution completes, p is gone, and the memory to which p pointed is not deallocated automatically. Worse yet, the heap memory referenced by the local variable p now unreachable because no other variables remain anything about it.

+   * delete operator should never be used to free memory that was not allocated by a previous call to new. This code fragment illustrates one example:
```
int list(calc), *p = list; // p points to list
//
Do some stuff

delete [p]; // Logic error, attempt to deallocate p's memory
//
```

+   * delete must not be used to deallocate the memory more than once. This can happen when two pointers refer to the same memory. Such pointers are called aliases. The following code fragment illustrates situation:
```
int *p = new int[10], *q = p; // q aliases p
//
Do some stuff with p and/or q
//
//
```
