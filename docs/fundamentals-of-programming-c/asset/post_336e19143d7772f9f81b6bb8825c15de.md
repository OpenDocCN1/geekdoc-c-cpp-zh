## Developing C++ Programs with the GNU Tools

The tools provided by the GNU Compiler Collection (http://gcc.gnu.org), or GCC for short, include one of the most up-to-date standards compliant C++ compilers. The GNU tools are free and available for the major computing platforms:

- **Microsoft Windows XP-Windows 8.1**
Windows-based GCC tools can be found at the MinGW website http://www.mingw.org. The Nuwen site offers an easy to install custom distribution of MinGW with some additional C++ libraries.

- **Apple Macintosh OS X**
The MacPorts website (http://www.macports.org/ports.php?by=variant&substr=gcc48) brings the GCC toolkit to Mac developers.

- **Linux**
Linux-based GCC tools are readily available for all the major Linux distributions. To get them, simply install the g++ development packages.

In this appendix we focus on building C++ programs with the GCC C++ compiler. We will concentrate on the GCC tools, the code in this text is not specific GCC. The code herein aims to be C++ standards compliant and platform independent.

The name of the C++ compiler is g++. It is a command-line tool, which means it is launched from a command shell—CMD.EXE in Windows or bash in the Mac and Linux environments.

There are few commands that are essential for using the command-line environment. Our discussion assumes the Windows CMD.EXE shell, and we will note differences with Mac and Linux as needed. Mac OS X and Linux are both Unix-like operating systems.

When you run CMD.EXE in Windows, the Terminal application, or a bash terminal in Linux, the operating system presents a text-console window. You type commands into this window and receive feedback. Most of the commands are programs that you launch by typing their name. The following lists common commands for using the command-line GCC C++ tools:

- **dir**
When the command line interface starts locates you in a particular folder, or directory, in the file system managed by the operating system. Your location is known as the current working directory. The command dir prints a list of the files in your current working directory. On Unix-like machine the ls -l command performs similar. The command dir /w displays a wide listing of files with fewer details; the ls command is equivalent on Unix-like systems.

- **mkdir name**
Creates a new directory (folder) named name in the current directory. Subdirectories allow you to better organize your files.

- **cd name**
Changes your current directory to be specified by name. Some examples of its include:

- cd Code
Changes the current working directory to be the subdirectory named Code. Here the name is relative to the current directory. It is an error to provide a name that does not correspond to a subdirectory of the current directory.
- cd
Changes the current working directory to its parent directory. Said another way, the current working directory is itself a subdirectory of some other directory. This command makes this other (parent) directory the current working directory. .. ..
- cd C:\Users\Documents\Code
Changes the current working directory to the completely specified one. The name is known as a full-path; it is not relative to the current directory. Unix-like systems do not have a drive letter (C:), and backslashes (\) would be forward slashes (/).
- cd .
Changes the current directory to itself, which effectively does nothing! This command does not work. The dot (.) in this context means "current directory."

- **del name**
Deletes the file named name. Use this command carefully. Unix-like systems use the rm command in its place.

- **rename name**
Renames the file to name. The move command does the same thing, and Unix-like systems use the mv command to rename files.

In preparation for our programming, we can create a new directory for our code with the commands:

```
mkdir Code
```

We can edit our source code with a simple text editor as Notepad for Windows, TextEdit on the Mac, or gEdit on Linux. More programming editors such as Notepad++ (http://notepad-plus.net) (Windows) and Vim (http://www.vim.org) (Windows, Mac, and Linux) making source code more convenient.

To see how the GNU C++ build system works, we will use an editor to create a text file containing the code for Listing 2.1 (simple.cpp), and save the file simple.cpp. In Windows, notepad++ is installed and set up properly, in the command shell you can type:

```
notepad++ simple.cpp
```

We can type the source code for Listing 2.1 (simple.cpp) and save the file. To create the executable program by GNU C++, in our command-line we issue the command:

```
g++ -Wall -std=c++11 -o simple simple.cpp
```

This command has five parts:

- g++ invokes the GCC C++ build process.
- g++ invokes the GCC C++ build process. This command runs the preprocessor, followed by the compiler, and finally the linker to produce the executable program. Even though the preprocessor and linker are also involved, we generally say we are "compiling the code."
- Wall stands for "warn" and directs the compiler to be very strict when it is compiling the source code. It goes beyond checking that the program is well-formed it also warns about code structures that many programmers consider questionable because The component can be interpreted to mean "warn about as many possible problems". It enables the compiler to catch many common mistakes that might otherwise go unnoticed. The Wall directive is for all C++ programmers from novice to expert.

> The C++ standards committee is responsible for defining the C++ language. The committee defines the language specification over time. In addition adding new features to the language, the committee also addresses shortcomings. As a result of the committee's newer compilers can check thoroughly the validity of C++ programs. Modern compilers do a better job of catching common programming errors.

The Wall directive is optional sometimes developers must work with older C++ code. The code was originally written under more relaxed C++ language rules, but it may not be worthy to rewrite the code to bring it to modern standards. If this older code has been proven to be reliable, it may be compiled without the more stringent checks. All new code, however, should advantage of the newer, better checking capabilities of the most-to-date C++ compiler; therefore, always use -Wall on the compiler line that you write.

The -std=c++11 option directs the compiler to process the C++ source code according to the rules of the C++11 standard which the International Standards Organization (ISO) adopted in 2011. This standard is relatively new, if you omit this part of the command, g++ assumes the programmer is writing the source code under the rules of the older, 1998 ISO C++ standard, usually referred to as C98.

The code in this book is based on the C++11 standard.

The -o part of the command specifies the name of the executable program. The desired name appears after the -o part, so our executable program will be named simple.exe on Windows systems. On Mac and Linux platforms the name of the executable produced will be just simple (no .exe extension). If the C++ source code contains no errors, the compiler will produce the executable file named simple.exe (or simple). On a Windows Machine we can run the compiled program from the command line by typing

# simple

(We can also use the full name, simple.exe). On a Unix-like system (OS X or Linux), we instead would

# .simple

to execute the program.

- -o simple.simple.cpp
-o part of the command specifies the name of the C++ source file we wish to compile. Here the file simple.cpp must reside in your current working directory for the compiler to process it.
