# 18.1. FUNCTION TEMPLATES

```
// Compare them // <-- Error!
if (less_than(fout1, fout2)) // <-- Error!
    cout << "fout1 is less than fout2" << endl;
```

The expression less_than(fout1, fout2) is illegal because no operator exists to compare two
::ostream objects; the compiler does not produce the machine language that represents
a expression < b when a and b are ofstream. Ultimately, the compiler cannot instantiate
a all_than function that accepts ofstream objects.

When programmers use incorrectly or construct incorrect template functions or classes, the
compiler can detect and report the problems. All C++ compilers share one weakness with template
programming: poor human-readable error messages. The error messages the compiler produces in
situations tend to be difficult and difficult to decipher even for experienced C++ programmers. This is
because the compiler bases its error on the instantiated code. Since programmers see only the un-instantiated code, deciphering the compiler's
template errors tends to be more challenging than usual.

As Listing 18.4 (templatescale.cpp) shows, a template can accept non-type parameters.

Listing 18.4: templatescale.cpp
#include <iostream>
using namespace std;

template <int N>
int scale(int value) {
    return value * N;
}

int main() {
    cout << scale<3>(5) << endl;
    cout << scale<4>(10) << endl;
}

Note that in Listing 18.4 (templatescale.cpp) the typename keyword is missing, and in its place is
actual type int. This means parameter N is a non-type template parameter. The program prints

![](bbox=[0.176, 0.665, 0.823, 0.725])

Listing 18.5 (templatescale2.cpp) uses both a type-parameter and a non-type parameter.

Listing 18.5: templatescale2.cpp
#include <iostream>
using namespace std;

template <typename T, int N>
T scale(const T value) {
    return value * N;
}
