Notice that, in the original version of linear search, the search will terminate early when it encounters an element larger than the sought element. Since the vector is sorted, there is no need to continue the search once you have been seeing elements larger than your value: seek cannot appear after a larger element in a sorted vector.

Suppose to search in elements. In the case—looking for an element larger than any currently in the vector—linear search takes n iterations. In the case of an element smaller than any other elements—binary search returns immediately without considering others. The number of iterations thus ranges from i to n, and on average linear search requires comparisons before the loop finishes and returns.

Now consider binary search of a vector that n elements. After each comparison the size of the vector left to consider is half-one. If the sought element is not found on the first probe, the number of remaining elements to consider is half-one of n. After the next iteration through the loop, the search drops to half-one of n. This process of searching the space in half continues each time until the process locates the sought element or runs out of elements to consider. The problem of determining how many times a set of things can be divided in half until only one remains can be solved with a base-2 logarithm. For binary search, the worst case scenario of not finding the sought element requires the loop to make log2 n iterations.

How does this analysis help us determine which search is better? The quality of an algorithm is judged by two key characteristics:

+   * How much time (processor cycles) does it take to run?
* How much space (memory) does it take to run?

In our situation, both search algorithms process the sequence with only a few local variables, so for large sequences they both require essentially the same space. The difference here is speed. Binary search performs more elaborate calculations each time the loop, and each operation takes time, so perhaps binary search is slower (fewer operations through the loop), but perhaps executes many more times than the loop in binary search, so it is slower.

We can deduce the faster algorithm in two ways: empirically and analytically. An empirical test is an experiment; we implement both and measure their execution time. The analytical approach analyzes the source code to determine how many operations the computer's processor must perform to run the loop on a problem of a particular size.
