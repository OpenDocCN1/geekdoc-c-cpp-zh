A for loop is ideal for stepping through rows and columns. The information about the control of both loops is packaged in the for statement instead of being spread out in various places in main. While the while loop, it is easy for the programmer to forget one or both of the control variables (row and column). The for makes it harder for the programmer to forget the loop variable update, since it is done right up front in the for statement.

It is considered good practice to do the following in a for statement:

- Modify the loop variable within the body of the loop--if the loop variable is modified within the body, the logic of the control is no longer completely isolated to the for header. The programmer must look closely within the statement to understand completely how the loop works.
- Prematurely exit the loop with a break--this action also violates keeping all the loop logic in one place (the for's header).

The language allows both of these practices, but experience shows that it is best to avoid them. If it seems necessary to validate this advice, consider a different kind of loop. The while and do-while loops do not implement the same degree of control regularly as a for loop.

While the for statement supports some complex headers, simpler is usually better. The for loop should manage just one control variable, and the initialization, condition, and modification parts should be straightforward. If particular programming situation warrants an overly complicated for construction, consider another kind of loop.

Any or all parts of the for may be omitted:

- Initialization. If the initialization is missing, as in
    for (; i < 10; i++)
    /* Body goes here */
then no initialization is performed.

- Condition. If the condition is missing, as in
    for (int i = 0; ; i++)
    /* Body goes here */
then the condition is true by default.

- Modification. If the modification is missing, as in
    for (int i = 0; i < 10; ;)
    /* Body goes here */
then no automatic modification.

- Body. An empty body,
```cpp
for (int i = 0; i < 10; i++) {
```

or

```cpp
for (int i = 0; i < 10; i++)
```

results in an empty loop. Some programmers use empty loop to produce a non-portable delay. Such an attempt using empty loop is non-portable for several reasons. If the program executes the loop, slower computers will delay longer than faster computers. The timing of the program's delay will differ from one computer to another. Worse yet, some compilers may detect that such code has no functional effect and optimize the empty loop.

> As mentioned in Section 5.3, be careful about accidentally putting a semicolon at the end of for header, as in
for (int i = 0; i < 10; i++);
/* Intended body goes here */
The semicolon terminates the for statement, and the intended body that follows is not the body, even if it properly indented.

One common C/++ idiom to make an infinite loop is to use a for statement with all control information:

```cpp
for ( ; );
/* Body goes here */
```

Omitting all parts of the for is a statement that the programmer says "I know what I am doing—I want an infinite loop." In reality the loop may not be infinite at all; its body could contain a break or goto statement.
