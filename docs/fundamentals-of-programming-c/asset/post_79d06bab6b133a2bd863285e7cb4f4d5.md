```

```

In the expression $e_1 \&\& e_2$ both $e_1$ and $e_2$ must be true for the overall expression to be true. Since the $&&$ operator evaluates expressions from left to right, this means that if $e_1$ is false, there is no need to evaluate $e_2$. If $e_1$ is false, no value $e_2$ can make $e_1 \&\& e_2$ true. The logical and operator tests the expression to its left. If it finds the expression to be false, it does not bother to check the right expression. This approach is called short-circuit evaluation. In a similar fashion, in the expression $e_1 ||_2$, if $e_1$ is true, then the expression is true unless both subexpressions to its left are false. The $|||$ operator uses short-circuit evaluation also.

Why is short-circuit evaluation important? Two situations show why it is important to consider:

- The order of the subexpressions can affect performance. When a program is running, complex expressions require more time for the computer to evaluate than simpler expressions. We classify an expression that takes a relatively long time to evaluate as an expensive expression. If a compound Boolean expression is made up of an expensive Boolean subexpression and an less expensive Boolean subexpression, the order of evaluation of the two expressions does not affect the behavior of the program, then place the more expensive Boolean expression first. If the first subexpression is false and $&&$ is being used, then the expensive subexpression is not evaluated; if the first subexpression is true and $|||$ is being used, then again, the expensive subexpression is avoided.

- Subexpressions can be ordered to prevent run-time errors. This is especially true when one of the subexpressions involves division. Consider the following expression:

```
(x != 0) && (z/x > 1)
```

Here, if $x$ is zero, the division by zero is avoided. If the subexpressions were switched, a run-time error would result if $x$ is zero.

## 5.7 Nested Conditionals

The statements in the body of the if or the else may be any C++ statements, including other if/else statements. We can nest if statements to build arbitrarily complex control flow logic. Consider Listing 5.6 (checkrange.cpp) that determines if a number is between 0 and 10, inclusive.

```
Listing 5.6: checkrange.cpp
#include <iostream>
using namespace std;

int main() {
    int value;
    cout << "Please enter an integer value in the range 0..10: ";
    cin >> value;
    if (value >= 0) // First check
        if (value <= 10) // Second check
            cout << "In range";
    cout << "Done" << endl;
}
```

Listing 5.6 (checkrange.cpp) behaves as follows:

- The program checks the value >= 0 condition. If value is less than zero, the executing program does not evaluate the second condition and does not print In range, it immediately executes the outer statement if which prints Done.
- If the executing finds value to be greater than or equal to zero, it checks the second condition. If the condition is met, it displays the In range message; otherwise, it is not. Regardless, the program Done before it terminates.

For the program to display the In range both of this nested if must be met. Said another way, the first condition and the second condition must be met for the In range message to be printed. From this perspective, we can rewrite the program to behave with way only one if statement, as Listing 5.7 (newcheck.cpp) shows.

## Listing 5.7:newcheck.cpp

```
#include <iostream>

    int value;
    cout << "Please enter an integer value in the range 0..10: ";
    cin >> value;
    if (value >= 0 && value <= 10)
        cout << "In range";
    cout << "Done" << endl;
}
```

Listing 5.7 (newcheck.cpp) uses a logical && to check both conditions at the same time. Its logic is simpler, using only one if statement, at the expense of a slightly more complex Boolean expression in its condition. The second version is preferable here because simple logic is a desirable goal.
