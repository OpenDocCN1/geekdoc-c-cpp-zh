

## 10.9. HIGHER-ORDER FUNCTIONS

```
swap(var1, var2);
```

does not require any special decoration. It looks like a normal pass by value function invocation. A programmer must be aware that swap reference parameters and any function that uses reference parameters can change the actual values passed to it.

Reference parameters were introduced in C++ so that some of the more advanced object-oriented features could be implemented more cleanly. Some argue that for simpler situations like the swap function, pointer pass is less desirable than reference pass because pass by pointer pass the caller is forced to looking inside of the function and seeing the actual parameters may be modified. In this way there can be no doubt that pass is going on. With reference parameters, pass by value pass cannot be denied at the call site, since a call with reference parameters looks exactly like a value invocation.

In general, pass by value functions are preferred to reference parameters. Functions using side effects can change the state of the program in ways that cannot be understood only by looking inside the function and seeing how it works. Functions that access global variables (see Section 10.1) can cause side effects. Development is much easier when functions can be treated as black boxes that perform computations without the possibility of affecting anything outside of their local context. The result of a function's work can be assigned to a variable thus changing the state of the program, but that change is the responsibility of the caller, not the responsibility of the function. With pass by value, the function's parameters and local variables come into existence when the function executes, and local variables disappear when the function is finished, and nothing is erased by the function's execution.

Side-effect-free functions can be developed in isolation from the rest of the program. Once programmers are satisfied with their correctness, they need not be touched again as the remainder of the system is developed. Functions with side effects, however, have dependencies to other parts of the program.

The functions can do different things based on the data they receive. The code within each function, however, is fixed at compile time. Consider the following function:

```cpp
int evaluate(int x, int y) {
  return x + y;
}
```

The call

```
evaluate(10, 2);
```

evaluates to 12. Since the evaluate function returns the sum of its two parameters. The call

```
evaluate(-4, 6);
```

returns 2. The function returns a different result this time because we passed parameters to it. The evaluate function in a sense behaves differently than the arguments passed by its caller; however, it always adds its two parameters. There is no way we can call evaluate and expect it to multiply its two parameters instead. The evaluate function is hard-coded to perform addition.

What if we wanted the evaluate function to perform arithmetic operations at different times during a program's execution? Unfortunately, evaluate as it is currently written cannot adapt to a different arithmetic operation. The good news is that we can rewrite evaluate so that it can flexibly adapt to a caller's changing needs.

C++ allows programmers to pass functions as parameters to other functions. A function that accepts one or more functions as parameters or returns a function is known as a higher-order function. As we will see, higher-order functions enable us new programming possibilities to customize the behavior of a function by plugging into it different functions to achieve different effects.

C++ achieves higher-order functions via pointers. During a program's execution, the compiled machine code for a function must reside in the computer's memory for the program to be able to invoke it. Every function has a memory address as each variable has its own memory address. A pointer to a function holds the starting address for the compiled code of a particular function.

Listing 10.19 (arithmeticeval.cpp) provides an example of a higher-order function in action.

```cpp
#include <iostream>

using namespace std;

int add(int x, int y) {
    return x + y;
}

int multiply(int x, int y) {
    return x * y;
}

int evaluate(int (*f)(int, int), int x, int y) {
    return f(x, y);
}

int main() {
    cout << add(2, 3) << endl;
    cout << multiply(2, 3) << endl;
    cout << evaluate(&add, 2, 3) << endl;
    cout << evaluate(&multiply, 2, 3) << endl;
}
```

The first parameter of the evaluate function is a function pointer. In Listing 10.19 (arithmeticeval.cpp), the first parameter a caller must pass to evaluate is the address of a function with a prototype that matches the formal parameter specified in evaluate's definition. Both the add and multiply functions qualify because they accept two integer parameters and return an integer result. The expression

```
evaluate(&add, 2, 3)
```

passes the address of the add function to evaluate. In the body of the evaluate function we see that evaluate invokes the function specified by its first parameter (f), passing to this function its second (x) and third (y) parameters as the two parameters function. The net effect, therefore, of the call

```
evaluate(&add, 2, 3)
```

is the same as

```
add(2, 3)
```

C++ has a somewhat relaxed syntax for function pointers.

## 10.10. SUMMARY

- A pointer is a variable that holds a memory address.
- A pointer to a function holds the starting address for the compiled code of a particular function.
- Higher-order functions are functions that accept one or more functions as parameters or return a function.
- C++ achieves higher-order functions via pointers.
- Pass by value is generally preferred to reference parameters to avoid side effects.
- Side-effect-free functions are easier to develop and maintain.
- Static variables persist for the duration of the program, unlike local variables.
