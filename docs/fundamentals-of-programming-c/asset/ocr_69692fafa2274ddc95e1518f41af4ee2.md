These private methods are called helper methods or auxiliary methods.

Why would programmer intentionally choose to access parts of an object? Restricting access obviously limits the client' control over the objects it creates. This may appear to be a disadvantage at first glance, this access restriction provides a number of advantages:

+   - Flexibility in implementation. A class conceptually can be separated into two parts:

+   - The interface—the public part. Clients see and use the public parts of an object. The public methods and variables of a class constitute the interface of the class. The class's interface specifies what it does.

+   - The implementation—the hidden part. Clients cannot see any private methods or variables. Since this private information is invisible to clients, class developers are free to do whatever they want with the private parts of the class. A class's implementation specifies how it accomplishes what it needs to do.

We would like objects to be black boxes: clients shouldn't need to know how the objects work but merely rely on what objects do.

> A good rule of thumb in class design is: make data private, and make methods that provide a service to clients public.
