# 15.4. SEPARATING METHOD DECLARATIONS AND DEFINITIONS

```
Point(double x, double y): x(x), y(y)
double get_x() const { return x; }
double get_y() const { return y; }
void set_x(double x) { x = x; }
void set_y(double y) { y = y; }
;
```

could be split up into the declaration:

```
class Point {
    double x;
    double y;
public:
    Point(double x, double y); // No constructor implementation
    double get_x() const; // and no method
    double get_y() const; // implementations
    void set_x(double x);
    void set_y(double y);
}
```

and method implementations:

```
// constructor
Point::Point(double x, double y) : x(x), y(y) {}

// Get the x value
double Point::get_x() const {
    return x;
}

// Get the y value
double Point::get_y() const {
    return y;
}

// Set the x value
void Point::set_x(double x) {
    x = x;
}

// Set the y value
void Point::set_y(double y) {
    y = y;
}
```

The class name prefix as Point:: is necessary not only so a method definition as get_x can be distinguished from a global function, but also to distinguish it from a different class that contains a method with the same name and parameters. A method signature for it is just like a global function signature, except a method signature includes the class name as well. Each of the following represent distinct signatures:

+   * get_x() is the signature for a global function named get_x that accepts no parameters.
