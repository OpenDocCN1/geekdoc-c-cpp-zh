
## 18.1. FUNCTION TEMPLATES

```cpp
/*
 * less_than(a, b)
 * Returns true if a < b; otherwise, returns
 * false.
 */
template template <typename T>
bool less_than(T a, T b) {
    return a < b;
}

int main() {
    cout << less_than(2, 3) << endl;
    cout << less_than(2.2, 2.7) << endl;
    cout << less_than(2.7, 2.2) << endl;

    string word1 = "ABC", word2 = "XYZ";
    cout << less_than(word1, word2) << endl;
    cout << less_than(word2, word1) << endl;
}
```

In the **less_than <typename T>** function definition:

```cpp
template <typename T>
bool less_than(T a, T b) {
    return a < b;
}
```

**template** and **typename** are reserved words, and **T** is a *type parameter*. The **template** keyword indicates that the function definition follows is not a normal function but rather a pattern or template from which the compiler can produce the correct function. A function is also known as a *generic function*. The **typename** keyword indicates that the identifier that follows (in this case **T**) is a placeholder for a C++ type name. **T** stands for an actual type to be determined. It is an identifier and can have any name legal for a variable, function, or class; some programmers use more descriptive names such as **CompareType** or **TypeParam**. Single capital letters like **T** and **U** are popular type parameter names among C++ programmers. Just as a regular parameter of a function or method represents a value, a template parameter represents a type.

You may use reserved word **class** interchangeably with the keyword **typename** in this context:

```cpp
template <class T>
bool less_than(T a, T b) {
    return a < b;
}
```

In Listing 18.2 (templatelessthan.cpp) the compiler generates three different less_than functions: one that accepts two integers, one that accepts double-precision floating-point values, and one that accepts three objects. Although the programmer cannot see them in the source code, the compiler in effect creates the following literal function definitions:

```cpp
bool less_than(int a, int b) {
    return a < b;
}

bool less_than(double a, double b) {
    return a < b;
}

bool less_than(string a, string b) {
    return a < b;
}
```

When the compiler generates an actual function definition from a template function, the process is called template instantiation, not to be confused with an instantiation from a class.

The compiler instances functions only as needed. If Listing 18.2 (templatelessthan.cpp) did not contain the std::string objects, then processing the source code would not instantiate the version of less_than that accepts two std::string objects.

For efficiency, the best way to write less_than

```cpp
template <typename T>
bool less_than(const T& a, const T& b) {
    return a < b;
}
```

Notice that a and b are passed by reference, not by value. This means the caller passes only the addresses of objects a and b and does not need to make copies to send to the function. This can make a big difference if T represents large objects. Since the parameters are const, the function cannot change the state of the caller's parameters; therefore, the function offers call-by-value safety without the overhead of copying parameters.

A caller attempts a statement such as

```cpp
cout << less_than(2, 2.2) << endl;
```

the compiler generates an error. This is because template definition specifies that its two parameters are identical. The literal 2 is an int and the literal 2.2 is a double. The compiler can automatically instantiate less_than functions that accept two ints or two doubles but not mixed types. In the expression

```cpp
less_than(2, 2.2)
```

the compiler cannot know which instantiated version of the template to call.

One solution requires the programmer to explicitly instantiate the function as shown here:

```cpp
cout << less_than<int>(2, 2.2) << endl;
```

This forces the compiler to instantiate and call the integer version. The compiler will issue a warning about truncating 2.2. The statement

```cpp
cout << less_than<double>(2, 2.2) << endl;
```

would use the double-precision floating-point value of less_than, and it compiles cleanly with no warnings seeing the int 2 to a double is automatic.

We can rewrite the less_than template function to avoid the need for explicit instantiation. For most flexibility, we can express the less_than template function as

```cpp
template <typename T, typename V>
bool less_than(const T& a, const V& b) {
  return a < b;
}
```
