
## Lemma 13.3

```
|- forall p x k s C. (1 < k) /\ (0 < q < 1)
=> (lim (\An. real (Cn_wsn p x k s C n q)) = 1)
```

where (lim (\An. f n)) returns the value of the sequence f when n becomes very large.
Lemma 13.1 can be used to deduce useful results for the given WSN application.
Hence, suppose that a network coverage intensity of at least 70% is targeted, then
the lower bound on the number of required nodes n is verified:

## Lemma 13.4

```
|- forall p x k s C n. (1 <= n) /\ (1 < k) /\ (Normal (0.7) <= Cn_wsn_first p x k s C n)
=> ln (1-0.7) / (ln (1 - 0.003/k)) <= \<delta>.
```

For example, we can deduce that under the randomized scheduling that organizes
the network into k = 4 sub-networks, at least 1606 nodes are required to be deployed
over the forest area in order to achieve a network coverage intensity of 70%.

In addition, we established, in Lemmas 13.2 and 13.3, that any network coverage
intensity Cn_wsn can be achieved by increasing the number of deployed nodes n,
for any values of the input variables k, s and q. These results can be easily verified
for the network coverage intensity, cn_wsn_first, in the context of the given forest
fire application (Lemmas 13.5 and 13.6).

## Lemma 13.5

```
|- forall p x k s C. (1 < k) =>
(mono_incr (\An. real (cn_wsn_first p x k s C (SUC n)))).
```

## Lemma 13.6

```
|- forall p x k s C. (1 < k) =>
(lim (\An. real (Cn_wsn_first p x k s C n)) = 1).
```

According to Lemmas 13.2 and 13.3, enhancing the coverage capacities of the
deployed WSN, is generally possible through the deployment of more nodes. Nevertheless,
after the initial deployment phase, the number of sensor nodes becomes
known and fixed. Moreover, a second deployment can be very costly in the context
of inhospitable fields like forests, since nodes are generally deployed by throwing
them from an airplane. Based on the parameter k, we perform now an interesting
study of the limiting behavior of the coverage performances. First, we formally
deduce that for a given n and a network coverage intensity of at least t, the upper
bound on the number of disjoint subsets k is given as follows:

## Lemma 13.7

```
⊢ ∀ p x k s C n q. (1 ≤ n) ∧ (1 < k) ∧ (0 < q < 1) ∧ (0 < t < 1) ∧ (Normal t ≤ (Cn_wsn p x k s C n q)) ⇒ k ≤ q / (1 - e ^ (ln (-t(1))/(sn)))
```

This result formally confirms the general intuition about the randomized scheduling approach. Increasing k saves energy, but leads to several sub-networks, which in turns translates to a worse network coverage intensity Cn_wsn. This can decrease the performance of the whole network, which makes the accuracy in the probabilistic analysis of the value of k very important after the deployment.

## Lemma 13.8

```
⊢ ∀ p x s C n q. (1 ≤ n) ∧ (0 < q < 1) ⇒ (mono_decr (∀k. real (Cn_wsn p x (SUC (SUC k)) s C n q))).
```

where the HOL function mono_decr defines a decreasing sequence as follows:

## Definition 13.14

```
⊢ ∀ f. mono_decr f = f (SUC n) ≤ f n.
```

Also, we formally confirm, in Lemma 13.9, that given a number of nodes n, the network coverage intensity Cn_wsn goes to 0 when k becomes very large. In other words, the network coverage intensity Cn_wsn decreases when the WSN is organized into a quite large number of sub-networks k.

## Lemma 13.9

```
⊢ ∀ p x s C n. (1 ≤ n) ∧ (0 < q < 1) ⇒ (lim (∀k. real (Cn_wsn p X k s C n q)) = 0).
```

The above lemma has been successfully verified in HOL using intermediate results associated to real and sequential limits. The above three Lemmas clearly demonstrate the impact of the k-value on the probabilistic coverage of the network. Regarding our application, it is possible to confirm the validity of the generic results given in Lemmas 13.7, 13.8 and 13.9. We thus formally verify, in Lemma 13.10, that in order to enhance the network coverage intensity from 70% to 90% the value of k has to be updated to 2, but it should not exceed 2 for a given n:

## Lemma 13.10

```
⊢ ∀ p x s k C n. (1 ≤ n) ∧ (1 < k) ∧ (Normal 0.9 ≤ (Cn_wsn_first p X k s C n)) ⇒ k ≤ 0.003 / (1 - e^(ln ((1-0.9)/(sn))))
```

Within the deployed WSN, the adjustment of the value of k is done by message flooding which informs all nodes about the new value. Consequently, for our forest fire detection application, increasing k surely saves more energy, a significant increase in k may lead to several sub-networks, which in turns translates to a poor network coverage intensity Cn_wsn.

## Lemma 13.11

```
⊢ ∀ p x s C n. (1 ≤ n) ⇒ (mono_decr (λ k. real (cn_wsn_first p X (SUC (SUC k)) s C n))).
```

In addition, we reconfirm the result of Lemma 13.9 using Lemma 13.12, i.e., increasing the number of deployed nodes n gives smaller network coverage and thus a poor performance of the deployed application:

## Lemma 13.12

```
⊢ ∀ p x s C n. (1 ≤ n) ⇒ (lim (λ k. real (cn_wsn_first p x k s C n)) = 0).
```

The randomized scheduling is thus a dynamic approach, which provides performance adjustments of the deployed WSN application according to the value of k.

The randomness in the nodes scheduling approach leads to sub-networks of different sizes with respect to the number of nodes. Obviously, the ideal case arises when the algorithm makes a fair split of the network so that all the subsets have the same size, i.e., the same number of nodes, which we denote by m. The number of nodes n can be written hence as k * m. In what follows, we closely investigate the asymptotic performance behavior of the k-set randomized algorithm regarding coverage in the case of a uniform split of the nodes.

In particular, we successfully verify, in Lemma 13.13, the upper limit of the network coverage Cn_wsn when n = k * m and k goes to infinity:

## Lemma 13.13

```
⊢ ∀ p x s C q. (0 < q < 1) ∧ (∀ k m. sn_covers p x p q (m * k)) ⇒ lim (λ k. real (Cn_wsn p x k s C (m*k))) = 1 - e^(-q*(sn))
```

The proof of Lemma 13.13 required the important mathematical result lim (1 + x/k)^k = e^1, which had to be proved in HOL beforehand.

Based on Lemma 13.13, we can hence verify that when m becomes very large, the uniform network coverage will surely approach 1. Such result is considered as a second verification of Lemma 13.3 in the specific case where n = k * m.

## Lemma 13.14

```
⊢ ∀ X p q. (0 < q < 1) ∧ (∀ k. sn_covers p X p q (m * k)) ⇒ lim (λ m. lim (λ k. real (Cn_wsn p X k s C (m*k) q)) = 1).
```

Finally, we show that the above-mentioned two results are also valuable for the given forest fire detection application through a simple instantiation of the input parameter q by its value. The corresponding HOL analysis is given in the following 2 lemmas.

## Lemma 13.15

```
⊢ ∀ p X s C. (∀ k m. sn_covers p X p (0.003) (m * k)) ⇒ lim (λ k. real (Cn_wsn_first p X k s C (m*k))) = 1 - e^(-0.003)*(sn)
```

## Lemma 13.16

```
⊢ ∀ X p. (∀ k. sn_covers p X p (0.003) (m * k)) ⇒ lim (λ m. lim (λ k. real (Cn_wsn_first p X k s C (m*k))) = 1).
```

The main motivation of the current work is to provide an accurate approach for the probabilistic performance evaluation of the k-set randomized scheduling algorithm for wireless sensor networks. Indeed, due to the inherent randomness of the studied scheduling approach coupled with the random deployment of nodes, the analysis of such algorithm becomes very challenging for all possible cases. Rigorous performance evaluation of such algorithm is hence a non-trivial task, especially given the non-exhaustive nature of classical performance analysis techniques. This chapter presents a higher-order-logic theorem prover based approach for the formalization of the k-set randomized scheduling within the sound core of the HOL theorem prover. In Section 13.3, we have been able to formally develop the foundational formalisms of the k-set randomized scheduling algorithm, upon which we have built accurate formalizations of the network coverage intensity. The practical usefulness of our approach is shown, in Section 13.4, to analyze a WSN for forest fire detection, using the k-set randomized scheduling algorithm. Due to the undecidable nature of higher-order logic, the HOL development consumed about 730 lines of code. On the other hand, the formal analysis of our application took only 200 lines of HOL code
