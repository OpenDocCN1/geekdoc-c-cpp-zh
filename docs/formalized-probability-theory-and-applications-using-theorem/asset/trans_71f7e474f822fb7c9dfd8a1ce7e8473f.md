

从自动定理证明用户的角度来看，形式化验证可以通过使用可用逻辑（即命题逻辑或一阶逻辑）为待验证系统开发形式化模型来完成。下一步是为给定系统形式化指定需要验证的属性。然后可以使用自动验证工具（如SMT求解器）来验证该属性。因此，在系统分析中使用自动定理证明的主要挑战在于系统模型和属性的形式化指定。

在系统分析中，我们经常会遇到模拟电路或光学系统等系统，其行为只能用涉及集合、实数等更一般的数学来描述。如前所述，一阶逻辑无法用于建模这类系统，因此我们必须使用高阶逻辑（Gordon, 1989）和交互式定理证明，其中用户与机器一起参与形式化验证过程。爱丁堡LCF（可计算函数逻辑）（Gordon, 1989）是开发交互式定理证明器最常用的方法之一。LCF风格的定理证明器是使用强类型函数式编程语言ML（元语言）（Paulson, 1996）或其变体实现的。ML抽象数据类型用于表示高阶逻辑定理，与定理证明器交互的唯一方式是执行对这些数据类型值进行操作的ML过程。交互式定理证明器通常包含许多自动证明助手和自动证明过程，以协助用户进行验证过程。用户与证明编辑器交互，并为其提供证明目标所需的策略，同时在问题归约为可判定子集时使用自动证明过程。这个过程可能非常繁琐，通常需要数千行证明脚本和数百个工时，才能验证用纸笔证明方法呈现的几页数学分析。然而，能够基于已验证结果进行构建是交互式定理证明的一大优势。

为说明问题，考虑一个返回实数数组最小值的算法的形式化验证。由于涉及实数和任意数量的元素，验证采用高阶逻辑定理证明。分析该算法的第一步是在高阶逻辑中对其进行形式化。这主要可以通过以下递归定义完成：

```
⊢ ∀ x. min_list [] (x: real) = x ∧
∀ h t x. min_list (h:: t) x = minimum (min_list t h) x
```

其中函数minimum接受两个实数并返回其中较小的一个，符号::表示数组头部和尾部之间的cons操作。该函数递归地查找实数列表和另一个实数x中的最小实数。

算法形式化之后的下一步是在定理证明器中将感兴趣的属性形式化为证明目标。以下属性用于此目的：

```
⊢ ∀ (L: real list) x. MEM x L ⇒ min_list (TL (L)) (HD L) ≤ x
```

谓词MEM x L确保x是列表L的成员，函数HD和TL分别返回其列表参数的头部和尾部。因此，该目标保证函数min_list返回的值小于或等于列表L中的所有值。现在可以在定理证明器中使用对变量L的归纳来验证该定理。其余推理基于上述实数和列表的定义和属性。上述分析的主要优势在于其通用性，这从对变量L和x使用“全称”量词中显而易见，并且准确性有保证，基于定理证明器固有的可靠性。然而，缺点是形式化涉及对高阶逻辑以及实数和列表理论的理解。此外，验证需要人工指导，并且是交互式进行的。

对于概率分析，我们需要将随机变量形式化为函数，并通过对随机变量进行量化来形式化随机变量的特征，例如CDF和期望等（Hasan, 2008）。因此，一阶逻辑不支持这种形式化，我们需要使用高阶逻辑来形式化概率分析。在这方面的第一步是在高阶逻辑中建模需要分析的系统的行为，同时用形式化随机变量来表达其随机或不可预测的元素。第二步是使用这个形式化模型在高阶逻辑中表达关于系统的概率和统计属性。最后，系统模型的这些概率和统计属性可以在定理证明器中机械地检查其正确性。基于这些原则，概率论及其相关数学基础的形式化推理支持已在各种高阶逻辑定理证明器中开发，包括HOL4（HOL4, 2015）、Isabelle/HOL（Isabelle/HOL, 2015）和PVS（PVS, 2015）。

上述基于定理证明的概率分析方法克服了基于仿真和模型检查的概率分析方法的局限性。由于模型和属性的形式化性质以及定理证明方法固有的可靠性，以这种方式进行的概率分析将不存在任何近似和精度问题。同样，高阶逻辑的高表达能力使我们能够在没有建模限制的情况下分析更广泛的系统，例如概率模型检查中的状态空间爆炸问题，并形式化验证分析上复杂的属性，例如期望、方差和尾分布界。此外，使用机械定理证明器将增加对传统纸笔方法的证明信心。鑒于使用高阶逻辑定理证明进行概率分析的这些好处，本手稿的主要范围是提供其基础原理和实际应用的全面指南。

## 2.4 结论

本章简要概述了形式化验证方法及其优势、劣势和应用。形式化验证提供精确的系统分析，这在安全关键系统设计中是迫切需要的。然而，这种精确性是以大量的工程时间和精力为代价的。定理证明是最通用的形式化验证方法之一，因为它可以自动处理可以用命题逻辑或一阶逻辑表达的系统的分析，也可以使用高阶逻辑处理涉及连续和不可预测组件的复杂系统，但代价是需要大量的手动工作。相比之下，模型检查需要在系统和属性的形式化规范方面进行手动工作，但验证是自动完成的。然而，它受到状态空间爆炸问题的限制，因此无法处理非常大的系统。
