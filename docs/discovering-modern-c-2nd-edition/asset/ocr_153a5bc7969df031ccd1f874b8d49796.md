If the view is instantiated with a type that is not a matrix (or not declared as such), the compilation aborts and the user-defined error message is printed. Since `static_assert` does not create run-time overhead, it should be used wherever errors can be detected at the type level or regarding compile-time constants. Up to C++20, the error message must be a literal. Later C++ versions will hopefully allow us to compose messages with type information.

When we try to compile our test with the static assertion, we will see that `trans(A)` compiles but not `trans(B)`. The reason is that `const dense2D<>` is considered different from `dense2D<>` in template specialization so it is still not considered as a matrix. The good news is that we do not need to double our specializations for mutable and constant types, but we can write a partial specialization for all constant arguments:

```
template <typename T>
struct is_matrix<const T>
    : is_matrix<T> {};
```
