Before each access to `interrupted` we must `lock` our mutex `m` and `unlock` it afterwards. Explicit usage of `lock` and `unlock` is discouraged by the standard since we might forget to `unlock` a `mutex` or an exception might be thrown and in this case our program would be blocked. Since the `mutex` is a resource that we acquire and release with the preceding operations, we can apply the RAII paradigm. A `lock_guard` does `lock` an object in the constructor and `unlock` it in the destructor so that we cannot forget to `unlock`. Our code above simplifies significantly:
