**Limitations:** The mechanism of enable_if is quite powerful but can complicate debugging. Especially with old compilers, error messages caused by enable_if are usually rather verbose and at the same time not very meaningful. When a function match is missing for a given argument type, it is hard to determine the reason because no helpful information is provided to the programmer; they are only told that no match is found, period. Current compilers (clang++ ≥ 3.3 or g++ ≥ 4.9) inform the programmer that an appropriate overload was found but disabled by enable_if.

Furthermore, the enabling mechanism cannot select the most specific condition. For instance, we cannot specialize implementation for, say, is_sparse_matrix. Thus, we must remove ambiguities by adding according negative conditions:
