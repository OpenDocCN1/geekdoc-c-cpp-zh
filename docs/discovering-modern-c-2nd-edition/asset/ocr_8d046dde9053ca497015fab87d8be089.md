lvalue or rvalue. Furthermore, those member data types can only depend on the class template parameters, so the latter must reflect the distinction between an lvalue and an rvalue argument. Assuming the class parameters are appropriately instantiated, we use those types directly for our member data:

```
template <typename V1, typename V2>
class vector_sum
{
    V1 v1;
    V2 v2;
};
```

What remains is the challenging task of where to determine if we are dealing with lvalue or rvalue class parameters. There are two options. The first involves a constructor with forward references:

Click here to view code image

```
template <typename V1, typename V2>
vector_sum(V1&& v1, V2&& v2);
```

If all references are correctly forwarded to it, we can find out which reference type it is. However, we don’t need this information for the constructor itself but for the class template parameters. For this propagation of argument types we introduce a deduction guide:

Click here to view code image

```
template <typename V1, typename V2>
vector_sum(V1&&, V2&&)
-> vector_sum <copy_or_cref<V1>, copy_or_cref<V2>> ;
```

To trigger this guide, our operator must return vector_sum without explicit template types:

```
template <typename V1, typename V2>
auto operator+(V1&& x, V2&& y)
{
    return vector_sum<std::forward<V1>(x), std::forward<V2>
    (y)>;
}
```
