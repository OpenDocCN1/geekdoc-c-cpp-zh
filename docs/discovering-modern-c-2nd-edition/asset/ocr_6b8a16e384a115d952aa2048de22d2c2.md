contexpr int sqrt_aux(int i, int j)

In cases where the argument isn’t a square number the algorithm runs into an infinite loop (possibly at compile time). With the `contexpr` features of C++14 we could have realized the `sqrt` function more compactly but we preferred showing that `contexpr` functions in C++11 are also Turing-complete.

We have now shown that `contexpr` functions implement \(\mu\)-recursive functions, i.e., that all \(\mu\)-recursive functions can be programmed with `contexpr` functions. Furthermore it has been proven that \(\mu\)-recursive functions implement \(\lambda\)-calculus which in turn implements Turing machines which in turn implement \(\mu\)-recursive functions:

> \(\mu\)-recursive f. \(<\lambda\)-calculus \(<\) Turing machines \(<\mu\)-recursive f.

Sketches of the proofs are found in [29]. This implies by transitivity:

> `contexpr` \(<\mu\)-recursive f. \(<\lambda\)-calculus \(<\) Turing machines.

Thus, every Turing-machine program can be built by `contexpr` functions.

The consequence of this proof is that every function computable by any algorithm can be calculated as a C++ compiler already in the compilation process.\(^1\) As Herb Sutter stated it once, the template system (and the `contexpr` functions) establish a functional programming language embedded in C++. We hope that we underlined these two statements with the examples in this chapter.
