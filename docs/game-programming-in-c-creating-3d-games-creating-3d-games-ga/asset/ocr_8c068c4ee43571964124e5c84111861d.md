Although z-buffering works well, there are some issues. For one, transparent objects don't work with z-buffering as specified. Suppose a game has semi-transparent water, and under this water is a rock. In z-buffering, drawing the water first writes to the z-buffer and prevents the rock from drawing, since the rock has a higher depth.

The solution to this dilemma is to render opaque objects first, using z-buffering. Then disable depth buffer writes and render transparent objects back-to-front. As the pixels render, you should test the depth at each pixel to ensure that transparent pixels behind opaque objects don't draw.
