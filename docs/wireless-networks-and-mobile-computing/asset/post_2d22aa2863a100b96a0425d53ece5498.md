In general, a radio in *transmit* or *receive* state consumes the maximum power while in *active* and *idle* states, it consumes very little power. Typically, the radio consumes the least power in idle state but takes longer to switch to transmit or receive state from idle state than from the active state. During these silence intervals, the transmitter can save significant energy. The family of phase and frequency modulations such as phase-shift keying (PSK), frequency-shift keying (FSK), $m$-ary PSK, $m$-ary FSK and their variants are superior to the amplitude-shift keying (ASK) and $m$-ary ASK techniques. When one chooses to employ $m$-ary PSK/FSK modulation along with silent intervals for the dominant symbol which corresponds to an ASK transmission, the instantaneous power levels of the $m-1$ non-silent symbols may have to be increased appropriately due to the higher SNR requirements of ASK for the same bit error rate (BER) value compared to $m$-ary PSK/FSK. Thus, for a successful energy-efficient communication, the difference between the energy saved due to silence and the additional energy needed for the increased instantaneous power for $m$-ary PSK/FSK needs to be positive.

Several successful approaches implementing the appropriate source coding technique and silent communication of the dominant symbol, along with suitable modulation and demodulation techniques have already been proposed by various researchers [39, 3, 4, 6, 5, 40]. ## 8.3 Redundant Binary Number Encoding with Silent Zero Communication (RBNSiZeComm)

This communication scheme is based on encoding the messages to be transmitted in a redundant binary number system (*RBNS*). We first discuss *RBNS* basics and the frequency distribution of the symbols in all possible messages (assuming that every binary string is equally likely to occur as a message to be transmitted) in this number system. After that, we describe the communication protocol using the concept of silent communication on encoded messages and then evaluate the performance of the protocol in terms of energy savings in the transceiver as described in [39].

### 8.3.1 Preliminaries on Redundant Binary Number System

The redundant binary number system (RBNS) [21] utilizes the digits from the set $\{-1, 0, 1\}$ for representing numbers using radix 2. In the rest of the chapter, for convenience, we denote the digit $-1$ by **1̄**. In RBNS, there can be more than one possible representation of a given number. For example, the decimal number 7 can be represented as either 111 or 1001̄ in RBNS. We utilize this property to recode a message string to reduce the number of 1’s in the string while transmitting the message. The original binary message can, however, be obtained at the receiver end by reconverting the received message from RBN to the binary number system.

The basic idea of the recoding scheme is as follows: Consider a run of *k* 1’s, *k* > 1. Let *i* be the bit position for the first 1 in this run, *i* ≥ 0 (bit position 0 refers to the least significant bit at the rightmost end). Let *v* represent the value of this run of *k* 1’s. Then,

$$v = 2^i + 2^{i+1} + 2^{i+2} + \dots + 2^{k+i-1}. \tag{8.1}$$

Alternatively, we can rewrite Equation (8.1) as,

$$v = 2^{k+i} - 2^i. \tag{8.2}$$

Equation (8.2) can be represented in RBNS by a 1 at bit position $(k+i)$ and a $\bar{1}$ at bit position $i$, while all the intermediate 1’s between them are converted to 0’s. We formalize this observation in the form of the following reduction rule.

**Reduction 1.** *A run of $k$ 1’s ($k > 1$) starting from bit position $i$, is replaced by an equivalent representation consisting of a 1 at bit position $k+i$ and a $\bar{1}$ at bit position $i$, with 0’s in all intermediate bit positions.*

Observe that for a run of $k$ 1’s, $k > 1$, the savings in terms of the number of non-zero digits is $k-2$. Note that the number of non-zero digits remains unchanged for $k = 2$. Also, if we consider a string, say 110111, with only one 0 trapped between runs of 1’s, after applying reduction rule 1, we would get the string $10\bar{1}100\bar{1}$. Note the presence of the pattern $\bar{1}1$ for this trapped 0. A second reduction can now be applied to the bit pattern $\bar{1}1$ to replace it with $0\bar{1}$. Thus, from $10\bar{1}100\bar{1}$, we get the string $100\bar{1}00\bar{1}$ with fewer non-zero digits. We thus have a second reduction rule.

**Reduction 2.** *Every occurrence of the bit pattern $\bar{1}1$ in a string obtained after applying reduction rule 1 is replaced by the equivalent bit pattern $0\bar{1}$.*

The application of reduction rules 1 and 2 warrants a two-pass algorithm. However, it is easy to combine the two rules to obtain a single-pass algorithm, as stated below.

```
1: procedure RBNSiZeComm(IN bit vector data_frame, IN integer len)
2:     /* The data frame is converted to RBNS */
3:     /* by applying reduction rules 1 and 2 */
4:     bit vector out_buf : array [0..len] ▷ size of len + 1 bits;
5:     boolean runflag : false;
6:     integer runlengthcount, lowbit : 0;
7:     Call ReductionRule1(data_frame, len, out_buf); ▷ Reduction Rule 1
8:     Call ReductionRule2(out_buf, len); ▷ Reduction Rule 2
9:     for i = 0 to len do
10:         if out_buf[i] ≠ 0 then
11:             transmit bit out_buf[i]; ▷ Either 1 or 1̄
12:         else
13:             remain silent; ▷ No transmission of bit value '0'
14:         end if
15:     end for
16: end procedure

1: procedure REDUCTIONRULE1(IN data_frame, IN len, OUT out_buf)
2:     for i = 0 to len - 1 do ▷ Test each bit of data frame
3:         if data_frame[i] = 1 then
4:             if runlengthcount = 0 then
5:                 lowbit ← i; ▷ Start index of run of 1's
6:             end if
7:             runlengthcount ← runlengthcount + 1; ▷ Run length
8:             if runlengthcount > 1 then
9:                 runflag ← true; ▷ Found a run of ones
10:             end if
11:         else ▷ data_frame[i] = 0
12:             if runlengthcount > 1 then ▷ Apply Reduction Rule 1
13:                 out_buf[lowbit] ← 1̄;
14:                 for j = lowbit + 1 to i - 1 do
15:                     out_buf[j] ← 0;
16:                 end for
17:                 out_buf[i] ← 1;
18:                 runflag ← false;
19:             else ▷ Single 1, just copy to out buffer
20:                 out_buf[lowbit] ← 1;
21:                 out_buf[i] ← 0;
22:             end if
23:             runlengthcount ← 0; ▷ Reset run length count
24:         end if
25:     end for
26:     if runflag = true then ▷ run of 1 ends at MSB
27:         out_buf[lowbit] ← 1̄;
28:         for j = lowbit + 1 to len - 1 do
29:             out_buf[j] ← 0;
30:         end for
31:         out_buf[len] ← 1; ▷ out_buf of length len + 1
32:         runflag ← false;
33:     end if
34: end procedure

1: procedure REDUCTIONRULE2(INOUT out_buf, IN len)
2:     for i = 1 to len do
3:         if (out_buf[i] = 1̄) and (out_buf[i - 1] = 1) then ▷ Reduction Rule 2
4:             out_buf[i - 1] ← 1̄;
5:             out_buf[i] ← 0;
6:         end if
7:     end for
8: end procedure
```

To convert *protocol RBNSiZeComm* to a single-pass routine, we replace procedures *ReductionRule1* and *ReductionRule2* by a single procedure with a change in the lines 13 and 27 (where we write a 1̄ in the output buffer) of the procedure *ReductionRule1*. Each of these lines 13 and 27 of the procedure *ReductionRule1* will be replaced with the following:

```
if (lowbit ≠ 0) and (out_buf[lowbit − 1] = 1) then
    out_buf[lowbit − 1] ← 1̄;
    out_buf[lowbit] ← 0;
else
    out_buf[lowbit] ← 1̄;
end if
```

On the receiver side, the reverse process must be done to correctly receive the data and then convert it into its binary equivalent representation for further processing by the different layers of the network protocol stack. The application of the reduction rules 1 and 2 on the RBN coded data during transmission prevents occurrences of the bit patterns 1̄1 and 1̄1̄ in the transmitted data. Also, if the original data was an *n*-bit binary data frame, RBN encoding can result in a frame of size *n* + 1 RBN bits.
