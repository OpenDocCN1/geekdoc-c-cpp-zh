
For each cell, a mobile terminal is also elected as the *cell leader* to handle mobility of mobile terminals, joining of new mobile terminals and MTs leaving the cell or network. For simplicity, we arbitrarily assume the lowest id MT in a cell to be the cell leader. An advantage of such a leader election protocol is that no additional communication is required among the MTs to elect the cell leader. The cell leader must:

- Compute the slot demand of the cell.
- Control admission of new mobile terminals into the network.
- Handle handoff situations and MTs leaving the network.
- Communicate to the *network leader* the demand of the cell and request a recomputation of the allocated slots whenever necessary.

To handle mobility of the mobile terminals, each cell keeps a few slots for transmitting control messages and some unused slots for handling new MTs joining the network and handoff scenarios. In general, a cell *i* computes its demand *wᵢ* as the sum of the number of mobile terminals in the cell, the number of slots allocated for control messages and an additional few unused slots. We assume the number of unused slots to be some fraction *f* of the number of mobile terminals currently in the cell. If *mᵢ* is the number of MTs currently in cell *i* and *c* slots are used for control purposes, then the demand, *wᵢ*, of cell *i* is, *wᵢ = mᵢ + c + max(1, ⌈fmᵢ⌉), 0 ≤ f ≤ 1*.

# 5.4.6.1  Algorithm COSA

The steps of the algorithm are:

- **Step 1:** Elect an MT as the *network leader* through some leader election protocol [10, 11] and call it *L*.

**Step 2:** *L* broadcasts the mapping to convert the geographical region into a hexagonal grid structure to all the nodes of the network. It transmits a message *M* consisting of:

- The id of the MT transmitting the message
- A mapping to convert the geographical region into a hexagonal grid structure
- A list of the ids of all MTs heard by *L*

Each node, on receiving this message, appends it with its own location coordinates to be known to all other nodes. An MT *i* transmits its message in the *i*th slot to avoid collisions during this step.

**Step 3:** For each cell *i*, a *cell leader* *Lᵢ* is elected from the MTs residing in cell *i*, based on some metric such as remaining battery power, load, location, etc. [11].

**Step 4:** The demand of each cell *i*, *wᵢ* is communicated by each cell leader *Lᵢ* to the network leader *L*. *L* produces an optimal, collision-free transmission schedule by executing the *homogeneous_slot_assignment* or the *heterogeneous_slot_assignment* algorithm.

**Step 5:** *L* broadcasts the slot assignment schedule of the network to each cell leader.

The slot assignment schedule details the slots assigned to each cell *i*, that demand *wᵢ* slots. Once a cell leader *Lᵢ* of cell *i* receives the information about the slots assigned to it from *L*, it generates a transmission schedule for the MTs in cell *i* and transmits a periodic local broadcast of this schedule within cell *i*.

For Step 2 of the *COSA algorithm*, assuming it takes *O(1)* time to transmit *M*, the broadcast algorithm will complete in *O(mD)* time slots where *D* is the diameter of

the ad hoc network. At the end of the broadcast, each MT $j$ would have the following information:

- The id $i$ of the hexagonal cell in which it is located
- The set of its neighbors, $N(j)$
- The ids of the MTs in cell $i$ and hence the number of MTs currently in cell $i$

In Step 5, if $d_i$ is the diameter of the ad hoc subgraph in cell $i$, after $O(d_i w_i)$ time slots, each MT $j$ of the cell $i$ will know the time slot allocated by $L_i$ in which it can transmit.

**Definition 11.** *A round of transmission for a cell $i$ consists of $w_i$ slots, where $w_i$ is the number of slots requested by cell $i*.*

Each cell leader periodically transmits in one or more control slots a *cell status message* $M_s$ containing the following information:

- The id of the cell leader
- The list of the control slots
- The list of used and unused slots in the corresponding cell and which slot is assigned to which MT so that when a new node joins or enters the cell, it knows the available slots in which it can transmit without causing collisions

> **Remark 20.** *We assume that the lowest numbered $c$ slots assigned to a cell are marked as the control slots. Also, the highest value control time slot is always assumed to be unused so that in the event that there are no unused time slots currently in the cell, a new mobile terminal in the cell can use this time slot to communicate with the cell leader.*

# 5.4.6.2 Complexity Analysis

The leader election process in Step 1 of *algorithm COSA* takes O(log log m) time [10, 11, 12]. Steps 2 and 5 take O(mD) time each for round-robin broadcast, assuming ∀ i, dᵢ ≪ D and wᵢ = O(m) for Step 5 of *algorithm COSA*. Step 3 of *algorithm COSA* takes O(1) time. Computation of an optimal slot assignment schedule by algorithm *homogeneous_slot_assignment* or algorithm *heterogeneous_slot_assignment* takes O(n) time where n is the number of cells in the cellular network. Thus, Step 4 takes O(mD) + O(n) time. Hence, the complexity of the *algorithm COSA* is O(log log m + mD + n) time.

# 5.4.6.3 New Mobile Terminal Joining the Network

In each cell, the cell leader periodically transmits a *cell status message* Mₛ as stated above. This message is locally broadcast within the cell. When a new MT j joins the network in some cell i, it first waits for the Mₛ message. Subsequently it executes the following steps to join the network in cell i:

**Step 1:** If there exists at least one unused time slot in cell i, mobile terminal j randomly selects an unused time slot k of cell i and sends a HELLO message to the cell leader Lᵢ. In the event that there are no free slots in cell i that can be used by j, j transmits a HELLO message in the highest value control slot, which according to the protocol is always unused. The HELLO message contains the following information and its structure is shown in Figure 5.15.

+   1. Message Type is set to HELLO

**Step 2:** The HELLO message, if heard by its neighbors, is retransmitted by each neighbor of j in cell i.

**Step 3:** If L_i hears a HELLO message from a new MT j in an unused time slot k of cell i, execute Steps 3.1 and 3.2, otherwise go to Step 4.

**Step 3.1:** L_i marks slot k to be allocated to j.

**Step 3.2:** L_i initiates a local cell broadcast of updated cell status message M_s reflecting the slot allocated to j. The cell status message is also an acknowledgment (ACK) from L_i to mobile terminal j that it has been assigned slot k.

**Step 4:** If the HELLO message from j was transmitted in a control slot,

**Step 4.1:** L_i initiates a garbage collection routine to reclaim slots assigned to MTs that have left cell i. The garbage collection process works as follows:

**Step 4.1.1:** L_i transmits a local cell broadcast requesting each MT in cell i to send an ACK to L_i.

**Step 4.1.2:** The ACKs from neighbors are piggy-backed on the ACK transmission of each MT.

**Step 4.2:** If after garbage collection L_i fails to find sufficient unused slots to accommodate all the new nodes in cell i,

**Step 4.2.1:** L_i computes the new demand w_i of cell i, taking the new nodes in i into account.

**Step 4.2.2:** $L_i$ sends a request to the *network leader* $L$ to reassign slots using the new $w_i$.

**Step 5:** If $j$ fails to hear an ACK message from $L_i$ within some timeout interval $T$, it assumes that it was not allocated any time slot by $L_i$. This can occur under the following conditions:

+   1. Case 1: $L_i$ was unable to allocate a slot to $j$.
+   2. Case 2: Some new nodes tried to transmit in the same time slot as $j$ and hence the transmission was garbled due to collision.

On timeout, $j$ uses an exponential backoff algorithm and tries to transmit again. It continues this until it receives an ACK from $L_i$.

# 5.4.6.4  **Mobile Terminal Leaving Cell or Network**

If a mobile terminal $u$ other than the cell leader or the network leader leaves the current cell, no immediate update action is taken. The slot assigned to $u$ may be reclaimed by the cell leader if the cell leader fails to find sufficient unused slots in the cell to satisfy a new incoming mobile terminal in the cell. If a cell leader leaves the network or the cell, according to this protocol no transmission will be heard by the nodes of the corresponding cells in the control slots. When such a situation occurs, a new *cell leader* is elected from the remaining MTs.

If the network leader has left the network, the existing cell leaders elect a new network leader.

# 5.4.6.5  **Handoff Situations**

A *handoff* is required when a mobile terminal $u$ moves from one cell $i$ to another cell $j$. The handoff is treated in the same way as a new MT joining cell $j$ is treated with an additional message sent from $L_j$ to $L_i$ indicating the new cell in which $u$ is located.
