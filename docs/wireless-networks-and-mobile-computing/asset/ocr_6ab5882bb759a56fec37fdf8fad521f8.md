If yes, then the node possessing _V_(_k_) authenticates the node sending the (message, authenticator) tuple (_m, a_). A node not having the function _S_(_k_) will not be able to correctly generate _a_ from its message _m_ and hence will not be authenticated by the node possessing the function _V_(_k_). The authenticators are usually exposed in a network and everybody can see it. Hence, _S_(_k_) should not only be secret, but also not be easily derivable from the authenticators.

There can be two types of authentication algorithms. In the first type, known as **message authentication code (MAC)** (not to be confused with the media access control protocol), knowledge of _S_(_k_) and _V_(_k_) are equivalent, i.e., one function can be derived easily from the other. Thus, anyone who knows _V_(_k_), can also find _S_(_k_) from it, and vice versa. An example is to have _S_(_k_)(_m_) = _f_(_k, m_), where the function _f_ cannot be derived easily by knowing _k_ and _f_(_k, m_<sub>1</sub>) = _f_(_k, m_<sub>2</sub>), when and only when _m_<sub>1</sub> = _m_<sub>2</sub>. In other words, the function _f_ is collision resistant on _m_. A corresponding verification algorithm will then be _V_(_k_)(_m, a_) ≡ (_f_(_k, m_) = _a_), i.e., if _f_(_k, m_) = _a_, then and only then _V_(_k_)(_m, a_) will produce a true value. Thus, anyone who knows _S_(_k_) knows _f_ and also knows _V_(_k_) and vice versa. For this reason, it is essential to keep both _S_(_k_) and _V_(_k_) secret in this scheme.

The other type of authentication algorithm is through **digital signature** in which it is computationally infeasible (or very difficult) to derive _S_(_k_) from a knowledge of _V_(_k_) and also _V_(_k_) is a one-way function, i.e., knowing _V_(_k_) makes it infeasible (or very difficult) to compute _k_. Thus, it is not necessary to keep _V_(_k_) secret. _V_(_k_) can be thought as a public key and _k_ can be treated as a private key in asymmetric key cryptography.
