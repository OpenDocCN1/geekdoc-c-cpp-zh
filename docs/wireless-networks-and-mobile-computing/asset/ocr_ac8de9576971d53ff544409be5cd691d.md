Thus, such a scheme using DRs can be used for significant overhead reduction in both location registration and call delivery processes.

Another possible scheme for reducing the overhead in location registration and call delivery is through *per-user location caching* [11] which stores the current location information of an MT in a cache at a nearby signal transfer point (STP). Whenever an MT is accessed through the STP, an entry is added to the cache which refers to the mapping from the ID of the MT to that of its serving VLR. When a call is initiated to an MT, the STP first checks whether a cache entry exists for this MT. If no cache entry exists, the usual (e.g., IS-41) call delivery scheme as described above is used to locate the MT. If, however, a cache entry is found for this MT, the STP will query the VLR as specified by the cache entry. If the MT still resides under this VLR, a cache hit occurs and the MT is found easily without the need for querying its HLR. If, however, the MT has already moved to another location not associated with this VLR, a miss occurs and the usual IS-41 call delivery scheme is followed in locating the MT. Figure 2.7 illustrates this scheme in which MT1 is trying to call MT2 and there is a cache entry at the signal transfer point STP1 corresponding to this MT2 that it is now mapped to VLR2. If the MT2 still resides under VLR2, the call is delivered to it immediately through VLR2 without querying the HLR of MT2. However, if MT2 moves to a new location under a VLR other than VLR2, there will be a cache miss and the usual IS-41 process will be applied to locate MT2. Thus, the overhead under this cache miss situation is more than that in the usual IS-41 scheme.
