The basic idea is to use a DR that covers the service area of a number of MSCs so that it stores the location pointer configuration for the MTs roaming in its service area. There are three basic types of location pointers used by a DR [1]:

+   1. A *local pointer* is stored at an MT’s serving DR pointing to the currently serving MSC of the MT.
+   
+   2. A *direct remote pointer* is stored at a remote DR which points to the currently serving MSC of the MT.
+   
+   3. An *indirect remote pointer* is stored at a remote DR which indirectly points to the currently serving MSC of the MT.

Along with this scheme of using the DRs, the HLR of the MT may now be configured to store a pointer to the serving DR and/or the currently serving MSC. In some cases, however, no such change in HLR may be made for a cost-effective operation and the original IS-41 scheme may be used in HLR. In view of these DRs, let us again consider the above example of an MT having its HLR in Kolkata, and currently roaming in Bangalore. Suppose it moves to Chennai and receives calls from the Bangalore area. If a significant number of incoming calls to this MT are detected as originating from Bangalore, a direct or indirect remote pointer can be set up for this MT in the DR at Chennai. When the next call is initiated for this MT from Chennai, the calling MSC first queries the DR and the call can be immediately forwarded to Bangalore, without the need for querying its HLR in Kolkata. This significantly reduces the signaling traffic in the network for call delivery.
