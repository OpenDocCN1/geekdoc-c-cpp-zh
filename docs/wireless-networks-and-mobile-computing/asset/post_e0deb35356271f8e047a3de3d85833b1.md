## 9.1.2 External Attacks

An external attack arises from an unauthorized node, i.e., a node which is not a part of the network. In the first type, the external attacker node injects a strong jamming signal in the communication band of a network, similar to constant jamming mentioned above. If an external node has enough information (from unauthorized sources) about the physical layer (communication band, modulation and demodulation mechanisms, etc.), MAC layer protocol and network layer protocol, it can generate false packets and insert those packets into the network continuously or at random intervals of time or as and when a packet is being transmitted over the channel, like similar attacks by an internal node. Packets injected by an external attacker node may eventually be ignored if the network has an appropriate authentication technique (which is often the case). The danger is that such an activity consumes a lot of network resources like communication band and node energy. However, considering that authentication will eventually be used by the network for allowing a node to take part in communication, an external attacker actually stands a very small chance of acceptance of its inserted packets by the nodes in the network. Based on this ultimate consequence, an external attacker may better choose to follow only constant jamming, generating random noise signals to jam the network, without taking the trouble of generating false or misguiding packets and trying to inject them in the network. It will suffice for an external attacker to create the desired denial-of-service through these jamming signals only.

The authenticators are usually exposed in a network and everybody can see them. Hence, _S_(_k_) should not only be secret, but also not be easily derivable from the authenticators.

There can be two types of authentication algorithms. In the first type, known as **message authentication code (MAC)** (not to be confused with the media access control protocol), knowledge of _S_(_k_) and _V_(_k_) are equivalent, i.e., one function can be derived easily from the other. Thus, anyone who knows _V_(_k_), can also find _S_(_k_) from it, and vice versa. An example is to have _S_(_k_)(_m_) = _f_(_k_, _m_), where the function _f_ cannot be derived easily by knowing _k_ and _f_(_k_, _m_<sub>1</sub>) = _f_(_k_, _m_<sub>2</sub>), when and only when _m_<sub>1</sub> = _m_<sub>2</sub>. In other words, the function _f_ is collision resistant on _m_. A corresponding verification algorithm will then be _V_(_k_)(_m_, _a_) ≡ (_f_(_k_, _m_) = _a_), i.e., if _f_(_k_, _m_) = _a_, then and only then _V_(_k_)(_m_, _a_) will produce a true value. Thus, anyone who knows _S_(_k_) knows _f_ and also knows _V_(_k_) and vice versa. For this reason, it is essential to keep both _S_(_k_) and _V_(_k_) secret in this scheme.

The other type of authentication algorithm is through **digital signature** in which it is computationally infeasible (or very difficult) to derive _S_(_k_) from a knowledge of _V_(_k_) and also _V_(_k_) is a one-way function, i.e., knowing _V_(_k_) makes it infeasible (or very difficult) to compute _k_. Thus, it is not necessary to keep _V_(_k_) secret. _V_(_k_) can be thought of as a public key and _k_ can be treated as a private key in asymmetric key cryptography.

As an example of the digital signature technique for authentication, assume that we use RSA, one of the most popular encryption algorithms introduced by Rivest, Shamir and Adleman in 1978. We assume that a large number _N_ is publicly known, where _N_ is a product of two large prime numbers _p_ and _q_. It is very difficult for even the most powerful computer to compute _p_ and _q_ within a reasonable time if it knows only _N_. We form a secret key _k_ as _k_ = (_d_, _N_), where _d_ is a private key although _N_ is publicly known. The signature algorithm to be executed by a node to be authenticated is _S_(_d_, _N_)(_m_) = _m_<sup>_d_</sup> mod _N_ (assuming that _m_<sup>_d_</sup> mod _N_ is a collision-resistant function of _d_). Thus, _a_ = _m_<sup>_d_</sup> mod _N_. The corresponding verification function will be _V_(_d_, _N_)(_m_, _a_) ≡ (_a_<sup>_e_</sup> mod _N_ = _m_), where _ed_ mod (_p_ − 1)(_q_ − 1) = 1. Even if a node knows _e_ and _N_, i.e., the verification function, it is computationally infeasible or very difficult to compute _d_ from the knowledge of _e_ and _N_, as _p_ and _q_ are difficult to compute from _N_. That is, the function _S_ cannot be computed from the knowledge of the function _V_.

## 9.2.2 Intrusion Detection

Intrusion detection techniques depend on detecting deviations of the characteristics of an internal node. If we gather statistical data about the contribution of a node to the various network function related parameters, an idea about the normal behavior of that node can be estimated. Any deviation from this estimated normal behavior might be considered an abnormal behavior or an anomaly that might be used for identifying this node as an intruder. The network function-related parameters that might be used for anomaly detection include packet drop ratio, delay in packet forwarding and successful forwarding of packets following the designated route (if route is computed at the source). In fact, this depends on the statistical behavior of nodes over a long period and appropriate modeling of the behavior of each constituent node. Inference from such analysis may require a lot of engineering. The potential problems with these techniques involve failure to detect a true intruder and false identification of a good node as an intruder.

## 9.2.3 Message Encryption

To guard against eavesdropping or man-in-the-middle attack, it is necessary that the source node properly encrypts its message _m_ which can be decrypted only by its intended recipient. Thus, the message cannot be known by an external attacker or an intermediate internal node. As a consequence, this message cannot be changed by the attacker. There are two different types of encryption algorithms. The first is based on a **symmetric key encryption** in which every pair of sender and receiver nodes share a common key which is kept secret from all other nodes. The example is the **Data Encryption Standard (DES)** adopted by the National Institute of Standards and Technology (NIST) in the U.S. and largely used for civilian applications. However, in 2001, DES was considered insecure for many applications as it used key values only 56 bits long which can be exhaustively searched with available computing resources. DES was replaced by the **Advanced Encryption Standard (AES)** which works on blocks of 128 bits and key lengths of 128 bits to 256 bits.

The main problem with the symmetric key encryption is key management. If there are _n_ nodes in the network, the number of possible communicating pairs will be _n_(_n_ − 1)/2, and thus we need _O_(_n_²) secret keys. Managing such a large number of secret keys, one for each pair of communicating nodes, is a problem in practice when the security of communication channel is questionable.

The other type of encryption algorithm is based on **asymmetric key encryption** which started with a ground-breaking idea of Diffie and Hellman in 1976. They proposed the notion of public key cryptography involving two different keys, one _public key_ known to all and the other a _private key_ known only to the recipient of a message. Anyone can use the public key to encrypt a message, but only someone who has the private key can decrypt the message. Thus, effectively, for all _n_ nodes, we need to manage only _n_ secret keys, far better than the _O_(_n_²) secret keys required for symmetric key encryption.
