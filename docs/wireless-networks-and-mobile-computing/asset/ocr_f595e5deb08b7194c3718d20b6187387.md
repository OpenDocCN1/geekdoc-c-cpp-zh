To minimize the overhead, we would like to use the four control slots to test whether an *active* node can move to the *transmit* state only once every $\lceil\log n\rceil$ rounds. However, this may cause a situation in which the nodes in layer 1 get the message in round 1 and then wait for the next $\lceil\log n\rceil - 1$ rounds until they become eligible for transmitting the message to the next layers. To avoid this unnecessary waiting, we propose using these control slots in two successive rounds in every $\lceil\log n\rceil$ rounds. Additionally, for mobility resilience, the source node will continue transmitting the message every $\lceil\log n\rceil$ rounds.

# 5.5.2.5   Algorithm bf_broadcast

We use a local variable *round_count* initialized to 0 at each node to keep track of the round number of transmissions. Subsequently, each node would increment its respective *round_count* variable at the start of successive rounds. The following steps are executed by all nodes in parallel for broadcasting a message $M$.

+   **Step 1:** (Initialization) The source node sets its state to *transmit*. All other nodes set their states to *receive*. The following steps are executed in each of the successive rounds.
+   
+   **Step 2:** (Actions taken by the source node) If $round\_count \mathop{\mathrm{MOD}} \log n = 0$, then the source node transmits $M$.
+   
+   **Step 3:** (Test for eligibility of an *active* node to move to *transmit* state) If the state is *active* and $round\_count \mathop{\mathrm{MOD}} \log n \leq 1$, execute Steps 3.1, 3.2 and 3.3.
+   
+       **Step 3.1:** Send a *test* signal (one of the four control signals) and wait for *ack2* or *ack3* signals.
