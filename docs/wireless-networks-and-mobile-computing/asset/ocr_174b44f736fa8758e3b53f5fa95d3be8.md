```
**Algorithm 1** Key Scheduling Algorithm

1: **procedure** KSA(Secret Key *K*)
2: Initialize *S* ← {0, 1, . . . , *N* − 1} and *j* ← 0
3: **for** *i* = 0, . . . , *N* − 1 **do**
4:       Increment: *j* ← *j* + *S*[*i*] + *K*[*i*]
5:       Swap: *S*[*i*] ↔ *S*[*j*]
6: **end for**
7: **return** S-box *S*
8: **end procedure**
```

```
**Algorithm 2** Pseudo-Random Generation Algorithm

1: **procedure** PRGA(*S*-box *S*)
2: Initialize indices: *i* ← 0, *j* ← 0
3: **while** TRUE **do**
4:       Increment: *i* ← *i* + 1, *j* ← *j* + *S*[*i*]
5:       Swap: *S*[*i*] ↔ *S*[*j*]
6:       **output** *Z* ← *S*[*S*[*i*] + *S*[*j*]]
7: **end while**
8: **end procedure**
```

Any arithmetic addition used in context of RC4 is in general addition modulo *N*, unless specified otherwise. The output keystream *Z* is XOR-ed with the plaintext (byte per byte) to generate the ciphertext at the sender end (*C* = *M* ⊕ *Z*), and is XOR-ed with the ciphertext to get back the plaintext at the receiver end (*M* = *C* ⊕ *Z*).

Efficiency of keystream throughput is used as a benchmarking parameter for stream ciphers. The efficiency of the RC4 obviously depends on the efficiency of KSA and PRGA. While the KSA invokes a fixed cost for generating the initial pseudo-random state *S*, the PRGA incurs a variable cost based on the number of keystream bytes to be generated. An efficient implementation of RC4 would minimize the cost per round of KSA and PRGA to provide better throughput.
