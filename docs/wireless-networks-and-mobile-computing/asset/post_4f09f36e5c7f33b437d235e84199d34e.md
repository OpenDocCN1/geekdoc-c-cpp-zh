Such a situation is shown in Figure 5.19, where node v is in active state in layer j, and node x is in collision state in the same layer j and lies within the hearing zone of node v. While the collision resolution at x is going on (by the process of selectively dropping its transmitting nodes in layer j - 1), the transition of node v from active to transmit state during this collision resolution period will cause further collision at node x due to the message transmitted from v which may not be resolved. This is illustrated by the following example.

**Example 26.** Assume that the node x in Figure 5.19 has two transmitting neighbors with id values equal to 11110001 and 11011011, differing first in the third bit from the msb side, while the node v has an id value equal to 10110001. Thus, in the third round after experiencing the collision for the first time, node x could get a clean message from the node 11110001 as the other node 11011011 would have been dropped based on the testing of the (msb-2)-th bit. However, if in this same round, node v moved from active to transmit state, x would instead experience a collision due to messages coming from both 11110001 and v (= 10110001). Note that the id value of v is identical to that of this node from the (msb-2)-th bit onward (toward the least significant bit side). Also, v would try to scan the bits of its own id from its msb, while node 11110001 would scan its bits from the (msb-3)-th bit, which will completely jeopardize the collision resolution at node x.

To avoid such a situation and to simplify the collision resolution algorithm, an active node in layer j would first determine through some additional control signals (described below), whether it is a neighbor of any node in collision state. If so, then this active node does not immediately move to the transmit state.

From the above discussions, we satisfy following properties by the broadcast protocol.

**Property 1.** *The above mechanism of changing an active state of a node to the transmit state guarantees that while a node u in collision state is resolving the collision arising from a set 𝒯 of its transmitting neighbors, no new transmitting node ∉ 𝒯 can join the nodes in 𝒯 to send the message to u.*

**Property 2.** *With the property 1 above satisfied, the collision resolution mechanism described in the above section guarantees that a collision experienced by a node u*

arising from a set $T$ of its transmitting neighbors can always be resolved so that eventually a clean message is received by $u$.

To minimize the overhead, we would like to use the four control slots to test whether an *active* node can move to the *transmit* state only once every $\lceil\log n\rceil$ rounds. However, this may cause a situation in which the nodes in layer 1 get the message in round 1 and then wait for the next $\lceil\log n\rceil - 1$ rounds until they become eligible for transmitting the message to the next layers. To avoid this unnecessary waiting, we propose using these control slots in two successive rounds in every $\lceil\log n\rceil$ rounds. Additionally, for mobility resilience, the source node will continue transmitting the message every $\lceil\log n\rceil$ rounds.

# 5.5.2.5   Algorithm bf_broadcast

We use a local variable *round_count* initialized to 0 at each node to keep track of the round number of transmissions. Subsequently, each node would increment its respective *round_count* variable at the start of successive rounds. The following steps are executed by all nodes in parallel for broadcasting a message $M$.

+   **Step 1:** (Initialization) The source node sets its state to *transmit*. All other nodes set their states to *receive*. The following steps are executed in each of the successive rounds.
+   
+   **Step 2:** (Actions taken by the source node) If $round\_count \mathop{\mathrm{MOD}} \log n = 0$, then the source node transmits $M$.
+   
+   **Step 3:** (Test for eligibility of an *active* node to move to *transmit* state) If the state is *active* and $round\_count \mathop{\mathrm{MOD}} \log n \leq 1$, execute Steps 3.1, 3.2 and 3.3.
+   
+       **Step 3.1:** Send a *test* signal (one of the four control signals) and wait for *ack2* or *ack3* signals.

**Step 3.2:** If neither *ack2* nor *ack3* signals were received in respective slots, node state is changed to *transmit*, set *transmission_count* = 0 and set *scanned_bit_position* = log *n* − 1. Increment *round_count* by 1 and go to Step 4 for the next round.

**Step 3.3:** If either *ack2* or *ack3* signal is received, increment *round_count* by 1 and go back to Step 3 for the next round.

**Step 4:** (*Transmit state actions*) If node state is *transmit*, execute steps 4.1 to 4.5.

**Step 4.1:** If *transmission_count* = 0, transmit the message, increment the value of *transmission_count* by 1, and wait for acknowledgment signals in the *S*, *C* and *N* slots. Increment *round_count* by 1 and go back to Step 4 for the next round.

**Step 4.2:** If an acknowledgment was received in the *C* slot of the preceding round:

**Step 4.2.1:** If the *id* bit value at the current *scanned_bit_position* is 1 and the node transmitted the message in the immediate previous round, retransmit *M*, increment *transmission_count* by 1, decrement the value of *scanned_bit_position* by 1, and look for *S*, *C* and *N* signals again. Increment *round_count* by 1 and go back to Step 4 for the next round.

**Step 5:** (*receive* state actions) If node state is *receive*, execute Steps 5.1 to 5.4.

**Step 5.1:** If a signal is received in *test* slot, send *ack1* in this round. If signal received in *ack2* slot, send *ack3* signal in this round. Increment *round_count* by 1 and go back to Step 5 for the next round.

**Step 5.2:** If clean *M* is received, send an acknowledgment in *S* slot and change state to *active*. Increment *round_count* by 1 and go back to Step 3 for the next round.

**Step 5.3:** If collision occurs in *message* slot, send acknowledgment in *C* slot and change state to *collision*. Increment *round_count* by 1 and go to Step 6 for the next round.

**Step 6:** (*Collision* state actions) If node state is *collision*, execute Steps 6.1 to 6.5.

**Step 6.1:** If a signal is received in *test* slot or *ack1* slot, send the *ack2* signal in this round. Increment *round_count* by 1 and go back to Step 6 for the next round.

**Step 6.2:** If a collision is encountered in the *message* slot, send an acknowledgment in *C* slot. Increment *round_count* by 1 and go back to Step 6 for the next round.
