The above protocol has the advantage of tuning the value of $r$ to suit a particular value of $\Delta$ to reduce the number of rounds to complete the broadcast process. The minimum value of $\tau$ for a given value of $n$ and $\Delta$ (over possible choices of $r$) is shown by **bold** entries in the table. The minimum values that are smaller than the corresponding values of $n$ are boxed by rectangles. We make the following observations:

+   - As noted in [3], the *division* protocol remains better than the *simple* protocol as long as $h < \log_2 n/(\log_2 \log_2 n + 1)$ (since for larger $h$ values the frame length $\tau$ exceeds $n$); note that this bound on $h$ is approximate and not exact. The above protocol remains better than the *simple* protocol as long as $h < \log_r n/(\log_r \log_r n + 1)$ (the bound is approximate, not exact) by suitably choosing $r$. For higher values of $n$, the range of $h$ and hence that of $\Delta$ over which the protocol remains better than *simple* is larger in this protocol. For example, for $n = 16384$, and $\Delta = 15$ (corresponding to $h = 4$), the value of $\tau$ for the above protocol is 13440 ($< n$) (by choosing $r = 4$) compared to 17472 for the *division* protocol (corresponding to $r = 2$).
