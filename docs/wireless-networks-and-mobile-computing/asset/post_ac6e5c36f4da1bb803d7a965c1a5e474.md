
In this chapter, we discuss various communication protocols used in ad hoc networks (stationary or mobile) for different types of communication requirements, e.g., broadcast, gossiping and point-to-point communication among the nodes in the network. Broadcast is a process by which a source node transmits a message to be received by every node in the network. On the other hand, if every node has a different message to be sent to all other nodes in the network, the situation is called gossiping [1].

While discussing the protocols for all these communication requirements, we assume that the nodes in an ad hoc network all communicate over only one single channel. Under this assumption, it is likely that when one node is trying to send a message to its neighbors (nodes within hearing zone of the transmitting node), other nodes may also transmit through the common channel during the same time. This may lead to a collision of two or more messages at the receiving end. Because of mobility and limited battery power of the nodes, it is important to have fast, energy-efficient and deterministic (as opposed to randomized) broadcast and gossiping protocols for ad hoc networks by resolving collisions efficiently. Such protocols with efficient collision resolution mechanisms would provide low end-to-end latency and low overhead for retransmission of the collided messages. We first discuss the broadcast problem, followed by descriptions of gossiping and point-to-point routing protocols.

# 5.2 Broadcast in Ad Hoc Networks

Broadcast protocols in ad hoc networks may be centralized or distributed and may be based on deterministic or randomized algorithms. A broadcast protocol should have the following desirable properties:

- The protocol should be *mobility independent* or *mobility resilient* so that the broadcast is always completed correctly without knowledge of the identities of the neighbors of a node or the mobility of the nodes.
- It should be *deterministic* so that an upper bound on the broadcast completion time can be ascertained.
- It should be *distributed* rather than centralized so that the nodes can execute the protocol without *a priori* knowledge of the topology of the entire network. This property would successfully handle the dynamic network topology of an ad hoc network in a more efficient way than a centralized protocol.
- It should be *simple* so that the computational overhead at each node is minimized.

We first describe some deterministic distributed broadcast protocols for which we assume a system model as given below.

## 5.2.1 System Model

Following the ideas of [2, 3], let us model an ad hoc network consisting of *n* nodes by an undirected graph *G = (V, E)*, where *V = 0, 1, 2, · · ·, n − 1* is the set of vertices and *E* is the set of bidirectional edges. We assume that there exists an edge between two vertices if the corresponding nodes in the network are in the hearing zone of each other. Note that it is possible that a node $u$ can hear some other node $v$, but $v$ is unable to hear $u$ for some reasons (e.g., transmission power of $u$ may be too small, sensitivity of the receiver at node $v$ may not be sufficiently high, etc.).

In that case there will be only a directed edge from $v$ to $u$, but no directed edge from $u$ to $v$. We, however, exclude this possibility in this chapter unless stated otherwise.

We denote the set of neighbors of a node $i$ by $N(i)$, the maximum degree of a node in the network by $\Delta$, and the diameter of the network graph $G$ by $D$. Thus,

$$D = \max_{i,j\in V} d(i,j),$$ where $d(i,j)$ is the distance between two nodes $i$ and $j$ of $G$.

There will be one distinguished node in the network called the source node $s$ which carries the message to be broadcast to all other nodes in the network. $s$ initiates the broadcast process. Any node $i$, $0 \le d(s,i) = \ell \le D$ is said to belong to the layer $\ell$ of the network starting from the initiator source node $s$.

We assume that the time axis is divided into several *phases*, and each phase will consist of $k$ rounds or time slots (numbered from 0 to $k-1$), each round having the same time duration which is long enough to complete one hop of communication from a node to its neighbor. Phase 1 will start only after $s$ initiates the broadcast process.

During any round, a node can be in the transmitting state (transmitting a message to its neighbors), or in the receiving state (ready to receive a message from any of its neighbors), or it may remain idle (neither transmitting nor receiving). However, a node cannot be in the transmitting state unless it receives some message correctly; and once it receives the message correctly, it will switch to the transmitting state or may remain idle during any round until the broadcast is completed. A node $u$ can receive a message correctly during a round if and only if only one of the nodes belonging to $N(u)$ is transmitting the message during that round; if more than one node belonging to $N(u)$ is in the transmitting state during a round, $u$ experiences a collision and no message can be received by $u$ during that round.

We also assume in this model that all nodes are synchronized on a round-by-round basis. Every node will have a phase counter. When a node receives a message $m$, it waits for the beginning of the next phase when it sets its phase counter to 0. From that time onward, the phase counter is incremented by 1 at the end of every $k$ rounds. Also, there will be a round counter at each node which will be incremented by 1 (modulo $k$) at the end of every round. We assume that the network always remains connected and the topology does not change during one broadcast process.

## 5.2.2 Deterministic Transmission Schedule

To have a distributed deterministic protocol for broadcasting a message originated at the source node $s$, we need to find a transmission schedule of every node $i$ a priori irrespective of its current set of neighbors $N(i)$ at the moment, given the values of only $n$, $\Delta$ and the identifier $(i)$ of the node. Note that the neighbor set $N(i)$ of a node $i$ may change due to factors like mobility of the nodes, reduced battery power of the nodes and other network conditions. Despite these dynamic situations in the network, we need to find a transmission schedule for every node, with an ultimate upper bound on the number of phases $p$, each phase having an appropriate number of rounds $k$, so that the message is correctly broadcast among all nodes of the network. In other words, once we can give a protocol requiring at most $p$ phases each of $k$ rounds, the broadcast will be guaranteed to be completed in $pk$ rounds of transmissions. Every node will execute some function, e.g., $Get\_Rounds$ to get the round numbers in a phase during which it should transmit, and will store these round numbers as its transmission schedule. After receiving a message $m$, a node should mechanically follow this computed transmission schedule to determine whether it should transmit the message or remain idle during any round in a given phase.

The simplest way of setting the transmission schedule of a node achieving the above goal can be as follows, where _my_id_ is the identifier of the node [3]:

```
Function Get_Rounds (n, Δ) : integer
begin
return _my_id_
end
```

There will be a total of _n_ rounds in every phase and only one node will be transmitting during any round. Hence, there will be no collisions and the broadcast will be completed in _D_ phases. The upper bound on the number of rounds required for broadcasting by following this protocol will thus be _nD_. However, this simple protocol has the drawback that even when the maximum node degree Δ is very small (as is usually the case), only one node will be allowed to transmit in a round although it might have been possible to allow more than one node to transmit in a round without causing a collision. That is, for low values of Δ and large values of _n_, the number of rounds needed to complete the broadcast may be much smaller than _nD_.

Another approach to compute the transmission schedule of a node which may lead to smaller number of rounds than _nD_ to complete the broadcast, particularly with very large _n_ and small Δ, may be to allow collisions to occur.
