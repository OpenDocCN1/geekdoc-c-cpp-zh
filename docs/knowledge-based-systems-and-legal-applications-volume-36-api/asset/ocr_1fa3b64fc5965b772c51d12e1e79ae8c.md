The policy team could also use the system to answer a variety of complaints. For example, if someone complained that Joe thought they were deserving and yet they did not get relief, the problem could quickly be spotted: Joe is not a bead.

So far three systems have a common KB. But it is unlikely that we would want the users to have the system as it stands. At a minimum we would provide an interface. A minimal interface might be:

```
I1 GiveReliefTo(X): ProvidedWithParishRelief(X).
```

for the assessment system and

```
I2 CanGetRelief(X): ProvidedWithParishRelief(X).
```

for the advice system. We might also wish to include some kind of thesaurus-type information to handle vocabulary differences between the assessors and the assessed. If the interface is knowledge-based, therefore, differences in the target users will necessitate differences in the KB.

Now we may formalize the case

```
CL1 ThinksDeserving(X,Y)- KnownDeserving(Y).
CL2 ThinksDeserving(X,Y)-
not(KnownUndeserving(Y)),
LooksDeservingTo(X,Y).
```

```
CL3 KnownDeserving(Y) :- widow(Y).
CL4 KnownDeserving(Y) :- orphan(Y).
CL5 KnownUndeserving(Y):CanMakeOwnShift(Y).
CL6 CanMakeOwnShift(Y):Sturdy(Y),Vagabond(Y).
```

Now we must formalize the guidance. Some parts will be latent in the case law, and some will not.
