In the preceding example, the destructor isn't virtual; it's not able to find the proper destructor when you pass a Derived instance. So it calls the destructor for whatever type is listed in the parameter.

**TIP** Getting into the habit of always making your destructors virtual is a good idea. That way, if somebody else writes a function, such as `ProcessAndDelete()`, you can be assured the function automatically calls the correct destructor.

# # Programming the Exceptions to the Rule

An exception is an unexpected situation that occurs in your software. For example, if you try to write to a file, but somehow that file is corrupted and you can't, the operating system might throw an exception. Or you might have a function that processes some data, and if the function encounters corrupted data, it might throw an exception. The following sections get you started using exceptions.
