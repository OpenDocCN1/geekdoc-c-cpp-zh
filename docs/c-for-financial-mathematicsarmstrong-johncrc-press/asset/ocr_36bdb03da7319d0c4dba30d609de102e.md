To create an option with strike 100 and maturity 2.0 one would then write

```
CallOption myOption( 100, 2.0 );
```

This may seem like a very convenient system, but it is probably not a very good design. The reason is that by introducing classes we got rid of the problem of having to remember in what order to put parameters when calling functions. By having a constructor with multiple parameters, we’ve reintroduced this problem!

This doesn’t mean that constructors that take parameters are always bad, just that you shouldn’t over-use them. Certainly the ability to construct a vector of given size and default value is a good use of constructors.

There is one strange trick with parameterised constructors that you should try to remember. Consider the class string. It has a constructor that takes raw text data:

```
string s("Some raw text");
```

C++ uses this constructor to automatically convert raw text data to strings without you having to think about it. For example, the code:

```
plot("myPlot.txt", xVec, yVec );
```

will work despite the fact that the first parameter of a plot is declared to be a const string& and not a char*.

In general, if your class has a constructor that takes a single parameter construction, C++ will perform similar automatic conversions.
