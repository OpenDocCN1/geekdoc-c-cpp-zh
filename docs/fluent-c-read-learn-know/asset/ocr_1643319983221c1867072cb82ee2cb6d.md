public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
        this.myEvent += new EventHandler(MyHandler);
    }
}
public event EventHandler myEvent;
protected void OnMyEvent(EventArgs e)
{
    myEvent(this, e);
}
public void MyHandler(Object sender, EventArgs e)
{
    MessageBox.Show("Hey, the event worked!");
}
private void button1_Click(object sender, RoutedEventArgs e)
{
    OnMyEvent(new EventArgs());
}
```
```

This is the code that adds the event handler to the myEvent observers collection.

Here's the event declaration.

Since the delegate is only used here, I've created it in the assignment statement. It's often done this way, but of course you could have created the delegate explicitly, which would be useful if you were going to use it for more than one event.

Creating a single method to raise the event makes it easier to be consistent about how you handle it. It's common, for example, to actually raise two events when a property changes: one before the property is changed and one after. You'd raise both of them in this On<Property>Change method.

Are you curious why there isn't any code to add the button1_Click() method as an observer of button1? Check the Designer. It's in the XAML that defines the window. We'll see how that works in Chapter 18.
