# MODEL-VIEW-VIEWMODEL

The Model-View-ViewModel (MVVM) presentation design pattern descends from MVC by way of Martin Fowler's Presentation Model. (We won't be exploring the Presentation Model, but you can read Fowler's original description of it at www.martinfowler.com.) Although it can be applied in other environments, the MVVM pattern was developed specifically with WPF in mind, which isn't surprising since it was first described by John Gossman, one of the architects of WPF and Silverlight.

MVVM is the most loosely coupled of all the presentation models we've explored. The View only knows the ViewModel, the ViewModel only knows the View, and the Model is lonely indeed.

![](bbox=[0.18, 0.33, 0.82, 0.62])

The MVVM View communicates with the ViewModel (which knows nothing about it) through data binding and WPF Commands. We'll be discussing both of those in up-coming chapters.

The ViewModel translates the data provided by the Model into a structure convenient for the View, exposes properties that represent the View's state, and commands that the View can use to interact with the Model.

The Model does basically the same thing in all the presentation patterns. (You know what that is by now, right?)

As with MVP Views, MVVM Views are directly responsible for handling events that affect themselves.

The MVVM View is usually developed using different tools and languages than the application code, and often by a different person.

Conceptually, the MVVM View is in charge, which is quite different from other presentation patterns.
