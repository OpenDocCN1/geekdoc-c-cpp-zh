# CLASS DEFINITIONS

Now that we've got our classes defined (at least roughly), let's look at the code that Visual Studio has generated for us. Open the Ingredient.cs file in the Solution Explorer. It should look like this

```
public class Ingredient
{
    private int m_quantityOnHand;
    public event EventHandler QuantityChanging;
    public String Name
    {
        get
        {
            throw new System.NotImplementedException();
        }
        set
        {
        }
    }
    public int QuantityOnHand
    {
        get
        {
            throw new System.NotImplementedException();
        }
        set
        {
        }
    }
}
```

The class statement looks like a declaration statement.

The field is a simple declaration statement.

The event statement looks like a declaration statement with a few extra bits. We'll examine events and how they're implemented at the end of the chapter. (Don't panic: this line won't be in your class file until then.)

Here are the two properties Name and QuantityOnHand. There are two components. The get clause contains code that will be executed when the value is referenced, and the set clause is executed when the value is changed. We'll look at how that all works in a few pages.

Recognize that NotImplementedException? This is one of the places that Visual Studio will throw it until you add the code.
