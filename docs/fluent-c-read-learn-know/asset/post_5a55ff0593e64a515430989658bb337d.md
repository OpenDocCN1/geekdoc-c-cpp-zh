## DECLARED ELEMENTS

You wouldn't ask your pet elephant to live in a goldfish bowl, would you? I certainly hope not. (The world doesn't need more unhappy elephants.) C# won't let you do anything so unkind. DECLARED ELEMENTS are the nouns of C#, the things you will be manipulating in your code. When you create one, you have to tell C# what type of information it's going to hold, and it won't let you put an elephant in a goldfish-holder, or vice versa.

There are two types of declared elements in C#: VARIABLES that can contain different elephants (but only elephants) over the course of the application, and CONSTANTS that always have to hold the same elephant. (Of course, you're probably not going to be working with elephants. We'll examine the .NET Framework type system, which defines the common data types and lets you define new ones, in Chapters 10 and 11.)

## DECLARING ELEMENTS

With a very few exceptions, everything you do in C# is a statement or part of a statement. To create a declared element, you use a particular kind of statement called a declaration statement. (No surprise there, right?)

We'll talk about modifiers in Chapter 8.

C# is case-sensitive. You have to use the word "const", not "Const" or "CONST".

The name of the element is the word you'll use to refer to it in your code. It's called an IDENTIFIER, and we'll look at the rules for creating one in a few pages.

```
[modifier] [const] <type> <name> [= <value>];
private const Elephant dumbo = new Elephant();
```

The keyword const tells the compiler that the element is a CONSTANT and its value will never change. You must provide the value of the constant when you declare it.

The type specifier tells the compiler whether your element will hold a goldfish or an elephant (or an Int32).

You can set an initial value for your element (you have to do it for a constant) using this syntax.

Don't forget the semicolon!

> MAKE A NOTE
> There's a convention for syntax diagrams, and I'm using it here. Anything in square brackets, like [modifier], is optional. Anything in angle brackets, like <type> is a placeholder that you'll need to replace with an actual value.

## IDENTIFIERS

In C#, an IDENTIFIER is the name of something. That “something” could be any programming construct, including variables (myVar), constants (myConst), types (Int32), and methods (DoSomething).

The rules for identifiers are simple:

- An identifier must begin with a letter or an underscore (“_”).
- An identifier can contain letters, numerals or punctuation after the first character.
- An identifier cannot contain spaces.
- An identifier cannot be a C# keyword.

> Actually, you can use a keyword if you prepend an @ symbol—@new is okay, but new isn't—but it’s not a good idea.
>
> A KEYWORD is an identifier that has meaning to the compiler, like const. You can find a complete list of keywords on MSDN: search for “C# Keywords”.

## HUNGARIAN CAMELS

C# gives you a lot of leeway in naming your identifiers, but it's considered best practice to abide by some basic conventions. Most important of these is that the identifier should be meaningful. IHaveACrushOnJim is not a good idea for the name of a constant that represents the name of your elephant. (Unless, of course, your elephant is sitting on Jim.) Beyond that, there are some common conventions that you should know about:

### HUNGARIAN NOTATION

Invented by and named for Charles Simonyi, a Hungarian-American software architect, Hungarian notation puts the type of an identifier at the beginning of the name. In MyInteger, a lot of programmers swear by Hungarian notation (I'm not one of them, so you'll see a lot of it in sample code, but Microsoft no longer recommends it.

![](img/1dcd2af4ae4fa0eb5cf4ed5437ff121a_142_0.png)

### CAMELCASE

Camel-cased identifiers begin with a lowercase letter, but capitalize the first letter of any other words contained in the identifier. myCamelCasedIdentifier. Microsoft recommends camel casing for private identifiers (we'll find out about private identifiers in Chapter 8) and the values you pass to methods. (These are called PARAMETERS, and we'll talk about them in the next chapter.)

![](img/1dcd2af4ae4fa0eb5cf4ed5437ff121a_142_1.png)

### PASCALCASE

Pascal case is like camel case, but the whole thing begins with a capital letter. MyPascalCasedIdentifier. Pascal case is the recommended default convention. Use it for everything except private identifiers and parameters.

![](img/1dcd2af4ae4fa0eb5cf4ed5437ff121a_142_2.png)
