# STRUCTURED EXCEPTIONS

C# and the .NET Framework provide an exception-handling mechanism called STRUCTURED EXCEPTION HANDLING that makes it much simpler to deal with exceptions, and much more likely that they'll be handled in a consistent way. (Unfortunately, you don't always have to use it, so it does still require some discipline. The days of ugly Windows error dialogs aren't completely gone.)

.NET structured exception handling relies on a set of classes (System.Exception and its children) and two C# commands, the try...catch...finally block that lets you handle problems gracefully and the throw command that generates an Exception when your code encounters a problem.

This bit of code wraps the call to DoSomething() in a try...catch block so it will be notified of a problem.

```
try
{
    x.DoSomething();
}
catch (Exception ex)
{
    MessageBox.Show(e.Message);
}
```

The catch clause lets the calling program respond to the exception.

When the Exception is created, DoSomething() passes a string that will be available in the Message property of the Exception.

If there's a problem inside DoSomething(), the code will create a new instance of the Exception and use the throw command to send it back to its caller.

```
DoSomething()
{
    ...
    if (ThereIsAProblem == true)
        throw new Exception("There's a problem");
}
```

The throw command sends the Exception object back to the calling program.
