## WHAT HAPPENS WHEN?

What's the result of this equation?

![](img/1dcd2af4ae4fa0eb5cf4ed5437ff121a_171_0.png)

Did you say 20 or 14? Depends on whether you did the multiplication or the subtraction first. If you typed the equation into a calculator, you probably said 20, because calculators always evaluate left to right. But in C# the answer is 14, because C# evaluates expressions according to a specified precedence, and multiplication precedes subtraction.

You can look up the detailed rules of operator precedence in MSDN (search for “C# Operators”), but best practice is to use parentheses to disambiguate an equation. The part of the equation inside the parentheses is always executed first:

## PUT ON YOUR THINKING HAT

You can't always ignore the rules of precedence completely. What do you think the values of x, y and z are after this code executes?

```
Int32 x = 1;
Int32 y = 5;
Int32 z;

z = x++ * --y;
```

## HOW'D YOU DO?

After the code is executed, x is equal to 2, y is equal to 4, and z is equal to 4. Don't worry if you said z was equal to 8. Hardly anybody gets that last one right, so let's look at how it happened.

The trick here is when the increment and decrement operations are executed, which is controlled by whether they're placed before or after the variable they operate on, which in turn controls their operator precedence. Let's walk through it:

- 1. The -- operator is placed before its operand y, so it is evaluated first, giving y the value of 4.
- 2. The multiplication operator, *, has the second priority, so it's evaluated next. The variable x is still equal to 1, so 4 * 1 = 4.
- 3. The ++ operator is placed after the variable x, which gives it the lowest precedence of this set, so it's evaluated last, giving x the value of 2.
- 4. Since the assignment operator, =, has the lowest level of precedence, the result of step 2 is assigned to the variable z, giving it the value 4.

```
z = x++ * --y;
```

This expression was executed right to left, but you can't assume that's true. If you want my advice, don't assume anything. Just use parentheses to make your meaning clear.

## BEGINNING BOOLEANS

An important type of expression, one you'll probably use a lot in your work, is a Boolean expression. Boolean expressions use relational or logical operators and return the values true or false. Be careful of the capitalization. Of the two, the relational operations are the simplest. They return true or false based on the relationship of two values:

Notice the two equals signs here. A single equals sign is the assignment operator; two of the symbols is a test for equality.

| op | Meaning | True Example | False Example |
|---|---|---|---|
| < | "less than" | 1 < 2 | 2 < 1 |
| <= | "less than or equal to" | 2 <= 2 | 4 <= 2 |
| > | "greater than" | 2 > 1 | 2 > 2 |
| >= | "greater than or equal to" | 3 >= 3 | 1 >= 2 |
| == | "is equal to" | 1 == 1 | 1 == 2 |
| != | "is not equal to" | 1 != 2 | 1 != 1 |

In C#, the exclamation point means "not"

### A BIT OF HISTORY

Boolean expressions and the Boolean values true and false are named after George Boole, the Victorian mathematician and logician who developed symbolic logic in the 1840s.

## BEING LOGICAL

The second category of Boolean operators is the logical operators that compare Boolean values.

| op | Meaning | True Example | False Example |
| :--- | :--- | :--- | :--- |
| & | "and" -- both are true | true & true | true & false |
| \| | "or" -- either are true | true \| anything | false \| false |
| ^ | "exclusive or" -- only one is true | true ^ false | true ^ true |
| && | "conditional and" -- stop if the first operand is false | true && true | false && anything |
| \|\| | "conditional or" -- stop if the first operand is true | true \|\| anything | false \|\| false |
| ! | "not" | !false | !true |

### CONDITIONAL OPERATORS & SIDE EFFECTS

To understand the conditional operators, consider the following snippet of code:

```
Int32 x = 1;
Int32 y = 5;
Boolean a;

a = (x < y) || (x++ < y);
```

What's the value of x after this code executes? You might expect it to be 2, because of the increment operator. But || is a conditional or. It doesn't evaluate the expression to the right(x++ < y) unless the result of the one to the left is false. Since x is indeed smaller than y, (x < y) is true, so the compiler never looks at the increment operator.

Confused? Probably; it's confusing. Incrementing x in that equation is called a SIDE EFFECT. (Means the same thing in programming as it does in spoken English.) Side effects are inherently confusing, and you should avoid them. They'll happen by accident sometimes (and I can almost guarantee you won't enjoy tracking down that bug), but it's considered very poor practice to create them on purpose because they're never necessary and it doesn't matter how many comments you write, they're just too hard to understand.
