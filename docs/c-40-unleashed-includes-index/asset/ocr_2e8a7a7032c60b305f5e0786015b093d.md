FIGURE 15.34 Arrays are covariant in .NET.

Intuitively, when drawing a diagram as the one shown here, if the subtyping arrows on both sides go in the same direction, we discuss covariance. In other words, when the type construction (in here the use of [] on a type to construct an array type over it) preserves the subtyping relationship, it is covariant. You can guess what contravariance will look like, but ignore that for now.

But there’s a problem with the covariant treatment for array types. Do you recall the title of this section? It implies somehow that array covariance is broken. What does this mean? In short, there’s no compile-time safety when treating arrays as covariant, so the runtime must introduce additional checks to ensure type safety. If it’s unsafe, the obvious concern is where things can go wrong. Let’s see:

```
```csharp
Apple[] apples = new Apple[] { apple1, apple2, apple3 };

// Because of array type covariance we can write the following.
Fruit[] fruits = apples;

// We're putting a Coconut, which is a Fruit, in a Fruit array. This is fine.
fruits[2] = new Coconut();
```
