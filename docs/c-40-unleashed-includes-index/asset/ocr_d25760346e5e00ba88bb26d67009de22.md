# REPEATED DISPOSAL SHOULD BE ALLOWED

It's a good practice to allow multiple Dispose calls because there may be multiple code paths that double, triple, and so on release an object. Every Dispose call beyond the first one should be a no-op. Such a Dispose method is said to be "idempotent."

Although this is already better, we're still in trouble. No matter how much you believe in the goodwill of mankind, there will be developers who forget to dispose the Job object. In such a case, you still don't want to leak the acquired handle if the object is no longer reachable by code. To accommodate for this eventuality, you want to put a finalized in place, too.
