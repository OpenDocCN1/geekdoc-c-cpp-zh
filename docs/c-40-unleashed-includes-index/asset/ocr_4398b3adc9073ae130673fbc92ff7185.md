The Foo.Point type specified for the field in the Program class now becomes a problem to resolve, as illustrated in Figure 24.15.

One way to resolve this is by changing the alias being used. Alternatively, the use of aliases can help here, too. In fact, the problem is of a syntactical nature, where the use of the . operator has different meanings. One is to dot off a type name (for example, into static members), whereas another is to dot into namespace hierarchies possibly using aliases. Replacing the . with a namespace alias qualifier using :: will resolve the issue:

```
class Program
{
    public Foo::Point point;
}
```

In short, namespaces help a lot with the logical organization of types in a hierarchical manner, but you should be prepared to resolve some remaining clashes using a variety of techniques as described here.
