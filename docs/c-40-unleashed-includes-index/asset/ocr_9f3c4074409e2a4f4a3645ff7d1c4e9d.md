Another way to deal with event logs is to create a component, as shown in Figure 27.8. Components are just classes that derive from a common component base class, which provides a few benefits. One is the ability to remote such objects through .NET Remoting; another is the design-time story in the Visual Studio IDE. We'll ignore the first aspect and just show the use of the component designer in Figure 27.9.

Using the log can be done now by exposing the private field created for the EventLog instance (for example, through a property) or by providing specialized wrappers. Other parts of your application leverage the component (which can be remoted, allowing it to support more-complex application architectures) to do all sorts of instrumentation actions, such as logging.
