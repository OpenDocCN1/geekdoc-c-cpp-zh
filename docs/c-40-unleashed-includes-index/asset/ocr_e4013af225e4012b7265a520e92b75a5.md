# THE "DEVELOPER-DESIGNER" MANTRA

The use of partial classes in Windows Forms 2.0 and later could be seen as the first split between the developer's and UI designer's orthogonal concerns. If it were possible to hand out the .Designer.cs file to a designer who could open this file in a fancy UI designer tool to stylize the look and feel, that person would never have to see the event handler code written by his colleague developer.

Unfortunately, the C# language is not an ideal way to express UI definitions, from the designer's point of view at least. Not just that, but this definition depends on the programming language chosen by the developer: In a Visual Basic project, the Windows Forms designer emits Visual Basic code for the second half of the partial class. Specialized markup languages unify UI definitions back into a single language and are perceived to be easier for use by designers. And that's where XAML in WPF come in.
