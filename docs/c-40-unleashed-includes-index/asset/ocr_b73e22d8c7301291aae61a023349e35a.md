# Win32

In the world of Win32, integer values were used to indicate errors produced by functions. This already introduces a problem: The meaning of a plain integer is not very clear by just looking at it. Instead, symbolic constants need to be introduced to make program code look more meaningful. Furthermore, those error codes need to be queried for manually after failed function calls using the GetLastError function. An example of such a function call, followed by error “handling,” is shown here:

```
```cpp
HWND hWindow = CreateWindowEx(0, g_szClassName, L"Hello Win32",
                              WS_OVERLAPPEDWINDOW, 100, 200, 300, 400,
                              NULL, NULL, hInstance, NULL);
if (NULL == hWindow) {
    dwError = GetLastError();
    // Analyze the error and handle appropriately or propagate to caller.
}
```
```

Combined with manual resource management, propagation of errors typically leads to the use of goto statements to jump to an epilogue in the containing function where proper release of acquired resources is done (for example, using CloseHandle and delete):

```
```cpp
int ShowStartDialog() {
    int dwError = 0;

    // More code goes here

    if (NULL == hWindow) {
        dwError = GetLastError();
        // Analyze the error and handle appropriately if possible.
        goto Exit; // Too bad, couldn't handle it meaningfully...
    }

    // More code goes here

Exit:
    if (hSomeResource != NULL) {
        CloseHandle(hSomeResource);
        hSomeResource = NULL;
    }

    // Release other resources.

    return dwError;
}
```
