On the level of the runtime, this guarantee is nice to have. But in higher-level languages, it's better for the user to be explicit about things. Zero (or the null reference) might be a good default value, but it might not be. For that reason, the seemingly equivalent C# code does not compile, resulting in the error shown in Figure 5.28:

```
using System;

class Zero
{
    static void Main()
    {
        int x;
        Console.WriteLine(x);
    }
}
```

To make the preceding code compile fine, you need to write the following where the intent is unambiguously expressed by the user:

```
using System;

class Zero
{
    static void Main()
    {
        int x = 0; // Or, in case the original code had a bug, another value...
        Console.WriteLine(x);
    }
}
```
