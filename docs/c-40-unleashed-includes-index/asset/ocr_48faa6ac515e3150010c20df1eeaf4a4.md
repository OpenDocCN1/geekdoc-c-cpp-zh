Starting with C# 2.0, it's possible to specify an alias in front of an assembly passed to the /reference (shorthand /r) flag. This is known as an extern alias:

```
csc /r:X=Assembly1.dll /r:Y=Assembly2.dll File1.cs File2.cs
```

In the preceding example, referring to namespaces and types inside Assembly1.dll can be abbreviated using X, while those in Assembly2.dll are accessible using alias Y. Inside Visual Studio, you can specify extern aliases from the Properties pane for a selected referenced assembly. This is illustrated in Figure 24.13.

![](bbox=[0.08, 0.39, 0.38, 0.62])

The default value for the Alias property is global, which has a corresponding keyword allowing reference to it. To traverse an alias followed by a namespace name, you use the :: operator, as shown here:

```
global::System.Collections.Generic.IEnumerable<int> numbers = ...;
```

Obviously, the global alias specification can be omitted unless we're trying to resolve a conflict. In our preceding example, we're faced with a conflict for the Bar.Foo type across two assemblies. Assuming we've configured the aliases as X and Y, we can now import those aliases in a code file using the extern keyword:

```
extern alias X;
extern alias Y;
```

Given those two alias imports, we can write the following:

```
var fooFromX = new X::Bar.Foo();
var fooFromY = new Y::Bar.Foo();
```
