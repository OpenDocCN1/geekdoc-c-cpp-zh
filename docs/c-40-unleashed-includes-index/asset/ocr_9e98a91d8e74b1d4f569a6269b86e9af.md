```
var x = Expression.Parameter(typeof(int), "x");
var f = Expression.Lambda<Func<int, int>>(
    Expression.Add(
        x,
        Expression.Constant(1)
    ),
    x
);
Calculate(f, 42);
```

Those factory method calls result in the creation of a data structure, at runtime, that represents the code of the lambda expression the user wrote as the first argument to the call to Calculate. In fact, this code could have been written manually in C# 2.0 (if the expression tree API would have been available in the BCL at that time), but it's clear you don't want to be involved in writing boilerplate code like this. Homoioconicity of lambda expressions allows you to generate expression trees by using exactly the same syntax for lambda expressions that can be used to create new delegate instances.
