## WR_MCP23S08 (register, databyte)

The WR_MCP23S08 function uses the spi_output function to write a byte of data to a SPI based Microchip I/O expander part number MCP23S08. The databyte can be written to a specific register location. The register value is based on the data sheet for the MCP23S08. The main registers are below:

**TABLE 1-2: REGISTER ADDRESSES**

| Address | Access to: |
|---|---|
| 00h | IODIR |
| 01h | IPOL |
| 02h | GPINTEN |
| 03h | DEFVAL |
| 04h | INTCON |
| 05h | IOCON |
| 06h | GPPU |
| 07h | INTF |
| 08h | INTCAP (Read-only) |
| 09h | GPIO |
| 0Ah | OLAT |

The value entered in the register location is written in hex form (i.e. 0x04 for the INTCON register). The WR_MCP23S08 function also offers a few nicknames for the most common three registers so you can use these names in place of the actual address value:

- IODIR // Data Direction Register Address 0x00
- OLAT // Output Latch Register Address 0x0A
- GPIO // Port Register Address 0x09

![](img/910b145bee7ca8076318eafbe6d13997_63_0.png)

Special Note: Notice the function name is all capitals. This is because this function is a SPI specific routine for a particular component.

Example:

```c
void main(void)
{
 init_micro();
 spi_init();
 WR_MCP23S08 (IODIR, 0x01);   // Setup pins
 while (1==1)
 {
   char y = 1;
   y = RD_MCP23S08 (GPIO); // Read switch
   y = y & 0x01;           // Mask all but bit 7
   if (y==0)
   {WR_MCP23S08 (OLAT, 0x40);} // If switch idle light LED
   else
   {WR_MCP23S08 (OLAT, 0x80);} // If switch pressed LED off
   pause(10);
 } //End While
} //End Main
```

## I2C Communication

As I showed in the previous chapter, I2C communication is useful for communicating with external circuitry. The I2C peripheral shares many of its communication I/O with the SPI peripheral on the PIC16F886. Therefore you will use either SPI or I2C but not both at the same time. These SimpleC functions make it easier to use the I2C peripheral.

### i2c_init()

The i2c_init function sets up the i2c port for serial communication as a master. The i2c connections are preset in the peripheral. Pin 4 (C3) is the clock, pin 3 (C4) is the data line. In order to use the i2c peripheral, the i2c_init must be at the top of your main loop.

Example:

```c
#include <simplec_1.0.h>

void
main(void)
{
init_micro();    // Initialize I/O
i2c_init();      // Initialize i2c
PORTB=0x00;      // All LEDs off
TRISB=0x00;      // All PORTB outputs
```

### i2c_restart()

The i2c_restart() function is used to send a new start bit in the i2c signal. This is used at the beginning of a new i2c communication message. This is commonly used when the first start bit is used to send a message requesting data to be sent back. The example below shows this function used in one of the SimpleC library functions.

Example:

```c
unsigned char I2C_EEIN(unsigned char address)
{
unsigned char data;
i2c_start();
i2c_write(0xa0);
i2c_write(address);
i2c_repStart();
i2c_write(0xa1);
data=i2c_read(0);
i2c_stop();
return(data);
}
```

### i2c_stop()

The i2c_stop() function is used to send a stop bit at the end of the i2c signal. This is used to indicate the end of the i2c communication message. The example below shows this function used in one of the SimpleC library functions.

Example:

```c

i2c_repStart();

```

### I2C_EEIN ( address )

The I2C_EEIN() function is used to receive data from a Microchip I2C serial EEPROM. It is written to specifically read from those parts with an 8-bit address.

Example:

```c
#include <simplec_1.1.h>

void
main(void)
{
    init_micro();        // Initialize I/O
    i2c_init();          // Initialize i2c
    PORTB=0x00;          // All LEDs off
    TRISB=0x00;          // All PORTB outputs

    unsigned char cnt=0;

    while(cnt<=10)  /* write 10 numbers to eeprom */
    {
        PORTB=cnt;        // The cnt value will display on the LEDs
        I2C_EEOUT(cnt,10-cnt);  // Store 9 at address 1, 8 at address 2, ...
        cnt=cnt+1;        // Increment cnt variable
        pause(255);       // Delay 255 milliseconds
    }

    cnt=0;

    while(cnt<=10)
    {
        PORTB=I2C_EEIN(cnt); // Display data read from EEPROM on LEDs in binary
        pause (1000);        // Delay for 1 second to read LEDs
        cnt=cnt + 1;         // Increment cnt variable
    }
}
```

## simplec1.1.h – How it Works

The header file contains the common elements every project should have. Let me go through this file in detail. First a description of the header and then the include files. The htc.h file is included and required for the HI-TECH compiler. The stdio.h file which is a standard input/output header file for an internal HI-TECH library. The stdio library handles the printf function along with the getch and putch functions.

```c
/*
 * Library of common functions
 * For the readers of the Beginner's Guide to Embedded C book series
 * by Chuck Hellebuyck
 * Copyright 2010
 * Version 1.1 - Written for Chipino with 16F886
 */

#include <htc.h>
#include <stdio.h>
```

The configuration settings for the PIC16F886 are included next. These set the various features for the CHIPINO module. The CHIPINO uses a 16 MHz crystal so the HS mode is selected. The watchdog timer is off and the external reset is enabled on the MCLR pin. The code is unprotected and the low voltage programming mode is disabled since the CHIPINO is programmed with a PICkit 2. The PIC16F886 can have the internal oscillator run if the 16 MHz crystal should fail but that option is turned off with the config settings. The CONFIG1 register section of the data sheet is shown below the __CONFIG line for reference.

```c
__CONFIG (HS & WDTDIS & MCLREN & UNPROTECT & LVPDIS & IESODIS & FCMDIS);
```

The configuration settings for the PIC16F886 are listed in the data sheet and that is reproduced on the next page. The actual settings used by the compiler come from the PIC16F887.h file in the HI-TECH compiler include directory. That header file is called from the htc.h file included at the top of the SimpleC1.1.h file.
