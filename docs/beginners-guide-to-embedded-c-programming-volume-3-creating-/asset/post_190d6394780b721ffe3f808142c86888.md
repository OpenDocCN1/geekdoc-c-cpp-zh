
A stop bit is similar. Using the i2c_stop() function, it waits for bus idle before sending the bit.

```c
//***********************************************
void i2c_stop()
{
    i2c_waitForIdle();
    PEN=1;
}
```

The heavy work of the I2C is sending and receiving the bytes. The receive portion is handled by the i2c_read() function. It issues an ACK bit if the ack parameter is zero.

```c
//***********************************************
int i2c_read( unsigned char ack )
{
    unsigned char i2cReadData;
    i2c_waitForIdle();
    RCEN=1;
    i2c_waitForIdle();
    i2cReadData = SSPBUF;
    i2c_waitForIdle();
    if ( ack )
    {
        ACKDT=0;
    }
    else
    {
        ACKDT=1;
    }
    ACKEN=1;      // send acknowledge sequence
    return( i2cReadData );
}
//***********************************************
```

The i2c_write() function stores the parameter byte in the I2C peripheral buffer and then sends that byte. If an ACK bit is received, the function returns a 1 indicating a proper communication occurred.

```c
unsigned char i2c_write( unsigned char i2cWriteData )
{
    i2c_waitForIdle();
    SSPBUF = i2cWriteData;
    return ( ! ACKSTAT ); // function returns '1' if transmission is acknowledged
}
```

// ******************************************

Probably the most common use of I2C is communicating with EEPROM so I wrote the I2C_EEOUT() and I2C_EEIN() functions to handle this communication using the functions I previously described. You can use these as the format for future I2C communication as they are all very familiar.

```c
void I2C_EEOUT(unsigned char address, unsigned char data)
{
    i2c_start();
    i2c_write(0xa0);
    i2c_write(address);
    i2c_write(data);
    i2c_stop();
    pause(11);
}
```
