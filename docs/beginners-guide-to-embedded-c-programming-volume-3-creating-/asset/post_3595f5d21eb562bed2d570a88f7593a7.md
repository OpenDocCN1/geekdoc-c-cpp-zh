
The HI-TECH compiler already has some pre-built functions included in the stdio library which is automatically included during the compile time if the stdio.h file is included. One of those is the printf() function. This is described in the HI-TECH manual and can be used for all USART communication but I wanted a couple specific byte control functions for the SimpleC library as well. The first is putch() which is used to send an ASCII character out of the USART. The function makes sure the transmit buffer is empty and then fills it with the ASCII byte in the parameter section of the function header.

// ****************************************
// Send ASCII Character from Hardware USART
// ****************************************

void
putch(unsigned char byte)
{
    /* output one byte */
    while(!TXIF); /* set when register is empty */
    TXREG = byte;
}

The second is the receive byte getch() function that tests for data in the receive register and then returns the byte received from the function call. These make serial communication very easy.

// ****************************************
// Receive ASCII Character from Hardware USART
// ****************************************

unsigned char
getch()
{
    /* retrieve one byte */
    while(!RCIF); /* set when register is not empty */
    return RCREG;
}

Another form of communication is through the Serial Peripheral Interface (SPI), which is commonly used to talk to EEPROM, temperature sensors, I/O expanders and many more external peripheral chips. Using the hardware SPI can also be a bit confusing at first so having these routines in the library is helpful. The first is the setup function spi_init(). This function controls the SSPCON and the SSPSTAT register bits for 250 Khz SPI communication. This is not the fastest possible SPI speed but certainly a reliable SPI communication speed.

// ****************************************
// Hardware SPI Setup
// ****************************************

/* SPI Peripheral Setup */
void spi_init(void)
{
// *** 16F886 Settings ***
TRISC5 = 0; // SDO pin set to output
TRISC3 = 0; // SCK pin set to output (Master Mode)
TRISA5 = 0; // CS pin set to output

/* SSPCON Settings */
// *** FOSC = 4Mhz ***
// SSPCON = 0b00000001; // SPI Clock Frequency set to FOSC/16 = 250khz

// *** FOSC = 16Mhz ***
SSPCON = 0b00000010; // SPI Clock Frequency set to FOSC/64 = 250khz
CKP = 0; // Idle state of clock is low

/* SSPSTAT Settings */
SMP = 1; // Sampled at end of data pulse
CKE = 1; // Data Transfered on rising edge of clock

/* SPI Peripheral on */
SSPEN = 1; // Enable SPI peripheral
pause(1); // Allow SPI to Stabilize
}

The SPI peripheral will send a bit out the SDO pin (Master Out Slave In) while it clocks in data at the SDI pin (Master In Slave Out). Therefore one function can handle it all. SPI_OUTPUT() is that function and first stores the byte defined in the parameter section of the function inside the internal SPI buffer register. The SPI hardware will then automatically send out that byte and then receive a byte in the receive buffer. The function returns the byte received to the routine that called this function.

// ****************************************
// Hardware SPI Output
// ****************************************

char SPI_OUTPUT ( char spi_byte )
{
SSPBUF = spi_byte;
do {
}
while(!IBF);
return SSPBUF;
}

As I mentioned, SPI is often used to communicate with external EEPROM chips. The WR_BYTE() function was created to talk to a SPI based

// External I/O Expander Write
// ****************************************
void WR_MCP23S08 ( char regist, char data )
{
    char dummy;
    CS = 0;                     // Select MCP23S08 by pulling CS low
    dummy = SPI_OUTPUT ( 0x40 ); // Send Device Opcode, select Write mode
    dummy = SPI_OUTPUT ( regist ); // Send Register Address location
    dummy = SPI_OUTPUT ( data ); // Send Data byte
    CS = 1;                     // Release EEPROM to allow byte to be written
}

Reading from the MCP23S08 is completed with the RD_MCP23S08 () function.

// ****************************************
// External I/O Expander Read
// ****************************************

char RD_MCP23S08 ( char regist )
{
    char dummy;
    CS = 0;                     // Set chip select low
    dummy = SPI_OUTPUT (0x41); // Send Device Opcode, select Read mode
    dummy = SPI_OUTPUT (regist); // Send Address
    char data = SPI_OUTPUT ( 0x00 ); // Receive data byte
    CS = 1;                     // Bring chip select high to terminate
    return data;
}

*Special Note: Notice that I used all capital letters for the special SPI functions. I did this to separate part specific functions from the generic library functions. When you use these, make sure you use capital letters.*

One of the more popular requests I received from the previous books was a simpler way to control the hardware PWM port. The PIC16F886 has two of them so I created two PWM functions; pwmout1 () and pwmout2 (). The parameters of the function define the duty cycle and the frequency. Since both PWM’s must use the same clock source on the PIC16F886, they have to have the same frequency. All the register settings are handled in the function so you don’t need to issue a pwm_init function. Once turned on though, the PWMs continue to run. If you want to shut them off you place a CCP1CON = 0 to shut off PWM 1 and CCP2CON = 0 to shut off PWM 2.

// ****************************************
char adcin (char chan)
{
switch(chan)
{
case 0:
    TRISA0 = 1;            // Make RA0/AN0 an Input
    ANS0 = 1;              // Configure RA0 to Analog to Digital input
    ADCON0 = 0b11000000;   // Configure A/D to use AN0, left justified
    break;

case 1:
    TRISA1 = 1;            // Make RA1/AN1 an Input
    ANS1 = 1;              // Configure RA1 to Analog to Digital input
    ADCON0 = 0b11000100;   // Configure A/D to use AN1, left justified
    break;

case 2:
    TRISA2 = 1;            // Make RA2/AN2 an Input
    ANS2 = 1;              // Configure RA2 to Analog to Digital input
    ADCON0 = 0b11001000;   // Configure A/D to use AN2, left justified
    break;

case 3:
    TRISA3 = 1;            // Make RA3/AN3 an Input
    ANS3 = 1;              // Configure RA3 to Analog to Digital input
    ADCON0 = 0b11001100;   // Configure A/D to use AN3, left justified
    break;

case 4:
    TRISA5 = 1;            // Make RA5/AN4 an Input
    ANS4 = 1;              // Configure RA5 to Analog to Digital input
    ADCON0 = 0b11010000;   // Configure A/D to use AN4, left justified
    break;

default:
    break;
}

ADON = 1;                // A/D Converter on;
GODONE = 1;              // Start A/D conversion on AN0
pause(1);               // Sample Time
while(GODONE == 1);      // Wait for conversion to complete
char value = ADRESH;
return value;
}

In the first chapter I showed how to use the I2C peripheral. Those functions are now part of the SimpleC library. The first is the i2c_init ().
// ****************************************
// Hardware I2C single master routines for PIC16F886
// for HI-TECH PIC C COMPILER.
//
// i2c_init - initialize I2C functions
// i2c_start - issue Start condition
// i2c_repStart- issue Repeated Start condition
// i2c_stop - issue Stop condition
// i2c_read(x) - receive unsigned char - x=0,
// don't acknowledge - x=1, acknowledge
// i2c_write - write unsigned char - returns ACK
//
//**********************************************************
void i2c_init()
{
TRISC3=1;      // set SCL and SDA pins as inputs
TRISC4=1;
SSPCON = 0x38;  // set I2C master mode
SSPCON2 = 0x00;
// Formula for SSPADD register value: SSPADD = [(Fosc/4)/BitRate] - 1
SSPADD = 0x27;   // 100K at 16Mhz clock
                 // [(16Mhz/4)/100khz]-1 = 39 or 0x27 hex

SMP=1;           // disable slew rate control for 100khz operation
SSPIF=0;         // clear SSPIF interrupt flag
BCLIF=0;         // clear bus collision flag
}

You have to make sure the I2C bus is ready for transmit or receive so a function to test the status bits is handled with the i2c_waitForIdle routine.

//**********************************************************
void i2c_waitForIdle()
{
while ((SSPCON2 & 0x1F ) | RW ){}; // wait for idle and not writing
}

An I2C start bit is created with the i2c_start( ) function.

//**********************************************************
void i2c_start()
{
i2c_waitForIdle();
SEN=1;
}

An I2C repeat start bit is created with the i2c_repstart( ) function.

//**********************************************************
void i2c_repStart()
{
i2c_waitForIdle();
RSEN=1;
}
