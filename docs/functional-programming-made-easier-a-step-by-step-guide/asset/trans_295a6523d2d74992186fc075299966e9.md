

```purescript
toString :: Int -> String
toString n = show n

toArray :: String -> Array String
toArray s = [s]

intToStringArray :: Int -> Array String
intToStringArray n = toArray (toString n)
```

- 1. `toString` 将 `Int` 映射到 `String`，即 给这个函数一个 `Int` 它就会返回一个 `String`。
- 2. `toArray` 将 `String` 映射到 `Array String`，即 给定一个 `String` 它会返回一个 `String` 数组。
- 3. 将 `Int` 映射到 `Array String`。
- 4. `intToStringArray` 是 `toString` 和 `toArray` 的手动组合。注意它如何接收一个 `Int` 并使用 `toString` 生成一个 `String`，然后将该 `String` 传递给 `toArray`，`toArray` 生成一个 `Array String`，即我们的返回值。

让我们使用 PureScript 的组合运算符 `<<<` 重写 `intToStringArray`：

```purescript
intToStringArray :: Int -> Array String
intToStringArray = toArray <<< toString
```

这里我们使用 `<<<` 组合了 2 个函数。注意组合运算符如何提醒我们函数组合像数学一样从右到左工作。但在 PureScript 中，与数学不同，我们也可以使用 `>>>` 从左到右进行组合。

让我们回顾一下上面简化的数学定义：

```text
f : Y → Z, g : X → Y ⇒ f ∘ g : X → Z
```

注意 `g` 的 **输出** 与 `f` 的 **输入** 匹配。如果 `toString` 的输出类型与 `toArray` 的输入类型不匹配，PureScript 编译器会给出错误。

为了帮助展示代码如何契合，请看以下代码：

```purescript
toString :: Int -> String
toString n = show n

toArray :: String -> Array String
toArray s = [s]

intToStringArray :: Int -> Array String
intToStringArray = toArray <<< toString
```

并以图示方式显示它：

![](img/8c0e9b687c62642e828ccb5481e11313_60_0.png)

`toString` 接收一个 `Int` 并输出一个 `String`，这是 `toArray` 的输入，`toArray` 输出 `Array String`。

组合 `toArray <<< toString` 给出我们 `intToStringArray`，它接收一个 `Int` 并生成一个 `Array String`。

函数组合是函数式语言的强大特性，在大多数函数式代码库中经常使用。Haskell 使用 `.` 运算符来模仿数学中的 `∘`，而 PureScript 使用 `<<<` 运算符来帮助我们记住数学中的组合是从右到左的：

```purescript
notLarge :: Int -> Boolean
notLarge = not <<< isLarge
```

> ❶ 在这个例子中你不需要使用 `<<<` 与 `not`。它只是作为示例使用。代码本可以只是 `not isLarge`。

PureScript 还提供了 `>>>` 运算符，当我们想反向组合时使用。这通常是因为代码读起来更好。在上面的例子中，使用 `<<<` 读起来更好。随着学习的深入，我们会看到 `>>>` 更可取的例子。

## 2.4.1. 无点记法

注意我们的 notLarge 函数没有正式定义的 参数。这是因为它以一种称为无点 的形式编写。

> 无点记法 或 风格 意味着函数是在 未显式提及一个或多个参数 的情况下定义的。

我们可以通过显式提及参数来编写 notLarge，但现在我们有命名和记住它们的负担：

```
notLarge :: Int -> Boolean
notLarge num = not (isLarge num) -- NOT Point-free
```

这个版本不如我们的无点版本易读。编写函数的无点版本并不总是使函数更易读，但当它确实如此时，绝对值得去做。

大多数命令式语言没有对组合或无点记法的直接支持。例如，在 Javascript 中，notLarge 必须写成：

```
const notLarge = num => not (isLarge num);
```

将其与我们的 PureScript 无点版本进行比较：

```
notLarge :: Int -> Boolean
notLarge = not <<< isLarge
```

无点版本读起来像英语（notLarge 是 not <<< isLarge）。这就是我选择使用 <<< 而不是 >>> 的原因，后者读起来是反的（isLarge >>> not）。

现在，假设你写了以下函数，用零在左侧填充字符串到指定大小：

```
zeroPad :: Int -> String -> String
zeroPad size s = padLeft '0' size s
```

是否可以将此函数重写为无点？size 和 s 在等号两边都出现这一事实应该表明这是可能的。

如果你看不出如何以无点方式编写它，那么添加冗余的括号可能会有所帮助：

```haskell
zeroPad :: Int -> String -> String
zeroPad size s = (padLeft '0') size s
```

如果我们将函数视为一个简单的等式，我们可以看到 (padLeft '0') 等于 zeroPad，给出：

```haskell
zeroPad :: Int -> String -> String
zeroPad = padLeft '0'
```

现在我们有了无点的 zeroPad。它也读起来更好（zeroPad 是 padLeft with 0）。

注意我们没有触及签名。这是因为函数仍然接收这些参数。它们只是未命名的参数。

有一种更简单的方法来看待这种简化，我称之为 **右侧抵消：**

```haskell
zeroPad :: Int -> String -> String
zeroPad size s = padLeft '0' size s
```

首先，注意 s 是等号两边最右边的参数。这意味着我们可以从等式两边抵消它：

```haskell
zeroPad :: Int -> String -> String
zeroPad size = padLeft '0' size
```

现在 size 是等号两边最右边的参数，所以我们也抵消它：

```haskell
zeroPad :: Int -> String -> String
zeroPad = padLeft '0'
```

由于等式左侧不再有参数，zeroPad 处于最简化的无点形式。

```
zeroPad :: String -> Int -> String
zeroPad s size = padLeft '0' size s
```

在这种情况下，我们将无法简化，因为 size 是等式左侧最右边的参数，而 s 是右侧最右边的。就像代数一样，我们不能用另一边的 s 抵消一边的 size。

在编码时，我经常会改变参数的顺序以允许这种抵消，从而帮助减少函数定义的复杂性。

## 2.5. 柯里化

你还记得函数式编程语言的一个限制是所有函数只接受 1 个参数吗？好吧，这个限制来自于由数学家 Haskell Curry 创建的 Lambda 演算。

在 Lambda 演算中，函数只能接受一个参数。它们以以下数学符号编写：

```
λx. x + 1
```

在 PureScript 中，我们会写成：

```
\x -> x + 1
```

注意 \ 有点像 Lambda，λ。 . 被替换为 ->，但思想是相同的。

在两种情况下，这都定义了一个匿名函数，它接受一个参数并加 1。

如果我们的函数只能接受一个参数，我们如何在 Lambda 演算中编写一个加两个数的函数？

别忘了函数可以返回其他函数：

```
λx. λy. x + y
```

这是 PureScript 的等价物：

```
\x -> \y -> x + y
```

当这个函数被 3 调用时：

```
(\x -> \y -> x + y) 3
```

值 3 绑定到变量 x 并返回以下函数：

```
\y -> 3 + y
```

当我们用 5 调用这个返回的函数时：

```
(\y -> 3 + y) 5
```

值 5 绑定到 y 返回：

```
3 + 5
```

由于 + 是一个函数，它返回：

```
8
```

在 PureScript（以及 Haskell 和 Elm）中我们可以写：

```
\x y -> x + y
```

虽然这在 Lambda 演算中是非法的，但在编程中，我们能够定义多个参数以减少视觉复杂性。当我们之前说所有函数式编程中的函数只接受单个参数时，这怎么可能。

这就是 *柯里化* 的作用。柯里化将一个函数如：

```
\x y -> x + y
```

转换为一个函数如：

```
\x -> \y -> x + y
```
