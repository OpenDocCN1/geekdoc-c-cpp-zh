  Nothing -> catMaybes xs

- ② Notice that I used y for the Value in the Just. I didn’t want to call it x as that would shadow the previous x in the Pattern Match and case expression.

## 5.33. Optimizing range

You might have written range as follows:

```
range :: Int -> Int -> List Int
range start end =
  let step = if start < end then 1 else (-1) in ①
  if start == end then singleton start
  else start : range (start + step) end
```

- ① The intent is to do this calculation only once.

If the intent of writing it this way was to do the step computation only once, then it actually doesn’t accomplish that. Since this Function is recursive, it will recalculate that value each call.

This is a common practice when you are writing loops in Imperative Languages. Typically, you would do this calculation before starting the loop. But for recursion, we have to make sure it’s out of the recursive calls, which did not happen here.

Now, it’s possible that the compiler can do some magic and optimize this repeated computation out, but I highly doubt it since start changes for every recursive call (it’s either incremented or decremented).

In reality, the overhead of the step computation is so minor that it’s not worth doing. But just for argument’s sake, let’s suppose it’s a far more expensive computation. How would we optimize this?

Think about it and give it a go before reading on.

We want to compute step only once and we want to keep it out of the recursive calls:

```
range :: Int -> Int -> List Int
range start end = go (if start < end then 1 else (-1)) start where ①
  go step start' | start' == end = singleton start' ②
                | otherwise      = start' : go step (start' + step) ③ ④
```

- ① Compute the step value only once and pass it to the first call to go.
- ② Had to name this variable start' so it wouldn’t shadow start.
- ③ The recursion only happens in our go Function where we pass in the step value, as opposed to computing it each time.
- ④ Make sure to import otherwise from Prelude if you haven’t already.

You may have thought to use a let-in expression so you wouldn’t have to pass in step:

```
-- DOES NOT COMPILE
range :: Int -> Int -> List Int
range start end = let step = if start < end then 1 else (-1) in go start
  where
  go start' | start' == end = singleton start'
            -- COMPILER ERROR!!
            | otherwise      = start' : go (start' + step) ①
```

- ① step is NOT in scope here.

Remember that the let values are only in scope for the in section, which terminates at the where.

But we can accomplish this by moving our step calculation to where section:

```
range :: Int -> Int -> List Int
range start end = go start where ①
  go start' | start' == end = singleton start'
            | otherwise      = start' : go (start' + step)
  step = if start < end then 1 else (-1) ①
```

- ① We no longer have to pass step to go since step is now in scope for go since they are both in the where section.

Now, even though we’ve optimized to this point, we still don’t have a Tail Recursive Function.

Let’s make that final optimization:

```
range :: Int -> Int -> List Int
range start end = go Nil start where ①
  go rl start' | start' == end = start' : rl ②
               | otherwise      = go (start' : rl) (start' + step) ③
  step = if start < end then 1 else (-1)
```

- ① Pass in an empty List as our starting point. It’s called rl in the go Function. It stands for Range List
- ② The base-case adds start' to the Range List.
- ③ In this version, we add to the list before we recurse, which makes this Tail Recursive.

## 5.34. Writing take

Everything you need to know to write this we’ve done before. So, try to write this before looking at the hint.

### 5.34.1. Hint for take

take needs to keep track of how many items it’s taken so it knows when it’s done. This would require a go Function, but maybe by using the number of elements to take as a countdown, we can avoid keeping track of any extra state and avoid the need for a local Function.

### 5.34.2. Code for take

Type Signature:

```
take :: ∀ a. Int -> List a -> List a
```

Next, the base-case:

```
take :: ∀ a. Int -> List a -> List a
take ??? ①
```

- ① Turns out there are 2 base-cases.

We actually have 2 base-cases. One when the countdown reaches 0 (or is initially 0) and the other when the List is emptied (or is initially empty):

```
take :: ∀ a. Int -> List a -> List a
take _ Nil = Nil
take 0 _   = Nil
```

Finally, the recursive case:

```
take :: ∀ a. Int -> List a -> List a
take _ Nil      = Nil
take 0 _        = Nil
take n (x : xs) = x : take (n - 1) xs ① ②
```

- ① Add (-) to your Prelude import list.
- ② This is NOT Tail Recursive since we need to return back here after the recursive call to add x to the head of the List.

In a lazy language like Haskell, this implementation would be fine since the take (n - 1) xs won’t be evaluated until it’s needed, if ever, so we get some optimization through laziness. But PureScript is a strict language, meaning that everything is evaluated up front. So, we have to worry about Stack usage for extremely large Lists.

Try to rewrite this to be Tail Recursive before looking at the solution.

Writing take as a Tail Recursive Function is just an exercise. I would normally just leave the Function as it is, since the chances of overflowing my Stack is extremely rare for the kinds of programs I write.

But it’s nice to be able to solve the problem if we ever encounter it:

```
take :: ∀ a. Int -> List a -> List a
take = go Nil where ① ④
  go nl _ Nil     = nl ②
  go nl 0 _       = nl ③
  go nl n (x : xs) = go (x : nl) (n - 1) xs -- WRONG ORDER!! ④
```

- ① This is written Point-free. The Parameters not named here are the number of items to take and the List. We initially call go with an empty List called nl.
- ② If we exhaust the List or initially get an empty List, then return our new List, which could be Nil.
- ③ If we exhaust our count or initially get a count of 0, then return our new List, which could be Nil.
- ④ To make this Tail Recursive, we wind up building the List backwards.

Here’s the correct version using reverse:

```
take :: ∀ a. Int -> List a -> List a
take n = reverse <<< go Nil n where ① ② ③
  go nl _ Nil     = nl
  go nl 0 _       = nl
  go nl n' (x : xs) = go (x : nl) (n' - 1) xs ④
```

- ① We had to add the n Parameter back since Functional Composition, <<<, expects Functions of one Parameter.
- ② We call reverse on the final result. We are trading Time for Space here. We’re using a Tail Recursive Function because we don’t have enough space in our Stack. So, we must spend Time reversing the List at the end.
- ③ Don’t forget to import (<<<) from Prelude if you haven’t already.
- ④ Had to rename n to n' so it wouldn’t shadow the Parameter n.

One thing to note here is that if you pass in a negative number for the count, this will infinitely recurse and overflow the Stack. Let’s fix that.

First, we’ll fix the non-Tail Recursive version:
