# 5.24. Writing findLastIndex

This is similar to findIndex, except that it finds the last index that fulfills the Predicate condition. Keep in mind that just because findLastIndex found an index doesn’t mean that it stops. findLastIndex needs to keep looking because there’s always a chance that there’s another match later in the List.

Many times, creating a simple examples to use as you code helps immensely. Let use the following Predicate:

```
(_ == 10)
```

Here are a few examples to keep in mind while coding findLastIndex:

```
Nil
10 : 5 : 10 : -1 : 2 : 10 : Nil
11 : 12 : Nil
```

Let’s also use these examples in our test code:

```
log $ show $ findLastIndex (_ == 10) (Nil :: List Int) ① ②
log $ show $ findLastIndex (_ == 10) (10 : 5 : 10 : -1 : 2 : 10 : Nil) ③ ④
log $ show $ findLastIndex (_ == 10) (11 : 12 : Nil) ⑤
```

① Explicit Type for empty List of Int since Predicate wants an Int.

② Prints Nothing.

③ Make sure you have negate imported from Prelude or you’ll get an error regarding Unknown value negate. All negative numbers actually use negate under the covers. Notice that we don’t have to put -1 in Parentheses since it’s part of a Cons Binary Operator, i.e. :.

④ Prints (Just 5)

⑤ Prints Nothing.

Keep these examples in mind while writing this Function before you move on to get some hints. Also, don’t hesitate to look back at findIndex for help since it’s a similar Function.

# 5.24.1. Hint for findLastIndex

The basic difference between findIndex and findLastIndex is that findLastIndex has to keep searching even after an index has been found. That means that in findLastIndex, we have to keep track of the current index (like in findIndex) but we also must keep track of what was found previously if any.
