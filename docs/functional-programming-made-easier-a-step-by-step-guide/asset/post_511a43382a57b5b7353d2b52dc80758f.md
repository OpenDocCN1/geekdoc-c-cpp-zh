
# 30.16. Logoff Page

The Logoff Page will be a fairly simple. When we navigate to that Page, it will call our backend to log the user off and display a message letting the user know that they have successfully logged off. This message will be on the page, not a Modal. The page will also have a button for them to log back on. Clicking that button will take them back to the Logon Page.

The Logoff Page will also display a Modal if there are errors in the API call.

We have done all of this before and so we can steal layouts from ChangePassword Page and Modals from the Logon or Users Page.

And now, we’ll handle the Initialize Action by making the API call to log the user off by looking at what we did on the Users Page:

```
import Control.Monad.Reader.Class (class MonadAsk, ask) ①
import Data.Api.Logoff (LogoffRequest(..), LogoffResponse(..)
    , LogoffResults(..))
import Data.Either (Either(..))
import Effect.Ref as Ref
import Env (Env)
import Utils (apiCall)

component
  :: ∀ m
  . MonadAff m
  => MonadAsk Env m ②
  => Navigate m Route
  => H.Component Query Input Output m
component = H.mkComponent
  { initialState: \_ ->
    { loggedOff: false
    , errorMessage: Nothing
    }
  , render
  , eval: H.mkEval H.defaultEval
    { initialize = Just Initialize ③
    , handleAction = handleAction
    }
  }
where
handleAction :: Action -> H.HalogenM State Action Slots Output m Unit
handleAction = case _ of
  Initialize -> do ④
    { userRef } <- ask
    loggedOnUser' <- H.liftEffect $ Ref.read userRef
    loggedOnUser' # maybe (pure unit) \{ authToken } -> do ⑤
      logoffResponse <- apiCall (LogoffRequest { authToken })
      case logoffResponse of
        Left err -> H.modify_ _ { errorMessage = Just err }
        Right (LogoffResponse LogoffResultsFailure) ->
          H.modify_ _ { errorMessage = Just $ "Unable to logoff" } ⑥
        Right (LogoffResponse LogoffResultsSuccess) -> do
          H.liftEffect $ Ref.write Nothing userRef ⑦
          H.modify_ _ { loggedOff = true } ⑧
