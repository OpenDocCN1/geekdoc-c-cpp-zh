since we do not want to give the user, which could be a hacker, any information that they could use to guess a `userName` or `password`.

Next, let’s design the Logoff Request:

```
```json
{
  "tag": "LogoffRequest",
  "contents": {
    "authToken": "e0fc09ad-894a-4399-9940-870895c27394"
  }
}
```
```

❶ This is the `authToken` that the user got from the `LogonRequest`.

Logoff Response for success:

```
```json
{
  "tag": "LogoffResponse",
  "contents": {
    "tag": "LogoffResultsSuccess"
  }
}
```
```

Logoff Response for failure:

```
```json
{
  "tag": "LogoffResponse",
  "contents": {
    "tag": "LogoffResultsFailure"
  }
}
```
```

❶ The only reason for a `Logoff` failure is that the `authToken` isn’t valid, i.e. the user isn’t logged on. This is why there is no `reason` field here.
