This overspecialization is fine if all of our parsers parsed Strings, but they don’t. temporaryPassword parses a Boolean. And these are the 2 Types that the compiler is complaining about.

Here’s the final code:

```
accountParser :: AccountParserT Account
accountParser = do
    userName' <- userName # comma
    passwordHash' <- passwordHash # comma
    temporaryPassword' <- temporaryPassword # comma
    admin' <- admin # comma
    firstName' <- firstName # comma
    lastName' <- lastName
    pure $ Account
        { userName: userName'
        , passwordHash: passwordHash'
        , temporaryPassword: temporaryPassword'
        , admin: admin'
        , firstName: firstName'
        , lastName: lastName'
        }
    where
        comma :: ∀ a. AccountParserT a -> AccountParserT a ①
        comma p = p <* char ','
```

① comma is Polymorphic in a and therefore requires an explicit Type Signature to prevent the compiler from overspecializing.
