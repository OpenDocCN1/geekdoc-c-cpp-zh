
只是比喻中冰山最顶端的很小一部分。虽然我在这里坚持使用语言的 ABC，并且只使用基础的控制台应用程序来演示，但 C# 比你在这里看到的要大得多、功能也更强大得多。但自 2014 年以来，C# 已作为开源项目提供，并支持开发针对 Windows、macOS 和 Linux 的控制台应用和 Web 应用。C# 也相当通用，可以用来构建从桌面应用到 Android 和 iOS 的移动应用，再到 Web 应用，甚至是游戏和来自微软 PowerShell 技术的自动化插件。总之 C# 相当易于上手，尽管主要面向有 C++ 或 Java 背景的开发者，而这正是出于其诞生背景的设计考虑。而且与 C++ 和 Java 一样，C# 是强类型或静态类型的，这有助于更早地捕获编程错误并确保程序的正确性。并且其强类型与运行时类型安全相结合，使得 C# 对变化非常有韧性，即使在引入编码错误或破坏性变更时也保持安全。虽然 C# 的根源是一种语言并完全支持经典设计，但它也已演进以支持更函数式的编程方法，所有这些都作为开源项目进行，并且可以用于满足各种应用开发需求。

目标机器上的系统本质上可以直接将原生可执行映像的内容馈送给 CPU，CPU 然后执行它。如果应用程序有一个被调用 1,000 次的函数，CPU 只是执行该方法二进制编码 1,000 次。绝对不会花费时间准备该代码以便执行，因为源代码到机器代码的转换早在该应用程序部署和运行之前就由编译器处理了。话虽如此，这种架构有几个缺点，包括我们上一个模块中看到的对变化缺乏韧性、缺乏可移植性以及需要使用多个编译器构建代码以生成可在不同平台上运行的应用版本，以及要求程序员手动管理程序生命周期内使用的内存和其他资源的分配和释放，这可以说是一个艰巨的任务。遵循本书的主题，我在这里大大简化了过程，但希望这能让你大致了解使用编译语言时代码如何被执行。相比之下，解释型或动态语言位于代码执行模型光谱的完全另一端。解释型语言往往是松散类型的，从完全没有类型到语言中实体的类型在运行时确定并且随着程序运行而可能发生变化。而且虽然程序员的内存管理负担减轻了，可移植性和生产力通常很好，但性能通常是解释型语言最明显的权衡，其次是由于类型宽松而导致的错误。这是因为尽管开发过程以使用编辑器或 IDE 创建包含类似 Python 源代码的文本文件的方式开始，

其余涉及将源代码转换为指令的所有工作都在解释器中进行，解释器是在目标机器上运行的程序，通常按语句为基础将语言语句转换为机器代码。因此，如果应用程序有一个被调用 1,000 次的方法，解释器对该方法源代码到机器代码的转换可能发生 1,000 次。有些解释器比这更聪明，会寻求检测何时可以更高效地将源代码转换为机器代码。但语言本身的设计，在功能和语法方面，往往限制了可以实现的效率提升。而正是这种架构使得像 Python 的 REPL 或 loop 以及可移植的 Jupyter Notebook 用于处理等交互式编码体验成为可能。这就把我们带到了一个某种程度上混合的系统，我在模块标题中称之为托管语言。托管语言如 C# 倾向于强类型，与其编译语言的表亲相似。但与编译语言不同，托管语言使在编码时可供开发者使用的所有类型信息在运行时也可用。这种类型信息的运行时可用性允许进行更强大的安全检查，通过类似垃圾收集器的自动内存管理的便利，这更接近解释型语言的体验，同时也使得实现更快的性能特征成为可能。对于托管语言，开发者通过类似于编译语言系统的编译器运行代码。然而，托管编译器不会产生可直接由机器处理的机器代码。相反，托管编译器会产生一个包含源代码中间表示的二进制文件，在 C# 的情况下称为中间语言，

或简称为 IL。Java 编译器工作方式类似，只是其输出被称为字节码。在 C# 的情况下，编译器产生的<|message|> 文件称为程序集，它包含开发者源代码的完整、无损二进制编码。因为 .NET 程序集不包含原生机器代码，所以它们不能被 CPU 直接执行。因此，为了被执行，某种执行引擎必须存在于目标机器上，该引擎在将代码传递给 CPU 执行之前，按即时或 JIT 方式将 IL 转换为 CPU 可理解的机器代码。该架构的关键部分是该系统的性质。机器代码生成步骤仅在给定方法首次被调用时执行一次。生成的代码随后被缓存并用于所有后续调用。但托管语言系统的整个设计是语言、中间语言二进制表示以及执行引擎本身都是从一开始就设计为仅在代码确实需要执行时才高效生成机器代码的，因此得名。因此，如果给定方法从未被调用，就不会花费任何时间和资源生成其中间语言表示的机器等价物。但如果给定方法被调用，则该方法的 IL 到机器代码的转换会在执行引擎内触发，随后该引擎会从所有后续调用的调用链中移除。换句话说，如果该函数被调用 1,000 次，IL 到机器代码的转换只发生一次，然后另外 999 次调用在执行引擎无需进一步参与的情况下完成。而 JIT 编译器也有助于运行时类型安全，因为 IL 到机器代码转换过程的一部分涉及验证正在编译的函数的类型安全并编码

诸如数组访问尝试之类的其他安全检查。这使得托管语言能够表现出编译语言的性能特征，同时仍提供我们之前看到的自动内存管理、安全性和对变化的韧性等便利。

话虽如此，如果你从未见过这些东西也没关系。本演示的重点不是让你理解这些东西，而是证明 C# 作为托管语言既可以安全且对变化有韧性，同时仍能表现出原生代码的性能特征这一说法。
