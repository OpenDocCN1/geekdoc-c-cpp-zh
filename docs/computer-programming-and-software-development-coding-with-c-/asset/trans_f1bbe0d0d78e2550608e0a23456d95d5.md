应用程序。如果我们需要添加新的数据读取器，我们需要重新编译应用程序。正如我们将看到的，这可能导致支持问题，但我们可以通过一种方法解决这个问题，即动态加载。我们已经看到过我们的建议，即编程到抽象而不是具体类型。在我们的世界中，这意味着编程到接口而不是具体类。我们在一定程度上已经这样做了。在我们的应用程序代码中，我们使用工厂方法获取实现我们接口的对象，IPersonReader。

```
```csharp
public IActionResult PopulatePeopleView(string readerType)
{
    IPersonReader reader = readerFactory.GetReader(readerType);

    IEnumerable<Person> people = reader.GetPeople();

    ViewData["ReaderType"] = reader.GetType().ToString();
    return View("Index", people);
}
```
```

然后我们调用该接口中包含的 GetPeople 方法。我们的应用程序代码对任何具体的 data reader 都没有引用，无论是 service reader、CSV reader 还是 SQL reader。我们的工厂方法负责为我们提供 data reader 的实例，它确实对我们每个 data reader 都有编译时引用。我们可以删除这些编译时引用，但我们真的需要这样做吗？
