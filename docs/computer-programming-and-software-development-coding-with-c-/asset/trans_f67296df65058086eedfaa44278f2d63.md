换句话说，我签署了契约，表明我的类型知道如何被排序。这就是接口重要的原因。因此，在员工列表上调用 Sort 方法将调用 CompareTo 方法来对我的列表进行排序。

```
public int CompareTo(object obj)
{
    var otherEmployee = (Employee)obj;
    if (Id > otherEmployee.Id)
        return 1;
    else if (Id < otherEmployee.Id)
        return -1;
    else
        return 0;
}
```

让我们在 Employee CompareTo 中设置一个断点，然后我们会看到当 Sort 方法在我的列表上运行时，此 CompareTo 方法会自动被调用。它被调用多次以对所有项目进行排序，一旦排序完成，我们会看到员工 1 是 id 为 100 的那个，这是最低的 id，第二名是 748，最后一个列表中的那个具有最高的 id。所以排序确实基于 id 工作。通过实现 IComparable 接口并提供自己的 CompareTo 方法，我签署了契约，说明我定义了一个方法来指定排序需要如何工作。接口可用于强制类型实现某些数字。在本书的最后部分，我想向你展示接口与多态性的关系。通过使用接口，例如 IEmployee 接口，我们也在接口和实现接口的类型之间建立了关系。就像继承一样，实现接口时会建立关系。
