# 第 9 章 如何使用泛型接口

在本章中，你将学习如何通过使用泛型接口来编写松散耦合的代码。首先，我会确保你理解为什么要使用泛型接口。在你知道这一点之后，你将学习如何创建泛型接口，以及如何使用泛型接口。在本章中，我还会确保你理解什么是协变，以及在使用泛型接口时它如何帮助你。我也会确保你理解什么是逆变。最后，你将学习在使用泛型接口时如何处理接口继承。现在，让我们确保你理解为什么要使用泛型接口。之前，你创建了 StorageApp，这是一个 .NET 控制台应用程序。在此应用程序中，你创建了 GenericRepository 类，它将员工和组织存储在 List 中。在本章中，你将继续处理这个 .NET 应用程序。你要做的第一件事是将 GenericRepository 类重命名为 ListRepository，以使它的作用更明显。然后，你将实现另一个泛型类，名为 SqlRepository。在这个类中，你将使用 Entity Framework Core 将项目存储在数据库中。但我不希望你在本书中必须设置数据库。这就是为什么你将使用带内存提供程序的 Entity Framework Core 数据库。该数据提供程序仅用于测试，因为它缺乏真实的数据库功能，例如引用完整性。但因为它设置非常简单，并且也足以满足我们的需求，所以我们将使用它。需要知道的重要一点是，

你在 SqlRepository 类中编写的代码与你在访问真实数据库（如 SQLite 或 SQL Server）时编写的代码完全相同。所以现在你会看到我们有两个不同的仓库实现，但是当你查看我们的 .NET 控制台应用程序的 Program 类时，你会看到像 AddEmployees 和 GetEmployeeById 这样的方法。这些方法有一个 ListRepository 参数。这意味着你不能将 SqlRepository 实例传递给这些方法。但是作为开发人员，公司希望你让 Program 类中的这些方法同时适用于列表仓库和 SQL 仓库。为了实现这一点，你将引入泛型 IRepository 接口，该接口将由 ListRepository 类和 SqlRepository 类实现。引入此接口后，你可以将 Program 类中方法的参数类型从 ListRepository 改为 IRepository。这意味着这些方法将适用于任何 IRepository 实现，例如 ListRepository 或 SqlRepository。因此，这些方法现在依赖于泛型 IRepository 接口，这是一种抽象，而不依赖于具体实现。这实际上是我们在软件开发中使用的一个原则，称为依赖倒置原则。它指出，像 Program 类中的静态方法这样的组件必须依赖抽象，而不是依赖实现。而这正是我们所做的。Program 类中的方法依赖于 IRepository 接口，这是一种抽象。现在让我们来实现它。在你创建这个 IRepository 接口之前，你将构建泛型 SqlRepository 类。在此演示中，你将学习如何构建泛型 SqlRepository 类。在这个类中，你将使用 Entity Framework Core，并将数据存储在数据库中。这里，我已经打开了你之前创建的 StorageApp 项目。让我们在这里选择 GenericRepository.cs 文件，并将该文件重命名为
