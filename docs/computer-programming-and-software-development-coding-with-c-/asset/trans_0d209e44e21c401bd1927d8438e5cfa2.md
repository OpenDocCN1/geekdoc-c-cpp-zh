## 第 6 章 如何引导 App 组件

现在我们需要告诉 Angular 通过一个称为引导的过程加载我们的根组件。我们首先设置 index.html 文件来托管我们的应用程序。然后我们定义我们的根 Angular 模块来引导我们的根组件。让我们查看这两个步骤。 web 应用程序通常是这样工作的。用户访问特定 URL。关联该 URL 的服务器被定位并发送请求。服务器通过返回其默认网页 index.html 来响应。浏览器接收并处理该 index.html 文件。对于 Angular 应用程序，index.html 文件包含引用已转译并捆绑成几个 JavaScript 文件的应用程序文件的脚本标签。这些应用程序文件随后被下载到浏览器并由浏览器处理，应用程序的主页面出现。index.html 文件包含应用程序的主页面。这个 index.html 文件通常是应用程序的唯一真正的网页。因此，应用程序通常被称为应用程序或 SPA。但不用担心。它看起来对用户来说就像我们有很多页面。我们所做的是将 HTML 片段插入到一个 HTML 页面中以找到一个 index.html。

```
import { Component } from '@angular/core';

@Component({
  selector: 'pm-root',
  template:
    <div><h1>{{pageTitle}}</h1>
      <div>My First Component</div>
    </div>
})
export class AppComponent {
  pageTitle: string = 'Acme Product Management';
}
```

这里再次是我们的 app 组件。回想一下，选择器是我们将组件用作 HTML 中的指令时的名称，模板定义了我们想要显示的 HTML。因此在 index.html 文件中，我们只需在我们想要显示模板的位置添加选择器。这里在模板中，我们称之为指令。指令基本上是一个自定义元素。一旦加载完成，组件模板中定义的 HTML 将插入到选择器元素标签之间并出现在页面上。但 Angular 编译器如何知道这个自定义 HTML 元素？它在 Angular 模块中查找。Angular 模块帮助我们将应用程序组织成功能一致的块，并在应用程序内提供边界。它们还提供模板解析环境。这是什么意思？当 Angular 编译器看到指令和模板时，它会查找 Angular 模块以获取定义。因此我们将 AppComponent 声明在 Angular 模块中，以便编译器可以找到它。我们还使用模块

浏览器应用程序必须导入。BrowserModule 注册重要的应用程序服务提供者，例如错误处理。bootstrap 数组定义应用程序的启动组件，即我们的 AppComponent。启动组件应包含我们在 index.html 文件中使用的选择器，在本例中确实如此。现在让我们在示例应用程序中查看它。接下来，我们将设置 index.html 以托管我们的应用程序并检查引导我们的 app 组件的根 Angular 模块。这里我们回到我们的示例应用程序，就像我们离开它时一样。由于我使用 Angular CLI 创建了这些启动文件，index.html 文件已经托管了我们的 app 组件，并且 app.module.ts 文件已经引导了我们的 app 组件。
