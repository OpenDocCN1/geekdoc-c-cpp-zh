# 3.9 GOING DEEPER: UNDERSTANDING HOW THE DATA STEP READS AND STORES DATA

To understand how SAS works, it can be helpful to “look under the hood” and see what is happening in bits and bytes as SAS reads and processes data. Knowing how SAS handles data is like knowing how the motor in your car works. You can drive away without knowing anything about pistons, but sometimes it is good to know that understanding of the data step can help you create programs that avoid problems (programming errors) and take advantage of the internal workings of the program. For example, consider the following simple program

```
DATA NEW;
INPUT ID $ TEMP;
TEMP=TEMP*(9/5)+32;
```

GOING DEEPER: UNDERSTANDING HOW THE DATA STEP READS AND STORES DATA

![](img/61344fee6085dba5f40c12.png) Figure 3.9 The SAS INPUT process

```
DATALINES;
0001 24 37.3
0002 35 38.2
RUN;
```

In this program, SAS reads lines of data. In addition to reading the data, it also performs a calculation. The TEMP statement calculates Fahrenheit temperature from Celsius temperature represented by the variable TEMP. To read these data and do this calculation, SAS goes through three stages represented by Figure 3.9:

**COMPILE**: SAS reads the syntax of the program to see if there are any errors. If no errors are found, SAS “compile” this code – that is, it transforms the code into code (You don’t need to know this.)

**EXECUTION**: If the syntax checks out, SAS begins performing the tasks specified by the code. For example, the first line of code is DATA NEW, so SAS creates a “blank” (no data in it) dataset that it will use to put the data into as it is read.

**OUTPUT**: SAS reads each line of data and interprets this line into values for each variable and stores them into the data set one at a time until all data have been output into the specified dataset. Specifically, once SAS passes the compile phase, it creates an area of memory called the input buffer. This buffer is the location where data values are placed before they are separated into values associated with a particular variable. In this instance, the first line contains the following information:

```
0001 24 37.3
```

# CHAPTER 3: READING, WRITING, AND IMPORTING DATA

SAS also creates another piece of memory called a Program Data Vector (PDV), as shown in the following:

| _N | _ERROR_ | ID | AGE | TEMPC | TEMPF |
|---|---|---|---|---|---|
| 1 | 0 | | | | |

The PDV contains the names of the variables specified in the INPUT statement, plus two temporary variables, _N and _ERROR_. The variable _N is the number of data lines being entered (set to 1 in this case for the first line) to indicate if an error reading has been encountered. It is initially set at 0 (which means no error detected).

The INPUT specification tells SAS how to move the characters in the input buffer into the PDV. In this case, the data entry tells SAS to read characters in the buffer starting with the left and going to the right, until it sees a blank. When a blank is encountered, SAS moves data to that point into the first variable specified in the PDV. In this case, it moves "0001" into the memory space in the PDV allocated for ID. When all the information in the first line has been read, the PDV looks like the following:

| _N | _ERROR_ | ID | AGE | TEMPC | TEMPF |
|---|---|---|---|---|---|
| 1 | | 0001 | 24 | 37.3 | |

Notice that the value of each read variable from the data line are now in the PDV. However, the TEMPF variable is set at missing. SAS continues to read the code and sees that the DATA step also includes a calculation: TEMPF=TEMPC*(9/5) +32;

Using the data already in the PDV for TEMPC (which is 37.3), it uses information to calculate TEMPF. Once the calculation is performed, that value is also placed in the PDV, and it looks like the following:

| _N | _ERROR_ | ID | AGE | TEMPC | TEMPF |
|---|---|---|---|---|---|
| 1 | 0 | 0001 | 24 | 37.3 | 99.14 |

Once all of the values for a line are read, all of the calculations specified in the DATA step have been performed, and there are no errors detected, SAS outputs the PDV to the data set. In this case:

| ID | AGE | TEMPC | TEMPF |
|---|---|---|---|
| 0001 | 24 | 37.3 | 99.14 |

At this stage, only the data values appear in the data set, and the two temporary variables, _N_ and _ERROR_, are not included. Therefore:

- The _N and _ERROR_ variables are available from one iteration of the data set to the next.
- However, they are not saved in the output data set.
- And they cannot be renamed, kept, or dropped.

The value of understanding how SAS handles data as it is read from raw data sources is that it provides you with insight in writing code to successfully input the data in the way you want it to. The brief discussion here is only an introduction to this process. If you want to delve deeper into the inner workings of the DATA step, refer to SAS documentation.
