a Few-to-Many (or some would call it Many-to-Few) match. Another example might be for a credit card company where there are millions of transactions each month. At the end of the month, you want to match each credit card sale (the) to the card owner (the fewer) in order to combine purchases by card owner to produce a monthly statement.

To continue with the auto parts example, suppose you want to produce a report of seven transactions (to keep it simple) defined as in Table 4.13. The table shows the part, type of customer, and the retail price. This is information in “many” data set. A second table (also shown in Table 4.13) contains the current discounts offered. In this data set, there are only three records. This is your “few” dataset.

The goal is to merge the discounts to the parts sold, allowing you to calculate the actual price you charged for the. To perform the merge that you want desire, first sort both files by the key identifier. Note that BUYERTYPE is in both data sets. This is the key identifier by which you want to sort in the merge. The following example illustrates this merge.

Note that this merge is very similar to merging any two files by a key identifier, and it is. The difference is in the first data set, there can be many of the same values for the key identifier (BUYERTYPE) and a list of named unique categories in the second data file.

# HANDS-ON EXAMPLE

+   1. Open the program DMGE2.SAS . The part of the code that performs the Few-to-Many merge is as follows:

```
PROC SORT DATA=SALES; BY BUYERTYPE;RUN;
PROC SORT DATA=DISCOUNT; BY BUYERTYPE;RUN; *COMPLETE THIS;
DATA REPORT;
MERGE SALES DISCOUNT;BY BUYERTYPE;*COMPLETE THIS;
FINAL = ROUND(PRICE*(1-DISCOUNT)),01);
```
