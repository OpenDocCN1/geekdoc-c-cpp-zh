
Formats are not limited to numeric variables. For example, a text variable was coded Y and N for Yes and No to survey answers, you could create the following text format (for the text variable ANSWER). Notice that formats for text begin with a dollar sign ($):

```sas
PROC FORMAT;
    VALUE $ANSWER 'Y' = 'Yes'
    'N' = 'No';
RUN;
```

This code causes PROC PRINT to use the formatted values Yes and No instead of Y and N in the output.

# HAND-ON EXAMPLE

In this example, you create a format definition (FMTMARRI) for a numeric variable and apply that definition to the variable MARRIED in PROC PRINT.

1. Open the program file FORMAT1.SAS.

```sas
PROC FORMAT;
    VALUE FMTMARRI 0="No"
    1="Yes";
RUN;

PROC PRINT DATA="C:\SASDATA\SURVEY";
VAR MARRIED;
FORMAT FMTMARRI.;
```

Note the use of the following:
- The PROC FORMAT statement defines a format named FMTMARRI.
- The FORMAT statement in PROC PRINT tells SAS to apply the FMTMARRI format definition to the variable MARRIED.
- Notice that in FORMAT statement, SAS format specification ends with a dot (.).
- When SAS lists data, in PROC PRINT, instead of listing data from MARRIED variable it outputs the data as Yes or No.

2. Run the program and observe the output. The MARRIED column should contain the words Yes and No rather than 1 and 0.

3. Another variable in this set is GENDER. This text variable includes codes M for Male and F for Female. Change the FORMAT step to also include a definition for a format named $FMTGENDER by adding the VALUE statement.

```sas
PROC FORMAT;
    VALUE $FMTGENDER "F" = "Female"
    "M" = "Male";
RUN;

PROC PRINT;
VAR MARRIED GENDER;
FORMAT $FMTGENDER.;
```

4. Submit the new program and observe the output. Does MARRIED column include Male and Female instead of M and F? See the results in Table 4.15.

However, it is often a good idea to use the prefix FMT in any user-created format name to help you avoid getting format names mixed with various names. Format names must follow SAS naming conventions, but they may not end in a number.

Formats also use ranges. For example, suppose that you want to classify your AGE using the designations Child, Teen, Adult, and Senior. You could do this with the following format:

```sas
PROC FORMAT;
    VALUE FMTAGE
    LOW-12 = 'Child'
    13,14,15,16,17,18,19 = 'Teen'
    20-59 = 'Adult'
    60-HIGH = 'Senior';
RUN;
```

The LOW means the lowest numeric value for this variable in the dataset: HIGH means the highest numeric value. You can also use the term OTHER= to indicate any data not specified by the other assignments. Also, you can use lists, as in the Teen specification. (Yes, it would have been simpler to use 13–19, but we did this for illustrative purposes.)

You can also assign the same format to several variables. If you have a questionnaire data with variables Q1, Q5, Q7 where each question is coded as 0 and 1 for answers Yes and No, respectively, and you have a format called FMTYN, you could use this FORMAT in a procedure as in the following:

```sas
PROC PRINT;
FORMAT Q1 Q5 Q7 FMTYN;
RUN;
```

# CHAPTER 4: PREPARING DATA FOR ANALYSIS

Occasionally, there is some confusion over the difference between labels and formats. Formats affect how data is displayed, not stored in SAS. Formats are temporary; they exist only while the procedure is running. To make them permanent, you must store them in a SAS library.

## 4.8 Creating Permanent Formats

In all the previous examples, formats were temporary. To create permanent formats, you must use the LIBRARY option in the PROC FORMAT statement. For example, to store formats in a

```sas
PROC FORMAT LIBRARY=C:\SASDATA\MYLIB;
```

(Note: The library MYLIB must exist in SAS for this to work). Once formats are stored in a library, you can use them in any procedure by using the LIBRARY option in the FORMAT statement:

```sas
PROC PRINT DATA=C:\SASDATA\SURVEY;
VAR AGE;
FORMAT AGE (C:\SASDATA\MYLIB.FMTAGE.);
```
