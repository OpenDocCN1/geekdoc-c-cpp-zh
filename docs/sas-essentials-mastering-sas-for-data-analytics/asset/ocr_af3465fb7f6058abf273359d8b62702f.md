# TABLE 5.3 Common Options for Titles and Footnotes

| Title | Meaning |
| :--- | :--- |
| C=color or COLOR= color | Specifies color. See Appendix A for a summary of colors available |
| C="RGBCode" | An RGB code allows you to specify over 16 million different colors using an RGB coding system. See Appendix A for more information. For example, C="CX803009" specifies vivid redish orange. Colors may also be defined as a Hex code. Companies often have defined colors to be used in official documents, and the RB or Hex code is a way to match colors |
| BCOLOR= color | Specifies background color |
| J=type | Justification. Options are left, right, or center |
| F=fontname | Specifies font for text. See Appendix A for more information. Example="SWISS" |
| H=n or HEIGHT=n | Specifies height of text. See Appendix A for more information. Default height is 1. H=16 pt means 16 points |
| BOLD | Specifies bold |
| ITALIC | Specifies italic |
| UNDERLINE=n | 0 means, 1, 2, or 3 means underline and may specify thickness in some instances |

Another technique is when you want to begin a comment with /* and end with /. This technique is useful when you want to include statements that contain not a semicolon. For example, you can comment out lines of code you do not use currently, but that you want to retain for possible future use or reference. Here are two examples of this comment technique:

```
/*This is a SAS comment*/
/* Use this comment technique to comment out lines of code
PROC PRINT;
PROC MEANS;
End of comment -- the PROCS were ignored*/
```

In your programming, it is a good idea to begin every program with a note about what it does, when it was written, and who wrote it. It may not important at the moment, 6 months or a year later the note can save you valuable time.\Note that you can put a comment using either method on a line of code, but you cannot put a comment on a line of data values that follow the DATALINES statement.
