You've already seen the major features of the program, but let's re-examine an old point. The program uses this code (in the form of the inline getline()) function after reading the planet's g value

```cpp
while (std::cin.get() != '\n')
```

This reads and discards input through the newline character. Consider the next input statement in the loop:
cin.get(pl.name, 20);

If the newline were left in place, this statement would read the newline as an empty line, terminating the loop.

You might wonder if this program could use a string instead of a character array for the name of the planet structure. The answer is no—at least without major changes in design. The problem is that a string object doesn't actually contain the string within itself; it contains a pointer to the memory location where the string is stored. So if you copy the structure to a file, you don't copy the string data, you copy the address of the string. When you run the program, that address is meaningless.

# Chapter 17 Input, Output, and Files

## Random Access

For our last example, let's look at random access. Random access means moving directly to any location in the file instead of moving through it. The random access approach is often used with database files. A program will maintain a separate index, giving the location of the data in the main file. Then it can jump directly to that location, read the data there, and perhaps modify it. This approach is done most simply if the file consists of a collection of equal-sized records. Each record represents a related collection of data. For example, in the example in Listing 17.19, each file record would represent all the data about a particular planet. A file record corresponds naturally to a structure or class.

The program assumes that the planets.dat file already exists and was created by the binary.cpp program in Listing 17.19. The first question to answer is what file mode to use. In order to read the file, you need the ios_base::binary mode. For binary I/O, you need the ios_base::binary mode (Again, on some nonstandard systems you can omit—you may have to omit it). In order to write to the file, you need the ios_base::out or the ios_base::app mode. However, the append mode allows a program to add data to the end of the file. Only the rest of the file is read-only; that is, you can read the original data but not modify it—so, to modify the data, you have to use ios_base::out. As Table 17.8 indicates, using the in and out modes simultaneously provides a read/write mode, so you have to add the binary element. As mentioned earlier, you use the | operator to combine modes. Thus, you use the following statement to set up:

```cpp
fin.open(file, ios_base::in | ios_base::out | ios_base::binary);
```

Next, you need a way to move through a file. The faststream class inherits two methods for this: seek() moves the input pointer to a given file location, and seekp() moves the output pointer to a given location. (Actually, the faststream class uses buffers for intermediate storage of data, the pointers to locations in the buffers, not in the actual file.) You can use seekg() with an ifstream object and seekp() with an ofstream object. Here are the seekg() prototypes:
```cpp
basic_istream<charT,traits&>& seekg(off_type, ios_base::seekdir);
basic_istream<charT,traits&>& seekg(pos_type);
```
As you can see, they are templates. This chapter uses a template specialization for the char type. For the char specialization, the two prototypes are equivalent to the:
```cpp
istream & seekg(streamoff, ios_base::seekdir);
istream & seekg(streampos);
```
The first prototype represents locating a file position measured, in bytes, as an offset from a file location specified by the argument. The second prototype represents locating a file position measured, in bytes, from the beginning of a file.

## Type Specialization

When C++ was young, life was simpler for the seekg() methods. The streamoff and streampos types were typedef of some standard integer type, such as long. However, the quest for creating a portable standard had to deal with the realization that an integer argument might not provide enough information for some file systems, streamoff and streampos were allowed to be structures or classes, as long as they allowed some basic operations, such as using an integer value as an initialization value. Next, the old istream class was replaced with the basic_istream, streampos and streamoff replaced with the template-based pos_type and off_type. However, streamoff and streampos continue to exist as char specializations of pos_type and off_type. Similarly, you can use the streampos and wstream types if you use seekg() with a wstream object.

Let's look at the arguments to the first prototype of seekg(). Values of the streamoff type are used to measure offsets, in bytes, from a particular location in a file. streamoff argument represents the file position, in bytes, as an offset from one of locations. (The type may be defined as an integer type or as a class.) The seek_dir argument is another integer type that is defined, with three possible values: the ios_base::beg means the offset from beginning of the file. The constant ios_base::cur measures the offset from the current position. The constant ios_base::end measures the offset from the end of the file. Here are some sample calls, showing that fin is an ifstream object:

```cpp
fin.seekg(30, ios_base::beg);      // 30 bytes beyond the beginning
fin.seekg(-1, ios_base::cur);      // back up one byte
fin.seekg(0, ios_base::end);        // go to the end of the file
```
