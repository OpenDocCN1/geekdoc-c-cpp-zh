
# Pointers and the C++ Philosophy

Object-oriented programming differs from traditional procedural programming in OOP OOP emphasizes making decisions during runtime instead of compile time. Runtime means while a program is running, and compile time means when the compiler is putting a program together. A runtime decision is like, on vacation, choosing what sights to see depending on the weather and your mood at the moment, whereas a compile-time decision is more like adhering to a preset schedule, regardless of the conditions.

Runtime decisions provide the flexibility to adjust to current circumstances. For example, consider allocating memory for an array. The traditional way is to declare an array. To declare an array in C++, you have to commit yourself to a particular array size. Thus, the array size is set when the program is compiled; it is a compile-time decision. Perhaps you think an array of 20 elements is sufficient 80% of the time but occasionally the program will need 120 elements. So you use an array with 200 elements. This results in your program wasting memory most of the time it used. OOP tries to make a program more flexible by delaying decisions until runtime. That way, after the program is running, you can tell it only 20 elements one time or that you need 205 elements another time.

In short, with OOP you would like to make the array size a runtime decision. To make this approach possible, the language allows you to declare an array—or the equivalent—while the program runs. The C++ method, as you soon see, involves using the keyword new to request the correct amount of memory and using pointers to keep track of where the newly allocated memory is found.

Making decisions is not unique to OOP C++ makes writing the code a bit more straightforward than does C.

The new strategy for handling stored data things around treating the location as a derived quantity and the value as a derived quantity. A special type of variable—the pointer—holds the address of a variable. Thus, the name of the pointer represents the location. Applying the * operator, called the indirect value or dereferencing operator, yields the value at the location. (Yes, this is the * symbol used for multiplication; C++ uses the context to determine whether you mean multiplication or dereferencing.) Suppose, for example, that manly is a pointer. In that case, manly represents an address, and *manly represents the value at that address. The combination *manly becomes equivalent to an ordinary type variable. ## Declaring and Initializing Pointers

Let's examine the process of declaring pointers. A computer needs to keep track of the type of value to which a pointer refers. For example, the address of a char typically looks the same as the address of a double, but they use different numbers of bytes and internal formats for values. Therefore, a pointer declaration must specify what type of data to which the pointer points. For example the preceding example has this declaration:

```cpp
int * p_updates;
```

This states that the combination *p_updates is type int. Because the * operator by applying it to a pointer, the p_updates variable itself must be a pointer. We say that p_updates points to type int. We also say that the type for p_updates is pointer-to-int or, more concisely, *. To repeat: p_updates is a pointer (an address), and *p_updates is an int and not a pointer (see Figure 4.9).

Incidentally, the use of spaces around * is optional. Traditionally, C programmers have used this form:

```cpp
int *ptr;
```

This accentuates the idea that the combination *ptr is type int value. Many C++ programmers, on the other hand, use this form:

```cpp
int* ptr;
```

## Compound Types

This emphasizes the idea that int* is type pointer-to-int. Where you put the spaces makes no difference to the compiler. You could even do this:

```cpp
int *ptr;
```

Be aware, however, the following declaration creates one pointer (p1) and one ordinary int (p2):

```cpp
int* p1, p2;
```

You need * for each pointer name.

Note: C++, the combination int * is a compound type, pointer-to-int. You use the syntax to declare pointers to other types:

```cpp
double *tax_ptr; // tax_ptr points to type double
char * str; // str points to type char
```

Because you declare tax_ptr as a pointer-to-double, the compiler knows that *tax_ptr is a double value. That is, it is known that *tax_ptr represents a number in floating-point format that occupies (on most systems) 8 bytes. A pointer variable is never a pointer. It is always a pointer to a specific type: tax_ptr (or double *), and str is type pointer-to-char (or char *). Although both are pointers, they are pointers of different types. Like arrays, pointers are based on other types.

Note where tax_ptr and str point to data types of different sizes, the two variables tax_ptr and str themselves are the same size. That, the address of a char is the same size as the address of a double, much as 1016 might be the street address of a department store, where 1024 could be the street address of a small cottage. The size or value of an address doesn't tell you about the size or kind of variable you find at address. Usually, addresses require 2 or 4 bytes, depending on the computer system (Some systems have larger addresses, and a system can use different addresses for different types).

You can use a declaration to initialize a pointer. In that case, the pointer, not the pointed-to, is initialized. That is, the following statements set pt and *pt to the value updates:

```cpp
int updates = 5;
int *pt = &updates;
```

Listing 4.16: how to initialize a pointer to an address.

## Listing 4.16 init_ptr.cpp

```cpp
// init_ptr.cpp -- initialize a pointer
#include <iostream>
int main()
{
    using namespace std;
    int updates = 5;
    int * pt = &updates;

    cout << "Value of updates = " << updates;
    cout << " Address of updates = " << &updates << endl;
    cout << "Value of *pt = " << *pt;
    cout << " Value of pt = " << pt << endl;
    return 0;
}
```

Here is some sample output from the program in Listing 4.16:
Value of updates = 5; Address of updates = 0x012FED4
Value of *pt = 5; Value of pt = 0x012FED4

You can see that the pointer initializes pt, not *pt, to the address of updates. (Your system most likely will show different values for the addresses and display them in a different format.)

# Pointers and the Free Store

## Pointer Danger

Danger awaits who incautiously use pointers. One extremely important point is that when you create a pointer in C++, the computer allocates memory to hold an address, but it does not allocate memory to hold the data to which the address points. Creating space for the data involves a separate step. Omitting that step, as in the following, is an invitation to disaster:

```cpp
long *fellow; // create a pointer-to-long
*fellow = 22323; // place a value in a never-ever land
```

# Caution

Pointer Golden Rule: Always initialize a pointer to a definite and appropriate address before you the dereferencing operator (*) to it.
