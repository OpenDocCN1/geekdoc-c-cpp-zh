
```cpp
class hold;
hold<T> q;
hold<int> n;
public:
    beta(T, int i) : q(t), n(i) {}
    template<typename U> // declaration
    U blab(U u, T t);
    void show() const { q.show(); n.show(); }
};
```

```cpp
// member definition
template<typename T>
template<typename V>
class beta<T>::hold
{
    private:
        V val;
public:
        hold(V v = 0) : val(v)
        void show() const { std::cout << val << std::endl; }
        V Value() const { return val; }
};
```

```cpp
// member definition
template<typename T>
template<typename U>
beta<T>::beta(U u, T t)
{
    return (n.Value() + q.Value()) * u / t;
}
```

The definitions have to identify T, V, and U as template parameters. Because the templates are nested, you have to use the

```cpp
template<typename T>
template <typename V>
```

syntax instead of this syntax:

```cpp
template<typename T, typename V>
```

The definitions also must indicate that hold and hold are members of the beta<T> class, and they use the scope-resolution operator to do so.

## Templates As Parameters

You've seen that a template can have type parameters, such as typename T, and non-type parameters, such as int n. A template can also have a parameter that is itself a template. Such parameters are yet another template feature addition that is used to implement the STL.

Listing 14.21 shows an example that begins with these lines:

```cpp
template <typename T> class Thing;
class Crab
```

The template parameter is `template <typename T> class Thing`. Here `template <typename T>` is the type, and Thing is the parameter. What does this imply? Suppose you have this declaration:

```cpp
Crab<King> legs;
```

For this to be accepted, the template parameter King has to be a template class declaration matches that of the template parameter Thing:

```cpp
template <typename T>
class King {...};
```

The Crab declaration in Listing 14.21 declares two objects:

```cpp
Thing<int> s1;
Thing<double> s2;
```

The previous declaration for legs would result in substituting King<int> for Thing<int> and King<double> for Thing<double>. However, Listing 14.21 has this declaration:

```cpp
Crab<Stack> nebula;
```

Hence, in this, Thing<int> is instantiated as Stack<int>, and Thing<double> is instantiated as Stack<double>. In short, the template parameter Thing is replaced by whatever T is used as a template argument in declaring a Crab object. The Crab declaration makes three assumptions about the class represented by Thing. The class should have a push() method, and these methods should have a particular interface. The Crab can use any template that matches the Thing type declaration and has pop() methods. This happens to have one such class, the Stack defined in stacktp.h, so the example uses that.

Listing 14.21 tempparam.cpp

```cpp
// tempparam.cpp - templates as parameters
#include <iostream>
#include "stacktp.h"

template <typename T>
class Thing
class Crab
{
private:
    Thing<int> s1;
    Thing<double> s2;
public:
    Crab(); // assumes the thing has push() and pop() members
    bool push(int a, double x) { return s1.push(a) && s2.push(x); }
    bool pop(int a, double x) { return s1.pop(a) && s2.pop(x); }
};

int main() {
using std::cout;
using std::cin;
using std::endl;
Crab nebula; // Stack must match template <typename T> class thing
int ni;
double nb;
cout << "Enter double pairs, such as 4.5 (0 to end):\n";
while ((cin >> ni >> nb) && ni > 0 && nb > 0) {
    if (!nebula.push(ni, nb))
        break;
}

while (nebula.pop(ni, nb))
    cout << " " << ni << " " << nb << endl;

cout << "Done.\n";
return 0;
}
```

You can mix template pairs with regular parameters. For example, the Crab declaration could start out like this:

```cpp
template <template <typename T> class Thing, typename U, typename V>
class Crab
{
private:
    Thing<U> s1;
    Thing<V> s2;
    ..
};
```

Now the types to be stored in the members s1 and s2 are generic types instead of hard coded types. This would require the declaration of nebula in the program to be changed to this:

```cpp
Crab<Stack, int, double> nebula; // T=Stack, U=int, V=double
```

The template T represents a template type, and the type parameters U and V represent non-template types.

## Template Classes and Friends

Template class declarations can have friends, too. You can classify friends of templates in three categories:

- Non-template friends
- Bound template friends, meaning the type of the friend is determined by the type of the class when a class is instantiated
- Unbound template friends, meaning that all specializations of the friend are friends to each specialization of the class

Let's look at examples of them.

## Non-Template Friend Functions to Template Classes

Let's declare an ordinary function in a template class as a friend:

```cpp
template <class T>
class HasFriend {
public:
    ..
    friend void counts(); // friend to all HasFriend instantiations
};
```

This declaration makes the counts() function a friend to all possible instances of the template. For example, it would be a friend to the HasFriend<int> class and the HasFriend<string> class.

The counts() function is not invoked by an object (it's a friend, not a member function), and it has no object parameters, so how does it access a HasFriend object? There are several possibilities. It could access a global object; it could access non-global objects by using a global pointer; it could create its own objects; and it could access static data members of a template class, which exist separately from an object.

## Class Templates

Suppose you want to provide a template class argument to a friend function. Can you have a friend declaration like this, for example?

```cpp
friend void report(HasFriend&); // possible?
```

The answer is no. The reason is that there is no such thing as a HasFriend object. There are only particular specializations, such as HasFriend<short>. To provide a template class argument, then you have indicate a specialization. For example, you can use:

```cpp
template <class T>
class HasFriend
{
    friend void report(HasFriend<T>&); // bound template friend
    ...
};
```

To understand what this does, the specialization produced if you declare an object of a particular type:

```cpp
HasFriend<int>;
```

The compiler would replace the template parameter T with int, giving the friend declaration this form:

```cpp
template <typename T>
class HasFriend
{
    friend void report(HasFriend<T>&); // bound template friend
    ...
};
```

That is, report() with a HasFriend<int> parameter becomes a friend to the HasFriend<int> class. Similarly, report() with a HasFriend<double> parameter would be a friend to the HasFriend<double> class.

Note that report() is not itself a template function; it just has a parameter. This means that you have to define explicit specializations for the friends you plan to use:

Listing 14.22 illustrates these points. The HasFriend template has a static member ct. Note that each specialization of the class has its own static member. The counts() method, which is a friend to all HasFriend specializations, reports the value of ct for two particular specializations: HasFriend<int> and HasFriend<double>.The program also two report() functions, each of which is a friend to one specialization.

## Reusing Code in C++

Listing 14.22 frndtmp.cpp

```cpp
// frndtmp.cpp -- template class with non-template friends
#include <iostream>
using std::cout;
using std::endl;

template <typename T>
class HasFriend {
private:
    T item;
    static int ct;
public:
    HasFriend(const T & i) : item(i) {ct++;}
    ~HasFriend() {ct--;}
    friend void counts();
    friend void reports(HasFriend<T> &); // template parameter
};

// each specialization has its own static data member
template <typename T>
int HasFriend<T>::ct = 0;

// non-template friend to all HasFriend<T> classes
void counts() {
    cout << "int count: " << HasFriend<int>::ct << " ";
    cout << "double count: " << HasFriend<double>::ct << endl;
}

// non-template friend to the HasFriend<int> class
void reports(HasFriend<int> & hf) {
    cout << "HasFriend<int>: " << hf.item << endl;
}

// non-template friend to the HasFriend<double> class
void reports(HasFriend<double> & hf) {
    cout << "HasFriend<double>: " << hf.item << endl;
}

int main() {
    cout << "No objects declared: ";
    counts();
    HasFriend<int> h1(10);
    HasFriend<double> h2(20.5);
    counts();
    reports(h1);
    reports(h2);
    return 0;
}
```
