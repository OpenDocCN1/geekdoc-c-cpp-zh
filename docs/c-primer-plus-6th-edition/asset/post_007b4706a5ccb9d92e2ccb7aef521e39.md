
# Chapter 8 Adventures in Functions

You might think this is a place you could use function overloading because the function signatures appear to be different. But consider things from the compiler's standpoint. Suppose that you have code like this:

```
cout << cube(x);
```

The x argument matches both the double x prototype and the double &x prototype. The compiler has no way of knowing which function to use. Therefore, to avoid such confusion, when it checks function signatures, the compiler considers a reference to a type and the type itself to be the same signature.

The function-matching process does discriminate between const and non-const variables. Consider the following prototypes:

```
void dribble(char * bits);           // overloaded
void dribble(const char *cbits);     // overloaded
void dribble(double * bits);            // not overloaded
void drivel(const char * bits);        // not overloaded
```

Here's what function calls would match:

```
char p1[20] = "How's the weather?"
char p2[20] = "How's business?";
dribble(p1);                                     // dribble(const char *)
dribble(p2);                             // dribble(char *)
dabble(p1);                             // no match
dabble(p2);                             // dabble(char *)
drivel(p1);                             // drivel(const char *)
drivel(p2);                             // drivel(const char *)
```

The drivel() function has two prototypes one or the other, for const pointers and one for non-const pointers—and the compiler selects one or the other, depending on whether the actual argument is const. The dabble() function only matches a call with a non-const argument. The reason for this difference in behavior between drivel() and dabble() is that it's valid to assign a non-const value to a const variable, but not versa.

Keep in mind that the signature, the function type, enables function overloading. For example, the following two declarations are incompatible:

```
long gronk(int n, float m);          // same signatures
double gronk(int n, float m);         // hence not allowed
```

Therefore, C++ doesn't permit you to overload gronk() in this fashion. You can have different return types, but only if the signatures are different:

```
long gronk(int n, float m);          // different signatures
double gronk(float n, float m);      // hence allowed
```

# Overloading Reference Parameters

Class designs and the STL often use reference parameters, and it's useful to know how overloading works with different reference types. Consider the three prototypes:

```
void sink(double& r1);           // matches modifiable lvalue
void sank(const double& r2);     // matches modifiable or const lvalue, rvalue
void sink(double&& r3);            // matches rvalue
```

The reference parameter r1 matches a modifiable lvalue argument, such as a double variable. The const reference parameter r2 matches a modifiable lvalue argument, such as a const lvalue, and an rvalue argument, such as the sum of double values. Finally, the rvalue reference r3 can match the same sort of arguments as r1 and r3. This raises the question of what happens when you overload a function on these three types of parameters. The answer is that the more exact match is made:

```
void staff(double& r1);          // matches modifiable lvalue
void staff(const double& rcs);  // matches rvalue, const lvalue
void stove(double& r1);         // matches modifiable lvalue
void stove(const double& r2);   // matches const lvalue
void stove(double&& r3);         // matches rvalue
```

This allows you to customize the behavior of a function based on the lvalue, const, or rvalue nature of the argument:

```
double x = 55.5;
const double y = 32.0;
stove(x);                      // calls stove(double&)
stove(y);                      // calls stove(const double&)
stove(x+y);                    // calls stove(double&&)
```

If, say, you omit the stove(double&&) function, then stove(x+y) will call the stove(const double&) function instead.

# An Overloading Example

In this chapter we've already developed a left() function that returns a pointer to the first n characters in a string. Let add a second left() function, one that returns the n digits in an integer. You can use it, for example, to examine the first three digits of a U.S. postal zip code as an integer, which is useful if you want to sort for urban areas.

The integer function is a bit more difficult to program than the string version because you don't have the benefit of each digit being stored in its own element. One approach is to compute the number of digits in the number. Dividing a number by 10 loops off digit, so you can use division to count digits. More precisely, you can do so with a loop:

```
unsigned digits = 1;
while (n /= 10)
  digits++;
```

This loop counts how many times you can remove a digit from n until none are left. Recall that n /= 10 is short for n = n / 10. If n is 8, for example, the test assigns to n the value 8 / 10, 0, because it's integer division. That terminates the loop, and digits remain at 1. If n is 238, the first loop sets n to 238 / 10, 23. That's nonzero, so the loop increases to 2. The next cycle sets n to 23 / 10, 2. Again, that's nonzero, so digits grows to 3. The next cycle sets n to 2 / 10, 0, and the loop leaves, digits to the correct value, 3.

Now suppose you have the number five and want to return the first three digits. You can get that value by dividing the number by 10 and then dividing by 10. Each division by 10 removes one digit. To calculate the number of digits to show, you just subtract the number of digits from the total number. For example, to show four digits of a nine-digit number, you off five digits. You can do this approach as follows:

```
ct = digits - ct;
while (ct--)
num /= 10;
```

The function includes some additional code to handle special cases, such as asking for zero digits or asking for more digits than the number possesses. Because the signature of the new left() differs from that of old left(), you can use both functions in the program.

```cpp
char * left(const char *str, int n = 1);

int main() {
	using namespace std;
	char * trip = "Hawaii"; // test value
	unsigned long n = 12345678; // test value
	int i;
	char * temp;

	for (i = 1; i < 10; i++) {
		cout << left(n, i) << endl;
		temp = left(trip, i);
		cout << temp << endl;
		delete temp; // point to temporary storage
	}
	return 0;
}
```

```cpp
// This function returns the first ct digits of the number num.
unsigned long left(unsigned long num, int ct)
{
    unsigned digits = 1;
    unsigned long n = num;

    if (ct == 0 || num == 0)
        return 0; // return 0 if no digits
    while (n /= 10)
        digits++;
    if (digits > ct)
        {
            ct = digits - ct;
            while (ct--)
                num *= 10;
            return num; // return left digits
        }
    else
        return num; // return the whole number
}
```

```cpp
// This function returns a pointer to a new string
// consisting of the first n characters in the str string.
char * left(const char *str, int n)
{
    if (n < 0)
        n = 0;
    char *p = new char[n+1];
    int i;
    for (i = 0; i < n && str[i]; i++)
        p[i] = str[i]; // copy characters
    while (i <= n)
        p[i++] = '\0'; // set rest of string to '\0'
    return p;
}
```

# When to Use Function Overloading

You might find function overloading fascinating, but you shouldn't overuse it. You should reserve function overloading for functions that perform basically the same task with different forms of data. Also you might want to check whether you can accomplish the same thing by using default arguments. For example, you could replace the single, string-oriented left () function with two overloaded functions:

```
char * left(const char * str, unsigned n); // two arguments
char * left(const char * str);           // one argument
```

But using the single with a default argument is simpler. There's just one function to write instead of two, and the program requires memory for just one function instead of two. If you decide to modify the function, you have edit only one however, If you require different types of arguments, default arguments are no avail, so in case, you should use function overloading.

# What Is Name Decoration?

How does C++ keep track of which function is which? It assigns a secret identity to each of these functions. When you use the editor of your C++ development tool to write and compile programs, your C++ compiler performs a bit of magic on your behalf—known as name decoration or mangling—through which each name is encoded, based on the formal parameters specified in the function's prototype. Consider the following undecoration function prototype:

```
MyFunctionFoo(int, float);
```

This format is fine for us humans; know that the function accepts two arguments of int and float, and it returns a value of type long. For your own use, the compiler documents this interface by transforming the name into an internal representation with a more unsightly appearance, perhaps something like this:

```
?MyFunctionFoo@YAXH
```

The apparent decipher the original name (or mangling, depending on your attitude) encodes the number and types of parameters. A different function signature would result in a different set of symbols being added, and different compilers would use different conventions for their efforts at decorating.
