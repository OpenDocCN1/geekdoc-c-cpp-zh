# Simple Variables

+   - You can't use a C++ keyword for a name.
- Names beginning with underscore characters or with an underscore character followed by an uppercase letter are reserved for use by the implementation—that is, the compiler and the resources it uses. Names beginning with a single underscore character are reserved for use as global identifiers by the implementation.
- C++ places no limits on the length of a name, and all characters in a name are significant. However, some platforms may have their own limits.

The next-to-last point is a bit different from the preceding points using a name such as __time_stop or _Donut doesn't produce a compiler error; instead, it leads to undefined behavior. In other words, there's no telling what the result will be. The reason there is no compiler error is that the names are not illegal but rather reserved for the implementation to use. The bit about global names refers to where the names are declared; Chapter 4 touches on that topic.

The final point differentiates C++ from ANSI C (C99), which guarantees only that the first 63 characters of a name are significant. (In ANSI C, two names that have the first 63 characters are considered identical, even if the 64 characters differ.)
Here are some valid and invalid C++ names:

```
int poodle; // valid
int Poodle; // valid and distinct from poodle
int PODLE; // valid and even more distinct
Int terrier; // invalid -- has to be int, not Int
int my_star3 // valid
int _Mystars3; // valid but reserved -- starts with underscore
int 4ever; // invalid -- because starts with a digit
int double; // invalid -- double is a C++ keyword
int begin; // valid -- begin is a Pascal keyword
int __foils; // valid but reserved -- starts with two underscores
int _the_very_best_variable_i_be_version_112; // valid
int honky-tonk; // invalid -- no hyphens allowed
```

If you want to form a name from two or more words, the rule is to separate the words with an underscore, as in my_onions, or to capitalize the initial character of each word after the first, as in myEyeTooth. # Naming Schemes

Schemes for naming, like schemes for naming, provide fertile ground for discussion. Indeed, this topic produces some of the most ardent disagreements in programming. Again, with function names, the C++ compiler doesn't care about your variable names as long as they satisfy the rules, but a consistent, precise naming convention will serve you well.
