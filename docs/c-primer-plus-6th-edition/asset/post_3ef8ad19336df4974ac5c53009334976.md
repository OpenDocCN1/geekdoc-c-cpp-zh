# Conversions in Expressions

Consider what happens when you combine two different arithmetic types in one expression. C++ makes two kinds of automatic conversions in that case. First, some types are automatically converted when they occur. Some types are converted when they are combined with other types in an expression.

First, let's examine the automatic conversions. When it evaluates, C++ converts bool, unsigned char, signed char, and short values to int. In particular, true is promoted to 1 and false to 0. These conversions are integral promotions. For example, consider the following statements:

```cpp
short chickens = 20; // line 1
short ducks = 35; // line 2
short fowl = chickens + ducks; // line 3
```

To execute the statement in line 3, a C++ program takes the values of chickens and ducks and converts both to int. The program converts the result to type short because the answer is assigned to a type short variable. You might find this bit roundabout, but it makes sense. The int type is generally chosen to be the computer's most natural type, which means the computer probably does calculations fastest for that type.

There are more integral promotions: The unsigned short type is converted to int if short is smaller than int. If the two types are the same size, unsigned short is converted to unsigned short. Similarly, wchar_t is promoted to the first of the following types that is wide enough to accommodate its range: int, unsigned int, long, or unsigned long.

# Chapter 3 Dealing with Data

Then there are the conversions that take place when you arithmetically combine different types, such as adding an int to a float. When an operation involves two types, the smaller is converted to the larger. For example, the program in Listing 3.11 divides 9.0 by 5. Because 9.0 is double, the program converts 5 to double before it performs the division. More generally, the compiler goes through a checklist to determine which conversions are made in an arithmetic expression. C++11 has modified the list slightly. Here's the C++11 version of the list, which the compiler goes through in order:

- 1. If either operand is type long double, the other operand is converted to double.
- 2. Otherwise, if either operand is double, the other operand is converted to double.
- 3. Otherwise, if either operand is float, the other operand is converted to float.
- 4. Otherwise, the operands are integer types and the integral promotions are made.
- 5. In that case, if both operands are signed or if both are unsigned, and one is of lower rank than the other, it is converted to the higher rank.
- 6. Otherwise, one operand is signed and one unsigned. If the unsigned operand is of higher rank than the signed operand, the latter is converted to the type of the unsigned operand.
- 7. Otherwise, if the signed type can represent all values of the unsigned type, the unsigned operand is converted to the type of the signed type.
- 8. Otherwise, both operands are converted to the unsigned version of the signed type.

ANSI follows the same rules as ISO 2003 C++, which are slightly different from the preceding rules, and K&R C have slightly different rules. For example, classic C always promotes float to double, even if both operands are float.

This list introduces the concept of ranking integer types. In brief, as you might expect, the best rank for signed integer types from high to low is long, long, int, short, and signed char. Unsigned types have the same rank as the corresponding signed type. The three chars char, signed char, and unsigned all have the same rank. The bool type has the lowest rank. The wchar_t, char16_t, and char32_t have the same types as their underlying types.

# Conversions in Passing Arguments

Normally, C++ function prototyping controls conversions for the passing of arguments, as you'll learn in Chapter 7, "Functions: C++ Programming Languages." However, it is possible, although unwise, to waive prototype control for argument passing. In that case, C++ applies the integral promotions to the char and short types (signed and unsigned). Also to preserve compatibility with huge amounts of code in classic C, C++ promotes float arguments to double when passing them to a function that waives prototyping.

# Type Casts

C++ empowers you to force type conversions explicitly via the type cast mechanism. (C++ recognizes the need for type rules, and it also recognizes the need to occasionally override those rules). The type cast comes in two forms. For example, to convert an int value stored in a variable called thorn to type long, you can use any of the following expressions:

- (long) thorn // returns a type long conversion of thorn
- long (thorn) // returns a type long conversion of thorn

The type cast doesn't alter the thorn itself; instead, it creates a new value of indicated type, which you can then use in an expression, as in the following:
`cout << int('Q'); // displays the integer code for 'Q'`

More generally, you can do the following:

- (typename) value // converts value to typeName
- typeName (value) // converts value to typeName

The first is straight C. The second is pure C++. The idea behind the new form is to make a type cast look like a function. This makes type casts for the built-in types like the type conversions you can design for user-defined classes.

C++ also introduces four type cast operators that are more restrictive in how they can be used. Chapter 15, "Friends, Exceptions, and More," cover them. Of the four, the static_cast<> operator, can be used for converting.

# Chapter 3 Dealing with Data

Listing 3.14 typecast.cpp

```cpp
// typecast.cpp -- forcing type changes
#include <iostream>
int main() {

    using namespace std;
    int auks, bats, costs;

    // the following statement adds values as double,
    // then converts the result to int
    auks = 19.99 + 11.99;

    // these statements add values as int
    bats = (int) 19.99 + (int) 11.99; // old C syntax
    costs = 19.99 + 11.99; // new C++ syntax
    cout << "auks = " << auks << ", bats = " << bats << ";\n";
    cout << "costs = " << costs << endl;

    char ch = 'Z';
    cout << "The code for " << ch << " is: " // print as char
    cout << (int)ch << endl; // print as int
    cout << "Yes, the code is: " << endl;
    cout << static_cast<int>(ch) << endl; // using static_cast
    return 0;
}
```

Here is the result of the program in Listing 3.14:
auks = 31, bats = 30, costs = 30
The code for Z is 90
Yes, the code is 90

First, 19.99 to 11.99 yields 31.98. When this value is assigned to the int variable, it is truncated to 31. But using type casts truncates the two values to 19 and 11 before addition, making 30 for both bats and costs. Then two statements use type cast to convert a type char value to int before they display the result. These conversions use cout to print the value as an integer rather than as character. This program illustrates two reasons to use type casting. First, you might have values that are stored as type double but are used to calculate a type value. For example, you might be fitting a position to a grid or modeling integer values, such as populations, floating-point numbers. You might want the calculations to treat the values as int. Type casting enables you to do so. Notice that you get a different result, at least for these values, when you convert to int and add versus what you do when you add and then convert to int.
