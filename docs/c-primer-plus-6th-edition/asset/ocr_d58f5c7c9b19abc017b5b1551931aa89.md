In naming a source file, you must use the proper suffix to identify the file as a C++ file. This not only tells you that the file is C++ source code, it tells the compiler, too. (If a Unix compiler complains to you about "bad magic number," that's its enduring obscure way of saying that you used the wrong suffix.) The suffix consists of a period followed by a character or group of characters called the extension (see Figure 1.4).

![](bbox=[0.328, 0.315, 0.672, 0.44])

Figure 1.4 The parts of a source code filename.

The extension you use depends on the C++ implementation. For example, spiffy.c is a valid C++ source code filename. Note that Unix is case sensitive, meaning you should use an uppercase C character. Actually, a lowercase c extension also works, but standard C uses that extension. To avoid confusion on Unix systems, you should use c with C programs and c with C++ programs. If you do not mind typing an extra character or two, you can also use the cc and cex extensions with some Unix systems. DOS, being a simple-minded compared to Unix, doesn't distinguish between uppercase and lowercase, so DOS implementations use additional letters, as shown in Table 1.1, to distinguish between C and C++ programs.

# Table 1.1 Source Code Extensions

| C++ Implementation | Source Code Extension(s) |
| --- | --- |
| Unix | c, cc, cxx, c |
| GNU C++ | c, cc, cxx, cpp, c++ |
| Digital Mars | cpp, c |
| Borland C++ | cpp |
| Watcom | cpp |
| Microsoft Visual C++ | cpp, cxx, cc |
| Freestyle CodeWarrior | cpp, cp, cc, cxx, c++ |
