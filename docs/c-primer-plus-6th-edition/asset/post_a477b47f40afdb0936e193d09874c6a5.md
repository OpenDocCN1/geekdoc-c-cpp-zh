## Inline Versus Macros

The inline facility is an addition to C++. C uses the preprocessor #define statement to provide macros, which are crude implementations of inline code. For example, here's a macro for squaring a number:

```cpp
#define SQUARE(X) X*X
```

This works by passing arguments but through text substitution, with the x acting as a symbolic label for the "argument":

```
a = SQUARE(5.0); is replaced by a = 5.0*5.0;
b = SQUARE(4.5 + 7.5); is replaced by b = 4.5 * 4.5 + 7.5 * 7.5;
d = SQUARE(c++); is replaced by d = c++*c++
```

Only the first example works properly. You can improve matters with a liberal application of parentheses:

```cpp
#define SQUARE(X) ((X)*(X))
```

Still, the problem remains macros don't pass by value. Even with this new definition, SQUARE(c++) increments c twice, the inline square () function in Listing 8.1 evaluates c, passes that value to be squared, and then increments c once.

The intent here not to show you how to use C macros. Rather, it is to suggest that if you are using C macros to perform function-like services, you should consider converting them to C++ inline functions.

## Reference Variables

C++ adds a new compound type to the language—the reference variable. A reference is a name that acts as an alias, or another name, for a previously defined variable. For example, if you make tween reference to the clemens variable, you can use tween and clemens interchangeably to represent variable. What of use of such an alias? It is to help people who are embarrassed by this choice of variable names? Maybe, the main use for a reference variable is a formal argument to a function. If you use a reference as argument, the function works with the original data instead of a copy. References provide a convenient alternative to pointers for processing large structures with a function, and they are essential for designing classes. Before you see how to use references with functions, however, let us examine the basics of defining and using a reference. Keep in mind the purpose of the following discussion is to illustrate how references work, not how they are typically used.

## Creating a Reference Variable

You might recall that C and C++ use the & symbol to indicate the address of a variable. C++ assigns an additional meaning to the & symbol and presses it into service for declaring references. For example, to make rodents an alternative name for the variable rats, you could do the following:

```cpp
int rats;
int & rodents = rats;    // makes rodents an alias for rats
```

In this context, & is not the operator identifier. Instead, it serves as part of the type identifier. Just as char * in a declaration means pointer-to-char, int & means reference-to-int. The declaration allows you to use rats and rodents interchangeably; both refer the same value and same memory location. Listing 8.2 illustrates the truth of this claim.

Listing 8.2 firstref.cpp

```cpp
// firstref.cpp -- defining and using a reference
#include <iostream>
int main() {
    using namespace std;
    int rats = 101;
    int & rodents = rats;    // rodents is a reference
    cout << "rats = " << rats;
    cout << "rodents = " << rodents << endl;
    cout << "*rats = " << rats;
    cout << "rodents = " << rodents << endl;

    // some implementations require casting the following to type unsigned
    cout << "rats address = " << &rats;
    cout << "rodents address = " << &rodents << endl;
    return 0;
}
```

Note that & operator in the following statement is not the address operator but declares that rodents is of int (that, it is a reference to an int variable):
int & rodents = rats;

But the & in the next statement is the address operator, with &rodents representing the address of the variable to which rodents refers: cout << "rodents address = " << &rodents;

Here is the output of the program in Listing 8.2:

```
rats = 101, rodents = 101
rats address = 0x65fd48, rodents address = 0x65fd48
```

As you can see, both rats and rodents have the same value and the same address (The address values vary from system). Incrementing rodents by one increments a single variable for which are two names. Again, keep in mind that although this example shows how reference works, it doesn't represent the type which is as function parameter, particularly for structure. References tend to be a bit confusing at first coming to C++ because they are reminiscent of pointers, yet somehow different. For example, you create both a reference and a pointer to:

```cpp
int rats = 101;
int & rodents = rats; // rodents reference
int *pr = &rats; // pr a pointer
```

Then you could use the expressions rodents and *pr interchangeably with rats and &rats. From this standpoint, a reference looks like a pointer in disguised notation in which dereferencing operator is understood implicitly. And, in fact, that's more or less what reference is. But there are differences besides those of notation. It is necessary to initialize the reference when you declare it; you can't declare the reference and then assign it a value later like you can with a pointer:

Note: You should initialize a reference when you declare it. A reference is rather like a pointer; you have to initialize it when you create it, and when a reference pledges its allegiance to a particular variable, it sticks to its pledge. That is,

```cpp
int & rodents = rats;
```

is essence, disguised notation for something like this the reference performs the same role as *pr. Listing 8.3 shows what happens if you try to make a reference from a variable to a variable.

# Listing 8.3 secref.cpp

```cpp
// secref.cpp -- defining and using a reference
#include <iostream>
int main() {
  using namespace std;
  int rats = 101;
  int & rodents = rats; // rodents is a reference

  cout << "rats = " << rats << endl;
  cout << "rodents = " << rodents << endl;

  cout << "rats address = " << &rats;
  cout << "rodents address = " << &rodents << endl;

  int bunnies = 50;
  rodents = bunnies; // can we change the reference?
  cout << "bunnies = " << bunnies << endl;
  cout << "rats = " << rats << endl;
  cout << "rodents = " << rodents << endl;

  cout << "bunnies address = " << &bunnies;
  cout << "rodents address = " << &rodents << endl;
  return 0;
}
```

Here's the output of the program in Listing 8.3:

```
rats = 101, rodents = 101
rats address = 0x65fd44, rodents address = 0x65fd44
bunnies = 50, rats = 50, rodents = 50
bunnies address = 0x65fd48, rodents address = 0x65fd44
```

Initially, rodents refers to rats, but then the program apparently attempts to make rodents a reference to bunnies:

rodents = bunnies;

For a moment, it looks as if this attempt has succeeded because the value of rodents changes from 101 to 50. Closer inspection reveals that rats also has changed to 50 and that rodents still share the same address, which differs from the bunnies address. Because rodents is an alias for rats, the assignment statement really means the same as the following:

That is, it means "Assign the value of the bunnies variable to the rats variable" in short, you can set a reference by an initializing declaration, not by assignment.

Suppose you tried this:

```cpp
int rats = 101;
int *pt = &rats;
int & rodents = *pt;
int bunnies = 50;
pt = &bunnies;
```

Initializing rodents to *pt makes rodents refer to rats. Subsequently altering pt to point to bunnies does not alter the fact that rodents refer to rats.

## References as Function Parameters

Most often, references are used as function parameters, making a variable name in a function an alias for a variable in the calling program. This method of passing arguments is called passing reference. Passing by reference allows a called function to access variables in the calling function. Passing by value, a break from C, which only passes by value, results in the called function working with copies of values from the calling program (see Figure 8.2). Of course, C lets you get around the passing by value limitation using pointers.

Let's compare using references and using pointers in a common computer problem: swapping two variables. A swapping function has to be able to alter variables in the calling program. This means the usual approach of passing variables by value will not work because the function will end up swapping the contents of the original variables instead of the variables themselves. If you pass references, however, the function can work with the original data. Alternatively, you can pass pointers in order to access the original data.
