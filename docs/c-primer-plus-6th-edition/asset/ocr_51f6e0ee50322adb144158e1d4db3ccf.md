# Summary 1055

Smart pointers such as auto_ptr and C++11s shared_ptr and unique_ptr make it easier to manage memory allocated by new. If you use one of smart pointers instead of a regular pointer to hold the address returned by new, you don't have to remember to use the delete operator. When the smart pointer object expires, its destructor calls the delete operator automatically.

The STL is a collection of container class templates, iterator class templates, object templates, and algorithm function templates that feature a unified design based on generic programming principles. The algorithms use templates to make them generic in terms of type stored object and an iterator interface to make them generic in terms of the type of container. Iterators are generalizations of pointers.

The STL uses the term concept to define a set of requirements. For example, the concept of forward iterators includes the requirements that a forward iterator object be dereferenced for reading and that it can be incremented. Actual implementations of the concept are called to model the concept. For example, the forward iterator could be modeled by an ordered pointer or by an object to navigate a linked list. Containers based on other concepts are termed refinements. The bidirectional iterator is a refinement of the forward iterator concept.

Containers, such as vector and set, are models of container concepts, such as containers, sequences, and associative containers. The STL defines several container templates: vector, deque, list, set, multiset, multimap, and bitset. It also defines the adapter class templates queue, priority_queue, and stack: these classes adapt an underlying container to give the adapter class template name. Thus, although based, by default, vector, allows insertion and removal only at the top of the stack. C++11 adds forward_list, unordered_set, unordered_multiset, unordered_map, and unordered_multimap.

Some algorithms are expressed as container class methods, but the bulk are expressed as general, nonfunction. This is made possible by using iterators as the interface between containers and algorithms. One advantage to this approach is that there needs to be just one for_() or copy() and so on, in a separate version for each container. A disadvantage is that STL algorithms can be used with non-STL containers, such as ordinary arrays, string objects, array objects, and any classes you design consistent with the STL iterator and container idiom.

Both containers and algorithms are characterized by the type of iterator they provide or need. You should check that a container features an iterator that supports the algorithm's needs. For example, the for_() algorithm uses an input iterator, whose minimal requirements are met by all STL container types. But sort() requires random access iterators, which not all containers support. A container class may offer a specialized method as an option if it doesn't meet the requirements for a particular algorithm. For example, the list class has a sort() method that is based on bidirectional iterators.

The STL also provides function objects, or functors, that are classes for which the () operator is overloaded—that is, for which operator() () method is defined.
