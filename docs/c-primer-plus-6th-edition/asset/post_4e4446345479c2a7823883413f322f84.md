## Conditional Operators and Bug Prevention

Many programmers reverse the more intuitive expression `variable == value` to `value == variable` to catch errors where the equality is mistyped as an assignment operator. For example, entering the conditional as valid and will work properly:

```cpp
if (3 == myNumber)
```

However, if you happen to mistype as follows, the compiler will generate an error message because it believes you are attempting to assign a value to a literal (3 always equals 3 and can't be assigned another):

```cpp
if (3 = myNumber)
```

Suppose you made a similar mistake, using the for notation:

```cpp
if (myNumber = 3)
```

The compiler would simply assign the value 3 to myNumber, and the block within the if run--a very common error, and a difficult one to find. (However, many compilers will issue a warning, which would be wise to heed.) As a general rule, writing code that allows the compiler to find errors is much easier than repairing the causes of mysterious faults.

## Logical Expressions

Often you test for more than one condition. For example, for a character to be a lowercase letter, its value must be greater than or equal to 'a' and less than or equal to 'z'. Or, if you want a user to respond with a y or an n, you want to accept uppercase (Y and N) as well as lowercase. To meet this kind of need, C++ provides three logical operators to combine or modify existing expressions. The operators are OR, written `||`; logical AND, written `&&`; and logical NOT, written `!`. Let's examine them:

### The Logical OR Operator: ||

In English, the word or can indicate one or both of conditions satisfy a requirement. For example, you can go to the MegaMicro company picnic or you work. The C++ equivalent is the logical OR operator, written `||`. This operator combines two expressions into one. If either or both of the original expressions is true, nonzero, the resulting expression has the value true. Otherwise, the expression has the value false. Here are some examples:

```cpp
5 == 5 || 5 == 9 // true because first expression is true
5 > 3 || 5 > 10 // true because first expression is true
5 > 8 || 5 < 10 // true because second expression is true
5 < 8 || 5 > 2 // true because both expressions are true
5 > 8 || 5 < 2 // false because both expressions are true
```

Because the `||` has a lower precedence than the relational operators, you don't need to use parentheses in these expressions. Table 6.1 summarizes how the `||` operator works.

Table 6.1 The || Operator

| The Value of expr1 || expr2 | Result |
|---|---|---|
| expr1 == true | expr1 == false | true |
| expr2 == false | true | false |

C++ provides that the `||` is a sequence point. That is, any value changes indicated on the left side before the right side is evaluated. (Or in the newer part of C++11, the subexpression to the left of the operator is sequenced before the subexpression to the right.) For example, consider the following expression:

```cpp
i < 6 || i == j
```

Suppose i originally has the value 10. By the time the comparison with j takes place, i has the value 11. Also C++ won't bother evaluating the expression on the right if the expression on the left is true, it only takes one expression to make the whole logical true. (The semicolon and the comma operator, recall, are also sequence points.)

Listing 6.4 uses the `||` operator in an if statement to check for uppercase and lowercase versions of a character. It also uses C++'s string concatenation feature (see Chapter 4, "Compound Types") to spread a single string over three lines.

Listing 6.4 or.cpp

```cpp
// or.cpp -- using the logical OR operator
#include <iostream>
int main() {
    using namespace std;
    cout << "This program will reformat your hard disk\n"
         "and destroy all your data.\n"
         "Do you wish to continue?\y/n";
    char ch;
    cin >> ch;
    if (ch == 'y' || ch == 'Y') // y or Y
        cout << "You were warned!\a\a\n";
    else if (ch == 'n' || ch == 'N') // n or N
        cout << "A wise choice ... bye\n";
    else
        cout << "That wasn't a y or n! Apparently you\n"
             << "can't follow instructions, so \n"
             << "I'll trash your disk anyway.\a\a\a\n";
    return 0;
}
```

### The Logical AND Operator: &&

The logical AND operator, written as `&&`, also combines two expressions into one. The resulting expression has the value true only if both original expressions are true. Here are some examples:

```cpp
5 == 5 && 5 == 9 // false because second expression is false
5 > 3 && 5 > 10 // true because second expression is false
5 > 8 && 5 < 10 // true because both expressions are true
5 < 8 && 5 > 2 // true because both expressions are true
5 > 8 && 5 < 2 // false because first expression is false
```

Because the `&&` also has a lower precedence than the relational operators, you don't need to use parentheses in these expressions. Like the `||` operator, `&&` is a sequence point. However, there is a key difference: if the expression on the left is false, the expression on the right is not evaluated. This is known as short-circuit evaluation.

Table 6.2 The && Operator

| The Value of expr1 && expr2 | Result |
|---|---|
| expr1 == false | false |
| expr1 == true | expr2 == false | false |
| expr1 == true | expr2 == true | true |

Listing 6.5 uses the `&&` operator in an if statement to check if a character is within a range.

Listing 6.5 and.cpp

```cpp
// and.cpp -- using the logical AND operator
#include <iostream>
int main() {
    using namespace std;
    char ch;
    cout << "Enter a character: ";
    cin >> ch;
    if (ch >= 'a' && ch <= 'z')
        cout << "You entered a lowercase letter.\n";
    else if (ch >= 'A' && ch <= 'Z')
        cout << "You entered an uppercase letter.\n";
    else
        cout << "You entered not a letter.\n";
    return 0;
}
```

The `&&` operator is particularly useful for checking multiple conditions, for example, checking if a pointer is not null before dereferencing it:

```cpp
if (ptr != nullptr && *ptr == 5) {
    // do something
}
```

In this case, the short-circuit evaluation ensures that the second part of the expression is never evaluated, preventing a crash if `ptr` is null.
