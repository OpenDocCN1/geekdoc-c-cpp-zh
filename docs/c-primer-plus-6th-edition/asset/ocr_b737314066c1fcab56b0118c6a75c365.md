# nullptr

The null pointer is a pointer guaranteed not to point to valid data. Traditionally, C++ has has represented this pointer in source code with 0, although the internal representation could be different. This raises some problems because it makes 0 both a pointer constant and an integer constant. As discussed in Chapter 12,"Classes and Dynamic Memory Allocation," C++11 introduces the keyword nullptr to represent the null pointer; it is a pointer type and not convertible to an integer type. For backward compatibility, C++ still allows the use of 0, and the expression nullptr == 0 evaluates as true, but using nullptr instead provides better type safety. For example, the value 0 could be passed to a function accepting an int argument, but the compiler will identify an attempt to pass nullptr to such a function as an error. So, for clarity and added safety, use nullptr if your compiler accepts it.

# Smart Pointers

A program that uses new to allocate memory from the heap (or free store) should use delete when memory is no longer needed. Earlier, C++ introduced the auto_ptr smart pointer to help automate the process. Subsequent programming experiences, particularly with the STL, indicated that something sophisticated was needed. Guided by the experience of programmers and solutions provided by the BOOST library, C++11 deprecates auto_ptr and introduces three new smart pointer types: unique_ptr, shared_ptr, and weak_ptr. Chapter 16 discusses the first.

The new smart pointers have been designed to work with STL containers and move semantics.

# Exception Specification Changes

C++ provides a syntax for specifying exceptions, if any, a function may throw (refer to Chapter 15,"Friends, Exceptions, and More");

```
void f501(int) throw(bad_dog);      // can throw bad_dog exception
void f733(long long) throw();          // doesn't throw an exception
```

With auto_ptr, the collective experience of the C++ programming community is that, in practice, exception specifications did not work as intended. Thus, the C++11 standard deprecated exception specifications. However, the committee felt there is some value in documenting that a function does not throw an exception, and it added the keyword noexcept

```
void f875(short, short) noexcept; // doesn't throw an exception
```
