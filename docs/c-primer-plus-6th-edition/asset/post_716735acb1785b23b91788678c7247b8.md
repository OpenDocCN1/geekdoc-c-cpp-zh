{
    if (top > 0)
    {
        item = items[--top];
        return true;
    }

    return false;

The default constructor guarantees that all stacks are created empty. The code for pop() and push() guarantees that the top of the stack is properly managed. Guarantees like one of the things that make OOP reliable. Suppose that, instead, you create a separate array to represent the stack and an independent variable to represent the index of the top. In that case, it is your responsibility to get the code right each time you create a new stack. Without the protection private data offers, there's always the possibility of making some blunder that alters data unintentionally.

# Summary

OOP emphasizes data and methods. The first step toward OOP is to design the class with an interface. Next, you need to implement the class methods. The interface is redundant if pop() and push() return information about the stack status (full or empty) instead of being void. This provides the programmer with a couple options on how to handle exceeding the stack limit or emptying the stack. He or can use isEmpty() and isFull() to check before attempting to modify the stack, or use the return value of push() and pop() to determine whether the operation is successful.

Rather than defining the stack in terms of some particular type, the class describes it in terms of a general Item type. In this case, the header file uses typedef to make the item unsigned long. If you want, a stack of doubles or a structure type, you can change the typedef and leave the class declaration and method definitions unaltered. Class templates (see Chapter 14, "Reusing Code in C++") provide a more powerful method for isolating from the class design to the type of data stored.

A class is a user-defined type, and an object is an instance of class. C++ tries to make user-defined types as similar as standard types, so you declare objects, pointers to objects, and arrays of objects. You can pass objects as arguments, return them as function values, and assign one object to another. If you provide a constructor method, you can initialize objects when they are created. If you provide a destructor method, the program executes it when the object expires.

Each object holds its own copy of the data, but they share the methods. If mr_object is the name of a particular object and try_me() is a member function, you invoke the member function using the dot membership operator: mr_object.try_me(). OOP terminology describes this function as sending a try_me message which then applies to the data members of the mr_object object. Similarly, the function call i_try_me() accesses the data members of the i_object object.

In the case, if you want an object to act on more than one object, you can pass additional objects as arguments. If a method needs to refer explicitly to the object it evoked, it can use this pointer. This pointer is set to the address of the evoking object, so this is an alias for the object itself.

Classes are well matched to describing ADTs. The public member function interface provides services described by an ADT, and the class's private section and the code for the class methods provide an implementation that is hidden from clients of the class.
