Finally.

total = pennyD + jennySt;

becomes

total = operator+(pennyD, jennySt); // friend function

Here, both arguments are type double, that both objects invokes the Stonew (double) construc-
t convert them to Stonew objects.

However, the member function version wouldn't be able to add jennySt to pennyD.
Converting the addition syntax to a function could look like this:

total = pennyD.operator(jennySt); // not meaningful

But this is meaningless because only a class object can invoke a member function.
++ does not attempt to convert pennyD to a Stonew object. Conversion takes place for
member function arguments, not for member function invokers.

The lesson here is defining addition as a friend makes it easier for a program to
commodate type conversions. The reason is that both operands become
function arguments, so function prototyping comes into play for both operands.

# Choices in Implementing Addition

Given that you want to add quantities to Stonew quantities, you have a couple
choices. The first, as you just saw, to define the following as a friend function and have
The Stonew (double) constructor handle conversions of type double arguments to type
Stonew arguments:

```
operator+(const Stonew &, const Stonew &)
```

The second choice is to further overload the addition operator with functions that
member function

```
Stonew operator+(double x); // member function
friend Stonew operator+(double x, Stonew & s);
```

That, the following statement exactly matches the operator+(double x) mem-
er function:

```
total = pennyD + jennyD; // Stonew + Stonew
```

And the following statement exactly matches the operator+(double x, Stonew
s) friend function:

```
total = pennyD + jennySt; // double + Stonew
```

Earlier, we did something similar for Vector multiplication.
Each choice has advantages. The first choice (relying on implicit conversions) results in
a shorter program because you define fewer functions. That also implies less work for you
f fewer to miss up. The disadvantage is the added overhead in time and mem-\ory needed to invoke the conversion constructor whenever a conversion is needed.
