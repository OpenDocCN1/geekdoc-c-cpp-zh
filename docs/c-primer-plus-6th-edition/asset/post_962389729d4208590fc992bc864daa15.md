## Chapter 13 Class Inheritance

### Showing Virtual Method Behavior

In Listing 13.9 the methods are invoked by objects, not pointers or references, so this program does not use the virtual method feature. Let's look at an example for which the virtual methods come into play. Suppose you would like to manage a mixture of Brass and BrassPlus accounts. It would be nice if you could have a single array that holds a mixture of Brass and BrassPlus objects, but that's not possible. Every item in an array has to be of the same type, and Brass and BrassPlus are separate types. However, you can create an array of pointers-to-Brass. In that case, every element is of the same type, but because of public inheritance, a pointer-to-Brass can point to either a Brass or BrassPlus object. Thus, in effect, you have a way of representing more than one type of object with a single array. This is polymorphism, and Listing 13.10 shows a simple example.

### Listing 13.10 use2.cpp -- polymorphic example

```cpp

#include <string>
#include "brass.h"

int main()
{
    int CLIENTS = 4;
    using std::cin;
    using std::cout;

    Brass *p_clients[CLIENTS];
    string temp;
    long tempnum;
    double tempbal;
    char kind;

    for (int i = 0; i < CLIENTS; i++)
    {
        cout << "Enter name: ";
        getline(cin, temp);
        cout << "Enter account number: ";
        cin >> tempnum;
        cout << "Enter opening balance: ";
        cin >> tempbal;
        cout << "Enter 1 for Brass Account or ";
        cout << "2 for BrassPlus Account: ";
        cout << "Enter 1 or 2: ";
        cin >> kind;

        if (kind == '1')
            p_clients[i] = new Brass(temp, tempnum, tempbal);
        else
        {
            double tmax, rate;
            cout << "Enter the overdraft limit: ";

            cout << "Enter the interest rate as a decimal fraction: ";
            cin >> rate;
            p_clients[i] = new BrassPlus(temp, tempnum, tempbal, tmax, rate);
        }
    }

    for (int i = 0; i < CLIENTS; i++)
    {
        p_clients[i]->ViewAcct();

    }
    for (int i = 0; i < CLIENTS; i++)

        delete p_clients[i]; // free memory
    }
    cout << "Done\n";

}
```

### Dynamic Binding

### The Need for Virtual Destructors

The program in Listing 13.10 uses delete to free the objects allocated by new. This illustrates why the base class should have a virtual destructor. If the destructors are not virtual, then the destructor corresponding to the pointer type is called. In Listing 13.10, this behavior isn't essential because the destructors do nothing. But using virtual destructors ensures the correct sequence of destructors is called.

### Pointer and Reference Type Compatibility

Dynamic binding in C++ is associated with methods invoked by pointers and references, and this is governed, in part, by the inheritance process. One public inheritance mode of the is-a relationship is how it handles pointers and references to objects. Normally, C++ does not allow you to assign one type to a pointer of another type. Does not let a refer to one type refer to another type:

```cpp
double x = 2.5;
```
