## Program Notes

You can pass an initializer_list object by value or by reference, as shown by sum() and average(). The object is small, typically two pointers (one to the beginning and one past end) or a pointer to the beginning and an integer representing the size, so the choice is not a major performance issue. (The STL passes them by value.)

The function argument can be a list literal, like {2, 3, 4}, or it can be a list variable, like dl.

The iterator types for initializer_list are const, so you can't change the values in a list:

```cpp
*dl.begin() = 2011.6; // not allowed
dl = {16.0, 25.0, 36.0, 40.0, 64.0}; // allowed
```

However, the intended use of the initializer_list class is to pass a list of values to a constructor or some other function.

## Summary

C++ includes a powerful set of libraries that provide solutions to many common programming problems and the tools to simplify many more problems. The string class provides a convenient way to handle strings objects as well as automatic memory management and a host of methods and functions for working with strings. For example, these methods and functions allow you to concatenate strings, insert one string into another, reverse a string, search a string for characters or substrings, and perform input and output operations.

Smart pointers such as auto_ptr and C++11s shared_ptr and unique_ptr make it easier to manage memory allocated by new. If you use one of smart pointers instead of a regular pointer to hold the address returned by new, you don't have to remember to use the delete operator. When the smart pointer object expires, its destructor calls the delete operator automatically.

The STL is a collection of container class templates, iterator class templates, object templates, and algorithm function templates that feature a unified design based on generic programming principles. The algorithms use templates to make them generic in terms of type stored object and an iterator interface to make them generic in terms of the type of container. Iterators are generalizations of pointers.

The STL uses the term concept to define a set of requirements. For example, the concept of forward iterators includes the requirements that a forward iterator object be dereferenced for reading and that it can be incremented. Actual implementations of the concept are called to model the concept. For example, the forward iterator could be modeled by an ordered pointer or by an object to navigate a linked list. Containers based on other concepts are termed refinements. The bidirectional iterator is a refinement of the forward iterator concept.

Containers, such as vector and set, are models of container concepts, such as containers, sequences, and associative containers. The STL defines several container templates: vector, deque, list, set, multimiset, multimap, and bitset. It also defines the adapter class templates queue, priority_queue, and stack: these classes adapt an underlying container to give the adapter class template name. Thus, although based, by default, vector, allows insertion and removal only at the top of the stack. C++11 adds forward_list, unordered_set, unordered_multiset, unordered_map, and unordered_multimap.

Some algorithms are expressed as container class methods, but the bulk are expressed as general, nonfunction. This is made possible by using iterators as the interface between containers and algorithms. One advantage to this approach is that there needs to be just one for() or copy() and so on, in a separate version for each container. A disadvantage is that STL algorithms can be used with non-STL containers, such as ordinary arrays, string objects, array objects, and any classes you design consistent with the STL iterator and container idiom.

Both containers and algorithms are characterized by the type of iterator they provide or need. You should check that a container features an iterator that supports the algorithm's needs. For example, the for() algorithm uses an input iterator, whose minimal requirements are met by all STL container types. But sort() requires random access iterators, which not all containers support. A container class may offer a specialized method as an option if it doesn't meet the requirements for a particular algorithm. For example, the list class has a sort() method that is based on bidirectional iterators.

The STL also provides function objects, or functors, that are classes for which the () operator is overloaded—that is, for which operator() () method is defined.

Objects of such classes can be invoked by using function notation but can carry additional information. Adaptable functors, for example, have typedef statements that identify the argument types and the return value for the functor. This information can be used by other components, such as function adapters.

By representing common container types and providing a variety of common operations implemented with efficient algorithms, all done in a generic manner, the STL provides an excellent source of reusable code. You may be able to solve a programming problem directly with the STL tools, or you may be able to use them as building blocks to construct the solution you need.
