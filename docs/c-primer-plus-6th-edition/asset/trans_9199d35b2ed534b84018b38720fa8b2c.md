# 程序说明

首先，注意列表 8.4 中每个函数是如何被调用的：

```
swapr(wallet1, wallet2);      // pass variables
swap(&wallet1, &wallet2);      // pass addresses of variables
swapv(wallet1, wallet2)        // pass values of variables
```

按引用传递（swapr(wallet1, wallet2)）和按值传递（swapv(wallet1, wallet2)）看起来是相同的。你唯一能确定 swapr() 按引用传递的方法是查看原型或函数定义。然而，地址运算符（&）的存在使得函数按地址传递时变得明显（(swap(&wallet1, &wallet2)）。（回想一下，声明 *p 表示 p 是 int 的指针，对应于 p 的参数应为地址，例如 &wallet1。）

接下来，考虑函数 swap()（按引用传递）和 swapv()（按值传递）的代码。两者之间唯一的外部区别是函数参数的声明方式：

```
void swapr(int &a, int &b)
void swapv(int *a, int *b)
```

内部的区别当然是，在 swap() 中，变量 a 和 b 作为 wallet1 和 wallet2 的别名，因此交换 a 和 b 是新的变量，复制了 wallet1 和 wallet2 的值，因此交换 a 和 b 对 wallet1 和 wallet2 没有影响。

最后，比较函数 swap()（按引用传递）和 swap()（按指针传递）。第一个区别在于函数参数的声明方式：

```
void swap(int &a, int &b)
void swapv(int *p, int *q)
```

第二个区别是指针版本在整个函数中都需要使用 * 解引用运算符使用 p 和 q。
更早的时候，我会用函数调用中的参数值初始化引用变量。因此引用函数参数被初始化为函数调用中传递的参数。也就是说，

以下函数调用将形式参数 a 初始化为 wallet1，将形式参数 b 初始化为 wallet2：

swapr(wallet1, wallet2);

# 引用属性和奇异性

使用引用参数有几个你需要了解的转折。首先，考虑列表 8.5。它使用两个函数对参数求立方。一个接受类型为 double 的参数，另一个接受对 double 的引用。实际的求立方代码故意有点奇怪以说明一个观点。

列表 8.5 cubes.cpp

```
// cubes.cpp -- regular and reference arguments
#include <iostream>
double cube(double a);
double refcube(double &ra);
int main ()
{
    using namespace std;
    double x = 3.0;

    cout << cube(x) << " = cube of " << x << endl;
    cout << " = " << refcube(x);
    cout << " = " << cube of " << x << endl;
    return 0;
}

double cube(double a)
{
    a *= a * a;
    return a;
}

double refcube(double &ra)
{
    ra *= ra * ra;
    return ra;
}
```

以下是列表 8.5 中程序的输出：

27 = cube of 3
27 = cube of 27

# 引用变量

请注意，refcube() 函数修改了 main() 中的 x 的值而 cube() 没有，提醒我们为什么按值传递是常态。变量 a 局部于 cube()。它被初始化为 x 的值，但改变 a 对 x 没有影响。但由于 refcube() 使用引用参数，它对 ra 所做的更改实际上是对 x 所做的更改。如果你希望函数使用传递给它的信息而不修改该信息，并且你使用引用，你应该使用常量引用。这里，例如，你应该在函数原型和头中使用 const double：

```
double refcube(const double&);
```

如果你这样做，编译器会在发现对 ra 的值进行编码时生成错误消息。

顺便说一下，如果你需要编写类似此示例的函数（即使用基本数值类型），你应该使用按值传递而不是更奇特的按引用传递。引用参数在更大的数据单元上变得有用，例如结构和类，你很快就会看到。

按值传递的函数，如列表 8.5 中的 cube() 函数，可以使用许多种实际参数。例如，以下所有调用都是：

```
double z = cube(x + 2.0); // evaluate x + 2.0, pass value
z = cube(8.0); // pass the value 8.0
int k = 10;
z = cube(k); // convert value of k to double, pass value
double yo[3] = { 2.2, 3.4, 4.4 }; = cube(yo[2]); // pass the value 4.4
```

假设你尝试对引用参数的函数使用类似的参数。看起来按引用传递应该更受限制。毕竟，如果 ra 是变量的替代名称，那么实际参数应该是变量。以下内容没有意义，因为表达式 x + 3.0 不是一个变量。

```
double z = refcube(x + 3.0); // should not compile
```

例如，你不能为此表达式赋值：

```
x + 3.0 = 5.0; // nonsensical
```

如果你尝试调用 refcube(x + 3.0) 会发生什么？在当代 C++ 中，这是一个错误，大多数编译器会给出类似以下的行警告：

```
Warning: Temporary used for parameter 'ra' in call to refcube(double &)
```

这种较温和响应的原因是 C++ 在早期确实允许你传递对变量的引用。在某些情况下，它会这样做。发生的情况是 x + 3.0 不是类型 double，程序会创建一个临时、无名的变量，将其初始化为表达式 x + 3.0 的值。然后 ra 成为对临时变量的引用。让我们更仔细地看看临时变量以及何时创建和不创建它们。
