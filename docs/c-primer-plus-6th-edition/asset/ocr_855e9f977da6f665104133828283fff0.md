# Consider the following code:

```
const int N = 6;
string sl[N] = {"buffoon", "thinkers", "for", "heavy", "can", "for"};
set<string> A(sl, sl + N);
ostream_iterator<string> out(cout, " ");
copy(A.begin(), A.end(), out);
```

Like other containers, set has a constructor (refer Table 16.6) that takes a range of iterators. This provides a simple way to initialize a set to the contents of an array. Remember that the last element of a range is one past-the-end, and sl + N points to position past-the output of this code fragment illustrates that keys are unique (the string "for" appears twice in the array but once in the set) and the set is sorted:

buffoon can be heavy thinkers

Mathematics defines some standard operations for sets. For example, the union of two sets is a set that combines the contents of the two sets. If a particular value is common to both sets, it appears just once in the union because of the unique feature. The intersection of two sets is a set that contains the elements that are common to both sets. The difference between two sets is the first set minus the elements common to both sets.

The STL provides algorithms for these operations. They are general functions rather than methods, so they aren't restricted to set objects. However, all sets automatically satisfy the precondition for using these algorithms—namely, the container is sorted. The set_union function takes five iterators as arguments. The first two define a range in one set, the second define a range in another set, and the final is an iterator that identifies a location to copy the resulting set. For example, to display the union of sets A and B, you can use:

```
set_union(A.begin(), A.end(), B.begin(), B.end(),nostream_iterator<string> out(cout, " \"));"
```

Suppose you want to place the result into a set C instead of displaying it. In this case, you would want the algorithm to be an iterator into C. The obvious choice is C.begin(), but that doesn't work for two reasons. The first reason is that associative sets treat keys as constant, so the iterator returned by C.begin() is a constant iterator and can't be used as an output iterator. The second reason is that C.begin() directly set_union(), like copy(), overwrites data in a container and requires the container to have sufficient space to hold the new information. C, being empty, does not satisfy that requirement. The insert_iterator template easily solves both problems. It also models the output iterator concept, so you can use it to write to a container. So you can create an anonymous insert_iterator to copy information to C. To construct, recall, takes the name of the container and an iterator as arguments:

```
set_union(A.begin(), A.end(), B.begin(), B.end(),ninsert_iterator<set<string>>(C, C.begin()));
```
