## Integer Types

Integers are numbers with no fractional part, such as 2, 98, -5286, and 0. There are infinitely many integers, assuming that you consider an infinite number to be a limit, so no finite amount of computer memory can represent all possible integers. Thus, a language can represent only a subset of integers. Some languages offer one integer type (one type fits all), C++ provides several choices. This gives you the option of choosing the integer type that best a program's particular requirements. This concern with matching type to data presages the design data types of OOP.

The various C++ integer types differ in the amount of memory they use to hold data. A larger block of memory can represent a larger range in integer values. Also some types (signed types) can represent positive and negative values, whereas others (unsigned) can't represent negative values. The usual term for describing the amount of memory used for an integer is width. C++'s basic integer types, in order of increasing width, are char, short, int, long, and, with C++11, long long. Each comes in signed and unsigned versions. This gives a choice of ten different integer types! Let's look at these integer types in more detail. Because the char has some special properties (it's most used to represent characters instead of numbers), this chapter covers the other types.

## The short, int, long, and long Integer Types

Computer memory consists of called bits. (See the "Bits and Bytes" later in this chapter.) By using different numbers of bits to store values, the C++ short, int, long and long long can represent up to four different integer widths. It would be convenient if each type were always some particular width for all systems—for example, if short were always 16 bits, int were always 32 bits, and so on. But life is not that simple.

## Simple Variables

No choice is suitable for all computer designs. C++ offers a flexible standard with some guaranteed minimum sizes, which it takes from C. Here's what you get:

- A short integer is at least 16 bits wide.
- An int integer is at least as big as short.
- A long integer is at least 32 bits wide and at least as big as int.
- A long long integer is at least 64 bits wide and at least as big as long.

## Bits and Bytes

The fundamental unit of computer memory is the bit. Think of bit as an electric switch that you can set to either off or on. Off represents value 0, and on represents the value 1. An 8-bit chunk of memory can be set to 256 different combinations. The number 256 comes from the fact that each bit has two possible settings, making the total of combinations for 8 bits 2 x 2 x 2 x 2 x 2 x 2 x 2 x 2 = 256. Thus, an 8-bit unit can represent, say, the values of 0 through 255 or -128 through 127. Each additional bit doubles the number of combinations. This means you can set a 16-bit to 65,536 different values, a 32-bit unit to 4,294,967,296 different values, and a 64-bit unit to 18,446,744,073,709,551,616 different values. As a point of comparison, unsigned long cannot represent the Earth's current population or the number of stars in our galaxy, but long can. (Wait, unsigned long cannot represent the Earth's current population or the number of stars in our galaxy, but long can.)

A byte means an 8-bit unit of memory. In this sense the byte is the unit of measurement that describes the amount of memory in a computer, with a kilobyte equal to 1024 bytes and a megabyte equal to 1,024 kilobytes. However, C++ defines byte differently. The C++ byte consists of least adjacent bits to accommodate the basic character set for the implementation. That is, the number of possible values must equal or exceed the number of distinct characters. In the United States, the basic character sets are usually ASCII and EBCDIC sets, which are accounted for by 8 bits, so the C++ byte is typically 8 bits on systems using those. For larger character sets, such as Unicode, some implementations may use a 16-bit or 32-bit byte. Some use the octet to denote an 8-bit byte.

Many systems currently use the minimum guarantee, making 16 bits and long 32 bits. This still leaves several choices for int. It could be 16, 24, or 32 bits in width and meet the standard. It could be 64, providing that long and long long are at least that wide. Typically, int is 16 bits (the same as short) for IBM PC implementations for Windows XP, Windows Vista, Windows 7, MacOS OS X, VAX, and many other mincomputer implementations. Some implementations give you a choice of how to handle int (What does your implementation use? The next example shows how to determine the limits for your system without having to open a manual.) The differences between implementations for type widths can cause problems when you move a C++ program from one environment to another, including a different compiler on the same system. But a little care, as discussed later in this chapter, can minimize these problems.

The sizeof Operator and the limits Header File

The sizeof operator reports that int is 4 bytes on the base system. You can use the sizeof operator to a type name or to a variable. When you use the sizeof operator with a type name, such as int, enclose the name in parentheses. When you use the operator with a variable, such as n_short, parentheses are optional.

The limits file defines symbolic constants (in the sidebar, "Symbolic Constants for the Preprocessor Way," later in chapter") to represent type limits. As mentioned previously, INT_MAX represents the largest value type int can hold; this turned out to be 2,147,483,647 for our Windows 7 system. The compiler manufacturer provides a file that reflects the values appropriate to that compiler. For example, the limits file for some older systems that used a 16-bit int, defines INT_MAX to 32,767.
