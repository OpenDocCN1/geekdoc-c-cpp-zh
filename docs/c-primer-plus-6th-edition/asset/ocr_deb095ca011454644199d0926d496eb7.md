# Note

A C++ constructor that contains one argument defines a type conversion from the argument to the class type. If the constructor is qualified with the keyword explicit, the constructor is used for explicit conversions only; otherwise, it is used for implicit conversions.

When does the compiler use the Stonew (double) function? If the keyword explicit is used in the declaration, Stonew (double) is used only for an explicit type cast; otherwise, it is also used for the implicit conversions:

+   * When you initialize a Stonew object to a double value
* When you assign a double value to a Stonew object
* When you pass a double value to a function that expects a Stonew argument
* When a function that's declared to return a Stonew value tries to return a double value
* When any of the preceding situations uses a built-in type that cannot be unambiguously converted to double

Let look at the last point in more detail. The argument-matching process provided by function prototyping lets the Stonew (double) constructor act as conversions for other numerical types. That is, both of the following statements work by converting int to double and then using the Stonew (double) constructor:

```
Stonew Jumbo(7000); // uses Stonew (double), converting int to double
Jumbo = 7300; // uses Stonew (double), converting int to double
```

However, this two-step conversion process works only if there is an unambiguous choice. That is, if the class also defines a Stonew (long) constructor, the compiler would reject these statements, probably pointing out that an int can be converted to either a long or double, so the call is ambiguous.
