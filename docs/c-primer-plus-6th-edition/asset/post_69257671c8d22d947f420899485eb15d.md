## Alternative Representations of Bitwise Operators

C++ provides alternative representations of several bitwise operators, as shown in Table E.4. They provide for locales that do not have the traditional bitwise operators as part of their character sets.

## Table E.4 Bitwise Operator Representations

| Standard Representation | Alternative Representation |
|---|---|
| & | bitand |
| &= | and_eq |
| | | bitor |
| |= | or_eq |
| ~ | compl |
| ^ | xor |
| ^= | xor_eq |

These alternative forms let you write statements like the following:
b = compl a bit b; // same as b = -a & b;
c = aor b; // same as c = a ^ c;

## A Few Common Bitwise Operator Techniques

Often controlling hardware involves turning bits on or off checking their status. The bitwise operators provide the means to perform such actions. We'll go through the methods quickly.

In the following examples, longbit represents a general value, and bit represents the value corresponding to a particular bit. Bits are numbered from right to left, beginning with bit 0, so the value corresponding to bit position n is 2^n. For example, an integer

with only bit number 3 set to 1 has the value 2³ or 8. In general, each individual bit corresponds to a power of 2, as described for binary numbers in Appendix A. So we will use the term to represent a power of 2; this corresponds to a particular bit being set to 1 and all other bits being set to 0.

## Turning a Bit On

The two operations each turn on the bit in longbit that corresponds to the bit represented by bit:

```
longbit = longbit | bit;
longbit |= bit;
```

Each sets the corresponding bit to 1, regardless of the former value of the bit. That's because ORing 1 with either 0 or 1 produces 1. All other bits in longbit remain unaltered. That's ORing 0 with 0 produces 0, and ORing 0 with 1 produces 1.

## Toggling a Bit

The two operations each toggle the bit in longbit that corresponds to the bit represented by bit. That is, they turn on if it is off, and turn off if it is:

```
longbit = longbit ^ bit;
longbit ^= bit;
```

XORing 1 with 0 produces 1, turning an bit off, and XORing 1 with 1 produces 0, turning an an bit off. All other bits in longbit remain unaltered. That's XORing 0 with 0 produces 0, and XORing 0 with 1 produces 1.

## Turning a Bit Off

The following operation turns off the bit in longbit that corresponds to the bit represented by bit:

```
longbit = longbit & ~bit;
```

These statements turn the bit off, regardless of its prior state. First, the operator ~bit produces an integer with all bits set to 1 *except* the bit that was originally set to 1; that bit ANDing 0 with any result produces 0, thus turning that bit off. All other bits in longbit are unchanged. That's ANDing 1 with any bit produces the value that bit had before.

Here's a brief way of doing the same thing:

```
longbit & ~bit;
```

## Testing a Bit Value

Suppose you want to determine whether the bit corresponding to the bit is set to 1 in longbit. The following test does not necessarily work:

```
if (longbit == bit) // no good
```

That's because even if the corresponding bit in longbit is set to 1, other bits might be set to 1. The equality above is true only when the corresponding bit is 1. The fix is to AND longbit with bit. This produces a value that is 0 in all the other bit positions because AND any value is 0. Only the bit corresponding to the bit value is left unchanged because 1 AND any value is true. Thus the proper test is:

```
if (longbits & bit == bit);    // testing a bit
```

Real-world programmers often simplify this test to the following:

```
if (longbit & bit)      // testing a bit
```

Because bit consists of one bit set to 1 and the rest set to 0, the value of longbit bit is either 0 (which tests false) or bit, which, being nonzero, tests as true.

## Member Dereferencing Operators

C++ lets you define pointers to members of a class. These pointers involve special notations to declare them and dereference them. To see what's involved, let's start with a class sample:

```
class Example
{
private:
    int feet;
    int inches;
public:
    Example();
    Example(int ft);
    ~Example();
    void show_in() const;
    void show_ft() const;
    void use_ptr() const;
};
```

Consider the inches member. Without a specific object, inches is a label. That is, the class defines inches as a member identifier, but you need an object before you actually have memory allocated:

```
Example obj; // now obj.inches exists
```

Thus, you specify an actual memory location using the identifier inches in conjunction with a specific object. (In a member function, you can omit the name of the object, but then it is understood to be the one pointed to by the pointer).

C++ lets you define a member pointer to the identifier inches like this:

```
int Example::*pt = &Example::inches;
```

This pointer is a bit different from a regular pointer. A regular pointer points to a specific memory location. But the pt pointer doesn't point to a specific memory location

because the declaration doesn't identify a specific object. Instead, the pointer pt identifies the location of inches member within an Example object. Like the inches, pt is designed to be used in conjunction with an object identifier. In essence, the expression *pt assumes the role of the identifier inches. Therefore, you can use an object identifier to specify which object to access and the pt pointer to specify the inches member of that. For example, a class method could use this:

```
Example::*pt = &Example::inches;
Example ob1;
Example ob2;
Example *pq = new Example;
cout << ob1.*pt << endl; // inches member of ob1
cout << ob2.*pt << endl; // inches member of ob2
cout << po->*pt << endl; // inches member of *po
```

.* and ->* are member dereferencing operators. When you have a particular object, such as ob1, then ob1.*pt identifies the inches member of the ob1 object. Similarly, pq->*pt identifies the inches of object pointed to by pq.
Changing the object in the preceding example changes which member is used. But you can also change the pt pointer itself. Because feet is of the same type as inches, you can reset pt to point to the feet instead of the inches member; then ob1.*pt will refer to the feet of ob1:

```
pt = &Example::feet;
cout << ob1.*pt << endl; // display member of ob1
```

In essence, the combination pt takes the place of a member name and can be used to identify different member names (of the same type).
You can also use member pointers to identify member functions. The syntax for this is relatively involved. Recall that declaring a pointer to an ordinary type function void with no arguments looks like this:

```
void (*pf)(); // pf points to a function
```

Declaring a pointer to a member function has to indicate that the function belongs to a particular class. For instance, here is how to declare a pointer to an Example class method:
void (Example::*pf)() const; // pf points to an Example member function

This indicates that pf can be used the same places that Example method can be used. Note that the term Example::*pf has to be in parentheses. You can assign the address of a particular member function to this pointer:
pf = &Example::show_inches;

Note that unlike in the case of ordinary pointer function assignment, you must use the object operator. Having made this assignment, you can then use an object to invoke the member function:

```
Example ob3(20);
(ob3.*pf)(); // invoke show_inches() using the ob3 object
```
