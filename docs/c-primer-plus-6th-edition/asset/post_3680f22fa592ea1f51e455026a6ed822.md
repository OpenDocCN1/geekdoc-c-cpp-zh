## Summary

This chapter covers many important aspects of defining and using classes. Several of these aspects are subtle—even difficult—concepts. If some of them seem obscure or unusually complex to you, don't feel bad; they affect newcomers to C++ that way. Often you will come to appreciate concepts such as copy constructors by getting into trouble ignoring them. Some of the material in this chapter may seem vague until your own experiences enrich your understanding.

You can use new in a class constructor to allocate memory for data and then assign the address of the memory to a class member. This enables a class, for example, to handle strings of various sizes without committing the class design in advance to a fixed array size. Using new in class constructors also prevents memory when an object expires. If an object has member pointers to memory allocated by new, the memory does not automatically free the memory pointed to by the object pointers. Therefore, if you use new in a class constructor to allocate memory, you should delete automatically in the class destructor to free memory. That way, the demise of an object triggers the deletion of pointed-to-memory.

Objects that have members pointing to memory allocated by new also have problems initializing one object or assigning one object to another. By default, C++ uses wise initialization which means that the initialized or the assigned-to object winds up with exact copies of the original object's members. If an original member points to a block of data, the copy member points to the same block. When the program eventually deletes the objects, the class destructor attempts to delete the block of memory twice, which is an error. The solution is to define a special constructor that redefines initialization and to overload the assignment operator. In each case, the new definition should create duplicates of any pointed-to-data and the new object points to the copies. Both the old and the new objects refer to separate but identical data, with no overlap. The same reasoning applies to defining an assignment operator. In each case, the goal is to make a deep copy—that is, to copy the real data and not just pointers to the data.

When an object has static storage or external storage, the destructor for that object is called automatically when the object ceases to exist. If you allocate for object by using new and assign its address to a pointer, the destructor for that object is called automatically when you apply delete to the pointer. However, if you allocate storage for class objects by using placement new instead of regular new, you also take on the responsibility of calling the destructor for the object explicitly by invoking the destructor method with a pointer to the object. C++ allows you to place structure, class, and enumeration definitions inside a class. Such nested types have class scope, meaning that they are local to the class and don't conflict with structures, classes, and enumerations of the same name that are defined elsewhere.

C++ provides a special syntax for class constructors that can be used to initialize data members. This syntax consists of a colon followed by a comma-separated list of initializers. This is placed after the parameter list of the constructor arguments and before the opening brace of the function body. Each initializer consists of the name of the member being initialized followed by parentheses containing the initialization value. Conceptually, these initializations take place when the object is created and before any statements in the function body. The syntax looks like this:

```
queue(int qs) : qsize(qs), items (0), front (NULL), rear (NULL) { }
```

This form is obligatory if the data member is a nonstatic const member or reference, except that C++11 in-class initialization can be used for nonstatic const members. C++11 allows in-class initialization (that is, initialization in the class definition):

```
class Queue
{
private:
    Node * front = NULL;
    enum (Q_SIZE = 10);
    Node * rear = NULL;
    int items = 0;
    const int qsize = Q_SIZE;
};
```

This is equivalent to using a member initialization list. However, any constructor a membership initialization list will override the corresponding in-class initializations.

As you might have noticed, classes require much more care and attention to detail than simple C-style structures. In return, they do much more for.
