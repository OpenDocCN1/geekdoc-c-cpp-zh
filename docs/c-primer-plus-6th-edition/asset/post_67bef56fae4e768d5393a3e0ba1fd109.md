Recall that C++ doesn't evaluate the right side of a logical AND expression if the left side is false. In such a case, evaluating the right side using cin to place input into the array is skipped. If i does equal Max, the loop terminates without trying to read a value into a location at the end of the array.

The preceding example doesn't attempt to read any input after non-numeric input. Let's look at a case that does. Suppose you are required to submit exactly five golf scores to a C++ program to establish your average. If a user enters non-numeric input, the program should object, insisting on numeric input. As you've seen, you can use the value of a cin expression to test for non-numeric input. Suppose the program finds that the user enters the wrong stuff. It needs to take three steps:

1. Reset cin to accept new input.
2. Get rid of the bad input.
3. Prompt the program to try again.

Note that the program has to reset cin before getting rid of the bad input. Listing 6.14 shows how these tasks can be accomplished.

## Listing 6.14 cingolf.cpp

```cpp
// cingolf.cpp -- non-numeric input skipped
#include <iostream>
const int Max = 5;
int main() {
    using namespace std;
    // get data
    int golf[Max];
    cout << "Please enter your golf scores.\n";
    cout << "You must enter " << Max << " rounds.\n";
    int i;
    for (i = 0; i < Max; i++) {
        cout << "round #" << i+1 << " ";
        while (!(cin >> golf[i])) {
            cin.clear(); // reset input
            while (cin.get() != '\n') {
                continue;
            } // get rid of bad input
            cout << "Please enter a number: ";
        }
    }
}
// calculate average
```

# Program Notes

The heart of the error-handling code in Listing 6.14 is the following:

```cpp
while (!(cin >> golf[i])) {
  cin.clear(); // reset input
  while (cin.get() != '\n')
    continue; // get rid of bad input
  cout << "Please enter a number: "; 
}
```

If the user enters 88, the expression is true, and a value is placed in the array. Furthermore, because cin is true, the expression !(cin >> golf[i]) is false, and inner loop terminates. If the user enters i?, the expression is false, nothing is placed into the array, the expression !(cin >> golf[i]) is true, and the program enters the inner while loop. The first statement in the loop uses the clear() method to reset input. If you omit this statement, the program refuses to read any more input. Next, the program uses cin.get() in a while loop to read the remaining input through the end of the line. This gets rid of bad input, along with anything else on the line. Another approach is to read the next whitespace, which gets rid of bad input one word at a time instead of one line at a time. Finally, the program tells the user to enter a number.

# Simple File Input/Output

Sometimes keyboard input is not the best choice. For example, suppose you've written a program to analyze stocks, and you've downloaded a file of 1,000 stock prices. It would be far more convenient to have the program read the file directly than to hand-enter all the values. Similarly, it can be convenient to have a program write output to a file so that you have a permanent record of the results.

Fortunately, C++ makes it simple to transfer the skills you've acquired for keyboard input and display output (collectively termed console I/O) to file input and output (file I/O). Chapter 17 explores these topics extensively, but we'll look at simple file I/O now.

# Text I/o and Text Files

Let's re-examine the concept of I/O. When you use cin for input, the program views input as a series of bytes, with each byte being interpreted as a character code. No matter what the data type, the input begins as character data—that is, text. The cin then has the responsibility of translating text to other types. To see how this works, let's examine how different code handles the same line of input:

Suppose you have the following sample of input:

38.5 19.2

Let's see how this line of input is handled by cin when used with different data types.
First, let's try type char:

```cpp
char ch;
cin >> ch;
```

The first character in the input line (binary) is assigned to ch. In this case, the first character is the digit 3, and the character code (binary) for this digit is stored in ch. The input and the destination are both characters, so no translation is needed. (Note that it's not the numeric value 3 that is stored; rather, it is the character code for the digit 3.) After the input statement, the digit 8 is the next character in the input queue and will be the next character examined by cin the int type with the same input:

Next, let's try the int type:

```cpp
int n;
cin >> n;
```

In this case, cin reads up to the first non-digit character. That is, it reads the 3 digit and the 8 digit, leaving the period as the next character in the input queue. Then cin computes that two characters correspond to the numeric value 38, and the binary code for 38 is copied to n.

Next, let's try the double type:

```cpp
double x;
cin >> x;
```

In this case, cin reads up to the first character that's not part of a floating-point number. That is, it reads the 3 digit, the period character, and the 5 digit, leaving the space as the next character in the input queue. Then cin computes these four characters correspond to the numeric value 38.5, and the binary code (floating-point format) for 38.5 is copied to x.

Next, let's try the char array type:

```cpp
char word[50];
cin >> word;
```

In this case, cin reads up to the whitespace character. That is, it reads the 3 digit, the period character, and the 5 digit, leaving the space as the next character in the input queue. Then cin stores the character code for these four characters in the array and adds a null character. No translation is needed.

Finally, let's try an input variant for the char array type:

```cpp
char word[50];
cin.getline(word, 50);
```

In this case, cin reads through the newline (the sample input had fewer than 50 characters). All the characters through the final 2 digit are stored in the array, and a null character is added; the next character in the input queue will be the first character on the next line. No translation is needed.

On output, the opposite translations take place. That is, integers are converted to sequences of digits, and floating-point numbers are converted to sequences of digits and other characters (for example, 284.53=-1.587E+06). Character data requires no translation.

The main point is to this that all the input starts out as text. Therefore, the file equivalence—that is, a file in which each byte stores a character code. Not all files are text files. For example, databases and spreadsheets numeric data in numeric forms—that is, in binary or binary floating-point form. Also word processing files may contain text information, but they also contain non-text data for formatting, printers, and the link.

The file I/O discussed in this chapter parallels console I/O and should be used with text files. To create a text file, use a text editor such as Notepad for Windows, or vi editor for Unix/Linux. You can use a word processor, as long as you save the file in text format. The code editors that are part of IDEs also produce text files; indeed, the source code files are examples of text files. Similarly, you can use text editors to look at files created with text output.
