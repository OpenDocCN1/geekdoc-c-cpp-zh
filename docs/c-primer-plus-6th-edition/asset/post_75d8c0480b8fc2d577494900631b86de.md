
## An Overview of C++ Input and Output

### Streams and buffers

A C++ program views input or output as a stream of bytes. On input, a program extracts bytes from an input stream, and on output, a program inserts bytes into the output stream. For a text-oriented program, each byte can represent a character. More generally, the bytes in an input stream can come from the keyboard, but they can also come from a storage device, such as a hard disk, or from another program. Similarly, the bytes in an output stream can flow to the display, to a printer, or to another program. A stream acts as an intermediary between the program and the stream's source or destination. This approach enables a C++ program to treat input from the keyboard in the same manner as it treats input from a file; the C++ program merely examines the bytes without needing to know where they come. Similarly, by using streams, a C++ program can process output independent of where the bytes going. Managing input involves two stages:

- Associating a stream with an input
- Connecting the stream to a file

In other words, an input stream needs two connections, one at each end. The file-end connection provides a source for the stream, and the program-end connection dumps the stream into the program. (The file-end connection can be a file, but it can also be a device.) Similarly, managing output involves connecting the stream to the program and associating some output with the stream. It's like plumbing with bytes instead of water (see Figure 17.1).

Usually, input and output can be handled more efficiently by using a buffer. A buffer is a chunk of memory used as an intermediate, temporary storage for the transfer of information from a device or to a device. Typically, devices such as disk drives transfer in chunks of 512 bytes or more, whereas programs often process information one byte at a time. The buffer matches these two rates. For example, assume that a program is supposed to count the number of characters in a hard disk. The program could read one character from the file, read the next character from the file, and so. Reading a file character at a time from a disk requires a lot of activity and is slow. The buffered approach is to read a large chunk from the disk, store it in the buffer, and read the buffer one character at a time. Because it is much quicker to read individual bytes of data from memory than from a disk, this approach is much faster as well as easier. After the program reaches the buffer, the program should read another chunk of data from the disk. The principle is similar to that of a reservoir that collects millions of water during a big storm and then releases it at a more civilized rate (see Figure 17.2). Similarly, on output, a program can first fill the buffer and then transfer this entire block of data to a hard disk, clearing the buffer for the next batch of output. This is called flushing the buffer. Perhaps you can come up with your own plumbing-based analogy for that process.

Keyboard input provides one character at a time, so in that case, a program doesn't need a buffer to help match data transfer rates. However, buffered keyboard input allows the user to back up and correct input before transmitting it to a program. A C++ program normally flushes the input buffer when you press Enter. The examples in this book don't begin processing input until you press Enter. For output to the display, a C++ program normally flushes the output buffer when you transmit a newline character. Depending on the implementation, a program may flush input on other occasions, too, such as impending input. That is, when a program reaches an input statement, it flushes any output currently in the output buffer. C++ implementations that are consistent with ANSI C should behave in that manner.

## Streams, Buffers, and the iostream File

The business of managing streams and buffers can get a bit complicated, but including the iostream (formerly iostream.h) file brings in several classes designed to implement and manage streams and buffers for you. The C++98 version of C++ I/O defines class templates in order to support both `char` and `wchar_t` data. C++11 adds `char16_t` and `char32_t` specializations. By using the `typedef` facility, C++ makes the characterizations of these elements mimic the traditional non-template I/O implementation. Here are some of those classes (see Figure 17.3):

- `streambuf` class provides memory for a buffer, along with class methods for filling the buffer, accessing buffer contents, and managing the buffer.
- `ios_base` class represents general properties of a stream, such as whether it's for reading and whether it is a binary or text stream.
- `ios` class is based on `ios_base`, and includes a pointer to a `streambuf` object.
- `ostream` class derives from `ios` and provides output methods.
- `istream` class derives from `ios` and provides input methods.
- `iostream` class is based on `istream` and `ostream` classes and thus inherits both input and output methods.

To use these facilities, you use objects of the appropriate classes. For example, you use an `ostream` object as `cout` to handle output. Creating an object opens a stream, automatically associates it with the stream and makes the member functions available to you.

## Redefining I/O

The ISO/ANSI C++98 standard revised I/O a couple of ways. First, the change from `iostream.h` to `iostream`, placing the classes in the `std` namespace. Second, the I/O classes have been rewritten. To be an international language, C++ has to be able to handle character sets that require 16-bit or wider character type. The language added `wchar_t` (or "wide") character type. C++11 adds `char16_t` and `char32_t` types. Each type needs its own I/O facilities. Rather than developing separate sets of classes, the standards committee developed a template set of I/O classes, including `basic_iostream<T, traits<T>>` and `basic_ostream<T, traits<T>>`. The `traits<T>`, in turn, is a template class that defines particular traits for a character type, such as how to compare and its EOF value. The C++11 Standard provides `char` and `wchar_t` specializations of the I/O classes. For example, `istream` and `ostream` are typedefed for `char` specializations. Similarly, `wstream` and `wostream` are `wchar_t` specializations. For example, there is `wcout` for outputting wide character streams. The `ostream` header file contains these definitions. Certain type-independent information that should be kept in the `ios_base` class has been moved to the new `ios_base` class. This includes the various constants such as `ios::fixed`, which is now `ios_base::fixed`. Also `ios_base` contains some options that weren't available in the old `ios`.

The C++ `iostream` library takes care of many details for you. For example, including the `iostream` file in a program creates stream objects (for narrow and wide character streams) automatically:

- `cin` object corresponds to the standard input stream. By default, this stream is associated with the standard input device, typically a keyboard. The `wcin` object is similar but with the `wchar_t` type.
- `cout` object corresponds to the standard output stream. By default, this stream is associated with the standard output device, typically a monitor. The `wcout` object is similar but with the `wchar_t` type.
- `cerr` object corresponds to the standard error stream, which you can use for displaying error messages. By default, this stream is associated with the standard output device, typically a monitor, and the stream is unbuffered. This means that information is sent directly to the screen, without waiting for a buffer to fill or for a newline character. The `wcerr` object is similar but with the `wchar_t` type.
- `clog` object corresponds to the standard error stream. By default, this stream is associated with the standard output device, typically a monitor, and the stream is buffered. The `wclog` object is similar but with the `wchar_t` type.

What does it mean to say that an object represents a stream? Well, for example, when the `iostream` file declares a `cout` object for the program, that object has data members holding information relating to output, such as the field used in displaying data, the number of places after the decimal to use, the number base used for displaying integers, and the address of a `streambuf` object that describes the buffer to handle the output flow. A statement such as the following places the characters from the string "Bjarne free" into the buffer managed by `cout` via the pointer-to-streambuf object:

```
cout << "Bjarne free";
// "Bjarne free";
```

The `ostream` class defines the `operator<<()` function used in this statement, and the `ostream` also stores the `cout` data members for a variety of other classes, such as the ones this chapter discusses. Furthermore, C++ sees to it that the output from the buffer is directed to the standard output, usually a monitor, provided by the operating system. In short, one end of a stream is connected to the program, and the other end is connected to the standard output, and the `cout` object, with the help of a type `streambuf` object, manages the flow of bytes through the stream.

## Redirection

The standard input and output normally connect to the keyboard and the screen. Many operating systems, including Unix, Linux, and Windows, support redirection, a facility that lets you change the associations for the standard input and the standard output.
