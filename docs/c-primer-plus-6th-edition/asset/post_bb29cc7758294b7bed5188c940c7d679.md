
Note that the Stonew class has three constructors. They allow you to initialize a Stonew object to a floating-point number of pounds or to a combination of stone and pounds. You can create a Stonew object without initializing it:

```cpp
Stonew blossom(132.5);    // weight = 132.5 pounds
Stonew buttercup(10, 2);   // weight = 10 stone, pounds
Stonew bubbles();             // weight = default value
```

The class doesn't really need to declare a destructor because the automatic default constructor is fine for this case. On the other hand, providing an explicit declaration prepares for the future, when you will have to define constructors.

Also the Ston class provides two display functions. One displays the weight in pounds, and the other displays the weight in stone and pounds. Listing 11.17 shows the class methods implementation. Note that each constructor assigns values to all three private members. Thus, creating a Stonew object automatically sets both representations of weight.

# Automatic Conversions and Type Casts for Classes


Because a Stonew object represents a single weight, it makes sense to provide ways to convert an integer or a floating-point value to a Stonew object. And you have already done so! In C++, a constructor that takes a single argument as a blueprint for converting a value of argument to the class type. This following constructor serves as instructions for converting a double value to a type Stonew value:

```cpp
Stonew(double lbs); // template for double-to-Stonew conversion
```

That is, you can write code like the following:

```cpp
Stonew myCat; // create a Stonew object
myCat = 19.6; // use Stonew(double) to convert 19.6 to StonCat
```

The program uses the Stonew(double) constructor to construct a temporary Stonew object, using 19.6 as the initialization value. Then member assignment copies the contents of the temporary object into myCat. This process is termed an implicit conversion because it happens automatically, without the need of an explicit type cast.

Only a constructor can be used with just one argument as a conversion function. The following constructor has two arguments, so it cannot be used to convert types:

```cpp
Stonew(int n, double lbs); // not a conversion function
```

However it would act as a guide to int conversion if it provided a default value for the second parameter:

```cpp
Stonew(int n, double lbs = 0); // int-to-Stonew conversion
```

Having a constructor work as an automatic type-conversion function seems like a nice feature. As programmers acquire more experience with C++, however, they found that the automatic aspect isn't always desirable because it can lead to unexpected conversions. So C++ added a keyword, explicit, to turn off the automatic aspect. That is, you can declare the constructor this way:

```cpp
explicit Stonew(double lbs); // no implicit conversions allowed
```

This turns off implicit conversions as the preceding example but still allows explicit conversions—that is, conversions using explicit type casts:

# Chapter 11 Working with Classes

```cpp
Stonew myCat; // create a Stonew
myCat = 19.6; // not valid if Stonew (double) is declared explicit
mycat = Stonew(19.6); // ok, an explicit conversion
mycat = (Stonew) 19.6; // ok, old form for explicit typecast
```

# Note

A C++ constructor that contains one argument defines a type conversion from the argument to the class type. If the constructor is qualified with the keyword explicit, the constructor is used for explicit conversions only; otherwise, it is used for implicit conversions.

When does the compiler use the Stonew (double) function? If the keyword explicit is used in the declaration, Stonew (double) is used only for an explicit type cast; otherwise, it is also used for the implicit conversions:

- When you initialize a Stonew object to a double value
- When you assign a double value to a Stonew object
- When you pass a double value to a function that expects a Stonew argument
- When a function's declared to return a Stonew value
- When any of the preceding situations uses a built-in type that cannot be converted to double

Let look at the last point in detail. The argument-matching process by function prototyping lets the Stonew (double) constructor act as conversions for other types. That is, both of the following statements work by converting int to double and using the Stonew (double) constructor:

```cpp
Stonew Jumbo(7); // uses Stonew(double), converting int to double
Jumbo = 7; // uses Stonew(double), converting int to double
```

However, this two-step conversion works only if there is an unambiguous choice. That is, if the class also defines a Stonew(long) constructor, the compiler would reject these statements, pointing out that an int can be converted to either long or double, so the call is ambiguous.

# Program Notes

Note that when a constructor has a single argument, you can use the following form when initializing a class object:

```cpp
// a syntax for initializing a class object
// using a constructor with one argument
Stonew incognito = 275;
```

This is equivalent to the other two forms shown earlier:

```cpp
// standard syntax forms for initializing class objects
Stonew incognito = 275;
Stonew incognito = Stonew(275);
```

However, the last two forms can also be used with constructors that have multiple arguments.

Next, note the following two assignments from Listing 11.18:

```cpp
incognito = 276.8;
taft = 325;
```

The first of these assignments use the constructor with a type double argument to convert 276.8 to a Stonew value. This sets the pounds member of incognito to 276.8. Because it uses the constructor, this assignment also sets the stone and pds_left of the class. The second assignment converts a type int value to double and then uses Stonew(double) to set all three member values in the process.

Finally, note the following function call:

```cpp
display(422, 2); // convert double to double, then to Stonew
```

The prototype for display() indicates that its first argument should be the Stonew object. Either a Stonew & formal parameter... Confronted with an int argument, the compiler looks for a Stonew(int) constructor to convert the int to the desired Stonew type. Failing to find that constructor, the compiler looks for a constructor with some other built-in type that an int can be converted. The Stonew(double) constructor fits the bill. The compiler converts int to double and then uses Stonew(double) to convert the result to a Stonew object.

# Conversion Functions

Listing 11.18 converts a number to a Stonew object. Can you do the reverse? That is, can you convert a Stonew object to a double value, as in the following?

```cpp
Stonew wolfe (285.5);
double host = wolfe; // ?? possible ??
```

The answer is that you can do this—but not by using constructors. Constructors only provide for converting another type to the class. To do the reverse, you have to use a special form of a C++ operator function called a conversion function.
