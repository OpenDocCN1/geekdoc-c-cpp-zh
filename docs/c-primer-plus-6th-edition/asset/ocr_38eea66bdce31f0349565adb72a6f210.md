# Listing 3.13 init.cpp

```
// init.cpp -- type changes on initialization
#include <iostream>
int main() {

    using namespace std;
    cout.setf(ios_base::fixed, ios_base::float);
    float tree = 3; // int converted to float
    int guess(3.9832); // double converted to int
    int debt = 7.2E12; // result not defined in C++
    cout << "tree" << tree << endl;
    cout << "guess" << guess << endl;
    cout << "debt" << debt << endl;

    return 0;
}
```

Here is the output of the program in Listing 3.13 for one system:

```
tree = 3.000000
gess = 3
debt = 163481904
```

In this case, tree is assigned the floating-point value 3.0. Assigning 3.9832 to the int variable guess causes it to be truncated to 3; C++ uses truncation (discarding the fractional part) and not rounding (finding the closest integer value) when converting floating-point types to integer types. Finally, the int variable debt is unable to hold the value 7.2E12. This creates a situation where C++ doesn't define the result. On this system, debt ends up with the value 163481904, or about 1.6E09. Well, that is a novel way to reduce massive indebtedness

Some compilers warn of possible data loss for those statements that initialize integer variables to floating-point values. The value displayed for debt varies from compiler to compiler. For example, running the same program from Listing 3.13 on a second system produced a value of 214783647.
