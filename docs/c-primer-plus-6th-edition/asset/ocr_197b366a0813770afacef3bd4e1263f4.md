(To distinguish between the prefix and postfix versions of the ++ operator, C++ adopted the convention of letting operator++(int) be the suffix version, the argument is never used and hence not needed a name).
The main point here is not how, in detail, to define the iterator class, but that with such a class, the second function can be written like this:

```
iterator start;
for (start = head; start!= 0; ++start)
    if (*start == val)
        return start;
return 0;
```

This is very nearly the same as find_ar().The difference is how the two functions determine whether they've reached the end of the values being searched. The find_ar() function uses an iterator to one-pass-the-end, where find_ll() uses a null value stored in the final node. Remove that, and you can make the linked list have one additional element after the last element. For example, you could require that both the array and the linked list have a past-the-element, and you could search the end when the iterator reaches the past-the-end position. Then find_ar() and find_ll() would have the same way of detecting the end of data and become identical algorithms. Note that requiring a past-the-end element moves making requirements on iterators to making requirements on the container class.

The STL follows the approach just outlined. Each container (vector, list, deque and so on) defines an iterator type appropriate to the class.
