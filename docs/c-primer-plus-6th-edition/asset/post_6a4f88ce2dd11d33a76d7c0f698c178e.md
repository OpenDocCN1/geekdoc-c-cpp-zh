## Caution

You should avoid implicit conversion functions with care. Often a function that can only be invoked explicitly is the best choice.

In summary, C++ provides the following type conversions for classes:

- A class constructor that has a single argument serves as an instruction for converting a value of the argument type to the class type. For example, the Stonew class constructor with type int argument is invoked automatically when you assign a type int to a Stonew object. However, using explicit in the constructor declaration eliminates implicit conversions and allows only explicit conversions.
- A special class member operator function called a conversion function serves as an instruction for converting a class object to some other type. The conversion function is a class member, has no declared return type, has no arguments, and is called operator typeName(), where typeName is the type to which the object is to be converted. This conversion function is invoked automatically when you assign a class object to a variable of that type or use the cast operator to that type.

## Conversions and Friends

Let's begin adding to the Stonew class. As mentioned in the discussion of the Time class, you can use either a member function or a friend function to overload addition. (To simplify matters, assume that no conversion functions of the operator double() are defined.) You can implement addition with the following member function:

```
Stonew::operator+(const Stonew & st) const
{
double pds = pounds + st.pounds;
Stonew sum(pds);
return sum;
}
```

Or you can implement addition as a friend function this way:

```
{
double pds = st1.pounds + st2.pounds;
Stonew sum(pds);
return sum;
}
```

```
Stonew jennySt(9, 12);
Stonew bennySt(12, 8);
Stonew total;

```

Also given the Stonew (double) constructor, each form lets you do the following:

```
Stonew jennySt(9, 12);
double jennyD = 176.0;
Stonew total;
total = jennySt + jennyD;
```

But only the friend function lets you do this:

```
Stonew jennySt(9, 12);
double bennyD = 146.0;
Stonew total;
total = pennyD + jennySt;
```

To see why, you can translate each addition into the corresponding function calls. First,

```
total = jennySt + bennySt;
```

In either case, the actual types match the formal arguments. Also the member-function is invoked, as required, by a Stonew object.

```
total = jennySt.operator+(bennySt); // member function
total = operator+(jennySt, bennySt); // friend function
```

```
total = jennySt + jennyD;
```

```
total = jennySt.operator+(jennyD); // member function
total = operator+(jennySt, jennyD); // friend function
```

Again, the member function is invoked, as required, by a Stonew object. This time, in each case, one argument (jennyD) is type double, which invokes the Stonew(double) constructor to convert the argument to a Stonew object.

By the way, an operator double() member function defined would create confusion at this point because that would create another option for interpretation. Instead of converting jennyD to double and performing Stonew addition, the compiler could convert jennySt to double and perform double addition. Having too many-conversion functions creates ambiguities.

Finally.

```
total = pennyD + jennySt;
becomes
total = operator+(pennyD, jennySt); // friend function
```

Here, both arguments are type double, that both objects invokes the Stonew (double) constructor convert them to Stonew objects.

However, the member function version wouldn't be able to add jennySt to pennyD. Converting the addition syntax to a function could look like this:

```
total = pennyD.operator(jennySt); // not meaningful
```

But this is meaningless because only a class object can invoke a member function. ++ does not attempt to convert pennyD to a Stonew object. Conversion takes place for member function arguments, not for member function invokers.

The lesson here is defining addition as a friend makes it easier for a program to accommodate type conversions. The reason is that both operands become function arguments, so function prototyping comes into play for both operands.

## Choices in Implementing Addition

Given that you want to add quantities to Stonew quantities, you have a couple choices. The first, as you just saw, to define the following as a friend function and have the Stonew (double) constructor handle conversions of type double arguments to type Stonew arguments:

```
operator+(const Stonew &, const Stonew &)
```

The second choice is to further overload the addition operator with functions that member function:

```
Stonew operator+(double x); // member function
friend Stonew operator+(double x, Stonew & s);
```

That, the following statement exactly matches:

```
total = pennyD + jennySt; // member function
```

And the following statement exactly matches:

```
total = pennyD + jennySt; // friend function
```

Earlier, we did something similar for multiplication. Each choice has advantages. The first choice (relying on implicit conversions) results in a shorter program because you define fewer functions. The second choice (additional functions), however, is the mirror image. It makes for a longer program and more work on your part. If your program makes intensive use of adding double values to Stonew objects, it may pay to overload addition directly. If you want to be more careful, on explicit conversions.

## Summary

This chapter covers many important aspects of defining and using classes. Some of the material in this chapter may seem vague until your experiences enrich your understanding. Normally, the way you can access class members is by using a method. C++ alleviates restriction with friend functions. To make a friend function, you declare the function in the class and preface the declaration with the keyword friend.

C++ extends overloading to operators by letting you define special operator functions that describe how operators relate to a particular class. An operator function can be a member function or a friend function. (A few can only be class members.) C++ lets you invoke an operator function by either calling the function or by using the overloaded operator with its usual syntax. An operator function for the operator op has this form:

```
operator op(argument-list)
```

argument-list represents operands for the operator. If the operator function is a member function, then the first operand is the invoking object and is not part of argument-list. For example, this overloaded addition for the Vector class. If up, right, and result are three vectors, you can use either of the following statements to invoke vector addition:

```
result = up.operator+(right);
result = up + right;
```

For the second version, the fact that the operands up and right are type Vector tells C++ to use the Vector definition of addition. When an operator function is a member function, the first operand is the invoking object.
