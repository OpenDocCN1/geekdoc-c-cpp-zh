

methods 将元素视为 const。类似地，crbegin() 和 crend() 是 rbegin() 和 rend() 的 const 版本。

更重要的是，STL 容器现在除了传统的拷贝构造函数和常规赋值运算符之外，还具有移动构造函数和移动赋值运算符。这将在后面描述移动语义。

## valarray 升级

valarray 模板是独立于 STL 开发的，其原始设计排除了使用基于范围的 STL 算法处理 valarray 对象。C++11 添加了两个函数 begin() 和 end()，每个函数都接受一个 valarray 参数。它们返回指向 valarray 对象中第一个元素和最后一个元素之后位置的迭代器，从而可以使用基于范围的 STL 算法（参见第 16 章）。

## export 废弃

C++98 引入了 export 关键字，希望创建一个将模板定义分离到包含原型和模板声明的接口文件以及包含模板函数和方法定义的实现文件的方式。事实证明这不切实际，并且 C++11 结束了对 export 的支持。然而，标准仍将 export 保留为关键字以供将来可能使用。

## 角括号

为避免与 >> 运算符混淆，C++ 要求在嵌套模板声明中在括号之间留有空格：

```
std::vector<std::list<int>> vl; // not ok
```

C++11 去除了该要求：

```
std::vector<std::list<int>> vl; // ok in C++11
```

## 右值引用

传统的 C++ 引用，现在称为左值引用，将标识符绑定到左值。左值是表示程序可以获取其地址的数据的表达式，例如变量名或解引用的指针。最初，左值可以出现在赋值语句的左侧，但 const 修饰符的出现允许构造不能赋值但仍可寻址的构造：

```
* pt = new int;
const int b = 101; // can't assign to b, but &b is valid
int & n = n; // n identifies datum at address &
int & rt = *pt; // pt identifies datum at address pt
const int & rb = b; // b identifies datum at address &
```

C++11 添加了右值引用（在第 8 章中讨论），用 && 表示，可以绑定到值——即可以出现在赋值表达式右侧且不能应用地址运算符的值。示例包括字面常量（如 C 风格字符串，其求值结果为地址）、诸如 x+y 之类的表达式，以及函数返回值，前提是函数不返回引用：

```
int x = 10;
int y = 23;
int && r1 = 13;
int && r2 = x + y;
double && r3 = std::sqrt(2.0);
```

请注意，r2 实际上绑定到 x + y 在那时求值得到的值。也就是说，r2 绑定到值 23，并且 r2 不受 x 或 y 后续更改的影响。

有趣的是，将右值绑定到右值引用会使值存储在可以取地址的位置。也就是说，虽然不能对 13 应用 & 运算符，但可以对 r1 应用。这将值绑定到特定地址正是使通过右值引用访问数据成为可能的原因。

清单 18.1 提供了一个简短的示例，说明了有关值引用的这些要点。

### Listing 18.1 rvref.cpp

```
// rvref.cpp -- simple uses of rvalue references
#include <iostream>

inline double f(double tf) {return 5.0*(tf-32.0)/9.0};
int main() {
    using namespace std;
    double &&r1 = 21.5;
    double &&r2 = 1.8 * tc + 32.0;
    double &&r3 = f(r2);
    cout << "tc value and address: " << tc << ", " << &tc << endl;
    cout << "r1 value and address: " << r1 << ", " << &r1 << endl;
    cout << "r2 value and address: " << r2 << ", " << &r2 << endl;
    cout << "r3 value and address: " << r3 << ", " << &r3 << endl;
    cin.get();
    return 0;
}
```

以下是示例输出：

rd1 value and address: 7.07, 002FF728
rd2 value and address: 70.7, 002FF70C
rd3 value and address: 21.5, 002FF6F0

## 移动语义与右值引用

引入右值引用的主要原因之一是为了实现移动语义，本章的下一个主题。

现在让我们继续讨论尚未讨论的话题。C++11 启用了一种称为移动语义的技术。这引发了一些问题，例如什么是移动语义，C++11 如何启用它们，以及为什么需要它们？我们将从最后一个问题开始。

## 需要移动语义

让我们看看在 C++11 之前复制过程是如何工作的。假设我们从以下内容开始：

```
vector<string> vstr;
// build up a vector of 20,000 strings, each of 1000 characters
```

```
vector<string> vstr_copy1(vstr); // make vstr_copy1 a copy memory allocation, so they
```

向量和字符串类都使用动态内存，因此它们将具有使用某种版本的 new 的拷贝构造函数。为了初始化 vstr_copy1 对象，vector<string> 拷贝构造函数将用于为 20,000 个对象分配内存，并且每个字符串对象依次将调用字符串拷贝构造函数，该构造函数将用于为 1000 个字符分配内存。然后将 20,000 个字符从 vstr 控制的内存复制到 vstr_copy1 控制的内存。这是一项大量工作，但如果必须完成，那就必须完成。

但它“必须完成”吗？有时答案是否定的。例如，假设我们有一个返回 vector<string> 对象的函数：

```
vector<string> allcaps(const vector<string>& & vs)
{
vector<string> temp;
// code that stores an all-uppercase version of vs in temp
return temp;
}
```

接下来，假设我们以这种方式使用它：

```
vector<string> vstr;
// build up a vector of 20,000 strings, each of 1000 characters
vector<string> vstr_copy1(vstr); // #1
vector<string> vstr_copy2(allcaps(vstr)); // #2
```

表面上，语句 #1 和 #2 相似；每个都使用现有对象来初始化新的 vector<string> 对象。如果我们按面值接受这段代码，allcaps() 创建一个管理 20,000,000 个字符的 temp 对象，向量和字符串拷贝构造函数会费力地创建一个 20,000,000 字符的副本，然后程序删除由 allcaps() 返回的临时对象。 （一个真正没有灵感的编译器甚至将 temp 复制到临时返回对象，删除 temp，然后删除返回对象。）主要问题是浪费了大量精力。因为临时对象被删除，所以最好能够将其数据所有权转移给 vstr_copy2？也就是说，而不是将 20,000,000 个字符复制到新位置并删除旧位置，将字符保留在原地并将 vstr_copy2 标签附加到它们。这类似于将文件从一个目录移动到另一个目录时发生的情况：这种方法称为移动语义。矛盾的是，移动语义实际上避免了移动数据；它只是调整了记账。

为了实现移动语义，我们需要一种方法让编译器知道何时需要真正复制，何时不需要。这里就是右值引用发挥作用的地方。我们定义两个构造函数：一个是常规构造函数，可以使用 const 左值引用作为参数。此引用将绑定到左值参数，如语句 #1 中的 vstr。另一个称为移动构造函数，可以使用右值引用，并可以绑定到右值参数，如语句 #2 中的 allcaps()。拷贝构造函数可以执行深度拷贝，而移动构造函数只需调整记账。移动构造函数在将所有权转移给新对象时可能会改变其身份，这意味着右值引用不应为 const。

## 一个移动示例

让我们看一个示例，了解移动语义和右值引用是如何工作的。清单 18.2 定义并使用了 Useless 类，该类结合了动态内存分配、常规构造函数和移动构造函数，该构造函数使用移动语义和右值引用。为了说明所涉及的过程，构造函数和析构函数异常，并且该类使用状态变量来跟踪对象的数量。此外，还省略了一些重要方法，例如赋值运算符。 （尽管有这些遗漏，Useless 类不应与环保的 Useless 类混淆。）
