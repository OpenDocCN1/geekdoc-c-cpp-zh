# Abstract Base Classes

When a class declaration contains a virtual function, you can't create an object of that class. The idea is that classes with pure virtual functions exist solely to serve as base classes. For a class to be a genuine ABC, it has to have at least one pure virtual function. It is the = 0 in the prototype that makes a virtual function a pure virtual function. In the class of the Area() method, which has no definition, C++ allows even a pure virtual function to have a definition. Perhaps all the base methods are like Move() in that they can be defined for the base class, but you still need to make the abstract virtual. You could make the prototype virtual:

```
void Move(int nx, ny) = 0;
```

This makes the base class abstract. But you could still provide a definition in the implementation file:

```
void BaseEllipse:Move(int nx, ny) { x = nx; y = ny; }
```

In short, the 0 in the prototype indicates that the class is an abstract base class and the class does not necessarily have to define the function.

Now you can derive the Ellipse and Circle class from the BaseEllipse class, adding the members to complete each class. One point to note is that the Circle class always represents circles, whereas the Ellipse represents ellipses that can also be circles. However, an Ellipse can be scaled to a non-circle, whereas a Circle class must remain a circle.

A program using BaseEllipse objects would be able to create Ellipse objects and Circle objects but no the same base class, a collection of such objects can be managed with an array of BaseEllipse pointers. Classes such as Circle and Ellipse are sometimes termed concrete classes to indicate that you can create objects of those types.

In short, an ABC describes an interface that uses at least one pure virtual function, and classes derived from ABC use regular virtual functions to implement the interface in terms of the properties of the particular class.
