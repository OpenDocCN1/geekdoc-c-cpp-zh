# Storage Duration, Scope, and Linkage

What if you define an external variable and then declare a variable by the same name inside a function? The second declaration is interpreted as a definition for an automatic variable. The automatic variable is the one that is in scope when the program executes that particular function. Listings 9.5 and 9.6, to be compiled together, illustrate using an external variable in two files and an automatic variable handles a global variable of the same name. The program also shows how you can use the keyword to re-declare an external variable defined earlier and how you can use C++ scope-resolution operator to access the other variable.

# Global Versus Local Variables

Now that you have a choice of using global or local variables, which should you use? At first, global variables have a seductive appeal—because all functions have access to a global variable, you do not have to bother passing arguments. But this easy access has a heavy price: unreliable programs. Computing experience has shown that the better your program does of isolating from unnecessary, the better the program does in preserving the integrity of the data. Most, you should use local variables and functions on a need-know basis rather than make data available indiscriminately. As the previous example, OOP takes this step further.

# Static Duration, Internal Linkage

Applying the static modifier to a file-variable gives it internal linkage. The difference between internal linkage and external linkage becomes meaningful in multifile programs. In this context, a variable with internal linkage means it is local to the file that contains. But a regular external variable has external linkage, meaning that it can be used in different files.

What if you want to use the same name to denote different variables in different files? Can you just omit the extern?

```cpp
// file1
int errors = 20; // external declaration
...

// file2
int errors = 5;
void froobish() {
    cout << errors; // fails
}
```

No, this attempt fails because it violates the one definition rule. The file2 definition attempts to create an external variable, the program winds up with two definitions of errors.

But if a file declares a static variable with the same name as an ordinary external variable in another file, the static version is the one in scope for that file:

```cpp
// file1
int errors = 20; // external declaration
...

// file2
static int errors = 5; // known to file2
void froobish() {
    cout << errors; // uses errors defined in file2
}
```

This does not violate the one definition rule because the keyword static establishes that the identifier has internal linkage, so no attempt is made to bring in an external definition.

> Note
In a multifile program, you can define an external variable in one and only one file. All others using that variable must declare that variable with the extern keyword.

You can use an external variable to share data among different parts of a multifile program.You use a static variable with internal linkage to share data among functions found in just one file.(Namespaces offer an alternative method for this.) If you also make a file-scope variable, you don't need to worry about its name conflicting with file-scope variables in other files.
