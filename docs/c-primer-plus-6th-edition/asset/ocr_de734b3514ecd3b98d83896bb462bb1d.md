# Pointers, Arrays, and Pointer Arithmetic

# Static Storage

Static storage is storage that exists throughout the execution of an entire program. There are two ways to make a static variable. One is to define it externally, outside a function. The other is to use the keyword static when declaring a variable:

```
static double fee = 56.50;
```

Under K&R C, you can initialize only static arrays and structures, whereas C++ Release 2.0 (and later) and ANSI C allow you to initialize automatic arrays and structures, too. However, as you may have discovered, C++ implementations do not yet initialization for automatic arrays and structures.

Chapter 9 discusses static storage in memory. The main point that you should note about automatic and static storage is that these methods define the lifetime of a variable. Either the variable exists for the entire duration of a program (a static variable) or it exists only when a particular function is being executed (an automatic variable).

# Dynamic Storage

The new and delete operators provide a more flexible approach than automatic and static variables. They manage a pool of memory, which C++ refers to as the free store or heap. Listing 4.22 shows how new and delete allow you to allocate memory in one function and free it in another. The lifetime of the data is not tied arbitrarily to the life of the program or the life of a function. Using new and delete gives you much more control over how your program uses memory than using ordinary variables. However, memory management becomes more complex. In a stack, the automatic addition and removal mechanisms in the use of memory are always continuous. The interplay between new and delete can leave holes in the free store, making keeping track of where to allocate new memory requests more difficult.

# Stacks, Heaps, and Memory Leaks

What happens if you don't delete after creating a variable on the free store (or heap) with the new operator? The variable or construct dynamically on the free store continues to persist if delete is not called, even though the memory that contains the pointer has freed by rules of scope and object lifetime. In essence, you have no way to access the memory because the pointer to the memory that contains it is gone. You have created a memory leak. Memory that has been leaked remains unusable through the life of the program; it is allocated but cannot be deallocated. In extreme (though not uncommon) cases, memory leaks can be severe that they use up all the memory for the application, causing it to crash with an out-of-memory error. In addition, these leaks may negatively affect some operating systems or other applications running in the same memory space, causing them to fail.

Even the best programmers and software companies create memory leaks. To avoid them, it's best to get into the habit of joining your new and delete operators immediately, planning for entering the deletion of your construction as soon as you dynamically allocate it on the free store. C++'s smart pointers (Chapter 16) help automate the task.
