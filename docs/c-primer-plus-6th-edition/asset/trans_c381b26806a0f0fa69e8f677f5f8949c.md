

## 异常

接下来，在程序开始时，你将此函数指定为你选择的意外异常处理动作：
set_unexpected(myUnexpected);

最后，你在异常规范和 catch 块序列中包含 bad_exception 类型：

```
double Argh(double, double) throw(out_of_bounds, bad_exception);
...
try {
    x = Argh(a, b);
}
catch(out_of_bounds & ex)
{
    ...
}
catch(bad_exception & ex)
{
    ...
}
```

## 异常注意事项

从前面关于使用异常的讨论中，你可能会推断出（并且是正确的）异常处理应该设计到程序中，而不是事后添加。尽管如此，这样做也有一些缺点。例如，使用异常会增加程序的大小并降低其速度。异常规范与模板配合得不好，因为模板函数会根据使用的特定特化而抛出不同种类的异常。异常和动态内存分配也并不总是配合得很好。

让我们进一步看看动态内存分配和异常。首先，考虑以下函数：

```
void test1(int n)
{
    string msg("I'm trapped in an endless loop");
    if (ob_no)
        throw exception();
    ...
    return;
}
```

string 类使用动态内存分配。通常，当函数到达 return 并终止时，msg 的 string 析构函数会被调用。得益于栈展开，throw 语句即使过早终止函数，仍然允许析构函数被调用。因此，在这种情况下，内存得到正确管理。

现在考虑这个函数：

```
void test2(int n)
{
    double * ar = new double[n];
    ...
    if (oh_no) {
        throw exception();
    ...}
    delete [] ar;
    return;
}
```

这里有一个问题。栈展开会将变量 ar 从栈中移除。但函数的过早终止意味着函数末尾的 delete [] 语句被跳过。指针消失了，但它所指向的内存块仍然完整且无法访问。简而言之，存在内存泄漏。
泄漏可以避免。例如，你可以在抛出异常的同一函数中捕获该异常，但在 catch 块中加入一些清理代码，然后重新抛出异常：

```
void test3(int n)
{
    double * ar = new double[n];
    ...
    try {
        if (oh_no) {
            throw exception();
        }
    } catch(exception & ex) {
        delete [] ar;
        throw;
    ...}
    delete [] ar;
    return;
}
```

然而，这显然增加了疏忽和其他错误的可能性。另一种解决方案是使用第 16 章“string 类和标准模板库”中讨论的智能指针模板之一。
简而言之，虽然异常处理对于某些项目极其重要，但它在编程工作量、程序大小和程序速度方面确实有成本。另一方面，没有错误检查的成本可能更糟。

## 异常处理

在现代库中，异常处理似乎达到了新的复杂程度——其中很大一部分是由于未记录或记录不佳的异常处理例程所致。任何熟悉现代操作系统使用的人都见过未处理的异常造成的错误和问题。这些错误的程序员往往面临着艰难的 uphill 战斗，学习库内部的复杂性：抛出了哪些异常、何时发生、以及如何处理它们。

初级程序员很快就会发现，研究库中异常处理的战斗与学习语言本身的斗争一样困难；现代库可以包含与任何 C++ 语法细节一样困难的例程和范式。对库和类的复杂性的接触和理解，对于良好的软件来说，与你花费在 C++ 本身上的时间一样必要。你从库的文档和源代码中解读的异常和错误处理细节将始终为你服务并保持良好状态。

## 运行时类型识别

运行时类型识别（RTTI）是 C++ 最新的添加之一，并且并非所有实现都支持。其他实现可能有 RTTI 开启/关闭的编译器设置。RTTI 的意图是为程序在运行时确定对象的类型提供一种标准方式。许多库已经为其自己的类对象提供了这样做的方法，但在 C++ 缺乏内置支持的情况下，每个厂商的机制通常与其它厂商的不兼容。为 RTTI 创建语言标准应该允许未来的库彼此兼容。

## RTTI 有何用途？

假设你有一个从公共基类派生的类层次结构。你可以将基类指针设置为指向该层次结构中任何类的对象。接下来，你调用一个函数，该函数在处理一些信息后，选择其中一个类，创建该类型的一个对象，并返回其地址，该地址被分配给基类指针。你如何知道指向的是什么类型的对象？

在回答这个问题之前，你需要思考为什么你想知道类型。也许你想调用类方法的正确版本。如果是这种情况，只要该函数是类层次结构中所有成员都拥有的虚函数，你实际上不需要知道对象类型。但也可能派生对象有一个未继承的方法。在这种情况下，只有某些对象可以使用该方法。或者，出于调试目的，你可能想跟踪生成了哪种类型的对象。对于这两种情况，RTTI 提供了答案。

## RTTI 如何工作？

C++ 有三个支持 RTTI 的组件：

- dynamic_cast 运算符如果可能，将基类指针生成为派生类型指针。否则，运算符返回 0，即空指针。
- typeid 返回一个标识对象确切类型的数值。
- type_info 结构保存关于特定类型的信息。

你只能在具有虚函数的类层次结构中使用 RTTI。原因在于，这些是唯一应该将派生对象的地址分配给基类指针的类层次结构。

## 注意事项

RTTI 仅适用于具有虚函数的类。

让我们检查 RTTI 的三个组件。

## dynamic_cast 运算符

dynamic_cast 运算符旨在成为使用最频繁的 RTTI 组件。它不回答指针指向什么类型的对象这个问题。相反，它回答的问题是你可以安全地将对象的地址分配给特定类型的指针吗？让我们看看这意味着什么。假设你有以下层次结构：

```
class Grand { has virtual methods };
class Superb : public Grand { ... };
class Magnificent : public Superb { ... };
```

接下来，假设你有以下指针：

```
Grand * pg = new Grand;
Grand * ps = new Superb;
Grand * pm = new Magnificent;
```

最后，考虑以下转换：

```
Magnificent * p1 = (Magnificent *) pm; // #1
Magnificent * p2 = (Magnificent *) pg; // #2
Superb * p3 = (Magnificent *) pm; // #3
```

这些转换中哪些是安全的？根据类声明，它们都可能是安全的，只有那些指针与对象相同类型或是对对象是直接或间接基类型的指针才保证安全。例如，类型转换 #1 是安全的，因为它将一个 Magnificent 类型指针设置为指向一个 Magnificent 对象。类型转换 #2 不安全，因为它将一个基类对象（Grand）的地址分配给一个派生类指针。然后，程序期望基类对象具有派生类属性，而一般来说这是错误的。例如，Magnificent 对象可能具有 Grand 对象所缺乏的数据成员。类型转换 #3 然而是安全的，因为它将一个派生类对象的地址分配给一个基类指针。也就是说，公有派生保证 Magnificent 对象也是一个 Super 对象（直接基类）和一个 Grand 对象（间接基类）。因此，安全地将其地址分配给所有类型的指针。使用三种类型中的任何一种指针对 Magnificent 对象调用虚函数都将调用 Magnificent 方法。

请注意，类型转换是否安全的问题比指针指向什么类型的对象这个问题更一般、更有用。想要知道类型的原因通常是为了知道是否可以安全地调用特定方法。你不一定需要确切的类型来调用方法。类型可以是为其定义了虚方法版本的基础类型。下一个示例说明了这一点。

首先，让我们看看 dynamic_cast 语法。运算符的使用如下，其中 pg 指向一个对象：

```
Super * pm = dynamic_cast<Super *>(pg);
```

这段代码询问 pg 是否可以安全地类型转换（正如前面所述）为类型 Super *。如果可以，运算符返回对象的地址。否则它返回空指针。

## 注释

通常，dynamic_cast<Type *>(pt) 转换如果指向的对象 (*pt) 是 Type 或直接或间接派生自类型 Type，则将指针 pt 转换为类型 Type * 指针。否则，表达式求值为 0，即空指针。

清单 15.17 说明了该过程。首先它定义了三个类，恰好命名为 Grand、Super 和 Magnificent。Grand 类定义了一个虚 Speak() 函数，每个其他类都定义了它。Super 类定义了一个虚 Say() 函数，Magnificent 重新定义了它（参见图 15.4）。程序定义了一个 GetOne() 函数，该函数随机创建并初始化这三种类型之一并返回一个类型为 Grand * 指针的地址。（GetOne() 函数模拟了一个做出决定的活跃用户。）一个循环将这个 Grand * 分配给一个名为 pg 的类型为 Grand * 的变量，并使用 pg 调用 Speak() 函数。因为这个函数是虚的，所以代码正确地调用了与指向对象相适应的 Speak() 版本：

```
for (int i = 0; i < 5; i++)
{
  pg = GetOne();
  pg->Speak();
}
```
