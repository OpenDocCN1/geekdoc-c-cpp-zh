## The Why of Lambdas

You may be wondering what need, other than the flowering of geekly expressionism, the lambda serves. Let's examine this question in terms of four qualities: proximity, brevity, efficiency, and capacity.

Many programmers feel that it is useful to locate definitions close to where they are. That way, you may need to scan through pages of source code to find, say, the third argument to a count_if() function call accomplishes. Also if you need to modify the code, all the components are close at hand. And if you cut and paste the code for use elsewhere, all the components are at hand. From that standpoint, lambdas are ideal because the definition is at the point of usage. Functors are worst for functions because functors cannot be defined inside other functions, so the definition will be located quite far from the point of usage. Functors can be pretty good as a class, including a functor class, can be defined inside a function, so the definition can be located close to the point of use.

In terms of brevity, the functor is more verbose than the equivalent function or lambda code. Functions and lambdas are approximately equally brief. One apparent exception would be if you had to use a lambda twice:

```
count1 = std::count_if(n1.begin(), n1.end(),
[] (int x){return x % 3 == 0});
count2 = std::count_if(n2.begin(), n2.end(),
[] (int x){return x % 3 == 0});
```

## Lambda Functions 1189

But you don't actually have to write out the lambda twice. Essentially, you can create a name for the anonymous lambda and use the name twice:

```
auto mod3 = [](int x){return x % 3 == 0}; // mod3 a name for the lambda
count1 = std::count_if(n1.begin(), n1.end(), mod3);
count2 = std::count_if(n2.begin(), n2.end(), mod3);
```

You can use this no-longer-anonymous lambda as an ordinary function:
bool result = mod3(z); // result is true if z % 3 == 0

Unlike an ordinary function, however, a named lambda can be defined inside a function. The actual type for mod3 will be some implementation-dependent type that the compiler uses to keep track of lambdas.

The relative efficiencies of the three approaches boils down to what the compiler chooses to inline. Here, the function pointer approach is handicapped by the fact that compilers traditionally don't inline a function that has address taken because the content of a address implies a non-inline function. With functions and lambdas, there is no apparent contradiction with inline.

Finally, lambdas have some additional capabilities. A lambda can capture any anonymous variable in scope.Variables to be captured by having their names within the brackets. If the variable is used, as in [=], the variable is accessed by value. If the name is preceded by &, as in [&count], the variable is accessed by reference. Using [&] provides access to all the automatic variables by reference, and [=] provides access to all the automatic variables by value. You can also mix and match. For instance, [&, &ed] would provide access to ted and ed by reference, [&,] would provide access by value and to all other automatic variables by reference, and [=, &ed] would provide access by reference to ed and by value to the remaining automatic variables. In Listing 18.4, you can replace

int count13;

```
count13 = std::count_if(numbers.begin(), numbers.end(),
    [](int x){return x % 13 == 0});
```

with this:

```
int count13 = 0;
std::for_each(numbers.begin(), numbers.end(),
    [&count13](int x){count13 += x % 13 == 0});
```

The [&count13] allows the lambda to use count13 in its scope. Because count13 is captured by reference, any changes to count13 in the lambda are changes to the original count13. The expression x % 13 == 0 evaluates to true if x is divisible by 13, and converts to 1 when added to count13. Similarly, for_each() applies the lambda expression to each element of numbers, count13 counts the number of elements divisible by 13.

The main motivation for adding lambdas to C++ was to enable using a function-like expression as an argument to a function expecting a function pointer or functor as an argument. The typical lambda would be a test expression or comparison expression that could be written as a simple return statement. That keeps the lambda short and easy to understand and enables automatic deduction of the return value. However, it is likely that a subset of the ingenious C++ programming community will develop others.

## Wrappers

C++ provides several wrappers or adapters. These are objects used to provide a more uniform or appropriate interface for other programming elements. For example, Chapter 16 described bind1 and bind2, which adapt functions with two parameters to match with STL algorithms that expect functions with one parameter specified as an argument. C++11 provides additional wrappers. They include the bind template, which provides a more flexible alternative to bind1 and bind2, the mem_fn template, which allows a member function to pass as a regular function, the reference_wrapper template allows you to create an object that acts like reference but can be copied, and the function wrapper, which provides a way to handle several function-like uniformly.

Let's look more closely at one example of wrapper, the function wrapper, and at the problem it addresses.

## The function Wrapper and Template Inefficiencies

Consider the following line of code:


What is ef? It could be the name of the function. It could be a pointer to a function. It could be a function object. It could be a name assigned to a lambda expression.
