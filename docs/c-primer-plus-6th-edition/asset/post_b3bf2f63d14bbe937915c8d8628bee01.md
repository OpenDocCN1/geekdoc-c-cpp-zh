# Pointers and Objects Summary

You should note several points about pointers to objects (refer to Figure 12.5 for a summary):

- You declare a pointer to an object by using the usual notation:
  `String * glamour;`

- You can initialize a pointer to point to an existing object:
  `String * first = &sayings[0];`

- You can initialize a pointer by using new. The following creates a new object:
  `String * favorite = new String(sayings[choice]);`

Also see Figure 12.6 for a more detailed look at an example of initializing a pointer with new.

- Using new with a class invokes the appropriate class constructor to initialize the newly created object:
  // invokes default constructor
  `String * gleep = new String;`

- invokes the String(const char *) constructor
  `String * glop = new String("my my my");`

```cpp
// invokes the String(const String &) constructor
String * favorite = new String(sayings[choice]);
```

- You use the -> operator to access a class method via:
  `if (sayings[i].length() < shortest->length())`

- You apply the dereference operator (*) to a pointer to an object to obtain:
  `if (sayings[i] < *first) // compare object values`
  `first = &sayings[i]; // assign object address`

# Looking Again at Placement new

Recall that placement new allows you to specify the memory location used to allocate memory. Chapter 9, "Memory Models and Namespaces," discusses placement new in the context of built-in types. Using placement new with objects adds some twists. Listing 12.8 uses placement new with regular new to allocate memory for objects. It defines a class with a constructor and destructor so that you can follow the history of objects.

Listing 12.8 placenew.cpp

```cpp
// placenew.cpp -- new, placement new, delete
#include <iostream>
#include <string>
#include <new>
using namespace std;
const int BUF = 512;
```

# Classes and Dynamic Memory Allocation

```cpp
class JustTesting
{
private:
    string words;
    int number;
public:
    JustTesting(const string & s = "Just Testing", int n = 0)
    {words = s; number = n; cout << "constructed\n"; }
    ~JustTesting() { cout << "destroyed\n"; }
    void Show() const { cout << number << endl; }
};

int main()
{
    char * buffer = new char[BUF]; // get a block of memory

    JustTesting *pc1, *pc2;

    pc1 = new (buffer) JustTesting; // place object in buffer
    pc2 = new JustTesting("Heap1", 20); // place object on heap

    cout << "Memory addresses:\n" << "buffer: " << (void *) buffer << " heap: " << pc2 << endl;
    cout << "Memory contents:\n";
    cout << pc1->Show();
    cout << pc2->Show();

    JustTesting *pc3, *pc4;
    pc3 = new (buffer) JustTesting("Bad Idea", 6);
    pc4 = new JustTesting("Heap2", 10);

    cout << "Memory contents:\n";
    cout << pc3->Show();
    cout << pc4->Show();

    delete pc2; // free Heap1
    delete pc4; // free Heap2
    delete [] buffer; // free buffer
    cout << "Done\n";
    return 0;
}
```

# Using Pointers to Objects

The program in Listing 12.8 uses new to create a memory buffer of 512 bytes. Then it uses new to create two objects of type JustTesting on the heap and attempts to use placement new to create two objects of type JustTesting in the memory buffer. Finally, it uses delete to free the memory allocated by new. Here is the output:

```
Just Testing constructed
Heap constructed
Memory block addresses:
buffer: 0032AB0    heap: 0032CE0
Memory contents:
0032AB0: Just Testing, 0
0032CE0: 20
Bad Idea constructed
Heap2 constructed
Memory contents:
0032AB0: Bad Idea, 6
0032ECB: Heap2, 10
Heap1 destroyed
Heap2 destroyed
Done
```

As usual, the formatting and exact values for the memory addresses will vary from system to system.

There are a couple of problems with placement new as used in Listing 12.8. First, when creating a second object, placement new simply overwrites the same location used for the first object with a new object. Not only is this rude, it means that the destructor was never called for the first object. This, of course, would create real problems if, say, the class used dynamic memory allocation for its members.

Second, using delete with pc2 and pc4 automatically invokes the destructors for the two objects that pc2 and pc4 point to. But using delete [] with buffer does not invoke the destructors for the objects created with placement new.

One to be learned here is the same you learned in Chapter 9: It's up to you to manage the memory locations in a buffer that placement new populates. To use two different locations, you provide two different addresses within the buffer, making sure that the locations don't overlap. You, for example, use this:

```cpp
pc1 = new (buffer) JustTesting;
pc3 = new (buffer + sizeof(JustTesting)) JustTesting("Better Idea", 6);
```

Here the pointer pc3 is offset from pc1 by the size of a JustTesting object.
The second to be learned here is that if you use placement new to store objects, you need to arrange for their destructors to be called. But how? For objects created on the heap, you can use this:

```cpp
delete pc2; // delete object pointed to by pc2
```

But you can't use:

```cpp
delete pc1;      // delete object pointed to by pc1? NO!
delete pc3;      // delete object pointed to by pc3? NO!
```

The reason is that delete works in conjunction with new but not with placement new. The pointer pc3, for example, does not receive an address returned by new, so delete pc3 throws a runtime error. The pointer endl, on the other hand, has the same numeric value as buffer, but buffer is initialized using new (), so it freed deleting [], not delete. Even if buffer was initialized by new instead of delete.
