Recall that for a x, in general, the expression x::value_type indicates the type of value stored in the container. For an associative container, the expression x::key_type indicates the type used for the key.

The strength of an associative container is that it provides rapid access to its elements. Like a sequence, an associative container allows you to insert new elements; however, you can't specify a particular location for the inserted elements. The reason is that associative container usually has a particular algorithm for determining where to place data so it can retrieve information quickly.

Associative containers are typically implemented using some form of tree. A tree is a data structure with a root node linked to one or two other nodes, each of which is linked to one or two nodes, forming a branching. The node aspect makes it relatively simple to add or remove a new data item, as a linked list. Compared to a list, a tree offers much faster searches.

The STL provides four associative containers: set, multiset, map, and multimap. The first two are defined in the set header file (formerly separately in set.h and multiset.h), and the second two are defined in the map header file (formerly separately in map.h and multimap.h).

The simplest of the bunch is set; the value is the same as the key, and the keys are unique, meaning there is no more than one instance of a key in a set. Indeed, for set, the value is the same as the key. The multiset is like the set except that it can have more than one value with the same key. For example, if the key and value type are int, a multiset object could say, 1, 2, 2, 3, 5, 7, and 7.

For the map, the value is different from the key type, and the keys are unique, with only one value per key. The multimap is similar to map, except one key can be associated with multiple values.

There's too much information about these types to cover in this chapter (Appendix G lists the methods), so let's look at a simple example that uses set and a simple example that uses multimap.

# A set Example

The STL set models several concepts. It is an associative set, it is reversible, it is sorted, and the keys are unique, so it can hold no more than one of any given value. Like vector and list, set uses a template parameter to provide the type stored:

```
set<string> A; // a set of string objects
```

An optional template argument may be used to indicate a comparison function or object to be used to order the key. By default, the less<> template (discussed later) is used. Older C++ implementations may not provide a default value and thus require an explicit template parameter:

```
set<string, less<string> > A; // order implementation
```

# Consider the following code:

```
const int N = 6;
string sl[N] = {"buffoon", "thinkers", "for", "heavy", "can", "for"};
set<string> A(sl, sl + N);
ostream_iterator<string> out(cout, " ");
copy(A.begin(), A.end(), out);
```

Like other containers, set has a constructor (refer Table Table 16.6) that takes a range of iterators. This provides a simple way to initialize a set to the contents of an array. Remember that the last element of a range is one past-the-end, and sl + N points to position past-the-end. The output of this code fragment illustrates that keys are unique (the string "for" appears twice in the array but once in the set) and the set is sorted:

buffoon can be heavy thinkers

Mathematics defines some standard operations for sets. For example, the union of two sets is a set that combines the contents of the two sets. If a particular value is common to both sets, it appears just once in the union because of the unique feature. The intersection of two sets is a set that contains the elements that are common to both sets. The difference between two sets is the first set minus the elements common to both sets.

The STL provides algorithms for these operations. They are general functions rather than methods, so they aren't restricted to set objects. However, all sets automatically satisfy the precondition for using these algorithms—namely, the container is sorted. The set_union function takes five iterators as arguments. The first two define a range in one set, the second define a range in another set, and the final is an iterator that identifies a location to copy the resulting set. For example, to display the union of sets A and B, you can use:

```
set_union(A.begin(), A.end(), B.begin(), B.end(), ostream_iterator<string> out(cout, " "));
```

Suppose you want to place the result into a set C instead of displaying it. The obvious choice is C.begin(), but that't work for two reasons. The first reason is that associative sets treat keys as constant, so the iterator returned by C.begin() is a constant iterator and can't be used as an output iterator. The second reason is that C.begin() directly set_union(), like copy(), overwrites data in container and requires container to have sufficient space to hold the new information. C, being empty, does not satisfy that requirement. insert_iterator template solves both problems. It also models the output iterator, so you can use it to write to container. So you can create an anonymous insert_iterator to copy the name of the container and an iterator as arguments:

```
set_union(A.begin(), A.end(), B.begin(), B.end(), insert_iterator<set<string>>(C, C.begin()));
```

# Generic Programming

The set_intersection() and set_difference() functions find the intersection and difference of two sets, and they have the same interface as set_union(). Two useful methods are lower_bound() and upper_bound(). lower_bound() takes a key-type value as its argument and returns an iterator that points to the first member of the set that is not less than the argument. Similarly, upper_bound() takes a key as its argument and returns an iterator that points to the member of the set that is greater than the key argument. For example, if you have a set of strings, you could use these methods to identify a range encompassing all strings from "b" to "f". Because sorting determines where additions to set go, the class has insertion methods that justify the material to be inserted without specifying a position. If A and B are sets of strings, you can use this:

```
string s("tennis");
A.insert(s); // insert a value
B.insert(A.begin(), A.end()); // insert a range
```

# Listing 16.13 sets.cpp

```
// sets.cpp -- some set operations
#include <iostream>
#include <string>
#include <set>
#include <algorithm>
#include <iterator>

int main() {
    using namespace std;
    const int N = 6;
    string s1[N] = {"buffer", "thinkers", "for", "heavy", "can", "for"};
    string s2[N] = {"metal", "any", "food", "elegant", "deliver"};

    set<string> A(s1, s1 + N);
    set<string> B(s2, s2 + N);

    ostream_iterator<string> out(cout, " ");
    cout << "Set A: " <<;
    copy(A.begin(), A.end(), out);
    cout << endl;
    cout << "Set B: " <<;
    copy(B.begin(), B.end(), out);
    cout << endl;

    cout << "Union of A and B:" << endl;
    set_union(A.begin(), A.end(), B.begin(), B.end(), out);
    cout << endl;

    cout << "Intersection of A and B:" << endl;
    set_intersection(A.begin(), A.end(), B.begin(), B.end(), out);
    cout << endl;

    cout << "Difference of A and B:" << endl;
    set_difference(A.begin(), A.end(), B.begin(), B.end(), out);
    cout << endl;

    set<string> C;
    cout << "Set C:" << endl;
    set_union(A.begin(), A.end(), B.begin(), B.end(), insert_iterator<set<string>>(C, C.begin()));
    copy(C.begin(), C.end(), out);
    cout << endl;

    string s3("grungy");
    C.insert(s3);
    cout << "Set C after insertion:" << endl;
    copy(C.begin(), C.end(), out);
    cout << endl;

    cout << "Showing a range:" << endl;
    copy(C.lower_bound("ghost"), C.upper_bound("spook"), out);
    cout << endl;

    return 0;
}
```
