# Chapter 17 Input, Output, and Files

```
C>counter
Hello
and goodbye!
Control-Z
Input contained 19 characters.
C>
```

In this case, input came from the keyboard, and output went to the screen.
With input redirection (<) and output redirection (>), you can use the same program to count number of characters in the okahoma file and to place the results in the cow_cnt file:

```
C>counter <okahoma >cow_cnt
C>
```

The <okahoma file of the command line associates the standard input with the okahoma file, causing cin to read input from that file instead of that. In others, the operating system changes the connection at the inflow of the input stream, while the output remains connected to the program. The >cow_cnt part of the command line associates the standard output with the cow_cnt file, causing cout to send output to that file instead of the screen. That is the operating system changes the outflow connection of the output, leaving its inflow still connected to the program. Windows command-prompt mode, Linux, and Unix automatically recognize this redirection syntax. (All of these forms of DOS permit optional space characters between the redirection operators and the filenames).

The standard output, represented by cout, is the normal channel for program output. The standard error streams (represented by cerr and clog) are intended for a program's error messages. By default, three of these objects are typically sent to the monitor. But redirecting the standard output does not affect cerr or clog; if you use one of these objects to print an error message, a program will display the error message on the screen even if the regular cout is redirected elsewhere. For example, consider this code fragment:

```
if (success)
	std::cout << "Here come the goodies!\n";nelse
{
	std::cerr << "Something horrible has happened.\n";n	exexit(1);
}
```

If redirection is not in effect, whichever message is selected is displayed onscreen. If, however the program output has been redirected to a file, the first message, if selected, would go to the file but the second message, if selected, would go to the screen. By the way, some operating systems permit redirecting the standard error, too. In Linux and Linux, for example, the 2> operator redirects the standard error.
