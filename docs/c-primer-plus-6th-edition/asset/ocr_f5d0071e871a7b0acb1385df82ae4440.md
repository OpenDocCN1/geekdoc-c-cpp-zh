# using Directives Versus using Declarations

Using a using directive to import all the names from a namespace wholesale is not the same as using multiple declarations. It's more like the application of a scope-resolution operator. When you use a using declaration, it is as if the name is declared at the location of the using declaration. If a particular name is already declared in a function, you can't import the name with a using declaration. When you use a using directive, however, name resolution takes place as if you declared the name in the smallest region containing both the declaration and the namespace itself. For the following example, that would be the global namespace. If you use a using directive to import a name that is already declared in a function, the local name will hide the space-name, just as it would hide a global variable of the same name. However, you can still use the scope-resolution operator, in the following example:

```
namespace Jill {
    double bucket(double n) { ... }
    double fetch;
    struct Hill { ... };
}
char fetch; // global namespace
int main() {
    using namespace Jill; // import all namespace names
    Hill Thrill; // create a type Jill::Hill structure
    double water = bucket(2); // use Jill::bucket();
    double fetch; // not an error, hides Jill::fetch
    cin >> fetch; // read a value into the local fetch
    cin >> fetch; // read a value into global fetch
    cin >> Jill::fetch; // read a value into Jill::fetch
}
```

Here, in main(), the name Jill::fetch is placed in the local namespace. It doesn't have local scope, so it doesn't override the global fetch. But the locally declared fetch hides Jill::fetch and the global fetch. However, both of the last two fetch variables are available if you use the scope-resolution operator.
