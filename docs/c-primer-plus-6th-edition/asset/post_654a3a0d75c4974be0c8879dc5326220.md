# What is an Interface?

*An interface* is a shared framework for interactions between two systems—for instance, between a computer and a printer or between a user and a computer program. For example, the user might be you and the program be a word processor. When you use the processor, you don't transfer words directly from the computer memory. Instead, you interact with the interface provided by the program. You press a key, and the computer shows a character on the screen. You move the mouse, and the computer moves a cursor on the screen. You click the mouse accidentally, and something weird happens to the pen you were typing. The program manages the conversion of your intentions to specific information stored in the computer.

For classes, we speak of public interface. In this case, the program is using the class, the interacting system consists of the class objects, and the interface consists of the methods provided by whoever wrote the class. The interface enables you, to write code that interacts with classes, and thus it enables the program to use the class objects. For example, to find the number of characters in a `string` object, don't open up the object to use; just use the `size()` method provided by the creators. It turns out that the class design denies direct access to the public user. But the public is allowed to use the `size()` method. The `size()` method, is part of the public interface between the user and a `string` class public interface; a program using `cin` doesn't tinker directly with the innards of a cin to read a line of input; instead, getline() does the work.

If you want a more personal relationship, instead of thinking of the program using a class as the public user, you can think of the person writing the program using the class as the public user. But in any case, you use a class, you need to know its public interface: to write a class, you need to create its public interface.

A class design attempts to separate the public interface from the specifics of the implementation. The public interface represents the abstraction component of the design. Gathers the implementation details together and separating them from the abstraction is called encapsulation. Data hiding (putting data into the private section of a class) is instance of encapsulation, and so hiding functional details of an implementation in the private section, and the Stock class does with set_tot(). Another example of encapsulation is the usual practice of placing class function definitions in a separate file from the class declaration. Whereas data hiding may be an unscrupulous act in say, a prospectus, it's a good practice in computing because it preserves the integrity of the data.
