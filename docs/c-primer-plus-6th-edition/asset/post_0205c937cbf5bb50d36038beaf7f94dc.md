
Listing 17.14 uses two approaches to read and echo input up to, but not including, a # character. The first approach reads through the # character and then uses putback() to insert the character into the input. The second approach uses peek() to look ahead.

# Listing 17.14 peeker.cpp

```cpp
// peeker.cpp -- some istream methods
#include <iostream>

int main()
{
    using std::cout;
    using std::cin;
    using std::endl;

    // read and echo input up to a # character
    char ch;

    while (cin.get(ch)) // terminates on EOF
    {
        if (ch != '#')
            cout << ch;
        else
        {
            cin.putback(ch); // reinsert character
            break;
        }
    }

    if (!cin.eof())
    {
        cin.get(ch);
        cout << endl << ch << " is next input character.\n";
    }
    else
    {
        cout << "End of file reached.\n";
        std::exit(0);
    }

    while (cin.peek() != '#') // look ahead
    {
        cin.get(ch);
        cout << ch;
    }
    if (!cin.eof())
    {
        cin.get(ch);
        cout << endl << ch << " is next input character.\n";
    } else
        cout << "End of file reached.\n";

    return 0;
}
```

# Program Notes

Let’s look more closely at some of the code in Listing 17.14. The first approach uses a while loop to read input:

```cpp
while(cin.get(ch)) // terminates on EOF

if (ch != '#')
    cout << ch;
else
{
    cin.putback(ch); // reinsert character
    break;
}
```

The expression cin.get(ch) returns false on reaching the end-of-file condition, simulating end-of-file from the keyboard terminates the loop. If the # character shows up first, the program puts the character in the input stream and uses a break statement to terminate the loop.

The second approach is simpler in appearance:

```cpp
while(cin.peek() != '#') // look ahead
{
    cin.get(ch);
    cout << ch;
}
```

The program peeks at the next character. If it is not the # character, the program reads the next character, echoes it, and peeks at the next character. This continues until the terminating character shows up.

Now let's look, promised, at an example—Listing 17.15—that uses peek() to determine whether an entire line has been read. If only part of a line fits in the input array, the program discards the rest of the line.

# Listing 17.15 truncate.cpp

```cpp
// truncate.cpp -- using get() to truncate input line, if necessary
#include <iostream>
const int SLEN = 10;
inline void eatline() { while (std::cin.get() != '\n') continue; }
int main() {
    std::cin;
    std::cout;
    std::endl;

    char name[SLEN];
    char title[SLEN];
    cout << "Enter your name: ";
    cin.get(name,SLEN);
    if (cin.peek() != '\n')
        cout << "Sorry, we only have enough room for \n"
        << name << endl;

    eatline();
    cout << "Dear " << name << endl;
}
```

Here is a sample run of the program in Listing 17.15:

We were forced to truncate your title.

Note that the following code makes sense whether or not the first input statement reads the entire line:

```cpp
while (cin.get() != '\n') continue;
```

If get() reads the whole line, it still leaves the newline in place, and this code discards the newline character. If get() just reads part of the line, this code discards the rest of the line. If you didn't dispose the rest of the line, the next input statement would begin at the beginning of the remaining input on the first input line. With this example, that would result in the program reading the string sniffer into the title array.

## File Input and Output

Most computer programs work with files. Word processors create document files. Database programs create and search files of information. Compilers create source code files and generate executable files. A file itself is a bunch of bytes stored on some device, perhaps magnetic tape, a floppy disk, or a hard disk. Typically, the operating system manages files, keeping track of their locations, their sizes, when they were created, and so on. Unless you're programming the operating system, you normally don't have to worry about those.

# Simple I/O

Suppose you want to write to a file. You must do the following:

- Create an ofstream object to manage the output.
- Associate that object with a particular file.
- Use the object as you use cout; the only difference is that output goes to the file instead of the screen.

To accomplish this, you begin by including the fstream file. Including this file automatically includes iostream, so you may not have to include it explicitly. Then you declare an ofstream object:

```cpp
ofstream fout; // create an ofstream named fout
```

The object's name can be any valid C++ name, such as fout, outfile, or out. Next, you must associate this object with a particular file. You can do so by using the open() method. Suppose, for example, that you want to output the jar.txt file. You would do the following:

```cpp
fout.open("jar.txt"); // associate fout with jar.txt
```

You can combine these two steps (creating the object and associating a file) into a single statement by using a different constructor:

```cpp
ofstream fout("jar.txt"); // create fout object, associate it with jar.txt
```

When you've gotten this far, you use fout (or whatever name you choose) in the same manner as cout. For example, if you want to put the words Dull Data into the file, you can do the following:

```cpp
fout << "Dull Data";
```

Indeed, as ofstream is a base class of ostream, you can use all the ofstream methods, including the insertion operator and the formatting methods. The ofstream class uses buffered output, so the program allocates space for an output buffer when it creates an ofstream object. If you create two ofstream objects, the program creates two buffers, one for each object. Then, when the buffer is full, it transfers the buffer contents en masse to the destination file. Because disk drives are designed to transfer data in larger chunks, not byte-by-byte, the buffered approach greatly speeds up the transfer rate of data from a program to a file.

Opening a file for output creates a new file if there is no file of name. If a file by name exists prior to opening it for output, the act of opening it truncates it so that output starts with a clean file. Later in this chapter you'll see how to open an existing file and retain its contents.
