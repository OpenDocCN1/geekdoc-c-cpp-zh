# Class Design Review

Star rigel; // create an object without explicit initialization
Star pleiades[6]; // create an array of objects

One might think an automatic default constructor does call the default constructors
for any base classes and for any members that are objects of another class.
Also if you wrote a derived-class constructor without explicitly invoking a base-class
constructor in the member initializer list, the compiler uses the base class default-
constructor to construct the base portion of the new object. If there is no base-class
default constructor, you get a compile-time error in this situation.

If you define a constructor of any kind, the compiler does not define a default construc-
tor for. In that case, it's up to you to provide a default constructor if one is needed.
Note that one of the motions for having constructors is to ensure that objects are
always properly initialized. Thus, if a class has any pointer members, they certainly should
be initialized. Thus, it's a good idea to use an explicit default constructor that initializes
all class data members to reasonable values.

# Copy Constructors

A copy constructor for a class is a constructor that takes an object of the class type as its
argument. Typically, the declared parameter is a constant reference to the class type. For
example, the copy constructor for a Star class would would have this prototype:

```
Star(const Star&);
```

A class copy is used in the following situations:

+   - When a new object is initialized to an object of the same class
- When an object is passed to a function by value
- When a function returns an object by value
- When the compiler generates a temporary object

If a program does not use a copy constructor (explicitly or implicitly), the compiler pro-\vidas a prototype but not a function definition. Otherwise, the program defines a copy
constructor that performs member initialization. That is, each member of the new
object is initialized to the value of the corresponding member of the original object. If a
member is itself a class object, then member initialization uses the copy constructor
defined for that particular class.

In some cases, member initialization is undesirable. For example, member pointers
initialized with new generally requires that you institute deep copying, as with the baseDMA
class example. Or a class may have a static variable that needs to be modified. In such
cases, you may need to define your own copy constructor.
