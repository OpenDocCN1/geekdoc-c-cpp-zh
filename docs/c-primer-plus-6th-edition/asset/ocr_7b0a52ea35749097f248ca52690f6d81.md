# Where Stringbag Assignment Goes Wrong

Listing 12.3 assigns headline to knot:

```
knot = headline;
```

When the destructor is called for knot, it displays this message:

"Celery Stalks at Midnight" object deleted, 2 left

When the destructor is called for headline, it displays this message:

"-|" object deleted, -2 left

Many encounter the same problem that the implicit constructor caused: corrupted data. Again, the problem is memberwise copying, which causes both headline.str and knot.str to point to the same address. Thus, when the destructor is called for knot, it deletes the string "Celery Stalks at Midnight", and when it's called for headline, it attempts to delete the previously deleted data. As mentioned earlier, the effect of attempting to delete previously deleted data is undefined, so it may change the memory contents, and it may cause a program to abort. As like to point out, if the effect of a particular operation is undefined, your compiler can do anything wants, including displaying the Declaration of Independence or freeing your hard disk of unsightly files. Or, would it be a rare thing for a compiler writer to take the time to include such frivolous or destructive behavior.

# Fixing Assignment

The solution for the problems created by an inappropriate default assignment operator is to provide your own assignment operator definition, that makes a deep copy.The implementation is similar to that of the copy constructor, but there are some differences:

+   - Because the object may already refer to previously allocated data, the function should use delete [] to free former obligations.

+   - The function should protect against assigning an object to itself; otherwise, the freeing of memory described previously could erase the object's contents before they are reassigned.

+   - The function returns a reference to the invoking object.

By returning an object, the function can emulate the ordinary assignment for built-in types by be chained. That is, if S0, S1, and S2 are StringBad objects, you can write the following:

```
S0 = S1 = S2;
```

In function notation, this becomes the:

```
S0.operator=(S1.operator=(S2));
```
