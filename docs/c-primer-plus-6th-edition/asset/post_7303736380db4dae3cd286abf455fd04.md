C-style string. But reading a line at a time instead of word at time uses a different syntax. Listing 4.10 shows this difference.

# Listing 4.10 strtype4.cpp

```cpp
// strtype4.cpp -- line input
#include <iostream>
#include <string> // make string class available
#include <cstring>     // C-style string library
int main() {
{
    using namespace std;
    char buffer[20];
    string str;
    cout << "Length of string in char before input: ";
    cout << strlen(buffer) << endl;
    cout << "Length of string in str before input: ";
    cout << str.size() << endl;
    cout << "Enter a line of text:\n";
    cin.getline(buffer, 20); // indicate maximum length
    cout << "You entered: " << buffer << endl;
    cout << "Enter another line of text:\n";
    getline(cin, str); // cin now an argument; no length specifier
    cout << "You entered: " << str << endl;
    cout << "Length of string in char after input: ";
    cout << strlen(buffer) << endl;
    cout << "Length of string in str after input: ";
    cout << str.size() << endl;

    return 0;
}
```

Here's a sample run of the program in Listing 4.10:

Length of string in char before input: 27
Length of string in str before input: 0
Enter a line of text:
peanut butter
You entered: peanut butter
Enter another line of text:
blueberry jam
You entered: blueberry jam
Length of string in char after input: 13
Length of string in str after input: 13

Note that the program says the length of the string in the array char before input is 27, which is larger than the size of the array! Two things are going on here. The first is that the contents of an uninitialized array are undefined. The second is that the strlen() function works by starting at the first element of the array and counting bytes until it reaches a null character. In this case, the first null character does not appear until several bytes after the end of the array. Where the first null character appears in uninitialized data is essentially random, so you well could get a different result with this program.

Also note that the length of the string in str before input is 0. That's because an uninitialized string object is automatically set to zero size.

This is the code for reading a line into an array:

```cpp
cin.getline(buffer, 20);
```

The dot notation indicates that the getline() function is a class method for the istream class.(Recall that cin is an istream object.) As mentioned earlier, the first argument is the destination array, and the second argument is the array size, which getline() used to avoid overrunning the array.

This is the code for reading a line into a string object:

```cpp
getline(cin,str);
```

There is no dot notation, which indicates that this getline() is not a class method. So it takes cin as an argument that tells it where to find the input. There isn't an argument for the size of the string because the string object automatically resizes to fit the string.

So why is getline() an istream class method and the other getline() not? The istream class was part of C++ long before the string class was added. So the istream class recognizes C++ types such as double and int, but it is ignorant of the string type. Therefore, there are istream class methods for processing double, int, and the other basic types, there are no istream class methods for processing string objects.

Because there are no istream class methods for processing string objects, you might wonder why code like this:

```cpp
cin >> str; // read a word into the str object
```

It turns out that code like the following (in disguised notation) use a member function of the istream class:

```cpp
cin >> x; // read a value into a basic C++ type
```

But the string class equivalent uses a friend function (also in disguised notation) of the string class. You'll have to wait until Chapter 11 to see what a friend function is and how this technique works. In the meantime, you can use cin and cout with string objects and not worry about the inner workings.

# Other Forms of String Literals

C++, recall, has the wchar_t type in addition to char. And C++11 adds the char16_t and char32_t types. It's possible to create arrays of these types and string literals of these types. C++ uses the L, u, and U prefixes, respectively, for string literals of these types. Here's an example of how they use:

```cpp
wchar_t title[] = L"Chief Astrogator"; // w_char string
char16_t name[] = U"Felonia Ripova"; // char_16 string
char32_t car[] = U"Humber Super Snipe"; // char_32 string
```

C++11 also supports an encoding scheme for Unicode UTF-8. In this scheme a character can be stored anywhere from 8-bit unit, or octet, to 4-bit units, depending on the numeric value. C++ uses the u prefix to indicate string literals of that.

Another C++11 addition is the raw string. In raw string, characters simply stand for themselves; instead of the sequence \n is not interpreted as the newline character; it is two ordinary characters, a backslash and an n, and it would display as two characters onscreen. For example, you can use a " inside a string instead of literal, no longer can use it to delete the ends of a string. Therefore, raw strings use "(" and "))" as delimiters, and you can use an R prefix to identify them as raw strings:

```cpp
cout << R"(King Tutt uses \\n" instead of endl.") << '\n';
```

This would display the following:

Jim "King" uses \n instead of endl.

The standard literal equivalent would be this:

```cpp
cout << "Jim \"King\" uses \\\n instead of endl." << '\n';
```

Here we had to use \\ to decode a single \ is interpreted as the first character of an escape sequence.

If you press the Enter or Return key while typing a raw string, that only moves the cursor to the next line onscreen, it also places a carriage return character in the raw string.
What if you want use the combination " in a raw string? (Who wouldn't)
Won't the compiler interpret the first occurrence of " as the end of the string? Yes, it will. But the raw syntax allows you to place additional characters to the opening and (This implies the same additional characters must appear between the final and "). So a string beginning with R"*(must terminate with "*). Thus, the statement

```cpp
cout << R"*((Who wouldn't?", she whispered.)*\*" << endl;
```

would display the following:

"(Who wouldn't?)", she whispered.

The prefix can be combined with the other string prefixes to produce raw strings of wchar_t and so on. It can be either the first or the last part of a compound prefix: Ru, Ur, and so on.

# Introducing Structures

Suppose you want to store information about a basketball player. You might want to store his name, salary, height, weight, scoring average, free-throw percentage, assists, and so on. You'd like some sort of data form could hold all this information in one unit. An array won't do. Although an array can hold several items, each item has to be the same type. That is, one array can hold 20 elements and another can hold 10 floats, but a single array can't store ints and floats in other elements.

The answer to your desire (the one storing information about basketball player) is the C++ structure. A structure is more versatile data than an array because a single structure can hold more than one type. This enables you to unify your data representation by storing all the related basketball information in a single variable. If you want to keep track of a whole team, you can use an array of structures. The structure type is also a stepping stone to that bulk of C++ OOP. Learning a little about structures now will take you that much closer to the OOP heart of C++.

A structure is a user-defined type, with a structure declaration serving to define the type's data properties. After you define the type, you can create variables of that type. Creating a structure is a two-part process. First, you define a structure description that describes and labels the different types of data that can be stored in a structure. Then you can create variables, or more generally, structure data objects, that follow the description's plan.

For example, suppose that Bloataire, Inc., wants to create a type to describe members of its product line of inflatables. In particular, the structure should hold the name of the item, its volume in cubic feet, and its selling price. Here is a structure description that meets needs:

```cpp
struct inflatable // structure declaration
{
    char name[20];
    float volume;
    double price;
};
```

The keyword struct indicates that the code defines the layout for a structure. The identifier inflatable is the name, or tag, for this form; this makes inflatable the name
