Normal function calls also involve a program jump to another address (the function's address) and then jump back when the function terminates. Let's look at a typical implementation of that process in a little more detail. When a program reaches the function call instruction, the program stores the memory address of the instruction immediately following the function call, copies arguments to the stack (a block of memory reserved for that purpose), jumps to the memory location that marks the beginning of the function, executes the function (perhaps returning a value in a register), and then jumps back to the address it saved. Jumping back and forth and keeping track of where to jump means that there is an overhead in elapsed time to use functions.

C++ inline functions provide an alternative. In an inline function, the compiled code is “inline” with the other code in the program. The compiler replaces the function call with the corresponding function code. With inline code, the program doesn't have to jump to another location to execute the code and jump back. Inline functions run faster than regular functions, but they come with a memory penalty. If a program calls an inline function at ten locations, the program winds up with ten copies of the function inserted into the code (see Figure 8.1).

You should be selective about using inline functions. If the time to execute the function is long compared to the time to handle the function call mechanism, the time saved is a relatively small portion of the entire process. If the code execution time is short, then an inline call can save a large portion of the time used by the non-inline call. On the other hand, you are now saving a large portion of a relatively quick process, so the absolute time saved may not be great unless the function is frequently called.

To use this feature, you must take at least one of two actions:

+   - Prefix the function declaration with the keyword inline.
- Prefix the function definition with the keyword inline.

A common practice is to omit the prototype and place the entire definition (meaning the function header and all function code) where the prototype would normally go.

The compiler does not have to honor your request to make a function inline. It might decide the function is too large or notice that it calls itself (recursion is not allowed or indeed possible for inline functions), or the feature might not be turned on or implemented for your particular compiler.
