# # Note

Some systems either do not support simulated EOF from the keyboard or support it imperfectly, and may prevent the example in Listing 5.19 from running as described. If you have been using cin.get() to freeze the screen until you read it, it won't work here because detecting the EOF turns off after attempts to read input. However, you can use a timing loop like that in Listing 5.14 to clear the screen for you. Or you can use cin.get(), to reset the input stream.

Let's analyze the condition:

while (ch = cin.get()) != EOF
The parentheses enclose the subexpression ch = cin.get() cause the program to evaluate that expression. To do the evaluation, the program first has to call the cin.get() function. Next, it assigns the return value to ch. Because the value of an assignment statement is the value of the left operand, the subexpression reduces the value of ch. If this value is EOF, the loop terminates; otherwise, it continues. The test condition needs all parentheses. Suppose you leave some parentheses out:

while (ch = cin.get()) != EOF
The! operator has higher precedence than =, so the first compares cin.get()'s return value to EOF. A comparison produces a false or true result; that boolean value converted to 0 or 1, and that's the value that gets assigned to ch.

Using cin.get(ch) (with an argument) for input, the other hand, doesn't create any type problems. Remember that the cin.get(char) function doesn't assign a special value to ch at the EOF. In fact, in that case, ch is never called on to hold a non-char value. Table 5.3 summarizes the differences between cin.get(char) and cin.get().
