# Private Inheritance

C++ has a second means of implementing the *has-a relationship*: private inheritance. With private inheritance, public and protected members of the base class become private members of the derived class. This means the methods of the base class do not become part of the public interface of the derived object. They can be used, inside the member functions of the derived class.

Let's look at the inheritance topic more closely. With public inheritance

With private inheritance, a class does inherit the implementation. For example, if you use a Student class on a string, the Student winds up with an inherited string component that can be used to store a string. Furthermore, the *Student* methods can use the *string* methods internally to access the *string* component.

Containment adds an object to a class as a named member, whereas private inheritance adds an object to a class as an unnamed member. This book uses the term *subject* to denote an object by inheritance or by containment.

Private inheritance, provides the implementation, don't acquire the interface. It too, can be used to implement a has-a relationship. In fact, you can produce a Student version with the same public interface. The differences between the two approaches affect the implementation, not the interface.
