
# Listing 17.17 count.cpp

```cpp
// count.cpp -- counting characters in a list of files
#include <iostream>
#include <fstream>
#include <cstdlib> // for exit()
int main(int argc, char * argv[])
{
    using namespace std;
    if (argc == 1) { // quit if no arguments
        cerr << "Usage: " << argv[0] << " << filename[s]\n";
        exit(EXIT_FAILURE);
    }

    ifstream fin; // open stream
    long count;
    long total = 0;
    char ch;

    for (int i = 1; i < argc; i++) {
        fin.open(argv[i]); // connect stream to argv[i]
        if (!fin.is_open()) {
            cerr << "Could not open " << argv[i] << endl;
            fin.clear();
            continue;
        }
        count = 0;
        while (fin.get(ch)) {
            count++;
        }
        cout << count << " characters in " << argv[i] << endl;
        total += count;
        fin.clear(); // needed for some implementations
        fin.close(); // disconnect file
    }
    cout << total << " characters in all files\n";

    return 0;
}
```

## Note

Some C++ implementations require using fin.clear() at the end of the program, and others do not. It depends on whether associating a new file with the ifstream object automatically resets the state. It does no harm to use fin.clear() even if it isn't needed.

On a Linux system, for example, you could compile Listing 17.17 to an executable file called a.out. Then sample runs could look like this:

```bash
$ a.out
Usage: a.out filename[s]
$ a.out paris rome
3580 characters in paris
4886 characters in rome
8466 characters in all files
$
```

Note that the program uses cerr for the error message. A minor point is that the message uses argv[0] instead of a.out.

This way, if you change the name of the executable file, the program will automatically use the new name. The program uses the is_open() method to verify that it was able to open the requested file. Let's examine that matter further.

## File Modes

The file mode describes how a file is to be used: read, write it, append, and so on. When you associate a stream with a file, either by initializing a file stream object with a filename or using the open() method, you can provide a second argument that specifies the file mode.

```cpp
ifstream fin("banjo", mode); // constructor with mode argument
ofstream fout;
fout.open("harp", mode2); // open() with mode arguments
```

The ios_base class defines an open mode to represent the file: like mflags and iost types, it is a bitmask type (In the old days, it was type int.). You can choose from several constants defined in the ios_base class to specify the mode. Table 17.7 lists the constants and their meanings. C++ file I/O has undergone changes to make it compatible with ANSI C I/O.

### Table 17.7 File Mode Constants

| Constant | Meaning |
| --- | --- |
| ios_base::in | Open file for reading. |
| ios_base::out | Open file for writing. |
| ios_base::ate | Seek to end-of-file upon opening. |
| ios_base::app | Append to end-of-file. |
| ios_base::trunc | Truncate file if it exists. |
| ios_base::binary | Binary file. |

## File Input and Output

If the ifstream and ofstream constructors and the open() methods take two arguments, how have we gotten by using just one one in the previous examples? As you have possibly guessed, the prototypes for these class member functions provide default values for the second argument (the file mode argument). For example, the ifstream open() method and constructor use ios_base::in (for reading) as the default value for the mode argument, and the ofstream open() method and constructor use ios_base::out | ios_base::trunc (for writing and truncate the file) as the default. The bitwise OR | is used to combine two bits into a single value that can be used to set bits. The fstream class does not provide a default mode, so you have to provide a mode explicitly when creating an object of that.

Note that the ios_base::trunc flag means an existing file is truncated when opened to receive program output; that, its previous contents are discarded. This behavior considerably minimizes the danger of running out of disk space, you can possibly imagine situations in which you don't want to open a file when you want it. Of course, C++ provides other options. If, for example, you want to preserve the file contents and add (append) new material to the end of the file, you can use the ios_base::app mode:

```cpp
ofstream fout("bags", ios_base::out | ios_base::app);
```

Again, the code uses | operator to combine modes. So ios_base::out | ios_base::app invokes both the out mode and the app mode (see Figure 17.6). You can find some differences among other C++ implementations. For example, allow you to omit the ios_base::out in the previous example.
