Useless two = one;      // calls copy constructor

## Move Semantics and the Rvalue Reference

接下来，同样去掉输出语句后，这里是移动构造函数：

Useless::Useless(Useless && f): n(f.n)
{
    ++pc;
    pc = f.pc;      // steal address
    f.pc = nullptr; // give old object nothing in return
    f.n = 0;
}

它通过将 pc 设置为指向数据来接管数据所有权。此时，pc 和 f.pc 都指向相同的数据。当析构函数被调用时，这会很棘手，因为程序不应对同一地址执行两次 delete []。为避免此问题，构造函数随后将原始指针设置为空指针，因为对空指针执行 delete [] 并不是错误。这种所有权的夺取本身被称为掠夺。代码还将原始对象中的元素计数设置为 0。这不是必需的，但它使我们示例的输出看起来更自洽。请注意，对 f 对象的更改要求参数声明中不能使用 const。

正是此构造函数在以下语句中使用：

Useless four (one + three); // calls move constructor

表达式 one + three 引发 Useless::operator()，并且右值引用 f 绑定到方法返回的右值对象。

## Move Constructor Observations

使用右值引用使移动语义成为可能，但它并不会神奇地使其发生。启用需要两个步骤。第一步是值引用允许编译器识别何时可以使用移动语义：

Useless two = one; // matches Useless::Useless(const Useless &)
useless four (one + three); // matches Useless::Useless (&)

对象是左值，因此匹配 Useless::Useless(const Useless &)，而表达式 one + three 是右值，因此匹配右值引用。因此，值引用将对象 four 的初始化指向移动构造函数。启用移动语义的第二步是编写移动构造函数，使其提供你想要的行为。

简而言之，一个带有右值引用的构造函数和第二个构造函数将可能的初始化分为两组。用左值对象初始化的对象使用拷贝构造函数，用右值对象初始化的对象使用移动构造函数。编写者随后可以用不同的行为定义这些构造。

这就引出了在右值引用成为语言一部分之前发生了什么的问题。如果没有移动构造函数并且编译器没有优化掉对拷贝构造函数的需要，会发生什么？在 C++98 下，以下语句将调用拷贝构造函数：

Useless four (one + three);
