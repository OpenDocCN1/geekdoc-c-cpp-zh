
## 3.2 C++ Escape Sequence Codes

| Character Name | ASCII Symbol | C++ Code | ASCII Code | ASCII Hex Code |
|---|---|---|---|---|
| Newline | NL (LF) | \n | 10 | 0xA |
| Horizontal tab | HT | \t | 9 | 0x9 |
| Vertical tab | VT | \v | 11 | 0xB |
| Backspace | BS | \b | 8 | 0x8 |
| Carriage return | CR | \r | 13 | 0xD |
| Alert | BEL | \a | 7 | 0x7 |
| Backslash | \ | \\ | 92 | 0x5C |
| Question mark | ? | \? | 63 | 0x3F |
| Single quote | ' | \' | 39 | 0x27 |
| Double quote | " | \" | 34 | 0x22 |

```
char alarm = '\a';
cout << alarm << "Don't do that again!\a\n";
cout << "Ben\\Buggsie\nwas here!\n";
```

The last line produces the following output:

Ben "Buggsie" Hacker
was here!

> Note that you treat an escape sequence, such as \n, just as a regular character, such as Q. That is, you include it in single quotes to create a character constant and don't use quotes when including it as part of a string.
The escape sequence dates back to when people communicated with computers using the teletype, an electromechanical typewriter-printer, and modern systems don't always remember the complete set of escape sequences. For example, some systems remain silent for the alarm character.
The newline provides an alternative to endl for inserting new lines into output. You can use the newline in character constant ('\n') or as character in a string ("\n"). All three of the following move the screen cursor to the beginning of the next line:

```
cout << endl; // using the endl manipulator
cout << '\n'; // using a character constant
cout << "\n"; // using a string
```

You can embed the newline in a longer string; this is often more convenient than using endl. For example, the following cout << endl produce the same output:

```
cout << endl << endl << "What next?" << endl << "Enter a number:" << endl;
cout << "\n\nWhat next?\n\nEnter a number:\n";
```

When you're displaying a number, endl is a bit easier to type than "\n" or '\n', when you're displaying a string, ending the string with a newline character requires less typing:

```
cout << x << endl;           // easier than cout << x << "\n"
cout << "Dr. X.\n";      // easier than cout << "The Dr. X." << endl;
```

Finally, you can use escape sequences by the octal or hexadecimal codes for a character. For example, Ctrl+Z is an ASCII code of 26, which is 032 in octal and 0xa in hexadecimal. You can represent this character with either of the following escape sequences: \032 or \xa. You can make constants out of these by enclosing them in single quotes, as in '\032', and you use them as parts of a string, as in "hi\xa there".

### Tip

When you choose to use a numeric escape sequence or a symbolic escape sequence, as in \x8 versus \b, use the symbolic code. The numeric representation is tied to a particular code, such as ASCII, but the symbolic representation works with all codes and is more readable.

### Universal Character Names

C++ implementations support a basic source character set—that is, the set of characters you can write using standard U.S. keyboard, the symbols, as { and =, in the C language, and a scattering of other characters, such as the space character. There is a basic execution character set, which includes characters that can be processed during the execution of a program (for example, characters read from a file or displayed on screen). This adds a few more characters, such as backspace and alert. The C++ Standard also allows implementation to extended source character sets and extended execution character sets. Furthermore, additional characters that qualify as letters can be used as part of the name of an identifier. a German implementation might allow you to use umlauted vowels, and a French implementation might allow accented vowels. C++ has a mechanism for representing international characters that is independent of any particular keyboard: the use of universal character names.

Using universal character names is similar to using sequences. A universal character name begins either with \u or \U. The \u form is followed by 4 hexadecimal digits, and the \U form by 8 hexadecimal digits. These digits represent the ISO 10646 point for the character. (ISO 10646 is an international standard under development that provides numeric codes for a wide range of characters. Use “Unicode and ISO 10646,” in this chapter.)

If your implementation supports extended characters, you can use universal character names in identifiers, as character constants, and in strings. For example, consider the following code:

```
int k\u00F6rper;
cout << "Let eat g\u00E2teau.\\n";
```

The ISO 10646 code point for ö is 00F6, and the code point for å is 00E2. Thus, this C++ code would set the variable name to Körper and display the following output:

Let them eat gâteau.

### Unicode and ISO 10646

Unicode provides a solution to the representation of various character sets by providing a standard numbering for a great number of characters and symbols, grouping them by type. For example, the ASCII code is incorporated as a subset of Unicode, so U. Latin characters such as A and Z have the same representation under both systems. But Unicode also incorporates other Latin characters, as those used in European languages; characters from other alphabets, including Greek, Cyrillic, Hebrew, Cherokee, Arabic, Thai and Bengali; ideographs, such as those for Chinese and Japanese. Unicode represents more than 109,000 symbols and more than 90 scripts, and it is still under development. If you want to know, you can check the Unicode Consortium's website, at www.unicode.org.

Unicode assigns a number, a called code point, for each of its characters. The typical notation for Unicode code points looks like this: U-222B. The U identifies as a Unicode character, and the 222B is the hexadecimal number for the character—an integral sign, in this case.

The International Organization for Standardization (ISO) established a working group to develop ISO 10646, as a standard for multilingual text. The ISO 10646 group and the Unicode group have worked together since 1991 to keep their standards synchronized with one another.

### signed char and unsigned char

Unlike int, char is not signed by default. Nor is it unsigned by default. The choice is left to the C++ implementation in order to allow the compiler best fit to the hardware properties. If it is vital to know that char has a particular behavior, you can use signed char or unsigned char explicitly as types:

```
char fodo; // may be signed
unsigned char bar; // definitely unsigned
signed char snark; // definitely signed
```
