In the example in Listing 10.10, the private section shows that the stack is implemented by using an array, but the public section doesn't reveal fact. Thus, you can replace the array with, say, a dynamic array without changing the class interface. This means the stack implementation doesn't require you to recode link or with existing program code.

The interface is redundant if pop() and push() return information about the stack status (full or empty) instead of being void. This provides the programmer with a couple options on how to handle exceeding the stack limit or emptying the stack. He or can use isEmpty() and isFull() to check before attempting to modify the stack, or use the return value of push() and pop() to determine whether the operation is successful.

Rather than defining the stack in terms of some particular type, the class describes it in terms of a general Item type. In this case, the header file uses typedef to make the item unsigned long. If you want, a stack of doubles or a structure type, you can change the typedef and leave the class declaration and method definitions unaltered. Class templates (see Chapter 14, "Reusing Code in C++") provide a more powerful method for isolating from the class design to the type of data stored.
