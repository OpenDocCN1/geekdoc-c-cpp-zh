However, there is another possibility—using a non-member function. (Remember, most nonmember operators can be overloaded using either member or nonmember functions.) A nonmember function is not invoked by an object; instead, any values it uses, including objects, are explicit arguments. Thus, the compiler could match the member expression

```
A = 2.75 * B; // might not correspond to a member function
```

to the following nonmember function call:

```
A = operator*(2.75, B);
```

The function would have this prototype:

```cpp
Time operator*(double m, const Time &t);
```

With the nonmember overloaded function, the left operand of an operator expression corresponds to the second argument. Meanwhile, the original member function handles operands in the opposite order—that is, a Time multiplied by a double value. Using a nonmember function solves the problem of getting the operands in the desired order (first double and Time), but it raises a new problem: Nonmember functions cannot directly access private data in a class. Well, at least nonmember functions lack access. But there is a special category of nonmember functions, called *friends*, that can access private members of a class.

## Creating Friends

The first step toward creating a friend function is to declare a prototype in the class declaration and prefix the declaration with the keyword friend:

```cpp
friend Time operator*(double m, const Time &t); // goes in class declaration
```

This prototype has two implications:

- Although the operator*() function is declared in the class declaration, it is not a member function. So it isn't invoked by the membership operator.
- Although the operator*() function is not a member function, it has the same access rights as a member function.

The second step is to write the function definition. Because it is not a member function, you don't use the Time:: qualifier. You also don't use the friend keyword in the definition. The definition should look like this:

```cpp
Time operator*(double m, const Time &t) // friend not used in definition
{
    Time result;
    long totalminutes = t.hours * m * 60 + t.minutes * m;
    result.hours = totalminutes / 60;
    result.minutes = totalminutes % 60;
    return result;
}
```

With this declaration and definition, the statement

```cpp
A = 2.75 * B;
```

translates to the following and invokes the nonmember friend function just defined:
A = operator*(2.75, B);

In short, a friend function to a class is a nonmember function that has the same access rights as a member function.

## Are Friends Unfaithful to OOP?

At first glance, it might seem that friends violate OOP principle of hiding because the friend mechanism allows nonmember functions to access private data. However, that is an arrow narrow view. Instead, you should think of friend functions as part of an extended interface for a class. For example, from a conceptual point of view, letting a double by a Time value is pretty much the same as multiplying a Time value by a double. The first requires a friend function whereas the second can be done with a member function is the result of C++ syntax, not of a deep conceptual difference. By using both friend function and a class method, you can express either operation with the same user interface. Also keep in mind that only a class declaration decide which functions are friends, so the class declaration still controls which functions access private data. In short, class methods and friends are simply two different mechanisms for expressing a class interface.

Actually, you can write this particular friend function as a non-friend by altering the definition so that it switches which value comes first in the multiplication:

```cpp
Time operator*(double m, const Time & t)
{
    return t * m; // use t.operator*(m)
}
```

The original version accessed t.minutes and t.hours explicitly, so it had to be a friend. This version uses only the Time object as a whole, letting a member function hand the private values, so this version does not have to be a friend. Nonetheless, there are reasons to make this a friend.

Tip: If you want to access private data, the function must be a friend.

## A Common Kind of Friend: Overloading <<

One very useful feature of classes is that you can overload the << operator to output data to the screen. To teach the class how to use it, use the following definition:

```cpp
void operator<<(ostream & os, const Time & t)
{
    os << t.hours << " " << t.minutes << " minutes";
}
```

This allows you to print data in the following format:
4 hours, 23 minutes
