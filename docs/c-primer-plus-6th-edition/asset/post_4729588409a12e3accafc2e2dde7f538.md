## Automatic Storage Duration

Function parameters and variables declared inside a function have, by default, automatic storage duration. They also have local scope and no linkage. That is, if you declare a variable `texas` in `main()` and declare another variable with the same name in a function called `oil()`, you created two independent variables, each known only in the function in which it was defined. Anything you do to `texas` in `oil()` has no effect on `texas` in `main()`, and vice versa. Also each variable is allocated when execution enters the innermost block containing the definition, and each is from existence when execution leaves that block. (Note that the variable is allocated when execution enters the block, but the scope begins only after the point of declaration.)

If you define a variable inside a block, the variable's persistence and scope are confined to that block. Suppose, for example, you define a variable called `tedeli` at the beginning of `main()`. Now you start a new block within `main()` and define a new variable, called `websight`, in the block. Then, `tedeli` is visible in both the outer and inner blocks, whereas `websight` exists only in the inner block and is in scope only from its point of definition until program execution passes the end of the block:

```cpp
main()
{
    int tedeli = 5;
    {
        cout << "Hello\n";      // websight allocated
        int websight = -2;         // websight scope begins
        cout << websight << ' ' << tedeli << endl;
        ...
        cout << tedeli << endl;    // websight expires
    }
} // tedeli expires
```

But what if you name the variable in the inner block `tedeli` instead of `websight` so that you have two variables of the same name, one in the outer and one in the inner block? In this case, the program interprets the `tedeli` name to mean the local block while the program executes statements within the block. We say the new definition hides the prior definition. The new definition is in scope, and the old definition is temporarily out of scope. When the program leaves the block, the original definition comes back into scope (see Figure 9.2).

```cpp
// autoscp.cpp -- illustrating scope of automatic variables
#include <iostream>
void oil(int x);
int main() {
    using namespace std;

    int texas = 31;
    int year = 2011;
    cout << "In main(), texas = " << texas << ", &texas = ";

void oil(int x)
{
  using namespace std;
  int texas = 5;

  cout << "In oil(), texas = " << texas << ", &texas = ";
  cout << &texas << endl;
  cout << "In oil(), x = " << x << ", &x = ";
  cout << &x << endl;
  // start a block
  int texas = 113;
  cout << "In block, texas = " << texas << endl;
  cout << " &texas = " << &texas << endl;
  cout << "In block, x = " << x << ", &x = ";
  cout << &x << endl;
} // end a block
  cout << "Post-block texas = " << texas << endl;
  cout << " &texas = " << &texas << endl;
}
```

Here is the output from the program 9.4:

main(), texas = 0012FED4
main(), year = 2011, &year = 0012FEC8
oil(), texas = 5, &texas = 0012FED4
oil(), x = 31, &x = 0012FD84
block, texas = 113, &texas = 0012FDD8
block, x = 31, &x = 0012FD84
Post-block texas = 5, &texas = 0012FDE4
main(), texas = 31, &texas = 0012FED4
main(), year = 2011, &year = 0012FEC8

Notice that each of the three variables in List 9.4 has its own distinct address and that the program only uses the particular variable in scope at the moment, so assigning the value 133 to `texas` in the inner block of `oil()` has no effect on the other variables of the same name. (As usual, the actual address values and format will differ from system to system.)

Let's summarize the sequence of events. When `main()` starts, the program allocates space for `texas` and `year`, and these come into scope. When the program calls `oil()`, these variables remain in memory but pass out of scope. Two new variables, `x` and `texas`, are allocated and come into scope. When program execution enters the inner block of `oil()`, the new `texas` (hidden) is superseded by a newer definition. The variable `x`, however, stays in scope because the block does not define a new `x`. When execution exits the block, the new `texas` is freed, and `texas` #2 comes back into scope. When the `oil()` function terminates, that `texas` and `x` expire, and the original `texas` and `year` come back into scope.

## Changes to auto in C++11

In C++11, the `auto` keyword is used for automatic deduction, as you have seen in Chapters 3, 7, and 8. In C and prior versions of C++, `auto` has an entirely different meaning. It's used to explicitly identify a variable as having automatic storage:

```cpp
int froob(int n)
{
    auto float ford;   // ford has automatic storage
    ...
}
```

Because programmers can use the `auto` keyword with variables that are already automatic by default, they rarely bother it. Its main function is to document that you really wanted to use a local automatic variable.

In C++11, this usage no longer is valid. The people who prepare standards are reluctant to introduce new keywords because so might invalidate existing code that already uses `auto` for other purposes. In this case, it was felt that the old use of `auto` was enough that it was better to repurpose this keyword rather than introduce a new one.

## Register Variables

C introduced the register keyword to suggest that the compiler use a CPU register to store an automatic variable:

```cpp
register int count_fast; // request for a register
```

The idea was that would allow faster access to the variable. Prior to C++11, C++ used the keyword in the same fashion, except that hardware and compilers developed in sophistication, the hint was generalized to mean that the variable was highly viable and perhaps the compiler could provide some sort of treatment. With C++11, even that is being deprecated, leaving register as just a way to explicitly identify a variable as automatic. Given that register can only be used with variables that would be automatic anyway, one reason to use this keyword is to indicate that you really want to use an automatic variable, perhaps with the same name as an external variable. This is the same purpose as use auto.

## Static Duration Variables

C++, like C, provides static storage duration variables with three kinds of linkage: external linkage (accessible across files), internal linkage (accessible to functions within a single file), and no linkage (accessible to one function or to one block within a function). All three for the duration of the program; they are less ephemeral than automatic variables. Because the number of static variables does not change as the program runs, the program does not need a special device such as a stack to manage them. Instead, the compiler allocates a fixed block of memory to hold all the static variables, and those variables present as long as the program executes. Or if you do not initialize a static variable, the compiler sets it to 0. Static variables and structures have all the bits of each member set to 0 by default.
