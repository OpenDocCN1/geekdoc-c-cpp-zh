### The C++ Preprocessor and the iostream File

Here's the short version of what you need to know. If your program is to use the usual C++ input or output facilities, provide these two lines:

```cpp
#include <iostream>
using namespace std;
```

There are some alternatives to using the second line, but let's keep things simple for now. (If your compiler doesn't C++98 compatible, it will have many other problems with the examples in this book.) That all you really must know to make your programs work, but let's take a more in-depth look.

C++, like C, uses a preprocessor. This is a program that processes a source file before the main compilation takes place. (Some C++ implementations, you might recall from Chapter 1, use a translator to convert a C++ program to C) Although the translator is also a preprocessor; we're not discussing preprocessor; instead, we're discussing the one that handles directives beginning with #.) You don't have to do anything to invoke this preprocessor. It automatically operates when you compile the program.

Listing 2.1 uses the #include directive:

```cpp
#include <iostream>    // a PREPROCESSOR DIRECTIVE
```

This directive tells the preprocessor to add the contents of the iostream file to your program. This is a typical preprocessor action: adding or replacing the text in the source code before it's compiled.

This raises the question of why you should add the contents of the iostream file to the program. The answer concerns communication between the program and the outside world. The io in iostream refers to input, which is information brought into the program, and to output, which is information sent out of the program. C++s input/output scheme involves several definitions in the iostream file. Your first program needs these definitions to use the cout facility to display a message. The #include directive causes the contents of the iostream file to be sent along with the contents of your file to the compiler. In essence, the contents of the iostream file replace the #include <iostream> line in the program. Your original file is not altered, but a composite file formed from your file and iostream goes on the next stage of compilation.

> Note
> Programs that use cin and cout for input and output must include the iostream.

### Header Filenames

Files as as iostream are called include files (because they are included in other files) or header files (because they are included at the beginning of a file). C++ compilers use many header files, each supporting a particular family of facilities. The C tradition has been used to the h extension with header files as a simple way to identify the type of file by its name. The C .h file supports various C functions. Initially, C++ did the same. For instance, the header file supporting input and output was named iostream.h. But C++ usage has changed. Now the h extension is reserved for the C old header files (where C+ programs can still use), whereas C++ header files have no extension. There are also C header files that have been converted to C++ header files. These files have been renamed by dropping the h extension (making it a C++-style name) and prefixing the filename with a c (indicating that it is C+). For example, the C++ version of math.h is the cm header file. Sometimes the C and C++ versions of files are identical, in other cases the new version might have a few changes. For purely C++ header files such as iostream, dropping the h is more than a cosmetic change, for h-free header files also incorporate namespaces. For purely C++ header files such as iostream, dropping the h is more than a cosmetic change, for h-free header files also incorporate namespaces, the next topic in this chapter. ### Namespaces

If you use iostream instead of iostream.h, you should use the following directive to make the definitions in iostream available to your program:

```cpp
using namespace std;
```

This is called a using directive. The simplest thing to do is to accept this for now and worry about it later (as in Chapter 9, Memory and Namespaces). But here's an overview of what's happening. Namespace support is a C++ feature designed to simplify the writing of large programs and organize them. One potential problem is that you might use two products that have both a function called (). If then the compiler won't know which version you mean. The namespace facility lets you use the name of namespace to indicate which version you want. So you could define namespace::() as the full name for your (). Similarly, you could discriminate between versions:

```cpp
std::cout("going"); // use namespace version
std::cout("a named"); // use namespace version
```

In this spirit, classes, functions, and variables are a standard component of C++ all now placed in the h-free header files. This means, for example, that cout is std::cout and endl is std::endl. Thus, you can omit the using directive and, instead, code in the following style:

```cpp
std::cout << "Come up and C++ me some time.";
std::cout << std::endl;
```

However, many users do not like converting-namespace code, which uses iostream.h and cout, to namespace code, which uses iostream and std::cout, unless they can do so without a lot of hassle. This is where the using directive comes. The following line means you can use names defined in the namespace without using the std:: prefix:

```cpp
using namespace std;
```

This using directive makes all the names in the namespace available. Modern practice regards this as a bit lazy and potentially a problem in large projects. The preferred approaches are to use the std:: qualifier or to use a declaration to make just particular names available:

```cpp
std::cout; // make cout available
std::endl; // make endl available
std::cin; // make cin available
```

If you use these directives in the following, you can use cin and cout without attaching std:: to them:

```cpp
using namespace std;
```

This book initially uses the lazy approach for a couple reasons. First, for simple programs, it's not really a big issue which management technique you use. Second, I rather emphasize the more basic aspects about learning C++. Later, the book uses the other namespace techniques.

### C++ Output with cout

Now let's out how to display a message. The first.cpp program uses the C++ statement:

```cpp
cout << "Come up and C++ me some time.";
```

The part enclosed within double quotation marks is the message to print. In C++, any series of characters enclosed in double quotation marks is a character string, presumably because it consists of several characters together into a larger unit. The << notation indicates that the statement is sending the string to cout; the symbols point the way the information flows. And what is cout? It's a predefined object that knows how to display a variety of things, including strings, names, and individual characters. An object, as you might remember from Chapter 1, is a particular instance of a class, and a class defines how data is stored and used.

Well, using objects so soon is a bit awkward because you won't learn about objects for several more chapters. Actually, this reveals one of the strengths of objects. You don't have to know the inside of an object in order to use it. All you must know is its interface—that is, how to use it. cout has a simple interface. If string represents a string, you can do the following to display it:

```cpp
cout << "string";
```

This is all you must know to display a string, but now take a look at how the C++ conceptual view represents the process. In this view, the output is a stream—that is, a series of characters flowing from the program. The cout object, whose properties are defined in the iostream file, represents that stream. The object properties for cout include an insertion operator (<<) that inserts the information on its right into the stream. Consider the following statement (note the terminating semicolon):

```cpp
cout << "Come up and C++ me some time.";
```

It inserts the say that "Come up and C++ me some time." into the output stream. Thus, rather than say that your program displays a message, you can say that it inserts a string into the output stream. Somehow, that sounds more impressive (see Figure 2.2).
