
```cpp
void inadequate(Brass &ba)
{
    ba.ViewAcct();
    cout << endl;
}
```

The first function passes an object by reference, and the second passes an object by value. Now suppose you use each with a derived class argument:

```cpp
BrassPlus buzz("Buzz Parsec", 0001111, 4300);
show(buzz);
inadequate(buzz);
```

The show() function call results in the rba argument being a reference to the BrassPlus object buzz, rba.ViewAcct() is interpreted as the BrassPlus version, as it should be. But in the inadequate() function, which passes an object by value, ba is a Brass object constructed by the Brass(const Brass &) constructor. (Automatic upcasting allows to refer to a BrassPlus) Thus, only the Brass component is displayed.

## Destructor Considerations

As mentioned earlier, a base class destructor should be virtual. That way, when you delete a derived object via a base-class pointer or reference to the object, the program uses the derived-class destructor followed by the base-class destructor rather than using only the base-class.

## Friend Considerations & operator<<

Because a friend function is not actually a class member, it's not inherited. However, you might still need a friend to a derived class to use a friend of the base class. The way to accomplish this is to type cast a derived-class reference or pointer to the base-class equivalent and use the type cast reference or pointer to invoke the base-class friend:

```cpp
ostream & operator<<(ostream &os, const baseDMA & hs)
{
    // type cast to match operator<<(ostream &os, const baseDMA &)
    os << (const baseDMA &)hs;
    os << "Style: " << hs.style << endl;
    return os;
}
```

You can also use the dynamic_cast<> operator, discussed in Chapter 15, "Exceptions, and More," for the type cast:

```cpp
os << dynamic_cast<const baseDMA &>(hs);
```

For reasons discussed in Chapter 15, this would be the preferred form of type cast.

## Observations on Using Base-Class Methods

Publicly derived objects use base-class methods in many ways:

- A derived object automatically uses inherited base-class methods if the derived class hasn't redefined the method.
- A derived-class destructor automatically invokes the base-class constructor.
- A derived-class constructor automatically invokes the base-class constructor if you don't specify another constructor in a member-initialization list.
- A derived-class constructor explicitly invokes the base-class constructor specified in a member-initialization list.
- Derived-class methods can use the resolution-operator to invoke public and protected base-class methods.
- Friends to a derived class can cast a derived-class reference or pointer to a base-class reference or pointer and then use that reference or pointer to invoke a friend to the base class.

## Summary

Inheritance enables you to adapt code by using a base class. A derived class is a kind of base class, and a derived-class object inherits the members of the base class. When a program creates a derived-class object, it first calls the base-class constructor and then the derived-class constructor. When a program deletes an object, it first calls the derived-class destructor and then the base-class destructor. If a class is meant to be a base class, its destructor should be virtual. You might define an ABC as an interface without getting into matters. For example, you could define Shape class from which shape classes, such as Circle and Square, will be derived. An ABC must include at least one pure virtual method. You declare a pure virtual method by placing = 0 before semicolon:

```cpp
virtual double area() = 0;
```

You don't have to define virtual methods, and you can't create an object of a class that contains pure virtual methods. Instead, pure virtual methods serve to define an interface for derived classes.
