 are several advantages to using the const approach. First, the declaration explicitely names the type.With #define, you must use various suffixes to a number to indicate types other than char, int, or double; for example, use 100L to indicate a long type and 3.14F to indicate a float type. Most importantly, the const approach can just as easily be used with compound types, as in this:

```
const int base_vals[5] = {1000, 2000, 3500, 6000, 10000};\nconst string ans[3] = {"yes", "no", "maybe"};
```

Finally, const identifies the same scope as variables. Thus, you can create constants with global scope, namespace scope, and block scope. If, you define a constant in a particular function, you don't have to worry about the definition conflicting with a global constant used elsewhere in a program. For example, consider the following:

The preprocessor will replace

int n;
with
int dz;

and induce a compilation error. The dz defined in fizzle(), however, will be a local variable. Also if necessary, fizzle() can use the scope-resolution operator (:) and access the constant as ::dz.

C++ has borrowed the const keyword from C, but the C++ version is more useful. For example, the C++ has internal linkage for external const values rather than the default external linkage used by variables and by the C const. This means that each file in a program using a const needs const defined in that particular file. This might sound like extra work, but in fact it makes life easier. With internal linkage, you can place const definitions in a header file used by various files in a project.That is a compiler error for external linkage but not for internal linkage. Because a const must be defined in the file that it uses (being in a header file used by that file that satisfies the requirement), you can use const values as array size arguments:

```
const int MAX_LENGTH = 100;
...
double loads[MAX_LENGTH];
```
