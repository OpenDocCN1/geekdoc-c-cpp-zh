On average, however, the step size quadruples the number of steps needed to cover a given distance. Probability theory suggests that, on average, the number of steps (N) of length l to reach a net distance of D is given by the following equation:

```
N = (D/s)^2
```

This is just average, but there will be considerable variations from trial to trial. For example, 1,000 trials of attempting to travel 50 feet in 2-foot steps yielded an average of 636 steps (close to the theoretical value of 625) to travel that far, but the range was 91 to 3,951. Similarly, 1,000 trials of traveling 50 feet in 1-foot steps averaged 2,557 steps (close to the theoretical value of 2,500), with a range of 345 to 10,882. If you find yourself walking randomly, be confident and take long steps. You still will not have any control over the direction you wind up, but at least you'll get further.

## Automatic Conversions and Type Cases for Classes

The next topic on the class menu is type conversion. We'll look into how C++ handles conversions to user-defined types. To set the stage, let's first review how C++ handles conversions for its builtin types. When you make a statement that assigns a value of one standard type to another standard type, C++ automatically converts the value to the same type as the receiving variable, provided that the two types are compatible. For example, the following statements generate type conversions:

```cpp
long count = 8;           // int value converted to long
double time = 11;        // int value converted to double
int side = 3.33;          // double value 3.33 converted to int
```

These assignments work because C++ recognizes that different numeric types represent the same base—a number—and because C++ incorporates builtin rules for making the conversions. Recall from Chapter 3, "Dealing with Data," however, that you may lose some precision in these conversions. For example, assigning 3.33 to the int variable side results in side getting the value 3.0.

The C++ language does not automatically convert types that are not compatible. For example, the following statement fails because the left side is a pointer type, whereas the right side is a number:

```cpp
int * p = 10; // type clash
```

And even though a computer may represent an address internally with an integer, integers and pointers are conceptually quite different. For example, you wouldn't square a pointer. However, when automatic conversions fail, you may use a type cast:

```cpp
int * p = (int *) 10; // ok, p and (int *) 10 both pointers
```

This sets the pointer to the address 10 by casting 10 to pointer-to-int (that is, type int *). Whether this assignment makes sense is another matter.

You may define a class sufficiently to a basic type or to another class that makes sense to convert from one to another automatically, perhaps, via a type cast. To see how that works, you can recast the pounds-to-stone from Chapter 3 into class form. First, you need to design an appropriate type. Fundamentally, you're representing one thing (weight) two ways (pounds and stone). A class provides an excellent way to incorporate two representations of one concept into a single entity. Therefore, it makes sense to place both representations of the weight into the same class and then provide class methods for expressing the weight in different forms. Listing 11.16 provides the class header.

```cpp
Listing 11.16 stonew.h
// stonew.h -- definition for the Stonew class
#ifndef STONEW_H_
#define STONEW_H_
class Stonew
{
private:
    enum {Lbs_per_stn = 14}; // pounds per stone
    int stone; // whole stones
    double pds_left; // fractional pounds
    double pounds; // entire weight in pounds
public:
    Stonew(double lbs); // constructor for double pounds
    Stonew(int stn, double lbs); // constructor for stone, lbs
    Stonew();
    ~Stonew(); // default constructor
    void show_lbs() const; // show weight in pounds format
    void show_stn() const; // show weight in stone format
};
#endif
```

As mentioned in Chapter 10, enum provides a convenient way to define class-specific constants, provided that they are integers. Or you could use the following alternative:

```cpp
static const int Lbs_per_stn = 14;
```
