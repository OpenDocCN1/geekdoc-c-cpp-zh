```
spiff(22); // want spiff from a C library
```

Its hypothetical symbolic name in the C library is _spiff, but for our hypothetical linker, the C++ look-up connection is for the symbolic name _spiff_i. To get around this, you can use the function prototype to identify which protocol to use:

```
extern C void spiff(int);      // use C protocol for name look-up
extern void spiff(int);         // use C++ protocol for name look-up
extern "C++" spiff(int);      // use C++ protocol for name look-up
```

The first and third examples use C++ language linkage; the second does by default, and the third does explicitly. C and C++ language linkage are the only specifiers required by the C++ Standard. Implementations have the option of providing additional language linkage specifies.

# Storage Schemes and Dynamic Allocation

You've seen the five schemes, excluding threaded memory, C++ uses to allocate memory for variables (including arrays and structures). They do not apply to allocate memory using the C++ new operator (or using the older malloc() function). We call that kind of memory dynamic memory. As you saw in Chapter 4, dynamic memory is controlled by the new and delete, not by scope and linkage rules. Thus, dynamic memory can be allocated from one function and freed from another function. Unlike atomic memory, dynamic memory is not LIFO; the order of allocation and freeing depends on when and how new and delete are used. Typically, the compiler uses three separate memory one for static variables (this might be subdivided), one for automatic variables, and one for dynamic storage.
