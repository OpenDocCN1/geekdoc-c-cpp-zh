
Well, maybe you can't trust it completely. Adding 11.17 to 50.25 yields 61.42, but the output reports involve 61.419998. This is not an arithmetic problem; it's a problem with the limited capacity of float. Remember, C++ guarantees six significant figures for float. If you round 61.41998 to six figures, you get 61.4200, which is the correct value to the guaranteed precision. The moral is that if you need greater accuracy, you should use long double.

Sometimes the precedence list is not. Consider the following statement:

```
float logs = 120 / 4 * 5; // 150 or 24?
```

Once again, 4 is an operand for two operators. The / and * operators have the same precedence, so precedence alone doesn' tell the program whether to divide 120 by 4 or multiply 4 by 5.Because the first choice leads to a result of 150 and the second to a result of 6, this is an important one. When two operators have the same precedence,C++ looks at whether they have a left-to-right associativity or a right-left associativity. Left-to-right associativity means if two operators acting on the same operand have the same associativity, you apply the left-hand operator first. For right-to-left associativity, you apply the right-hand operator first. The associativity information, too, is in Appendix D.Appendix D shows that multiplication and division associate left-to-right. That means you use 4 with the leftmost operator first. That is, you divide 120 by 4, get 30 as a result, and then multiply the result by 5 to get 150.
