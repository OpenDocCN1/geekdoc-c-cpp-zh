# Stream States

Let's take closer look at what happens for inappropriate input. A cin or cout object contains a data member (inherited from the ios_base class) that describes the stream state. A stream state (defined as type iostate, when in, is a bitmask type, such as described earlier) consists of three ios_base elements: eofbit, badbit, and failbit. Each element is a single bit that can be set (1) or cleared (0). When an operation reaches the end of a file, it sets eofbit. When an operation fails to read the expected characters, in the earlier example, it sets failbit. IO failures, such as trying to read a non-accessible file or writing to a write-protected disk, also can set failbit to 1. The badbit element is set when some undiagnosed failure may have corrupted the stream. (Implementations do not necessarily agree about which events set failbit and set badbit.) When all of these three states are set to 0, everything is fine. Programs can check the stream state and use that information to decide what to do next. Table 17.4 lists these bits, along with some ios_base methods that report or alter the stream state.

# Table 17.4 Stream States

| Member | Description |
| --- | --- |
| eofbit | Is set to 1 if end-of-file reached. |
| badbit | Is set to 1 if stream may be corrupted; for example, there could be a file read error. |
| failbit | Is set to 1 if an input operation failed to read the expected characters or an output operation failed to write the expected characters. |
| good | Just another saying 0. |
| good() | Returns true if the stream can be used (all bits are cleared). |
| eof() | Returns true if eofbit is set. |

| Member | Description |
| --- | --- |
| bad() | Returns true if badbit is set. |
| fail() | Returns true if badbit or failbit is set. |
| rdstate() | Returns the stream state. |
| exceptions() | Returns a bit mask that identifies flags cause an exception to be thrown. |
| exceptions(iostate ex) | Sets states which will state bits clear to throw an exception; for example, if ex is eofbit, then clear() will throw an exception if eofbit is set. |

clear(iostate s) Sets the stream state to s; the default for s is 0 (goodbit); throws a basic_ios::failure exception if (rdstate() & exceptions()) != 0.

setstate(iostate s) Calls clear(rdstate() | s). This sets state bits corresponding to those bits set in s; other stream state bits are unchanged

# Setting States

Two of the methods in Table 17.4, clear() and setstate(), are similar. Both reset the state, but they do so in a different fashion. The clear() method sets the state to its argument. Thus, the following call uses the default argument of 0, which clears all three bits (eofbit, badbit, and failbit):

```cpp
clear();
```

Similarly, the following call makes the state equal to eofbit; that is, eofbit is set, and the other two state bits are cleared:

```cpp
clear(eofbit);
```

The setstate() method, however, affects only those bits that are set in its argument. Thus, the following call sets eofbit without affecting the other bits:

```cpp
setstate(eofbit);
```

So if badbit was already set, it sets state. Why would you reset the stream state? For a program, the most common reason is to use clear() with no argument after encountering mismatched input or end-of-file; doing so depends on what the program is trying to accomplish. You'll see some examples shortly. The main purpose for setstate() is to provide a means for input and output functions to change the state. For example, if num is an int, the following call can result in operator>>(int &) using setstate() to set failbit or eofbit:

```cpp
cin >> num; // read an int
```

# I/O and Exceptions

Suppose that an input function eofbit. Does this cause an exception to be thrown? By default, the answer is no. However, you can use the exceptions() method to control how exceptions are handled.

First, here's some background. The exceptions() method returns a bitfield with three bits corresponding to eofbit, failbit, and badbit. Changing the stream state involves clear() or setState(), which uses clear(). After changing the stream state, the clear() method compares the current stream state to the value returned by exceptions(). If a bit is set in the value and the corresponding bit is set in the current state, clear() throws an ios_base::failure exception. This would happen, for example, if both badbit and eofbit are set. If it follows that exceptions() returns goodbit, no exceptions are thrown. The ios_base::failure exception class derives the std::exception and has a what() method. The default setting for exceptions() is goodbit—that is, no exceptions thrown. However, the overloaded exceptions(iostate) function gives you control over the behavior:

```cpp
cin.exceptions(badbit); // setting badbit causes exception to be thrown
```

The bitwise OR operator, discussed in Appendix E, allows you to specify more than one. For example, the following statement results in an exception being thrown if either badbit or eofbit is set:

```cpp
cin.exceptions(badbit | eofbit);
```

Listing 17.12 validates that the program verifies and catches an exception if failbit is set.

# Listing 17.12 exceptions.cpp

```cpp
// exceptions.cpp -- having cin throw an exception
#include <iostream>
#include <exception>

int main() {
    using namespace std;
    // have failbit cause an exception to be thrown
    cin.exceptions(ios_base::failbit);
    cout << "Enter numbers: ";
    int sum = 0;
    int input;
    try {
        while (cin >> input) {
            sum += input;
        }
    } catch (ios_base::failure& bf) {
        cout << bf.what() << endl;
        cout << "the horror!\n";
    }
    cout << "Last value entered = " << input << endl;
    cout << "Sum = " << sum << endl;
    return 0;
}
```

Enter a sample run of the program in Listing 17.12: the what() depends on the implementation:

Enter numbers: 200 30 40 pi
ios_base::failure in clear
the horror!
Last value entered = 40
Sum = 270

So that you can use exceptions for input. But should you use them? It depends on the context. For this example, the answer is no. An exception should catch an unusual, unexpected occurrence, but this particular program would use a mismatch as the way to exit the loop. It might make sense, however, for a program to throw an exception for badbit that would be unexpected. Or if the program were designed to read numbers from a data file up to end-of-file, it might make sense to throw an exception for failbit that would represent a problem with the data file.

# Stream State Effects

An if or while test like the following tests true only if the stream state is good (all bits cleared):

```cpp
while (cin >> input)
```

If a test fails, you can use the member functions in Table 17.4 to discriminate among possible causes. For example, you could modify the central part of Listing 17.11 to look like this:

```cpp
while (cin >> input) {
  sum += input;
}
if (cin.eof()) {
  cout << "Loop terminated because EOF encountered\n";
}
```

Setting a state bit has a very important consequence: the stream is closed for further input or output until the bit is cleared. For example, the following code will not:

```cpp
while (cin >> input) {
    sum += input;
}
cout << "Last value entered = " << input << endl;
cout << "Sum = " << sum << endl;
cout << "Enter a new number: ";
cin >> input; // won't work
```

If you want a program to read further input after a stream state bit has been set, you have to reset the stream state to good. This can be done by calling the clear() method:

```cpp
while (cin >> input) {
    sum += input;
}
cout << "Last value entered = " << input << endl;
cout << "Sum = " << sum << endl;
cout << "Enter a new number: ";
cin.clear(); // reset stream state
while (isspace(cin.get()))
    continue; // get rid of bad input
cin >> input; // will not work
```

Note that it is not enough to reset the stream state. The mismatched input is still in the the input queue, and the program has to pass it over. One way is to keep reading characters until reaching white space. The isspace() function in Chapter 6, "Branching Statements and Logical Operators" is a ctype function that returns true if it is a white-space character. Or you can discard the rest of the line instead of just the next word:

```cpp
while (cin.get() != '\n')
    continue; // get rest of line
```

This example assumes that the loop terminated because of end-of-file or because of a hardware failure. The new code disposing of bad input makes no sense. You can fix matters by using the fail() method to test whether the assumption was correct. For historical reasons, fail() returns true either fail or eof, the code is set to exclude the latter case. The following code shows an example of such exclusion:

```cpp
while (cin >> input) {
    sum += input;
    cout << "Last value entered = " << input << endl;
    cout << "Sum = " << sum << endl;
    if (cin.fail() && !cin.eof()) // failed because of mismatched input
}
```
