### When Exceptions Go Astray

抛出异常后，它有两次机会导致问题。首先，如果它是在具有异常规范的函数中抛出的，它必须与规范列表中的其中一个类型匹配。记住，在继承层次结构中，一个类匹配该类型及其派生类型的对象。如果异常与规范不匹配，未匹配的异常将被标记为 *unexpected exception*，并且默认情况下，它会导致程序中止。虽然 C++11 已弃用异常规范，但它们仍然保留在语言中，并在某些代码编辑器中存在。如果异常通过了这一关，或者因为函数没有异常规范，那么它必须被捕获。如果没有被捕获，会发生什么？如果没有包含的 try 块或没有 catch 块，异常将被标记为 *uncaught exception*，并且默认情况下，它会导致程序中止。然而，你可以改变程序对意外和未捕获异常的响应。

未捕获的异常不会立即引发中止。相反，首先调用一个名为 `terminate()` 的函数。默认情况下，`terminate()` 调用 `abort()` 函数。你可以通过注册一个函数来修改 `terminate()` 的行为，使 `terminate()` 改为调用该函数而不是 `abort()`。为此，你调用 `set_terminate()` 函数。`set_terminate()` 和 `terminate()` 都在异常头文件中声明：

```
void (*terminate_handler)();
void set_terminate(terminate_handler f) throw(); // C++98
terminate_handler set_terminate(terminate_handler f) noexcept; // C++11
void terminate(); // C++98
void terminate() noexcept; // C++11
```

这里的 `typedef` 使 `terminate_handler` 成为指向一个函数指针的类型名称，该函数没有参数且没有返回值。`set_terminate()` 函数以函数名作为参数，即其地址，该函数没有参数且没有返回类型。如果 `set_terminate()` 函数被调用多次，`terminate()` 将调用最近一次对 `set_terminate()` 的调用所设置的函数。

让我们看一个例子。假设你希望未捕获的异常导致程序打印一条消息，然后调用 `exit()` 函数，提供退出状态 5。首先，如果你包含异常头文件。你可以使用直接或适当的 using 声明使其声明可用，或者你可以使用 `std::` 限定符：

```
#include <exception>
using namespace std;
```

接下来，你设计一个执行所需操作并具有正确原型的函数：

```
void myQuit()
{

```

exit(5);

最后，在程序开始时，你指定此函数作为你选择的终止操作：

```
set_terminate(myQuit);
```

现在，如果抛出异常且未被捕获，程序将调用 terminate()，而 terminate() 将调用 MyQuit()。

接下来，让我们看一下意外的异常。通过为函数使用异常规范，你为函数用户提供了了解应捕获哪些异常的手段。也就是说，假设你有以下原型：

```
double Argh(double, double) throw(out_of_bounds);
```

那么你可能会这样使用该函数：

```
try {
  x = Argh(a, b);
} catch(out_of_bounds & ex) {
  ...
}
```

知道应捕获哪些异常是很好的；请记住，未捕获的异常默认会中止程序。

然而，故事还有更多。在原则上，异常规范应包括被讨论的函数所调用的函数抛出的异常。例如，如果 Argh() 调用一个可以抛出 retort 对象的 Duh()，那么 retort 应该出现在 Argh() 的异常规范中，就像在 Duh() 的异常规范中一样。除非你自己编写所有函数并且小心，否则无法保证这一点会正确完成。例如，你可能会使用一个没有异常规范的旧商业库。这表明你应仔细查看当函数抛出不在其异常规范中的异常时会发生什么。这也表明整个异常规范机制可能过于笨重，这也是 C++11 弃用它的原因之一。

行为与意外异常类似。如果存在意外的 unexpected() 函数？你没有预料到 unexpected() 函数？没有人预料到意外函数！此函数反过来调用 terminate()，默认情况下，abort()。正如有 set_terminate() 函数可以修改 terminate() 的行为一样，也有 set_unexpected() 函数可以修改 unexpected() 的行为。这些新函数也声明在异常处理程序文件中：

```
typedef void (*unexpected_handler)();
unexpected_handler set_unexpected(unexpected_handler f) throw(); // C++98
unexpected_handler set_unexpected(unexpected_handler f) noexcept; // C++11
```

然而，你为 set_unexpected() 提供的函数的行为比为 set_terminate() 提供的函数更规律。特别是，unexpected_handler 函数有以下选择：

- 它可以通过调用 terminate()、abort() 或 exit() 来结束程序，这是默认行为。
- 它可以抛出一个异常。

抛出异常的结果取决于 replacement unexpected_handler 抛出的异常以及抛出意外的函数的原始异常规范：

- 如果新抛出的异常与原始异常规范匹配，那么程序将从那里正常继续；也就是说，它将寻找匹配新抛出异常的 catch 块。从根本上说，这种方法用预期类型的异常替换了意外类型的异常。
- 如果新抛出的异常与原始异常规范不匹配，并且异常规范不包括 std::bad_exception 类型，程序将调用 terminate()。bad_exception 类型派生自 exception 类型，并在异常头文件中声明。
- 如果新抛出的异常与原始异常规范不匹配，并且异常规范确实包括 std::bad_exception 类型，未匹配的异常将被替换为 std::bad_exception 类型的异常。

简而言之，如果你想捕获所有异常，无论是预期还是其他，你可以做如下操作。首先，你确保异常头文件声明为：

```
#include <exception>
using namespace std;
```

接下来，使用一个将意外异常转换为 bad_exception 类型的替换函数，并且具有正确的原型：

```
void myUnexpected()
{
    throw std::bad_exception(); //or just throw;
}
```

仅使用 throw 而不带异常会导致原始异常被重新抛出。然而，如果异常规范包含该类型，异常将被替换为 bad_exception 对象。
