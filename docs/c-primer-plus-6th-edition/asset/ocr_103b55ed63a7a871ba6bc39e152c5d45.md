Thus, the return value of $S1.operator=(S2) becomes the argument of the S0.operator=() function. Because the return value is a reference to a String object, it is the correct argument type.

Here's how you could write an assignment operator for the StringBad class:

```
StringBad & StringBad::operator=(const StringBad &st)
{
    if (this == &st)            // object assigned to itself
        return *this;               // all done
    delete [str];               // free old string
    len = st.len;
    str = new char[len + 1];   // get space for new string
    std::strcpy(str, st.str);   // copy the string
    return *this;               // return reference to invoking object
}
```

First, the code checks for self-assignment. It does so by seeing if the address of the right-hand side of the assignment (&s) is the address of the receiving object (this). If so, the program returns *this and terminates. You may recall from Chapter 10 that the assignment operator is one of the operators that can be overloaded by a class member function.

Otherwise, the function proceeds to free the memory str pointed to. The reason for this is that shortly str will be assigned the address of a new string. If you don't first apply delete operator, the previous string will remain in memory. Because the program no longer has a pointer to the old string, that memory will be wasted.

Next, the program proceeds like a copy constructor, allocating enough space for the new string and then copying the right-hand object to the new location. When it is finished, the program returns *this and terminates. Assignment does not create a new object, so you don't have to adjust the value of the static data member num_strings.

Adding the copy constructor and the assignment operator described previously to the StringBad clears all the problems. Here, for example, are the few lines of output after these changes have made:
