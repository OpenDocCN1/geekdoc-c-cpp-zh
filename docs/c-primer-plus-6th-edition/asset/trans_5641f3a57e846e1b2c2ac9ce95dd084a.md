

# 枚举 151

默认情况下，枚举器会被赋予从 0 开始的整数值，第一个枚举器为 0，第二个为 1，以此类推。您可以通过显式地分配整数值来覆盖默认值。您将在本章后面看到如何操作。

您可以使用枚举名称来声明枚举类型的变量：spectrum band; // band 是 spectrum 类型的变量

枚举变量具有特殊的属性，我们现在就来考察。您可以在不进行类型转换的情况下赋给枚举变量的唯一有效值是用于定义该类型的枚举器。因此，我们有以下情况：

```
band = blue; // 有效，blue 是一个枚举器
band = 2000; // 无效，2000 不是枚举器
```

因此，spectrum 变量仅限于八个可能的值。某些编译器在您尝试分配无效值时会发出编译错误，而其他编译器则发出警告。为了获得最大可移植性，您应将非枚举值赋给枚举视为错误。

仅为枚举定义了赋值运算符。特别是，算术运算未定义：

```
band = orange; // 有效
++++; // 无效，定义在第 5 章
band = orange + red; // 无效，有点 tricky
```

然而，一些实现并不遵守此限制。这可能会导致违反类型限制。例如，如果 band 的值为 ultraviolet，或 7，则 ++++; 如果有效，将 band 增加到 8，而 8 不是 spectrum 类型的有效值。同样，为了获得最大可移植性，您应采用更严格的限制。

枚举器是整数类型，可以提升为 int 类型，但 int 类型不会自动转换为枚举类型：

```
int color = blue; // 有效，spectrum 类型提升为 int
band = 3; // 无效，int 未转换为 spectrum
color = 3 + red; // 有效，red 转换为 int
...
```

请注意，在此示例中，即使 3 对应于枚举器 green，将 3 分配给 band 也是类型错误。但将 green 分配给 band 是可以的，因为两者类型都是 spectrum。同样，一些实现并不强制执行此限制。在表达式 3 + red 中，枚举器的加法未定义。然而，red 被转换为 int 类型，结果为 int 类型。由于在此情况下枚举到 int 的转换，您可以在算术表达式中使用枚举来组合它们，尽管枚举本身未定义算术运算。

```
band = orange + red; // 无效，有点 tricky
```

失败的原因有点复杂。确实，+ 运算符未为枚举器定义。枚举器在用于算术表达式时也会转换为整数，表达式 orange + red 被转换为 1 + 0，这是一个有效表达式。但其类型为 int，因此无法分配给 spectrum 类型变量 band。

您可以在使用显式类型转换的前提下将 int 值赋给枚举，前提是该值有效：

```
band = spectrum(3);          // 将 3 类型转换为 spectrum
```

如果您尝试转换不适当的值会怎样？结果未定义，这意味着尝试不会被标记为错误，但您不能依赖结果的值：

```
band = spectrum(40003);      // 未定义
```

（请参阅本章后面的“枚举的值范围”，以讨论哪些值是适当和不适当的。）
正如您所见，管理枚举的规则相当严格。实际上，枚举更常被用作定义符号常量的值，而不是作为新类型。例如，您可能会使用枚举来为 switch 语句定义符号常量。（参见第 6 章“分支语句和逻辑运算符”）如果您计划仅使用常量而不创建枚举类型的变量，可以省略枚举类型名称，如此示例所示：

```
enum {red, orange, yellow, green, blue, violet, indigo, ultraviolet};
```

## 设置枚举器值

您可以通过赋值运算符显式设置枚举器值：

```
enum bits{one = 1, two = 2, four = 4, eight = 8};
```

分配的值必须是整数。您也可以仅显式定义部分枚举器：

```
enum bigstep{first, second = 100, third};
```

在这种情况下，first 默认值为 0。后续未初始化的枚举器比其前驱大一。因此，third 的值将为 101。

最后，您可以创建多个具有相同值的枚举器：

```
enum {zero, null = 0, one, numero_uno = 1};
```

这里，zero 和 null 都是 0，而 numero_uno 和 uno 都是 1。在 C++ 的早期版本中，您只能为枚举器分配 int 值（或可提升为 int 的值），但该限制已被移除，以便您可以使用 long 或 long long 类型的值。

## 枚举的值范围

最初，枚举的有效值仅限于声明中命名的那些值。然而，C++ 已通过使用类型转换扩展了可以分配给枚举变量的有效值列表。每个枚举都有一个范围，您可以使用类型转换将范围内的任何整数分配给枚举变量，即使它不是枚举值。例如，假设 bits 和 myflag 是这样定义的：

```
enum bits{one = 1, two = 2, four = 4, eight = 8};
bits myflag;
```

在这种情况下，以下是有效的：

```
myflag = bits(6); // 有效，因为 6 在 bits 范围内
```

这里 6 不是枚举器之一，但它位于枚举器定义的范围内。范围定义如下。首先，找到上限，您取最大值然后减一；结果是范围的上端。（例如，以前定义的最大的 bigstep 为 101。大于此的最小 2 的幂为 128，因此范围的上端为 127。）接下来，找到下限，您找到最小的枚举值。如果它为 0 或更大，则范围的下限为 0。如果最小枚举器为负，则使用与查找下限相同的方法但带负号。（例如，如果最小枚举器为 -6，下一个 2 的幂 [乘以负号] 为 -8，下限为 -7。）

其思想是编译器可以选择用于保存枚举的空间。它可能会为范围小的枚举使用 1 字节或更少，为具有 long 类型值的枚举使用 4 字节。

C++11 通过一种称为作用域枚举的形式扩展了枚举。第 10 章在“类作用域”部分简要讨论了这种形式。

## 指针和自由存储

第 3 章开头提到计算机程序必须跟踪数据的三个基本属性。为了节省您翻回该章节的麻烦，这里再次列出这些属性：

- 信息存储在何处
- 在那里保存什么值
- 存储的是什么类型的信息

您使用的一种实现这些目标的策略是定义简单变量。声明语句提供值的类型和符号名称。它还导致程序为值分配内存并在内部跟踪其位置。

现在让我们看第二种策略，在开发 C++ 类时变得特别重要。这种策略基于指针，指针是存储值地址而不是值本身的变量。在讨论指针之前，让我们谈谈如何显式查找普通变量的地址。您只需将地址运算符 & 应用于变量即可获得其位置；例如，如果 home 是一个变量，&home 就是其地址。清单 4.14 演示了此运算符。

### 清单 4.14 address.cpp

```
// address.cpp -- 使用 & 运算符查找地址
#include <iostream>
int main()
{
    using namespace std;
    int donuts = 6;
    double cups = 4.5;

    cout << "donuts value = " << &donuts << endl;
    // NOTE: you may need to use unsigned (donuts)
    // and unsigned (cups)
    cout << "cups value = " << &cups;
    cout << " and cups address = " << &cups << endl;
    return 0;
}
```

以下是清单 4.14 程序在一个系统上的输出：
donuts value = 6 and donuts address = 00065fd40
cups value = 4.5 and cups address = 00065fd44

这里显示的 cout 实现使用十六进制表示法显示值，因为这是指定内存地址时通常使用的表示法。（某些实现使用十进制。）我们的实现将 donuts 存储在比 cups 更低的内存位置。两个地址之间的差值为 00065fd44 - 00065fd40，即 4。这是有意义的，因为 donuts 是 int 类型，使用 4 字节。不同系统会给出不同的地址值。有些系统先存储 cups，然后存储 donuts，差值为 8 字节，因为 cups 是 double。有些系统甚至可能不使用相邻位置。

使用普通变量时，值被视为命名量，位置被视为派生量。现在让我们看指针策略，这是 C++ 编程哲学中内存管理必不可少的。（参见下面的边栏，“指针和 C++ 哲学”。）
