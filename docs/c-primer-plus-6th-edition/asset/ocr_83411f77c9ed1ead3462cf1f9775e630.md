# Program Notes

Because the const array object Snames is declared above all the functions, it can be used in any of the following function definitions. The const Seasons, Snames is shared by the whole source code file. The program doesn't have a using directive, so array and string have to be used with the str:: qualifier. To keep the program short and focused on how functions use objects, the fill() function doesn't check for valid input.

Both fill() and show() have drawbacks. For show(), the problem is that expenses holds double values and is inefficient to create a new object and copy the expenses into it. The gets worse if we modify the program to handle expenses on a monthly or daily basis and expand expenses accordingly.

The fill() avoids this inefficiency by using a pointer so that the function acts on the original object. But this comes at the cost of notation that the programming look more complicated:

```
fill(&expenses); // don't forget the &
...
cin >> (*pa) [i];
```

In the statement, pa is a pointer to an array<double, 4> object, *pa is the object, and (*pa)i is an element of the object. The parents are required because of operator precedence. The logic is straightforward, but enhances opportunities for making errors.

Using references, as discussed in Chapter 8, helps solve both the efficiency and the notational problems.
