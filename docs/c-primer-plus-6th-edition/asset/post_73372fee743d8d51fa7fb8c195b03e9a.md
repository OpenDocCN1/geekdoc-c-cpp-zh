# Program Notes

Listing 7.6 illustrates some very interesting points about array functions. First, note that cookies and arr both evaluate to the same address, exactly as claimed. But sizeof cookies is 32, whereas sizeof arr is only 4. That's because sizeof cookies is the size of the whole array, whereas sizeof arr is the size of the pointer variable. (This program execution takes place on a system that uses 4-byte addresses.) By this way, this is why you have to explicitly pass the size of the array rather than use sizeof arr in sum_arr(); the pointer by itself doesn't reveal the size of the array.

The only way sum_arr() knows the number of elements in the array is through what you tell it with the second argument, you can lie to the function. For example, the second program uses the function, it makes this calls:

```cpp
sum = sum_arr(cookies, 3);
```

By telling the function that cookies has just three elements, you get the function to calculate the sum of the first three.

Why stop there? You can also lie about where the array starts:

```cpp
sum = sum_arr(cookies + 4, 4);
```

Because cookies acts as the address of the first element, cookies + 4 acts as the address of the fifth element. This statement says the fifth, seventh, and eighth elements of the array. Note in the output how the call to the function assigns a different address to add than the first two calls did. And, you can use &cookies[4] instead of cookies + 4 as the argument; they both mean the same thing.

# Filling the Array

Because a function with an array argument accesses the original array, not a copy, you can use a function to assign values to array elements. One argument to the function will be the name of the array to be filled. In general, a program might manage more than one person's investments, hence more than one, so you don't want to build the array size into the function. Instead, you pass the array size as a second argument, as in the previous example. It's possible that you might want to read data before filling the array, so you want to build that feature into the function. You might enter fewer than the maximum number of elements, it makes sense to have the function return the actual number of values entered. These considerations suggest the following function prototype:

```cpp
int fill_array(double array[], int limit);
```

The function takes an array name and an argument specifying the maximum number of items to read. For example, if you use this function with an array of five elements, you pass 5 as the second argument. If you then enter only three values, the function returns 3.

You can use a loop to read successive values into the array, but how can you terminate the loop early? One way is to use a special value to indicate the end of input. Because no property should have a negative value, you can use a negative number to indicate the end of input. The function should do something about bad input, as terminating further input. Given these considerations, you can code the function as:

```cpp
int fill_array(double array[], int limit)
{
    using namespace std;
    double temp;
    int i;
    for (i = 0; i < limit; i++)
    {
        cout << "Enter value #" << (i + 1) << ": ";
        if (!(cin >> temp)) // bad input
        {
            cin.clear();
            while (cin.get() != '\n')
                continue;
            cout << "Bad input; input terminated.\n";
            break;
        } else if (temp < 0) // signal to terminate
            break;
        array[i] = temp;
    }
    return i;
}
```

# Showing the Array and Protecting it with const

Building a function to display the array contents is simple. You pass the name of the array and the number of filled elements to the function, which then uses a loop to display each element. But there is another consideration—guaranteeing that the display function doesn't alter the original. Unless the purpose of a function is to alter data passed to it, you should safeguard from doing so. Protection comes automatically with ordinary arguments because C++ passes them by value, and the functions that use an array work with the original. After all, that's the fill_array() function is able to do its job. To keep a function from accidentally altering the contents of an array, you can use the keyword const (discussed in Chapter 3,"Dealing with Data") when you declare the formal argument:

```cpp
void show_array(const double ar[], int n);
```

The declaration states that the pointer points to constant data. This means that you can't use it to change the data. That is, you can use a value as ar[0], but you can't change value. Note that this doesn't mean the original array needs to be constant; it just means that you can't use ar in the show_array() function to change the data. Thus, show_array() treats the array as read-only data. Suppose you violate this restriction by doing something like the following in the show_array() function:

```cpp
ar[0] += 10;
```

In this case, the compiler will put you to your wrongful ways. Borland C++, for example, gives an error message like this (edited slightly):

```
Cannot modify a const object in function

show_array(const double *,int);
```

Other compilers may choose to express their displeasure in different words.
