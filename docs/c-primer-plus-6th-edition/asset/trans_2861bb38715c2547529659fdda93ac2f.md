## Summary

本章涵盖了定义和使用类的许多重要方面。其中一些方面是微妙的——甚至困难的概念。如果其中一些对你来说似乎晦涩或异常复杂，不要感到沮丧；它们对 C++ 新手来说就是这样。经常你会通过忽视它们而遇到麻烦，从而开始欣赏诸如拷贝构造函数之类的概念。本章的一些内容可能在你自己的经验丰富你的理解之前显得模糊。

你可以在类构造函数中使用 new 为数据分配内存，然后将内存的地址赋给类成员。这使得一个类例如能够处理各种大小的字符串，而无需在设计类时预先承诺固定的数组大小。在类构造函数中使用 new 也能防止对象过期时内存泄漏。如果一个对象具有指向由 new 分配的内存的成员指针，则内存不会自动释放对象指针所指向的内存。因此，如果你在类构造函数中使用 new 分配内存，你应该在类析构函数中自动 delete 以释放内存。这样，对象的消亡就会触发指向内存的删除。

具有由 new 分配的内存的成员指针的对象在初始化一个对象或将一个对象赋给另一个对象时也会出现问题。默认情况下，C++ 使用浅拷贝初始化，这意味着被初始化或被赋值的对象最终会得到原始对象成员的精确副本。如果原始成员指向一块数据，拷贝成员指向同一块数据。当程序最终删除对象时，类析构函数会尝试两次删除同一块内存，这是一个错误。解决方案是定义一个特殊的构造函数来重新定义初始化，并重载赋值运算符。在每种情况下，新定义都应创建指向数据的副本，并且新对象指向这些副本。旧对象和新对象引用的是分开但相同的数据，没有重叠。相同的推理适用于定义赋值运算符。在每种情况下，目标都是进行深拷贝——即复制实际数据而不是仅仅复制指向数据的指针。

当一个对象具有静态存储或外部存储时，该对象的析构函数会在对象停止存在时自动调用。如果你通过使用 new 为对象分配内存并将其地址赋给指针，则当你对该指针应用 delete 时，该对象的析构函数会自动调用。然而，如果你通过使用 placement new 而不是常规 new 为类对象分配存储，你也必须承担通过调用析构函数方法并传入指向对象的指针来显式调用该对象的析构函数的责任。C++ 允许你在类内部放置结构、类和枚举定义。这种嵌套类型具有类作用域，这意味着它们是局部的，不会与在其他地方定义的同名结构、类和枚举冲突。

C++ 为类构造函数提供了一种特殊的语法，可用于初始化数据成员。这种语法由冒号后跟逗号分隔的初始化器列表组成。这放在构造函数参数列表之后、函数体大括号之前。每个初始化器由正在初始化的成员的名称组成，后跟包含初始化值的括号。从概念上讲，这些初始化在对象创建时、在函数体中的任何语句之前进行。语法如下所示：

```
queue(int qs) : qsize(qs), items (0), front (NULL), rear (NULL) { }
```

如果数据成员是非静态 const 成员或引用，则此形式是强制性的，除非 C++11 类内初始化可用于非静态 const 成员。C++11 允许类内初始化（即在类定义中初始化）：

```
class Queue
{
private:
    Node * front = NULL;
    enum (Q_SIZE = 10);
    Node * rear = NULL;
    int items = 0;
    const int qsize = Q_SIZE;
};
```

这等同于使用成员初始化列表。然而，任何构造函数的成员初始化列表都会覆盖相应的类内初始化。

正如你可能注意到的那样，类比简单的 C 风格结构需要更多的谨慎和细节关注。作为回报，它们能做更多的事情。
