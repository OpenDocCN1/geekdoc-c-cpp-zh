
# Introducing Friends

```cpp
int x = 5;
int y = 8;
cout << x << y;
```

C++ reads the output statement from left to right, meaning it is equivalent to the following:

```
(cout << x) << y;
```

The << operator, as defined in iostream, takes an ostream object to its left. Clearly, the expression cout << x satisfies that requirement because cout is an ostream object. But the output statement also requires that the whole expression (cout << x) be a type ostream object because it is to the left of y. Therefore, the ostream class implements the operator<<() function so that it returns a reference to an ostream object. In particular, it returns a reference to the invoking object—cout, and in this case the expression (cout << x) is itself the ostream object, and it can be used to the left of the operator.

You can take the same approach with the friend function. You just revise the operator<<() function so that it returns a reference to an ostream object:

```cpp
ostream & operator<<(ostream & os, const Time &t)
{
    os << t.hours << " hours, " << t.minutes << " minutes";
    return os;
}
```

Note that the return type is ostream &. Recall that this means the function returns a reference to an ostream object. Because a program passes an object reference to the function to begin with, the net effect is that the function's return value is just the object passed to it. That is, the statement

```
cout << trip;
operator<< (cout, trip);
```

And that call returns the cout object. Now so the following statement works:

```cpp
cout << "Trip time: " << trip << " (Tuesday)\n"; // can do
```

Let's break this into separate steps to see how it works. First, the following invokes the particular ostream definition of << that displays a string and returns the then for cout object:

```cpp
cout << "Trip time:
```

So the expression << "Trip time: " displays the string and then is replaced by its return value, cout. This reduces the original statement to the following:

```cpp
cout << trip << "Tuesday)\n";
```

# Chapter 11 Working with Classes

Next, the program uses the Time declaration of << to display the trip values and return the cout object again. This reduces the statement to the following:

```cpp
cout << *(Tuesday)\n";
```

The program finishes by using the ostream definition of << for strings to display the string.

As a point of interest, this version of operator<<() also can be used for file output:

```cpp
#include <fstream>

ofstream fout;
fout.open("savtime.txt");
Time trip(12, 40);
fout << trip;
```

The last statement becomes:

```cpp
operator<< (fout, trip);
```

And as Chapter 8 points out, the properties of class inheritance allow an ostream reference to refer to ostream objects and to ofstream objects.

> Tip
> in general, to overload the << operator to display an object of class c_name, you use a friend function with a definition in this form:

```cpp
ostream& operator<<(ostream & os, const c_name & obj)
{
os << ...; // display object contents
return os;
}
```

# Overloaded Operators: Member Versus Nonmember Functions

For many operators, you have a choice between using member functions or nonmember functions to implement operator overloading. Typically, the nonmember version is a friend function so that it can directly access the private data for a class. For example, consider the addition operator for the Time class. It has this prototype in the Time class declaration:

Instead, the class could use the following prototype:

```cpp
// nonmember version
friend Time operator+(const Time & t1, const Time & t2);
```

The addition operator requires two operands. For the member function version, one is passed implicitly via this pointer and the second is passed explicitly as a function argument. For the friend version, both are passed as arguments.

> Note
> A nonmember version of overloaded operator function requires as many formal parameters as the operator has. A member version of the same operator requires one fewer parameters because one operand is passed implicitly as the invoking object.

Each of these two prototypes matches the expression T2 + T3, where T2 and T3 are type objects. That the compiler can convert the statement

```cpp
T1 = T2 + T3;
```

to either of the following:

```cpp
T1 = T2.operator+(T3);      // member function
T1 = operator+(T2, T3);     // nonmember function
```

Keep in mind that you choose one or the other form when defining a given operator, but not both forms match the expression, defining both forms is an ambiguity error, leading to a compilation error.

Which form, is it best to use? For operators, as mentioned earlier, the member function is the only valid choice. Otherwise, it often does not make difference. Sometimes, depending on the class design, the nonmember version may have advantage, particularly if you have defined type conversions for the class. The section "Conversions and Friends," near the end of this chapter, discusses this situation.
