# Binary Files

When you store data in a file, you store the data in text format or in binary format. Text form means storing everything as text, even numbers. For example, storing the value –2.32416e+07 in text form means storing the 13 characters used to write this number. That requires converting the computer’s internal representation of a floating-point number to character form, and that’s exactly what the << insertion operator does. Binary-format, on the other hand, stores the computer’s internal representation of a value.

# Chapter 17 Input, Output, and Files

That is, instead of storing characters, the computer stores the (typically) 64-bit double representation of the value. For a character, the binary representation is the same as the text representation—the binary representation of the character's ASCII code (or equivalent). For numbers, however, the binary representation is much different from the text representation (see Figure 17.7).

# Binary representation of 0.375

| sign bit | exponent bits | binary fraction bits |
| --- | --- | --- |
| 0 | 01111110 | 1100000000000000000 |

# Text representation of 0.375

| 00110000 | 00101110 | 00110011 | 00101111 | 00110111 |
| --- | --- | --- | --- | --- |
| code for the 0 character | code for the character | code for the 3 character | code for the 7 character | code for the 5 character |

> Figure 17.7 Binary and text representations of a floating-point number.

Each format has advantages. The text format is easy to read. With it, you can use an ordinary editor or word processor to read and edit a text file. You can easily transfer a file from one computer system to another. The binary format is more accurate for numbers because it stores the exact internal representation of a value. There are no conversion errors or round-off errors. Saving data in binary format can be faster because there is no conversion and you may be able to save data in larger chunks. And the binary format takes less space, depending on the nature of the data. Transferring to another system can be a problem, however, if the new system uses a different internal representation for values. Even different compilers on the same system may use different internal representations for structures. In these cases, you (or someone) may have to write a program to translate one data format to another.

Let's look at a more concrete example. Consider the following structure definition and declaration:

```cpp
const int LIM = 20;
struct planet {
    char name[LIM]; // name of planet
    double population; // its population
    double g; // its acceleration of gravity
}
 planet;
```

To save the contents of the structure pl in text form, you can use this:

```cpp
ofstream fout("planets.dat", ios_base::out | ios_base::app);
fout << pl.name << " " << pl.population << " " << pl.g << "\n";
```

Note that you have to provide each structure member explicitly by using the member operator, and you must separate adjacent data for legibility. The structure contains, say, 30 members, this could get tedious.

To save the same information in binary form, you can use this:

```cpp
ofstream fout("planets.dat",
ios_base::out | ios_base::app | ios_base::binary);
fout.write((char*)&pl, sizeof(pl));
```

This code saves the entire structure as a single unit, using the computer's representation of data. You won't be able to read the file as text, but the information will be stored more compactly and precisely as text. And it is certainly easier to type the code. This approach makes two changes:

- It uses a binary file mode.
- It uses the write() member function.

# Binary Files and Text Files

Using binary file mode allows you to save data exactly as it is in memory. This is particularly useful for complex data structures like arrays and structures. However, the binary format is not human-readable and cannot be easily edited with a text editor. To save data in binary format, you use the write() member function. To read data, you use the read() member function. These functions require you to specify the address of the buffer and the number of bytes to read or write.

```cpp
fout.write((char*)&pl, sizeof(pl));
```

To read data from a binary file, you use the read() function:

```cpp
fin.read((char*)&pl, sizeof(pl));
```

This approach is much faster than converting data to text format, but it is important to remember that binary files are not portable between different systems with different architectures. If you need your files to be portable, you should use a text format like XML or JSON.
