The cause is that the implicit copy constructor copies by value. Consider Listing 12.3, for example. The effect, recall, is this:
sailor.str = sport.str;

This does not copy the string; it copies the pointer to the string. That is, after sailor is initialized to str, you wind up with two pointers to the same string. That's a problem when the operator<< function uses the pointer to delete the string. It is a problem when the StringBad destructor frees the memory pointed to by the str pointer. The effect of destroying sailor is:
delete [] sailor.str; // delete the string ditto points to

The sailor.str pointer points to "Spinach Leaves Bowl for Dollars" because it is assigned the value of sports.str, which points to that string. So the delete statement frees the memory occupied by the string "Spinach Leaves Bowl for Dollars".
Next, the effect of destroying sports is:
delete [] sports.str; // effect is undefined

Here, sports.str points to the same memory location that has already been freed by the destructor for sailor, and this is undefined, potentially harmful, behavior. In the case of Listing 12.3, the program produces mangled strings, which is usually a sign of memory misgement.
Another disturbing symptom is attempting to delete the same memory twice can cause the program to abort. Microsoft Visual C++ 2010 (debug mode), for example, displays an error message window "Debug Assertion Failed!", and g++ 4.4.1 on Linux reports "double free or corruption" and others. Others might provide different messages or no message, but the same evil lurks within the programs.

# Fixing the Problem by Defining an Explicit Copy Constructor

The cure for the problems in the class design is to make a deep copy. That is, rather than just copying the address of the string, the copy constructor should duplicate the string and assign the duplicate to the str member. That way, each object gets its own string rather than referring to another object's string. And each of the destructor frees a different string rather than making attempts at freeing the same string.
