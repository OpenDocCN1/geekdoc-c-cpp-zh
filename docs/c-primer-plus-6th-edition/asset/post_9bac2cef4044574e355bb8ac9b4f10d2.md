## Namespaces and the Future

As programmers become more familiar with namespaces, common programming idioms will emerge. Here are some current guidelines:

- Use variables in a namespace instead of global variables.
- Use variables in an unnamed namespace instead of global variables.
- If you develop functions or classes, place them in a namespace

The older-style header files, such as iostream.h, do not use namespaces, but the C++ header file should use the std namespace

- Using the using directive as a temporary means of converting old code to namespace.
- Don't use using directives in header files; for one thing, doing so conceals names are made available. Also the ordering of header files may affect behavior. If you use a using directive, place it after all the preprocessor #

- Preferentially import names by the scope-resolution or using a declaration.
- Preferentially use local scope instead of global scope for using declarations

Bear in mind the main motivation for using namespaces is to simplify large programming projects. For simple, one-file programs, using a using directive is no great sin.

C++ encourages the use of multiple files in developing programs. An organizational strategy is to use a header file to define user types and provide function prototypes for functions to manipulate the user types.You should use a separate source code for the function definitions. Together, the header file and the source file define the user-defined type and how it can be used. main() and other functions using those functions can go into a third file.

C++'s storage schemes determine how long variables remain in memory (storage duration) and what parts of a program have access to them (scope and linkage). Automatic variables are those that are defined within a block, as a function body or a block within the body.They exist and are known when the program executes statements in the block that contains them. Automatic variables may be declared using the storage class register or with no qualifier, in which case the variable is automatically automatic. The register specifier is a hint to the compiler that the variable is heavily used, but that is deprecated in C++11.

Static variables exist for the duration of a program. A variable defined outside any function is known to all functions following its definition (file scope) and is available to other files in the program (external linkage). For another file to use such a variable, that file must declare it using the extern keyword. A variable that is shared across files should have a defining declaration in one file (extern needn't to be used but it can be used if combined with initialization) and reference declarations in the other.
