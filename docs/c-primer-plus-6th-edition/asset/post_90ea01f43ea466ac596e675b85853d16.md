
# EOF Ends Input

Remember when a cin method detects the EOF, it sets a flag in the cin object, indicating the EOF condition. When this flag is set, cin does not read any more input, and further calls to cin have no effect. For file input, this makes sense because you want to. For keyboard input, however, you might use a simulated EOF to terminate a loop but then read more input later. The cin.clear() method clears the EOF flag and lets input proceed again. Chapter 17, "Input, Output, and Files," discusses this further. Keep in mind, however, that in some systems, Ctrl+Z effectively terminates input and output beyond the powers of cin.clear() to restore them.

# Common Idioms for Character Input

The following is the essential design of a loop to read text character at a time until EOF:

```
cin.get(ch); // attempt to read a char
while (cin.fail() == false) // test for EOF
{
    // do stuff
    cin.get(ch); // attempt to read another char
}
```

There are some shortcuts you can take with this code. Chapter 6 introduces the operator, which toggles true to false and vice versa. You can rewrite the while loop to look like this:

```
while (!cin.fail()) // while input has not failed
```

The return value for the cin.get(char) method is cin, an object. However, the istream class provides a function that can convert an istream object such as cin to a bool value; this conversion function is called when cin occurs in a loop where bool is expected, such as in the test condition of a while loop. Furthermore, the bool value for the conversion is true if the last attempted read was successful and false otherwise. This means you can rewrite the while loop like this:

```
while (cin) // while input is successful
```

This is a bit more general than using cin.fail() or !cin.eof() because it detects other possible causes of failure, such as disk failure.

Finally, because the return value of cin.get(char) is cin, you can condense the loop to this format:

```
while (cin.get(ch)) // while input is successful
{
    // do stuff
}
```

Here, cin.get(char) is called once in the test condition indent—once before the loop and at the end of the loop. To evaluate the loop test, the program

### Another Version of cin.get()

Nostalgic C users might yearn for C's I/O functions, getchar() and putchar(). They are available in C++ if you want. You use the stdio.h header file as you would in C (or the more current cio). You can use member functions from the istream and ostream classes that work in the same way. Let's look at that approach.

The cin.get() member function with no arguments returns the next character from the input. That is, use it in this way:

```
ch = cin.get();
```

(Recall that cin.get(ch) returns an object, not the character read.) This function works much the same as C's getchar(), returning the character code as a type int value. Similarly, you can use the cout.put() function (see Chapter 3, "Dealing with Data") to display the character:

```
cout.put(ch);
```

It works like C's putchar(), except that its argument should be type char instead of type.

Note Note

Originally, the put() member had the single prototype put(char). You could pass it to an int argument, which would then be type cast to char. The Standard calls for a single prototype; however, some C++ implementations provide: put(char), put(signed char), and put(unsigned char). Using put() with an int argument in these implementations generates an error message because there is more than one choice for converting the int. An explicit type, such as cin.put(char(ch)), works for int types.

Use cin.get() successfully, you need to know how to handle the EOF condition. When the function returns the EOF, there are no more characters to be returned. cin.get() returns a special value, represented by the symbolic constant EOF. This constant is defined in the istream header file. The EOF value must be different from any valid character value so that the program won't confuse EOF with a regular character. Typically, EOF is defined as the value -1 no character has an ASCII code of -1, but you don't need to know the actual value. You can use EOF in a program. For example, the heart of Listing 5.18 looks like this:

You can use int ch, replace cin.get(char) with cin.get(), replace cout with cout.put(), and replace the cin.fail() test with a test for EOF:

```
int ch;
// for compatibility with EOF value
while (ch != EOF)
{
    cout.put(ch); // cout.put(char(ch)) for some implementations
    ++count;
    ch = cin.get();
}
```

If ch is a character, the loop displays it. If ch is EOF, the loop terminates.

> Tip
You should realize that EOF does not represent a character in the input. Instead, it is a signal that there are no more characters.

There's a subtle but important point about using cin.get() beyond the changes so far. Because EOF returns a value outside the valid character codes, it's possible that it might not be compatible with the char type. For example, on some systems char is unsigned, so char variable could never have the usual EOF value of -1. For this reason, you use cin.get() (with no argument) and test for EOF, you must assign the return value to int instead of type char. Also if you make ch int instead of type char, you might have to do a type cast to char when displaying ch.

Let's analyze the condition:

while (ch = cin.get()) != EOF
The parentheses enclose the subexpression ch = cin.get() cause the program to evaluate that expression. To do the evaluation, the program first has to call the cin.get() function. Next, it assigns the return value to ch. Because the value of an assignment statement is the value of the left operand, the subexpression reduces the value of ch. If this value is EOF, the loop terminates; otherwise, it continues. The test condition needs all parentheses. Suppose you leave some parentheses out:

while (ch = cin.get()) != EOF
The! has higher precedence than =, so the first compares cin.get()'s return value to EOF. A comparison produces a false or true result; that boolean value converted to 0 or 1, and that's the value that gets assigned to ch.

Using cin.get(ch) (with an argument) for input, the other hand, doesn't create any type problems. Remember that the cin.get(char) function doesn't assign a special value to ch at the EOF.
