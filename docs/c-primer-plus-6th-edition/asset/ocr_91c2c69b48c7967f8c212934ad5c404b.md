# Strings 121

The idea of a series of characters stored in consecutive bytes implies that you can store a string in an array of char, with each character in its own array element. Strings provide a convenient way to store text information, such as messages to the user (“Please tell me your Swiss bank account number”) or responses from the user (“You must be joking C-style strings have a special feature: the last of every string is the null character. Character, written \0, is the character with ASCII code 0, and it serves to mark the string's end. Consider the following demonstrations:

```
char dog[8] = {'b', 'e', 'a', 'u', 'x', ' ', '1', '1'}; // not a string!
char cat[8] = {'f', 'a', 't', 'e', 'g', 'a', '\0'}; // a string!
```

Both of these are arrays of char, but only the second is a string. The null character plays a fundamental role in C-style strings. C++ has many functions that handle strings, including those used by count. They work by processing string character-by-character until they reach the null character. If you count to display a nice string like cat in the preceding example, it displays the first seven characters, the null character, and stops. But if you are enough to count to display the dog array from the preceding example, which is not a string, count prints the first letters in the array and then marches through memory byte-by-byte, interpreting each byte as a character to print, until it reaches a null character. Because null characters, which really are bytes set to zero, the memory damage is usually contained quickly; otherwise, you would need to terminate nonzero characters as arrays.

The cat example makes initializing an array to a string look tedious—all single quotes and then having to remember the null character. Don't worry. There is a better way to initialize a character to a string. Just use a quoted string, called a string constant or literal, in the following:

```
char bird[11] = "Mr. Cheeps"; // the the \0 is understood
char fish[8] = "Bubbles"; // let the compiler count
```

Quoted strings always include the terminating null character implicitly, so you don't have to spell it out (see Figure 4.2). Also the various C++ input facilities for reading a string from keyboard into a char array automatically terminate the null character for you. (If, when you run the program in Listing 4.1, you discover that you have to use the keyword static to initialize an array, you may use it with these chars too.)

Of course, you should make sure the array is large enough to hold all the characters of the string, including the null. Initializing a character array with a string constant is one case where it might be safer to let the compiler count the number of elements for you. There is no harm, other than wasted space, in making an array larger than the string. That's functions that work with strings are guaranteed by the location of the null character, not by the size of the array. C++ imposes no limits on the length of a string.
