A using declaration, then, makes a single name available. In contrast, the using directive makes all the names available. A using directive involves preceding a namespace name with the keywords using namespace, and it makes all the names in the namespace available without the use of the scope-resolution operator:

```cpp
using namespace Jack; // make all the names in Jack
```

Placing a directive at the global level makes the namespace names available globally. You've seen this in a few times in this book in the following form:

```cpp
#include <iostream> // places names in namespace std
using namespace std; // make names available globally
```

Placing a directive in a particular function makes the names available just in that function. Here's an example:

```cpp
int main()
{
    using namespace jack; // make names available in vorn()
...}
```

You've seen this form in this book with the std namespace.
One thing to keep in mind about using directives and using declarations is that they increase the possibility of name conflicts. If, you have both namespace jack and jill pal available, and you use the scope-resolution operator, there is no ambiguity:

```cpp
jack::pal = 3;
jill::pal = 10;
```

The variables jack::pal and jill::pal are distinct identifiers for distinct memory locations. However, if you employ using declarations, the situation changes:

```cpp
using jack::pal;
using jill::pal;
pal = 4; // which one? now have a conflict
```

## using Directives Versus using Declarations

Using a using directive to import all the names from a namespace wholesale is not the same as using multiple declarations. It's more like the application of a scope-resolution operator. When you use a using declaration, it is as if the name is declared at the location of the using declaration. If a particular name is already declared in a function, you can't import the name with a using declaration. When you use a using directive, however, name resolution takes place as if you declared the name in the smallest region containing both the declaration and the namespace itself. For the following example, that would be the global namespace:

```cpp
namespace Jill {
    double bucket(double n) { ... }
    double fetch;
    struct Hill { ... };
}
char fetch; // global namespace
int main() {
    using namespace Jill; // import all namespace names
    Hill; // create a type Jill::Hill
    double water = bucket(2); // use Jill::bucket();
    double fetch; // not an error, hides Jill::fetch
    cin >> fetch; // read a value into local fetch
    cin >> fetch; // read a value into global fetch
    cin >> Jill::fetch; // read a value into Jill::fetch
}
```

```cpp
int foam() {
    Hill; // ERROR
    Hill::crest; // valid
}
```

Here, in main(), the name Jill::fetch is placed in the local namespace. It doesn't have local scope, so it doesn't override the global fetch. But locally declared fetch hides Jill::fetch and the global fetch. However, both of the last two variables are available if you use the scope-resolution operator. You might want to compare this example to the preceding one, which uses a using declaration.

One other point of note is that although a using directive in a function treats the namespace as being declared outside the function, it doesn't make those names available to other functions in the file. Hence in the preceding example, foo() function can't use the unqualified identifier.

> Note
> Suppose a namespace and declarative region both define the same name. If you attempt to use a using declaration to bring the namespace name into the declarative region, the two names conflict, and you get an error. If you use a using directive to bring the namespace name into the declarative region, the local version of it hides the namespace version.

Generally speaking, the using declaration is safer to use than a using directive because it shows exactly names you are making. And if the name conflicts with a local name, the compiler lets you know. The using directive adds all names, even ones you might not need. If a local name conflicts, it overrides the namespace version, and you aren't warned. Also the open nature of namespaces means the complete list of names in a namespace might be spread over several locations, making it difficult to know exactly which names you are adding. This is the approach used for most of this book's examples:

```cpp
#include <iostream>
int main()
{
  using namespace std;
}
```

First, the include header file puts everything in the std namespace. Then, the using directive makes the names available within main(). Some examples do this:

```cpp
#include <iostream>
using namespace std;
int main()
{}
```

This exports everything from the std namespace into the global namespace. The main rationale for this approach is expediency. It's easy to do, and if your system doesn't have namespaces, you can replace the first two of the preceding lines with the original form:

```cpp
#include <iostream.h>
using namespace std; // avoid as too indiscriminate
```

Instead, you should use this:

```cpp
int x;
std::cin >> x;
std::cout << x << std::endl;
```

Or you could use this:

```cpp
using std::cin;
using std::cout;
using std::endl;
int x;
cin >> x;
cout << x << endl;
```

You can nest namespaces, as described in the following section, to create a namespace that holds the using declarations you commonly use.

## More Namespace Features

You can nest namespace declarations, like this:

```cpp
namespace elements
    namespace fire
    {
        int flame;
    }
    float water;
}
```

In this case, you refer to the flame variable as elements::fire::flame. Similarly, you can make the inner names available with this using directive:

```cpp
using namespace elements::fire;
```

Also you can use using directives and using declarations inside namespaces, like this:

```cpp
namespace myth
{
    using Jill::fetch;
    using namespace elements;
    using std::cout;
    using std::cin;
}
```

Suppose you want to access Jill::fetch. Because Jill::fetch is now part of the myth namespace, where it can be called fetch, you can access it this way:

```cpp
std::cin >> myth::fetch;
```

## Namespaces

Of course, because it is also part of the Jill namespace, you can still call it Jill::fetch:

```cpp
std::cout << Jill::fetch; // display value into myth::fetch
```

Or you can do this, provided that no local variables conflict:

```cpp
using namespace myth;
cin >> fetch; // really std::cin and Jill::fetch
```

Now consider applying a using directive to the myth namespace. The using directive is transitive. We say that an operation is transitive if A op B and B op C implies A op C. For example, the > operator is transitive. (That is, A bigger than B and B than C implies A bigger than C.) In this context, the upshot is that the following statement places both the myth and the elements in namespace:

```cpp
using namespace myth;
```

This directive has the same effect as the following two:

```cpp
using namespace myth;
using namespace elements;
```

You can create an alias for a namespace. For example, suppose you have a namespace defined as follows:

```cpp
namespace my_very_favorite_things { ... };
```

You can make an mft alias for my_very_favorite_things by using the following statement:

```cpp
namespace mft = my_very_favorite_things;
```

You can use this technique to simplify nested namespaces:

```cpp
namespace MEF = myth::elements::fire;
using MEF::flame;
```

## Unnamed Namespaces

You can create an unnamed namespace by omitting the namespace name:

```cpp
namespace // unnamed namespace
{
int ice;
int bandycoot;
}
```

This code behaves as if it were followed by a using directive; that is, the names declared in this namespace are in potential scope until the end of the declarative region that contains the unnamed namespace. In this respect, names in an unnamed namespace are like global variables.
