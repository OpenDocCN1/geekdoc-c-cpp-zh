# Functions and Arrays

So far the sample functions in this book have been simple, using only the basic types for arguments and return values. But functions can be the key to handling more involved types, such as arrays and structures. Let's take a look at how arrays and functions get along each other.

Suppose you use an array to track how many cookies each person has eaten at a family picnic. Each array index corresponds to a person, and the value of the element corresponds to the number of cookies that person has. Now you want the total. That's easy; just use a loop to add all the array elements. By adding elements is a common task that makes sense to design a function to do the job. You won't have to write a new loop every time you want to sum an array.

Let's consider what the function interface involves. Because the function calculates a sum, it should return the answer. If you keep your cookies intact, you can use a function with a type `int` return value. So that the function knows what array to sum, you want to pass the array as an argument. And make the function general so it is not restricted to an array of a particular size, you pass the size of the array. The only new ingredient here is you declare that one of the formal arguments is an array name. Let's see what that and the rest of the function header look like:

```cpp
int sum_arr(int arr[], int n) // array name, n = size
```

This looks plausible. The brackets seem to indicate that arr is an array, and the fact that the brackets are empty indicate that you can use the function with any size. But things are not always as they seem: arr is not really an array; it's a pointer! The good news is that you can write the rest of the function as if arr were an array. First, let's use an example to check that this approach works, and then let's look into why

Listing 7.5 illustrates using a pointer as if it were an array name. The program initializes the array to some values and uses the `sum_arr()` to calculate the sum. Note that the `sum_arr()` function uses arr as if it were an array name.

# Listing 7.5 arrfun1.cpp

```cpp
// arrfun1.cpp -- functions with an array argument
#include <iostream>
const int ArSize = 8;
int sum_arr(int arr[], int n); // prototype
int main() {
    using namespace std;
    int cookies[ArSize] = {1,2,4,8,16,32,64,128};
    // some systems requiring preceding int with static to
    // enable array initialization

    int sum = sum_arr(cookies, ArSize);
    cout << "Total cookies eaten: " << sum << "\n";
    return 0;
}

// return the sum of the integer array
int sum_arr(int arr[], int n)
{
    int total = 0;
    for (int i = 0; i < n; i++)
        total = total + arr[i];
    return total;
}
```

Here is the output of the program in Listing 7.5:
Total cookies eaten: 255

As you can see, the program works. Now let's look at why it works.

# How Pointers Enable Array-Processing Functions

The key to program in Listing 7.5 is C++, like C, in most contexts treat the name of an array as if it were a pointer. Recall from Chapter 4, "Compound Types," that C++ interprets an array name as the address of its first element:
`cookies = &cookies[0] // array name is address of first`

(There are a few exceptions to this rule. First, the array declaration uses the array name to label the storage. Second, applying `sizeof` to an array name yields the size of the array in bytes. Third, as mentioned in Chapter 4, applying the address operator `&` to an array name returns the address of the whole array, for example, `&cookies` would be the address of a 32-byte block of memory if `int` is 4 bytes.)

Listing 7.5 makes the following function call:

```cpp
int sum = sum_arr(cookies, ArSize);
```

Here cookies is the name of an array, by C++ rules cookies is the address of the array's first element. The function passes an address. Because the array has `int` elements, cookies must be pointer-to-int, or `int*`. This suggests that the correct function header should be:

```cpp
int sum_arr(int *arr, int n) // arr = array name, n = size
```
