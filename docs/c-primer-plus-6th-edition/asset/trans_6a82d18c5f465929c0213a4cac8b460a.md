## 可变参数模板

可变参数模板提供了一种创建可接受可变数量参数的模板函数和模板类的方法。我们这里来看可变参数模板函数。例如，假设我们想要一个函数，它可以接受任意数量的任意类型参数，前提是该类型可以用 cout 显示，并将参数作为逗号分隔的列表显示。例如，考虑以下代码：

```
int n = 14;
double x = 2.71828;
std::string mr = "Mr. String objects";nshow_list(n, x);
show_list(x*,, '!', 7, mr);
```

目标是以这样的方式定义 show_list()，使这段代码能够编译并产生以下输出：
14, 2.71828
7.38905, 1, 7, Mr. String objects!

为了创建可变参数模板，需要理解几个关键点：

- 模板参数包
- 函数参数包
- 解包
- 递归

### 模板和函数参数包

作为了解参数包如何工作的一个起点，让我们考虑一个简单的模板函数，它只显示一个项目组成的列表：

```
template<typename T>
void show_list0(T value)
{
  std::cout << value << " \ ";
}
```

## 第 18 章 访问新的 C++ 标准

此定义有两个参数列表。模板参数列表只有 T。函数参数列表只有 value。像这样的函数调用将模板参数列表中的 T 设为 double，并将参数列表中的 value 设为 2:15。

```
show_list(2:15);
C++11 提供了省略号元操作符，使你能够为模板参数包声明一个标识符，本质上是一个类型列表。同样，它让你为函数参数包声明一个标识符，本质上是一个值列表。语法如下所示：
template<typename... Args> // Args 是模板参数包
void show_list1(Args... args) // args 是函数参数包
{}
```

Args 是模板参数包，args 是函数参数包。（与其它参数名一样，任何满足 C++ 标识符规则的名称都可用于这些包。）Args 与 T 的区别在于 T 匹配单个类型，而 Args 匹配任意数量的类型，包括零个。考虑以下函数调用：

```
show_list1('S', 80, "sweet", 4,5);
```

在此参数包 Args 中包含与函数调用中的参数匹配的类型：char、int、const char * 和 double。
接下来，就像

```
void show_list0(T value)
声明 value 的类型为 T，行
void show_list1(Args... args) // args 是函数参数包
```

args 的类型为 Args。更准确地说，这意味着函数包 args 包含的值列表与模板包 Args 中的类型列表在类型和数量上都匹配。在此例中，args 包含值 'S'、80、"sweet" 和 4.5。

以这种方式，show_list1() 可变参数模板可以匹配以下任意函数调用：

```
show_list1();
show_list1(99);
show_list1(88.5, "cat");
show_list1(2,4,6,8, "who do we", std::string("appreciate"));
);
```

在最后一种情况中，Args 参数包将包含类型 int、int、int、const char * 和 std::string；args 函数参数包将包含匹配的值 2、4、6、8、"who do we" 和 std::string("appreciate")

### 解包参数包

但函数如何访问这些包的内容呢？没有索引功能。也就是说，你不能使用类似 Args [2] 这样的东西来访问包中的第三个类型。

## 可变参数模板 1199

相反，你可以通过将省略号放在函数参数名右侧来解包。 例如，考虑以下有缺陷的代码：

```
template<typename...> Args> // Args 是模板参数包
void show_list1(Args... args) // args 是函数参数包
{
    show_list1(args...); // 将解包后的 args 传递给 show_list1()
}
```

这是什么意思，为什么它有缺陷？假设我们有这个函数调用：
show_list1(5, 'L', 0.5);

调用将值 5、'L' 和 0.5 打包到 args 中。在函数内部，调用
show_list1(args...);

展开为以下内容：
show_list1(5, 'L', 0.5);

也就是说，单个实体 args 被替换为包中存储的三个值。因此，记号 args... 展开为一组离散的函数参数。不幸的是，新的调用也是原始函数调用，因此它将再次以参数调用自身，引发无限且徒劳的递归（这就是缺陷）。

### 在可变参数模板函数中使用递归

尽管递归使 show_list1() 的抱负成为无用的函数，但适当的递归提供了解决访问列表中项目的方法。中心思想是解包函数参数包，处理列表中的第一个项目，然后将剩余列表传递给递归调用，依此类推，直到列表为空。重要的是要确保有一个终止递归的调用。技巧的一部分涉及将模板头改为：

```
template<typename T, typename... Args>
void show_list3(T value, Args... args)
```

使用此定义，show_list3() 的第一个参数被作为类型 T 拾取并赋给 value。剩余参数被 Args 和 args 拾取。这允许函数对 value 做一些事情，正如我们显示它一样。剩余参数以 args... 的形式可以传递给 show_list3() 的递归调用。每次递归调用都会打印一个值并将缩短的列表传递下去，直到列表耗尽。

列表 18.9 展示了一个实现，虽然不完美，但说明了该技术。

列表 18.9 variadic1.cpp

```
//variadic1.cpp -- using recursion to unpack a parameter pack
#include <iostream>
#include <string>

// definition for 0 parameters -- terminating call
void show_list3() {

// definition for 1 or more parameters
template<typename T, typename... Args>
void show_list3( T value, Args... args) {
    std::cout << value << " ,";
    show_list3(args...);
}

int main() {
    int n = 14;
    double x = 2.71828;
    std::string mr = "Mr. String objects!";
    show_list3(n, x);
    show_list3(x*x, '!\', 7, mr);
    return 0;
}
```

### 程序说明

考虑此函数调用：
show_list3(x*x, '!\', 7, mr);

第一个参数将 T 匹配为 double 并将 value 设为 x*x。剩余的三种类型（char、int、std::string）被放入 Args 包中，剩余的三个值（'!'、7、mr）被放入 Args 包中。

接下来，show_list3() 函数使用 cout 显示 value（大约 7.38905）和字符串 "。这处理了显示列表中的第一项。

接下来是此调用：
show_list3(args...);

这，鉴于 args... 的展开，与以下内容相同：
show_list3('!\', 7, mr);

正如所承诺的，列表被缩短了一项。这次 T 和 value 变为 char 和 '!'，剩余的两种类型和值分别打包到 Args 和 args 中。下一个递归调用处理这些缩减的包。最后，当 args 为空时，参数为零的 show_list3() 版本被调用，过程终止。

以下是列表 18.5 中两个函数调用的输出：

14, 2.71828, 7.38905, '!', 7, Mr. String objects!

## 可变参数模板 1201

### 改进

我们可以用两个改动改进 show_list3()。目前，函数在列表中的每个项目后都显示一个逗号，但最好省略最后一个项目后的逗号。这可以通过添加仅一个项目的模板并使其行为与通用模板略有不同来实现：

```
// definition for 1 parameter
template<typename T>
void show_list3(T value)
{
    std::cout << value << '\n';
}
```

因此，当 args 减少到一个项目时，此版本被调用，并打印换行符而不是逗号。由于它没有对 show_list3() 的递归调用，因此它也终止了递归。

第二个改进领域是当前版本按值传递所有内容。对于我们使用过的简单类型来说这没问题，但对于 cout 可打印的大型类来说效率低下。最好使用 const 引用。使用可变参数模板，你可以在解包上施加一个模式。不要使用

```
show_list3(Args... args);
```

你可以使用这个：

```
show_list3(const Args&... args);
```

这将导致每个函数参数都应用 const& 模式。因此，而不是 std::string mr，最终参数的节省变为 const
