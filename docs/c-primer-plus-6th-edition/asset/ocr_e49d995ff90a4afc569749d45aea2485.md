The functions in this section determine the order of two elements using the < operator for the elements or by using a comparison operator designated by the template type. If comp is an object of type Compare, then comp(a,b) is a generalization of a < b and returns true if a precedes b in the ordering scheme. If a < b is false and b < a is also false, a and b are equivalent. A comparison object must provide at least strict ordering. This means the following:

+   - The expression comp(a,a) must be false,a generalization of the fact that a value can't be itself.(This is the strict part)
- If comp(a,b) is true and comp(b,c) is true, then comp(a,c) is true (that, comparison is a transitive relationship).
- If a is equivalent to b and b is equivalent to c, then a is equivalent to c (that, equivalence is a transitive relationship).

If you think of applying < to integers, then equivalence implies equality, but this doesn't have to hold for more general cases. For example, you could define a structure with several members describing a mailing address and define a compare object that orders them according to zip code. Then two addresses with the same zip code would be equal but not equal.
