The program sets a short variable (sam) and an unsigned short variable (sue) to the largest short value, which is 32,767 on our system. It adds 1 to each value. This causes problems for sue because the new value is still much less than the maximum value for an unsigned integer. But sam goes from 32,767 to -32,768. Similarly, subtracting 1 from 0 creates no problems for sam, but it makes the unsigned variable go from 0 to 65,535. As you can see, these integers behave much like an odometer. If you go past the limit, the values just start at the other end of the range (see Figure 3.1). C++ guarantees that unsigned types behave in this fashion. However, C++ does not guarantee that signed integer types can exceed their limits (overflow and underflow) without complaint, but that is the most common behavior in implementations.

### Choosing an Integer Type

With the richness of C++ integer types, which should you use? Generally, int is set to the most "natural" integer size for the target computer. Natural size refers to the integer form that the computer handles most efficiently. If there is no compelling reason to choose another type, you should use int.

Now look at reasons why you might use another type. If a variable represents something is never negative, such as the number of words in a document, you can use an unsigned type; that way the variable can represent higher values.

If you know that the variable might have to represent integer values too great for a 16-bit integer, you should use long. This is true even if int is 32 bits on your system. That way, if you transfer your program to a system with a 16-bit int, your program won't embarrass you by suddenly failing to work properly (see Figure 3.2). And if a mere billion is inadequate for your needs, you can move up to long long.

```
// myprofit.cpp

long also = 560334;

out << also << "\n";
```

Using short can conserve memory if short is smaller than int. Most typically, this is important only if you have a large array of integers. (An array is a data structure that stores several values of the same type sequentially in memory.) If it is important to conserve space, you should use short instead of int, even if they are the same size. Suppose, for example, that you move your program from a 16-bit system to a 32-bit int system. That doubles the amount of memory needed to hold an int array, but it doesn't affect the requirements for a short array. Remember, a bit saved is earned.

If you need only a single byte, you can use char. We will examine that possibility soon.

### Integer Literals

An integer literal, or constant, is one you write out explicitly, such as 212 or 1776. C++, like C, lets you write integers in three different number bases: base 10 (the public favorite), base 8 (the Unix favorite), and base 16 (the hardware hacker's). Appendix A, "Number Bases," describes these bases; here we will look at the C++ representations. C++ uses the first digit or two to identify the base of a number constant. If the first digit is in range 1–9, the number is 10 (decimal); thus 9 is 10. If the first digit is 0 or 0A, the number is in the range 1–7 (octal); thus 8 is octal. 042 is octal and 0xA (hexadecimal); thus the first two characters are 0x or 0X, the base is 16. The characters a–f and A–F represent the hexadecimal digits corresponding to the values 10–15. 01F is 15 and 0xA5 is 65 (sixteen plus five). Listing 3.3 is tailor-made to show the three bases.

### Listing 3.3 hexoct1.cpp

```
// hexoct1.cpp -- shows hex and octal literals
#include <iostream>
int main() {
    using namespace std;
    int chest = 42; // decimal integer literal
    int waist = 0xa2; // hexadecimal integer literal
    int inseam = 042; // octal integer literal

    cout << "Monsieur cuts a striking figure!\n";
    cout << "chest = " << chest << " (42 in decimal)\
";
    cout << "waist = " << waist << " (0xa2 in hex)\
";
    cout << "inseam = " << inseam << " (042 in octal)\
";
    return 0;
}
```

By default, cout displays integers in decimal format, regardless of how they are written in a program, as the following output:

Monsieur cuts a striking figure!
chest = 42 (42 in decimal)
waist = 66 (0xa2 in hex)
inseam = 34 (042 in octal)

Keep in mind that these notations are merely nominal conveniences. For example, if you belong to a vintage PC club and read that the CGA memory system is B000 in hexadecimal, you don't have to convert the value to base 10 45,056 before using it in your program. Instead, you can simply use 0xB000. But whether you write the value as 10, 012, or 0xA, it's stored in the computer—as a binary (base 2) value.

### How C++ Decides What Type a Constant Is

A program's declarations tell the C++ compiler compile the type of a particular integer variable. But what about constants? That is, suppose you represent a number with a constant in a program:

```
cout << "Year = " << 1492 << "\n";
```

Does the program store 1492 as an int, long, or some other type? The answer is that C++ stores integer constants as int unless there is a reason to do otherwise. Two such reasons are you use a special suffix to indicate a particular type or if a value is too large to be an int.

First, look at the suffixes. These are letters placed at the end of a numeric constant to indicate the type. An l or L suffix on an integer means the integer is a long constant, a u or U suffix indicates an unsigned int, and ul or UL (in any combination of uppercase and lowercase) indicates an unsigned long. (Because a lower case l can look much like the digit, you should use the uppercase L). For example, on a system using a 16-bit int and a 32-bit long, the number 22022 is stored in 16 bits as an int. Similarly, 22022LU and 22022UL are unsigned long. C++ provides the LL and U suffixes for long, and ULL for unsigned long.

Next, look at size. C++ has slightly different rules for decimal integers than for hexadecimal and octal integers. (Here decimal base 10, as hexadecimal base 16; the term decimal does not necessarily imply a decimal point.) A decimal integer without a suffix is represented by the smallest of the types that can hold it: int, long, or long long. On a computer system using a 16-bit int and a 32-bit long, 20000 is represented as type int, 40000 is represented as long, and a hexadecimal or octal integer without a suffix is represented by the smallest of the types that can hold it: unsigned int, unsigned long, unsigned long long, or unsigned long long. The same computer system that represents 40000 as long long represents the hexadecimal value 0x9C40 as an unsigned int. That's hexadecimal is frequently used to express memory addresses, which are intrinsically unsigned. So unsigned int is more appropriate than long for a 16-bit address.

### The char type: Characters and Small Integers

It is time to turn to the final integer type: char. As you probably know from its name, the char type is designed to store characters, such as letters and numeric digits. Whereas storing numbers is no big deal for characters, storing letters is another matter. Programming languages take the easy way out by using number codes for letters. The char type is another integer type. It is guaranteed to be large enough to represent the range of basic symbols—all the letters, digits, punctuation, and the like—the target computer system. In practice, many systems support more than 128 kinds of characters, so a single byte can represent the whole range. Although char is most used to handle characters, you can also use it as an integer type that is typically smaller than short.
