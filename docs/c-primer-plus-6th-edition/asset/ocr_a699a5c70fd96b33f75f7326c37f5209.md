Does the simpler interface that vararray provides translate better performance? In most cases, no. The simple notation is typically implemented with the same sort of loops you would use with ordinary arrays. However, some designs allow vector operations in which the values are in an array loaded simultaneously into an array of registers and then processed simultaneously. In principle, vararray operations could be implemented to take advantage of such designs.

Can you use the STL with vararray objects? Answering this provides a quick review of some STL primitives. Suppose you have a vararray<double> object that has 10 elements:

```
vararray<double> vad(10);
```

After the array has filled with numbers, you can say, use the STL sort function on it? The vararray class doesn't have begin() and end() methods, so you can't use them as the arguments:

```
sort(vad.begin(), vad.end()); // NO, no begin(), end()
```

Also vad is an object, not a pointer, so you can't imitate ordinary array usage and vide vad + 10, as the following code attempts to:

```
sort(vad, vad + 10); // NO, no vad an object, not an address
```

You can use the array operator:

```
sort(&vad[0], &vad[10]); // maybe?
```

But the behavior of using one pass past the end is undefined for vararray. It doesn't necessarily mean using &vad[10] won't work.(In fact, it did work for all six compilers to test this.) But it means that it might not work. For the code to fail, you would probably need a very unlikely circumstance, such as the array being against the end of the block of memory set aside for the heap. But if a $385-million depends on your code, you might not want to risk that failure.

C++11 remedies the situation by providing begin() and end() template functions that take a vararray object as an argument. So you use begin(vad) instead of vad.begin().These return values are compatible with STL range requirements

```
sort(begin(vad), end(vad)); // C++11 fix
```
