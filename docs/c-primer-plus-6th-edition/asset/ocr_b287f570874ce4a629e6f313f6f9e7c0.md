A class is a user-defined type, and an object is an instance of a class. This means an object is a variable of type or the equivalent of a variable, such as memory allocated by new according to the class specification. C++ tries to make user-defined types as similar as standard types, so you declare objects, pointers to objects, and arrays of objects. You can pass objects as arguments, return them as function values, and assign one object to another of the same type. If you provide a constructor method, you can initialize objects when they are created. If you provide a destructor method, the program executes it when the object expires.

Each object holds its own copy of the data of a class declaration, but they share the methods. If mr_object is the name of a particular object and try_me() is a member function, you invoke the member function using the dot membership operator: mr_object.try_me(). OOP terminology describes this function as sending a try_me message which then applies to the data members of the mr_object object. Any reference to class members in the try_me() method then applies to the data members of the mr_object object. Similarly, the function call i_try_me() accesses the data members of the i_object object.

If you want an object to act on more than one object, you can pass additional objects as arguments. If a method needs to refer explicitly to the object it evoked, it can use this pointer. This pointer is set to the address of the evoking object, so this is an alias for the object itself.

Classes are well matched to describing ADTs. The public member function interface provides services described by an ADT, and the class's private section and the code for the class methods provide an implementation that is hidden from clients of the class.
