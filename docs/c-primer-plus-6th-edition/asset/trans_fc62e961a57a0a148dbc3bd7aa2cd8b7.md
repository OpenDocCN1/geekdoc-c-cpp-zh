
// definition for 2 or more parameters
template<typename T, typename... Args>
void show_list(const T& value, const Args&... args)
{
    std::cout << value << " ,";
    show_list(args...);
}

int main()
{
    int n = 14;
    double x = 2.71828;
    std::string mr = "Mr. String objects!";
    show_list(n, x);
    show_list(x*x, '!', 7, mr);

}

## More C++11 Features

C++11 在本书所能涵盖的范围之外添加了更多特性，甚至忽略了在本书撰写时其中许多特性尚未得到广泛实现这一事实。尽管如此，快速了解其中一些特性的本质仍然值得。

### Concurrent Programming

如今，通过增加处理器来提升计算机性能比提高处理器速度更容易。具有双核或四核处理器，甚至多个多核处理器的计算机已成为常态。这使得计算机能够同时运行多个执行线程。一个处理器可能处理视频下载，而另一个处理器处理电子表格。

某些活动可以从多线程中受益，而另一些则不能。考虑在单链表中搜索。程序必须从开头开始并按顺序跟随链接到列表末尾；第二个线程几乎帮不上什么忙。现在考虑一个未排序的数组。利用数组的随机访问特性，你可以让一个线程从数组开头开始...

多线程确实会带来问题。如果一个线程挂起或两个线程同时尝试访问相同数据会怎样？C++11 通过

定义支持线程执行的内存模型，通过添加 thread_local 关键字，并提供库支持来解决并发问题。thread_local 关键字用于声明相对于特定线程具有静态存储期的变量；也就是说，在其定义的线程中过期。

库支持包括原子操作库，指定 atomic 头文件，以及线程支持库，指定 thread、mutex、condition_variable 和其他 future 文件。

### Library Additions

C++11 添加了多个专业库。一个可扩展的随机数库，由 random 头文件支持，提供比 rand() 更广泛、更复杂的数字设施。例如，它提供随机数生成器的选择和分布的选择，包括均匀分布（如 rand()）、二项式、正态等。

chrono 头文件支持处理时间持续时间的方式。

tuple 头文件支持 tuple 模板。tuple 对象是对 pair 对象的推广。pair 对象可以保存类型不必相同的数值，而 tuple 可以保存任意数量不同类型项。

编译时有理数算术库，由 ratio 头文件支持，允许精确表示任何分母可以用最宽整数类型表示的有理数。它还为这些数字提供算术运算。

其中一个最有趣的补充是正则表达式库，由 regex 头文件支持。正则表达式匹配可用于匹配文本字符串中字符的模式。例如，括号匹配单个 c、k 或 K，而 [eckK] 匹配单词 Cat、cat 和 Rat。其他模式包括 \d 表示数字，\w 表示单词，\t 表示制表符，还有许多其他。反斜杠在 C++ 中作为转义序列的第一个字符具有特殊含义这一事实意味着像 \d\t\w（即数字-制表符-单词-数字）这样的模式需要写成字符串字面量 "\\d\\t\\w"，使用 \\ 表示 \。这就是引入 string 的原因之一（第 4 章）；它允许你将相同模式写为 R"\d\t\w"。

Unix 实用程序如 ed、grep 和 awk 使用了正则表达式，而解释型 Perl 语言对其进行了扩展。C++11 正则表达式库允许你从多种正则表达式风格中选择。

### Low-Level Programming

“低级”中的“低级”指的是抽象级别，而不是编程质量。低级意味着更接近计算机硬件的字节和位以及机器语言。低级编程对于嵌入式编程和某些操作的效率很重要。C++11 为从事低级编程的人提供了一些帮助。

## Chapter 18 Visiting with the New C++ Standard

一个变化是放宽了被视为“Plain Old Data”，即 POD 的限制。在 C++98 中，POD 是标量类型（单值类型，如 int 或 double）或没有构造函数、基类、私有数据、虚函数等的老式结构。POD 是可以安全地进行字节到字节复制的东西这一想法仍然存在，但 C++11 认识到可以取消一些 C++98 限制而仍然拥有可行的 POD。这有助于低级编程，因为一些低级操作，例如使用 C 函数进行按字节复制或二进制 I/O，需要 POD。

另一个变化是使联合更灵活，允许它们具有构造函数和析构函数，但对其他属性有一些限制，例如不允许虚函数。联合通常在尽量减少内存使用时使用，新的规则允许程序员为这些情况带来更多灵活性和能力。

C++11 解决了内存对齐问题。计算机系统可以限制数据在内存中的存储方式。例如，一个系统可能要求 double 值存储在偶数内存位置，而另一个可能要求存储从八的倍数位置开始。alignof 运算符（参见附录 E，“其他运算符”）提供类型或对象的对齐要求信息。alignas 关键字指定对使用的对齐的控制。constexpr 机制扩展了编译器在编译时求值为常量值的表达式的求值能力。其低级方面允许 const 变量存储在只读内存中，这在嵌入式编程中特别有用。（在运行时初始化的变量，无论是否 const，都存储在随机访问内存中）。

### Miscellaneous

C++11 遵循 C99 的做法，允许实现相关的扩展整数类型。这些类型例如可以在具有 128 位整数的系统上使用。扩展类型在 C 头文件 stdint.h 中得到支持，并在 C++11 版本 cstdint 中得到支持。

C++11 提供了一种机制，字面量运算符，用于创建用户定义字面量。使用此机制，例如，可以定义二进制字面量，如 101001b，对应的字面量运算符会将其转换为整数值。

C++11 有一个调试工具叫做 assert。它是一个宏，在运行时检查断言是否为假，如果断言为假则显示消息并调用 abort()。断言通常是程序员认为在程序该点应为真的东西。C++11 添加了 static_assert，可用于在编译时测试断言。主要动机是使调试模板更容易，因为模板的实例化发生在编译时，而不是运行时。

C++11 为元编程提供了更多支持，元编程是创建或修改其他程序甚至它们自身的程序。在 C++ 中，这可以在编译时使用模板完成。

### Language Change

计算机语言如何成长和演变？在 C++ 使用变得足够广泛之后，对国际标准的需求变得清晰，语言的控制基本上移交给了标准委员会——首先是 ANSI 委员会，目前是 ISO/IEC JTC1/SC22/WG21（C++ 标准委员会）。ISO 是国际标准化组织，IEC 是国际电工委员会，JTC1 是前述组织的联合技术委员会 1，SC22 是 JTC1 的编程语言委员会，WG21 是 SC22 的 C++ 工作组。

委员会考虑语言变更和扩展的报告和提案，并试图达成共识。这既不是快速的过程也不是简单的过程。C++ 的设计与演进（Stroustrup，Addison-Wesley，1994）对此提供了一些见解。无论如何，寻求共识委员会的可能存在争议且缓慢的动态并不是鼓励大量创新蓬勃发展的最佳方式。

但在 C++ 中存在第二条变革途径：C 编程社区的直接行动。程序员不能独立更改语言，但他们可以创建有用的库。设计良好的库可以扩展语言的用途和多功能性，提高可靠性，并使编程更愉快。基于语言现有特性构建的库，因此不需要任何额外的编译器支持。如果它们是通过模板实现的，它们可以以头文件的形式作为文本文件分发。

这一变化的一个例子是 STL，主要由 Alexander Stepanov 创建，并由 Hewlett-Packard 免费提供。其在编程社区的成功使其成为第一个 ANSI/ISO 标准的候选。事实上，其设计影响了新兴标准的其他方面。

### The Boost Project

最近，Boost 库已成为 C++ 编程的重要组成部分，并对 C++ 产生了重大影响。Boost 项目始于 1998 年，当时 C++ 库工作组主席 Beman Dawes 将该组的另外两名成员召集在一起，并制定了在标准委员会限制之外开发新库的计划。基本思路是提供一个网站作为人们发布免费 C++ 库的论坛。该项目为许可和编程实践提供指导，并要求对拟议的库进行同行评审。结果是一组备受赞誉且使用广泛的库。该项目为编程社区提供了一个测试和评估编程思想并提供反馈的环境。

Boost 在撰写本文时拥有超过 100 个库，可以作为一套从 www.boost.org 下载，以及文档。大多数库可以通过包含适当的头文件来使用。
