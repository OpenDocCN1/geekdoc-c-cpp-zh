Table 16.8 merits a comment or two. First, notice that a[n] and a.at(n) both return a reference to the nth element (numbering from 0) in a container. The difference between the two is a.at(n) does bounds checking and throws an out_of_range exception if n is outside the valid range for the container. Next, you might wonder why push_front() is defined for list and deque but not for vector. Suppose you want to insert a new value at the front of a vector of 100 elements. To make room, you would move element 99 to position 100, and then move element 98 to 99, and so on. This is an operation with linear-time complexity moving 100 elements would take 100 times as long as moving a single element. But the operations in Table 16.8 are supposed to be implemented only if they can be performed with constant-time complexity. The design for lists and double-ended queues allows element to be added to the front without moving the other elements to new locations, so they can implement push_front() with constant-time complexity. # vector

You've already seen several examples using the vector template, which is declared in the vector header file. In brief, vector is a representation of an array. The class provides automatic memory management that allows the size of a vector to grow dynamically, growing and shrinking as elements are added or removed. It provides random access to elements. Elements can be added to or removed from the end in constant time, but insertion and removal from the beginning and the middle are linear-time operations.
