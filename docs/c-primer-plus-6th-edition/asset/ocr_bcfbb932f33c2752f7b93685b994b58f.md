The main point to this exercise is class friendship is a natural idiom in which to express some relationships.Without some of friendship, you would either have to make the awkward parts of the Tv class public or construct some awkward, larger class that encompasses both a television and a remote control. And that solution wouldn’t reflect the fact that a single remote control can be used with several televisions.

# Friend Member Functions

Looking at the code for the last example, you may notice that most of the Remote methods are implemented by using the public interface for the Tv class. This means that those methods don't really need friend status. The only Remote method that accesses a private Tv member directly is Remote::set_chan(),so that's the only method that needs to be friend. You have the option of making just selected class friends to another class rather making the entry bit awkward. You need to be careful about the order in which you arrange the various declarations and definitions. Lets look at how

The way to make Remote::set_chan() a friend of the Tv class is to declare it as a friend in the Tv class declaration:

```
class Tv
{
    friend void Remote::set_chan(Tv & t, int c);
    ...
n};
```
