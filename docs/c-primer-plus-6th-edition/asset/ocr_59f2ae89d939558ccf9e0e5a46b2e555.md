# Multiple Representations and Classes

Quantities that have different, but equivalent, representations are common. For example, you can measure gasoline consumption in miles per gallon, as done in the United States, or in liters per 100 kilometers, as done in Europe. You can represent a number in string form or numeric form, and you can represent intelligence as an IQ or in kitourkeys. Classes themselves nicely encompassing differing aspects and representations of a single object. First, you can store multiple representations in one object. Second, you can write the class functions that assigning values for one representation automatically assigns values for the other representation(s). For example, the set_by_polar() method for the Vector class sets the mag and members to the function arguments, but it also sets the x and y members. You can store a simple representation and use methods to make other representations available. By handling conversions internally, a class can help you think of a quantity in terms of its essential nature rather than in terms of its representation.

# Overloading Arithmetic Operators for the Vector Class

Adding two vectors is very simple when you use your y coordinates. You just add the two x components to get the x component of the answer and add the two y components to get the y component of the answer. From this description, you might be tempted to use this code:

```
Vector::operator+(const Vector & b) const
{
Vector sum;
sum.x = x + b.x;
sum.y = y + b.y;

return sum; // incomplete version
}
```

And this would be if the object failed to store only the x and y components. Unfortunately, this version of the code could fix this problem by adding more code:

```
Vector::operator+(const Vector & b) const
{
Vector sum;
sum.x = x + b.x;
sum.y = y + b.y;
sum.set_ang(sum.x, sum.y);
}
```
