# Changes to auto in C++11

In C++11, the `auto` keyword is used for automatic deduction, as you have seen in Chapters 3, 7, and 8. In C and prior versions of C++, `auto` has an entirely different meaning. It's used to explicitly identify a variable as having automatic storage:

```
int froob(int n)
{
    auto float ford;   // ford has automatic storage
    ...
}
```

Because programmers can use the `auto` keyword with variables that are already automatic by default, they rarely bother it. Its main function is to document that you really wanted to use a local automatic variable.

In C++11, this usage no longer is valid. The people who prepare standards are reluctant to introduce new keywords because so might invalidate existing code that already uses auto for other purposes. In this case, it was felt that the old use of auto was enough that it was better to repurpose this keyword rather than introduce a new one.

# Initialization of Automatic Variables

You can initialize an variable with any expression value will be known when the declaration is reached. The following example shows the variables x, big, y, and z being initialized:

```
int w; // value of w is indeterminate
int x = 5; // initialized with a numeric literal
int big = INT_MAX - 1; // initialized with a constant expression
int y = 2 * x; // use previously determined value of x
cin >> w;
int z = 3 * w; // use new value of w
```

You might get a better understanding of automatic variables if you look at how a typical C++ compiler implements them. Because the number of automatic variables grows and shrinks as functions start and terminate, the program has to manage automatic variables as it runs. The usual means is to set aside a section of memory and treat it as a stack for managing the flow and ebb of variables. A stack created new data is figuratively stacked old data (that is, at an adjacent location, not the same location) and removed from the stack when the program is finished with it. The default size of the stack depends on the implementation, a compiler typically provides the option of changing the size. The program keeps track of the stack by using two pointers. One points to the base of the stack, where the memory set aside for the stack begins, and one points to top of the stack, which is the next free memory location. When a function is called, automatic variables are added to the stack, and the pointer to the top points to the next available free space following the variables.
