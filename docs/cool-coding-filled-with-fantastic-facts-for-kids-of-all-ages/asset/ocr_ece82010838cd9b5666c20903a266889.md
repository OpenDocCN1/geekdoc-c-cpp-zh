# Assembly code

Assembly code was invented in the 1950s as a way to make programming somewhat simpler. Now the raw code was replaced by a set of short instructions that were (sort of) English, like move, add, for move, jump for jump and add, for well, add. The language also included things like variable names to hold data. This assembly code could then be automatically turned into machine code for the CPU to run.

> **That's neat!**
> 
> For a long time programmers still used assembly code if their programs needed to be really small and fast, but as other programming languages have advanced, the machine code they automatically generate can often be better than the very best human-written assembly code. Now there are only a few niche cases where it still makes sense for people to write directly in assembly code.

Here’s an example of some assembly code:

```
```asm
loop: add $t1, 1
      bne $t1, $t2, end
      jmp loop
end:  nop
```
```

Assembly code was easier to write than machine code, but it was still slow going, and different for each type of CPU. By the 1970s most programmers were using higher-level languages (so called because they were further up from the CPU than low-level assembly language and machine code) that were more like English. These higher-level languages are then converted into machine code for the CPU to execute.
