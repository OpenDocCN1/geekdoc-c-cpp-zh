# 5.9 FORK AND JOIN

When working with a multitasking embedded system, a common sequence of operations is for a parent process to start and then spawn several child tasks to do the real work. The child tasks complete their jobs and terminate and then the parent class follows.

+   - **fork** of splitting the control flow into two or more flows of control or subtasks is called a fork. Each subtask represents a separate, independent thread of control.
+   - **join** When the subtasks are brought back together or resynchronized, it is called a join.
