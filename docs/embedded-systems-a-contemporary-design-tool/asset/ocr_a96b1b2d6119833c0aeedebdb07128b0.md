That is, one cannot say that the measured values guarantee performance of the system under all circumstances. Any such instruments should be used with caution. # 14.14 MEMORY LOADING

Today, in many applications, the amount of available memory appears to be unlimited. In many cases, however, it is not. At the end of the day, actual amount of memory used may have to be reduced to save weight in such applications as aircraft or spacecraft. Memory may be limited by severe cost constraints, such as those found in very high-volume consumer products such as televisions or the automobile. Instances may arise when one must eliminate parts to reduce power, as is common in portable systems, such as cell phones or the PDA. In such cases, one must optimize the use of what memory is available. As we learned earlier, memory has several different components: code space, data space, and system memory. Recall once again that we optimize a design to focus most of the resources on getting the target application completed. Memory loading is defined as the percentage of usable memory being devoted to that application.

The total memory loading will be the sum of the individual loadings for Instructions, Stack, and RAM. The loading is given by:

```
$M_T = M_I \bullet P_I + M_R \bullet P_R + M_S \bullet P_S$ (14.23)
```

The values $M_i$ reflect the memory loading for each portion of memory. The values $P_i$ represent the percentage of total memory allocated for the program. $M_T$ will be expressed as a percentage.
