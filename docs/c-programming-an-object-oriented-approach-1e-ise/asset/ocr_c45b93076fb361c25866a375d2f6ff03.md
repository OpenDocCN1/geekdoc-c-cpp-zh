# **Some Pitfalls**

When we use an *if* statement for one-way selection, we must look carefully for pitfalls. These errors normally are not caught by the compiler because they are logic errors, not syntactical ones. We compile and run the program, but we find that the result is not correct.

**Using the Assignment Operator Instead of the Equality Operator** A common mistake is to use the assignment operator (=) instead of the equality operator (==). The following shows an example:

```
```java
if (x = 0)        // This statement is always false.
{
  statement;      // The statement is never executed.
}
```
```

Note that in this case the condition is always *false* no matter what the value of x is. The expression changes the value of x to 0 (which we did not intend). The result of the expression is the value of x, which is 0. We have seen that the value of 0 is interpreted as *false* in an expression that needs a Boolean value. This means the statement is never executed.

Similarly, if we have (x = 5) instead of (x == 5), the result is always *true* and the statement is always executed as shown below:

```
```java
if (x = 5)        // This condition is always true.
{
  statement;      // The statement is always executed.
}
```
```

**Forgetting Braces** Another common mistake is to forget the braces when we have more than one statement to be executed:

```
```java
if (x == 0)
  statement1;     // Statement1 is executed if x is equal to 0.
  statement2;     // Statement2 is always executed.
```
