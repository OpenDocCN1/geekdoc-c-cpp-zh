
```cpp
number3 = number1 + number2;
cout << "The sum is " << number3 << endl;
Console::ReadKey();
return 0;
}
```

This program causes a similar error message to be displayed:

```text
1>------ Build started: Project: ErrorHandling, Configuration: Debug Win32 ------
1>  ErrorHandling.cpp
1>ErrorHandling.cpp(14): error C2065: 'number3': undeclared identifier
1>ErrorHandling.cpp(15): error C2065: 'number3': undeclared identifier

```

This time, though, the error message is not the result of leaving out a library but because the program forgot to declare the variable number3. Notice that the error message lists both times the variable was used as errors and not just the first occurrence.

There are more possible syntax errors you can make, of course, but the errors we've just discussed are three of the more common errors you are likely to make. By discussing what the error messages look like, and how to read them, you should now at least be somewhat less intimidated by the new error messages you will encounter in the future.

## Logic Errors

Once your program compiles and runs, any errors that occur will have to be what are called *logic errors*, or errors in the logic of the program. Logic errors are much harder to find than syntax errors because a computer program only does what the programmer tells it to do, and nothing more. A program can't decipher what the programmer meant to do with the code he or she writes; it can only execute the statements as it comes across them.

Logic errors come in all shapes and sizes, so we can only just give you a couple of examples to demonstrate how logic errors differ from syntax errors. The following program displays the last element of an array of numbers:

```cpp
// ErrorHandling.cpp : main project file.

#include "stdafx.h"
using namespace System;

#include <iostream>
using namespace std;

int main(array<System::String ^> ^args)
{
    const int size = 10;
    int numbers[size];
    for(int i = 0; i < size; ++i)
        numbers[i] = i + 1;
    cout << "The last item in the array is: "
         << numbers[size] << endl;
    Console::ReadKey();
    return 0;
}
```

Can you spot the error? If not, what do you think the output should be? Now, run the program to see what the output actually is:

The last item in the array is -1231954775

But you thought the last item should be 10.

If you look carefully at the code, you'll see that the constant size was used in the cout statement and the value of size is 10. However, the upper bound of the array is 9, so the subscript that should have been used to display the last array element is size - 1.

This is an example of a logic error. The program runs correctly but doesn't give the expected output. Usually, the only way to find a logic error is to review your code and look carefully for where you might have gone wrong with your programming.

Here's another example: You have to write a program to find the maximum value in a set of numbers stored in a file. In the line where the variable to store the maximum value is declared, you initialize its value to 0. You run the program and it reports that the maximum value is 0. Huh? After scratching your head for awhile, you go look at the data file and see that all the numbers in the file are negative numbers. Clearly, no value ever passed the test (currentValue > max), when max is equal to 0, so 0 is the maximum value according to the logic of your program.

Finding errors of this type can be as much of an art as it is a science. You have to work through each line of the program carefully, and you must have a thorough understanding of the data your program is working with. Experience is the best teacher for finding errors. The more experience you have, the better you will get. And you will gain experience with errors if you continue to write programs.
