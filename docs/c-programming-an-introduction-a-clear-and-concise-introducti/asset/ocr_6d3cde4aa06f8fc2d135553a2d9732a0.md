don't have to re-declare the data members from the Employee class in the Manager class.

The constructor for the Manager class also takes advantage of inheritance by using the member assignments from the Employee class definition for the employee name and the employee pay. Let's focus just on the constructor to see how it works:

```
Manager(string name, double payRate,
        bool isSalaried)
    : Employee(name, payRate)
{
    salaried = isSalaried;
}
```

The parameter list for the constructor include parameters for all the data members. After the list, though, there is a colon followed by a call to the base class constructor for the Employee class. Think of this like a function call. At this point in the code, the compiler transfers control to the code defined for the Employee class constructor. This is a classic example of code reuse and one of the most important features of inheritance. There is no reason to include the statements:

```
empName = name;
pay = payRate;
```

since we've already written them in the base class.

The rest of the constructor body assigns the last parameter to the new data member of the Manager class, the boolean data member salaried.

The other piece of code that requires explanation is the grossPay() method. Here is the definition again:

```
double grossPay(double hours)
{
    if (salaried)
        return pay;
    else
        return Employee::grossPay(hours);
}
```
