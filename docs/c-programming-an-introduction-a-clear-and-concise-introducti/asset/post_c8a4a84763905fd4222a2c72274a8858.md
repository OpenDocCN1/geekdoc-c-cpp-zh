Attaching Name:: before the method name assures that the compiler will correctly recognize that the method belongs to the Name class and is not just a “regular” function that is not attached to any particular class.

The :: operator is called the scope resolution operator and it requires, in this case, a class name on the left side of the operator and a method name on the right side. Defining the scope like this is necessary because we are defining the methods for the class outside of the class definition and the compiler has to know what these method definitions belong to.

## Developing a List Class

The Name class was a useful first example but it doesn't demonstrate all you can do with a class. Many classes we need to develop will require storing more than one piece of data (like a name) per object. A class that stores a list will demonstrate how to incorporate a data structure into a class design.

### Creating an Abstract Data Type

When developing a class, the first thing you need to do before writing any code is think through the design of the class. You can do this by asking yourself a few questions – what data is going to be stored in the class? What operations need to be performed on the data? It is not a bad idea to write this information down before you start programming.

A class that is sketched out before programming starts is called an *abstract data type*, or *ADT* for short. An ADT will include information such as the name of the class, a list of the members of the class and what data they are storing, and a list of methods of the class and what operation they perform.

If we want to design an ADT for a List class, we have to first decide what we want the class to do. Of course, we want the class to store a collection of items (the list). We want to be able to add items to the list, display the items in the list, erase the list and start over, and show the number of items in the list. There are more things we can do with a list but these operations are enough for this example. (For example, removing items from a list and sorting the list into alphabetical order involve advanced C++ techniques we don’t have room to discuss in this book.)

We also need to decide what data we will store in the class. Since we are building a List class, we need something that will store a collection of data, such as a vector. Another piece of data that might be useful is the number of items in the list, or the count.

An ADT for the List class lists out each member and method of the ADT and describes either what data is stored in the member, or what operation the method is supposed to perform. Here is an ADT for the List class:

ADT Name: List  
ADT Purpose: store related items

### ADT Members

| # | Member | Description |
|---|---|---|
| 1 | Datastore | string vector |
| 2 | numItems | integer |

### ADT Methods

| # | Method | Description |
|---|---|---|
| 1 | Add | add new string item to list |
| 2 | Clear | remove all items from list |
| 3 | Display | write the list as a string |
| 4 | Count | number of items in list |

There may still be some details left out of the ADT description, such as how exactly do we implement the sort method, but the process of writing this information down will help us with the actual programming of the class by focusing our attention on what we know we want the class to do. You’ll notice that when a data type is needed, one is supplied. For example, the vector will be storing strings and the numItems member will be storing integers.

### Developing Code for the List Class

We can now go directly from the ADT for the List class to writing the class's header file. Here it is:

```cpp
#include <iostream>
using namespace std;

class List
{
private:
    vector<string> datastore;
    int numItems;
public:
    List();
    void add(string);
    void clear();
    void display();
    int count();
};
```

The next step is to write the code for the List class source file. Many of the methods for this class are almost identical to the vector method we need to perform that task. For example, the remove() method will call the vector erase() method, so all we're really doing is renaming the vector method to something a little more common for a list operation. Even one of the members of the class, numItems, is really just another name for the vector size() method. In fact, when we need to use numItems we'll assign its value by calling the size() method on the datastore vector. Otherwise, we'd have to keep a running count of items added and removed and doing that in code is prone to errors.

Here is the source file code for the List class:

```cpp
#include "stdafx.h"
using namespace System;
#include "List.h"

List::List()
{
    vector<string> datastore;
    int numItems = 0;
}

void List::add(string item)
{
    datastore.push_back(item);
}

void List::clear()
{
    datastore.clear();
}
```
