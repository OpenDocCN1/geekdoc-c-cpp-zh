
```cpp
// Swap.cpp : main project file.

#include "stdafx.h"

using namespace System;

#include <iostream>
#include <string>
using namespace std;

void swap(string *word1, string *word2)
{
        string temp;
        temp = *word1;
        *word1 = *word2;
        *word2 = temp;
}

int main(array<System::String ^> ^args)
{
        string word1, word2;
        word1 = "banana";
        word2 = "apple";
        cout << word1 << " " << word2 << endl;
        swap(&word1, &word2);
        cout << word1 << " " << word2 << endl;
        Console::ReadKey();
        return 0;
}
```

Swapping with pointers works in the same way swapping with references works because we are passing memory addresses to the swap function and not just copies of the values of the variables.

## Pointers and Arrays

Pointers and arrays have a very close relationship in C++. In fact, the relationship is so close that an array name can serve as a pointer into the first element of the array.

First, let's see how we would create a pointer to an array using standard pointer techniques. The following program creates an array of 100 random numbers, displays the first element of the array, initializes a pointer variable to point to the array, and prints the first element of the array via the pointer:

```cpp
// PointersAndArrays.cpp : main project file.

#include "stdafx.h"
using namespace System;

#include <iostream>
#include <cstdlib>
#include <ctime>
using namespace std;

int main(array<System::String ^>^args)
{
        int nums[100];
        srand(time(NULL));
        const int size = 100;
        for(int i = 0; i < size; ++i)
            nums[i] = rand() % 100 + 1;
        cout << nums[0] << endl;
        int *ptrNums;
        ptrNums = &nums[0];
        cout << *ptrNums;
        Console::ReadKey();
        return 0;
}
```

However, since an array name serves as a pointer into the array, we don't need to go to the trouble of creating a pointer variable to the array. We can just use the array name as a pointer:

```cpp
// PointersAndArrays.cpp : main project file.

#include "stdafx.h"
using namespace System;

#include <iostream>
#include <cstdlib>
#include <ctime>
using namespace std;

int main(array<System::String ^> ^args)
{
    int nums[100];
    srand(time(NULL));
    const int size = 100;
    for (int i = 0; i < size; ++i)
        nums[i] = rand() % 100 + 1;
    cout << nums[0] << endl;
    cout << *nums << endl;
    Console::ReadKey();
    return 0;
}
```

The array name is a pointer to the first element of the array. All we have to do is dereference the array name to get access to the first element.

If we want to access the second element of the array using pointer notation, we do it like this:

```cpp
cout << *(nums+1);
```

The use of the parentheses here is very important. The array name by itself is a reference to the first element of the array. If we want the next element, which is in position 1, we need to reference that position by writing `(nums+1)`. However, without the parentheses, we are saying “give me the element in the 0th position of the array and add 1 to it.” Here's a program that demonstrates this:

```cpp
// PointersAndArrays.cpp : main project file.

#include "stdafx.h"
using namespace System;

#include <iostream>
#include <cstdlib>
#include <ctime>
using namespace std;

int main(array<System::String ^> ^args)
{
    int nums[100];
    const int size = 100;
    srand(time(NULL));
    for(int i = 0; i < size; ++i)
        nums[i] = rand() % 100 + 1;
    cout << "The first element: " << *(nums+0) << endl;
    cout << "The second element: " << *(nums+1) << endl;
    cout << "Accessing the second element ";
    cout << " without parentheses: " << *nums+1 << endl;
    Console::ReadKey();
    return 0;
}
```

The output from this program is:

```text
The first element: 95
The second element: 83
Accessing the second element without parentheses: 96
```

We can use pointer notation instead of using subscripts whenever we need to access the elements of an array. The following program demonstrates this technique on the array we used in the earlier examples:

```cpp
// PointersAndArrays.cpp : main project file.

#include "stdafx.h"
using namespace System;

#include <iostream>
#include <cstdlib>
#include <ctime>
using namespace std;

int main(array<System::String ^> ^args)
{
    int nums[100];
    const int size = 100;
    srand(time(NULL));
    for(int i = 0; i < size; ++i)
        nums[i] = rand() % 100 + 1;
    for(int i = 0; i < size; ++i)
        cout << nums[i] << " ";
    Console::ReadKey();
    return 0;
}
```

Accessing arrays using pointer notation instead of subscripts is usually more efficient. However, pointer notation is sometimes harder to read and is mostly avoided except in those circumstances when efficiency is particularly necessary.

Another situation when pointer notation is sometimes used is when large data structures, such as vectors, are used as function arguments. Passing a large data structure as a pointer or a reference is more efficient than passing it by value for the obvious reason that the compiler has to make a copy of the data structure when passing by value, while if passing by pointer or reference the compiler merely passes a memory address to the function.

## Chapter 15: Inheritance and Composition

One of the reasons we use object-oriented programming in C++ is because we want to create our own data types. In the previous chapter we discussed how to build a List data type by creating a class that exhibited the attributes and behaviors of a class. Another reason to use object-oriented programming is to be able to build hierarchies of data types that build off of each other. This is called *inheritance*.

Another way we can use object-oriented programming is to create classes that contain other classes. This is called *composition*. For example, a College class can consist of Faculty classes, Student classes, and Staff classes. This chapter discusses how to build more useful classes using inheritance and composition.

## Inheritance

A class can inherit the members and methods of another class. A class that inherits members and methods is called a derived class. A class that is inherited from is called a base class.

Inheritance is used to describe *is-a* relationships between objects. In other words, a bear is a mammal; a trout is a fish; a novel is a book. These relationships tend to be described in a hierarchical manner. A concrete example will help explain how inheritance works in the abstract.

### An Inheritance Example – Vehicles

The Vehicle class contains information about vehicles. We'll limit our discussion of vehicles to vehicles with wheels. So what are some of the attributes and behaviors of wheeled vehicles? First, they have wheels. Most, but not all, wheeled vehicles have a steering mechanism. Most have an engine and a braking system, though again not all do, and most have some type of seating arrangement. Vehicles have the ability to move, as well as to stop, and to turn.

Now we can start thinking about derived classes from the base class Vehicle. The automobile is derived from the Vehicle class, as is the truck, the bus, and the train, just to mention a few. Each of these has features in common with all vehicles, but each also have features distinctly their own.

Inheritance works by first defining the attributes and behaviors that define all instances of the base class, and then deriving classes from the base class that differ from the base class in some way. You could also say that derived classes can exhibit more specific features of the base class. A wheeled vehicle just has wheels; a car has four wheels and a motorcycle has two wheels (except for those that have three).

The advantage to using inheritance is that when we build a derived class from a base class, we can choose to use the features of the base class in our derived class as is, or we can modify them in some way. We don't have to completely start over with a definition just because the derived class differs in some manner from the base class. This can save us a lot of programming and debugging time, since once a method is written and debugged in the base class, we can use it as-is in the derived class and feel confident that the method works as expected.
