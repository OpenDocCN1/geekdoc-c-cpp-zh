对于基础编程，你知道你可以为两个方法命名相同的名称，但你唯一需要更改的是参数的数量或参数所接收的数据类型。这产生了编译器可以理解的区分。因此，当编译器尝试编译你的代码时，不会返回错误。

# 错误处理

**目标：** 在部署应用程序之前，你需要修复任何 bug。本章侧重于调试以及你在部署给用户和生产环境之前如何测试你的应用程序。

在将应用程序推广到生产服务器或部署给用户之前，测试应用程序始终是首要任务。在实际部署完整版本之前，你仍然可以使用 beta 测试应用程序，但即使如此，你也应该调试你的应用程序。调试的一个部分是通过错误处理。错误处理是一种捕获错误并为用户“处理”它们的方法。这些错误处理事件向用户显示友好的信息，这样你的代码就不会让用户感到沮丧。本章将讨论你如何在代码中管理这种类型的流程。

## 使用 Visual Studio 调试器

如所述，你需要 Visual Studio 代码编辑器来创建和编译 C# 代码。Visual Studio 包含一个调试器，你可以用它来逐行执行代码。与没有良好编程 IDE 的其他语言相比，使用 C# 的优势之一是 C# 允许你逐行执行每一行代码，然后你可以在执行这些行时观察变量的值。

你可以通过 F5 键或调试菜单启动调试器。你可以在代码中设置断点（breakpoints），这些断点可以让程序停下来以查看正在发生什么。例如，假设你的模块中存在错误，你不确定哪个变量导致了问题。

调试器中的变量监视窗口（Watch List）对于这一过程非常重要，因为它让你能够实时查看变量的值。如果没有这个工具，你在执行代码时只能猜测变量的值。监视窗口让你在执行代码时查看变量的值。它是识别变量是否被赋予错误值的绝佳方法由于逻辑错误发生在运行时，这对你的调试过程非常有用。

## C# 中的 Try Catch 语句

对于错误处理，任何 .NET 语言（包括 C# 和 VB.NET）的主要组件都是 `try-catch` 语句。该语句允许你捕获错误并执行一个处理用户错误的友好的函数。你不想为用户创建不友好、混乱的错误。在某些情况下，这些错误会给应用程序带来安全问题。处理不当的错误可能会显示信息，在某些情况下，它们可能会显示用于破解你服务器的密码和用户信息——这些是你不想向互联网公开的。解决此问题的方案是捕获错误并显示友好的信息，告诉用户如何处理错误而不会让他们感到沮丧。

让我们先看看创建 `try-catch` 语句的模板。我们为你创建了一个可以遵循的基础模板。

```csharp
try
{
  // 导致异常的语句
}
catch(ExceptionName e1)
{
  // 错误处理代码
}
catch(ExceptionName e2)
{
  // 错误处理代码
}
catch(ExceptionName eN)
{
  // 错误处理代码
}
finally
{
  // 将执行的语句
}
```

在上面的代码中，我们首先声明 `try` 语句。这表示你正在开始 `try-catch` 语句。

`try-catch` 语句中的每个 `catch` 语句捕获不同类型的错误。如果你不知道应该遇到什么类型的错误，语句的语句可能会很难，但你应该创建捕获任何类型错误的 `catch` 语句。当编译器捕获到这些类型的语句时，它们将进入 `catch` 语句块，这就是你创建处理你遇到的错误的自定义代码的地方。
