For error handling, the main component in any .NET language (including C# and VB.NET) is the try catch statement. This statement lets you trap errors and perform a user-friendly function that handles the errors for your users. You don't want to create unfriendly, messy errors for your users. In some cases, these errors can cause security issues for your application. Poorly handled error messages can display information, and in some cases, they can show passwords and user information that can be used for hacking your server—which you don't want displayed to the Internet public. The solution to this issue is to trap your errors and display a user-friendly message that tells your user how to handle the errors without causing them much frustration.

Let's first look at the template used to create a try catch statement. We have created a basic template for you to follow.

```
try
{
  // statements causing exception
}
catch(ExceptionName e1)
{
  // error handling code
}
catch(ExceptionName e2)
{
  // error handling code
}
catch(ExceptionName eN)
{
  // error handling code
}
finally
{
  // statements to be executed
}
```

In the code above, we first declare the try statement. This indicates that you're starting the try catch statement.

Each catch statement in the try catch statement catches a different type of error. This part of the statement can be tricky if you don't know what type of errors you should expect, but you should create catch statements that trap any type of error.
