## Some Basic Best Practices

Once you install Visual Studio and get your entire environment set up, there are a few best practices to follow before you start programming. They are small standards that most developers work with C#. If you decide to work in the industry, you should know these standards to maintain consistency and to understand code when you're supposed to take over for another coder.

Use StringBuilder instead of strings when building large strings. StringBuilder is a class that we'll learn about in future chapters. It has better performance than a primitive string variable. You'll be tempted to just use a primitive string instead of a StringBuilder, but always use a StringBuilder when working with dynamic strings.

Use verbs to create methods. We'll discuss classes and methods in future chapters, but naming schemes are important when creating your classes and their methods. Methods are given verb names because they perform the actions that either store data or manipulate data. They also take input from users and provide output for your users to.

Class properties should always be nouns. Again, we’ll cover classes and properties in future chapters, but remember that properties should be given noun names. For instance, if a property holds a user’s name, it should be named something like m_name, m_fullname, or _fullname. Notice that a class member property should have some kind of prefix. It should be either m_ or _ as a prefix. This is standard among naming schemes.

Comment on your code often. Remember that someone must come after you and edit your code. This means that you need to comment on your code so that others are able to pick up where you left off. Comments help other coders understand what your code is supposed to do, what type of input it should expect, and if the coder should pay attention to any quirks in the system.

### Data Types

**Objective:** Data types determine the data you can store in your variables. C# has several data types, and this chapter helps you understand them and what you can do with these variables.

When you write a program, you need to tell the operating system what it can expect for each variable set up in the system. The reason you need to define variable data types is that the operating system allocates memory based on the data type. The data type tells the operating system what you will store in a variable, and is required for each variable you define.

## Basic Data Type Syntax

Before we get into specific data types, we should take a look at basic syntax. The following is a basic template for defining a variable.

```
<data type><variable name>;
```

We'll cover several data types that you'll use in your programs, but just for the sake of this section, know that the data type specifier is always the first item in your variable declaration statement.

The next item in your variable declaration statement is the variable name. You can give your variables any name, but usually coding standards define the way you name your variables. For instance, most developers require "camelCase" in variable names. You start the name with a lowercase letter, and then any subsequent words within the variable are capitalized. For you give your variable name "camelCase" instead of "CamelCase" or "camelcase." However, you can name your variables anything you want.

Note that different cases are different variables in C#. In the camelCase example, each variable camelCase, camelcase, and CamelCase are different variables. This follows the C convention of variable naming schemes. You'll notice that C# follows many of the standard C styles.

The final requirement for the statement is the semicolon. The semicolon tells the compiler that the end of the statement has been reached. If you forget the semicolon, the compiler will give you an error.

The final optional rule for variables is that you can define the variable and give it a value at the same time you declare it. Let's take a look at the syntax.

```
datatype variable name = value;
```

Again, assigning a value is optional, but the above syntax is how you assign a value at the same time you declare it. Remember that the value must match the data type. For instance, if you attempt to assign a string character to an integer data type, the compiler will give you an error.

### String Data Type

In any program, you'll work with strings. Strings are the variables that contain words. These words can be any alphanumeric character or even special characters. Most user input data is in the form of a string, but then you can convert that to another data type. For instance, you might ask for a number for user input but then convert the number to an integer to perform some type of calculation using the input.

Let's look at an example at a string variable.

```
string myName = "John";
```

Notice that the string data type is first used to define the string variable. This is a primitive string data type. The data type "String" is a class definition and is only used if you need to perform complex string functions on a variable. For the most part, you will use the primitive string variable definition when you set up your variables.

The next item in the statement is the variable name. We've used camel case, with the first letter in the variable name set in lowercase. The next names use a capital letter.

In this statement, we assign a value to the variable in the definition. We assign the value "John" to the variableName. Notice that the end of the statement terminates with a semicolon. This tells the compiler that the end of the statement has been met. If we forget the semicolon in this statement, the next statement would cause a syntax error.

You can also declare a string variable with no value. We can use the same statement to illustrate how to define variables with no value.

```
string myName;
```
