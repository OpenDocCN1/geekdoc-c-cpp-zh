# Creating Enums

Enums are a bit different than structures, but they are set up in a similar way. Enums can only store integer values. They are useful when you have a list of integer values that you don't want to statically set in several variables. For instance, suppose you want to use a list of days and represent them with integer values from 0 to 6. If you did this without an enum variable, you've have to create variables for each function you call. Instead of creating seven variables every time you need to work with the days of the week, you can create an enum that can be called at any time. The enum also lets you represent these values with friendly names that are more easily recognizable.

Let's take a look at the template syntax for creating an enum.

```
enum enum_name
{
// list of enum variables
}
```

With the enum, you use the enum keyword to indicate that you want to create an enum data type. Then, after you specify that you want to create an enum data type, you give your enum structure a name. You can give your enum any name that you want. Enums have the same variable naming rules as regular variables.

Within the enum brackets are all of the properties that you need to define an enum. let's take a look at a real-world example using the days of the week enum that we described previously.

```
enum Days { Sun, Mon, Tue, Wed, Fri, Sat };
```

Notice that with an enum, you don't define a public specifier and you don't declare any data types. Remember that enums only hold integer data types, so you don't need to define any of these specifiers. They are all public by default, so you don't need to use the public specifier.

When you define a list of enum variables, the compiler automatically assigns values to each variable. The first value is always zero unless you specify otherwise. Each additional variable is given the next number in the list. In this example, the first variable Sunday Monday has the value of 1, and so on.

Let's take a look at how you would use this in code.

```
class EnumProgram {
    enum Days { Sun, Mon, tue, Wed, thu, Fri, Sat };
    static void Main () {
        int monday = (int)Days.Mon;
        int friday = (int)Days.Fri;
        Console.WriteLine("Monday: {0}", monday);
        Console.WriteLine("Friday: {0}", friday);
    }
}
```

In the above code, you can see how an enum variable returns a value. We assign the value to two integer variables. In the code above, the output first displays integer value of Monday, which is 1. The next output value is Friday, which is 5.

You can also reassign the integer values are set in an enum. For instance, suppose you want all of your enum values to start with the value of 1 and assign integer values from 1 to 7. Let's take a look at the code that would alter the enum values.

enum Days { Sun = 1, Mon, Tue, Wed, Thu, Fri, Sat };

In the above code, we start the integer assignment with a value of 1. In this instance, instead of the last variable Sat having the value of 6, you will have the value of 7.

You won't need enums and structures as often as you need classes, but they are useful in many scenarios when you don't need the bulky overhead of a class definition. We showed you a couple of examples, and you'll figure out where they are useful when you create your program design.

## Inheritance

**Objective:** Classes and OOP give you the ability to derive from parent classes. This chapter explains inheritance within your class structure.

OOP is more than just creating classes and building a program that can call other classes. You can derive your child classes from parent classes, so you don't need to repeat code for similar objects. Inheritance can be complex if you don't create a good class design, so this chapter attempts to explain inheritance and how you should set up your class structure for the best scalable code.

## Understanding Basic Inheritance

Inheritance lets you derive child classes from parent classes. Think about animals. If you have a lion and a parrot, both of these animals have very different characteristics, and they have similar ones as well. They are both animals, but one is a bird and one is a mammal. If you didn't use inheritance, you would need to create two classes that describe both animals from top to bottom.

With inheritance, you can create one class that describes basic features of an animal, and then derive child classes from the main parent class. For instance, both birds and lions have eyes and feet. Their eyes and feet might look different, but they still have them. Other characteristics are different, but all lions and birds have feet. You can create a parent animal class that defines feet and eyes, and then the child lion and bird classes can define characteristics specific to their respective animals.

The purpose of inheritance is to make it unnecessary to repeat your code. Without it, you'd have to create a bird and a lion class that defined the eyes and feet of each animal, which would create redundant code. When you create redundant code, you make it more difficult to manage your code. When you create ten classes that define the eyes of an animal and you need to change that description, you need to change all ten of those classes. This opens up more room for bugs and issues when you try to scale your code, which you want to avoid.

Not every class must be a parent or child class. You can create code with standalone classes that aren't derived from any other code. The way you design your code is up to you and the needs of the program you want to create.

## Inheriting from a Parent Class

Before you create your child class, you need to create a parent class. Since we're using an animal as an example parent class, we’ll first create an animal class that defines the very basic, shared characteristics between all animals.

Let’s take a look at an example animal class.

```
abstract class Animal
{
    public string eye_color;
    public string number_of_feet;
    public function breath()
    {
        return "Animals breathe air.";
    }
}
```

We created an Animal class in the above code. But it can be used as a parent class. Most abstract classes cannot be instantiated, as abstract are high-level main classes that can be used as parent classes for a number of child objects. The above code sets up some standard characteristics. Two properties take the eye color of the animal and the number of feet the animal has. All animals breathe, so we set up a method that indicates every animal breathes.

Now it’s time to derive your child class. Let’s derive a lion class from the main animal class.
