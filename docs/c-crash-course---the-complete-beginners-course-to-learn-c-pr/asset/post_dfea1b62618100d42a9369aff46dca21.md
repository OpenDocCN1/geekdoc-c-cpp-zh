## Inheritance and Interfaces

Interfaces are the foundation of inheritance. Interfaces allow you to define one class that can contain the declaration of each class that links to the interface, but any class can derive from it. It provides a way to create a “contract” between the child class and the parent classes that are linked to the interface.

Interfaces are different than classes in that they only contain the declaration of the classes and not the class definitions. Let’s take a look at a sample interface.

```c
public interface IAnimal {
    // interface members
    void breathe();
}
```

Since we only have one method in the Animal class, we only have one animal method defined in the interface. Notice that there are no class definitions in the interface. You just define the functions that are used in the interface. This also defines the ones that can be used in child classes. These interfaces make it easier to scale your classes, because you can create methods within your class that aren't ready to be released without any child classes to derive these methods until they are ready for use.

The standard naming scheme is also to use an I prefix when you name your interfaces. The prefix distinguishes the difference between the class and the interface when you work with both of them in your code.

Once you create your interface, you can inherit it in your classes. Let’s take a look at the Animal class when it derives from the IAnimal interface.

```csharp
public interface IAnimal {
    // interface members
    void breathe();
}

abstract class Animal : IAnimal {
    public string eye_color;
    public string number_of_feet;
    public function breathe() {
        return "Animals breathe air.";
    }
}
```

That’s all it takes to derive from the main Animal interface. Now, any of your other classes can inherit from the interface or the main Animal class. It’s standard for a program that includes interfaces to only allow programmers to derive from the interface, but it depends on the way you want to design your code and lay out your classes.

## Static Classes

Static classes need a mention, because they are a bit different than regular public classes. Static classes don’t need to be instantiated, which makes them beneficial when you want to create a class that has functions you want to use randomly in your code. Static classes are defined using the static keyword.

You might need a static class when it contains a function that you could need on the fly as you work with your code. For instance, the ToString method in C# is a static method. You can use it at any time without instantiating a class. Just call the ToString method and it turns your variable into a string. You use this method when you want to change a number, for instance, into a string value. The ToString method will turn any variable into a string regardless of the type of data it contains.

Let’s take a look at a static class.

```csharp
static class Animal : IAnimal
{
    public string eye_color;
    public string number_of_feet;
    public function breathe()
    {
        return "Animals breathe air.";
    }
}
```

Notice that we changed the abstract type in the above Animal class to static. Now, we don't need to instantiate this class. We can instantiate the class now that it's not an abstract defined class. With the static specifier, we can call the class with no instantiation. Let's take a look at what this looks like in a C# method.

```csharp
static class Animal : IAnimal
{
    public string eye_color;
    public string number_of_feet;
    public function breathe()
    {
        return "Animals breathe air.";
    }
}

class StaticTester
{
    static void Main(string[]) args
    {
        Console.WriteLine("This is what happens when you call a static class: {0}", Animal.breathe());
    }
}
```

In the above code, we define our static Animal class and then we call the breathe method using the static method contained within the class. Notice that we didn't instantiate the class before we called the method. This is valid syntax when you use the static specifier in your code.

Inheritance is a complex topic that most developers need some time to understand when creating their programs. You don't always need to inherit classes when you design your program, but it will greatly reduce the time you need to scale your code as your program grows and has more users. It takes some practice before you can get the hang of inheritance, classes, and OOP. As you practice with OOP, use some inheritance with parent and child classes to get used to the way they work within your designs.
