The standard naming scheme is also to use an I prefix when you name your interfaces. The prefix distinguishes the difference between the class and the interface when you work with both of them in your code.

Once you create your interface, you can inherit it in your classes. Let’s take a look at the Animal class when it derives from the IAnimal interface.

```
public interface IAnimal {
    // interface members
    void breathe();
}

abstract class Animal : IAnimal {
    public string eye_color;
    public string number_of_feet;
    public function breathe() {
        return "Animals breathe air.";
    }
}
```

That’s all it takes to derive from the main Animal interface. Now, any of your other classes can inherit from the interface or the main Animal class. It’s standard for a program that includes interfaces to only allow programmers to derive from the interface, but it depends on the way you want to design your code and lay out your classes.

# Static Classes

Static classes need a mention, because they are a bit different than regular public classes. Static classes don’t need to be instantiated, which makes them beneficial when you want to create a class that has functions you want to use randomly in your code. Static classes are defined using the static keyword.

You might need a static class when it contains a function that you could need on the fly as you work with your code. For instance, the ToString method in C# is a static method. You can use it at any time without instantiating a class. Just call the ToString method and it turns your variable into a string. You use this method when you want to change a number, for instance, into a string value. The ToString method will turn any variable into a string regardless of the type of data it contains.
