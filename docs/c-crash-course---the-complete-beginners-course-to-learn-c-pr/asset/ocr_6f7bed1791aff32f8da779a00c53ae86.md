#  Chapter 8
Structures and Enums

**Objective:** Structures and Enums are two other ways to create custom data types. This chapter shows you how to use both data types to structure your code and make it easier to read.

We covered classes in the previous chapter, which allowed you to create your own data types. Structures and enums are the other two ways to create your own data types, but these data types work differently than classes. You're bound by stricter rules with structures and enums, and they are used in different scenarios that you saw with classes. In this chapter, we'll look at both of these structures and give you an idea of when you would use them in your C# programs.

# Why Use a Structure or Enum Instead of a Class?

When you start programming in C#, you might be tempted to create classes for everything. Until up this chapter, we've pushed the idea that each component should be a class, but you can use enums and structures for smaller components of your program.

For instance, suppose you have a list of customer types. Each type has a value of 0 to 3 in your database. You could create a class for customer type, but you can also create an enum for these values. The enum gives these values a friendly name, and they store an integer to represent each friendly name coding value.

A structure is useful in the same way as an enum. A structure allows you to contain more than just integer values. An enum is for integer values, and a structure is useful when you need to store other data types. For instance, you could create a structure for a customer data type when you need to store the customer ID and a string value for the type. You might want to store a description in the structure that matches the customer ID. You could use a class for this type of structure, but sometimes a class is not necessary when you just need one or two properties to represent a custom data type.

In this chapter, we'll show you when you should use these data types instead of building an entire class. For the most part, you will use classes to define your application, but in a few examples, you won't need a full blown class instead of a small enum or structure.
