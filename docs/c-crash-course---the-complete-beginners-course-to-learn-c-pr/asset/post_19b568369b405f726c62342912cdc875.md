
You can also add an if statement to your else statement. This lets you create several conditions in one if statement block. Let's take a look at the template.

```
if (expression)
{
  // statements that execute when the expression equals true
}
else if (expression)
{
  // statements that execute when the expression doesn’t equal true
}
else
{
  // statements that execute when the expression doesn’t equal true
}
```

Notice that we still kept the else statement with the two conditions. The else statement is optional for any statement. For instance, you could have just the two if statements from the template above and leave out the else statement.

Now, let’s take a look at some actual code that uses the template. We’ll use the same variables from previous examples.

```
int myNumber1= 1;
int myNumber2 = 2;
if ( myNumber1 = 2)
{
  Console.WriteLine("The variable equals the value of 2");
}
else if ( myNumber1= 1)
{
  Console.WriteLine("The variable equals the value of 1");
}
else
{
  Console.WriteLine("The variable does not equal 2 or 1");
}
```

In this statement, we use the same condition in the first block and the else block. If you notice, the first block evaluates to false. This time, we now have an else if statement. This statement has another condition for evaluation. This time, the condition is equal to true. Therefore, the second block is executed and the else statement is skipped. The result of the above statement is that “The variable equals the value of 1” is displayed on the console.

## The Switch Statement

The final conditional statement is the switch statement. The switch statement is similar to the if statement, but it evaluates one variable for multiple conditions. Let’s first a look at the template for this statement.

```
switch(expression) {
  case constant-expression :
    // statement to execute
    break;
  case constant-expression :
    // statement to execute
    break;
  default :
    // statement to execute
}
```

With this statement, the variable is set in the switch expression, and then each case statement determines if the variable equals that value. Let’s take a look at the switch statement in action.

```
int myNumber = 1;
switch (myNumber) {
  case: 1
    Console.WriteLine("Value is 1");
    break;
  case: 2
    Console.WriteLine("Value is 2");
    break;
  default:
    Console.WriteLine("Don’t know the value");
}
```

In the above code, we evaluate the value of the variable myNumber. We initialize it to 1 and then use the case statements to go through each possible value. Because we know the value is 1, we can see that the first case statement evaluates to true, and then “Value is 1” is displayed in the console.

The default statement is similar to the else statement in an if block. If none of the case statements evaluate to true, then the default statement executes.

The break statements are used to exit out of the case statement. If you didn’t add the break statements, the next case would execute until the code reached the default statement. Just remember that each case statement requires a break to exit out of the switch block.

We looked at several loop and if statements in this chapter. It's important that you understand code execution flow, because these statements are very common in any programming language, including C#. These statements take some practice to understand the way code executes, as each statement changes the workflow. Use these statements to practice code flow in your own programs.

## Chapter 6: Introduction to OOP

Objective: OOP is the main architecture coding design for a C# program. This chapter covers the basics of C# programming using OOP concepts.

Object-Oriented Programming (OOP) is very different from linear development. OOP uses the concept of components for software development. Instead of just writing line-by-line and having each line execute until the end of the code is found, the concept of classes uses components that execute in the order in which the classes are defined and called. This chapter helps the coder understand how to work with OOP and its concepts.

## Understanding OOP Basics

OOP uses the concept of creating parts that come together to build a whole program. These parts are called classes. They are also referred to as class objects. Classes represent each part of your program.

To understand the why classes represent parts of a program, think of a car. A car has several parts that come together to form an entire car. Each part individually is useless, but when they are put together, they create a machine that many people can't do.

Using the car example, you need (among other things) an engine, a steering wheel, and tires to make up a car. Without these components, the car is useless. Classes represent these parts of the car. The class contains all attributes for these parts and any actions that they need to move or stop the car.

Before you begin your program, you need to design it prior to programming it. When you design your classes using either a third-party diagramming program or your own sketches and drawings. Whatever you use, it's important to lay out the program and determine the way your classes will represent the parts of your program. When you design the program prior to coding it, you avoid any mistakes caused by missing aspects of the program.

When you design your classes, you should also make sure that every property and method work well with the class itself. For instance, if you have an ecommerce application with a Customer and Product class, you wouldn't put a method in the Customer class that deals with product inventory. You would put product inventory in the Product class or you would risk the possibility of accidentally creating the same method twice when you realize it's not available in the right class.

## The Public Specifier

Once you design your classes, you have to decide if you want to make them available to other parts of your program. We’ll discuss how to create classes in the next chapter, but it’s important to understand the basics around them.

The public specifier tells the program that the class can be accessed in any area of the program. Let's take a look at an example of a Customer class with the public specifier.

```
public class Customer {
    public Customer() { }
    public string first_name;
    public string last_name;
    public string phone;
}
```

In the above Customer class, notice that the first specifier for the class is the public keyword. If we eliminated the public keyword, this class would not be accessible to other parts of your program.

You’ll also notice the constructor is set to public. We’ll cover the purpose of the constructor in the next chapter, but just know that this is necessary for other parts of your program to instantiate the class and use its properties and methods. It is too [sic] also set to public, but we could also set it to private. The public specifier lets other parts of the program instantiate the class.

To show you an example, the following code instantiates the class and sets it to a variable.

```
Customer cust = new Customer();
cust.firstLine = "John";
Console.WriteLine(cust.first_name);
```
