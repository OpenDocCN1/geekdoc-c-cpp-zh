Introduction to OOP

Objective: OOP is the main architecture coding design for a C# program. This chapter covers the basics of C# programming using OOP concepts.

Object-Oriented Programming (OOP) is very different from linear development. OOP uses the concept of components for software development. Instead of just writing line-by-line and having each line execute until the end of the code is found, the concept of classes uses components that execute in the order in which the classes are defined and called. This chapter helps the coder understand how to work with OOP and its concepts.

# Understanding OOP Basics

OOP uses the concept of creating parts that come together to build a whole program. These parts are called classes. They are also referred to as class objects. Classes represent each part of your program.

To understand the why classes represent parts of a program, think of a car. A car has several parts that come together to form an entire car. Each part individually is useless, but when they are put together, they create a machine that many people can't do.

Using the car example, you need (among other things) an engine, a steering wheel, and tires to make up a car. Without these components, the car is useless. Classes represent these parts of the car. The class contains all attributes for these parts and any actions that they need to move or stop the car.

Before you begin your program, you need to design it prior to programming it. When you design your classes using either a third-party diagramming program or your own sketches and drawings. Whatever you use, it's important to lay out the program and determine the way your classes will represent the parts of your program. When you design the program prior to coding it, you avoid any mistakes caused by missing aspects of the program.

When you design your classes, you should also make sure that every property and method work well with the class itself. For instance, if you have an ecommerce application with a Customer and Product class, you wouldn't put a method in the Customer class that deals with product inventory. You would put product inventory in the Product class or you would risk the possibility of accidentally creating the same method twice when you realize it's not available in the right class.
