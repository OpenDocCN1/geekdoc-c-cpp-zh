The location of your methods is dependent on your class design that you set up when you create your program architecture design. Regardless of your method name, you notice, the important part of your design is where the method is located. You always place a method in the appropriate class. For instance, you wouldn't put the method DecrementInventory in the Customer class, because it's not related to anything that has to do with customers. Poorly designed code can have a negative effect on your application architecture.

Let's take a look at a method within a class. We mentioned a class method that allows a user to change a phone number. Let's take a look at what an example method would look like in a customer class.

We added a ChangePhone method to the Customer class. If you notice, this method takes a new_phone variable. This variable takes the phone number for the customer and assigns it to the local class property. Notice again that we use this designation to specify that we want to assign the local class variable and not any other variable. This is especially important when you assign a local variable to a global class variable and both of them have the same name, just as we've illustrated in the above code.

Notice that we added the void specifier as well. You specify what type of value is returned by a method. In this example, nothing is returned, so the specifier is set to void. If we returned, for instance, a string value, we would specify a string return type instead of the void keyword.

Also notice that we set the method to public. This means that any other parts of your code can use the method regardless of whether it's a child class.
