# The Public Specifier

Once you design your classes, you have to decide if you want to make them available to other parts of your program. We’ll discuss how to create classes in the next chapter, but it’s important to understand the basics around them.

The public specifier tells the program that the class can be accessed in any area of the program. Let's take a look at an example of a Customer class with the public specifier.

```
public class Customer {
    public Customer() { }
    public string first_name;
    public string last_name;
    public string phone;
}
```

In the above Customer class, notice that the first specifier for the class is the public keyword. If we eliminated the public keyword, this class would not be accessible to other parts of your program.

You’ll also notice the constructor is set to public. We’ll cover the purpose of the constructor in the next chapter, but just know that this is necessary for other parts of your program to instantiate the class and use its properties and methods. It is too set to public, but we could also set it to private. The public specifier lets other parts of the program instantiate the class.

To show you an example, the following code instantiates the class and sets it to a variable.

```
Customer cust = new Customer();
cust.firstLine = "John";
Console.WriteLine(cust.first_name);
```

# The Private Specifier

Just like the public specifier, the private specifier is also an option for your classes. This hides the class from other parts of your program. With the private specifier, you’re unable to call the class from other parts of your program.

Let’s take a look at the same code as the previous section, but we’ll use the private specifier.

