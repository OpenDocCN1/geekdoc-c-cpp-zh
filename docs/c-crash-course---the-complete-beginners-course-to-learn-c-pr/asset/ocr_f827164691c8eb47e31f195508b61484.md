Structures look like classes with a long list of properties, but you use the “struct” keyword to define them instead of the class definition.

Let’s take a look at the template used to define a structure.

```
struct structure_name
{
    public data_type name
    // any other structure properties that you need
}
```

The “struct” keyword indicates that you want to create a structure. After the struct keyword, you give your structure a name. This can be any name that properly describes what the structure should contain.

Within the structure’s brackets are the properties. Each property should be set to public or you won’t be able to access them. With classes, there are reasons not to allow access to properties, but with structures you should have them set to public. You can add as many structure properties as you need, but when you get too complicated it is sometimes better to choose a class instead of using a structure.

Let’s take a look at a real-world example of a structure. We’ll use the same example we mentioned earlier. We’ll use a customer type structure.

```
struct customer_type
{
    public int id
    public string description;
    public string type_name;
}
```

In the code above, we created a structure named customer_type. Within the structure definition, we created three properties. The first one will represent the ID for the customer type. The second property, named description, represents a brief description of the type, and then the type_name property is the name for the customer type.
