We now have a derived child Lion class that inherits from the parent Animal class. We don't need to redefine the lion's eyes and feet, because we have these values in the parent Animal class.

Notice that the class definition is first named Lion, and then a colon is added with the Animal class. This is how you indicate to the compiler that you want to inherit a parent class. You can derive from multiple classes by adding a comma and then adding more names of parent classes to indicate that you want to derive from multiple parents. Child classes can also derive from other child classes. The parent class definition doesn't matter as long as it's not set to private. Once you set a class to private, you can't derive from or instantiate it, so be careful with the specifiers that you choose for your.

Our Lion class also has properties and methods that define characteristics that are specific to a lion. The lion roars, so we have a Roar method that defines the way a lion speaks. We also have a mane property to define a lion's mane. These two characteristics are specific to lions, so they belong in the Lion class. If they were global to all animals, we would place them in the Animal class so all other child classes could use these properties and methods.

# Inheritance and Interfaces

Interfaces are the foundation of inheritance. Interfaces allow you to define one class that can contain the declaration of each class that links to the interface, but any class can derive from it. It provides a way to create a “contract” between the child class and the parent classes that are linked to the interface.

Interfaces are different than classes in that they only contain the declaration of the classes and not the class definitions. Let’s take a look at a sample interface.

```
public interface IAnimal {
    // interface members
    void breathe();
}
```

Since we only have one method in the Animal class, we only have one animal method defined in the interface. Notice that there are no class definitions in the interface. You just define the functions that are used in the interface. This also defines the ones that can be used in child classes. These interfaces make it easier to scale your classes, because you can create methods within your class that aren't ready to be released without any child classes to derive these methods until they are ready for use.
