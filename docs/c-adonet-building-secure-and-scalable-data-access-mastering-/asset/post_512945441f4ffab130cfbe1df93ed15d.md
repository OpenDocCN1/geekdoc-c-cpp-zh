### Entity-Relationship Diagrams (ERDs)

### What is an ERD?

An ERD is a visual representation of the structure of a database. It consists of entities (tables), attributes (columns), and relationships between entities. ERDs help database designers understand the structure of a database and its relationships, making it easier to design and maintain the database.

### Entities and Attributes

Entities represent the tables in the database, while attributes represent the columns in the tables. For example, in a database for a library, the "Book" entity might have attributes such as "Title", "Author", and "ISBN".

### Relationships

Relationships between entities represent how the tables in the database are related to each other. There are three types of relationships:

- **One-to-One (1:1):** In a one-to-one relationship, each record in one table is related to exactly one record in another table. For example, in a database for a university, each student might have exactly one student ID.
- **One-to-Many (1:N):** In a one-to-many relationship, each record in one table can be related to many records in another table. For example, in a database for a library, each book can have multiple authors.
- **Many-to-Many (M:N):** In a many-to-many relationship, each record in one table can be related to many records in another table, and vice versa. For example, in a database for a university, each student can have multiple courses, and each course can have multiple students.

### Cardinality

Cardinality is a measure of the number of entities that are related in a relationship. It is represented using the symbols "0..1" for zero or one, "1" for exactly one, and "0..*" for zero or more.

### ERD Symbols

There are several symbols used in ERDs to represent entities, attributes, relationships, and cardinality. These symbols help database designers create a visual representation of the database structure.

### Normalization Techniques

In this section, we'll discuss normalization techniques, an essential aspect of database design.

### What is Normalization?

Normalization is the process of organizing data in a database to reduce redundancy and improve data integrity. It involves breaking down a large table into smaller, more manageable tables, and then linking them together using relationships.

### Normalization Forms

There are several normalization forms, each with its own set of rules and guidelines:

- **First Normal Form (1NF)**: The first normal form requires that each column in a table contains atomic (indivisible) values. This means that a column cannot contain multiple values or a combination of values.
- **Second Normal Form (2NF)**: The second normal form requires that a table be in first normal form and that all non-key attributes are fully functionally dependent on the primary key. This means that each non-key attribute is determined by the entire primary key, not just part of it.
- **Third Normal Form (3NF)**: The third normal form requires that a table be in second normal form and that all non-key attributes are non-transitively dependent on the primary key. This means that each non-key attribute is determined by the primary key, not by any other non-key attributes.
- **Boyce-Codd Normal Form (BCNF)**: The Boyce-Codd normal form is a stricter form of the third normal form. It requires that a table be in third normal form and that every determinant (a set of attributes that uniquely determines another attribute) is a candidate key.
- **Fourth Normal Form (4NF)**: The fourth normal form requires that a table be in third normal form and that there are no non-trivial multi-valued dependencies.
- **Fifth Normal Form (5NF)**: The fifth normal form requires that a table be in fourth normal form and that there are no non-trivial join dependencies.
