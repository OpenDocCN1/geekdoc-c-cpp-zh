## Querying Databases with Dapper

Dapper is known for its simplicity and raw performance, especially when it comes to querying databases. In this section, we'll explore how to use Dapper to execute various types of queries against a database.

### Basic Query

The Query method is used to retrieve a collection of objects from the database. You pass in the SQL query and any parameters needed for the query. For example:

```csharp
using (var connection = new SqlConnection(connectionString))
{
    var users = connection.Query<User>("SELECT * FROM Users WHERE Age > @Age", new { Age = 18 }).ToList();
}
```

### Single Row Query

The QueryFirstOrDefault and QuerySingleOrDefault methods are used to retrieve a single row from the database. They are similar to the Query method but return a single object or null if no object is found. For example:

```csharp
using (var connection = new SqlConnection(connectionString))
{
    var user = connection.QueryFirstOrDefault<User>("SELECT * FROM Users WHERE Id = @Id", new { Id = 1 });
}
```

### Query with Multiple Results

The QueryMultiple method is used when you want to execute multiple queries and retrieve multiple result sets. For example:

```csharp
using (var connection = new SqlConnection(connectionString))
{
    var query = @"SELECT * FROM Users; SELECT * FROM Orders;";
    using (var multi = connection.QueryMultiple(query))
    {
        var users = multi.Read<User>().ToList();
        var orders = multi.Read<Order>().ToList();
    }
}
```

### Dynamic Query

Dapper supports dynamic queries, where you can pass in a dynamic object containing the query parameters. For example:

```csharp
using (var connection = new SqlConnection(connectionString))

    dynamic parameters = new { FirstName = "John", LastName = "Doe" };
```

```csharp
using (var connection = new SqlConnection(connectionString))
```

## Best Practices for Using Dapper

Dapper is a lightweight and efficient ORM tool for .NET applications. To make the most out of Dapper and ensure your data access code is performant and maintainable, it's essential to follow some best practices. Here are some recommendations for using Dapper effectively:

- **Parameterized Queries**: Always use parameterized queries to protect against SQL injection attacks and improve query performance. Dapper automatically handles parameterization when you pass an anonymous type as the parameter to its methods.
- **Use Transactions**: Use transactions to group multiple database operations into a single, atomic unit of work. This ensures that either all operations succeed or none of them do, maintaining data consistency and integrity.
- **Bulk Operations**: Use Dapper's support for bulk operations when you need to insert, update, or delete multiple records in a single operation. This can improve performance by reducing the number of round trips to the database.
- **Connection Management**: Dapper does not manage database connections for you. You need to open and close connections manually. Use the using statement or the IDisposable pattern to ensure connections are properly closed and resources are released.
- **Use the IDbConnection Interface**: When working with Dapper, use the IDbConnection interface instead of specific database connection classes (e.g., SqlConnection). This allows your code to be more flexible and support different database providers.
- **Error Handling**: Properly handle exceptions when using Dapper to execute queries. Use try-catch blocks to catch and handle any exceptions that may occur during database operations.
- **Avoid Overuse of Dynamic Queries**: While Dapper supports dynamic queries, it's generally best to avoid them whenever possible. Dynamic queries can be harder to maintain and can lead to performance issues if overused.
- **Optimize Query Performance**: Optimize your queries to improve performance. Use indexes, avoid unnecessary joins, and consider denormalizing data when appropriate.
- **Logging and Profiling**: Enable logging and profiling in your Dapper applications to monitor query performance and identify potential bottlenecks. Dapper provides built-in logging capabilities that can be customized to suit your needs.
