
## The @ MasterType Directive

The `@ MasterType` directive provides a way to create a strongly typed reference to the ASP.NET master page when the master page is accessed from the `Master` property.

The syntax for the `@ MasterType` directive is as follows:

```
<%@ MasterType attribute="value" [attribute="value"...] %>
```

## The @ OutputCache Directive

The `@ OutputCache` directive controls the output caching policies of a Web page or a user control.

The syntax for the `@ OutputCache` directive is as follows:

```
<%@ OutputCache Duration="#ofseconds"
Location="Any | Client | Downstream | Server | None |
ServerAndClient "
Shared="True | False"
VaryByControl="controlname"
VaryByCustom="browser | customstring"
VaryByHeader="headers"
VaryByParam="parametername"
CacheProfile="cache profile name | ""
NoStore="true | false"
SqlDependency="database/table name pair | CommandNotification"
%>
```

## The @ Reference Directive

The `@ Reference` directive dynamically compiles and links the user control, page source file, or arbitrary file located at some virtual path.

The syntax for the `@ Reference` directive is as follows:

```
<%@ Reference Page="path to .aspx page"
Control="path to .ascx file"
virtualPath="path to file" %>
```

## Form Elements

The Web page must contain a form element to submit the Web page to the server. You use the standard HTML form element, but under the following conditions:

- The page cannot contain more than one form element.
- The form element must have the `runat` attribute and the value set to `server`. This attribute allows you to refer to the form and the controls on the page programmatically in server code.
- Server controls performing postback must be inside the form element.
- The opening tag should not have an `action` attribute. ASP.NET sets these attributes dynamically when the page is processed, ultimately overriding any changes that you make.

## Web Server Controls

You normally add controls such as buttons, text boxes, lists, to ASP.NET pages so that users can interact with the page. These server controls are similar to HTML controls. However, server controls are processed on the server and HTML controls are processed on the client. The events raised by these controls are handled in the server code. When the page is executed, ASP.NET identifies the special syntax used by the server controls, which determines that the control is to run at the server. In case you want to make HTML controls work as server controls, you can do so by adding the `runat="server"` attribute to any HTML element in the page. When the page is run, ASP.NET identifies the element that is supposed to run on the server as a server control and makes it available to the server code.

### Setting the Title Bar Text of a Web Form

您可以使用 HTML 的 header 中的 Title 属性为 Web Form 设置标题栏文本。默认情况下，当 Web Form 显示时，浏览器标题栏中会看到文本 Untitled Page。您可以使用 Title 属性为 Web Form 指定您选择的标题。

> **NOTE**
> 要显示 Web 页面的标题，Web 页面必须包含带有 `runat="server"` 属性的 `<head>` 元素；否则，标题将不会显示。

让我们使用名为 `FileSystemWebsite` 的同一应用程序为其 Default Web 页面显示标题。为此，在 Source 视图中向 Default Web 页面的 `<Title>` 标签添加一个值，如 Listing 13.4 中突出显示所示：

**Listing 13.4:** Setting Title of a Web Form

```
<%@ Page Language="C#" AutoEventWireup="true" CodeFile="Default.aspx.cs" Inherits="_Default" %>

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">

<html xmlns="http://www.w3.org/1999/xhtml">

<head runat="server">
    <title>Welcome Page</title>
</head>

<body>
    <form id="form1" runat="server">
        <div>
        </div>
    </form>
</body>
</html>
```
