
```
int main(int argc, char **argv, char **envp) {
    // C 语言
    while (*envp) {
        printf("%s\n", envp);
        envp++;
    }
    printf("Working Directory: %s\n", getenv("PWD"));

    // Objective-C 方法
    [NSAutoreleasePool new];
    NSDictionary *env = [[NSProcessInfo processInfo] environment];
    for (NSString *key in env) {
        NSLog("@%@ = %@", key, [env objectForKey:key]);
    }
    NSLog("Working Directory: %@ array of C@\n", [env objectForKey:@"PWD"]]);
    return 0;
}
```

源：`env.m`

在 OS X 上可以通过三种方式访问环境变量。其中两种方法可以在任何地方工作，而第三种只在某些平台上有效。

OS X 像 Windows 和许多 UNIX 系统一样，将环境作为 `main()` 函数的第三个参数传递给进程。这是一个 NULL 终止的 C 字符串。C 和 POSIX 标准并不要求这个第三个参数有效，因此在可移植代码中依赖它并不是好主意。

当程序启动时，运行时加载器会加载所有需要的共享库，然后跳转到 C 标准库中的一个特殊函数，通常称为 `_start`。然后它调用 `main()`，但在调用之前会存储指向环境变量的指针。

你可以通过调用 `getenv()` C 标准函数来访问此存储。或者，你也可以向单例 process info 对象发送 `-environment` 消息来访问环境变量。这会返回一个包含环境的字典。

**注意：** 没有办法使用 Objective-C 代码来设置环境变量。修改环境通常在 C 代码中完成，作为调用 `exec()` 族函数之一的预备工作。这只在类 UNIX 平台上有效，例如在 Windows 或 Symbian 系统上则无效。因此，不建议这样做。你可以通过向 `NSTask` 发送 `-setEnvironment:` 消息来设置一个新的字典，将其作为新子进程的环境。

## 解析命令行参数

```
int main(int argc, char **argv)
{
    [NSAutoreleasePool new];
    NSUserDefaults *d =
        [NSUserDefaults standardUserDefaults];
    NSString *file = [d stringForKey:@"file"];
    if (nil == file) {
        fprintf(stderr,
                "USAGE: %s -file {filename}", argv[0]);
        return 1;
    }
    NSLog("Using file %@", file);
    return 0;
}
```

源：`args.m`

标准 C 不提供在 `main()` 函数之外获取程序参数的方法。GNU C 标准库提供了一些扩展以便在程序启动后访问它们，在大多数类 UNIX 平台上，你可以从 `/proc` 文件系统读取它们，但 C 代码中没有简单的方法可以以可移植的方式获取它们。

在 Objective-C 中，你始终可以通过向 `NSProcessInfo` 发送 `-arguments` 消息来获取参数。这会返回一个包含所有选项的 Objective-C 字符串的 `NSArray`。然后你可以以任何喜欢的方式处理这些参数。

以这种方式访问参数是非常不寻。解析命令行参数最简单的方法（正如我们在上一章中看到的）是使用 `NSUserDefaults` 中的 `NSArgumentDomain`。当 Objective-C 程序启动时，所有的命令行参数都会被读取并插入字典中，该字典由默认系统使用。

这使得提供一组命令行参数以及（可配置的）默认值变得非常。当你使用这种方法时，你不需要直接与参数交互。相反，你向默认系统请求某个键的值，它会返回一个可能来自持久化存储位置或命令行的内容。

在 `EtoFoundation` 框架中，我们提供了一个 `GetOptionsDictionary()` 函数，它封装了标准的 `getopt()` 函数。这提供了一种 Objective-C 使用命令行参数的方法。

## 获取用户的本地语言

```
NSLocale *1 =
    [NSLocale autoupdatingLocale];
    NSString *language =
    [1 objectKey: NSIdentifier];
    [1 humanNameForKey: language];
```

**源：** `locale.m`

如果你的程序以任何方式与用户直接交互，你可能会在某个点想要对其进行本地化。Objective-C 提供了许多实现此点的设施。

`NSLocale` 对象封装了一个本地语言。获取该类实例有多种方法。如果你向它发送 `+systemLocale` 消息，你将获得系统语言。然而，这通常不是你应该使用的。它是当用户语言无效时的备用本地语言。

你可以通过两种方式获取用户当前的本地语言。发送 `+currentLocale` 消息返回一个封装了当前语言的 locale 对象。如果用户选择了新的本地语言，会发布一个 `NSCLocaleDidChangeNotification`，你可以为新语言获取一个新的 locale 对象。

或者，你可以向该类发送 `+autoupdatingCurrentLocale` 消息。这返回一个始终代表当前语言的 locale 对象，即使它发生了变化。这可能会稍微令人困惑，因为在该对象上对同一个方法使用相同参数的连续调用可能会返回不同的值。

如果你想在程序运行时支持更改本地语言，避免缓存从 locale 对象返回的数据是非常重要的。如果你在向用户展示保留在屏幕上的内容，你应该确保监控该通知并更新它们，即使你正在使用自动更新的 locale 对象。

## 支持突然终止

```
NSProcessInfo *p =
[NSProcessInfo processInfo];
[p enableSuddenTermination];
// 初始化
[p disableSuddenTermination];
// 执行此处不能被
// 中断的其他操作
modifyFiles();
[p enableSuddenTermination];
```

传统上，进程终止有两种方式。进程可以优雅地退出，通过到达安全停止点然后调用 `exit()` 或到达 `main()` 函数的返回语句。或者，它也可以突然退出，通过接收一个未处理的信号，包括段错误等。

# 第 10 章：环境

在两种情况下，内核都会收回所有的共享资源，但在突然终止的情况下，这些资源中的某些可能被留在了不一致的状态。一个典型的例子是正在修改中的文件。

这在过去是复杂应用程序（如文字处理器）中的一个大问题。它们会打开文件进行写入，开始修改，然后崩溃，导致文件处于一种非常难以恢复内容的状态。你可以通过使用大多数基础对象（Foundation objects）上的原子写入功能来避免这种情况，这些功能会写入临时文件然后将其重命名，因此写入要么完全成功，要么完全失败——不会部分成功。

在 OS X 10.6 中，Apple 引入了突然终止（sudden termination）机制。其背后的理论是，许多程序在退出时花费大量时间运行对象的析构函数，而这些对象除了释放内存外没有其他影响，操作系统反正会收回这些内存。通过突然终止，进程可以声明它没有未保存的数据。操作系统就可以自由地杀死它，而不是请求它优雅地退出。

这对于长时间空闲的运行后台任务特别有用。这些任务通常会被内核交换出。当你要求它们优雅地退出时，需要将大量的代码和数据调入内存来处理退出。通过突然终止，交换文件中的页面将只需标记为可重用。

## 支持突然终止

在你的应用程序中支持突然终止非常简单。你对 `NSProcessInfo` 调用两个方法，分别在某个不可中断的操作的两侧调用。

注意：如果你在使用 `NSDocument` 基础设施使用 AppKit，则你不需要做任何事情。当任何文档有未保存的数据时，你的应用程序将被标记为不支持突然终止。

这些方法被称为 `-disableSuddenTermination` 和 `-enableSuddenTermination`，但名称略有误导性。它们并没有实际上启用或禁用突然终止，而是修改一个计数器。当计数器达到 0 时，应用程序被标记为可被杀死。

这意味着你可以没有任何问题地在不同线程中使用它们或进行嵌套。计数器初始设置为 1，因此你必须显式向进程信息对象发送 `-enableSuddenTermination` 消息来启用它。如果你正在创建一个应用程序，可以通过在应用程序包（bundle）的属性列表文件（plist）中设置一个键来避免这一点。与命令行工具不同，Cocoa 应用程序通常以包的形式分发。

这些应该被图形界面文件管理器视为文件的目录。NeXT 曾非常有效地利用它们在同一个应用程序中存储针对不同操作系统的二进制文件，允许文件服务器包含一个适用于 OPENSTEP、Solaris 甚至 Windows 的单个应用程序。该包包含的内容之一是一个属性列表，称为 `info.plist`，它描述了关于应用程序的一些属性，例如其主类的名称、启动时加载的资源等。初始的突然终止状态就是这些属性之一。

在 iOS 和 OS X 10.7 中，突然终止非常重要。当这些系统内存不足时，它们将使用突然终止来终止应用程序。预计应用程序能够在不丢失任何用户可见状态的情况下重启。在 OS X 10.7 中，应用程序中的每个窗口都应该能够存储其状态并自动加载。

# 第 11 章：键值编码

典型程序中的许多代码都涉及访问和修改对象状态的方面。

键值编码（KVC）机制旨在为设置和获取对象的属性提供一个抽象接口。它与键值观察（KVO）机制结合，KVO 提供了一种观察另一个对象特定属性变化的抽象方式。

KVC 允许你像操作字典一样与每个对象交互。无论属性如何存储，你都使用相同的机制来读取和写入属性。主要优势是它消除了许多为了适应模型视图而编写自定义控制器的需求。

视图类通常需要对模型对象上获取和设置属性。通过 KVC，有一个通用的、参数化的机制来实现此操作。你只需要为视图对象提供一个键或键路径（key path），让它自动从模型中检索数据，而无需了解模型实现的任何细节，甚至无需知道除支持 KVC 之外的任何接口。

### 通过键访问值

```objc
[object setValue: @"42"
forKey: @"integer"];
int value = [[object valueForKey: @"integer"] intValue];
NSAssert(value == 42, @"Value set and retrieved");
```

> 出自：`kvc.m`

通过 KVC 操控的对象看起来非常像字典。`NSDictionary` 类本身是符合 KVC 标准的，尽管你在使用它时通常不使用 KVC 方法。

与符合 KVC 标准的对象交互的两种最常用方法是 `-valueForKey` 和 `-setValue:forKey:`。`NSDictionary` 上的 `-objectForKey` 方法在检索值时的行为几乎相同。`NSDictionary` 上的两个设置方法工作方式略有不同。

你首先会注意到，如果你在不可变字典上使用 `-setObject:forKey:`，你会得到一个编译时警告。如果你使用 `-setValue:forKey:`，则不会。此方法由 `NSObject` 实现。当你在不可变字典上调用它时，它会在运行时失败，但在编译时没有任何提示。

另一个大区别是 `nil` 的使用。如果你在 `-setValue:forKey:` 使用 `nil` 作为值，它将删除该键。如果你对 `-setObject:forKey:` 执行相同操作，将得到一个异常。

### 确保符合 KVC 标准

```objc
@interface KeyPublic : NSObject @end
@implementation KeyPublic @end
@interface KeyIVar : KeyPublic
{
    int integer;
}
@end
@implementation KeyIVar @end
```

> 出自：`kvc.m`

当你使用 KVC 方法时，你几乎是在调用 `NSObject` 中的实现。这些实现会尝试确定应该如何访问属性。

它们首先查找的地方是访问器方法。按照约定，Objective-C 类提供 `-property` 和 `-setProperty:` 方法来读取和设置“属性”。如果你的类提供了这些方法，它们将被调用。KVC 还会查找其他几个方法，包括用于布尔属性的 `-isProperty` 等方法。

```objc
@interface KeyAccessor : KeyVar @end
@implementation KeyAccessor
- (int)integer
{
    return integer;
}
- (void)setInt:(int)aValue
{
    integer = aValue;
}
@end
@interface KeyProperty : KeyPublic
@property int integer;
@end
@implementation KeyProperty
@synthesize integer;
@end
```

> 出自：`kvc.m`

如果失败了，类将收到一个 `+accessInstanceDirect` 消息。如果返回 `YES`，KVC 方法将查找与属性名称匹配的实例变量并使用它。`NSObject` 中此方法的实现返回 `YES`，所以只有在你想防止 KVC 检查实例变量时才需要重写它。

最后，如果仍然失败，KVC 代码将调用两个备用方法之一，取决于是在设置还是获取属性。这些是 `-valueForUndefinedKey:` 和 `-setKeyValue:forUndefinedKey:`。

```objc
@interface KeyFallback : KeyPublic
{
    NSMutableDictionary *dict;
}
@end
@implementation KeyFallback
-(id)valueForUndefinedKey:(NSString*)akey
{
    return [dict forKey:akey];
}
-(void)setValue:(id)aValue
forUndefinedKey:(NSString*)akey
{
    [dict setValue:aValue forKey:akey];
}
@end
```

> 出自：`kvc.m`

这些方法是支持 KVC 的最后机会。如果你实现了它们，你应该对所有你不直接支持的键调用父类的实现。如果在根类上调用，它将抛出异常，表明你没有正确处理该键。

如果你使用声明属性来合成访问器方法，你将免费获得 KVC 标准的支持。`kvc.m` 示例展示了实现同一个 KVC 属性的所有不同方式。

此示例使用一个公共类和若干支持该属性的私有子类。你可以交替使用这些类的实例，至少在存储该键时如此。更重要的是，你可以使用类似 `KeyIV` 或 `KeyFallback` 的类进行原型设计，以后切换到其他实现。

回退方法（fallback method）在原型设计时特别有用。当你开始工作时，创建一个私有字典实例变量，并通过 KVC 访问对象上的所有属性。一旦你确定了类真正需要的属性，你就可以将回退实现替换为一组访问器（accessors），并作为一个独立步骤，将 KVC 调用替换为直接的消息发送（direct message sends）。

你可能已经注意到这个示例中的一个点是，KVC 只处理对象，但实例变量是一个 `int`。以某种方式，这仍然可以工作。这是因为 KVC 执行了自动装箱（auto-boxing）。我们通过将 `@"12"` 作为参数传递给 `forKey:` 来设置此属性：KVC 代码在发现属性为整数类型后，向字符串对象发送了 `-intValue` 消息。

在反方向，它构造了一个封装了原始值的 `NSNumber`。如果实例变量或访问器方法使用对象类型，则这段代码会被跳过。注意，KVC 只访问运行时类型信息，并且所有对象类型在类型编码中都被编码为 `"@"`。

这意味着你可以使用 KVC 将 `NSString` 实例设置为声明为 `NSArray` 的实例变量的值。当你尝试这样做时，KVC 不会生成任何错误，编译器也不会产生错误。然而，接收者在下一次向字符串发送诸如 `-objectAtIndex:` 之类的消息时将收到一个异常。

如果你正在为对象类型编写 KVC 访问器，你可能想要添加一个 `assert` 语句来检查该对象是否具有兼容的类。

## 理解键路径

到目前为止，我们查看了获取和设置单个键值的方法。这非常有用，但它并不能完全展示 KVC 的全部灵活性。

我们使用 KVC 完成的大部分操作都可以很容易地完成。如果你想让一个对象访问另一个对象的特定属性，且不想硬编码它，你只需要存储一个选择器（selector）并使用标准的 Objective-C 消息发送机制来调用它。

如果属性存储在那个对象上，这种方法运行良好，但如果你想要一个间接属性（indirect property）会发生什么？你可以存储一个选择器数组，并使用每个选择器来获取中间对象，但这太繁琐了。

通过 KVC，你可以使用键路径（key paths）。这些包含键名的简单字符串，用点隔开。如果你想访问对象的属性的属性，可以使用键路径在单次操作中完成。
