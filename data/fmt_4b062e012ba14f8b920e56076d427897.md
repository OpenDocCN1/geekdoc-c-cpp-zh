
- `propertyChangedMethod` – 表示作为 `PropertyChangedCallback` 委托参数传递的方法名称

- `dObject` – 表示依赖属性的所有者

> NOTE
>
> 强制值回调和属性更改回调属于属性元数据；然而，验证回调不包含在属性元数据中。

现在，让我们讨论依赖属性元数据。

# 依赖属性元数据

每个依赖属性都有一个元数据，该元数据引用一个包含有关依赖属性的许多信息的对象。依赖属性元数据可以包括依赖属性的默认值以及对强制和属性更改回调的引用。您可以访问元数据以检索或更改有关依赖属性的信息。当您想要更改现有依赖属性的值而不重新实现依赖属性或创建新的依赖属性时，依赖属性元数据很有用。您可以在依赖属性所有者的派生类中更改或覆盖依赖属性的元数据。

依赖属性元数据通过 `PropertyMetadata` 类实现。`PropertyMetadata` 类有一个名为 `UIPropertyMetadata` 的派生类，而 `UIPropertyMetadata` 又被 `FrameworkPropertyMetadata` 类继承。`FrameworkPropertyMetadata` 类是主要用于处理依赖属性的属性元数据的类。`FrameworkPropertyMetadata` 类有几个布尔属性，影响依赖属性的各种元数据选项。表 9.12 列出了 `FrameworkPropertyMetadata` 类的一些值得注意的属性：

| Table 9.12: Noteworthy Properties of the FrameworkPropertyMetadata Class |

| Property | Description |

| `AffectsArrange` | 允许您指定依赖属性是否影响元素的排列传递。元素的排列传递意味着为元素提供多少空间并要求其排好队。此属性为布尔类型，可以设置为 true 或 false。 |

| `AffectsMeasure` | 允许您指定依赖属性是否影响元素的测量传递。元素的测量传递意味着确定元素用于显示目的所需的空间。此属性为布尔类型，可以设置为 true 或 false。 |

| `AffectsParentArrange` | 允许您指定依赖属性是否影响其父元素的排列传递。此属性为布尔类型，可以设置为 true 或 false。 |

| `AffectsParentMeasure` | 允许您指定依赖属性是否影响其父元素的测量传递。此属性为布尔类型，可以设置为 true 或 false。 |

# 自定义依赖属性

尽管 WPF 提供了通过不同 WPF 类公开的各种依赖属性，但您可能需要创建自己的依赖属性，即自定义依赖属性。您可以实现任何类型的 WPF 功能来创建自定义依赖属性。例如，如果您想在属性上使用动画、样式和数据绑定，则可以创建依赖属性。

请注意，您只能为直接或间接继承 `DependencyObject` 类的类创建依赖属性。然后实例化 `DependencyProperty` 类以创建依赖属性标识符（依赖属性的名称）。然后需要使用 `DependencyProperty` 类的 `Register()` 方法将依赖属性注册到 WPF 属性系统。在将依赖属性与 WPF 属性系统注册时，您可以指定其属性元数据以及验证、强制值和属性更改回调。

在注册依赖属性后，它会被 CLR 属性包装，该属性使用 `GetValue()` 和 `SetValue()` 公共方法。请注意，虽然在 XAML 和代码隐藏文件中都将依赖属性作为传统的 CLR 属性访问，但您也可以直接在代码隐藏文件中访问 `GetValue()` 和 `SetValue()` 方法。

现在，让我们创建一个名为 `SquareBoxDependencyProperty` 的独立 WPF 应用程序（也在 CD 上提供）来演示自定义依赖属性。在代码隐藏文件（`MainWindow.xaml.cs`）中，在 `SquareBoxDependencyProperty` 命名空间中添加以下代码片段：

```
public partial class Box : UIElement
{
    public static readonly DependencyProperty BoxHeightProperty;
    public static readonly DependencyProperty BoxWidthProperty;
    public static readonly DependencyProperty IsSquareProperty;
}
```

在前面的代码片段中，一个名为 `Box` 的部分类派生自 `UIElement`，而 `UIElement` 继承自 `DependencyObject` 类。在 `Box` 类中，声明了三个名为 `BoxHeightProperty`、`BoxWidthProperty` 和 `IsSquareProperty` 的静态只读字段，其类型为 `DependencyProperty`。请注意，所有三个字段都以 Property 字为后缀。必须将 `DependencyProperty` 字段以 Property 字为后缀。

如果您想对 `Box` 类的依赖属性的值提供验证和强制，则需要包含验证和强制回调。以下代码片段显示了如何在 `Box` 类中使用验证和强制：

```
public static void IsSquareBoxTrue(DependencyObject myObject, DependencyPropertyChangedEventArgs myObjectArgs)
{
    myObject.CoerceValue(BoxHeightProperty);
    myObject.CoerceValue(BoxWidthProperty);
}
public static object myBoxHeightWidthSquare(DependencyObject myObject, object myValue)
{
    Box box1 = (Box)myObject;
    Boolean square = (Boolean)myValue;
    if (square == true)
        if (box1.BoxHeight > box1.BoxWidth)
            box1.BoxHeight = box1.BoxWidth;
        else
            box1.BoxWidth = box1.BoxHeight;
        return true;
}
public static Boolean IsValidHeight(object height)
{
    if ((int)height <= 0)
        return false;
    else
        return true;
}
public static Boolean IsValidWidth(object width)
{
    if ((int)width <= 0)
        return false;
    else
        return true;
}
```

在前面的代码片段中，`IsSquareBoxTrue()` 方法是属性更改回调，它有两个参数。第一个参数为 `DependencyObject` 类型，指的是包含依赖属性的类的对象。第二个参数为 `DependencyPropertyChangedEventArgs`。在 `IsSquareBoxTrue` 方法中，对 `BoxHeightProperty` 和 `BoxWidthProperty` 有两次调用 `CoerceValue()` 方法。`CoerceValue()` 方法调用 `myBoxHeightWidthSquare()` 方法。`myBoxHeightWidthSquare()` 方法有两个参数，分别为 `DependencyObject` 和 `object` 类型。`DependencyObject` 参数指的是 `Box` 的对象，而 `object` 参数指的是用于强制其他依赖属性值的 value。在 `myBoxHeightWidthSquare()` 方法中，如果 `square` 变量为 true 且 `BoxHeight` 属性大于 `BoxWidth` 属性，则 `BoxHeight` 属性变为等于 `BoxWidth` 属性。如果 `BoxHeight` 不大于 `BoxWidth` 属性，则 `BoxWidth` 属性被赋予 `BoxHeight` 属性的值。

前面的代码片段还包含了另外两个方法，`IsValidHeight()` 和 `IsValidWidth()`。这两个方法是在 `BoxHeight` 和 `BoxWidth` 属性需要验证时被调用的验证方法。通常，验证方法是在值被强制转换之后调用的。

现在，你需要注册 `Box` 类的依赖属性。在这种情况下，依赖属性是在 `Box` 类的静态构造函数中注册的，如以下代码片段所示：

```
static Box() {
    FrameworkPropertyMetadata myBoxHeightMetadata = new FrameworkPropertyMetadata(5);
    FrameworkPropertyMetadata myBoxWidthMetadata = new FrameworkPropertyMetadata(5);
    FrameworkPropertyMetadata squareBoxMetadata = new FrameworkPropertyMetadata
        (false, FrameworkPropertyMetadataOptions.None, new
        PropertyChangedCallback(IsSquareBoxTrue), new
        CoerceValueCallback(myBoxHeightSquare));
    BoxHeightProperty = DependencyProperty.Register("BoxHeight", typeof(int), typeof(Box),
        myBoxHeightMetadata, new ValidateValueCallback(IsValidHeight));
    BoxWidthProperty = DependencyProperty.Register("BoxWidth", typeof(int), typeof(Box),
        myBoxWidthMetadata, new ValidateValueCallback(IsValidWidth));
    IsSquareProperty = DependencyProperty.Register("IsSquare", typeof(Boolean),
        typeof(Box), squareBoxMetadata);
}
```

在前面的代码片段中，`Box` 类的静态构造函数包含三个 `FrameworkPropertyMetadata` 类的对象，用于配置三个依赖属性的元数据。`myBoxHeightMetadata` 和 `myBoxWidthMetadata` 对象使用 5 作为 `BoxHeight` 和 `BoxWidth` 属性的默认值进行实例化。`squareBoxMetadata` 对象指定 false 作为默认值，并为 `IsSquare` 属性指定属性更改和强制值回调方法。

Listing 9.5 中的最后三个语句使用 `DependencyProperty` 类的 `Register()` 方法注册 `BoxHeight`、`BoxWidth` 和 `IsSquare` 依赖属性。`Register()` 方法的第一个参数是依赖属性的实际名称（不带 Property 后缀）。第二个参数是属性值的类型；第三个参数是所有者类型（包含依赖属性的类）；第四个参数是属性元数据对象；第五个参数是 validate value callback() 方法。

现在剩下的唯一事情就是用 CLR 包装器包装依赖属性并实现 get 和 set 访问器。你可以通过在 `Box` 类中添加以下代码片段来做到这一点：

```
public int BoxHeight
{
    get { return (int)GetValue(BoxHeightProperty); }
    set { SetValue(BoxHeightProperty, value); }
}
public int BoxWidth
{
    get { return (int)GetValue(BoxWidthProperty); }
    set { SetValue(BoxWidthProperty, value); }
}
public Boolean IsSquare
{
    get { return (Boolean)GetValue(IsSquareProperty); }
    set { SetValue(IsSquareProperty, value); }
}
```

在前面的代码片段中，`BoxHeight`、`BoxWidth` 和 `IsSquare` 依赖属性被实现为 CLR 属性，它们的 get 和 set 访问器调用 `GetValue()` 和 `SetValue()` 方法。

你现在可以在 XAML 或代码隐藏文件中将这些依赖属性作为 CLR 属性访问。

> NOTE
>
> 如果你想重置依赖属性的值，那么你可以使用 `ClearValue()` 方法。使用此方法，依赖属性不一定会变回属性元数据中指定的默认值。事实上，依赖属性回退到的值取决于当时可用的输入。

让我们继续学习一种特定类型的依赖属性，即附加属性。

## Attached Properties

附加属性是指你可以访问并设置给任何子对象或元素的依赖属性。附加属性帮助子元素向父元素提供有关其外观和呈现的信息。元素的附加属性可用于其所有子元素，每个子元素可以为同一个附加属性设置不同的值。

请注意，附加属性是在父或拥有元素中作为依赖属性实现的，并且可以在 XAML 和代码隐藏文件中访问。但是，除了样式触发器中的某些情况外，你不能在 XAML 中检索附加属性的值。与其他依赖属性不同，附加属性不会被包装在 CLR 属性中，因为它们必须可访问所有元素（父元素以及子元素）。这些元素应该能够分配不同的值。附加属性的一些示例包括 `Grid` 元素的 `Row` 和 `Column` 属性。

你也可以创建用户定义的附加属性。为此，父或拥有元素需要继承 `DependencyObject` 类，除非附加属性仅适用于其他元素而不适用于父元素。声明 `DependencyProperty` 类型的字段以创建附加属性，然后使用 `RegisterAttached()` 方法进行注册。你还需要通过两个静态方法实现属性的 get 和 set 访问器。附加属性的 get 访问器方法的语法如下：

```
public static type GetPropertyName (type target) {
    //return statement
}
```

在前面的语法中：

- public, static—表示 C# 关键字。

- type—表示有效类型。

- GetPropertyName—表示实现附加属性的 get 访问器方法的方法名。请注意，GetPropertyName 中的 PropertyName 表示附加属性的实际名称；因此，方法名称根据属性名称而变化。例如，如果附加属性的名称为 Center；那么实现其 get 访问器的静态方法命名为 GetCenter。

- target—表示获取附加属性值的对象或元素。

请注意，附加属性的 get 访问器需要有 return 语句。

附加属性的 set 访问器的语法如下：

```
public static type SetPropertyName( type target, type value) {
    //statements
}
```
