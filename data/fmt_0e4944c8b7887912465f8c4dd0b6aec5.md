
# 第 26 章 实例示例

## 26.1 使用 `STREAMBUF` 类使用文件符

### 26.1.1 成员函数

当使用 `istream` 对象构造 `Fistream` 对象时，`Fistream` 部分直接使用流的 `streambuf` 对象：

```cpp
Fistream::Fistream(std::istream &stream)
    : istream(stream.rdbuf()),
      d_filebuf(rdbuf()),
      d_width(0)
{}
```

当使用文件名构造 `Fistream` 对象时，`istream` 初始化器被赋予一个新的 `filebuf` 对象用作其 `strebuf`。由于类的数据成员在类基类构造之前没有初始化，`d_filebuf` 只能通过返回一个 `strebuf` 来初始化。然而，由于它实际上是一个 `filebuf`，使用了 `static_cast` 将 `rdbuf()` 返回的 `strebuf` 指针转换为 `filebuf`。

```cpp
Fistream::Fistream(char const *name, std::ios::openmode mode)
    : istream(name, mode),
      d_filebuf(static_cast<filebuf*>(rdbuf())),
      d_width(0)
{}
```

用于固定大小字段提取的 `Fistream` 类定义了一个 `istream` 类，支持固定大小字段和空格分隔的提取以及未格式化的读取调用。该类使用现有 `istream` 的包装器进行初始化，也可以使用现有文件的名称进行初始化。该类派生自 `istream`，允许所有 `istream` 支持的提取和操作。`Fistream` 定义了以下成员：

- `d_filebuf`：当 `Fistream` 从现有文件读取信息时使用的缓冲区。该缓冲区仅在那种情况下需要，并且是动态分配的，被定义为 `unique_ptr<filebuf>` 对象。
- `d_streambuf`：指向 `Fistream` `streambuf` 的指针。当 `Fistream` 通过名称打开文件时，它指向 `d_filebuf`。当使用现有的 `istream` 构造 `Fistream` 时，它指向现有 `istream` 的 `streambuf`。
- `d_iss`：用于固定字段提取的 `istream` 对象。
- `d_width`：指示要提取的字段宽度的 `size_t`。如果没有字段提取，则从 `istream` 基类对象使用标准提取获取信息。

### 26.1.3 从 istream 对象提取固定大小字段

通常在从 `istream` 对象 `>>` 提取信息时，标准提取运算符非常适合该任务，因为在大多数情况下，提取的字段是用空格或其他明显的方式分隔开的。但这在所有情况下并不成立。例如，当 Web 表单提交到处理脚本或程序时，接收程序可能会以 URL 编码的形式接收字段值：字母和数字保持不变，空格被发送为 `+`，所有其他字符后面都跟着一个 `%`，字符的 ASCII 值由其数字十六进制值表示。

在解码 URL 编码信息时，简单的十六进制提取将不起作用，因为提取会提取许多十六进制字符，而不是仅仅两个。由于字母 `a-f` 和 `0-9` 是合法字符，像 `My name is 'Ed'` 这样的文本经过 URL 编码后：

```
My+name=is%60Ed27
```

在结果中的十六进制值为 `60ed` 和 `27`，而不是 `60` 和 `27`。名字 `Ed` 从视图中消失了，这显然是我们不想要的。

在这种情况下，看到 `%` 后，我们提取 2 个字符，将它们放入 `istringstream` 对象中，并从 `istream` 对象中提取十六进制值。虽然有点麻烦，但双重保险。其他方法也是可能的。

用于固定大小字段提取的 `Fistream` 类定义了一个 `istream` 类，支持固定大小字段和空格分隔的提取以及未格式化的读取调用。该类使用现有 `istream` 的包装器进行初始化，也可以使用现有文件的名称进行初始化。该类派生自 `istream`，允许所有 `istream` 支持的提取和操作。`Fistream` 定义了以下成员：

- `d_filebuf`：当 `Fistream` 从现有文件读取信息时使用的缓冲区。该缓冲区仅在那种情况下需要，并且是动态分配的，被定义为 `unique_ptr<filebuf>` 对象。
- `d_streambuf`：指向 `Fistream` `streambuf` 的指针。当 `Fistream` 通过名称打开文件时，它指向 `d_filebuf`。当使用现有的 `istream` 构造 `Fistream` 时，它指向现有 `istream` 的 `streambuf`。
- `d_iss`：用于固定字段提取的 `istream` 对象。
- `d_width`：指示要提取的字段宽度的 `size_t`。如果没有字段提取，则从 `istream` 基类对象使用标准提取获取信息。

## 26.2. `fork` 系统调用

在 C 语言中，`fork` 系统调用是广为人知的。当程序需要启动新进程时，可以使用 `system` 函数。`system` 函数要求程序等待子进程。更通用的创建子进程的方法是使用 `fork`。

在本节中，我们将研究如何使用 C++ 类来封装如 `fork` 这样复杂的系统调用。接下来的大部分内容直接适用于 Unix 操作系统，讨论也集中于该操作系统。其他系统提供了类似的设施。以下内容与模板设计模式（Gamma 等，1995 年《设计模式》，Addison-Wesley）密切相关。

当调用 `fork` 时，当前程序会在内存中复制，创建一个新进程。复制完成后，两个进程都将从 `fork` 系统调用下方继续执行。两个进程可能会检查 `fork` 的返回值：原始进程称为父进程，新创建的进程称为子进程：

- 在父进程中，`fork` 返回由 `fork` 系统调用创建的子进程的进程 ID `PID`。
- 在子进程中，`fork` 返回 `0`。
- 如果 `fork` 失败，则返回 `-1`。

### 26.2.1 基础 Fork 类

基础 `Fork` 类应该向用户隐藏诸如 `fork` 等系统的所有后台管理细节。这里开发的 `Fork` 类正是如此。该类本身只确保 `fork` 系统调用的正确执行。通常，调用 `fork` 是为了启动子进程，通常归结为执行一个独立的进程。该子进程可以从其标准输入接受输入，并或向标准输出和或标准错误生成输出。`Fork` 并不知道这一切，也不需要知道子进程将做什么。`Fork` 对象应该能够启动它们的子进程。

`Fork` 的构造函数知道子进程应该执行什么操作。同样，它不知道父进程应该执行什么操作。对于这类情况，开发了模板方法设计模式。根据 Gamma 等人的观点，模板方法设计模式

> 在操作中定义算法的骨架，将某些步骤推迟给子类。模板方法允许子类定义某些类型的算法，而不改变算法的结构。

这种设计模式允许我们定义一个抽象基类，该基类已经为 `fork` 系统调用提供了基本步骤，并将 `fork` 系统调用其他部分的实现推迟给子类。

`Fork` 抽象基类具有以下特征：

- 它定义了一个数据成员 `d_pid`。在父进程中，该成员包含子进程的进程 ID，在子进程中它的值为 `0`。它的公共接口定义了两个成员：
  - 一个虚函数 `fork`，负责实际的派生，即创建新的子进程；
  - 一个虚析构函数 `~Fork` 函数体为空。

以下是 `Fork` 的接口：

```cpp
class Fork {
  int d_pid;
  public:
    virtual ~Fork();
    void fork();
  protected:
    int pid() const;
    int waitForChild(); // 返回状态
  private:
    virtual void childRedirections();
    virtual void parentRedirection();
    virtual void childProcess() = 0; // 纯虚成员
    virtual void parentProcess() = 0;
};
```

所有其他非虚成员函数都声明在类的 `protected` 区域，因此只能由派生类使用。它们是：

`pid()`：成员函数 `pid` 允许派生类访问系统 `fork` 的返回值：

```cpp
inline int Fork::pid() const
{
    return d_pid;
}
```

`waitChild()`：成员 `int waitChild` 可以被父进程调用，以等待其子进程的完成。该成员在类中声明。它的实现是：

```cpp
#include "fork.h"
int Fork::waitChild()
{
    int status;
    waitpid(d_pid, &status, 0);
    return WEXITSTATUS(status);
}
```

这种简单的实现返回子进程的退出状态。`waitpid` 阻塞直到子进程终止。

当进行系统调用时，父进程和子进程必须被区分。这两个进程的主要区别在于 `d_pid` 在父进程中变为子进程的进程 ID，而在子进程中变为 `0`。由于 `Fork` 接口强制要求派生类实现成员 `childProcess` 定义子进程操作 和 `parentProcess` 定义父进程操作 是纯虚函数。

如果父进程和子进程需要通过标准流进行通信，则需要重定向标准流。可以使用管道等设施。為了实现这种进程间通信，派生类可以实现：

- `childRedirection()`：如果子进程需要重定向标准流 `cin`, `cout`，则在子进程中重写它。默认实现为空。
- `parentRedirection()`：如果父进程需要重定向标准流 `cin`, `cout`，则在父进程中重写它。默认实现为空。

由于这些函数是虚函数，它们不应该内联实现，而应该在各自的源文件中实现：

```cpp
void Fork::childRedirections()
{}
void Fork::parentRedirection()
{}
```

### 26.2.2 父子进程

成员函数 `fork` 调用系统函数 `fork`。注意由于系统函数 `fork` 被同名的成员函数调用，必须使用 `::` 作用域运算符以防止递归调用自身。`fork` 的返回值决定了调用 `parentProcess` 还是 `childProcess`。`Fork` 的实现在调用 `childProcess` 之前调用 `childRedirections`，在调用 `parentProcess` 之前调用 `parentRedirections`：

```cpp
#include "fork.h"
void Fork::fork() {
    if ((d_pid = ::fork()) < 0)
        throw "Fork::fork() failed";
    if (d_pid == 0) // 子进程 pid == 0
    {
        childRedirections();
        childProcess();
        exit(0); // 我们不应该到达这里：childProcess() 应该退出
    }
    parentRedirections();
    parentProcess();
}
```

在 `fork` 中包含了类的内部头文件 `fork.h`。该头文件负责处理必要的系统头文件的包含，以及 `fork.h` 自身的包含。其实现如下：

```cpp
#include "fork.h"
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <wait.h>
```

存在一种情况：子进程继续运行，但父进程结束了。这是一个相当自然的事件：父进程往往比子进程先去世。在我们的语境下即 C++ 中，这被称为守护进程 `daemon` 进程。在守护进程中，父进程和子进程继续作为 `init` 进程的子运行。同样，当子实体死亡时，一个信号会被发送给它的继父 `init`。它不会产生僵尸，因为它捕获了所有其继子进程的终止信号。在可以使用 `Fork` 类的情况下，构建一个守护进程是非常简单的。

### 26.2.3 重新审视重定向

在之前的第 6.6.2 节中，使用 `ios::rdbuf` 成员函数对流进行了重定向。通过将一个流的 `streambuf` 赋值给另一个流，两个对象都访问同一个 `streambuf`，从而在编程语言层面实现了重定向。

这在 C++ 程序的上下文中可能是没问题的，但一旦我们离开该上下文，重定向就会终止。操作系统并不认识 `streambuf` 对象。当程序使用 `system` 系统调用启动子进程时，就会遇到这种情况。本节末尾的示例程序使用 C++ 将插入 `cout` 的信息重定向到文件，然后调用

```cpp
system("echo hello world")
```

来回显这句著名的文本。由于 `echo` 将其信息写入标准输出，如果操作系统能够识别 C++ 的重定向，那么该程序本该是被重定向的。

但重定向并没有发生。`hello` 仍然出现在程序的标准输出中，而重定向的文件保持原样。若要将 `hello` 写入重定向后的文件，必须在操作系统层面实现重定向。某些操作系统如 Unix 及其类提供了诸如 `dup` 和 `dup2` 的系统调用来实现此。这些系统调用的使用示例见第 26.2.5 节。

以下在使用 C++ 重定向后，在系统层面出现重定向失败的示例：

```cpp
#include <iostream>
#include <fstream>
#include <cstdlib>
using namespace std;
int main()
{
    streambuf *buf = cout.rdbuf(of.rdbuf());
    cout << "To of the stream\n";
    system("echo hello world");
    cout << "To of the stream\n";
    cout.rdbuf(buf);
}
/*
生成的输出：在文件 'output' 中
to of the stream
*/
```
