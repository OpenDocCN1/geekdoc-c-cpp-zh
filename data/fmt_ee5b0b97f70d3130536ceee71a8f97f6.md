## 类

在 C# 中，所有类都是用户定义的数据类型，被视为对象。所有对象都派生自一个单一的基类，称为 `System.Object`。它将所有对象定义给系统并以相同的方式对待它们。当你将对象传递给函数时，你可以通过使用它们作为关键字来了解你正在处理的对象类型。

C# 中的所有应用程序都基于一个类。与 C++ 或 C 不同，你不能拥有一个独立运行的简单函数。所有 C# 控制台应用程序都包含一个单一的静态方法，称为 `Main`。列表 2.4 显示了基本 C# 应用程序中类的代码：

### 列表 2.4：显示基本 C# 应用程序中的类

```
class Greetings
{
    static void Main()
    {
        System.Console.WriteLine("Hello world from C#");
    }
}
```

在列表 2.4 中，我们定义了一个名为 `Greetings` 的简单类，通常驻留在名为 `Greetings.cs` 的文件中。编译后，它形成一个名为 `Greetings.exe` 的可执行文件，可从命令行运行。此可执行文件从 `System` 命名空间获取 `Console` 对象并调用该对象的静态 `WriteLine()` 方法。此方法将字符串 `Hello world from C#` 作为输出返回到控制台设备。

## 接口

接口定义了一组可与任何类或结构相关的功能。C# 中的接口类似于 Java 中的接口，但在实现上更灵活。如果你熟悉 C++，则 C# 中的接口相当于 C++ 中的抽象基类。需要注意的是，你不能通过接口实例化对象。当你创建接口时，你定义了一组实现特定任务的功能。

你可以以与任何其他类类似的方式声明接口。然而，它使用 `interface` 关键字将其与其他类区分开来。接口的行为类似于包含方法声明的模板。这些方法本质上是抽象的，即方法体中没有方法的实现。实现特定接口的类需要使用该接口的所有方法；否则，编译器不会编译代码并引发错误。

你可以使用以下语法在 C# 中声明接口：

```
interface Interface_name
{
    //abstract method declarations in interface body
}
```

在前述语法中，`interface` 关键字声明了名为 `Interface_name` 的接口。接口将在第 5 章 C# 2010 中的面向对象编程中详细讨论。

## 委托

委托几乎等同于 C++ 或 C 中的函数指针。C# 包含两种对象——那些产生变化的对象和那些响应变化的对象。委托充当两种对象之间的隧道——将信息从一侧移动到另一侧。C# 委托是类方法，可以是静态或实例类方法。委托可以通过在所属对象中维护信息来跟踪其自身状态。

你可以使用 `delegate` 关键字创建委托，如以下代码片段所示：

```
public delegate int IntDelegate(int a);
```

简单的委托类型不是方法或函数。事实上，它是函数指针的定义。你不能直接使用委托；你需要将一个函数与其关联。

现在，让我们创建一个使用委托从外部源完成内部任务的类，如列表 2.5 所示：

### 列表 2.5：显示使用委托的类的代码

```
public delegate int IntDelegate(int a); //creating a delegate
class Calculator
{
    public static int SquareNum(int num)
    {
        return num * num;
    }
}
class DelegateUser
{
    static void Main(string[] args)
    {
        Console.WriteLine("Demonstrating a Simple Delegate");
        IntDelegate delObj = new IntDelegate(Calculator.SquareNum); /*initializing and calling a delegate */
        Console.WriteLine("The square of 5 is {0}", delObj(5));
        Console.ReadLine();
    }
}
```

在列表 2.5 中，我们创建了一个名为 `IntDelegate` 的委托。接下来，我们声明了一个类型为 `IntDelegate` 的变量 `delObj`，为其分配了新对象，并通过传递 `Calculator` 类的 `SquareNum()` 方法调用了委托。

## 指针类型

保存另一个类型的内存地址的变量称为指针。指针类型用作声明为指针的变量的数据类型。在 C# 中，指针类型提供的功能与 C 和 C++ 语言提供的功能相同。指针和引用都表示内存地址，但区别在于引用由垃圾收集器跟踪，而指针则不会。在保持引用上下文中的类型安全和安全性的同时，C# 使用委托而不是指针。然而，你可以使用 `unsafe` 关键字定义一个不安全上下文，在其中可以自由使用指针。指针类型可以使用以下语法声明：

```
type* identifier;
```

以下代码片段展示了如何创建指针变量：

```
char* c;
int*[] x;
```

前面代码片段的第一行说明 `c` 是指向 `char` 类型的指针，第二行说明 `x` 是指向整数类型的指针的一维数组。

使用指针时，务必记住：在方法之间使用指针可能会导致未定义的行为。你将在第 6 章“指针、委托和事件”中了解更多关于指针的内容。

## 类型转换

在编写 C# 应用程序时，你经常需要执行一个典型的任务，即将一种数据类型转换为另一种数据类型。对于这种类型的转换，需要使用类型转换。类型转换有两种形式：隐式转换和显式转换。

```

Single s = I;
```

## 装箱和拆箱

装箱和拆箱是 C# 类型系统中使用的两个重要概念。它们用于在 C# 的两大数据类型（值类型和引用类型）之间建立联系。所有值类型都存储在栈上，但在某些情况下，它们需要作为堆上的引用。由于引用类型存储在堆上，因此你可以将值类型转换为引用类型。这种转换称为装箱。

当值类型转换为基对象或接口时，就需要进行装箱。公共语言运行时（CLR）将值类型转换为引用类型。CLR 在堆上分配内存，然后将值类型实例复制到该内存中。装箱是一个昂贵的过程，因为它将对象从栈复制到堆，这需要大量的处理器周期以及堆上的空间。使用装箱的另一个缺点是，同一个对象在内存中的两个不同位置出现，这可能导致相互矛盾的状态。

拆箱是将对象类型或接口的实例转换回值类型的过程。这是通过使用拆箱显式完成的。以下代码片段演示了如何隐式完成装箱，而拆箱则必须通过使用类型转换显式完成：

```
int y = 123; //一个值类型
object obj = y; //装箱是隐式的
int z;
z = (int) obj; //拆箱是显式的（使用类型转换来拆箱）
```
