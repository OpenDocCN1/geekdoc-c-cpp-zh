
### 表面内存 (Surface Memory)

表面内存与纹理具有相似之处，包括硬件加速功能和空间访问优化。然而，它支持写操作，使其成为需要“读-修改-写”循环任务的多用途工具，例如原地图像编辑或涉及动态数据更新的模拟。

### 特性

与纹理内存不同，表面内存允许读和写操作，便于需要进行就地数据处理的算法。硬件插值：它继承了纹理内存的硬件插值和灵活寻址模式，使其适用于类似的空间局部化数据访问模式，但增加了修改数据的能力。

### 应用

表面内存对于需要动态纹理更新的图形渲染流水线，或在模拟数据随时间演变的科学计算场景中特别有用。它的能力允许高效地实现对空间结构化数据进行频繁“读-修改-写”循环的算法。

### 示例

以下示例了如何使用表面内存对 2D 数据数组进行原地操作。这可以代表一个简化的图像处理算法，根据某些标准修改像素值。

```cpp
// Define surface reference
cudaSurfaceType2D surfRef; 

__global void factor(cudaSurfaceObject_t surfRef, float factor) {
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    float data;
    // Read from the surface
    tex2DToArray(&data, surfRef, x, y);
    // Modify the data
    data *= factor; 
    // Write to the surface
    tex2DToArray(data, surfRef, x, y); 
}

int main() {
    // Create and bind surface
    cuArray_t cuArray;
    cudaChannelDesc channelDesc = cudaChannelDescToArray();
    int width, height; 
    cuArrayCreate(&cuArray, &channelDesc, width, height); 
    // Call kernel
    dim3 blocks(16, 16);
    dim3 grid((width + blocks.x - 1) / blocks.x, (height + blocks.y - 1) / blocks.y);
    factor<<<grid, blocks>>>(surfRef, 2.0f);
    // Clean up
}
```

在 CUDA 应用中理解并利用纹理和表面内存可以显著提高各种计算任务的性能，特别是涉及空间数据的任务。通过利用这些内存类型的独特功能，开发者可以实现优化的数据访问模式，并利用硬件加速更高效的计算。

# 4.10

### 统一内存 (Unified Memory)：简化内存管理

CUDA 演进过程中，旨在简化图形处理器（GPU）内存管理复杂性的关键进展之一是统一内存。该模型抽象了主机（CPU）和设备（GPU）之间内存的物理隔离，从而允许一个可以从 CPU 和 GPU 同时访问的统一内存视图。从本质上，统一内存允许开发者编写更少的代码来显式管理数据移动，从而提高了生产力，并使其能够更多地关注应用程序逻辑，而不是内存管理的细节。

统一内存通过利用托管内存空间实现了简单性，该空间由 NVIDIA 驱动程序根据访问模式和需求在主机和设备之间进行自动迁移。作为编程员，当使用统一内存 API 分配内存时，你就不再需要手动在主机和设备之间拷贝数据。统一内存封装的这种无缝数据迁移大幅提升了开发者的效率，特别是对于那些初接触 CUDA 编程的人来说。

### 分配统一内存

在统一内存空间中分配内存可以使用 `cudaMallocManaged` API。此调用动态分配可以从主机和 GPU 访问的内存，而不需要显式的数据传输命令。以下是操作方法：

```cpp
cudaError_t cudaMallocManaged(void **devPtr, size_t size, unsigned int flags);
```

`cudaMallocManaged` 函数接受三个参数：指向分配内存的指针、要分配的内存大小，以及一个决定内存附加行为的可选 `flags` 参数。通常使用 `cudaMemAttachGlobal` 标志，它指定分配的内存可以被支持统一内存的系统中所有 GPU 访问。

这是一个使用统一内存分配整数数组的示例：

```cpp
int *arr; size_t size = 100 * sizeof(int); cudaMallocManaged(&arr, size);
```

### 访问统一内存

从 GPU 或 CPU 访问统一内存非常简单，与访问任何动态分配的内存没有区别。CUDA 运行时会在后台处理任何必要的数据迁移。以下代码演示了如何从 CUDA 核函数访问统一内存：

```cpp
__global__ void kernel(int *arr, int value, int n) {
    int idx = threadIdx.x + blockIdx.x * blockDim.x;
    if (idx < n) { arr[idx] = value; }
}
```

需要注意的是，尽管统一内存简化了内存管理，但仍应优化访问模式。欠佳的访问模式会导致主机和设备之间频繁的数据迁移，引起性能下降。

### 同步与数据一致性

在启动访问统一内存的核函数后，必须确保主机和设备之间的数据一致性。CUDA 提供了 `cudaDeviceSynchronize` 函数，它会等待所有之前的设备活动完成，确保 GPU 进行的数据修改对主机可见，反之亦然。

尽管统一内存通过抽象数据移动极大地简化了内存管理，但开发者仍应该意识到底层内存访问模式及其对性能的影响。有效使用统一内存需要理解数据迁移何时以及如何发生，以及最小化开销的策略。尽管如此，对于许多应用程序，统一内存为 GPU 内存管理的复杂挑战提供了一个优雅且高效的解决方案，使开发者能够更多关注计算问题，而不是底层硬件的细节。

# 4.11

### 高效数据传输策略

主机（CPU）和设备（GPU）之间的数据传输是 CUDA 编程的一个关键方面。高效的数据传输对于实现 CUDA 应用的高性能至关重要，因为主机内存和设备内存之间的带宽通常是限制因素。在这一节中，我们将探索优化 CUDA 应用中数据传输的几种策略。

### 理解 PCIe 和内存带宽

为了优化数据传输，理解底层硬件至关重要。NVIDIA GPU 通过 PCIe（外设部件 Express）总线连接到 CPU。PCIe 总线有不同的代，每一代提供不同的数据传输速率。了解 PCIe 版本及其理论最大带宽对于估计数据传输的性能至关重要。

GPU 全局内存与其处理器之间的带宽远高于 CPU 和 GPU 之间 PCIe 的带宽。这种差异使得最小化 PCIe 上的数据传输以及确保必须传输的数据尽可能高效变得关键。

### 最小化数据传输

减少数据传输性能影响的一项基本策略是减少主机和设备之间需要传输的数据量。这涉及多种技术：

- 尽可能直接在设备上处理数据，以避免传回主机。
- 尽可能将数据传输与计算重叠。
- 构造应用程序以最大化设备上的数据重用，从而减少对数据传输的需求。

### 固定主机内存 (Pinning Host Memory)

为了实现更快速的数据传输，CUDA 允许分配固定（或页锁定）主机内存。固定内存不会被操作系统交换出，这使得主机和设备之间具有更高的传输率。

```cpp
size_t size;
cudaMallocHost(&ptr, size);
```

`cudaMallocHost` 是从固定内存传输数据比可页内存更快，因为 GPU 可以通过 DMA（直接内存访问）直接访问固定内存，而跳过 CPU。

### 使用统一内存 (Unified Memory)

从 CUDA 6 开始，NVIDIA 引入了统一内存（Unified Memory），通过提供一个 CPU 和 GPU 均可访问的内存空间简化了内存管理。统一内存会自动在主机（host）和设备（device）之间迁移数据，根据访问模式优化数据传输。

对于手动优化数据传输具有挑战性的复杂应用程序，统一内存特别有益。它还允许开发者编写更少的内存传输样板代码。然而，对于数据传输模式明确且可预测的应用程序，手动优化可能仍然提供更好的性能。

### 数据传输与计算的重叠

最大化 GPU 的利用率涉及数据传输与计算的重叠。这种技术允许 CPU 启动到 GPU 的数据传输，同时 GPU 对之前传输传输的数据执行计算。

CUDA 流（CUDA Streams）是实现计算与数据传输之间重叠的关键。CUDA 流是一系列在 GPU 上按顺序执行的操作序列。然而，不同的流彼此之间的操作可以是无序执行的，甚至是并发执行的。下面的示例演示了如何使用 CUDA 流来实现数据传输与计算的重叠：

```cpp
cudaStream_t stream; src, size, cudaMemcpyHostToDevice, stream;
blockSize, 0, stream>>>(...);
```

在这种情况下，`cudaMemcpyAsync` 在流中队列了一个非阻塞传输，内核执行（kernel execution）也被队列在同一个流中，允许数据传输与之前的内核执行或传输之间产生潜在的重叠。

### 选择正确的传输方向

最后，根据应用程序的需求选择正确的数据传输方向至关重要。CUDA 提供了不同类型的内存拷贝函数，包括：

- 从主机内存传输数据到设备内存。
- 从设备内存传输数据到主机内存。
- 在设备内存的不同区域之间传输数据。

合适的内存拷贝函数和传输方向的选择基于应用程序中的数据流。例如，在 GPU 上初始化数据结构通常需要这样做，而检索计算结果则是在主机完成。

高效的数据传输对 CUDA 应用的性能至关重要。通过理解并实现本节概述的策略，例如最小化数据传输、使用锁页（pinned）和统一内存、将数据传输与计算重叠以及选择正确的传输方向，开发者可以显著提高 CUDA 应用的速度和效率。

# 4.12

### 高级内存管理技术

有效的内存管理是 CUDA 高性能计算的基石。NVIDIA GPU 提供了复杂的内存层次结构，理解如何有效利用这一结构会极大影响你的 CUDA 应用的效率。本节探索了管理内存的高级技术，包括内核内的动态分配、利用内存填充（padding）和对齐，以及采用高效的数据传输策略。

### 内核内的动态分配

传统的 CUDA 内核内存分配是在内核启动之前在主机上进行的。然而，从计算能力（Compute Capability）2.x 开始，CUDA 引入了在内核代码中动态分配内存。此功能允许更灵活的数据结构，对于在运行时无法确定数据结构大小的应用程序特别有益。

要在内核内动态分配内存，可以使用 `malloc` 和 `free` 函数，类似于标准的 C 语言编程。这是一个示例：

```cpp
__global__ void dynamicAllocationExample() { ptr = * (ptr != NULL) {
Use the allocated memory = 5; } }
```

请记住，由于 `malloc` 和 `free` 相关的开销，内核中的动态内存分配应该谨慎使用。

### 内存填充与对齐 (Padding and Alignment)

内存对齐对于实现最佳访问速度至关重要，特别是在处理全局内存时。CUDA 架构倾向于访问在 32、64 或 128 字节边界上对齐的内存。未对齐或不规则的内存访问模式由于内存事务增加而严重影响性能。

改进内存访问模式的常用策略是对数据结构进行填充和对齐。例如，考虑以下结构：

```cpp
struct PaddedData { int x; y; z; w; // Padding 以对齐到 16 字节 };
```

通过对结构进行填充以确保其大小是偏好对齐边界的倍数，可以确保更高效的内存访问。

### 高效数据传输策略

主机与设备之间的数据传输通常是 CUDA 应用的瓶颈。为了最小化数据传输时间，采用高效策略至关重要，例如使用锁页（pinned）内存和利用异步数据传输。

锁页内存：锁页内存或页锁定内存是操作系统不会将其交换到磁盘的主机内存区域。与可分页内存相比，此类内存可以更快地传输到设备。分配和释放锁页内存，请使用：

```cpp
hostArray; // Use the allocated memory
```

异步传输：为了进一步最大化数据传输效率，可以异步执行数据传输，允许 GPU 在数据传输时进行计算。这在使用以下操作时特别有效：

```cpp
cudaStream_t stream; // Perform asynchronous transfer hostArray, size, cudaMemcpyHostToDevice, stream);
```

使用这些内存管理技术可以显著增强 CUDA 应用的性能。明智地结合这些策略至关重要，要考虑应用程序的特定需求和访问模式，以获得最佳结果。

## CUDA 中的内核编程 (Kernel Programming)

内核编程是 CUDA 应用开发的核心，允许在 GPU 上执行并行代码。本章引入了内核（kernels）的概念，详细介绍了了如何定义、执行和优化它们。它涵盖了内核编程的关键方面，如线程层次结构、内存访问和同步技术，为读者提供了关于如何有效利用纵 GPU 并行能力的全面理解。

# 5.1

### CUDA 内核简介 (Introduction to CUDA Kernels)

CUDA（统一设备架构）是由 NVIDIA 发明的一种并行计算平台和编程模型。它通过利用图形处理器（GPU）的力量实现了计算性能的巨大提升。CUDA 编程的核心是内核的概念，这是一种特殊设计的函数，调用时会在 GPU 上一组 CUDA 线程中并行执行。理解如何有效地编写和部署 CUDA 内核是充分利用 GPU 计算能力的基础。

CUDA 内核使用 `__global__` 关键字定义，它指示编译器该函数应编译为运行在 GPU 上而不是 CPU。与标准 C 函数不同，CUDA 内核可以由多个线程并行执行，每个线程都有自己的线程 ID。这些 ID 通常用于将线程映射到数据，实现跨大型数据集的并行处理。

内核的执行配置指定了应该使用多少线程和线程块。这在内核调用处使用三重角括号定义，如下例所示：

```cpp
threadsPerBlock>>>(argument1, argument2, ...);
```

在这里，`numBlocks` 代表应该使用的块数，`threadsPerBlock` 指定每个块内的线程数。

这些参数的最优数值取决于所解决的具体问题以及所使用的 GPU 硬件特性。

CUDA 编程中的核心概念是将线程组织成块（blocks）和网（grids）。同一块内的线程可以使用共享内存和同步原语进行相互通信并同步执行。块被组织成一个网，每个块可以使用其块 ID 来标识。线程、块和网的层级结构允许将并行计算灵活高效地映射到 GPU 架构上。

在 CUDA 核函数（kernel）内部访问内存时，可以使用多种类型的内存，每种内存都有自己的作用域、生命周期和缓存行为。这些包括：

- 全局内存：所有线程均可见，无缓存。
- 共享内存：同一块内线程之间共享，速度远快于全局内存。
- 局部内存：每个线程私有，存储在全局内存中。
- 常量内存和纹理内存：针对特定访问模式进行了缓存和优化。

有效利用内存类型对于优化 CUDA 核内核的性能至关重要。糟糕的内存访问模式会导致严重的瓶颈，因为内存带宽通常是 GPU 计算的限制因素。

线程和块之间的同步是 CUDA 编程的另一个重要方面。在块内部，线程可以使用 `_syncthreads()` 函数进行同步，确保块中的所有线程都到达执行的相同点。跨块同步更具挑战性，通常依赖于核函数执行的完成或对共享数据结构使用原子操作。

总结来说，CUDA 核函数是在 GPU 上执行并行计算的强大工具。通过在考虑线程组织、内存访问和同步的情况下仔细设计内核函数，开发者可以充分释放 GPU 计算的潜力，应用于广泛的领域。

## 5.2

### 定义和启动内核函数

CUDA C 编程中的一个基本概念是内核函数的定义和部署。内核函数本质上是一个带有 `__global__` 修饰符声明的函数，设计用于在 GPU 上执行。在本节中，我们将深入探讨定义和启动内核函数的细微差别，为理解 CUDA 如何利用并行计算提供坚实的基础。

### 定义内核函数

在 CUDA 中定义内核函数时，必须在其声明之前加上 `_global_` 修饰符。这告诉 CUDA 编译器该函数是一个内核函数，可以从宿主机（host）调用或启动，并在设备（GPU）上执行。以下是内核函数定义的一个骨架表示：

```cpp
__global__ void KernelName(parameters){ 每个线程将执行的内核代码 }
```

必须注意，内核函数必须返回 void。内核函数的参数可以是任何类型，但它们是按值传递的，确保每个线程都获得自己的副本。

### 启动内核函数

内核函数的调用使用一种特定的语法，该语法指明了执行配置，包括线程数和线程块数。启动内核函数的语法如下：

```cpp
kernel<<<numBlocks, blockSize>>>(parameters);
```

- 用于内核函数执行的块数。
- 每个块中的线程数。

这种语法是 CUDA 特有的，对于指定如何将并行计算分发到 GPU 架构上至关重要。

### 示例：向量加法

让我们考虑一个简单的示例，它展示了 CUDA 内核函数的定义和启动，旨在执行向量加法。

```cpp
// 定义向量加法的内核函数
__global__ void vectorAddition(float *A, const float *B, float *C, int N) { 
    int i = threadIdx.x + blockIdx.x * blockDim.x; 
```
