
首先，如果你有像这样的嵌套结构，你可以顺着变量名向下找到初始化子结构的成员：

```
struct foo x = {.a.b.c=12};
```

让我们来看一个例子：

```c
#include <stdio.h>

struct cabin_information {
    int window_count;
    int o2level;
};

struct spaceship {
    char *manufacturer;
    struct cabin_information ci;
};

int main(void) {
    struct spaceship s = {
        .manufacturer="General Products",
        .ci.window_count = 8, // <-- 嵌套初始化！
        .ci.o2level = 21
    };
}
```

```c
printf("%s:%d seats, %d oxygen\n",
    s.manufacturer, s.window_count, s.ci.o2level);
}
```

查看第 16-17 行！这就是我们如何在 `struct spaceship` 的定义中初始化 `struct cabin_information` 成员的。

这是该初始化器的另一种选择——这次我们将使用看起来更标准的写法，但两种方法都有效：

```c
struct spaceship s = {
    .manufacturer="General Products",
    .ci={
        .window_count = 8,
        .o2level = 21
    }
};
```

现在，如果上面的信息还不够精彩，我们也可以其中混合数组初始化器。

让我们修改它以包含一个乘客信息数组，也可以查看初始化在其中是如何工作的。

```c
#include <stdio.h>
```

```c
struct passenger {
    char *name;
    int covid_vacinated; // 布尔值
}
```

```c
#define MAX_PASSENGERS 8
```

```c
struct spaceship {
    char *manufacturer;
    struct passenger passenger[MAX_PASSENGERS];
}
```

```c
int main(void) {
    struct spaceship s = {
        .manufacturer="General Products",
        .passenger = {
            // 一次初始化一个字段
            [0].name = "Gridley, Lewis",
            [0].covid_vacinated = 0,
            // 或者一次性初始化
            [7] = {.name="Brown, Teela", .covid_vacinated=1},
        }
    }
}
```

```c
printf("Passengers for %s\n", s.manufacturer);
```

```c
for (int i = 0; i < MAX_PASSENGERS; i++) {
    if (s.passenger[i].name != NULL)
        printf(" %s (%svacinated)\n", s.passenger[i].name, s.passenger[i].covid_vacinated ? "yes" : "not");
}
}
```

## 20.2 匿名结构体

这些是没有名字的“结构体”。我们在 `typedef` 部分也提到过它们，但在这里我们会复习一下。

这是一个普通的结构体：

```c
struct animal {
    char *name;
    int leg_count, speed;
};
```

这是它的匿名等效物：

```c
struct { // <-- 没有名字！
    char *name;
    int leg_count, speed;
};
```

好吧。所以我们有一个结构体，但它没有名字，所以我们没有办法在以后使用它？看起来完全没意义。

诚然，在某个例子中确实是如此。我们仍然可以使用几种方法。

一种很罕见，但由于匿名结构体代表了一种类型，我们只需要在后面加上一些变量名并使用它们。

```c
struct { // <-- 没有名字！
    char *name;
    int leg_count, speed;
} a, b, c; // 3个该结构体的变量
```

`a.name = "antelope"; // 例如`

`c.leg_count = 4;`

但这并不用。

更常见的方法是将匿名结构体与 `typedef` 使用，以便我们以后可以使用它（例如将变量传递给函数）。

```c

typedef struct { // <-- 没有名字！

    char *name;

    int leg_count;

} animal; // 新类型：animal

```

`animal a, b, c;`

`a.name = "antelope"; // 例如`

`c.leg_count = 4;`
```

就个人而言，我不使用匿名结构体。我认为在声明中于变量名之前看到整个 `animal` 结构体会更舒服。

但这仅仅是我的观点而已。

### 20.3 自引用

对于自引用结构体，你必须使用指向相同类型的指针。这在链表和树中很常见。

```c
struct node {
    int data;
    struct node *next;
};
```

### 20.4 灵活数组成员

灵活数组成员是结构体末尾的一个没有指定大小的数组。这允许结构体拥有一个变大小的数组。它必须是结构体的最后一个成员。

```c
struct tree_node {
    int value;
    struct tree_node *left;
    struct tree_node *right;
    int data[]; // 灵活数组成员
};
```

要使用它，你需要分配结构体加上你需要的元素的内存：

```c
struct tree_node *root = malloc(sizeof(struct tree_node) + sizeof(int) * 10);
```

### 20.5 填充字节

注意，C 允许根据其需要在结构体内部添加填充字节。你不能保证它们在内存中是相邻的。

让我们来看这个。我们输出两个数字。一个是各个字段类型 `sizeof` 之和。另一个是整个结构体的大小。

人们期望它们是相同的。总大小应该是各个部分之和，对吧？

```c
#include <stdio.h>

struct foo {
    int a;
    char b;
    int c;
    char d;
};

int main(void) {
    printf("%zu\n", sizeof(struct foo));
}
```

在我们的系统上，这输出：

10

16

它们并不相同！编译器添加了 6 字节的填充以提高性能。可能在你的编译器上会得到不同的输出，除非你强制要求，否则你无法确定没有填充。

## 20.6 offsetof

在上一节中，我们看到编译器可以在结构体内部注入填充字节。

但如果我们需要知道它们在哪里呢？我们可以使用在 `<stddef.h>` 中的 `offsetof` 来测量。

让我们修改上面的代码以打印结构体中各个字段的偏移量：

```c
#include <stdio.h>
#include <stddef.h>

struct foo {
    int a;
    char b;
    int c;
    char d;
};

int main(void) {
    printf("%u\n", offsetof(struct foo, a));
    printf("%u\n", offsetof(struct foo, b));
    printf("%u\n", offsetof(struct foo, c));
    printf("%u\n", offsetof(struct foo, d));
}
```

对我来说，它的输出是：

+   0

4

8

12

这意味着我们为每个字段都使用了 4 个字节。这有点奇怪，因为 `char` 只有 1 字节，对吧？编译器在 `char` 之后放置了 3 个字节的填充字节，使得所有字段都是 4 字节长。这这会在我的 CPU 上运行。

## 20.7 伪 OOP

使用结构体（struct）有一种有点像面向对象（OOP）的方法可以做。

由于指向结构体的指针等于指向结构体第一个元素的指针，你可以自由地将指向结构体的指针转换为指向其第一个元素的指针。

这意味着我们可以设置类似这样的情况：

```c
struct parent {
    int a, b;
};

struct child {
    struct parent super; // 必须是第一个
    int c, d;
};
```

那么，我们就能将指向 `struct child` 的指针传递给一个期望该指针或指向 `struct parent` 指针的函数！

因为 `parent super` 是 `struct child` 中的第一个项，所以任何 `struct child` 的指针都等于指向该 `super` 字段的指针。

让我们在这里举例子。我们将像上面那样创建结构体，但我们将一个指向 `struct child` 的指针传递给一个需要 `struct parent` 指针的函数……它仍然可以工作。

> 顺便说一下，`super` 不是关键字。我只是借用了一些 OOP 的术语。

## 第20章 结构体 II：更有趣的结构体

```c
#include <stdio.h>

struct parent {
    int a, b;
};

struct child {
    struct parent super; // 必须是第一个
    int c, d;
};

// 将参数设为 void*，以便我们可以将任何类型传递进去
// （即 struct parent 或 struct child）
void print_parent(void *p)
{
    // 期望一个 struct parent - 但一个 struct child 也可以工作
    // 因为指针指向结构体第一个字段
    // 中的 struct parent：
    struct parent *self = p;
    printf("Parent: %d, %d\n", self->super.a, self->super.b);
}

void print_child(struct child *self)
{
    printf("Child: %d, %d\n", self->c, self->d);
}
```

```c
int main()
{
    struct child c = {.super.a=1, .super.b=2, .c=3, .d=4};

    print_parent(&c);
    print_child(&c); // 即使是 struct child 也可以工作
}
```

看到我们在 `main()` 的最后一行做了什么了吗？我们调用了 `print_parent()`，但传递了一个 `struct child*` 作为参数！尽管 `print_parent()` 需要参数指向 `struct parent`，但我们之所以成功了，是因为 `struct child` 中的第一个字段是一个 `struct parent`。

再次，这之所以可行，是因为指针的值与指向结构体第一个字段的指针的值相同。

这一切都取决于规范中的部分内容：

> §6.7.2.11 [...] 指向结构对象的指针在经过适当转换后，指向其初始成员 [...]，反之亦然。

以及

> §6.7.5 对象的存储值应仅通过具有以下类型之一的左值表达式进行访问：

- * 与对象的有效类型兼容的类型

- [...]

以及我的假设——“适当转换”意味着“强制转换”到初始成员的有效类型。

## 20.8 位域 (Bit-Fields)

根据我的经验，这些很少被使用，但你偶尔会看到它们，特别是在那些将位打包进更大空间中的低级应用中。

让我们来看一些代码来演示一个用例：

```c
#include <stdio.h>

struct foo {
    unsigned int a;
    unsigned int b;
    unsigned int c;
    unsigned int d;
};
```

```c
int main(void) {
    printf("%u\n", sizeof(struct foo));
}
```

对我来说，它输出了 16。这是合理的，因为在我的系统上 `unsigned` 是 4 字节。

但如果我们知道存储在 `a` 和 `b` 中的所有值将存储在 5 位中，`c` 和 `d` 中的值将存储在 3 位中呢？总共 16 位。如果我们只使用 16 位，为什么要为它们预留 128 位呢？

嗯，我们可以让 C 语言尝试打包这些值。我们可以指定值可以占据的最大位数（从 1 直到包含类型的大小）。

我们通过在字段名后加上冒号，然后跟位宽来实现。

```c
struct foo {
    unsigned int a:5;
    unsigned int b:5;
    unsigned int c:3;
    unsigned int d:3;
};
```

现在当我询问我的 `struct foo` 有多大，它告诉我是 16 字节，但实际上只有 4 字节。它将这 4 个值“压缩”到了 4 字节中，这节省了四倍的内存。

权衡是，5 位字段只能持有 0-31 之间的值，而 3 位字段只能持有 0-7 之间的值。毕竟，生活就是充满妥协。

### 20.8.1 非相邻位域

注意：C 只会合并相邻的位域。如果它们被非位域中断，你得到的将不仅是节省空间，而是：

```c
struct foo {
    unsigned int a:1;
    // 因为 a 与 c 不相邻。
    unsigned int b;
    unsigned int c:1;
    unsigned int d;
};
```

在示例中，由于 `a` 与 `c` 不相邻，它们都分别“打包”在各自的领地里。

所以 `a`、`b`、`c` 和 `d` 各占一个。由于我的 `int` 是 4 字节，总共是 16 字节。

# 第 20 章 结构体 II：更有趣的结构体

由于联合体（union）的成员共享相同的内存，向其中一个成员写入必然影响其他成员。而且如果你从写入另一个成员的地方读取其中一个，你将得到一些奇怪的副作用。

```c
#include <stdio.h>
```

```c
union foo {
  float b;
  short a;
};

int main(void) {
  union foo x;

  x.b = 3.14159;

  printf("%f\n", x.b); // 3.14159, 理所当然

  printf("%d\n", x.a); // 但这个又是什么？
}
```

在我的系统上，它的输出是：

3.141590

4048

因为在底层，float 3.14159 的对象表示与 short 4048 的对象表示是相同的。在我的系统上是如此。你的结果可能会有所不同。

### 20.9.2 联合体的指针

如果你有一个指向联合体的指针，你可以将指针强制转换为联合体中任何字段类型的指针，并借此获取值。

在这个示例中，我们看到联合体内部包含整数和浮点数。我们获取指向联合体的指针，并将它们强制转换为 *int* 和 *float* 类型（强制转换会消除编译警告）。然后，如果对这些指针进行解引用，就会发现这些值是直接存储在联合体中的。

```c
#include <stdio.h>
```

```c
union foo {
  int a, b, c, d, e, f;
  float g, h;
  char i, j, k, l;
};

int main(void) {
  union foo x;

  int *foo_int_p = (int *)&x;
  float *foo_float_p = (float *)&x;

  x.a = 12;
  printf("%d\n", x.a);      // 12
  printf("%d\n", *foo_int_p); // 12，再次如此
}
```

反之亦然。如果我们有一个指向联合体内部类型的指针，可以可以将其转换为指向联合体的指针并访问其成员。

```c
union foo x;
int *foo_int_p = (int *)&x;      // 指向 int 字段的指针
union foo *p = (union foo *)foo_int_p;  // 回到指向联合体的指针

p->a = 12;                      // 这一行与...
x.a = 12;                        // 相同。
```

这一切告诉我们，在底层，联合体中的所有这些值都从内存中的同一个位置，这与整个联合体的位置相同。

## 20.9.3 联合体中的公共初始序列

如果你有一个结构体联合体，且所有这些结构体都以一个共同的初始序列开头，那么从该联合体的任何成员中访问该序列的成员是有效的。

什么？这里有两个具有公共初始序列的结构体：
