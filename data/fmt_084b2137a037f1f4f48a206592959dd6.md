## 深入探讨

Web 服务可以定义为托管在 Internet 上的软件应用程序的独立且自包含的单元。Web 服务实现特定的功能来执行应用程序的业务逻辑。Web 服务可用于实现各种功能，例如为公司员工准备工资单、计算所得税、播报天气预报以及提供最新新闻。在 .NET Framework 4.0 中，可以创建 Web 服务。在 ASP.NET 4.0 中创建的 Web 服务称为 ASP.NET 4.0 Web 服务，它包含一个基础结构，该基础结构含有用于为 Web 服务实现基本功能的各种组件，例如定位 Web 服务、调用 Web 服务等。在创建 Web 服务时，还可以使用 ASP.NET Web 服务的代码模型和属性。你还可以创建使用 ASP.NET AJAX 功能的 Web 服务。此外，在创建的 Web 服务中还需要加入检查未授权访问的安全性措施。

在本章中，你将了解 Web 服务、ASP.NET Web 服务的基础结构、ASP.NET Web 服务的代码模型、Web 服务属性、保护 Web 服务，以及 ASP.NET AJAX 与 Web 服务的结合使用。你还将学习如何创建 ASP.NET Web 服务、如何使用 ASP.NET Web 服务、如何在 Web 服务之间共享数据、如何在 Web 服务之间进行异步通信、如何使用支持 ASP.NET AJAX 的 Web 服务，以及如何将 `UpdatePanel` 控件与 Web 服务配合使用。

## Web 服务简介

Web 服务是一种可编程的实体，用于通过 Internet 为应用程序提供特定功能。假设你想在 Internet 上托管一个网站，该网站可计算个人的单利、复利和所得税。要实现这一点，可以使用一个 Web 服务来计算单利和复利，使用另一个 Web 服务来计算所得税。在这种情况下，使用 Web 服务的优势在于，你无需在网站中编写计算单利、复利和所得税的代码。相反，你只需使用提供这些功能的 Web 服务即可。在网站中使用 Web 服务之前，需要先订阅该 Web 服务。

Web 服务允许网站与其他网站通信，无论这些网站是用什么编程语言创建的。此外，任何应用程序都可以访问 Web 服务，无论该应用程序运行在何种软件和硬件平台上，因为 Web 服务遵循通用行业标准，例如简单对象访问协议（SOAP）和 Web 服务描述语言（WSDL）。Web 服务没有任何用户界面；它只包含为使用者提供特定服务的逻辑。Web 服务在使用者（客户端）和 Web 服务提供者之间提供了一种抽象。Web 服务只需要了解客户端和 Web 服务提供者的输入、输出和位置信息。在引入 Web 服务之前，开发人员使用组件对象模型（COM）和分布式组件对象模型（DCOM）等技术在另一个应用程序中使用一个应用程序的功能。这些技术允许开发人员一次性创建代码组件并打包这些组件，以便多个开发人员可以在多个应用程序之间共享它们。然而，使用这些组件存在一些根本性的困难。其中一个困难是这些组件需要在每台客户端计算机上进行物理分发并显式注册。Web 服务克服了这些困难，因为它们可以在多个网站之间共享，而无需安装在每台客户端计算机上。

Web 服务之所以流行，是因为它们提供了基于组件的技术所不具备的额外功能。与 COM 和 DCOM 相比，Web 服务的优势如下：

- Web 服务使用简单；因此，它们可以在各种平台上实现
- Web 服务是松散耦合的；因此，其接口和方法可以扩展
- Web 服务不携带任何状态信息，因此可以同时处理多个请求

Web 服务最适合在跨平台通信或在服务器与客户端之间建立可信连接时使用。此外，在以下情况下使用 Web 服务也是一种很好的做法：

- 使用 ASP.NET 的缓存功能
- 使用安全套接字层（SSL）安全或 Windows 身份验证
- 将 ASP.NET Web 应用程序与第三方系统集成

## ASP.NET Web 服务的基础结构

ASP.NET Web 服务的基础结构为 Web 服务提供了一个简单的应用程序编程接口（API），用于创建和理解 SOAP 消息，从而帮助调用远程方法。Web 服务不能依赖于操作系统、对象模型和编程语言的选择。与其他基于 Web 的技术一样，Web 服务应该是松散耦合的，能够在需要时进行通信，并具有通用的数据格式来在服务及其用户之间传输数据。Web 服务基础结构中包含的机制如下：

- 包含一个目录，为 Web 服务提供者提供中心位置
- 包含一种发现机制，用于定位 Web 服务
- 包含服务描述，用于了解如何使用这些 Web 服务
- 包含标准线路格式（协议），用于在 Web 服务及其用户之间传输数据

### Web 服务目录

Web 服务目录为 Web 服务提供者提供了一个中心位置。换句话说，它是 Web 服务用户（使用者）可以轻松找到其他公司和组织提供的服务的地方。如果不使用任何资源，很难搜索 Web 服务。Web 服务目录提供了集中位置，你可以在其中发布有关你的 Web 服务的信息。一个 Web 服务可以作为其他 Web 服务的目录，并将查询结果提供给 Web 服务客户端。你需要 Web 服务目录来了解由多个组织或特定组织提供的 Web 服务。可以使用名为通用描述、发现和集成（UDDI）的规范来发布和发现 Web 服务。与 UDDI 关联的架构为 Web 服务定义了四种类型的信息：业务、Web 服务、绑定和规范。这些信息类型使开发人员能够使用已发布的 Web 服务。

### Web 服务发现

Web 服务发现提供了定位 Web 服务的能力。该组件通过 WSDL 定位描述特定 Web 服务的文档。如果你想在网站中使用 Web 服务，首先需要知道该 Web 服务的位置。另一方面，如果你希望其他人使用你的 Web 服务，他们也需要知道你的 Web 服务的位置。在这种情况下，必须有一种搜索（发现）机制，该机制可以定位所需的 Web 服务。以下两种方法用于搜索 Web 服务的统一资源定位符（URL）：

- Web 服务发现工具（`Disco.exe`）——用于发布和发现 Web 服务。该工具发现 Web 服务器上所有 Web 服务的 URL，并将它们列在一个称为 DISCO 文件（扩展名为 `.disco` 的文件）的文件中。组织可以在其 Web 服务器上发布自己的 DISCO 文件。客户端可以访问此文件，以了解组织提供的 Web 服务类型。
- UDDI——集中式目录，不同组织提供的 Web 服务都在此发布。它是一种平台无关的方法，内置于 .NET 平台中。UDDI 目录相对于 DISCO 文件的一个优势在于，该目录提供了一个单一位置，客户端可以在其中搜索不同组织提供的 Web 服务。

以下是 UDDI 的一些重要特性：

- 充当目录并存储有关 Web 服务的信息
- 使用万维网联盟（W3C）和 Internet 工程任务组（IETF）的 Internet 标准，例如可扩展标记语言（XML）、超文本传输协议（HTTP）和域名服务器（DNS）协议
- 使用 WSDL 描述 Web 服务的接口
- 通过 SOAP 进行通信

使用 UDDI 的一些好处是：

- 帮助从当前在线的大量商业组织中找到合适的商业组织
- 一旦发现首选业务，即可实现商务交易
- 帮助接触新客户并增加对现有客户的访问
- 帮助扩展产品供应和市场覆盖范围
- 允许快速参与全球 Internet 经济
- 在单一、开放、安全的环境中，以编程方式描述 Web 服务和业务流程

### Web 服务描述

Web 服务描述以 XML 格式提供 Web 服务的描述，这种格式称为 WSDL。WSDL 文档定义了消息格式，例如 HTTP-GET 和 HTTP-POST，以促进 Web 服务与客户端之间的通信。消息模式决定了客户端和服务之间如何交换消息。Web 服务定义并支持一些消息模式，例如请求/应答、单向或双工。Web 服务的行为取决于这些消息模式，从理论上讲，这些模式规定了 Web 服务用户在向其提交消息时的要求。现在，我们来更详细地讨论 WSDL。WSDL 是一种基于 XML 的语言，用于定义 Web 服务。每个 Web 服务都包含一个相应的 WSDL 文档，该文档指定了 Web 服务的位置，并列出了该 Web 服务可以执行的所有服务。

WSDL 文档是一个简单的 XML 文档，包含不同的 XML 元素来定义 Web 服务。WSDL 文档的主要元素列于表 18.1：

```xml
<wsdl:message>
```
