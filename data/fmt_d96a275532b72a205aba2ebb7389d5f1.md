
# 第 15 章 朋友类、异常及更多

它们并没有真正违背面向对象编程的精神。相反，它们为公共接口提供了灵活性。

## 朋友类

你什么时候想让一个类成为另一个类的朋友呢？让我们来看一个例子。假设你想编写一个简单的电视和遥控器仿真程序。你决定定义一个 `Tv` 类来表示电视，并定义一个 `Remote` 类来表示遥控器。显然，这些类之间应该存在某种关系，但是什么关系呢？遥控器不是电视，反之亦然，所以公共继承的“是”关系并不适用。它也不是对方的组件，因此包含关系或私有/保护继承的“有”关系也不适用。事实是，遥控器可以修改电视的状态，这使得 `Remote` 类成为 `Tv` 类的朋友。

让我们定义 `Tv` 类。你可以用一组状态成员来表示电视——即描述电视各个方面的变量。以下是一些可能的状态设置：

- 开启/关闭
- 频道设置
- 音量设置
- 有线或天线调谐模式
- 电视调谐器或 A/V 输入

调谐模式反映了这样一个事实：在美国，频道 14 及以上频道的间距在有线接收和 UHF 广播接收之间是不同的。输入选择在电视和 DVD 之间进行切换。某些电视可能提供更多选择，例如多个 DVD/Blu-ray 输入，但此列表仅用于本示例的演示。

此外，电视还有一些不是状态变量的参数。例如，电视可以接收的频道数量各不相同，你可以包含一个成员来跟踪该值。

接下来，你必须为该类提供更改设置的方法。如今许多电视将控制按钮隐藏在面板后面，但大多数电视仍然可以在没有遥控器的情况下切换频道和开启/关闭。然而，通常情况下你一次只能向上或向下切换一个频道，而不能随机选择频道。通常，有一个按钮用于增加音量，另一个按钮用于减少音量。

遥控器应该复制电视内置的控制功能。它的许多方法可以使用 `Tv` 的方法来实现。此外，遥控器提供了随机访问选择频道的功能。也就是说，你可以直接从频道 2 跳到频道 20，而不需要经过中间的所有频道。此外，许多遥控器在两种或两种模式下工作，例如作为电视控制器和 DVD 控制器。

这些考虑建议采用如列表 15.1 所示的定义。该定义包含了几个定义为枚举的常量。接的语句将 `Remote` 声明为朋友类：

```
friend class Remote;
```

朋友类声明可以出现在公共、私有或保护区域；其位置没有区别。由于 `Remote` 类提到了 `Tv` 类，编译器在处理 `Remote` 类之前必须知道 `Tv` 类。实现这一点的最简单方法是先定义 `Tv` 类。或者，你可以使用前向声明；我们很快会讨论这个选项。

## 列表 15.1 tv.h

```cpp
// tv.h -- Tv 和 Remote 类
#ifndef TV_H_
#define TV_H_

class Tv {
public:
    friend class Remote; // Remote 可以访问 TV 的私有部分
    enum (Off, On);
    enum (MinVal, MaxVal = 20);
    enum (Antenna, Cable);
    enum (TV, DVD);

    Tv(int s = Off, int mc = 125) : state(s), volume(5),
        maxchannel(mc), channel(2), (Cable), input(TV) {}
    void onoff() {state = (state == On) ? Off : On;}
    bool ison() const {return state == On;}
    bool vol();
    bool volold();
    void changechannel();
    void changeinput();
    void set_mode() {mode = (mode == Antenna) ? Cable : Antenna;}
    void set_input() {input = (input == TV) ? DVD : TV;}
    void settings(); // 显示所有设置
private:
    int state; // 开启或关闭
    int volume; // 假设是数字化的
    int maxchannel; // 最大频道数
    int channel; // 当前频道设置
    int mode; // 广播或有线
    int input; // TV 或 DVD
};
```

## 列表 15.2 Remote.h

```cpp
class Remote
{
private:
    int mode; // 控制电视或 DVD
public:
    Remote(int m = Tv::Tv) : mode(m) {}
    bool volup(Tv & t) { return t.volup(); }
    bool voldown(Tv & t) { return t.voldown(); }
    void off(Tv & t) { t.off(); }
    void chanup(Tv & t) { t.chanup(); }
    void chdown(Tv & t) { t.chdown(); }
    void set_channel(Tv & t, int c)
    void set_mode(Tv & t);
    void set_input(Tv & t);

```

## 列表 15.3 main.cpp

```cpp
#include <iostream>
#include "tv.h"
#include "remote.h"

int main() {
    Tv tv;
    std::cout << "Initial settings: " << std::endl;
    tv.settings();

    Remote remote;
    std::cout << "\nIncreasing volume: " << std::endl;
    remote.volup(tv);
    tv.settings();

    std::cout << "\nChanging channel to 20: " << std::endl;
    remote.set_channel(tv, 20);
    tv.settings();

    std::cout << "\nTurning off TV: " << std::endl;
    remote.off(tv);
    tv.settings();

    return 0;
}
```

然而，为了让编译器处理这条语句，它必须已经看到 `Remote` 的定义。否则，它不知道 `Remote` 是一个类，也不知道 `set_chan()` 是该类的方法。这暗示 `Remote` 的定义在 `Tv` 定义之上。但 `Remote` 方法操作 `Tv` 对象这一事实表明 `Tv` 定义应该出现在 `Remote` 定义之前。解决这种循环依赖的方法之一是使用前向声明。为此，你在 `Remote` 定义上方插入以下语句：

```cpp
class Tv;
// 前向声明
```

这提供了如下安排：

```cpp
class Tv; // 前向声明
class Remote { ... };
class Tv { ... };
```

你可以使用下面的安排代替吗？

```cpp
class Remote; // 前向声明
class Tv { ... };
class Remote { ... };
```

答案是否定的。正如前面提到的，原因是当编译器看到 `Tv` 类声明中将一个 `Remote` 方法声明为友元时，编译器需要预先查看过 `Remote` 类的通用声明，特别是 `set_chan()` 方法的声明。

另一个困难仍然存在。在列表 15.1 中，`Remote` 的定义包含了如下内联代码：

```cpp
void onoff(Tv & t) { t.onoff(); };
```

这调用了一个 `Tv` 方法，编译器此时需要看到 `Tv` 类声明，以便它知道 `Tv` 拥有哪些方法。正如你所看到的，声明必须在 `Remote` 声明之后。这个问题的解决方法是限制 `Remote` 仅包含方法声明，并将实际定义放在 `Tv` 类之后。这导致了如下的顺序：

```cpp
class Tv; // 前向声明
class Remote { ... }; // Tv 使用方法作为原型的
class Tv { ... };
// 在此处放置方法定义
```

`Remote` 的原型看起来像这样：

```cpp
void onoff(Tv & t);
```

编译器在检查此原型时，只知道 `Tv` 是一个类，而前向声明提供了这一信息。当编译器到达实际的方法定义时，它已经读取了 `Tv` 类声明，并拥有了编译这些方法所需的额外信息。通过在方法定义中使用 `inline` 关键字，你仍然可以使这些方法成为内联方法。列表 15.4 显示修改后的头文件。

## 列表 15.4 tvfm.h

```cpp
// tvfm.h -- 使用友元成员的 Tv 和 Remote 类
#ifndef TVFM_H_
#define TVFM_H_

class Tv;

// 前向声明
class Remote
{
public:
    enum State{Off, On};
    enum {MinVal,MaxVal = 20};
    enum {Antenna, Cable};
    enum {TV, DVD};
private:
    int mode;
public:
    Remote(int m = TV) : mode(m) {}
    bool volup(Tv & t);
    bool vol(Tv & t);
    void onoff(Tv & t);
    void chanup(Tv & t);
    void chandown(Tv & t);
    void set_mode(Tv & t);
    void set_input(Tv & t);
    void set_chan(Tv & t, int c);
};

class Tv
{
public:
    friend void Remote::set_chan(Tv & t, int c);
    enum State{Off, On};
    enum {MinVal,MaxVal = 20};
    enum {Antenna, Cable};
    enum {TV, DVD};

    Tv(int s = Off, int mc = 125) : state(s), volume(5);
    maxchannel(mc), channel(2), mode(Cable), input(TV) {}
    void onoff() {state = (state == On) ? Off : On;}
    bool ison() const {return state == On;}
    bool volup();
    bool voldown();
    void chanup();
    void chandown();
    void set_mode() {mode = (mode == Antenna)? Cable : Antenna;}
    void set_input() {input = (input == TV)? DVD : TV;}
    void settings() const;
private:
    int state;
    int volume;
    int maxchannel;
    int channel;
    int mode;
    int input;
}
```

作为内联函数的 `Remote` 方法：

```cpp
inline bool Remote::volup(TV & t) { return t.volup(); }
inline bool Remote::voldown(TV & t) { return t.voldown(); }
inline void Remote::inoff(TV & t) { t.inoff(); }
inline void Remote::chanup(TV & t) {t.chanup(); }
inline void Remote::chandown(TV & t) {t.chandown();}
inline void Remote::set_mode(TV & t) {t.set_mode(); }
inline void Remote::set_input(TV & t) {t.set_input(); }
inline void Remote::set_chan(TV & t, int c) {t.channel = c;}
```

如果你在 `tv.cpp` 和 `use_tv.cpp` 中包含 `tfvm.h` 而不是 `tv.h`，生成的程序与原始程序相同。区别在于 `Remote` 方法之一是 `TV` 类的友元。
