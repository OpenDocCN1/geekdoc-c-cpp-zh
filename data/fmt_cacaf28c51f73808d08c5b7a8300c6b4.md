## 可复用组件

可复用且可组合的组件让你能够构建强大的组件层次结构。它们是 React 视图层的基础。最后章节提到了“可复用性”这一术语。现在你已经复用 Table 和 Search 组件了。甚至 App 组件也是可复用的，因为你可以在其他地方再次实例化它。

让我们再定义一个可复用组件——Button 组件，它最终会被频繁地使用。

src/App.js

```
class Button extends Component {
  render() {
    const {
      onClick,
      className,
      children,
    } = this.props;

    return (
      <button
        onClick={onClick}
        className={className}
        type="button"
      >
        {children}
      </button>
    );
  }
}
```

声明这样一个组件似乎是多余的。你将使用 `Button` 组件而不是 `button` 元素。它只是省去了 `type="button"`。除了 `type` 属性外，当你想要使用 `Button` 组件时必须定义其他所有内容。但你必须考虑长远投资。想象你的应用程序中有几个按钮，但你想更改按钮的属性、样式或行为。如果没有组件，你将不得不重构每一个按钮。相反，`Button` 组件确保了只有一个真理来源。通过一个 `Button` 即可一次性重构所有按钮。一个 `Button` 统治一切。

既然你已经有一个 `button` 元素，你可以使用 `Button` 组件。它省略了 `type` 属性，因为 `Button` 组件已经指定了它。

## 组件声明

现在你有了四个 ES6 类组件。但你可以做得更好。让我为你介绍函数式无状态组件作为 ES6 类组件的替代方案。在你重构组件之前：

- 函数式无状态组件（Functional Stateless Components）：这些是接收 `props` 并返回 JSX 的函数。它们没有状态或生命周期方法。

- 函数式状态组件（Functional Stateful Components）：如果你需要状态或生命周期方法，可以使用 Hooks（在 React 较后版本中引入）或继续使用类组件。

# 代码游乐场

你现在不需要它。这就是为什么你可以保留之前的不带块体的版本。当使用块体时，人们往往倾向于在函数中做过多的事情。通过省略块体，你可以专注于函数的输入和输出。
