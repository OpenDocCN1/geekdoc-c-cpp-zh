
请记住，本书是基于 JavaScript 对真值（truthfulness）的简写表示构建的。在上在上例子中，使用了 `if (result)` 代替 `if (result === null)`。书中的其他情况也同样适用于这一点。例如，使用 `if (!list.length)` 代替 `if (list.length === 0)`，或者使用 `if (someString)` 代替 `if (someString !== '')`。如果你不熟悉该主题，请阅读 API 相关内容。

回到你的应用程序：现在 `hits` 列表应该是可见的。然而，你的应用程序中存在两个回归错误（regression bugs）。首先，“Dismiss”按钮失效了。它并不知道复杂的响应对象，在移除某项时操作的是本地状态中的普通列表。其次，当列表显示但你想搜索其他内容时，即使初始搜索是通过服务器端进行的，列表也会在客户端进行过滤。更完美的行为是在使用 `Search` 组件时从 API 获取另一个对象。这两个回归错误将在后续章节中修复。

## 条件渲染

条件渲染在 React 应用中很早就引入了。但在本书中还没有引入，因为没有这样的这样的用例。当你想要决定渲染一个元素还是另一个元素时，就会发生条件渲染。有时这意味着渲染一个元素或什么都不渲染。毕竟，简单的条件渲染可以用 JSX 中的 `if-else` 语句来表示。

内部组件状态中的结果对象初始为 `null`。到目前为止，当结果从 API 返回之前，`App` 组件没有返回任何元素。这已经是一种条件渲染了，因为你根据特定条件提前从 `render()` 生命周期方法中返回。`App` 组件要么不渲染任何内容，要么渲染它的元素。

但让我们更进一步。将 `Table` 组件（它是唯一依赖结果的组件）封装在一个独立的条件渲染中是有意义的。其他所有内容都应该显示，即使目前还没有结果。你可以在这里中使用三元运算符：

```javascript
src/App.js
class App extends Component {
  ...
  render() {
    const { searchTerm, result } = this.state;
    return (
      <div className="page">
        <div className="interactions">
          <Search
            value={searchTerm}
            onChange={this.onSearchChange}
          />
        </div>
        { result
        ? <Table
            list={result.hits}
            pattern={searchTerm}
            onDismiss={this.onDismiss}
          />
        : null
        }
      )
    );
  }
}
```

这是你表达条件渲染的第二种方案。第三种方案是逻辑 `&&` 运算符。在 JavaScript 中，`true && 'Hello World'` 始终求值为为 `'Hello World'`。`false && 'Hello World'` 始终求值为为 `false`。

## 代码游场

```javascript
const result = true && 'Hello World';
console.log(result);
// output: Hello World
```

```javascript
const result = false && 'Hello World';
console.log(result);
// output: false
```

在 React 中你可以使用这种行为。如果条件为 `true`，`&&` 之后的表达式将被输出。如果条件为 `false`，React 会跳过该表达式。这适用于条件渲染的情况，因为它应该返回 `Table` 或什么都不渲染。

### src/App.js

```javascript
{ result &&
<Table
list={result.hits}
pattern={searchTerm}
onDismiss={this.onDismiss}
/>
```

这些都是在 React 中使用条件渲染的几种方法。你可以阅读更多关于条件渲染方法的示例¹，以及何时应用它们。

毕竟，你应该能够在数据获取挂起时在应用程序中看到获取的数据。一旦请求解析并将其存储到本地状态中，`Table` 就会显示，`render()` 方法再次运行，以便于显示 `Table` 组件。

## 客户端或服务端搜索

当你现在使用带有输入字段的 `Search` 组件时，它将过滤列表。这发生在客户端。但你想在 `onClick()` 处理程序中显式地执行。作为替代方案，你可以对 `onChange()` 函数进行防抖处理并省去按钮，但这会增加复杂性，并不是预期的效果。让我们先保持简单，不使用防抖。

`src/App.js`

```javascript
class App extends Component {
  constructor(props) {
    super(props);

    this.state = {
      result: null,
      searchTerm: DEFAULT_QUERY,
    };

    this.setSearchStories = this.setSearchStories.bind(this);
    this.fetchSearchStories = this.fetchSearchStories.bind(this);
    this.onSearchChange = this.onSearchChange.bind(this);
    this.onSubmit = this.onSubmit.bind(this);
    this.onDismiss = this.onDismiss.bind(this);
  }

  fetchSearchStories(searchTerm) {
    fetch(`${PATH_BASE}${PATH_SEARCH}${searchTerm}`)
      .then(response => response.json())
      .then(result => this.setSearchStories(result))
      .catch(error => error);
  }

  componentDidMount() {
    const { searchTerm } = this.state;
    this.fetchSearchStories(searchTerm);
  }

  onSubmit() {
    const { searchTerm } = this.state;
    this.fetchSearchStories(searchTerm);
  }
}
```
