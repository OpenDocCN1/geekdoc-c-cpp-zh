## 第一节 – .NET 简介

.NET Framework 是 Windows 的内部组件，支持使用各种编程语言（如 Visual C#、Visual Basic、Visual F# 和 Visual C++）创建的应用程序的执行。这些编程语言是 Visual Studio .NET 的一部分。.NET Framework 由一个名为通用语言运行库（CLR）的虚拟执行系统和一组类库组成。CLR 是通用语言基础结构（CLI）的 Microsoft 产品，CLI 是一项国际标准，也是创建语言和库协同工作的执行和开发环境的基础。

Microsoft 推出 .NET 的目的是弥合差距并确保不同语言创建的应用程序之间的互操作性。.NET Framework 用于集成以各种编程语言和服务实现的应用业务逻辑。因此，它在代码重用性、代码专业化、资源管理、以多种编程语言开发应用程序、安全性、部署以及以多种编程语言开发的程序的管理方面带来了显著改进。

由于本书是关于 C# 语言的，让我们探讨 C# 与 .NET Framework 之间的关系。C#，我们所知，是设计用于构建在 .NET Framework 上运行的各种应用程序（如 Windows Forms 和 Web）的编程语言。它是一种简单、类型安全且面向对象的语言。你可以使用 C# 创建传统的 Windows 客户端应用程序、分布式组件、客户端-服务器 Web 应用程序和数据库应用程序。此外，C# 2010 提供了高级代码编辑器、用户界面设计器、集成调试器以及许多其他工具，使基于最新版本的 .NET Framework 开发应用程序变得更容易。

本章分为四个部分，讨论 .NET Framework、Visual Studio 2010 的安装、Visual Studio 2010 集成开发环境（IDE）的功能以及 C# 2010 相关技术。本章还提供了本书各章中讨论的 .NET 相关技术的快照。现在，让我们开始讨论 .NET 的演进。

### .NET 的演进

大约在 1995 年，由于其平台无关的方法和 Sun Microsystems 的开源政策，Java 开始流行。后来在 2002 年，Sun Microsystems 发布了 Java 的企业版，即 Java 2 企业版（J2EE），这是一个基于 N 层架构开发和执行分布式 Java 应用程序的 Java 平台。J2EE 的出现最终导致了 Microsoft 市场份额的下降。因此，Microsoft 启动了一个名为下一代 Windows 服务（NGWS）的项目以重新夺回市场份额。开发该产品花了三年多时间，现在它被称为 .NET。

以下是 .NET Framework 的一些好处：

- 一致的编程模型 – 为不同语言提供一致的面向对象编程模型，以执行各种任务，例如连接到数据库并从数据库检索数据，以及从文件读取和写入文件。
- 跨平台支持 – 能够在多个 Windows 操作系统之间实现互操作性。
- 语言互操作性 – 使不同语言编写的代码能够相互交互。例如，你可以在 Visual Basic 环境中继承 C# 开发的类，反之亦然。
- 自动资源管理 – 自动管理应用程序资源，例如文件、内存或网络和数据库连接。
- 部署简便 – 提供应用程序的轻松部署。在大多数情况下，要安装应用程序，只需将应用程序及其组件复制到目标计算机即可。.NET Framework 以程序集的形式提供 .NET 应用程序的部署，因此无需在注册表条目中存储有关组件和应用程序的信息。

#### CLR

.NET Framework 的最重要组件之一是 CLR，更为人所知的运行时。它提供诸如内存管理、异常处理、调试、安全、线程执行、代码执行、代码安全、验证和编译等功能。CLR 可以托管多种语言并确保其代码之间的互操作性。CLR 还支持应用程序用于访问各种资源（如集合、数组和操作系统文件夹）的服务。运行时在资源不再使用时会自动释放资源。这种自动内存管理解决了内存泄漏和无效内存引用的问题。

运行时对应用程序的代码施加代码访问安全（CAS）。CAS 是 CLR 的安全系统，可防止未经授权访问资源和操作。CAS 还有助于使代码健壮，即它使代码具有可扩展性和可重用性。

现在让我们探索 CLR 中的托管代码、非托管代码和内存管理。

##### 托管代码和非托管代码

托管代码是直接由 CLR 执行的代码。因此，使用托管代码创建的应用程序会自动具有 CLR 服务，例如类型检查、安全性和自动垃圾回收。这些服务有助于为托管代码应用程序提供平台和语言独立性。CLR 将应用程序编译为中间语言（IL）代码而不是机器代码。此 IL 代码连同描述代码的属性、类和方法元数据一起驻留在程序集中。

CLR 执行以下步骤来执行一段托管代码：

1. **选择语言编译器** — 指根据应用程序创建的编程语言选择编译器的过程。
2. **将代码编译为 IL 代码** — 指将源代码转换为与 CPU 无关的 IL 代码的过程。当你将源代码编译为 IL 代码时，会生成所需的元数据。元数据包含类型定义、成员签名、代码中的成员以及代码在执行时使用的其他详细信息。运行时在执行应用程序代码期间从文件中定位并提取元数据。
3. **将 IL 代码编译为本地代码** — 指由即时（JIT）编译器将 IL 代码转换为本地或机器代码的过程。编译后，代码会经过验证过程，该过程检查 IL 代码和元数据以检查代码是否类型安全，即代码只能访问其有权访问的内存位置。
4. **执行代码** — 指执行机器代码的过程。

> **注意：** CLR 还支持另一种名为安装时代码生成的编译方法。此方法用于一次性将 IL 代码转换为本地代码，一次取较大的代码单元。

CLR 为代码的编译和执行提供了一个安全的环境。JIT 编译器也会重复此代码编译和执行过程，直到执行完成。在整个代码执行过程中，托管代码会接收诸如垃圾回收、安全、与非托管代码的互操作性、跨语言调试支持以及增强的部署和版本控制支持等服务。

##### 内存管理

CLR 在托管执行期间提供的最重要的服务之一是自动内存管理。CLR 使用垃圾回收器来管理应用程序的内存分配和释放。CLR 的这一特性对开发人员有益，因为它减少了在开发托管应用程序时编写管理内存代码的负担。自动内存管理消除了许多常见问题，例如忘记释放对象导致内存泄漏，或尝试访问已释放对象的内存。

#### CTS

CTS 是运行时不可或缺的一部分，有助于支持跨语言通信。它为在运行时声明、使用和管理类型制定了某些准则。CTS 执行的功能如下：

- 通过建立框架，有助于跨语言通信、类型安全以及代码的高性能执行
- 支持不同编程语言实现的对象模型
- 为不同语言制定准则，确保其对象之间正确交互的范围
- 支持在应用程序开发过程中使用的原始数据类型，例如 `Boolean`、`Byte`、`Char` 和 `Int32`

CTS 可分为两种数据类型，值类型和引用类型。值类型变量由 CLR 管理，可以将其值存储在堆栈或堆内存中。垃圾回收器通过在变量不再使用时释放其内存空间来管理分配给这些类型的内存。值类型的实例，例如 `string`，其值分配在堆栈上，而引用类型的实例，例如数组，仅将其实际值的引用分配在堆栈上。

声明为值类型的变量拥有各自独立的数据副本；因此，对一个变量的任何操作都不会影响其他变量。另一方面，声明为引用类型的变量始终共享同一份数据副本或指向同一对象；因此，在一个变量上执行的任何操作都会直接影响引用同一实例的另一个变量。

#### 元数据和程序集

元数据是程序在二进制格式中的自我描述。换句话说，元数据包含程序中使用的类、方法和其他元素的信息。此信息存储在 CLR 可移植可执行文件（PE）文件中或内存中。当你编译 PE 文件中的代码时，元数据被插入到文件的一个部分，而代码被转换为 IL 并插入到文件的另一部分。元数据描述了程序中的每个数据类型和成员。当代码处于运行模式时，CLR 将元数据加载到内存中并查找有关类和成员的信息。程序的元数据包括：

- 程序集信息，例如其标识，可以是名称、版本、区域性、公钥、程序集类型、其他引用的程序集和安全权限
- 有关类型的信息，例如名称、可见性、基类、使用的接口以及成员（方法、字段、属性、事件和嵌套类型）
- 修改类类型和成员的属性信息

提供上述信息后，CLR 能够创建对象、访问数据并调用成员函数。程序集被打包成包含程序和库的单元。程序集包含一个自描述的二进制文件，可以是动态链接库（DLL）或可执行文件（EXE）文件。它还包含一组类型，例如类、接口和结构。单个程序集可以包含多个代码文件，或单个代码文件可以有多个程序集。

程序集可以分为两种类型，静态或动态。静态程序集包括接口、类和资源。这些程序集存储在磁盘上的 PE 文件中。使用 .NET Framework，你可以创建动态程序集，它们可以直接从内存运行，而无需在执行前保存到磁盘。但是，执行后你可以将它们保存到磁盘。

##### 程序集内容

通常，程序集是一个逻辑单元，由四个元素组成——清单、类型元数据、实现类型的 IL 代码，以及一组资源，例如位图和联合图像专家组（JPEG）文件。这些元素可以以单个文件或多个文件的集合形式分组。

##### 程序集清单

每个程序集都包含描述程序集中元素之间关系的数据。程序集清单是一个文件，其中包含程序集的元数据，即程序集的版本要求和安全标识信息。清单可以存储在包含 IL 代码的 PE 文件中，也可以存储在仅包含清单信息的独立 PE 文件中。

表 1.1 列出了存储在程序集清单中的信息：

| 信息 | 描述 |
| --- | --- |
| 程序集名称 | 指定程序集的名称。 |
| 版本号 | 指示主版本号、次版本号以及修订号和内部版本号。CLR 使用这些数字来强制执行版本策略。 |
| 区域性 | 提供有关程序集支持的区域性或语言的信息。 |
| 强名称信息 | 指示公钥，当程序集包含强名称时，强名称是用于加密程序集中名称和内容以及公钥的哈希令牌。 |
| 程序集中所有文件列表 | 包含程序集中包含的每个文件的哈希令牌和名称。哈希令牌是根据文件内容生成的字母数字字符串。请注意，程序集的所有文件必须存储在包含程序集清单文件的同一目录中。 |
| 类型引用信息 | 包含将类型引用映射到包含此类型引用声明和实现的文件所需的信息。从程序集导出的类型使用类型引用信息。 |
| 引用程序集信息 | 包含由程序集静态引用的程序集列表。程序集引用包含有关程序集的信息，例如依赖程序集的名称、程序集元数据（版本、操作系统等）和公钥。 |

程序集清单中的信息可以通过使用程序集属性进行修改。你还可以更改程序集的版本、信息和属性，例如商标、产品、公司和版权。

##### 全局程序集缓存

全局程序集缓存（GAC）是计算机中机器范围的代码缓存，是注册程序集的中心位置。你应该注意，只有在需要时，程序集才必须通过在全局程序集缓存中注册使其可共享；否则，它们必须保持私有。此外，将程序集安装到 GAC 中并不是使其可供组件对象模型（COM）互操作或非托管代码访问的强制性条件。COM 互操作是一项服务，使 .NET Framework 对象能够与 COM 对象通信。

你可以使用以下任一方式将程序集部署到 GAC 中：

- 专为 GAC 设计的安装程序
- 名为 `Gacutil.exe` 的 GAC 工具
- 使用 Windows 资源管理器将程序集拖入缓存

##### 强命名程序集

强名称是一个哈希令牌，包含程序集的标识，即关于程序集名称、版本号、区域性、公钥和数字签名的信息。使用私钥，包含清单的程序集文件会生成强名称。你可以使用 Microsoft Visual Studio .NET 和其他开发工具为程序集提供强名称。为程序集使用强名称具有以下好处：

- 通过生成私钥确保名称的唯一性
- 确保你使用的程序集版本与构建应用程序时所用的版本来自同一发布者
- 便于进行完整性检查，确保程序集内容自上次构建以来未被更改

##### 私有程序集和共享程序集
