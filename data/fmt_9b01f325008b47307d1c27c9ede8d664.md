
如果在替换列表中，一个参数前面紧跟一个 `#` 预处理令牌，则两者都被替换为单个字符字符串字面量预处理令牌，该令牌包含对应参数的预处理令牌序列的拼写。参数预处理令牌之间的每个空白将变为字符字符串字面量中的单个空格字符。构成参数的第一个预处理令牌之前的空白和最后一个预处理令牌之后的空白将被删除。否则，参数中每个预处理令牌的原始拼写保留在字符字符串字面量中，但对生成字符串字面量和字符常量拼写有特殊处理：在每个常量或字符串字面量的 `"` 和 `\` 字符之前都会插入一个 `\` 字符，无论在通用字符名称起始的 `\` 之前是否插入了 `\`。如果替换结果不是有效的字符串字面量，则行为未定义。对应空参数的字符字符串字面量为 `""`。`#` 和 `##` 运算符的评估顺序未指定。

## 6.10.3.3 ## 运算符

### 限制条件

`##` 预处理令牌不应出现在任何形式宏定义的替换列表的开头或结尾。

### 语义

如果在函数型宏的替换列表中，一个参数前面紧跟或后面紧跟一个 `##` 预处理令牌，则该参数被相应参数的预处理令牌替换；然而，如果参数不包含任何预处理令牌，则该参数被占位符（placemark）预处理令牌替换。

对于对象型和函数型宏调用，都会对替换列表中的每个 `##` 预处理令牌重新检查替换列表，删除该令牌（并非来自参数），并将前面的预处理令牌与后面的预处理令牌拼接。占位符预处理令牌有特殊处理：两个占位符的拼接产生单个占位符预处理令牌，占位符与非占位符预处理令牌的拼接产生非占位符预处理令牌。如果结果不是有效的预处理令牌，则行为未定义。`##` 运算符的评估顺序用于进一步的宏替换。

示例 在以下片段中：

```
#define hash_hash # ##
#define mkstr(a) # a
#define in_between(a) mkstr(a)
#define join(c, d) in_between(c hash_hash d)

char p[] = join(x, y); // 等同于
      // p[] = "x ## ## y";
```

展开在不同阶段产生：

```
join(x, y)
in_between(x hash_y)
in_between(x ## y)
mkstr(x ## y)
"x ## ## y"
```

换句话说，展开 `hash_hash` 会产生一个新的令牌，由两个相邻的井号组成，但这个新令牌不是 `##` 运算符。

173) 占位符预处理令牌不在语法中，因为它们是仅存在翻译阶段4的临时实体。

## 6.10.3.4 重新扫描和进一步替换

在替换列表中的所有参数都被替换且完成了 `# ##` 处理后，所有的占位符预处理令牌将被移除。然后对生成的预处理序列以及源文件中所有后续预处理令牌进行重新扫描，以寻找更多待替换的宏名。

如果在扫描替换列表期间（不包括源文件的其余预处理令牌）发现了正在被替换的宏名，则不进行替换。此外，如果任何嵌套替换遇到了正在被替换的宏名，则不进行替换。这些未被替换的宏名预处理令牌，如果稍后在（重新）检查中本该被替换宏名预处理令牌的上下文，将不再用于进一步替换。

生成的完全经过宏替换的预处理令牌序列如果类似于预处理指令，则不会被作为预处理指令处理，但其中所有的 `pr unary` 一元运算符表达式将按照 6.10.9 的规定进行处理。

示例 在某些情况下，不清楚替换是否是嵌套。例如，以下宏定义：

```

#define g(a) f(a)
invocation

可能展开为：

```

或者

```

```

严格遵守的程序被允许依赖这种行为。

## 6.10.4 行控制

### 约束条件

- 1 `#line` 指令的字符串字面量（如果存在）应当是一个字符字符串字面量。
- 2 在处理源文件到当前标记时，翻译阶段 1 中读取或引入的换行符字符数量（5.1.1.2）小于当前源行的行号。

### 语义

- 3 形式如下的预处理指令：

`# line digit-sequence new-line`

会导致实现将当前源文件的行号设置为 `digit-sequence` 指定的数字。

- 4 形式如下的预处理指令：

`# line digit-sequence "s"`

该实现将行号设置为 `digit-sequence`，并将源文件名设置为 `"s"` 的内容。

- 5 形式如下的预处理指令：

`# line pp-tokens new-line`

实现将当前源文件的行号设置为 `new-line` 指定的数字，该数字不为 0，也不大于 214748367。

## 6.10.5 错误指令

### 语义

形式如下的预处理指令：

```c
# error pp-tokens
```

会导致实现产生包含 `pp-tokens` 的诊断信息。

## 6.10.6 指令

### 语义

形式如下的预处理指令：

```c
# pragma pp-tokens
```

实现应当忽略 `pp-tokens`。

## 6.10.7 空指令

### 语义

形式如下的指令：

```c
#
```

没有任何影响。

## 6.10.8 预定义宏

除下述宏外，预定义宏的值在整个翻译单元中保持不变。

这些宏的任何标识符都不应以下划线后跟大写字母开头。

### 6.10.8.1 强制宏

实现应当定义以下宏：

- `__DATE__` 翻译日期：形式为 "mm dd yyyy" 的字符串字面量。如果日期不可，应提供一个实现有效的日期。
- `__FILE__` 假设源文件名（字符字符串），¹⁶
- `__LINE__` 假设行号（整数）。¹⁷
- `__STDC__` 整数常量 1，用于表示实现是标准的。
- `__STDC_HOSTED__` 如果实现是宿主的则为 1，否则为 0。

### 6.10.8.2 环境宏

以下宏根据条件定义：

- `__STDC_ISO_10646__` 形式为 yymmL 的整数常量（例如 1997L）。如果该符号被定义，则存储在 `char_t` 对象中的每一个字符都与其值相等。Unicode 要求集包含了截至指定年份月份 ISO/IEC 10646 定义的所有修订和技术修正。如果使用了其他编码，则该宏不定义，且实际编码由实现决定。
- `__STDC_MB_MIGHT_NEO_WC__` 常量 1，用于表示在 `char_t` 编码中，基本字符集的成员在作为整数常量中的唯一字符使用时，其值可能与其相等。
- `__STDC_UTF_16__` 整数常量 1，用于表示 `char16_t` 的值为 UTF–16。
- `__STDC_UTF_32__` 整数常量 1，用于表示 `char32_t` 的值为 UTF–32。

¹⁶ 参见“未来方向”（6.11）。
¹⁷ 假设源文件名和行号可以通过 `#line` 指令更改。
¹⁸ `__STDC_VERSION__` 整数常量形式为 yymmL

### 6.10.8.3 条件特征宏

1 以下内容由实现有条件地定义：

- `__STDC_ANALYZABLE__` 整数常量 1，用于表示符合附录 L（可分析性）中的规范。
- `__STDC_IEC_559__` 整数常量 1，用于表示符合附录 F（IEC 60559 浮点数算术）中的规范。
- `__STDC_IEC_559_COMPLEX__` 整数常量 1，用于表示符合附录 G（IEC 60559 兼容复数算术）中的规范。
- `__STDC_LIB_EXT1__` 整数常量 2019mL，用于支持附录 K（边界检查接口）中的扩展。^{179}
- `__STDC_NO_ATOMICS__` 整数常量 1，用于表示实现不支持原子类型（包括 _Atomic 类型限定符）以及 <atomic.h> 头文件。
- `__STDC_NO_COMPLEX__` 整数常量 1，用于表示实现不支持复数类型或 <complex.h> 头文件。
- `__STDC_NO_THREADS__` 整数常量 1，用于表示实现不支持 <threads.h> 头文件。
- `__STDC_NO_VLA__` 整数常量 1，用于表示实现不支持变长数组或可变修改类型。

2 定义了 `__STDC_NO_COMPLEX__` 的实现不应定义 `__STDC_IEC_559_COMPLEX__`。

> 179) 意图是使其保持 long 类型的整数常量，并随着本国际标准的每次修订而增加。

## 6.10.9 Pragma 运算符

### 语义

1 形式如下的一元运算符表达式：

```
_Pragma ( string-literal )
```

其处理方式如下：字符串字面量通过以下操作进行*去字符串化*：删除任何编码前缀、删除前后的双引号、将每个转义序列 \" 替换为双引号、将每个转义序列 \\ 替换为单反斜杠。生成的字符序列将通过翻译阶段 3 处理，生成预处理令牌，这些令牌将如同作为 pragma 指令中的 pp-令牌 一样被执行。元运算符表达式中的原始四个预处理令牌被移除。

2 形式如下的指令：

```
#pragma listing on "..\listing.dir"
```

也可以表示为：

```
_Pragma ( "listing on \\\..listing.dir\" )
```

后者无论是以字面形式显示所示，还是通过宏替换产生（如下所示），其处理方式都是相同的：

```
#define LISTING(x) PRAGMA(listing on #x)
#define PRAGMA(x) _Pragma (#x)
LISTING ( ..\listing.dir )
```

## 6.11 语言未来方向

### 6.11.1 浮点类型

未来的标准化可能包含额外的浮点类型，包括具有更大范围、精度或两者兼具的 long double。

### 6.11.2 标识符的链接

在文件作用域声明具有内部链接的标识符而不使用 static 存储类特征，是一项过时的特征。

### 6.11.3 外部名

将外部名的显著性限制为少于255 个字符（将每个通用字符名称或扩展源字符视为单个字符）是一项过时的特征，这是对现有实现的妥协。

### 6.11.4 字符转义序列

小写字母作为转义序列被留给未来的标准化。其他字符可以在扩展中使用。

### 6.11.5 存储类限定符

在声明中，将存储类分类符放置在声明标识符开头之外，是一项过时的特征。

### 6.11.6 函数声明符

使用带有空括号的函数声明符（不是原型格式的参数类型声明符）是一项过时的特征。

### 6.11.7 函数定义

使用分离参数标识符和声明列表的函数定义（不是原型格式的参数类型和标识符声明符）是一项过时的特征。

### 6.11.8 Pragma 指令

第一个处理令牌为 STDC 的 pragmas 被留给未来的标准化。

### 6.11.9 预定义宏名称

以 `__STDC_` 开头的宏名称被留给未来的标准化。

## 7.1.1 术语定义

字符串是连续的字符序列，以第一个空字符终止并包含该字符。有时使用多字节字符串（multibyte string）来强调对字符串中包含的多字节字符进行的特殊处理，或者为了与宽字符串（wide string）混淆。字符串的指针是指其初始（地址最低）字符的指针。字符串的长度是空字符之前的字节数，字符串的值是所包含字符的值按顺序排列的序列。

小数点字符用于将浮点数或从字符序列转换函数，用表示此类字符序列的小数部分的开始.¹180) 它在文本和示例中用句号表示，但可能被 setlocale 函数更改。

宽字符是代码值为零的宽字符。

宽字符串是连续的宽字符序列，以第一个空宽字符终止并包含该宽字符。宽字符串的指针是指其初始（地址最低）宽字符的指针。宽字符串的长度是空宽字符之前的宽字符数，宽字符串的值是所包含字符的代码值按顺序排列的序列。
