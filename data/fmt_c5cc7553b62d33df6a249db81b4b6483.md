如图 17.1 所示，Silverlight 3.0 是多种技术和功能的融合。它有两个主要组件，Silverlight 的 .NET Framework 和核心演示框架。现在，让我们详细了解这两个组件。

## Silverlight 的 .NET Framework

Silverlight 附带了 .NET Framework 的一个较小版本，它具有精简版的公共语言运行时（CLR），提供一些基本功能，例如通用类型系统、类型检查、调试和垃圾回收。Silverlight 组件的 .NET Framework 还提供了一定的类库，让你能够处理字符串、集合、泛型、反射和输入/输出。Silverlight 的某些类库还提供了一系列 WPF 控件，例如 `Button`、`TextBox` 和 `RadioButton`。Silverlight 组件的 .NET Framework 还允许你通过 XML、LINQ 和 XLINQ 在 Silverlight 应用程序中集成数据，并通过序列化操作数据。

> **NOTE**
>
> Silverlight 组件的 .NET Framework 中的类库会随 Silverlight 应用程序一起打包并部署到用户的计算机上。

Silverlight 组件中的 .NET Framework 还能让你轻松地通过 Windows Communication Foundation (WCF) 访问远程位置的数据和服务。此外，你还可以在 Silverlight 应用程序中使用 HTTP 对象、跨域 HTTP 请求、RSS 源、JavaScript Object Notation (JSON) 和 Simple Object Access Protocol (SOAP) 服务。

## The Core Presentation Framework

核心演示框架是 Silverlight 中的一个组件，它提供用于通过控件、样式、模板、2-D 矢量图形、动画和多媒体来设计 Silverlight 应用程序 UI 的功能和服务。该组件还允许你通过各种输入设备（如鼠标和键盘）合并用户输入和交互。它还允许你将数据与各种控件绑定，并指定 Silverlight 应用程序的 UI 布局。此外，你还可以通过此组件管理 Silverlight 应用程序中使用的多媒体内容的数字版权。用于处理 Silverlight 应用程序中 XAML 内容的 XAML 解析器也由核心演示框架提供。

现在，你已经了解了 Silverlight 是什么，并且它是一个用于开发交互式和丰富的 Internet 应用程序的强大且连贯的平台。接下来，让我们继续学习如何使用 Visual Studio 2010 开发 Silverlight 应用程序。

## Silverlight Applications in Visual Studio 2010

你可以使用文本编辑器（如 Notepad）创建 Silverlight 应用程序。然而，各种工具，如 Visual Studio 2010、Expression Studio 和 ComponentOne Studio，提供了一种高效且快速创建 Silverlight 应用程序的方式，因为这些工具默认包含基本文件和功能。在这些工具中，Visual Studio 2010 是 Silverlight 基于应用程序的设计师和开发人员的理想选择。请注意，Silverlight 使 .NET 设计师和开发人员能够轻松协调彼此，共同构建引人注目且引人入胜的 Web 应用程序。

使用 Visual Studio 2010 IDE，你可以轻松创建 Silverlight 3.0 应用程序。在 Visual Studio 2010 中，当你从菜单栏选择 File→New→Project 时，注意创建 Silverlight 3.0 应用程序的模板已经可用。然而，如果你尝试创建 Silverlight 应用程序，你会收到一个错误，提示你的系统上未安装 Silverlight 开发人员运行时。要创建 Silverlight 3.0 应用程序，你需要安装 Silverlight 3 SDK 和 Silverlight 3 开发人员运行时。你可以从 `http://www.microsoft.com/downloads/details.aspx?displaylang=en&FamilyID=d09b6ecf-9a45-4d99-b752-2a330a937bc4` 获取 Silverlight 3 SDK，以及从 `http://go.microsoft.com/fwlink/?LinkID=143433` 获取 Silverlight 3 开发人员运行时。

> **NOTE**
>
> 如果你使用 Visual Studio 2010 开发 Silverlight 3.0 应用程序，那么你可以像创建 Windows、WPF 或 ASP.NET Web 应用程序时一样，将 Silverlight 控件从 Toolbox 拖放到 Silverlight 应用程序界面。

## Assemblies and Files in Silverlight Applications

当你使用 Visual Studio 2010 创建 Silverlight 3.0 应用程序时，一些基本程序集引用和文件会自动成为应用程序的一部分。Silverlight 3.0 应用程序中引用的程序集如下：

- `mscorlib.dll`
- `System.dll`
- `System.Core.dll`
- `System.Windows.dll`
- `System.Windows.Browser.dll`
- `System.Windows.Controls.dll`
- `System.Net.dll`
- `System.Xml.dll`

在这些程序集中，`mscorlib.dll`、`System.dll` 和 `System.Windows.dll` 是 Silverlight 3.0 应用程序的基本程序集。其余程序集被添加到处理某些常见功能，例如与 Web 浏览器和 XML 内容的工作。你可以从 Add Reference 对话框中添加对其他程序集的引用，该对话框会在你在 Solution Explorer 中右键单击 Silverlight 应用程序的名称并从出现的上下文菜单中选择 Add Reference 选项时出现。

Visual Studio 2010 集成开发环境（IDE）会自动在新创建的 Silverlight 3.0 应用程序中包含一些文件，例如 `App.xaml` 和 `MainPage.xaml`，如图 17.5 所示：

![](img/e073a4882197be4ab61103cbe0bcb394_873_0.png)

### Figure 17.5: Showing the Files that Constitute a Silverlight 3.0 Application

如图所示，自动包含在 Silverlight 应用程序中的文件如下：

- `App.xaml` — 指 XAML 文件，你可以在其中定义应用于整个应用程序的应用程序级资源，例如画刷和样式对象。
- `App.xaml.cs` — 指 `App.xaml` 文件的代码隐藏类。`App.xaml.cs` 文件可用于处理应用程序级事件，例如 `Application_Startup`、`Application_Exit` 和 `Application_UnhandledException`。
- `MainPage.xaml` — 指 XAML 文件，用于定义一个页面，类似于网站中的页面。`MainPage.xaml` 文件默认是初始 UI 控件，在应用程序激活时加载。你可以在 `MainPage.xaml` 文件中使用 `Button`、`Label` 和 `TextBox` 等 UI 控件来定义 Silverlight 应用程序的 UI。
- `MainPage.xaml.cs` — 指 `MainPage.xaml` 文件的代码隐藏类，你可以在其中编写 Silverlight 应用程序的托管代码。

你选择的用于托管 Silverlight 应用程序的 ASP.NET Web 应用程序项目会由 Visual Studio 2010 自动创建。此 Web 应用程序包含 HTML 和 ASP.NET 测试主机页面以及自动添加到其中的 JavaScript 辅助文件。你可以使用 HTML 或 ASP.NET 测试页面运行和测试你的 Silverlight 应用程序。你可以在 Solution Explorer 中查看其中一些文件的引用，如图 17.6 所示。

## ASP.NET 和 HTML 宿主页（测试页）

每当您创建一个 Silverlight 应用程序时，您都需要一个页面来托管该 Silverlight 应用程序。在 Visual Studio 2010 中，您可以选择将 Silverlight 应用程序托管在简单的 HTML Web 页面或 ASP.NET Web 应用程序中。在 Visual Studio 2010 中，当您选择 ASP.NET Web 应用程序项目来托管 Silverlight 应用程序时，ASP.NET Web 应用程序会自动添加到 Silverlight 应用程序中。ASP.NET Web 应用程序包含两个测试页，即 ASP.NET 和 HTML 测试页，由默认创建用于整个 Silverlight 应用程序。换句话说，这意味着 ASP.NET 和 HTML 页面是用于托管您的 Silverlight 内容的测试页。ASP.NET 和 HTML 测试页可用于在应用程序开发期间测试 Silverlight 应用程序的 XAML 内容。此外，它们具有与 Silverlight 应用程序相同的名称，后缀为 `TestPage`。

HTML 测试页（即 `.html` 测试页）很大程度上包含与托管在单个 HTML 页面中的 Silverlight 应用程序的 `TestPage.html` 文件相同的代码。这意味着 HTML 测试页包含创建和初始化 Silverlight 应用程序的代码。ASP.NET 测试页（即 `.aspx` 测试页）包含 HTML 测试页的等效 ASP.NET 代码。此外，ASP.NET 测试页是默认启动页，因为它是用户运行 Silverlight 应用程序时出现的第一个页面。您可以在解决方案资源管理器中找到 ASP.NET 和 HTML 测试页，如图 17.7 所示：
