## 2.6

### 初探 CUDA C 代码

开启 CUDA C 编程领域的旅程最初可能看起来令人敬畏。CUDA，即统一计算设备架构，通过添加控制 GPU 并行特性的特定功能扩展了 C 语言。本节旨在通过基础示例消除 CUDA C 的神秘感，突出其与标准 C 编程的关键区别，并阐述 CUDA 并行计算方法的底层概念。

CUDA 编程的核心是内核（kernels）的概念。内核是函数，当被调用时会在 GPU 上的大量线程中并发执行。为了将它们与普通 C 函数区分来，使用 `__global__` 关键字定义内核。此示例演示了如何实现并调用一个简单的内核来相数组：

```cpp
// 用于加两个数组元素的 CUDA 内核函数
__global__ void add(int *a, int *b, int *c, int N) {
    int index = threadIdx.x;
    if (index < N) c[index] = a[index] + b[index];
}

int main() {
    int N = 10;
    // 在主机分配内存
    int size = N * sizeof(int);
    // 为设备分配内存
    int *a, *b, *c;
    int *d_a, *d_b, *d_c;
    // 拷贝数据到设备
    for (int i = 0; i < N; i++) {
        a[i] = i;
        b[i] = i + 1;
    }
    cudaMalloc(&d_a, size);
    cudaMalloc(&d_b, size);
    cudaMalloc(&d_c, size);
    cudaMemcpy(d_a, a, size, cudaMemHostToDevice);
    cudaMemcpy(d_b, b, size, cudaMemHostToDevice);

    // 启动内核
    int threadsPerBlock = 256;
    int numBlocks = (N + threadsPerBlock - 1) / threadsPerBlock;
    add<<<numBlocks, threadsPerBlock>>>(d_a, d_b, d_c, N);

    // 将结果拷贝回主机
    cudaMemcpy(c, d_c, size, cudaMemDeviceToHost);
    for (int i = 0; i < N; i++) {
        printf("%d + %d = %d\n", a[i], b[i], c[i]);
    }

    // 释放内存
    cudaFree(d_a);
    cudaFree(d_b);
    cudaFree(d_c);
    return 0;
}
```

在这个程序中，`VectorAdd` 内核以指定的配置启动，执行并行向量加法。这个示例封装了 CUDA 编程的核心：定义内核、配置其执行以及管理内存。

精通 CUDA C 语法和结构是开发高性能 GPU 加速应用程序的基础。通过利用内核、理解 CUDA 的内存层次结构并恰当地配置内核执行，开发者可以释放 GPU 的计算能力，用于无数并行处理任务。

## 2.7

### CUDA C 与标准 C 的区别

CUDA C 的引入和演进标志着计算任务处理和执行方式的重大变革，特别是在利用 GPU 的并行处理领域。核心，CUDA（统一计算设备架构）是由 NVIDIA 开发的一种并行计算平台和编程模型，允许开发者使用支持 CUDA 的图形处理器（GPU）进行通用用途处理——这种方法被称为 GPGPU（在图形处理器上的通用计算）。虽然 CUDA C 的语法很大程度上源于标准 C 编程语言，让已经精通 C 编程的人感到熟悉，但存在一些区分 CUDA C 的显著区别，这些区别要求思维和实现上的转变。这些区别不仅是语法上的，也是概念上的，反映了 GPU 相较于 CPU 的根本性架构差异。

### 内存模型区别

CUDA C 与标准 C 之间的主要区别在于它们处理内存管理以及底层内存模型的方法。在标准 C 编程中，内存管理相对简单，对抽象内存空间具有通用的视图。相反，CUDA C 引入了更复杂的内存层次结构，旨在满足 GPU 架构的特性：

- 全局内存（Global）：所有线程均可访问，但延迟较高且带宽较低。
- 共享内存（Shared）：更快的、块级限制内存区域，同一块内的线程可以访问，便于更快速的数据交换。
- 寄存器（Registers）：最快的内存形式，按线程使用。
- 常数和纹理缓存优化空间（Constant and Texture Cache-optimized spaces）：适用于只读数据。

内存类型的这种多样性使得 CUDA C 需要更具策略性的内存分配和访问模式方法，旨在最大限度地提高吞吐量和效率。

## 并行执行模型

CUDA C 与标准 C 的另一个核心区别是并行执行模型。标准 C 主要为代码的顺序执行而设计，并行性（在使用时）通常通过库或 `OpenMP` 等扩展进行管理。然而，CUDA C 内生依赖于并行执行模型，将线程组的分层组织作为其计算的基础：

## 核函数 (Kernel Functions)

CUDA C 编程的一个独特特性是“核”的概念，即函数由 N 个不同的 CUDA 线程并行执行 N 次：

```cpp
__global__ void kernel(float *array) { 
    int index = threadIdx.x + blockIdx.x * blockDim.x;
    // ...; // 执行某些计算 
}
```

`__global__` 限定符指定该函数为内核函数，可以从主机（CPU）代码调用，但在设备（GPU）上运行。这与标准 C 函数调用不同，它强调的是并发操作的执行而非顺序执行。

## 执行控制

标准 C 程序按顺序执行指令，由 CPU 的流控制逻辑控制。相比之下，CUDA C 引入了对并行执行的显式控制，包括用于管理不同线程和块之间依赖关系和执行流的同步点。例如，`__syncthreads()` 函数充当屏障，块中的所有线程在任何线程继续之前必须在此等待，以确保正确的数据共享和任务协调。

```cpp
__global__ void kernel(float *array) { 
    // 部分 1: 执行初始计算 
    // 同步块中的所有线程 
    // 部分 2: 执行依赖于部分 1 的后续计算 
}
```

这种程度的执行控制对于高效管理 GPU 的并行计算能力至关重要。

## 开发环境与工具

CUDA C 的开发环境和工具链与标准 C 编程使用的工具也显著不同。NVIDIA 为 CUDA 开发提供了一套完整的工具包，包括 NVIDIA CUDA 编译器 `NVCC`、CUDA 库以及用于性能优化的 NVIDIA Visual Profiler。这些工具专门为支持 CUDA C 程序的开发、调试、优化和部署而设计，提供了比标准 C 开发环境通常提供的的功能。

总之，虽然 CUDA C 在语法上与标准 C 具有相似之处，但它们在内存模型、执行模型、核函数、执行控制和开发工具方面的差异反映了 GPU 计算的独特性质。因此，掌握 CUDA C 编程不仅需要理解这些差异，还需要转变视角，以有效利用 GPU 的并行处理能力。

## 2.8

## 理解 CUDA 的扩展性

可扩展性（Scalability）是定义并行计算框架（包括 CUDA）效率和有效性的基石。

CUDA 的扩展性是指其利用图形处理器（GPU）不断增加的核心数量来更有效地处理并行任务的能力，而无需对代码进行重大重构。这种增长能力不仅能够适应更大的数据集和更复杂的计算，还确保了使用 CUDA 开发的应用程序可以利用未来 GPU 硬件的。

## 架构概述

要充分理解 CUDA 的可扩展性，必须理解 GPU 架构的分层组织以及 CUDA 如何将计算映射到该架构上。支持 CUDA 的 GPU 由流多处理器（SM）阵列组成，每个 SM 包含多个 CUDA 核心。CUDA 将计算组织成块网格，每个块可以在单个 SM 上并发执行，而块中的每个线程可以在单个 CUDA 核心上并发执行。

这种分层结构提供了两个级别的并行性：块级和线程级。CUDA 的设计允许将计算任务灵活且可扩展地映射到这种层次结构中，从而高效利用 GPU 的并行处理能力。

## 适应硬件增强

CUDA 可扩展性的关键方面在于其适应 GPU 技术演进的能力。随着新一代 GPU 增加 SM 和 CUDA 核心的数量，基于 CUDA 的应用程序可以在极少更改代码库的情况下，自动从这些增强中获益。

- CUDA 核心数量的增加允许更多线程并行执行，从而缩短处理时间。
- 新版 GPU 中改进的内存架构提高了数据吞吐量并减少了瓶颈，进一步放大了性能收益。
- 增强的 SM 特性（例如并发内核执行和动态并行）能够更复杂、更高效地利用 GPU 资源。

CUDA 的编程模型抽象了硬件的复杂性，允许开发者专注于算法中固有的并行性，而不是并行执行的底层机制。这种抽象对于扩展性至关重要，因为它在不同代 GPU 之间提供了一致的编程接口。

## 通过内核设计的代码扩展性

为优化性能配置内核是一门艺术，涉及到理解计算负载和目标 GPU 架构的细节。CUDA 提供了多种可以调整的内存和执行配置选项，以提高性能和扩展性。

```cpp
__global__ void vectorAdd(float *A, const float *B, float *C, int N) { 
    int i = blockDim.x * blockIdx.x + blockIdx.x; 
    if (i < N) C[i] = A[i] + B[i]; 
}
```

在这个简单的示例中，`vectorAdd` 内核执行两个向量的逐元素加法。内核的执行配置可以根据数据的大小和 GPU 的能力进行扩展，以确保高效利用 GPU 资源。

CUDA 的扩展性是分层编程模型、适应硬件增强的能力以及灵活内核配置选项的函数。这种设计哲学确保了今天编写的应用程序可以利用未来的 GPU 硬件，使 CUDA 成为加速计算时代并行编程的前瞻性和可持续选择。

### Hello, CUDA World：一个简单的示例

开启 CUDA C 编程之旅始于一个简单、传统的编程入门仪式：“Hello, World!” 示例。然而，考虑到 CUDA 的并行性质，我们的“Hello, World!” 看起来将会有所不同，但它将作为理解如何利用 GPU 并行计算能力的基石。

CUDA C 使用用于表示并行性的结构扩展了 C 编程语言。在深入研究 CUDA 并行编程的细微差别之前，理解 CUDA 程序的结构并识别它与传统 C 程序的区别至关重要。本节通过一个简单的 CUDA 程序展开，该程序演示了如何利用 GPU 执行并行计算。

CUDA 编程的核心在于内核（kernels）的设计。内核本质上是一个函数，当调用时，由 N 个不同的 CUDA 线程并行执行 N 次，而不是传统顺序程序中的单次执行。

考虑数组中两个数字相法的简单任务。在标准的 C 实现中，此操作通常会遍历每个元素并顺序执行加法。相反，CUDA 允许我们利用 GPU 强大的并行计算能力并行执行这些加法。

### 用于两个数组相加 CUDA 内核

让我们用一个基本的 CUDA 示例来说。此示例的目标是创建两个整数数组并将它们逐元素相加，结果存储在第三个数组中。此将在 GPU 上并行执行。

首先，我们需要包含 CUDA 头文件：

```
#include <cuda_runtime.h>
#include <stdio.h>
```

随后，我们定义执行加法的 CUDA 内核：

```
__global void add(int *a, int *b, int *c, int N) { 
    int index = threadIdx.x + blockIdx.x * blockDim.x; 
    if (index < N) c[index] = a[index] + b[index]; 
}
```

在这里，`__global__` 限定符表示该函数是一个运行在 GPU 上的内核，但可以从主机代码（CPU）调用。变量‘a’、‘b’ 和‘c’ 代表用于加法的数组指针，而‘N’代表数组的大小。计算‘index’ 的行标识了线程在并行执行上下文中唯一的索引，允许每个线程操作数组的不同元素。

接下来，我们编写主机代码来分配内存、初始化数组并调用：
