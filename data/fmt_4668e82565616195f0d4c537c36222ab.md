# WCF 架构

WCF 支持多种协议，例如 SOAP 和二进制。它还提供可互操作的通信，这是不同技术之间通信所必需的，例如 Java 2 Platform Enterprise Edition（J2EE）和 .NET。WCF 使用面向服务的架构（SOA）来解决通信时出现的互操作性问题。

> NOTE
> SOA 是一种软件设计模式，定义了松耦合的软件应用程序组件如何交互以实现整个应用程序的业务逻辑。

下面我们详细讨论这些层次。

## 契约层

契约层提供了消息系统不同功能的信息。一个涉及从一端点向另一端点发送和接收消息的系统称为消息系统。契约层包含以下四个组件：

- **数据契约** —— 描述消息参数。这些参数基于 XML，用于创建由 WCF 服务形成或消费的消息。
- **消息契约** —— 使用 SOAP 定义消息的特定部分。
- **服务契约** —— 向客户端提供特定信息，使客户端能够理解服务提供了哪些功能。
- **策略与绑定** —— 指定传输介质，如 HTTP 或传输控制协议（TCP），还包括通信所需的一些安全要求。

## 服务运行时层

服务运行时层指定并管理 WCF 服务在运行期间发生的行为，例如消费或承载服务。以下是服务运行时层管理的行为列表：

- **限制行为** —— 控制 WCF 服务处理的消息数量
- **错误行为** —— 指定消息在服务运行时显示错误时应采取的操作
- **元数据行为** —— 检查元数据的处理，确保元数据可供外部客户端使用
- **实例行为** —— 指定可供客户端使用的 WCF 服务实例数量
- **消息检查** —— 在服务运行期间检查消息的全部或部分内容，以确认消息是否有效
- **事务行为** —— 如果发生故障，则更改事务的状态
- **调度行为** —— 决定 WCF 基础结构如何处理和处理消息
- **并发行为** —— 控制在客户端和服务器通信时运行的并行函数
- **参数筛选** —— 在调用方法之前筛选该方法的参数

## 消息传递层

消息传递层提供处理消息时所需的不同通道的信息。这些通道有助于消息处理，消息传递层处理需要通信的消息。消息传递层使用两种通道来传达消息：传输通道和协议通道。传输通道用于读取、写入并将消息转换为 XML 格式；而协议通道包含用于处理消息的协议。其中一些协议是 WS-Security 和 WS-Reliability。

## 承载与激活层

承载与激活层为服务提供了各种承载和激活选项。在此层中，可以使用 Internet 信息服务（IIS）或 Windows 激活服务（WAS）来承载服务。WCF 提供了以下三种承载服务的选项：

- **在自身的应用程序域中自我承载服务** —— 在自己的应用程序域中承载服务。某些应用程序通常需要从其自身的进程公开服务，而不是依赖 Windows 提供的进程。当客户端请求 WCF 服务时，承载该服务的进程必须处于运行状态。以这种方式承载的 WCF 服务在 Windows 服务中运行，并允许它在系统启动时或当 WCF 服务托管在图形用户界面（GUI）应用程序中时启动。承载与激活层的实现将在本章后续通过示例进行说明。
- **承载在 IIS 服务器提供的应用程序域和进程中** —— 依赖虚拟目录来承载 WCF 服务。当您使用 WCF 承载 IIS 提供的服务时，这些服务会自动集成到 ASP.NET 中。这种集成使 WCF 能够利用 ASP.NET 的继承特性。使用 IIS 的最大优势之一是您不需要在 WCF 服务中包含任何承载代码来承载它。IIS 使用传统的 Web 承载技术自动激活 WCF 服务。
- **承载在 WAS 服务器提供的应用程序域和进程中** —— 指定一种新的进程激活机制，该机制保留了 IIS 的进程模型和承载功能。当 WCF 应用程序部署在运行 WAS 的计算机上时，WAS 会自动激活它们。

您可以根据不同的场景和关键优势选择不同的承载环境，如表 19.1 所示：

**表 19.1：选择正确承载环境的各种场景**

| 承载环境 | 常见场景 | 关键优势与局限性 |
|---|---|---|
| 自我承载 | • 在开发期间使用控制台应用程序<br>• 使用富 Winform 和 WPF 客户端应用程序访问 WCF 服务 | • 允许轻松部署 WCF 服务<br>• 不提供 WCF 服务的企业级解决方案 |
| IIS | • 通过 ASP.NET 内容运行 WCF 服务<br>• 在 Internet 上使用各种传输协议运行 WCF 服务<br>• 使用 HTTP 协议同时运行 WCF 服务和 ASP.NET 内容 | • 支持 ASP.NET 与 IIS 内容的集成<br>• 提供 WAS 优势<br>• 支持基于消息的激活<br>• 管理进程回收空闲时间<br>• 监视进程运行状况<br>• 仅使用 HTTP 协议 |
| WAS | • 在 Internet 上使用各种传输协议运行 WCF 服务，而无需安装 IIS | • 不要求 IIS<br>• 管理空闲时间<br>• 监视进程运行状况<br>• 支持基于消息的激活<br>• 适用于 HTTP、TCP、MSMQ 和命名管道等协议 |
| Windows 服务或 NT 服务 | • 在 IIS 外部承载 WCF 服务 | • 提供安全环境<br>• 使用操作系统（OS）控制服务进程生命周期 |

接下来，您将了解 WCF 终结点。

## WCF 终结点

WCF 服务通过终结点与客户端连接，终结点包含契约、地址和绑定。契约通常是两个或多个当事方之间的协议。类似地，在 WCF 服务中，契约定义了协议以确定客户端应如何与服务通信。从技术上讲，它描述方法的参数和返回值。契约还描述了可以通过终结点调用的操作。它是通过定义操作的接口名称来标识的。

终结点可被访问的位置由地址指定，称为统一资源定位符（URL）。绑定定义了如何调用终结点的操作。它指定数据在服务及其客户端之间的传输方式，即使用哪些通信协议访问服务，以及 WCF 服务中应使用哪些安全模型。

WCF 服务包含针对大多数常见通信协议的预定义绑定，例如 SOAP over HTTP、SOAP over TCP 和 SOAP over Message Queues。当客户端想要通过终结点访问 WCF 服务时，它会访问指定的绑定。图 19.4 显示了终结点的三个主要组件：

当消息在传输通道被处理并编码时，它会发送到每个协议通道进行进一步处理，直到达到通道堆栈的顶部。最后，消息由调度器分派到 WCF 服务实现。

在 WCF 中，绑定由 `System.ServiceModel.Channels.Binding` 类表示。所有绑定必须从该基类派生。表 19.2 显示了系统提供的绑定列表：

| `WSHttpBinding` | `<wsHttpBinding>` | 支持 WS-* 功能以及使用 SOAP 安全性的可靠和安全会话的分布式事务。它使用 HTTP 和 HTTPS 传输协议进行通信。 |

## 服务契约

服务契约定义了 WCF 服务可以支持的操作、服务契约使用的消息交换模式以及每个消息的格式。它生成服务描述，以便每个 WCF 服务至少能实现一个服务契约。要创建服务契约，首先需要定义一个接口，该接口包含表示服务操作的方法。接下来，需要对接口应用 `ServiceContractAttribute` 属性，以指示它是一个服务契约。表示服务契约操作的方法使用 `OperationContractAttribute` 属性，如以下代码片段所示：

```
[ServiceContract]
public interface IRailwayReservation
{
    [OperationContract]
    bool ReserveSeat(SeatReservation seatReservation);
}
```

表19.3列出了 `ServiceContractAttribute` 属性的属性：

**表19.3：展示 `ServiceContractAttribute` 属性的属性**

| 属性 | 说明 |
|---|---|
| `ConfigurationName` | 定义配置文件中服务配置的名称。 |
| `CallbackContract` | 定义当服务用于双工消息传递时在客户端实现的协定。 |
| `Name` | 定义Web服务描述语言（WSDL）中`<portType>`元素的名称。 |
| `Namespace` | 定义WSDL中`<portType>`元素的XML命名空间。 |
| `SessionMode` | 指定调用服务协定的操作是否需要会话。此属性的可能值为`Allowed`、`NotAllowed`和`Required`。 |
| `ProtectionLevel` | 定义绑定是否保护通信。此属性的可能值为`None`、`Sign`和`EncryptAndSign`。 |

服务协定包括以下两个组件：

- 操作协定
- 数据协定

让我们逐一详细讨论这些内容。

### 操作协定

操作协定定义了应暴露给外部客户端的方法。它提供了 `OperationContractAttribute` 属性，用于标记作为服务协定组成部分的每个方法。表19.4描述了 `OperationContractAttribute` 属性的属性：

**表19.4：展示 `OperationContractAttribute` 属性的属性**

| 属性 | 说明 |
|---|---|
| `Action` | 指定唯一标识操作的操作，并根据操作将请求消息分派到相应的方法。 |
| `ReplyAction` | 设置回复消息的操作名称。 |
| `AsyncPattern` | 指示操作是异步实现的，或者可以使用 Begin/End 方法对异步调用。 |
| `IsInitiating` | 从一系列操作中启动一个操作。启动操作会开始一个新会话；而…… |
| `IsTerminating` | 从一系列操作中终止一个操作。服务器通过终止操作结束会话。 |
| `IsOneWay` | 允许客户端不等待回复消息。客户端没有直接方法确保请求是否正确发送。 |
| `Name` | 定义操作的名称。 |
| `ProtectionLevel` | 指定消息应签名、加密，还是两者皆需。 |

**清单19.2：展示将 `ServiceContractAttribute` 和 `OperationContractAttribute` 属性应用于服务协定的代码**

```
[ServiceContract]
public interface IService
{
    // 由于参数和返回类型都是基元类型，因此不需要数据协定。
    [OperationContract]
    double Area(int area);

    // 由于参数和返回类型都标记有 SerializableAttribute 属性，因此不需要数据协定。
    [OperationContract]
    System.Drawing.Bitmap GetImage(System.Uri pictureUri);

    // MyComplexTypes.ReservationForm 是一个复杂类型，
    // 因此需要数据协定。
    [OperationContract]
    bool ApproveReservationForm(MyComplexTypes.ReservationForm rf);
}
```

### 数据协定

数据协定是客户端与服务之间的一种约定，在概念上描述了要交换的数据。客户端与服务之间的通信不需要相同的类型，但需要相同的数据协定。与服务协定只能处理简单类型不同，数据协定可以处理复杂类型。这意味着数据协定可以处理复杂的服务调用；即具有复杂类型参数并返回复杂类型值的调用。

在WCF中，服务协定通过接口定义，而数据协定通过类定义。这些类以 `DataContractAttribute` 属性为前缀，其成员以 `DataMemberAttribute` 属性为前缀。

清单19.3展示了如何在应用程序中应用 `DataContractAttribute` 和 `DataMemberAttribute` 属性来创建 `MyComplexTypes.ReservationForm` 类型：

**清单19.3：展示应用 `DataContractAttribute` 和 `DataMemberAttribute` 属性的代码**

```
namespace MyComplexTypes
{
    [DataContract]
    public class ReservationForm
    {
        private int rfid_value;

        // 将[DataMember]属性应用于该属性。
        [DataMember]
        public int ReservationFormId
        {
            get { return rfid_value; }
            set { rfid_value = value; }
        }
    }
}
```

## 行为

行为用于自定义服务终结点的运行时行为。它们还允许你向服务添加自定义扩展，以检查和验证服务配置，或修改应用程序的运行时行为。你可以通过配置文件或为其提供的属性将行为应用于WCF服务。以下是WCF服务使用的行为列表：

- 服务行为——在服务实现（类）级别标识服务范围的实现行为。你不能在协定（接口）级别应用此属性。
- 协定行为——实现 `IContractBehavior` 接口以扩展客户端和服务的运行时。
- 终结点行为——实现 `IEndpointBehavior` 接口以修改特定终结点的服务或客户端运行时。
- 操作行为——实现 `IOperationBehavior` 接口以扩展客户端和服务对操作的运行时。

## WCF服务的配置

你可以使用配置文件配置WCF服务，这些文件以XML格式包含WCF服务的配置信息。这些文件中的XML元素允许你逐机修改配置细节，例如WCF服务的终结点地址。WCF还包含一些系统定义的元素，使你能够快速选择WCF服务最基本的功能。部署WCF服务时，配置文件为你呈现终结点和服务行为数据提供了灵活性。你可以使用`web.config`文件或WCF配置编辑器工具更改WCF服务的配置。

### 使用 `web.config` 文件

你可以使用`web.config`或`app.config`文件来配置WCF服务。选择哪种配置文件（`web.config`或`app.config`）来配置WCF服务取决于你为WCF服务选择的主机环境。如果你的主机环境是IIS，则可以使用`web.config`文件；如果主机环境不是IIS，则使用`app.config`文件。清单19.4展示了`web.config`文件的主要元素：

**清单19.4：展示`web.config`文件的主要元素**

```
<system.serviceModel>
  <services>
    <service>
      <endpoint/>
    </service>
    <service>
      <endpoint/>
    </service>
  </services>
  <bindings>
    <binding>
      <!--系统提供的绑定或自定义绑定-->
    </binding>
    <binding>
      <!--系统提供的绑定或自定义绑定-->
    </binding>
  </bindings>
  <behaviors>
    <behavior>
      <!--系统提供的行为或自定义行为-->
    </behavior>
    <behavior>
      <!--系统提供的行为或自定义行为-->
    </behavior>
  </behaviors>
</system.serviceModel>
```
