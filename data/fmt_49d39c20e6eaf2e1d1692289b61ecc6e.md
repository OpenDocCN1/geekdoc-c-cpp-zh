
## 竞态条件示例

### 进程 A
`count = count`
`count = count + 1`

### 进程 B
`count = count`
`count = count + 1`

如果 `count` 的初始值为 0，执行顺序如下：

```
// 进程 A 读取 count
```

```
// 进程 B 读取 count
```

```
// 进程 A 写入 count
```

```
// 进程 B 写入 count
```

`count` 的值将变为 1，而不是预期的 2。这就是由于竞态条件导致的错误。为了防止这种情况，可以使用互斥锁（`mutex`）。互斥锁可以确保在任何时刻只有一个进程可以执行特定的代码段。

### 使用互斥锁

```
// 进程 A
lock(mutex)
count = count
count = count + 1
unlock(mutex)
```

```
// 进程 B
lock(mutex)
count = count
count = count + 1
unlock(mutex)
```

在这种情况下，`count` 的值将是正确的 2。

## 实现互斥锁 (IMPLEMENTING MUTEXES)

某些计算机可能提供硬件使得互斥锁更高效。在其他计算机上，互斥锁必须通过软件实现。

以下伪代码显示了如何添加互斥锁到之前的算法：

```
// 初始化互斥锁
mutex = 0

// 获取互斥锁
while (mutex == 1) {
    // 等待
}
mutex = 1

// 释放互斥锁
mutex = 0
```

然而，这种实现本身也存在竞态条件。如果两个进程同时检查 `mutex == 1`，它们可能都发现它为 0，然后都将其设为 1。

为了解决这个问题，可以使用原子操作。

```
// 检查互斥锁
```

```
// 进程 A 检查 mutex
```

```
// 进程 B 检查 mutex
```

如果这些操作是原子的，那么它们就不会同时发生。

```
// 原子地检查并设置
if (test_and_set(&mutex) == false) {
    // 进入临界区
}
```
