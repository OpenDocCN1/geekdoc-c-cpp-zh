
### (2.7) 关联命名空间和类

如果`*T*`是类`*X*`的数据成员，其关联命名空间和类是与成员类型关联的以及与`*X*`关联的。

如果关联命名空间是一个内联命名空间，其包含的命名空间也包含在集合中。如果关联命名空间直接包含内联命名空间，则这些内联命名空间也包含在集合中。此外，关联命名空间和类是每个成员关联内容的并集，即与其参数类型和返回类型关联的类和命名空间。此外，如果关联函数名为一个`*template-id*`，其关联类和命名空间还包括它的`*template-arguments*`和它的`*template-namespaces*`。

`*X*`为无限定查找（6.4.1）产生的查找集，`*Y*`为参数查找（下文定义）产生的查找集。如果`*X*`包含

- (3.1) — 类成员的声明，
- (3.2) — `*Y*`为空且不是未使用`*declaration*`的函数声明，或
- (3.3) — 不是模板函数的声明

则`*Y*`为空。否则，`*Y*`是下文所述与参数类型关联的命名空间中的声明。通过名称查找找到声明集是`*X*`和`*Y*`的并集。*注：与参数类型关联的命名空间和类可以包括普通查找已经考虑命名空间和类。* — *注结束*

示例:

```cpp
namespace NS {
class T {
    void f();
    void g(int);
};
NS::T param;
void g(NS::T, float);
int main() {
    f(param);
    extern void g(NS::T, float);
    g(param, 1);
} // OK: calls NS::f; OK: calls g(NS::T, float)
```

## 6.4.3 限定查找 [basic:lookup.qual]

### 4

当考虑关联命名空间时，查找与将关联命名空间用作限定符（6.4.3.2）时执行的查找相同，但：

- 4.1 关联命名空间中的任何`any-指令`被忽略。
- 4.2 在关联类中声明的任何命名空间作用域友元或函数模板在它们各自的命名空间内可见，即使它们在普通查找（14.3）中不可见。
- 4.3 除（可能重载的）函数和函数模板外，所有名称均被忽略。

### 1

类或命名空间成员或枚举类的的称为通过`::`作用域解析运算符（8.1）应用于表示其类、命名空间或枚举的嵌套名称指定符（nested-name-specifier）。如果在嵌套名称指定符中执行的`::`作用域解析运算符之前没有去斜杠限定符（declype-specifier），则对该`::`之前的名称的查找仅考虑特化化为类型的命名空间、类型和模板。如果该名称未指定命名空间或类、枚举或依赖类型，则程序构造为错误的。

示例：

```cpp
class A {
public:
    static int n;
int main() {
    int A;
    A::n = 42;
    B::n; // OK
// ill-formed: A does not name a type
} // 示例
```

### 2

[注：多重限定名，例如`R1::N2::N3::`，可以用于引用类的成员（12.2.5）或命名空间的成员。--注]

### 3

在声明符-标识（declarator-id）为限定标识（qualified-id）的声明中，在声明的限定标识之前使用的名称在定义的命名空间中查找；在限定标识之后的之后的名称在成员的类或命名空间的作用域中查找。

示例:

```cpp
class X {
class C {
static const int number = 50;
};
X::arr[number]; // ill-formed: to ::X::arr[number]
// and not to: X::C::arr[number];
```

### 4

以`::`为缀的名称在成员的类或命名空间的作用域内查找。

示例：

```cpp
class X {
class C {
static const int number = 50;
};
X::arr[number]; // ill-formed: to ::X::arr[number]
// and not to: X::C::arr[number];
```

### 5

以`::`为缀的名称在全局作用域内查找。

示例：

```cpp
struct A {
    ~A();
};
typedef AB;
int main() {
    A* p;
    AB(); // 明确调用析构函数
}
```

### 6

如果未使用嵌套名称指定符，则程序构造为错误的。

示例：

```cpp
class A {
public:
    static int n;
int main() {
    int A;
    A::n = 42;
    B::n; // OK
// ill-formed: A does not name a type
} // 示例
```

### 6.4.3.1 类成员

#### 1

如果嵌套名称指定符指定一个类，该名称在类的作用域（13）内查找，该名称应代表类的多个成员或其类的成员。名称规则的例外如下：

- (1.1) 析构函数的查找见 6.4.3；
- (1.2) 转换函数的转换类型以与类成员相同的方式查找（见 6.4.5）；
- (1.3) 模板参数（10.3.3）中指定名称的查找还会查找相同作用域内隐藏的类或枚举名称（6.3.10）；
- (1.4) 成员声明（10.3.3）中指定名称的查找还会查找类或枚举

#### 2

在不忽略函数名称的查找中，且嵌套名称指定符指定类`C`时：

- (2.1) 如果相同的名称指定符在`C`中查找是`C`的注入类名（第 12 节），
- (2.2) 在成员声明（10.3.3）中，如果嵌套名称指定符之后的名称与嵌套名称指定符最后一个组件中的标识符或简单模板 ID 的模板名称相同，则该名称被视为类`C`的构造函数。注：例如，该名称在限定类型指定符中不是可接受的结果（构造函数不会被替换注入类——注结束）。此类构造函数应仅用于构造函数的声明符-标识或使用声明。

示例：

```cpp
struct A {
    public B;
};
struct B : public A { B(); };
```

#### 3

位于嵌套名称指定符、限定类型指定符或基类指定符中的名称查找。

# ISO/IEC 14882:2017(E)

```cpp
A::A() { }
B::B() { }

B::ba;               // object of type A
A::m;               // error, A::A is not a type name
struct A {::A a2;   // object of type A
    end example;
```

- 3 被嵌套声明中的名称隐藏的`A`类名，该成员仍然可以通过其类名后接`::`运算符以限定名的方式找到。[namespace.qual]

### 6.4.3.2 命名空间成员

- 1 如果限定标识符（qualified-id）的嵌套名限定符（nested-name-specifier）指定了一个命名空间（包括嵌套名限定符为`::`的情况，即指定全局命名空间），则在嵌套名限定符之后的名称在指定的命名空间的作用域内查找。模板标识符（template-id）的模板参数中的名称在整个后置表达式（postfix-expression）发生的上下文中进行查找。

- 2 对于命名空间`X`和名称`m`，命名空间限定的查找集`S(X,m)`定义如下：令`S'(X,m)`为`X`中所有`m`的声明以及`X`的内联命名空间集（10.3.1）。如果`S'(X,m)`不空，则`S(X,m)`为`S'(X,m)`；否则，它是`X`中通过使用-指令（using-directives）指定的所有命名空间`Ni`及其内联命名空间的`S(Ni, m)`的并集。

- 3 给定`X::`（其中`X`是用户声明的命名空间），或给定`::m`（其中`X`是全局命名空间），如果`S(X,m)`恰好有一个成员，或者引用的上下文是格式良好的（well-formed），则程序是格式不良的（ill-formed）。否则，如果`m`的使用是一个使用-声明（10.3.3），则`S(X,m)`是所需的`m`的声明所需的集。否则，如果`m`的使用不是允许从`S(X,m)`中选择唯一声明的用法，则程序是格式不良的。

示例：

```cpp
int x;
namespace Y {
    void f(float);
    void h(int);
}
namespace Z {
    void h(double);
}
namespace A {
    using namespace Y;
    void f(int);
    void g(int);
    int i;
}
namespace B {
    using namespace Z;
    void f(char);
    int i;
}
namespace AB {
    using namespace A;
    using namespace B;
    void g();
}

void h()
{}

AB::g();
// g 在 AB 中直接声明，因此 S 是 (AB::g())，且选择了 AB::g()

// f 不在 AB 中直接声明，因此在 A 和 B 中递归查找；
// 命名空间 Y 被查找且 Y::f(float) 被考虑；
// S 是 (A::f(int), B::f(char))，重载解析选择了 A::f(int)

AB::f(1);
// x 不在 AB 中直接声明，也不在 A 或 B 中直接声明，
// 因此在 A 和 B 中递归查找；
// S 是 {}，所以程序是格式不良的

AB::i++;
// i 不在 AB 中直接声明，因此在 A 和 B 中递归查找；
// S 是 (A::i, B::i) 是歧义的，程序是格式不良的

AB::h(16);
// h 不在 AB 中直接声明，也不在 A 或 B 中直接声明，
// 因此在 Y 和 Z 中递归查找；
// S 是 (Y::h(int), Z::h(double))，重载解析选择了 Z::h(double)

}
// 示例

- 4 注意：找到一次相同的声明不是歧义（因为是一个唯一的声明）。

示例：

```cpp
namespace A {
    int a;
}
namespace B {
    using namespace A;
}
namespace C {
    using namespace A;
}
namespace BC {
    using namespace B;
    using namespace C;
}
void f()
BC::a++;
// OK: S 是 {A::a, A::a}
namespace D {
    using A::;
}
namespace BD {
    using namespace B;
    using namespace D;
}
void g()
{
  BD::a++; // OK: S 是 {A::a, A::a}
}
// 示例

示例：每个引用的命名空间最多查找一次，以下情况是定义的：

```cpp
namespace B {
  int b;
}
namespace A {
  using namespace B;
  int a;
}
namespace B {
  using namespace A;
}
void f()
{
  A::a++; // OK: a 在 A 中直接声明，S 是 {A::a}
  B::a++; // OK: A 和 B 被查找（一次），S 是 {A::a}
  A::b++; // OK: A 和 B 被查找（一次），S 是 {B::b}
  B::b++; // OK: b 在 B 中直接声明，S 是 {B::b}
}
// 示例

在查找限定命名空间名称时，查找找到了成员的多个声明，如果一个声明引入了类名或枚举名，而其他声明引入了相同的变量、相同的枚举常量或一组函数，那么当且仅当声明来自同一个命名空间时，非类型名称会隐藏类名或枚举名；否则（声明来自不同的命名空间），程序是格式不良的。

示例：

```cpp
namespace A {
  struct x { };
  int x;
  int y;
}
namespace B {
  struct y { };
}
namespace C {
  using namespace A;
  using namespace B;
  int i = C::x; // OK, A::x（类型为 int）
  int j = C::y; // 歧义，A::y 或 B::y
}
// 示例

- 7 在命名空间成员的声明中，声明符（declarator-id）是一个限定标识符，给定命名空间成员的限定形式为

`nested-name-specifier unqualified-id`

`unqualified-id`应当命名嵌套名限定符所指定的命名空间的成员，或者命名空间集（10.3.1）中的元素。

示例：
```cpp
namespace A {
    namespace B {
        void f1(int);
    }
    using namespace B;
    void A1::f1(int) // 格式不良，f1 不是 A 的成员
}
```

然而，在这样的命名空间成员声明中，嵌套名限定符可能依赖使用-指令来隐式提供嵌套名限定符的起始部分。

示例：

```cpp
namespace A {
    namespace B {
        void f1(int);
    }
}
namespace C {
    namespace D {
        void f1(int);
    }
}
using namespace A;
using namespace C::D;
void B::f1(int) {} // OK，定义了 A::f1
} // 示例
```

## 6.4.4 详化类型（Elaborated type）

- 1 可以详化限定符（10.7）来引用类名或枚举名，嵌套名限定符是起始部分。

- 2 如果详化限定符是如下形式的声明：

```cpp
nested-name-specifier unqualified-id
```

`unqualified-id`应当命名嵌套名限定符所指定的命名空间的成员，或者命名空间集（10.3.1）中的元素。

示例：

```cpp
namespace A {
    namespace B {
        void f1(int);
    }
    using namespace B;
    void A1::f1(int) // 格式不良，f1 不是 A 的成员
} -- 示例
```

然而，在这样的命名空间成员声明中，嵌套名限定符可能依赖使用-指令来隐式提供嵌套名限定符的起始部分。

示例：

```cpp
namespace A {
    namespace B {
        void f1(int);
    }
}
namespace C {
    namespace D {
        void f1(int);
    }
}
using namespace A;
using namespace C::D;
void B::f1(int) {} // OK，定义了 A::f1
} // 示例
```

- 3 如果详化限定符是一个使用-声明（10.3.3），则详化限定符是所需的名称的声明集。否则，如果对名称的使用不是允许从查找集从中选择唯一声明的用法，程序是格式不良的。

## 6.4.5 类成员访问

- 1 在类成员访问（8.2.5）中，如果`.`或`->`紧跟一个带有列表的标识符，则查找该标识符以确定`<`是模板参数列表（17.2）的开始还是小于运算符。标识符在对象的类的上下文中查找。如果未找到标识符，则在整个后置表达式的上下文中查找，并声明类名。

- 2 如果类成员访问（8.2.5）中的`id-expression`是一个未限定标识符，且对象的类型是类`C`，则未限定标识符在类`C`的作用域内查找。对于伪析构函数调用（8.2.4），未限定标识符在整个后置表达式的作用文中查找。

如果`id-expression`是-类型，则在整个后置表达式的上下文中查找名称。如果对象的类型`T`是类`C`，则类型名也在类`C`的作用域内查找。至少有一个查找应该找到一个引用`cv T`的名称。

示例：

```cpp
struct B {
    struct A;
    void f(::A* a);
};
void B::f(::A* a) {
    a->A();
} // OK：在 *a 中查找找到了注入类名
```
