
在上述查询中，对所有相关表使用了`JOIN`子句来获取结果。基于上述语法，开发人员在实现此类查询时会遇到以下问题：

- 语法复杂，不必要地耗费更多精力和时间。在此示例中，为了检索所需信息，应用程序必须处理两个表，即`Students`和`Contacts`表。
- 有时，数据库的逻辑模式无法根据开发人员的需求使用应用程序的某些部分。在这种情况下，应用程序必须处理整个逻辑模式，这会不必要地增加服务器的额外负载。
- 逻辑模式无法理解业务实体及其相互关系，因为关系模型等模型无法呈现应用程序的概念领域知识。
- 如果应用程序处理的是数据子集，开发人员应该能够指出应用程序所需的适当子集。

这些问题在面向数据的应用程序中非常常见。为了解决这些问题，ADO.NET 引入了实体框架的概念，其设计目的是解决数据格式之间的不匹配问题。数据以表的形式存储在数据库中，并通过面向对象的编程语言来使用。ADO.NET Entity Framework 由数据模型组成，并提供设计时和运行时服务，使开发人员能够描述应用程序数据。

当我们使用逻辑模式时，查询会返回某些值与数据源无关的值。这意味着在整个应用程序中，关于核心应用程序概念，数据库元素之间没有共同的关系。Entity Framework 允许开发人员描述应用程序数据，并将应用程序与底层逻辑数据库模式隔离开来。

ADO.NET Entity Framework 旨在支持面向数据的应用程序和服务，并提供一个编程平台，将抽象级别从逻辑关系级别提高到概念级别。ADO.NET Entity Framework 通过使开发人员能够在更高的抽象级别上处理数据，来支持独立于任何特定数据存储（如 SQL Server 引擎或逻辑模式）的代码。概念模型通常用作捕获数据知识和解释应用程序需求的工具，这些需求通常在项目的早期阶段讨论。Entity Framework 提供了将实体和关系规范化为带外键约束的表的能力。因此，它使应用程序能够避免对特定数据引擎甚至特定逻辑模型的硬编码依赖。图 22.1 显示了实体框架的架构：

## Exploring the Features of Entity Framework

为了开发 Entity Framework 应用程序，我们需要在 Visual Studio 2010 中创建概念模型、逻辑模型和可编程对象模型。概念模型定义应用程序中的实体和关系。可编程对象模型随后从概念模型生成。逻辑模型表示关系模型以及概念模型与关系模型之间的映射。Entity Framework 的一些功能提高了数据编程的抽象级别并帮助开发人员提高生产力，如下所示：

- 通过提高对象查询执行的速度并使 `SQL` 查询的生成更简单来增强性能。
- 使用断开连接的组件操作，该组件在本地缓存数据集和实体集，以便在偶尔连接的环境中使用 Entity Framework。
- 通过在代码生成中使用部分方法来增强可扩展性和业务逻辑，以实现属性和属性更改事件的更改。
- 构成许多查询改进，例如为 `LINQ to Entities` 添加规范函数以及添加更多与数据库一起使用的操作。
- 扩展在开发过程中描述数据的模型。EDM 提供两种数据模型，即概念数据模型和存储模型，以及在这两个模型之间进行转换的映射。

除此之外，在 .NET Framework 的新版本中引入了一些 Entity Framework 的新功能，如下所示：

引入外键，以便简化在实体类型之间创建和修改关系的过程。开发人员对在概念和对象模型中包含外键有两种观点。一些人认为包含外键非常有利，而另一些人则认为外键污染了他们的概念和对象模型。因此，在 .NET Framework 4.0 中，添加了对一种新型关联的支持，即 FK 关联。此关联简化了在外键作为实体属性公开时生成概念模型的过程。

当您从现有数据库生成模型时，Entity Designer 工具的默认行为是为实体类型创建标量属性，这些属性对应于数据库中相应的外键列。

- 引入 Plain-Old Common Language Runtime Objects (POCO)，允许开发人员创建不仅简单而且可以包含在 Entity Framework 中的类。在 .NET Framework 的早期版本中，从模型派生的类继承自 `EntityObject` 类。如果开发人员想要创建不绑定到框架的简单类，这会阻碍开发人员。POCO 帮助 Entity Framework 在不更改数据类的情况下使用自定义数据类以及数据模型。简单来说，如果你有一个名为 `Employee` 的类，其中包含姓名、地址和电话号码，那么 Entity Framework 在实现它时不会更改该类。这意味着该类不会包含 `EntityKey` 或任何其他属性，这要求你在创建应用程序时实现 Entity Framework 特定的接口。
- 在此版本的 .NET Framework 中引入了 Entity Framework 中的延迟加载。延迟加载功能是许多对象关系映射 (ORM) 工具（如 `LINQ to SQL`）的常见功能。延迟加载功能简单来说是一种设计模式，有助于将对象的初始化重新安排到需要时为止。此功能有助于提高程序操作的效率。在 Entity Framework 中，延迟加载功能将在通过导航属性访问时加载相关对象。此新功能可以通过将 `LazyLoadingEnabled` 属性设置为 true 来在 Entity Framework 中实现（默认设置为 false）。`LazyLoadingEnabled` 属性是 `ObjectContext` 类的一个实例，该类是 Entity Framework 中以对象形式与数据交互的主要类。
- 引入对 `QueryExtender` 控件和 POCO 的支持，以用于 `EntityDataSource` 控件。`EntityDataSource` 控件是 ASP.NET 数据源控件，是早期版本 Entity Framework 的一部分。然而，随着新版本，`EntityDataSource` 控件已改进以支持 ASP.NET 中引入的新功能，即 `QueryExtender` 控件，该控件有助于更好地控制从数据源检索数据。`QueryExtender` 控件是在开发快速应用程序开发 (RAD) 网站时非常有用的控件。

除了对 `QueryExtender` 控件的支持外，`EntityDataSource` 控件现在还支持 POCO 实体，这有助于 `EntityDataSource` 控件使用生成的类进行其功能。

- 引入对二进制键的支持。Entity Framework 的新版本现在提供对映射为实体/外键的二进制属性类型的支持（通常称为二进制键）。
- 引入 `ObjectMaterialized` 事件。在此版本的 Entity Framework 中，可以编写在对象被物化后立即执行的逻辑。
- 介绍对象服务，即应用程序编程接口（API）改进，以支持 N 层和自跟踪实体。这意味着现在你可以使用 `ObjectStateEntry.GetUpdatableOriginalValues` 方法访问更新后的数据来建立实体的原始状态。
- 介绍在查询 Entity Framework 时使用 `SQL` 语句的改进，例如删除连接和消除用于内部目的的常量。
- 介绍导航属性管理，现在可以帮助开发者删除和添加导航属性，并且能够创建单向关联。
- 介绍对 Microsoft SQL Server Compact（SQL CE）版的支持。这将有助于简化数据库生成的定制。
- 介绍可扩展性 API，这将有助于向模型中的任何对象添加自定义属性。
- 介绍模型优先开发技术，这意味着开发者可以从 EDM 开始，然后从模型生成关联的 `T-SQL` 和定制代码。
- 介绍使用 Entity Framework 的应用程序的测试，其中包括一个接口，有助于更好地测试使用 Entity Framework 的应用程序。
- 介绍持久性忽略，这有助于开发者在 Entity Framework 应用程序中使用自己的类，而无需引入特定于 Entity Framework 的接口或元素。

让我们现在了解实体数据模型。

## 理解实体数据模型

数据模型通常在项目的分析或规划阶段设计。这是因为数据类型之间的关系、它们的属性以及数据中的约束必须在概念上组织好，然后才能在应用程序代码中实现。EDM 用于扩展应用程序设计者在开发过程中用来描述数据的模型。这些模型提供规范来定义应用程序使用的数据。基于 EDM 的应用程序在设计模式中定义应用程序域中的实体和关系，该设计模式用于生成可编程类，然后应用程序代码使用这些类。

在 EDM 中，映射规范连接设计模式和存储模式。包含应用程序数据的存储结构在存储模式中表示。存储模式映射到设计模式，以便映射规范有效地将可编程类连接到存储结构。现在，让我们了解与 EDM 设计相关的以下概念：

- 数据建模
- CSDL
- SSDL
- MSL
- EDM 类型
- 类型约束
- 数据模型工具

让我们现在逐一详细了解这些概念。

### 数据建模

数据建模是一种结构化和组织应用程序所需数据的技术。例如，应用程序中的一个实体必须由数据表示，例如客户、订单和产品，而关系则指定实体之间的逻辑连接。定义实体和关系可能是一个非常复杂的过程。它可能需要意想不到的细节量，例如，订单可能是电话订单、目录订单或互联网订单，这很令人困惑。为了解决这个问题，EDM 定义实体并使用数据读取器以序列化形式或作为具体化对象读取实体。

对象模型表示可以在通用语言运行时（CLR）中编程的类，可以从设计模式中定义的概念模型构建。EDM 概念模型是对应用程序域中实体和关系的规范。对象模型和存储元数据，由数据库结构的逻辑描述组成，被映射到概念层。

### 设计和实现

EDM 类型在模式中设计，以保持数据的逻辑完整性以及业务和技术应用程序的约束。根据 EDM 规范，实现数据模型需要以下三个开发阶段：

- 应用程序域中的实体和关系在 XML 文件中指定
- 描述数据库结构的元数据也在 XML 文件中指定
- 实体和关系到相应数据库的映射在存储元数据文件中指定

### EDM 映射到 CLR 和数据库管理系统

EDM 支持跨各种存储模型的应用程序场景，并映射到 CLR 和数据库管理系统，例如 SQL Server。随着 EDM 的引入，ADO.NET 提供了一个全面的平台，将应用程序代码连接到存储结构。它使用存储无关的视图机制，利用关系数据库管理系统（RDBMS）的概念来实现模式、编程语言和数据库表之间的映射。EDM 数据服务不依赖于任何特定存储模式。需要多个数据源的应用程序可以为每个数据源维护单独的映射。

使用 Entity Framework 开发应用程序需要创建和映射概念 EDM 和存储实体模型。Entity Framework 已通过 XML 文件的组合使实体关系建模可执行，例如概念模式定义语言（`.csdl`）、存储模式定义语言（`.ssdl`）和映射规范语言（`.msl`）。
