## 作为字节数组的结构体

#include <stdio.h>
#include <time.h>

void main() {
    struct {
        time_t unix_time;
        int i;
    } t;

    t.unix_time = time(NULL);

    for (i = 0; i < 9; i++) {
        for (j = 0; j < 4; j++) {
            printf("0x%02X ", ((unsigned char*)&t)[i*4+j]);
        }
        printf("\n");
    }
}

我们把结构作为一个整体传递，实际上，正如我们看到的，结构在第 10 行被复制到一个临时结构中（栈中的一个地方），并且包含了所有 4 个字段，每个字段的地址都对齐在 4 字节边界上。然后，通过第 12 ... 19 行，其指针（地址）被传递。

结构之所以被复制是因为不知道 `f()` 函数是否会修改该结构。如果它被更改了，`main()` 中的结构就必须保持原样。

我们可以使用 C/C++ 指针，生成的代码几乎相同，但不需要复制。

正如我们所看到的，每个字段都占据一个 4 字节的边界。这就是为什么这里每个 `char` 占据 4 字节（像 `int` 一样）。为什么？因为 CPU 访问对齐地址的内存并缓存数据要更容易。

然而，这并不经济。

让我们尝试使用选项 `/Zp1` 将结构按 1 字节边界对齐。

现在结构只占用 10 字节，而每个 `char` 占用 1 字节。这带给了我们什么？空间节省，缺点——CPU 访问这些字段比较慢。结构在 `main()` 中也是被复制的，不是逐个字段的，而是直接通过 10 字节。为什么不是 4 个？编译器决定使用 10 字节（3 组 `MOV`）来复制两个 32 位字和一个 16 位字。另外，使用 `MOV` 代替调用 `memcpy()` 是明智的——对于短块来说。除了 MSVC `/Zp` 对齐每个字段外，还有 `#pragma pack` 选项，可以直接在源代码中定义。在 MSVC 和 GCC 中可用。`WinNT.h` 文件有：

我们在数据窗口看到了 4 个字段。

但随机字节 (0x30, 0x37, 0x01) 是从哪里来的，它们位于第一个 (a) 和第三个 (c) 字段旁边？

通过查看我们的 Listing 1.345，我们可以看到第一个和第三个字段是 `char`，因此只写入了一个字节，分别为 1 和 3（第 6 和第 8 行）。

内存中剩余的 3 个字节（32 位字）没有被修改！因此，那里留下了随机垃圾。

这些垃圾不会影响 `printf()` 输出，因为它的值是使用 `MOVSX` 指令准备的，该指令处理字节而不是字：Listing 1.345（第 34 和第 38 行）。

另外，这里使用了 `MOVSX`（符号扩展）指令，因为 `char` 在 MSVC 中默认是有符号的，如果这里使用 `unsigned char` 类型或 `uint8_t`，将使用 `MOVZX` 指令。
